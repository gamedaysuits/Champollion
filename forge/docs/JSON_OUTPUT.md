# nmt-forge `--json` output — the agent contract

Every `nmt-forge` subcommand takes `--json`. With it:

- **stdout carries exactly one JSON document** — the command's payload, below.
  Everything else the command prints (schedule diagnostics, trainer logs,
  harness chatter) goes to **stderr**, so `json.loads(stdout)` always works.
- **A refusal** (any guard, bad arguments, a missing file) prints one JSON
  object on stdout and exits **2**:

  ```json
  {"error": {"type": "PreregistrationInvalid", "guard": "preregister",
             "message": "first line of the refusal",
             "why": "why it would corrupt results (or null)",
             "fix": "the exact command/action that fixes it (or null)",
             "how_to_get": "for missing resources (or null)",
             "text": "the full human message"}}
  ```

  `type` is the exception class (`UsageError` for bad arguments —
  abbreviated flags are refused, never guessed). Exit codes: `0` ok, `2`
  refused. `preflight` also exits `2` when any gate fails, with its normal
  payload. When an error's text quoted a sentence of a withheld corpus
  (below), that sentence reads `[sentence withheld]` in every field and the
  object adds `text_withheld` (the one-line reason); an UNEXPECTED error
  scrubbed this way exits `1` (an unexpected error with nothing to scrub is
  a plain Python traceback, as before). Some refusals add `details`, a
  content-free object with their numbers (`SplitSizeRefused`: `{deviations,
  group_size_report}` — see `split`).
- **Long-running commands** (`serve`, `monitor`) print ONE "ready" document
  and then keep running.

Payloads are content-free (counts, hashes, paths, row numbers) except where
text is the command's purpose (`prereg template`). Shapes are stable: fields
may be ADDED in later versions; existing fields keep their meaning.

**Private corpora.** A corpus the harness withholds text for — local-only
(a steward's `<file>.champollion.json` sidecar or a JSON envelope's
`dataset.transmission`), sealed (a held-out / gold-standard segment,
quarantined) or consent-required (a LicenseRef / bespoke licence) — never
has its sentences in a payload, with or without `--show-text` (which only
changes the HUMAN rendering, for a person at the terminal). Payloads that
can name such corpora carry `text_withheld` so an agent knows not to go and
read the file itself. `DatasetId` below = `{dataset_id, dataset_id_source}`:
the id `mt-eval` knows the set by — the mt-eval registry id (`add-harness`),
a JSON envelope's `dataset.id`, the registered corpora card's `id` (only
while the file's sha256 matches the sidecar's), the sidecar's `id`, else
forge's set name (`dataset_id_source: "forge set name"`). forge's own name
(`set` / `eval_set` / the registry key) is what the ledger, preregistrations
and `--eval-set` use. `CarriedMark` = `{from, mark: {transmission?, segment?,
license?}, sidecars: [path, …]}` or null — the source corpus's terms,
joined strictly with the harness's own mark for derived files
(`corpus_loader.derived_mark`, which also covers a set the mt-eval registry
seals or marks consent-required), written as a `.champollion.json` sidecar
next to each file a command carved from it — the shape `mt-eval` writes
next to its run logs and reports; a sidecar already there is joined, never
loosened.

The summary names each kind ("90 of the leaking rows match your registered dev set (80 rows): 80 are copies of its own rows and 10 are near-duplicates of its answers"). `verdict.audit_order` is set only for a plain audit that dropped the registered dev set's own rows (a `--drop-test-twins` audit after the split drops them on purpose, and its summary says so). ## The model export (`forge-model.json`)

`nmt-forge export` writes `forge-model.json` (format `nmt-forge-model/2`)
INTO the deployable model directory `<out>/model/` (into `<out>/evaluation/`
for a `--no-model` export, at `<out>/` with neither): `{format, name,
exported_utc, nmt_forge_version, run: {name, config_hash, manifest,
selected_checkpoint, backend, base, git_commit}, language: {source, target,
target_name, source_locales, target_locales}, model_dir, model_params,
model_export, decode: {max_new_tokens, num_beams, hook}, dev_report: {set,
scores}, test_report: {set, dataset_id, dataset_id_source, n, groups,
strict_groups, weighted, strict_overall, near_twin, prereg,
harness_reads, battery_manifest} | null, harness: {runlog, test_report, harness_version,
metrics: MetricCoverage} | null, evaluation: {dir, deployed: false, note,
mark} | null, data_rights, caveats: [..], serve: {command, endpoint,
openai_base} | null}`. Every path in it (`model_dir`, `battery_manifest`,
`harness.*`, `evaluation.dir`) is relative to the forge-model.json itself:
`model_dir` is `"."`, the evidence `"../evaluation/…"`. Format
`nmt-forge-model/1` (exports before 2026-10-03) sat at the export root with
`model_dir: "model"` and the evidence in `eval/` and `harness/`; `serve` and
`prereg check` read both.

The mt-eval TestReport in `evaluation/runlog_report.json` is the harness's own (scored with the plugins `mt-eval run` loads for the target language),
plus these fields in `overall` (ignored by the harness's readers and by
`mt-eval publish`, which read `overall` by key): `nmt_forge_near_twin_checked`,
`nmt_forge_near_twin_rows`, `nmt_forge_near_twin_share`, `nmt_forge_strict_n`,
`nmt_forge_strict_corpus_chrf`, `nmt_forge_strict_corpus_chrf_ci`,
`nmt_forge_recall_not_translation`, `nmt_forge_score_caveat` — so the
near-twin caveat travels with `corpus_chrf` — `nmt_forge_set` (forge's
name for the test set; `config.dataset_id` is its `DatasetId`), and
`nmt_forge_metrics_computed` / `nmt_forge_metrics_not_computed` (the
`MetricCoverage` lists: what the report does not carry, why, and the command
that computes it). The RunLog's
`provenance.dataset_meta` is what an `mt-eval run` on the file records (its
envelope + steward sidecar + registered card: `transmission`, `segment`,
licence, `id`, `corpus_card`, `contamination`) plus `nmt_forge_set`;
`config.transmission_policy` is the harness's policy for the file, enforced
for forge's in-process decode (`channel_basis` says nothing was
transmitted) — so `mt-eval compare` withholds a local-only, sealed or
consent-required test set's sentences on its terminal too. Both files KEEP
the text: they are written only where you point `--out` (into
`<out>/evaluation/`, never the model directory) / `--harness-out`.

## The served HTTP contracts (`nmt-forge serve`)

- `POST /translate` — the champollion api-method contract:
  request `{source_locale, target_locale, method, keys: {key: source},
  text_format?}`, response `{translations: {key: target}, meta: {model,
  method, note}}` — exactly the keys asked for; `207` with `errors: {key:
  {message}}` for unusable values; `400` for a language pair the model does
  not translate; `401` without the bearer token (when one is set); `413`
  over the size limits (500 strings, 20,000 characters each, 5,000 pieces of
  text for the model, 1 MB body); `500` when the model itself fails (never
  a partial answer). `text_format: "markdown"` (what the CLI sends for a
  content body) joins hard-wrapped paragraph lines before translating;
  without it every line break is kept.
- `POST /v1/chat/completions` — OpenAI-compatible; the user message is read
  by shape: a trailing JSON object of strings → the same keys back,
  translated; the CLI's content block-batch prompt (`⟦SEG_N⟧` lines) → every
  segment back under its own marker; the CLI's whole-page content prompt
  (instructions, `---`, body) → the translated body; anything else →
  translated as Markdown. Instructions are not followed (header
  `X-NMT-Forge-Note`).
- Every string goes through `nmt_forge.textpipe`: placeholders (`{x}`,
  `{{x}}`, printf), ICU plural/select skeletons, HTML/JSX tags and
  entities, inline code, URLs, e-mail addresses, the CLI's `⟦…⟧`
  placeholders and Markdown structure are copied verbatim; the model sees
  only the text between them, sentence by sentence.
- `GET /v1/models`, `GET /health` (health is unauthenticated; it names the
  text pipeline under `text_pipeline`, and beside the test score
  (`test_report`) the eval harness's `score_caveats` from forge-model.json,
  verbatim — null when it recorded none).
