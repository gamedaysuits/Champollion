# Champollion

[![إصدار npm](https://img.shields.io/npm/v/champollion.svg)](https://www.npmjs.com/package/champollion)
[![الترخيص: PolyForm Noncommercial 1.0.0](https://img.shields.io/badge/license-PolyForm--Noncommercial--1.0.0-blue.svg)](#license)


ترجم ملفات الترجمة الخاصة بك بأمر واحد:

```bash
npx champollion sync
```

يكتشف Champollion تلقائيًا ملفات الترجمة الخاصة بك، وتنسيقها، واللغات المستهدفة. ويقوم بترجمة المفاتيح المفقودة، ويتخطى ما تم إنجازه بالفعل، ويكتب النتائج. هذا كل شيء.

**الترخيص:** متاح المصدر بموجب [ترخيص PolyForm غير التجاري 1.0.0](../LICENSE) — مجاني للاستخدام والتعديل والمشاركة للأغراض غير التجارية (المشاريع الشخصية، والبحث، والتدريس، والاستخدام من قبل المؤسسات الخيرية والمدارس والهيئات العامة). لا يغطي هذا الترخيص استخدامه لغرض تجاري. بيئة التقييم (evaluation harness) مفتوحة المصدر (AGPL-3.0-or-later). [من يحق له استخدام هذا](https://champollion.dev/docs/getting-started/who-may-use-this) · [التفاصيل](#license).

> **جزء من Champollion** — بنية تحتية لتقييم الترجمة الآلية الموثوقة عبر كل لغة، متاحة المصدر ومجانية للاستخدام غير التجاري (بيئة التقييم والسجلات المشتركة مفتوحة المصدر). واجهة سطر الأوامر (CLI) هذه هي نقطة النشر لمشروع أكبر يبني مجموعات الاختبار والخريطة التي توضح من يمكنه ترجمة ماذا، ومدى جودة كل طريقة في كل نوع من النصوص، وأين لا تزال الفجوات موجودة. يعمل المشروع على نوعين من المعايير: المعايير العامة على البيانات المفتوحة (شاملة، منخفضة التكلفة، ترحب بكل طريقة) والمعايير السيادية — مجموعات اختبار سرية تنشئها المجتمعات وتمتلكها وتتحكم فيها، ولا نراها أبدًا. البنية التحتية متاحة المصدر وتدار بشكل فردي؛ مجموعات الاختبار والطرق الخاصة بلغة مجتمع ما تنتمي إلى ذلك المجتمع. صُمم للعمل مع المجتمعات، ولا يستضيف نصوصها أبدًا — التصميم يضع المفاتيح في أيديهم. نرحب بكل طريقة، سواء كانت بشرية أو آلية. استكشف الشبكة على [champollion.dev/docs/network](https://champollion.dev/docs/network/).

## لماذا لا تكتب البرنامج النصي بنفسك؟

يمكنك كتابة برنامج نصي سريع يمر عبر مفاتيحك الإنجليزية ويستدعي Google Translate. يفعل معظم المطورين ذلك — يستغرق الأمر حوالي 30 سطرًا. إليك سبب فشل ذلك:

- **لا يوجد اكتشاف للتغييرات.** عندما تقوم بتحديث نص إنجليزي، تظل الترجمة قديمة إلى الأبد. يتتبع Champollion كل قيمة مصدر باستخدام تجزئات SHA-256 ويعيد ترجمة ما تغير فقط.
- **لا يوجد تجميع (batching).** استدعاء API واحد لكل مفتاح يعني 200 مفتاح = 200 رحلة ذهاب وإياب. يقوم Champollion بالتجميع بذكاء (قابل للتهيئة، الافتراضي 80 مفتاحًا/دفعة للنماذج اللغوية الكبيرة (LLM)، و128 لـ Google).
- **لا توجد بوابة جودة.** الترجمة الآلية تهلوس، أو تعيد المصدر كما هو، أو تخرج بنظام كتابة خاطئ. يتحقق Champollion من كل ترجمة قبل كتابتها — يتم التقاط ورفض المخرجات الفارغة، وتكرار المصدر، وحلقات التكرار، وتضخم الطول، والمحتوى المحذوف، ونظام الكتابة الخاطئ. تلتقط البوابة المخرجات المعطلة، وليس المعنى الخاطئ.
- **لا يوجد وعي بالتنسيق.** هل هو مبرمج ثابتًا لـ JSON؟ يتعامل Champollion مع JSON، و TOML، و YAML، و Hugo Markdown (البيانات التمهيدية + النص الأساسي) مع الاكتشاف التلقائي.
- **لا يوجد أمان.** يحمي Champollion من تلوث النموذج الأولي (prototype pollution)، واجتياز المسار (path traversal) عبر رموز اللغات المحلية المصاغة، وتلف كتل التعليمات البرمجية أثناء ترجمة Markdown.

Champollion هو إصدار الإنتاج من ذلك البرنامج النصي.

> [!NOTE]
> **ما يترجمه Champollion.** يستهدف Champollion **ملفات الترجمة والمحتوى المهيكل** — أزواج المفتاح-القيمة في JSON، وتكوين TOML/YAML، وصفحات Hugo Markdown، ومستندات التبادل XLIFF. تم تحسينه للنصوص المكتوبة الرسمية: نصوص واجهة المستخدم، والوثائق، والاتصالات الرسمية، والمواد التعليمية. إنه ليس روبوت محادثة، أو مترجم كلام في الوقت الفعلي، أو ذكاء اصطناعي حواري للأغراض العامة. لكل زوج لغوي، تكون طريقة الترجمة قابلة للتهيئة — بدءًا من واجهات برمجة التطبيقات التجارية (Google Translate، DeepL) إلى المكونات الإضافية التي يطورها المجتمع والتي تم قياس أدائها من خلال [MT Eval Arena](https://champollion.dev/arena).

## البدء السريع

```bash
npm install --save-dev champollion
```

### الحصول على مفتاح API

يحتاج Champollion إلى واجهة خلفية للترجمة. اختر واحدة:

| المزود | المفتاح | الأفضل لـ |
|----------|-----|----------|
| **OpenRouter** (موصى به) | `OPENROUTER_API_KEY` | المشاريع كثيفة المحتوى، Markdown، أكثر من 200 نموذج |
| **OpenAI** | `OPENAI_API_KEY` | الوصول المباشر إلى GPT-4o |
| **Anthropic** | `ANTHROPIC_API_KEY` | الوصول المباشر إلى Claude |
| **Gemini** | `GEMINI_API_KEY` | تتوفر فئة مجانية |
| **DeepL** | `DEEPL_API_KEY` | اللغات الأوروبية، دعم المسارد |
| **Google Translate** | `GOOGLE_TRANSLATE_API_KEY` | أكثر من 130 لغة، الحجم الكبير |

**أسرع بداية** (مجاني): سجل في [aistudio.google.com](https://aistudio.google.com/apikey) للحصول على مفتاح Gemini مجاني:

```bash
export GEMINI_API_KEY=AI...
npx champollion sync --method gemini
```

**OpenRouter** (أكثر من 200 نموذج): سجل في [openrouter.ai](https://openrouter.ai)، ثم:

```bash
export OPENROUTER_API_KEY=sk-or-v1-...
npx champollion sync
```

بديل **Google Translate** (أزواج المفتاح-القيمة فقط — لا يوجد وعي بـ Markdown):

```bash
export GOOGLE_TRANSLATE_API_KEY=...
npx champollion sync --method google-translate
```

> **ملاحظة**: إذا تم تعيين `GOOGLE_TRANSLATE_API_KEY` فقط، يتحول champollion تلقائيًا إلى Google Translate. لا حاجة لتغيير التهيئة. يستخدم REST API مباشرة — بدون SDK، وبدون حساب خدمة، وبدون `pip install`. فقط المفتاح.

هذا كل شيء. لمزيد من التحكم، قم بإنشاء ملف تهيئة:

```bash
npx champollion init                        # guided wizard — walks you through registers, methods, and content
npx champollion init --yes --langs fr,de,ja  # quick setup with specific languages and default registers
```

تأتي كل لغة مع **إعدادات مسبقة للسجل** — تعليمات مبنية مسبقًا للنبرة/الرسمية مضبوطة وفقًا لنظامها اللغوي (vouvoiement للفرنسية، Siezen للألمانية، です/ます لليابانية، 해요체 للكورية). يتيح لك معالج التهيئة تصفح واختيار الإعدادات المسبقة، أو تمرير `--yes` لقبول الإعدادات الافتراضية.

### مصدر غير إنجليزي

إذا كانت لغتك المصدر ليست الإنجليزية:

```bash
champollion sync --source fr                      # CLI flag
```

أو قم بتعيينها بشكل دائم في ملف التهيئة الخاص بك:

```json
{ "inputLocale": "fr" }
```

## ماذا يفعل

أنت تتعامل مع إطار عمل التدويل (i18n) (مثل next-intl، i18next، Hugo). ويتعامل Champollion مع ملفات الترجمة.

- **متعدد التنسيقات** — JSON، و TOML، و YAML، و Hugo Markdown (البيانات التمهيدية + النص الأساسي)، و XLIFF 1.2
- **تزايدي** — يترجم فقط ما تغير (تتبع تجزئة SHA-256)
- **مخزن مؤقتًا** — تخزن ذاكرة الترجمة النتائج السابقة؛ إعادة تشغيل المزامنة لا تكلف شيئًا للمفاتيح غير المتغيرة
- **بوابة جودة** — يتحقق من كل ترجمة بحثًا عن المخرجات المعطلة: حلقات التكرار، ومخرجات نظام الكتابة الخاطئ، وتكرار المصدر، وتضخم الطول، والمحتوى المحذوف (لا يتحقق من المعنى)
- **مدرك للمحتوى** — تحمي طرق النماذج اللغوية الكبيرة (LLM) كتل التعليمات البرمجية، والرموز القصيرة، والروابط، ومتغيرات الاستيفاء أثناء ترجمة Markdown
- **أدوات مسار العمل** — `lint`، و `audit`، و `integrity`، و `seo` لبوابات التكامل المستمر (CI)
- **التوافق مع XLIFF** — تصدير الترجمات للمراجعة الاحترافية في أدوات الترجمة بمساعدة الحاسوب (مثل memoQ، و SDL Trados، و Phrase)، واستيرادها مرة أخرى
- **تبعيات قليلة** — تبعيتان في وقت التشغيل: `@translated/lara` (حزمة تطوير برمجيات مزود Lara) و `cree-sro-syllabics` (محول Plains Cree SRO ⇄ المقاطع اللفظية الخاص بـ ALTLab/NRC). يتطلب Node 20+

## ما وراء Google Translate

يجعلك البدء السريع تعمل باستخدام نموذج لغوي كبير (LLM) أو Google Translate. لكن Google Translate يدعم حوالي 130 لغة. بينما يوجد أكثر من 7000 لغة.

**الفكرة الأساسية لـ Champollion: طريقة الترجمة قابلة للتهيئة لكل زوج لغوي.** استخدم Google Translate للغة الفرنسية، ونموذجًا لغويًا كبيرًا (LLM) مدربًا بملاحظاتك النحوية وقاموسك للغة Plains Cree، وواجهة برمجة تطبيقات (API) تستضيفها للغة لا تغطيها أي خدمة — كل ذلك في نفس المشروع، وكل ذلك باستخدام نفس واجهة سطر الأوامر (CLI).

```json
{
  "version": 3,
  "pairs": {
    "en:fr": { "method": "google-translate" },
    "en:ja": { "method": "llm" },
    "en:crk": { "method": "llm-coached" }
  }
}
```

إذا تمكنت من معرفة كيفية ترجمة زوج لغوي — من خلال هندسة التلقين، أو قواميس المجتمع، أو مسارات FST، أو النماذج المضبوطة بدقة — يتيح لك champollion حزم هذه الطريقة كمكون إضافي ونشرها جنبًا إلى جنب مع كل شيء آخر.

> نشأ من ترجمة موقع ويب إنتاجي إلى لغة Plains Cree، حيث لا توجد واجهة برمجة تطبيقات (API) جاهزة للاستخدام. البنية القائمة على الزوج اللغوي ليست نظرية — فهي موجودة لأن أحد المشاريع احتاج إلى Google Translate للغة الفرنسية ومسار FST مدرب للغة أصلية، يعملان جنبًا إلى جنب في نفس أمر المزامنة.

تتيح لك الأداة المرافقة [MT Eval Harness](https://github.com/gamedaysuits/Champollion) قياس ومقارنة مناهج الترجمة، ثم تصدير الطرق الفعالة كمكونات إضافية لـ champollion. يمكن لأي شخص يتحدث كلتا اللغتين تطوير واختبار ومشاركة طريقة ترجمة — دون الحاجة إلى منصة احتكارية.

### اختر طريقتك

يدعم Champollion 10 طرق للترجمة. يمكن لكل زوج لغوي استخدام طريقة مختلفة.

**مزودو النماذج اللغوية الكبيرة (LLM)** — الأفضل من حيث الجودة، ومدركون لـ Markdown، ومتوافقون مع التدريب:

| الطريقة | المفتاح | ماذا تفعل |
|--------|-----|-------------|
| `llm` (الافتراضي) | `OPENROUTER_API_KEY` | نموذج لغوي كبير (LLM) عبر OpenRouter — أكثر من 200 نموذج، توجيه تلقائي |
| `llm-coached` | `OPENROUTER_API_KEY` | نموذج لغوي كبير (LLM) + قواعد نحوية، قواميس، ملاحظات الأسلوب |
| `openai` | `OPENAI_API_KEY` | واجهة برمجة تطبيقات OpenAI المباشرة (gpt-4o، gpt-4o-mini) |
| `anthropic` | `ANTHROPIC_API_KEY` | واجهة برمجة تطبيقات Anthropic المباشرة (Claude Sonnet، Haiku، Opus) |
| `gemini` | `GEMINI_API_KEY` | واجهة برمجة تطبيقات Google Gemini المباشرة (Flash، Pro) — تتوفر فئة مجانية |
| `local` | *(لا يوجد)* | نموذجك الخاص خلف نقطة نهاية متوافقة مع OpenAI (مثل Ollama، vLLM، LM Studio، أو نموذج مدرب باستخدام `nmt-forge`). قم بتعيين `LOCAL_API_BASE` إذا لم يكن في الإعداد الافتراضي لـ Ollama. النص لا يغادر بنيتك التحتية أبدًا |

**الترجمة الآلية التقليدية** — الأفضل من حيث السرعة، والتكلفة، وأزواج المفتاح-القيمة ذات الحجم الكبير:

| الطريقة | المفتاح | ماذا تفعل |
|--------|-----|-------------|
| `google-translate` | `GOOGLE_TRANSLATE_API_KEY` | واجهة برمجة تطبيقات Google Cloud Translation v2 (أكثر من 130 لغة) |
| `deepl` | `DEEPL_API_KEY` | واجهة برمجة تطبيقات DeepL مع دعم المسارد (أكثر من 30 لغة) |
| `microsoft-translator` | `MICROSOFT_TRANSLATOR_API_KEY` | مترجم Azure Cognitive Services (أكثر من 100 لغة) |
| `libretranslate` | *(استضافة ذاتية)* | LibreTranslate مستضاف ذاتيًا (AGPL، مجاني) |

**البنية التحتية** — لنقاط النهاية المخصصة أو المستضافة من قبل المجتمع:

| الطريقة | المفتاح | ماذا تفعل |
|--------|-----|-------------|
| `api` | *(لكل مزود)* | عميل HTTP خفيف لأي نقطة نهاية REST |

```bash
# Force a specific method for one run
champollion sync --method deepl

# Or configure per pair
```

```json
{
  "pairs": {
    "en:fr": { "method": "deepl" },
    "en:ja": { "method": "openai", "model": "gpt-4o" },
    "en:crk": { "method": "llm-coached" }
  }
}
```

> **ملاحظة**: تتعامل طرق الترجمة الآلية التقليدية (Google Translate، DeepL، Microsoft Translator، LibreTranslate) مع أزواج المفتاح-القيمة بشكل جيد ولكنها لا تستطيع ترجمة محتوى Markdown بأمان. بالنسبة للمشاريع كثيفة المحتوى، يوصى باستخدام طرق النماذج اللغوية الكبيرة (LLM) — فهي تحمي بشكل صريح كتل التعليمات البرمجية، والرموز القصيرة، ومتغيرات الاستيفاء.

## المكونات الإضافية

المكونات الإضافية هي وصفات ترجمة معبأة مسبقًا لأزواج لغوية محددة. إنها بيانات JSON — وليست تعليمات برمجية — تخبر champollion بالطريقة التي يجب استخدامها، وبأي إعدادات، وما هي الجودة التي تم قياسها.

```bash
champollion plugin install ./french-formal-v1/    # install from directory
champollion plugin list                           # see installed plugins
champollion plugin remove french-formal-v1        # uninstall
champollion status                                # shows each pair's method, model + plugin benchmarks
```

راجع [الوثائق المرجعية](https://champollion.dev/docs/reference/plugin-spec) لمعرفة تنسيق البيان.

## الأوامر

| الأمر | الغرض |
|---------|---------|
| `init` | معالج الإعداد التفاعلي (أو `--yes` للإعدادات الافتراضية السريعة) |
| `sync` | ترجمة ومزامنة جميع ملفات الترجمة |
| `serve` | تقديم حزمة الترجمة الخاصة بهذا المشروع عبر HTTP (عقد api-method) |
| `watch` | المزامنة التلقائية عند تغيير الملفات |
| `audit` | وضع علامة على اللغات المحلية غير المكتملة (بوابة CI) |
| `lint` | العثور على السلاسل النصية المبرمجة ثابتًا في التعليمات البرمجية المصدر |
| `status` | إظهار تهيئة الزوج اللغوي، والطرق، والسجلات، ومعايير المكونات الإضافية |
| `provenance` | تدقيق ترخيص موارد الترجمة |
| `wrap` | التغليف التلقائي للسلاسل النصية المبرمجة ثابتًا في استدعاءات `t()` (مع إمكانية التراجع) |
| `seo` | إنشاء hreflang، أو sitemap.xml، أو مخطط JSON-LD |
| `integrity` | التحقق من تلف العناصر النائبة، والترميز، واكتمال صيغ الجمع في ICU |
| `plugin` | تثبيت، أو إزالة، أو سرد المكونات الإضافية للطرق |
| `fonts` | تنزيل خطوط الويب لمحوّلات نصوص PUA |
| `tm` | إدارة ذاكرة التخزين المؤقت لذاكرة الترجمة (الإحصائيات، المسح، التأسيس، التقليم) |
| `xliff` | تصدير/استيراد XLIFF 1.2 لمراجعة المترجمين المحترفين |
| `models` | سرد النماذج المتاحة لمزود (`--method gemini`) |
| `verify` | إعادة قراءة ملفات الترجمة المكتوبة والتأكد من وجود الترجمات وصحتها (بوابة CI) |
| `doctor` | فحص صحة النظام: البطاقات، والتهيئة، والطرق، والمحولات |

الأوامر التي تعمل مع الفهرس المشترك ولوحة الصدارة، بدلاً من مشروعك، مجمعة تحت `champollion network` (يعمل كل منها أيضًا بدون البادئة):

| الأمر | الغرض |
|---------|---------|
| `network card` | طباعة منسقة لبطاقة لغة (`network card <code>`، `--json` للبيانات الخام) |
| `network recommend` | إرشادات الطريقة لزوج لغوي — التوافر + الأدلة المستشهد بها (`network recommend eng fra`، `--use`، `--json`) |
| `network leaderboard` | إظهار لوحة صدارة الترجمة الآلية (`--pair`، `--sort`، `--install N`) |
| `network register-corpus` | تسجيل مجموعة نصوص للتقييم: اختيار ترخيص + مستوى التعرض (محلي فقط/خاص/عام/مختوم) |
| `network seal-corpus` | أفعال التشفير للمستوى المختوم: `keygen` / `seal` / `open` (جسر العقدة المنظمة) |
| `network submit` | اقتراح إدخال في الفهرس (خاضع للمراجعة) — يطبع مشكلة GitHub معبأة مسبقًا |

قم بتشغيل `champollion <command> --help` للحصول على مساعدة مفصلة حول أي أمر.

المرجع الكامل: [الوثائق المرجعية](https://champollion.dev/docs/reference/cli)

### بوابة ما قبل الالتزام

تم بناء `champollion lint` ليكون بوابة التزام: يخرج بـ `1` عندما يجد سلاسل نصية مبرمجة ثابتًا تواجه المستخدم ويخرج بـ `0` عندما يكون نظيفًا (يقوم `--warn-only` بالإبلاغ دون حظر). قم بربطه في دليل خطافات متتبع في مشروعك:

```bash
mkdir -p .githooks
printf '#!/bin/sh\nnpx --yes champollion@0.5 lint\n' > .githooks/pre-commit   # pinned: a new release never changes what the hook runs
chmod +x .githooks/pre-commit
git config core.hooksPath .githooks   # once per clone
```

أو قم بتشغيله من [lint-staged](https://github.com/lint-staged/lint-staged) بحيث يعمل فقط عندما تكون الملفات المصدر في مرحلة التجهيز:

```json
{
  "lint-staged": {
    "src/**/*.{js,jsx,ts,tsx}": "champollion lint"
  }
}
```

أبقِ `champollion sync` خارج مرحلة ما قبل الالتزام — فهو يجري استدعاءات شبكة لواجهة برمجة التطبيقات، لذا فهو بطيء في أحسن الأحوال ويحظر الالتزامات عند عدم الاتصال بالإنترنت في أسوأ الأحوال. قم بتشغيله في التكامل المستمر (CI) أو في خطاف ما قبل الدفع بدلاً من ذلك، مع استخدام `champollion audit` / `champollion verify` كبوابة.

## التهيئة

قم بإنشاء `champollion.config.json` أو تشغيل `champollion init`:

```json
{
  "version": 3,
  "inputLocale": "en",
  "localesDir": "./locales",
  "model": "google/gemini-3.8-flash",
  "pairs": {
    "en:fr": { "qualityTier": "high" },
    "en:ja": { "method": "google-translate" }
  }
}
```

| الخيار | الافتراضي | الوصف |
|--------|---------|-------------|
| `inputLocale` | `"en"` | رمز اللغة المصدر |
| `localesDir` | `"./locales"` | مسار ملفات الترجمة: ملف واحد لكل لغة (`fr.json`) أو مجلد واحد لكل لغة (`fr/common.json`، i18next) |
| `localesPattern` | `null` | أي تخطيط آخر، مثل `"src/i18n/{ns}/{lang}.json"` (يستبدل `localesDir`) |
| `contentDir` | `null` | مجلد Markdown/MDX المراد ترجمته (مثل `content/` في Hugo أو أي مجلد)؛ تُكتب كل ترجمة بجوار مصدرها كـ `<name>.<locale>.md` |
| `format` | `"auto"` | تنسيق الملف: `json`، أو `toml`، أو `yaml`، أو `auto` |
| `model` | `"google/gemini-3.8-flash"` | النموذج الافتراضي (معرف OpenRouter). يحدد المزودون المباشرون الإعداد الافتراضي الخاص بهم في وقت التشغيل. قم بتشغيل `champollion models --method gemini` لاكتشاف النماذج المتاحة. |
| `defaultMethod` | `"llm"` | طريقة الترجمة الافتراضية (يتم تجاوزها بواسطة علامة `--method`) |
| `batchSize` | `80` | عدد المفاتيح لكل دفعة ترجمة |
| `pairs` | `{}` | تجاوزات الطريقة، والنموذج، والجودة لكل زوج لغوي |

**تجاوزات لكل لغة**: تحتوي كل لغة على [بطاقة لغة](https://champollion.dev/docs/reference/language-card-spec) — وهي واحدة من 50 بطاقة منسقة تحتوي على إعدادات مسبقة للسجل، وأنظمة الرسمية، وقواعد الطباعة، وعلامات دعم الطريقة. تستخدم البطاقات [بنية ثنائية المستوى](https://champollion.dev/docs/concepts/architecture) (وقت التشغيل + المرجع) من أجل الأداء على نطاق واسع. قم بإنشاء هيكل بطاقة جديدة باستخدام `node scripts/generate-language-card.mjs <code>`. استخدم مفاتيح الإعداد المسبق كاختصار، أو اكتب نص سجل مخصص:

```json
{
  "languages": {
    "fr": "casual-tu",
    "ko": "formal-hapsyo",
    "crk": {
      "name": "Plains Cree",
      "register": "SRO syllabics with grammatical precision.",
      "model": "google/gemini-3.1-pro-preview",
      "batchSize": 5,
      "maxRetries": 5,
      "script": "Cans"
    }
  }
}
```

**وضع عدم التهيئة**: لا يوجد ملف تهيئة؟ يكتشف Champollion تلقائيًا ملفات الترجمة، والتنسيق، واللغات المستهدفة من مشروعك.

يمكن أن تكون قيم اللغة مفتاح إعداد مسبق (مثل `"casual-tu"`)، أو نص سجل مخصص، أو كائنًا (تحكم كامل). التجاوزات على مستوى الزوج اللغوي في `pairs` لها الأولوية على الإعدادات على مستوى اللغة. قم بتشغيل `npx champollion init` لتصفح الإعدادات المسبقة المتاحة لكل لغة.

راجع [مرجع واجهة سطر الأوامر](https://champollion.dev/docs/reference/cli) للحصول على تفاصيل الإعداد الخاصة بإطار العمل.

## التحصين

- **التراجع الأسي** — 3 محاولات إعادة مع تذبذب عند أخطاء 429/5xx
- **مهلة الطلب 30 ثانية** — يمنع AbortController التعليق
- **التحقق من الاستجابة** — يقبل فقط المفاتيح التي تم إرسالها للترجمة
- **بوابة الجودة** — تلتقط حلقات الهلوسة، ومخرجات نظام الكتابة الخاطئ، وتضخم الطول، وتكرار المصدر
- **تتالي إعادة المحاولة** — عند فشل تحليل JSON، يعيد محاولة الدفعة ← نصف الدفعة ← المفاتيح الفردية (محدود الميزانية عبر `maxRetries`)
- **ذاكرة الترجمة** — يقوم `.champollion/tm.json` بتخزين الترجمات مؤقتًا مفهرسة بالنص المصدر + اللغة المحلية + الطريقة؛ يتم تقديم المفاتيح غير المتغيرة من ذاكرة التخزين المؤقت في عمليات المزامنة اللاحقة، مما يلغي استدعاءات API الزائدة
- **التخزين المؤقت للتلقين** — يتيح تقسيم رسائل النظام/المستخدم التخزين المؤقت على مستوى المزود، مما يقلل من تكلفة الرموز عبر الدفعات
- **فرض المصطلحات** — يتم التحقق من الترجمات المدربة مقابل مصطلحات القاموس بعد استجابة النموذج اللغوي الكبير (LLM)
- **حماية تلوث النموذج الأولي** — يحظر `__proto__`، و `constructor`، و `prototype`
- **احتواء المسار** — يتم التحقق من صحة عمليات كتابة الملفات للبقاء ضمن الدلائل المهيأة
- **حماية الكتل** — حماية كتل التعليمات البرمجية، والرموز القصيرة، و HTML أثناء ترجمة المحتوى
- **بنية الفشل الصاخب** — تؤدي إخفاقات الترجمة دائمًا إلى طرح رسائل خطأ قابلة للتنفيذ، ولا تكتب أبدًا بيانات غير صالحة بصمت
- **التحقق بعد المزامنة** — يعيد الأمر `verify` قراءة الملفات المكتوبة ويؤكد وجود الترجمات، وصحة نظام الكتابة، وسلامة العناصر النائبة
- **نجاح جزئي** — فشل دفعة واحدة لا يعيق الباقي
