# 데이터 및 전송 규칙

언어 데이터를 보유한 분들이 데이터 사용 방식을 결정해요. 레일은 각 파일 옆에 이 결정을 기록하며, 모든 도구는 기록된 내용을 따라요. 이는 언어 데이터에 대한 커뮤니티의 소유권과 통제권을 단순한 설정이 아닌 설계 원칙으로 삼기 때문이에요. 이 페이지는 정확한 규칙 모음이에요. 각 필드의 역할, 도구가 거부하는 작업, 그리고 사용자만이 보관할 수 있는 부분을 다뤄요.

## 사이드카 (set/1)

모든 데이터 파일 옆에 `<file>.champollion.json`, `$schema`
`https://champollion.dev/schemas/set/1.json`가 위치해요. 알 수 없는 키는 거부되며, 메모는 `x-` 아래에 들어가요. set/1 이전에 작성된 사이드카(`$schema` 없음)는 set/0으로 읽히며 계속 유효해요(`champollion upgrade`가 이를 다시 작성해요).

| 필드 | 값 | 효과 |
|---|---|---|
| `transmission` | `local-only` (유일한 값) | 이 컴퓨터에 있는 모델만 텍스트를 볼 수 있어요. 모든 도구는 어디로든 이를 전송하기를 거부해요(`mt-eval project offer` 포함) |
| `role` | `train` · `dev` · `test` · `sealed` · `input` · `resource` | 파일의 용도예요. `test` 및 `sealed`은 학습에 절대 사용되지 않아요 |
| `kind` | `parallel` · `monolingual` · `lexicon` · `grammar` · `glossary` | 파일에 담긴 내용이에요 |
| `pair` | `{source, target}` | 카드의 코드 기준으로, 열이 진행되는 방향이에요 |
| `fields` | `{source, target}` | 어느 열 또는 JSON 필드가 어느 쪽을 담고 있는지예요 |
| `terms.training` | `allowed` · `not-allowed` | `not-allowed`: 어떤 모델도 이를 학습할 수 없어요 |
| `terms.owner` | 텍스트 | 보유자의 말로 적은, 데이터를 보유한 주체예요 |
| `terms.speakers` | 텍스트 | 보유자의 말로 적은, 누구의 말이 담겨 있는지예요 |
| `terms.speakers_agreed` | `yes` · `not-yet` · `some-said-no` | 이 말의 주인공들이 동의했는지 여부예요 |
| `terms.consent_record` | 경로 | 파일 폴더 기준 동의서 경로예요 |
| `holders_agreed` | `{by, date}` | 로컬 전용 출력이 있는 자리에 그대로 머무는 데 동의한 보유자예요(아무것도 완화되지 않아요) |
| `derived_from` | 경로 | 이 파일이 만들어진 원본 보호 파일 경로예요. 원본의 표식이 여기로 복사되었어요 |
| `id`, `name`, `license`, `tier`, `segment`, `sha256`, `rows`, `card`, `registeredAt` | | `champollion network register-corpus`가 기록해요. 변경된 파일(다른 sha256)은 더 이상 카드의 id를 받지 못해요 |
| `written_by` | 텍스트 | 이를 기록한 명령이에요 |

**잠금.** 사이드카는 파일을 더 엄격하게만 만들 뿐이에요. 말뭉치 엔벨로프나 레지스트리 항목에 명시된 내용을 절대 완화하지 않아요.

## 로컬 전용과 임시 기본값

`champollion data add`는 프로젝트의 `defaults.transmission`가 `local-only`일 때(`champollion new`가 기록하는 값), 그리고 `--into test`에 대해서는 항상 생성하는 파일을 로컬 전용으로 표시해요. 이 표시는 보유자가 답변할 때까지 도구가 제공하는 보호 조치이며, `"x-transmission-default": true` 플래그가 붙어요.

- 보유자의 첫 번째 답변이 결정을 내려요. `champollion data mark <file>
  --may-leave` lifts a provisional mark; `--local-only` 명령을 실행하면 보유자의 결정이 적용돼요(플래그가 제거돼요).
- **참고.** 도구는 누가 명령을 실행했는지 알 수 없어요. 보유자 본인의 답변이 있을 때만 임시 표시를 해제하세요.
- **잠금.** 보유자가 지정한 로컬 전용 표시는 어떤 명령으로도 해제할 수 없어요. *"이 파일은 로컬 전용으로 표시되어 있으며, 사이드카는 오직 더 엄격해질 뿐입니다. 이 파일이 이 컴퓨터를 떠날 수 있는지는 보유자의 결정에 달려 있습니다. 보유자가 동의한다면 사이드카를 직접 수정하세요."*
- **잠금.** 아직 로컬 전용이 아닌 파일에 대한 `data mark`는 `--local-only` 또는 `--may-leave`가 필요해요. *"이 파일의 텍스트가 외부 AI 서비스로 전송될 수 있는지는 보유자의 결정 사항이므로, 이를 임의로 가정하지 않습니다."*

각 도구에서 로컬 전용이 의미하는 바는 다음과 같아요:

| 위치 | 동작 |
|---|---|
| 모든 평가(`mt-eval run`, forge 채점) | 정책이 `sealed`(티어 `local-only`)로 확인돼요. 루프백 엔드포인트, 하네스 자체 프로세스 내 어댑터(`local-model`), 또는 `--attest-local-transport`로 실행되는 외부 메서드만 텍스트를 볼 수 있어요 |
| 터미널 및 `--json` 출력 | 문장은 숨겨져요. 대신 줄 번호, id, 개수, 점수가 그 이유를 설명하는 한 줄과 함께 출력돼요 |
| 이를 가공해 만든 파일 | 분할본, 정제본, 가설본, 실행 로그는 텍스트를 유지하며(사용자의 폴더에 위치함) 자체 사이드카에 해당 표시를 이어받아요 |
| 이를 학습한 모델 | 모델의 출력 역시 로컬 전용이 돼요(`forge-model.json` `trained_on.terms`. 기록되지 않은 경우 로컬 전용으로 간주함). `try_translation`는 모델 페이지만 반환하고, 루프백 외부의 `champollion connect`, `mt-eval serve` 및 프로젝트 외부의 `mt-eval translate`에는 `--holders-agreed-by`가 필요하며, `sync`는 `api` 및 `local` 메서드 모두에서 답변을 보류해요([서빙](/docs/agents/serving)) |
| 코칭 파일 또는 사전 | 사이드카가 있는 코칭 파일은 프롬프트에 해당 정책을 적용해요. 사전이 로컬 전용인 경우 어휘집 실행의 출력이 보류돼요 |

**참고.** `--attest-local-transport`는 메서드의 엔드포인트를 로컬로 선언해요. 엔드포인트가 이 컴퓨터에 있는지 확인한 경우에만 전달하세요. 루프백 주소라도 어디로든 전달하는 프록시일 수 있어요.

## 학습

- **잠금.** nmt-forge는 사이드카에 `terms.training: not-allowed`라고 적힌 파일의 학습을 거부해요. 읽을 수 없는 사이드카는 제한이 없는 것이 아니라 제한이 있는 것으로 간주해요.
- **잠금.** `champollion data combine`는 허용되지 않은 파일을 절대 병합하지 않아요. 사이드카와 함께 해당 파일을 `data/not-for-training/`로 이동해요. 보유자가 아직 답변하지 않은 파일—`terms.training` 또는 `terms.speakers_agreed`가 없는 파일(*"말이 담긴 모든 사람이 동의했는지 아직 아무도 말하지 않았습니다. champollion이 다음에 사람들에게 질문할 것입니다. 그 후에 병합하세요"*)—은 거부하며, 병합된 파일은 원본 파일들의 조건 중 가장 엄격한 조건을 이어받아요(하나라도 로컬 전용이면 로컬 전용, 하나라도 허용되지 않음이면 허용되지 않음, 모든 소유자 이름 명시).
- **잠금.** 여정의 조건 단계에서는 사이드카에 `terms.training`와 `terms.speakers_agreed`가 모두 있고(학습 관련 답변은 아래의 도구 주의사항이 아니라 보유자의 답변이어야 함), 그제서야 `data/parallel/`, `data/lexicon/`, `data/grammar/` 또는 `data/monolingual/`에 있는 파일을 답변 완료된 것으로 간주해요. 그때까지는 다시 질문하며 레일은 더 이상 진행되지 않아요.
- **참고.** nmt-forge는 `speakers_agreed`가 아니라 `terms.training`를 읽어요. 하나의 쌍 파일만 있으면 병합 과정이 없으므로 조건 단계에서만 해당 답변을 기다려요. 화자의 답변이 누락된 파일은 절대 학습하지 마세요.
- **잠금.** `test` 또는 `sealed` 파일은 절대 학습에 사용되지 않아요. 해당 파일에는 `--training allowed`가 거부되며, 다른 역할을 부여하는 것도 거부돼요.
- **잠금.** `not-allowed`는 명령을 통해 `allowed`로 변경될 수 없어요(*"보유자가 학습에 동의하면 사이드카를 직접 수정하세요"*). 아래의 한 가지 예외는 제외해요.
- 성경(USFM)은 도구의 주의 표식(`"x-training-default": true`)으로 `terms.training: not-allowed`가 표시된 채 들어와요. 보유자의 답변이 이를 대체해요.

## 누구의 말이며, 누가 동의했는가

`--speakers`는 파일에 누구의 말이 담겨 있는지를 기록하고, `--speakers-agreed`는 그들이 동의했는지 여부를 기록해요.

| `speakers_agreed` | 효과 |
|---|---|
| `yes` | 보유자가 정한 대로 학습해요 |
| `not-yet` | 모두가 동의할 때까지 학습이 `not-allowed`로 강제되며, 파일이 `waiting_for_agreement`에 나타나요 |
| `some-said-no` | 어떤 모델도 이 파일로부터 절대 학습할 수 없어요: *"그분들의 말을 다른 파일로 분리하고 나머지를 표시하세요"* |
| (답변 없음) | 조건 단계에서 계속 질문하며, `data combine`가 파일을 거부해요(위 내용 참조) |

**명령으로 완화할 수 있는 유일한 경우:** `--training allowed`와 함께 `not-yet` → `yes`로 변경하는 경우예요. `combine`가 따로 보관해 두었던 파일이 다음 병합을 위해 `data/parallel/`로 다시 돌아와요.

**참고.** `waiting_for_agreement` 질문은 세션당 한 번씩 정중하게 묻고, 모두가 동의했다는 당사자의 확답이 있을 때만 답변을 입력하세요.

**`--holders-agreed-by "<who>"`**는 로컬 전용 출력이 특정한 장소로 이동하는 데 동의한 데이터 보유자의 이름을 지정해요. 앱의 로캘 파일(`champollion connect`, 쌍의 `holdersAgreed`로 기록됨), 다른 컴퓨터가 접속할 수 있는 주소(`mt-eval serve`, `nmt-forge serve`, `/health`에 보고됨), 또는 프로젝트 외부의 파일(`mt-eval translate`, 사이드카의 `holders_agreed`로 기록됨) 등이 해당돼요. 그 외의 다른 사항은 완화되지 않으며, 출력은 모든 도구에서 로컬 전용으로 유지돼요. **참고.** 상대방이 직접 알려준 이름만 전달하세요.

## 도구가 출력하는 내용과 절대 출력하지 않는 내용

| 도구 | 출력하는 내용 | 절대 출력하지 않는 내용 |
|---|---|---|
| `champollion data add` | 개수, 열(문자, 채움 비율, 평균 길이, 라틴 문자 비율), 쌍의 언어 중 하나를 지정할 때만 표시되는 헤더 셀, 번호별 ELAN 티어, 행 검사가 지정한 행 번호 | 문장, 기타 모든 헤더 셀(대신 길이 표시), ELAN 티어의 id |
| `champollion data mark`, `combine`, `next`, `validate` | 필드, 개수, 상태 | 데이터 파일의 텍스트 — 파일을 절대 열지 않아요 |
| `champollion improve …` | 개수 및 백분율 | 시트의 문장 |
| `champollion sync` (`local` 및 `api` 메서드) | 서버의 `meta.unseen_words`를 기준으로 forge 모델이 학습에서 본 적 없는 단어가 포함된 키 | 텍스트 또는 단어 자체 |
| `nmt-forge`, `mt-eval` | 로컬 전용, 봉인 또는 동의 필요 말뭉치의 경우: id, 줄 번호, 개수, 점수, 오류 메시지 내의 `[sentence withheld]` | 사람이 읽는 출력이나 `--json` 출력의 문장 |
| MCP 레일 도구 | CLI가 출력하는 내용(축약본) | 문장, 로컬 전용 모델의 출력 |

**참고.** `--show-text`(nmt-forge, `mt-eval compare`)는 보류된 문장을 출력해요. 이는 사용자가 자신의 터미널에서 보라고 있는 기능이며 에이전트를 위한 것이 절대 아니에요. 에이전트가 읽는 내용은 모델 제공자에게 전송돼요.

**참고.** 사용자가 파일을 여는 것을 막을 수 있는 도구는 없어요. 커뮤니티의 데이터 파일, 테스트 문장, 단어 목록 또는 시트를 절대 열거나 출력하거나 요약하거나 붙여넣지 마세요. 내보내기의 `input-words.json`도 마찬가지예요. 여기에는 학습 문장의 단어들이 나열되어 있으며, 모델 폴더 내가 아니라 항상 모델 폴더 옆에 위치해요([서빙](/docs/agents/serving#what-an-export-holds)).

**행 검사.** `data add`는 파일(쌍, 테스트 세트 또는 단어 목록)을 가져올 때 사전 없이, 아무것도 제거하지 않고 파일 자체의 두 열을 기준으로 행을 검사해요. 문제 항목의 개수를 세고 행 번호로 명시해요:

- 복사본: 번역이 원문 문장과 동일한 경우(이름이나 외래어는 괜찮지만, 그렇지 않다면 번역이 누락된 것이에요)
- 이전 쌍의 반복
- 파일의 일반적인 비율보다 번역이 훨씬 길거나 짧은 경우(중간에 잘렸거나 한 셀에 두 문장이 들어간 경우)
- 뒤바뀐 것으로 보이는 행: 원문이 파일의 번역문처럼 읽히거나 그 반대인 경우
- 한 행씩 어긋난 것으로 보이는 연속 행: 번역이 다음 행이나 이전 행에 더 잘 맞는 경우 — 숫자, 물음표, 길이가 한 행 차이로 일치하며 단어도 마찬가지예요. 즉, 같은 파일의 나머지 부분에서 두 단어가 얼마나 자주 함께 등장하는지를 바탕으로(더 드문 단어에 더 큰 가중치를 부여하며, 해당 행 자체는 제외함) 한 행의 원문 단어가 번역문의 단어와 얼마나 잘 일치하는지를 살펴봐요. 이는 길이가 모두 비슷해 보이는 템플릿 문장 파일에서 밀림 현상을 찾아내지만, 파일의 단어 수가 너무 적을 때는 큰 도움이 되지 않아요.

유형별로 최대 12개의 행 번호(한 행씩 어긋난 행은 최대 6개 구간)를 출력하며(스프레드시트의 경우 헤더를 포함하여 사용자의 파일에 있는 행 번호 기준), 개수를 사이드카의 `x-import.quality`에 기록해요. 길이, 뒤바뀜, 밀림 검사에는 최소 20개의 쌍이 필요해요. 단어 목록(`--into lexicon`)은 복사본과 반복만 검사해요. **참고.** 행 번호만 전달하세요. 사용자가 자신의 파일에서 해당 행을 직접 확인하고 결정해요. 직접 확인하기 위해 파일을 열어보지 마세요.

**ELAN 파일.** `data add`가 어느 티어가 어느 쪽인지 알 수 없을 때(플래그로 지정되지 않은 쪽으로, 해당 언어로 정확히 하나의 티어만 기록되어 있지 않은 경우), 작업을 거부하고 파일의 순서대로 티어 번호를 나열해요. 다른 티어를 참조하는 티어의 경우 `tier <n> (<language or
"no language">, <count> annotation(s))`, with `, under tier <m>` 형식으로 표시돼요. 해당 번호를 `--source-col` 및 `--target-col`(`champollion data add <file> --source-col <number> --target-col <number>`)로 전달하세요. 사이드카에 이 번호가 기록돼요(`x-import.elan_tiers`). 어떤 티어도 가리키지 않는 번호나 id는 거부되며(`no such tier — … Name a tier by its number`), 기록된 언어가 해당 쪽의 언어와 일치하지 않는 티어도 거부돼요. 두 티어는 한 티어가 다른 티어를 참조하거나 시간대를 공유할 때만 짝지어지며, 절대 추측으로 짝짓지 않아요. **참고.** 티어 id는 파일 제작자가 입력한 내용이며 사람 이름인 경우가 많으므로 `data add`는 이를 절대 출력하지 않아요. 사용자가 정확한 id를 직접 입력할 수는 있지만, 여러분은 번호만 전달하세요.
LIFT 파일은 언어 코드로 일치시키고, Toolbox 파일은 MDF 마커로 일치시켜요(표준상 `\ge`와 `\xe`는 영어예요).

## 전송 모드

모든 평가는 전송 전에 말뭉치의 모드를 하나로 확정하고(`arena/mt_eval_harness/transmission_policy.py`), 이를 실행 로그에 기록해요:

| 모드 | 조건 | 원격 모델 |
|---|---|---|
| `cleared` | 재배포가 허가된 라이선스 | 허용됨 |
| `no-train` | 표준 Creative Commons 비영리 또는 변경금지 라이선스, 또는 라이선스를 명시하지 않은 미등록 말뭉치 | 입력 데이터를 학습하지 않는 채널을 통해서만 허용: `data_collection: deny`로 고정된 OpenRouter, 퍼스트 파티 벤더 API, 또는 로컬. 보관 방지가 아닌 학습 방지 보장 |
| `consent-required` | 수정되었거나 맞춤형이거나 명시되지 않은 라이선스(`LicenseRef-*`) | 데이터셋 항목에 `transmission_consent` 부여(`granted_by`, `date`, `scope`, `evidence`)가 기록될 때까지 거부됨(로컬은 여전히 작동함) |
| `sealed` | 테스트용 격리(held-out) 또는 골드 스탠더드 세그먼트, 격리된 세트, 또는 관리자의 로컬 전용 표시 | 거부됨(재정의 불가) |

- **잠금.** `consent-required` 또는 `sealed` 말뭉치의 텍스트는 터미널에서도 보류돼요.
- `no-train` 말뭉치에 대한 외부 메서드(플러그인)는 거부되지 않고 경고만 표시돼요. 하네스가 플러그인의 채널을 볼 수 없기 때문이에요. `consent-required` 및 `sealed` 말뭉치에서는 `--attest-local-transport`가 아니면 거부돼요.
- **잠금.** 로컬 제공자는 엔드포인트가 루프백 주소(`localhost`, `127.0.0.1`, `::1`, 유닉스 소켓)일 때만 로컬로 간주되며, 이름만 보고 판단하지 않아요.
- **참고.** `transmission_consent` 부여를 임의로 기록하지 말고, 권리자를 대신하여 라이선스를 해석하지 마세요. 권리 부여는 권리자가 동의한 후 데이터셋 관리자가 기록해요.
- **참고.** `--allow-data-collection`는 라이선스를 명시하지 않은 미등록 말뭉치에 대해서만 학습 금지 고정을 해제해요. 이는 호출자가 권리를 보유하고 있음을 선언하는 것이에요. 당사자가 권리를 보유하고 있다고 말한 경우에만 전달하세요.

## 등록 티어

말뭉치 등록은 선택 사항이에요. 레일에는 등록이 꼭 필요하지 않아요. 등록하면 말뭉치 이름을 지정하고 비교하며, 보유자가 원하는 경우 목록에 올릴 수 있도록 메타데이터 카드가 작성돼요. `champollion network register-corpus`는 터미널에서 대화형으로 실행되며 플래그(`--tier`, `--data`, `--license`, `--name`, …)를 사용해 스크립트로 작성할 수도 있어요.
**참고.** 모든 조건과 마찬가지로 티어도 보유자가 결정해요.

| 티어 | 카드 | 텍스트 | 거부하는 작업 |
|---|---|---|---|
| `local-only` (기본값) | `--data` 파일 옆(또는 `--out`, 또는 현재 위치)에 작성되며, 공유 카드 폴더에는 절대 들어가지 않아요 | 이 컴퓨터를 절대 떠나지 않아요. 사이드카에 `transmission: local-only`가 지정돼요 | — |
| `private` | `quarantine: true`가 포함된 메타데이터예요. npm 설치 시 로컬에 유지되며, 목록에 올리는 것은 별도의 요청(`champollion network submit --type dataset`)이에요 | 절대 업로드되지 않아요. 전송 표시 없음 — 라이선스에 따라 모드가 결정돼요 | — |
| `public` | 메타데이터와 원본 가져오기 포인터(`--repo-url`, `--builder`) | 절대 호스팅되지 않아요. 원본에서 직접 가져와요 | 비영리, 변경금지, 제한적이거나 확인되지 않은 라이선스(*"대신 비공개 또는 로컬 전용으로 등록하세요."*), `--data` |
| `sealed` | `quarantine: true` 및 봉인된 블록(`--seal-input`, `--threshold-pubkey`, `--custodian-group`, `--qualifier-id`)이 포함된 메타데이터 | 암호문만 존재하며, `<id>.sealed.json` 또는 `--seal-out`에 작성돼요 | 공개 말뭉치의 바이트 단위 복사본인 파일, `--data` |

모든 티어에서 등록 시 아무것도 업로드되지 않아요(`--json`에 `uploadedContent: false`라고 명시됨). npm 설치 시 발생하는 유일한 네트워크 호출은 파일의 sha256을 이 컴퓨터의 공개 카탈로그와 비교하는 것뿐이에요(해시는 컴퓨터 외부로 절대 나가지 않아요). `CHAMPOLLION_OFFLINE=1`를 사용하면 카드에 비교가 수행되지 않았다고 기록돼요. `--data`를 사용하면 사이드카에 `id`, `name`, `license`, `tier`, `sha256`, `rows`, `card`, `registeredAt`가 기록돼요. **잠금.** 등록된 id는 다시 파생되지 않아요. 다른 id로 파일을 다시 등록하는 것은 거부되며, 변경된 파일(다른 sha256)은 더 이상 카드의 id나 등급을 받지 못해요.

## 출력은 파생물이에요

제한된 문장에 대한 모델의 출력은 해당 문장의 파생물이며, 평가는 이러한 출력을 대규모로 생성해요. 도구는 입력을 다루는 방식 그대로 출력을 다뤄요:

- `cleared`가 아닌 모든 말뭉치에 대해, 실행 시 예측 결과는 제한된 문장의 기계적 파생물이므로 배포해서는 안 된다는 안내문이 기록되고 출력돼요.
- 텍스트가 보류되는 경우(로컬 전용, 봉인, 동의 필요), 이를 기반으로 만들어진 모든 파일(실행 로그, 보고서, 비교, 캐시 항목, `mt-eval translate` 출력, forge의 분할본, 정제된 말뭉치 및 가설본)은 해당 표시가 포함된 set/1 사이드카(`derived_from`, `written_by`)를 받아요. `no-train` 말뭉치는 안내문만 받고 사이드카는 받지 않아요.
- 로컬 전용 텍스트로 학습된 모델은 로컬 전용 출력을 작성해요(위 내용 참조).
- `mt-eval publish`는 `--publish-entries` 옵션을 사용하더라도 로컬 전용 말뭉치의 문장을 절대 업로드하지 않으며, 이러한 말뭉치에 대해서는 코칭된 프롬프트를 기본적으로 해시값으로만 게시해요. 다른 말뭉치의 경우 `--redact-coaching`가 아니면 프롬프트가 게시돼요.

**참고.** 게시는 당사자분들이 결정할 일이며, 미리보기(`--dry-run`)를 먼저 보여드린 후 그분들의 말로 직접 결정해야 해요. 그분들을 대신하여 실행 출력을 게시하거나 붙여넣거나 전송하지 마세요.
