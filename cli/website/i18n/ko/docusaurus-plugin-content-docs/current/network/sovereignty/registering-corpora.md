# 코퍼스 및 노출 레인 등록

> **핵심 요약.** 평가 말뭉치(evaluation corpus)를 네트워크에 등록하여 **데이터를 저희에게 넘기지 않고도** 번역 방식(methods)을 벤치마킹할 수 있어요. 모든 말뭉치는 내용이 아닌 SHA로 고정된 *메타데이터 카드(metadata card)*로 등록되며, 실제 문장들은 평가 시점에 원본 소스에서 가져와요. 등록할 때 두 가지 독립적인 선택을 해야 해요. 하나는 기기 외부로 얼마나 많은 데이터를 내보낼지 결정하는 **노출 계층(exposure tier)**(`local-only`, `private`, `public`, 또는 말뭉치가 기기 내에서 M-of-N 관리자 키로 암호화되는 `sealed`)이고, 다른 하나는 말뭉치의 사용 목적을 제어하는 **라이선스 레인(license lane)**(공개, 비상업적 연구 전용, 또는 비공개)이에요. 이는 커뮤니티가 언어를 *추출 가능(extractable)*하게 만들지 않으면서도 *측정 가능(measurable)*하게 만들 수 있도록 해주는 메커니즘이에요.

기계 번역 평가는 대개 데이터 주권과 정반대되는 것을 요구해요:
"테스트 세트를 업로드하면 그에 대해 채점해 드립니다." 이는
데이터가 그 출처가 되는 사람들의 소유인 원주민 언어 및 기타 커뮤니티 보유
코퍼스에는 받아들일 수 없는 조건이에요. Network는 여러분이 절대 그런
거래를 하지 않아도 되도록 구축되었어요.

---

## 1. 등록은 콘텐츠가 아니라 메타데이터예요 {#1-registration-is-metadata-not-content}

등록된 코퍼스는 하나의 **카드**예요: 코퍼스가 *어디에* 있고 *무엇인지*를
설명하는 작은 JSON 레코드로, 정확한 바이트를 검증할 수 있도록 콘텐츠 해시를
포함하지만 — **문장은 없어요**. 카드에는 다음이 담겨요:

| 필드 | 무엇인지 |
|-------|-----------|
| `url` | 코퍼스를 가져오는 위치(여러분이 관리하는 업스트림 아카이브) |
| `sha256` | 고정된 아카이브의 콘텐츠 해시 — 아무도 데이터를 바꿔치기하지 않았음을 증명 |
| `license` | SPDX 식별자(또는 맞춤형 라이선스의 경우 `LicenseRef-…`) |
| `language_pair` | 소스 → 타깃, 예: `eng-crk` |
| `do_not_train` | 항상 설정됨 — 평가 데이터는 절대 학습에 사용해서는 안 됨 |
| `attribution` | 코퍼스가 표시되는 모든 곳에 나타나는 빌더/언어학자 크레딧 |

평가 시점에 하네스는 **소스에서 가져와서** `sha256`를 검증하고,
새로 가져온 참조에 대해 채점해요. Network는 코퍼스 콘텐츠를 저장하거나 호스팅하거나
재배포하지 않아요. 업스트림 아카이브를 오프라인으로 전환하면
코퍼스는 그냥 실행 불가능해져요 — 통제권은 여러분에게 있어요. 이것은
카탈로그 전체에 적용되는 동일한 소스에서 가져오기 원칙이에요(참조:
[평가 데이터셋](/docs/network/leaderboard/datasets)).

:::info[복사본 대신 해시를 사용하는 이유]
콘텐츠 해시를 사용하면 자체 보고된 점수를 실제의 수정되지 않은
코퍼스에 대해 **다시 검증**할 수 있으며, 저희가 해당 코퍼스를 직접 보유하지 않아도 됩니다. 해시로
고정된 원본과 대조했을 때 수치가 재현되지 않는 실행은 거부돼요. 검증 가능성과
비보유는 여기서 서로 충돌하지 않아요 — 해시가 바로 이 두 가지를 모두 가능하게 만드는 요소예요.
:::

## 2. 두 가지 독립적인 선택

등록 시 두 가지 독립적인 질문을 받게 되며, 이 둘은 서로 다른 것을 보호하므로 구분해서 생각하는 것이 좋아요.

1. **기기 외부로 내보낼 데이터** — *노출 계층(exposure tier)*.

2. **말뭉치의 사용 목적** — *라이선스 레인(license lane)*.

말뭉치는 봉인(sealed)된 비상업적 용도일 수도 있고, 공개되어 상업적으로 자유롭게 사용 가능할 수도 있으며, 그 외의 어떤 조합도 가능해요. 하나의 선택이 다른 선택을 의미하지는 않아요.

### 2a. 노출 계층 — 기기 외부로 내보낼 데이터

`cli/lib/corpus-registration.mjs`에 정의된 네 가지 계층이 있어요. **어떤 계층에서도 평문(plaintext) 말뭉치 내용은 절대 업로드되지 않아요.** 이는 단순한 정책 설정이 아니라 모든 계층에 적용되는 사실이에요. 등록 시 항상 가장 비공개적인 설정이 기본값으로 적용돼요.

| 계층(Tier) | 등록 여부 | 수신 데이터 | 카드 추적 여부 |
|---|:---:|---|:---:|
| **비공개 / 로컬 전용(Private / local-only)** | ❌ | 없음. 카드와 텍스트는 기기에 유지돼요. **기본값이에요.** | ❌ |
| **비공개 등록(Register privately)** | ✅ | 메타데이터만 — WMT 스타일의 비밀 보류 세트(secret held-out set)예요. 데이터 보관 권한은 사용자에게 있으며, 데이터를 노출하지 않고도 결과를 게시할 수 있어요. | ✅ |
| **공개 등록(Register publicly)** | ✅ | 메타데이터 + 소스 가져오기 포인터. 텍스트는 필요할 때 업스트림에서 가져오며, 이곳에 호스팅되지 않아요. 재배포가 허용된 라이선스가 필요해요. | ✅ |
| **봉인(Sealed)** | ✅ | 암호문 + 내용이 없는 카드. 그 외에는 없어요. | ✅ |

**봉인(Sealed)은 시스템이 제공하는 가장 강력한 보장이에요.** 단 1바이트의 데이터가 외부로 나가기 전에, 말뭉치는 **사용자의 기기에서** 관리자 그룹의 임계값 키(threshold key)로 암호화돼요. Champollion은 암호문만 수신하며 이를 해독할 수 없어요. 개별 관리자 역시 단독으로는 해독할 수 없으며, 실행을 승인하려면 전체 N명 중 **M명**이 함께 참여해야 해요. 봉인된 세트는 카탈로그에 등록되지만 격리되며, 봉인된 실행을 제안하기 전에 번역 방식이 반드시 통과해야 하는 공개 *자격(qualifier)* 말뭉치와 짝을 이뤄요. [주권 콘테스트 실행하기(Run a Sovereign Contest)](/docs/network/sovereignty/run-a-sovereign-contest) 및 [주권 평가 노드(Sovereign Eval Node)](/docs/network/sovereignty/sovereign-eval-node)를 참고하세요.

### 2b. 라이선스 레인 — 말뭉치의 사용 목적

이와 별개로, 라이선스는 결과가 표시될 수 있는 위치를 제어해요.

#### 공개(Public)

개방형 라이선스를 가진 코퍼스(예: CC0, CC-BY)로, 그 참조가 공개
영역에 나타날 수 있고 그 실행이 공개 리더보드에 순위가 표시될 수 있어요. 콘텐츠는 여전히
소스에서 가져오며 — "public"은 호스팅이 아니라 *참조와 순위의 노출*을
규율해요. 카탈로그의 대부분(Tatoeba, GlobalVoices, TICO-19, IN22, SMOL, ALT,
Turkic-x-WMT, WMT24++)이 이 레인에 있어요.

#### 비상업적 연구 전용(Non-commercial research-only)

비상업적 라이선스(예: CC BY-NC-SA, 또는 Gamayun 키트의 `LicenseRef-TWB-Gamayun` 같은
맞춤형 커뮤니티/NGO 라이선스)를 가진 코퍼스예요. **연구 목적으로 벤치마킹할 수
있어요** — 메서드가 그 위에서 실행되고 점수가 계산돼요 —
하지만 **모든 상업, 상금, API 경로에서는 배제돼요.** 자격은
코퍼스 기반이 아니라 **사용 기반**이에요:

- **상업 레인은 엄격해요** — 명확하게 상업용으로 라이선스되지 않은 것은 무엇이든
  제외돼요;
- **연구 레인은 관대해요** — 비상업적 코퍼스를 환영해요;
- **격리가 항상 우선해요** — 부적절한 하위 집합으로 표시된(또는
  달리 금지된) 코퍼스는 라이선스와 관계없이 *어떤* 레인에서도 절대 순위에 오를 수 없어요.

이것이 바로 커뮤니티가 자신의 코퍼스를 누군가의 제품에서 배제한 채로
연구 진전을 이끌 수 있게 하는 방식이에요.

#### 비공개(Private)

**자체 채점 실행**을 위해 등록되는 코퍼스로, 참조는 절대
공개되지 않아요. 여러분이 소스를 보유하고, 여러분이 평가를 실행하고, 무엇이든
공개될지 여부를 여러분이 결정해요. private 코퍼스는 나중에 public이나 non-commercial로
전환할 수 있어요 — 노출은 오직 명시적이고 소유자 주도의 결정에 의해서만 *완화*되며,
결코 조용히 이루어지지 않아요.

| 라이선스 레인 | 벤치마크 가능 여부 | 참조 공개 여부 | 공개 게시판 순위 등록 여부 | 상업용 / 상금 / API 경로 포함 여부 |
|------|:---:|:---:|:---:|:---:|
| **공개(Public)** | ✅ | ✅ | ✅ | ✅ (라이선스 허용 시) |
| **비상업적 연구 전용(Non-commercial research-only)** | ✅ | 라이선스에 따라 다름 | 연구 레인 전용 | ❌ |
| **비공개(Private)** | ✅ (사용자 실행) | ❌ | ❌ | ❌ |

:::note[상업적 레인은 사업이 아니라 안전장치예요]
Champollion 자체는 비상업적이에요 — 이 모든 것 뒤에는 유료 API나 제품이
없어요. 상업/상금 레인은 *전방향* 안전장치로 존재해요: 어떤 코퍼스가
상금 또는 상업적 맥락에서 합법적으로 등장할 수 있는지를 기계적으로 기록해서,
누구에 의한 미래의 어떤 사용도 라이선스나 관리자의 조건을 벗어나 표류하지
않도록 해요.
:::

## 3. 주권 보장

등록은 [데이터 관리 입장](/docs/network/sovereignty/data-sovereignty)을 중심으로 설계되었어요.
구체적으로:

- **보유는 소스에 남아요.** 우리는 데이터가 아니라 해시와 URL을 보유해요.
- **통제권은 소유자의 것이에요.** 레인은 소유자의 선택이며, 노출은 오직
  명시적 결정에 의해서만 완화돼요. 업스트림 아카이브를 내리면 실행 가능성이 취소돼요.
- **비상업적은 비상업적을 의미해요.** NC 코퍼스는 상업, 상금, API 레인에서
  기계적으로 배제돼요 — 약속이 아니라 게이트에 의해서요.
- **부적절한 하위 집합은 절대 순위에 오를 수 없어요.** 격리가 라이선스를 무효화하므로,
  순위에서 금지된 코퍼스는 모든 곳에서 금지된 채로 남아요.
- **출처 표시는 필수예요.** 빌더/언어학자 크레딧은 코퍼스가 나타나는 모든
  영역에 카드와 함께 전달돼요.

후원 상금을 위한 메서드 소유권 이전을 포함하여 — 언어별 조건이
어떻게 설정되는지는 [소유권 및 조건](/docs/network/sovereignty/ownership-transfer)을 참조하세요.

## 4. 등록 방법

코퍼스 카드 스키마와 빌드/검증 도구는
[코퍼스 설계 프레임워크](/docs/network/specifications/corpus-design)와
[코퍼스 생성 쿡북](/docs/network/tutorials/corpus-creation)에 문서화되어 있어요. 요약하면:

1. 여러분이 관리하는 어딘가에 코퍼스 아카이브를 호스팅하세요(그것은
   거기에 그대로 남아요 — 절대 Network로 복사되지 않아요).
2. 카드를 작성하세요: `url`, `sha256`, `license`, `language_pair`, `attribution`,
   `do_not_train`.
3. 노출 레인(public / non-commercial / private)을 선택하세요.
4. 카드를 등록하세요. 이제 메서드를 레인의 규칙에 따라 소스에서 가져오기
   방식으로 그 코퍼스에 대해 벤치마킹할 수 있어요.

여러분은 문장을 절대 업로드하지 않아요. 언제든지 중단할 수 있어요.
