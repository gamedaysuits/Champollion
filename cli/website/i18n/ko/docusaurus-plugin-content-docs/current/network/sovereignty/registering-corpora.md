# 코퍼스 및 노출 레인 등록

> **핵심 요약.** 평가 말뭉치를 네트워크에 등록하여 **데이터를 저희에게 넘겨주지 않고도** 여러 방법론을 벤치마크할 수 있어요. 모든 말뭉치는 콘텐츠가 아닌 sha로 고정된 *메타데이터 카드*로 등록되며, 실제 문장은 평가 시점에 해당 소스에서 가져와요. 등록할 때는 두 가지 독립적인 선택을 하게 돼요. 컴퓨터 외부로 나가는 데이터의 범위를 결정하는 **노출 등급(exposure tier)**(말뭉치가 M-of-N 관리인 키로 기기에서 암호화되는 `local-only`, `private`, `public`, 또는 `sealed`)과, 말뭉치의 용도를 규정하는 **라이선스 레인(license lane)**(공개, 비상업적 연구 전용, 또는 비공개)이에요. 이 메커니즘을 통해 커뮤니티는 언어 데이터를 *추출 가능하게* 만들지 않으면서도 *측정 가능하게* 만들 수 있어요.

기계 번역 평가는 대개 데이터 주권과 정반대되는 것을 요구해요:
"테스트 세트를 업로드하면 그에 대해 채점해 드립니다." 이는
데이터가 그 출처가 되는 사람들의 소유인 원주민 언어 및 기타 커뮤니티 보유
코퍼스에는 받아들일 수 없는 조건이에요. Network는 여러분이 절대 그런
거래를 하지 않아도 되도록 구축되었어요.

---

## 1. 등록은 콘텐츠가 아니라 메타데이터예요 {#1-registration-is-metadata-not-content}

등록된 코퍼스는 하나의 **카드**예요: 코퍼스가 *어디에* 있고 *무엇인지*를
설명하는 작은 JSON 레코드로, 정확한 바이트를 검증할 수 있도록 콘텐츠 해시를
포함하지만 — **문장은 없어요**. 카드에는 다음이 담겨요:

| 필드 | 무엇인지 |
|-------|-----------|
| `url` | 코퍼스를 가져오는 위치(여러분이 관리하는 업스트림 아카이브) |
| `sha256` | 고정된 아카이브의 콘텐츠 해시 — 아무도 데이터를 바꿔치기하지 않았음을 증명 |
| `license` | SPDX 식별자(또는 맞춤형 라이선스의 경우 `LicenseRef-…`) |
| `language_pair` | 소스 → 타깃, 예: `eng-crk` |
| `do_not_train` | 항상 설정됨 — 평가 데이터는 절대 학습에 사용해서는 안 됨 |
| `attribution` | 코퍼스가 표시되는 모든 곳에 나타나는 빌더/언어학자 크레딧 |

평가 시점에 하네스는 **소스에서 가져와서** `sha256`를 검증하고,
새로 가져온 참조에 대해 채점해요. Network는 코퍼스 콘텐츠를 저장하거나 호스팅하거나
재배포하지 않아요. 업스트림 아카이브를 오프라인으로 전환하면
코퍼스는 그냥 실행 불가능해져요 — 통제권은 여러분에게 있어요. 이것은
카탈로그 전체에 적용되는 동일한 소스에서 가져오기 원칙이에요(참조:
[평가 데이터셋](/docs/network/leaderboard/datasets)).

:::info[복사본 대신 해시를 사용하는 이유]
콘텐츠 해시를 사용하면 자체 보고된 점수를 실제의 수정되지 않은
코퍼스에 대해 **다시 검증**할 수 있으며, 저희가 해당 코퍼스를 직접 보유하지 않아도 됩니다. 해시로
고정된 원본과 대조했을 때 수치가 재현되지 않는 실행은 거부돼요. 검증 가능성과
비보유는 여기서 서로 충돌하지 않아요 — 해시가 바로 이 두 가지를 모두 가능하게 만드는 요소예요.
:::

## 2. 두 가지 독립된 선택

등록 시에는 두 가지 독립적인 질문을 받게 되며, 보호하는 대상이 서로 다르므로 둘을 구분해서 이해하는 것이 좋아요:

1. **컴퓨터 외부로 나가는 데이터의 범위** — *노출 등급(exposure tier)*.
2. **말뭉치의 사용 용도** — *라이선스 레인(license lane)*.

말뭉치는 봉인(sealed) 상태이면서 비상업적일 수도 있고, 공개 상태이면서 상업적으로 허용될 수도 있으며, 그 밖의 어떤 조합도 가능해요. 한쪽이 다른 쪽을 내포하지는 않아요.

### 2a. 노출 등급 — 컴퓨터 외부로 나가는 데이터의 범위

`cli/lib/corpus-registration.mjs`에 정의된 네 가지 등급이 있어요. **어떤 등급에서도 일반 텍스트(plaintext) 말뭉치 콘텐츠는 절대 업로드되지 않아요** — 이는 정책 설정이 아니라 모든 등급에 동일하게 적용되는 사실이에요. 등록은 항상 가장 비공개적인 등급을 기본값으로 사용해요.

| 등급 | 등록 여부 | 수신되는 정보 | 카드 추적 여부 |
|---|:---:|---|:---:|
| **비공개 / 로컬 전용** | ❌ | 없음. 카드와 텍스트가 사용자의 컴퓨터에 유지돼요. **기본값.** | ❌ |
| **비공개 등록** | ✅ | 메타데이터만 전송 — WMT 스타일의 비밀 홀드아웃 세트. 보관 권한은 사용자가 유지하며, 데이터를 공개하지 않고도 결과를 게시할 수 있어요. | ✅ |
| **공개 등록** | ✅ | 메타데이터 + 소스에서 가져오는(fetch-from-source) 포인터. 텍스트는 필요할 때 업스트림에서 가져오며, 여기에 절대 호스팅되지 않아요. 재배포가 허용된 라이선스가 필요해요. | ✅ |
| **봉인(Sealed)** | ✅ | 콘텐츠가 없는 카드. 암호문은 사용자가 보관해요. | ✅ |

#### 외부 AI 서비스로부터 테스트 세트 격리하기

텍스트를 업로드하지 않는 것은 하나의 보장에 불과해요. 평가 중에 텍스트를 모델 API로 *전송하지 않는 것*은 또 다른 문제이며, 민감한 표현이 포함된 테스트 세트에서는 특히 중요해요. 파일 이름 뒤에 `.champollion.json`이 붙은 작은 파일을 같은 위치에 두어 로컬 전용으로 표시할 수 있어요:

```bash
# data/nurse_checked_test.tsv  →  data/nurse_checked_test.tsv.champollion.json
echo '{"transmission": "local-only"}' > data/nurse_checked_test.tsv.champollion.json
```

이 방식은 모든 말뭉치 형식(TSV, JSONL, 일반 텍스트 쌍, JSON)에서 작동해요. 그 이후부터 `mt-eval run`는 해당 말뭉치를 봉인된 것으로 취급해요:
- 원격 제공업체(OpenRouter, OpenAI, Anthropic, Gemini)의 경우, **텍스트를 전송하기 전**이자 API 키를 요청하기 전에 실행이 거부돼요.
- `--provider local`가 로컬 머신의 모델(`http://localhost:11434/v1`와 같은 루프백 주소)을 가리키는 경우 실행이 진행돼요.
- `--method local-model -m <model>`(평가 하네스가 자체 프로세스에서 로드하는 NLLB, OPUS-MT 또는 MADLAD 모델, `-m` 필요)의 경우 실행이 진행돼요. 어떤 문장도 컴퓨터 외부로 나가지 않으며, 가중치를 다운로드할 때 모델 파일만 이동할 뿐 사용자의 텍스트는 절대 전송되지 않아요.
- MT 엔진이나 메서드 플러그인(`--method <plugin dir>`)의 경우, 전송 방식이 완전히 로컬임을 직접 증명(`--attest-local-transport`, 실행 로그에 기록됨)하지 않는 한 실행이 거부돼요. 플러그인이나 서비스가 텍스트를 어디로 전송하는지 하네스가 확인할 수 없기 때문이에요.
- 언어 카드에 포함된 해당 언어 자체의 평가 메트릭은 **로드되지 않아요**. 이 메트릭은 온라인 사전과 같은 외부 서비스에서 단어를 조회할 수 있는 별도의 패키지에서 제공되기 때문이에요. 실행은 이러한 메트릭 없이 점수가 매겨지며, 실행 카드에는 메트릭이 제외된 사실과 그 이유가 명시돼요.
- `mt-eval publish`는 문장을 제외하며, 기본적으로 코칭 프롬프트나 커스텀 프롬프트를 해당 프롬프트의 sha256으로 대체해요. 따라서 사용자의 문장에서 가져온 프롬프트 예시도 로컬 머신에 안전하게 유지돼요. 점수와 함께 공개되는 말뭉치 메타데이터는 id, 버전, 언어 쌍, 크기, 파일의 sha256, 라이선스 및 출처 표기, 오염도 등급, 로컬 전용 표시 여부, 세그먼트 이름 등 일부 정보뿐이에요. 등록된 데이터세트가 아닌 id의 경우, 게시 시 동일한 id, 언어 쌍, 크기, sha256뿐 아니라 도메인, 세그먼트 이름, 난이도 범위가 포함된 공개 `datasets` 행도 함께 생성돼요. `--dry-run` 미리보기에는 로컬에 남는 정보(모든 문장, 파일 및 해당 경로)와 함께 이러한 항목이 나열돼요. 따라서 다른 사람들은 열어볼 수 없는 테스트 세트에 대한 점수만 보게 돼요. 이는 자체 벤치마크이며 다른 사람은 다시 실행할 수 없고, sha256을 통해 동일한 파일을 보유한 사람만이 해당 파일임을 확인할 수 있어요.
- 도구가 출력하는 내용에는 문장이 제외돼요. 터미널 출력을 읽는 AI 에이전트가 읽은 내용을 모델 제공업체로 전달할 수 있기 때문이에요. `mt-eval compare`는 문장 대신 항목 id와 점수를 표시하며, 문장을 인용하는 오류 메시지가 있는 경우 문장을 제거한 상태로 출력해요. `--show-text`는 터미널 앞에 있는 사용자를 위해 문장을 그대로 출력해요. 결과 폴더에 작성되는 파일에는 텍스트가 유지되며, 각 파일에는 말뭉치 표시가 부여돼요. 하네스가 말뭉치로부터 작성하는 모든 실행 로그, 보고서, 비교 파일 및 대시보드에는 동일한 조건과 `derived_from`가 포함된 자체 `.champollion.json`가 생성돼요. 그러면 다음 도구나 해당 파일에 대한 후속 실행에서도 이를 보호된 것으로 취급해요. 터미널에는 텍스트가 포함된 각 파일의 이름이 표시돼요.
- 번역 캐시는 이 말뭉치의 항목을 별도로 분리하여 보관해요. `<cache-dir>/protected/<namespace>/`(기본값 `eval/cache/harness/protected/…`) 아래에서 실행 설정, 말뭉치의 sha256, 라이선스 조건을 키로 하는 네임스페이스에 저장되므로, 캐시 항목은 오직 동일한 말뭉치에 대한 실행에만 다시 제공되며 다른 말뭉치나 표시가 없는 말뭉치의 실행에는 절대 제공되지 않아요. 해당 위치의 모든 캐시 파일에는 동일한 `.champollion.json` 표시가 적용돼요. (이 보호 기능이 존재하기 전에 캐시된 항목은 일반 캐시에 표시 없이 남아 있으므로, 한 번 `eval/cache/harness/`를 삭제하여 정리하세요.)

이 표시는 말뭉치의 제한을 더 엄격하게만 만들 수 있어요. 어떠한 라이선스나 `--allow-data-collection` 플래그로도 이를 완화할 수 없어요. 마커 파일을 읽을 수 없는 경우, 실행은 이를 무시하지 않고 중단돼요.

**봉인은 시스템이 제공하는 가장 강력한 보안 보장이에요.** 말뭉치는 **사용자의 기기에서** 관리인 그룹의 키로 암호화되며, 암호문은 사용자의 컴퓨터나 평가 노드에 유지돼요. Champollion은 콘텐츠가 없는 카드만 수신해요. 오프라인 노드에서는 키가 분할되어 **N명 중 M명(M of N)**의 관리인이 함께 승인해야만 실행을 진행할 수 있어요. 이 의식(ceremony) 절차는 구현되어 있지만 실제 관리인을 대상으로 사용된 적은 아직 없어요. 봉인된 세트는 카탈로그에 등록되지만 격리되며, 봉인된 실행을 제안하기 전에 방법론이 먼저 통과해야 하는 공개 *자격 검증(qualifier)* 말뭉치와 쌍을 이뤄요. [소버린 콘테스트 실행하기](/docs/network/sovereignty/run-a-sovereign-contest) 및 [소버린 평가 노드](/docs/network/sovereignty/sovereign-eval-node) 문서를 참고하세요.

### 2b. 라이선스 레인 — 말뭉치의 사용 용도

이와 별개로, 라이선스는 결과가 표시될 수 있는 위치를 규정해요.

#### 공개

개방형 라이선스를 가진 코퍼스(예: CC0, CC-BY)로, 그 참조가 공개
영역에 나타날 수 있고 그 실행이 공개 리더보드에 순위가 표시될 수 있어요. 콘텐츠는 여전히
소스에서 가져오며 — "public"은 호스팅이 아니라 *참조와 순위의 노출*을
규율해요. 카탈로그의 대부분(Tatoeba, GlobalVoices, TICO-19, IN22, SMOL, ALT,
Turkic-x-WMT, WMT24++)이 이 레인에 있어요.

#### 비상업적 연구 전용

비상업적 라이선스(예: CC BY-NC-SA, 또는 Gamayun 키트의 `LicenseRef-TWB-Gamayun` 같은
맞춤형 커뮤니티/NGO 라이선스)를 가진 코퍼스예요. **연구 목적으로 벤치마킹할 수
있어요** — 메서드가 그 위에서 실행되고 점수가 계산돼요 —
하지만 **모든 상업, 상금, API 경로에서는 배제돼요.** 자격은
코퍼스 기반이 아니라 **사용 기반**이에요:

- **상업 레인은 엄격해요** — 명확하게 상업용으로 라이선스되지 않은 것은 무엇이든
  제외돼요;
- **연구 레인은 관대해요** — 비상업적 코퍼스를 환영해요;
- **격리가 항상 우선해요** — 부적절한 하위 집합으로 표시된(또는
  달리 금지된) 코퍼스는 라이선스와 관계없이 *어떤* 레인에서도 절대 순위에 오를 수 없어요.

이것이 바로 커뮤니티가 자신의 코퍼스를 누군가의 제품에서 배제한 채로
연구 진전을 이끌 수 있게 하는 방식이에요.

#### 비공개

**자체 채점 실행**을 위해 등록되는 코퍼스로, 참조는 절대
공개되지 않아요. 여러분이 소스를 보유하고, 여러분이 평가를 실행하고, 무엇이든
공개될지 여부를 여러분이 결정해요. private 코퍼스는 나중에 public이나 non-commercial로
전환할 수 있어요 — 노출은 오직 명시적이고 소유자 주도의 결정에 의해서만 *완화*되며,
결코 조용히 이루어지지 않아요.

| 라이선스 레인 | 벤치마크 가능 여부 | 레퍼런스 공개 표시 여부 | 공개 순위표 랭킹 등록 가능 여부 | 상업적 / 상금 / API 경로 포함 여부 |
|------|:---:|:---:|:---:|:---:|
| **공개** | ✅ | ✅ | ✅ | ✅ (라이선스가 허용하는 경우) |
| **비상업적 연구 전용** | ✅ | 라이선스에 따라 다름 | 연구 레인 전용 | ❌ |
| **비공개** | ✅ (사용자 실행만 해당) | ❌ | ❌ | ❌ |

:::note[상업적 레인은 사업이 아니라 안전장치예요]
Champollion 자체는 비상업적이에요 — 이 모든 것 뒤에는 유료 API나 제품이
없어요. 상업/상금 레인은 *전방향* 안전장치로 존재해요: 어떤 코퍼스가
상금 또는 상업적 맥락에서 합법적으로 등장할 수 있는지를 기계적으로 기록해서,
누구에 의한 미래의 어떤 사용도 라이선스나 관리자의 조건을 벗어나 표류하지
않도록 해요.
:::

## 3. 주권 보장

등록은 [데이터 관리 입장](/docs/network/sovereignty/data-sovereignty)을 중심으로 설계되었어요.
구체적으로:

- **보유는 소스에 남아요.** 우리는 데이터가 아니라 해시와 URL을 보유해요.
- **통제권은 소유자의 것이에요.** 레인은 소유자의 선택이며, 노출은 오직
  명시적 결정에 의해서만 완화돼요. 업스트림 아카이브를 내리면 실행 가능성이 취소돼요.
- **비상업적은 비상업적을 의미해요.** NC 코퍼스는 상업, 상금, API 레인에서
  기계적으로 배제돼요 — 약속이 아니라 게이트에 의해서요.
- **부적절한 하위 집합은 절대 순위에 오를 수 없어요.** 격리가 라이선스를 무효화하므로,
  순위에서 금지된 코퍼스는 모든 곳에서 금지된 채로 남아요.
- **출처 표시는 필수예요.** 빌더/언어학자 크레딧은 코퍼스가 나타나는 모든
  영역에 카드와 함께 전달돼요.

후원 상금을 위한 메서드 소유권 이전을 포함하여 — 언어별 조건이
어떻게 설정되는지는 [소유권 및 조건](/docs/network/sovereignty/ownership-transfer)을 참조하세요.

## 4. 등록 방법

코퍼스 카드 스키마와 빌드/검증 도구는
[코퍼스 설계 프레임워크](/docs/network/specifications/corpus-design)와
[코퍼스 생성 쿡북](/docs/network/tutorials/corpus-creation)에 문서화되어 있어요. 요약하면:

1. 여러분이 관리하는 어딘가에 코퍼스 아카이브를 호스팅하세요(그것은
   거기에 그대로 남아요 — 절대 Network로 복사되지 않아요).
2. 카드를 작성하세요: `url`, `sha256`, `license`, `language_pair`, `attribution`,
   `do_not_train`.
3. 노출 레인(public / non-commercial / private)을 선택하세요.
4. 카드를 등록하세요. 이제 메서드를 레인의 규칙에 따라 소스에서 가져오기
   방식으로 그 코퍼스에 대해 벤치마킹할 수 있어요.

여러분은 문장을 절대 업로드하지 않아요. 언제든지 중단할 수 있어요.

### 카드 id

`champollion register-corpus`는 카드를 대신 작성하고 `eval-<source>-<target>-<name>[-<role>]-v1` 형식의 id를 부여해요:

- **name**은 `--name`에서 가져와요. 예컨대 "Ward phrases"는 `ward-phrases`가 돼요. 게시자(publisher)는 이름에 a–z나 0–9 문자가 없는 경우(예: 음절 문자(syllabics)로만 작성된 이름)에만 사용돼요.
- **role**은 데이터세트의 용도를 나타내며, `--role test`, `--role dev` 또는 `--role train` 중 하나예요. 직접 전달한 경우에만 id에 표시돼요. 도구가 역할을 임의로 추측하지 않으므로, 직접 명시한 경우에만 홀드아웃 테스트 세트가 테스트 세트로 지정돼요.

```bash
champollion register-corpus --yes --name "Ward phrases" --pair "eng>xyz" \
  --license proprietary --tier private --role test --size 120 --domain medical
```

이렇게 하면 `eval-eng-xyz-ward-phrases-test-v1`가 등록돼요. id를 직접 지정하려면 `--id eval-…`를 전달하세요. 전달된 그대로 사용돼요.

### 비공개 테스트 세트에 사용할 라이선스 id

`--license`는 데이터를 소유한 사람들이 실제로 허용한 조건을 기록해요. 이는 단순한 플레이스홀더가 아니며 도구가 대신 선택해주지도 않아요. 먼저 소유자(가족, 임상의, 커뮤니티의 데이터 스튜어드 등)에게 문의한 후, 그들의 의사를 반영하는 id를 선택하세요:

| 소유자가 허용하는 조건 | `--license` |
|---|---|
| 이미 표준 라이선스로 텍스트를 공개하고 있는 경우 | 해당 SPDX id(예: `CC-BY-NC-4.0`) |
| 시스템 점수 측정에만 사용: 학습 금지, 재배포 금지, 유료 점수 측정 불가 | `community-eval-grant-nc` (`LicenseRef-Champollion-Eval-Grant-NC`) |
| 위와 동일하지만 유료 사용자를 위한 점수 측정이 허용되는 경우 | `community-eval-grant` (`LicenseRef-Champollion-Eval-Grant`) |
| 소유자 본인 사용 외 권한 부여 없음: 모든 권리 보유(all rights reserved) | `proprietary` (`LicenseRef-Proprietary`) |
| 위 항목 중 어느 것에도 해당하지 않는 독자적인 조건 | `LicenseRef-<a name for their terms>`(그대로 입력) 및 스튜어드가 보관하는 위치에 조건 명시 |

표에 있는 모든 `LicenseRef-…` id(두 가지 평가 권한과 `proprietary` 포함)는 맞춤형 권한 부여(bespoke grant)예요. Champollion은 소유자를 대신해 이를 임의로 해석하지 않아요. 스튜어드가 허가를 기록할 때까지 원격 평가는 거부되므로, 로컬 머신의 모델만 이에 대해 테스트할 수 있어요. 확신이 서지 않는다면 측정이 가능하면서도 가장 보수적인 선택지는 `community-eval-grant-nc`예요. 임시로 기록해 두고 스튜어드의 확인을 받거나 적절한 id를 지정하도록 요청하세요.

라이선스가 문장의 이동 위치를 변경하지는 않아요. 로컬 전용 세트(`.champollion.json` 마커 또는 `--tier local-only`)는 라이선스 내용과 관계없이 항상 로컬 머신에 머물러요. 마커가 모든 원격 모델을 거부하며, 라이선스가 이를 완화할 수는 없어요. 라이선스는 데이터세트가 공유될 경우 타인이 이를 어떻게 사용할 수 있는지, 그리고 어떤 평가 레인에 진입할 수 있는지를 규정해요. 파일이 `--data`로 한 번 등록되면 해당 id가 파일 옆의 `.champollion.json` 파일에 기록되며 절대 변경되지 않아요. 해당 파일을 다시 등록하려고 하면 작업이 중단되고 `--id`로 id를 전달하라는 메시지가 표시돼요.

모델 학습에 사용할 수 있는 테스트 세트(`--role test` 또는 역할이 지정되지 않은 로컬 전용 혹은 비공개 세트)의 경우, 명령어는 해당 세트의 첫 점수 측정 전에 반드시 거쳐야 하는 nmt-forge 단계를 출력해요: 등록, 학습 말뭉치 스크리닝, 예측값 작성이 이에 해당해요. 기준치인 `mt-eval run`는 그 뒤에 나와요. 벤치마크는 점수를 읽는 작업이며, nmt-forge는 점수 측정이 이루어진 후에 작성된 예측값은 거부해요.

`mt-eval run --corpus <that file>`는 동일한 `.champollion.json` 파일을 통해 카드를 찾아요. 실행의 데이터세트 id는 카드의 id가 되므로, 해당 세트에 대한 모든 실행은 동일한 이름을 가지며 파일 이름은 말뭉치 경로로 실행에 유지돼요. 카드의 오염도 등급은 카드에 명시된 대로 보고돼요. 둘 다 등록 당시의 파일과 일치할 때만 적용돼요. 그 후 파일이 변경되었다면 실행 시 이를 알리고 둘 다 사용하지 않아요.

`local-only`, `private` 또는 `sealed` 카드는 해당 텍스트가 미공개(`Contamination: NONE`) 상태임을 명시하므로, 등록 시 먼저 `--data`(또는 `--seal-input`)로 전달한 파일을 공개 말뭉치와 비교해요. 저장소를 체크아웃한 환경에서는 보관 중인 말뭉치 카드와 비교해요. 말뭉치 카드가 포함되지 않는 npm 설치본의 경우 공개 말뭉치 카탈로그와 비교해요. CLI가 공개 말뭉치의 id와 체크섬을 다운로드하여 로컬 머신에서 비교하므로, 파일의 체크섬은 절대 외부로 나가지 않아요. 파일이 공개 말뭉치와 바이트 단위까지 완전히 일치(sha256 동일)하는 경우, 등록이 중단되고 해당 말뭉치 이름이 표시돼요. 이를 공개로 등록하거나, 완전히 비공개인 문장을 사용하거나, 등급을 유지한 채 `--contamination`로 노출 상태를 명시하세요(이 경우 카드에 텍스트가 공개 상태임이 기록돼요). 공개 텍스트로 구성된 봉인 세트는 거부돼요. 아무것도 테스트할 수 없기 때문이에요.

비교를 수행할 수 없는 경우(오프라인 상태이거나 카탈로그에 연결할 수 없는 경우), `--contamination`로 직접 등급을 명시하지 않는 한 카드는 `NONE`가 아닌 `Contamination: UNCHECKED`로 분류돼요. 비교하려면 온라인 상태에서 다시 등록하세요. `mt-eval`는 `UNCHECKED` 말뭉치를 `LOW` 등급을 받지 않은 일반 말뭉치와 동일하게 취급해요. 즉, 해당 점수는 상대 비교 전용(relative-comparison-only) 레인에 들어가요. 이 검사는 전체 파일을 비교하므로, 수정되었거나 서식이 변경된 공개 세트는 인식되지 않아요. `mt-eval contest prepare`는 행 단위로 비교해요.
