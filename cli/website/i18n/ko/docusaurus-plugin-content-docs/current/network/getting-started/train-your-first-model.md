# 첫 모델 학습하기 (에이전트와 함께)

신경망 기계 번역 모델을 학습하는 방법을 알 필요는 없어요. **코딩 에이전트에게 원하는 것을 말할 수 있으면** 돼요 — Claude, Sonnet/Flash급 모델, 또는 셸 명령을 실행할 수 있는 모든 에이전트요. **nmt-forge**는 에이전트가 *기계적으로* 이를 구동할 수 있도록 만들어졌어요. 매 단계마다 도구가 에이전트에게 다음에 무엇을 해야 하는지 정확히 알려주고, 어떤 단계가 결과를 손상시킬 수 있을 때는 — 큰 소리로, 해결책과 함께 — 거부해요.

이 페이지는 전체 루프예요. 각 단계는 **에이전트에게 무엇을 말하는지**, **forge가 무엇을 하는지**, **거부는 어떻게 보이는지**(그래서 거부가 발생했을 때 둘 다 당황하지 않도록 — 거부는 도구가 제대로 작동하는 거예요), 그리고 마지막으로 **보고서를 읽는 방법**으로 작성되어 있어요.

:::tip 에이전트를 위한 한 가지 규칙
에이전트에게 이렇게 말하세요: *"항상 `nmt-forge status --json`를 먼저 실행하고, 매 단계마다 실행해. 그 `next_command`가 말하는 대로 해."* 그 하나의 습관이 forge를 안내 레일로 바꿔줘요. 에이전트가 MCP로 연결된다면, 같은 루프가 `forge_status` 도구예요 — [에이전트 가이드](/docs/network/getting-started/agent-guide)를 참고하세요.
:::

---

## 0단계 — 에이전트를 당신의 언어로 향하게 하기

**당신이 말해요:** *"영어→[당신의 언어] 모델을 학습하고 싶어. forge가 그것에 대해 무엇을 알고 있는지 발견하는 것부터 시작해. ISO 639-3 코드는 `crk`야"* (당신 언어의 코드를 사용하세요).

**forge가 해요:** `nmt-forge discover crk`가 그 언어의 카드를 읽어요 — 문자 체계, 사전, 형태소 분석기, 기존 코퍼스와 평가 세트(`do_not_train` / 격리 플래그와 함께), 그리고 언어별 심판 지표를 읽어요. 그리고 당신의 언어를 **자산 사다리**에 배치해요: (1) 병렬 텍스트 → 가드가 있는 학습; (2) + 단일 언어 → 태깅된 역번역; (3) + 사전/문법 → 인용된 합성 데이터; (4) + 분석기 → 왕복 검증된 합성; (5) + 심판 지표 → 채점과 체크포인트 선택에서 그 언어 자체의 지표.

**빈 필드는 0이 아니라 UNKNOWN을 의미해요.** 카드가 비어 있다는 것은 "이 언어에 아무것도 없다"는 뜻이 아니에요 — 단지 아직 그 리소스를 기록하지 않았을 수 있어요. 언제든지 자신의 병렬 코퍼스를 가져올 수 있어요.

그런 다음: *"프로젝트를 스캐폴딩해."* → `nmt-forge init crk`가 작업 공간, 시작용 설정, 그리고 `NEXT_STEPS` 브리프를 작성해요.

## 1단계 — 부정행위를 할 수 없는 분할 만들기

**당신이 말해요:** *"여기 내 병렬 코퍼스 `corpus.jsonl`가 있어. 이것을 train/dev/test로 분할하고 dev와 test 세트를 등록해."*

**forge가 해요:** `nmt-forge split corpus.jsonl --test 200 --dev 100 --seed 7
--out data/splits --register mypair`. 이것은 **그룹 분리** 분할을 만들어요: 소스 *또는* 타겟을 공유하는 두 문장 쌍은 **같은** 쪽에 놓여요. 이것은 저자원 점수가 부풀려지는 가장 흔한 방법이에요 — 교과서는 많은 영어 연습 문제를 하나의 타겟 단어로 매핑하고, 순진한 무작위 분할은 한 복사본을 train에, 그 쌍둥이를 test에 넣게 되며, 모델은 암기한 답을 "번역"해요.

**거부는 어떻게 보이는지:** 직접 만든 분할을 forge에 건넸는데 그것이 분리되지 않았다면, `verify-split`는 공유된 키의 이름과 함께 충돌해요 — *"이 행들은 train과 test 전체에서 정규화된 타겟을 공유합니다."* 해결책: forge가 분할을 하도록 하세요.

---

## 2단계 — 누출 검사하기

**당신이 말해요:** *"학습하기 전에, 평가 세트에 대해 학습 코퍼스의 누출을 확인해."*

**forge가 해요:** `nmt-forge leak-audit corpus.jsonl`. 이것은 당신의 코퍼스를 등록된 모든 dev/test/sealed 세트에 대해 검사해요:

- **타겟 측 정확한 또는 근접 중복**(참조 답이 학습 데이터에 있음) → **치명적**. 이것은 답 누출이에요.
- **타겟이 *다른* 소스 측 근접 중복** → **정보성, 유지됨**. 같은 프롬프트에 다른 번역은 정당한 최소 대조 쌍이지, 누출이 아니에요 — forge는 이것을 보고하지만 절대 삭제하지 않아요. (이 구별은 우리가 자체 사용으로 잡아낸 실제 버그였어요: 이전 버전은 진짜 누출이 17개뿐인데 44개 행을 치명적으로 표시했어요.)

**거부는 어떻게 보이는지:** *"row 118: test 세트 `mypair-test`의 타겟 측 근접 중복 (Jaccard 0.83) — 답 누출."* 해결책: 에이전트가 `nmt-forge leak-audit corpus.jsonl --clean-to corpus.clean.jsonl`를 실행하고 살아남은 것들로 학습해요.

## 3단계 — 엿보기 전에 예측하기

**당신이 말해요:** *"모델이 무엇을 할 것으로 기대하는지 적어두고, 그다음 학습하자."*

**forge가 해요:** `nmt-forge prereg new p1 --eval-set mypair-test --predictions
predictions.md`. 당신(또는 에이전트가 소리 내어)은 어떤 테스트 점수가 존재하기 **전에** 반증 가능한 예측 — 어떤 지표를, 어느 방향으로, 얼마나 크게 — 을 커밋해요.

**거부는 어떻게 보이는지:** 에이전트가 사전 등록 없이 test 세트를 채점하려고 하면, `score`가 거부해요: *"test 세트 채점은 첫 채점 읽기보다 앞선 사전 등록 없이는 거부됩니다."* 이것이 결과와 결과 우선 스토리텔링을 구분하는 것이에요. 해결책: 먼저 사전 등록하세요.

:::info 이것이 왜 추가 작업처럼 느껴지는지
그것이 바로 작업이에요. 여기 있는 모든 가드는 실제 연구자들을 속인 실수예요. 이 도구는 정직한 길을 쉬운 길로 만들고, 부정직한 길을 당신을 멈추게 하는 길로 만들어요.
:::

## 4단계 — 게이트를 확인한 다음, 학습하기

**당신이 말해요:** *"학습 실행이 모든 검사를 통과할까? 그렇다면 학습해."*

**forge가 해요:** `nmt-forge preflight run`는 실행이 마주칠 모든 게이트를 나열해요 — dev 펜스 존재, 누출 감사 통과, 스케줄 하한 도출, 디코드 여유 확인 — 각각 ✓ 또는 ✗와 해결책과 함께요. 모두 초록색일 때: `nmt-forge run config.json`.

학습은 즉각적인 도구 호출이 **아닌** 유일한 단계예요 — GPU를 사용하고 몇 분에서 몇 시간이 걸려요. 에이전트는 터미널에서 이것을 실행하고 `[schedule-sanity]` 라인을 지켜봐요. forge는 데이터 믹스로부터 조기 종료 **하한**을 도출하기 때문에, 합성 데이터가 많은 실행이 실제 dev 손실이 흔들릴 때 반 에폭에서 죽지 않아요 (실제 실패 모드예요 — [학습 실행 진단하기](/docs/network/getting-started/diagnosing-training)를 참고하세요).

학습이 끝나면, forge는 **펜스된 dev 세트에서 체크포인트를 선택**했고(절대 test 세트에서가 아니에요) `run-manifest.json`를 작성했어요.

---

## 5단계 — 루프 닫기: 평가하고 진단하기

**당신이 말해요:** *"모델을 test 배터리에서 채점하고 무엇을 개선할지 알려줘."*

**forge가 해요:** `nmt-forge evaluate .forge/runs/<run>/run-manifest.json --config
config.json`. 이것은 하나의 명령으로 **루프를 닫아요**: 실행이 선택한 체크포인트로 test 배터리를 디코드하고, 채점하며(사전 등록 게이트 적용, 모든 수치에 95% 신뢰 구간과 함께), 평이한 언어로 된 **진단 및 권장 사항** 섹션을 추가해요. (이 명령이 존재하기 전에는, 체크포인트를 심링크하고 디코더를 손으로 실행해야 했어요 — 바로 초보자가 길을 잃는 지점이었어요.)

### battery-lint 보고서 읽는 방법

보고서는 **레지스터별**(교과서, 정부, 구술 이야기, …) 점수 테이블로, 각각 신뢰 구간과 함께 있고, 그 뒤에 진단이 이어져요. 진단은 당신의 **가장 약한 레지스터**의 이름을 밝히고, 각각에 대해 가장 가능성 있는 원인과 다음에 당길 **레버**를 알려줘요:

| 진단이 …라고 말하면 | 그것은 …을 의미해요 | 레버 |
|---|---|---|
| `R1-vocabulary-gap` | 레지스터 점수가 낮고 **그리고** 출력이 미완성이에요; 모델에 단어가 부족해요 | **VOCABULARY** — 어휘를 늘린 다음, 퍼널을 다시 확인하세요 |
| `R2-structure-gap` | 단어는 알지만 문장 *형태*를 몰라요 | **STRUCTURE** — 누락된 구문을 추가하세요 (템플릿/컴포지터) |
| `R3-mixed-convention` | 출력이 철자를 섞어요 | **ORTHOGRAPHY** — 코퍼스를 하나의 관례로 정규화하고, 다시 학습하세요 |
| `R4-optimism-bound` | "전체" 점수가 근접 쌍둥이 평가 행으로 부풀려졌어요 | **MEASUREMENT** — 일반화를 위해 엄격한 점수를 인용하세요 |
| `R5-low-power` | 신뢰 구간이 넓어요 | **MEASUREMENT** — CI보다 작은 델타에 대해 행동하지 마세요; 평가 세트를 늘리세요 |
| `R7-transfer-plateau` | 합성 데이터에서는 훌륭하지만, 실제 텍스트에서는 정체됐어요 | **REAL-DATA** — 단일 언어 데이터를 역번역하거나 실제 병렬 문장을 확보하세요 |

각 발견 사항은 그것이 발생한 증거를 담고 있어요. `--json` 발견 사항에 대해서는 에이전트가 프로그래밍 방식으로 행동할 수 있어요: `nmt-forge lint <battery-manifest.json>`.

## 방금 당신이 한 일

당신은 점수를 실제로 믿을 수 있는 모델을 학습했어요: 누출된 답이 없고, test 세트를 엿보지 않고 선택한 체크포인트, 모든 수치의 오차 막대, 결과 전에 작성한 예측, 그리고 추측하도록 두지 않고 다음 레버의 이름을 밝혀주는 진단이 있어요. 그것이 바로 요점이에요 — **정직한 결과가 기본값이고, 거기 도달하는 데 MT 전문 지식이 필요하지 않았어요.**

수치가 실망스러울 때(처음에는 그럴 거예요), [학습 실행 진단하기](/docs/network/getting-started/diagnosing-training)로 가세요 — 증상 우선으로, 바로 그 순간을 위해 작성되었어요.
