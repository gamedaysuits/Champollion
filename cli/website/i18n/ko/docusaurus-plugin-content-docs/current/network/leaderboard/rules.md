# MT 평가

> **요약.** 이 페이지에서는 리더보드 제출 기준, 점수 산정(주요 지표인 chrF++와 함께 제공되는 표준 지표 및 진단 지표), 어뷰징 방지 정책, 검증 등급, 제출 워크플로를 정의해요. 평가 데이터에 노출된 방식(method)은 자격이 박탈돼요.

champollion에는 번역 방법의 **재현 가능한 벤치마킹**을 위해 설계된 기계 번역 평가 프레임워크가 포함되어 있어요 — 특히 표준 MT 벤치마크가 존재하지 않고 품질 주장을 검증하기 어려운 저자원 및 원주민 언어를 위한 것이에요.

---

## 리더보드

핵심은 **[방식 리더보드(Method Leaderboard)](https://champollion.dev/leaderboard)**예요. 연구자와 커뮤니티 구성원이 핑거프린팅된 재현 가능한 평가를 통해 번역 방식을 제출하고 비교할 수 있는 공개 스코어보드로, 현재 실시간으로 **제출을 받고 있어요**.

모든 제출에는 다음이 포함돼요:

- **핑거프린트된 파이프라인** — 특정 Git 커밋 및 설정 해시와 연결되어, 결과를 생성한 정확한 코드까지 역추적할 수 있어요
- **버전 관리되는 데이터셋** — 콘텐츠 해시 및 버전이 관리되며, 점수는 동일한 데이터셋 버전 내에서만 비교할 수 있어요
- **표준화된 지표** — 모든 점수 산정은 공유 평가 하네스(evaluation harness)로 계산되어 구현 차이를 없애요
- **신뢰 등급** — 자체 벤치마크(self-benchmarked), Champollion 인증(Champollion Verified), 커뮤니티 검증(Community Validated)
- **비용 추적** — 제출당 API 비용을 추적하여 비용 대 품질 간의 트레이드오프가 투명해요

리더보드는 WMT, FLORES-200, AmericasNLP 공유 태스크가 MT(기계 번역) 평가를 보고하는 방식에 따라 실행 결과를 순위 매겨요. **단일 표준 지표인 chrF++**를 기준으로 하며, 95% 신뢰 구간 및 sacreBLEU 시그니처(예: `chrF++ 47.5 [45.9, 49.0]`)와 함께 표시돼요. 다른 모든 지표는 그 옆에 나란히 표시되며, 결코 chrF++에 혼합되지 않아요.

| 지표 | 역할 | 측정 대상 |
|--------|------|------------------|
| **chrF++** | **주요 및 순위 지표** | 참조 번역에 대한 문자 n-그램 F-스코어(sacreBLEU, `word_order=2`). 단어 수준 지표보다 풍부한 형태론적 언어를 더 잘 다뤄요 |
| **BLEU, spBLEU, TER, COMET** | 표준 지표, 주요 지표 옆에 표시 | MT 논문에서 보고하는 기타 지표. COMET은 계산된 경우 모델 ID와 함께 표시돼요 |
| **Exact Match** | 진단 | 번역이 참조 번역과 정확히 일치하는 빈도예요 |
| **FST Acceptance** | 진단 | 유한 상태 전이 변환기(FST)가 있는 언어의 경우, 출력 단어 중 유효한 형태의 비율이에요. 소스나 참조 번역과 비교하지 않으므로 점수로 취급되지 않아요 |
| **Equivalent Match** | 진단 | 참조 번역 또는 허용 가능한 변형(어순, 철자 규칙)과 일치하는 비율이에요. 현재 CRK에 적용 중이며, 일반화 작업 중이에요. |
| **Semantic Score** | 진단 | 결정론적 검증기를 통한 의미 보존율이에요. 현재 CRK에 적용 중이며, 일반화 작업 중이에요. |
| **점수 주의 사항** | 주요 지표 옆에 표시 | 출력이 소스를 그대로 복사했거나, 참조 번역보다 훨씬 짧거나 길거나, 여러 입력에 대해 하나의 출력을 반복하거나, 테스트 행이 학습 데이터에 쌍둥이처럼 존재하는 경우예요 |

한 실행이 다른 실행보다 더 나은지는 두 숫자의 순서가 아니라 chrF++에 대한 대응 유의성 검정(paired significance test)으로 결정돼요. 구간이 겹치면 순서가 단순 노이즈일 수 있다는 경고예요([통계적 유의성 검정](/docs/network/specifications/significance)). 대회 순위는 이 검정을 사용하여 순위 클러스터를 형성해요. chrF++는 동일한 데이터셋 내에서만 시스템 순위를 매기며, 언어 간에는 절대 비교하지 않아요. 어떤 자동 점수도 품질 라벨을 갖지 않으며, 화자의 인적 검토만이 품질을 보증해요. 이전에 사용되던 가중 종합 점수 및 품질 등급은 폐지되었으며, 이전 카드의 종합 점수는 표시되더라도 "legacy composite (retired)"로 표시돼요.

:::info[전체 지표 제품군]
[점수 산정 사양](/docs/network/specifications/scoring#how-runs-are-scored)에서는 실행 점수 산정 방식과 전체 지표 목록(표층, 구조, 의미, 행동, 규정 준수, 보고된 비교 지표의 6가지 카테고리)을 정의해요.
:::

## 사용 가능한 데이터셋

실행에 대해 점수를 산정할 수 있는 항목은 도구에 나열되어 있으므로, 이 페이지에서는 별도의 목록을 유지하지 않아요.

```bash
# the runnable corpora for a pair: size, contamination, domain, licence, provider
mt-eval corpora --source eng --target crk

# …and the catalogued ones that can never run, each with its reason
mt-eval corpora --source eng --target crk --include-quarantined
```

[평가 데이터셋](/docs/network/leaderboard/datasets) 페이지에서는 카탈로그, 말뭉치(corpus) 형식, 난이도 등급, 라이선스 트랙(licence lane), 자체 데이터셋 생성 방법을 설명해요. 해당 카탈로그의 세 가지 규칙이 순위에 오를 수 있는 대상을 결정해요.

- **격리된(quarantined) 말뭉치는 절대 순위에 오르지 않아요.** 카탈로그에는 포함되지만 절대 실행할 수 없으며, 데이터베이스는 이에 대해 등록된 점수를 거부해요. EdTeKLA의 영어→플레인스 크리어 말뭉치(`eval-eng-crk-edtekla-dev-v1` 및 `eval-eng-crk-edtekla-textbook`)는 격리되어 있어요. 이 말뭉치는 수정된 주권 범위의 CC BY-NC-SA(`LicenseRef-EdTeKLA-Modified-CC-BY-NC-SA-4.0`)를 따르며, 모든 리더보드, 상금 및 상업적 트랙에서 제외돼요.
- **오염된 말뭉치는 상대 순위로만 매겨져요.** FLORES+ 및 오염도 등급이 `HIGH` 또는 `MEDIUM`로 평가되었거나 등급이 전혀 매겨지지 않은 모든 말뭉치는 실행 카드에 상대 비교 전용(relative-comparison-only)으로 스탬프가 찍혀요. 해당 말뭉치에서 실행된 방식들을 비교할 뿐이며, 절대적인 품질로는 절대 보고되지 않아요. `LOW` 등급을 받은 말뭉치만이 절대 품질로 순위를 매겨요.
- **라이선스 트랙이 유지돼요.** 비상업용 말뭉치는 상업 및 상금 경로에서 제외돼요. 수정되었거나 맞춤형이거나 명시되지 않은 허가 조건의 말뭉치는 권리 보유자의 허가가 해당 항목에 기록될 때까지 원격 모델 API 평가를 거부해요.

**대회는 주최 측이 보관하는 봉인된 세트에서 진행돼요.** 대회는 이러한 공개 말뭉치로 점수를 매기지 않아요. 주최 측(커뮤니티 또는 조직)은 자체 인프라에 봉인된 보류 테스트 세트(held-out test set)를 보관해요. 참가자는 주최 측이 공개한 공개 dev 세트에서 자격을 얻은 후, 실행할 모델이나 방식을 주최 측 노드에 전달해요. 주최 측 관리자가 각 실행을 승인하며 점수만 외부로 출력돼요. [주권 대회 운영하기](/docs/network/sovereignty/run-a-sovereign-contest)를 참고하세요.

:::danger[평가 데이터로 학습하지 마세요]

**이 데이터셋은 평가 전용이에요.** 평가 데이터로 학습, 미세 조정, few-shot 프롬프트, 또는 그 외 방식으로 노출된 방법은 인위적으로 부풀려진 점수를 만들며 **리더보드에서 실격 처리돼요.**

이것은 제안이 아니에요 — 평가 무결성의 가장 중요한 단일 규칙이에요. 학습에는 별도의 코퍼스를 사용하세요. 평가 세트는 개발 중 모델에 노출되지 않은 상태로 유지되어야 해요.

코칭 데이터나 few-shot 예제를 사용하는 경우, 그것들은 **완전히 별개의 출처**에서 나와야 해요. 확신이 없다면 포함하지 마세요.
:::

:::warning[LLM 비결정성]

LLM 출력은 비결정적이에요. 점수는 특정 모델 버전과 API 구성 하에서의 특정 시점 측정치를 나타내요. 모델 제공자는 언제든지 가중치, 디코딩 전략, 안전 필터를 업데이트할 수 있으며, 이는 실행 간 점수 편차를 유발할 수 있어요. 리더보드는 모든 제출에 대해 정확한 모델 slug와 타임스탬프를 기록해요.
:::

## 좋은 방법을 만드는 요소

모든 방법이 동등하게 만들어지는 것은 아니에요. 엄밀한 작업과 부풀려진 점수를 구분하는 것이 여기 있어요.

### 강력한 방법의 특성

- **학습 데이터와 평가 데이터의 명확한 분리** — 개발, 튜닝, 프롬프트 엔지니어링, few-shot 예제 선택 중에 방법이 평가 세트를 한 번도 본 적이 없어요
- **재현 가능** — 다른 사람이 저장소를 복제하고 하네스를 실행해 동일한 점수를 얻을 수 있어요 (LLM 비결정성 범위 내에서)
- **문서화** — [방법 카드](/docs/network/specifications/methods)가 방법이 무엇을 하고, 어떤 도구를 사용하며, 어떤 한계가 있는지 설명해요
- **범위에 대한 정직성** — 방법이 한 언어 쌍에만 작동한다면 그렇게 말하세요; 특정 형태론 패턴에서 성능이 저하된다면 그것을 문서화하세요
- **커뮤니티 인식** — 원주민 언어의 경우, 방법이 데이터 주권을 존중해요. 언어 커뮤니티와 상의했거나 공개 라이선스 데이터만 사용했어요

### 위험 신호 (실격되는 것들)

| 위험 신호 | 왜 문제인가 |
|----------|--------------------|
| 평가 데이터로 학습 | 평가의 목적을 완전히 무너뜨려요. 부풀려진 점수는 모두를 오도해요. |
| 결과 체리피킹 | 10번 실행하고 나머지를 공개하지 않은 채 최고 실행만 제출 |
| 공개되지 않은 후처리 | 채점 전에 출력을 수동으로 수정 |
| 오염된 코칭 데이터 | 평가 세트 예제를 few-shot 프롬프트나 사전 항목으로 사용 |
| 출처 없이 상업적 준비 완료 주장 | 방법이 CC BY-NC-SA 데이터를 사용한다면 상업적으로 준비되지 않은 것이에요 |

### 검증 등급

검증 등급은 **누가 결과를 검증했는지**를 나타내요. 품질 라벨이 아니에요(이전의 자동 품질 등급은 [폐지되었어요](/docs/network/specifications/scoring#5-quality-tiers)).

| 등급 | 의미 | 획득 방법 |
|------|---------|--------------|
| **Self-benchmarked** | 하네스를 직접 실행하고 결과를 제출한 경우예요 | `mt-eval publish` 명령어로 실행 카드를 발행하세요 |
| **Champollion Verified** | 프로젝트에서 제출된 출력을 sha 고정 참조 말뭉치와 독립적으로 다시 채점하여 점수를 재현한 경우예요 | 재채점기(re-scorer)는 메인테이너 도구이며 수동 배치로 실행돼요. 스케줄링되지 않으므로 제출 즉시 재채점되는 제출물은 없어요(아래 참고) |
| **Community Validated** | 커뮤니티 자체 프로토콜에 따라 자격을 갖춘 대상 언어의 이중언어 구사자가 출력물의 층화 표본(≥30개 항목, ≥2명 검토자)을 검토하여 ≥70%가 커뮤니티 기준을 충족한 경우예요. 커뮤니티 자체 테스트를 통해서만 부여되며, 불시 감사를 통한 등급 강등도 동일하게 적용돼요 | 방식 코드를 거버넌스 조직에 제출하세요. 조직에서 이를 골드 표준 세트에 대해 실행하고 출력물을 커뮤니티 검토에 회부해요 |

**커뮤니티 검증 평가는 별도의 트랙이며, 아직 인적 평가 점수는 존재하지 않아요.** 하네스는 마감된 대회의 동결된 순위에서 정해진 인적 검토 예산으로 처리할 수 있는 시스템을 선택할 수 있지만(전체 동점 그룹 단위로만 선택 — 클러스터가 중간에 잘리지 않음), 평가 점수를 기록하지는 않으며 현재 리더보드에는 인적 판단이 반영된 항목이 없어요.

**순위는 엄격한 일렬 순서가 아니라 클러스터예요.** 유의성 검정에서 구분할 수 없는 인접 항목들은 순위를 공유하며 순위 *범위*를 갖게 돼요. 세그먼트별 출력이 주최자의 머신 외부로 절대 나가지 않는 봉인된 대회에서는 대응 검정이 해당 머신에서 실행되어 서명된 판정 결과만 외부로 출력돼요. 이러한 서명이 없으면 신뢰 구간이나 점 추정치 일치 근거에 의존해 동점을 판정해요. 이것이 어떻게 작동하는지, 그리고 증거 사다리의 각 단계가 얼마나 약한지는 [통계적 유의성 검정 → 순위 클러스터](/docs/network/specifications/significance#ranking-clusters)에 명시되어 있어요.

### 검증 확장 방식: 평판 가중치 감사

**우리는 출처(provenance)를 입증한다고 주장하지 않아요.** 리더보드 행은 기여자가 *자신의* 머신에서 *오픈 소스* 하네스를 실행하여 생성돼요. "이 실행이 실제로 하네스를 통해 나왔다"는 것은 자체 호스팅 연산에 대해 서버가 검증할 수 있는 영역이 아니에요. 하네스의 서명 키는 기여자의 손에 있으므로, 서명은 *정직함이 아니라 머신을 인증*할 뿐이에요. 그렇지 않은 척하기보다는, **여기서의 유효성은 획득되며 자정 작용을 거쳐요**. 특정 행이 신뢰할 수 있는 이유는 점수가 **재현 가능**하고, 기여자가 **적발 시 파멸을 초래할 평판을 걸었기 때문**이에요. 검증은 4개 계층으로 실행되어 철저해야 할 곳에서는 철저하고 저렴해야 할 곳에서는 저렴하게 운영돼요. 따라서 프로젝트가 모든 사람의 작업을 다시 실행할 필요가 없어요.

- **L0 — 전체 재채점 (무료, 약 100%).** 재채점기는 하네스가 사용하는 것과 동일한 지표를 사용하여 **sha 고정 참조 말뭉치**(기여자가 로컬에 저장한 복사본이 아님)를 바탕으로 *제출된 출력물*에서 점수를 다시 산출해요. 점수가 출력물에서 재현되지 않거나 저장된 참조가 변경된 경우 해당 실행은 **자격이 박탈돼요**. 이것만으로도 직접 타이핑하거나 편집한 점수를 걸러낼 수 있어요. 재현된 실행은 대회 순위에서 기본으로 사용되며 상금을 받을 수 있는 유일한 등급인 **Champollion Verified**로 승격돼요. 이 기능은 구축되어 있고 비용도 적게 들지만, **수동으로 실행되는 메인테이너 명령**이에요. 제출 시 자동으로 실행되지 않으며 스케줄링되지도 않아요. 변경되기 전까지는 모든 행이 자체 벤치마크 상태로 등록되고 유지돼요.
- **L1 — 기여자 평판 사다리.** 각 기여자(로그인으로 식별됨)는 아래의 심층 검사를 통과해야만 평판을 얻을 수 있어요. 제출량만으로는 평판을 얻을 수 없으므로 새 계정을 대량 생성해도 아무런 이득이 없어요. 평판은 **공개**되며, 비용이 많이 드는 검사가 얼마나 자주 실행될지를 결정해요.
- **L2 — *표본* 재실행 (비용이 많이 드는 검사; 정책만 존재하며 아직 재실행기 없음).** *공개* 개발 세트의 경우, 참조 번역을 단순히 자신의 "번역"으로 복사한 기여자를 L0로는 잡아낼 수 없어요. 이를 적발하려면 실제로 모델을 재실행(실제 컴퓨팅 리소스 소모)해야 하므로 모든 사람이 아닌 **표본**에 대해서만 진행해요. **표본 추출 정책**은 구축 및 테스트를 마쳤어요. 실행은 **중요도**(전체 어족으로 향하는 최초의 가교 역할을 하는 실행은 *항상* 선택됨)가 높을수록, **이상 징후**(이전 최고 기록 대비 믿기 힘들 정도의 급상승은 *항상* 선택됨)가 클수록 선택 확률이 높아지고, **평판**(많은 감사를 통과한 기여자는 드물게 불시 점검을 받으며, 신규 또는 익명 제출자는 신뢰를 얻을 때까지 모든 실행마다 점검을 받음)이 높을수록 선택 확률이 낮아져요. L2 감사를 통과하면 평판이 올라가요. **이 정책을 실행할 재실행기(re-runner)는 아직 존재하지 않으므로** 지금까지 L2 감사가 실행된 적은 없어요. 선택된 실행은 *L2 보류(L2-pending)*로 기록돼요.
- **L3 — 교차 입증 (무료 검증).** 두 명의 *독립적인* 기여자가 동일한 말뭉치에서 동일한 모델을 실행하고 재채점된 출력이 **일치**할 때, 그 일치 자체가 검증이 되며 두 사람의 평판이 모두 올라가요. 진정한 **불일치**가 발생하면 두 실행 모두 L2 감사 대상으로 플래그가 지정돼요. 재현은 불필요한 중복으로 취급되는 대신 보상을 받아요.

**적발된 조작 한 건은 논문 철회처럼 치명적이에요.** 입증된 조작은 기여자의 평판을 0으로 만들고, **인증된 전체 이력을 재감사**(인증된 모든 실행이 다시 검증 절차로 회부됨)하며 감사 로그에 **공개적으로** 기록돼요. 가벼운 샘플링이 안전한 이유가 바로 여기에 있어요. 공개 dev 세트를 속이는 것은 한 번쯤 넘어갈 수 있을지 몰라도, 그로 인한 기대 비용(얻은 모든 신뢰를 잃고 전체 기록이 다시 정밀 조사를 받는 것)을 고려하면 승산 없는 도박이기 때문이에요. 이 규칙은 메인테이너 자신의 실행에도 동일하게 적용돼요.

**그럼에도 기여할 가치가 있는 이유.** 기여자는 항상 비용이 많이 드는 부분(방식 실행)을 부담하고, 프로젝트는 모든 사람에 대한 무료 L0 재채점과 신규 참여자 및 중요도가 높은 실행에는 높고 검증된 기여자에게는 낮은 *점점 줄어드는 표본*에 대한 L2 재실행 비용만 부담해요. 검증 비용은 매번 전부 지불되는 것이 아니라 *평판을 통해 분할 상환되고 교차 입증을 통해 공유*돼요.

## 제출 방법

1. **방식 구축하기** — 방식 인터페이스에 대해서는 [방식 구축하기](/docs/network/specifications/methods)를 참고하세요
2. **하네스 실행하기** — 설정 및 사용법은 [평가 하네스](/docs/network/specifications/harness)를 참고하세요
3. **실행 카드 생성하기** — 하네스가 점수, 핑거프린트, 메타데이터가 포함된 JSON 실행 카드를 생성해요
4. **발행하기** — `mt-eval publish eval/logs/harness/<run-id>_report.json --prod` 명령어로 실행 카드를 리더보드에 업로드해요(`--dry-run`로 미리보기 가능)
5. **리더보드에 표시** — 여러분의 실행이 *자체 벤치마크(미검증)*로 표시돼요. [방식 리더보드](https://champollion.dev/leaderboard)에는 `disqualified` 상태가 아닌 모든 행이 표시 및 순위 지정되며, 자체 벤치마크 항목도 해당 라벨이 붙어 포함돼요. 재채점된 결과만 보려면 *Champollion Verified*로 필터링하세요. 실행을 해당 등급으로 승격시키는 L0 재채점은 메인테이너 배치 작업이며 자동으로 스케줄링되지 않으므로, 현재 리더보드의 모든 행은 자체 보고된 주장이에요. **대회** 순위에서는 '인증 전용'이 기본값이며, 상금을 받을 수 있는 유일한 등급이에요

## 무결성 정책: 철회, 재실행, 목록 제외, 이의 제기

집행이 감정 소모가 아닌 정해진 절차가 되도록 사전에 작성되었어요. 이 규칙은 메인테이너 자신의 실행을 포함하여 모든 사람에게 동일하게 적용돼요.

**철회는 불가해요.** 발행된 실행은 영구적인 기록이에요. 결과가 부끄럽다는 이유로 점수를 삭제할 수 있는 메커니즘은 그 누구에게도 제공되지 않아요. 모든 실행 행에는 서버가 스탬프한 `submitted_at` 타임스탬프와 불변 감사 내역이 포함되며, 관리 조치 자체도 기록돼요.

**재실행은 추가될 뿐, 결코 대체되지 않아요.** 방식을 개선했다면 새 실행을 발행하세요. 이전 실행은 그대로 유지돼요. 여러 변형을 비공개로 테스트하고 승자만 발행하는 선택적 공개는 다른 리더보드들이 어뷰징에 취약해진 원인이었어요. 추가 전용(append-only) 기록은 이에 대한 구조적인 해법이에요. 핑거프린트 중복 제거는 바이트 단위로 동일한 재제출 스팸을 차단할 뿐, 역사를 덮어쓰지 않아요.

**목록 제외(Delisting)는 규칙 집행이며, 해당 규칙의 명칭이 명시돼요.** 실행은 명시된 사유가 있을 때만 목록에서 제외(조용히 삭제되지 않고 눈에 띄게 `disqualified`로 표시)돼요. 해당 사유는 격리되었거나 부적절한 하위 세트 데이터셋(모든 클라이언트 하위의 데이터베이스 트리거에 의해 강제됨), 말뭉치 체크섬 불일치, 조작되었거나 범위를 벗어난 점수, 콘텐츠 보호 규정 위반, 기본 데이터 등록에 대한 관리자의 철회예요. 목록 제외 시 해당 규칙과 근거가 명시돼요. 새로운 사유는 특정 사례에 소급 적용되지 않으며, 적용되기 전에 날짜가 명시된 편집을 통해 여기에 먼저 추가돼요.

### 결과 신고하기(Flagging)

*2026-09-07 추가됨.*

:::caution[아직 신고를 접수하지 않아요]

신고 기능은 구축되었고 2026-09-07 기준으로 데이터베이스도 준비되었지만, 신고를 접수하는 폼이 아직 이에 맞춰 재배포되지 않아 *Flag this result(이 결과 신고)*를 제출할 수 없어요. 신고를 묵묵히 접수하는 대신 실패 처리돼요. 그동안은 `info@champollion.dev`로 이메일을 보내주세요. 이 안내문은 폼이 배포되는 날 내려갈 예정이에요.

:::

**누구나 결과를 신고할 수 있어요.** 리더보드에서 해당 행을 펼치고 *Flag this result*를 누르세요. 해당 실행 ID와 이미 연결된 메시지 폼이 열리며, 무엇이 잘못되었다고 생각하는지와 그렇게 생각하는 이유(오염된 말뭉치, 라벨과 일치하지 않는 지표, 잘못 귀속된 방식 등)를 작성할 수 있어요. 신고에는 반드시 이유가 있어야 해요. 이유 없는 신고는 비추천(downvote)에 불과하며, 이 리더보드에는 비추천 기능이 없어요.

**신고는 투표가 아니라 비공개 메시지예요.** 메인테이너에게 티켓으로 전달되며 다른 곳에는 공개되지 않아요. 눈에 보이는 집계 자체가 어뷰징의 대상이 될 수 있고, 결과의 위상은 반대한 사람의 수가 아니라 증거에 기반해야 하므로 신고 횟수는 행에도, 실행 카드에도, 그 어디에도 표시되지 않아요. 신고를 접수하는 것 자체만으로는 해당 행에 아무런 변화도 일어나지 않아요.

**신고가 인용되면 오직 한 가지 방식으로만 나타나요.** 이 페이지에 이미 명시된 사유로 인해 결과가 `disqualified` 상태로 표시돼요. 다른 모든 목록 제외와 마찬가지로, 새로운 사유는 **누구에게든 적용되기 전에 날짜가 명시된 편집을 통해 여기에 먼저 추가돼요**. 따라서 신고로 인해 비밀 규칙이나 소급 적용 규칙이 만들어질 수 없어요. 신고가 기각되면 해당 행은 변경 없이 유지되며, 연락처를 남긴 경우 결과에 관계없이 답변을 받으실 수 있어요.

**신뢰 등급은 라벨일 뿐 수정이 아니에요.** `self-benchmarked` 행은 주장에 불과해요. `Champollion Verified` 행은 sha 고정 말뭉치에 대해 제출자의 출력물을 바탕으로 독립적으로 재채점된 상태예요. `Community Validated`는 커뮤니티 자체 테스트를 통해서만 부여돼요. 검증은 행의 등급을 변경할 뿐, 행의 점수를 변경하지 않아요.

**평판은 공개되며 자정 작용을 거쳐요.** 기여자 평판과 모든 재채점, 표본 재실행, 교차 입증, 조작 적발 내역을 기록하는 감사 로그는 공개돼요. 평판은 점수 배수가 아니며 실행의 숫자에 절대 손을 대지 않아요. 기여자의 실행이 얼마나 자주 재감사될지만을 결정해요(위의 *평판 가중치 감사* 참고). 입증된 조작은 철회 공지와 마찬가지로 공개적으로 기록되며 기여자의 인증된 전체 이력을 재감사해요. 동일한 규칙이 메인테이너 자신의 실행에도 적용돼요.

**이의 제기.** 실행 ID와 구체적인 주장(잘못된 점수, 잘못된 데이터셋, 잘못 적용된 규칙)을 포함하여 이슈를 등록해 주세요. 메인테이너는 결정론적 검사를 공개적으로 다시 실행하며, 결과와 그 근거를 이슈에 게시해요. 분쟁이 커뮤니티의 데이터나 검증에 관한 것이라면 커뮤니티 자체 권한에 따라 결정되며 리더보드는 해당 결정을 이행해요. 상금 대회의 경우에도 동일한 규칙이 적용되며 사전에 발표된 대회의 예선 및 감사 단계가 추가돼요. 상금 지급 **전에** 수상자에 대한 감사가 진행되며, 자격 박탈 시 다른 목록 제외와 마찬가지로 해당 규칙이 명확히 인용돼요.

## 향후 방향

- **포괄적인 모델 비교 실행** — 맞춤형 평가 코퍼스(공개 벤치마크가 아님)를 사용하여 champollion 언어 전반에서 최전선 모델(GPT-4o, Claude, Gemini 등)의 체계적 평가
- **더 많은 언어 쌍** — 커뮤니티 검증 데이터셋이 사용 가능해지면 Quechua, Inuktitut, 기타 저자원 언어
- **데이터셋 임포트** — 외부 평가 데이터셋(WMT, Tatoeba 등)을 champollion 평가 형식으로 변환하는 도구
- **자동 재실행** — 모델 버전 변경을 감지하고 벤치마크를 재실행하여 점수 편차 추적
