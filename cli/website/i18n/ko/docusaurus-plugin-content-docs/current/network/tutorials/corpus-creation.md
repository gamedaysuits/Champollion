# 코퍼스 생성 가이드

> **아이디어:** 번역 방법을 평가하려면 먼저 평가 코퍼스가 필요해요. 이 가이드에서는 데이터 소싱, 형식 요구사항, 품질 기준, 라이선싱, Network 기여에 이르기까지 코퍼스를 처음부터 구축하는 방법을 다뤄요.

:::info[이것은 번역 방법이 아니에요]
이 가이드는 많은 방법의 전제 조건이에요. 좋은 평가 코퍼스는 다른 모든 것을 가능하게 하는 기반이에요. 엄선된 50개의 쌍만으로도 새로운 리더보드 트랙을 열기에 충분해요.
:::

## 언제 사용해야 할까요

- Network 리더보드에 **새로운 언어 쌍을 추가**하고 싶을 때
- 학생 번역을 벤치마크하려는 **언어 교사**일 때
- 이중 언어 자료에 접근할 수 있는 **커뮤니티 언어 활동가**일 때
- 자신의 언어 쌍에 대한 표준화된 평가 세트가 필요한 **연구자**일 때

## 코퍼스 형식

harness는 간단한 JSON을 받아요:

```json title="my-corpus.json"
{
  "metadata": {
    "name": "Quechua Dev v1",
    "version": "1.0.0",
    "source_language": "eng",
    "target_language": "que",
    "entry_count": 75,
    "license": "CC-BY-SA-4.0",
    "author": "Your Name / Organization",
    "description": "75 English-Quechua pairs from educational materials"
  },
  "entries": [
    {
      "id": 1,
      "source": "Hello, how are you?",
      "reference": "Allillanchu, imaynallan kashanki?"
    },
    {
      "id": 2,
      "source": "The sun is shining today",
      "reference": "Kunan p'unchay inti k'anchashan"
    }
  ]
}
```

## 데이터를 어디서 소싱하나요

| 소스 | 품질 | 규모 | 라이선싱 |
|--------|---------|--------|-----------|
| **교과서 / 교육 자료** | 높음 (전문가 검토) | 낮음-중간 | 출판사에 확인 |
| **정부 문서** | 중간 (격식체) | 중간-높음 | 대개 퍼블릭 도메인 |
| **이중 언어 사전** | 높음 (검증된 항목) | 중간 | 다양함 |
| **커뮤니티 어르신 / 화자** | 최고 (원어민 직관) | 낮음 (제한된 시간) | 커뮤니티 관리 |
| **종교 텍스트** | 중간 (도메인 특화) | 높음 | 대개 공개 |
| **기존 코퍼스** (Hansard, FLORES) | 중간-높음 | 높음 | 라이선스 확인 |
| **직접 제작** | 최고 | 낮음 | 본인 소유 |

## 품질 기준

좋은 평가 코퍼스가 갖추어야 할 것:

1. **다양한 콘텐츠** — 인사말이나 간단한 문구만이 아니에요. 질문, 명령문, 복잡한 문장, 도메인 특화 용어를 포함하세요
2. **검증된 번역** — 최소 한 명, 이상적으로는 두 명의 유창한 화자가 검토한 번역
3. **일관된 정서법** — 전반에 걸쳐 하나의 문자 체계, 하나의 표기 관례
4. **독립적인 소스** — 방법이 학습할 텍스트에서 파생되지 않은 것
5. **명확한 라이선싱** — 평가 사용을 허용하는 명시적인 라이선스

:::danger[코퍼스 오염]
평가 코퍼스는 어떤 학습 데이터와도 **독립적**이어야 해요. 어떤 방법이 평가 코퍼스의 데이터로 학습되거나 프롬프트에 사용되었다면 실격 처리돼요. 첫날부터 평가 코퍼스가 학습에서 분리되도록 설계하세요.
:::

## 규모 가이드라인

| 규모 | 무엇을 가능하게 하나요 |
|------|----------------|
| **50개 항목** | 최소한의 유효 평가 — 큰 품질 차이를 감지하기에 충분함 |
| **100–200개 항목** | 신뢰할 수 있는 순위 — 방법 간 통계적 유의성에 충분함 |
| **500개 이상 항목** | 연구 수준 — 견고한 종합 점수, 신뢰 구간 |
| **1,000개 이상 항목** | 골드 스탠다드 — FLORES devtest 커버리지에 상응함 |

작게 시작하세요. 50개 항목이면 리더보드 트랙을 열기에 충분해요. 나중에 확장할 수 있어요.

## Network에 기여하기

1. 위의 JSON 형식으로 **코퍼스를 생성하세요**
2. **라이선스를 지정하세요** — 공개 평가에는 CC BY-SA 4.0을, 제한적 사용에는 CC BY-NC-SA 4.0을 권장해요
3. **안정적인 소스에 호스팅하세요** (본인의 저장소, 기관 아카이브 또는 데이터 레지스트리) — Champollion은 절대로 코퍼스 콘텐츠를 호스팅하거나 추적하지 않아요
4. **소스에서 가져오기 메타데이터 카드를 제출하세요** — [공개 저장소](https://github.com/gamedaysuits/Champollion)에 PR을 열어 harness가 업스트림 소스(로더/URL, SHA 핀, 라이선스, 출처)를 가리키도록 하는 레지스트리 항목을 추가하세요. 카드 형식은 [Datasets](/docs/network/leaderboard/datasets#creating-a-new-dataset)를 참조하세요
5. 카드가 병합되면 해당 언어 쌍에 대한 **리더보드가 열려요**

## 원주민 언어 커뮤니티를 위해

코퍼스 생성은 **언어 주권**의 행위예요. 여러분의 코퍼스, 여러분의 조건:

- 라이선스와 접근 조건을 여러분이 결정해요
- **공개 개발 세트**(방법 개발용)를 기여하면서 **비밀 테스트 세트**(공식 평가용)를 커뮤니티 통제 하에 유지할 수 있어요
- [주권 프레임워크](/docs/network/sovereignty/data-sovereignty)는 모든 수준에서 여러분의 데이터를 보호해요

작은 코퍼스라도 **전략적 자산**이에요 — 여러분의 언어에서 "충분히 좋다"가 무엇을 의미하는지 결정하는 벤치마크예요.
