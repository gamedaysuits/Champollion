# 커버리지 집계: 집계 방식

> **요약.** 사이트에서 **552개의 현존하는 언어가 기계 번역을 지원**하고 **196개의 언어가 배포된 서비스로 제공**된다고 할 때, 이는 의도적으로 분리된 두 개의 다른 집계입니다. 이 페이지에서는 두 티어(tier)를 정의하고, 빌드 시 각 숫자를 읽어오는 단일 진실 공급원(SSOT)을 명시하며, 목록이 어떻게 갱신되는지 설명해요. 커버리지는 *존재한다는 주장*일 뿐, 결코 품질을 보장하는 주장이 아니에요.

## 두 가지 티어

**Tier 1 — 모든 전용 MT 엔진 ("지원됨").** 현존하는 언어가 추적 대상인 전용 MT 엔진 — 배포된 소비자/API 서비스(Google Translate, Microsoft Translator, DeepL, LibreTranslate, …) **또는** 오픈 리서치 모델(NLLB-200, OPUS-MT, M2M-100, MADLAD-400, …) — 중 *어느 하나라도* 공식 지원 언어 목록에 포함되어 있다면 지원되는 것으로 간주해요. 이는 네트워크 지도에서 점을 녹색으로 표시하는 합집합이에요.

**Tier 2 — 배포된 서비스 ("제공됨").** 더 엄격한 기준이에요. 누구나 소비자 또는 API 서비스로 *오늘 당장 실제로 사용할 수 있는* 엔진의 목록에 해당 언어가 있어야 해요. 직접 다운로드하고 호스팅하여 서비스해야 하는 오픈 리서치 체크포인트는 여기에 포함되지 않아요. 이 숫자는 "엔지니어링 작업 없이 화자가 지금 당장 웹페이지를 번역할 수 있는가?"라는 질문에 대한 답이 돼요.

이 두 티어는 서로 다른 질문에 답하기 위해 존재하며, 이를 하나로 합치면 전 세계의 커버리지를 과장하게 돼요. 두 티어 모두 **ISO 639-3 개별 현존 언어**만을 대상으로 집계해요 (`isoType: 'L'`).

## 숫자의 출처 (수동 입력 없음)

표시되는 모든 집계는 기계 SSOT(단일 진실 공급원)를 **빌드 시점에 읽어온** 결과예요. 사이트의 어떤 수치도 텍스트로 직접 입력되어 오래된 상태로 방치되지 않아요.

1. **엔진별 목록**은 `cli/shared/catalogue/method-coverage.json`에 있어요. —
   엔진당 하나의 항목이 있으며, 해당 제공자가 공식적으로 발표한
   지원 언어 목록에서 *인용 목적으로만* 가져오고 `source_url` 및 `asOf` 날짜를 포함해요. Champollion은
   이 목록을 감사하거나 재생산하지 않아요. 이는 제공자 자체의 주장일 뿐이에요.
2. **빌드 프로세스는** 이 목록들을 현존 언어 인덱스와 교차 대조하여
   사이트의 빌드 통계에 티어별 집계를 출력해요 (Tier 1은 `stats.coverage.dedicatedLiving`,
   Tier 2는 `stats.coverage.serviceLiving`, 전체 현존 언어는 `stats.livingTotal`).
3. **페이지는 통계를 렌더링하며**, 텍스트와 통계가 어긋날 경우
   푸시 전(pre-push) 패리티 게이트가 빌드를 실패 처리해요.

## "194개 언어"와 "187개 언어"는 둘 다 사실일 수 있어요

제공자의 목록과 *언어*의 수는 동일한 대상이 아니므로, SSOT의 각 항목은 해당 숫자가 무엇을 의미하는지 명시해요.

- **`publisher-list-rows`** — 제공자가 공식적으로 발표한 목록의 길이로,
  발표된 그대로의 수치예요. Google의 Cloud Translation 페이지에는 NMT 모델에 대해
  **194**개의 행이 나열되어 있으며, 이 사이트에서 Google의 이름으로 표시하는 수치가 바로 이것이에요.
- **`champollion-derived-enumeration`** — 해당 목록을 고유한 ISO 639-3 기본 언어로
  *우리가* 병합한 결과예요. `zh-CN`와 `zh-TW`은 두 가지 문자로 표기된 하나의 언어이고, `pt-PT`과
  `pt-BR` 등도 마찬가지이므로, 동일한 194개의 Google 행은 **187**개의 언어가 돼요.
  이 숫자는 우리의 기준이며, 제공자의 기준이 아니에요.
- **`publisher-stated-headline`** — 제공자가 뒷받침하는 목록 없이
  주장하는 총합이에요. 이 수치에서는 아무것도 파생될 수 없어요.

처음 두 수치 사이의 차이는 산술적인 것이지 의견 불일치가 아니며, 이는 모든 제공자에게 적용돼요. Microsoft 135개 행 → 128개 언어, LibreTranslate 49개 → 47개, NLLB-200의 200개 FLORES 변형 → 196개와 같은 식이에요. 지도와 티어 집계는 헤드라인이 아닌 *열거된 목록*을 읽어와요. 항목에 선언된 기준과 목록이 서로 모순될 경우 푸시 전(pre-push) 게이트가 빌드를 실패 처리해요.

또한 제공자가 여러 목록을 발표할 수도 있다는 점에 유의하세요. Google의 페이지에는 Translation LLM 티어에 대한 별도의 표(2026년 8월 16일 기준 127개 행)가 있으며 통합된 총합을 전혀 명시하지 않아요. 따라서 "Google은 몇 개의 언어를 지원하는가?"에 대해 공식적으로 발표된 단일 답변은 없으며, 이 사이트에서도 임의로 답변을 만들어내지 않아요.

## 주장하는 커버리지가 품질을 의미하지는 않으며, 항상 배포 가능한 것도 아니에요

제공자의 목록에 있는 언어는 제공자가 *지원을 주장*한다는 의미일 뿐, 그 이상은 아니에요. 이 사이트에서 집계가 표시되는 모든 곳에 적용되는 두 가지 정직성 원칙은 다음과 같아요.

- **커버리지 ≠ 품질.** 번역 품질이 좋은지 여부는 별도로
  측정해야 하는 문제이며, 이것이 벤치마크 네트워크의 핵심 목적이에요. 품질에 대한
  주장은 (방법, 데이터셋, 지표)를 기준으로 리더보드에 표시되며, 커버리지에 대한
  주장은 여기에 표시돼요.
- **주장됨 ≠ 배포 가능함.** 광범위한 리서치 모델은 매우 많은 언어를 지원한다고 주장할 수
  있지만, 자체 문서에서는 훨씬 적은 하위 집합에 대해서만 사용 가능한 품질을 보고하기도 해요.
  제공자가 이러한 자체 평가를 발표한 경우, 사이트에서는 주장하는 집계*와*
  제공자 자체의 배포 가능/품질 수치를 모두 표시하며, 각각 제공자의 자료를 인용해요.

## 갱신 원칙

제공자의 목록은 변경되며, 집계도 기계적으로 이를 따라야 해요.

- `method-coverage.json`의 각 항목은 고유한 `asOf` 날짜를 가지며, 파일에는
  최상위 `asOf`(마지막 점검 날짜)가 포함돼요. 커버리지 집계를 보여주는
  화면에서는 이 날짜를 표시하거나 링크해요.
- **SOTA 점검**(모든 제공자의 공식 발표 목록을 재확인하고 새로
  추적된 엔진을 추가하는 작업)은 주기적인 유지보수 작업이에요. 점검을 통해 SSOT를 업데이트하면,
  사이트의 모든 집계는 다음 빌드 시 이를 따르게 돼요. 페이지 텍스트에서
  "기억"해야 할 것은 아무것도 없어요.
- 점검과 점검 사이의 집계는 정확히 `asOf` 날짜만큼 최신 상태를 유지해요. 이것이
  해당 날짜가 각주 관례가 아닌 데이터의 일부인 이유예요.

## 수정 및 토론 환영

제공자의 목록이 변경되었거나, 언어가 잘못 분류되었거나, 티어 경계가 잘못 설정되었다고 생각하시면 저희에게 알려주세요. [github.com/gamedaysuits/Champollion/issues](https://github.com/gamedaysuits/Champollion/issues)에서 이슈를 열거나 [info@champollion.dev](mailto:info@champollion.dev)로 이메일을 보내주시면 돼요.

## 출처

- **엔진별 목록** — `cli/shared/catalogue/method-coverage.json`: 각 엔진이
  공식적으로 발표한 지원 언어 목록 (인용 전용, 항목당 `source_url` + `asOf`).
- **현존 언어 세트** — 인용된 언어 카드에서 구축된 언어 인덱스의
  ISO 639-3 개별 현존 언어 (`isoType: 'L'`).
- **티어 집계** — 빌드 시 출력되는 `stats.coverage.dedicatedLiving` (Tier 1),
  `stats.coverage.serviceLiving` (Tier 2), `stats.livingTotal`. Champollion에서 파생됨.
- **이 집계를 바탕으로 한 인구 추정치** —
  [커버리지 격차: 추정 방식](/docs/network/context/coverage-gap-estimate)을 참조하세요.
