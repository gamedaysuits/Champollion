# 큐 구성 명세

**공식 버전: `ecv-v3` (브리지 신뢰도를 반영한 예상 체인 값).**
이 문서는
[champollion.dev/queue.json](https://champollion.dev/queue.json)이
어떻게 정렬되는지를 규정하는 표준 정의예요. 구현체
(공개 하네스 저장소의 `arena/scripts/generate_sweep_queue.py`)는 이 페이지를
섹션별로 그대로 반영하며, 큐의 메타데이터는 생성 시점에 사용된
정확한 매개변수 값을 다시 표시하고, **모든 항목은 전체 공식 분해
내역을 포함**하므로, 어떤 순위든 게시된 JSON만으로 직접 다시 도출할
수 있어요. 이 페이지와 큐가 서로 어긋난다면 그건 버그이니
신고해 주세요.

**오늘날의 큐를 한 단락으로 요약하면 다음과 같아요.** 퍼블릭 큐는 LLM 항목(단순(naive) 및 코칭(coached) 프롬프팅 조건)과 MT 서비스 엔진 항목을 하나의 보드에 함께 담고 있으며, 서베이 정렬 순서(`map`, §2.2)에 따라 순위가 매겨져요. 비용(달러) 대비 언어 쌍, 언어 및 어족 전반의 첫 관측(first light)을 우선시하고, 한 번도 측정되지 않은 언어에 대한 최초 측정 부스트(§2.2)가 적용되며, 프리뷰에는 예산 티어가 공개되고(§2.1.1), 전체 순위는 데이터베이스를 통해 제공돼요(전체 순위가 크기 한도를 초과하면 정적 파일에는 상위 일부만 포함되며, 해당 사실이 명시돼요). 아래 섹션들은 날짜가 표기된 결정 이력과 함께 유지되는 표준 정의이며, 제공되는 모든 큐의 메타데이터에는 순위를 매긴 정확한 매개변수가 명시되어 있어요.

> **v3 (2026-06-13).** 이제 모든 엣지는 품질과 신뢰도라는 두 개의
> 수치를 가진 *브리지*이며, 체인 행렬은 이 둘의 곱으로 동작해요
> (§1.5). 한 번만 실행된 62개의 단일 단어 어휘 항목은 더 이상
> 경로처럼 보일 수 없으며, 복제, 더 큰 코퍼스, 더 풍부한 코퍼스,
> 더 좁은 신뢰 구간 모두 값이 매겨진 가치를 지녀요. v2 큐
> (품질 전용)는 자체 메타데이터를 통해 해석 가능한 상태로
> 남아 있어요.

## 1. 목표: 품질 가중 메시

목표는 *측정된 개별 언어 쌍 체인으로 구축되는 언어 간 번역*이에요. 직접적인 벤치마크가 없는 두 언어 간의 번역은 벤치마크된 언어 쌍을 **연계(chaining)**(X→피벗→Y)하여 제공되므로, 벤치마크의 가치는 말뭉치 수가 아니라 **해당 그래프의 체인 용량**에 달려 있어요.

**정의.** *벤치마크 그래프*가 언어당 하나의 노드를 가지고, 게시된
비실격 실행이 하나 이상 있는 모든 언어 쌍에 대해 **엣지 강도**를
가진다고 해요.

```
s(e) = (best published corpus-level chrF++ on that pair) / 100   ∈ [0, 1]
```

코퍼스 수준 chrF++가 표준 게시 수치예요
([Scoring Specification](/docs/network/specifications/scoring) 참조).
*최선(best)*인 이유는 체인이 각 홉마다 가장 잘 입증된 시스템을 통해
경로를 잡기 때문이에요. 게시된 실행이 없는 쌍은 s(e) = 0이에요.

두 언어 사이 경로 P의 **추정 체인 강도**는 다음과 같아요.

```
strength(P) = λ^(|P|−1) · Π_{e ∈ P} s(e)
```

— 엣지 품질은 곱셈적으로 결합되며, 각 *접합부*(각 중간 피벗)는
추가적인 충실도 계수 **λ < 1**의 비용을 발생시켜요. 두 선택 모두
피벗 번역 문헌에 근거해요. 피벗을 통한 번역은 단순 합성이 시사하는
것 이상으로 직접 번역 대비 품질을 안정적으로 잃으며(Utiyama &
Isahara 2007; Wu & Wang 2007), 손실의 크기는 선택된 피벗에 따라
달라지고(Paul et al. 2009), *직접적인* 비영어 중심 쌍을 구축하는
것이 대규모에서 영어 피벗 방식을 측정 가능하게 능가하는데 —
M2M-100의 다대다 설정에서 약 10 BLEU만큼이에요(Fan et al. 2021).
λ는 추정 체인이 측정이 아니라는 점을 상기시키는 공식의 상수예요.
직접 실행만이 이 할인을 제거해요.

그러면 **최선 체인 행렬**과 **메시 목표**는 다음과 같아요.

```
Q(u,v) = max over paths P from u to v of strength(P)      (1 if u = v, 0 if disconnected)

Φ = mean over ordered language pairs (u ≠ v) of Q(u,v)    ∈ [0, 1]
```

Q는 표준 로그 변환 하의 최단 경로 문제로 정확히 계산돼요
(엣지 가중치 −ln(λ·s(e)) ≥ 0, Dijkstra, 그 다음
Q = exp(−d)/λ). Φ는 [Latora & Marchiori
(2001)](https://arxiv.org/abs/cond-mat/0101396)의 *전역 효율성*
구성에서 1/거리 커널을 곱셈적 체인 충실도로 대체한 것이며 — 이는
엣지가 단위 길이가 아니라 홉당 품질 유지율을 지닐 때 자연스러운
커널이에요. (큐 v1은 가중치 없는 전역 효율성 이득으로 순위를
매겼는데 — 엣지에 대해 아는 것이 존재 여부뿐인 이 계열의 특수한
경우예요.)

### 1.5 신뢰도: 브리지는 (q, r)

작고 얇으며 한 번도 복제된 적 없는 코퍼스에서 나온 화려한 점수는
브리지가 아니에요. 따라서 v3은 측정된 모든 엣지를 다음과 같이
분할해요.

```
quality      q(e)   = best published corpus-level chrF++ / 100
reliability  r(e)   = f_size · f_rich · f_conf · f_repl        ∈ [0, 1]
effective    s_eff(e) = q(e) · r(e)        ← what chains compose over
```

| 계수 | 정의 | 완전 인정 기준 | 근거 |
|---|---|---|---|
| `f_size` | min(1, n/100), n = 최선 실행의 평가된 항목 수 | 항목 100개 | [corpus-design](/docs/network/specifications/corpus-design)의 유의성 하한; Koehn (2004)은 약 300문장 세트에 대한 부트스트랩 테스트를 검증함 — 300개조차 "작은" 수준이므로, 크기는 단순히 표시를 막는 것이 아니라 신뢰도를 할인함 |
| `f_rich` | min(1, L̄/5), L̄ = 평균 *유효* 소스 길이 | 유효 단어 5개 | AmericasNLP (Mager et al. 2021)는 단어 수준 단위가 풍부한 형태론에서 깨지기 때문에 chrF를 채택; Mager et al. (2022)은 공백 토큰을 잘못된 단위로 기록함 |
| `f_conf` | min(1, 5/h), h = 최선 실행의 chrF 95% CI 절반폭 (게시되지 않은 경우 프록시 `50/√n`) | CI ≤ ±5 chrF | 작은 코퍼스에서 델타가 구분되지 않는 노이즈 하한; Kocmi et al. (2021)은 CI 내 델타가 인간 선호와 자주 모순됨을 보임 |
| `f_repl` | min(1, runs/2) | 게시된 실행 2회 | Marie, Fujita & Rubino (2021), 769개 논문 메타 평가: 복제되지 않은 단일 비교는 이 분야의 기록된 신뢰성 실패임 |

**유효 길이**는 공백 단어가 아니라 콘텐츠 단위로 측정해요.
`L̄ = mean source chars / c(L)`이며, 여기서 *문자 경제성*
`c(L)`은 정렬된 측면의 영어 단어당 언어 L 측면의 중앙값
문자 수로, 이 프로젝트 자체의 병렬 코퍼스에서 측정해요
(v3 출시 시점 기준 7,400개 이상의 정렬된 항목: cmn 1.6, jpn 2.3,
kor 2.6; eng 기준선 5.0; deu 6.0; crk 4.7 — 다종합 단어는 그것이
담은 콘텐츠로 값이 매겨짐). 유형론 조회 테이블은 없으며, 추정치는
코퍼스가 커짐에 따라 정밀해지고, eng 쌍 데이터가 없는 언어는 기본
경제성을 사용해요. 레지스트리에서 코퍼스별로 기록돼요
(`richness` 블록).

**브리지 등급**(표시 용어): **established** — n ≥ 100,
L̄ ≥ 5, h ≤ 5, runs ≥ 2; **provisional** — 측정되었으나 어느 하나라도
미달; **registered** — 게시된 실행 없음. 체인 주장("X에서 Y로 갈 수
있다")은 가장 약한 홉의 등급만큼만 강하며, 메시 시각화는 신뢰도를
엣지 불투명도로 표시해요.

**검증된 확인**(v3 출시 전에 실행되는, 커밋된 검증 스크립트에서):
*단일 단어 어휘 항목 62개, 1회 실행* → r ≈ **0.04**
(경로 아님); *200문장, ±3 CI, 3회 실행* → r = **1.00**; 순진한 단어
수가 1.0(스크립트 아티팩트)인 101개 항목의 일본어 코퍼스는 유효
단어 6.5개와 완전한 `f_rich`로 복구돼요.
경계와 계수별 단조성은 속성 테스트로 검증돼요.

**v3에서의 실행 가치.** 실행은 브리지를 두 가지 방식으로 개선할 수
있으며, ΔΦ는 둘 중 더 나은 것을 취해요. **(a)** 그것이 엣지의 최선
실행이 됨 —
`ŝ_eff = 예측 품질 × r(그 코퍼스의 n, 풍부도, CI 프록시,
runs+1)`; 또는 **(b)** 단지 복제만 함 — 현재 최선이 유지되고,
`f_repl`가 상승함. 따라서 단일 실행 엣지에 대한 복제는 실제로
값이 매겨진 가치이며, 측정된 쌍에서 더 크거나 더 풍부한 코퍼스가
작은 것의 재실행보다 우선해요. 항목은 `edge_quality`,
`edge_reliability`, `edge_tier`, `effective_strength`,
`post_run_reliability`, `predicted_effective`을 v2 예측 필드와 함께 노출해요.

**Φ가 아닌 것.** Φ는 큐의 내부 우선순위 결정 통화이지, 역량 주장이
아니에요. 그 입력값은 [Corpus Design
Framework](/docs/network/specifications/corpus-design)의 모든 주의사항을
지닌 개발 세트 점수예요. 가능한 훈련 데이터 오염으로 인해 각 점수는
상한선이고, chrF++ 값은 언어 간에 엄밀히 비교 가능하지 않으며, 작은
코퍼스는 넓은 신뢰 구간을 지녀요. 공식은 Φ가 *유용성에 따라 실행을
정렬*하기만 하면 되며, 결코 품질 보증으로 게시되지 않아요.

## 2. 결정 문제

큐의 미결 항목은 자격 요건(개발 분할, 재배포 가능한 라이선스, 격리되지 않음, 전송 적격성, **벤치마크 식별 가능(benchmark-resolvable)** — §2.2의 언어 식별 게이트 참조)을 충족하면서 아직 리더보드에 없는 모든 (말뭉치, 모델, 조건) 조합이에요. 이미 다룬 조합의 동일한 재실행은 제외되며(게시 시 런 카드 지문으로 중복 제거됨), 이미 측정된 언어 쌍에 대한 새로운 모델이나 조건은 미결 항목으로 유지돼요.

기여된 연산은 예산이에요. 메시가 가장 빠르게 개선되도록 다음에
실행할 열린 항목을 고르는 것은 예산이 제한된 커버리지형 최대화
문제이며, 표준적인 접근은 **단위 비용당 한계 가치**에 따른 탐욕적
선택이에요. 단조 서브모듈러 목표에 대해 탐욕 규칙은 고전적인
(1 − 1/e) 보장을 수반하며(Nemhauser, Wolsey & Fisher 1978), 그
편익/비용 비율 형식은 예산 하에서의 표준 알고리즘이에요(Khuller,
Moss & Naor 1999). 우리는 이 비율 규칙을 순위 결정 원칙으로 사용해요.
(솔직한 참고: 우리의 목표는 결정론적 핵심에서 커버리지와 유사한
수확 체감을 보이지만, 확률적 예측 계층 때문에 우리는 탐욕 보장을
이 정확한 시스템에 관한 정리가 아니라 *동기*로서 인용해요.)

```
ECV(item) = ΔΦ(item) / max(est_cost_usd, COST_FLOOR)
```

항목은 ECV 내림차순으로 순위가 매겨져요. 동점 시: naive가 coached
보다 먼저, 더 저렴한 것이 먼저, 그 다음 항목 id 순이에요.

### 2.1 순위 보정 — 2026-07-12

탐욕적 ECV 규칙 위에 네 가지 조정이 계층적으로 적용되며, 각각은
큐의 메타데이터에 반영돼요 (`priority_parameters.contamination_ecv_factors`,
`priority_parameters.frontier_interleave`, `metadata.preview_policy`):

1. **오염 배수(Contamination multiplier).** 각 항목의 ECV는 해당
   코퍼스의 오염 등급에 따른 계수로 곱해져요: **LOW 1.0 / MEDIUM
   0.4 / HIGH 0.1**이며, 알 수 없거나 누락된 등급은
   MEDIUM으로 처리돼요(절대 깨끗하다고 가정하지 않음). 근거: 깨끗한
   체인 그래프는 LOW 오염 엣지만 허용하므로, LOW가 아닌 실행은
   그 그래프에 진입할 수 없고 동일 비용에서 깨끗한 메시 작업보다
   높은 순위를 차지해서는 안 돼요. LOW가 아닌 항목도 큐에
   남아 있어요 — 상대 레인 비교는 실질적인 가치이기 때문이에요 — 다만
   깨끗한 작업보다 뒤에 순위가 매겨질 뿐이에요.
2. **프론티어 인터리브(Frontier interleave).** 탐욕적 정렬 이후,
   매 5번째 우선순위 슬롯에는 프론티어 모델 집합(생성기 내에서
   데이터로 유지되고 메타데이터에 반영됨) 중 아직 배치되지 않은
   최상위 항목이 배치돼요. 그래서 프론티어 근거가 저렴한 계층이
   포화된 후에만 도달하는 것이 아니라, 예측 사전 확률에
   일찍 도달하게 돼요. 순수한 재정렬이에요: 어떤 것도 삭제되거나
   중복되지 않고, 자연스러운 슬롯을 얻은 프론티어 항목은 그것을
   유지하며, 우선순위는 짜인 순서로 번호가 매겨져요 — 공개된
   순위가 곧 진실이에요.
3. **프리뷰 소스 허브 상한(Preview source-hub cap).** 상위 25개
   공개 프리뷰는 하나의 소스 언어를 공유하는 항목을 최대 **6**개까지만
   표시해요. 그래서 자원이 풍부한 단일 허브가 진열창을 독점할
   수 없어요. 상한을 초과한 항목은 전체 큐에서 실제 우선순위를
   유지하며, 프리뷰는 단순히 순위 순서상 다음으로 적격한 항목을
   가져와요.
4. **프리뷰 인공어 제외(Preview constructed-language exclusion).**
   소스 또는 대상이 인공어인 항목은 프리뷰에서 건너뛰어져요. 이
   판정은 카드 패밀리 기반이에요(언어 카드에서 읽어들이는
   Glottolog의 Artificial Language 분류 — 하드코딩된 언어
   집합이 아님). 그리고 파생된 코드 목록은
   `metadata.preview_policy`에 게시되므로 서버 측 새로 고침도 동일한
   선택을 적용해요.

(3)과 (4)는 **표현 정책일 뿐이에요**: 전체 `queue.json`,
그 순위, 그리고 우선순위는 영향을 받지 않아요.

### 2.1.1 예산 티어 — "$X로 무엇을 할 수 있나요?" (2026-08-24)

`queue-preview.json`에는 **$1 / $10 / $100 / $1000**의 예산에 대해 공개된 순위의 탐욕적 예산 내 접두사(greedy affordable prefix)를 요약한 `budget_tiers` 배열이 포함되어 있어요. 우선순위대로 항목을 탐색하면서 예상 비용이 예산 범위 내에 있는 항목을 선택하고, 맞지 않는 항목은 건너뛰며, 뒤이어 나오는 더 저렴한 항목들로 계속 채워 넣는 방식이에요. 각 티어는 해당 예산으로 구매할 수 있는 항목 수, 총 예상 비용, 대상이 되는 고유 언어 쌍 및 모델 수, 그리고 예산이 순위의 어느 깊이까지 도달하는지(`max_priority`)를 보고해요.

순위 자체가 이미 비용 대비 한계 가치(marginal-value-per-cost)(§2)를 반영하고 있기 때문에, 탐욕적 예산 내 접두사는 해당 지출에 대해 이 모델이 권장하는 할당 그 자체예요. 누구에게도 맞지 않게 암묵적으로 크기가 정해진 단일 목록 대신, 소규모 기여자든 대규모 기여자든 동일하게 공개된 순위에서 구체적이고 최적화된 해답을 얻을 수 있어요. 티어는 요약일 뿐이에요. 할당 자체는 순위를 순서대로 확인하며 자신의 예산에 맞추는 과정일 뿐이에요. 서버 측 새로고침은 동일한 탐색 방식으로 남아 있는 항목들에 대해 티어를 재계산해요(생성기와 새로고침 함수는 쌍둥이처럼 동일하게 구현되어 있으며 양쪽 모두에서 테스트돼요).

### 2.2 레인 및 순위 지정 모드 — 2026-07-19

제공되는 큐는 자체 메타데이터에서 어떤 **레인(lane)**을 다루고 어떤 **순위 지정 모드(ranking mode)**로 정렬되었는지를 선언해요. 메타데이터가 공식 기준이며, 이 섹션에서는 관련 용어를 정의해요.

**레인** (`metadata.lane`, `metadata.lane_policy`). 2026-08-27부터 퍼블릭 큐는 **both** 레인을 다뤄요. 즉 LLM 항목(모델 × 프롬프팅 조건)과 MT 서비스 항목(조건 `engine` — DeepL, Google Translate, Microsoft Translator, LibreTranslate, Tilde; 각 서비스는 자체 공개 지원 범위 목록에 포함된 언어 쌍에 대해서만 큐에 등록됨)을 **모두** 포함해요. 2026-07-19의 **llm** 레인(LLM 항목 전용, 적어도 한쪽 언어가 모든 MT 서비스의 공개 지원 범위 밖에 있는 언어 쌍으로 제한됨)은 결국 실행되지 않은 주최자 주도 캠페인을 위해 서비스 벤치마킹을 유보해 두었고, 이로 인해 카탈로그의 대부분이 방치되었어요. 서비스를 측정하는 것은 커버리지 맵의 근간이므로, 이제 두 종류의 작업이 모두 하나의 보드에 올라와 있어요. (언어 카드를 통해 거대언어(macrolanguage) 별칭이 지정된) 지원 범위 합집합은 여전히 `service_coverage_methods` 및 `service_covered_languages`으로 표시되며, llm 레인 큐는 제외된 언어 쌍을 여전히 `pairs_dropped_fully_covered`로 보고해요.

**BLOB 크기 한도** (2026-08-27). 제공되는 `queue.json`은 호스팅 용량의 엄격한 상한선이 있는 정적 파일이므로, 전체 순위가 이를 초과하면 파일에는 순위의 **상위 일부(top slice)**만 포함되고 `metadata.blob_truncated {kept, total}`에 그 사실이 명시돼요(알림 없는 제한은 절대 없어요). 데이터베이스 큐(`queue_top()` / `queue_pairs()`)는 항상 **전체** 순위를 제공하며 신뢰할 수 있는 공식 작업 목록이에요. 프리뷰의 언어 쌍 집계와 예산 티어는 함께 제공되는 아티팩트를 설명해요.

**언어 식별 게이트** (2026-07-19). 큐 항목은 **활성 개별 ISO 639-3 코드**만을 대상으로 해요. 거대언어('아랍어')나 집합적 어족 코드('베르베르어파')에 대한 점수는 평가된 적 없는 변종에 대한 반증 불가능한 주장이 되기 때문이에요(FLORES-200/NLLB가 데이터를 `arb`/`quy`/`zsm`로 코딩하는 것과 동일한 논리예요). 업스트림 말뭉치 라벨은 그대로 따르거나 버리지 않고 *식별(resolve)*을 거쳐요. 문자 태그는 기계적으로 제거되며(`eng→cmn-Hans` 말뭉치는 `eng→cmn`용으로 큐에 등록되고 문자는 항목 표시 메타데이터 `source_script`/`target_script`로 유지됨), 완전히 폐기된 코드는 공식 ISO 후속 코드를 따르고, 매크로 라벨이 붙은 말뭉치는 레지스트리 항목에 기록되고 인용된 **변종 식별(variety resolution)**이 있는 경우에만 큐에 등록돼요(예: FLORES+는 케추아어를 `quy`으로 문서화함). 두 경로 중 어느 쪽으로도 식별되지 않는 말뭉치는 제외되며, `metadata.doctrine_exclusions`에 기계 판독 가능한 사유(총계, 사유별 개수, 말뭉치별 사유)가 공개되고 데저트 원장(desert ledger)(`service_landscape.invisible_reasons.corpus_excluded_by_doctrine`)에 집계돼요. 알림 없이 누락되는 일 없이 명시적으로 제외돼요. 포괄적 라벨이 붙은 말뭉치의 기존 결과는 하위 변종으로 병합되지 않고 정직하게 이름 붙여진 자체 메시 노드를 유지해요(노드 `scope`: `macrolanguage` / `collective` / `retired`). 식별 입력값은 모두 공개되어 있어요. 레지스트리의 항목별 `language_resolution` 스탬프에 식별된 코드, 범위, 고정 인용이 포함돼요.

**순위 지정 모드** (`metadata.rank_mode`, `metadata.priority_model`에 기술됨). 동일한 항목들에 대한 두 가지 정렬 방식이에요:

- **ecv** — §2–§3의 탐욕적 기대 체인 가치(expected-chain-value) 규칙으로, 예상 비용(달러)당 메시 개선도를 의미해요. 활용(exploitation) 정렬 방식이며, 보드가 예측과 ΔΦ가 유의미한 신호를 가질 만큼 충분히 조밀할 때 적합해요.
- **map** (map-value v2) — 서베이 정렬 순서:
  `MapValue = novelty × uncertainty × promise × connectivity × corpus-quality × contamination ÷ cost`이며, 정확한 탐욕적 추적(greedy trace)으로 구성돼요. *Novelty(참신성)*는 위치 기반 첫 관측 점수로, 이미 배치된 항목이 동일한 방향성 언어 쌍(1/(1+n)), 대상 언어, 대상 어족, 방법 × 대상 어족 셀, 대상 × 도메인 셀(각각 1/√(1+n); 어족은 언어 카드에서, 도메인은 말뭉치 레지스트리의 분류 체계에서 가져옴 — 대상 언어의 초기 커버리지는 처음 측정된 도메인을 반복하지 않고 다양한 사용역에 걸쳐 분산되어야 함)을 차지함에 따라 감쇄돼요. *Uncertainty(불확실성)*는 §3.1 예측의 백오프 깊이(언어 쌍 0.25 · 대상 언어 0.55 · 출발 언어 0.75 · 전역 1.0) × 1/(1+해당 에지에서 공개된 실행 수)예요. *Promise(유망성)*는 §3.1의 예측 강도로 최솟값은 0.25로 제한돼요. 잘 작동할 가능성이 높은 미지의 영역이 앞서며, 황무지(desert)일 가능성이 높은 영역을 지도화하는 것도 여전히 가치가 있어요. *Connectivity(연결성)*는 **측정된 네트워크를 아직 도달할 수 없는 언어와 연결하는** 언어 쌍의 순위를 높여요. 측정된 메시 에지(`mesh.json`, 상태 `measured`)에 있거나 임의의 MT 서비스의 공개 커버리지 목록(위의 레인 게이트와 동일하게 거대언어 별칭 적용)에 속하는 경우 해당 엔드포인트는 *구축된(established)* 것으로 간주돼요. **브리지(bridge)**(구축된 엔드포인트가 정확히 하나)와 **아일랜드(island)**(둘 다 아님)는 모두 1.0점을 받아요. 2026-08-27부터는 단절된 황무지의 첫 관측도 온전히 점수에 반영돼요(2026-07-19 네트워크 확장 사이징에서는 아일랜드에 0.5점을 부여하여 가장 깊은 롱테일을 구조적으로 강등시켰음). 반면 **내부(interior)** 조밀화(둘 다 구축됨)는 0.5점을 받아요. 알려진 지점 간의 강화는 ecv 모드의 역할이기 때문이에요. 추가로, 출발 언어나 대상 언어에 대해 어디에도 공개된 측정치가 전혀 없는(0개) 항목의 서베이 가치에는 **최초 측정치 부스트(first-reading boost)**(×2.0)가 곱해져요. 이는 명확히 기술된 아홉 번째 원칙이에요: **언어의 최초 측정이 정밀화보다 우선해요**. 불확실성 요인만으로는 이를 표현할 수 없어요(잘 측정된 두 언어 간의 미측정 언어 쌍과 한 번도 측정되지 않은 언어에 동일한 점수를 부여하기 때문이에요). 이 부스트를 통해 롱테일의 첫 관측은 우연한 결과가 아니라 명시적인 목표가 돼요. 두 요인 모두 `metadata.map_value_parameters`을 따르며 edv의 서베이 컴포넌트(§2.3) 내부에서도 동일하게 적용돼요.

  아홉 번째 원칙의 나머지 절반은 순위 체계 외부에 존재해요. 기존 항목의 어떤 정렬 방식으로도 말뭉치가 전혀 없는 언어(현재 기준 개별 코드를 가진 살아있는 언어 약 7,500개)에는 도달할 수 없어요. **말뭉치 위시리스트**(`/corpus-wishlist.json`, 큐와 함께 재생성됨)는 이러한 확보 프론티어를 공개해요. 살아있고 개별 코드를 가지며 말뭉치가 전무한 모든 언어를 인용된 최대 화자 수 순으로 순위를 매겨요(화자 수는 실제로 말뭉치를 구축할 수 있는 커뮤니티의 실현 가능성을 나타내는 프록시로 사용됨). 모든 화자 수는 출처가 명시되며 자의적으로 조정되지 않아요.
  *Corpus-quality(말뭉치 품질)*는 §1.5에 따른 말뭉치의 내재적 신뢰도 잠재력 `f_size × f_rich`이에요. 서베이는 신뢰할 만한 무게를 견딜 수 있는 말뭉치를 대상으로 해야 하므로, 62개 항목의 단일 단어 어휘 목록이 단지 저렴하다는 이유만으로 상위를 차지하지 않아요. 풍부도(richness) 측정치가 없는 경우는 중립을 유지해요(측정치 부재가 곧 빈약함의 증거는 아니에요). 비용 및 오염 규율은 ecv와 동일해요. 프론티어 인터리브 및 동점 처리 규정(§2.1)은 그대로 적용돼요. 서베이 단계에 적합한 방식이에요. 메시 강도의 성장이 느려지는 대가를 감수하는 대신, 비용(달러)당 *지도가 학습하는 정보*(무작위로 흩어지지 않고 측정된 네트워크로부터 확장되는 언어 쌍, 언어, 어족, 방법 셀 및 도메인 전반의 첫 측정치)를 극대화해요.

> **map-value v2 (2026-07-19).** 서베이 정렬 순서에 설립자가 지시한 두 가지 추가 사항: 이제 *측정된 네트워크로 연결되는(bridge into)* 언어 쌍이 단절된 탐색이나 내부 조밀화보다 높은 순위를 차지하며, 말뭉치 품질(크기 하한 × 유효 풍부도, §1.5) 및 대상별 도메인 확산이 순위에 반영돼요. 기여자의 연산 자원은 충분한 가치를 지닌 말뭉치를 기반으로 구축된 경로를 새로운 경로와 연결해야 해요. 라이선스는 여전히 **가중치가 아닌 게이트(gate)**로 작용해요. 라이선스 및 전송 채널 규칙은 큐에 등록될 수 있는지 여부 자체를 결정해요(§2 및 큐의 `transmission_note` 참조). 적격한 말뭉치 사이에서 순위는 라이선스를 고려하지 않으므로, 특정 언어 쌍의 유일한 말뭉치인 경우가 많은 제한적이지만 고정된 연구용 데이터셋이 구조적으로 소외되지 않아요. v1 큐(novelty × uncertainty × promise만 반영)는 자체 메타데이터를 통해 여전히 해석 가능해요.

생성 시 사용된 정확한 요인 값은 `metadata.map_value_parameters`에 포함되어 제공돼요. 연결성 및 품질 입력값은 공개된 `mesh.json`(측정된 에지), 메타데이터에 표시된 서비스 지원 범위 합집합, `registry.json`(항목 수 + 풍부도)에서 다시 도출할 수 있어요. 또한 모든 항목은 모드와 관계없이 전체 ecv-v3 진단 필드를 유지하므로, 동일한 아티팩트에서 두 정렬 순서 중 어느 것이든 다시 도출할 수 있어요.

### 2.3 순위 지정 모드 `edv` — 기대 결정 가치 (2026-08-27)

*상태: 구현 완료되었으나, §2.3.6의 측정된 비교 평가 전까지 기본적으로 비활성화되어 있어요. 그때까지 공개 기본값은 `map`으로 유지돼요.*

큐가 구매하는 결과물은 정확히 두 가지예요. 바로 **역량 지도(capability map)**(솔직한 불확실성을 바탕으로 어떤 방법이 무엇을 잘하는지)와 **라우팅 메시(routing mesh)**(경로로 연계되는 측정된 언어 쌍들)예요. `edv`은 각 후보 항목이 두 가지를 얼마나 진전시키는지 가중 포트폴리오 형태로 가격을 매겨요:

```
EDV(item) = [ w_judge·Ĵ + w_mesh·M̂ + w_survey·Ŝ ] × contamination ÷ max(cost, COST_FLOOR)
```

기본값은 `w_judge = 0.35, w_mesh = 0.25, w_survey = 0.40`이에요(설립자가 조정 가능하며, 모든 생성 작업 시 실제로 사용된 가중치가 `metadata.edv_parameters`에 표시돼요). 오염 요인(§2.1 해결책 1)은 외부 승수로서 정확히 한 번만 적용돼요. 라이선스 및 전송은 여전히 **가중치가 아닌 게이트**예요. 자격 요건은 가치가 계산되기 전에 결정되며, 적격 말뭉치 사이에서 순위는 라이선스를 고려하지 않아요.

#### 2.3.1 Ĵ — 방법 판정 가치

해당 실행이 **동일 말뭉치에서의 방법 간 비교 확정**을 얼마나 진전시키는지에 대한 가치를 산정해요. 이는 본 프로젝트의 자체 측정 연구가 허용하는 유일한 방법 간 비교 주장이에요. (W2 난이도 전이 연구는 언어 간 능력 연결을 기각했어요. 해당 연구에서 허용된 긍정적 결과인 언어 내 가산적 방법 × 말뭉치 조정이 바로 이 컴포넌트가 사용하는 방식이에요. 캘리브레이션 파일럿에 따라 점수는 정렬과 분리에만 사용되며 수용 가능성 확률로 절대 변환되지 않아요.)

후보 (말뭉치 C, 방법 M, 조건)에 대해: **대조 파트너(contrast partners)**는 (C, 동일 조건)에 대해 이미 공개된 실행 결과가 있는 방법 M′을 의미해요. 각 파트너에 대해, 풀링된 CI 반폭 대비 chrF 포인트 점수 분리를 `sep`(기록된 CI, 미공개 시 대리값 `50/√n`), §3.1의 예측 점수에 대해 동일하게 계산된 값을 `sep_pred`라고 할 때 다음과 같아요:

| 해당 언어 쌍에서 {M, M′}의 대조 상태 | 크레딧 |
|---|---|
| **unmet** — 공유 말뭉치가 아직 없음 | `JUDGE_FIRST = 1.0` |
| **contested** — 공유 말뭉치가 존재하며 모두 `sep < Z_DEC` | `JUDGE_CONTESTED = 0.8 × clip(sep_pred / Z_DEC, 0, 1)` |
| **decided** — 일부 `sep ≥ Z_DEC`, n_dec개 말뭉치가 이를 판정함 | `JUDGE_DECIDED = 0.25 / (1 + n_dec)` |

각각에 `w_top = 1/√(rank(M)·rank(M′))`이 곱해져요. 1위와 2위를 판정하는 것이 7위와 8위를 판정하는 것보다 더 가치 있기 때문이에요. 언어 쌍별 방법 순위는 해당 언어 쌍에 대해 2개 이상의 방법 × 2개 이상의 말뭉치가 측정된 경우 허용된 가산적 방법 × 말뭉치 적합(관측된 셀에 대한 교대 최소제곱법)을 사용하고, 그렇지 않은 경우 방법별 최고 점수를 사용해요. 이 적합은 **엄격하게 언어 쌍별로 이루어지며, 여러 언어에 걸쳐 풀링되지 않아요**. `Z_DEC = 1.96`.

동일한 (C, M)에서 코칭 대 단순(coached-vs-naive) 대조는 `JUDGE_COND = 0.5 / (1 + n_cond)`을 추가해요. 항목의 대조는 수확 체감(내림차순 정렬 시 추가 대조당 `JUDGE_GAMMA = 0.7`)과 함께 합산되며, **시드 항(seed term)** `JUDGE_SEED = 0.25 × min(1, m_C/3) × corpus-quality`(m_C = C에 큐 항목이 있는 다른 라인업 방법)이 더해져 빈 보드에서도 향후 비교를 판정할 수 있는 말뭉치를 여전히 선호해요. 이는 비교 장소로서의 가치(venue value)이며 빌려온 점수가 아니에요. 조립 과정에서 판정 컴포넌트는 `1/(1 + items already placed on the same pair and condition lane)`으로 감쇄돼요.

#### 2.3.2 M̂ 및 Ŝ

`M̂`은 §3의 기대 메시 이득(ΔΦ)으로 변경되지 않으며, 체인 행렬은 생성 시점에 동결돼요. `Ŝ`는 §2.2의 map-value v2 핵심인 `uncertainty × promise × connectivity × corpus-quality`(위치 기반 참신성 감쇄 포함)이며 변경되지 않아요. 예측 점수 *수준*(promise)은 Ŝ에만 존재하고, Ĵ는 점수 *차이(separations)*만을 사용하므로 두 컴포넌트가 동일한 낙관적 기대를 중복 계산할 수 없어요.

#### 2.3.3 정규화

세 컴포넌트는 서로 비교 불가능한 척도를 가지므로, 각 정적 컴포넌트는 후보 세트 전체에서의 95번째 백분위수 값으로 나누어져요(최댓값은 `EDV_NORM_CAP = 4.0`로 제한됨). 세 가지 정규화 인자는 `metadata.edv_parameters.normalizers`에 포함되어 제공되므로, 공개된 모든 EDV 값은 자체 아티팩트에서 다시 도출할 수 있어요.

#### 2.3.4 조립

정렬 순서는 map 모드와 완전히 동일한 지연 탐욕적 추적(lazy-greedy trace)이에요. 순서에 의존하는 모든 승수(서베이 참신성, 판정 배치 감쇄)는 항목이 배치됨에 따라 단조 비증가하므로, 오래된 힙 엔트리는 과대평가만 할 수 있어요. 따라서 지연 탐욕 불변성이 유지되며 추적 결과는 무차별 탐욕(brute-force greedy)과 동일해요. 프론티어 인터리브, 프리뷰 정책 및 예산 티어는 그대로 적용돼요.

#### 2.3.5 설명 가능성

모든 항목은 자체 진단 정보에 크레딧이 부여된 대조 목록(파트너, 상태, 예측 분리도, 순위 가중치), 시드 및 감쇄 항, 모든 §2.2 및 §3 필드, 가중치와 정규화 인자를 유지해요. 따라서 공개된 EDV 값은 해당 행에서 정확하게 다시 계산할 수 있어요. 외부 상태 없이도 "이 항목이 어떻게 이 순위를 얻었는가?"라는 질문에 답할 수 있어요.

#### 2.3.6 채택 기준

동일한 보드에서 `map` 및 `ecv`와 측정을 통한 비교를 거친 후에만 `edv`이 공개 기본값이 돼요. 모든 서베이 지표(첫 관측 깊이 백분위수, 깊이별 고유 언어 쌍/언어/어족 수, 한계 신규 언어 쌍 비율)에서 map 대비 10% 이내여야 하고, 두 판정 지표(시뮬레이션된 $1k당 해결된 경합 대조 수, 고정 지출 시 방법 순위 복원력) 모두에서 확실히 우수해야 하며, 비용(달러)당 메시 성장률이 map보다 나쁘지 않아야 해요. 비교 보고서는 전환과 함께 공개돼요.

## 3. 한 번의 실행이 지니는 가치

### 3.1 실행 전에 점수 예측하기

실행되지 않은 (쌍, 모델, 조건)의 예상 점수는 의도적으로 단순하고
완전히 검사 가능한 합이에요 — 양방향 주효과 예측에 구조화된 낙관성을
더한 것으로, 모든 항이 항목에 게시돼요.

```
ŝ = clip( pair_prior + model_offset + condition_offset + exploration_bonus,  0, S_CAP )
```

- **`pair_prior`** — 게시된 강도에 대한 계층적 백오프: 이 쌍의
  평균 → 이 대상 언어의 평균 → 이 소스 언어의 평균 → 전역 평균 →
  `S0_FALLBACK`. 사용된 수준은 `prior_basis`로 게시돼요.
- **`model_offset`** — 이 모델이 같은 쌍의 *다른* 모델들에 비해
  어떻게 수행하는지를, 비교가 존재하는 모든 쌍에 대해 평균낸 값.
  본 적 없는 모델은 0이에요.
- **`condition_offset`** — 같은 쌍에서 관찰된 coached 빼기 naive
  델타(같은 대상 언어로 백오프), 그 외에는 **0**: coaching 이득은
  측정된 곳에서는 실재하지만 언어 간 전이된다고 가정하지 않으므로,
  근거 없는 쌍에서는 baseline 우선 관례가 유지돼요.
- **`exploration_bonus`** — 불확실성에 직면한 낙관성, UCB1 스케줄
  (Auer, Cesa-Bianchi & Fischer 2002):
  `κ·sqrt(2·ln(1+N)/(1+n))`, 여기서 N은 게시된 점수 매겨진 실행의 총
  개수이고 n은 이 (쌍, 모델)에 대한 개수예요. 한 번도 시도되지 않은
  셀은 가장 큰 보너스를 받고, 잘 측정된 셀은 0으로 감쇠해요.
  우리는 스케줄을 차용해요 — 탐색이 부족한 암을 적절한 비율로 다시
  부상시키는 형태를 — 정상(stationary) 밴딧을 가정하는 후회 정리는
  아니에요. 이 시스템은 그런 밴딧이 아니거든요.

### 3.2 메시 이득, 닫힌 형식으로

실행은 자신의 쌍의 엣지를 `s' = max(s(e), ŝ)`로 올림으로써만 메시를
개선할 수 있어요. 단일 엣지 변경의 경우, 임의의 두 언어 사이의 새로운
최선 체인은 새 엣지를 무시하거나 정확히 한 번 사용하므로, 업그레이드된
행렬 — 따라서 ΔΦ — 은 정확한 한 줄 형식을 가져요(전체 그래프를 다시
풀 필요 없음).

```
Q'(u,v) = max( Q(u,v),  E(u,a)·s'·E(b,v),  E(u,b)·s'·E(a,v) )

E(x,y) = λ·Q(x,y) for x ≠ y;  E(x,x) = 1        (edge e = {a, b})

ΔΦ = mean over ordered pairs of (Q'(u,v) − Q(u,v))
```

E는 "새 엣지의 끝점까지의 최선 체인으로, 거기에 이어 붙이기 위해
접합부 비용을 지불한 것"이며, 두 항은 엣지를 가로지르는 두 방향이에요.
이는 하네스 스위트에서 Φ의 무차별 재계산에 대해 테스트돼요.

현재 엣지 강도를 능가할 수 없는 예측은 ΔΦ = 0을 산출해요. 공식은
입증된 것을 재측정하는 것이 아니라 미지의 것을 확인하는 데 기부자의
돈을 써요. (탐색 보너스는 약하거나 표본이 부족한 셀이 영원히 굶주리는
것을 막아줘요.)

### 3.3 무엇이 증거로 간주되는가 vs. 무엇을 큐에 올릴 수 있는가

두 개의 서로 다른, 의도적으로 비대칭적인 게이트예요.

- **증거**는 *모든* 게시된 비실격 실행에서 나와요 — 공개적으로 큐에
  올릴 수 없는 코퍼스(예: 비상업 라이선스 세트)에서의 실행도
  포함해서요. 어떤 쌍에 대한 게시된 측정은, 재실행할 수 있든 없든
  지식이에요.
- **행동**(큐 항목)은 공개적으로 실행 가능한 코퍼스에서만 나와요.
  개발 분할, CC-BY 계열 라이선스, 누구나 가져올 수 있음.

큐에 올릴 수 없는 코퍼스를 통해서만 도달 가능한 언어도 여전히
그래프에 있어요. 그 언어 *주변*의 엣지를 개선하면 그들의 체인 값이
변하며, 공식은 이를 반영해요.

## 4. 매개변수

| 매개변수 | 기본값 | 의미와 근거 |
|---|---|---|
| `λ` (`lambda_junction_discount`) | **0.9** | *추정* 체인의 접합부당 충실도 유지율. "직접 측정이 곱셈 동등 체인을 능가한다"를 인코딩함(Utiyama & Isahara 2007; Wu & Wang 2007; Fan et al. 2021). 약 10% 삭감은 보정 선택이며, 측정된 체인 삼각형이 쌓임에 따라 재검토됨(§6). |
| `κ` (`kappa_exploration_scale`) | **0.05** | 강도 단위로 표현된 탐색 보너스 척도. 0.05 ≡ 5 chrF++ 점 — 100개 미만 항목 코퍼스에서 점수 차이가 구분되지 않는 노이즈 하한([Corpus Design §6.3](/docs/network/specifications/corpus-design)). 낙관성은 측정 기구의 해상도에서 상한이 설정됨. |
| `S_CAP` | **0.95** | 예측 상한 — 어떤 추정 엣지도 입증하지 않은 거의 완벽한 충실도를 주장할 수 없음. |
| `S0_FALLBACK` | **0.5** | 최후의 수단으로서의 쌍 사전값(prior). 게시된 결과가 전혀 없을 때만 사용됨(관찰된 전역 평균 — 첫 429회 실행에 걸쳐 ≈ 0.54 — 이 결과가 하나라도 존재할 때마다 선호됨). |
| `COST_FLOOR` | **$0.01** | ECV 분모의 하한이므로, 거의 무료인 실행이 달러당 무한한 가치를 주장할 수 없음. |
| `N_FULL` | **100** | 완전한 크기 인정을 위한 평가된 항목(§1.5). |
| `L_HEALTHY` | **5.0** | 완전한 풍부도 인정을 위한 유효 단어(§1.5). |
| `H_NOISE` | **±5 chrF** | 완전한 신뢰도 인정을 위한 CI 절반폭; 누락된 CI는 50/√n으로 프록시됨(n=100에서 ±5에 고정). |
| `RUNS_FULL` | **2** | 완전한 복제 인정을 위한 게시된 실행. |

**버저닝.** 매개변수나 공식 변경은 `formula_version`
(메타데이터)와 이 페이지의 버전 줄을 올려요. 큐는 현재 Φ를 포함해
`metadata.priority_parameters`에서 사용된 정확한 값을 항상 다시 표시하므로, 과거
큐도 해석 가능한 상태로 남아요. 민감도 실행은 플래그 하나면 돼요.
`generate_sweep_queue.py --lam 0.8 --kappa 0.1`.

## 5. 검증된 예시 (라이브 값, 2026-06-12)

점수 매겨진 실행 424회, 측정된 엣지 59개, 언어 60개에 대한 생성;
**Φ = 0.272**. 최상위 항목:

```
eng>fao · claude-haiku-4.5 · naive
  edge_strength        0.0      (no published eng→fao runs)
  pair_prior           0.613    basis: target-language (Faroese runs exist via dan→fao)
  model_offset        −0.114    (haiku trails other models on shared pairs)
  condition_offset     0.0      (no coaching evidence for fao)
  exploration_bonus   +0.174    (never-run cell: κ·√(2·ln 425 / 1))
  predicted_strength   0.673
  expected_mesh_gain   0.0181   (eng→fao is a near-component join)
  est_cost_usd         0.0101
  ecv_per_usd          1.79     ← rank #1
```

다시 읽어보면: 페로어는 덴마크어를 통해서만 메시에 연결되어 있으므로,
측정된 eng→fao 엣지는 거대한 체인 계열을 단축시켜요(큰 ΔΦ); 모델은
이와 같은 쌍에서 중간 정도로 예측되고(사전값 + 오프셋), 아무도 이 셀을
시도한 적이 없으며(큰 보너스), 실행 비용은 1센트예요. 큐의 다른 어떤
것도 달러당 더 많은 메시를 사주지 않아요. 모든 입력값이 게시된 채로
같은 산술이 다른 모든 순위를 만들어내요.

## 6. 알려진 한계 (그리고 무엇이 이를 고칠 것인가)

1. **chrF++는 언어 간에 비교 가능하지 않아요.** 형태론이 척도를
   이동시켜요. 바스크어로 가는 0.5 엣지는 네덜란드어로 가는 것과
   같은 성취가 아니에요. 완화: 우선순위는 척도 효과가 이차적인
   *구조*(s = 0 → s > 0 전환)에 의해 지배돼요. 해결: 언어별 점수
   정규화, 또는 이러한 언어에 사용 가능해지는 더 나은 교차 언어
   보정을 가진 메트릭.
2. **곱셈-λ 체인 모델은 사전값이지 측정이 아니에요.** 피벗 문헌에
   의해 방향성 있게 뒷받침되지만 LLM 번역에 대해서는 보정되지
   않았어요. 해결(계획됨): 메시는 이제 측정된 삼각형을 포함하므로
   (예: deu→eng→fra와 함께 deu→fra 직접), 체인 출력을 직접 점수
   매기고 λ를 선택하는 대신 데이터에 맞출 수 있어요.
3. **오염과 개발 세트 상태.** 엣지 강도는 공개 개발 세트의 모든
   주의사항을 물려받아요 — Φ를 역량 주장이 아니라 상한선 계획 신호로
   취급하세요
   ([Corpus Design](/docs/network/specifications/corpus-design)).
4. **도메인 맹점.** 대화 텍스트에서 측정된 엣지는 하나의 수치로
   취급돼요. 도메인을 가로지르는 체인은 λ가 예측하는 것보다 더
   저하될 거예요.
5. **방향성.** 엣지는 현재 무방향이에요(X→Y 증거가 X↔Y를 밝힘).
   체인 합성이 실제로 방향에 민감해지면 강도는 방향별로 분할돼요 —
   공식은 변하지 않고, 그래프만 두 배가 돼요.
