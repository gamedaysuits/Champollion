# 큐 구성 명세

**공식 버전: `ecv-v3` (브리지 신뢰도를 반영한 예상 체인 값).**
이 문서는
[champollion.dev/queue.json](https://champollion.dev/queue.json)이
어떻게 정렬되는지를 규정하는 표준 정의예요. 구현체
(공개 하네스 저장소의 `arena/scripts/generate_sweep_queue.py`)는 이 페이지를
섹션별로 그대로 반영하며, 큐의 메타데이터는 생성 시점에 사용된
정확한 매개변수 값을 다시 표시하고, **모든 항목은 전체 공식 분해
내역을 포함**하므로, 어떤 순위든 게시된 JSON만으로 직접 다시 도출할
수 있어요. 이 페이지와 큐가 서로 어긋난다면 그건 버그이니
신고해 주세요.

**오늘날의 대기열을 한 문단으로 요약해요.** 공개 대기열은 LLM 항목(단순(naive) 및 코칭(coached) 프롬프팅 조건)과 MT 서비스 엔진 항목을 하나의 보드에 담아 설문조사 순서(`map`, §2.2)에 따라 순위를 매겨요. 달러당 언어 쌍, 언어, 어족에 걸친 최초 측정(first light)을 우선시하며, 한 번도 측정된 적 없는 언어에 대한 최초 읽기 부스트(first-reading boost)(§2.2), 미리보기에 게시된 예산 계층(§2.1.1), 그리고 데이터베이스에서 제공되는 전체 순위(전체 순위가 크기 제한을 초과할 경우 정적 파일은 상위 슬라이스만 포함하며 이를 명시함)를 제공해요. 아래 섹션은 날짜가 지정된 결정 이력과 함께 유지되는 규범적 정의(normative definition)예요. 제공되는 모든 대기열의 메타데이터는 순위를 매긴 정확한 매개변수를 명시해요.

> **v3 (2026-06-13).** 이제 모든 엣지는 품질과 신뢰도라는 두 개의
> 수치를 가진 *브리지*이며, 체인 행렬은 이 둘의 곱으로 동작해요
> (§1.5). 한 번만 실행된 62개의 단일 단어 어휘 항목은 더 이상
> 경로처럼 보일 수 없으며, 복제, 더 큰 코퍼스, 더 풍부한 코퍼스,
> 더 좁은 신뢰 구간 모두 값이 매겨진 가치를 지녀요. v2 큐
> (품질 전용)는 자체 메타데이터를 통해 해석 가능한 상태로
> 남아 있어요.

## 1. 목표: 품질 가중 메시

미션은 *측정된 개별 쌍 체인을 통한 모든 언어에서 모든 언어로의
번역*이에요. 직접적인 벤치마크가 없는 두 언어 간 번역은 벤치마크된
쌍들을 **연결(chaining)**하여 처리하므로(X→피벗→Y), 벤치마크의
가치는 코퍼스 수가 아니라 **그래프의 체인 용량**에 달려 있어요.

**정의.** *벤치마크 그래프*가 언어당 하나의 노드를 가지고, 게시된
비실격 실행이 하나 이상 있는 모든 언어 쌍에 대해 **엣지 강도**를
가진다고 해요.

```
s(e) = (best published corpus-level chrF++ on that pair) / 100   ∈ [0, 1]
```

코퍼스 수준 chrF++가 표준 게시 수치예요
([Scoring Specification](/docs/network/specifications/scoring) 참조).
*최선(best)*인 이유는 체인이 각 홉마다 가장 잘 입증된 시스템을 통해
경로를 잡기 때문이에요. 게시된 실행이 없는 쌍은 s(e) = 0이에요.

두 언어 사이 경로 P의 **추정 체인 강도**는 다음과 같아요.

```
strength(P) = λ^(|P|−1) · Π_{e ∈ P} s(e)
```

— 엣지 품질은 곱셈적으로 결합되며, 각 *접합부*(각 중간 피벗)는
추가적인 충실도 계수 **λ < 1**의 비용을 발생시켜요. 두 선택 모두
피벗 번역 문헌에 근거해요. 피벗을 통한 번역은 단순 합성이 시사하는
것 이상으로 직접 번역 대비 품질을 안정적으로 잃으며(Utiyama &
Isahara 2007; Wu & Wang 2007), 손실의 크기는 선택된 피벗에 따라
달라지고(Paul et al. 2009), *직접적인* 비영어 중심 쌍을 구축하는
것이 대규모에서 영어 피벗 방식을 측정 가능하게 능가하는데 —
M2M-100의 다대다 설정에서 약 10 BLEU만큼이에요(Fan et al. 2021).
λ는 추정 체인이 측정이 아니라는 점을 상기시키는 공식의 상수예요.
직접 실행만이 이 할인을 제거해요.

그러면 **최선 체인 행렬**과 **메시 목표**는 다음과 같아요.

```
Q(u,v) = max over paths P from u to v of strength(P)      (1 if u = v, 0 if disconnected)

Φ = mean over ordered language pairs (u ≠ v) of Q(u,v)    ∈ [0, 1]
```

Q는 표준 로그 변환 하의 최단 경로 문제로 정확히 계산돼요
(엣지 가중치 −ln(λ·s(e)) ≥ 0, Dijkstra, 그 다음
Q = exp(−d)/λ). Φ는 [Latora & Marchiori
(2001)](https://arxiv.org/abs/cond-mat/0101396)의 *전역 효율성*
구성에서 1/거리 커널을 곱셈적 체인 충실도로 대체한 것이며 — 이는
엣지가 단위 길이가 아니라 홉당 품질 유지율을 지닐 때 자연스러운
커널이에요. (큐 v1은 가중치 없는 전역 효율성 이득으로 순위를
매겼는데 — 엣지에 대해 아는 것이 존재 여부뿐인 이 계열의 특수한
경우예요.)

### 1.5 신뢰도: 브리지는 (q, r)

작고 얇으며 한 번도 복제된 적 없는 코퍼스에서 나온 화려한 점수는
브리지가 아니에요. 따라서 v3은 측정된 모든 엣지를 다음과 같이
분할해요.

```
quality      q(e)   = best published corpus-level chrF++ / 100
reliability  r(e)   = f_size · f_rich · f_conf · f_repl        ∈ [0, 1]
effective    s_eff(e) = q(e) · r(e)        ← what chains compose over
```

| 계수 | 정의 | 완전 인정 기준 | 근거 |
|---|---|---|---|
| `f_size` | min(1, n/100), n = 최선 실행의 평가된 항목 수 | 항목 100개 | [corpus-design](/docs/network/specifications/corpus-design)의 유의성 하한; Koehn (2004)은 약 300문장 세트에 대한 부트스트랩 테스트를 검증함 — 300개조차 "작은" 수준이므로, 크기는 단순히 표시를 막는 것이 아니라 신뢰도를 할인함 |
| `f_rich` | min(1, L̄/5), L̄ = 평균 *유효* 소스 길이 | 유효 단어 5개 | AmericasNLP (Mager et al. 2021)는 단어 수준 단위가 풍부한 형태론에서 깨지기 때문에 chrF를 채택; Mager et al. (2022)은 공백 토큰을 잘못된 단위로 기록함 |
| `f_conf` | min(1, 5/h), h = 최선 실행의 chrF 95% CI 절반폭 (게시되지 않은 경우 프록시 `50/√n`) | CI ≤ ±5 chrF | 작은 코퍼스에서 델타가 구분되지 않는 노이즈 하한; Kocmi et al. (2021)은 CI 내 델타가 인간 선호와 자주 모순됨을 보임 |
| `f_repl` | min(1, runs/2) | 게시된 실행 2회 | Marie, Fujita & Rubino (2021), 769개 논문 메타 평가: 복제되지 않은 단일 비교는 이 분야의 기록된 신뢰성 실패임 |

**유효 길이**는 공백 단어가 아니라 콘텐츠 단위로 측정해요.
`L̄ = mean source chars / c(L)`이며, 여기서 *문자 경제성*
`c(L)`은 정렬된 측면의 영어 단어당 언어 L 측면의 중앙값
문자 수로, 이 프로젝트 자체의 병렬 코퍼스에서 측정해요
(v3 출시 시점 기준 7,400개 이상의 정렬된 항목: cmn 1.6, jpn 2.3,
kor 2.6; eng 기준선 5.0; deu 6.0; crk 4.7 — 다종합 단어는 그것이
담은 콘텐츠로 값이 매겨짐). 유형론 조회 테이블은 없으며, 추정치는
코퍼스가 커짐에 따라 정밀해지고, eng 쌍 데이터가 없는 언어는 기본
경제성을 사용해요. 레지스트리에서 코퍼스별로 기록돼요
(`richness` 블록).

**브리지 등급**(표시 용어): **established** — n ≥ 100,
L̄ ≥ 5, h ≤ 5, runs ≥ 2; **provisional** — 측정되었으나 어느 하나라도
미달; **registered** — 게시된 실행 없음. 체인 주장("X에서 Y로 갈 수
있다")은 가장 약한 홉의 등급만큼만 강하며, 메시 시각화는 신뢰도를
엣지 불투명도로 표시해요.

**검증된 확인**(v3 출시 전에 실행되는, 커밋된 검증 스크립트에서):
*단일 단어 어휘 항목 62개, 1회 실행* → r ≈ **0.04**
(경로 아님); *200문장, ±3 CI, 3회 실행* → r = **1.00**; 순진한 단어
수가 1.0(스크립트 아티팩트)인 101개 항목의 일본어 코퍼스는 유효
단어 6.5개와 완전한 `f_rich`로 복구돼요.
경계와 계수별 단조성은 속성 테스트로 검증돼요.

**v3에서의 실행 가치.** 실행은 브리지를 두 가지 방식으로 개선할 수
있으며, ΔΦ는 둘 중 더 나은 것을 취해요. **(a)** 그것이 엣지의 최선
실행이 됨 —
`ŝ_eff = 예측 품질 × r(그 코퍼스의 n, 풍부도, CI 프록시,
runs+1)`; 또는 **(b)** 단지 복제만 함 — 현재 최선이 유지되고,
`f_repl`가 상승함. 따라서 단일 실행 엣지에 대한 복제는 실제로
값이 매겨진 가치이며, 측정된 쌍에서 더 크거나 더 풍부한 코퍼스가
작은 것의 재실행보다 우선해요. 항목은 `edge_quality`,
`edge_reliability`, `edge_tier`, `effective_strength`,
`post_run_reliability`, `predicted_effective`을 v2 예측 필드와 함께 노출해요.

**Φ가 아닌 것.** Φ는 큐의 내부 우선순위 결정 통화이지, 역량 주장이
아니에요. 그 입력값은 [Corpus Design
Framework](/docs/network/specifications/corpus-design)의 모든 주의사항을
지닌 개발 세트 점수예요. 가능한 훈련 데이터 오염으로 인해 각 점수는
상한선이고, chrF++ 값은 언어 간에 엄밀히 비교 가능하지 않으며, 작은
코퍼스는 넓은 신뢰 구간을 지녀요. 공식은 Φ가 *유용성에 따라 실행을
정렬*하기만 하면 되며, 결코 품질 보증으로 게시되지 않아요.

## 2. 결정 문제

대기열의 열린 항목(open items)은 적격하고(개발 분할(development split), 재배포 가능한 라이선스, 격리되지 않음, 전송 가능, 그리고 **벤치마크 해결 가능(benchmark-resolvable)** — §2.2의 언어 식별 게이트 참조) 아직 리더보드에 없는 모든 (코퍼스, 모델, 조건) 조합이에요. 이미 다룬 조합의 동일한 재실행은 제외되지만(게시 시 런 카드(run-card) 지문이 중복을 제거함), 이미 측정된 쌍에 대한 새로운 모델이나 조건은 열린 항목으로 유지돼요.

기여된 연산은 예산이에요. 메시가 가장 빠르게 개선되도록 다음에
실행할 열린 항목을 고르는 것은 예산이 제한된 커버리지형 최대화
문제이며, 표준적인 접근은 **단위 비용당 한계 가치**에 따른 탐욕적
선택이에요. 단조 서브모듈러 목표에 대해 탐욕 규칙은 고전적인
(1 − 1/e) 보장을 수반하며(Nemhauser, Wolsey & Fisher 1978), 그
편익/비용 비율 형식은 예산 하에서의 표준 알고리즘이에요(Khuller,
Moss & Naor 1999). 우리는 이 비율 규칙을 순위 결정 원칙으로 사용해요.
(솔직한 참고: 우리의 목표는 결정론적 핵심에서 커버리지와 유사한
수확 체감을 보이지만, 확률적 예측 계층 때문에 우리는 탐욕 보장을
이 정확한 시스템에 관한 정리가 아니라 *동기*로서 인용해요.)

```
ECV(item) = ΔΦ(item) / max(est_cost_usd, COST_FLOOR)
```

항목은 ECV 내림차순으로 순위가 매겨져요. 동점 시: naive가 coached
보다 먼저, 더 저렴한 것이 먼저, 그 다음 항목 id 순이에요.

### 2.1 순위 보정 — 2026-07-12

탐욕적 ECV 규칙 위에 네 가지 조정이 계층적으로 적용되며, 각각은
큐의 메타데이터에 반영돼요 (`priority_parameters.contamination_ecv_factors`,
`priority_parameters.frontier_interleave`, `metadata.preview_policy`):

1. **오염 배수(Contamination multiplier).** 각 항목의 ECV는 해당
   코퍼스의 오염 등급에 따른 계수로 곱해져요: **LOW 1.0 / MEDIUM
   0.4 / HIGH 0.1**이며, 알 수 없거나 누락된 등급은
   MEDIUM으로 처리돼요(절대 깨끗하다고 가정하지 않음). 근거: 깨끗한
   체인 그래프는 LOW 오염 엣지만 허용하므로, LOW가 아닌 실행은
   그 그래프에 진입할 수 없고 동일 비용에서 깨끗한 메시 작업보다
   높은 순위를 차지해서는 안 돼요. LOW가 아닌 항목도 큐에
   남아 있어요 — 상대 레인 비교는 실질적인 가치이기 때문이에요 — 다만
   깨끗한 작업보다 뒤에 순위가 매겨질 뿐이에요.
2. **프론티어 인터리브(Frontier interleave).** 탐욕적 정렬 이후,
   매 5번째 우선순위 슬롯에는 프론티어 모델 집합(생성기 내에서
   데이터로 유지되고 메타데이터에 반영됨) 중 아직 배치되지 않은
   최상위 항목이 배치돼요. 그래서 프론티어 근거가 저렴한 계층이
   포화된 후에만 도달하는 것이 아니라, 예측 사전 확률에
   일찍 도달하게 돼요. 순수한 재정렬이에요: 어떤 것도 삭제되거나
   중복되지 않고, 자연스러운 슬롯을 얻은 프론티어 항목은 그것을
   유지하며, 우선순위는 짜인 순서로 번호가 매겨져요 — 공개된
   순위가 곧 진실이에요.
3. **프리뷰 소스 허브 상한(Preview source-hub cap).** 상위 25개
   공개 프리뷰는 하나의 소스 언어를 공유하는 항목을 최대 **6**개까지만
   표시해요. 그래서 자원이 풍부한 단일 허브가 진열창을 독점할
   수 없어요. 상한을 초과한 항목은 전체 큐에서 실제 우선순위를
   유지하며, 프리뷰는 단순히 순위 순서상 다음으로 적격한 항목을
   가져와요.
4. **프리뷰 인공어 제외(Preview constructed-language exclusion).**
   소스 또는 대상이 인공어인 항목은 프리뷰에서 건너뛰어져요. 이
   판정은 카드 패밀리 기반이에요(언어 카드에서 읽어들이는
   Glottolog의 Artificial Language 분류 — 하드코딩된 언어
   집합이 아님). 그리고 파생된 코드 목록은
   `metadata.preview_policy`에 게시되므로 서버 측 새로 고침도 동일한
   선택을 적용해요.

(3)과 (4)는 **표현 정책일 뿐이에요**: 전체 `queue.json`,
그 순위, 그리고 우선순위는 영향을 받지 않아요.

### 2.1.1 예산 계층 — "$X로 무엇을 얻을 수 있나요?" (2026-08-24)

`queue-preview.json`은(는) **$1 / $10 / $100 / $1000**의 예산에 대해 게시된 순위의 탐욕적 감당 가능 접두사(greedy affordable prefix)를 요약하는 `budget_tiers` 배열을 포함해요. 우선순위에 따라 항목을 순회하며, 예상 비용이 예산에 맞는 각 항목을 취하고, 그렇지 않은 항목은 건너뛰며, 나중에 나오는 더 저렴한 항목으로 계속 채워요. 각 계층은 해당 예산으로 구매할 수 있는 항목 수, 총 예상 비용, 다루는 고유한 언어 쌍과 모델 수, 그리고 예산이 순위에서 얼마나 깊이 도달하는지(`max_priority`)를 보고해요.

순위는 이미 비용 대비 한계 가치(marginal-value-per-cost)(§2)를 따르기 때문에, 탐욕적 감당 가능 접두사는 이 모델이 해당 지출에 대해 권장하는 할당 **그 자체**예요. 소규모 기여자든 대규모 기여자든, 아무에게도 맞지 않게 암묵적으로 크기가 정해진 하나의 목록이 아니라, 동일하게 게시된 순위에서 구체적이고 최적화된 답변을 읽을 수 있어요. 계층은 요약일 뿐이며, 할당 자체는 자신의 예산에 맞춰 순서대로 순회하는 순위일 뿐이에요. 서버 측 새로고침은 동일한 순회 방식을 사용하여 남은 항목들에 대해 계층을 다시 계산해요(생성기와 새로고침 함수는 이를 쌍둥이처럼 구현하며, 양쪽 모두에서 테스트돼요).

### 2.2 레인(Lanes) 및 순위 모드 — 2026-07-19

제공되는 대기열은 자체 메타데이터에 어떤 **레인(lane)**을 포함하고 어떤 **순위 모드(ranking mode)**로 정렬되었는지 선언해요. 메타데이터가 기준이 되며, 이 섹션에서는 관련 용어를 정의해요.

**레인(Lanes)** (`metadata.lane`, `metadata.lane_policy`). 2026-08-27부터 공개 대기열은 **both** 레인을 포함해요. 즉, LLM 항목(모델 × 프롬프팅 조건)과 **더불어** MT 서비스 항목(조건 `engine` — DeepL, Google Translate, Microsoft Translator, LibreTranslate, Tilde; 각각 자체적으로 게시된 커버리지 목록 내의 쌍에 대해서만 대기열에 추가됨)을 모두 다뤄요. 2026-07-19의 **llm** 레인(LLM 항목만 포함하며, 적어도 한쪽이 모든 MT 서비스의 게시된 커버리지 밖에 있는 쌍으로 제한됨)은 실행되지 않은 주최자 운영 캠페인을 위해 서비스 벤치마킹을 보류했고, 이로 인해 카탈로그의 대부분이 묶여 있었어요. 서비스를 측정하는 것 *자체가* 커버리지 맵의 중추이므로, 이제 두 종류의 작업이 하나의 보드에 놓이게 돼요. 커버리지 합집합(언어 카드를 통해 대언어(macrolanguage)로 별칭 지정됨)은 여전히 `service_coverage_methods` 및 `service_covered_languages`(으)로 표시되며, llm 레인 대기열은 제외된 쌍을 여전히 `pairs_dropped_fully_covered`(으)로 보고해요.

**Blob 크기 제한** (2026-08-27). 제공되는 `queue.json`은(는) 엄격한 호스팅 한도가 있는 정적 파일이므로, 전체 순위가 이 크기를 초과하면 파일은 순위의 **상위 슬라이스(top slice)**만 포함하며 이를 `metadata.blob_truncated {kept, total}`에 명시해요. 절대 조용히 제한하지 않아요. 데이터베이스 대기열(`queue_top()` / `queue_pairs()`)은 항상 **전체** 순위를 제공하며 권위 있는 작업 목록(work-list) 역할을 해요. 미리보기의 쌍 집계 및 예산 계층은 함께 제공되는 아티팩트를 설명해요.

**언어 식별 게이트** (2026-07-19). 대기열 항목은 **활성 상태의 개별 ISO 639-3 코드**만을 대상으로 해요. 대언어("Arabic")나 집합적 어족 코드("Berber languages")에 대한 점수는 평가된 적 없는 변종에 대한 반증 불가능한 주장이 될 수 있기 때문이에요(FLORES-200/NLLB가 데이터를 `arb`/`quy`/`zsm`(으)로 코딩하는 것과 같은 논리예요). 업스트림 코퍼스 레이블은 *해결(resolved)*되며, 절대 그대로 따르거나 폐기되지 않아요. 스크립트 태그는 기계적으로 제거되고(`eng→cmn-Hans` 코퍼스는 `eng→cmn`(으)로 대기열에 추가되며, 스크립트는 항목 표시 메타데이터 `source_script`/ `target_script`(으)로 유지됨), 완전히 폐기된 코드는 공식 ISO 후속 코드를 따르며, 매크로 레이블이 지정된 코퍼스는 레지스트리 항목에 기록되고 인용된 **변종 해결(variety resolution)** 하에서만 대기열에 추가돼요(예: FLORES+는 Quechua를 `quy`(으)로 문서화함). 두 경로 모두에서 해결되지 않는 코퍼스는 `metadata.doctrine_exclusions`(총계, 사유별 개수, 코퍼스별 사유)에 게시된 기계 판독 가능한 사유와 함께 제외되며 사막 원장(desert ledger)(`service_landscape.invisible_reasons.corpus_excluded_by_doctrine`)에 집계돼요. 즉, 명시적으로 제외될 뿐 조용히 누락되지 않아요. 포괄적 레이블이 지정된 코퍼스에 대한 과거 결과는 정직하게 명명된 자체 메시 노드(노드 `scope`: `macrolanguage` / `collective` / `retired`)를 유지하며, 절대 구성원 변종으로 병합되지 않아요. 해결 입력값은 모두 게시돼요. 레지스트리의 항목별 `language_resolution` 스탬프에는 해결된 코드, 범위, 고정된 인용(pin citations)이 포함돼요.

**순위 모드** (`metadata.rank_mode`, `metadata.priority_model`에 설명됨). 동일한 항목에 대한 두 가지 정렬 방식이에요.

- **ecv** — §2–§3의 탐욕적 예상 체인 가치(expected-chain-value) 규칙이에요. 예상 달러당 메시 개선을 의미해요. 활용(exploitation) 정렬 방식이며, 보드가 예측과 ΔΦ가 신호를 전달할 만큼 충분히 밀집되어 있을 때 적합해요.
- **map** (map-value v2) — 설문조사 정렬 방식이에요. `MapValue = novelty × uncertainty × promise × connectivity × corpus-quality × contamination ÷ cost`로 계산되며, 정확한 탐욕적 추적(greedy trace)을 통해 조립돼요. *Novelty(참신성)*는 위치 기반 최초 측정(first-light) 크레딧으로, 이미 배치된 항목이 동일한 방향성 쌍(1/(1+n)), 타겟 언어, 타겟 어족, 방법 × 타겟 어족 셀, 타겟 × 도메인 셀(각각 1/√(1+n); 어족은 언어 카드에서, 도메인은 코퍼스 레지스트리의 분류 체계에서 가져옴 — 타겟의 초기 커버리지는 처음 측정된 도메인을 반복하는 것이 아니라 레지스터 전반에 걸쳐 분산되어야 함)을 차지함에 따라 감소해요. *Uncertainty(불확실성)*는 §3.1 예측의 백오프 깊이(쌍 0.25 · 타겟 언어 0.55 · 소스 언어 0.75 · 글로벌 1.0) × 1/(1+에지에 게시된 실행 수)예요. *Promise(가능성)*는 §3.1의 예측 강도로 하한선이 0.25예요. 작동할 가능성이 높은 미지의 항목이 우선시되며, 가능성 있는 사막을 매핑하는 것 역시 가치를 지녀요. *Connectivity(연결성)*는 **측정된 네트워크를 아직 도달할 수 없는 언어와 연결하는** 쌍의 순위를 높여요. 엔드포인트는 측정된 메시 에지(`mesh.json`, 상태 `measured`)에 있거나 MT 서비스의 게시된 커버리지 목록(대언어 별칭 지정, 위의 레인 게이트와 동일한 별칭 지정) 내에 있을 때 *확립된(established)* 것으로 간주돼요. **브릿지(bridges)**(정확히 하나의 확립된 엔드포인트)와 **섬(islands)**(둘 다 아님)은 모두 1.0점을 받아요. 2026-08-27부터 단절된 사막의 최초 측정은 온전히 계산돼요(2026-07-19의 네트워크 확장(grow-out-of-the-network) 크기 조정에서는 섬이 0.5점을 받았으며, 이는 구조적으로 가장 깊은 꼬리 부분을 강등시켰음). 반면 **내부(interior)** 고밀도화(둘 다 확립됨)는 0.5점을 받아요. 알려진 지점 간의 강화를 담당하는 것은 ecv 모드의 역할이기 때문이에요. **최초 읽기 부스트(first-reading boost)**(×2.0)는 소스 또는 타겟 언어가 어디에도 게시된 측정값이 없는 항목의 설문조사 가치를 추가로 곱해줘요. 아홉 번째 원칙을 명확히 말하자면, **언어의 최초 읽기는 개선보다 우선순위가 높아요**. 불확실성 요소만으로는 이를 표현할 수 없어요(잘 측정된 두 언어 사이의 측정되지 않은 쌍을 한 번도 측정되지 않은 언어와 동일하게 채점함). 이 부스트는 롱테일의 최초 측정을 우발적인 결과가 아닌 명시적인 목표로 만들어줘요. 두 요소 모두 `metadata.map_value_parameters`에 의존하며 edv의 설문조사 구성 요소(§2.3) 내에서 동일하게 적용돼요.

  아홉 번째 원칙의 나머지 절반은 순위 **외부**에 존재해요. 기존 항목을 어떻게 정렬하든 코퍼스가 전혀 없는 언어(오늘날 약 7,500개의 살아있는 개별 코드 언어)에는 도달할 수 없어요. **코퍼스 위시리스트(corpus wish-list)**(`/corpus-wishlist.json`, 대기열 옆에 재생성됨)는 이러한 획득의 최전선을 게시해요. 코퍼스가 없는 살아있는 모든 개별 코드 언어를 가장 잘 인용된 화자 수(실제로 코퍼스를 구축할 수 있는 커뮤니티의 실현 가능성 지표로서의 화자 수)를 기준으로 순위를 매기며, 모든 수치는 출처가 명시되고 절대 임의로 조정되지 않아요.
  *Corpus-quality(코퍼스 품질)*는 §1.5의 코퍼스 고유의 신뢰성 잠재력 `f_size × f_rich`이에요. 설문조사는 무게를 견딜 수 있는 코퍼스에 안착해야 하므로, 62개 항목의 단일 단어 어휘 목록이 단지 저렴하다는 이유만으로 더 이상 헤드라인을 장식하지 않아요. 누락된 풍부함(richness) 측정값은 중립을 유지해요(측정값의 부재가 빈약함의 증거는 아님). 비용 및 오염 규율은 ecv와 동일해요. 최전선 인터리브(frontier interleave) 및 동점자 처리(tie-breaks)(§2.1)는 변경 없이 적용돼요. 설문조사 단계에 적합하게, 달러당 *맵이 학습하는 것*을 극대화해요. 즉, 분산되는 대신 측정된 네트워크에서 확장하여 쌍, 언어, 어족, 방법 셀, 도메인 전반에 걸친 최초 측정을 수행하며, 의도적으로 메시 강도 성장을 늦추는 대가를 치러요.

> **map-value v2 (2026-07-19).** 설립자의 지시에 따라 설문조사 정렬에 두 가지가 추가되었어요. *측정된 네트워크로 연결되는 브릿지* 역할을 하는 쌍이 이제 단절된 탐색 및 내부 고밀도화보다 높은 순위를 차지하며, 코퍼스 품질(크기 하한선 × 유효 풍부함, §1.5)과 타겟별 도메인 확산이 순위에 가중치를 부여해요. 기여자의 컴퓨팅은 무게를 견딜 만큼 충분히 좋은 코퍼스에서 확립된 경로를 새로운 경로와 연결해야 해요. 라이선스는 여전히 **가중치가 아닌 게이트(gate, not a weight)**로 남아 있어요. 라이선스 및 전송 채널 규칙은 무엇을 대기열에 추가할 수 있는지 결정하며(§2 및 대기열의 `transmission_note`), 적격한 코퍼스 중에서 순위는 라이선스를 따지지 않으므로 제한적이지만 고정된 연구 세트(종종 쌍의 유일한 코퍼스임)가 체계적으로 굶주리는 일은 결코 없어요. v1 대기열(참신성 × 불확실성 × 가능성만 포함)은 자체 메타데이터를 통해 여전히 해석할 수 있어요.

생성 시 사용된 정확한 요소 값은 `metadata.map_value_parameters`에 포함되어 제공돼요. 연결성 및 품질 입력값은 게시된 `mesh.json`(측정된 에지), 메타데이터에 반영된 서비스 커버리지 합집합, 그리고 `registry.json`(항목 수 + 풍부함)에서 다시 도출할 수 있어요. 모든 항목은 모드와 관계없이 전체 ecv-v3 진단 필드를 추가로 유지하므로, 동일한 아티팩트에서 두 정렬 방식을 모두 다시 도출할 수 있어요.

### 2.3 순위 모드 `edv` — 예상 결정 가치(expected decision value) (2026-08-27)

*상태: 구현됨, §2.3.6의 측정된 비교가 완료될 때까지 기본적으로 꺼져 있음. 그때까지 게시된 기본값은 `map`(으)로 유지됨.*

대기열은 정확히 두 가지 제품을 구매해요. **기능 맵(capability map)**(어떤 방법이 무엇에 능한지, 정직한 불확실성과 함께)과 **라우팅 메시(routing mesh)**(경로로 연결되는 측정된 쌍)예요. `edv`은(는) 가중치가 부여된 포트폴리오로서 각 후보 항목이 이 두 가지를 얼마나 발전시키는지에 따라 가격을 매겨요.

```
EDV(item) = [ w_judge·Ĵ + w_mesh·M̂ + w_survey·Ŝ ] × contamination ÷ max(cost, COST_FLOOR)
```

기본값은 `w_judge = 0.35, w_mesh = 0.25, w_survey = 0.40`이에요(설립자가 조정 가능하며, 모든 생성은 `metadata.edv_parameters`에서 실제로 사용된 가중치를 반영함). 오염 요소(§2.1 해결책 1)는 외부 승수로서 정확히 한 번 적용돼요. 라이선스 및 전송은 여전히 **가중치가 아닌 게이트**로 남아 있어요. 적격성은 가치가 계산되기 전에 결정되며, 순위는 적격한 코퍼스 중에서 라이선스를 따지지 않아요.

#### 2.3.1 Ĵ — 방법 판단 가치(method-judgment value)

실행이 **동일 코퍼스 방법 비교를 해결하는 데** 얼마나 기여하는지 가격을 매겨요. 이는 이 프로젝트 자체의 측정 연구가 허용하는 유일한 교차 방법(cross-method) 주장이에요. (W2 난이도 전이(difficulty-transfer) 연구는 언어 간 능력 연결을 거부했어요. 허용된 긍정적인 결과인 언어 내 가산적 방법 × 코퍼스 조정이 바로 이 구성 요소가 사용하는 것이에요. 점수는 정렬 및 분리에만 사용되며, 보정 파일럿(calibration pilot)에 따라 절대 수용 가능성 확률로 변환되지 않아요.)

후보(코퍼스 C, 방법 M, 조건)의 경우, **대조 파트너(contrast partners)**는 (C, 동일 조건)에 대해 이미 게시된 실행을 가진 방법 M′이에요. 각 파트너에 대해 `sep`은(는) 풀링된 CI 반너비(기록된 CI, 게시되지 않은 경우 프록시 `50/√n`)에 대한 chrF 포인트의 점수 분리이고, `sep_pred`은(는) §3.1 예측 점수에 대해 동일하게 계산된 값이에요.

| 쌍에 대한 {M, M′}의 대조 상태 | 크레딧 |
|---|---|
| **unmet(미충족)** — 아직 공유된 코퍼스 없음 | `JUDGE_FIRST = 1.0` |
| **contested(경합 중)** — 공유된 코퍼스가 존재하며, 모두 `sep < Z_DEC` | `JUDGE_CONTESTED = 0.8 × clip(sep_pred / Z_DEC, 0, 1)` |
| **decided(결정됨)** — 일부 `sep ≥ Z_DEC`, n_dec 코퍼스가 이를 결정함 | `JUDGE_DECIDED = 0.25 / (1 + n_dec)` |

각각에 `w_top = 1/√(rank(M)·rank(M′))`을(를) 곱해요. 1위와 2위를 결정하는 것이 7위와 8위를 결정하는 것보다 더 가치 있기 때문이에요. 쌍별 방법 순위는 쌍에 ≥2 방법 × ≥2 코퍼스가 측정된 경우 허용된 가산적 방법 × 코퍼스 적합(관찰된 셀에 대한 교대 최소 제곱법(alternating least squares))을 사용하고, 그렇지 않으면 방법별 최고 점수를 사용해요. 이 적합은 **엄격하게 쌍별로 이루어지며, 절대 언어 간에 풀링되지 않아요**. `Z_DEC = 1.96`.

동일한 (C, M)에 대한 코칭(coached) 대 단순(naive) 대조는 `JUDGE_COND = 0.5 / (1 + n_cond)`을(를) 추가해요. 항목의 대조는 수확 체감(추가 대조당 `JUDGE_GAMMA = 0.7`, 내림차순 정렬)과 함께 합산되며, 여기에 **시드 항(seed term)** `JUDGE_SEED = 0.25 × min(1, m_C/3) × corpus-quality`(m_C = C에 대기열 항목이 있는 다른 라인업 방법)이 더해져 빈 보드에서도 향후 비교를 판단할 수 있는 코퍼스를 선호하게 돼요. 이는 장소의 가치(venue value)이며, 결코 빌려온 점수가 아니에요. 조립하는 동안 판단(judge) 구성 요소는 `1/(1 + items already placed on the same pair and condition lane)` 감소해요.

#### 2.3.2 M̂ 및 Ŝ

`M̂`은(는) §3의 예상 메시 이득(ΔΦ)으로, 생성 시 체인 행렬이 고정된 상태로 변경되지 않아요. `Ŝ`은(는) §2.2의 map-value v2 핵심으로, 위치 기반 참신성 감소가 포함된 `uncertainty × promise × connectivity × corpus-quality`이며 변경되지 않아요. 예측 점수 *수준*(가능성)은 Ŝ에만 존재하고, Ĵ는 점수 *분리*만 사용해요. 두 구성 요소는 동일한 낙관성을 이중으로 계산할 수 없어요.

#### 2.3.3 정규화(Normalization)

세 가지 구성 요소는 비교할 수 없는 척도에 존재하므로, 각 정적 구성 요소는 후보 세트에 대한 95번째 백분위수(`EDV_NORM_CAP = 4.0`(으)로 제한됨)로 나뉘어요. 세 가지 정규화기(normalizers)는 `metadata.edv_parameters.normalizers`에 포함되어 제공되므로, 게시된 모든 EDV 값을 자체 아티팩트에서 다시 도출할 수 있어요.

#### 2.3.4 조립(Assembly)

정렬은 map 모드와 정확히 동일한 지연 탐욕적 추적(lazy-greedy trace)이에요. 모든 순서 종속 승수(설문조사 참신성, 판단 배치 감소)는 항목이 배치됨에 따라 단조 비증가(monotone non-increasing)하므로, 오래된 힙(heap) 항목은 과대평가만 할 수 있어요. 즉, 지연 탐욕적 불변성(lazy-greedy invariant)이 유지되며 추적은 무차별 대입 탐욕(brute-force greedy)과 동일해요. 최전선 인터리브, 미리보기 정책, 예산 계층은 변경 없이 적용돼요.

#### 2.3.5 설명 가능성(Explainability)

모든 항목은 진단 정보에 크레딧을 받은 대조 목록(파트너, 상태, 예측된 분리, 순위 가중치), 시드 및 감소 항, 모든 §2.2 및 §3 필드, 가중치 및 정규화기를 유지해요. 게시된 EDV 값은 해당 행에서 정확하게 다시 계산할 수 있어요. "이 항목이 어떻게 이 순위를 얻었나요?"라는 질문은 외부 상태 없이도 답변할 수 있어요.

#### 2.3.6 채택 기준(Adoption criterion)

`edv`은(는) 동일한 보드에서 `map` 및 `ecv`과(와) 측정된 비교를 거친 후에만 게시된 기본값이 돼요. 모든 설문조사 지표(최초 측정 깊이 백분위수, 깊이에서의 고유한 쌍/언어/어족, 한계 신규 쌍 비율)에서 map의 10% 이내여야 하고, 두 가지 판단 지표(시뮬레이션된 $1k당 해결된 경합 대조, 고정 지출에서의 방법 순위 회복)에서 엄격하게 더 나아야 하며, 달러당 메시 성장이 map보다 나쁘지 않아야 해요. 비교 보고서는 전환(flip)과 함께 게시돼요.

## 3. 한 번의 실행이 지니는 가치

### 3.1 실행 전에 점수 예측하기

실행되지 않은 (쌍, 모델, 조건)의 예상 점수는 의도적으로 단순하고
완전히 검사 가능한 합이에요 — 양방향 주효과 예측에 구조화된 낙관성을
더한 것으로, 모든 항이 항목에 게시돼요.

```
ŝ = clip( pair_prior + model_offset + condition_offset + exploration_bonus,  0, S_CAP )
```

- **`pair_prior`** — 게시된 강도에 대한 계층적 백오프: 이 쌍의
  평균 → 이 대상 언어의 평균 → 이 소스 언어의 평균 → 전역 평균 →
  `S0_FALLBACK`. 사용된 수준은 `prior_basis`로 게시돼요.
- **`model_offset`** — 이 모델이 같은 쌍의 *다른* 모델들에 비해
  어떻게 수행하는지를, 비교가 존재하는 모든 쌍에 대해 평균낸 값.
  본 적 없는 모델은 0이에요.
- **`condition_offset`** — 같은 쌍에서 관찰된 coached 빼기 naive
  델타(같은 대상 언어로 백오프), 그 외에는 **0**: coaching 이득은
  측정된 곳에서는 실재하지만 언어 간 전이된다고 가정하지 않으므로,
  근거 없는 쌍에서는 baseline 우선 관례가 유지돼요.
- **`exploration_bonus`** — 불확실성에 직면한 낙관성, UCB1 스케줄
  (Auer, Cesa-Bianchi & Fischer 2002):
  `κ·sqrt(2·ln(1+N)/(1+n))`, 여기서 N은 게시된 점수 매겨진 실행의 총
  개수이고 n은 이 (쌍, 모델)에 대한 개수예요. 한 번도 시도되지 않은
  셀은 가장 큰 보너스를 받고, 잘 측정된 셀은 0으로 감쇠해요.
  우리는 스케줄을 차용해요 — 탐색이 부족한 암을 적절한 비율로 다시
  부상시키는 형태를 — 정상(stationary) 밴딧을 가정하는 후회 정리는
  아니에요. 이 시스템은 그런 밴딧이 아니거든요.

### 3.2 메시 이득, 닫힌 형식으로

실행은 자신의 쌍의 엣지를 `s' = max(s(e), ŝ)`로 올림으로써만 메시를
개선할 수 있어요. 단일 엣지 변경의 경우, 임의의 두 언어 사이의 새로운
최선 체인은 새 엣지를 무시하거나 정확히 한 번 사용하므로, 업그레이드된
행렬 — 따라서 ΔΦ — 은 정확한 한 줄 형식을 가져요(전체 그래프를 다시
풀 필요 없음).

```
Q'(u,v) = max( Q(u,v),  E(u,a)·s'·E(b,v),  E(u,b)·s'·E(a,v) )

E(x,y) = λ·Q(x,y) for x ≠ y;  E(x,x) = 1        (edge e = {a, b})

ΔΦ = mean over ordered pairs of (Q'(u,v) − Q(u,v))
```

E는 "새 엣지의 끝점까지의 최선 체인으로, 거기에 이어 붙이기 위해
접합부 비용을 지불한 것"이며, 두 항은 엣지를 가로지르는 두 방향이에요.
이는 하네스 스위트에서 Φ의 무차별 재계산에 대해 테스트돼요.

현재 엣지 강도를 능가할 수 없는 예측은 ΔΦ = 0을 산출해요. 공식은
입증된 것을 재측정하는 것이 아니라 미지의 것을 확인하는 데 기부자의
돈을 써요. (탐색 보너스는 약하거나 표본이 부족한 셀이 영원히 굶주리는
것을 막아줘요.)

### 3.3 무엇이 증거로 간주되는가 vs. 무엇을 큐에 올릴 수 있는가

두 개의 서로 다른, 의도적으로 비대칭적인 게이트예요.

- **증거**는 *모든* 게시된 비실격 실행에서 나와요 — 공개적으로 큐에
  올릴 수 없는 코퍼스(예: 비상업 라이선스 세트)에서의 실행도
  포함해서요. 어떤 쌍에 대한 게시된 측정은, 재실행할 수 있든 없든
  지식이에요.
- **행동**(큐 항목)은 공개적으로 실행 가능한 코퍼스에서만 나와요.
  개발 분할, CC-BY 계열 라이선스, 누구나 가져올 수 있음.

큐에 올릴 수 없는 코퍼스를 통해서만 도달 가능한 언어도 여전히
그래프에 있어요. 그 언어 *주변*의 엣지를 개선하면 그들의 체인 값이
변하며, 공식은 이를 반영해요.

| 매개변수 | 기본값 | 의미와 근거 |
|---|---|---|
| `λ` (`lambda_junction_discount`) | **0.9** | *추정* 체인의 접합부당 충실도 유지율. "직접 측정이 곱셈 동등 체인을 능가한다"를 인코딩함(Utiyama & Isahara 2007; Wu & Wang 2007; Fan et al. 2021). 약 10% 삭감은 보정 선택이며, 측정된 체인 삼각형이 쌓임에 따라 재검토됨(§6). |
| `κ` (`kappa_exploration_scale`) | **0.05** | 강도 단위로 표현된 탐색 보너스 척도. 0.05 ≡ 5 chrF++ 점 — 100개 미만 항목 코퍼스에서 점수 차이가 구분되지 않는 노이즈 하한([Corpus Design §6.3](/docs/network/specifications/corpus-design)). 낙관성은 측정 기구의 해상도에서 상한이 설정됨. |
| `S_CAP` | **0.95** | 예측 상한 — 어떤 추정 엣지도 입증하지 않은 거의 완벽한 충실도를 주장할 수 없음. |
| `S0_FALLBACK` | **0.5** | 최후의 수단으로서의 쌍 사전값(prior). 게시된 결과가 전혀 없을 때만 사용됨(관찰된 전역 평균 — 첫 429회 실행에 걸쳐 ≈ 0.54 — 이 결과가 하나라도 존재할 때마다 선호됨). |
| `COST_FLOOR` | **$0.01** | ECV 분모의 하한이므로, 거의 무료인 실행이 달러당 무한한 가치를 주장할 수 없음. |
| `N_FULL` | **100** | 완전한 크기 인정을 위한 평가된 항목(§1.5). |
| `L_HEALTHY` | **5.0** | 완전한 풍부도 인정을 위한 유효 단어(§1.5). |
| `H_NOISE` | **±5 chrF** | 완전한 신뢰도 인정을 위한 CI 절반폭; 누락된 CI는 50/√n으로 프록시됨(n=100에서 ±5에 고정). |
| `RUNS_FULL` | **2** | 완전한 복제 인정을 위한 게시된 실행. |

**버저닝.** 매개변수나 공식 변경은 `formula_version`
(메타데이터)와 이 페이지의 버전 줄을 올려요. 큐는 현재 Φ를 포함해
`metadata.priority_parameters`에서 사용된 정확한 값을 항상 다시 표시하므로, 과거
큐도 해석 가능한 상태로 남아요. 민감도 실행은 플래그 하나면 돼요.
`generate_sweep_queue.py --lam 0.8 --kappa 0.1`.

## 5. 검증된 예시 (라이브 값, 2026-06-12)

점수 매겨진 실행 424회, 측정된 엣지 59개, 언어 60개에 대한 생성;
**Φ = 0.272**. 최상위 항목:

```
eng>fao · claude-haiku-4.5 · naive
  edge_strength        0.0      (no published eng→fao runs)
  pair_prior           0.613    basis: target-language (Faroese runs exist via dan→fao)
  model_offset        −0.114    (haiku trails other models on shared pairs)
  condition_offset     0.0      (no coaching evidence for fao)
  exploration_bonus   +0.174    (never-run cell: κ·√(2·ln 425 / 1))
  predicted_strength   0.673
  expected_mesh_gain   0.0181   (eng→fao is a near-component join)
  est_cost_usd         0.0101
  ecv_per_usd          1.79     ← rank #1
```

다시 읽어보면: 페로어는 덴마크어를 통해서만 메시에 연결되어 있으므로,
측정된 eng→fao 엣지는 거대한 체인 계열을 단축시켜요(큰 ΔΦ); 모델은
이와 같은 쌍에서 중간 정도로 예측되고(사전값 + 오프셋), 아무도 이 셀을
시도한 적이 없으며(큰 보너스), 실행 비용은 1센트예요. 큐의 다른 어떤
것도 달러당 더 많은 메시를 사주지 않아요. 모든 입력값이 게시된 채로
같은 산술이 다른 모든 순위를 만들어내요.

## 6. 알려진 한계 (그리고 무엇이 이를 고칠 것인가)

1. **chrF++는 언어 간에 비교 가능하지 않아요.** 형태론이 척도를
   이동시켜요. 바스크어로 가는 0.5 엣지는 네덜란드어로 가는 것과
   같은 성취가 아니에요. 완화: 우선순위는 척도 효과가 이차적인
   *구조*(s = 0 → s > 0 전환)에 의해 지배돼요. 해결: 언어별 점수
   정규화, 또는 이러한 언어에 사용 가능해지는 더 나은 교차 언어
   보정을 가진 메트릭.
2. **곱셈-λ 체인 모델은 사전값이지 측정이 아니에요.** 피벗 문헌에
   의해 방향성 있게 뒷받침되지만 LLM 번역에 대해서는 보정되지
   않았어요. 해결(계획됨): 메시는 이제 측정된 삼각형을 포함하므로
   (예: deu→eng→fra와 함께 deu→fra 직접), 체인 출력을 직접 점수
   매기고 λ를 선택하는 대신 데이터에 맞출 수 있어요.
3. **오염과 개발 세트 상태.** 엣지 강도는 공개 개발 세트의 모든
   주의사항을 물려받아요 — Φ를 역량 주장이 아니라 상한선 계획 신호로
   취급하세요
   ([Corpus Design](/docs/network/specifications/corpus-design)).
4. **도메인 맹점.** 대화 텍스트에서 측정된 엣지는 하나의 수치로
   취급돼요. 도메인을 가로지르는 체인은 λ가 예측하는 것보다 더
   저하될 거예요.
5. **방향성.** 엣지는 현재 무방향이에요(X→Y 증거가 X↔Y를 밝힘).
   체인 합성이 실제로 방향에 민감해지면 강도는 방향별로 분할돼요 —
   공식은 변하지 않고, 그래프만 두 배가 돼요.
