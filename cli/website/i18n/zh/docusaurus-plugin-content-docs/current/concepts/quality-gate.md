# 质量门

每次翻译在写入磁盘前都会通过一个确定性的验证门。质量门捕捉常见的机器翻译失败模式——没有无声回退，没有垃圾数据写入你的本地化文件。

## 验证检查

| 检查项 | 捕获的问题 | 门禁标签 |
|-------|----------------|-----------|
| **空值/空白** | 模型返回了空字符串或空白字符 | `[GATE] empty` |
| **源文回显** | 模型原封不动或变相返回了原始英文输入（重音符、大小写、全角字母），出现在整个值或某一复数形式中 | `[GATE] source-echo` |
| **ICU / 占位符结构** | 被翻译的变量、复数关键字或选择器，遗漏的 `#` 或 `%s` | `[GATE] icu` |
| **标记** | 标签的打开、闭合或嵌套方式与源文本不一致 | `[GATE] markup` |
| **占位符旁的断句** | 源文本在此处没有断句，但译文在占位符紧邻的前后加入了句末标点：`Take this medicine at {time}.` → `… sina. {time}.` | `sentence break beside a placeholder` |
| **幻觉循环** | 重复的三元语法（trigram）模式（例如：`"Qo' Qo' Qo'"`） | `[GATE] hallucination` |
| **长度膨胀** | 输出明显长于源文本 | `[GATE] length` |
| **内容删除** | 输出本质上是移除了字母的源文本 | `[GATE] content` |
| **书写系统合规** | 目标语言区域使用了错误的书写系统（文字） | `[GATE] script` |
| **相同输出对应不同输入** | 针对多个不同的源字符串返回了相同的文本（模型记住了某句话） | `[GATE] shared-output` |
| **ICU 复数类别** | 缺少该语言区域所需的复数形式 | `[GATE] icu-plural` |

声明为 [`noTranslate`](/docs/getting-started/configuration#no-translate) 的键绝不会进入门禁——它们会逐字复制自源文本，因此无需验证。

**Markdown 页面会逐块接受相同的检查。** 在内容文件夹（`contentDir`、Docusaurus 文档）中，每个标题、段落、列表项和表格单元格都会单独检查，每个 front-matter 字段也是如此。检查项与上述相同：空值、源文回显、幻觉循环、长度膨胀、内容删除、书写系统以及相同输出对应不同输入。诸如 `## Feast` 这样被返回为一整句话的短标题会被拒绝，就像包含相同文本的应用键一样。

被拒绝的块会**附带原因再次请求**。模型会被告知错误所在，并提示按原样书写正确的文本可以原样返回。有些拒绝无法通过任何固定规则来判定：作为专有名词的标题（`### BLEURT (Sellam et al., 2020)`）、参考资料列表项、代码对照表或术语解释，既可能原样书写完全正确，也可能是遗漏的翻译。如果该块原样返回，或者在非拉丁语言中保留了拉丁字母，且模型再次给出相同答案，则该答案会被判定为刻意为之并予以接受。其他任何拒绝都必须在第二次回答时完全通过门禁。声明不遵循指令的端点（`"acceptsInstructions": false`）不会被再次询问；其第一次回答就会直接按照第二次回答的标准进行判定。

仍被拒绝的内容会转交给语言对的 `fallback` 方法。若未配置回退方法，**该块将保留其源文本，且页面中不会添加任何标记**，绝不会被缓存，页面的 lock 条目将记录为 `pending:<hash>`。`status` 和 `verify` 会列出此类页面，且 sync 会列出每个具体的块。该拒绝会被记住：下次普通同步不会再将该块发送给同一个模型（参见[被拒绝的 Markdown 块与 front-matter 字段](#refused-markdown-blocks-and-front-matter-fields)）。块中的代码、链接和标记会单独受到保护，HTML 注释绝不会被发送。某些文本无需询问即可直接按原样保留：
- 短专有名词（`## GitHub`），计算长度时不计行内代码、引号、括号及 `{#anchor}`；
- 参考资料列表项，或整块参考资料列表；
- 源文本自身就包含的全角字母。

表格的度量基于单元格，而非竖线和分隔行。`verify` 以相同方式检查磁盘上已有的块，但与 sync 已为其源文本接受并缓存的内容完全一致的块除外。失败的块会触发一条警告，导致 `verify --strict` 失败，并附带修复命令 `champollion sync --pair en:fr --redo files:<page>`。Sync 会为同一个文件输出相同的命令。

### 空白/空字符串

拒绝空字符串、仅空格或 `null` 的翻译。这捕捉模型对困难键返回空值的情况。

### 源文本回显

检测模型何时返回了英文源文本而非进行翻译。这种情况常见于简短字符串以及提示词描述不充分的场景。此处适用两条规则，分别度量不同的特征：

1. **完全复制**（与源文本逐字节相同）会被拒绝——但**简短且以 ASCII 为主**的值除外：30 个字符或以内，且 80% 以上为纯 ASCII。`"Blog"`、`"GitHub"`、`"npm"` 保留为英文是合理的，因此在拉丁字母目标语言中，此类复制会被接受（`verify` 会将其列为源文回显）；在非拉丁字母目标语言中，模型会被询问一次该内容是否为专有名词，如果连续两次给出相同答案，则作为专有名词接受。**此项豁免取决于长度，且仅适用于完全复制。**
2. **伪装复制**——仅修改了大小写、重音符、间距、不可见字符或兼容形式（全角字母、连字）的源文本——当源文本包含**三个或更多**含有字母的单词时（占位符如 `{count}` 或 `%s` 以及标记标签不计入），**无论多短**都会被拒绝。`"Book an appointment"`（19 个字符，3 个单词）→ `"Bóok án appóintment"` 会被拒绝；`"cafe"` → `"café"`（1 个单词）会被接受，因为真正的翻译可能仅在重音符上与英文有所不同。合理带有重音符的较长专有名词（`"Universite de Montreal"`），只需将带重音符的拼写声明为受保护术语即可被接受。

这两条规则同样适用于**每种复数形式**。gettext 的 `msgstr[n]` 复数、ICU 的 `{n, plural, …}` 分支或 i18next 的 `_one`/`_other` 键都遵循与单数形式相同的规则：俄语复数中若 `few` 形式返回为带重音符的英文，将像单数形式一样被拒绝。

同样按原样保留才是正确的较长值——URL、仓库路径、产品标识符——不属于门禁问题，也无法通过微调门禁来解决：正确的答案*就是*回显，因此模型的任何可能输出都是错的。使用 [`noTranslate`](/docs/getting-started/configuration#no-translate) 声明这些键，它们即可完全绕过流水线。URL 值类型的键默认就是这样处理的。

### 幻觉循环

分析输出中的三字符（trigram）模式。如果任何三字符相对于输出长度重复次数超过阈值，翻译将被拒绝。这捕捉产生退化输出的情况，如 `"Qo' Qo' Qo' Qo' Qo'"`。

### 长度膨胀

拒绝输出长度超过 `maxLengthRatio × source length`（默认：4×）的翻译——严格大于：刚好为 4× 的翻译可以通过。这能捕获模型在输入简短时产生大段文本的幻觉。

可通过配置中的 `maxLengthRatio` 配置。

### 内容删除

与长度膨胀相反的情况。当模型对某个字符串缺乏词汇储备时，它可能会删掉所有无法翻译的字母，只留下源文本的标点符号和空格：

```
"low-resource nmt · tokenizers · nêhiyawêwin"  →  "   ·   · êhiêi"
"the simple-builder approach"                  →  "  "
```

其他检查项都无法捕获这种情况。它不是空值，不是回显，没有重复，而且其长度占源文本*长度*的 33%，可以轻松通过 `minLengthRatio`。

该检查会比对源文本与输出之间的**内容字符**——即字母和数字，忽略标点、空白符和不可见格式。但单凭密度无法作为判定规则，因为合法的高信息密度书写系统也具有完全相同的特征：

| 源文本 | 输出 | 保留内容比例 | 判定 |
|--------|--------|------------------|---------|
| `low-resource nmt · tokenizers · nêhiyawêwin` | `   ·   · êhiêi` | 14% | **拒绝** |
| `Getting started` | `入门` | 14% | 接受 |
| `Frequently asked questions` | `常见问题` | 17% | 接受 |

任何能捕获第一种情况的单一阈值都会直接误杀中文、日文和韩文。区分它们的分水岭不在于保留了多少内容，而在于这些内容*来自何处*：被掏空的输出是其自身源文本的**子序列**（subsequence）——可以通过从中删除字符得到——而真正的翻译与源文本基本没有任何重合。标记该问题需要**同时满足**这两个信号，因此该检查与重复检测器一样，属于必要非充分条件。

可通过 `minContentRetention`（默认 `0.35`）按语言对或按语言进行配置。调高该值会使检查更严格；它仅在同时出现子序列信号时才会触发。

:::note[这是词汇匮乏的信号，而非质量调节旋钮]
当此问题针对某个目标语言反复出现时，说明模型缺乏对应文本的词汇——通常是词汇封闭语言中简短且术语密集的字符串。放宽阈值只会重新引入静默损坏，并不能生成有效的翻译。应修复提示词、辅导数据（coaching data）或语言对配置。
:::

### 脚本合规性

对于语言卡片中记录为非拉丁文字系统（阿拉伯语、CJK、西里尔字母等）的语言区域，验证输出不仅包含拉丁字母。字母按 **Unicode 书写系统**分类，而非按字节：带重音的拉丁字母（`"Bóók"`）和全角拉丁字母（`"Ｂｏｏｋ"`）都属于拉丁字母，因此两者都不能算作俄语。在 CJK 排版之外（日文中 `"ＯＫ"` 属于日常用法），全角拉丁字母在任何目标语言中都会被拒绝——它们属于伪装的英文。常规豁免依然有效：按原样保留的短专有名词（上述专有名词或标签判定）、声明的受保护术语以及 `noTranslate` 键（包括 URL）绝不会因此失败。

关于该检查*不涉及*的内容的两点澄清：

- 它**不受 `script:` 配置字段控制。** 该字段用于为[书写系统转换](/docs/getting-started/configuration#script-conversion)选择输出正字法；门禁的预期直接来自语言卡片。
- 它始终在任何书写系统转换*之前*，验证**模型发出的工作文字系统**。配置了书写系统转换器的语言区域（crk、sr、tlh 等）会正常生成拉丁工作文字输出，因此它们免受此项检查；如果配置启用了转换，转换会在通过门禁之后进行。

### 标记

标签就是代码。对于每个标签名称，译文中打开、闭合和自闭合标签的数量必须与源文本一致，且嵌套方式相同（`<a>` 内部的 `<b>` 必须保持在 `<a>` 内部）；同级标签的顺序可随词序调整。`"Please <strong>book</strong> now"` → `"Veuillez <strong>réserver maintenant"` 会被拒绝——丢失闭合标签会导致页面崩溃。在复数消息中，每个形式都会与其翻译的源形式进行比对。`verify` 对文件执行相同的检查。

### 占位符旁的句末断句

占位符是在运行时填充的，因此译文紧挨着它放置的句末标点会改变读者的阅读体验：`"Take this medicine at {time}."` → `"… sina. {time}."` 会将时间单独显示为一个句子。如果源文本在相应位置没有标点，且译文中的句末标点数量多于源文本，门禁将拒绝把句末标点（`.`、`!`、`?` 或其他文字系统的标点：`。`、`？`、`।`、`؟`、`።`、`᙮` 等）紧挨着放在占位符**之前**，或放在占位符**之后**且其后仍有文本的翻译。仅将占位符移至句末的情况（`"Shipped by {carrier} on {date}."` → `"Expédié le {date} par {carrier}."`）可以通过。省略号、小数或文件名（`{host}.com`）以及单字母缩写（`"M. {name}"`）也可以通过。占位符前较长的缩写（`"ca. {count}"`）无法与句末标点区分开来，因此也会被拒绝，由语言对的回退机制或重写后的答案来接管。`verify` 会标记磁盘上的相同值，并附带用于重新请求的 `--redo` 命令。ICU 复数和选择消息交由 ICU 检查项处理。

### 相同输出对应不同输入

记住了某个训练句子的模型，可能会对不认识的字符串返回相同的内容：应用标题、"Contact the school"、简报标题及其小标题都返回同一个句子，而每个句子单独来看都能通过上述所有检查。在某个语言区域的运行中，当同一个译文回答了**三个或更多不同的源字符串**——且该译文包含四个或更多单词，或者各源文本均为两个或更多单词且几乎没有共同点时——这些键将被拒绝（以便由重试及后续的回退机制接管）。当证据充分时，**两个**不同的源字符串就足以触发：两者都是两个或更多单词，彼此重合的单词少于一半，且共享的翻译包含四个或更多单词（用同一句话回答了 `"Thank you for coming!"` 和 `"Please bring the forms."`）。以此方式捕获的句子会在该语言区域中被记录：后续同步即使只针对一个字符串返回了该句子，也会将其拒绝，并且此前提供过该句子的缓存条目会被移除，以便重新执行时再次询问模型，而不是直接从缓存写入。多个同义词合并为同一个简短翻译的情况（`"OK"`/`"Okay"`/`"Sure"` → `"D'accord"`，`"Close"`/`"Dismiss"` → `"Fermer"`）可以通过，同一个源文本在多个键下使用的情况也可以通过。本次运行的内容文件的 Markdown 块和 front-matter 字段同样计算在内，ICU 复数或选择消息的每个分支亦然（同一个复数消息的分支计为一个源文本——没有数形态变化的语言在每个分支中都会写出相同的文本）。比对输出时会忽略大小写、标点符号和 Markdown 块标记，因此 `"S?"`、`"S."` 和标题 `# S` 被视为同一个输出。计数包含该语言区域在磁盘上已有的内容以及缓存将要提供的内容（被其他工具一次缓存一条文本的句子会在缓存层被拒绝，不会写入），因此每次同步仅新增一个键的情况也能被捕获。`verify` 会针对磁盘上的相同模式报错，MCP `translate` 工具会在调用内拒绝该情况。

### 丢失问号的疑问句

当源文本以 `?` 或 `!` 结尾，而译文既未以此结尾，也未使用其书写系统中的对应标点（`？`、`؟`、希腊语 `;`、`¿…?`、`！` 等）时，`sync` 和 `verify` 会发出警告：写成陈述句的 `"Where does it hurt?"` 读起来就是陈述句。这是一条警告而非拒绝，因为某些语言使用特定词汇或语气助词而非标点符号来表示疑问。警告会指出具体的键以及用于重新请求的 `--redo keys:<key> --fresh` 命令（`--fresh`，因为缓存中存有答案）。

## 失败时的处理

1. 失败的翻译会记录到 stderr，带有 `[GATE]` 前缀、键名、原因以及值的预览
2. 该键**不会**写入语言区域文件
3. 触发重试级联（见下文）
4. 如果仍然失败，该拒绝会被**记住**（参见[被拒绝的键会被暂扣](#refused-keys-are-held-back)）

```
[GATE] hero.title: source-echo — "Welcome to our platform"
[GATE] nav.about: hallucination — "À À À À À À À À"
```

## 反馈重试与重试级联

被门禁拒绝的键会获得**一次反馈重试**：拒绝原因会作为单键上下文注入到提示词中（在低温度下盲目重试只会返回逐字节完全相同的输出）。如果重试通过，该键将被写入且同步状态为**正常（green）**——能够自我修复的门禁拒绝不属于失败，这也是设计的本意。重试后仍然失败的键将被跳过并报告（同步以 `2` 退出）。

重试会通过语言对自身的翻译方法执行，无论是 LLM、Google Translate、DeepL 还是直接提供商。只有 LLM 方法会读取反馈；运行日志行会注明这一点（`retrying with feedback` 或 `asking once more (deepl takes no instructions…)`）。`api` 端点只有在声明了 `"acceptsInstructions": true`（在语言对或其插件清单中）时才会接收反馈；声明了 `false` 的端点——例如训练好的 NMT 模型 `nmt-forge serve`，重试只会给出相同答案——根本不会被再次询问：其答案会直接按照第二次回答的标准进行判定，被其拒绝的内容会转入语言对的回退机制。重试同样适用于翻译记忆库（TM）命中项：被门禁拒绝的缓存值会在同一次运行中被逐出并重新翻译，从而使被污染的缓存能够自我修复。

### 被拒绝的键会被暂扣

拒绝记录保存在 `.champollion.lock` 中，按键划分，针对该键的**当前源文本**以及生成被拒答案的**方法和模型**进行记录。Docusaurus UI 字符串（`i18n/<locale>/code.json` 和插件的 JSON 文件）遵循相同规则，按文件和 id 记录。下次普通的 `sync` 不会再将该键发送给同一个模型——否则会为相同的答案产生账单费用——并会说明暂扣了多少项以及如何处理：

- 重新请求：`champollion sync --redo keys:<key>`（或 `--redo all`，或 `--fresh`）——显式指定键名即为显式重试；
- 换种方式填充：为语言对添加 `"fallback"` 方法（用于处理语言对自身方法拒绝的键），如果保持原样，将键列入 `noTranslate`，或在文件中手动编写翻译。

被暂扣的键处于未翻译状态，因此同步将以 `2` 退出，直到其被填充。更改源文本、模型或方法即可解除暂扣（拒绝是针对该模型生成的该文本）。系统仍会为其读取缓存——暂扣阻止的是付费调用，而非免费调用。重做未能完成的键是唯一的例外，见下文。

### 被拒绝的 Markdown 块与 front-matter 字段

相同的规则适用于内容文件（`contentDir`、Docusaurus 文档）。被门禁拒绝的块或 front-matter 字段记录在 `.champollion-content.lock` 中，按页面、块和语言区域划分，针对该块的**当前源文本**以及生成被拒答案的**方法和模型**进行记录。块以其源文本命名，因此编辑段落即可解除暂扣。下次普通的 `sync` 不会将其再次发送给同一个模型，并会说明哪个页面暂扣了多少个块和字段：

- 被暂扣的块在页面上保留其源文本，且不带任何标记，直到其被填充；页面的其余部分正常写入；
- 被暂扣的 front-matter 字段同样保留其源文本，页面的其余部分正常写入；
- 整体翻译的页面（`contentSegmentation: "page"`）在其答案损坏了受保护块或掏空页面内容时会被整体拒绝。它会按其正文文本记录并整体暂扣：在填充之前，既不会写入，也不会发送其中的任何内容。编辑正文，或切换到块分段模式，即可解除暂扣。

早期版本门禁产生的拒绝记录会自动解除。当某项检查放宽时，先前被其拒绝的内容会在下次同步时再次请求，无需执行重做命令。

其优先级与键的优先级一致：

1. 指定重做的页面始终会发送：`champollion sync --redo files:<page>`、`--redo content`（所有页面）、`--retranslate` 或 `--fresh` 下的任何内容。
2. 否则，被拒绝的块或字段将被暂扣。如果该语言对配置了尚未拒绝过该内容的 `fallback` 方法，将向回退方法请求，而不再向语言对自身的方法请求。
3. 更改模型或方法会解除暂扣，修改块的源文本同样会解除暂扣。

缓存仍会优先读取，因此暂扣阻止的是付费调用，而非免费调用。通过其他方式填充的块会清除其记录：通过回退机制、通过缓存，或通过您自己在译文中编写的段落（内容文件夹会保留手动编写的段落）。被暂扣的块或字段处于未翻译状态，因此同步将以 `2` 退出，直到其被填充。本次运行期间被门禁拒绝的块也是如此。Dry-run 会列出实际运行中将暂扣的内容。

### 未能完成的重做

当 `--redo all`、`--redo keys:` 或切换模型（`--redo all --fresh-on-model-change`）导致键值文件中的某些键未被翻译时，它们会在 `.champollion.lock` 中被记录为 **pending**，且下次普通的 `sync` 会向模型再次请求这些键——向模型请求，而非从缓存读取（重做的目的就是获取新模型的文本）。`champollion status` 会列出这些键。如果该重试仍然被拒绝，该键将保持 pending 状态（状态中会体现），并像其他被拒绝的键一样被暂扣。按优先级排列：通过 `--redo`/`--fresh` 指定的键始终会发送；pending 状态的键获得那一次重试；被拒绝的键被暂扣。Docusaurus UI 字符串没有 pending 重试机制：在重做中被拒绝后，下次普通同步会直接将其暂扣，就像内容块一样。

此外，当整个批次失败（JSON 解析错误）时，Champollion 会以逐渐缩小的批次进行重试：

```
Full batch (80 keys) → parse error
  └→ Half batch (40 keys) → 2 failures
      └→ Individual keys (1 each) → isolates the 2 problem keys
```

重试预算由 `maxRetries`（默认值：3，每种语言可配置）限制。这防止了对持续失败的键的无限制令牌支出。

耗尽重试次数后，问题键会被记录并跳过。未获得可用答案的键（响应中缺失）会在下次 `sync` 时再次请求；被门禁拒绝的键会被暂扣，如上所述。

## 提示缓存

系统消息（寄存器、语法规则、风格说明）与用户消息（要翻译的键）分离。这种分离是有意的：

- 系统消息对于给定的语言环境**在批次间相同**
- Anthropic 和 Google 等提供商缓存重复的系统消息
- 结果：第一个批次支付全部令牌成本，后续批次仅支付用户消息的成本

这可以显著降低具有许多批次的项目的令牌成本。

## ICU MessageFormat 验证

`integrity` 命令根据 CLDR 复数规则验证 ICU MessageFormat 复数模式。如果你的源文件使用 ICU 语法，如：

```json
"items": "{count, plural, one {# item} other {# items}}"
```

Champollion 验证翻译版本包含目标语言环境所需的所有复数类别。例如，阿拉伯文需要六个类别（`zero`、`one`、`two`、`few`、`many`、`other`）——而不仅仅是 `one` 和 `other`。

### 译文未提供的复数形式

提示词会指明目标语言的 CLDR 类别。当复数消息返回时缺少了该语言日常计数所需的类别（从 0 到 1000 的任意计数——俄语中 2、3、4 对应的 `few` 以及 0、5、6 对应的 `many`），门禁会再次询问模型，并指明缺失的形式及其覆盖的计数。若第二次回答仍然缺少这些形式，则予以接受，绝不会进行第三次询问，工具也不会自动补全——此时 sync 会：

- 发出警告，指出每个键及其缺失的形式，以及重新请求的命令（`sync --redo keys:… --fresh`，此时更强的 `--model` 会有所帮助）；
- 在每个 `msgstr[n]` 都必不可少的 gettext 目录中，将缺失的形式写入为 `other` 的副本，并使用 `# champollion:` 翻译者注释标记该条目（Poedit 和 Weblate 会显示该注释；`verify` 也会读取它，包括在没有缓存的 CI 环境中）；
- 在 ICU 文件（next-intl、ARB）中按原样写入该消息；应用程序将对这些计数显示 `other` 形式。

此类消息不会被视作已翻译。后续使用其他方法或模型运行的同步——即尚未对此生成答案的配置，例如在本地模型后运行的 CI 托管模型——会再次向模型请求，而不是从缓存（其中存有不完整的答案）中读取；预估成本会将其计入。`sync --redo gaps` 会请求所有此类消息，无论当初是由谁留下的。如果新的答案仍然缺少这些形式，该消息将保持原样（在目录中被标记），且 `.champollion.lock` 会记录哪些配置在缺少这些形式的情况下给出了答案，以便不再针对相同文本询问其中的任何配置（[CI 指南](/docs/guides/ci-cd#plural-gaps)）。

`verify` 会报告这两种情况并提供修复命令。仅在大于 1000 或小数时才会触发的形式（如法语和西班牙语中用于 1 000 000 的 `many`）只会收到 info 提示行，而非警告。机器翻译引擎（DeepL、Google 等）无法被指示写入特定形式，因此其答案不会重试——仅作报告。对于 i18next 文件，源文本中不具备的每种形式（从英语翻译而来的法语 `count_many`）都是一个单独的键，从 `_other` 文本翻译而来：LLM 会被要求提供该形式，sync 会明确提示；对于机器翻译引擎，它会提示该值沿用了 `other` 形式。

运行 `champollion integrity` 检查所有语言环境的复数完整性。

## 术语强制

对于带有字典的教练对，champollion 运行翻译后的术语检查。质量门通过后，它验证 LLM 是否实际使用了所需的字典术语。

```
[TERM] en→fr: 2 term violation(s)
  • hero.title: "dashboard" → expected "tableau de bord" but got "panneau de contrôle"
```

术语违规是**警告，不是阻止错误**。翻译仍然被写入磁盘。这是有意的——LLM 可能有选择替代方案的有效理由（上下文、语法），而对术语不匹配的阻止会造成更多伤害。

要修复违规，请更新教练字典或手动编辑本地化文件。
