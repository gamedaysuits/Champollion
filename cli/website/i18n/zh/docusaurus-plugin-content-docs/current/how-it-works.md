# 工作原理：轨道化与护栏

想象并排的两行文字：一种语言中的一句话，以及另一种语言中对应的同一个句子。这就是翻译器学习的材料，也是它写出的内容。

以前，构建翻译器需要专门的人员。你得懂得如何准备句子、如何教会翻译器，而且——最难的一点——如何在不自欺欺人的前提下测试它。这些教训大多来之不易。

Champollion 将这一切铺设为**轨道**（rails）：按部就班的每个步骤，各就其位。沿着轨道运行着**护栏**（guardrails）：拦截常见错误的检查机制，让你的语言材料始终处于你的掌控之下。你——或者你信任的 AI 助手——沿着轨道前行。由你来做决定。

## 谁来做决定

轨道负责执行步骤，人来做决定。每一个步骤都属于以下四类之一：

- **只有人能做的事**——编写句子和检查翻译。没有任何工具会假装成母语使用者。
- **只有你能回答的事**——你的语言材料属于谁、翻译器是否可以从中学习、在看到任何结果之前你的预期是什么。你的助手会提问；它绝不会替你作答。
- **你的助手会先询问的事**——任何安装软件、训练翻译器、产生费用或将内容上传到网络的操作，都需要等待你的许可。回答“*稍后再说*”也可以：轨道在当前会话中不会再次询问。
- **你的助手直接处理的事**——比如检查句子是否存在问题，或是挑出一部分备用。

## 轨道：各就其位

一个项目就是你电脑上的一个文件夹，每类内容都有一处独立的“搁架”：

| 搁架 | 存放内容 |
|---|---|
| 供学习的句子 | 成对的双语句子，每种语言一句 |
| 测试句 | 经流利的母语者核对过的句子。仅用于评估，绝不用于学习 |
| 词汇表 | 词典与词表 |
| 语法笔记 | 关于该语言运作机制的任何书面记录 |
| 协议 | 记录谁在何时同意了什么内容的说明 |
| 收件箱 | 你的原始文件，等待导入 |

你构建的翻译器、它们产生的结果以及每一步的记录，也都有各自专属的搁架。

你的句子最终会被分成三堆。大部分用于**学习**。一部分——起初
占四分之一，数量变多后占十分之一——成为**练习
句**——就像模拟练习题，每一轮都会用来
查看它的表现。少数经母语者核对过的，则是**测试
句**，仅偶尔使用。翻译器绝不会从
后两者中学习。

因为一切各就其位，工具随时都能清楚哪些已完成、接下来要做什么。你随时询问，它们都能直接读取文件夹并指出**下一步**。你的助手不需要成为专家，也不用记着你进行到了哪里。它只需沿着轨道前行。

这些步骤按以下顺序进行：

1. **启动项目**——指定两种语言，以及你的翻译方向。
2. **收集数据**——导入你现有的材料，并记录其归属及使用权限。
3. **保护测试集**——留出用于评估每个翻译器的测试句子。
4. **安装训练工具**——在获得你的同意后执行一次。
5. **构建并测试翻译器**——训练它，然后查看它在测试句上的表现。
6. **逐轮优化**——由母语者检查其初稿，并在每一轮中针对出错之处进行改进。

你始终可以用自己的方式完成某个步骤——手动处理或借助其他工具——轨道会根据文件夹当前所记录的状态顺势接续。

## 护栏

护栏分为两种。

**一种用来防止你自欺欺人。** 翻译器若在它学过的句子上进行测试，看起来会很出色，但实际上并非如此。偶尔一次运气好，看起来就像取得了进步。因此，轨道会：

- 在开始任何训练之前将测试句单独存放，
- 剔除与测试句几乎完全相同的句子，
- 要求你在看到结果之前写下你的预期，
- 并且只有当新翻译器显著超越旧翻译器（而非仅凭运气）时，才认为它有所提升。

**另一种用来确保你的语言材料处于你的掌控之下。** 每个文件都会附带一份说明，记录拥有者做出的决定——文件是否可以离开这台电脑、翻译器是否可以从中学习——所有工具都必须遵守该说明。

工具会拒绝跳过绝大多数此类检查。少部分检查取决于你和你的助手，[护栏页面](/docs/guardrails)详细说明了具体是哪些。
