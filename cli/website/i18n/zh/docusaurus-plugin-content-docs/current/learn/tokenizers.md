# 分词器如何决定哪些语言的成本更低

:::info[目标读者]
所有人。本页面假设读者没有机器学习背景，也没有语言学
背景。只要你知道什么是语言模型——即接收文本并
生成文本的软件——就足够了。
:::

每个语言模型都有一个不可见的第一步。在它读取一个单词之前，会有一段
软件将该单词切分成多个片段。这些片段才是模型
真正看到的内容。

这一步被称为**分词（tokenization）**，几乎没有人会去关注它。但它值得
我们去了解，因为正是在这一步，某些语言的使用成本变得比其他语言高出
好几倍——而且这个决定在任何人考虑质量、公平性或覆盖率之前
就已经做出了。

---

## 1. 模型不会阅读

神经网络是对数字进行算术运算。它没有字母或
单词的概念。因此，文本必须首先转换成数字。

**分词器（tokenizer）**就是执行这种转换并在最后将其还原的
软件。它将字符串转换为整数列表，每个整数都指向
一个大型查找表中的一行。

它会做出两个决定：

**词表（The vocabulary）**——允许模型看到的固定片段清单。
不是单词：而是*片段（pieces）*。常见的片段是完整的单词，但较罕见的内容会被拆分
开来。该清单具有预先选定的固定大小——通常包含数万个
条目。

**分词方式（The segmentation）**——对于任何实际的字符串，使用哪些片段，以什么顺序排列。
单词 *unbelievable* 可能会变成 `un` + `believ` + `able`，或者是一个单一的片段，又或者
是十一个单独的字母。最终得到哪种结果，完全取决于
词表中的内容。

> **实例演示。** 如果 `believ` 在词表中，*unbelievable* 会消耗
> 三个片段。如果不在，分词器就会退而求其次，使用越来越小的
> 片段，直到能够覆盖这个单词——可能每个字母算作一个片段。同样的
> 单词，同样的含义，可能是三倍的片段，也可能是十一倍的片段，
> 这完全取决于在你输入它很久之前所做出的一个决定。

---

## 2. 词表是*学习*得来的，而且它优化错了方向

这就是让人感到惊讶的地方。

词表并不是由语言学家设计的。它是**从一堆文本中学习得来的**，
所使用的算法的目标是**压缩**——用尽可能少的
片段来覆盖这些文本。

含义在其中不起任何作用。算法根本不知道什么是单词，什么是前缀，
甚至不知道某种语言的存在。它只统计经常一起出现的内容，并为
高频序列分配独立的条目，因为这样能让文本变得更短。

其后果是机械性产生的。分配给某种语言的片段数量，大致
与**该语言在文本堆中所占的比例**成正比。占比较大的
语言会获得许多专属片段，其单词就能保持完整
或几乎完整。而几乎没有占比的语言则几乎得不到属于自己的片段，
它的单词只能被碰巧合适的通用片段拼凑覆盖。

完全没有出现在文本堆中的语言，获得的专属片段为**零**。它
依然能运行——分词器总能找到*某种*方式来表示文本，
因为它可以退回到单个字符或原始字节。只不过表达任何内容的
成本都会大幅增加。

:::note[这不是一个 Bug]
没有任何东西发生故障。压缩算法完全按照要求
执行了任务。问题在于，“让训练文本变短”被当作了
“良好地表示语言”的替代指标，而对于那些未出现在该文本中的语言来说，
这个替代指标完全失效了。
:::

---

## 3. 分词率（Fertility）：量化这种损害的指标

**分词率（Fertility）**是指一个单词平均消耗的 token 数量。

对于分词器经过大量训练的语言，其分词率接近于 1——
大多数单词都是一个单一的片段。而对于它从未见过的语言，同样的指标可能
要高出许多倍，因为每个单词都必须由碎片拼凑而成。

这一个简单的数字会引发四种不同的代价（taxes）：

| 代价 | 含义 |
|---|---|
| **成本 (Cost)** | 大多数商业模型按 token 计费。每个单词的 token 越多，意味着翻译、总结或生成相同句子的金钱成本就越高。 |
| **上下文 (Context)** | 模型具有固定的窗口大小。高分词率意味着能放入的实际文档内容更少。 |
| **计算 (Compute)** | 序列越长，速度越慢，在任何情况下永远如此。 |
| **学习 (Learning)** | 这是最棘手的一点。含义现在被分散在许多低信息量的碎片中，因此模型需要解决更困难的问题——即使数据完全相同。 |

前三点是不公平的。而第四点则是损害质量的元凶。

**这是经过测量得出的，而非凭空断言。** Petrov、La Malfa、Torr 和 Bibi 发现，
相同的文本翻译成不同的语言后，其分词后的长度差异可**高达 15 倍**，
而且这种差异在专门为多语言使用而构建的分词器中
依然存在。

他们的发现让显而易见的修复方案变得复杂：字符级和字节级
模型——即直观的答案“只使用字母，那么每种语言就平等了”——
在某些语言对中仍然表现出**超过 4 倍**的差异。退回到
更小的单位只能缩小差距。它并不能消除差距。

> Aleksandar Petrov, Emanuele La Malfa, Philip Torr, Adel Bibi.
> *Language Model Tokenizers Introduce Unfairness Between Languages.*
> [NeurIPS 2023](https://proceedings.neurips.cc/paper_files/paper/2023/hash/74bb24dca8334adce292883b4b651eda-Abstract-Conference.html).

## 4. 为什么这在结构上（而不仅仅是统计上）打击了某些语言

在训练文本堆中代表性不足是原因之一。还有第二个原因，而且
它并不会因为增加数据而消失。

不同语言中，单个单词所承载的信息量是不同的。

在英语中，一个句子主要是一连串独立的单词：*I saw them*。三个
单词，三个概念，中间用空格隔开。分词器是由研究
这类语言的人构建的，他们也以此为前提——大多数分词器
实际上直接将空格视为片段的边界。

其他语言则通过将有意义的部分堆叠在一起，把整个从句构建成**一个单词**。
语言学家称这些为**多式综合语（polysynthetic languages）**，它们
在美洲原住民语言以及其他地方很常见。

> **实例演示。** 在 Plains Cree（nêhiyawêwin）中，*nikî-wâpamâwak* 的意思
> 大致是“我看见了他们”。这是一个单词。它内部包含了几个有意义的部分：
> 谁在行动、动作发生在过去、看见这个动作本身，以及谁
> 被看见。
>
> 英语使用者用四个单词来表达，而一个在英语上训练的分词器
> 可能会消耗四个片段。一个从未见过 Cree 语的分词器
> 没有这些部分的任何条目，因此它会将这个单一的单词撕碎成
> 毫无意义边界可言的碎片。

有两件事同时被破坏了。这个单词消耗了远超其应有数量的片段——
而且这些片段**切断了意义单元**，因此模型不得不
重新组装一个刚刚被分词器破坏的结构。

在训练文本堆中添加更多的 Cree 语文本可以改善第一个问题。但它只能
部分缓解第二个问题，因为算法仍然在优化压缩率，
而压缩算法并不知道边界是有意义的。

## 5. 从分词到错误答案

从“糟糕的分词”到“错误的输出”，这条链条很短。

1. 分词器在不携带任何含义的边界处将单词断开。
2. 模型学到的关联性变弱，因为同一个概念出现在
   许多不同的碎片拼写中，而不是一个一致的片段。
3. 在生成时，模型逐个片段地组装输出。
4. 单独看起来合理的片段，可能会组合成一个在该语言中**根本
   不存在**的单词。

最后一步是需要牢记的。在一种由各个部分构建单词的语言中，
模型可能会生成一些在不懂该语言的人看来格式良好的内容——
看起来正确的片段，被组装成了一个任何母语者都
绝不会说的单词。

标准的自动评分通常无法捕捉到这一点，因为这些评分主要
衡量与参考答案的重叠度，而由看起来正确的片段组成的错误单词
仍然可能产生重叠。

:::danger[为什么这比质量评分更重要]
流畅但错误的输出比明显损坏的输出更危险。不懂该语言的读者
根本无从分辨。这在很大程度上解释了为什么 Champollion 坚持
由懂该语言的人进行验证，并坚持进行结构检查，询问“这是一个真实的单词吗？”
而不是仅仅问“这与预期答案相似吗？”
:::

## 6. 谁来决定，以及为什么这才是真正的关键

上述一切都源于一个选择：**哪些文本进入了分词器
学习的文本堆中。**

做出这个选择的人，决定了每种语言将被如何切分、使用它的
成本有多高，以及模型需要付出多大的努力来表示它。这个
决定在早期一次性做出，通常由一小群人决定，并且在
该模型的生命周期内实际上是永久性的——分词器不是你事后
可以调整的东西。

而且它几乎从未被讨论过。关于语言技术的辩论往往集中在
数据、模型大小和质量评分上。而决定一种语言是否
能够被表示的这一步，却隐藏在所有这些之下，被当作
底层管道一样对待。

这就是本页面存在的原因。如果一个社区想要真正控制机器
处理其语言的方式，仅仅控制数据是不够的。
*“谁决定了我们的单词如何被切成碎片？”* 这个问题是有答案的，
而对于世界上大多数语言来说，目前的答案是：其他人，作为
压缩一堆几乎完全不包含该语言的文本的副作用。
