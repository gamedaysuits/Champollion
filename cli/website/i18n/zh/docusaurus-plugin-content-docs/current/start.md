# 启动项目

有两种开始方式。无论哪种，工具都在你自己的计算机上运行，一步一步引导你完成。

## 借助 AI 助手

这是最简单的方式。助手负责输入命令；你只需回答该由你决定的问题。

**你需要准备的：**一个在你的计算机上作为应用程序运行（而不仅是手机应用）且能够使用本地工具的 AI 助手。

### 1. 为助手添加轨道

复制下方这段简短的配置，粘贴给你的助手，并说：
*“请帮我完成这个配置。”* 许多助手都能做到。如果你的助手无法做到，请找一位熟悉计算机的朋友帮忙配置一次——具体步骤见下方。

```json
{
  "mcpServers": {
    "champollion": { "command": "npx", "args": ["-y", "champollion-mcp-server"] }
  }
}
```

<details>
<summary>手动配置</summary>

助手通过名为 MCP 的通用标准连接到工具；上面的配置会告诉你的助手如何启动轨道。你的计算机还需要安装 Node.js 20.11 或更高版本（一个免费程序）。

- **Claude 桌面应用：** Settings → Developer → Edit Config。将配置添加到该文件中，保存并重启应用。
- **Claude Code：** 在终端中运行一次此命令：
  `claude mcp add champollion -- npx -y champollion-mcp-server`
- **Cursor：** 将配置添加到项目 `.cursor` 文件夹中的 `mcp.json` 文件，或者用户主目录 `.cursor` 文件夹下的对应文件中。

</details>

### 2. 用你自己的话告诉它

比如：

> *我们想构建一个从英语翻译成我们语言的翻译器——使用 champollion。*

### 3. 回答它的提问

首先，它会向你复述翻译方向——*“输入英语，输出你的语言。这是你想要的方向吗？”*——因为把方向弄反是一个很容易犯的错误。接着它会创建一个项目文件夹，并向你索取数据文件。

从那之后，每当有需要你决定的事项时，它都会询问：语料归谁所有、翻译器是否可以从中学习、是否安装某些组件。请根据你的实际情况回答。如果目前还不确定，直说就行——轨道可以等待。而且*“现在先不处理”*也是完全可以的回答：轨道在当前会话中不会再问第二次。

**首先需要注意的一点。** 大多数助手会把读取到的内容发送给运营它们的公司。对于保存在本机上的文件，本工具只会告诉助手你拥有*多少句*语料，绝不会发送句子本身——但能够操作你计算机的助手可以打开你能打开的任何文件。对于希望保密的语料，请明确要求它不要读取，或者使用完全在你本机上运行的助手。[你的语料，你的规则](/docs/your-words-your-rules)对此有详细说明。

## 自行操作

如果你习惯输入命令行，只需四行命令。安装项目工具（需要 Node.js 20.11 或更高版本），初始化项目，然后询问下一步：

```bash
npm install -g champollion
champollion new family --from English --to qaa --target-name "Our language"
cd family
champollion next
```

`qaa` 表示“暂无代码的语言”——这完全可以正常工作；只是工具无法为你自动填写字母表等基础信息。引号中的名称是你对它的称呼。如果你的语言已有代码，或是工具有记录的名称，请改用该代码或名称。如果一个名称可能指代多种语言，在选择代码前请先询问使用者他们说的是哪一种；在确定之前，使用 `qaa` 即可，但它没有语言信息卡，因此不会自动提供复数规则或书写系统。

从那时起，`champollion next` 会始终提示下一步是什么，并给出确切的执行命令。到了需要训练翻译器的时候，轨道会在安装训练工具之前先征求你的许可。

## 离线工作

在安装以及首次训练期间请保持联网：训练工具和性能更强的翻译器（约 1.2 GB）需要在此期间下载。之后的工作全部在你的计算机上本地完成。要阻止工具自身的网络查询——工具可能会获取语言的公开信息卡，且仅会发送语言代码——请在终端以及助手的配置中设置以下内容：

```bash
export CHAMPOLLION_OFFLINE=1
```

运行在云端服务器上的 AI 助手仍然需要联网。如需完全离线工作，请使用完全运行在你自己计算机上的本地助手。

## 预期效果

你制作的第一个翻译器大概会像一本短语手册：擅长翻译它学习过的类似句子，其他方面则尚不擅长。每个项目都是这样起步的。[当前尚无法做到的事](/docs/what-it-cant-do-yet)直白地说明了预期效果，而[进一步优化](/docs/make-it-better)则展示了它是如何逐步提升的。
