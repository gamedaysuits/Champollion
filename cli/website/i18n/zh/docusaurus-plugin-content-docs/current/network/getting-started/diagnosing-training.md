# 诊断训练运行

模型训练完成了，但指标并不如预期。本页从**你当前观察到的现象**出发，逐步引导你找到可能的原因以及用于修复该问题的 forge 工具。其中大部分诊断都是自动完成的——`nmt-forge export`（以及仅输出评分的部分 `nmt-forge evaluate`）会附加一个 **Diagnosis & Recommendations**（诊断与建议）部分，明确指出检测到的问题及对应的调整方案；本指南则是其通俗易懂的解读版本，并补充了 forge 目前只能*发出警告*的少数情况（标记为 ⚠ **注意此项**）。

告诉你的智能体：*“运行 `nmt-forge lint <battery-manifest.json> --json` 并处理严重程度最高的问题。”* 导出后，测试套件清单为 `export/evaluation/battery-hyps-battery.json`。然后将报告的内容与下文各小节进行比对。

---

## “默认模型的评分较低”

你使用了默认的 `cpu-tiny` 预设进行训练，测试得分在 5 到 30 chrF++ 之间。

**原因分析：** 该预设的表现本就如此。它是一个仅根据你提供的语料对从头开始训练的小型 Transformer，因此在 1,000–2,000 条句对的规模下，它学到的是数据中的短语和句式结构，而非语言本身的通用规律——只有在数据具有高度模板化特征时，得分才会达到该区间的上限。它的作用是跑通并验证整个闭环流程（受隔离保护的验证集、经审计的数据、预注册的测试集，以及 CLI 可调用的模型），而非作为可交付上线的成品模型。

**解决方案：** 每次调整一个变量并在验证集（dev set）上进行评估，按预期收益大致排序如下：

1. **增加更多真实句对。** 在此数据规模下，数据量的提升优于任何参数调优。
2. **基于预训练模型起步。** `nmt-forge init <code> --model cpu-finetune --base
   <hf-id>` 会在 CPU 上微调一个预训练的小型 Marian/opus-mt 模型——选择一个*相近*语言对的模型，并在验证集上将其与 `cpu-tiny` 进行对比，而不要盲目假定它一定更优。`--model nllb-600m` 是效果最强的起点，但需要 GPU。
3. **从现有资源中扩充更多数据**——单语文本回译，或者在目标语言具备分析器的情况下进行验证式数据合成（参见[想要训练自己的模型？](/docs/network/tutorials/train-your-own-model)）。

⚠ **注意此项：** `cpu-tiny` 产生的高分在庆祝之前更应引起怀疑——参见[“评分看起来太高了”](#the-score-looks-too-good)。

## "在我的教科书示例上表现很好，在真实句子上表现很差"

**最常见的低资源陷阱。** 你的合成/模板数据得分很高；真实文本崩溃了。

**发生了什么：** 一个**迁移平台期**。在训练期间，你的真实开发集上的损失很早就达到了底部，然后在训练损失继续下降时漂移上升 — 模型掌握了合成数据的*数量*，而不是学会翻译。更多合成数据**不会**有帮助。

**forge 发现：** `R7-transfer-plateau`（来自运行清单的计划故事）。**解决方案：REAL-DATA。**

**修复：** 添加真实文本。反向翻译单语目标语言数据（`nmt_forge.training.backtranslation`），或获取真实平行句子。合成数据的数量不是解决方案 — *真实*数据的多样性才是。

⚠ **注意这一点：** 如果你的混合比例约为 99% 合成数据对比一个小的真实开发集，你在看到分数之前就已经处于风险中。目前还没有针对病理比例的飞行前检查 — 检查你的混合清单中的黄金/合成计数。

## "一个语域的表现远差于其他语域"

查看按语域分类的表格。单个语域（比如政府或法律）远低于其他语域。

**两个不同的原因 — 诊断通过查看*覆盖率*和输出是否*未完成*来区分它们：**

- **模型缺少词汇**（`R1-vocabulary-gap`：低覆盖率**且**高不完整率）。**解决方案：VOCABULARY。** 扩展词汇表（字典/证词收集），然后运行 `nmt-forge` 漏斗计数来确认新条目实际上到达了语料库 — 一个单字符的正字法不匹配之前已经无声地删除了数千个词。
- **模型有词汇但没有句子结构**（`R2-structure-gap`：覆盖率正常，仍然未完成）。**解决方案：STRUCTURE。** 针对你的语法检查清单运行覆盖率图，并添加缺失的构式（祈使句、疑问句、所有格、反向 — 无论你的模板从未要求什么）。

## "输出在一个句子中混合拼写"

模型用两种方式写同一个音，有时在一个句子中。

**发生了什么：** 你的训练目标教会它约定是可互换的 — 语料库包含多种正字法中的相同内容。

**forge 发现：** `R3-mixed-convention`。**解决方案：ORTHOGRAPHY。**

**修复：** `convention-lint` 语料库，在数据边界处规范化为**一个**规范约定，然后重新训练。在你的测试套件中保持混合约定率，这样你可以看到它下降。

---

## "模型 B 击败模型 A — 但只是略微领先"

你比较了两个模型，其中一个领先几分。

**发生了什么：** 差异可能小于噪声。在 80 个句子上，0.4 chrF++ 的差距是一个硬币翻转。

**forge 发现：** `R5-low-power`（置信区间比差异更宽）。**解决方案：MEASUREMENT。**

**修复：** 不要根据小于 CI 的差异采取行动。为该语域增加评估集，或使用 `nmt-forge compare` 报告*配对*显著性检验而不是两个重叠的区间。forge 从不呈现裸分数 — 区间始终存在，正是为了让你看到这一点。

⚠ **注意这一点：** 来自**单个种子**的结果不包含跨种子的方差带。在重新播种中不能存活的收益不是真实的。如果决定很重要，用 2–3 个种子重新运行。

## "分数看起来太好了"

可疑地高，特别是在早期或数据很少的情况下。相信你的怀疑。

**按顺序检查：**

1. **数据泄漏。** `nmt-forge leak-audit <corpus>`——测试集中的句子是否混入了训练集中？它会剔除提示词与测试提示词完全相同的行（即使翻译不同）、答案与测试答案完全相同的行，以及包含测试答案、作为其片段、或与测试答案相似度 ≥90% 的行。`nmt-forge run` 会直接拒绝泄漏到已注册测试集或封存集中的训练行，因此这主要影响 forge 之外的数据或流水线——或者是你从未注册过的测试集。
2. **检查点选择。** 检查点是否是在**隔离受保护的验证集**上选取的，而不是在测试集上？forge 拒绝在没有验证集的情况下进行训练，正是为了杜绝这种情况，但自建流水线往往没有这种保护。
3. **近似孪生样本导致的虚高乐观。** `R4-optimism-bound`：如果“完整”测试套件评分比“严格”评分高出数分，这部分差距便是来自操练孪生样本（drill-sibling）的虚高乐观。`leak-audit` 会特意*保留*模板孪生样本（例如训练集中的*“I see the dog”*，测试集中的*“I see the cat”*），并列出存在此类孪生样本的测试行；将 `eval.near_dupe_corpus` 设置为你的训练文件时（初学者配置已默认设置），报告会单独对*没有*孪生样本的测试行进行评分，并标记为“(strict)”。在主张任何泛化能力时，**请务必引用严格模式的数据**。如果*每一个*测试行都存在孪生样本（`R4-recall-not-translation`：严格子集为空，因此该评分仅衡量对训练短语的召回率），且测试集不可变动，则可以使用 `nmt-forge leak-audit <train> --clean-to <train>.notwins.jsonl --drop-test-twins` 将无孪生样本的语料单独写入文件，并基于此训练第二个无孪生样本的模型（leak-audit 不会覆盖第一个模型所训练的文件）——或者获取独立于训练模板编写的测试句。
4. **输出并未遵循输入。** `R9-harness-score-caveat`：mt-eval 报告提示评分存在附加保留条件——最常见的情况是**近乎恒定的输出**：许多不同的测试句子得到了相同的少数几种输出（某医疗机构的模型针对 150 个不同的句子仅给出了 9 种输出；其 chrF++ 得分仍高达 48，因为常用短语与很多参考译文共享了大量字符）。无孪生样本模型通常是此类问题的诱因：当训练模板被移除后，小型模型可能会退化并反复生成出现频率最高的句子。forge 会以测试套件的原话转达此警告——在导出摘要中包含 `DEPLOY.md`、`status`、`report`、`compare` 和 `lint`——并且在没有该警告的情况下绝不会将此类评分称为“可引用的指标”。在将评分当作翻译质量汇报之前，请先阅读部分输出内容（在存放测试集的机器上运行 `<export>/evaluation/battery-hyps.jsonl`）；引入更多真实、多样的训练句对是解决此问题的根本途径。

## "训练几乎立即停止"

运行在几百步后结束；模型几乎没有看到它的数据。

**发生了什么：** 早期停止将预期的合成数据为主的开发集波动误认为是收敛。

**forge 的机制：** 这种情况默认是*被阻止*的——`nmt-forge run` 会根据你的数据配比推导出一个早停**下限**（floor），并压制低于该下限的早停行为，同时在 `[schedule-sanity]` 行中记录原因。验证集的评估频率同样基于运行规模推导得出，以确保小型运行也不会被遗漏评估。如果你遇到了意料之外的停止，请阅读这些日志行；运行清单完整记录了具体情况及原因。（正常达到最后计划步骤的运行会被报告为已完成，而非早停。）

## “运行在真正启动前被拒绝”

**原因分析：** 触发了守卫门禁（gate）——这总比运行数小时后才失败的代价小得多。常见原因包括：

- **缺少训练附加组件（extra）**——`nmt-forge preflight run --config config.json` shows `✗ backend-installed`，附带修复方案 `python3 -m pip install 'nmt-forge[hf]'`。
- **缺少验证集，或验证集配置错误**——验证集隔离栅栏（dev-fence）会拒绝 `data.dev` 不是角色为 `dev` 的已注册数据集的运行。使用 `nmt-forge split … --register project` 切分出一个验证集。
- **数据泄漏**——训练文件与已注册的测试集或封存集存在相同的提示词或答案。使用 `nmt-forge leak-audit <file> --clean-to <file.clean.jsonl>` 进行清理，并将配置文件指向清理后的文件。
- **训练时长超限（Wall-clock）**——在开始的几分钟内，forge 会测算训练速度，并拒绝预计耗时超过 `model.time_budget_hours` 的运行。在 CPU 上，这通常意味着该预设需要 GPU（`nllb-600m`），或者数据混合规模远超预期。提示信息会指明调整手段：缩减数据规模、缩短序列长度，或者在确实愿意等待的前提下增加时间预算。

**解决方案：** 每次运行前执行 `nmt-forge preflight run --config config.json`；它会以 ✓/✗ 列出每个门禁，并为每个 ✗ 提供修复方案。

## "我想要的指标在报告中就是…缺失"

报告是诚实的，但在一个轴上是空白的（COMET、FST 有效性检查）。

**forge 发现：** `R6-referee-unavailable` — 该通道被命名为不可用，并说明原因。**解决方案：REFEREE。**

**解决方案：** 安装/配置指定的裁判程序（referee）并重新评分。当语言卡片（language card）声明了裁判程序时，forge 的提示信息会给出安装命令（`mt-eval setup --lang <code>`）。你当前获得的评分依然真实有效——只是在裁判程序就绪之前，缺少该维度的评估视角。

## "模型发出 `<unk>` 或乱码字符"

特别是在音节文字或扩展拉丁字母上。

**这取决于所选的预设。**

- **`cpu-tiny`** 会从训练行中自主学习词表，因此训练集中出现的每个字符都会被覆盖。这里的 `<unk>` 意味着输入中包含了从未在训练集出现的字符——罕见的字母或变音符号，或是其不同的 Unicode 形式（文本会被规范化为 NFC，因此组合字符与分解字符视作相同）。请检查你的训练和测试数据是否使用了相同的正字法。
- **`cpu-finetune` 和 `nllb-600m`** 使用预训练基座模型的分词器（tokenizer）。

⚠ **注意此项——尚未自动化（预训练基座）。** 基座模型的**分词器可能无法表示目标语言的文字系统（script）**。forge 暂未在训练前自动审计分词器的覆盖率。请对照目标文字系统的样本检查基座模型的分词器；优先选择词表能够覆盖该文字系统的基座（许多低资源语言均被 NLLB 家族的基座所覆盖），或在训练前扩展分词器。

## 当 forge 拒绝而你不明白为什么

拒绝总是说明**发生了什么**、**为什么**它会破坏结果，以及**修复**。如果仍然不清楚：

- `nmt-forge status` —— 你当前所处的状态以及接下来的单条命令。
- `nmt-forge preflight <command>` —— 该命令将触发的每一个门禁（✓/✗），以及针对每个 ✗ 的修复方案，便于你一次性解决所有问题，而无需反复排查（对于 `run`、`evaluate` 和 `export`，请添加 `--config config.json`）。
- 当有智能体读取运行结果时，为任意命令添加 `--json`：此时若被拒绝，将以单个 JSON 对象的形式返回——`{"error": {"type", "guard", "message", "why", "fix", …}}`——退出代码为 2。

拒绝不是你的设置中的错误 — 它是工具在错误到达你的结果之前捕捉它。这就是整个设计。
