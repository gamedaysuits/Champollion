# 诚实的局限

> 这些是我们**不会**超越的声明。如果本网站其他地方的任何内容暗示超过这里所写的内容，请将其视为错误并[告诉我们](/docs/network/perspectives/reporting-errors-and-owning-corrections)。

评估基础设施只有通过对其边界诚实才能赢得信任。以下是我们的边界，表述得足够清楚以便验证。

## 1. 深层形态学验证目前仅覆盖一个语言对

基于 FST 的形态学验证——检查每个输出词是否是目标语言中格式正确的词——在实践中仅针对**英语 → 平原克里语**进行了配置。`GiellaLTFSTMetric` 本身是**通用的**：它可以对任何发布了 GiellaLT `.hfstol` 分析器的语言进行评分（平原克里语、萨米语族、芬兰语、挪威博克马尔语、因纽特语等），因此该功能范围很广。但是**评估语料库目前仅存在于平原克里语**，所以 crk 是实践中唯一使用 FST 评分的语言对。排行榜上的所有其他语言对都使用表面指标（chrF++、BLEU）和行为检查进行评分。这些是有用的信号，但它们**不能**保证形态学有效性。我们不对任何没有 FST 和评估语料库的语言声称形态学验证。

## 2. 信任等级在启动时自我报告

大多数分数由贡献者自己运行测试工具并发布结果计算得出。服务器端**验证**——针对 SHA 固定的规范语料库重新评分提交——存在且在扩展，但"已验证"还不是通用的。阅读每一行上的信任徽章：**"自我报告"意味着完全如此**，这是默认设置。

## 3. 社区使用者验证尚未进行

我们的奖项要求**双语使用者的接受度 ≥ 70%**。该门槛已指定，运行它的工具正在建设中——但**尚未进行社区使用者审查**，**本网站上的任何分数都未通过使用者门槛**。复合指标和 chrF++ 数字是机器信号，而非社区裁决。

## 4. 评估沙箱存在；其保管仪式尚未进行

我们从源头获取语料库并对其进行 SHA 固定，保留的拆分数据集会被封存。当社区持有一个秘密测试集时，可以在测试集不离开他们手中的情况下对某种方法进行评分——而这种评估现在有**两条通道**。对于标准神经模型，首选通道是**声明式**的：参与者仅提交数据——safetensors 权重 + 声明式分词器 + 配置——组织者在他们自己受信任的推理引擎中运行它（`trust_remote_code=False`，离线；对架构要求宽松，因为安全性在于无代码格式，而不是架构名称）。完全没有参与者的代码运行，因此不需要沙盒隔离；安全检查是可判定的格式验证（这是 safetensors 而不是 pickle 吗？没有 `trust_remote_code` 吗？），而不是试图证明任意代码是安全的。对于真正属于代码的方法（流水线、LLM 辅助的混合方法），后备方案是网络隔离的**沙盒**（静态检查、`--network=none` 容器、仅输出分数的网络出口、可选的真正物理隔离文件传输）。沙盒包含不受信任的代码，而不是拒绝运行它，因此坦诚来说它是较弱的通道——其核心安全保证是 `--network=none`（启发式静态扫描无法审查二进制模型），而更深层次的加固（seccomp、microVMs）被推迟了。请参阅 [run a sovereign contest](/docs/network/sovereignty/run-a-sovereign-contest) 了解究竟哪些功能已上线，哪些未上线。无论哪种方式都**尚未**构建的是：社区密钥托管方面——门限签名、密钥仪式和节点证明。如今的授权是记录在案的流程（单一托管人、单一密钥、如实标记），因此在托管工作和社区同意跟上之前，黄金标准的**奖金**评估仍处于关闭状态。

## 5. 密钥保管已决定；社区保管人在确认中

保管*机制*已决定：一个**Champollion 持有零密钥份额**的阈值/多签方案。保管人本身由社区选择，这些对话正在进行中——因此我们说**"社区密钥保管人（在确认中）"**。保管不是同意：关系型的社区同意流程是其自身的、更缓慢的、更重要的轨道。
