# MT 评估

> **执行摘要。** 本页面定义了排行榜提交标准、评分机制（以 chrF++ 作为首要指标，旁边附带标准指标和诊断指标）、防刷榜策略、验证层级以及提交工作流。曾接触过评估数据的方法将被取消资格。

champollion 包含一个机器翻译评估框架，专为翻译方法的**可重复基准测试**而设计——特别是对于低资源和土著语言，其中标准 MT 基准不存在，质量声明难以验证。

---

## 排行榜

核心是 **[方法排行榜](https://champollion.dev/leaderboard)** —— 一个公开的计分板，实时运行且**开放提交**，研究人员与社区成员可以在此提交并对比带有指纹标记、可复现评估的翻译方法。

每次提交包括：

- **带指纹的流水线** — 绑定到特定的 Git commit 和配置哈希，使结果可追溯到生成它们的确切代码
- **版本化数据集** — 经过内容哈希与版本控制；得分仅在相同数据集版本内具有可比性
- **标准化指标** — 所有评分均由共享的评估测试工具包（evaluation harness）计算，消除实现上的差异
- **信任层级** — 自行基准测试（Self-benchmarked）、Champollion 验证（Champollion Verified）或社区验证（Community Validated）
- **成本跟踪** — 记录每次提交的 API 成本，让成本与质量的权衡透明可见

排行榜像 WMT、FLORES-200 和 AmericasNLP 共享任务报告机器翻译评估一样对运行记录进行排名：采用**单一标准指标 chrF++**，并展示其 95% 置信区间和 sacreBLEU 签名 —— 例如 `chrF++ 47.5 [45.9, 49.0]`。所有其他指标均并列显示在其旁边，绝不混杂其中：

| 指标 | 角色 | 衡量内容 |
|--------|------|------------------|
| **chrF++** | **首要与排名指标** | 针对参考译文的字符级 n-gram F-score（sacreBLEU，`word_order=2`）。相比词级指标能更好地应对形态丰富的语言 |
| **BLEU, spBLEU, TER, COMET** | 首要指标旁附带的标准指标 | 机器翻译论文报告的其他指标；若计算了 COMET，则附带其模型 ID |
| **Exact Match** | 诊断指标 | 翻译结果与参考译文完全一致的频率 |
| **FST Acceptance** | 诊断指标 | 针对拥有有限状态转换器（FST）的语言：输出词汇中合法形态的比例。它不与源文本或参考译文对比，因此绝不是评分 |
| **Equivalent Match** | 诊断指标 | 与参考译文或可接受变体（词序、正字法惯例）相匹配的比例。目前支持 CRK；正在泛化推广。 |
| **Semantic Score** | 诊断指标 | 通过确定性验证器检查的语义保留程度。目前支持 CRK；正在泛化推广。 |
| **Score caveats** | 显示在首要指标旁 | 当输出复制了源文本、远短于或远长于参考译文、针对多个输入重复同个输出，或测试行在训练数据中有孪生副本时给出警告 |

某次运行是否优于另一次运行，是由针对 chrF++ 的配对显著性检验决定的，而不是单纯比较两个数字的先后顺序 —— 重叠的区间是一个警告，表明先后顺序可能是噪声（参见[统计显著性检验](/docs/network/specifications/significance)）；竞赛排名使用该检验来形成排名聚类。chrF++ 仅对同一数据集上的系统进行排名，绝不跨语言排名。任何自动评分都不代表质量标签 —— 只有母语者的同行人工评审才能认证质量。先前使用的加权综合评分和质量层级已被废除；旧卡片上的综合评分即使显示，也会标注为“传统综合评分（已废除）”。

:::info[完整指标套件]
[评分规范](/docs/network/specifications/scoring#how-runs-are-scored)定义了运行记录的评分机制以及完整的指标清单（六大类别：表面、结构、语义、行为、合规性以及报告的对比项）。
:::

## 可用数据集

运行记录可依据哪些指标进行评分由工具列出，因此本页面不作单独罗列：

```bash
# the runnable corpora for a pair: size, contamination, domain, licence, provider
mt-eval corpora --source eng --target crk

# …and the catalogued ones that can never run, each with its reason
mt-eval corpora --source eng --target crk --include-quarantined
```

[评估数据集](/docs/network/leaderboard/datasets)页面介绍了目录、语料库格式、难度层级、许可证赛道以及如何创建您自己的数据集。该目录中的三条规则决定了什么可以参与排名：

- **隔离语料库绝不参与排名。** 它会被收录在目录中，但绝不可运行，数据库会拒绝针对它提交的评分。EdTeKLA 的英语→平原克里语（Plains Cree）语料库（`eval-eng-crk-edtekla-dev-v1` 和 `eval-eng-crk-edtekla-textbook`）已被隔离。它们附带修改过的、具有主权范围限制的 CC BY-NC-SA（`LicenseRef-EdTeKLA-Modified-CC-BY-NC-SA-4.0`），并被排除在所有排行榜、奖项和商业赛道之外。
- **受污染语料库仅限相对排名。** FLORES+ 以及在污染度评级为 `HIGH` 或 `MEDIUM`（或完全未评级）的任何语料库，其运行卡片上都会盖上“仅限相对比较”的印章。它仅用于对比在同一语料库上运行的方法，绝不作为绝对质量进行报告。只有评级为 `LOW` 的语料库才能按绝对质量进行排名。
- **许可证赛道规则有效执行。** 非商业语料库不得进入商业与奖金通道。依据修改版、定制或未说明的授权许可发布的语料库，在权利持有者的许可记录在其条目之前，拒绝远程模型 API 评估。

**竞赛在主办方保管的密封集上运行。** 竞赛不会根据这些公开语料库进行评分。主办方（社区或组织）在其自己的基础设施上保存一个密封的保留测试集。参赛者通过主办方发布的公开开发集获得参赛资格，然后向主办方的节点提供模型或方法以供运行。主办方的保管人授权每次运行，且对外仅输出评分。请参见[举办主权竞赛](/docs/network/sovereignty/run-a-sovereign-contest)。

:::danger[不要在评估数据上进行训练]

**这些数据集仅用于评估。** 在评估数据上进行训练、微调、少样本提示或以其他方式接触的方法将产生人为夸大的分数，并将**被取消排行榜资格**。

这不是建议——这是评估完整性的唯一最重要的规则。使用单独的语料库进行训练。评估集必须在开发期间对您的模型保持不可见。

如果您使用教练数据或少样本示例，这些必须来自**完全独立的来源**。如有疑问，不要包括它。
:::

:::warning[LLM 非确定性]

LLM 输出是非确定性的。分数代表特定模型版本和 API 配置下的时间点测量。模型提供商可能随时更新权重、解码策略或安全过滤器，这可能导致运行之间的分数漂移。排行榜记录每次提交的确切模型 slug 和时间戳。
:::

## 什么是好方法

并非所有方法都是平等的。以下是严谨工作与夸大分数的区别。

### 强方法的特征

- **训练和评估数据的清晰分离** — 您的方法在开发、调优、提示工程或少样本示例选择期间从未见过评估集
- **可重复** — 其他人可以克隆您的仓库、运行工具并获得相同的分数（在 LLM 非确定性范围内）
- **有文档** — 您的[方法卡](/docs/network/specifications/methods)描述了您的方法做什么、使用什么工具以及其局限性
- **对范围诚实** — 如果您的方法仅适用于一个语言对，请说明；如果它在某些形态模式上降级，请记录下来
- **社区意识** — 对于土著语言，您的方法尊重数据主权。您已咨询了语言社区或仅使用开放许可数据

### 危险信号（被取消资格的内容）

| 危险信号 | 为什么这是个问题 |
|----------|--------------------|
| 在评估数据上训练 | 完全破坏了评估的目的。夸大的分数误导所有人。 |
| 精选结果 | 运行 10 次并提交最佳运行而不披露其他运行 |
| 未披露的后处理 | 在评分前手动修复输出 |
| 受污染的教练数据 | 使用评估集示例作为少样本提示或字典条目 |
| 声称商业就绪而无来源 | 如果您的方法使用 CC BY-NC-SA 数据，则不是商业就绪 |

### 验证层级

验证层级描述了**谁验证了该结果**。它们不是质量标签（旧的自动质量层级已[废除](/docs/network/specifications/scoring#5-quality-tiers)）。

| 层级 | 含义 | 如何获得 |
|------|---------|--------------|
| **自行基准测试 (Self-benchmarked)** | 您自行运行了测试工具包并提交了结果 | 使用 `mt-eval publish` 发布您的运行卡片 |
| **Champollion 验证 (Champollion Verified)** | 本项目根据固定 SHA 的参考语料库独立对您提交的输出重新评分，并复现了您的得分 | 重新评分器是一个维护者工具，以批处理方式手动运行。没有任何定时调度，因此提交不会在到达时立即重新评分（见下文） |
| **社区验证 (Community Validated)** | 根据社区自身协议获得资质的目标语言双语母语者，对输出的分层抽样样本进行了评审（≥30 个条目，≥2 位评审员），且 ≥70% 达到了社区的标准。仅通过社区自身的测试授予；抽检降级的机制是对称的 | 将方法代码提交给治理组织 —— 他们会在黄金标准集上运行代码并将输出提交给社区评审 |

**社区验证评审是一个独立的赛道，目前尚不存在人工评估得分：** 测试工具包可以根据已结束竞赛的冻结排名，选出固定人工评审预算所能覆盖的系统（仅限完整的平局组 —— 绝不会将一个聚类切成两半），但它不记录评分，目前排行榜上的任何内容都不包含人工评审结果。

**排名是聚类，而不是严格的次序。** 显著性检验无法区分的相邻条目共享一个排名，并带有排名*范围*；在密封竞赛中，每个片段的输出绝不会离开组织者的机器，配对检验在该机器上运行，仅输出其签名的判定结论；若没有这些签名，平局则基于置信区间或点估计相等证据。其运作机制以及证据阶梯中每个层级的可靠程度，详见[统计显著性检验 → 排名聚类](/docs/network/specifications/significance#ranking-clusters)。

### 验证如何扩展：基于声誉权重的审计

**我们不声称溯源可信。** 排行榜上的每一行都是由贡献者在他们*自己的*机器上运行*开源*测试工具包生成的。对于自托管计算，服务器无法验证“此运行确实来自该测试工具包” —— 测试工具包的签名密钥掌握在贡献者手中，因此签名认证的是*机器，而非诚信*。与其自欺欺人，不如承认**此处的有效性是通过实践赢得的，并且具备自我修正机制**：某一行之所以值得信赖，是因为其得分是**可复现的**，并且背后的贡献者已经**押上了自己的声誉，一旦被发现伪造就会名誉扫地。** 验证分为四层进行，因此在必须严格的地方做到彻底，在可行的地方保持低成本 —— 本项目永远不必重新运行每个人的工作。

- **L0 — 对所有内容重新评分（免费，约 100%）。** 重新评分器使用测试工具包所用的相同指标，根据*您提交的输出本身*针对**固定 SHA 的参考语料库**（而不是您本地存储的副本）重新推导出您的得分。如果输出无法复现该得分，或者存储的参考译文被篡改，该运行记录就会被**取消资格** —— 仅此一项就能杜绝手动输入或修改评分的行为。能够复现的运行记录将晋升为 **Champollion 验证 (Champollion Verified)** —— 这是竞赛排名默认采用的层级，也是唯一有资格获奖的层级。该功能已构建且成本极低，但它是一个**由维护者手动运行的命令**：提交时不会自动运行，也没有任何调度程序执行它。在此机制改变之前，每一行到达时 —— 以及之后 —— 都保持为自行基准测试状态。
- **L1 — 贡献者声誉阶梯。** 每个贡献者（通过登录身份识别）*仅*能通过通过下述更深层次的检查来获得声誉 —— 绝不可能仅凭数量累积，因此批量创建新身份没有任何用处。声誉是**公开的**，它决定了触发昂贵检查的频率。
- **L2 — 重新运行*样本*（昂贵检查；仅限策略，尚无重跑器）。** 对于*公开*开发集，L0 无法捕获直接复制参考译文作为其“翻译”的贡献者。要发现这种情况，需要实际重新运行模型 —— 这需要真实的算力 —— 因此我们会在**抽样样本**上进行，而不是针对所有人。**抽样策略**已构建并经过测试：选定某次运行的概率随着**重要性**的提高而增加（首次打通通往整个语系桥梁的运行记录*总是*会被选中），随着**异常度**的提高而增加（好得令人难以置信、远超之前最佳成绩的跃升*总是*会被选中），并随着**声誉**的提高而降低（通过多次审计的贡献者极少会被抽检；新人或匿名提交者在赢得信任之前每次运行都会被检查）。通过 L2 审计会提高声誉。**该策略所驱动的重跑器尚不存在**，因此从未触发过 L2 审计：被选中的运行记录将被标记为 *L2-pending*。
- **L3 — 相互佐证（免费验证）。** 当两名*独立*贡献者在同一语料库上运行同一模型，且他们重新评分的输出**一致**时，该一致性*即为*验证 —— 并且会同时提高他们两人的声誉。若出现真实的**不一致**，则会将两次运行均标记以进行 L2 审计。结果复现会获得奖励，而不是被视为冗余。

**一次被抓到的伪造就是灾难性的 —— 犹如论文撤稿。** 经证实的伪造行为会使该贡献者的声誉归零，**重新审计其全部已验证历史记录**（其所有已验证的运行记录都会被送回重新验证），并在审计日志中**公开**记录。这就是轻量抽样之所以安全的原因：在公开开发集上作弊可能在单次运行中蒙混过关，但其预期代价 —— 失去所有已建立的信任并导致整个历史记录被重新审查 —— 使其成为一项极不划算的赌注。这些规则对称地约束维护者自己的运行记录。

**为什么做出贡献仍然值得。** 您始终承担昂贵的部分（运行您的方法）；项目仅承担针对所有人的免费 L0 重新评分，以及针对*不断缩小的样本*的 L2 重新运行 —— 对于新手和高风险运行比例较高，对于经验证的贡献者比例较低。验证成本通过*声誉摊销并通过相互佐证分担*，而不是每次都全额重新支付。

## 如何提交

1. **构建您的方法** — 有关方法接口，请参见[构建方法](/docs/network/specifications/methods)
2. **运行测试工具包** — 有关安装和用法，请参见[评估测试工具包 (Eval Harness)](/docs/network/specifications/harness)
3. **生成运行卡片** — 测试工具包会生成一份包含您的评分、指纹和元数据的 JSON 运行卡片
4. **发布** — `mt-eval publish eval/logs/harness/<run-id>_report.json --prod` 将运行卡片上传至排行榜（使用 `--dry-run` 进行预览）
5. **展示在排行榜上** — 您的运行记录将列为*自行基准测试（未验证）*。[方法排行榜](https://champollion.dev/leaderboard)列出并对所有未被 `disqualified` 的行进行排名，包含自行基准测试的记录并打上相应标签；筛选 *Champollion Verified* 可仅查看已重新评分的结果。将运行记录提升至该层级的 L0 重新评分是一项由维护者执行的批处理任务，没有任何定时调度，因此目前榜单上的每一行都是自行申报的主张。仅显示已验证记录是**竞赛**排名的默认设置，也是唯一有资格获得奖金的层级

## 诚信策略：撤稿、重跑、除名、争议

预先制定，从而使执行成为规范流程，而非无谓纠纷。这些规则对称地约束所有人 —— 包括维护者自己的运行记录。

**不可撤稿。** 已发布的运行记录是一条永久记录。任何人都没有机制可以因为得分令人尴尬而将其删除。每一行运行记录都带有服务器标记的 `submitted_at` 时间戳和不可篡改的审计追踪；管理操作本身也会被记录。

**重跑记录仅限追加，绝不替换。** 如果您改进了您的方法，请发布一次新的运行记录。旧的运行记录将予以保留。选择性披露 —— 在私下测试多个变体且仅发布胜出者 —— 是导致其他排行榜容易被刷榜钻空子的原因；仅追加（append-only）的记录方式是在结构层面给出的解决方案。指纹去重可阻止完全相同字节的重复提交垃圾信息；它绝不会重写历史。

**除名是规则的执行，且必须指明具体规则。** 运行记录仅会因列出的原因而被除名（显式标记为 `disqualified` —— 而不是静默移除）：使用了被隔离或不合规子集的数据集（由每个客户端底层的数据库触发器强制执行）、语料库校验和不匹配、伪造或超出范围的评分、违反内容安全守则，或者数据保管人撤回了底层数据的注册。除名操作会指明规则和证据。新的除名原因必须在应用到任何案例之前，通过注明修订日期的编辑添加到此处，绝不会针对单一案例进行溯及既往的临时编造。

**任何人都可以标记举报某项结果。** 展开排行榜上的对应行并使用*标记此结果 (Flag this result)*：这将打开一个已预先绑定该运行 ID 的消息表单，您可以说明您认为存在的问题以及判定依据 —— 受污染的语料库、与标签不符的指标、错误归属的方法或其他任何问题。标记必须说明原因。没有原因的标记等同于点踩（downvote），而本排行榜没有点踩机制。

**标记是一条私信，而不是投票。** 它作为工单送达维护者手中，不会流向任何其他地方。永远不会显示标记的数量 —— 无论在行中、运行卡片中还是任何其他地方 —— 因为公开的计数本身就会引来刷票投机，而且一项结果的地位必须建立在证据之上，而不是取决于有多少人反对。仅仅提交标记，不会对该行产生任何改变。

**被支持的标记仅会以一种方式体现：** 该结果被标记为 `disqualified`，原因必须是本页面上已列出的缘由。与其他所有除名一样，新的原因必须**在应用到任何人之前，通过注明修订日期的编辑添加到此处** —— 因此标记绝不会催生秘密规则或追溯适用的规则。如果标记未被支持，该行将保持不变；如果您留下了联系地址，无论哪种情况您都会收到回复。

**信任层级是标签，而非修改。** `self-benchmarked` 的行属于自行申报的主张；`Champollion Verified` 的行已根据固定 SHA 的语料库对提交者的输出进行了独立重新评分；`Community Validated` 仅通过社区自身的测试授予。验证会更改某一行的层级 —— 绝不会更改该行的评分。

**声誉是公开的且具备自我修正机制。** 贡献者声誉，以及记录了每次重新评分、抽样重跑、相互佐证和伪造惩罚（fabrication burn）的审计日志，均是公开的。声誉不是评分乘数，绝不会触动单次运行的数值 —— 它仅决定该贡献者的运行记录被重新审计的频率（见上文*基于声誉权重的审计*）。经证实的伪造行为会像撤稿一样被公开记录，并会对该贡献者的整个已验证历史进行重新审计；同样的规则也适用于维护者自己的运行记录。

**争议。** 附带运行 ID 和具体诉求（评分错误、数据集错误、规则适用不当）提交 Issue。维护者将在公开环境下重新运行确定性检查；结果及其证据将附在 Issue 中。如果争议涉及社区的数据或验证，则由社区自身的主管机构裁决，榜单将执行其决定。对于设有奖金的竞赛，同样适用这些规则，外加竞赛预先发布的资格赛和审计步骤 —— 获奖者会在发放奖金**之前**接受审计，取消资格将如同其他任何除名一样明确援引相应规则。

## 未来方向

- **综合模型比较运行** — 使用自定义评估语料库（不是公开基准）对 champollion 语言进行前沿模型（GPT-4o、Claude、Gemini 等）的系统评估
- **更多语言对** — 随着社区验证的数据集变得可用，克丘亚语、因纽特语和其他低资源语言
- **数据集导入** — 将外部评估数据集（WMT、Tatoeba 等）转换为 champollion 评估格式的工具
- **自动重新运行** — 检测模型版本更改并重新运行基准以追踪分数漂移
