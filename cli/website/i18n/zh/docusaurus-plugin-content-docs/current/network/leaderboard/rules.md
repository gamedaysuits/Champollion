# MT 评估

> **执行摘要。** 本页定义了排行榜提交标准、评分指标（chrF++、FST 接受度、精确匹配、等价匹配、语义分数）、反作弊政策、验证层级和提交工作流程。已接触评估数据的方法将被取消资格。

champollion 包含一个机器翻译评估框架，专为翻译方法的**可重复基准测试**而设计——特别是对于低资源和土著语言，其中标准 MT 基准不存在，质量声明难以验证。

---

## 排行榜

核心部分是 **[方法排行榜](https://champollion.dev/leaderboard)** —— 这是一个公开的计分板，实时更新并**开放提交**，研究人员和社区成员可以在这里提交并比较翻译方法，并进行带有指纹记录、可复现的评估。

每次提交包括：

- **指纹化流水线 (Fingerprinted pipeline)** —— 绑定到特定的 Git 提交和配置哈希，因此结果可以追溯到生成它们的具体代码
- **版本化数据集 (Versioned dataset)** —— 经过内容哈希处理并进行版本控制；分数只能在相同的数据集版本内进行比较
- **标准化指标 (Standardised metrics)** —— 所有评分均由共享的评估测试框架 (evaluation harness) 计算，消除了实现上的差异
- **信任层级 (Trust tiers)** —— 自行基准测试 (self-benchmarked)、Champollion 验证 (Champollion Verified) 或社区验证 (Community Validated)
- **成本追踪 (Cost tracking)** —— 每次提交的 API 成本，使成本与质量的权衡保持透明

排行榜评分五个指标。三个适用于任何语言；两个可用于平原克里语，随着我们的扩展将被推广：

| 指标 | 类型 | 测量内容 |
|--------|------|------------------|
| **chrF++** | 字符 n-gram F 分数 | 主要质量指标 — 与人类判断相关性好，特别是对于形态丰富的语言 |
| **精确匹配** | 完美匹配的比例 | 严格准确性 — 翻译与黄金标准完全相同的频率如何？ |
| **FST 接受度** | 形态学门槛通过率 | 对于具有有限状态转换器验证的方法 — 多少比例的输出在形态学上有效？ |
| **等价匹配** | 可接受变体率 | 与参考或可接受变体匹配的比例（词序、正字法约定）。目前为 CRK；正在推广。 |
| **语义分数** | 语义保真度 | 意义保留 — 翻译是否捕捉了预期的意义，无论表面形式如何？目前为 CRK；正在推广。 |

:::info[完整指标套件]
[评分规范](/docs/network/specifications/scoring)定义了完整的指标清单（六个类别：表面、结构、语义、行为、合规性和报告比较器）、复合评分公式、权重表和质量等级阈值。
:::

**[→ 查看排行榜](https://champollion.dev/leaderboard)**

## 可用数据集

### EDTeKLA 开发集 v1

第一个评估数据集，为英语→平原克里语 (SRO) 翻译而构建。由阿尔伯塔大学 [EdTeKLA 研究小组](https://spaces.facsci.ualberta.ca/edtekla/)创建。

| 属性 | 值 |
|----------|-------|
| **ID** | `edtekla-dev-v1` |
| **语言对** | EN → CRK（平原克里语，SRO 正字法） |
| **条目数量** | 436 个条目的开发集划分 (`textbook_dev.json`)；完整明细在[评估数据集页面](/docs/network/leaderboard/datasets#edtekla-development-set-v1)中统一说明 |
| **许可证** | [EdTeKLA 修改版的 CC BY-NC-SA](https://github.com/EdTeKLA/IndigenousLanguages_Corpora) (`LicenseRef-EdTeKLA-Modified-CC-BY-NC-SA-4.0`，主权范围) —— 非商业用途；从排行榜、奖金和商业/API 渠道中剥离 |
| **出处** | `gold_standard`（由母语者验证），`textbook`（已出版的教育材料） |

### FLORES+ Devtest — 仅限开发使用

> [!WARNING]
> **FLORES+ 可用于开发和调试，但不用于官方排行榜评估。** FLORES+（原 Meta FLORES-200）是一个广泛公开的基准数据集，前沿 LLM 几乎肯定已在其上进行了训练。针对 FLORES+ 的分数不能可靠地反映基于 LLM 方法的真实翻译质量。非 LLM 方法（FST、基于规则、微调 NMT）受影响较少，但 FLORES+ 分数仍不发布到排行榜。

FLORES+ 测试装置仍可在 `test/benchmark/fixtures/` 中获得，用于管道冒烟测试、跨语言验证和开发使用。官方评估使用从人工编写文本构建的自定义语料库，这些文本不以平行形式公开提供。

有关完整的数据集架构、难度层级以及如何创建自己的数据集，请参阅[评估数据集](/docs/network/leaderboard/datasets)。

:::danger[不要在评估数据上进行训练]

**这些数据集仅用于评估。** 在评估数据上进行训练、微调、少样本提示或以其他方式接触的方法将产生人为夸大的分数，并将**被取消排行榜资格**。

这不是建议——这是评估完整性的唯一最重要的规则。使用单独的语料库进行训练。评估集必须在开发期间对您的模型保持不可见。

如果您使用教练数据或少样本示例，这些必须来自**完全独立的来源**。如有疑问，不要包括它。
:::

:::warning[LLM 非确定性]

LLM 输出是非确定性的。分数代表特定模型版本和 API 配置下的时间点测量。模型提供商可能随时更新权重、解码策略或安全过滤器，这可能导致运行之间的分数漂移。排行榜记录每次提交的确切模型 slug 和时间戳。
:::

## 什么是好方法

并非所有方法都是平等的。以下是严谨工作与夸大分数的区别。

### 强方法的特征

- **训练和评估数据的清晰分离** — 您的方法在开发、调优、提示工程或少样本示例选择期间从未见过评估集
- **可重复** — 其他人可以克隆您的仓库、运行工具并获得相同的分数（在 LLM 非确定性范围内）
- **有文档** — 您的[方法卡](/docs/network/specifications/methods)描述了您的方法做什么、使用什么工具以及其局限性
- **对范围诚实** — 如果您的方法仅适用于一个语言对，请说明；如果它在某些形态模式上降级，请记录下来
- **社区意识** — 对于土著语言，您的方法尊重数据主权。您已咨询了语言社区或仅使用开放许可数据

### 危险信号（被取消资格的内容）

| 危险信号 | 为什么这是个问题 |
|----------|--------------------|
| 在评估数据上训练 | 完全破坏了评估的目的。夸大的分数误导所有人。 |
| 精选结果 | 运行 10 次并提交最佳运行而不披露其他运行 |
| 未披露的后处理 | 在评分前手动修复输出 |
| 受污染的教练数据 | 使用评估集示例作为少样本提示或字典条目 |
| 声称商业就绪而无来源 | 如果您的方法使用 CC BY-NC-SA 数据，则不是商业就绪 |

### 验证层级

验证层级描述**谁验证了结果** — 与[评分规范，§5](/docs/network/specifications/scoring#5-quality-tiers)中定义的质量层级（基线 → 流畅）分开，后者描述自动复合分数的含义。

| 层级 | 含义 | 如何获取 |
|------|---------|--------------|
| **自行基准测试 (Self-benchmarked)** | 您自行运行了测试框架并提交了结果 | 使用 `mt-eval publish` 发布您的运行卡片 (run card) |
| **Champollion 验证 (Champollion Verified)** | 服务器根据固定 SHA 值的参考语料库，独立对您提交的输出进行了重新评分，并复现了您的分数 | 自动 —— 每次提交都会被重新评分（见下文） |
| **社区验证 (Community Validated)** | 符合社区自身协议资质的目标语言双语者，审查了输出的分层样本（≥30 个条目，≥2 名审查员），且 ≥70% 达到了社区的标准。仅通过社区自身的测试授予；通过抽查降级是对等的 | 向治理组织提交方法代码 —— 他们会针对黄金标准集运行该代码，并将输出交由社区审查 |

### 验证如何扩展：基于声誉加权的审计

**我们不声明出处。** 排行榜上的一行数据是由贡献者在他们**自己**的机器上运行**开源**测试框架生成的。“这次运行确实是通过测试框架完成的”这一点，服务器无法对自托管计算进行验证 —— 测试框架的签名密钥在贡献者手中，因此签名验证的是**机器，而不是诚实度**。与其假装可以验证，不如承认**这里的有效性是靠争取和自我纠正的**：一行数据值得信任，是因为它的分数是**可复现的**，并且其背后的贡献者**押上了自己的声誉，一旦被发现造假，声誉就会毁于一旦。** 验证分为四个层级运行，因此在必须彻底的地方做到彻底，在可以节省成本的地方保持低廉 —— 项目永远不需要重新运行所有人的工作。

- **L0 —— 重新评分所有内容（免费，100%）。** 服务器会根据**固定 SHA 值的参考语料库**（而不是您存储的副本），使用与测试框架相同的指标，从**您自己提交的输出**中重新推导您的分数。如果无法从输出中复现分数，或者存储的参考内容被篡改，该次运行将被**取消资格** —— 仅凭这一点就能杜绝手动输入或篡改的分数。成功复现的运行将被提升为 **Champollion 验证 (Champollion Verified)**，这是排行榜唯一进行排名的层级。此过程在每次提交时运行，仅需几毫秒。
- **L1 —— 贡献者声誉阶梯。** 每个贡献者（通过其登录信息识别）*只能*通过通过以下更深层次的检查来获得声誉 —— 绝不能仅靠提交数量，因此注册新身份毫无意义。声誉是**公开的**，它决定了昂贵检查的触发频率。
- **L2 —— 重新运行*样本*（昂贵的检查）。** 对于*公开的*开发集，L0 无法抓住那些简单地将参考内容复制为“翻译”的贡献者。要抓住这种行为，需要实际重新运行模型 —— 真实的计算 —— 因此我们只对**样本**进行此操作，而不是对所有人。一次运行被抽样进行 L2 重新运行的概率随着**风险/重要性 (stakes)** 的增加而增加（例如，为整个语系搭建第一座桥梁的运行*总是*会被重新运行），随着**异常度 (anomaly)** 的增加而增加（例如，比之前最佳成绩有令人难以置信的飞跃的运行*总是*会被重新运行），并随着**声誉 (reputation)** 的增加而降低（通过多次审计的贡献者很少被抽查；新手或匿名提交者在每次运行时都会被检查，直到他们赢得了信任）。通过 L2 审计会提升声誉。
- **L3 —— 交叉印证（免费验证）。** 当两名*独立的*贡献者在相同的语料库上运行相同的模型，并且他们重新评分的输出**一致**时，这种一致性*本身*就是验证 —— 并且它会提升双方的声誉。真正的**分歧**会将这两次运行都标记为需要进行 L2 审计。复现会得到奖励，而不是被视为多余。

**一次被发现的造假是灾难性的 —— 就像撤稿一样。** 经证实的造假会将贡献者的声誉清零，**重新审计其整个已验证的历史记录**（他们的每一次已验证运行都会被送回重新验证），并**公开**记录在审计日志中。这就是轻量级抽样之所以安全的原因：在公开的开发集上作弊可能会在某次运行中蒙混过关，但其预期成本 —— 失去所有赢得的信任并让整个记录受到重新审查 —— 使其成为一个糟糕的赌注。这些规则同样对等地约束维护者自己的运行。

**为什么贡献仍然是值得的。** 您始终承担昂贵的部分（运行您的方法）；项目仅支付对所有人免费的 L0 重新评分，以及对*不断缩小的样本*进行 L2 重新运行的成本 —— 对于新手和高重要性的运行，抽样率很高；对于已证明可靠的贡献者，抽样率很低。验证成本*通过声誉摊销并通过交叉印证分担*，而不是每次都全额支付。

## 如何提交

1. **构建您的方法** —— 有关方法接口，请参阅 [构建方法](/docs/network/specifications/methods)
2. **运行测试框架** —— 有关设置和用法，请参阅 [评估测试框架](/docs/network/specifications/harness)
3. **生成运行卡片** —— 测试框架会生成一个包含您的分数、指纹和元数据的 JSON 运行卡片 (run card)
4. **发布** —— `mt-eval publish eval/logs/harness/<your-run-card>.json` 将运行卡片上传到排行榜
5. **出现在排行榜上** —— 您的运行最初被标记为*自行基准测试（未验证）*，然后服务器会自动根据固定 SHA 值的语料库对您的输出进行重新评分 (L0)；当成功复现时，该运行将晋升为 *Champollion 验证* —— 这是 [方法排行榜](https://champollion.dev/leaderboard) 唯一进行排名的层级。更深层次的基于声誉加权的审计遵循上述信任层级

## 诚信政策：撤回、重新运行、下架与争议

提前制定这些规则，是为了让执行成为一种程序，而不是一场闹剧。这些规则对等地约束所有人 —— 包括维护者自己的运行。

**禁止撤回。** 已发布的运行是永久记录。没有任何机制 —— 对任何人而言 —— 可以因为分数难看而删除它。每一行运行记录都带有服务器盖章的 `submitted_at` 时间戳和不可变的审计跟踪；审核操作本身也会被记录。

**重新运行只能追加，绝不替换。** 如果您改进了方法，请发布一次新的运行。旧的运行记录会保留。选择性披露 —— 私下测试许多变体并仅发布获胜者 —— 正是其他排行榜容易被操纵的原因；仅限追加的记录是结构性的解决方案。指纹去重可以阻止字节完全相同的重复提交垃圾信息；它绝不会改写历史。

**下架是规则的执行，并会指明具体规则。** 一次运行被下架（标记为 `disqualified`，可见地 —— 而不是悄悄移除）仅限于以下列出的原因：被隔离或不当子集的数据集（由每个客户端底层的数据库触发器强制执行）、语料库校验和不匹配、伪造或超出范围的分数、违反内容保护规则，或数据管理员撤回底层数据的注册。下架操作会指明违反的规则和证据。新的原因会在应用之前通过带有日期的编辑添加到此处，绝不会为了某个案例而追溯性地捏造。

**信任层级是标签，而不是编辑。** `self-benchmarked` 行是声明；
`Champollion Verified` 行已根据固定 SHA 值的语料库，从提交者的输出中进行了独立的重新评分；`Community Validated` 仅通过社区自身的测试授予。验证只会改变一行的层级 —— 它绝不会改变该行的分数。

**声誉是公开且自我纠正的。** 贡献者的声誉，以及记录每次重新评分、抽样重新运行、交叉印证和造假惩罚的审计日志，都是公开的。声誉不是分数的乘数，也绝不会影响运行的数值 —— 它只决定贡献者的运行被重新审计的频率（参见上文的*基于声誉加权的审计*）。经证实的造假会像撤稿一样被公开记录，并重新审计该贡献者的整个已验证历史记录；同样的规则也适用于维护者自己的运行。

**争议。** 请提交一个 Issue，提供运行 ID 和具体的诉求（分数错误、数据集错误、规则误用）。维护者将在公开场合重新运行确定性检查；结果及其证据将记录在该 Issue 中。如果争议涉及社区的数据或验证，则由社区自身的权威机构做出决定，排行榜将执行他们的决定。对于有奖竞赛，适用相同的规则，外加竞赛预先公布的资格赛和审计步骤 —— 获胜者在发放奖金**之前**会接受审计，取消资格时会像任何其他下架操作一样准确引用相关规则。

## 未来方向

- **综合模型比较运行** — 使用自定义评估语料库（不是公开基准）对 champollion 语言进行前沿模型（GPT-4o、Claude、Gemini 等）的系统评估
- **更多语言对** — 随着社区验证的数据集变得可用，克丘亚语、因纽特语和其他低资源语言
- **数据集导入** — 将外部评估数据集（WMT、Tatoeba 等）转换为 champollion 评估格式的工具
- **自动重新运行** — 检测模型版本更改并重新运行基准以追踪分数漂移
