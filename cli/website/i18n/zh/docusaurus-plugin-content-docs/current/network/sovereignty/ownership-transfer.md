# 所有权与条款

> **执行摘要**：Champollion 按照设计理念，不设通用的统一协议。
> 条款由拥有数据的数据管理方按语料库、按语言以及按奖项分别制定——平台的职责是尊重并遵守这些设定的任何条款。本页说明了条款清单所涵盖的各维度，以及**社区转让模板**：这是供社区治理机构在主办奖项并选择 `pass_to_holders` 条款时采用和修改的起点。

## 条款框架

Champollion 的设计在条款上具有灵活性，以便尊重所有许可证——并且能够支持新颖的安排：保密语料库、社区持有的测试集和主权部署要求。不同的语言将有不同的协议。CC0 语料库、仅限研究的社区语料库和由部落委员会管理的密封黄金标准集都可以参与，各自按照自己的条款。

统一的是尊重这些条款的机制：曝光通道、许可证门控、隔离和从源获取注册（见[注册语料库](/docs/network/sovereignty/registering-corpora)）。*永远*不统一的是协议本身。

当语料库管理者设定条款——用于基准参与、赞助奖项或其他任何事项——条款表回答一小组问题：

| 维度 | 涉及的问题 |
|---|---|
| **语料库公开范围** | 属于哪个通道——公开、仅限研究还是私有？参考译文是否会公开展示？ |
| **方法所有权** | 如果赢得奖项，获胜的方法归谁所有——开发者、社区还是双方共有？ |
| **部署** | 谁可以在何处、依何种条件部署该方法？ |
| **自托管** | 该方法是否必须完全在社区控制的基础设施上运行？ |
| **保密性** | 测试集是否封存？谁持有密钥？每次评估运行由谁授权？ |
| **报酬** | 构建者、验证者和审阅者获得多少报酬？（公开默认标准：[与母语者合作](/docs/working-with-speakers)） |

这些都没有平台强制的答案。下面的默认值是一个模板，而不是规则。

## 社区转让模板

封存竞赛的主办方会从三种奖项条款中选择一种——`pass_to_holders`、`retain_ip` 或 `release_open`——并在任何人参赛之前予以公布（[奖项规范](/docs/network/specifications/prizes#condition-7-in-detail-the-term-is-one-choice-of-three)）。
在公开排行榜上占有一席之地，在任何条款下都不会转移任何权利。本模板详细阐述了针对原住民语言语料库的 `pass_to_holders`，作为社区治理机构进行修改的起点。其运作机制如下：

### 1. 方法开发
研究人员、学生或开发者使用自己的资源和开放许可数据构建翻译方法——FST 门控管道、指导的 LLM、微调模型或任何其他方法。

### 2. 网络评估
该方法通过[评估工具](/docs/network/specifications/harness)进行基准测试。
每次提交都被指纹识别到特定的 Git 提交和数据集版本。
分数是可重现的。

### 3. 社区审查
结果由社区语言工作者审查。高排行榜分数证明该方法*有效*；它不证明它是*合适的*。双语使用者验证输出样本，社区的审查者可以因任何原因拒绝一个方法。

### 4. 所有权转让
当方法达到奖项标准（自动化指标**和**人工验证）时，开发者将方法——源代码、训练权重、配置、指导数据——转让给社区的治理组织（由社区选择的部落委员会、语言机构或类似机构，绝不由 Champollion 选择）。社区完全拥有该工件：它可以检查、修改、部署、搁置或许可它，开发者或 Champollion 没有任何持续的权利主张。

开发者不拥有的第三方组件（开放权重基础模型、AGPL FST）不能转让其所有权——它们在自己的开放许可下传递给社区，这就是为什么奖项可接纳性要求每个依赖项都携带社区实际可以接收的权利。见[方法接口规范](/docs/network/specifications/methods#method-validity-and-dependency-classes)中的依赖项类别。

开发者保留研究人员应该保留的东西：无限制的权利来发布方法和结果、在任何地方重用他们的技术，以及作为方法创建者的永久署名。

### 5. 部署——如果以及社区如何选择
社区决定该方法是否被部署、由谁部署以及在什么条件下部署。独立部署完全是社区的事务：
**Champollion 不从社区拥有的资产中获得任何收益的份额**，也不持有自己的部署权。

:::note[状态：模板，非过往记录]
目前尚未开放任何奖项，也未发生任何权利转让。记录此模板是为了在任何人投入精力之前确保预期条款透明，并让社区治理机构拥有具体草案可供反馈，而非面对一张白纸。
只有由特定各方咨询法律顾问后起草并签署的正式法律文件，才会使其中的任何内容具有法律约束力。
:::

## 对于研究人员

如果您正在为原住民语言开发方法：

1. **在开始之前建立与语言社区的关系**
2. **使用开放许可数据**进行开发（不是社区限制的资源）
3. **在您的[运行卡](/docs/network/specifications/run-card)中记录出处**——每个资源、其许可证和来源
4. **在为奖项构建之前阅读奖项的条款**——如果条款包括转让，您的贡献是架构和技术（您可以发布和重用）；社区的贡献是使其适用于他们语言的语言学知识
