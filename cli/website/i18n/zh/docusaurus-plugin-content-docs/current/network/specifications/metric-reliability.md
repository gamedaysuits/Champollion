# 指标可靠性规范

> **执行摘要。** 基准分数的意义只取决于其背后的指标——自动指标与人类判断的一致程度在不同语言间并不相等。本文档规定了 Champollion 如何衡量**指标可靠性**：对于每个语言族，每个自动指标（BLEU、spBLEU、chrF、chrF++、COMET、MetricX）与人类质量判断的相关性有多强，这些判断来自 WMT 指标共享任务档案（2019–2025）。输出是一个已发布的、机器可读的证据工件，工具集、CLI 和 MCP 服务器在将任何分数呈现为可信之前会查阅它。据我们所知，没有其他评估基础设施按语言发布这种证据；这正是将"我们运行了一个指标"转变为"你应该相信它多少"的关键。
>
> **范围。** 本文档定义了*可靠性证据是什么、来自何处、确切的计算方式以及它有意排除的内容*。指标定义本身位于[评分规范](/docs/network/specifications/scoring)；分数差异的统计检验位于[显著性](/docs/network/specifications/significance)。重新生成工件的导入器是`arena/scripts/import_wmt_metaeval.py`在工具集存储库中——代码是实现细节的最终权威，并且开放供审查。

---

## 1. 本方案解决的问题

机器翻译质量最终是一种人类判断。自动指标存在是因为人类评估缓慢且昂贵；每个自动分数都是有能力的双语人士会给出的*代理*。整个领域的简写——"系统 A 比系统 B 高 2 个 BLEU"——默认假设该代理是忠实的。

这个假设已经被 WMT 指标共享任务测试多年，但几乎总是*总体上*：指标按平均相关性排名，与该年活动涵盖的任何语言对的人类判断相关——主要是高资源欧洲语言对加上中文和日文。按语言的细节存在于原始数据和按年份的研究论文中，但它没有作为可查询的、按语言族的证据层发布，评估管道可以查阅。

对于低资源和形态丰富的语言，这些细节至关重要。我们自己导入的两个发现说明了风险所在（§7 有完整表格）：

- **英语→因纽克提图特语（wmt20）。** BLEU 的系统级相关性与人类判断的相关性是**+0.16**——本质上没有信息量。chrF 达到 +0.35。COMET 达到 +0.86。按 BLEU 排名的排行榜对于这个语言对来说是在排名噪声；同一排行榜按 COMET 排名则携带信号。
- **英语→马赛语（wmt25）。** 相反的失败：MetricX-25 的相关性是**−0.09**——一个最先进的*学习*指标对于其训练中不存在的语言给出与人类判断无关的数字，而计算的 chrF++（一个"愚蠢"的字符串指标，没有缺失的训练数据）达到 +0.50。

这两种失败模式在全局平均中都不可见，它们指向相反的方向：对于一种语言，学习指标是唯一可用的；对于另一种，它是唯一*不可用的*。任何用固定指标套件对数百个语言对进行评分的基础设施——如 Champollion 所做的——都应该向其用户提供这种证据。

## 2. 定义

下面的定义是精确阅读文档其余部分所需的最少内容。熟悉机器翻译评估的读者可以跳到 §3。

**自动指标。** 从（系统输出、参考翻译，有时还有源文本）到一个数字的函数。*字符串指标*——BLEU、spBLEU、chrF、chrF++——比较输出和参考之间的表面重叠。*学习指标*——COMET、MetricX、BLEURT——是在过去人类判断上训练的神经模型，用于预测质量。本文档中所有指标的规范标识符来自 Champollion 的指标注册表（`shared/metric-registry.json`）：`bleu`、`spbleu`、`chrf_plain`、`chrf_plus_plus`、`comet_score`、`metricx_score`。

**人类判断协议。** WMT 活动在多个协议下收集了人类质量分数，本工件将其区分开来：

- **DA（直接评估）** ——众包工作者或研究人员对翻译评分 0–100。*z 标准化* DA（写作`wmt-z`）将每个评分者的分数标准化为平均值 0、方差 1，消除评分者慷慨度效应。
- **DA+SQM**（`da-sqm`、`wmt`）——在 0–100 量表上收集的 DA，带有标量质量指标锚点描述；从 WMT22 开始使用。
- **MQM（多维质量指标）**（`mqm`）——专业注释者标记和分类具有严重程度的单个错误跨度；加权错误计数成为分段分数。缓慢、昂贵，且是可用的最受信任的信号；每年仅为少数高资源对收集（注释来自 Google 的`wmt-mqm-human-evaluation`发布）。
- **ESA（错误跨度注释）**（`esa`、`esa-merged`）——WMT24 和 WMT25 的协议，结合错误跨度标记和标量评分；比 MQM 便宜，比 DA 更有信息量。

**元评估。** 评估评估者：衡量每个自动指标的分数与相同翻译上的人类分数的一致程度。一致性在两个级别上测量：

- **系统级**（`sys`）：每个机器翻译系统获得一个测试集的聚合人类分数和一个聚合指标分数；一致性跨系统计算。这提出了：*指标是否按照人类的方式排名整个系统？*——排行榜关心的问题。
- **分段级**（`seg`）：跨单个（系统、句子）对的一致性。这提出了：*指标能否区分好句子和坏句子？*——质量估计和数据过滤关心的问题。这要困难得多，相关性系统性地较低。

**相关性统计。** 四个标准统计，定义如下：

- **皮尔逊 r** ——两个分数向量之间的线性相关性。
- **斯皮尔曼 ρ** ——在平均排名上计算的皮尔逊 r；衡量单调一致性，对尺度不敏感。
- **肯德尔 τ-b** ——在所有项目对中，协调排序对与不协调排序对的（调整平局的）超额。我们使用标准调整平局的 τ-b 公式（等同于`scipy.stats.kendalltau`；我们的实现不依赖于依赖项，并针对测试套件中的蛮力参考进行交叉检查）。
- **成对排名准确度**（仅系统级）——在所有人类*严格*排序的系统对中，指标以相同方式排序的比例，指标平局计为未能重现顺序。这是 Kocmi 等人（2021）的准确度统计，最近的 WMT 活动用作其标题系统级数字。

**语言族。** *目标*语言（被翻译成的语言）的系谱分组，如 Champollion 语言数据库（`languages.family`，源自 Glottolog）中记录的那样。§5 讨论了为什么是目标端，以及一个族可以和不能代理什么。

## 4. 方法

导入器遍历每个（测试集、语言对）并为每个（人类判断通道、级别、指标）计算一个**单元**：

1. **发现人类通道。** 该对的所有可用人类分数文件都与明确的允许列表匹配（§4.1）。评分者级别的文件、原始错误跨度文件和文档/域级分数超出范围。
2. **排除人类"系统"。** WMT 分数文件包括参考翻译本身作为评分系统（`refA`、`refb`、`HUMAN.0`…）。将指标与其自己的参考相关联是没有意义的，因此任何与该对的参考集或前缀`ref`/`human`/`synthetic`匹配的系统在整个过程中被排除。
3. **对齐。** 系统级：同时拥有人类和指标分数的系统的交集（缺失值被丢弃，从不强制为零）。分段级：每个（系统、分段）都有两个分数，跨系统汇集而不分组——这是 mt-metrics-eval 的"无平均"展平。不规则文件（分段计数不匹配）导致单元失败，而不是近似对齐。
4. **计算。** 皮尔逊、斯皮尔曼和肯德尔 τ-b 在两个级别；成对排名准确度在系统级。少于 3 个对齐系统（sys）或少于 10 个对齐点跨至少 2 个系统（seg）的单元，或任一侧方差为零的单元，在排除分类账中记录为退化（当前构建中有 20 个单元）。
5. **汇总。** 按目标语言族、按指标、按级别：跨*首选*单元的 n 加权平均值（§4.1），保留贡献的（测试集、对）列表，以便任何聚合都可以分解回其输入。

### 4.1 人类通道偏好

当一个对有多个人类判断通道时，所有都被计算，但恰好一个被标记为**首选**，只有首选单元进入族汇总——否则在 MQM 和 DA 下都被判断的对会计算两次。偏好顺序按信号质量：

```
mqm > esa-merged > esa > da-sqm > wmt-z > wmt-appraise-z > wmt-appraise > wmt > wmt-raw
```

专家错误注释（MQM）优于错误跨度协议（ESA），后者优于标量直接评估；在 DA 中，z 标准化通道优于原始通道。非首选单元保留在工件中，供任何想要研究协议效应的人使用。

### 4.2 指标身份和版本控制

学习指标逐年变化（COMET-20、COMET-22、MetricX-23/24/25 是不同的模型），将它们视为一个指标会模糊元评估存在的确切区别。因此，每个单元记录**逐字上游分数名称**（`COMET-22`、`MetricX-25-Ref`、`metricx_xxl_MQM_2020`…）以及规范注册表 id，工件列出哪些上游名称馈送每个 id。当活动针对多个参考对指标进行评分时，使用的参考流也按单元记录。

分数完全按档案分发的方式使用（所有通道更高更好；MQM 错误分数和 MetricX 在上游被存储为否定）。不应用符号翻转或重新缩放；相关性对尺度不变，方向约定在导入前经过实证验证。

### 4.3 计算的 chrF++ 通道

chrF++——工具集的主要字符串指标——仅提交到 wmt20 活动，因此上游分数存在一年。对于每个其他测试集，导入器从缓存的系统输出针对记录的参考自己计算 chrF++（sacreBLEU，`word_order=2`）。这些单元被标记为`computed: true`，其上游名称说明了这一点：Champollion 计算的分数从不作为 WMT 提交呈现。所有其他指标单元都是逐字上游值；Champollion 添加到它们的唯一内容是相关性算术。

## 5. 设计选择、替代方案和理由

这些是审查者应该质疑的决定。每个都列出了选择的内容、未选择的内容以及原因。

**按目标语言族键入。** *选择：*按被翻译*成的*语言的族聚合。*替代方案：*仅按对（无聚合）；源端或对级类型学；类型学特征向量而不是系谱。*理由：*指标可靠性由*输出*语言的难度主导——形态丰富性为字符串指标增加表面不匹配，训练数据稀缺性降低学习指标——这两个属性都是目标的属性。族是一个粗糙但普遍可用的键（Champollion 数据库中的每种语言都有一个）；类型学特征会更精细，但对于这个存在的低资源语言来说，它们缺失或有争议。完整保留按对单元，因此可以从工件构建更精细的重新聚合（按属、按形态类型），而无需重新导入。

**展平分段级相关性。** *选择：*跨汇集（系统、分段）向量的肯德尔 τ-b。*替代方案：*具有平局校准的项目分组成对准确度（最近 WMT 研究论文的 acc*-eq）；按分段平均的 τ。*理由：*展平统计是最简单的可防御选择，完全可从其定义重现，无需平局校准程序，并保留本工件需要的跨语言可比性。它*不是*最新的 WMT 标题统计，§8 将其列为限制而不是假装等价。

**指标平局在成对准确度中计为指标的失败。** 无法分离人类分离的两个系统的指标已经未能重现人类顺序；给予半分会奖励分数量化。

**汇总中的加权平均。** 族聚合按样本大小加权每个单元（系统级的系统数、分段级的点数），因此 17 系统 MQM 对计数超过 6 系统 DA 对。未加权的按单元值保持可用。

**阈值。** 单元需要 ≥3 个对齐系统（超过 2 个点的相关性是没有意义的）或 ≥10 个对齐分段点跨 ≥2 个系统。这些是针对退化算术的下限，而不是显著性声明——§8。

**逐字上游规程。** Champollion 重新计算它能引用的任何东西（除了标记的 chrF++ 通道），因为重新评分的学习指标会引入版本和环境漂移，按单元上游名称存在以防止。权衡——活动未运行指标的覆盖范围缺口——显示为缺失单元而不是被掩盖。

**诚实失败排除。** 所有跳过的内容（没有人类判断的测试集、无法解析的语言代码、退化单元）都写入排除分类账，并附带原因。工件的读者可以列举*不在*其中的内容——大多数聚合报告缺少的属性。

## 6. 已发布的工件

证据作为一个机器可读的 JSON 文件发布，在 monorepo 中跟踪（有意不捆绑到 npm/PyPI 包中）：

```
shared/catalogue/metric-reliability.json    # the artifact (≈0.6 MB)
shared/schemas/metric-reliability.schema.json  # its JSON-Schema contract
```

当前构建：**1,810 个单元**（1,052 个首选）跨**57 个语言对**、**10 个测试集**、**11 个目标族**，有 21 个分类账排除。顶级块：固定`sources`和`provenance`（每个派生值携带`champollion-derived`出处，命名上游——相关性是我们的，判断不是）；`correlation_definitions`（§2 的确切统计定义）；`metrics`（注册表 id ↔ 上游名称）；`languages`（代码 → 族/属）；`families`（汇总）；`cells`（每个相关性，完全归属）；`excluded`（分类账）。

三个消费者表面今天读取它：

- **工具集 CLI：** `mt-eval recommend SRC TGT`呈现"目标的指标信任"块，以及方法可用性和引用结果。
- **Champollion CLI：** `champollion recommend SRC TGT`（相同的有效负载合约；工件是 monorepo 跟踪的，因此打包安装降级为明确的"索引不可用"注释）。
- **MCP 服务器：** `get_metric_reliability`工具回答"我应该为语言 X 信任哪个指标？"对于任何连接的 AI 代理，包括对于没有 WMT 活动判断的语言的明确 UNMEASURED 答案。

如何阅读这个——以及如何不阅读：

- **广泛的模式与该领域的聚合发现相匹配。** 在 42 对印欧语族的大量数据上，学习指标领先（MetricX +0.84、COMET +0.81），chrF 在后面，BLEU 最后——标准 WMT 结果，从原始数据重现作为理智锚点。
- **按族的偏差是有效负载。** 对于多综合因纽克提图特语，字符串指标崩溃，COMET 是唯一可用的信号。对于马赛语和 wmt25 中的英语→阿拉伯语，MetricX 相关性*为负*，而字符串指标保持可用——一个学习指标外推超出其训练分布会默默失败，带有看起来自信的分数。这些正是全局平均擦除的情况。
- **单对族是证据，不是结论。** 十一个族中的八个基于来自单个活动的一个或两个对。"爱斯基摩-阿留申语族：BLEU +0.16"的诚实阅读是*"在人类判断 en→iu 的一个活动中，BLEU 没有信息量"*——一个记录的测量、一个红旗和收集更多的理由，而不是关于该族的法律。
- **负单元不意味着指标在任何地方都被破坏。** 这意味着：在该对上，在该活动的系统池中，指标针对人类判断排序系统。范围限制（见 §8）可以在系统质量紧密聚集时压低任何相关性。

## 8. 限制

明确陈述，因为工件的价值在于其诚实：

1. **族是代理，不是机制。** 系谱族与驱动指标行为的形态属性相关，但不决定。按对单元（每种语言记录属）允许更精细的切片；族键是可查询的默认值，而不是类型学因果关系的声明。
2. **覆盖范围是 WMT 判断的，不是世界说话的。** 57 对，欧洲权重很大；每个 xx→英语对汇总到印欧语族；整个宏观族（阿尔冈昆语族、南岛语族、克丘亚语族、…）*根本没有人类判断覆盖*。对于那些，Champollion 的表面回答 UNMEASURED 而不是借用邻居的数字。Champollion 自己的主权基准计划——社区控制的测试集，具有本地使用者验证——是正好针对这个缺口的长期修复。
3. **族内转移是一个假设。** 当查询的语言从未直接被判断时，族级证据来自*其他*族中的语言，每个消费表面都明确说明了这一点。
4. **还没有置信区间。** 单元携带样本大小但不携带自举区间；单对族聚合尤其应该以 §7 暗示的宽度阅读。添加按单元自举 CI（工具集已经有分数 CI 的机制）是计划中的工作。
5. **范围限制。** 相关性在每个活动的提交系统上计算。最近的活动将许多强系统紧密聚集在一起，这压低了所有指标的相关性——部分原因是为什么 wmt25 派生单元（马赛语、阿拉伯语）显示极端值。每个单元上的按测试集归属保持这个可检查。
6. **分段级统计选择。** 展平的 τ-b 简单且可重现，但不是最近 WMT 研究论文的平局校准分组准确度；这里的数字不应该与这些出版物逐位比较。
7. **数据许可。** 上游人类判断数据不附带明确的许可证声明（§3.1）。Champollion 不重新分发其中任何一个，仅发布具有完全归属的派生统计，并在**非商业证据通道**中保留此工件（`license_lane.commercial_ok: false`）直到态度得到解决。MQM 通道另外追溯到 Google 的 Apache-2.0 注释发布。
8. **档案是一个移动目标。** 新活动被添加到同一 tarball URL。固定标识我们的快照确切；针对较新快照的再生是一个新的工件版本，具有新的固定，从不是默默更新。

## 9. 再现

任何人都可以从源代码重新生成工件：

```bash
# 1. Fetch the archive (912 MB compressed; NOT immutable — keep the pins)
mkdir -p ~/.mt-eval/mt-metrics-eval && cd ~/.mt-eval/mt-metrics-eval
curl -sSL -D mt-metrics-eval-v2.headers -o mt-metrics-eval-v2.tgz \
     https://data.statmt.org/wmt26/mt-metrics-eval-v2.tgz
shasum -a 256 mt-metrics-eval-v2.tgz > mt-metrics-eval-v2.sha256
tar xzf mt-metrics-eval-v2.tgz

# 2. Regenerate (refuses to run without a checksum pin)
python3 arena/scripts/import_wmt_metaeval.py
```

注意档案自己的 README 指向已停用的 storage.googleapis.com URL；`data.statmt.org`是实时主机。导入器是纯 Python 标准库（仅用于计算的 chrF++ 通道的 sacreBLEU）；其相关性实现针对`arena/tests/test_wmt_metaeval.py`中的蛮力参考进行交叉检查，工件的结构合约由其 JSON 模式加上两个运行时中的完整性测试强制执行。
