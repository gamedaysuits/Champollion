# 覆盖率统计：我们如何进行统计

> **内容摘要。** 当网站显示 **552 种现存语言拥有任意机器翻译** 且 **196 种语言由已部署的服务提供支持** 时，这是两个不同且刻意区分的统计数据。本页面定义了这两个层级，指明了构建时读取每个数字的单一事实来源（SSOT），并描述了这些列表是如何刷新的。覆盖率是一种*存在性声明*，绝非质量声明。

## 两个层级

**第 1 层级 — 任意专用机器翻译引擎（“已覆盖”）。** 如果一种现存语言出现在*任何*被追踪的专用机器翻译（MT）引擎发布的受支持语言列表中，即算作已覆盖——无论是已部署的消费者/API 服务（Google Translate、Microsoft Translator、DeepL、LibreTranslate 等），**还是**开放研究模型（NLLB-200、OPUS-MT、M2M-100、MADLAD-400 等）。正是这个并集点亮了网络地图上的绿点。

**第 2 层级 — 已部署的服务（“受支持”）。** 更严格的划分：该语言存在于任何人*今天就能实际使用*的消费者或 API 服务引擎的列表中。需要你自己下载、托管并提供服务的开放研究检查点（checkpoint）不计算在内。这个数字回答了“母语者现在能否在无需工程开发的情况下翻译网页？”的问题。

这两个层级的存在是因为它们回答了不同的问题，将它们合并会夸大全球的覆盖率。两者都仅针对 **ISO 639-3 独立现存语言** 进行统计（`isoType: 'L'`）。

## 数据来源（无手动输入）

显示的每个统计数据都是对机器单一事实来源（SSOT）的**构建时读取**——网站上没有任何数字是手动输入到文本中并任其过时的：

1. **各引擎列表** 存放在 `cli/shared/catalogue/method-coverage.json` 中——
   每个引擎一个条目，*仅作为引用*从该提供商自行发布的受支持语言列表中导入，并附带其 `source_url` 和 `asOf` 日期。Champollion
   不会审计或复现这些列表；它们是提供商自己的声明。
2. **构建过程会将** 这些列表与现存语言索引取交集，并将层级统计数据输出到网站的构建统计信息中（`stats.coverage.dedicatedLiving` 用于
   第 1 层级，`stats.coverage.serviceLiving` 用于第 2 层级，基于 `stats.livingTotal` 种
   现存语言）。
3. **页面渲染统计数据**，如果文本和统计数据出现偏差，推送前的一致性检查（parity gate）将导致构建失败。

## “194 种语言”和“187 种语言”可能都是正确的

提供商的列表和*语言*的统计数量并不是同一个概念，因此 SSOT 中的每个条目都会声明其数字代表哪一个：

- **`publisher-list-rows`** — 提供商自行发布的列表长度，
  与其发布的内容完全一致。Google 的 Cloud Translation 页面为其 NMT 模型列出了 **194** 行；
  这就是本网站明确归属于 Google 的数字。
- **`champollion-derived-enumeration`** — *我们*将该列表折叠为独立的
  ISO 639-3 基础语言后的数量。Google 同样的 194 行对应 **187** 种语言，
  因为 `zh-CN` 和 `zh-TW` 是同一种语言的两种文字，`pt-PT`
  和 `pt-BR` 也是如此，依此类推。这个数字是我们的，绝非提供商的。
- **`publisher-stated-headline`** — 提供商声明的总数，但背后
  没有发布任何列表。不能从中推导出任何内容。

前两者之间的差距是算术上的，而非存在分歧，并且这种情况贯穿于每个提供商：Microsoft 135 行 → 128 种语言，LibreTranslate 49 → 47，NLLB-200 的 200 种 FLORES 变体 → 196。地图和层级统计读取的是*枚举列表*，绝非标题数字。如果条目声明的基础与其列表发生矛盾，推送前的检查将导致构建失败。

另请注意，一个提供商可能会发布多个列表。Google 的页面为其 Translation LLM 层级提供了一个单独的表格（截至 2026-08-16 为 127 行），并且根本没有说明合并后的总数——因此“Google 支持多少种语言？”并没有单一的官方答案，本网站也不会凭空捏造一个。

## 声明的覆盖率不等于质量——也不总是可部署的

提供商列表中的语言仅意味着提供商*声明支持*，仅此而已。本网站在这些统计数据出现的任何地方都会应用两条诚信声明：

- **覆盖率 ≠ 质量。** 翻译质量好坏是一个独立的、
  需要衡量的问题——这正是基准测试网络（benchmark network）的全部意义所在。质量
  声明位于排行榜上，由（方法、数据集、指标）作为键值；覆盖率
  声明则位于此处。
- **声明的 ≠ 可部署的。** 追求广度的研究模型可能会声明非常庞大的语言
  数量，而其自身文档却报告只有小得多的子集具备可用质量。
  如果提供商发布了此类自我评估，本网站会同时显示
  声明的数量*和*提供商自己的可部署/质量数字，并分别引用
  提供商的资料。

## 刷新规范

提供商的列表会发生变化；统计数据必须机械地跟进：

- `method-coverage.json` 中的每个条目都带有自己的 `asOf` 日期，并且该文件
  带有一个顶级的 `asOf` ——即最后一次全面检查（sweep）的日期。显示
  覆盖率统计数据的界面会展示或链接到此日期。
- **SOTA 全面检查**（重新检查每个提供商发布的列表，添加新
  追踪的引擎）是一项定期维护任务；全面检查会更新 SSOT，并且
  网站上的每个统计数据都会在下一次构建时跟进。页面文案中不需要“记住”
  任何内容。
- 在两次全面检查之间，统计数据的新鲜度完全取决于其 `asOf` 日期——这正是
  为什么这些日期是数据的一部分，而不是脚注惯例。

## 来源

- **各引擎列表** — `cli/shared/catalogue/method-coverage.json`：每个引擎
  自行发布的受支持语言列表（仅作引用；每个条目包含 `source_url` + `asOf`）。
- **现存语言集合** — ISO 639-3 独立现存语言（`isoType: 'L'`），
  位于从引用的语言卡片构建的语言索引中。
- **层级统计** — 构建输出的 `stats.coverage.dedicatedLiving`（第 1 层级），
  `stats.coverage.serviceLiving`（第 2 层级），`stats.livingTotal`。由 Champollion 派生。
- **基于这些统计数据的人口估计** — 参见
  [覆盖率差距：我们如何进行估计](/docs/network/context/coverage-gap-estimate)。
