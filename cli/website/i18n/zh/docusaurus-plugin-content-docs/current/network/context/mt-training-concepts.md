# 机器翻译训练简明指南

机器翻译（MT）模型训练有其独特的词汇，但大多数术语从未向新手解释过——人们假设你已经知道。本页面不做任何假设。下面的每个术语都用简明的语言定义，并附带具体例子，这样当你阅读[训练演练](/docs/network/tutorials/train-your-own-model)或观看你的编码代理运行命令时，你就知道这些词的含义，更重要的是，**你能识别出哪些术语隐藏着那些悄悄毁掉结果的错误。**

:::info[这是为谁准备的]
你不需要写 Python。现在做这项工作的预期方式是**指导一个编码代理**——Claude Code、OpenAI Codex、Cursor、OpenCode、Google Antigravity 或类似工具——让它为你运行这些工具。你的工作是充分理解这些概念，以便给出好的指令并诚实地阅读结果。这正是本页面的目的。当我们提到一个工具时，我们指的是[**nmt-forge**](/docs/network/getting-started/training-honestly)，这些理念所构建的训练套件；但这些词汇是整个领域的，不仅仅是我们的。
:::

一个贯穿全页的运行示例。假设你想构建一个模型，将**英语 → 低资源语言**翻译——称之为你的*目标语言*——几乎没有翻译文本存在。下面的一切都是该项目的一部分。

## 1. 两堆数据：训练数据和评估数据

**平行数据**是文本与其翻译配对——两种语言中相同的意思，按句子逐行对齐。

> `The children are playing.` → `awâsisak mêtawêwak.`

模型通过研究数千个这样的配对来学习。但你必须将这些配对保持在**两堆永不接触的数据中**：

- **训练数据**——模型*被允许研究*的配对。它反复阅读这些数据并调整自己以重现它们。
- **评估数据**（或**eval 数据**）——模型在训练期间*永远不被允许看到*的配对。你隐藏翻译，要求模型冷启动翻译源端，并将其答案与隐藏的真实值进行比较。这是衡量它是否学会了*翻译*而不是*记忆*的唯一诚实方法。

:::tip[本页所有内容的一句话版本]
只有当模型从未见过答案时，测试才有意义。下面几乎每个错误都是答案从 eval 堆泄漏到训练堆而没有人注意到的不同方式。
:::

### 真实平行数据与合成平行数据

- **真实（或*黄金*）平行数据**是人工制作的：双语教科书、由人翻译的政府记录、社区存档的故事。它是可信的，但对于大多数语言来说，极其稀缺——通常只有几百个句子对。
- **合成平行数据**是由程序*制造*的，而不是由人编写的。当你只有 400 个真实对时，你无法训练一个可用的模型——所以你从规则生成数十万个额外的对（更多信息见[§7](#7-manufacturing-data-when-you-dont-have-enough)）。

这种关系极其重要：

> **实际例子。** 一个项目有 435 个真实的英语→克里语对，并制造了约 1,000,000 个合成对。模型在大型合成堆*加上*几百个真实对上进行训练。合成数据购买覆盖范围；真实数据将模型锚定到语言的实际使用方式。整个工艺是 (a) 使合成堆尽可能覆盖语言的大部分，以及 (b) 仅在模型从未接触过的真实文本上进行测量。

:::danger[永远不要在合成数据上测试]
评估集必须**仅包含真实数据**。如果你在制造的句子上测试，你测量的是模型是否与你的*生成器*匹配——而不是它是否能翻译。一个好的训练套件根本不会将合成行注册为测试集。
:::

## 2. 分割：训练、开发和测试

你从一堆真实对开始，并将其**分割**成三个角色。

| 分割 | 也称为 | 用途 | 模型在训练中看到它吗？ |
|---|---|---|---|
| **train** | 训练集 | 模型研究的配对 | 是 |
| **dev** | 验证集、held-in | 决定*何时停止*和*哪个版本最好* | 否（仅*评分*，从不研究） |
| **test** | held-out、评估集 | 最终诚实的成绩 | **永远不** |

该表中隐藏了两个想法：

- **Held-out** 只是意味着"搁置并远离训练"。测试集是有意 held out 的。
- **dev 集**是聪明的中间孩子。模型从不*研究*它，但你在训练期间*查看*模型在其上的表现以做出决定——就像一次练习考试，告诉你是否继续学习，而不是真正的考试。以这种方式使用 dev 集是合法的；以这种方式使用*测试*集是作弊（见[§4](#4-contamination-and-leakage-the-mistake-that-eats-results)）。

### 密封集和重新分割

- **密封集**是一个测试集，可能**恰好评分一次**。你查看其分数的那一刻，它就"用完了"——因为一旦你知道这个数字，你之后做出的每个决定都会被它微妙地塑造。密封集是竞赛和社区如何保持最终成绩真正最终的方式。
- **重新分割**是从头开始重建 train/dev/test 分割——通常是因为你发现旧分割被污染了。你不能通过逐行删除来修复泄漏的分割；你必须重新分组所有内容并重新划分（[§4](#4-contamination-and-leakage-the-mistake-that-eats-results)解释了原因）。

## 3. "训练"实际做什么：损失及其两个方面

训练是一个循环。模型做出预测，看到它有多错，并轻微调整其内部数字以下次少错一点——数百万次。

**损失**是衡量"有多错"的单个数字。越低越好。但有*两个*损失，混淆它们是一个经典陷阱：

- **训练损失**——模型在它正在积极研究的配对上有多错。这几乎总是不断下降，因为模型在极限情况下可以简单地*记忆*训练对。
- **Dev 损失**（验证损失）——模型在它*不*研究的 held-back dev 集上有多错。这是诚实的信号。当 dev 损失停止改进而训练损失继续下降时，模型已经停止*学习语言*并开始*记忆训练集*。

> **实际例子。** 一段时间后，你看到训练损失为 0.8 并继续下降，但 dev 损失卡在 1.9 并缓慢*上升*。这个差距是告诉你的：模型在背诵其训练对方面变得更好，在翻译任何新东西方面没有变得更好——甚至更糟。

### 损失是代理。解码是真实的东西。

这里有一个细微之处让几乎每个人都绊倒。损失衡量的是当正确答案已经摆在面前时，模型是否为正确的下一个词分配高概率。这**不**等同于模型实际上自己产生一个好的翻译。

- **解码**（也称*生成*或*推理*）是模型**实际翻译**：仅给定源句子，它逐字发出目标句子，没有任何支持。
- **损失**是在训练期间计算的廉价*代理*。它与质量相关，但不完美。

> **实际例子。** 两个检查点的 dev 损失几乎相同，但当你*解码* dev 句子并评分实际翻译时，一个明显更流畅。损失看不到这个差异；解码可以。这就是为什么认真的检查点选择会解码 dev 集并评分真实输出，而不是仅仅信任损失。

:::note["Dev 损失是否跟踪质量？"是一个开放问题，不是民间传说]
你会听到有信心的声称"eval 损失撒谎"。将其视为**未确定**，而不是已证明——许多民间传说来自被污染的实验。诚实的立场：dev 损失是一个有用的、廉价的信号；dev **生成指标**（解码，然后评分）是一个更直接的。对于最终决定，更倾向于直接的，不要将"损失撒谎"作为事实重复。
:::

## 4. 污染和泄漏：吃掉结果的错误

**污染**（或**泄漏**）意味着 eval 答案已秘密地进入训练堆。模型然后通过记忆"通过测试"，你的分数看起来很好，结果是无用的。这是低资源 MT 结果被证明是假的最常见的单一方式——也是这整个页面警告你的最重要的事情。

经典的、狡猾的形式是**共享目标最小对**：

> **实际例子——"Feed him"/"Feed her"。** 一本语言教科书将许多不同的英语练习映射到**一个**目标词。*"Feed him"* 和 *"Feed her"* 都翻译成相同的形式，`asam`。一个天真的随机分割将 *"Feed him"* → `asam` 放入**训练**，将 *"Feed her"* → `asam` 放入**测试集**。目标答案 `asam` 现在在两堆中。模型从训练中记忆了 `asam` 并在测试中"答对了"——但它什么都没学到。在一个真实项目中，54 个"测试"行中的 17 个以这种方式泄漏，这些行在质量指标上得分**83**，而干净行得分**44**。建立在该数字上的每个发现都必须被丢弃。

泄漏有多种形式，适当的**泄漏审计**检查所有形式：

- **完全重叠**——相同的源*或*相同的目标出现在两侧（上面的例子）。
- **近似重复重叠**——不完全相同，但测试句子的*改写*版本位于训练中。同域文档共享释义；精确匹配会错过这些，所以审计也测量词重叠相似性。
- **整个文件重叠**——有人不小心在测试文件本身的副本上进行了训练。（这真的会发生：一个"训练"收获结果*是*黄金教科书，489 行中的 489 行匹配。）

### 组不相交分割——修复

你不能通过逐行删除有问题的行来修复泄漏；这个模式只会重新出现。修复是**组不相交分割**：在分割之前，将共享源*或*目标的每一对绑定到一个**组**中，然后将每个*整个组*发送到恰好一侧。现在 `asam` 和共享它的所有内容完全位于 train *或*完全位于 test——永远不会两者都有。在划分后，你**验证零重叠**并在任何重叠仍然存在时拒绝继续。

:::tip[这是"分割守卫"为你做的]
当你的代理运行分割器时，它默认进行组不相交分割并自动验证零重叠。你不必记住"Feed him / Feed her"陷阱——该工具使提交它变得困难，如果你绕过它，它会拒绝并显示一条命名修复的消息。
:::

## 5. 过拟合、早期停止和平台

**过拟合**是当模型继续研究超过学习点并开始*记忆*时发生的情况。其训练损失看起来很好；其真实翻译质量变得更差。[§3](#3-what-training-actually-does-loss-and-its-two-faces)损失差距是你如何发现它的。

**早期停止**是防御：观察 dev 信号，当它在设定数量的检查中停止改进时（其**耐心**），停止训练并保留最佳的早期版本——最佳**检查点**（训练中途模型的保存快照）。早期停止同时防止浪费计算和过拟合。

但早期停止在你主要在合成数据上训练时有一个著名的失败模式——**合成→真实转移平台**：

> **实际例子——半个 epoch 的死亡。** 一个模型在 97.5% 合成的混合上训练，并在一个*真实* dev 集上评判，包含 42 个句子。早期，模型快速擅长合成质量，所以真实句子上的 dev 损失下降很快，在步骤 8,000 左右触底——然后向*上*漂移。天真的早期停止看到"dev 损失连续 6 次检查上升"并在 epoch 0.52 宣布胜利，这是计划训练的二十分之一。但模型还没完成；它仅仅完成了*简单*的合成学习，还没有开始缓慢的**转移**到真实语言质量。它在平台处被停止，在收益之前。

教训：对于合成重型混合，dev 损失中的*早期*下降和上升是**预期的**，而不是收敛。停止规则必须足够聪明以通过平台保持训练——一个从你的混合大小派生的下限，而不是你应该知道的魔法数字。

:::note[诚实的设置暴露真实的错误]
那个平台错误在几个月内是看不见的——因为早期的运行（非法地）使用了*测试*集作为他们的 dev 集，这隐藏了它。第一个*干净*的运行是暴露它的。这是反复出现的主题：诚实地做不仅让你保持真实，它使真实的问题可见。
:::

## 6. 测量质量：指标、电池、寄存器

当模型*解码*一个测试句子时，你如何根据参考翻译评分其答案？

### 部分学分指标：chrF++ 和 BLEU

翻译很少完全是参考逐字逐句，但它可以完全好。所以 MT 使用**部分学分**指标，奖励*重叠*而不是要求完全匹配：

- **chrF++** 评分模型输出和参考之间的**字符序列**重叠（加上一些词序列）。因为它在字符级别工作，它对获得一个词*几乎*正确给予部分学分——正确的词干但错误的结尾仍然赚取一些东西。这使其非常适合形态丰富的语言，其中一个根采取许多形式。越高越好；它通常在 0–100 的范围内报告。
- **BLEU** 是较旧的标准。它评分模型输出和参考之间的**整词**块（n-gram）重叠。它仍然被广泛报告，但对于词有许多屈折形式的语言来说很严厉，因为结尾的近似错误被计为完全错误。

> **实际例子。** 参考：`awâsisak mêtawêwak`。模型输出：`awâsisak mêtawêw`（正确的根，错误的最后音节）。BLEU 将第二个词视为简单错误。chrF++ 看到大多数字符匹配并授予部分学分。相同的输出，非常不同的分数——这就是为什么你选择的指标改变了故事。

:::tip[相信哪个指标是一个有根据的问题]
并非每个指标对每种语言的人类判断追踪相等。对于某些语族，BLEU 几乎不与人类认为的相关；对于其他语族，一个花哨的神经指标是不可靠的。在你优化*任何*指标之前，检查你的语言族的[指标可靠性](/docs/network/specifications/metric-reliability)证据——如果诚实的答案是"未测量"，说出来而不是信任一个数字。
:::

### 神经指标：COMET、MetricX

超越字符/词重叠，**神经指标**（COMET、COMET-QE、MetricX）使用训练的模型来*判断*翻译更像人类会做的。它们可以远更可靠——但仅对它们被训练来判断的语言，这排除了大多数低资源语言。它们也以方向相关的方式运行：**MetricX** 是**越低越好**，与 chrF++ 相反——一个在你比较数字之前值得知道的细节。

### 误差条：永远不要相信一个数字

一个没有不确定性的单一分数是一个陷阱。在小测试集上，差异通常只是噪音。

> **实际例子。** "模型在口头故事集上从 16.7 改进到 18.1"听起来像进步——直到你注意到该集有 37 个句子。有那么少的数据，±3 点的波动是纯粹的机会。诚实的报告是 `17.4 [15.1, 19.8] 95% CI`：数字，加上**置信区间 (CI)**——真实值可能落在的范围。如果两个模型的区间重叠很大，你不能声称一个比另一个更好。

好的工具拒绝打印没有其 CI 的分数，并在宣布 A-beats-B 胜利之前使用[显著性测试](/docs/network/specifications/significance)。

### 电池和寄存器

真实语言不是一个平的东西。**寄存器**（或**域**）是一*种*语言：随意对话、教科书练习、新闻文章、口头故事、正式政府散文。一个模型可以在一个上很好，在另一个上很差。

**电池**是一个评估集，故意分成几个寄存器，**分别**评分，所以单一平均值不能隐藏弱点。

> **实际例子。** 一个模型总体得分 46——可敬。但电池分解显示教科书练习上 58，口头故事上 22。平均值隐藏了对自然语音的近乎完全的失败。只有每个寄存器的电池才能揭示它。

## 7. 当你没有足够的数据时制造数据

当真实对稀缺时，你制造合成对。两种技术占主导地位，两者都靠一个词生死存亡：**验证**。

### FST 和形态分析器

**形态分析器**是一个知道语言词法语法的工具：根如何与前缀和后缀结合以制造有效词。许多被构建为 **FST**——*有限状态转换器*，一个精确的、基于规则的技术（不是神经网络），可以双向运行：

- **分析**：给定一个词，将其分解为根 + 语法标签（`nipâw` → "sleep, 3rd-person singular"）。
- **生成**：给定一个根 + 标签，拼写正确的词形（`sleep + 3sg` → `nipâw`）。

对于多综合语言——其中单个词可以承载英语需要整个句子的东西——FST 是黄金：它可以拼写*任何*已知根的*任何*有效形式，这正是制造训练数据的原始材料。

### 往返验证——使合成数据可信的规则

制造数据是危险的：生成器可以悄悄发出无意义的东西。防止它的纪律是**往返法则**：每个制造的词必须存活*生成 → 分析 → 你开始的相同分析*。如果你要求 FST 拼写一个形式，然后将该拼写反馈回去，没有得到你的标签返回，该词被丢弃。任何未通过往返的东西都永远不被允许进入训练数据。

> **实际例子——单字符泄漏。** 一本字典用字母 `ý` 拼写一个声音；分析器期望普通 `y`。因为没有人在两个组件相遇的边界处协调这两个拼写，*1,375 个动词*被悄悄判断为"未知"并从生成中删除——几周内，看不见。修复是**规范化器**：一个函数，在两个组件相遇的任何地方将拼写规范化为单一约定，加上**漏斗审计**，计算有多少项在管道的每个阶段存活，所以一个看不见的 1,375 项下降永远无法再隐藏。

### 覆盖范围，而不仅仅是数量

一百万个制造的句子听起来很全面。如果它们是相同几个形状的一百万个变体，它们就不是。

> **实际例子。** 一个 1,000,000 对的合成语料库结果包含**没有祈使句**（"Vote!"）、**没有疑问词问题**（"who/where/when"）、**没有所有格**（"my dog"）和**没有反向形式**（"she sees *me*"——许多语言中的核心语法）。分析器可以生成所有这些；模板只是从未询问过。数量隐藏了结构洞。

防御是一个**覆盖范围清单**，从已发布的语法转录：所需的语法现象，每个都被引用，所以如果所需的一个有零个例子，构建就会失败。和一个**每种类型的上限**阻止任何一个模板形状占主导——在一个语料库中，两个形状是 54% 的数据，所以模型的"经验"的一半是两个句子模式。

### 回译

**回译**是另一个大型合成技术，它很聪明。如果你有纯粹的、*未翻译的*文本在你的目标语言中（一个**单语**语料库——比平行文本更容易找到），你可以：

1. 取一个*反向*模型（目标 → 英语），
2. 机器翻译你的单语目标文本*进入*英语，
3. 将每个机器英语句子与你开始的**真实**目标句子配对，以及
4. 在这些对上训练你的前向（英语 → 目标）模型。

目标端是真实语言；只有英语端是合成的——通常是一个好的交易。

> **实际例子。** 你有 50,000 个真实句子在你的目标语言中，但只有 400 个平行对。将 50,000 回译成粗糙英语，你已经将单语文本转变为 50,000 个训练对，其*目标*端是真实的。

:::danger[也对你的单语文本进行泄漏审计]
回译感觉安全，因为"它只是单语文本"——但该文本可以*是*你的 eval 数据伪装。在一个项目中，泄漏审计捕获了一个单语收获，它完全匹配黄金测试集。审计**每个**输入对抗**每个** eval 集，合成和单语包括——不仅仅是你明显的平行语料库。
:::

### 标记合成数据

最后一个实践：**标记**合成源用一个标记（如 `<synth>` 或 `<bt>`）并保留真实（黄金）数据未标记。这让模型区分"练习材料"和"真实的东西"，所以真实数据锚定其输出风格；在翻译时你不添加标签，模型依靠它从黄金学到的。（见[回译食谱](/docs/network/tutorials/back-translation)以深入了解这个技术。）

## 8. 各部分如何连接

从上到下阅读，这是一个工作流：

1. 收集**真实平行数据**（[§1](#1-the-two-piles-training-data-and-evaluation-data)）——通常太少。
2. **分割**它组不相交进入 train / dev / test（[§2](#2-splitting-train-dev-and-test)、[§4](#4-contamination-and-leakage-the-mistake-that-eats-results)）。
3. **制造**合成数据以填补空白——往返验证、覆盖范围检查、泄漏审计（[§7](#7-manufacturing-data-when-you-dont-have-enough)）。
4. **训练**混合，观察**dev 损失 / dev 生成**以避免**过拟合**并存活**平台**（[§3](#3-what-training-actually-does-loss-and-its-two-faces)、[§5](#5-overfitting-early-stopping-and-the-plateau)）。
5. **解码** held-out **测试电池**并用**部分学分指标 + 置信区间**评分，每个**寄存器**（[§6](#6-measuring-quality-metrics-batteries-registers)）。
6. 做所有这一切而不让 eval 答案接触训练（[§4](#4-contamination-and-leakage-the-mistake-that-eats-results)）——其他五个服务的规则。

这里的每个规则对应一个真实的、被测量的错误，一个真实的项目犯了并记录了。你不必记住它们：训练套件将每一个机械化，所以诚实的路径是默认的，不诚实的路径拒绝并给出解释。这是下一页的主题。

## 用这个词汇指导你的代理
