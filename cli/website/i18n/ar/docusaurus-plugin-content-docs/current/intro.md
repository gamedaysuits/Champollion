# champollion

إطار عمل للتدويل (internationalization) قابل للتخصيص بالكامل. أمر واحد يترجم ملفات الترجمة (locale files) الخاصة بك. إعداد واحد يتحكم في كل طريقة، ونموذج، وزوج لغوي. وإذا لم تكن الطرق المدمجة كافية — فقم ببناء طريقتك الخاصة، واختبر عملها، ثم انشرها.

```bash
npx champollion sync
```

يكتشف champollion تلقائيًا ملفات الترجمة، وتنسيقها، واللغات المستهدفة. يترجم ما هو مفقود، ويتخطى ما تم إنجازه، ويتحقق من صحة كل نتيجة، ويكتب مخرجات نظيفة. هذه هي نقطة البداية.

:::info[جزء من شيء أكبر]

واجهة سطر الأوامر (CLI) هذه هي واجهة النشر لـ **Champollion** — وهي بنية تحتية
تقيس الترجمة الآلية للغات لا يقيسها أحد غيرنا، و
تنشر ما تتوصل إليه. يبني جانب القياس مجموعات اختبار للتقييم و
خريطة عامة توضح من يمكنه ترجمة ماذا، وبأي جودة، وعلى أي أنواع من النصوص؛
بينما واجهة سطر الأوامر هي المكان الذي تتحول فيه الطريقة المُثبتة إلى شيء يمكنك تشغيله فعليًا.

قاعدة واحدة تشكل كل شيء: تُعامل البيانات اللغوية مثل البيانات الحيوية (biodata)، لذا فإن
الأشخاص الذين يقدمون المتن اللغوي (corpus) يمتلكون مفاتيحه ومفاتيح أي شيء يُقاس
بناءً عليه. الصورة الكاملة — ما هو موجود، وما هي القواعد، وأين
موقعك — تجدها في [ما هو Champollion](/docs/what-is-champollion)، و
جانب القياس يندرج تحت [الشبكة (the Network)](/docs/network/).

:::

## لماذا لا تكتب سكريبت بنفسك؟

يمكنك كتابة حلقة تكرار (loop) سريعة تستدعي Google Translate لكل مفتاح. يفعل معظم المطورين ذلك — يستغرق الأمر حوالي 30 سطرًا. ولكن هنا تكمن المشكلة:

- **لا يوجد اكتشاف للتغييرات.** عند تحديث نص إنجليزي — تظل الترجمة قديمة إلى الأبد. يتتبع champollion كل قيمة مصدرية باستخدام تجزئات SHA-256 ويعيد ترجمة ما تغير فقط.
- **لا يوجد تجميع (Batching).** استدعاء واجهة برمجة التطبيقات (API) لكل مفتاح يعني 200 مفتاح = 200 طلب ذهاب وإياب. يقوم champollion بالتجميع بذكاء (قابل للإعداد، الافتراضي 80 مفتاحًا/دفعة للنماذج اللغوية الكبيرة (LLM)، و128 لـ Google).
- **لا يوجد تخزين مؤقت (Caching).** كل عملية مزامنة تعيد ترجمة كل شيء. تقوم ذاكرة الترجمة (Translation Memory) في champollion بتخزين الترجمات مؤقتًا حسب النص المصدر + اللغة + الطريقة — إعادة تشغيل المزامنة بعد تغيير مفتاح واحد يترجم ذلك المفتاح فقط، وليس الملف بأكمله.
- **لا توجد بوابة جودة.** الترجمة الآلية تهلوس، أو تعيد النص المصدر كما هو، أو تخرج نصًا بنظام كتابة خاطئ. يتحقق champollion من صحة كل ترجمة قبل كتابتها — يتم التقاط ورفض أنظمة الكتابة الخاطئة، وتضخم الطول، وتكرار النص المصدر.
- **لا يوجد وعي بالتنسيق.** هل هو مبرمج ثابتًا (Hardcoded) لـ JSON؟ يتعامل champollion مع JSON، و TOML، و YAML، و Hugo Markdown (الترويسة + النص) مع الاكتشاف التلقائي.
- **لا يوجد تحكم في الطريقة.** يحصل كل زوج لغوي على نفس الطريقة. يتيح لك champollion استخدام Google Translate للفرنسية، ونموذج لغوي كبير (LLM) لليابانية، ومسار مخصص مستضاف مجتمعيًا للغة Plains Cree — في نفس ملف الإعداد.

champollion هو نسخة الإنتاج من ذلك السكريبت.

## ما الذي يجعله مختلفًا

### كل طريقة هي إضافة (Plugin)

طريقة الترجمة **قابلة للإعداد لكل زوج لغوي**. يمكنك المزج بين Google Translate، والنماذج اللغوية الكبيرة (LLMs)، والموجهات الموجهة (coached prompts)، وواجهات برمجة التطبيقات (APIs) المخصصة في نفس المشروع:

```json title="champollion.config.json"
{
  "version": 3,
  "pairs": {
    "en:fr": { "method": "google-translate" },
    "en:ja": { "method": "llm", "model": "google/gemini-2.5-pro" },
    "en:crk": { "methodPlugin": "crk-coached-v1" }
  }
}
```

تحصل الفرنسية على Google Translate (سريع ورخيص). وتحصل اليابانية على نموذج لغوي كبير (LLM) متميز (دقيق). وتحصل لغة Plains Cree على إضافة موجهة بقواعد نحوية، وقواميس، وتحقق صرفي. نفس الأمر `sync`. نفس بوابة الجودة. نفس واجهة سطر الأوامر (CLI).

### اكتشف ما ينجح

هل تعتقد أن طريقتك يمكنها الترجمة من الإنجليزية إلى الإسبانية؟ أو من التركية إلى الأذربيجانية؟ أو من الإنجليزية إلى Cree؟

**قم ببنائها واختبارها.** تقوم [أداة التقييم (eval harness)](/docs/network/specifications/harness) المرافقة بقياس أداء أي طريقة ترجمة بنتائج قابلة للتكرار وموثقة ببصمة. تسجل [لوحة الصدارة (leaderboard)](/leaderboard) كل عملية تشغيل منشورة، حتى يتمكن الجميع من رؤية ما ينجح.

تتشارك أداة التقييم وواجهة سطر الأوامر (CLI) الخاصة بالإنتاج في نفس واجهة الإضافات (plugin interface). الطريقة التي تسجل نتائج جيدة في أداة التقييم يمكن استخدامها في الإنتاج — إذا وافق المجتمع الذي تخدم لغته على ذلك. بالنسبة للغات الشعوب الأصلية واللغات ذات الموارد المحدودة، فإن هذه الموافقة مهمة. راجع [سيادة البيانات (Data Sovereignty)](/docs/network/sovereignty/data-sovereignty).

```bash
# Benchmark a method against a real, non-bundled eval corpus
# (GlobalVoices amh->fra, 945 sentences, fetched from source on first run)
pip install mt-eval-harness
export OPENROUTER_API_KEY=sk-or-...   # any OpenRouter-proxied model works
mt-eval run --corpus eval-amh-fra-globalvoices-test-v1 --model gemini-pro --yes

# Use it locally
npx champollion sync
```

نفس الإضافة. ركّب واختبر.

### مجموعة الأدوات الكاملة

champollion ليس مجرد `sync`. بل هو مسار تدويل (i18n) متكامل:

| الأمر | وظيفته |
|---------|-------------|
| `sync` | ترجمة المفاتيح المفقودة والقديمة (مع التحقق بعد المزامنة) |
| `watch` | المزامنة التلقائية عند تغيير الملف المصدر |
| `lint` | فحص الكود المصدري بحثًا عن النصوص المبرمجة ثابتًا (hardcoded strings) |
| `wrap` | التغليف التلقائي للنصوص المبرمجة ثابتًا في استدعاءات `t()` |
| `audit` | سرد جميع علامات التراجع `[EN]` من عمليات التشغيل السابقة |
| `verify` | التحقق من وجود الترجمات وصحتها (بوابة التكامل المستمر CI) |
| `integrity` | اكتشاف تلف العناصر النائبة (placeholders)، ومشاكل الترميز، واكتمال صيغ الجمع في ICU |
| `seo` | إنشاء وسوم hreflang، وخرائط الموقع (sitemaps)، ومخطط JSON-LD |
| `status` | عرض إعدادات الزوج اللغوي، والإضافات، ونتائج قياس الأداء |
| `provenance` | تدقيق تراخيص موارد الترجمة |
| `plugin` | تثبيت، وإزالة، وسرد إضافات الطرق |
| `fonts` | تنزيل خطوط الويب لمحولات نصوص PUA |
| `tm` | إدارة ذاكرة التخزين المؤقت للترجمة (الإحصائيات، المسح، لكل لغة) |
| `xliff` | تصدير/استيراد XLIFF 1.2 لمراجعة المترجمين المحترفين |

أربعة من هذه الأوامر — `lint`، `sync`، `verify`، `audit` — تشكل مسار تكامل مستمر (CI) يلتقط النصوص المبرمجة ثابتًا، ويترجمها، ويتحقق من صحتها، ويفشل عملية البناء (build) إذا كانت أي لغة غير مكتملة.

## الشبكة (The Network)

[لوحة صدارة الطرق (Method Leaderboard)](/leaderboard) هي لوحة النتائج — مباشرة، وعامة، ومفتوحة للتقديم. يتم توثيق كل تقديم ببصمة لالتزام Git (Git commit)، وتعيين إصدار لمجموعة بيانات محددة، وتقييمه بواسطة نفس أداة التقييم. يمكن لأي شخص التقديم.

**ما الذي يمكنك بناؤه؟** تأخذ أداة التقييم تنسيق JSON. وتأخذ الإضافات تنسيق JSON. يمكن اختبار أي طريقة تنتج JSON:

| النهج | مثال |
|----------|---------|
| **نموذج لغوي كبير موجه (Coached LLM)** | حقن القواعد النحوية والقواميس في موجه (prompt) نموذج متقدم |
| **نموذج مضبوط دقيقًا (Fine-tuned model)** | تدريب نموذج مفتوح على نصوص متوازية — ولكن ليس على بيانات التقييم |
| **مسار محكوم بـ FST (FST-gated pipeline)** | النموذج اللغوي الكبير يولد → محول الحالة المحدودة (FST) يتحقق من الصرف → إعادة المحاولة |
| **نماذج متسلسلة (Chained models)** | النموذج أ يصيغ → النموذج ب يحرر لاحقًا → النموذج ج يقيم |
| **قاموس + نموذج لغوي كبير (Dictionary + LLM)** | فرض مصطلحات معروفة من قاموس، وترك النموذج اللغوي الكبير يتعامل مع الباقي |
| **تطوري (Evolutionary)** | توليد مرشحين، وتقييمهم، وتغيير الأفضل، ثم التكرار |
| **ترجمة جزئية (Partial translation)** | ترجمة عينة يدويًا، وإثبات تطابق النموذج اللغوي الكبير الخاص بك، ثم الترجمة التلقائية للباقي |

قم بضبط النماذج دقيقًا. انشر خوارزميات تطورية. اختبر إجابات الطلاب في امتحانات اللغة. ابنِ جداول بحث (lookup tables). اربط ثلاثة نماذج معًا. طالما أن طريقتك تنتج JSON، فإن أداة التقييم ستقيمها وإطار العمل سيشغلها.

:::danger[القاعدة الوحيدة]
**لا تتدرب على بيانات التقييم.** سيتم استبعاد الطرق التي تتعرض لمجموعة بيانات القياس. قم بالضبط الدقيق على أي شيء تريده. ولكن ليس على مجموعة الاختبار.
:::

هذه دعوة مفتوحة. إذا كنت تعمل مع لغة ذات موارد محدودة — كباحث، أو عضو في المجتمع، أو طالب، أو مجرد شخص مهتم — فقم ببناء طريقة، وشغل أداة التقييم، وعزز الشبكة للجميع. المشكلة لم تُحل بعد. البنية التحتية موجودة هنا، وهي مفتوحة.
