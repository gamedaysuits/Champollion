# ترجمة التطبيقات والمواقع

يحافظ `champollion sync` على مواكبة ترجمات التطبيق أو الموقع الإلكتروني للغته
المصدر. فهو يقرأ ملفات الإعدادات المحلية لديك (أو صفحات Markdown)، ويكتشف
ما هو مفقود أو قديم، ويترجمه وحده، ويفحص كل نتيجة، ثم
يعيد كتابتها بالتنسيق الخاص بالملف نفسه.

```bash
npx champollion sync
```

هذا القسم هو المرجع لهذا المسار. وإذا أردت الاطلاع على النسخة
المكتوبة بكلمات مبسطة أولاً، فاقرأ [ترجمة تطبيق أو موقع إلكتروني](/docs/translate-an-app-or-website).

## ما يفعله `sync`

1. **يعثر على ملفاتك.** يكتشف مجلد الإعدادات المحلية وتنسيقه (JSON أو TOML أو
   YAML أو gettext PO أو Flutter ARB)، أو مجلد صفحات Markdown/MDX (Hugo أو
   Docusaurus أو أي مجلد تحدده بواسطة `--content-dir`).
2. **يحدد ما تغيّر.** تُسجَّل كل قيمة مصدر برمز تجزئة SHA-256
   الخاص بها في `.champollion.lock`. وتوضع المفاتيح المفقودة أو الفارغة أو التي تغيّر
   نصها المصدر في قائمة الانتظار؛ أما باقي العناصر فتُترك دون مساس.
3. **يترجم بالطريقة التي اخترتها لكل زوج.** يمكن لملف تكوين واحد أن
   يرسل زوجاً إلى LLM، وزوجاً آخر إلى API ترجمة آلية، وزوجاً ثالثاً
   إلى نموذج دربته وتستضيفه بنفسك. تترجم طرق LLM عند درجة حرارة (temperature) قدرها 0 افتراضياً (القيمة
   الافتراضية الوحيدة في `shared/model-defaults.json`)؛
   ومع ذلك قد يتباين النموذج المستضاف قليلاً بين جولات التشغيل، وهو أحد أسباب
   احتفاظ ذاكرة الترجمة بما حصلت عليه بالفعل.
4. **يعيد استخدام ما دُفعت تكلفته بالفعل.** تخزن ذاكرة الترجمة مؤقتاً كل
   ترجمة وفقاً للنص المصدر والإعداد المحلي والطريقة: فالنص الذي يتكرر (سلسلة
   نصية أُعيدت إلى أصلها، أو الجملة نفسها في ملف آخر، أو إعادة تنفيذ) يكون مجانياً.
5. **يفحص كل نتيجة قبل كتابتها.** ترفض بوابة الجودة المخرجات الفارغة،
   أو النسخ المطابق للأصل، أو حلقات التكرار، أو المخرجات المكتوبة بنظام كتابة غير صحيح،
   أو العناصر النائبة التالفة وما شابه ذلك من أعطال، مع محاولة إعادة واحدة تتضمن تغذية راجعة. وهي
   ترصد المخرجات المعطوبة، لا المعنى الخاطئ.
6. **يتحقق بعد الكتابة.** تعيد خطوة ما بعد المزامنة قراءة الملفات المكتوبة
   وتفحص تطابق المفاتيح، والقيم الفارغة، ونظام الكتابة، والعناصر النائبة؛
   ويجري كل من `champollion verify` و`champollion audit` النوع نفسه من الفحوصات كبوابات
   ضمن CI.

لا يُكتب أي شيء بصمت. فالمفتاح الذي تظل البوابة ترفضه بعد محاولة الإعادة
يُترك دون ترجمة ويُبلَّغ عنه، وتنهي المزامنة عملها بالرمز `2`. وتُحفظ
حالة الرفض، بحيث لا تدفع المزامنة العادية التالية للنموذج نفسه مقابل الإجابة
نفسها: يمكنك أن تطلب مجدداً باستخدام `--redo`، أو تضيف طريقة `fallback` إلى الزوج، أو
تكتب القيمة يدوياً.

## متى تستخدمه

- لديك تطبيق أو موقع إلكتروني توجد نصوصه في ملفات إعدادات محلية أو Markdown،
  وتريد إبقاء لغاته الأخرى محدّثة باستمرار مع تغيّر النص المصدر.
- تريد طريقة مختلفة لكل زوج لغوي في مشروع واحد، مع وضع حد للإنفاق
  (`--max-cost`) وإمكانية معاينته قبل تحصيل أي رسوم (`--dry`).
- قمت ببناء مترجم على المسارات وتريد من أحد التطبيقات استخدامه:
  يضع `champollion connect` نموذجاً قيد الاستضافة في مشروع التطبيق، ثم يترجم
  `sync` باستخدامه. ولا يُربط النموذج المدرب على بيانات محلية فقط
  إلا بعد موافقة أصحابها.

ليس `sync` الطريقة التي تبني بها مترجماً للغة لا تخدمها أي خدمة
بشكل جيد. للقيام بذلك، ابدأ من [بدء مشروع](/docs/start).
