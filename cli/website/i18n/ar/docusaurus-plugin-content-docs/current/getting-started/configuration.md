# التهيئة

يعمل Champollion دون أي تهيئة مسبقة (zero-config) — حيث يكتشف تلقائيًا ملفات اللغات والتنسيق واللغات الهدف من مشروعك. لمزيد من التحكم، أنشئ `champollion.config.json` في جذر مشروعك، أو شغّل:

```bash
npx champollion init
```

## المرجع الكامل للتهيئة

```json title="champollion.config.json"
{
  "version": 3,
  "inputLocale": "en",
  "localesDir": "./locales",
  "localesPattern": null,
  "localesLayout": null,
  "contentDir": null,
  "translatableFields": null,
  "format": "auto",
  "model": "google/gemini-3.8-flash",
  "temperature": 0,
  "defaultMethod": "llm",
  "batchSize": 80,
  "coachingFile": null,
  "promptContext": null,
  "genderGuidance": null,
  "protectedTerms": [],
  "jsonConcurrency": 200,
  "contentConcurrency": 48,
  "fallbackPrefix": "[EN] ",
  "apiKeyEnvVar": "OPENROUTER_API_KEY",
  "noTranslate": [],
  "noTranslateUrls": true,
  "baseUrl": "",
  "pairs": {},
  "languages": {},
  "lint": {
    "srcDir": null,
    "ignore": ["node_modules", ".next", "dist"],
    "minLength": 2
  },
  "seo": {
    "urlPattern": "/:locale/:path",
    "pages": null
  },
  "typegen": {
    "output": null,
    "autoGenerate": false
  }
}
```

:::note[typegen لم يُنفّذ بعد]
يتم التعرّف على كتلة التهيئة `typegen` والاحتفاظ بها بواسطة أداة تحميل التهيئة، ولكن توليد أنواع TypeScript لم يُنفّذ بعد. هذا عنصر نائب لميزة مخطط لها. تعيين هذه القيم ليس له أي تأثير حاليًا.
:::


### الحقول

| الحقل | النوع | القيمة الافتراضية | الوصف |
|-------|------|---------|-------------|
| `version` | `number` | `3` | إصدار مخطط التكوين. دائمًا `3`. |
| `inputLocale` | `string` | `"en"` | رمز لغة المصدر (BCP 47). |
| `localesDir` | `string` | `"./locales"` | المسار إلى ملفات اللغات. يحتوي على ملف واحد لكل لغة (`fr.json`) أو مجلد واحد لكل لغة (`fr/common.json`). راجع [تخطيطات ملفات اللغات](#locale-layouts). |
| `localesPattern` | `string` | `null` | مكان وجود ملفات كل لغة عندما لا يناسب أي من التخطيطين، مع `{lang}` وعنصر اختياري `{ns}`: `"public/locales/{lang}/{ns}.json"`، `"src/strings/app_{lang}.json"`. نسبي بالنسبة لجذر المشروع. يحل محل `localesDir`. راجع [تخطيطات ملفات اللغات](#locale-layouts). |
| `localesLayout` | `string` | `null` | يتجاوز الكشف التلقائي عن التخطيط: `"flat"` (ملف واحد لكل لغة) أو `"dir"` (مجلد واحد لكل لغة). يلزم فقط عند وجود كل من `en.json` و`en/`. |
| `defaultNamespace` | `string` | `null` | في مشروع يعتمد مجلدًا لكل لغة مع عدة ملفات، الملف الذي يضيف `champollion wrap` مفاتيح جديدة إليه (مثل `"common"`). |
| `contentDir` | `string` | `null` | مجلد ملفات Markdown/MDX المراد ترجمتها: مجلد `content/` الخاص بـ Hugo أو أي مجلد آخر، مثل `./newsletters` في تطبيق Next.js. تُكتب كل ترجمة بجوار مصدرها كـ `<name>.<locale>.md`، على سبيل المثال `2026-10.md` ← `2026-10.crk.md`. الملفات المسماة بالفعل `<name>.<code>.md` تُعامل كترجمات وليست مصادر. راجع [ترجمة المحتوى](/docs/guides/content-translation). |
| `translatableFields` | `string[]` | `null` | تجاوز حقول frontmatter الافتراضية القابلة للترجمة لترجمة المحتوى. `null` يستخدم الإعدادات الافتراضية المضمنة (`title`، `description`، `summary`). |
| `format` | `string` | `"auto"` | تنسيق الملف: `json`، `toml`، `yaml`، `po` ([gettext](#gettext))، `arb` ([Flutter](#arb))، أو `auto` (اكتشاف تلقائي من امتداد ملف المصدر؛ `.yml` يُحسب كـ YAML وتحتفظ الأهداف بـ `.yml`). أي قيمة أخرى تتوقف مع ظهور خطأ. |
| `model` | `string` | `"google/gemini-3.8-flash"` | النموذج الافتراضي لطرق LLM. معرف نموذج دقيق: معرف OpenRouter الكامل (`provider/model`). تُرفض الأسماء المستعارة القصيرة (`gemini-flash`) والمعرفات المتغيرة (`~vendor/…`، `…-latest`)، مع تحديد المعرف الذي يجب كتابته. يستخدم الموفرون المباشرون الأسماء المجردة (مثل `gpt-4o`)؛ ويُربط معرف OpenRouter التابع لمزودهم الخاص به (`openai/gpt-4o` ← `gpt-4o`)، والمعرف الذي لا يملكون نموذجًا له يوقف التشغيل قبل إرسال أي شيء ([أسماء النماذج](/docs/guides/translation-methods#model-names)). |
| `temperature` | `number` | `0` | درجة حرارة LLM (0.0–2.0). الأقل = أكثر حتمية. القيمة الافتراضية هي الموجودة في `shared/model-defaults.json`، وهي نفس القيمة التي تقيم بها أداة التقييم، وبذلك فإن ما يُقاس هو ما يُطرح في الإنتاج. |
| `defaultMethod` | `string` | `"llm"` | طريقة الترجمة الافتراضية: `llm`، `llm-coached`، `openai`، `anthropic`، `gemini`، `local`، `google-translate`، `deepl`، `microsoft-translator`، `libretranslate`، `apertium`، `tilde`، `translated`، `api`. `local` هو خادم متوافق مع OpenAI على جهازك (Ollama افتراضيًا). يمكن تجاوزه عبر خيار CLI `--method`. |
| `batchSize` | `number` | `80` | عدد المفاتيح لكل دفعة ترجمة. الأكبر = استدعاءات API أقل، ولكن مطالبات أطول. |
| `coachingFile` | `string` | `null` | المسار إلى ملف موجه التوجيه ذي النص الحر (نسبي بالنسبة لجذر المشروع). تُقرأ المحتويات عند بدء التشغيل وتُحقن في موجه النظام ككتلة `Coaching guidance:`. |
| `promptContext` | `string` | `null` | سلسلة سياق التطبيق المحقونة في موجه النظام (مثل: "أوصاف منتجات التجارة الإلكترونية"). تساعد النموذج على تخصيص الترجمات لتناسب مجالك. |
| `genderGuidance` | `string` \| `false` | `null` | كيفية تعامل مطالبات LLM مع الجنس النحوي. `null` يحتفظ بالإعداد الافتراضي لكل لغة من دليل Champollion — بالنسبة للفرنسية، *الكتابة الشاملة* باستخدام النقطة الوسطية (`Connecté·e`، `Utilisateur·rice·s`)؛ وبالنسبة للألمانية، صيغة النقطتين (`Benutzer:innen`). `false` لا يرسل أي تعليمات خاصة بالجنس؛ واستخدام سلسلة نصية يرسل تعليماتك الخاصة (مثل `"Use the masculine generic."`). يمكن تعيينه أيضًا لكل لغة ولكل زوج لغوي. راجع [إرشادات الجنس النحوي](#gender-guidance). |
| `protectedTerms` | `string[]` | `[]` | أسماء يجب الإبقاء عليها تمامًا كما كُتبت في كل لغة: أشخاص، شركات، منتجات (مثل `["Curtis Forbes", "Game Day Suits"]`). يُوجّه النموذج للإبقاء عليها، والقيمة المكونة فقط من هذه الأسماء لا تُصنف أبدًا كغير مترجمة أو مكتوبة بنظام كتابة خاطئ. هذا يختلف عن `noTranslate`، الذي يتخطى **المفاتيح** بالكامل. |
| `jsonConcurrency` | `number` | `200` | الحد الأقصى لترجمات اللغات المتوازية لمزامنة مفاتيح JSON. يمكن تجاوزه عبر خيار CLI `--json-concurrency`. |
| `contentConcurrency` | `number` | `48` | الحد الأقصى لاستدعاءات API المتوازية لترجمة المحتوى (Markdown/MDX). يمكن تجاوزه عبر خيار CLI `--content-concurrency`. |
| `fallbackPrefix` | `string` | `"[EN] "` | بادئة علامة يستخدمها `audit` و`verify` لاكتشاف القيم القديمة غير المترجمة من عمليات تشغيل سابقة. لا يكتب Champollion هذه البادئة — بل يقرؤها فقط للاكتشاف. |
| `apiKeyEnvVar` | `string` | `"OPENROUTER_API_KEY"` | اسم متغير البيئة لمفتاح API. تجاوزه لاستخدام أسماء مخصصة لمتغيرات البيئة. |
| `minContentRetention` | `number` | `0.35` | نسبة الحروف/الأرقام من المصدر التي يجب أن يحتفظ بها الناتج قبل أن يراجع [فحص حذف المحتوى](/docs/concepts/quality-gate) إشارته الثانية. يمكن تعيينه أيضًا لكل زوج ولكل لغة. |
| `noTranslate` | `string[]` | `[]` | مفاتيح المسار النقطي وأنماط glob التي تُنسخ قيمتها حرفيًا إلى كل لغة. راجع [مفاتيح غير قابلة للترجمة](#no-translate). يُقبل أيضًا كـ `skipKeys`. |
| `noTranslateUrls` | `boolean` | `true` | معاملة قيم المصدر التي لا تمثل سوى عنوان `scheme://` URL كقيم غير قابلة للترجمة. عيّن `false` لإرسال المفاتيح ذات قيم URL إلى واجهة الترجمة الخلفية. |
| `baseUrl` | `string` | `""` | عنوان URL الأساسي لإنشاء عناصر تحسين محركات البحث SEO (hreflang، وملفات sitemap، وJSON-LD). |
| `pairs` | `object` | `{}` | تجاوزات الطريقة والنموذج والجودة لكل زوج لغوي. راجع [تكوين الأزواج اللغوية](#pair-configuration). |
| `languages` | `object` | `{}` | تجاوزات خاصة بكل لغة. راجع [تكوين اللغات](#language-configuration). |
| `lint.srcDir` | `string` | `null` | دليل المصدر لفحص التدقيق اللغوي البرمجي (lint). `null` = اكتشاف تلقائي من إطار العمل. |
| `lint.ignore` | `string[]` | `["node_modules", ...]` | أنماط glob لاستبعادها من التدقيق (lint). |
| `lint.minLength` | `number` | `2` | الحد الأدنى لطول السلسلة النصية لتحديدها كنص ثابت (hardcoded). |
| `seo.urlPattern` | `string` | `"/:locale/:path"` | قالب نمط URL لإنشاء وسوم hreflang. |
| `seo.pages` | `string[]` | `null` | قائمة صريحة بالصفحات لتحسين محركات البحث SEO. `null` = اكتشاف تلقائي من مفاتيح ملفات اللغات. |
| `typegen.output` | `string` | `null` | مسار الإخراج لأنواع TypeScript المنشأة. `null` = معطل. |
| `typegen.autoGenerate` | `boolean` | `false` | إعادة إنشاء الأنواع تلقائيًا بعد كل مزامنة. |

## تخطيطات ملفات اللغات {#locale-layouts}

يقرأ Champollion ملفات اللغات في المواضع التي يحتفظ بها إطار عملك فيها بالفعل. هناك ثلاثة هياكل لتنظيم الملفات.

**ملف واحد لكل لغة** (`flat`). يُستخدم مع next-intl وvue-i18n وHugo ومعظم الإعدادات المخصصة يدويًا:

```text
messages/
  en.json      ← source
  fr.json
  de.json
```

```json title="champollion.config.json"
{ "localesDir": "./messages" }
```

**مجلد واحد لكل لغة** (`dir`). يُستخدم مع i18next وreact-i18next، حيث يمثل كل ملف *مساحة أسماء* (namespace):

```text
public/locales/
  en/
    common.json      ← source namespaces
    admin/users.json
  fr/
    common.json
    admin/users.json
```

```json title="champollion.config.json"
{ "localesDir": "./public/locales" }
```

يختار Champollion التخطيط `dir` عندما يكون `<localesDir>/<inputLocale>/` مجلدًا لملفات اللغات. تتم مزامنة كل ملف مصدري مع المسار نفسه تحت مجلد كل لغة، ويتم إنشاء الملفات والمجلدات المفقودة. يمكن أن تكون مساحة الأسماء مسارًا متداخلًا (`admin/users`).

**أي هيكل آخر** (`localesPattern`). حدد المسار باستخدام `{lang}` وإذا كانت اللغة تحتوي على ملفات متعددة، استخدم `{ns}`:

```json title="champollion.config.json"
{ "localesPattern": "src/translations/{ns}/{lang}.json" }
```

قد يتكرر `{lang}` كما في `"{lang}/app_{lang}.json"`. قد يظهر `{ns}` مرة واحدة ويمكن أن يمتد عبر مجلدات. يتم تحديد التنسيق من الامتداد ما لم يتم تعيين `format`.

يكتشف أمر `champollion init` هذه التخطيطات نيابة عنك. يتحقق أولاً من وجود تطبيق Flutter (`pubspec.yaml`، مع `l10n.yaml` إن وجد) وفهارس gettext (`locale/<lang>/LC_MESSAGES/`، `translations/`، GNU `po/`)، ويكتب `localesPattern` لتلك الحالات. ثم يتحقق من المجلد المعتاد لإطار عملك (`messages/` لـ next-intl، و`public/locales/` ثم `locales/` لـ i18next، و`src/locales/` لـ vue-i18n، و`i18n/` لـ Hugo)، ثم `locales`، `messages`، `i18n`، `lang`، `translations`، `public/locales`، `src/locales` و`src/i18n`. لا يستخدم إلا مجلدًا يحتوي على ملف لغة المصدر الخاصة بك، ويطبع ما عثر عليه. يقوم `init --langs fr,de` أيضًا بإنشاء الملفات الهدف الفارغة وفق ذلك التخطيط.

:::note[كيف تتم مزامنة لغة متعددة الملفات]
تتم مقارنة كل ملف وترجمته وكتابته بصورة مستقلة. يسجل `.champollion.lock` المفاتيح بصيغة `<namespace>::<key>` (`common::nav.home`)، وكذلك تفعل `--force-keys` ومعرفات وحدات `xliff` و`sync --dry --json`. المفتاح المجرد في `--force-keys` يطابق ذلك المفتاح في كل ملف. المشاريع التي تعتمد ملفًا واحدًا لكل لغة تحتفظ بمفاتيح بسيطة، لذا لا يتغير ملف القفل الخاص بها.

ذاكرة الترجمة مفهرسة بالنص المصدري، وليس بالملف. يتم ترجمة السلسلة النصية التي تظهر في مساحتي أسماء مرة واحدة فقط لكل لغة، ويحصل الملف الثاني عليها من التخزين المؤقت دون أي تكلفة إضافية.
:::

إذا وجد كل من `en.json` ومجلد `en/` غير فارغ، يتوقف Champollion ويطلب منك تعيين `"localesLayout": "flat"` أو `"dir"` بدلاً من التخمين.

### مفاتيح الجمع في i18next {#i18next-plurals}

يخزن i18next صيغ الجمع كمفاتيح متجاورة ذات لاحقة CLDR: `item_one`، `item_other`. تختلف صيغ الجمع باختلاف اللغات؛ فالفرنسية والإسبانية تستخدمان أيضًا `_many`، وتستخدم العربية ست صيغ، بينما تستخدم اليابانية `_other` فقط. عندما يحتوي ملف JSON المصدري على هذه المفاتيح، يحصل كل هدف على صيغ لغته الخاصة بدقة، والمقروءة من CLDR عبر واجهة برمجة تطبيقات JavaScript `Intl.PluralRules`:

```json title="en.json"
{ "item_one": "{{count}} item", "item_other": "{{count}} items" }
```

بعد المزامنة، يحتوي `fr.json` على `item_one` و`item_many` و`item_other`، ويحتوي `ja.json` على `item_other` فقط. وتوضح عملية المزامنة للغاتك الخاصة الصيغ التي تكتسبها أو تفقدها كل لغة.

تُترجم الصيغ الجديدة من نص `_other` المصدري، و`_one` من `_one`. ويتم الاحتفاظ بـ `_zero` الموجود في المصدر في جميع اللغات، لأن i18next يبحث عنه عندما يكون العدد 0 في جميع اللغات. إذا كتبت عملية مزامنة سابقة صيغة لا تستخدمها اللغة، مثل `item_one` في اليابانية، فإن المزامنة تزيلها فقط عندما تُظهر ذاكرة الترجمة أن المزامنة هي من أنتج تلك القيمة، بينما يتم الاحتفاظ بأي قيمة كُتبت يدويًا. لا تتم إزالة مفتاح لصيغة لا تملكها اللغة ولم يتضمن المصدر مفتاحًا لها أيضًا (مثل `item_two` في الإسبانية) تلقائيًا على الإطلاق: حيث يسميه `verify`، ويزيل `sync --prune plural-extras` تلك المفاتيح تحديدًا مع إدراج كل منها (ومع `--dry` يوضح ما كان سيتم حذفه). بالنسبة للغة لا تتضمن CLDR قواعد جمع لها، تُنسخ صيغ المصدر واحدة تلو الأخرى، وتوضح عملية المزامنة ذلك.

### رسائل ICU {#icu}

القيم المكتوبة بتنسيق ICU MessageFormat (في next-intl وreact-intl وvue-i18n وFlutter) تمزج بين الكود والنص:

```json
{ "items": "{count, plural, =0 {No events} one {# event} other {# events}}" }
```

يتم ترجمة النص الموجود داخل الفروع فقط. وترفض [بوابة الجودة](/docs/concepts/quality-gate) أي ترجمة تُحدث تغييرًا في أي شيء آخر:

- أسماء المتغيرات (`count`، `{name}`)، والتي لا يُعاد تسميتها أو حذفها مطلقًا؛
- الكلمات `plural` و`select` و`selectordinal`، ونوع `{price, number}`؛
- المحددات (`=0`، `one`، `other`، `male`). يحتفظ `select` بخياراته بدقة. ويحتفظ `plural` بمحددات المصدر وقد يضيف الفئات التي تستخدمها اللغة الهدف استنادًا إلى CLDR: تضيف الفرنسية `many`، والبولندية `few` و`many`. وقد تُحذف فئة لا تستخدمها اللغة، كما تحتفظ اليابانية بـ `other` فقط؛
- `#` في كل فرع جمع يحتوي عليه، باستثناء `zero` و`one` و`two` و`=N`، حيث يمكن للغة كتابة الرقم ككلمة؛
- `offset:N`، والوسائط المتداخلة، وتحويلات printf مثل `%s` و`%d` و`%(name)s`.

يتم إخطار النموذج بالفئات التي تستخدمها اللغة الهدف. وتتم إعادة محاولة الترجمة المرفوضة مرة واحدة مع ذكر السبب، على سبيل المثال `ICU keyword 'other' was translated to 'óthér'`. الفاصلة العليا قبل العنصر النائب (`d'{name}`) مقبولة. يُجري `verify` و`integrity` الفحص ذاته على الملفات المكتوبة بالفعل. تحتفظ عملية `sync` العادية بالقيمة الموجودة بالفعل على القرص، لذا يحدد كل تقرير الأمر الذي يصلحها، وهو `champollion sync --pair <pair> --redo keys:<key>`. وعندما تأتي القيمة التالفة من ذاكرة الترجمة، تتم إزالتها من ذاكرة التخزين المؤقت، بحيث يعيد هذا الأمر ترجمة المفتاح بدلاً من تقديم النص المعطوب نفسه؛ ولا حاجة لاستخدام `--fresh`.

### فهارس gettext (.po) {#gettext}

وجّه `localesPattern` (أو `localesDir`) إلى فهارسك:

```json title="Django"
{ "localesPattern": "locale/{lang}/LC_MESSAGES/{ns}.po" }
```

```json title="GNU (po/fr.po, po/de.po, po/hello.pot)"
{ "localesDir": "./po", "format": "po" }
```

**المصدر** هو فهرس لغة المصدر، على سبيل المثال `locale/en/LC_MESSAGES/django.po` من `django-admin makemessages -l en`. ويُعد `msgid` الخاص به هو النص المراد ترجمته عندما يكون `msgstr` فارغًا. عندما لا يكون هذا الفهرس موجودًا، يكون المصدر قالب `.pot`:

- مع `localesDir`: ملف `.pot` الوحيد في ذلك المجلد.
- مع `localesPattern`: `<name>.pot` في المجلد السابق للعنصر النائب الأول أو المجلد الذي يعلوه. يمثل `<name>` مساحة الأسماء (`{ns}`، قالب واحد لكل نطاق مثل `django.pot`)، أو اسم ملف النمط بدون `{lang}` (`messages.po` ← `messages.pot`).
- مع `localesLayout: "dir"`: لا يتم البحث عن أي قالب. احتفظ بفهرس المصدر في `<localesDir>/<source>/`.

وجود قالبين في موضع يُتوقع فيه وجود قالب واحد يوقف التشغيل. لا يخمن Champollion أيّهما هو المصدر.

**المفاتيح.** كل `msgid` يمثل مفتاحًا. الإدخال الذي يحتوي على `msgctxt` يُفهرس كـ `msgctxt` + U+0004 + `msgid`، وهو ترميز gettext الخاص. يُعد الفعل "Open" والصفة "Open" مفتاحين منفصلين وإدخالين مستقلين في ذاكرة التخزين المؤقت. تطبع التقارير الفاصل كـ `␄` (`verb␄Open`)، ويقبله `--force-keys "verb␄Open"`. إذا لم تتمكن من كتابة `␄`، فاكتب `\x04` (`--force-keys 'verb\x04Open'`): كلاهما يعمل. يقوم `--force-keys` (و`--redo keys:`) بالتقسيم عند الفواصل؛ اكتب الفاصلة داخل msgid كـ `\,` وضع المعامل بين علامتي اقتباس: `--redo 'keys:Welcome back\, %(name)s!'`. تُجلب الإدخالات غير المتغيرة من التخزين المؤقت دون تكلفة.

**ما يتم ترجمته.** الإدخال الذي يحتوي على `msgstr` فارغ، أو تم تمييزه بـ `fuzzy`، يُعد غير مترجم. تقوم المزامنة بترجمته وإزالة `fuzzy` مع أسطر `#|` لـ msgid السابق. يتم الاحتفاظ بتعليقات المترجم (`# …`). وتؤخذ المراجع (`#:`) والتعليقات المستخرجة (`#.`) والشارات من المصدر. تُرسل تعليقات `#.` و`msgctxt` إلى النموذج كسياق. تُعاد كتابة الإدخالات التي لم تغيرها المزامنة بايت ببايت كما هي. ويتم الاحتفاظ بالإدخالات التي لم تعد موجودة في المصدر، وإدخالات `#~` المهملة، في النهاية.

الفهرس الذي ينشئه Champollion (`init --langs`، أو المزامنة لإعداد محلي لا يملك فهرسًا بعد) يحصل على الترويسة الكاملة التي يكتبها `msginit --no-translator` والتي يقبلها `msgfmt -c`: `Project-Id-Version` و`Report-Msgid-Bugs-To` و`POT-Creation-Date` منسوخة من القالب (يُستبدل `PACKAGE VERSION` باسم مجلد المشروع، ولا يوجد `POT-Creation-Date` دون تاريخ القالب)، و`PO-Revision-Date` (وقت إنشاء الملف)، و`Last-Translator: Automatically generated`، و`Language-Team: none`، و`Language`، و`MIME-Version: 1.0`، و`Content-Type: text/plain; charset=UTF-8`، و`Content-Transfer-Encoding: 8bit` و`Plural-Forms`. لا تتم إعادة كتابة ترويسة الفهرس الموجود مسبقًا مطلقًا — بل يتم فقط ملء العناصر النائبة `Plural-Forms` أو `charset=CHARSET` الموجودة فيها.

**صيغ الجمع.** يُترجم أي إدخال يحتوي على `msgid_plural` كرسالة جمع ICU واحدة (`{n, plural, one {One file} other {%(count)d files}}`)، وبذلك يكتب النموذج كل صيغة دفعة واحدة. ثم يُكتب بعد ذلك في `msgstr[0]`…`msgstr[n]` عبر ترويسة `Plural-Forms` الخاصة بالهدف. يأخذ كل فهرس فئة CLDR للأرقام التي تحدده. ففي الروسية تكون `nplurals=3` هي `one`، و`few`، و`many`. وإذا لم تكن لدى الهدف ترويسة `Plural-Forms`، أو كان يحتوي فقط على العنصر النائب في القالب، فإنه يحصل على الترويسة التي يكتبها `msginit` للغته، بحيث تكون خانات `msgstr[]` الخاصة بالكتالوج هي تلك التي يحددها gettext وDjango: الفرنسية `nplurals=2; plural=(n > 1);`، الألمانية `nplurals=2; plural=(n != 1);`، الروسية `nplurals=3; …`. أما اللغة التي ليس لدى `msginit` إدخال لها، فتحصل على ترويسة مشتقة من CLDR، وتُفحص مقابل `Intl.PluralRules` لكل رقم حتى 3,000 وللأرقام الكبيرة. وإذا تعذر كتابة قواعد اللغة كتعبير gettext، تتوقف المزامنة وتذكر الأمر الذي يكتب الترويسة: `msginit --locale=<lang> --input=<template>.pot`. وأي صيغة ليس للكتالوج خانة لها (مثل `many` الفرنسية للرقم 1 000 000 في كتالوج ثنائي الصيغ) لا يُطلب إدخالها مجددًا، ولا تُعلَّم أو يُبلَّغ عنها كمفقودة؛ ويحتفظ الكتالوج الذي يمتلك ترويسة خاصة به بها، وتكون خاناته هي تلك التي تخضع للفحص.

**القيود.** يجب أن تكون الفهارس بترميز UTF-8. قم بتحويل الفهارس الأخرى باستخدام `msgconv --to-code=UTF-8`. لا يمكن كتابة msgid الجمع الذي لا تتطابق أقواسه كرسالة ICU، لذا يُبلغ عنه ويُترك لك لترجمته يدويًا. يُنصح بتشغيل `msgfmt --check-format` (في Django: `compilemessages`) قبل النشر. فهو يفحص فقط الإدخالات المميزة بـ `#, python-format` (أو `c-format`، …): يضيف `makemessages` الشارة إلى الإدخالات التي يستخرجها بعنصر نائب `%`، لكن الفهرس المنشأ يدويًا قد يفتقر إليها، وتمر تلك الإدخالات دون فحص. يقارن `champollion verify` عناصر printf النائبة في كل إدخال — الاسم وحرف النوع — أياً كانت شاراته، وتحتفظ المزامنة بشارات إدخال المصدر في كل إدخال تترجمه.

### ملفات Flutter ARB (.arb) {#arb}

```json title="champollion.config.json"
{ "localesPattern": "lib/l10n/app_{lang}.arb" }
```

استخدم `arb-dir` و`template-arb-file` من `l10n.yaml` الخاص بك إذا كانا مختلفين (`assets/i18n/intl_{lang}.arb`). تتم ترجمة الرسائل فقط. وعند الكتابة:

- يُعيّن `@@locale` إلى الهدف بصيغة Flutter، بما يطابق اسم الملف (`app_pt_BR.arb` ← `"pt_BR"`). يرفض `gen-l10n` الملف الذي يتعارض `@@locale` الخاص به مع اسمه.
- يُنسخ كل كائن بيانات وصفية `@key` (العناصر النائبة، أنواعها، الأوصاف) من المصدر. ويحتفظ المفتاح الذي لا يملك المصدر بيانات وصفية له ببيانات الهدف.
- تتبع المفاتيح ترتيب المصدر. وتُستبعد الرسائل غير المترجمة، بحيث يرجع Flutter إلى القالب الافتراضي تلقائيًا.

تُرسل عناصر `description` الخاصة بالرسالة إلى النموذج كسياق. وتتم حماية العناصر النائبة لـ `{name}` وصيغ جمع ICU بواسطة [فحص ICU](#icu). يُبلغ `verify` و`integrity` أيضًا عن أي `@@locale` خاطئ وبيانات وصفية للعناصر النائبة تختلف عن المصدر. وأي عملية مزامنة تعيد كتابة الملف تصلح كلا الأمرين: يقدّم `champollion sync --pair en:fr --force` كل رسالة لم تتغير مباشرة من التخزين المؤقت.

## مفاتيح مستثناة من الترجمة {#no-translate}

تحتوي بعض القيم على تمثيل صحيح واحد فقط في كل لغة: رابط URL، أو مسار مستودع، أو اسم حزمة، أو معرّف منتج. الترجمة الصحيحة لـ `https://example.org/paper` هي `https://example.org/paper`.

ترفض [بوابة الجودة](/docs/concepts/quality-gate) في Champollion تكرار المصدر (source-echo) — أي ترجمة مطابقة لمصدرها — لأن ذلك عادةً ما يكون ناتجًا عن رفض النموذج أداء الترجمة. بالنسبة لهذه المفاتيح، يجعل ذلك الإجابة الصحيحة هي الإجابة المرفوضة، ولا توجد مخرجات يمكن أن ينتجها النموذج لتجتاز الفحص. تتعلم النماذج الأضعف تجاوز البوابة عن طريق تعديل القيمة بشكل طفيف (مثل إضافة `#fragment` غير حقيقي، أو شرطة مائلة لاحقة شاردة، أو مسافة غير مرئية بعرض صفري)، مما يؤدي إلى شحن روابط معطوبة. أما النماذج الأقوى فتعيد القيمة دون تغيير وتفشل في تجاوز البوابة، مما يجعل `sync` ينهي التشغيل برمز خروج غير صفري في كل مرة.

بدلاً من ذلك، قم بالتصريح عن تلك المفاتيح:

```json title="champollion.config.json"
{
  "noTranslate": ["**.url", "pages.software.*.repo", "meta.appId"]
}
```

المفتاح المطابق **يُنسخ من لغة المصدر حرفيًا** — ولا يُرسل أبدًا إلى خلفية الترجمة، ولا يخضع لبوابة الجودة، ولا يُحسب إطلاقًا كحالة فشل، ولا تُفرض عليه أي تكلفة. كما يُستبعد من تقدير التكلفة المسبق للتشغيل للسبب نفسه.

### صياغة الأنماط

الأنماط هي مسارات نقطية عبر مساحة المفاتيح المسطحة، مع وجود رمزي استبدال (wildcards):

| النمط | يطابق | لا يطابق |
|---------|---------|----------------|
| `nav.brand` | `nav.brand` (مسار دقيق) | `nav.brandName` |
| `**.url` | `url`، `pages.a.b.url` (عنصر فرعي `url` عند أي عمق) | `pages.urlLabel`، `pages.url.caption` |
| `pages.software.*.repo` | `pages.software.portal.repo` | `pages.software.a.b.repo` |
| `meta.og*` | `meta.ogImage`، `meta.ogTitle` | `meta.twitterImage`، `meta.og.image` |

يطابق `*` ضمن مقطع واحد؛ بينما يطابق `**` صفرًا أو أكثر من المقاطع الكاملة.
النمط الخالي من رموز الاستبدال يمثل مسار مفتاح دقيق.

### معالجة روابط URL افتراضيًا

نظرًا لعدم وجود نتيجة مقبولة للمفتاح ذي قيمة URL تحت بوابة الجودة، تم ضبط `noTranslateUrls` على `true` افتراضيًا: أي قيمة مصدرية لا تتجاوز كونها رابط `scheme://` مطلقًا تُعامل كمستثناة من الترجمة دون الحاجة لتهيئة إضافية.

عملية الاكتشاف دقيقة ومحددة عمدًا — يجب أن تكون القيمة الكاملة بعد إزالة الفراغات هي رابط URL نفسه. أما النصوص العادية التي تحتوي فقط على رابط (`"Read the paper at https://…"`) فتتم ترجمتها بشكل طبيعي.

عطّل هذا الإعداد باستخدام `"noTranslateUrls": false` إذا كانت روابطك مخصصة لكل لغة بالفعل (مثل استضافات التوثيق المنفصلة لكل لغة) — ثم صرّح عن الروابط المشتركة غير المخصصة باستخدام `noTranslate`.

### الإصلاح والإنفاذ

بالنسبة للمفاتيح المستثناة من الترجمة، توجد قيمة هدف صحيحة واحدة فقط، وبالتالي يُعتبر أي اختلاف عيبًا صريحًا. يفرض Champollion ذلك في كلا الاتجاهين:

- **`sync` يصلحه.** المفتاح المستثنى من الترجمة الذي يكون هدفه مفقودًا، أو مسبوقًا ببادئة `[EN] `، أو معدلاً، يُعاد كتابته من المصدر. لا يترتب على ذلك أي استدعاء لـ API، وتتميز العملية بأنها لا تحدث تغييرًا بعد التطبيق الأول (idempotent): بمجرد تطابق القيم، تتخطى عمليات المزامنة اللاحقة المفتاح بالكامل.
- **`verify` و`integrity` يفشلان عند وجود اختلاف.** يتم الإبلاغ عن المفتاح المستثنى من الترجمة والمائل عن الأصل كـ `NO-TRANSLATE DRIFT` مع توضيح القيمة المتوقعة والفعلية — وتُكتب الأحرف غير المرئية بترميز الهروب `\uXXXX`، نظرًا لاستحالة ملاحظة هذا النوع من التلف في مقارنة الفروق (diff) بخلاف ذلك. يخرج `champollion integrity` بالرمز `1`، مما يسمح لأي عملية بناء مرتبطة به باكتشاف روابط URL التالفة قبل نشرها.

إذا فشل `integrity` بهذه الطريقة في مشروع انتهيت للتو من تهيئته، فهذا يعني أنه يبلغ عن أضرار كانت موجودة بالفعل في ملفات لغاتك. شغّل `champollion sync` مرة واحدة لإصلاحها.

## تحويل نظام الكتابة {#script-conversion}

بعض اللغات التي يترجمها Champollion يمكن *كتابتها* بأكثر من طريقة. يعمل النموذج دائمًا **بنظام الكتابة التشغيلي** للغة (الترجمة الصوتية اللاتينية — SRO للغة Plains Cree، ونظام Okrand للغة الكلينغونية)، ويمكن لمحوّل حتمي إعادة كتابة المخرجات إلى نظام كتابة العرض بعد ذلك. وتحديد ما إذا كان ينبغي القيام بذلك هو قرار يُتخذ عبر التهيئة — **وليس خيارًا افتراضيًا أبدًا**:

| اللغة | نظام الكتابة التشغيلي | قابل للتحويل إلى | النوع |
|--------|---------------|----------------|------|
| `crk` (Plains Cree) | `Latn` (SRO) | `Cans` (المقطعي) | Unicode قياسي — **الاختيار مطلوب** |
| `sr` / `srp` (الصربية) | `Latn` | `Cyrl` (السيريلية) | Unicode قياسي — **الاختيار مطلوب** |
| `tlh` (الكلينغونية) | `Latn` (اللاتيني) | `Piqd` (pIqaD) | PUA — تفعيل اختياري |
| `x-elvish-s` (السندارينية) | `Latn` | `Teng` (Tengwar) | PUA — تفعيل اختياري |
| `x-kryptonian` | `Latn` | الكريبتونية | PUA — تفعيل اختياري عبر `"script": "x-kryptonian"` |

**أزواج Unicode القياسية (crk, sr) تتطلب الاختيار صراحة.** فالكتابة المقطعية للغة Cree والأبجدية السيريلية مدعومتان بالكامل في Unicode — وتظهران على جميع الأنظمة — وكلا الرسمين الإملائيين مستخدمان واقعيًا. لن يختار Champollion نظام كتابة مجتمع معين نيابة عن المشروع: يطلب `init` منك التحديد عند اختيار اللغة، ويرفض `sync` العمل حتى تحدد التهيئة الخيار المطلوب:

```json
{
  "languages": {
    "crk": { "script": "Cans" }
  }
}
```

**أنظمة كتابة PUA (مثل tlh وx-elvish-s وx-kryptonian) تعتمد الكتابة بالحروف اللاتينية افتراضيًا.** فنظم pIqaD وTengwar والكريبتونية *ليست مدرجة في معيار Unicode* — حيث تصدر المحولات نقاط ترميز في منطقة الاستخدام الخاص (PUA) لا تظهر على الشاشة ما لم تقم بتضمين خط مخصص يدعم نقاط الترميز تلك. تُعد الحروف اللاتينية المخرج الوحيد الذي يُعرض في كل مكان، لذا تم اعتمادها كخيار افتراضي. لإصدار نظام كتابة العرض بدلاً من ذلك:

```json
{
  "languages": {
    "tlh": { "script": "Piqd" }
  }
}
```

...وشغّل `champollion fonts install` حتى يحتوي موقعك على خط قادر على رسمها. إذا كانت خطوطك مبنية على النقل الحرفي اللاتيني (كما هو الحال في العديد من خطوط اللغات المصنوعة)، فاحتفظ بالإعداد الافتراضي.

يأخذ `script` رمز ISO 15924، بأي حالة أحرف (`"cans"` و`"Cans"` و`"CANS"` متطابقة). ويمكن أيضًا تعيينه لكل زوج لغوي، وهو ما يتفوق على الإعداد المحدد على مستوى اللغة. وتؤدي القيمة غير الصالحة، أو نظام الكتابة الذي لا يمكن للمعرف اللغوي إنتاجه، إلى فشل العملية عند بدء التشغيل — قبل إجراء أي استدعاء لـ API.

### الحروف غير المعينة و`scriptFallback` {#script-fallback}

تترجم المحولات ما يحدده رسمها الإملائي فقط ولا شيء غير ذلك. لا تحتوي الكتابة اللاتينية للغة الكلينغونية على `d` أو `c` أو `f` أو `g` أو `i` أو `k` أو `s` أو `x` أو `z` — لذا فإن مخرجات النموذج التي تحتوي على اسم علم مثل "GitHub" لا يمكن تحويلها بالكامل. **لا يكتب Champollion قيمة محولة جزئيًا على الإطلاق**: إذا كان أي حرف غير قابل للتعيين، تظل القيمة بأكملها في نظام الكتابة التشغيلي، ويحدد التحذير الأحرف غير المعينة بالإضافة إلى سطر التهيئة الذي يمكنه تعيينها.

هذه التعيينات متروكة لك للتصريح عنها:

```json
{
  "languages": {
    "tlh": {
      "script": "Piqd",
      "scriptFallback": { "d": "D", "f": "p", "z": "S" }
    }
  }
}
```

تستبدل كل قاعدة تسلسلاً في نظام الكتابة التشغيلي بآخر *يمكن* للمحوّل تعيينه، وذلك قبل بدء عملية التحويل. يتم التحقق من صحة القواعد عند بدء التشغيل — ويُرفض أي استبدال يكون هو نفسه غير قابل للتعيين.

لا يوفر Champollion **أي قواعد بديلة تلقائية من تلقاء نفسه**: فاختراع التعديلات الإملائية، لا سيما لنظام كتابة لغة حقيقية، ليس قرارًا تتخذه الأداة نيابة عنك. تمتلك المجتمعات وأوساط المعجبين أعرافًا وتقاليد معتمدة — فاعتمدها بصورة مدروسة لكل مشروع على حدة.

### إصلاح التحويل غير المرغوب فيه {#repair-script}

قبل الإصدار 0.3.0، كان التحويل غير مشروط — وكانت المشاريع التي تستهدف معرفات PUA اللغوية تحصل على مخرجات غير قابلة للعرض سواء أرادت ذلك أم لا. تسد أداتان هذه الثغرة:

- **`champollion repair-script`** يفحص اللغات التي تنص تهيئتها على أن التحويل *معطّل* بحثًا عن نقاط ترميز PUA، ويستعيد الكتابة اللاتينية باستخدام جدول العكس الخاص بالمحوّل نفسه (استخدم `--dry` للمعاينة). يتم عكس pIqaD بدقة متناهية؛ بينما تفقد عمليات عكس Tengwar والكريبتونية حالة الأحرف الكبيرة وتوضح ذلك.
- **`champollion integrity`** يفشل (برمز خروج 1) عند العثور على ترميزات PUA في الأماكن التي تم فيها تعطيل التحويل — بحيث تكتشف بوابة البناء النصوص غير القابلة للعرض قبل شحنها، ويحدد التقرير طريقة الإصلاح.

لا تحتاج ذاكرة الترجمة إلى إصلاح على الإطلاق: فهي تخزن القيم قبل التحويل، وبالتالي فإن تشغيل `script:` أو إيقافه لاحقًا لا يتطلب أي تعديل على التخزين المؤقت.

ينطبق تحويل نظام الكتابة على نصوص واجهة المستخدم (ملفات المفتاح-القيمة وملفات Docusaurus JSON). لا يتم تحويل نصوص Markdown البرمجية على الإطلاق — فمحول الأحرف الشامل لا يملك طريقة آمنة للمرور عبر كتل الكود وعناوين URL وحقول frontmatter دون إتلافها.

## تهيئة الأزواج اللغوية {#pair-configuration}

يمكن تهيئة كل زوج (مصدر ← هدف) بشكل مستقل:

```json
{
  "pairs": {
    "en:fr": {
      "method": "google-translate",
      "qualityTier": "high"
    },
    "en:ja": {
      "method": "llm",
      "model": "google/gemini-3.1-pro-preview"
    },
    "en:crk": {
      "method": "llm-coached"
    }
  }
}
```

### حقول الأزواج اللغوية

| الحقل | النوع | الوصف |
|-------|------|-------------|
| `method` | `string` | طريقة الترجمة: `llm`، `llm-coached`، `openai`، `anthropic`، `gemini`، `local`، `google-translate`، `deepl`، `microsoft-translator`، `libretranslate`، `apertium`، `tilde`، `translated`، `api` |
| `methodPlugin` | `string` | اسم الإضافة المثبتة (من `.champollion/methods/`) |
| `model` | `string` | تجاوز النموذج الافتراضي لهذا الزوج اللغوي |
| `temperature` | `number` | تجاوز درجة الحرارة الافتراضية لهذا الزوج اللغوي |
| `batchSize` | `number` | تجاوز حجم الدفعة الافتراضي لهذا الزوج اللغوي |
| `register` | `string` | تجاوز الأسلوب/النبرة (مفتاح مسبق الضبط أو نص حر) |
| `endpoint` | `string` | عنوان URL لنقطة نهاية API البعيدة. مطلوب عندما يكون `method` هو `api`. |
| `coachingFile` | `string` | مسار ملف مطالبات التوجيه لهذا الزوج، يُقرأ نسبيًا إلى المشروع؛ ويحل محل أي توجيه عام أقل تحديدًا، وإذا تعذر قراءة الملف يتوقف التشغيل |
| `promptContext` | `string` | سياق التطبيق لهذا الزوج اللغوي |
| `genderGuidance` | `string` \| `false` | تعليمات التذكير والتأنيث لمطالبات هذا الزوج: نص مخصص من عندك، أو `false` لإلغائها. راجع [إرشادات التذكير والتأنيث](#gender-guidance). |
| `qualityTier` | `string` | تسمية تحددها لمخرجات هذا الزوج: `standard`، `high`، `research`، `verified`. لا تُقاس آليًا، وتترجم المزامنة بنفس الطريقة بصرف النظر عن التسمية؛ يعرضها `status` (فقط عند تعيينها) ويعلن عنها `serve` |
| `fallback` | `object` | طريقة بديلة ثانية لما لا تستطيع طريقة هذا الزوج ترجمته بأمان. راجع [الطريقة البديلة](#fallback). القيمة `null` تزيل الطريقة البديلة المحددة للغة. |

### الطريقة البديلة {#fallback}

يمكن للزوج اللغوي تحديد طريقة ثانية بديلة. تترجم طريقة الزوج الأساسية أولاً، وما لا تستطيع ترجمته بأمان ينتقل إلى الطريقة البديلة لمرة واحدة:

- **ملفات المفتاح-القيمة:** المفاتيح التي رفضتها [بوابة الجودة](/docs/concepts/quality-gate) (مثل حذف `{name}`، أو صيغة جمع معطوبة، أو تسمية من كلمتين تحولت إلى فقرة كاملة) والمفاتيح التي لم تُرجع الطريقة أي نتيجة لها.
- **Markdown (محتوى Hugo ووثائق Docusaurus):** حقول front-matter التي تم إغفالها أو تفريغ كلماتها، وكتل النص البرمجي التي أُسقطت من الاستجابة، أو تلفت (بفقدان عنصر محمي: كود، أو وسم HTML، أو shortcode) أو تم تفريغها. وفي تجزئة `page`، الصفحة بأكملها.

```json
{
  "pairs": {
    "en:crk": {
      "method": "api",
      "endpoint": "http://127.0.0.1:8378/translate",
      "fallback": { "method": "llm-coached", "model": "google/gemini-3.8-flash" }
    }
  }
}
```

عندما يُحظر خروج أي نصوص من أجهزتك (كما في حالة مستشفى، أو مدرسة، أو مجتمع محلي يحتفظ ببيانات لغته داخل مقراته)، اجعل الطريقة البديلة نموذجًا تشغله محليًا بنفسك. ترسل الطريقة `local` الطلبات إلى خادم متوافق مع OpenAI على هذا الجهاز (مثل Ollama وllama.cpp وvLLM وLM Studio؛ يحدد `LOCAL_API_BASE` العنوان، راجع [`local`](/docs/guides/translation-methods#local--your-own-model-ollama-vllm-lm-studio-a-trained-model)):

```json
{
  "pairs": {
    "en:crk": {
      "method": "api",
      "endpoint": "http://127.0.0.1:8378/translate",
      "fallback": { "method": "local", "model": "<your local model>" }
    }
  }
}
```

أيهما تختار:

- **النموذج المستضاف سحابيًا** (`llm-coached` مع نموذج Gemini، أو طريقة API أخرى) يقدم عادةً الخيار الثاني الأقوى للغات شحيحة الموارد (low-resource)، وتتم محاسبته لكل طلب. استخدمه عندما يكون إرسال النص إلى مزود الخدمة مسموحًا به.
- **`local`** يحتفظ بجميع المفاتيح على هذا الجهاز، ويظهره التقدير كـ `$0 API cost (runs on this machine)`. استخدمه عندما يُحظر تمامًا خروج أي بيانات من الجهاز، حتى وإن كان النموذج المتاح تشغيله محليًا أصغر حجمًا.

يمر ناتج طريقة الملاذ الأخير (fallback) عبر بوابة الجودة نفسها. ما تترجمه يُخزن مؤقتًا تحت طريقتها الخاصة في ذاكرة الترجمة (Translation Memory)، وبذلك يسجل التخزين المؤقت الطريقة التي أنتجت كل قيمة. تعيد عمليات المزامنة اللاحقة استخدامه بدلاً من طلب الترجمة من الطريقة الأولى مرة أخرى؛ وتطلب `--fresh` أو `--retranslate` الترجمة مجددًا. وما تعجز الطريقتان عن ترجمته يظل على حاله كما لو لم يكن هناك ملاذ أخير. يُترك المفتاح دون ترجمة ويحتفظ بمدخله القديم في ملف القفل، وبذلك تعيد المزامنة التالية المحاولة معه وتدرجه `champollion verify`. وتحتفظ كتلة Markdown بنصها المصدري، دون إضافة أي علامة، ولا تُخزن مؤقتًا، ويُسجل مدخل قفل الصفحة `pending:<hash>`، وبذلك تُعالج الصفحة مرة أخرى في المزامنة التالية. وأي كتلة أو حقل front-matter ترفضه بوابة الجودة من كلتا الطريقتين يُحجب، ولا يُعاد إرساله إليهما إلا بعد أن تحدد `--redo files:<page>` الصفحة بالاسم ([كتل Markdown وحقول front-matter المرفوضة](/docs/concepts/quality-gate#refused-markdown-blocks-and-front-matter-fields)). وأي حقل front-matter تتركه الطريقتان فارغًا، أو أي صفحة تعجز الطريقتان عن ترجمتها، يؤدي إلى إخفاق الملف، تمامًا كما هو الحال دون طريقة ملاذ أخير.

تقبل الطريقة البديلة الحقول نفسها التي يقبلها الزوج اللغوي: `method` (مطلوب)، `model`، `provider`، `endpoint`، `methodPlugin`، `coachingFile`، `coachingPrompt`، `promptContext`، `register`، `temperature`، `batchSize`، `maxRetries`، `qualityTier`، `contentSegmentation`، `name`. وتتم معالجتها تمامًا كالزوج اللغوي؛ حيث تُورث الحقول التي لم تعيّنها صراحة (كالأسلوب، والتوجيه، وسياق المطالبة، ...) من الزوج اللغوي التابعة له. وتصل قيمة `coachingFile` الخاصة بها إلى مطالبتها ومفتاح التخزين المؤقت الخاص بها، ويعرضها `champollion status`. ونظرًا لأن نظام الكتابة يرتبط بالزوج اللغوي، فإن `script` و`scriptFallback` يُرفضان في الطريقة البديلة، وكذلك يُرفض تعيين `fallback` بديل ثانٍ لها. وأي طريقة غير معروفة، أو طريقة بديلة مطابقة لطريقة الزوج الأساسية، توقف المزامنة مع إظهار خطأ يحدد الزوج المعني. كما يجب أن تكون الطريقة البديلة جاهزة للعمل قبل بدء المزامنة تمامًا مثل الطريقة الأساسية للزوج (على سبيل المثال، يجب أن يكون مفتاح API الخاص بها معينًا مسبقًا).

- **`--method` و`--model` يغيران طريقة الزوج الأساسية فقط.** وتحتفظ الطريقة البديلة بما هو منصوص عليه في ملف التهيئة.
- **التكلفة.** يغطي تقدير ما قبل التشغيل الطريقة الأساسية للزوج فقط، إذ لا يمكن لأحد معرفة ما سيفشل مسبقًا. يتم تسعير كل دفعة من الدفعات البديلة قبل تشغيلها مباشرة، باستخدام أداة التقدير ذاتها. مع `--max-cost`، يتم تخطي الدفعة التي قد تدفع تكلفة التشغيل لتجاوز الحد الأقصى (التقدير بالإضافة إلى كل دفعة بديلة حتى اللحظة)، مع إظهار تحذير يحدد المفاتيح المعنية؛ وكذلك يتم تخطي أي طريقة بديلة لا يمكن تقدير تكلفتها (فالمجهول ليس مجانيًا). وتظل تلك المفاتيح في حالة فشل، وينتهي تشغيل المزامنة برمز غير صفري مثل أي فشل جزئي.
- **إعداد التقارير.** يطبع `sync` سطرًا واحدًا لكل زوج، مثل `[FALLBACK] en:crk — 6 key(s) the primary (api) could not translate safely → translated by llm-coached (4 accepted, 2 still failing)`. يوضح ملخص `--json` لكل زوج ما قامت به الطريقة البديلة (`method`، `attempted`، `accepted`، `failed`، `cached`): في كل إدخال من `locales` لملفات المفتاح-القيمة، وفي `fallback` لملفات Docusaurus JSON، وفي `content.fallback` لملفات Markdown. ويعرض `champollion status` الطريقة البديلة مدرجة تحت الزوج الخاص بها. لا يمكن لـ `--dry` معرفة ما سيفشل، لذا لا يقدم أي تقرير بخصوص الطريقة البديلة.
- **عندما تترجم الطريقة البديلة معظم المحتوى.** عندما تأتي أكثر من نصف الترجمات الجديدة للزوج اللغوي أثناء التشغيل (الإجابات المقبولة من طريقة الزوج بالإضافة إلى إجابات الطريقة البديلة) من الطريقة البديلة، يضيف `sync` تحذيرًا واحدًا: يوضح عدد الترجمات من المجموع الكلي، وبأي طريقة ونموذج، وأسباب عدم استخدام إجابات طريقة الزوج الأساسية (مع حساب كل سبب: جملة محفوظة تكررت لنصوص مصدرية مختلفة، أو تضخم في الطول، ...)، وما يجب مراعاته — فقد لا تكون طريقة الزوج مناسبة لهذه النصوص؛ تحقق مما كُتب (`verify` يفحص البنية، والمتحدث باللغة يتحقق من المعنى)؛ أو فكر في طريقة بديلة أقوى. وتتضمن إدخالات `--json` الحقلين `primaryAccepted` و`primaryReasons` إلى جانب `accepted`. ويقدم `champollion status` النسبة نفسها للملفات ("من الطريقة البديلة: 8 قيمة (قيم) في الملفات (...) — 8 من أصل 8 كتبتها المزامنة (100%)")، ويوضح متى شكلت النسبة الأكبر من نص اللغة الهدف.
- يستخدم `champollion serve` الطريقة البديلة أيضًا، ضمن حدود `--max-cost-per-request` / `--max-session-cost` المحددة له.

## تهيئة اللغات {#language-configuration}

تقبل اللغات ثلاثة تنسيقات:

### مصفوفة من الرموز (الأبسط)

```json
{
  "languages": ["fr", "de", "ja"]
}
```

تحصل كل لغة على أسلوبها الافتراضي من جدول الأساليب المدمج. واللغات التي ليس لها أسلوب افتراضي تحصل على `"Professional register."`.

### كائن يحتوي على نصوص الأسلوب

يمكن أن تكون القيمة **مفتاحًا مسبق الضبط** من بطاقة اللغة، أو نص أسلوب مخصص:

```json
{
  "languages": {
    "fr": "casual-tu",
    "ko": "formal-hapsyo",
    "ja": "Custom: Polite Japanese for a gaming app."
  }
}
```

يتحقق Champollion مما إذا كانت السلسلة النصية تطابق مفتاحًا مضبوطًا مسبقًا في بطاقة اللغة. وإذا تطابقت، يُستخدم موجه الأسلوب اللغوي الكامل من البطاقة. وإذا لم تتطابق، تُستخدم السلسلة النصية كما هي. راجع [التكوين](/docs/getting-started/configuration) للاطلاع على الإعدادات المسبقة المتاحة.

### كائن مع تهيئة كاملة

```json
{
  "languages": {
    "crk": {
      "name": "Plains Cree",
      "register": "SRO syllabics with grammatical precision.",
      "model": "google/gemini-3.1-pro-preview",
      "batchSize": 5,
      "maxRetries": 5,
      "script": "Cans"
    }
  }
}
```

يمكنك الجمع بين الصيغة المختصرة والكائنات الكاملة داخل الكتلة نفسها.


### حقول اللغة

| الحقل | النوع | الوصف |
|-------|------|-------------|
| `register` | `string` | تعليمات الأسلوب/النبرة. يمكن أن تكون **مفتاح إعداد مسبق** (مثل `casual-tu`، `formal-hapsyo`) أو نصًا مخصصًا. راجع [بطاقات اللغات](/docs/getting-started/configuration). |
| `name` | `string` | اسم اللغة المقروء بشريًا (لعرض الحالة) |
| `model` | `string` | تجاوز النموذج الافتراضي |
| `temperature` | `number` | تجاوز درجة الحرارة الافتراضية |
| `batchSize` | `number` | تجاوز حجم الدفعة الافتراضي |
| `coachingFile` | `string` | مسار إلى ملف موجه التوجيه لهذه اللغة، يُقرأ نسبيًا بالنسبة للمشروع؛ يحل محل التوجيه عالي المستوى، والملف الذي يتعذر قراءته يوقف التشغيل |
| `promptContext` | `string` | سياق التطبيق لهذه اللغة |
| `genderGuidance` | `string` \| `false` | تعليمات الجنس لمطالبات هذه اللغة: نصك الخاص، أو `false` لعدم استخدام أي تعليمات. راجع [إرشادات الجنس النحوي](#gender-guidance). |
| `maxRetries` | `number` | الحد الأقصى لميزانية إعادة المحاولة للدفعات الفاشلة (افتراضيًا: 3) |
| `script` | `string` | رمز ISO 15924 لنظام الكتابة الإملائي الذي يكتب به Champollion (مثل `"Cans"`، `"Piqd"`). راجع [تحويل نظام الكتابة](#script-conversion). |
| `scriptFallback` | `object` | قواعد الحَرْفَنَة للحروف التي لا يستطيع محول نظام الكتابة مطابقتها. راجع [تحويل نظام الكتابة](#script-conversion). |
| `endpoint` | `string` | عنوان URL لنقطة نهاية API البعيدة، لـ `"method": "api"` |
| `fallback` | `object` | طريقة ثانية لما لا تستطيع طريقة هذه اللغة ترجمته بأمان. راجع [طريقة الملاذ الأخير](#fallback). |

:::info[سلسلة التوريث]
يتم حل الإعدادات وتطبيقها بهذا الترتيب (الأولية للأول):

**مستوى الزوج اللغوي** ← **مستوى اللغة** ← **التهيئة العامة** ← **الإعدادات الافتراضية**

على سبيل المثال، إذا عيّن `pairs["en:fr"]` القيمة `model`، فإنه يتجاوز قيم `model` المحددة على مستوى اللغة وعلى المستوى العام.
:::

### إرشادات التذكير والتأنيث {#gender-guidance}

تتضمن مطالبات نماذج LLM تعليمات حول التذكير والتأنيث النحوي للغات التي تحتوي على هذه الخاصية، وتؤخذ هذه التعليمات من دليل Champollion: فتطلب الفرنسية *الكتابة الشاملة* (écriture inclusive) باستخدام النقطة الوسطية عندما يكون جنس القارئ غير معروف (`Connecté·e`، وليس `Connecté(e)` أو `Connectée`؛ و`Utilisateur·rice·s` في الجمع)، وتطلب الألمانية صيغة النقطتين (`Benutzer:innen`)، واليابانية الصيغة المحايدة `私`. يطبع `champollion init` هذه التعليمات بجانب أسلوب كل لغة، ويعرضها `champollion status` لكل زوج مع بيان مصدرها.

يمكنك اختيار نمط آخر باستخدام `genderGuidance`، لجميع اللغات أو للغة معينة:

```json
{
  "languages": {
    "fr": { "register": "formal-vous", "genderGuidance": "Use the masculine generic (Connecté), as the Académie française recommends." },
    "de": { "register": "formal-Sie", "genderGuidance": false }
  }
}
```

القيمة `false` لا ترسل أي تعليمات بخصوص الجنس؛ والنص المخصص يحل محل ما هو موجود في الدليل. ينطبق هذا الإعداد على الطرق التي تقبل التعليمات (طرق LLM)؛ بينما لا تُخطر به محركات الترجمة الآلية التقليدية (مثل DeepL وGoogle وغيرها). وتؤدي أي تعليمة جنس متغيرة إلى إنشاء مطالبة مختلفة، وبالتالي تصبح لها إدخالات تخزين مؤقت خاصة بها: فما تمت ترجمته بالفعل يظل كما هو حتى تعيد ترجمته (`champollion sync --redo all`، وهو ما تقترحه المزامنة عندما تحتوي الملفات على النمط السابق).

## ملف القفل

ينشئ Champollion الملف `.champollion.lock` لتتبع تجزئات SHA-256 للقيم المصدرية المترجمة. **قم بإيداع (commit) هذا الملف في نظام إدارة النسخ** ليتشارك جميع المطورين نفس الأساس المرجعي للترجمة. في المشاريع التي تعتمد مجلدًا واحدًا لكل لغة، تُسجل المفاتيح كـ `<namespace>::<key>`.

لكل لغة هدف، يسجل ملف القفل أيضًا بصمة لكل قيمة كتبتها المزامنة وللنص المصدري الذي تُرجمت منه (للتعرف على القيمة التي عدلها شخص يدويًا والإبلاغ عن أي ترجمة قديمة)، والمفاتيح التي لم تكتمل إعادة ترجمتها (**pending**)، والمفاتيح التي رفضتها بوابة الجودة (**held back** لمنع إرسالها للنموذج نفسه). وإذا تطلب الأمر تسجيل أي من ذلك، يتخذ الملف صيغة الإصدار الثاني، `{"version": 2, "source": {…}, "locales": {…}}`؛ بينما يُقرأ قفل الإصدار الأول (خريطة مسطحة: مفتاح ← تجزئة) كما كان من قبل. ويتم الاحتفاظ بالتعديل اليدوي المستبدل في ملف `.champollion-replaced-edits.jsonl` بجواره — احرص على إيداع كليهما. راجع [بوابة الجودة](/docs/concepts/quality-gate#refused-keys-are-held-back) و[تعديل الترجمات](/docs/guides/professional-translators#editing-key-value-files).

عندما تتغير قيمة المصدر، تصبح التجزئة غير متطابقة، ويعيد Champollion ترجمة ذلك المفتاح في المزامنة التالية.

## `.champollionignore`

أنشئ ملف `.champollionignore` في جذر مشروعك لاستبعاد الملفات من فحص `lint`. يستخدم الملف أنماط glob تمامًا مثل `.gitignore`:

```text title=".champollionignore"
src/components/legacy/**
src/utils/constants.js
**/*.test.js
```

## مجلد `.champollion/`

ينشئ Champollion مجلد `.champollion/` في جذر مشروعك لحفظ الحالة الداخلية. احتفظ به خارج نظام إدارة النسخ (version control) — فهو تخزين مؤقت خاص بكل جهاز وليس جزءًا من شفرة المصدر للمشروع. يضيف `champollion init` هذا السطر إلى `.gitignore`، منشئًا الملف إن لم يكن موجودًا (وكذلك في المجلد الذي لم يُهيأ كمستودع git بعد، حتى لا تؤدي أوامر `git init` و`git add --all` لاحقًا إلى إيداع ذاكرة التخزين المؤقت):

```gitignore
.champollion/
```

قم بإيداع ملفات القفل الموجودة بجواره (`.champollion.lock`، `.champollion-content.lock`): فهي تسجل النص المصدري الذي أُنشئت منه كل ترجمة.

| الملف | الغرض | هل يتم إيداعه؟ |
|------|---------|--------|
| `tm.json` | ذاكرة التخزين المؤقت لذاكرة الترجمة — تخزن الترجمات السابقة مفهرسة حسب النص المصدري + اللغة + الطريقة | لا (تخزين مؤقت محلي) |
| `xliff/*.xliff` | ملفات تصدير XLIFF لمراجعة المترجمين المحترفين | لا (ملفات عابرة مؤقتة) |
| `methods/` | بيانات بيان إضافات الطرق المثبتة | يتم تجاهلها بواسطة سطر `.champollion/`. ولمشاركة الإضافات المثبتة، استبدل ذلك السطر بـ `.champollion/*` و`!.champollion/methods/` |
| `backups/` | نسخ احتياطية قبل الالتفاف (تُنشأ بواسطة `wrap --undo`) | لا (شبكة أمان مؤقتة) |

راجع [ذاكرة الترجمة](/docs/concepts/translation-memory) للحصول على تفاصيل حول `tm.json` وكيف يوفر تكاليف استدعاء API.

## واجهة برمجة التطبيقات البرمجية (API)

بالنسبة لنصوص البناء البرمجية وعمليات التكامل المخصصة، يمكنك الاستيراد مباشرة من الحزمة:

```javascript
import { GeminiMethod, runSync, resolveConfig } from 'champollion';

// Use a method class directly
const gemini = new GeminiMethod();
const result = await gemini.translate(
  ['greeting', 'farewell'],
  { greeting: 'Hello', farewell: 'Goodbye' },
  { target: 'fr', name: 'French', register: 'formal', model: 'gemini-2.5-flash' },
  { cwd: process.cwd() }
);
// result = { greeting: 'Bonjour', farewell: 'Au revoir' }
```

### العناصر المصدرة المتاحة

| العنصر المصدر | وظيفته |
|--------|-------------|
| `TranslationMethod` | الفئة الأساسية لجميع الطرق |
| `LLMMethod` | الفئة الأساسية لطرق LLM (مثل OpenRouter) |
| `DirectLLMMethod` | الفئة الأساسية لمزودي LLM المباشرين (OpenAI، Anthropic، Gemini) |
| `OpenAIMethod`، `AnthropicMethod`، `GeminiMethod` | فئات مزودي LLM المباشرين |
| `DeepLMethod`، `MicrosoftTranslatorMethod`، `LibreTranslateMethod`، `TildeMethod`، `TranslatedMethod` | فئات الترجمة الآلية التقليدية (Traditional MT) |
| `GoogleTranslateMethod` | Google Cloud Translation |
| `LLMCoachedMethod` | نموذج LLM الموجّه (OpenRouter + بيانات التوجيه) |
| `APIMethod` | عميل واجهة برمجة التطبيقات البعيدة (Remote API client) |
| `runSync`، `runContentSync` | خط أنابيب المزامنة الكامل |
| `translateWithFallback`، `translateAndValidate` | خط أنابيب زوج لغوي واحد لدفعة من المفاتيح، كما يشغله `sync`: التخزين المؤقت، ثم الطريقة، ثم بوابة الجودة، ثم التخزين المؤقت، ثم الطريقة البديلة للزوج. مرر زوجًا من `resolvePairs`، و`tm` من `loadTM`، و`cwd` وهو دليل المشروع: حيث تقرأ الطريقة مفتاحها ونقطة النهاية والتوجيه والقاموس من هناك، وليس من `process.cwd()` |
| `createFallbackBudget` | حارس `--max-cost` لدفعات الطريقة البديلة (`{ maxCost, committed, cwd }`) |
| `discoverLocaleLayout`، `resolveLocaleFiles` | الملفات التي تشكل كل لغة (مسطحة، أو مجلد لكل لغة، أو `localesPattern`) |
| `resolveConfig`، `resolvePairs` | حل واستخراج التهيئة |
| `validateTranslations` | بوابة الجودة |
| `loadCoachingData`، `findDictionaryMatches` | أدوات مساعدة للتوجيه |

### توسيع مزود مخصص

قم بتوسيع `DirectLLMMethod` لإضافة مزود LLM جديد في حوالي 40 سطرًا فقط:

```javascript
import { DirectLLMMethod } from 'champollion';

class MistralMethod extends DirectLLMMethod {
  constructor(options) {
    super(options);
    this.name = 'mistral';
  }
  _getApiKeyEnvVar()     { return 'MISTRAL_API_KEY'; }
  _getApiKeyOptionsKey() { return 'mistralApiKey'; }
  _getDefaultModel()     { return 'mistral-large-latest'; }
  _getProviderLabel()    { return 'Mistral'; }

  _buildApiRequest({ prompt, systemMessage, apiKey, model, temperature }) {
    return {
      url: 'https://api.mistral.ai/v1/chat/completions',
      headers: { 'Authorization': `Bearer ${apiKey}`, 'Content-Type': 'application/json' },
      body: {
        model,
        messages: [
          ...(systemMessage ? [{ role: 'system', content: systemMessage }] : []),
          { role: 'user', content: prompt },
        ],
        temperature,
      },
    };
  }

  _extractResponseText(json) {
    return json.choices?.[0]?.message?.content;
  }

  // Optional but recommended: provider-specific setup help when translation fails
  getSetupHelp() {
    if (!process.env.MISTRAL_API_KEY) {
      return [
        '',
        '  ┌─ Missing API Key ─────────────────────────────────────────────┐',
        '  │ Mistral requires an API key from https://console.mistral.ai   │',
        '  │ Run: export MISTRAL_API_KEY=...                               │',
        '  └────────────────────────────────────────────────────────────────┘',
      ];
    }
    return ['        API key is set but translation failed. Check your Mistral dashboard.'];
  }
}
```

تحصل مجانًا على الترجمة، والتوجيه، وحلقات إعادة المحاولة، والتحقق من صحة النموذج، وتسمية `qualityTier`، ومساعدة الإعداد. هيكل طلب HTTP وحده هو ما يختلف باختلاف المزود. بالنسبة للمحولات غير المعتمدة على LLM والتي تستخدم `fetch()` الخام، استخدم الدالة المساعدة المشتركة `fetchWithRetry()` من `lib/methods/fetch-with-retry.js` بدلاً من كتابة حلقة إعادة المحاولة الخاصة بك.
