# واجهة الطريقة المشتركة

> **ملخص تنفيذي.** تحدد هذه الصفحة بروتوكول `TranslationMethod` الذي يجب أن تنفذه جميع طرق الشبكة (Network)، وفئات الطرق الست (`raw-llm`، `coached-llm`، `pipeline`، `custom-plugin`، `api`، `human`)، ومحور **النموذج** (paradigm) المتعامد (`rule-based`، `statistical`، `neural-nmt`، `llm`، `hybrid`، ...) الذي يجعل *كيفية ترجمة الطريقة* قابلة للمقارنة عبر الأنظمة، وتنسيق المكون الإضافي للطريقة، و**فئات التبعية** (S/O/A1/A2/X) التي تحدد ما إذا كان يمكن تشغيل الطريقة في بيئة التقييم المعزولة (sandbox) وتأهلها للجوائز. هذه ثلاثة محاور مستقلة. يمكن قياس أداء أي نهج ينفذ هذا البروتوكول؛ وما يعتمد عليه يحدد أين يمكنه المنافسة.

تشترك أداة التقييم (eval harness) و Champollion في مفهوم مشترك لـ **طريقة الترجمة** (translation method). الطريقة هي أي إجراء يأخذ نصاً مصدرياً وينتج نصاً مترجماً — سواء كان ذلك استدعاءً مباشراً لنموذج لغوي كبير (LLM)، أو مسار عمل (pipeline) متعدد المراحل، أو واجهة برمجة تطبيقات (API) لجهة خارجية، أو مترجماً بشرياً.

## البنية

```
Method Plugin (v2 Spec)
├── method.json           ← Manifest (name, class, entry_point, dependencies, metadata)
├── method_card.json      ← Leaderboard description (what, not how)
├── pipeline.py           ← Python module implementing TranslationMethod
└── (optional helpers)    ← Additional Python modules
```

يتم تحميلها عبر `--method path/to/dir`. لا تكتشف أداة التقييم أي شيء تلقائياً.

## نظامان، واجهة واحدة

| | أداة التقييم (Eval Harness) | Champollion |
|---|---|---|
| **اللغة** | Python | Node.js |
| **نقطة الدخول** | `translate.py` | `translate.js` |
| **الواجهة** | بروتوكول `TranslationMethod` | تكوين `methodPlugin` |
| **الغرض** | تقييم دفعي مع تسجيل النقاط | توطين مباشر في بيئة التطوير/التكامل المستمر (dev/CI) |
| **المخرجات** | بطاقة التشغيل مع المقاييس | ملفات الترجمة المحلية (locale files) |

توفر الطريقة التي تدعم كلا النظامين نقطتي دخول — واحدة لكل بيئة تشغيل لغة. **بطاقة الطريقة** (method card) هي الجسر: فهي تصف الطريقة بتنسيق يفهمه كلا النظامين.

## بطاقة الطريقة {#method-card}

تصف بطاقة الطريقة *ماهية* طريقة الترجمة دون الكشف عن تفاصيل الملكية مثل موجه النظام (system prompt) الكامل. وهي تجيب على:

- ما هي فئة هذه الطريقة؟ (نموذج لغوي كبير خام، نموذج لغوي كبير موجه، مسار عمل، واجهة برمجة تطبيقات، إلخ.)
- ما هو **النموذج** (paradigm) الذي تستخدمه؟ (قائم على القواعد، إحصائي، ترجمة آلية عصبية، نموذج لغوي كبير، هجين)
- ما هي الأدوات التي تستخدمها؟ (محلل FST، قاموس، إلخ.)
- هل التنفيذ مفتوح المصدر؟
- ما هي أزواج اللغات التي تدعمها؟

راجع [مواصفات بطاقة الطريقة](/docs/network/specifications/methods#method-card) للحصول على مخطط JSON الكامل.

### مثال

```json
{
  "method_id": "fst-gated-v8",
  "name": "FST-Gated Coached Translation v8",
  "class": "pipeline",
  "paradigm": "hybrid",
  "description": "LLM translation with morphological validation. Failed words are retried with FST feedback.",
  "author": "Curtis Forbes",
  "tools_used": ["HFST morphological analyzer", "Wolvengrey dictionary"],
  "open_source": false,
  "dependency_class": "A2",
  "supported_pairs": ["eng>crk"]
}
```

يلخص الحقل `dependency_class` ما تحتاجه الطريقة للتشغيل والنقل — راجع [صلاحية الطريقة وفئات التبعية](#method-validity-and-dependency-classes) أدناه. يضع الحقل `paradigm` الطريقة على **محور النموذج** (هنا `hybrid`: نموذج لغوي كبير مقيد بواسطة FST قائم على القواعد) — راجع [النماذج](#paradigms) أدناه.

### فئات الطريقة

| الفئة | الوصف |
|-------|-------------|
| `raw-llm` | استدعاء مباشر لنموذج لغوي كبير (LLM) مع تعليمات بالحد الأدنى |
| `coached-llm` | نموذج لغوي كبير (LLM) مع موجه منظم، وأمثلة، وقيود |
| `pipeline` | مسار عمل (pipeline) متعدد المراحل مع مكونات حتمية |
| `custom-plugin` | عملية خارجية تنفذ بروتوكول `TranslationMethod` |
| `api` | واجهة برمجة تطبيقات (API) للترجمة تابعة لجهة خارجية (Google Translate، DeepL، إلخ.) |
| `human` | ترجمة بشرية (لإنشاء خطوط الأساس) |

### النماذج {#paradigms}

**النموذج** (paradigm) هو محور ثالث مستقل: *كيفية ترجمة الطريقة على المستوى الخوارزمي*. وهو متعامد مع كل من فئة الطريقة وفئة التبعية. فئة الطريقة وحدها تتمحور حول النماذج اللغوية الكبيرة (LLM) — فنظام [Apertium](https://www.apertium.org/) القائم على القواعد و Google Translate يقعان كلاهما في `pipeline`/`api`، لذا فإن المقارنة بين "القائم على القواعد مقابل العصبي" تكون غير مرئية بدونه. يجعل محور النموذج هذه المقارنة من الدرجة الأولى وقابلة للفلترة في لوحة الصدارة (leaderboard).

| النموذج | الوصف | أمثلة |
|----------|-------------|----------|
| `rule-based` | محولات الحالة المحدودة (FST)، قواعد نحوية مكتوبة يدوياً، نقل صرفي | Apertium، توليد GiellaLT FST |
| `statistical` | ترجمة آلية إحصائية (SMT) / قائمة على العبارات مستفادة من المتون المتوازية | Moses الكلاسيكي |
| `neural-nmt` | نموذج ترجمة آلية (MT) عصبي مخصص للتشفير وفك التشفير | Google Translate، DeepL، Microsoft Translator، OPUS-MT، LibreTranslate، Tilde MT، Translated (Lara) |
| `llm` | نموذج لغوي كبير (LLM) للأغراض العامة موجه للترجمة | استدعاء GPT / Claude / Gemini خام أو موجه |
| `hybrid` | يجمع بين نموذجين أو أكثر في طريقة واحدة | نموذج لغوي كبير مقيد بواسطة FST قائم على القواعد (crk-translate)؛ ترجمة آلية عصبية (NMT) + تحرير لاحق قائم على القواعد |
| `human` | ترجمة بشرية (خط أساس على مستوى النموذج) | خط أساس لمترجمي المجتمع |
| `unknown` | غير محدد — لم تعلن البطاقة عن أي نموذج | افتراضي للتوافق مع الإصدارات السابقة للبطاقات التي تسبق النماذج |

المحاور مستقلة. بعض الأمثلة العملية:

| الطريقة | `class` | `paradigm` | `dependency_class` |
|--------|---------|-----------|--------------------|
| Google Translate | `api` | `neural-nmt` | A2 |
| Tilde MT / Translated (Lara) | `api` | `neural-nmt` | A2 |
| LibreTranslate (استضافة ذاتية، مفتوح المصدر) | `api` | `neural-nmt` | O |
| Apertium | `pipeline` | `rule-based` | O |
| crk-translate (مقيد بـ FST، موجه بـ LLM) | `pipeline` | `hybrid` | A2 |
| استدعاء GPT خام | `raw-llm` | `llm` | A1 |

النموذج **اختياري** في بطاقة الطريقة؛ يتم تسجيل النموذج الغائب كـ `unknown` (لا يمنع النشر أبداً — المحور إضافي). التعداد (enum) أعلاه هو المفردات الأساسية المدعومة، والتي تفرضها أداة التقييم (`config.VALID_PARADIGMS`). نظراً لأن الفرض يتم على جانب التطبيق بدلاً من كونه قيداً في قاعدة البيانات، يمكن إضافة نماذج جديدة لاحقاً دون الحاجة إلى ترحيل (migration)؛ فقط إعادة تسمية أو إزالة قيمة بمجرد اعتماد الطرق عليها هو أمر مكلف.

## صلاحية الطريقة وفئات التبعية {#method-validity-and-dependency-classes}

تكون الطريقة قابلة للتشغيل وقابلة للنقل بقدر التبعية الأقل توفراً لديها. تعتمد آليتان في الشبكة (Network) على معرفة ما تحتاجه الطريقة بالضبط:

1. **التقييم في بيئة معزولة** ([مواصفات المعيار المرجعي §8.2](/docs/network/specifications/benchmark)) — تأتي الدرجات الرسمية ذات المعيار الذهبي من بيئة معزولة (sandbox) تكون سياسة الشبكة الخاصة بها هي **الرفض الافتراضي** (default-deny). لا يمكن للطريقة التي تتطلب خدمة خارجية بصمت أن تنتج درجة رسمية.
2. **نقل الجائزة** ([مواصفات الجوائز](/docs/network/specifications/prizes)) — تُنقل الطرق الفائزة بالجوائز إلى منظمة الحوكمة الخاصة بمجتمع اللغة. لا يمكن نقل الطريقة التي تجمع محتوى لم يكن لمقدمها الحق في تضمينه بشكل قانوني. يجب أن يمتلك المقدم (أو يُمنح) حقوق كل شيء داخل الحزمة.

لجعل كلا الفحصين آليين بدلاً من كونهما مخصصين (ad hoc)، تعلن كل طريقة عن **فئة تبعية**، مشتقة من **بيان التبعية** (dependency manifest) في `method.json`.

> **ملاحظة حول التسمية — ثلاثة محاور مستقلة.** تصف *فئة الطريقة* (§أعلاه: `raw-llm`، `pipeline`، ...) *شكل* الطريقة — عقد الواجهة الذي تقدمه. يصف *النموذج* ([§النماذج](#paradigms): `rule-based`، `neural-nmt`، `llm`، ...) *كيفية ترجمتها خوارزمياً*. تصف *فئة التبعية* (هذا القسم) *ما تحتاجه للتشغيل والنقل*. الثلاثة متعامدة: يمكن أن تكون طريقة `pipeline` إما `rule-based` أو `hybrid`، ويمكن أن تكون من أي فئة تبعية. (تم فصل الفئة والنموذج عن قصد لأن الفئة وحدها تتمحور حول النماذج اللغوية الكبيرة — ولا يمكنها التمييز بين نظام قائم على القواعد ونظام عصبي عندما يظهر كلاهما كـ `pipeline` أو `api`.)

### فئات التبعية الخمس

| الفئة | الاسم | التعريف | قابلة للتشغيل في بيئة معزولة؟ | مؤهلة للجوائز؟ |
|-------|------|-----------|-------------------|-----------------|
| **S** | مكتفية ذاتياً (Self-contained) | يتم شحن جميع التعليمات البرمجية والبيانات والنماذج والأوزان داخل دليل الطريقة، بموجب تراخيص تسمح بإعادة التوزيع والنقل المجتمعي. | ✅ نعم، كما هي | ✅ نعم |
| **O** | خارجية مفتوحة (Open external) | تعتمد على عناصر مستضافة خارجياً بموجب تراخيص مفتوحة تسمح بإعادة التوزيع (بما في ذلك تراخيص الحقوق المتروكة مثل AGPL) — على سبيل المثال، FST يتم تنزيله في وقت التثبيت. | ✅ نعم — يتم تثبيت العناصر و**عكسها في التقديم** | ✅ نعم، مع شروط توافق الترخيص: يتم الحفاظ على شروط الحقوق المتروكة (copyleft) من خلال النقل، ويتلقى المجتمع نفس الحقوق التي يمنحها الترخيص للجميع |
| **A1** | تعتمد على API، قابلة للاستبدال | تتطلب استدلال نموذج لغوي كبير (LLM) في وقت التشغيل، حيث يكون النموذج **تكويناً قابلاً للاستبدال** — يمكن إدخال أي نموذج قادر بما فيه الكفاية. تكمن قيمة الطريقة في موجهاتها، وبيانات التوجيه، والتعليمات البرمجية، وليس في نموذج أي مزود واحد. | ⚠️ فقط عبر **بوابة LLM** التي تحددها مواصفات البيئة المعزولة (🔲 مخطط لها — راجع أدناه) | ⚠️ مشروط — راجع أدناه |
| **A2** | تعتمد على API، غير قابلة للاستبدال | تتطلب استدعاءات في وقت التشغيل لبيانات خارجية أو واجهة برمجة تطبيقات (API) لخدمة لا يمكن عكسها أو استبدالها — عادةً لأن المحتوى المقدم مملوك أو غير مرخص (على سبيل المثال، واجهة برمجة تطبيقات لقاموس لا يحتوي قاموسه الأساسي على ترخيص عام). | ❌ لا — لا يمكن أن توجد التبعية في البيئة المعزولة دون إذن صاحب الحقوق | ❌ ليس حتى يمنح صاحب الحقوق أذونات التضمين في البيئة المعزولة **و** النقل. مسموح بها في لوحة الصدارة المفتوحة (شريحة التطوير) مع علامة **"تبعية خارجية"** مرئية |
| **X** | مغلقة (Closed) | تجمع محتوى لا يحق للمقدم إعادة توزيعه — مجموعات بيانات غير مرخصة، محتوى مملوك تم استخراجه (scraped)، مكونات غير متوافقة مع الترخيص. | ❌ | ❌ غير مقبولة في كل مسار. تجميع المحتوى بدون حقوق يعد انتهاكاً للترخيص بغض النظر عن مكان تشغيل الطريقة |

**الفئة الفعالة.** فئة تبعية الطريقة هي الفئة *الأكثر تقييداً* من بين جميع تبعياتها المعلنة، بالترتيب S < O < A1 < A2 < X. قاموس واحد غير مرخص يجعل مسار العمل المكتفي ذاتياً من الفئة A2 (إذا تم الوصول إليه في وقت التشغيل) أو الفئة X (إذا تم تجميعه بدون حقوق).

### التمييز بين A1/A2: قابلية الاستبدال

تستدعي معظم الطرق النماذج اللغوية الكبيرة (LLMs). لا تتظاهر الشبكة (Network) بخلاف ذلك — لكنها تميز بين نوعين مختلفين تماماً من تبعية واجهة برمجة التطبيقات (API):

- **A1 (قابلة للاستبدال):** توفر واجهة برمجة التطبيقات (API) استدلالاً لنموذج لغوي كبير (LLM) كسلعة. معرف النموذج هو تكوين: يجب أن تعمل الطريقة من البداية إلى النهاية مقابل أي نقطة نهاية استدلال متوافقة، بما في ذلك نموذج مفتوح الأوزان مستضاف من قبل المجتمع. قد تختلف جودة المخرجات عبر النماذج — هذه هي مخاطرة المطور، وترتبط الدرجات الرسمية بالنموذج المثبت المستخدم في التقييم. الطريقة التي تعتمد على **حالة من جانب المزود** (ضبط دقيق مستضاف فقط لدى المزود، مخازن ملفات المزود، مساعدين خاصين بالمزود) هي *غير* قابلة للاستبدال: لا يمكن إخراج هذه الحالة، لذا فإن التبعية هي A2 ما لم يتم تضمين الأوزان أو البيانات الأساسية في التقديم.
- **A2 (غير قابلة للاستبدال):** تخدم واجهة برمجة التطبيقات (API) شيئاً فريداً — عادةً بيانات مملوكة أو غير مرخصة. لا يمكن لأي نقطة نهاية بديلة توفيرها، ولا يمكن عكس المحتوى في البيئة المعزولة دون إذن صاحب الحقوق. تعمل الطريقة على لوحة الصدارة المفتوحة (مع وضع علامة عليها)، ولكن لا يمكنها إنتاج درجات رسمية للبيئة المعزولة أو التأهل للجوائز حتى تتوفر الأذونات.

**ما ينقله نقل جائزة A1 فعلياً.** لا يتلقى المجتمع النموذج — لا يمكن لأحد نقل أوزان Anthropic أو Google أو OpenAI. يغطي النقل الوصفة الكاملة *حول* النموذج: جميع الموجهات، وبيانات التوجيه، ورمز مسار العمل، ومنطق إعادة المحاولة، والتكوين، ومتطلبات النموذج الموثقة. نظراً لأن النموذج قابل للاستبدال بحكم تصميمه، يمكن للمجتمع توجيه الطريقة المنقولة إلى أي مزود يختارونه — أو إلى نموذج مفتوح الأوزان على أجهزتهم الخاصة — دون تدخل المطور. الوصفة مملوكة؛ والمحرك مستأجر وقابل للاستبدال.

### بيان التبعية (`method.json`)

تعلن كل طريقة عن تبعياتها في بيان `method.json`. يسجل كل إدخال ماهية العنصر، ومن أين يأتي، وما هو الترخيص الذي يغطيه، وكيف تصل الطريقة إليه:

```json
{
  "name": "FST-Gated Coached Translation v8",
  "method_id": "fst-gated-v8",
  "class": "pipeline",
  "paradigm": "hybrid",
  "entry_point": "pipeline:PipelineMethod",
  "supported_pairs": ["eng>crk"],
  "dependency_class": "A2",
  "dependencies": [
    {
      "id": "giellalt-lang-crk-fst",
      "kind": "software",
      "license": "AGPL-3.0-or-later",
      "access": "mirrored",
      "source": "https://github.com/giellalt/lang-crk",
      "pin": "sha256:3f1a…",
      "redistributable": true,
      "transferable": true
    },
    {
      "id": "llm-inference",
      "kind": "model",
      "license": "proprietary",
      "access": "gateway",
      "source": "openrouter:google/gemini-2.5-flash",
      "substitutable": true,
      "redistributable": false,
      "transferable": false,
      "notes": "Any compatible chat-completions endpoint works; the model slug is configuration."
    },
    {
      "id": "crk-dictionary-api",
      "kind": "service",
      "license": "none",
      "access": "external-api",
      "source": "https://itwewina.altlab.app/",
      "redistributable": false,
      "transferable": false,
      "notes": "Dictionary content has no public license; runtime lookups only. Class A2 until the rights holders grant permission."
    }
  ]
}
```

| الحقل | مطلوب | الوصف |
|-------|----------|-------------|
| `id` | ✅ | معرف ثابت للتبعية |
| `kind` | ✅ | `data`، `model`، `software`، أو `service` |
| `license` | ✅ | معرف SPDX، `proprietary`، أو `none`. `none` يعني عدم وجود ترخيص عام — يُعامل على أنه جميع الحقوق محفوظة |
| `access` | ✅ | `bundled` (يُشحن في دليل الطريقة)، `mirrored` (يتم جلبه عند التثبيت، وتثبيته، وتضمينه في التقديم)، `gateway` (استدلال LLM في وقت التشغيل عبر بوابة التقييم)، `external-api` (أي استدعاء شبكة آخر في وقت التشغيل) |
| `source` | ✅ | عنوان URL أساسي أو معرف `provider:slug` |
| `pin` | لـ `mirrored` | الإصدار، أو الالتزام (commit)، أو تجزئة المحتوى (content hash) التي تثبت العنصر الدقيق |
| `substitutable` | لـ `gateway`/`external-api` | ما إذا كانت أي نقطة نهاية متوافقة يمكنها خدمة هذه التبعية |
| `redistributable` | ✅ | ما إذا كان الترخيص يسمح بإعادة توزيع العنصر |
| `transferable` | ✅ | ما إذا كان العنصر (أو حقوقه) يمكن نقله إلى مجتمع بموجب شروط نقل الجائزة |
| `notes` | ❌ | سياق حر |

**اشتقاق الفئة.** تساهم كل تبعية بفئة؛ `dependency_class` الخاص بالطريقة هو الأكثر تقييداً:

| ملف تعريف التبعية | يساهم بـ |
|--------------------|-------------|
| `bundled` + الترخيص يسمح بإعادة التوزيع والنقل | S |
| `mirrored` + ترخيص مفتوح يسمح بإعادة التوزيع (بما في ذلك الحقوق المتروكة) | O |
| `gateway` + `substitutable: true` (استدلال LLM) | A1 |
| `external-api`، أو `gateway` مع `substitutable: false` | A2 |
| `bundled` + `license: none` أو ترخيص غير متوافق مع إعادة التوزيع | X |

يجب أن يتطابق `dependency_class` المعلن مع الفئة التي تستمدها أداة التقييم من البيان. عدم التطابق يعد خطأ في التحقق.

تعلن الطريقة التي **ليس** لها تبعيات خارجية عن `"dependency_class": "S"` و `"dependencies": []`. المصفوفة الفارغة هي بيان إيجابي، يتم تدقيقه مثل أي بيان آخر.

### كيفية التحقق من الصلاحية

ثلاث طبقات، من الأقل تكلفة إلى الأكثر موثوقية:

1. **تدقيق البيان.** تستمد أداة التقييم الفئة الفعالة من البيان وترفض حالات عدم التطابق. يتحقق المراجعون من كل تبعية معلنة مقابل ترخيصها ومصدرها المذكورين — التبعية المعلنة كـ `redistributable: true` والتي ينص ترخيصها الأصلي على خلاف ذلك تفشل في المراجعة.
2. **التحليل الثابت.** يتم فحص التعليمات البرمجية المقدمة بحثاً عن استدعاءات الشبكة، والتنزيلات الديناميكية، والوصول إلى نظام الملفات التي لا يفسرها البيان. التبعية *غير المعلنة* التي يتم العثور عليها في المراجعة هي سبب للرفض بغض النظر عن الفئة التي كانت ستكون عليها — يجب أن يكون البيان كاملاً، وليس دقيقاً فقط.
3. **سياسة شبكة البيئة المعزولة.** تتطلب مواصفات البيئة المعزولة **رفض الخروج الافتراضي** (default-deny egress): لا تحصل حاويات الطريقة على وصول إلى الشبكة ما لم يتم إدراج مسار صراحةً في قائمة السماح. مسار الخروج الوحيد الذي تحدده المواصفات هو **بوابة LLM** — وكيل استدلال (inference proxy) يتم تشغيله بواسطة البنية التحتية للتقييم، ويقتصر على قائمة سماح صريحة للنماذج المثبتة، مع تسجيل كل طلب واستجابة لتدقيق ما بعد التشغيل. أي شيء غير موجود في قائمة السماح يفشل في طبقة الشبكة، وليس في طبقة السياسة. راجع [مواصفات المعيار المرجعي §8.6](/docs/network/specifications/benchmark) للتعرف على سياسة الشبكة وتصميم البوابة.

> **بيئتان معزولتان مختلفتان — واحدة مخططة، وواحدة حية.** اقرأ هذا بعناية، لأن كلمة "بيئة معزولة" (sandbox) تغطي شيئين متميزين:
>
> - 🔲 **مخطط لها: البيئة المعزولة للمنصة وبوابة LLM الخاصة بها.** البيئة التي تديرها البنية التحتية للتقييم والموصوفة في هذا القسم — تلك التي ستسمح بوابة LLM الخاصة بها لطرق الفئة A1 بإنتاج درجات رسمية ذات معيار ذهبي — محددة ولكن لم يتم بناؤها بعد. حتى يتم ذلك، فإن طرق الفئة A1 مؤهلة للجوائز *من حيث المبدأ* ولكن لا يمكنها بعد إنتاج درجات رسمية ذات معيار ذهبي.
> - ✅ **حية: مسار تنفيذ الطريقة لعقدة المنظم.** تقوم عقدة تسجيل النقاط الخاصة بمنظم المسابقة بالفعل بتنفيذ حزم الطرق المقترحة داخل حاوية معزولة عن الشبكة (`mt-eval node run-method`): مبنية ومشغلة بـ `--network=none`، وجذر للقراءة فقط، وتبعيات مضمنة (vendored) — مما يقصرها على الطرق التي لا تحتاج إلى شبكة في وقت التشغيل (الفئة S/O بحكم التصميم). يمكن تشغيلها على جهاز معزول تماماً عن الشبكة (true-airgap) مع عبور حزم الدرجات الموقعة فقط عبر وسائط قابلة للإزالة. راجع [تشغيل مسابقة سيادية](/docs/network/sovereignty/run-a-sovereign-contest) للحصول على المسار من البداية إلى النهاية.
>
> يصف هذا القسم ما تتطلبه مواصفات المنصة، وليس ما يعمل حالياً على المنصة.

### عرض لوحة الصدارة

- تعرض لوحة الصدارة فئة التبعية لكل طريقة بجانب شارة فئة الطريقة الخاصة بها.
- تحمل طرق الفئة A2 في لوحة الصدارة المفتوحة علامة **"تبعية خارجية"** مرئية: تعتمد درجاتها على خدمة تابعة لجهة خارجية قد تتغير أو تختفي، وهي غير مؤهلة حالياً للجوائز.
- طرق الفئة X غير مدرجة.

## أداة التقييم: بروتوكول TranslationMethod {#eval-harness-translationmethod-protocol}

تستخدم أداة التقييم الكتابة الهيكلية (structural typing) في Python (`Protocol`) للمكونات الإضافية. أي فئة تحتوي على الأعضاء الصحيحين تعمل — لا يلزم الوراثة. يحتوي البروتوكول على **ثلاثة** أعضاء مطلوبين، وليس فقط `translate`:

1. **`name`** (`str`) — اسم طريقة قابل للقراءة بشرياً، يُستخدم في معرفات التشغيل والسجلات.
2. **`method_card()`** (`-> dict | None`) — البيانات الوصفية للطريقة لتتبع المصدر، مضمنة في سجل التشغيل وبطاقة التشغيل المنشورة. أرجع `None` إذا لم يكن للطريقة بطاقة.
3. **`async translate(entries, config)`** (`-> list[dict]`) — الترجمة نفسها: دفعة من الإدخالات كمدخلات، وقاموس نتيجة واحد لكل إدخال كمخرجات.

عندما تقوم أداة التقييم بتحميل مكون إضافي عبر `--method path/to/dir`، فإنها تتحقق من أن `translate` قابل للاستدعاء ثم تقرأ `method.name` وتستدعي `method.method_card()` دون قيد أو شرط — المكون الإضافي الذي يفتقر إلى أي منهما سيتعطل في وقت التحميل، ولن يفشل بسلاسة.

```python
class MyMethod:
    name = "My Pipeline v1"  # required — run IDs and logs

    def method_card(self) -> dict | None:
        # required — provenance metadata (or None for no card)
        return {
            "method_id": "my-pipeline-v1",
            "name": self.name,
            "class": "pipeline",
        }

    async def translate(self, entries: list[dict], config: RunConfig) -> list[dict]:
        results = []
        for entry in entries:
            translation = await self.do_translation(entry["source"])
            results.append({
                "id": entry["id"],
                "predicted": translation,
                "latency_s": 0.5,
                "usage": {"prompt_tokens": 0, "completion_tokens": 0},
                "error": None,
                "tool_calls": [],
                "tool_call_count": 0,
                "metadata": {},
            })
        return results
```

يحتاج دليل المكون الإضافي إلى بيان `method.json` مع `name` و `entry_point` على الأقل (`"module_name:ClassName"` — يتم تحميل الوحدة من دليل المكون الإضافي ويتم إنشاء مثيل للفئة). إذا أعلنت بطاقة الطريقة المرجعة عن `class` أو `paradigm`، فيجب أن تستخدم المفردات الأساسية أعلاه — البطاقة الخارجة عن التصنيف تفشل في التحقق في وقت التحميل بدلاً من السقوط بصمت من فلاتر لوحة الصدارة.

للحصول على مثال عملي كامل — بناء وتشغيل وتقديم مكون إضافي من البداية إلى النهاية — راجع [تقديم طريقة](/docs/network/getting-started/submit-a-method) و [دليل مسار العمل المقيد بـ FST](/docs/network/tutorials/fst-gated-pipeline).

## Champollion: تكوين methodPlugin

في Champollion، يتم تسجيل الطرق لكل زوج لغوي في `champollion.config.json`:

```json
{
  "version": 3,
  "pairs": {
    "en:crk": {
      "methodPlugin": "crk-coached-v1"
    }
  }
}
```

راجع [مواصفات المكون الإضافي](https://champollion.dev/docs/reference/plugin-spec) للحصول على الواجهة من جانب Champollion.

## تكامل لوحة الصدارة

عند إرفاق بطاقة طريقة بتشغيل (عبر `--method-card`)، يتم تضمينها في بطاقة التشغيل وعرضها على لوحة الصدارة:

```bash
# Run with method card attached
mt-eval run \
  --method path/to/my-method \
  --corpus eval-amh-fra-globalvoices-test-v1 \
  --method-card method_card.json

# Publish to the leaderboard
mt-eval publish eval/logs/harness/your-run-card.json
```

إذا لم يتم توفير `--method-card`، يقوم `mt-eval publish` بتشغيل معالج تفاعلي يرشدك خلال وصف طريقتك.

تعرض لوحة الصدارة:
- **شارة الفئة** — مؤشر مرئي (مثل "مسار عمل"، "نموذج لغوي كبير موجه")
- **النموذج** — النموذج الخوارزمي (مثل "قائم على القواعد"، "ترجمة آلية عصبية"، "نموذج لغوي كبير"، "هجين")، وهو عمود قابل للفلترة (راجع [النماذج](#paradigms))
- **فئة التبعية** — S/O/A1/A2 (راجع [صلاحية الطريقة وفئات التبعية](#method-validity-and-dependency-classes))؛ تحمل طرق A2 علامة "تبعية خارجية"
- **اسم الطريقة** — من بطاقة الطريقة
- **الأدوات المستخدمة** — مدرجة من بطاقة الطريقة
- **مؤشر مفتوح المصدر**

عند عدم إرفاق بطاقة طريقة، تعرض لوحة الصدارة التكوين الأصلي لأداة التقييم (النموذج، إصدار الموجه، درجة الحرارة، الأدوات الممكنة).

:::danger[لا تتدرب على بيانات التقييم]
الطرق التي تضمنت عملية تطويرها التعرض لمجموعة بيانات التقييم — كبيانات تدريب، أو أمثلة قليلة اللقطات (few-shot)، أو إدخالات قاموس، أو مواد ضبط الموجه — سيتم **استبعادها** من لوحة الصدارة. راجع [تقييم الترجمة الآلية](/docs/network/leaderboard/rules) لمعرفة ما يميز الطريقة الجيدة عن السيئة.
:::
