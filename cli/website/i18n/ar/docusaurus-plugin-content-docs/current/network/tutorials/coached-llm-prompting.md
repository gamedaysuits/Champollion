# التوجيه الإرشادي لـ LLM

> **الفكرة:** حقن قواعد النحو، والقواميس ثنائية اللغة، وملاحظات الأسلوب مباشرةً في موجه النظام (system prompt) الخاص بـ LLM. دون أي تدريب، ودون ضبط دقيق (fine-tuning) — مجرد معرفة لغوية مهيكلة توجّه المخرجات نحو ترجمات صحيحة.

:::info[هذا دليل إرشادي تطبيقي (Cookbook)، وليس تطبيقًا نهائيًا]
يستعرض هذا الدليل النهج وأبرز القرارات التصميمية الخاصة به. قم بتكييفه ليناسب زوج اللغات لديك، والموارد المتاحة، وأهداف التقييم.
:::

## حالات الاستخدام

- لديك **معرفة لغوية** باللغة الهدف (قواعد نحوية، مدخلات قاموس، تفضيلات أسلوبية) ولكنك لا تملك بيانات موازية كافية للضبط الدقيق
- ترغب في **التكرار السريع** — تُطبَّق تغييرات الموجهات في ثوانٍ، دون الحاجة لإعادة التدريب
- تحتوي اللغة الهدف على **أنماط معروفة** يخطئ فيها LLM (مطابقة الجنس، معايير نظام الكتابة، مستويات الرسمية)
- ترغب في مقارنة أداء التوجيه الإرشادي مقابل خط أساس (baseline) والتطوير المستمر بناءً على ما ينجح

## كيف تعمل

1. **تجميع بيانات الإرشاد** — قواعد نحوية، وقاموس ثنائي اللغة، وملاحظات أسلوبية في ملف JSON مهيكل
2. **تكوين السجل اللغوي (register)** — بادئة لموجه النظام تحدد اللغة ونظام الكتابة والنبرة
3. **تشغيل أداة التقييم (harness)** — تُحقَن بيانات الإرشاد في كل موجه لـ LLM
4. **مراجعة حالات الفشل** — فحص ما ترفضه بوابة الجودة (quality gate)، وإضافة قواعد لمعالجة هذه الأنماط
5. **التكرار والتحسين** — كل تعديل على ملف الإرشاد يمثل تجربة جديدة؛ وتقوم أداة التقييم بتتبعها جميعًا

## بنية بيانات الإرشاد

```json title="coaching/<locale>.json"
{
  "grammar_rules": [
    "Adjectives agree in gender and number with the noun they modify",
    "Use formal register (vous) for all UI text",
    "Preserve interpolation variables exactly: {{name}}, {count}"
  ],
  "dictionary": {
    "dashboard": "tableau de bord",
    "settings": "paramètres",
    "deploy": "déployer"
  },
  "style_notes": "Prefer active voice. Avoid anglicisms where a native term exists. Keep sentences concise for UI readability."
}
```

يرسل `mt-eval run --coaching-file` النص الكامل للملف إلى النموذج كما كُتب تمامًا، وبالتالي يمكن لملف بتنسيق Markdown أو نص عادي (plain-text) أن يؤدي دور الإرشاد أيضًا. يضيف تنسيق JSON الموضح أعلاه أمرًا واحدًا: عند عدم تحديد `--glossary`، يكون `dictionary` الخاص به بمثابة المسرد لمقياس **الالتزام بالمصطلحات** (terminology adherence)، الذي يتحقق، لكل مصطلح قاموس موجود في الجملة المصدر، مما إذا كانت ترجمته تظهر في المخرجات (قد يرتبط المصطلح بترجمة واحدة أو بقائمة من الترجمات المقبولة). يؤدي ذلك إلى تقييم دورة التشغيل بالاستناد إلى إرشاداتها الخاصة، لذا لمقارنة دورة تشغيل مدعومة بالإرشاد مع دورة أخرى غير مدعومة به، مرّر قائمة المصطلحات نفسها لكلتيهما باستخدام `--glossary terms.json`. يُستخدم هذا فقط للتقييم ولا يُرسل إطلاقًا إلى النموذج. وفي حال عدم وجود أي منهما، يظل المقياس غير نشط.

## القرارات التصميمية الرئيسية

**خصوصية القواعد مقابل نافذة السياق:** توفر القواعد الأكثر إرشادًا أوسع لـ LLM، ولكنها تستهلك من نافذة السياق (context window) المتاحة للترجمة الفعلية. ابدأ بـ 5 إلى 10 قواعد عالية التأثير، ولا تضف المزيد إلا عندما تلاحظ أنماط فشل محددة.

**تغطية القاموس:** لا تحتاج إلى قاموس كامل — ركّز على المصطلحات التي يخطئ فيها LLM باستمرار. حتى مع وجود 20 إلى 30 مصطلحًا إلزاميًا فقط، يمكن تحسين الاتساق بشكل كبير.

**ترتيب القواعد مهم:** ضع القواعد الأكثر أهمية أولًا. تولي نماذج LLM اهتمامًا أكبر للتعليمات الأولى في السياق.

## تشغيل تجربة

```bash
mt-eval run \
  --corpus eval-amh-fra-globalvoices-test-v1 \
  --model google/gemini-2.5-pro \
  --name coached-v1 \
  --coaching-file coaching/crk.json
```

## الإيجابيات والسلبيات

| | |
|---|---|
| ✅ انعدام تكاليف التدريب | ❌ سقف الجودة محدود بالمعرفة الأساسية لـ LLM |
| ✅ تكرار فوري (تعديل الموجه ← إعادة التشغيل) | ❌ نافذة السياق تحدّ من حجم الإرشاد الذي يمكن تضمينه |
| ✅ يعمل مع أي مزود لـ LLM | ❌ احتمالية تعارض القواعد — استكشاف أخطاء التفاعلات بين الموجهات فنٌّ بحد ذاته |
| ✅ شفاف تمامًا — يمكنك قراءة ما يراه LLM بالضبط | ❌ لا ينشئ معرفة جديدة، بل يوجّه المعرفة الموجودة فحسب |
