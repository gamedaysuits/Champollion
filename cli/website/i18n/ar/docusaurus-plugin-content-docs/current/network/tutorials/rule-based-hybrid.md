# هجين قائم على القواعد + LLM

> **الفكرة:** استخدام قواعد لغوية حتمية للأنماط التي تتيقن من صحتها (الإلحاق الصرفي، تنسيق الأرقام، تراكيب العبارات المعروفة)، وترك الترجمة الإبداعية للنموذج اللغوي الكبير (LLM) فيما عدا ذلك. تتفوق القواعد على LLM في مواضع تطبيقها؛ بينما يسد LLM الفجوات.

:::info[هذا دليل عملي (Cookbook)، وليس تنفيذاً نهائياً]
يستعرض هذا الدليل البنية الهجينة. تعتمد القواعد المحددة كلياً على قواعد اللغة المستهدفة والموارد اللغوية المتاحة.
:::

## متى تستخدم هذا النهج

- لديك **خبرة لغوية متعمقة** في اللغة المستهدفة (أو يمكنك الاستعانة بخبير لغوي)
- بعض أنماط الترجمة **حتمية** — حيث تعرف المخرجات الصحيحة بكل يقين
- يفشل LLM **باستمرار** في أنماط محددة (تنسيق الأرقام، الألقاب التشريفية، الإلصاق الصرفي)
- ترغب في **ضمان صحة** الأنماط بالغة الأهمية مع الحفاظ على سلاسة الصياغة في بقية النص

## كيف تعمل

```
Input ──→ [Rule Engine] ──→ [LLM] ──→ [Merge] ──→ Output
              │                │           │
              │ Known patterns │ Unknown    │ Rules override
              │ handled here   │ parts      │ LLM where both
              ▼                ▼            ▼ produced output
         Deterministic     Creative     Final translation
         fragments         translation
```

1. **تحديد القواعد** — أنماط التعبيرات النمطية (regex)، وعمليات بحث FST، وجداول البحث للترجمات المعروفة
2. **المعالجة المسبقة** — تحديد واستخراج المقاطع المطابقة للقواعد من المصدر
3. **ترجمة LLM** — النص المتبقي، مع اعتبار مخرجات القواعد كقيود
4. **الدمج** — إعادة تجميع الترجمة، مع تفضيل مخرجات القواعد حيثما توفرت
5. **التحقق** — فحص اختياري باستخدام FST/القواعد على النتيجة المدمجة

## مثال: قواعد الأرقام والتواريخ

```python
import re

# Rule: Numbers stay as-is (don't let the LLM hallucinate number translations)
def rule_preserve_numbers(text):
    return re.sub(r'\b\d+\b', lambda m: f'__NUM_{m.group()}__', text)

# Rule: Known greetings have exact translations
GREETING_RULES = {
    "hello": "tânisi",
```

## قرارات التصميم الرئيسية

**أولوية القواعد:** عندما تُنتج كل من القاعدة وLLM مخرجات لنفس المقطع، أيهما يُعتمد؟ يجب أن تُعتمد القواعد في الأنماط **التي تعتمد على الدقة والصحة**. بينما يجب أن يُعتمد LLM في الأنماط **التي تعتمد على سلاسة الصياغة**.

**مستوى التفصيل:** قواعد على مستوى الكلمة (البحث في القاموس) مقابل قواعد على مستوى العبارة (مطابقة التعابير الاصطلاحية) مقابل قواعد هيكلية (إعادة ترتيب الجمل). ابدأ بمستوى الكلمة؛ ثم أضف مستوى العبارة كلما تمكنت من تحديد الأنماط.

**صيانة القواعد:** كل قاعدة تمثل التزاماً بالصيانة. يُفضل استخدام مجموعة صغيرة من القواعد الموثوقة للغاية بدلاً من مجموعة كبيرة من القواعد التقريبية. إذا لم تكن متأكداً من صحة قاعدة ما، فاترك الأمر لـ LLM.

## الإيجابيات والسلبيات

| | |
|---|---|
| ✅ ضمان الصحة حيثما تنطبق القواعد | ❌ يتطلب خبرة لغوية متعمقة |
| ✅ الشفافية — القواعد قابلة للقراءة والتدقيق | ❌ يمكن أن ينتج عن التداخل بين القاعدة وLLM مخرجات غير طبيعية |
| ✅ القواعد سريعة (بدون تكلفة API) | ❌ يزداد عبء الصيانة مع زيادة عدد القواعد |
| ✅ تدريجي — أضف القواعد كلما تعلمت | ❌ صعوبة التعامل مع التصريف عند حدود القواعد |
