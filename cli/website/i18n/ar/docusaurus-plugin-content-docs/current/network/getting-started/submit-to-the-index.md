# الإرسال إلى الفهرس

> **ملخص تنفيذي.** اقترح شيئًا لفهرس Champollion — معيار تقييم، أو مورد، أو طريقة ترجمة، أو خدمة ترجمة بشرية، أو نتيجة خارجية منشورة. تقوم بملء نموذج منظم قصير (في متصفحك أو من واجهة سطر الأوامر CLI)؛ **يقوم أحد المشرفين بمراجعة كل إرسال يدويًا** للتحقق من الامتثال للملكية الفكرية، والترخيص، والمجتمع/السيادة قبل إضافة أي شيء. **لا تتم الموافقة على أي شيء تلقائيًا.**

الفهرس هو الخريطة المشتركة: مجموعات البيانات التي يتم تقييم الطرق بناءً عليها، والقواميس والأدوات المساعدة، والطرق نفسها، والأشخاص الذين يترجمون يدويًا، والنتائج التي نشرها الآخرون. يمكن لأي شخص اقتراح إضافة. ولأن هذه بنية تحتية للمجتمعات اللغوية، يمر كل اقتراح عبر بوابة مراجعة بشرية أولاً.

## ما يمكنك إرساله

| النوع | ما هو | ما نضيفه |
|---|---|---|
| **معيار تقييم / مجموعة بيانات** | مدونة تقييم أو معيار تقييم | بطاقة بيانات وصفية + مؤشر *جلب من المصدر* — لا نضيف محتوى المدونة أبدًا |
| **مورد** | قاموس، أو أرشيف، أو تطبيق، أو FST (محلل صرفي)، أو أداة | إدراج مع مؤشر + مستوى الوصول (مفتوح / مقيد / يتطلب الموافقة) |
| **طريقة ترجمة** | محرك ترجمة آلية (MT)، أو مزود نماذج لغوية كبيرة (LLM)، أو مسار معالجة | إدخال في سجل الطرق بحيث يمكن تشغيله وتقييمه |
| **خدمة ترجمة بشرية** | مكتب مجتمعي اختياري، أو وكالة، أو مترجم فردي | إدراج لكل زوج لغوي (تبقى تفاصيل الاتصال خارج النطاق العام — ولا تُنشر أبدًا في المشكلة العامة) |
| **نتيجة خارجية منشورة** | نتيجة أبلغ عنها نظام آخر أو ورقة بحثية | **استشهاد** — يتم الاستشهاد بالنتائج الخارجية، ولا يتم إعادة استضافتها أو إعادة تصنيفها كقياس خاص بنا أبدًا |
| **تصحيح بطاقة لغة** | شيء ما في [بطاقة اللغة](/catalogue) خاطئ، أو قديم، أو مفقود — تقدير لعدد المتحدثين، أو حالة، أو نظام كتابة، أو مورد لم نقم بإدراجه | **إصلاح مستشهد به يُطبق في مصدر البيانات** (يتم إنشاء البطاقات، لذا يظل التصحيح ثابتًا)؛ عندما تختلف المصادر، تعرض البطاقة جميع المصادر مع نسبتها لأصحابها |

تحمل كل بطاقة لغة أيضًا رابط **"اقتراح تصحيح أو إضافة"**
والذي يفتح نموذج التصحيح مع ملء حقل اللغة مسبقًا.

**طلبات الإزالة والتقييد من المجتمع.** إذا كنت عضوًا في المجتمع
أو جهة مسؤولة وترغب في تقييد أو إزالة بيانات حول لغتك، فاستخدم
نموذج التصحيح (أو اتصل بالمشرف خارج النطاق العام إذا كنت تفضل ألا يكون ذلك
علنيًا). تمر هذه الطلبات عبر [مراجعة السيادة](/docs/network/sovereignty/data-sovereignty)
بأولوية — ولا يُشترط تقديم استشهاد.

## كيف تعمل المراجعة

هذا هو الجزء المهم: **تتم مراجعة الإرسالات بواسطة إنسان، وليس روبوتًا.** عندما ترسل، فإنك تفتح مشكلة (issue) على GitHub. هذه المشكلة هي قائمة انتظار المراجعة. يقرأها أحد المشرفين ويتحقق منها مقابل قواعد المشروع قبل إضافة أي شيء:

- **الملكية الفكرية والترخيص.** يجب أن يُسمح لنا بإدراجه. لا يزال من الممكن *فهرسة* المواد غير التجارية، أو التي لا يُسمح بإعادة توزيعها، أو ذات الترخيص غير الواضح، ولكن يتم حظرها من أي مسار تجاري / جائزة / جلب عام.
- **المجتمع والسيادة.** تُدرج بيانات لغات الشعوب الأصلية والمجتمعات فقط بموافقة المجتمع. لا يتم أبدًا تسمية المزود أو الوصي علنًا قبل تأكيدهم.
- **لا نستضيف محتوى المدونات أبدًا.** تُدرج مجموعات البيانات كبيانات وصفية بالإضافة إلى مؤشر لمكان جلب البيانات منه. **لا تلصق الجمل المصدرية/المرجعية في الإرسال.**
- **لا توجد بيانات شخصية.** لا توجد رسائل بريد إلكتروني، أو أرقام هواتف، أو معلومات تعريف شخصية (PII) أخرى في مشكلة عامة. بالنسبة لخدمات الترجمة البشرية، يتم تزويد المشرف بتفاصيل الاتصال خارج النطاق العام.
- **النطاق.** المدونات الكتابية / الليتورجية وغيرها من المدونات المفروضة استعماريًا تقع خارج النطاق وسيتم رفضها.

ينتهي كل نموذج بإقرار مطلوب:

> *"أؤكد أن هذا قابل للإدراج علنًا، ولا يحتوي على أي محتوى مدونة أو بيانات شخصية، ويحترم ترخيص المصدر وأي قيود مجتمعية/سيادية."*

## طريقتان للإرسال

### من متصفحك

افتح منتقي المشكلات (issue chooser) واختر النموذج الذي يطابق ما ترسله:

➡️ **[افتح نموذج إرسال على GitHub](https://github.com/gamedaysuits/Champollion/issues/new/choose)**

يطلب كل نموذج فقط ما يحتاجه الفهرس المطابق (الاسم، اللغات/الأزواج، الترخيص، عنوان URL للمصدر، وما إلى ذلك) ومربع اختيار الإقرار.

### من واجهة سطر الأوامر (CLI)

إذا كان لديك [واجهة سطر أوامر champollion](/docs/network/getting-started/submit-a-method)، فإن `champollion submit` يجمع الحقول ويقدم لك نسخة **معبأة مسبقًا** من نفس نموذج GitHub:

```bash
# Interactive — pick a type and answer the prompts
champollion submit

# See the submission types
champollion submit --list

# Fully scripted (prints a pre-filled GitHub issue URL)
champollion submit --yes --type dataset --attest \
  --field dataset-name="GlobalVoices eng-amh" \
  --field pairs=eng-amh \
  --field license=CC-BY-4.0 \
  --field source-url=https://globalvoices.org
```

تطبع واجهة سطر الأوامر (CLI) عنوان URL — افتحه، وراجع الإقرار في المتصفح، ثم أرسل. أضف `--out submission.json` لحفظ نسخة محلية خالية من المحتوى لما تقترحه أيضًا. لا تقوم واجهة سطر الأوامر أبدًا بتحميل أي شيء بنفسها ولا تكتب أبدًا في الفهرس.

## ماذا يحدث بعد الإرسال

1. يصل إرسالك كمشكلة (issue) على GitHub — قائمة انتظار المراجعة.
2. يراجعه أحد المشرفين مقابل قواعد الملكية الفكرية / الترخيص / السيادة المذكورة أعلاه.
3. **إذا تم القبول:** يضيف المشرف الإدخال إلى مصدر الحقيقة ذي الصلة (سجل مجموعة البيانات، أو بطاقة، أو سجل الطريقة أو الخدمة البشرية، أو كتالوج النتائج الخارجية) من خلال تغيير عادي، ويصنف المشكلة بعلامة **accepted** (مقبول).
4. **إذا لم يكن من الممكن إدراجه كما هو:** يصنف المشرف المشكلة بعلامة **declined** (مرفوض) (أو يطلب المزيد من المعلومات) مع ذكر السبب.

لا يوجد دمج تلقائي ولا نشر تلقائي. يتخذ شخص ما القرار في كل مرة.
