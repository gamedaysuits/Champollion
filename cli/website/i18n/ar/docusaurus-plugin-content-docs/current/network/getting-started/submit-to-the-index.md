# الإرسال إلى الفهرس

> **ملخص تنفيذي.** اقترح إضافة إلى فهرس Champollion — سواء أكان معيار تقييم (benchmark)، أو موردًا، أو طريقة ترجمة، أو خدمة ترجمة بشرية، أو نتيجة منشورة خارجيًا. تقوم بملء نموذج منظم وقصير (في متصفحك أو عبر CLI)؛ ويقوم **أحد المشرفين بمراجعة كل طلب يدويًا** للتحقق من حقوق الملكية الفكرية والترخيص والامتثال لمتطلبات المجتمع والسيادة اللغوية قبل إضافة أي شيء. **لا تتم الموافقة على أي شيء تلقائيًا.**

يمثل الفهرس الخريطة المشتركة: مجموعات البيانات التي تُقاس الطرق بناءً عليها، والقواميس والأدوات المساعدة، والطرق نفسها، والأشخاص الذين يترجمون يدويًا، والنتائج التي نشرها الآخرون. يمكن لأي شخص اقتراح إضافة. ونظرًا لأن هذه بنية تحتية مخصصة للمجتمعات اللغوية، فإن كل مقترح يمر عبر مرحلة مراجعة بشرية أولاً.

---

## ما يمكنك إرساله

| النوع | ما هو | ما نضيفه |
|---|---|---|
| **معيار تقييم / مجموعة بيانات** | مدونة تقييم أو معيار قياس | بطاقة بيانات وصفية (metadata) + مؤشر *جلب من المصدر* — دون استضافة محتوى المدونة مطلقًا |
| **مورد** | قاموس، أو أرشيف، أو تطبيق، أو محول ذو حالات محدودة FST (محلل صرفي)، أو أداة | إدراج يتضمن مؤشرًا + مستوى الوصول (مفتوح / مقيد / يتطلب موافقة) |
| **طريقة ترجمة** | محرك ترجمة آلية (MT)، أو مزود نماذج لغوية كبيرة (LLM)، أو مسار معالجة (pipeline) | مدخل في سجل الطرق ليتسنى تشغيلها وتقييمها |
| **خدمة ترجمة بشرية** | مكتب مجتمعي، أو وكالة، أو مترجم فردي (باشتراك اختياري) | إدراج مخصص لكل زوج لغوي (تبقى تفاصيل الاتصال خارج القنوات العامة — ولا تُنشر إطلاقًا في البلاغ العام) |
| **نتيجة منشورة خارجيًا** | درجة أو نتيجة أبلغ عنها نظام آخر أو ورقة بحثية | **استشهاد مرجعي** — يتم الاستشهاد بالنتائج الخارجية دون إعادة استضافتها أو إعادة تصنيفها كقياس خاص بنا مطلقًا |
| **تصحيح بطاقة لغة** | وجود خطأ أو معلومة قديمة أو ناقصة في [بطاقة لغة](/catalogue) — مثل تقدير عدد المتحدثين، أو الحالة، أو نظام الكتابة، أو مورد لم نقم بإدراجه | **تصحيح موثق يُطبق على مصدر البيانات مباشرة** (تُولَّد البطاقات تلقائيًا، وبذلك يثبت التصحيح)؛ وعند اختلاف المصادر، تعرض البطاقة جميعها مع نسبتها لأصحابها |

تحتوي كل بطاقة لغة أيضًا على رابط **"اقتراح تصحيح أو إضافة"**
يفتح نموذج التصحيح مع تعبئة اسم اللغة مسبقًا.

**طلبات المجتمع للحذف والتقييد.** إذا كنت فردًا من المجتمع المحلي
أو جهة مسؤولة وترغب في تقييد أو إزالة بيانات متعلقة بلغتك، فيرجى استخدام
نموذج التصحيح (أو التواصل مع المشرف عبر قناة خاصة إذا كنت تفضل ألا يكون
الأمر علنيًا). تخضع هذه الطلبات لـ [مراجعة السيادة اللغوية](/docs/network/sovereignty/data-sovereignty)
بأولوية قصوى — دون الحاجة لأي استشهاد مرجعي.

## آلية المراجعة

هذا هو الجزء الأهم: **تتم مراجعة الطلبات من قِبل إنسان، وليس روبوتًا.** عند الإرسال، تقوم بفتح بلاغ (Issue) على GitHub، ويمثل هذا البلاغ قائمة انتظار المراجعة. يقرأه أحد المشرفين ويفحصه وفقًا لقواعد المشروع قبل إضافة أي شيء:

- **الملكية الفكرية والترخيص.** يجب أن نكون مخولين بإدراجه. المواد غير التجارية، أو التي تحظر إعادة التوزيع، أو غير واضحة الترخيص يمكن *فهرستها*، ولكنها تُستبعد تمامًا من أي مسار تجاري / جوائز / جلب عام.
- **المجتمع والسيادة.** لا تُدرج بيانات لغات المجتمعات والشعوب الأصلية إلا بموافقة مجتمعاتها. ولا يُذكر اسم أي مزود أو جهة راعية علنًا قبل الحصول على تأكيدهم.
- **لا نستضيف محتوى المدونات إطلاقًا.** تُدرج مجموعات البيانات على هيئة بيانات وصفية (metadata) بالإضافة إلى مؤشر يوضح مصدر جلب البيانات. **لا تقم بلصق جمل المصدر/المرجع في طلب الإرسال.**
- **عدم تضمين بيانات شخصية.** يُمنع وضع عناوين البريد الإلكتروني أو أرقام الهواتف أو أي معلومات تعريف شخصية (PII) أخرى في بلاغ عام. بالنسبة لخدمات الترجمة البشرية، تُقدم تفاصيل الاتصال إلى المشرف عبر قناة خاصة.
- **نطاق العمل.** تُعد المدونات الدينية/الكتابية وغيرها من المدونات ذات الطابع الاستعماري المفروض خارج نطاق عمل المشروع وسيتم رفضها.

ينتهي كل نموذج بإقرار إلزامي:

> *"أقر بأن هذا المحتوى قابل للإدراج العام، ولا يحتوي على أي محتوى من المدونة أو بيانات شخصية، ويحترم ترخيص المصدر وأي قيود مجتمعية أو قيود متعلقة بالسيادة."*

## طريقتان للإرسال

### من المتصفح

افتح قائمة اختيار البلاغات واختر النموذج المطابق لما تريد إرساله:

➡️ **[فتح نموذج إرسال على GitHub](https://github.com/gamedaysuits/Champollion/issues/new/choose)**

يطلب كل نموذج فقط ما يحتاجه الفهرس المطابق (الاسم، اللغات/الأزواج اللغوية، الترخيص، رابط المصدر، وما إلى ذلك) مع خانة الإقرار.

### من واجهة سطر الأوامر (CLI)

إذا كانت لديك [أداة CLI الخاصة بـ champollion](/docs/network/getting-started/submit-a-method)، فإن أمر `champollion submit` يجمع الحقول ويزودك بنسخة **معبأة مسبقًا** من نموذج GitHub نفسه:

```bash
# Interactive — pick a type and answer the prompts
champollion submit

# See the submission types
champollion submit --list

# Fully scripted (prints a pre-filled GitHub issue URL)
champollion submit --yes --type dataset --attest \
  --field dataset-name="GlobalVoices eng-amh" \
  --field pairs=eng-amh \
  --field license=CC-BY-4.0 \
  --field source-url=https://globalvoices.org
```

تطبع أداة CLI رابط URL — افتحه، وراجع الإقرار في المتصفح، ثم أرسل الطلب. أضف `--out submission.json` لحفظ نسخة محلية خالية من المحتوى لما تقترحه. لا تقوم أداة CLI أبدًا برفع أي شيء بنفسها ولا تكتب مباشرة في الفهرس.

## ماذا يحدث بعد الإرسال

1. يصل طلبك كبلاغ (Issue) على GitHub — وهو قائمة انتظار المراجعة.
2. يراجع المشرف الطلب وفقًا لقواعد الملكية الفكرية / الترخيص / السيادة الموضحة أعلاه.
3. **في حال القبول:** يضيف المشرف المدخل إلى مصدر الحقيقة المعني (سجل مجموعات البيانات، أو البطاقة، أو سجل الطرق أو الخدمات البشرية، أو فهرس النتائج الخارجية) من خلال تغيير اعتيادي، ويصنف البلاغ بعلامة **مقبول (accepted)**.
4. **إذا تعذر إدراجه بحالته الحالية:** يضع المشرف على البلاغ علامة **مرفوض (declined)** (أو يطلب مزيدًا من المعلومات) مع توضيح السبب.

لا يوجد دمج تلقائي ولا نشر تلقائي. القرار دائمًا بيد إنسان.
