# استكشاف الأخطاء وإصلاحها

المشكلات الشائعة وحلولها لأداة Champollion.

## واجهة برمجة التطبيقات (API) والمصادقة

### "OPENROUTER_API_KEY not found"

يتطلب Champollion مفتاح واجهة برمجة تطبيقات (API key) للترجمة باستخدام النماذج اللغوية الكبيرة (LLM). قم بتعيينه كمتغير بيئة:

```bash
export OPENROUTER_API_KEY="sk-or-v1-..."
```

أو في ملف `.env` (إذا كان مشروعك يحمل ملفات `.env`):

```
OPENROUTER_API_KEY=sk-or-v1-...
```

:::tip
إذا كان لديك مفتاح واجهة برمجة تطبيقات لـ Google Translate فقط، فسيكتشف Champollion ذلك تلقائيًا ويستخدم Google Translate كطريقة افتراضية. لا حاجة لتغيير الإعدادات.
:::

### "401 Unauthorized" من OpenRouter

مفتاح واجهة برمجة التطبيقات الخاص بك غير صالح أو منتهي الصلاحية. تحقق منه عبر [openrouter.ai/keys](https://openrouter.ai/keys).

### "429 Too Many Requests" / تقييد معدل الطلبات (Rate Limiting)

يتعامل Champollion مع حدود معدل الطلبات داخليًا باستخدام التراجع الأسي (exponential backoff). إذا كنت تصل باستمرار إلى حدود معدل الطلبات:

1. **تقليل حجم الدفعة (batch size)** في إعداداتك:
   ```json
   { "batchSize": 15 }
   ```
2. **استخدام نموذج بحدود معدل طلبات أعلى** (على سبيل المثال، `google/gemini-3.5-flash` لديه حدود سخية)
3. **استخدام طريقة أرخص/أسرع** للأزواج اللغوية ذات الحجم الكبير — لا يوجد لدى Google Translate حدود لمعدل الطلبات:
   ```json
   { "pairs": { "en:it": { "method": "google-translate" } } }
   ```

### النموذج غير موجود / أخطاء 404

يتحقق مزودو النماذج اللغوية الكبيرة المباشرون (`openai`، `anthropic`، `gemini`) من سلسلة النموذج (model string) عند الاستخدام الأول. إذا رأيت تحذيرًا:

**"looks like an OpenRouter path"** — أنت تستخدم نموذجًا بتنسيق OpenRouter (`google/gemini-3.5-flash`) مع مزود مباشر. يستخدم المزودون المباشرون أسماء النماذج المجردة:

```diff
- { "method": "gemini", "model": "google/gemini-3.5-flash" }
+ { "method": "gemini", "model": "gemini-2.5-flash" }
```

أو قم بالتبديل إلى طريقة `llm` لاستخدام OpenRouter:
```json
{ "method": "llm", "model": "google/gemini-3.5-flash" }
```

**"is an Anthropic/OpenAI/Gemini model"** — أنت ترسل نموذجًا إلى المزود الخاطئ:

```diff
- { "method": "gemini", "model": "claude-sonnet-4-6" }
+ { "method": "anthropic", "model": "claude-sonnet-4-6" }
```

**"not found in available models"** — قد يكون النموذج مهملًا (deprecated) أو مكتوبًا بشكل خاطئ. يجلب Champollion قائمة النماذج الحية للمزود ويقترح بدائل. تحقق من وثائق المزود لمعرفة أسماء النماذج الحالية.

:::tip[إهمال النماذج أمر وارد]
يقوم المزودون بإيقاف أسماء النماذج بانتظام. إذا فشلت الترجمات فجأة بعد تحديث من المزود، فتحقق من مخرجات `[WARN]` — ستعرض لك البدائل الحالية.
:::

## جودة الترجمة

### الترجمات تكرر لغة المصدر

تلتقط بوابة الجودة (quality gate) هذا الأمر. إذا كانت الترجمة مطابقة للمصدر الإنجليزي، يتم رفضها وإعادة المحاولة. إذا استمرت المشكلة:

1. **تحقق من النموذج** — أداء بعض النماذج ضعيف لأزواج لغوية معينة
2. **أضف تعليمات الأسلوب (register instructions)** — أخبر النموذج باللغة التي يجب إنتاجها:
   ```json
   {
     "languages": {
       "ja": { "name": "Japanese", "register": "Polite/formal Japanese" }
     }
   }
   ```
3. **جرب نموذجًا مختلفًا** — قم بالتبديل من `gpt-4o-mini` إلى `gpt-4o` أو `google/gemini-2.5-pro`

### مخرجات بنظام كتابة خاطئ (مثل نص لاتيني للغة اليابانية)

يلتقط فحص الامتثال لنظام الكتابة في بوابة الجودة معظم الحالات. إذا استمرت المشكلة:

- تحقق من صحة رمز اللغة (locale code) (استخدم `ja`، وليس `jp`)
- أضف تعليمات صريحة لنظام الكتابة في حقل `register`:
  ```json
  { "register": "Japanese using hiragana, katakana, and kanji" }
  ```

### أنماط الهلوسة في المخرجات

يتم التقاط أنماط الترايغرام (trigram) المتكررة (مثل "مرحبا مرحبا مرحبا") بواسطة كاشف حلقات الهلوسة. إذا كانت المخرجات مشوهة ولكنها تجاوزت الكاشف:

1. **تقليل حجم الدفعة** — تنتج الدفعات الأصغر مخرجات أكثر تركيزًا
2. **استخدام نموذج أقوى** — النماذج الأكبر تهلوس بشكل أقل في أنظمة الكتابة غير اللاتينية
3. **إضافة بيانات توجيهية (coaching data)** — مصطلحات القاموس تثبت الترجمة

## مشكلات الملفات والتنسيقات

### "No locale files found"

يكتشف Champollion ملفات اللغة (locale files) تلقائيًا. إذا لم يتمكن من العثور عليها:

1. **تحقق من `localesDir`** — يجب أن يشير إلى الدليل الذي يحتوي على ملفات اللغة:
   ```json
   { "localesDir": "./locales" }
   ```
2. **تحقق من تسمية الملفات** — يجب تسمية الملفات برمز اللغة: `en.json`، `fr.json`، إلخ.
3. **تحقق من التنسيق** — التنسيقات المدعومة: JSON، JSON المتداخل (nested JSON)، YAML، TOML

### تعارضات ملف القفل (Lock file)

إذا أصبح `.champollion.lock` في حالة سيئة:

```bash
# Reset the lock file (next sync will retranslate everything)
rm .champollion.lock
npx champollion sync
```

:::warning
حذف ملف القفل يعني أن عملية المزامنة التالية ستعيد ترجمة جميع المفاتيح، وليس فقط المفاتيح التي تم تغييرها. هذا له آثار على تكلفة واجهة برمجة التطبيقات (API) للمشاريع الكبيرة.
:::

### إعادة ترجمة مفاتيح محددة

إذا كانت هناك ترجمات فردية خاطئة وأردت إجبار النظام على إعادة ترجمتها دون حذف ملف القفل:

```bash
# Re-translate a single key
npx champollion sync --force-keys "hero.title"

# Re-translate multiple keys
npx champollion sync --force-keys "nav.home,nav.about,footer.copyright"
```

تتجاوز العلامة `--force-keys` فحص التجزئة (hash check) لملف القفل لتلك المفاتيح المحددة، مما يجبر النظام على إعادة الترجمة دون التأثير على أي مفاتيح أخرى.

### ترجمة المحتوى تفسد كتل التعليمات البرمجية (code blocks)

لا ينبغي أن يحدث هذا — حيث يتم حماية كتل التعليمات البرمجية قبل الترجمة. إذا حدث ذلك:

1. تحقق من أن كتلة التعليمات البرمجية تستخدم التنسيق القياسي (ثلاث علامات اقتباس خلفية)
2. تحقق من وجود كتل تعليمات برمجية غير مغلقة في ملف Markdown المصدري
3. قم بفتح مشكلة (File an issue) — هذا خطأ (bug) في نظام الحماية الحارس (sentinel shielding system)

## مشكلات واجهة سطر الأوامر (CLI)

### `--watch` لا يكتشف التغييرات

تستخدم مراقبة الملفات وظيفة `fs.watch` الأصلية في Node.js. المشكلات المعروفة:

- **محركات أقراص الشبكة** — لا تعمل `fs.watch` بشكل موثوق على حوامل NFS/SMB
- **وحدات تخزين Docker** — استخدم وضع الاستقصاء (polling mode) أو قم بتشغيل Champollion داخل الحاوية
- **الأدلة الكبيرة** — يراقب المراقب `localesDir` بشكل متكرر (recursively)؛ قد تتجاوز الأشجار العميقة جدًا حدود نظام التشغيل

### `npx` يقوم بتشغيل إصدار قديم

```bash
# Clear the npx cache
npx --yes champollion@latest sync
```

أو قم بالتثبيت بشكل عام (globally):

```bash
npm install -g champollion
champollion sync
```

## الأداء

### المزامنة بطيئة للعديد من اللغات

يترجم Champollion جميع اللغات بالتوازي افتراضيًا. إذا كانت المزامنة لا تزال بطيئة:

1. **استخدم Google Translate للأزواج اللغوية ذات الحجم الكبير** — فهو أسرع بـ 10 إلى 50 مرة من الترجمة باستخدام النماذج اللغوية الكبيرة (LLM)
2. **زيادة حجم الدفعة** (الافتراضي هو 80):
   ```json
   { "batchSize": 120 }
   ```
3. **ضبط التزامن (concurrency)** — التوازي الافتراضي للغات JSON هو 200 وللمحتوى 48. إذا كان مزود واجهة برمجة التطبيقات الخاص بك يدعم حدود معدل طلبات أعلى:
   ```bash
   npx champollion sync --json-concurrency 80 --content-concurrency 20
   ```
4. **استخدم نموذجًا سريعًا** — `gpt-4o-mini` أسرع بكثير من `gpt-4o`

### تكاليف واجهة برمجة التطبيقات (API) مرتفعة

- **تحقق من أحجام الدفعات** — دفعات أكبر = استدعاءات أقل لواجهة برمجة التطبيقات = تكلفة أقل
- **استخدم ذاكرة الترجمة (Translation Memory)** — ذاكرة الترجمة (TM) مفعلة افتراضيًا. قم بتشغيل `champollion tm stats` للتحقق من عملها. إذا رأيت 0 إدخالات بعد عمليات مزامنة متعددة، فقد يكون هناك خطأ ما في أذونات دليل `.champollion/` الخاص بك
- **استخدم التخزين المؤقت للمطالبات (prompt caching)** — يقسم Champollion رسائل النظام/المستخدم لتحقيق إصابات التخزين المؤقت (cache hits) في نماذج Anthropic و Google
- **استخدم Google Translate للغات المستوى الثاني (Tier 2)** — راجع دليل [ترجمة 30 لغة](/docs/tutorials/translate-30-languages)

### ترجمات قديمة (Stale) بعد تبديل المزودين

إذا قمت بالتبديل من طريقة ترجمة إلى أخرى (على سبيل المثال، من `llm` إلى `deepl`)، فقد تستمر ذاكرة التخزين المؤقت لذاكرة الترجمة (TM cache) في تقديم ترجمات قديمة من الطريقة السابقة للمفاتيح التي لم يتغير نصها المصدري. يتضمن مفتاح ذاكرة التخزين المؤقت اسم الطريقة، لذلك يتم التعامل مع معظم الحالات تلقائيًا. ولكن إذا قمت بتغيير `model` ضمن نفس الطريقة:

```bash
# Force fresh translations for all keys
champollion sync --no-tm

# Or clear the cache entirely and re-sync
champollion tm clear --yes
champollion sync
```

راجع [ذاكرة الترجمة](/docs/concepts/translation-memory) للحصول على تفاصيل حول تصميم مفتاح ذاكرة التخزين المؤقت.

## التعافي من إصدار سيئ {#recover-old-damage}

القيم المكتوبة بواسطة مسار معالجة (pipeline) أقدم **لا تتعافى ذاتيًا أبدًا**: تتطابق تجزئات البيان (manifest hashes) الخاصة بها مع المصدر الحالي، لذلك يعتبرها `sync` مستقرة ولا تراها أي بوابة (gate) مرة أخرى. إذا كنت تقوم بترقية مشروع كان يعمل بإصدارات ما قبل 0.3.0، فافترض أنه قد يكون هناك تلف في ملفات اللغة الخاصة بك وقم بإجراء تدقيق (audit) أولاً:

```bash
champollion integrity
```

يكتشف التدقيق تواقيع التلف المعروفة ويحدد الإصلاح لكل منها:

| النتيجة | ما هي | الإصلاح |
|---------|-----------|-----|
| `UNEXPECTED PUA` | مخرجات تحويل نظام الكتابة (pIqaD/Tengwar/Kryptonian) المكتوبة عندما لم يكن التحويل مطلوبًا — تظهر فارغة | `champollion repair-script` (دون اتصال، دقيق لـ pIqaD) |
| `HOLLOWED VALUES` | المصدر مع حذف أحرفه — مخرجات من قبل بوابة الحفاظ على المحتوى | إعادة الترجمة (انظر أدناه) |
| `NO-TRANSLATE DRIFT` | عنوان URL أو مفتاح حرفي آخر تمت "ترجمته" | `champollion sync` (يتم إصلاحه مجانًا، تلقائيًا) |

بالنسبة للقيم المجوفة (hollowed values) — أو أي لغة لم تعد تثق بها ببساطة — قم بإعادة بنائها:

```bash
champollion sync --pair en:tlh --force
```

يقوم `--force` بإعادة وضع كل مفتاح مصدري في قائمة الانتظار للزوج (أو الأزواج) اللغوية المحددة. لا تزال إصابات ذاكرة الترجمة (Translation Memory hits) تُقدم، ولكن كل إصابة مُقدمة **يتم التحقق من صحتها مقابل البوابات الحالية أولاً** — يتم طرد القيمة المخزنة مؤقتًا التي ترفضها البوابة الآن وإعادة فوترتها، وبالتالي فإن ذاكرة التخزين المؤقت المسمومة تعالج نفسها بدلاً من تغذية عملية إعادة البناء. أضف `--no-tm` إذا كنت تريد إعادة فوترة جديدة تمامًا بغض النظر عن ذلك، و `--max-cost` لوضع حد أقصى للإنفاق في كلتا الحالتين.

يُبلغ التحقق بعد المزامنة أيضًا عن هذه التواقيع، لذلك تفشل اللغة التالفة في `sync` بصوت عالٍ (مع تحديد الإصلاح) بدلاً من شحنها بهدوء.

### إعادة وضع في قائمة الانتظار لمرة واحدة بعد عمليات تنظيف `--no-tm` {#one-time-requeue}

إذا استخدمت عملية التعافي الخاصة بك `--no-tm`، فتوقع أن تقوم المزامنة **التالية** بوضع دفعة من مفاتيح تكرار المصدر (source-echo keys) التي اعتقدت أنها استقرت في قائمة الانتظار. يكتب `--no-tm` القيم دون ختمها في ذاكرة الترجمة، والقيمة *غير المختومة* المطابقة لمصدرها لا يمكن تمييزها عن القيمة غير المترجمة — لذلك يتم إعادة وضعها في قائمة الانتظار مرة واحدة، وتعود (غالبًا ما تكون متطابقة)، ويتم ختمها، وتستقر بشكل دائم. هذه تكلفة لمرة واحدة، وليست حلقة مفرغة. قم بمعاينة المفاتيح الدقيقة باستخدام:

```bash
champollion sync --dry --list-keys
```
