# استكشاف الأخطاء وإصلاحها

المشكلات الشائعة وحلولها لـ champollion.

## واجهة برمجة التطبيقات (API) والمصادقة

### "OPENROUTER_API_KEY not found"

يتطلب Champollion مفتاح API لترجمة LLM. عيّنه كمتغير بيئة:

```bash
export OPENROUTER_API_KEY="sk-or-v1-..."
```

أو في ملف `.env` (إذا كان مشروعك يحمّل ملفات `.env`):

```
OPENROUTER_API_KEY=sk-or-v1-...
```

:::tip
إذا كان لديك مفتاح API لـ Google Translate فقط، فإن champollion يكتشف ذلك تلقائيًا ويستخدم Google Translate كطريقة افتراضية. لا يلزم أي تغيير في التكوين.
:::

### "401 Unauthorized" من OpenRouter

مفتاح API الخاص بك غير صالح أو منتهي الصلاحية. تحقق منه على [openrouter.ai/keys](https://openrouter.ai/keys).

### "429 Too Many Requests" / حدود معدل الطلبات (Rate Limiting)

يتعامل Champollion مع حدود معدل الطلبات داخليًا باستخدام التراجع الأسي (exponential backoff). إذا كنت تصطدم بحدود المعدل باستمرار:

1. **قلل حجم الدفعة (batch size)** في ملف التكوين الخاص بك:
   ```json
   { "batchSize": 15 }
   ```
2. **استخدم نموذجًا بحدود معدل أعلى** (على سبيل المثال، يمتلك `google/gemini-3.8-flash` حدودًا سخية)
3. **استخدم طريقة أرخص/أسرع** لأزواج اللغات ذات الحجم الكبير — لا توجد حدود للمعدل في Google Translate:
   ```json
   { "pairs": { "en:it": { "method": "google-translate" } } }
   ```

### النموذج غير موجود / أخطاء 404 (Model Not Found)

يتم إرسال الأسماء الخاصة بمزودي LLM المباشرين (`openai`، `anthropic`، `gemini`) لنماذجهم. يتم تعيين معرّف بتنسيق OpenRouter للمزود تلقائيًا نيابة عنك (`google/gemini-3.8-flash` ← `gemini-3.8-flash` على `gemini`). إذا توقف التشغيل مع:

**"is an OpenRouter model id … which has no model by that name"** — أنت تستخدم نموذجًا بتنسيق OpenRouter من مزود آخر (`google/gemini-3.8-flash` مع `openai`). لم يتم إرسال أي شيء. حدد اسم نموذج تابع لذلك المزود، أو استخدم الطريقة التي تحتوي على النموذج، أو انتقل إلى طريقة `llm` لاستخدام OpenRouter — توضح الرسالة كلاً منها ومكان تعيين النموذج:

```diff
- { "method": "openai", "model": "google/gemini-3.8-flash" }
+ { "method": "openai", "model": "gpt-4o" }
```
```json
{ "method": "llm", "model": "google/gemini-3.8-flash" }
```

يقومون أيضًا بالتحقق من اسم النموذج الخاص بك عند الاستخدام الأول. إذا رأيت تحذيرًا:

**"is an Anthropic/OpenAI/Gemini model"** — أنت ترسل نموذجًا إلى المزود الخطأ:

```diff
- { "method": "gemini", "model": "claude-sonnet-4-6" }
+ { "method": "anthropic", "model": "claude-sonnet-4-6" }
```

**"not found in available models"** — قد يكون النموذج مهجورًا أو يحتوي على خطأ إملائي. يجلب Champollion قائمة النماذج المباشرة للمزود ويقترح بدائل. راجع وثائق المزود لمعرفة أسماء النماذج الحالية.

:::tip[إيقاف النماذج أمر وارد]
يقوم المزودون بإيقاف أسماء النماذج بانتظام. إذا فشلت الترجمات فجأة بعد تحديث لدى المزود، فتحقق من مخرجات `[WARN]` — ستعرض لك البدائل الحالية.
:::

### `local`: "could not reach …"

ترسل طريقة `local` الطلبات إلى خادم متوافق مع OpenAI على جهازك (Ollama أو vLLM أو LM Studio أو llama.cpp). وعندما يتعذر عليه الاتصال، يحدد الخطأ العنوان الذي تمت محاولته والإعداد الذي اختاره:

```text
[ERR] Local (OpenAI-compatible) Batch 1 failed: fetch failed (ECONNREFUSED) — could not reach http://localhost:8000/v1 (from LOCAL_API_BASE in .env)
```

يأتي العنوان من أول خيار تم تعيينه من بين هذه الخيارات، إما في البيئة أو في `.env.local` / `.env`: `LOCAL_API_BASE`، ثم `OPENAI_API_BASE`، ثم `OPENAI_BASE_URL`. وإذا لم يتم تعيين أي منها، فإنه يستخدم القيمة الافتراضية لـ Ollama وهي `http://localhost:11434/v1`. شغّل الخادم، أو أصلح الإعداد المذكور في الرسالة.

## جودة الترجمة

### تكرار لغة المصدر في الترجمات

ترصد بوابة الجودة (quality gate) هذه المشكلة. إذا كانت الترجمة مطابقة للمصدر الإنجليزي، فسيتم رفضها وإعادة المحاولة. إذا استمرت المشكلة:

1. **تحقق من النموذج** — بعض النماذج يكون أداؤها ضعيفًا لأزواج لغوية معينة
2. **أضف تعليمات الأسلوب (register)** — أخبر النموذج باللغة المطلوب إنتاجها:
   ```json
   {
     "languages": {
       "ja": { "name": "Japanese", "register": "Polite/formal Japanese" }
     }
   }
   ```
3. **جرب نموذجًا مختلفًا** — بدّل من `gpt-4o-mini` إلى `gpt-4o` أو `google/gemini-3.1-pro-preview`

### مخرجات بنظام كتابة خاطئ (مثل نص لاتيني للغة اليابانية)

يكتشف فحص مطابقة نظام الكتابة في بوابة الجودة معظم الحالات. إذا استمرت المشكلة:

- تحقق من صحة رمز الإعداد الإقليمي (locale) (`ja` وليس `jp`)
- أضف تعليمات صريحة لنظام الكتابة في حقل `register`:
  ```json
  { "register": "Japanese using hiragana, katakana, and kanji" }
  ```

### فشل التحقق من الأسماء (مثل "Curtis Forbes" باليابانية)

تكون الأسماء صحيحة بالحروف اللاتينية، لذا أخبر champollion بالأسماء التي لديك:

```json
{ "protectedTerms": ["Curtis Forbes", "Game Day Suits"] }
```

يتم إبلاغ النموذج بالإبقاء عليها كما هي مكتوبة، ولا يتم أبدًا الإبلاغ عن قيمة تتكون فقط من هذه الأسماء كقيمة غير مترجمة أو ذات نظام كتابة خاطئ. بدون هذه القائمة، تخضع القيمة القصيرة المكتوبة بالحروف اللاتينية في لغة غير لاتينية لإعادة محاولة واحدة تسأل عما إذا كانت اسمًا أم تصنيفًا. وإذا احتفظ النموذج بها، فسيتم قبولها كاسم وتخزينها مؤقتًا، بحيث لا تتم محاسبتك عليها مجددًا. لا تحتاج إلى `--no-verify`.

### أنماط الهلوسة في المخرجات

تكتشف أداة رصد حلقات الهلوسة أنماط الثلاثيات المكررة (على سبيل المثال، "hello hello hello"). إذا كانت المخرجات مشوشة ولكنها تجاوزت أداة الرصد:

1. **قلل حجم الدفعة** — تنتج الدفعات الأصغر مخرجات أكثر تركيزًا
2. **استخدم نموذجًا أقوى** — تقل هلوسة النماذج الأكبر في أنظمة الكتابة غير اللاتينية
3. **أضف بيانات التوجيه (coaching data)** — تثبّت مصطلحات القاموس الترجمة بدقة

## مشكلات الملفات والتنسيقات

### "No locale files found"

يكتشف Champollion ملفات اللغات/الإعدادات الإقليمية (locale files) تلقائيًا. إذا لم يتمكن من العثور عليها:

1. **تحقق من `localesDir`** — يجب أن يشير إلى الدليل الذي يحتوي على ملفات اللغات:
   ```json
   { "localesDir": "./locales" }
   ```
2. **تحقق من تسمية الملفات** — يجب تسمية الملفات وفقًا لرمز اللغة: `en.json`، `fr.json`، وما إلى ذلك.
3. **تحقق من التنسيق** — التنسيقات المدعومة: JSON، وJSON متداخل (nested JSON)، وYAML، وTOML

### تعارضات ملف القفل (Lock file)

يسجل `.champollion.lock` النص الإنجليزي الذي تم إنشاء كل ترجمة
منه. يمكنك حل تعارض الدمج فيه كأي ملف يتم إنشاؤه تلقائيًا: احتفظ بأي من
الجانبين، ثم شغّل `npx champollion sync`، واعتمد (commit) النتيجة.

:::warning[حذف ملف القفل لا يعيد ترجمة أي شيء]
بدون ملف القفل، لا يمكن لعملية المزامنة (sync) معرفة السلاسل النصية الإنجليزية التي تغيرت منذ
إنشاء الترجمات الحالية. حيث تترجم فقط المفاتيح **المفقودة**
من الملف الهدف، وتسجل النص الإنجليزي الحالي كنقطة مرجعية جديدة. ويبقى النص
الإنجليزي الذي تم تعديله قبل حذف ملف القفل محتفظًا بترجمته القديمة بصمت.
لإعادة بناء لغة ما عن قصد، استخدم `--force` (وقيّد نطاقه باستخدام
`--pair`)؛ يُعاد استخدام الترجمات المخزنة مؤقتًا، وبالتالي لن تتم محاسبتك
إلا على النصوص التي لم يشهدها التخزين المؤقت من قبل.
:::

### إعادة ترجمة مفاتيح محددة

إذا كانت هناك ترجمات فردية خاطئة وتريد فرض إعادة ترجمتها دون حذف ملف القفل:

```bash
# Re-translate a single key
npx champollion sync --force-keys "hero.title"

# Re-translate multiple keys
npx champollion sync --force-keys "nav.home,nav.about,footer.copyright"
```

يتجاوز الخيار `--force-keys` فحص تجزئة (hash) ملف القفل لتلك المفاتيح المحددة، مما يفرض إعادة الترجمة دون التأثير على أي مفاتيح أخرى. و`--redo keys:hero.title` هو الشيء نفسه باسمه الأحدث. يتم تقديم كليهما من ذاكرة الترجمة (Translation Memory) عندما تحتوي على النص؛ أضف `--fresh` للدفع مقابل ترجمة جديدة بدلاً من ذلك. المفتاح الذي يحتوي على فاصلة (مثل msgid في gettext الذي يمثل جملة كاملة) يُكتب باستخدام `\,`، مع وضع المعامل بين علامتي اقتباس للطرفية (shell): `--redo 'keys:Welcome back\, %(name)s!'`.

### `verify` يُبلغ عن عدم تطابق في العناصر النائبة (أو قيمة تالفة أخرى)

يُبلغ `champollion verify` (والفحص الذي يعمل بعد كل مزامنة) عن القيم التالفة: عنصر نائب (placeholder) فُقد أو تم تغيير اسمه، أو صيغة جمع ICU معطوبة، أو قيمة حُذفت أحرفها. أمر `champollion sync` العادي **لا** يصلحها؛ فالقيمة موجودة بالفعل على القرص ويشير مدخل القفل الخاص بها إلى أنها محدثة، لذا تتجاهلها المزامنة.

تذكر كل نتيجة يكتشفها الأمر الذي يصلح تلك المفاتيح تحديدًا، على سبيل المثال:

```text
[ERR] [VERIFY] fr: 1 i18next {{…}} placeholder mismatch(es): greeting (placeholder {{name}} was changed to {{nom}}) — fix: `champollion sync --pair en:fr --redo keys:greeting`
```

شغّل ذلك الأمر. عندما تمتد لغة ما عبر عدة ملفات، تُكتب المفاتيح بصيغة `<file>::<key>` (على سبيل المثال `common::nav.home`)، مما يعيد ترجمة مفتاح ذلك الملف فقط دون غيره.

لا تحتاج إلى `--fresh`. إذا كانت القيمة التالفة قادمة من ذاكرة الترجمة (Translation Memory)، فإن `verify` قد أزالها بالفعل من التخزين المؤقت، ويذكر ذلك صراحة: `[TM] Evicted 1 cached translation(s) that produced damaged values`. تقوم إعادة التنفيذ بعد ذلك بترجمة النص مرة أخرى (أو تقديم ترجمة التخزين المؤقت المختلفة له) بدلاً من تقديم القيمة التالفة مجددًا. أما القيمة التي قام شخص ما بتعديلها يدويًا فلا يتم تخزينها مؤقتًا على الإطلاق، لذا لا يتم حذف أي شيء لها، وتعمل إعادة التنفيذ بالطريقة نفسها.

بالنسبة لملفات محتوى Markdown/MDX، استخدم `--retranslate` مع مسار أو نمط glob بدلاً من ذلك (مثل `--retranslate docs/intro.md`). فهو يترجم تلك الملفات من جديد حتى لو كانت محدثة أو تمت ترجمتها يدويًا. استخدم `--files` لقصر التشغيل على بعض ملفات المحتوى دون فرض إعادة ترجمتها.

### ترجمة المحتوى تؤدي إلى تلف كتل التعليمات البرمجية (code blocks)

لا ينبغي أن يحدث هذا — يتم حماية كتل التعليمات البرمجية قبل الترجمة. إذا حدث ذلك:

1. تأكد من أن كتلة التعليمات البرمجية تستخدم التحديد القياسي (علامات backticks الثلاثية)
2. تحقق من وجود كتل تعليمات برمجية غير مغلقة في ملف Markdown المصدري
3. أرسل بلاغًا عن المشكلة (issue) — فهذا خطأ في نظام الحماية بالعلامات (sentinel shielding)

## مشكلات واجهة سطر الأوامر (CLI)

### `--watch` لا يكتشف التغييرات

تستخدم مراقبة الملفات `fs.watch` الأصلي في Node.js. المشكلات المعروفة:

- **محركات أقراص الشبكة** — لا يعمل `fs.watch` بشكل موثوق على وحدات تخزين NFS/SMB المثبتة
- **وحدات تخزين Docker (Docker volumes)** — استخدم وضع الاستقصاء (polling mode) أو شغّل champollion داخل الحاوية
- **الأدلة الكبيرة** — يراقب الراصد (watcher) `localesDir` بشكل متكرر (recursively)؛ قد تتجاوز شجرات الأدلة العميقة جدًا حدود نظام التشغيل

### `npx` يشغّل إصدارًا قديمًا

```bash
# Clear the npx cache
npx --yes champollion@latest sync
```

أو ثبته عالميًا:

```bash
npm install -g champollion
champollion sync
```

## الأداء

### المزامنة بطيئة عند وجود لغات متعددة

يترجم Champollion جميع اللغات/الإعدادات الإقليمية بالتوازي بشكل افتراضي. إذا كانت المزامنة لا تزال بطيئة:

1. **استخدم Google Translate للأزواج اللغوية الكبيرة** — إنه أسرع بـ 10 إلى 50 مرة من ترجمة LLM
2. **زد حجم الدفعة** (القيمة الافتراضية هي 80):
   ```json
   { "batchSize": 120 }
   ```
3. **اضبط التزامن (concurrency)** — التوازي الافتراضي للغات بتنسيق JSON هو 200 وللمحتوى 48. إذا كان مزود API يدعم حدود معدل أعلى:
   ```bash
   npx champollion sync --json-concurrency 80 --content-concurrency 20
   ```
4. **استخدم نموذجًا سريعًا** — `gpt-4o-mini` أسرع بكثير من `gpt-4o`

### تكاليف API مرتفعة

- **تحقق من أحجام الدفعات** — دفعات أكبر = استدعاءات API أقل = تكلفة أقل
- **استخدم ذاكرة الترجمة (Translation Memory)** — تكون ذاكرة الترجمة (TM) مفعّلة افتراضيًا. شغّل `champollion tm stats` للتحقق من عملها. إذا رأيت 0 مدخلات بعد عدة عمليات مزامنة، فقد تكون هناك مشكلة في أذونات دليل `.champollion/`
- **استخدم التخزين المؤقت للمطالبات (Prompt Caching)** — يقسم Champollion رسائل النظام/المستخدم لتحقيق نتائج إيجابية في التخزين المؤقت (cache hits) على نماذج Anthropic وGoogle
- **استخدم Google Translate للغات المستوى الثاني (Tier 2)** — راجع دليل [ترجمة 30 لغة](/docs/tutorials/translate-30-languages)

### الترجمات بعد تبديل النموذج أو المزود

يؤدي تبديل الطريقة (على سبيل المثال، من `llm` إلى `deepl`) أو الأسلوب أو التوجيه إلى الحصول على ترجمات جديدة لما يُعاد ترجمته، لأن مفتاح التخزين المؤقت يتضمنها — لكن المزامنة العادية لا تعيد ترجمة أي شيء تم بالفعل، بل يفعل ذلك `champollion sync --redo all`. وإعادة تبديل **النموذج** ضمن الطريقة نفسها تعيد استخدام ما ترجمه النموذج السابق دون أي تكلفة؛ وتخبرك المزامنة بذلك قبل عرض التقدير. إذا كنت تريد ترجمات النموذج الجديد الخاصة به:

```bash
# Have the new model translate what an earlier model wrote
# (what the new model already translated still comes from the cache)
champollion sync --redo all --fresh-on-model-change

# Re-translate specific content files from scratch
champollion sync --retranslate "docs/guides/**"
```

لا يغير `--fresh-on-model-change` بمفرده سوى المفاتيح التي يترجمها التشغيل على أي حال (الجديدة أو المغيّرة): فبعد تبديل النموذج وحده، لا يرسل أمر `sync --fresh-on-model-change` العادي أي شيء.

راجع [ذاكرة الترجمة](/docs/concepts/translation-memory) للحصول على تفاصيل حول تصميم مفتاح التخزين المؤقت.

## التعافي من إصدار به مشكلات {#recover-old-damage}

القيم المكتوبة بواسطة مسار عمل (pipeline) قديم **لا تتعافى تلقائيًا أبدًا**: فتجزئات البيان (manifest hashes) الخاصة بها تطابق المصدر الحالي، لذلك يعتبرها `sync` مستقرة ولا تراها أي بوابة بعد ذلك. إذا كنت تقوم بترقية مشروع كان يعمل بإصدارات أقدم من 0.3.0، فافترض أن التلف قد يكون مستقرًا في ملفات اللغات الخاصة بك وأجرِ تدقيقًا أولاً:

```bash
champollion integrity
```

يكتشف التدقيق بصمات التلف المعروفة ويحدد الإصلاح المناسب لكل منها:

| النتيجة المكتشفة | ما تعنيه | الإصلاح |
|---------|-----------|-----|
| `UNEXPECTED PUA` | مخرجات تحويل نظام الكتابة (pIqaD/Tengwar/Kryptonian) كُتبت في حين لم يكن التحويل مطلوبًا — وتظهر فارغة | `champollion repair-script` (دون اتصال بالإنترنت، دقيق لـ pIqaD) |
| `HOLLOWED VALUES` | المصدر بعد حذف أحرفه — مخرجات من مرحلة ما قبل بوابة الحفاظ على المحتوى | إعادة الترجمة (انظر أدناه) |
| `NO-TRANSLATE DRIFT` | عنوان URL أو مفتاح حرفي آخر تمت "ترجمته" | `champollion sync` (يتم إصلاحه مجانًا وتلقائيًا) |

بالنسبة للقيم المفرغة — أو أي لغة لم تعد تثق بها ببساطة — أعد بناءها:

```bash
champollion sync --pair en:tlh --force
```

يعيد `--force` إدراج كل مفتاح مصدر في قائمة الانتظار للزوج (أو الأزواج) المحددة. ولا يزال يتم تقديم نتائج ذاكرة الترجمة، ولكن كل نتيجة تُقدم **يتم التحقق من صحتها مقابل البوابات الحالية أولاً** — وتُطرد أي قيمة مخزنة مؤقتًا ترفضها البوابة الآن وتتم فوترتها من جديد، وبذلك يتعافى التخزين المؤقت الملوث ذاتيًا بدلاً من تغذية عملية إعادة البناء. أضف `--no-tm` إذا كنت ترغب في إعادة فوترة جديدة تمامًا بغض النظر عن ذلك، و`--max-cost` لتحديد سقف الإنفاق في كلتا الحالتين.

يُبلغ التحقق اللاحق للمزامنة أيضًا عن هذه البصمات، بحيث تفشل اللغة التالفة في `sync` بوضوح (مع تحديد الإصلاح) بدلاً من نشرها دون ملاحظة ذلك.

### إعادة إدراج لمرة واحدة في قائمة الانتظار بعد عمليات تنظيف `--no-tm` {#one-time-requeue}

إذا استخدمت عملية التعافي لديك `--no-tm`، فتوقع أن تدرج المزامنة **التالية** مجموعة من المفاتيح المكررة للمصدر في قائمة الانتظار والتي كنت تعتقد أنها استقرت. يكتب `--no-tm` القيم دون ختمها في ذاكرة الترجمة، والقيمة *غير المختومة* المطابقة لمصدرها لا يمكن تمييزها عن القيمة غير المترجمة — لذا يُعاد إدراجها في قائمة الانتظار مرة واحدة، وتعود (مطابقة في الغالب)، وتُختم، وتستقر نهائيًا. هذه تكلفة لمرة واحدة وليست حلقة مفرغة. يمكنك معاينة المفاتيح المعنية بدقة باستخدام:

```bash
champollion sync --dry --list-keys
```
