# champollion للمؤسسات

يترجم فريقك المحتوى بانتظام. لديك مجموعة من ملفات الترجمة المحلية (locale files)، ومسار تكامل مستمر (CI pipeline)، وعملية تتضمن على الأرجح قيام شخص ما بتشغيل Google Translate يدويًا، ونسخ النتائج إلى ملف JSON، وتمني الأفضل. أو ربما تدفع مقابل منصة نظام إدارة الترجمة (TMS) حيث تكون مقيدًا بمحرك ترجمة تابع لمزوّد واحد.

يمنحك champollion خيارًا أكثر سلاسة: اختر الطريقة المناسبة لكل لغة — سواء كانت آلية أو بشرية — وشغّلها جميعًا من خلال أمر واحد.

## لماذا تستخدم الفِرق champollion

1. **اختيار الطريقة المناسبة لكل لغة** — آلية أو بشرية، وليس ما يفرضه مزوّدك افتراضيًا
2. **النشر بأمر واحد** — يُترجم `npx champollion sync` كل لغة محلية، وكل تنسيق، في كل مرة
3. **تبديل الطرق دون تغيير التعليمات البرمجية** — مجرد تغيير في الإعدادات، وليس عملية ترحيل كاملة
4. **امتلاك مسار عملك بالكامل** — دون التقيد بمزوّد معين، ودون لوحات تحكم شهرية، ودون حسابات

```json title="champollion.config.json"
{
  "version": 3,
  "pairs": {
    "en:fr": { "method": "deepl" },
    "en:ja": { "method": "llm", "model": "google/gemini-3.1-pro-preview" },
    "en:de": { "method": "google-translate" },
    "en:ko": { "method": "llm", "register": "polite-haeyo" },
    "en:es": { "method": "api", "endpoint": "https://review.your-lsp.example/mtpe" },
    "en:crk": { "method": "llm-coached" }
  }
}
```

تحصل الفرنسية على DeepL (يفضل فريقك سلاسته اللغوية الأوروبية). وتحصل اليابانية على نموذج لغوي كبير (LLM) رائد. وتحصل الألمانية على Google Translate (سريع، واقتصادي، وجيد بما فيه الكفاية). وتحصل الكورية على نموذج لغوي كبير ذي أسلوب رسمي. وتُوجَّه الإسبانية إلى خدمة ترجمة بشرية احترافية / تحرير لاحق للترجمة الآلية (MTPE) عبر طريقة `api` — فالترجمة البشرية هنا طريقة من الدرجة الأولى وليست مجرد إضافة ثانوية. أما لغة كري السهول (Plains Cree) فتحصل على طريقة النموذج اللغوي الكبير الموجَّه (coached LLM)، مع ملاحظات نحوية وقاموس توفره بنفسك.

**الأمر نفسه. مسار CI نفسه. طرق مختلفة لكل زوج لغوي — بشرية أو آلية. ملف إعدادات واحد.**

:::note[طرق لغات المجتمعات المحلية تتمتع بالسيادة]
الزوج اللغوي للغة كري السهول (Plains Cree) المذكور أعلاه ليس مجرد زوج لغوي آخر. فطرق ترجمة لغات الشعوب الأصلية ولغات المجتمعات المحلية الأخرى هي **مملوكة للمجتمع وتخضع لإدارته**: يمتلك المجتمع مفاتيح البيانات الكامنة وراءها، ويحدد شروط الاستخدام، وتُستثنى أي مدونة لغوية أو طريقة غير تجارية (NC) من المسارات التجارية افتراضيًا. إذا كان استخدامك تجاريًا، فتحقق من ترخيص الطريقة قبل النشر أو الإطلاق في الإنتاج. راجع [سيادة البيانات](/docs/network/sovereignty/data-sovereignty).
:::

## سير العمل: من لوحة الصدارة إلى النشر

:::tip[`champollion network leaderboard` يأتي مدمجًا مع CLI]
يعمل سير العمل الموضح أدناه عبر الأمر `champollion network leaderboard` — تصفح لوحة صدارة [Network](/arena) من الطرفية الخاصة بك وثبّت المكون الإضافي للطريقة مباشرةً منها. راجع [مرجع CLI](/docs/reference/cli#leaderboard) للاطلاع على جميع الخيارات.
:::

شبكة [Network](/arena) هي المكان الذي تُقاس فيه كفاءة طرق الترجمة مقارنةً بمعايير مرجعية مع تقييم قابل للتكرار ومميّز ببصمة فريدة. ويتم ترتيب عمليات التشغيل بالطريقة المتبعة في مجال الترجمة الآلية (MT): باستخدام مقياس chrF++ على مستوى المدونة اللغوية مع فترة ثقة تبلغ 95%. وتُعرض مقاييس BLEU وTER وCOMET بجانبه، كما يُبلغ عن المقاييس التشخيصية مثل التطابق التام وقبول محولات الحالات المحدودة (FST) بشكل منفصل، ولا تُدمج أبدًا في المؤشر الرئيسي. وما إذا كانت طريقة ما أفضل حقًا من طريقة أخرى هو أمر يحدده اختبار الدلالة الإحصائية المقترن، وليس مجرد فارق رقمي بين قيمتين. وتتتبع لوحة الصدارة كل مشاركة مقدمة.

سير العمل:

```bash
# Browse the leaderboard from your terminal
npx champollion network leaderboard --pair "eng>fra"

# Output (abridged):
#   #   Model         chrF++ [95% CI]      BLEU   …   EM     FST
#   1   gemini-3.5    72.3 [70.8, 73.7]    48.1   …   0.31   —
#   2   deepl         70.9 [69.2, 72.4]    46.0   …   0.29   —
#   3   claude-4      68.4 [66.9, 70.0]    43.7   …   0.27   —
#   Headline: chrF++ with its 95% bootstrap CI; rows whose intervals overlap are not distinguishable.

# Install the method that fits as a plugin (by its rank)
npx champollion network leaderboard --install 1

# Use it
npx champollion sync
```

*للتوضيح فقط — صفوف لوحة الصدارة أعلاه هي تخطيط توضيحي تمثيلي. في هذا المثال، تتداخل الفترات للسطرين الأولين، وبالتالي لا تشير اللوحة إلى تفوق أحدهما على الآخر. اللوحة مفتوحة حاليًا للمشاركات ولا تحتوي على أي عمليات تشغيل منشورة بعد.*

**أنت لا تبني الطريقة، ولا تدرب النموذج؛ بل تختار الطريقة التي تناسب مجالك وميزانيتك وترخيصك — بشرية كانت أم آلية — وتنشرها.** وإذا ظهرت طريقة أكثر ملاءمة في الشهر التالي، يمكنك استبدالها بأمر واحد.

## ما هو متاح اليوم

الجسر الرابط بين لوحة الصدارة وواجهة سطر الأوامر (CLI) قيد التطوير حاليًا. إليك ما يعمل الآن:

### الطرق المدمجة (لا تتطلب أي مكونات إضافية)

| الطريقة | الأنسب لـ | التكلفة |
|--------|----------|------|
| `llm` (الافتراضية) | التركيز على الجودة، لأي لغة | لكل رمز مميز (Token) عبر OpenRouter |
| `gemini` | الجودة + باقة مجانية | مجاني (محدود)، ثم لكل رمز مميز (Token) |
| `google-translate` | السرعة + الحجم الكبير | 20 دولارًا / مليون حرف |
| `deepl` | اللغات الأوروبية | 25 دولارًا / مليون حرف |
| `llm-coached` | اللغات التي تتوفر لها بيانات توجيه | لكل رمز مميز (Token) عبر OpenRouter |
| `api` | الطرق المخصصة أو المستضافة مجتمعيًا | استضافة ذاتية |

### طرق المكونات الإضافية (تُثبَّت بشكل منفصل)

يمكن للمكونات الإضافية المخصصة تغليف أي منطق ترجمة — سواء كان نموذجًا مضبوطًا بدقة (fine-tuned model)، أو مسار عمل مقيدًا بمحولات الحالات المحدودة (FST-gated pipeline)، أو واجهة برمجة تطبيقات مجتمعية (Community API)، أو أي شيء آخر يُنتج JSON. راجع [بناء مكون إضافي](/docs/tutorials/build-a-plugin).

## سير العمل للمؤسسات

### 1. تقييم جودتك الحالية

```bash
# See what you're getting today
npx champollion status

# Output shows: method per pair, cache hit rate, quality gate stats
```

### 2. تشغيل أداة التقييم (eval harness) على الخيارات المرشحة

تتيح لك [أداة التقييم (eval harness)](/docs/network/specifications/harness) قياس كفاءة طرق متعددة مقارنةً بمجموعة البيانات نفسها. قم بإجراء اختبار شامل وقارن الدرجات واختر الطرق الفائزة:

```bash
# In the eval harness repo
python -m mt_eval_harness.run \
  --methods coached-v3 baseline prompt-tuned \
  --dataset data/your-corpus.json
```

### 3. تكوين الطرق الفائزة لكل زوج لغوي

حدّث ملف الإعدادات لاستخدام أفضل طريقة لكل زوج لغوي. فاللغات المختلفة تناسبها طرق مختلفة — وهذا هو الهدف الأساسي.

### 4. التكامل مع مسار CI/CD

```bash
# In your CI pipeline — pinned to the 0.5 line, so a new release never
# changes what the pipeline runs (the CI guide has the complete workflow)
npx --yes champollion@0.5 lint        # Catch hardcoded strings
npx --yes champollion@0.5 sync        # Translate what changed
npx --yes champollion@0.5 audit       # Fail if any locale is incomplete
npx --yes champollion@0.5 integrity   # Validate placeholder consistency
```

ثلاثة أوامر. صفر ترجمة يدوية. يلتقط مسار العمل النصوص المضمنة مباشرةً في الشيفرة (hardcoded strings)، ويترجمها بالطرق التي اخترتها، ويوقف عملية البناء (Build) إذا كان هناك أي محتوى مفقود أو تالف.

### 5. المراجعة الاحترافية (اختياري)

للمحتوى بالغ الأهمية والحساسية، يمكنك التصدير إلى تنسيق XLIFF للمراجعة البشرية:

```bash
npx champollion xliff export --locale ja --out translations.xliff
# → Send to your translation agency
# → Import corrections back:
npx champollion xliff import translations.xliff
```

ترجم الجزء الأكبر آليًا. ودع المراجعة البشرية للمسارات الحيوية. لا تدفع مقابل الوقت البشري إلا حيثما يهم ذلك حقًا.

## نموذج التكلفة

لا يتطلب champollion **أي اشتراك ولا يعتمد تسعيرًا لكل مستخدم (per-seat)**. واجهة سطر الأوامر (CLI) متوفرة المصدر بموجب ترخيص PolyForm Noncommercial 1.0.0 — وهي مجانية للاستخدام غير التجاري: الأبحاث، والتعليم، والجمعيات الخيرية، والمستشفيات والعيادات العامة، والجهات الحكومية، والمشاريع الشخصية. أما استخدامها لأغراض تجارية، مثل منتجات الشركات الربحية، فلا يغطيه هذا الترخيص. تحقق من [من يمكنه استخدام هذا](/docs/getting-started/who-may-use-this) قبل اعتماده. وعلاوة على ذلك، فإنك تدفع فقط مقابل استدعاءات واجهة برمجة تطبيقات (API) الترجمة:

| الحجم | Google Translate | نموذج لغوي كبير (Gemini Flash) | نموذج لغوي كبير (GPT-4o) |
|--------|-----------------|---------------------|---------------|
| 1,000 مفتاح × 5 لغات محلية | حوالي 0.50 دولار | حوالي 0.30 دولار (باقة مجانية) | حوالي 2.00 دولار |
| 10,000 مفتاح × 15 لغة محلية | حوالي 15 دولارًا | حوالي 8 دولارات | حوالي 60 دولارًا |
| 50,000 مفتاح × 30 لغة محلية | حوالي 75 دولارًا | حوالي 40 دولارًا | حوالي 300 دولار |

تعني ذاكرة الترجمة (Translation Memory) أنك تدفع فقط مقابل **المفاتيح المعدلة** في عمليات المزامنة اللاحقة. فإذا قمت بتحديث 10 سلاسل نصية من أصل 10,000، فستدفع مقابل 10 ترجمات فقط، وليس 10,000.

## مقارنة بأنظمة إدارة الترجمة (TMS)

| | champollion | Crowdin / Phrase / Locize |
|---|---|---|
| **التسعير** | مجاني للاستخدام غير التجاري ([من يمكنه استخدام هذا](/docs/getting-started/who-may-use-this)) + تكاليف API | 50–500 دولار/شهريًا + لكل مستخدم |
| **التقيد بمزوّد الخدمة** | لا يوجد — بدّل بين المزوّدين في ملف الإعدادات | مرتفع — البيانات مخزنة في سحابتهم |
| **اختيار الطريقة** | أي مزوّد، أي نموذج، لكل زوج لغوي | ما يقدمونه فقط |
| **التكامل مع CI/CD** | دعم أصيل ومن الدرجة الأولى (`lint → sync → audit`) | مكون إضافي / webhook |
| **طرق مخصصة** | نظام مكونات إضافية، ومكونات مجتمعية | غير مدعوم |
| **بوابة الجودة** | مدمجة (نظام كتابة خاطئ، تكرار، طول) | يتفاوت |
| **استضافة ذاتية** | نعم (LibreTranslate، وواجهة API مخصصة) | لا |

راجع [المقارنة الكاملة](/docs/guides/comparison) للحصول على التفاصيل.
