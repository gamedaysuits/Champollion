# مقارنة Champollion بغيرها

تشغل champollion فئة مختلفة عن معظم أدوات التوطين. إليك مقارنة صريحة.

## المشهد العام

تندرج معظم أدوات التوطين تحت واحدة من ثلاث فئات:

| الفئة | أمثلة | النموذج |
|----------|----------|-------|
| **منصات TMS السحابية** | Crowdin, Phrase, Locize, Tolgee | لوحة تحكم SaaS + مترجمون بشريون + اشتراك شهري |
| **أدوات استخراج المفاتيح** | i18next-scanner, FormatJS CLI | فحص الكود المصدري بحثاً عن استدعاءات دوال الترجمة |
| **محركات الترجمة عبر واجهة سطر الأوامر (CLI)** | **champollion** | تعمل داخل مشروعك، وتترجم الملفات مباشرة، ولا تتطلب حساباً سحابياً |

تُعد Champollion **محرك ترجمة عبر واجهة سطر الأوامر (CLI)** — حيث تترجم ملفات الترجمة (locale files) الخاصة بك مباشرةً باستخدام نهايات خلفية قابلة للتهيئة (نماذج لغوية كبيرة (LLMs)، Google Translate، إضافات مخصصة). لا توجد لوحة تحكم سحابية، ولا سير عمل للمترجمين البشريين، ولا رسوم شهرية.

## متى تستخدم Champollion

**تُعد Champollion خياراً مناسباً عندما:**

- ترغب في دمج الترجمة الآلية في مسار البناء (build pipeline) الخاص بك — وليس كسير عمل منفصل
- تحتاج إلى التحكم في الطريقة لكل لغة على حدة (LLM للبعض، Google Translate للبعض الآخر، وإضافات مخصصة للبقية)
- تترجم إلى لغات لا تغطيها واجهات برمجة التطبيقات (اللغات الأصلية، المهددة بالانقراض، المصطنعة)
- تريد مخرجات نصية حتمية (مقاطع لغة Cree، أو Klingon pIqaD، أو Tengwar)
- تريد التخلص من التبعية لمورد معين (vendor lock-in) والتبعيات السحابية
- كنت مطوراً مستقلاً أو فريقاً صغيراً لا يحتاج إلى لوحة تحكم TMS كاملة
- تريد تسليم الملفات بصيغة XLIFF للمترجمين المحترفين دون الحاجة لاشتراك سحابي

**يُعد نظام TMS السحابي خياراً أفضل عندما:**

- يكون لديك مترجمون بشريون محترفون يراجعون كل سلسلة نصية (سير عمل XLIFF في champollion أبسط من نظام TMS كامل)
- تحتاج إلى إدارة ذاكرة الترجمة وقواميس المصطلحات عبر مشاريع متعددة
- تحتاج إلى التحرير المرئي في السياق (معاينة الترجمات داخل واجهة المستخدم الخاصة بك)
- يكون لديك فريق كبير يحتاج إلى تحكم في الوصول بناءً على الأدوار (role-based access control)
- تحتاج إلى دعم لأكثر من 50 صيغة ملفات

## ما تقدمه Champollion ولا يقدمه غيرها

### 1. سجلات لغوية مخصصة (Custom Registers)

يحصل كل زوج لغوي على تعليمات نبرة مناسبة ثقافياً لنموذج LLM:

```json
{
  "de": {
    "register": "Standard professional register. Use Sie-form for formal address."
  },
  "tl": {
    "register": "Educated Manila Taglish. Use Tagalog as the primary language but keep technical terms in English."
  },
  "tlh": {
    "register": "Warrior's honor. OVS grammar. Use Marc Okrand vocabulary."
  }
}
```

لا توجد أداة أخرى تأتي مزودة بـ 47 سجلاً لغوياً مُعداً مسبقاً، أو تتيح لك تحديد سجلات مخصصة لكل مشروع.

### 2. محولات نصوص حتمية (Deterministic Script Converters)

تأتي Champollion مزودة بخمسة محولات نصوص مدمجة تعمل كخطافات ما بعد الترجمة (post-translation hooks) — دون الحاجة إلى نموذج LLM:

| اللغة (Locale) | التحويل | مثال |
|--------|-----------|---------|
| `crk` | SRO → مقاطع Cree | `nêhiyawêwin` → `ᓀᐦᐃᔭᐍᐏᐣ` |
| `sr` | لاتيني → سيريلي | `Beograd` → `Београд` |
| `tlh` | رومنة → pIqaD | `tlhIngan Hol` → (رموز pIqaD) |
| `x-elvish-s` | لاتيني → Tengwar | Sindarin → Tengwar (وضع Beleriand) |
| `x-kryptonian` | لاتيني → كريبتوني | استبدال الشفرات (يتطلب خطاً) |

هذه محولات تعتمد بالكامل على جداول البحث (lookup-table) — حتمية، وقابلة للتدقيق، وبلا أي خطر لهلوسة نماذج LLM.

### 3. حماية مدركة للمحتوى (Content-Aware Shielding)

عند ترجمة Markdown أو المحتوى الغني، تقوم Champollion بحماية:

- كتل الأكواد المحاطة بعلامات (` ``` `)
- الأكواد المضمنة (`` ` ` ``)
- الرموز القصيرة (shortcodes) الخاصة بـ Hugo (`{{</* */>}}`, `{{%/* */%}}`)
- متغيرات الاستيفاء (Interpolation variables) (`{{ .Count }}`, `{name}`, `{{t('key')}}`)
- كتل HTML الخام

يتم استبدال هذه العناصر برموز حارسة (sentinel tokens) من Unicode قبل الترجمة واستعادتها بعد ذلك. لا يرى نموذج LLM أبداً الكود الخاص بك، أو الرموز القصيرة، أو المتغيرات.

### 4. إضافات الطرق الموجهة (Coached Method Plugins)

بالنسبة للغات التي لا تغطيها واجهات برمجة التطبيقات (API)، يمكنك بناء طريقة ترجمة موجهة:

1. كتابة بيانات التوجيه اللغوي (القواعد النحوية، المفردات، الأمثلة)
2. حزمها كإضافة (plugin)
3. قياس أدائها مقابل الترجمات المرجعية باستخدام [أداة التقييم](https://github.com/gamedaysuits/Champollion)
4. تثبيتها في مشروعك باستخدام `champollion plugin install`

هذه هي الطريقة التي تتعامل بها champollion مع لغة Plains Cree — وكيف يمكنك التعامل مع أي لغة، بما في ذلك اللغات التي لم توجد بعد.

## الخلاصة

لا تُعد Champollion بديلاً عن Crowdin. إنها أداة مختلفة لسير عمل مختلف. إذا كنت بحاجة إلى مترجمين بشريين، فاستخدم نظام TMS. أما إذا كنت بحاجة إلى واجهة سطر أوامر (CLI) تترجم ملفاتك بأمر واحد وتمنحك تحكماً لكل لغة في الطرق، والنماذج، والسجلات اللغوية — فاستخدم champollion.
