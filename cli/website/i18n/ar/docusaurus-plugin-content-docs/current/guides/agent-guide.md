# دليل الوكيل: استخدام champollion

champollion هي أداة CLI تترجم ملفات الترجمة المحلية (locale files) لتطبيقك بأمر واحد. هذا الدليل مخصص لوكلاء الذكاء الاصطناعي (أو المطورين الذين يعملون مع وكلاء الذكاء الاصطناعي) الذين يرغبون في الانتقال من الصفر إلى ملفات ترجمة محلية مترجمة بسرعة.

:::tip[هل أنت على دراية بالأداة بالفعل؟]
إذا كنت تحتاج فقط إلى الأوامر، فانتقل مباشرةً إلى [مرجع CLI](/docs/reference/cli). وإذا كنت ترغب في إنشاء طريقة ترجمة وقياس أدائها، فراجع [دليل وكيل الشبكة](/docs/network/getting-started/agent-guide).
:::

---

## إعداد البيئة

```bash
# No global install needed — npx runs it directly
npx champollion sync
```

**المتطلبات:**
- Node.js 20.11+‎ (ESM أصلي)
- مفتاح API لمزود خدمة الترجمة الخاص بك

**إعداد مفتاح API** — يحتاج champollion إلى مفتاح واحد على الأقل اعتماداً على الطرق التي تستخدمها:

```bash
# Option 1: export (session only)
export OPENROUTER_API_KEY="sk-or-..."        # for llm / llm-coached methods
export GOOGLE_TRANSLATE_API_KEY="AIza..."    # for google-translate method

# Option 2: .env file in your project root (persistent, gitignored)
echo 'OPENROUTER_API_KEY=sk-or-...' > .env
```

يقرأ Champollion كلاً من `.env.local` و`.env` تلقائياً (الأولوية: `process.env` → `.env.local` → `.env`). احصل على مفتاح OpenRouter من [openrouter.ai/keys](https://openrouter.ai/keys).

## المزامنة الأولى

يكتشف Champollion تلقائياً ملفات الترجمة المحلية لديك، وتنسيقها (JSON أو TOML أو YAML)، ولغاتك المستهدفة:

```bash
npx champollion sync
```

**ما يحدث:**
1. تحميل `champollion.config.json` (أو الاكتشاف التلقائي للإعدادات)
2. فحص ملف الترجمة المحلية المصدر وتسطيح المفاتيح المتداخلة
3. المقارنة مع `.champollion.lock` (تجزئات SHA-256 للقيم المترجمة سابقاً)
4. التحقق من `.champollion/tm.json` للبحث عن ترجمات مخزنة مؤقتاً (ذاكرة الترجمة)
5. ترجمة **المفاتيح التي تغيرت أو المفقودة أو القديمة** فقط عبر الطريقة المحددة
6. تشغيل بوابة الجودة (5 عمليات تحقق) على كل ترجمة
7. كتابة الترجمات الناجحة في ملف الترجمة المحلية المستهدف
8. تحديث ملف القفل وذاكرة الترجمة (TM) المخزنة مؤقتاً

في عملية إعادة تشغيل نموذجية بعد تغيير مفتاح واحد، تقدم الخطوة 4 نحو 142 مفتاحاً من الذاكرة المؤقتة، وتقوم الخطوة 5 بترجمة مفتاح واحد فقط. ولهذا السبب تكون عمليات المزامنة اللاحقة سريعة وغير مكلفة.

## الإعدادات

أنشئ `champollion.config.json` في المجلد الجذري لمشروعك:

```json
{
  "inputLocale": "en",
  "pairs": {
    "en:fr": { "method": "llm-coached" },
    "en:ja": { "method": "google-translate" },
    "en:crk": { "method": "api", "endpoint": "http://localhost:3000/translate" }
  }
}
```

تستخدم مفاتيح الأزواج **نقطتين متعامدتين** (`en:fr`)، وليس شرطة — فالشرطات مخصصة لرموز الإعدادات الإقليمية مثل `es-MX`.

الحقول الأساسية:

| الحقل | الغرض | القيمة الافتراضية |
|-------|---------|---------|
| `inputLocale` | لغة المصدر | `en` |
| `languages` | اللغات المستهدفة (مصفوفة أو كائن) | `[]` |
| `pairs` | تجاوزات لكل زوج (مفاتيح `"src:tgt"`) مع تهيئة الطريقة | اختياري |
| `localesDir` | مسار وجود ملفات الترجمة المحلية | `./locales` |
| `model` | نموذج LLM لطرق `llm`/`llm-coached` | `google/gemini-3.8-flash` |
| `batchSize` | عدد المفاتيح لكل استدعاء API | 80 (لنماذج LLM)؛ يبلغ الحد الأقصى لـ Google Translate نحو 128 مقطعاً/طلب |
| `jsonConcurrency` | ترجمات اللغات المستهدفة المتوازية لمفاتيح JSON | 50 |
| `contentConcurrency` | استدعاءات API المتوازية لترجمة المحتوى | 48 (لوثائق Docusaurus)، و12 لـ (`contentDir`) |

المرجع الكامل: [التهيئة](/docs/getting-started/configuration)

## طرق الترجمة

| الطريقة | متى تُستخدم | التكلفة | مفتاح API المطلوب |
|--------|------------|------|---------------|
| **`llm`** | للأغراض العامة، وجيدة للغات ذات الموارد الوفيرة | لكل رمز (يعتمد على النموذج) | `OPENROUTER_API_KEY` |
| **`llm-coached`** | عندما تتوفر لديك قواعد نحوية/قاموس للغة المستهدفة | لكل رمز + سياق التوجيه | `OPENROUTER_API_KEY` |
| **`google-translate`** | اللغات ذات الموارد العالية التي يعمل معها Google Translate جيداً | 20 دولاراً لكل مليون حرف | `GOOGLE_TRANSLATE_API_KEY` |
| **`api`** | مسار معالجة مخصص مستضاف خلف نقطة نهاية HTTP | يحددها الخادم | لا يوجد (تتولى نقطة النهاية المصادقة) |
| **`plugin`** | طريقة مسبقة الحزم ومثبتة محلياً | متفاوتة | متفاوت |

التفاصيل: [طرق الترجمة](/docs/guides/translation-methods)

## بيانات التوجيه

بالنسبة لأزواج `llm-coached`، توجه بيانات التوجيه نموذج LLM بمعرفة لغوية واضحة وصريحة. أنشئ ملف توجيه:

```json title="coaching/fr.json"
{
  "grammar_rules": [
    "Use formal register (vous) for all UI text",
    "Adjectives agree in gender and number with the noun"
  ],
  "dictionary": {
    "dashboard": "tableau de bord",
    "settings": "paramètres"
  },
  "style_notes": "Prefer active voice. Avoid anglicisms."
}
```

أشر إليه في تهيئة الزوج لديك:

```json
"en:fr": { "method": "llm-coached", "coachingFile": "coaching/fr.json" }
```

تتحقق بوابة الجودة من ظهور مصطلحات القاموس بالفعل في المخرجات — وتُسجل الانتهاكات كتحذيرات `[TERM]`.

التفاصيل: [بيانات التوجيه](/docs/concepts/coaching-data)

## بوابة الجودة

تمر كل ترجمة عبر خمس عمليات فحص مؤتمتة قبل كتابتها على القرص:

| الفحص | ما يكتشفه | مثال |
|-------|----------------|---------|
| **فارغ/متروك** | لم يُرجع النموذج أي شيء | `""` |
| **صدى المصدر** | أرجع النموذج النص الإنجليزي المدخل دون تغيير | `"Welcome"` لليابانية |
| **حلقة الهلوسة** | تكرار ثلاثيات الحروف/الكلمات (trigrams) | `"Qo' Qo' Qo' Qo'"` |
| **تضخم الطول** | المخرجات تتجاوز 4 أضعاف طول المصدر (4 أضعاف بالضبط تنجح) | مصدر بطول 10 أحرف ← مخرجات بطول 50 حرفاً |
| **مطابقة نظام الكتابة** | نظام كتابة خاطئ للإعداد المحلي | نص لاتيني لإعداد محلي عربي |

تُسجل حالات الفشل مع البادئة `[GATE]`. لا توجد بدائل احتياطية صامتة — إذا فشلت الترجمة، يتم الإبلاغ عنها بدلاً من قبولها بصمت.

التفاصيل: [بوابة الجودة](/docs/concepts/quality-gate)

## ذاكرة الترجمة

يخزن Champollion الترجمات مؤقتاً في `.champollion/tm.json`، وتُفهرس حسب النص المصدر + الإعداد المحلي + الطريقة. وفي عمليات المزامنة اللاحقة، يتم تقديم المفاتيح غير المعدلة من الذاكرة المؤقتة — دون أي استدعاء لـ API، ودون أي تكلفة.

```
[TM] 142 key(s) served from cache
Translating 3 key(s) to French (llm)... [OK]
```

لتجاوز الذاكرة المؤقتة لتشغيل واحد: `npx champollion sync --no-tm`

التفاصيل: [ذاكرة الترجمة](/docs/concepts/translation-memory)

## الملفات المُولّدة

ينشئ Champollion عدة ملفات في مشروعك. تعرّف عليها حتى لا تحذفها دون قصد أو تدرج الملفات الخاطئة في سجل git:

| الملف | الغرض | Git؟ |
|------|---------|------|
| `.champollion.lock` | تجزئات SHA-256 لقيم المصدر المترجمة (لاكتشاف التغييرات)، بالإضافة إلى بيانات لكل إعداد محلي: ما كتبته المزامنة، والمفاتيح التي تركتها إعادة المحاولة معلقة، والمفاتيح المحتجزة بعد الرفض | **نعم** — يجب تضمينه |
| `.champollion-replaced-edits.jsonl` | الترجمات المعدلة يدوياً التي استبدلتها المزامنة، مع صياغتها الأصلية (تُكتب فقط عند حدوث ذلك) | **نعم** — يجب تضمينه |
| `.champollion-content.lock` | الأمر نفسه، ولكن لملفات محتوى Markdown/MDX | **نعم** — يجب تضمينه |
| `.champollion/` | دليل الحالة الداخلية (ذاكرة `tm.json` المؤقتة، وتصديرات XLIFF، والنسخ الاحتياطية) | **لا** — أضفه إلى gitignore؛ إذ يُعد `tm.json` ذاكرة مؤقتة محلية (راجع [التهيئة](/docs/getting-started/configuration)) |
| ملفات التوجيه التي تؤلفها (مثل `coaching/fr.json`) | معرفتك اللغوية | **نعم** — يجب تضمينها |
| `champollion.config.json` | تهيئة المشروع | **نعم** — يجب تضمينه |

## الأنماط الشائعة

**ترجمة جميع الأزواج المحددة في التهيئة:**
```bash
npx champollion sync
```
يترجم Champollion جميع الإعدادات المحلية بالتوازي. ومع التخزين المؤقت في ذاكرة الترجمة (TM)، لا تصل إلى API إلا المفاتيح التي تغيرت فقط (يتم تقديم الأزواج غير المعدلة من الذاكرة المؤقتة، مما يجعل المزامنة الكاملة منخفضة التكلفة).

**ترجمة أزواج محددة فقط:**
```bash
npx champollion sync --pair en:fr          # one pair
npx champollion sync --pair en:fr,en:de    # comma-separated list
```
يُقصر خيار `--pair` التشغيل على الزوج (أو الأزواج) المسمى فقط؛ وتنطبق فحوصات الجاهزية والإنفاق على تلك الأزواج فقط. تسمية زوج غير موجود في مخطط الأزواج المهيأة يفشل صراحةً مع عرض قائمة بالأزواج المهيأة — دون حدوث تجاهل صامت للعملية على الإطلاق.

**طريقة كتابة الزوج.** يُكتب زوج المشروع بالطريقة التي يحدد بها `champollion.config.json` مفاتيحه، أي `en:fr`. وتقرأ الأوامر `sync` و`verify` و`serve` أيضاً `en>fr` و`en-fr`، وتُطابق `en-pt-BR` مع الأزواج التي قمت بتهيئتها. وتكتب أوامر الشبكة (`network register-corpus`، `leaderboard`، `recommend`، `submit`) الزوج بالصيغة `eng>crk`، وهي الصيغة التي تخزنها لوحة الصدارة، وتقرأ `eng-crk` و`eng:crk` بالطريقة ذاتها. وهناك، يجب أن يتكون الزوج الذي يحتوي على شرطات فقط من رمزين يتألف كل منهما من حرفين أو ثلاثة أحرف (`eng-crk`). أما الرمز الذي يحتوي على شرطة خاصة به فيتطلب `>`: `--pair "eng>pt-BR"`. ويمكن أن يعني `eng-pt-BR` أيضاً `eng-pt` و`BR`، لذلك يتم رفضه ولا يتم تخمينه أبداً. في سطر الأوامر، ضع صيغة `>` بين علامتي اقتباس: `--pair "eng>crk"`. وبدون علامات اقتباس، سيوجه سطر الأوامر المخرجات إلى ملف باسم `crk`.

**وضع المحتوى (مجلد ملفات Markdown/MDX: مجلد Hugo `content/` أو أي مجلد آخر؛ ويتم العثور على وثائق Docusaurus بدونه):**
```bash
npx champollion sync --content-dir ./content
```
يترجم الوثائق ومقالات المدونة وملفات المحتوى إلى جانب ملفات JSON للإعدادات المحلية. تُكتب كل ترجمة بجانب ملفها المصدري باسم `<name>.<locale>.md`؛ ويتم الاحتفاظ بالتعديلات التي يُجريها المراجع عليها عندما يتغير المصدر في مكان آخر ([ترجمة المحتوى](/docs/guides/content-translation#reviewing-and-editing-translations)). تعمل ترجمة المحتوى بالتوازي؛ ويمكن ضبطها باستخدام `--content-concurrency`.

**تشغيل تجريبي (معاينة بدون كتابة):**
```bash
npx champollion sync --dry-run
```

**فرض إعادة ترجمة مفاتيح محددة:**
```bash
npx champollion sync --force-keys "hero.title,nav.about"
```

**إعادة معالجة جميع ملفات المحتوى (يُعاد استخدام النص المخزن مؤقتاً، لذا فالنص غير المتغير مجاني):**
```bash
npx champollion sync --force-content
```

**ترجمة ملفات محتوى محددة من جديد (مدفوعة)، أو قصر التشغيل على بعض الملفات:**
```bash
npx champollion sync --retranslate docs/intro.md
npx champollion sync --files "docs/guides/**"
```

**تشغيل قابل للقراءة آلياً:** يكتب `--json` كائن JSON واحداً في كل سطر (NDJSON)، يحتوي كل منها على `level`: على stdout رسائل `info` و`ok`، وسجلات `event` (`"event": "cost"` — التقدير، قبل بوابة `--max-cost` — وسجل `"event": "file"` واحد لكل ملف محتوى وإعداد محلي)، وفي النهاية ملخص الختام `{"level": "summary", "command": "sync", …}`؛ وعلى stderr أسطر `warn` و`error` بتنسيق JSON أيضاً. حدد الملخص حسب مستواه، وليس حسب موضع السطر بمفرده أبداً: `npx champollion sync --dry --json 2>/dev/null | jq -c 'select(.level == "summary")'`. يشير رمز الخروج `2` إلى اكتمال جزئي (تم إنجاز بعض العمل وفشل جزء آخر).

في التقدير (الحدث `cost`، و`costEstimate` في الملخص)، تكون قيمة `totalEstimatedCost` هي `null` كلما كان هناك أي جزء ليس له سعر معروف — ولا يكون أبداً مجموعاً جزئياً، ولا يُعيّن `0` للمجهول؛ يحتوي `knownEstimatedCost` على الجزء المحدّد سعره، ويحدد `unknownCost.reason` الأزواج التي ليس لها سعر، ويوضح `unknownCost.notes` ما الذي يفتقر إلى سعر ولماذا — `{ subject, pairs, note }`، مثل اسم نموذج غير موجود في قائمة OpenRouter (وهو خطأ إملائي محتمل، مع إيراد أقرب الأسماء المدرجة)، أو نموذج مدرج لا يتضمن سعراً لكل رمز، أو قائمة أسعار تعذرت قراءتها. النموذج الموجود على هذا الجهاز (نقطة نهاية `local` أو `api` عند `localhost`/`127.0.0.1`/`::1`) يُسعّر بـ `0` مع `"local": true`. يَعُد حقل `sentToModel` في الملخص المفاتيح التي تم إرسالها إلى الطريقة خلال هذا التشغيل (`tmHits`: تم تقديمها من الذاكرة المؤقتة). يحمل ملخص التشغيل التجريبي الحقل `preflight: { ready, failures }` — وتعني القيمة `ready: false` أن التشغيل الفعلي كان سيتوقف ويخرج بالرمز `1` (مفتاح مفقود، أو خادم نموذج يتطلبه التشغيل ولا يستجيب)، على الرغم من أن التشغيل التجريبي نفسه يخرج بالرمز `0` ([رموز الخروج](/docs/reference/cli#sync-exit-codes)). ومع `--max-cost` يحمل أيضاً `maxCost: { cap, estimatedCost, wouldStop }` — وتعني القيمة `wouldStop: true` (مع `exitCode: 2` و`reason`) أن التشغيل الفعلي كان سيتوقف عند الحد الأقصى قبل أي استدعاء لـ API. القيمة `realRun: { exitCode, wouldStop, reasons }` هي رمز الخروج الذي سينتهي به التشغيل الفعلي، وفقاً لما يمكن للمعاينة معرفته: التحقق الأولي (preflight) والحد الأقصى (cap)، بالإضافة إلى ما يجعله جزئياً — المفاتيح المحتجزة، ورسائل الجمع الموجودة على القرص دون صيغة تستخدمها اللغة ولن يطلبها مرة أخرى (المحسوبة في `totalPluralGaps` للتشغيل التجريبي). لا يتحقق التشغيل التجريبي من أي شيء (`verify: { "ran": false }`). نفّذ التشغيل التجريبي باستخدام `--method`/`--model` الخاصين بالتشغيل الفعلي: فبدونهما سيتحقق من الطريقة المحددة في التهيئة.

**التحقق من حالة الترجمة:**
```bash
npx champollion status
```
يعرض طريقة كل زوج ونموذجه ونسبة التغطية ومعلومات الإضافة (يظهر `qualityTier` فقط عندما تحدده التهيئة — وهي تسمية توضيحية وليست مقياساً).

**تدقيق القيم الاحتياطية غير المترجمة:**
```bash
npx champollion audit
```
يسرد جميع قيم `[EN]` الاحتياطية التي تحتاج إلى ترجمة.

## استكشاف الأخطاء وإصلاحها

| المشكلة | الحل |
|---------|-----|
| `OPENROUTER_API_KEY not set` | قم بتصدير المفتاح أو إضافته إلى `.env` في المجلد الجذري لمشروعك |
| `No locale files found` | عيّن `localesDir` في التهيئة، أو تأكد من أن ملفات الترجمة المحلية تطابق التسمية القياسية (`en.json`، `fr.json`) |
| `[GATE] Script compliance failed` | استلم الإعداد المحلي المستهدف نصاً لاتينياً بدلاً من نظام الكتابة المتوقع — جرب نموذجاً مختلفاً أو أضف بيانات توجيه |
| `[GATE] Source echo` | أرجع النموذج النص الإنجليزي دون تغيير — عادةً ما تؤدي إضافة بيانات توجيه أو استخدام نموذج مختلف إلى إصلاح ذلك |
| جميع الترجمات مخزنة مؤقتاً | شغّل مع `--no-tm` لتجاوز الذاكرة المؤقتة، أو `--force-keys` لمفاتيح محددة |
| تعارضات ملف القفل | يحتوي `.champollion.lock` على قيم تجزئة — من الآمن حل تعارض الدمج بالاحتفاظ بأي من النسختين، ثم إعادة تشغيل المزامنة. قد يؤدي الاحتفاظ بسجل الإعداد المحلي للطرف الآخر إلى قراءة بعض القيم على أنها معدلة يدوياً (وعندها ستحتفظ بها عملية إعادة التنفيذ الجماعية وتذكر أسماءها؛ بينما يستبدل `--redo keys:` واحدة منها) — ولا يحدث العكس أبداً |
| مفاتيح "محتجزة" | رفضت بوابة الجودة إجابة ذلك النموذج من قبل؛ والمزامنة العادية لا تعيد إرسالها (حتى لا تُحسب تكلفة الإجابة نفسها مرة أخرى). يطلب `champollion sync --redo keys:<key>` الترجمة مجدداً؛ أو يمكنك إضافة `fallback`، أو إدراجه في `noTranslate`، أو كتابته يدوياً |
