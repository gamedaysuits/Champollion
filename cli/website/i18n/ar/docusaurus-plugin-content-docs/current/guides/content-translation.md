# ترجمة المحتوى (Markdown)

يترجم Champollion ملفات Markdown وMDX، بما في ذلك حقول front matter والمتن. وتتم حماية كتل التعليمات البرمجية والأكواد القصيرة (shortcodes) والعناصر المهيكلة الأخرى من الترجمة.

توجد الملفات في **دليل المحتوى** (`contentDir`). يمكن أن يكون ذلك أي مجلد يحتوي على ملفات Markdown: مثل `content/` في موقع Hugo، أو مجلد للنشرات الإخبارية داخل تطبيق Next.js. يختلف موقع Docusaurus (الموقع الذي يحتوي على `docusaurus.config.js`): إذ تُترجم ملفات `docs/` و`blog/` الخاصة به إلى مجلدات `i18n/<locale>/` دون `contentDir`. راجع [تكامل أطر العمل](/docs/guides/framework-integration).

## الإعداد

قم بتعيين `contentDir` في ملف التكوين الخاص بك، أو مرّر `--content-dir` عبر سطر الأوامر:

```json title="champollion.config.json"
{
  "version": 3,
  "inputLocale": "en",
  "localesDir": "./messages",
  "contentDir": "./newsletters"
}
```

```bash
npx champollion sync                              # translates string files and content files
npx champollion sync --content-dir ./newsletters  # same, folder given on the command line
```

في بداية عملية التشغيل، يحدد أمر sync اسم المجلد ويوضح أين ستستقر الترجمات:

```
[INFO] Content directory: newsletters — a folder of Markdown/MDX files (no Hugo site found); each translation is written beside its source as <name>.<locale>.md
```

في موقع Hugo، فإنه يذكر أيضاً الأدلة التي عثر عليها، مثل `Detected framework: Hugo (hugo.toml)`. يُعتبر Hugo موجوداً عند توفر ملف `hugo.toml`/`.yaml`/`.yml`/`.json`، أو مجلد `config/_default/` الخاص بـ Hugo، أو `config.toml` أو `config.yaml` مع إعداد خاص بـ Hugo حصراً مثل `baseURL`، أو مجلد `archetypes/`، أو مجلد `layouts/` لقوالب Hugo. سواء كان Hugo أم لا، تُترجم الملفات وتُسمى بالطريقة نفسها.

## مسار حفظ الترجمات

تُكتب كل ترجمة **بجوار ملف المصدر الخاص بها**، مع إضافة اللغة المحلية المستهدفة قبل الامتداد. هذا هو أسلوب التسمية المعتمد للترجمة في Hugo:

```
newsletters/2026-10.md      → newsletters/2026-10.crk.md
newsletters/2026-10.md      → newsletters/2026-10.fr.md
posts/launch.mdx            → posts/launch.crk.mdx       (.mdx stays .mdx)
posts/launch.en.md          → posts/launch.crk.md        (the source-language suffix is dropped)
```

يتم البحث في المجلدات الفرعية أيضاً، وتبقى كل ترجمة في مجلد المصدر الخاص بها. يختار تطبيقك الملف المناسب للغة معينة بناءً على ذلك الاسم. على سبيل المثال، تقرأ صفحة Next.js الملف `newsletters/2026-10.crk.md` للغة كرِي السهول (Plains Cree).

**الملفات التي تُعتبر مصادر.** كل ملف `.md` و`.mdx` في المجلد يُعد مصدراً، ما لم ينتهِ اسمه بـ `.<code>.md` (أو `.mdx`) وكان `<code>` يبدو كرمز لغة. يتكون رمز اللغة هنا من حرفين أو ثلاثة أحرف صغيرة، يتبعها اختيارياً نظام كتابة مثل `-Hant` و/أو منطقة مثل `-BR` أو `-419`. تُعتبر تلك الملفات ترجمات ويتم تخطيها. تظل اللاحقة الخاصة بلغة المصدر (`launch.en.md`) تُحتسب كمصدر. فخ يجب الانتباه له: الملف المصدر المسمى مثل `guide.faq.md` ينتهي أيضاً بلاحقة من حرفين إلى ثلاثة أحرف، وبالتالي يُعامل كترجمة إلى "faq" ولا تتم ترجمته. أعد تسميته، على سبيل المثال إلى `guide-faq.md`.

## ما يتم ترجمته

### الـ Front Matter

يتم دعم كل من محددات YAML (`---`) وTOML (`+++`). بشكل افتراضي، تتم ترجمة هذه الحقول:

- `title`
- `description`
- `summary`
- `subtitle`
- `caption`
- `linkTitle`
- `sidebar_label`

يتم نسخ جميع الحقول الأخرى (`date`، `draft`، `tags`، `weight`، `slug`، إلخ) من المصدر كما هي. يمكنك تعديل هذه القائمة باستخدام `translatableFields` في ملف التكوين.

### محتوى المتن

بشكل افتراضي، يتم تقسيم المتن إلى فقرات وكتل أساسية أخرى، وتتم ترجمة كل كتلة على حدة. تُحمى العناصر المهيكلة باستخدام عناصر نائبة قبل الترجمة وتُستعاد بعدها. عند استخدام `contentSegmentation: "page"`، يُترجم المتن كقطعة واحدة.

## حماية الكتل

تمر هذه العناصر عبر عملية الترجمة دون أي تغيير:

| العنصر | مثال | الحماية |
|---------|---------|-----------|
| كتل التعليمات البرمجية | ``````` ```js ... ``` ``````` | حماية الكتلة بالكامل |
| الكود المضمن | `` `variable` `` | محمي |
| أكواد Hugo القصيرة | `{{< figure >}}`، `{{% note %}}` | حماية الكتلة بالكامل |
| كود HTML الخام | `<div>`، `<table>` | محمي |
| الروابط (URLs) | `[text](https://...)` | الحفاظ على الرابط مع ترجمة النص |
| الاستيفاء (Interpolation) | `{{ .Count }}` | محمي |

## عند إعادة ترجمة ملف

تسجل أداة sync بصمة تعريفية (SHA-256) لكل ملف مصدر في `.champollion-content.lock`. قم بإيداع (commit) هذا الملف مع ترجماتك.

- **المصدر لم يتغير:** لا يتم المساس بالترجمة.
- **المصدر تغير:** يتم تحديث الملف. الفقرات التي لم يتغير نصها الإنجليزي تُجلب من [ذاكرة الترجمة (Translation Memory)](/docs/concepts/translation-memory) دون أي تكلفة، وبذلك تدفع فقط مقابل الفقرات التي طرأ عليها تغيير.
- **ملف ترجمة بدون إدخال في ملف القفل** (ملف قمت بكتابته يدوياً) يتم الإبقاء عليه كما هو وتسجيله على أنه خاص بك. الاستثناء الوحيد هو الملف الذي لا يزال يحتوي على علامات `[EN] ` المكتوبة بواسطة إصدار CLI أقدم من 0.5.0، حيث يُعاد ترجمته.
- **الكتلة التي رفضتها بوابة الجودة، حتى بعد إعادة طلبها مع ذكر السبب،** تحتفظ بنص المصدر الخاص بها، دون وضع أي علامة على الصفحة. يظهر إدخال القفل الخاص بالصفحة بالحالة `pending:<hash>`، ويتم تسجيل الرفض في `.champollion-content.lock`. عمليات المزامنة اللاحقة لن ترسل تلك الكتلة إلى النموذج نفسه مجدداً، وبالتالي لن تُحسب تكلفتها مرة أخرى. تسرد كل من `status` و`verify` هذه الصفحة. أعد المحاولة باستخدام `--redo files:<page>`، أو أضف طريقة `fallback`، أو اكتب الفقرة بنفسك (حيث سيتم الاحتفاظ بها). يحافظ حقل front-matter المرفوض على نص المصدر بالطريقة نفسها، ويُكتب باقي محتوى الصفحة. راجع [كتل Markdown وحقول front-matter المرفوضة](/docs/concepts/quality-gate#refused-markdown-blocks-and-front-matter-fields).

لإعادة ترجمة ملف عن قصد، حدد اسمه. المسار المطلوب هو نفس المسار الذي يطبعه أمر sync، بالنسبة إلى دليل المحتوى:

```bash
npx champollion sync --redo files:2026-10.md          # rebuild from the cache (free for unchanged text)
npx champollion sync --redo files:2026-10.md --fresh  # translate it again from scratch (paid again)
```

## مراجعة الترجمات وتعديلها {#reviewing-and-editing-translations}

يمكن للمراجع تصحيح محتوى Markdown المترجم مباشرة في الملف المترجم. ويحتفظ Champollion بتلك التصحيحات عند تغيير المصدر لاحقاً.

1. شغّل `champollion sync` وقم بإيداع (commit) الترجمات مع `.champollion-content.lock`.
2. يفتح المراجع الملف المترجم، مثل `newsletters/2026-10.crk.md`، ويقوم بتعديله. يمكنه تغيير أي فقرة، أو أي حقل front-matter مترجم مثل `title` أو `description`.
3. يقوم المراجع بإيداع الملف. لا يلزم أي أمر لـ "قبول" التعديلات.

ما يحدث للتعديلات في عملية `champollion sync` التالية:

| الحالة | ما يفعله أمر sync |
|---|---|
| لم يتغير المصدر | لا شيء. تظل الترجمة كما تركها المراجع تماماً. |
| تغير المصدر في فقرات **أخرى** | يتم **الاحتفاظ بفقرات وحقول المراجع حرفياً** وتتم ترجمة الفقرات التي طرأ عليها تغيير. يوضح تقرير التشغيل ذلك، على سبيل المثال `kept the edits made by hand to 1 paragraph(s) of 2026-10.crk.md`. تظل نصوص المراجع ملكاً له في كل عملية مزامنة لاحقة. |
| فقرة المصدر التي عدّلها المراجع قد تغيرت **هي الأخرى** | يُعاد ترجمة تلك الفقرة، لأن نسخة المراجع تُترجم نصاً إنجليزياً لم يعد له وجود. يطبع تقرير التشغيل تحذيراً يحتوي على صياغة المراجع، ليتمكن من إعادة تطبيقها إذا كانت لا تزال ملائمة. |
| قام المراجع بإضافة فقرات أو حذفها أو دمجها، أو أن الزوج اللغوي يستخدم `contentSegmentation: "page"` | لا يمكن مطابقة التعديلات فقرة بفقرة. عند تغيير المصدر، يُترك الملف **كما هو تماماً**، ويُصدر كل إجراء مزامنة تحذيراً ويدرجه في القائمة حتى تتم معالجته. يمكنك إما تحديثه يدوياً (وعندئذ تعتبر عملية المزامنة التالية الملف المُعدل هو النسخة الحالية)، أو استبداله بالترجمة الآلية باستخدام `--redo files:<path>`. |

التعديلات التي تُجرى على كتل الأكواد البرمجية، والمسافات البيضاء بين الفقرات، وحقول front-matter غير المترجمة (`date`، `tags`، وهكذا) لا يتم الاحتفاظ بها عند إعادة كتابة الملف. تأتي تلك الأجزاء دائماً من المصدر.

**استبدال التعديلات عمداً.** لا يتم استبدال التعديلات إلا عند تحديد اسم الملف صراحة. يُعيد `--redo files:2026-10.md` الترجمة الآلية المخزنة مؤقتاً. بينما يقوم `--redo files:2026-10.md --fresh` (أو `--retranslate 2026-10.md`) بإعادة الترجمة من البداية. أي تشغيل يعيد معالجة كل المحتوى دون تحديد أسماء ملفات (`--redo content`، `--force-content`) يحتفظ بالتعديلات.

**كيفية التعرف على التعديلات.** في كل مرة يكتب فيها أمر sync ترجمة، فإنه يسجل أيضاً في `.champollion-content.lock` بصمة تعريفية قصيرة لكل فقرة كتبها. والفقرة الموجودة على القرص والتي لم تعد متطابقة تُعد قد عُدلت بواسطة شخص. إذا فُقد ملف القفل، فلن يمكن التعرف على التعديلات، لذا احرص على حفظه في نظام التحكم في الإصدارات (version control). يتم تسجيل الترجمة المكتوبة بواسطة إصدار أقدم من Champollion في عملية المزامنة التالية. وإذا كانت تعديلاتك عليها تختلف عما تحتفظ به ذاكرة الترجمة، فسيتم التعرف عليها على أنها تعديلاتك.

لا يتم حفظ نص المراجع مطلقاً في ذاكرة الترجمة كمخرجات آلية.

:::note[تنسيق XLIFF يغطي ملفات السلاسل النصية فقط]
يقوم `champollion xliff export` بتمرير **ملفات السلاسل النصية** الخاصة بتطبيقك (المفاتيح والقيم) إلى أداة الترجمة بمساعدة الحاسوب (CAT) الخاصة بالمترجم. راجع [العمل مع المترجمين المحترفين](/docs/guides/professional-translators). لا يتوفر تصدير XLIFF لمحتوى Markdown حتى الآن، لذا تتم مراجعة محتوى Markdown المترجم داخل الملفات نفسها، كما هو موضح أعلاه.
:::

## طرق خاصة بـ Markdown فقط

:::warning[ترجمة Google وMarkdown]
ترجمة Google **ليست على دراية** بكتل التعليمات البرمجية، أو الأكواد القصيرة (shortcodes)، أو متغيرات الاستيفاء. وستؤدي إلى إتلاف محتوى Markdown المهيكل. استخدم طرق نماذج اللغة الكبيرة (LLM) (`llm` أو `llm-coached`) لترجمة المحتوى، لأنها تحمي العناصر المهيكلة بشكل صريح.
:::

عندما تتراجع ترجمة المحتوى من ترجمة Google إلى إحدى طرق نماذج اللغة الكبيرة (LLM)، يسجل champollion تحذيراً يوضح السبب.
