# بناء ترجمة آلية للغتك

تأخذك هذه الصفحة من تساؤل *"نريد ترجمة للغتنا — كيف نبدأ؟"* إلى سير عمل ترجمة قمت **بقياسه على جملك الخاصة** وبدأت العمل به. كُتب هذا الدليل للبشر ووكلاء الذكاء الاصطناعي (AI agents): توفر كل خطوة الأمر البرمجي للتشغيل، وحيثما وُجدت، [أداة MCP](/docs/network/getting-started/mcp-server) التي يستدعيها الوكيل بدلاً من ذلك.

مثالان عمليان متتابعان:

- **مدرسة** تريد الترجمة من الإنجليزية إلى لغة كري السهول (Plains Cree) لنشرتها الإخبارية وتطبيق صغير. راجع المعلمون بضع مئات من الجمل ويريدون الحفاظ على خصوصيتها.
- **مستشفى** يريد الترجمة من الإنجليزية إلى لغة بالكاد يغطيها الفهرس، لاستخدامها في كتيب عبارات عند أسرة المرضى. تحتوي جُمل الاختبار على صياغات سريرية ويجب عدم إرسالها إطلاقاً إلى أي خدمة ذكاء اصطناعي خارجية.

ستصل في النهاية إلى: مجموعة اختبار خاصة، ودرجات تقييم لطرق متعددة عليها، وطريقة أفضل (نموذج مُدرَّب بالتوجيه أو نموذج دربته بنفسك)، ونشر هذه الطريقة عبر واجهة سطر الأوامر (CLI) — مع إمكانية تتبع كل رقم ومعرفة ما أنتجه.

:::info[ما لا يفعله هذا الدليل]
لا يوجد شيء هنا يجعل الترجمة صحيحة تلقائياً. تخبرك درجات التقييم بأي الخيارات هو *الأقل خطأً على جُملك*؛ ويبقى المتحدث الطليق هو من يقرر ما هو صالح للاستخدام. اقرأ [القيود الصادقة](/docs/network/honest-limitations) قبل الاعتماد على أي رقم.
:::

:::warning[للوكلاء: قبل فتح أي من ملفات المستخدم]
إذا كانت مجموعة الاختبار خاصة محتملة (راجعها معلمون، أو راجعها ممرضون، أو أي بيانات لم ينشرها المجتمع)، فلا تقرأها — لا `cat` ولا `head` ولا معاينة، ولا حتى للاطلاع على تنسيقها. فكل ما تقرأه يُرسل إلى مزود النموذج الخاص بك. اسأل المستخدم، وعيّن الملف كملف محلي فقط أولاً ([الخطوة 2](#2-gather-your-data--and-protect-your-test-set)).
:::

## 0. التثبيت

```bash
npm install -g champollion        # translate + deploy        (Node 20.11+)
python3 -m pip install mt-eval-harness       # measure                   (Python 3.11+)
python3 -m pip install 'nmt-forge[hf]'       # train a model (optional; a CPU is enough to start)
```

بالنسبة للوكيل، أضف خادم MCP إلى إعداداته:

```json
{
  "mcpServers": {
    "champollion": { "command": "npx", "args": ["-y", "champollion-mcp-server"] }
  }
}
```

## 1. اكتشف ما هو موجود بالفعل

ما هو معروف بالفعل عن اللغة — القواميس، وقواعد النحو، والمدونات اللغوية (corpora)، والمحللات الصرفية (FSTs)، والنماذج، والنتائج المنشورة، والخدمات — ومصدر كل معلومة.

```bash
champollion network card crk                 # the cited language card
champollion network recommend eng crk        # methods you can run, with the evidence for each
mt-eval corpora --source eng --target crk   # registered test sets for the pair
nmt-forge discover crk               # what a training project can use
```

**الوكيل:** تعثر `search_languages { "query": "Atya" }` على الرمز حتى في حال وجود خطأ إملائي (أقرب الأسماء حسب مسافة التعديل edit distance). تبيّن كل نتيجة مكان التحدث باللغة فقط عندما تستشهد بطاقتها بمصدر لذلك، وتعرض ذلك المصدر حتى يتمكن المستخدم من الاختيار بين اللغات ذات الأسماء المتشابهة. لا يتم عرض أي موقع بدون مصدر إطلاقاً: يوضح السطر ذلك ويضع رابطاً لسجل اللغة على Glottolog بدلاً من ذلك، حيث يمكن مقارنة الخيارات المرشحة عند المصدر. وعند التثبيت عبر npm، تُستكمل أي لغة خارج المجموعة الأساسية المضمنة من جداول البطاقات المنشورة على champollion.dev، والتي لا تحمل مصادر لكل حقل بعد (ستتوفر مع التحديث التالي للجداول)، لذا يحتوي سطرها على رابط Glottolog بدلاً من الموقع الجغرافي. وعندما لا يظهر ما يميز المرشحين عن بعضهم، فإن المتحدثين هم من يقررون (أدناه). بعد ذلك، تقدم `language_overview { "code": "<code>" }` صفحة واحدة: ما هو موجود، وما هي المعايير والنتائج المتوفرة، والخطوات التالية المرقمة. وأي أداة تقبل لغة واحدة تقبلها أيضاً كـ `language`.

اقرأ البطاقة كما هي مكتوبة: **الغياب يعني أنه غير معروف، وليس صفراً.** البطاقة التي لا تدرج أي قاموس تعني أن الفهرس لم يسجل قاموساً — وليس أنه لا يوجد قاموس إطلاقاً. وحيثما تختلف المصادر (كما هو الحال غالباً في أعداد المتحدثين)، تعرض البطاقة جميع تلك المصادر.

إذا لم تكن للغتك بطاقة على الإطلاق، فلا يزال بإمكانك القيام بكل ما هو مذكور أدناه؛ فقط ستعرف الأدوات معلومات أقل عنها (تبدأ `nmt-forge init <code> --no-card --name <name>` مشروع تدريب على أي حال).

### عندما لا يكون التنويع اللغوي (variety) مؤكداً بعد

يمكن للاسم الواحد أن ينطبق على عدة لغات. "Ayta"، على سبيل المثال، يطابق ست لغات من لغات Ayta في الفلبين، ولكل منها رمزها الخاص. **اسأل المتحدثين أولاً.** فالمجتمع يعرف أي تنويع لغوي يتحدث، واختيار رمز نيابة عنهم هو بمثابة ادعاء بشأنهم.

إذا كان لا بد من البدء قبل أن يتمكنوا من الإجابة، فاستخدم رمزاً للاستخدام الخاص: يحجز معيار ISO 639 النطاق من `qaa` إلى `qtz` لهذا الغرض تحديداً. امنحه اسماً للعرض، حتى تذكر المطالبات والتقارير اسم اللغة:

```bash
champollion init --yes --langs qaa --name qaa="Ayta (variety not yet confirmed)"
```

وهو ما يُكتب في `champollion.config.json`:

```json
"languages": { "qaa": { "name": "Ayta (variety not yet confirmed)" } }
```

توضح `init` أن الرمز مخصص للاستخدام الخاص ولا يملك بطاقة لغة (ولا تطلب منك التحقق من الإملاء).

تقبل كل من `init` و`sync` و`verify` و`network register-corpus` رمز الاستخدام الخاص. ما تخسره مقابل ذلك، حتى يحل الرمز الحقيقي محله:

- **غياب حقائق البطاقة.** لا توجد إعدادات مسبقة لمستوى الخطاب (register presets)، أو قواعد للجمع، أو نظام كتابة من بطاقة اللغة. ستستخدم المزامنة (sync) إعدادات عامة، لذا تحقق من النتائج الأولى مع متحدث باللغة.
- **غياب المحلل الصرفي (FST).** لا يرتبط أي محلل صرفي برمز الاستخدام الخاص، لذا لن يتم فحص أي شيء كلمة بكلمة.
- **غياب النتائج السابقة.** المعايير المنشورة وقائمة الانتظار مفهرسة بالرموز الحقيقية، لذا لن يكون لدى `recommend` و`corpora` ما يعرضانه بشأنه.

عندما يؤكد المجتمع التنويع اللغوي، انتقل إلى رمزه:

1. في `champollion.config.json`، استبدل `qaa` بالرمز (واحذف `name` إذا كان اسم البطاقة مناسباً).
2. أعد تسمية ملفات اللغات المدعومة (locale) (`messages/qaa.json` ← `messages/ayt.json`). تظل الترجمات صالحة: حيث يحتفظ بها أمر `champollion sync` التالي ويترجم الجديد فقط.
3. سجّل مجموعة الاختبار مجدداً تحت الزوج اللغوي الحقيقي:
   `champollion network register-corpus --pair "eng>ayt" --data <file> --role test …`.
   يطبع الأمر خيار `--id` لتمريره، لأن الملف المسجل يحتفظ بمعرّفه ما لم تختر معرّفاً جديداً. (يقبل `--pair` الصيغة `eng-ayt` أو `"eng>ayt"` هنا وفي `nmt-forge init`؛ ضع صيغة `>` بين علامتي اقتباس، لأن سطر الأوامر (shell) يفسر `>` المجردة كأمر "كتابة إلى ملف").

## 2. اجمع بياناتك — واحمِ مجموعة الاختبار الخاصة بك

**افصل مجموعة الاختبار أولاً.** ضع جانباً الجمل التي ستحكم من خلالها على كل شيء (تلك التي راجعها المعلمون، أو التي راجعها الممرضون) قبل أن تدرب أو تضبط أي شيء، وإياك أن تدرب النموذج عليها.

مجموعة الاختبار هي ملف TSV: زوج جُمل واحد في كل سطر، المصدر، ثم علامة جدولة (TAB)، ثم الترجمة المرجعية. وتُعد الأسطر التي تبدأ بـ `# ` تعليقات.

```text
# teacher-checked, 2026 term 1
The library opens at nine.	<the teacher's translation>
```

ثم قرر إلى أي مدى يُسمح لهذه البيانات بالانتقال:

| إذا كنت تريد... | افعل هذا |
|---|---|
| ألا يغادر أي شيء هذا الجهاز — ولا يجوز لأي خدمة ذكاء اصطناعي خارجية رؤية هذه الجمل إطلاقاً | ضع ملف علامة (marker file) بجانبه (أدناه). يمكن فقط اختبار نموذج موجود على جهازك الخاص مقابلها. |
| أن يتمكن الآخرون من رؤية وجود مجموعة الاختبار، ولكن دون رؤية محتوياتها أبداً | `champollion network register-corpus --tier private --role test …` يسجل البيانات الوصفية فقط |
| إقامة مسابقة عليها، وتُشغَّل على جهاز تتحكم فيه، وربما معزول عن الشبكة (air-gapped) | `--tier sealed` بالإضافة إلى [العقدة السيادية (sovereign node)](/docs/network/sovereignty/sovereign-eval-node) |
| أن تكون عامة ومرخصة بشكل مفتوح | `--tier public` يشير إلى مكان وجودها؛ ومع ذلك نحن لا نستضيفها أبداً |

علامة "لا يغادر هذا الجهاز أبداً":

```bash
echo '{"transmission": "local-only"}' > data/nurse_checked_test.tsv.champollion.json
```

عند وضع هذا الملف، يرفض `mt-eval run` أي مزود عن بُعد لهذا الملف ويعمل فقط مقابل نموذج على المضيف المحلي (loopback). التفاصيل:
[تسجيل المدونات اللغوية (Registering Corpora)](/docs/network/sovereignty/registering-corpora).

**أي معرّف ترخيص تختار.** يتطلب التسجيل `--license`: الشروط التي يمنحها مالكو البيانات بالفعل، وليس مجرد نص مؤقت أبداً. اسألهم، ثم اختر المعرّف الذي يعبر عن ذلك: معرّف SPDX إذا كانوا ينشرون النص بالفعل بموجبه؛ أو `community-eval-grant-nc` التي تعني "لتقييم الأنظمة فقط، دون تدريب، ودون مشاركة، ودون تقييم مدفوع"؛ أو `community-eval-grant` لنفس الشروط مع السماح بالتقييم المدفوع؛ أو `proprietary` لجميع الحقوق محفوظة؛ أو `LicenseRef-<name>` لشروط خاصة بهم. الأربعة الأخيرة هي معرّفات `LicenseRef-…`، وهي أذونات مخصصة: يُرفض التقييم عن بُعد مقابلها حتى يسجل المسؤول (steward) الإذن. وإلى أن يؤكد المسؤول ذلك، سجّل اختيارك كإجراء مؤقت. يبقى خيار المحتوى المحلي فقط محلياً أياً كان الترخيص: فملف العلامة، وليس الترخيص، هو ما يحدد أين تذهب الجمل.
[أي معرّف ترخيص لمجموعة اختبار خاصة](/docs/network/sovereignty/registering-corpora#which-licence-id-for-a-private-test-set).

**للوكلاء: لا تقرأوا ملف اختبار مخصصاً للاستخدام المحلي فقط.** لا `cat` ولا `head` ولا تفتحه لإلقاء نظرة. ما تقرأه يُرسل إلى مزود النموذج الخاص بك، وهو المكان الذي تنص العلامة على عدم جواز إرسال هذه الجمل إليه. وأنت لست بحاجة إلى ذلك: فالأدوات تبقي جمله خارج ما تطبعه (يعرض `mt-eval compare` معرّفات الإدخالات والنتائج بدلاً من ذلك)، وأمر `--show-text` موجود فقط لشخص يستخدم الطرفية (terminal).

**الوكيل:** يعرض `language_overview { "code": "<code>" }` خيارات الحماية للغة؛ ويلتزم `run_benchmark` بملف العلامة ويُرجع رفضاً (مع ذكر السبب) بدلاً من إرسال الجمل المحمية إلى الخارج.

### إذا كنت تنوي تدريب نموذج لاحقاً: سجّل، وافحص، وتوقع — قبل أي تقييم

قم بهذه الأمور الثلاثة الآن، بهذا الترتيب، قبل أن تقيس الخطوة 3 أي شيء على مجموعة الاختبار. تحسب منصة Forge كل اطلاع على مجموعة الاختبار، ويُعد الاختبار المعياري (الخطوة 3) قراءة لغرض التقييم: وسيتم رفض التسجيل المسبق إذا كُتب بعد ذلك. الترتيب مهم؛ فتنفيذه لاحقاً ليس كالمبكر.

1. **سجّل مجموعة الاختبار لدى NMT Forge.** يبدأ سجل القراءة من هنا، وبالتالي تُحسب كل قراءة لاحقة (تُدرج القراءة لغرض التقييم قبل التسجيل، لكنها لا تُحتسب).
2. **افحص مدونة التدريب الخاصة بك مقابلها** (`leak-audit`). يقرأ هذا الأمر مجموعة الاختبار لغرض التدقيق فقط، وليس للتقييم، لذا لا يُحسب ضمن توقعاتك. اقرأ النتيجة: إذا كانت معظم صفوف الاختبار تحتوي على تطابق شبه تام (near-twin) في مدونتك، فإن النموذج المدرب على البيانات بأكملها سيقيّم مدى استرجاع عبارات التدريب، وليس الترجمة. في هذه الحالة، ستدرب عادةً نموذجين: أحدهما على جميع البيانات، والآخر خالٍ من البيانات شبه المتطابقة (يكتب `--drop-test-twins` مدونته وملف إعداده، `config-notwins.json`).
3. **دوّن ما تتوقعه، تسجيل مسبق واحد لكل نموذج تخطط لتدريبه**، مسمى باسم النموذج. هذه التوقعات هي ما ستُحكم بناءً عليه درجات الاختبار لاحقاً: يقارن التصدير كل نموذج مقابل النموذج الذي تحدده باستخدام `--prereg <id>` (وفي حال وجود اثنين على مجموعة اختبار واحدة فإنه يرفض التخمين). يمكنك بدلاً من ذلك تثبيت توقع على إعداد نموذجه باستخدام `--config-hash <hash>`، وهو رمز التجزئة الكامل (hash) الذي يطبعه `nmt-forge preflight run --config config-notwins.json`. وأي تعديل لاحق على هذا الإعداد (كميزانية الوقت مثلاً) يغير رمز التجزئة ويزيل التثبيت، لذا فإن تسمية التسجيل المسبق عند التصدير هي الطريقة الأبسط.

```bash
nmt-forge init crk --dir school-crk
cd school-crk
nmt-forge registry add project-test ../data/test.tsv --role test
nmt-forge leak-audit ../data/corpus.tsv --clean-to corpus.clean.jsonl
nmt-forge prereg template --out predictions.json      # edit it: what you expect, and why
nmt-forge prereg new all-data --eval-set project-test --predictions predictions.json
cd ..                                                 # step 3 runs from here
```

إذا كانت النتيجة SEVERE (شديد)، فأضف النموذج الخالي من البيانات المتطابقة وتوقعاته الخاصة (في `school-crk/`):

```bash
nmt-forge leak-audit ../data/corpus.tsv --clean-to corpus.notwins.jsonl --drop-test-twins
nmt-forge prereg new notwins --eval-set project-test --predictions predictions-notwins.json  # your edited copy
```

تحصل المدونة الخالية من البيانات المتطابقة على ملف خاص بها. ويبقى `corpus.clean.jsonl` هو ملف المدونة الشاملة لجميع البيانات: إذ يرفض تدقيق التسريب (leak-audit) الكتابة فوق ملف يقرأه إعداد أو تشغيل أو تقسيم، أو كتبه تدقيق آخر (يستبدل `--overwrite` الملف عن قصد). تسرد إجابة `--json` أرقام الصفوف القليلة الأولى من كل قائمة؛ بينما يحتفظ ملف `.audit.json` المجاور للمدونة المنقاة بها جميعاً.

يوجد `--allow-after-reads` فقط للتوقعات التي دُوّنت بالفعل قبل عمليات القراءة (على الورق مثلاً). ويتم تسجيل ذلك، وكل تقرير،
export and DEPLOY.md then says the predictions came after the scores.

**الوكيل:** `forge_init { "code": "<code>", "dir": "<dir>" }`، ثم
`forge_register_eval { "name": "project-test", "path": "../data/test.tsv", "role": "test", "project_dir": "<dir>" }`،
`forge_leak_audit { "corpus": "../data/corpus.tsv", "clean_to": "corpus.clean.jsonl", "project_dir": "<dir>" }`
(تُقرأ المسارات من `project_dir`، حيث يتم تشغيل الأوامر أعلاه من داخل المشروع؛ ويعمل المسار المطلق في أي مكان)،
ثم `forge_prereg_template` ← `forge_prereg { id, eval_set, predictions }`
مع المستخدم، واحد لكل نموذج، ويُسمى كل منها باسم نموذجه (يأخذ `forge_export` بعد ذلك ذلك المعرّف كـ `prereg`؛ بينما يثبت `config_hash` في `forge_prereg` أحدها على إعداده بدلاً من ذلك). تذكر `forge_status` هذه الخطوة بمجرد تسجيل مجموعة الاختبار. يتم التدريب في الخطوة 4 داخل نفس المشروع.
وتسرد `language_overview` هذه الخطوات بهذا الترتيب أيضاً.

## 3. قياس الخيارات وتقييمها

شغّل كل خيار مرشح مقابل مجموعة الاختبار **الخاصة بك** (المسجلة والمفحوصة والمسجلة مسبقاً لدى forge أولاً، إذا كنت تنوي التدريب لاحقاً — [الخطوة 2](#2-gather-your-data--and-protect-your-test-set)). تقيّم بيئة الاختبار (harness) كل خيار بنفس الطريقة، وهي الطريقة المتبعة في تقارير تقييم الترجمة الآلية في هذا المجال: المعيار الرئيسي هو chrF++ للمدونة مع فاصل الثقة بنسبة 95%، وبجانبه BLEU وspBLEU وTER (دون دمجها أبداً في رقم واحد). وتُعرض المطابقة التامة (Exact match) والفحوصات السلوكية (مخرجات بنظام كتابة خاطئ، إشارات الهلوسة) كتشخيصات، إلى جانب التكلفة والسرعة. وحيثما تملك بيئة الاختبار محللاً صرفياً مثبتاً للغة، فإنها تضيف قبول المحلل الصرفي (FST acceptance) والدقة الصرفية كتشخيصات؛
تسرد `mt-eval setup --status` تلك اللغات، وتضيف `mt-eval setup --comet` مقياس COMET حيثما ينطبق.

```bash
# a hosted model (needs OPENROUTER_API_KEY); --max-cost stops before spending more
mt-eval run --corpus data/test.tsv --source-lang English --target-lang "Plains Cree" \
  --target-lang-code crk --provider openrouter --model google/gemini-3.8-flash \
  --max-cost 1 -n gemini-3.8-flash -o results

# a model on your own machine (Ollama, llama.cpp, vLLM — anything OpenAI-compatible)
mt-eval run --corpus data/test.tsv --source-lang English --target-lang "Plains Cree" \
  --target-lang-code crk --provider local --base-url http://127.0.0.1:11434/v1 \
  --model llama3.1 -n local-llama -o results

mt-eval compare results/*_report.json --significance
```

يوضح `compare` ما إذا كان الفارق حقيقياً أم مجرد تشويش إحصائي (العشوائية التقريبية المقترنة - paired approximate randomization). الفارق داخل فترات الثقة لا يُعد ترتيباً تفاضلياً. يكتب الأمر `comparison-<hash>.json`، المسمى باسم عمليات التشغيل التي يقارن بينها، بجانب التقارير عندما تتشارك في مجلد واحد، أو داخل مجلد `comparisons/` يعلوها عندما لا تتشارك، ولا يكتبه إطلاقاً داخل مجلد خاص بعملية تشغيل مفردة. ولا تقوم أي مقارنة أخرى بالكتابة فوقه أبداً.

**حزم التقييم.** تعلن بعض اللغات عن أدوات إضافية تحتاجها مقاييسها (بالنسبة للغة كري السهول Plains Cree، تحتاج إلى محلل صرفي). يذكر أول أمر `mt-eval run` ما هو مفقود. ولا يؤدي غياب المحلل إلى إيقاف التشغيل أبداً: حيث يُشار إلى قبول FST بأنه لم يُحسب، ويقوم `mt-eval setup --lang crk` بتثبيته (مرة واحدة لكل جهاز)، ثم يضيف `mt-eval test <run log>` النتيجة بعد ذلك دون إعادة الترجمة.

**الوكيل:** `run_benchmark { "corpus": "data/test.tsv", "provider": "local",
"base_url": "http://127.0.0.1:11434/v1", "model": "llama3.1",
"target_language": "crk" }` plans first and runs only with `confirm: true`؛
يُرجع `get_run_status { "job_id": "<id>" }` النتائج. ولا ينشر أي شيء ما لم تمرر `publish: true`. يتم تسمية الرمز الممرر كـ `target_language` استناداً إلى بطاقة لغته ("Plains Cree") قبل أن يصل إلى المحث (prompt)، وتُظهر الخطة المحث الذي سيتلقاه النموذج. يستبدل ملف التوجيه (coaching file) ذلك المحث، وتوضح الخطة ذلك. وعندما تدرج البطاقة نظامي كتابة ولا تمرر `script`، تقرأ الخطة نظام الكتابة الذي تستخدمه المراجع (تُحسب الحروف على جهازك، دون عرض أي جملة) وتطلب ذلك النظام. تستقر تقاريره بجانب ملف الاختبار، في `data/results/mcp-run-<id>/`، مع وجود ذاكرة التخزين المؤقت لترجمات بيئة الاختبار في `data/results/cache/`. يطبع `get_run_status` أمر `mt-eval compare` لها، وبالنسبة لعمليات التشغيل على معرّف مدونة مسجل فإنه يسرد التقارير حسب المسار. وتوضح خطة `local-model` أولاً حجم التنزيلات التي ستتم عند التأكيد ومكان حفظها.

**أي مقياس تثق به** يعتمد على اللغة:
توضح أداة `get_metric_reliability { "language": "<code>" }` (MCP) ما إذا كان قد تم التحقق من صحة أي مقياس تلقائي مقابل الأحكام البشرية لتلك اللغة. وبالنسبة لمعظم اللغات شحيحة الموارد (low-resource languages)، لم يتم التحقق من أي منها، لذا فإن مقياس chrF++ هو المعتمد بالعرف — واقرأه كمقارنة بين الطرق المختلفة على نفس مجموعة الاختبار، وليس كعلامة أو تقييم مطلق.

## 4. بناء شيء أفضل

هناك مساران. قم بقياس كليهما بنفس الطريقة المتبعة في الخطوة 3.

**توجيه نموذج عام (Coach a general model).** زوّده بمسرد مصطلحات وإرشادات، ثم أعد تشغيل الخطوة 3 مع التوجيه:

```bash
mt-eval run --corpus data/test.tsv --source-lang English --target-lang "Plains Cree" \
  --target-lang-code crk --provider openrouter --model google/gemini-3.8-flash \
  --coaching-file coaching.json -n gemini-coached -o results
```

يقبل `--coaching-file` تنسيقات Markdown أو النص العادي أو JSON؛ ويُعد النص الكامل للملف هو تعليمات النموذج، وتُرسل كما هي مكتوبة.

لتقييم المصطلحات (هل يظهر كل مصطلح مدرج بترجمته المطلوبة؟)، امنح كل عملية تشغيل تقارنها نفس قائمة المصطلحات باستخدام `--glossary terms.json` (`{"blood pressure": "…"}`، أو قائمة بالصيغ المقبولة لكل مصطلح). يُستخدم المسرد للتقييم فقط؛ ولا يُرسل أبداً إلى النموذج، بحيث يتم تقييم التشغيل العادي والتشغيل الموجه بناءً على نفس المصطلحات. بدون `--glossary`، يتم استخدام `dictionary` من ملف التوجيه بتنسيق JSON (بنية [الحث الموجه](/docs/network/tutorials/coached-llm-prompting): `grammar_rules`، `dictionary`، `style_notes`) بدلاً من ذلك. وفي هذه الحالة، يتم تقييم التشغيل مقابل توجيهه الخاص، وتوضح المخرجات ذلك. يوجه ملف Markdown بنفس الطريقة ولكنه لا يوفر مسرداً.

راجع [الحث الموجه (coached prompting)](/docs/network/tutorials/coached-llm-prompting) و[الحث المعزز بالقاموس (dictionary-augmented prompting)](/docs/network/tutorials/dictionary-augmented-llm).

**درّب نموذجك الخاص** باستخدام NMT Forge، الذي يرفض الأخطاء التي تجعل نتائج البيانات الصغيرة تبدو أفضل مما هي عليه في الواقع (تسريب جمل الاختبار، والتقسيم السيئ للبيانات، واختيار نقطة الفحص بناءً على مجموعة الاختبار، وتفسير التشويش على أنه تقدم):

```bash
cd school-crk     # after step 2: registered, screened, preregistered
nmt-forge split corpus.clean.jsonl --test 0 --dev 100 --seed 42 --out data/split --register project
nmt-forge preflight run --config config.json          # every check run makes, with fixes
nmt-forge run config.json
nmt-forge export .forge/runs/<run>/run-manifest.json --prereg all-data --out export/
```

تجري أداة `preflight run` الفحوصات التي يجريها `run` قبل التدريب — مجموعة التطوير (dev set)، وتدقيق التسريب لكل ملف تدريب، وطول فك التشفير (decode length) — حتى لا يُرفض التشغيل الذي يجتازها في بدايته. يقرأ `config.json` التقسيم من `data/split/`؛ ويحدد التقسيم المكتوب في مكان آخر الأسطر التي يجب تغييرها.

توضع أزواج التدريب في ملف TSV مثل مجموعة الاختبار (أو JSONL مع `source` و`target`)؛ وقد أسقط `leak-audit` (الخطوة 2) أي زوج قد يسرب مجموعة الاختبار إلى التدريب مع توضيح سبب كل منها. هل تريد تدريب نموذجين؟ بعد التقسيم، شغّل تدقيق التسريب الخالي من التطابقات (twin-free leak-audit) من الخطوة 2 مرة أخرى (مع تسجيل مجموعة التطوير، تخرج صفوفها من الملف الخالي من التطابقات أيضاً)، ثم `nmt-forge run config-notwins.json` وexport it to its own folder with `--prereg notwins`. `nmt-forge status` names
الأمر التالي في أي نقطة. يتدرب النموذج الافتراضي على وحدة المعالجة المركزية (CPU) في غضون دقائق؛ ومع وجود 1-2 ألف زوج من الجمل، توقع الحصول على chrF++ في حدود 5-30 تقريباً — فهو يتعلم عبارات بياناتك وأنماطها، وليس اللغة بشكل عام. يقيم `export` مجموعة الاختبار مرة واحدة ويكتب تقرير mt-eval، بحيث يمكن مقارنة النموذج المدرب مع كل ما ورد في الخطوة 3. الدليل الإرشادي الكامل: [تدريب أول نموذج لك](/docs/network/getting-started/train-your-first-model).

**الوكيل:** `forge_status { "project_dir": "<dir>" }` أولاً وبعد كل خطوة؛ بعد `forge_init` و`forge_register_eval` و`forge_leak_audit` و`forge_prereg` في الخطوة 2: نفّذ `forge_split { corpus, test, seed, out }` و`forge_preflight { "target": "run" }`، ثم — بعد `nmt-forge run` في الطرفية — `forge_export { run_manifest, out, prereg }`. استدعِ `get_training_guardrails` مرة واحدة قبل `forge_split`: فهو يسرد كل قاعدة تفرضها forge والخطأ الذي تمنعه تلك القاعدة. يقبل `register` الخاص بـ `forge_split` بادئة أو `true` (`project`)، والقيمة الافتراضية لـ `out` هي `data/split`. وتأخذ كل أداة من أدوات forge بعد `forge_init` المعامل `project_dir` الذي تُرجعه. تشرح أداة `get_training_guardrails` (مع `topic` الاختياري) كل قاعدة. للاطلاع على جميع وسائط كل أداة:
[خادم MCP](/docs/network/getting-started/mcp-server#arguments).

## 5. إثبات النتائج — بشكل خاص، أو علناً

نتائجك ملك لك وحدك. لا يُنشر أي شيء إلا إذا اخترت ذلك.

```bash
mt-eval publish results/<run-id>_report.json --dry-run   # shows exactly what would leave, and what is withheld
mt-eval publish results/<run-id>_report.json --scores-only --prod
```

لا تقوم مجموعة الاختبار الخاصة أو المحلية فقط برفع جملها أبداً؛ ويوضح `--dry-run` ذلك سطراً بسطر. للسماح للآخرين بالتنافس على مجموعة الاختبار الخاصة بك دون رؤيتها على الإطلاق، قم بتشغيل مسابقة على جهاز تتحكم فيه: يقدم المشاركون طريقتهم، وتعمل على عقدتك الخاصة، ولا يخرج منها سوى النتائج فقط. تخفي المسابقات الجديدة جميع النتائج حتى تغلق المسابقة، بحيث لا يمكن لأحد ضبط نموذجه بناءً على مجموعة اختبارك. راجع [تشغيل مسابقة سيادية](/docs/network/sovereignty/run-a-sovereign-contest). للمشاركة بنموذج دربته في مسابقة شخص آخر، يحدد `DEPLOY.md` §6 في تصديره الملفات التي يتكون منها الإدخال وأمر `mt-eval contest submit-model` الدقيق.

**الوكيل:** `list_contests { "language": "<code>" }`، `get_contest { id }`؛
`get_results { "target_language": "<code>" }` و`get_run_card { id }` للوحة العامة.

## 6. الجمع بين الأفضل

**اختر من بين قياساتك الخاصة أولاً.** كل ما قيّمته على مجموعة الاختبار الخاصة بك هو تقرير mt-eval: خطوط الأساس وعمليات التشغيل الموجهة من الخطوتين 3 و4 وتصدير كل نموذج مدرب (`evaluation/runlog_report.json` في export folder). A terminal run with `-o results` writes to
`results/*_report.json`؛ وعملية التشغيل التي تبدأ باستخدام أداة MCP `run_benchmark` تكتب بجانب ملف الاختبار، في `data/results/mcp-run-<id>/`). قارن بينها جميعاً دفعة واحدة — نمط glob الأول لعمليات تشغيل الطرفية، والثاني لعمليات تشغيل الوكيل (استخدم النمط الذي يطابق عمليات التشغيل لديك؛ حيث يتوقف zsh عند وجود نمط glob لا يطابق أي شيء):

```bash
mt-eval compare results/*_report.json school-crk/export*/evaluation/runlog_report.json --significance
mt-eval compare data/results/mcp-run-*/*_report.json school-crk/export*/evaluation/runlog_report.json --significance
```

الفارق داخل فترات الثقة لا يُعد ترتيباً تفاضلياً، والنموذج المدرب الذي تحتوي صفوف اختباره على بيانات شبه متطابقة في بيانات تدريبه يكون تقييمه معتمداً على الاسترجاع: اذكر رقمه الخالي من التطابقات بجانبه (يوضح ملف DEPLOY.md و`nmt-forge report` أيهما تختار)، إلى جانب أي **تحذير بشأن النتيجة (score caveat)** وضعه mt-eval على ذلك الرقم. يعني تحذير *المخرجات شبه الثابتة (near-constant output)* (تقديم جملة واحدة من بضع جمل لعدد كبير من جمل الاختبار المختلفة) أن المخرجات لا تتبع المدخلات، مهما كانت النتيجة؛ يطبع forge ذلك بجانب النتيجة في `export` و`DEPLOY.md` و`status` و`report` و`compare` و`lint`. عند وجود عدة نماذج مصدَّرة، يسرد `nmt-forge status` كل نموذج بنتيجته ونتيجته الخالية من التطابقات والتحذير الخاص به، ويطلب منك اختيار النموذج المراد نشره. سجّل الاختيار باستخدام `nmt-forge choose <export>/model` (أو `nmt-forge serve <export>/model --choose`). يُسجل تشغيل نموذج لتجربته على أنه قيد التشغيل (served)، وليس كاختيارك النهائي، لذا يستمر `status` في السؤال حتى تختار.

**الوكيل:** `forge_status { "project_dir": "<dir>" }` — في حالة `choose-export`، اعرض للمستخدم `result.advice.exports`، ودرجة كل نموذج مصدّر مع `score_caveats` الخاصة به، واسأله عن النموذج المراد نشره؛ تُسجل إجابة المستخدم باستخدام `nmt-forge choose` في الطرفية. التشغيل المؤقت لا يجيب عن السؤال. يُجري `forge_compare { eval_set, hyps_a, hyps_b }` اختبار مقارنة A/B بين نموذجي forge مع إظهار تحذير التطابقات شبه التامة وتحذيرات نتائج mt-eval لكل منهما بجانب الفائز؛ ويكون ملف فرضيات كل نموذج هو مسار `hypotheses` الذي تُرجعه `forge_export` (`<export>/evaluation/battery-hyps.jsonl`).

ثم انظر إلى ما هو أبعد من عمليات التشغيل الخاصة بك. فطرق مختلفة تتفوق باختلاف الأزواج اللغوية وباختلاف أنواع النصوص. تسرد صفحة [الشبكة (Network)](/docs/network/) الطرق والخدمات المتاحة والأدلة الخاصة بكل منها — أي ما تم نشره، وليس ما قمت بقياسه:

```bash
champollion network recommend eng crk               # runnable methods + cited evidence for the pair
champollion network leaderboard --pair "eng>crk"     # published results for the pair
```

يمكن تثبيت طريقة منشورة على لوحة المتصدرين (leaderboard) مع إعداداتها تماماً كما تم تقييمها: يضيف الأمر `champollion network leaderboard --install <method> --apply` تلك الطريقة إلى مشروعك لذلك الزوج اللغوي. تقوم واجهة سطر الأوامر (CLI) بتهيئة الطريقة **لكل زوج لغوي على حدة**، بحيث يمكن أن تستخدم لغة كري (Cree) في النشرة الإخبارية نموذجك المدرب، بينما تستخدم اللغة الفرنسية نموذجاً مستضافاً. وتتم تغطية سلسلة الطرق (على سبيل المثال: نموذج يتبعه مدقق) في [النماذج المتسلسلة](/docs/network/tutorials/chained-models).

## 7. استخدامها

انشر الطريقة التي قمت بقياسها — وليس طريقة مختلفة.

```bash
nmt-forge serve export/model                     # your trained model on http://127.0.0.1:8378
LOCAL_API_BASE=http://127.0.0.1:8378/v1 champollion sync --method local
```

أثناء تشغيله، يعرض `nmt-forge status` الرسالة `serving` (حيث يتحقق من استمرار استجابة الخادم)؛ وبعد توقف الخادم، يذكر أمر `serve` مرة أخرى، على نفس المنفذ.

أو، بالنسبة لنموذج مستضاف وموجّه، عيّنه على الزوج اللغوي في `champollion.config.json`. وفي كلتا الحالتين:

```bash
champollion init --langs crk     # detects your app's locale files
champollion sync                 # translates only what changed
champollion verify               # placeholders, scripts, key parity
```

**ما لا يستطيع نموذجك الخاص فعله بعد.** يتعلم النموذج الصغير المدرب على بضعة آلاف من الجمل عباراتها. وغالباً ما يُتلف العناصر النائبة (placeholders) مثل (`{name}`)، وصيغ الجمع والتنسيقات، أو يحول تسمية قصيرة مثل "Home" إلى جملة كاملة. ترفض بوابة الجودة (quality gate) تلك المخرجات؛ ولا يتم كتابة أي شيء تالف. حدد **طريقة بديلة (fallback)** للزوج اللغوي، وستنتقل هذه النصوص إلى طريقة ثانية ضمن نفس عملية المزامنة:

```json
"pairs": {
  "en:crk": {
    "method": "api",
    "endpoint": "http://127.0.0.1:8378/translate",
    "fallback": { "method": "llm-coached", "model": "google/gemini-3.8-flash" }
  }
}
```

إذا كان غير مسموح لأي نص بمغادرة أجهزتك، فاجعل البديل نموذجاً تقوم بتشغيله هناك أيضاً: يرسل `"fallback": { "method": "local", "model": "<your local model>" }` إلى خادم متوافق مع OpenAI على هذا الجهاز (Ollama، أو llama.cpp، أو vLLM)، بتكلفة 0 دولار لـ API. عادةً ما يكون النموذج المستضاف هو الرأي الثاني الأقوى؛ استخدمه عندما يكون من المسموح إرسال النص إلى مزوده.

يترجم نموذجك كل ما يستطيع ترجمته. ويحصل البديل فقط على ما رفضته البوابة منه، وكتل Markdown التي أسقطها أو أتلفها، وتمر مخرجاته عبر نفس البوابة. يطبع `sync` سطراً بعنوان `[FALLBACK]` لكل زوج مع الإحصائيات، ويسرد `champollion verify` أي شيء لم تتمكن أي من الطريقتين من ترجمته. راجع [الطريقة البديلة (Fallback method)](/docs/getting-started/configuration#fallback).

بدلاً من ذلك، لترجمة تلك النصوص مرة واحدة استثنائياً، ترجمها بطريقة أخرى:

```bash
champollion sync --method llm-coached --redo keys:nav.home,greeting
```

...أو يدوياً، أو عبر مراجع باستخدام `champollion xliff export`. وضع نصوص التطبيق نفسه في مجموعة الاختبار الخاصة بك: فالنموذج الذي يحقق درجات جيدة في جمل المعلمين قد يخطئ في عبارة مثل "أين يؤلمك؟".

**أنظمة الكتابة.** إذا كانت اللغة تُكتب بأكثر من نظام كتابة (لغة كري السهول Plains Cree: الكتابة بالحروف اللاتينية القياسية والكتابة المقطعية syllabics)، فستطلب منك واجهة سطر الأوامر (CLI) الاختيار قبل أن تترجم. عيّن `"script"` لتلك اللغة في ملف الإعداد؛ وتسرد الرسالة الخيارات المتاحة.

تعني ذاكرة الترجمة أن الجملة غير المتغيرة لا يُدفع ثمنها مرتين أبداً، كما أن تبديل النماذج لا يؤدي إلى إعادة ترجمة كل شيء. اربطها بالتكامل المستمر باستخدام [دليل CI/CD](/docs/guides/ci-cd). يحتوي ملف `export/model/DEPLOY.md` (من الخطوة 4) على الإعداد الدقيق للنموذج المدرب، بما في ذلك طريقة `api` وكيفية إتاحته على الشبكة بأمان.

**الوكيل:** يشغل `translate { texts, source_language, target_language }` النصوص عبر نفس مسار المعالجة (pipeline). أضف `method: "local"` و`base_url`، أو `method: "api"` و`endpoint`، لنموذج تستضيفه بنفسك، و`script` للغة تُكتب بأكثر من نظام كتابة.

## قرارات أثناء المسار

| القرار | اختر... | متى |
|---|---|---|
| أين توضع مجموعة الاختبار | محلي فقط (local-only) | إذا كانت حساسة، أو لم تسأل الأشخاص الذين كتبوها بعد |
| | خاصة / محكمة الإغلاق (private / sealed) | إذا كنت تريد أن يعرف الآخرون بوجودها، أو يتنافسوا عليها، دون رؤيتها |
| التوجيه أم التدريب | توجيه نموذج مستضاف | إذا كان لديك مسرد وقليل من النصوص المتوازية، والخدمات الخارجية مقبولة |
| | التدريب باستخدام forge | إذا كان لديك بضعة آلاف من الأزواج أو أكثر، أو يجب أن تبقى البيانات على أجهزتك |
| النشر | النتائج فقط | الخيار الافتراضي لأي شيء لم تكتبه بنفسك |
| | لا شيء | مسموح به دائماً — فالقياس مفيد داخلياً بشكل خاص |

## ما هي التكلفة

- الأدوات مجانية للاستخدام غير التجاري: حيث تشمل المدارس، أو المستشفيات والعيادات العامة، أو المؤسسات الخيرية أو المشاريع البحثية (تخضع واجهة سطر الأوامر CLI، وnmt-forge، وخادم MCP لترخيص PolyForm Noncommercial 1.0.0؛ بينما بيئة التقييم مفتوحة المصدر بترخيص AGPL-3.0-or-later). [من يحق له استخدام هذا](/docs/getting-started/who-may-use-this).
- يكلف النموذج المستضاف ما يفرضه مزوده من رسوم؛ ويوقف `--max-cost` التشغيل قبل أن ينفق أكثر مما تسمح به، ويعرض التقرير التكلفة لكل جملة. بينما لا يكلف النموذج المحلي سوى وقت جهازك وموارده.
- يتطلب تدريب نموذج forge الافتراضي وحدة معالجة مركزية (CPU) وبضع دقائق؛ بينما تحتاج الإعدادات المسبقة الأكبر إلى وحدة معالجة رسومية (GPU).
