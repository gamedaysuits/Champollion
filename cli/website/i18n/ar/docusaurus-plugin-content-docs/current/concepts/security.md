# الأمن والسلامة

تم تصميم Champollion ليكون آمناً في البيئات المعادية — حيث قد تأتي بيانات اللغة من مصادر غير موثوقة، وحيث يمكن لأسماء الملفات المصممة خصيصاً أن تتجاوز حدود الدلائل، وحيث يمكن أن تحتوي مخرجات النماذج اللغوية الكبيرة (LLM) على أي شيء.

## نموذج التهديد

| التهديد | ناقل الهجوم | التخفيف |
|--------|--------------|-----------|
| **تلوث النموذج الأولي (Prototype pollution)** | مفاتيح JSON مصممة خصيصاً (`__proto__`، `constructor`) | تُرفض في وقت التحليل |
| **اجتياز المسار (Path traversal)** | رموز لغة مثل `../../etc/passwd` | يتم التحقق من صحة كتابة الملفات في الدلائل المكونة |
| **تلف كتل التعليمات البرمجية** | يقوم LLM بالترجمة داخل حدود التعليمات البرمجية | الحماية باستخدام حراس Unicode (Unicode sentinel) |
| **المفاتيح المهلوسة (Hallucinated keys)** | يُرجع LLM مفاتيح لم يتم إرسالها | التحقق من صحة الاستجابة — تُكتب المفاتيح المقبولة فقط |
| **استهلاك الرموز (Tokens) الخارج عن السيطرة** | حلقات إعادة المحاولة اللانهائية | تحديد الميزانية عبر `maxRetries` |

## حماية تلوث النموذج الأولي (Prototype Pollution Guard)

يتم التحقق من صحة جميع مفاتيح اللغة مقابل قائمة حظر قبل المعالجة:

- `__proto__`
- `constructor`
- `prototype`

يتم رفض أي مفتاح يطابق هذه الأنماط مع ظهور خطأ. يمنع هذا المهاجمين من استخدام ملفات لغة مصممة خصيصاً لتعديل النماذج الأولية لكائنات JavaScript.

## احتواء المسار

عند كتابة ملفات اللغة، يتحقق champollion من أن مسار المخرجات يظل داخل الدلائل المكونة (`localesDir`، `contentDir`). يتم تعقيم رموز اللغة — لا يمكن لرمز مثل `../../secrets` الكتابة خارج الدليل المتوقع.

## حماية الكتل

أثناء ترجمة محتوى Markdown، يتم استبدال العناصر المهيكلة بعناصر نائبة حارسة من Unicode (Unicode sentinel placeholders) قبل إرسال النص إلى LLM:

1. **كتل التعليمات البرمجية** (المحاطة والمضمنة) → حارس (sentinel)
2. **أكواد Hugo القصيرة (shortcodes)** (`{{< >}}`، `{{% %}}`) → حارس (sentinel)  
3. **HTML الخام** → حارس (sentinel)
4. **متغيرات الاستيفاء (Interpolation variables)** (`{{ .Count }}`) → حارس (sentinel)

بعد الترجمة، يتم استبدال الحراس بالمحتوى الأصلي. لا يرى LLM أبداً كتل التعليمات البرمجية أو الأكواد القصيرة أو HTML — وبالتالي لا يمكنه إتلافها.

## التحقق من صحة الاستجابة

عندما يُرجع LLM استجابة JSON، يتحقق champollion مما يلي:
- ظهور المفاتيح التي تم إرسالها في الدفعة فقط في الاستجابة
- عدم حقن أي مفاتيح إضافية
- تحليل الاستجابة كـ JSON صالح

يتم إسقاط المفاتيح المهلوسة بصمت. يمنع هذا مخرجات LLM من حقن ترجمات غير متوقعة في ملفات اللغة الخاصة بك.

## بوابة الجودة (Quality Gate)

يتم التحقق من صحة كل ترجمة من خلال خمسة فحوصات حتمية قبل كتابتها على القرص. راجع [بوابة الجودة](/docs/concepts/quality-gate) للحصول على التفاصيل.

## التراجع الأسي (Exponential Backoff)

تستخدم استدعاءات واجهة برمجة التطبيقات (API) التراجع الأسي مع التذبذب (jitter) عند تلقي استجابات 429 (حد المعدل) و 5xx (خطأ في الخادم). تمنع ثلاث محاولات إعادة مع تأخير متزايد الضغط الزائد على واجهة برمجة التطبيقات أثناء فترات الانقطاع.

## مهلة الطلب

يحتوي كل طلب واجهة برمجة تطبيقات (API) على مهلة قدرها 30 ثانية عبر `AbortController`. يمنع هذا عملية المزامنة من التعليق إلى أجل غير مسمى بسبب اتصال ميت.

## إخفاقات الترجمة الصريحة (Fail-Loud)

عندما تكون واجهة برمجة التطبيقات (API) غير متاحة أو تفشل الترجمة، يُصدر champollion خطأً صريحاً مع إرشادات قابلة للتنفيذ بدلاً من كتابة بيانات غير صالحة بصمت. لا يتم أبداً كتابة أي عناصر نائبة مسبوقة بـ `[EN]` أثناء المزامنة.

```
[ERR] Content sync for fr: no API key available.
  Set OPENROUTER_API_KEY in .env.local to translate content.
```

لا يؤدي فشل ملف واحد إلى إيقاف المزامنة بأكملها — يتم تسجيل الخطأ ويستمر مسار العمل (pipeline) إلى الملف التالي، مما يتيح لك تحقيق أقصى تقدم في كل عملية تشغيل.

## التحقق ما بعد المزامنة

بعد اكتمال جميع الترجمات، يعيد champollion قراءة ملفات اللغة المكتوبة من القرص ويُجري دورة تحقق. يكتشف هذا الفجوة بين إبلاغ المزامنة بالنجاح وكون الترجمات خاطئة في الواقع:

- **تكافؤ المفاتيح (Key parity)** — جميع المفاتيح المصدرية موجودة في كل هدف
- **علامات `[EN]`** — علامات التراجع القديمة من عمليات التشغيل السابقة
- **الترجمات الفارغة** — القيم الفارغة التي تسربت
- **التوافق مع نظام الكتابة (Script compliance)** — اللغات غير اللاتينية ذات الترجمات التي تقتصر على ASCII فقط
- **الحفاظ على العناصر النائبة** — تطابق العناصر النائبة لـ ICU مع المصدر

يمكنك التخطي باستخدام `--no-verify` أو التشغيل بشكل مستقل باستخدام `npx champollion verify`.

## الاختبار

يتم التحقق من خصائص الأمان بواسطة مجموعة الاختبارات المعادية (adversarial test suite):

```bash
npm run test:redteam    # prototype pollution, path traversal, encoding attacks
```
