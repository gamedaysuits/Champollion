# الأمان والسلامة

صُمم Champollion ليكون آمناً في البيئات المعادية — حيث قد تأتي بيانات الـ locale من مصادر غير موثوقة، وحيث قد تتجاوز أسماء الملفات المصنوعة خصيصاً حدود الدلائل، وحيث يمكن أن تحتوي مخرجات نماذج اللغة الكبيرة (LLM) على أي شيء.

## نموذج التهديد

| التهديد | موجه الهجوم | إجراء التخفيف |
|--------|--------------|-----------|
| **تلوث النموذج الأولي (Prototype pollution)** | مفاتيح JSON المصنوعة خصيصاً (`__proto__`، `constructor`) | تُرفض أثناء التحليل (parse time) |
| **اجتياز المسار (Path traversal)** | رموز locale مثل `../../etc/passwd` | التحقق من صحة كتابة الملفات واقتصارها على الدلائل المحددة |
| **تلف كتل الشيفرة البرمجية** | قيام نموذج LLM بالترجمة داخل أسوار الشيفرة (code fences) | الحماية باستخدام علامات Unicode الحارسة |
| **المفاتيح المهلوسة** | إرجاع نموذج LLM لمفاتيح لم يتم إرسالها | التحقق من صحة الاستجابة — كتابة المفاتيح المقبولة فقط |
| **استنزاف غير منضبط للرموز (Tokens)** | حلقات إعادة المحاولة اللانهائية | تحديد سقف الميزانية عبر `maxRetries` |

## الحماية من تلوث النموذج الأولي

يتم التحقق من صحة جميع مفاتيح الـ locale بمطابقتها مع قائمة الحظر قبل المعالجة:

- `__proto__`
- `constructor`
- `prototype`

يتم رفض أي مفتاح يطابق هذه الأنماط مع إظهار خطأ. هذا يمنع المهاجمين من استخدام ملفات locale مصاغة خصيصاً لتعديل النماذج الأولية لكائنات JavaScript.

## احتواء المسارات

عند كتابة ملفات الـ locale، يتحقق champollion من بقاء مسار المخرجات داخل الدلائل المحددة (`localesDir`، `contentDir`). يتم تعقيم رموز الـ locale — وبالتالي لا يمكن لرمز مثل `../../secrets` أن يكتب خارج الدليل المتوقع.

## حماية الكتل

أثناء ترجمة محتوى Markdown، تُستبدل العناصر الهيكلية بعلامات حارسة بديلة في ترميز Unicode قبل إرسال النص إلى نموذج LLM:

1. **كتل الشيفرة البرمجية** (المحاطة بأسوار والمضمنة في السطر) ← علامة حارسة
2. **أكواد Hugo القصيرة** (`{{< >}}`، `{{% %}}`) ← علامة حارسة  
3. **شيفرة HTML الخام** ← علامة حارسة
4. **متغيرات الاستيفاء** (`{{ .Count }}`) ← علامة حارسة

بعد اكتمال الترجمة، تُستبدل العلامات الحارسة بالمحتوى الأصلي. لا يرى نموذج LLM كتل الشيفرة البرمجية، أو الأكواد القصيرة، أو HTML إطلاقاً — وبالتالي لا يمكنه إتلافها.

## التحقق من صحة الاستجابة

عندما يُرجع نموذج LLM استجابة بتنسيق JSON، يتحقق champollion مما يلي:
- ظهور المفاتيح التي أُرسلت في الدفعة فقط داخل الاستجابة
- عدم حقن أي مفاتيح إضافية
- إمكانية تحليل الاستجابة كـ JSON صالح

يتم إسقاط المفاتيح المهلوسة بصمت. يمنع ذلك مخرجات نموذج LLM من حقن ترجمات غير متوقعة في ملفات الـ locale لديك.

## بوابة الجودة

تخضع كل ترجمة للتحقق عبر خمسة فحوصات حتمية قبل كتابتها على القرص. راجع [بوابة الجودة](/docs/concepts/quality-gate) للحصول على التفاصيل.

## التراجع الأسي

تستخدم استدعاءات API خوارزمية التراجع الأسي مع التباين العشوائي (jitter) عند الاستجابات برمز 429 (تجاوز حد المعدل) و5xx (خطأ في الخادم). تمنع المحاولات الثلاث المتكررة بفترات تأخير متزايدة إغراق واجهة API بالطلبات أثناء فترات الانقطاع.

## مهلة انتظار الطلب

لكل طلب API مهلة انتظار محددة بـ 30 ثانية عبر `AbortController`. يمنع هذا تعليق عملية المزامنة إلى أجل غير مسمى عند انقطاع الاتصال.

## الإخفاق الصريح عند فشل الترجمة

عندما تكون واجهة API غير متاحة أو تفشل الترجمة، يطلق champollion خطأً صريحاً مصحوباً بإرشادات قابلة للتنفيذ بدلاً من كتابة نصوص تالفة بصمت. لا تتم أبداً كتابة علامات نائبة مسبوقة بـ `[EN]` أثناء المزامنة.

```
[ERR] Content sync for fr: no API key available.
  Set OPENROUTER_API_KEY in .env.local to translate content.
```

فشل ملف واحد لا يوقف المزامنة بأكملها — يتم تسجيل الخطأ ويستمر مسار المعالجة مع الملف التالي، مما يضمن تحقيق أقصى تقدم ممكن في كل تشغيل.

## التحقق ما بعد المزامنة

بعد اكتمال جميع الترجمات، يعيد champollion قراءة ملفات الـ locale المكتوبة من القرص ويجري مرحلة تحقق. يكشف هذا التناقض بين إبلاغ المزامنة بالنجاح وكون الترجمات خاطئة في الواقع:

- **تكافؤ المفاتيح** — وجود جميع مفاتيح المصدر في كل لغة مستهدفة
- **علامات `[EN]`** — علامات احتياطية سابقة من عمليات تشغيل سابقة
- **ترجمات فارغة** — قيم فارغة تسللت دون معالجة
- **التوافق مع نظام الكتابة** — لغات locales غير اللاتينية التي تحتوي على ترجمات لاتينية فقط (تُصنف الحروف وفقاً لنظام كتابة Unicode، لذا تُحسب الحروف اللاتينية المشكولة والكاملة العرض كحروف لاتينية)
- **الحفاظ على العناصر النائبة** — تطابق عناصر ICU النائبة مع المصدر

يمكن التخطي باستخدام `--no-verify` أو التشغيل بشكل مستقل عبر `npx champollion verify`.

## الاختبار

يتم التحقق من الخصائص الأمنية بواسطة حزمة الاختبارات المعادية:

```bash
npm run test:redteam    # prototype pollution, path traversal, encoding attacks
```
