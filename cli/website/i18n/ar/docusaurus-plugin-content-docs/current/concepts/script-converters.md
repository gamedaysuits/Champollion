# محولات أنظمة الكتابة

محولات أنظمة الكتابة (Script Converters) هي خطافات حتمية (deterministic) لما بعد الترجمة لا تعتمد على النماذج اللغوية الكبيرة (LLM)، وتعمل على تحويل النص من نظام كتابة إلى آخر. وتتيح سير عمل قائم على مبدأ "ترجم مرة واحدة، واعرض بأنظمة كتابة متعددة" — حيث تترجم إلى نظام كتابة للعمل (عادةً ما يكون اللاتيني)، ثم يُحوَّل النص تلقائيًا إلى نظام كتابة العرض.

## لماذا نستخدم محولات أنظمة الكتابة؟

تستخدم بعض اللغات أنظمة كتابة متعددة لنفس اللغة المنطوقة:

- **كري السهول (Plains Cree)**: كتابة SRO (اللاتينية) للتحرير ← المقاطع اللفظية (ᓀᐦᐃᔭᐍᐏᐣ) للعرض
- **الصربية**: اللاتينية للاستخدام الدولي ← السيريلية للاستخدام المحلي
- **الكلينغونية**: النقحرة اللاتينية للكتابة باللوحة ← pIqaD (  ) للعرض

تتسبب الترجمة المباشرة إلى أنظمة كتابة غير لاتينية في حدوث مشكلات: إذ تهلوس النماذج اللغوية الكبيرة أحيانًا في المحارف، وتصبح ملفات JSON صعبة التتبع في أنظمة التحكم بالإصدارات، ولا تستطيع أدوات مقارنة الفروق (diff) مقارنة التغييرات بدقة. تحل محولات أنظمة الكتابة هذه المشكلة عن طريق الاحتفاظ بالترجمات في نظام كتابة ملائم لأنظمة التحكم بالإصدارات، وتحويلها بطريقة حتمية في وقت المزامنة.

## المحولات المتاحة

يأتي Champollion مزودًا بخمسة محولات مدمجة لأنظمة الكتابة:

| اللغة (Locale) | من | إلى | النوع | هل يلزم خط مخصص؟ |
|----------------|----|-----|------|-------------------|
| `crk` | SRO (الإملاء اللاتيني القياسي) | مقاطع كري اللفظية | حتمي (Deterministic) | لا — مدعوم في Unicode الأصلي |
| `sr` | اللاتينية | السيريلية | حتمي (Deterministic) | لا — مدعوم في Unicode الأصلي |
| `tlh` | النقحرة اللاتينية | pIqaD | حتمي (Deterministic) | نعم — PUA U+F8D0–F8FF |
| `x-elvish-s` | اللاتينية | Tengwar (نمط بيليرياند) | حتمي (Deterministic) | نعم — PUA U+E000–E07F |
| `x-kryptonian` | اللاتينية | الكريبتونية | شفرة استبدال قائمة على الخط | نعم — PUA U+E100–E119 |

### المحولات الحتمية مقابل القائمة على الخطوط

- **المحولات الحتمية** (كري، الصربية، الكلينغونية، Tengwar) تُجري مطابقة حقيقية محرفًا بمحرف باستخدام قواعد لغوية. ويحتوي الخرج على محارف Unicode حقيقية.
- **المحولات القائمة على الخطوط** (الكريبتونية) هي شفرات استبدال بنسبة 1:1، حيث يكون الخرج عبارة عن محارف Unicode تقع ضمن منطقة الاستخدام الخاص (PUA) ولا تظهر بالشكل الصحيح إلا عند تحميل خط مخصص بعينه.

## كيف تعمل؟

تعمل محولات أنظمة الكتابة **بعد** اكتمال الترجمة كخطوة معالجة لاحقة. ويكون مسار المعالجة كالتالي:

```
Source (English) → LLM Translation → Working Script → Script Converter → Display Script
```

على سبيل المثال، في لغة كري السهول:
```
"Welcome" → LLM → <its translation, in SRO> → Converter → <the same text, in Syllabics>
```

يطابق المحول أشكال الهجاء وليس الكلمات: فالمقاطع `pâ tê ki` (وهي مثال هجائي وليست كلمة) تصبح `ᐹ ᑌ ᑭ`.

### المطابقة الجشعة من اليسار إلى اليمين

تستخدم جميع المحولات الخوارزمية ذاتها: عند كل موضع محرف، تبدأ بتجربة أطول تطابق ممكن أولاً، ثم تنتقل تدريجيًا إلى التطابقات الأقصر. أما المحارف التي لا تطابق أي نمط (مثل المسافات وعلامات الترقيم والأرقام) فتمر كما هي دون تغيير.

يتعامل هذا الأسلوب مع الحروف المزدوجة (digraphs) والثلاثية (trigraphs) بشكل صحيح:
- الكلينغونية: `tlh` ← محرف pIqaD واحد (وليس `t` + `l` + `h`)
- الصربية: `nj` ← `њ` (وليس `н` + `ј`)
- كري: `twê` ← محرف مقطعي واحد (وليس `t` + `w` + `ê`)

## استخدام محولات أنظمة الكتابة

عملية التحويل هي **قرار إعداد يُحدد يدويًا، وليست تلقائية أبدًا** (منذ الإصدار 0.3.0 — كانت الإصدارات السابقة تُجري التحويل دون شروط، مما تسبب في إرسال نصوص PUA غير قابلة للعرض إلى مشاريع كانت خطوطها تتوقع نقحرة لاتينية):

- **تتوفر لكل من crk وsr طريقتان حقيقيتان للإملاء** (SRO/المقاطع اللفظية، اللاتينية/السيريلية). لا يوجد خيار افتراضي: يسألك `champollion init` عن النظام الذي ترغب في كتابته، ويرفض `sync` التشغيل حتى يتم تحديد ذلك في ملف الإعدادات. لا يفرض Champollion أي نظام كتابة على مجتمع اللغة.
- **تعتمد tlh وx-elvish-s وx-kryptonian النقحرة اللاتينية افتراضيًا** — إذ إن أنظمة العرض الكتابية الخاصة بها تقع ضمن منطقة الاستخدام الخاص (PUA)، ولا يمكن عرضها بدون خط مخصص. لذا يجب تفعيلها صراحةً.

```json title="champollion.config.json"
{
  "languages": {
    "crk": { "script": "Cans" },
    "tlh": { "script": "Piqd" }
  }
}
```

عندما يقوم champollion بمزامنة `en:crk` مع `"script": "Cans"`، تُنتج الترجمات بنظام SRO (نظام كتابة العمل الذي تتحقق منه بوابة الجودة)، ثم تُحوَّل إلى المقاطع اللفظية قبل كتابتها في `crk.json`. أما مع `"script": "Latn"` — أو بالنسبة إلى tlh دون تحديد `script:` على الإطلاق — فإن نظام كتابة العمل هو الناتج النهائي ولا يُحوَّل أي شيء.

الحروف التي لا يستطيع المحول مطابقتها (على سبيل المثال، تفتقر الكلينغونية إلى الأحرف `d`، `c`، `f`، `g`، `i`، `k`، `s`، `x`، `z` — وبالتالي لا يمكن تحويل "GitHub" تحويلًا كاملاً) تحتفظ بـ **القيمة بالكامل** في نظام كتابة العمل بدلاً من خلط أنظمة الكتابة، مع إظهار تحذير يحدد تلك الأحرف. يمكنك تعريف قواعد النقحرة الخاصة بك باستخدام [`scriptFallback`](/docs/getting-started/configuration#script-fallback).

للتراجع عن التحويل الذي حدث عندما كان غير مشروط، شغّل [`champollion repair-script`](/docs/getting-started/configuration#repair-script)؛ سيفشل `champollion integrity` عند العثور على محارف PUA في المواضع التي يكون التحويل فيها معطلاً.

### التحقق من حالة المحول

```bash
npx champollion status
```

يُظهر مخرج الحالة (status) قرار نظام الكتابة المحسوم لكل زوج لغوي — ما سيتم كتابته، وما إذا كان هناك محول متاح ولكنه غير مُمكّن.

## متطلبات خطوط الويب

تُخرج ثلاثة محولات محارف تقع ضمن منطقة الاستخدام الخاص في Unicode (PUA)، وهي تتطلب خطوط ويب مخصصة:

### الكلينغونية (pIqaD)

ثبّت خط pIqaD متوافقًا مع معيار CSUR (مثل "pIqaD qolqoS" أو "Klingon pIqaD HaSta"):

```css
@font-face {
  font-family: 'pIqaD';
  src: url('/fonts/pIqaD.woff2') format('woff2');
  unicode-range: U+F8D0-F8FF;
}

:lang(tlh) {
  font-family: 'pIqaD', sans-serif;
}
```

### Tengwar (السندرينية)

ثبّت خط Tengwar متوافقًا مع معيار CSUR (مثل "Tengwar Formal CSUR" أو "Tengwar Annatar"):

```css
@font-face {
  font-family: 'Tengwar';
  src: url('/fonts/tengwar-formal-csur.woff2') format('woff2');
  unicode-range: U+E000-E07F;
}

:lang(x-elvish-s) {
  font-family: 'Tengwar', serif;
}
```

### الكريبتونية

ثبّت خطًا كريبتونيًا معيّنًا لنقاط رموز PUA من U+E100 إلى E119:

```css
@font-face {
  font-family: 'Kryptonian';
  src: url('/fonts/kryptonian.woff2') format('woff2');
  unicode-range: U+E100-E119;
}

:lang(x-kryptonian) {
  font-family: 'Kryptonian', sans-serif;
}
```

:::tip[طريقة بديلة للكريبتونية]
نظرًا لأن الكريبتونية هي مجرد شفرة استبدال بحتة لأحرف A-Z، يمكنك الاستغناء عن محول نظام الكتابة بالكامل وتطبيق الخط على النص اللاتيني عبر CSS. غالبًا ما يكون هذا الخيار أبسط لعمليات النشر على الويب — ما عليك سوى توفير الخط الكريبتوني وتعيين `font-family` على العناصر المطلوبة.
:::

## إضافة محول مخصص

لإضافة محول للغة جديدة، عدّل الملف `lib/scripts.js`:

1. **أنشئ خريطة التحويل** — مصفوفة مرتبة من أزواج `[from, to]`، مع وضع التسلسلات الأطول أولاً
2. **أنشئ دالة المحول** — ماسح جشع من اليسار إلى اليمين (استخدم `latinToCyrillicSr` كقالب). وحيثما وُجد محول يتولى المجتمع صيانته، استخدمه بدلاً من إنشاء جدول خاص بنا: على سبيل المثال، يفوض محول كري السهول العمل إلى `cree-sro-syllabics`، وهو المحول الذي يستخدمه مشروع itwêwina التابع لـ ALTLab
3. **سجّله** في كائن `SCRIPT_CONVERTERS` باستخدام رمز اللغة (locale) كمفتاح
4. **أضف الحقل `script`** إلى إدخال السجل الخاص باللغة في `registers.js`

```javascript
// Example: adding a converter for Cherokee (chr)
const LATIN_TO_CHEROKEE_MAP = [
  ['ga', 'Ꭶ'], ['ka', 'Ꭷ'], ['ge', 'Ꭸ'], // ...
];

function latinToCherokee(text) {
  // Same greedy left-to-right pattern as other converters
}

SCRIPT_CONVERTERS['chr'] = {
  from: 'Latin',
  to: 'Cherokee Syllabary',
  type: 'deterministic',
  converter: latinToCherokee,
};
```
