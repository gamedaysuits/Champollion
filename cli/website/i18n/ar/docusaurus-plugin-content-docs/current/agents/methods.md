# الطرق والبوابات

**الطريقة** هي أي شيء يترجم: نموذج مدرب، أو نموذج لغوي كبير موجّه، أو
بحث في قاموس، أو محرك قواعد، أو خدمة، أو أشخاص. **البوابة** هي فحص
بين مخرجات الطريقة وما يتم شحنه. الطريقة الافتراضية للمسارات هي
نموذج مدرب باستخدام nmt-forge ([التدريب](/docs/agents/training))؛ وتعرض هذه الصفحة
التنسيق الذي كُتب به كلاهما، والوصفات الأخرى.

تلتزم كل وصفة أدناه بـ [قواعد الإرسال](/docs/agents/data-rules):
**الطريقة التي تستدعي موفّر نماذج ترسل نصًا إلى ذلك الموفّر**، والملف
المخصص للاستخدام المحلي فقط أو المغلق أو الذي يتطلب الموافقة يرفض ذلك.

## method/1

`$schema` `https://champollion.dev/schemas/method/1.json`. الحقول المطلوبة: `id`
(كلمات بحروف صغيرة مفصولة بشرطات)، `name`، `kind` — بالإضافة إلى الإعداد الوحيد
الذي يحتاجه هذا النوع، وتتحقق منه أدوات القراءة بنفس الرسائل في كلا
بيئتي التشغيل.

| `kind` | الإعداد المطلوب | يعمل في | يرسل النص إلى |
|---|---|---|---|
| `llm` | `model` (معرّف دقيق، لا يمكن أن يكون اسمًا مستعارًا أبدًا)؛ اختياري `provider` | واجهة سطر الأوامر (CLI)؛ بيئة التقييم (harness) عبر `-m` و`--provider` | الموفّر |
| `llm-coached` | `model`؛ يوضع التوجيه في `coaching` (`file`، أو `prompt`، أو `dir`) | واجهة سطر الأوامر؛ بيئة التقييم عبر `-m` و`--coaching-file` | الموفّر: الجمل والتوجيه |
| `mt-api` | `engine` (من `shared/method-registry.json`) | واجهة سطر الأوامر؛ بيئة التقييم | خدمة المحرك |
| `local-model` | `model` (معرّف Hugging Face أو مجلد محلي) | بيئة التقييم، داخل العملية | لا مكان |
| `nmt-checkpoint` | `model_dir` | عبر خدمته (`nmt-forge serve`) | خادم هذا الكمبيوتر |
| `lexicon` | `dictionary` | بيئة التقييم، داخل العملية | لا مكان |
| `python` | `entry_point` (`module:Class`) | بيئة التقييم (`mt-eval run --method <folder>`) | أينما يرسله الملحق (`dependency_class`) |
| `service` | `service.endpoint` | واجهة سطر الأوامر (طريقة `api`) | نقطة النهاية تلك |
| `human` | — | الأشخاص؛ يتم تقييم مخرجاتهم باستخدام `mt-eval test` | — |

اختياري: `version`، `description`، `author`، `pairs` (`{source?, target}`)،
`decode` (`temperature` 0–2، `batch_size`، `max_tokens`)، `card` (ما تعرضه
لوحة الصدارة)، `dependency_class` (`S` قائم بذاته، `O` خارجي مفتوح،
`A1`/`A2` يعتمد على واجهة برمجة التطبيقات، `X` مغلق)، `evidence` (عمليات التشغيل المقاسة: `dataset`،
`metric`، `score`، `ci`، `n` — أرقام فقط)، `runtimes` (`cli`، `engine`).

**من أين يأتي ملف method.json:** `methods/<id>/method.json` في مشروع؛
`nmt-forge export` (النوع `nmt-checkpoint`)؛ `mt-eval export --report <report>
--name <name> --type <type> --locales <code>`; `champollion serve
--emit-manifest` (kind `service`). لا تزال الأشكال القديمة (بيان ملحق CLI مع
`type`، وبيان ملحق بيئة التقييم مع `entry_point`) مقروءة، باعتبارها
method/0، مع تحذير. أما المستند الذي يحمل `$schema` فيُقرأ كـ
method/1 ويجب التحقق من صحته.

**أي بيئة تشغيل تقبل أي نوع.** ترفض واجهة سطر الأوامر (CLI) `python` و`lexicon`
و`local-model` و`human` (*"يعمل في محرك التقييم (mt-eval run --method)،
وليس في CLI الخاص بـ champollion — أو قم بتوفيره كخدمة واستخدمه عبر نقطة نهايته"*).
وتحمّل أداة `--method <folder>` في بيئة التقييم `python` فقط؛ وبالنسبة لأي نوع آخر،
توضح الرايات التي تشغله بدلاً من ذلك.

**فك الترميز.** درجة الحرارة الافتراضية هي **0** (`shared/model-defaults.json`):
قيمة موحدة لما يترجم به التطبيق وما تقيمه بيئة التقييم، وبذلك
فإن ما يُقاس هو ما يُشحن — ويكون `mt-eval run --temperature` افتراضيًا عليها.
يمكن لزوج اللغات أو الإعدادات أو عملية التشغيل تحديد القيمة الخاصة به.
معرّفات النماذج هي معرفات نصية دقيقة، وليست أسماء مستعارة مطلقًا.

## سلاسل البوابات

`$schema` `https://champollion.dev/schemas/gate-chain/1.json`، ملف واحد في
`gates/`. الحقول المطلوبة: `id`، `gates` (واحد أو أكثر). اختياري: `description`،
`fallback`.

كل بوابة: `id`، `kind` (`metric-threshold`، النوع الوحيد)، `metric` (اسم
ملحق المقياس)، `field` (مفتاح في نتيجة ذلك الملحق لكل مقطع —
رقم، أو صواب/خطأ مقروء كـ 1/0)، `min` و/أو `max`، `on_refuse`.

**القواعد** (`arena/mt_eval_harness/gates.py`):

- تعمل البوابات بالترتيب؛ وأول بوابة ترفض مقطعًا هي التي تقرر ما
  يتم شحنه:

  | `on_refuse` | ما يُشحن | يُحسب كـ |
  |---|---|---|
  | `drop` | لا شيء | مرفوض |
  | `keep-source` | النص المصدر | مرفوض |
  | `flag` | المخرجات، مع وسمها | تم الإبلاغ عنه، وليس مرفوضًا |
  | `fallback` | ترجمة البديل، إذا قبلتها البوابات نفسها؛ وإذا رُفضت مجددًا، لا شيء | مرفوض |

- **قفل.** أي مقطع لا يستطيع الملحق تقييمه يتم رفضه (`no_value`، أو
  `plugin_error:<type>`) — ولا يُشحن أبدًا كما لو أنه اجتاز الفحص.
- **قفل.** البوابة التي لم يُحمَّل ملحقها، أو لا تستطيع التقييم هنا، توقف
  التشغيل قبل ترجمة أي شيء: *"البوابة التي لا تستطيع الحكم لا تُعامل أبدًا على أنها اجتازت الفحص"*.
- **قفل.** يجب تشغيل البديل داخل هذه العملية (`lexicon`، أو `local-model`،
  أو ملحق يصرح بـ `dependency_class` `S` أو `O`)، حتى لا يغادر المقطع المرفوض
  إلى أي مكان آخر.
- **قفل.** يرفض `mt-eval run` و`mt-eval test` السلسلة التي تحتوي على بوابة `fallback`:
  *"البديل مخصص لتقديم الخدمة والترجمة، وليس للقياس أبدًا:
  فالنتيجة ستكون جزئيًا لهذه الطريقة وجزئيًا للبديلة، تحت اسم
  واحد"*. قِس البديل كطريقة مستقلة بذاتها.
- **أين تنطبق البوابات:** `mt-eval run --gates`، و`mt-eval test <run log>
  --gates` (re-scored without translating again), `mt-eval translate --gates`،
  و`mt-eval serve --gates`، و`gates` الخاص بالنشر.
- في القياس، تقيّم النتيجة الرئيسية ما يتم شحنه؛ وتوضع بجانبها نتيجة chrF++ غير الخاضعة للبوابات
  ومعدل الرفض، وتنتقل البصمة الإلكترونية للسلسلة (sha256 لملف JSON القياسي الخاص بها)
  مع التقرير ([القياس](/docs/agents/measurement#gated-measurement)).
  مع `keep-source`، تقيّم النتيجة الرئيسية النص المصدر حيثما تم شحنه.
- **قفل.** تحتاج كل بوابة إلى `min` و/أو `max`، وتكون معرّفات البوابات فريدة، وتحتاج بوابة
  `fallback` إلى `fallback` الخاص بالسلسلة — يعطي `champollion validate` وبيئة التقييم
  نفس النتيجة. إعادة محاولة المقطع المرفوض مع سبب البوابة غير مدمجة.

## مثال تطبيقي: بوابة التحقق عبر FST

يحدد محلل الحالات المنتهية (FST) ما إذا كانت الكلمة سليمة التكوين في
اللغة أم لا. يُبلغ ملحق المقياس `giellalt_fst_validity` في بيئة التقييم، لكل
مقطع، عن `fst_total_words`، و`fst_valid_words`، و`fst_invalid_words`،
و`fst_validity_rate` (0–1). يتم تقسيم الكلمات عند المسافات البيضاء مع تجريد علامات الترقيم
الطرفية؛ ويُعاد اختبار الكلمة المكتوبة بحرف استهلالي كبير بأحرف صغيرة.

```json
{
  "$schema": "https://champollion.dev/schemas/gate-chain/1.json",
  "id": "fst-every-word",
  "description": "Ship a sentence only when the analyzer accepts every word.",
  "gates": [
    { "id": "fst-all-words", "kind": "metric-threshold",
      "metric": "giellalt_fst_validity", "field": "fst_validity_rate",
      "min": 1.0, "on_refuse": "flag" }
  ]
}
```

```bash
mt-eval setup --status               # the languages with a pinned analyzer
mt-eval setup --fst                  # the analyzer runtime
mt-eval setup --lang <code>          # the language's analyzer, once per machine
mt-eval run --corpus <dev file> --target-lang-code <code> --method local-model -m <model folder> \
  --gates gates/fst-every-word.json
```

- المحلل **غير مدمج**: لا تشحن بيئة التقييم سوى التثبيتات (اسم الملف
  وsha256 لكل لغة)، ويقوم `setup --lang` بجلب المحلل من مصدره الأصلي
  إلى `~/.mt-eval/fsts/<code>/`، وفقًا لشروط المصدر الأصلي. ويتم تشغيله
  كأداة منفصلة، ولا يتم ربطه أبدًا بـ CLI الخاص بـ `champollion`.
- المحلل المفقود لا يصبح صفرًا أبدًا: كمقياس، يُصنف بأنه غير
  محسوب؛ وكبوابة، يوقف عملية التشغيل.
- المخرجات الفارغة تسجل 0 وتُرفض دون `min`.
- للتقديم كخدمة باستخدامه، استخدم `on_refuse: "fallback"` و`fallback` مثل
  `{"method": "lexicon", "model": "data/lexicon/words.tsv"}` — لكل من
  `translate` و`serve` فقط.
- **ملاحظة.** قبول FST يعني أن الكلمة موجودة، وليس أن الجملة تؤدي
  المعنى الصحيح. إنه فحص تشخيصي: ولا يدخل أبدًا في النتيجة الرئيسية لـ chrF++.

## الوصفات

### نموذج لغوي كبير موجّه (`llm-coached`)

نموذج عام يُوجّه بإرشادات المجتمع اللغوي: ملاحظات نحوية، والأسلوب،
والمصطلحات.

```bash
mt-eval run --corpus <dev file> -m <exact model id> --coaching-file coaching.md --glossary terms.json
champollion sync --method llm-coached --coaching-file coaching.md
```

- **في بيئة التقييم**، يُمثل نص ملف التوجيه مطالبة النظام بأكملها،
  لذا يجب أن يحدد ما يجب ترجمته وإخراج الترجمة فقط.
  يُعد `--glossary` مدخلاً للتقييم (الالتزام بالمصطلحات)، ولا يُرسل أبدًا.
- **قفل.** عملية تشغيل بيئة التقييم تحتوي على توجيه واحد فقط: إما `--coaching-file`، أو `--coaching`
  (نص سطري)، أو الخيار الأقدم `--custom-prompt` — حدد واحدًا فقط. ويُرفض وجود اثنين معًا:
  *"--coaching-file و --coaching يحدد كل منهما التوجيه الخاص بالتشغيل —
  حدد أحدهما (ضع النص السطري في الملف، أو احذف الملف)"*.
- **في واجهة سطر الأوامر (CLI)**، يرسل `llm-coached` مطالبته الخاصة مع تضمين التوجيه ككتلة
  "Coaching guidance"، بالإضافة إلى `.champollion/coaching/<locale>.json`
  (`grammar_rules`، `style_notes`، `dictionary`).
- **ملاحظة.** هما مطالبتان مختلفتان: النتيجة الموجهة المقاسة في
  بيئة التقييم ليست نفس المطالبة الدقيقة التي تشحنها واجهة سطر الأوامر. اذكر ذلك عند الاستشهاد بإحداهما
  كدليل على الأخرى.
- **ما يُرسل:** كل جملة مصدر والتوجيه بالكامل إلى الموفّر. وملف
  التوجيه المرفق بملف جانبي محلي فقط لا يعمل إلا على نقطة نهاية استرجاعية
  (حيث يحدد `champollion data mark coaching.md --local-only` ذلك).

### الترجمة بالأمثلة القليلة (Few-shot)

أمثلة على ترجمات جيدة داخل التوجيه. إنها نموذج لغوي كبير موجّه: نفس
الأوامر، ونفس وسيلة النقل — تنتقل الأمثلة في مطالبة النظام إلى
الموفّر.

- **ملاحظة.** إياك أن تأخذ أمثلة من مجموعة الاختبار، ولا من ملف
  مخصص للاستخدام المحلي فقط لموفّر بعيد. لا يوجد ما يفحص أمثلة few-shot
  تلقائيًا مقابل المراجع الاختبارية.

### نموذج لغوي كبير معزز بالقاموس

- **واجهة سطر الأوامر (CLI):** يتم إرسال `dictionary` الموجود في `.champollion/coaching/<locale>.json`
  إلى كل طريقة نموذج لغوي كبير كـ "REQUIRED TERMINOLOGY" للمصطلحات الموجودة في كل
  دفعة (مطابقة سلاسل نصية فرعية غير حساسة لحالة الأحرف). وتتلقاه خدمة DeepL كمسرد مصطلحات.
  يتم التحذير من المخالفات بعد الترجمة؛ ولا توجد إعادة محاولة.
- **بيئة التقييم:** لا يصل القاموس إلى النموذج إلا كنص في ملف
  التوجيه.
- **القاموس بمفرده:** `mt-eval run --method lexicon -m data/lexicon/words.tsv
  --corpus <dev file>` — العبارة الأطول أولاً، مع الاحتفاظ بالكلمات غير المعروفة، داخل
  العملية. يمثل `nmt-forge floor` هذا الأمر، على مجموعة التطوير
  ([القياس](/docs/agents/measurement#the-dictionary-floor)).
- **ما يُرسل:** المدخلات المطابقة في القاموس، مع الجمل، إلى
  الموفّر. ويجب ألا يُرسل قاموس مخصص للاستخدام المحلي فقط إلى موفّر بعيد.

### النموذج الهجين القائم على القواعد

لا يوجد محرك قواعد مدمج. ما هو متوفر: `lexicon` (حتمي، داخل
العملية)؛ و`mt-eval run --method apertium` (محرك قائم على القواعد — يرسل النص
إلى `apertium.org` ما لم يشر `APERTIUM_API_URL` إلى خادمك الخاص)؛
وملحقات `python` لقواعدك الخاصة، اختياريًا مع نموذج لغوي كبير. تحتاج فئة الملحق
إلى `async def translate(self, entries, config)`؛ شغّلها باستخدام `mt-eval run
--method <folder>`. تحقق من صحة مخرجاتها باستخدام سلسلة بوابات.

- **ما يُرسل:** أي شيء يستدعيه الملحق. الملحق طريقة خارجية: ففي مدونة نصوص
  تتطلب الموافقة أو مغلقة (بما في ذلك المخصصة للاستخدام المحلي فقط)، ترفض بيئة التقييم
  ذلك ما لم يتم تمرير `--attest-local-transport` — والذي لا تمرره إلا بعد التحقق
  من أن كل ما يستدعيه موجود على هذا الجهاز.

### الطرق المتسلسلة

هناك سلسلتان مدمجتان:

1. **بديل سلسلة البوابات:** الطريقة ← البوابات ← البديل داخل العملية ←
   البوابات نفسها. لكل من `translate` و`serve` فقط.
2. **بديل الزوج في واجهة سطر الأوامر** (`"fallback": {"method": …}` على زوج لغات التطبيق):
   الطريقة الأساسية ← بوابة الجودة في واجهة سطر الأوامر ← إعادة المحاولة مع ملاحظات البوابة
   (طرق النماذج اللغوية الكبيرة، أو نقطة نهاية `api` تعلن عن `acceptsInstructions`) ←
   البديل لمرة واحدة، عبر البوابة نفسها.

أي شيء أطول من ذلك (توليد، تحرير، تحقق عبر نماذج متعددة) يكون ملحق `python`
أو `service`.

- **ما يُرسل:** تُرسل كل حلقة ما يرسله نوعها. وتكون خصوصية السلسلة بمستوى خصوصية
  أقل حلقاتها أمانًا.

### الترجمة الجزئية (البشر والآلة)

يُعدّ النموذج المسودة؛ ويقوم متحدث باللغة بالمراجعة والتصحيح. في المسارات، هذه هي جولة
التحسين: يضع `champollion improve sheet` المسودات، ويضع المتحدث علامة `Y`/`N`/`?`،
ويحوّل `champollion improve marks` التصحيحات والمسودات المؤكدة إلى أزواج تدريب،
وصفوف التدريب إلى جمل تطوير ([التوجيه](/docs/agents/coaching)).
ولتقييم ترجمات الأشخاص كطريقة قائمة بذاتها (`kind` `human`)، شغّل
`mt-eval test` على مخرجاتهم. وتعلّم البوابة المزودة بـ `on_refuse: "flag"` المخرجات
للمراجعة.

- **ملاحظة.** يجب ألا تكون الجملة المستخدمة لتوجيه طريقة ما أو تدريبها ضمن الجمل التي
  يتم تقييمها عليها مطلقًا.
- **ما يُرسل:** لا شيء يتجاوز القواعد الخاصة بنموذج إعداد المسودات؛ وتبقى الجداول في
  مجلد المشروع.

### النموذج المضبوط بدقة

- **في المسارات:** `nmt-forge` (`nmt-checkpoint`؛ الإعدادات المسبقة `cpu-tiny`،
  `byt5-small`، `byt5-small-lowmem`، `cpu-finetune`، `nllb-600m`)، بعد تصديره
  وتقديمه كخدمة وتوصيله —
  [التدريب](/docs/agents/training)، [التقديم كخدمة](/docs/agents/serving).
- **نموذج مفتوح لديك بالفعل:** `mt-eval run --method local-model -m
  <Hugging Face id or folder>` — داخل العملية؛ ولا شيء يغادر الجهاز.
- **نموذج لغوي كبير تستضيفه بنفسك** (Ollama، أو vLLM، أو أي نموذج متوافق مع OpenAI):
  `mt-eval run --provider local --base-url http://127.0.0.1:11434/v1 -m
  <model name>`. ولا يُعتبر محليًا إلا عندما تكون نقطة النهاية عنوان استرجاع.
- **ما يُرسل:** لا شيء يخرج عن الجهاز، عندما تكون نقطة النهاية محلية حقًا.
