# การแก้ไขปัญหา

ปัญหาที่พบบ่อยและวิธีแก้ไขสำหรับ champollion

## API และการยืนยันตัวตน

### "OPENROUTER_API_KEY not found"

Champollion ต้องการ API key สำหรับการแปลด้วย LLM ตั้งค่าเป็นตัวแปรสภาพแวดล้อม:

```bash
export OPENROUTER_API_KEY="sk-or-v1-..."
```

หรือในไฟล์ `.env` (หากโปรเจกต์ของคุณโหลดไฟล์ `.env`):

```
OPENROUTER_API_KEY=sk-or-v1-...
```

:::tip
หากคุณมีเพียง Google Translate API key, champollion จะตรวจจับและใช้ Google Translate เป็นวิธีการเริ่มต้นโดยอัตโนมัติ ไม่จำเป็นต้องเปลี่ยนการตั้งค่า
:::

### "401 Unauthorized" จาก OpenRouter

API key ของคุณไม่ถูกต้องหรือหมดอายุแล้ว ตรวจสอบได้ที่ [openrouter.ai/keys](https://openrouter.ai/keys)

### "429 Too Many Requests" / การจำกัดอัตราการใช้งาน

Champollion จัดการข้อจำกัดอัตราการใช้งานภายในด้วย exponential backoff หากคุณพบปัญหานี้อย่างต่อเนื่อง:

1. **ลดขนาดแบตช์ (batch size)** ในคอนฟิกของคุณ:
   ```json
   { "batchSize": 15 }
   ```
2. **ใช้โมเดลที่มีขีดจำกัดอัตราการเรียกใช้ (rate limit) สูงกว่า** (เช่น `google/gemini-3.8-flash` มีขีดจำกัดที่สูงมาก)
3. **ใช้วิธีการที่ถูกกว่า/เร็วกว่า** สำหรับคู่ภาษาที่มีปริมาณงานสูง — Google Translate ไม่มีขีดจำกัดอัตราการเรียกใช้:
   ```json
   { "pairs": { "en:it": { "method": "google-translate" } } }
   ```

### โมเดลไม่พบ / ข้อผิดพลาด 404

ผู้ให้บริการ LLM โดยตรง (`openai`, `anthropic`, `gemini`) จะได้รับชื่อโมเดลตามรูปแบบของตนเอง ID ในรูปแบบ OpenRouter ของผู้ให้บริการรายนั้นจะถูกแมปให้คุณโดยอัตโนมัติ (`google/gemini-3.8-flash` → `gemini-3.8-flash` บน `gemini`) หากการทำงานหยุดลงพร้อมข้อความ:

**"is an OpenRouter model id … which has no model by that name"** — คุณกำลังใช้โมเดลในรูปแบบ OpenRouter จากผู้ให้บริการรายอื่น (`google/gemini-3.8-flash` ร่วมกับ `openai`) จึงไม่มีการส่งคำขอใด ๆ ให้ระบุชื่อโมเดลของผู้ให้บริการรายนั้น, ใช้วิธีการที่มีโมเดลดังกล่าว หรือเปลี่ยนไปใช้วิธี `llm` เพื่อใช้งาน OpenRouter — ข้อความแจ้งเตือนจะระบุแต่ละรายการ รวมถึงตำแหน่งที่มีการตั้งค่าโมเดลไว้:

```diff
- { "method": "openai", "model": "google/gemini-3.8-flash" }
+ { "method": "openai", "model": "gpt-4o" }
```
```json
{ "method": "llm", "model": "google/gemini-3.8-flash" }
```

ระบบจะตรวจสอบชื่อโมเดลของคุณเมื่อใช้งานครั้งแรกด้วยเช่นกัน หากคุณเห็นคำเตือน:

**"is an Anthropic/OpenAI/Gemini model"** — คุณกำลังส่งโมเดลไปยังผู้ให้บริการที่ไม่ถูกต้อง:

```diff
- { "method": "gemini", "model": "claude-sonnet-4-6" }
+ { "method": "anthropic", "model": "claude-sonnet-4-6" }
```

**"not found in available models"** — โมเดลอาจถูกยกเลิกหรือสะกดผิด Champollion ดึงรายการโมเดลที่ใช้งานได้จากผู้ให้บริการและแนะนำทางเลือกอื่น ตรวจสอบเอกสารของผู้ให้บริการสำหรับชื่อโมเดลปัจจุบัน

:::tip[การเลิกใช้งานโมเดลเป็นเรื่องปกติ]
ผู้ให้บริการมักจะยกเลิกชื่อโมเดลเป็นประจำ หากการแปลล้มเหลวกะทันหันหลังจากผู้ให้บริการอัปเดต ให้ตรวจสอบผลลัพธ์ของ `[WARN]` — จะแสดงตัวเลือกอื่นที่ใช้งานได้ในปัจจุบัน
:::

### `local`: "could not reach …"

วิธีการ `local` จะส่งคำขอไปยังเซิร์ฟเวอร์ที่เข้ากันได้กับ OpenAI บนเครื่องของคุณ (Ollama, vLLM, LM Studio, llama.cpp) เมื่อไม่สามารถเชื่อมต่อได้ ข้อผิดพลาดจะระบุแอดเดรสที่พยายามเชื่อมต่อและการตั้งค่าที่เลือกแอดเดรสนั้น:

```text
[ERR] Local (OpenAI-compatible) Batch 1 failed: fetch failed (ECONNREFUSED) — could not reach http://localhost:8000/v1 (from LOCAL_API_BASE in .env)
```

แอดเดรสจะนำมาจากค่าแรกที่ถูกกำหนดไว้ใน environment หรือใน `.env.local` / `.env` ตามลำดับ: `LOCAL_API_BASE`, ถัดมาคือ `OPENAI_API_BASE`, และ `OPENAI_BASE_URL` หากไม่มีการตั้งค่าใด ๆ จะใช้ค่าเริ่มต้นของ Ollama คือ `http://localhost:11434/v1` ให้เริ่มการทำงานของเซิร์ฟเวอร์ หรือแก้ไขการตั้งค่าตามที่ข้อความระบุ

## คุณภาพการแปล

### การแปลสะท้อนภาษาต้นฉบับ

quality gate จะตรวจจับสิ่งนี้ หากการแปลเหมือนกับต้นฉบับภาษาอังกฤษ จะถูกปฏิเสธและลองใหม่ หากยังคงเกิดขึ้น:

1. **ตรวจสอบโมเดล** — โมเดลบางตัวอาจทำงานได้ไม่ดีสำหรับคู่ภาษาเฉพาะบางคู่
2. **เพิ่มคำสั่งระดับภาษา (register)** — กำหนดให้โมเดลทราบว่าต้องสร้างผลลัพธ์เป็นภาษาใด:
   ```json
   {
     "languages": {
       "ja": { "name": "Japanese", "register": "Polite/formal Japanese" }
     }
   }
   ```
3. **ลองใช้โมเดลอื่น** — สลับจาก `gpt-4o-mini` เป็น `gpt-4o` หรือ `google/gemini-3.1-pro-preview`

### ผลลัพธ์เป็นสคริปต์ที่ไม่ถูกต้อง (เช่น ข้อความ Latin สำหรับภาษาญี่ปุ่น)

การตรวจสอบการปฏิบัติตามสคริปต์ของ quality gate จะตรวจจับกรณีส่วนใหญ่ หากยังคงเกิดขึ้น:

- ตรวจสอบว่า locale code ถูกต้อง (`ja` ไม่ใช่ `jp`)
- เพิ่มคำแนะนำสคริปต์อย่างชัดเจนในฟิลด์ `register`:
  ```json
  { "register": "Japanese using hiragana, katakana, and kanji" }
  ```

### ชื่อเฉพาะไม่ผ่านการตรวจสอบยืนยัน (เช่น "Curtis Forbes" ในภาษาญี่ปุ่น)

ชื่อเฉพาะเหล่านี้ถูกต้องแล้วในอักษรละติน ดังนั้นให้แจ้ง Champollion ทราบว่าชื่อของคุณมีอะไรบ้าง:

```json
{ "protectedTerms": ["Curtis Forbes", "Game Day Suits"] }
```

โมเดลจะได้รับคำสั่งให้คงชื่อเหล่านั้นไว้ตามที่เขียน และค่าที่มีเฉพาะชื่อเหล่านี้จะไม่ถูกรายงานว่ายังไม่ได้แปลหรือใช้อักษรผิดเด็ดขาด หากไม่มีรายการนี้ ค่าสั้น ๆ ที่เป็นอักษรละตินในภาษาที่ไม่ใช่อักษรละตินจะได้รับการลองใหม่ (retry) หนึ่งครั้งเพื่อถามว่าเป็นชื่อเฉพาะหรือป้ายกำกับ (label) หากโมเดลคงค่านั้นไว้ ระบบจะยอมรับว่าเป็นชื่อเฉพาะและแคชไว้ ทำให้ไม่ต้องเสียค่าใช้จ่ายซ้ำอีก คุณไม่จำเป็นต้องใช้ `--no-verify`

### รูปแบบ hallucination ในผลลัพธ์

รูปแบบ trigram ที่ซ้ำกัน (เช่น "hello hello hello") จะถูกตรวจจับโดย hallucination loop detector หากผลลัพธ์ผิดปกติแต่ผ่านตัวตรวจจับ:

1. **ลดขนาด batch** — batch ที่เล็กกว่าให้ผลลัพธ์ที่มีสมาธิมากขึ้น
2. **ใช้โมเดลที่แข็งแกร่งกว่า** — โมเดลขนาดใหญ่กว่า hallucinate น้อยกว่าสำหรับสคริปต์ที่ไม่ใช่ Latin
3. **เพิ่มข้อมูล coaching** — คำศัพท์จากพจนานุกรมช่วยยึดการแปล

## ปัญหาไฟล์และรูปแบบ

### "No locale files found"

Champollion ตรวจจับไฟล์ locale โดยอัตโนมัติ หากไม่พบ:

1. **ตรวจสอบ `localesDir`** — ต้องชี้ไปยังไดเรกทอรีที่มีไฟล์ locale:
   ```json
   { "localesDir": "./locales" }
   ```
2. **ตรวจสอบการตั้งชื่อไฟล์** — ไฟล์ต้องตั้งชื่อตาม locale code: `en.json`, `fr.json` เป็นต้น
3. **ตรวจสอบรูปแบบ** — รูปแบบที่รองรับ: JSON, nested JSON, YAML, TOML

### ความขัดแย้งของ lock file

`.champollion.lock` บันทึกว่าคำแปลแต่ละรายการสร้างขึ้นมาจากข้อความภาษาอังกฤษใด
แก้ไขความขัดแย้งในการผสาน (merge conflict) ในไฟล์นี้เช่นเดียวกับไฟล์ที่ถูกสร้างขึ้น (generated file) อื่น ๆ: เลือกเก็บฝั่งใดฝั่งหนึ่งไว้, รัน `npx champollion sync` แล้วคอมมิตผลลัพธ์

:::warning[การลบไฟล์ล็อกไม่ได้ทำให้เกิดการแปลใหม่]
หากไม่มีไฟล์ล็อก คำสั่ง sync จะไม่สามารถบอกได้ว่าข้อความภาษาอังกฤษใดเปลี่ยนแปลงไปบ้างนับตั้งแต่มีการแปลครั้งก่อนหน้า คำสั่งจะแปลเฉพาะคีย์ที่**ขาดหายไป**จากไฟล์ปลายทางเท่านั้น และบันทึกข้อความภาษาอังกฤษปัจจุบันเป็นค่าฐานใหม่ ข้อความภาษาอังกฤษที่ถูกแก้ไขก่อนที่ไฟล์ล็อกจะถูกลบจะยังคงใช้คำแปลเดิมต่อไปอย่างเงียบ ๆ หากต้องการสร้างโลแคลขึ้นมาใหม่ทั้งหมด ให้ใช้ `--force` (กำหนดขอบเขตด้วย `--pair`); คำแปลที่แคชไว้จะถูกนำกลับมาใช้ใหม่ ดังนั้นจะมีการคิดค่าใช้จ่ายเฉพาะข้อความที่แคชไม่เคยพบมาก่อนเท่านั้น
:::

### การแปล key เฉพาะใหม่

หากการแปลบางรายการไม่ถูกต้องและคุณต้องการบังคับให้แปลใหม่โดยไม่ลบ lock file:

```bash
# Re-translate a single key
npx champollion sync --force-keys "hero.title"

# Re-translate multiple keys
npx champollion sync --force-keys "nav.home,nav.about,footer.copyright"
```

แฟล็ก `--force-keys` จะข้ามการตรวจสอบแฮชของไฟล์ล็อกสำหรับคีย์ที่ระบุเหล่านั้น เพื่อบังคับให้แปลใหม่โดยไม่ส่งผลกระทบต่อคีย์อื่น ๆ `--redo keys:hero.title` คือคำสั่งเดียวกันภายใต้ชื่อใหม่ ทั้งสองคำสั่งจะดึงผลลัพธ์จาก Translation Memory มาใช้หากมีข้อความนั้นอยู่แล้ว ให้เพิ่ม `--fresh` หากต้องการจ่ายเพื่อขอรับการแปลใหม่แทน คีย์ที่มีเครื่องหมายจุลภาค (comma) อยู่ภายใน (เช่น msgid ของ gettext ที่เป็นทั้งประโยค) ให้เขียนด้วย `\,` และใส่เครื่องหมายคำพูดครอบอาร์กิวเมนต์สำหรับเชลล์: `--redo 'keys:Welcome back\, %(name)s!'`

### `verify` รายงานว่าตัวแทนข้อความ (placeholder) ไม่ตรงกัน (หรือค่าอื่น ๆ เสียหาย)

`champollion verify` (และการตรวจสอบที่รันหลังการ sync ทุกครั้ง) จะรายงานค่าที่เสียหาย: ตัวแทนข้อความ (placeholder) ที่สูญหายหรือถูกเปลี่ยนชื่อ, พหูพจน์ ICU (ICU plural) ที่ใช้งานไม่ได้, ค่าที่ตัวอักษรถูกลบหายไป การรัน `champollion sync` แบบธรรมดาจะ**ไม่**ซ่อมแซมค่าเหล่านี้ เนื่องจากค่านั้นมีอยู่บนดิสก์แล้วและรายการในล็อกระบุว่าเป็นปัจจุบัน sync จึงข้ามค่านั้นไป

ผลการตรวจสอบแต่ละรายการจะระบุคำสั่งที่ใช้ซ่อมแซมเฉพาะคีย์เหล่านั้น เช่น:

```text
[ERR] [VERIFY] fr: 1 i18next {{…}} placeholder mismatch(es): greeting (placeholder {{name}} was changed to {{nom}}) — fix: `champollion sync --pair en:fr --redo keys:greeting`
```

ให้รันคำสั่งดังกล่าว เมื่อโลแคลครอบคลุมหลายไฟล์ คีย์จะถูกเขียนในรูปแบบ `<file>::<key>` (เช่น `common::nav.home`) ซึ่งจะแปลคีย์ของไฟล์นั้นใหม่เพียงไฟล์เดียวและไม่แตะต้องส่วนอื่น

คุณไม่จำเป็นต้องใช้ `--fresh` หากค่าที่เสียหายมาจาก Translation Memory คำสั่ง `verify` จะลบมันออกจากแคชให้เรียบร้อยแล้ว พร้อมข้อความแจ้ง: `[TM] Evicted 1 cached translation(s) that produced damaged values` การทำซ้ำ (redo) จะแปลข้อความใหม่อีกครั้ง (หรือนำคำแปลอื่นที่ถูกต้องจากแคชมาใช้) แทนที่จะนำค่าที่เสียหายกลับมาใช้ซ้ำ ส่วนค่าที่มีการแก้ไขด้วยตนเองจะไม่ถูกแคชอยู่แล้ว จึงไม่มีอะไรต้องลบ และการทำซ้ำก็จะทำงานในลักษณะเดียวกัน

สำหรับไฟล์เนื้อหา Markdown/MDX ให้ใช้ `--retranslate` พร้อมระบุพาธหรือ glob แทน (เช่น `--retranslate docs/intro.md`) คำสั่งนี้จะแปลไฟล์เหล่านั้นใหม่ทั้งหมด แม้ว่าไฟล์จะเป็นปัจจุบันอยู่แล้วหรือเคยแปลด้วยตนเองก็ตาม ใช้ `--files` เพื่อจำกัดการทำงานให้อยู่ในไฟล์เนื้อหาบางไฟล์โดยไม่บังคับแปลใหม่

### การแปลเนื้อหาทำให้ code block เสียหาย

สิ่งนี้ไม่ควรเกิดขึ้น — code block จะถูกป้องกันก่อนการแปล หากเกิดขึ้น:

1. ตรวจสอบว่า code block ใช้ fencing มาตรฐาน (triple backticks)
2. ตรวจสอบ code block ที่ไม่ได้ปิดในต้นฉบับ Markdown
3. รายงานปัญหา — นี่คือ bug ในระบบ sentinel shielding

## ปัญหา CLI

### `--watch` ไม่ตรวจจับการเปลี่ยนแปลง

การเฝ้าดูไฟล์ใช้ Node.js native `fs.watch` ปัญหาที่ทราบ:

- **Network drives** — `fs.watch` ทำงานไม่น่าเชื่อถือบน NFS/SMB mounts
- **Docker volumes** — ใช้ polling mode หรือรัน champollion ภายใน container
- **ไดเรกทอรีขนาดใหญ่** — watcher ตรวจสอบ `localesDir` แบบ recursive; tree ที่ลึกมากอาจเกินขีดจำกัดของ OS

### `npx` รันเวอร์ชันเก่า

```bash
# Clear the npx cache
npx --yes champollion@latest sync
```

หรือติดตั้งแบบ global:

```bash
npm install -g champollion
champollion sync
```

## ประสิทธิภาพ

### การ sync ช้าสำหรับหลายภาษา

Champollion แปลทุก locale พร้อมกันโดยค่าเริ่มต้น หากการ sync ยังช้าอยู่:

1. **ใช้ Google Translate สำหรับคู่ภาษาที่มีปริมาณสูง** — เร็วกว่าการแปลด้วย LLM 10–50 เท่า
2. **เพิ่มขนาด batch** (ค่าเริ่มต้นคือ 80):
   ```json
   { "batchSize": 120 }
   ```
3. **ปรับ concurrency** — parallelism ของ JSON locale ค่าเริ่มต้นคือ 200 และ content คือ 48 หาก API provider ของคุณรองรับขีดจำกัดอัตราการใช้งานที่สูงกว่า:
   ```bash
   npx champollion sync --json-concurrency 80 --content-concurrency 20
   ```
4. **ใช้โมเดลที่เร็ว** — `gpt-4o-mini` เร็วกว่า `gpt-4o` อย่างมีนัยสำคัญ

### ค่าใช้จ่าย API สูง

- **ตรวจสอบขนาด batch** — batch ที่ใหญ่กว่า = การเรียก API น้อยกว่า = ค่าใช้จ่ายต่ำกว่า
- **ใช้ Translation Memory** — TM เปิดใช้งานโดยค่าเริ่มต้น รัน `champollion tm stats` เพื่อตรวจสอบว่าทำงานอยู่ หากคุณเห็น 0 รายการหลังจาก sync หลายครั้ง อาจมีปัญหากับสิทธิ์ไดเรกทอรี `.champollion/` ของคุณ
- **ใช้ prompt caching** — Champollion แยก system/user messages สำหรับ cache hits บนโมเดล Anthropic และ Google
- **ใช้ Google Translate สำหรับภาษา Tier 2** — ดู cookbook [แปล 30 ภาษา](/docs/tutorials/translate-30-languages)

### การแปลหลังจากสลับโมเดลหรือผู้ให้บริการ

การสลับวิธีการ (เช่น จาก `llm` เป็น `deepl`), ระดับภาษา (register) หรือการโค้ช (coaching) จะให้คำแปลใหม่สำหรับสิ่งที่ถูกแปลใหม่อีกครั้ง เนื่องจากแคชคีย์รวมข้อมูลเหล่านี้ไว้ด้วย — แต่การ sync แบบธรรมดาจะไม่แปลสิ่งที่มีอยู่แล้วซ้ำอีก: คำสั่ง `champollion sync --redo all` จะทำหน้าที่นั้น การสลับ**โมเดล**ภายในวิธีการเดียวกันจะนำสิ่งที่โมเดลก่อนหน้าแปลไว้กลับมาใช้ใหม่โดยไม่มีค่าใช้จ่าย ซึ่ง sync จะแจ้งให้คุณทราบก่อนแสดงการประเมินราคา หากคุณต้องการคำแปลจากโมเดลใหม่เอง:

```bash
# Have the new model translate what an earlier model wrote
# (what the new model already translated still comes from the cache)
champollion sync --redo all --fresh-on-model-change

# Re-translate specific content files from scratch
champollion sync --retranslate "docs/guides/**"
```

`--fresh-on-model-change` เพียงอย่างเดียวจะเปลี่ยนเฉพาะคีย์ที่การรันต้องแปลอยู่แล้ว (คีย์ใหม่หรือคีย์ที่เปลี่ยนแปลง): หลังจากสลับเฉพาะโมเดล การรัน `sync --fresh-on-model-change` แบบธรรมดาจะไม่ส่งคำขอใด ๆ

ดู [Translation Memory](/docs/concepts/translation-memory) สำหรับรายละเอียดเกี่ยวกับการออกแบบ cache key

## การกู้คืนจากเวอร์ชันที่มีปัญหา {#recover-old-damage}

ค่าที่ถูกเขียนโดยไปป์ไลน์เวอร์ชันเก่าจะ**ไม่มีวันซ่อมแซมตัวเองโดยอัตโนมัติ**: แฮชของ manifest ยังคงตรงกับต้นฉบับปัจจุบัน ดังนั้น `sync` จึงถือว่าค่านั้นเสร็จสมบูรณ์แล้ว และไม่มีเกต (gate) ใดได้ตรวจสอบค่านั้นอีก หากคุณกำลังอัปเกรดโปรเจกต์ที่เคยใช้เวอร์ชันก่อน 0.3.0 ให้สันนิษฐานไว้ก่อนว่าอาจมีความเสียหายหลงเหลืออยู่ในไฟล์โลแคลของคุณ และควรตรวจสอบ (audit) ดูก่อน:

```bash
champollion integrity
```

การตรวจสอบจะตรวจหารูปแบบความเสียหายที่เป็นที่รู้จักและระบุวิธีแก้ไขสำหรับแต่ละรูปแบบ:

| สิ่งที่พบ | คำอธิบาย | วิธีแก้ไข |
|---------|-----------|-----|
| `UNEXPECTED PUA` | ผลลัพธ์จากการแปลงอักษร (pIqaD/Tengwar/Kryptonian) ที่ถูกเขียนเมื่อไม่ต้องการการแปลง — แสดงผลเป็นค่าว่าง | `champollion repair-script` (ออฟไลน์, แม่นยำสำหรับ pIqaD) |
| `HOLLOWED VALUES` | ต้นฉบับที่ตัวอักษรถูกลบหายไป — ผลลัพธ์จากช่วงก่อนมีเกตตรวจสอบการคงเนื้อหา (content-preservation gate) | แปลใหม่ (ดูด้านล่าง) |
| `NO-TRANSLATE DRIFT` | URL หรือคีย์ที่ต้องคงค่าเดิม (verbatim) ที่ถูก "แปล" | `champollion sync` (ซ่อมแซมฟรีโดยอัตโนมัติ) |

สำหรับค่าที่ตัวอักษรกลวงหายไป — หรือโลแคลใดก็ตามที่คุณไม่ไว้วางใจอีกต่อไป — ให้สร้างใหม่ทั้งหมด:

```bash
champollion sync --pair en:tlh --force
```

`--force` จะนำทุกคีย์ต้นฉบับเข้าคิวใหม่สำหรับคู่ภาษาที่กำหนดไว้ ผลลัพธ์ที่ตรงกับ Translation Memory จะยังคงถูกนำมาใช้ แต่ทุกค่าที่ดึงมาใช้จะ**ได้รับการตรวจสอบความถูกต้องผ่านเกตปัจจุบันก่อนเสมอ** — ค่าในแคชที่เกตปฏิเสธจะถูกขับออกและคิดค่าบริการเพื่อแปลใหม่ เพื่อให้แคชที่มีข้อมูลเสียหายรักษาตัวเองแทนที่จะป้อนข้อมูลเดิมให้กับการสร้างใหม่ ให้เพิ่ม `--no-tm` หากต้องการคิดค่าบริการเพื่อแปลใหม่ทั้งหมดตั้งแต่ต้น และใช้ `--max-cost` เพื่อจำกัดงบประมาณการใช้งานไม่ว่าในกรณีใด

การตรวจสอบหลังการ sync จะรายงานรูปแบบความเสียหายเหล่านี้ด้วยเช่นกัน ดังนั้นโลแคลที่เสียหายจะทำให้ `sync` ล้มเหลวอย่างชัดเจน (พร้อมระบุวิธีแก้ไข) แทนที่จะปล่อยผ่านไปสู่การเผยแพร่โดยไม่รู้ตัว

### การเข้าคิวใหม่เพียงครั้งเดียวหลังทำความสะอาดด้วย `--no-tm` {#one-time-requeue}

หากการกู้คืนของคุณใช้ `--no-tm` โปรดทราบว่าการ sync ใน**รอบถัดไป**จะนำกลุ่มของคีย์ที่สะท้อนต้นฉบับ (source-echo keys) ซึ่งคุณคิดว่าเสร็จสมบูรณ์แล้วเข้าคิวใหม่ เนื่องจาก `--no-tm` เขียนค่าลงไปโดยไม่ได้ประทับตรา (stamp) ลงใน Translation Memory และค่าที่*ไม่ได้ประทับตรา*ซึ่งเหมือนกับต้นฉบับจะไม่สามารถแยกแยะจากข้อความที่ยังไม่ได้แปลได้ — ดังนั้นจึงต้องเข้าคิวใหม่อีกหนึ่งครั้ง และเมื่อได้ผลลัพธ์กลับมา (ซึ่งมักจะเหมือนเดิม) จะได้รับการประทับตราและเสร็จสมบูรณ์อย่างถาวร สิ่งนี้เป็นค่าใช้จ่ายเพียงครั้งเดียว ไม่ใช่การวนลูปไม่รู้จบ คุณสามารถดูตัวอย่างล่วงหน้าว่ามีคีย์ใดบ้างได้ด้วยคำสั่ง:

```bash
champollion sync --dry --list-keys
```
