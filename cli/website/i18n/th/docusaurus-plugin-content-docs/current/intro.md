# การแปลแอปและเว็บไซต์

`champollion sync` ช่วยให้คำแปลของแอปหรือเว็บไซต์เป็นปัจจุบันตรงกับภาษาต้นทางเสมอ เครื่องมือนี้จะอ่านไฟล์ภาษา (หรือหน้า Markdown) ของคุณ ค้นหาส่วนที่ยังขาดหรือล้าสมัย แปลเฉพาะส่วนนั้น ตรวจสอบผลลัพธ์แต่ละรายการ แล้วเขียนกลับลงในรูปแบบไฟล์เดิม

```bash
npx champollion sync
```

ส่วนนี้คือเอกสารอ้างอิงสำหรับกระบวนการดังกล่าว หากคุณต้องการอ่านเวอร์ชันที่ใช้ภาษาเรียบง่ายก่อน โปรดอ่าน [แปลแอปหรือเว็บไซต์](/docs/translate-an-app-or-website)

## สิ่งที่ `sync` ทำ

1. **ค้นหาไฟล์ของคุณ** เครื่องมือจะตรวจหาโฟลเดอร์ภาษาและรูปแบบไฟล์ (JSON, TOML,
   YAML, gettext PO, Flutter ARB) หรือโฟลเดอร์ของหน้า Markdown/MDX (Hugo,
   Docusaurus หรือโฟลเดอร์ใดก็ตามที่คุณระบุด้วย `--content-dir`)
2. **ตรวจหาว่ามีอะไรเปลี่ยนแปลงบ้าง** ค่าต้นทางทุกค่าจะถูกบันทึกด้วยแฮช SHA-256
   ใน `.champollion.lock` คีย์ที่ขาดหายไป ว่างเปล่า หรือข้อความต้นทางเปลี่ยนไปจะถูกจัดเข้าคิว
   ส่วนข้อความอื่นๆ ทั้งหมดจะคงไว้เช่นเดิม
3. **แปลด้วยวิธีที่คุณเลือกสำหรับแต่ละคู่ภาษา** ไฟล์การกำหนดค่าไฟล์เดียวสามารถ
   ส่งคู่ภาษาหนึ่งไปยัง LLM, ส่งอีกคู่หนึ่งไปยัง API การแปลด้วยเครื่อง และส่งคู่ที่สาม
   ไปยังโมเดลที่คุณฝึกฝนและโฮสต์ขึ้นใช้งานเอง โดยวิธีที่ใช้ LLM จะแปลที่
   temperature 0 เป็นค่าเริ่มต้น (ค่าเริ่มต้นหนึ่งเดียวใน `shared/model-defaults.json`)
   ส่วนโมเดลที่โฮสต์ไว้อาจยังให้ผลต่างกันเล็กน้อยในการรันแต่ละครั้ง ซึ่งเป็นเหตุผลหนึ่ง
   ที่หน่วยความจำการแปล (Translation Memory) เก็บสิ่งที่เคยได้ไว้
4. **นำสิ่งที่จ่ายไปแล้วกลับมาใช้ซ้ำ** Translation Memory จะแคชการแปลแต่ละรายการ
   ตามข้อความต้นทาง ภาษา และวิธีที่ใช้: ข้อความที่กลับมาเป็นแบบเดิม (สตริงที่ถูกเปลี่ยนกลับ,
   ประโยคเดียวกันในอีกไฟล์หนึ่ง หรือการแปลซ้ำ) จึงไม่มีค่าใช้จ่ายเพิ่ม
5. **ตรวจสอบผลลัพธ์ทุกรายการก่อนเขียนไฟล์** เกตควบคุมคุณภาพ (quality gate) จะปฏิเสธ
   ผลลัพธ์ที่ว่างเปล่า การคัดลอกข้อความต้นทางมา ลูปข้อความซ้ำ ผลลัพธ์ที่ใช้อักษรผิด
   ตัวยึดตำแหน่ง (placeholder) ที่เสียหาย และข้อผิดพลาดในทำนองเดียวกัน พร้อมลองซ้ำแบบมีฟีดแบ็กหนึ่งครั้ง
   เครื่องมือจะตรวจจับผลลัพธ์ที่เสียหาย ไม่ใช่ความหมายที่ผิด
6. **ตรวจสอบซ้ำหลังเขียนไฟล์** ขั้นตอนหลังการซิงก์จะอ่านไฟล์ที่เขียนแล้วอีกครั้ง
   และตรวจสอบความครบถ้วนของคีย์ ค่าที่ว่างเปล่า อักษร และตัวยึดตำแหน่ง
   โดย `champollion verify` และ `champollion audit` จะทำการตรวจสอบแบบเดียวกันนี้ในฐานะ
   CI gate

ไม่มีสิ่งใดถูกเขียนลงไฟล์โดยไม่แจ้งให้ทราบ หากคีย์ใดยังคงถูกเกตปฏิเสธหลังจากการลองซ้ำ คีย์นั้นจะ
ถูกปล่อยไว้โดยไม่แปลและจะมีการรายงานให้ทราบ และการซิงก์จะออกจากระบบด้วย `2` การปฏิเสธนี้จะ
ถูกจดจำไว้ การซิงก์ธรรมดาครั้งต่อไปจึงไม่ต้องจ่ายเงินให้โมเดลเดิมสำหรับ
คำตอบเดิมซ้ำอีก: คุณสามารถสั่งขอใหม่อีกครั้งด้วย `--redo` เพิ่มวิธี `fallback` ให้กับคู่ภาษานั้น หรือ
เขียนค่านั้นด้วยตนเอง

## ควรใช้เมื่อใด

- คุณมีแอปหรือเว็บไซต์ที่เก็บข้อความไว้ในไฟล์ภาษาหรือ Markdown
  และคุณต้องการให้อีกหลายภาษาเป็นปัจจุบันอยู่เสมอเมื่อภาษาต้นทางเปลี่ยนแปลง
- คุณต้องการใช้วิธีที่แตกต่างกันสำหรับแต่ละคู่ภาษาในโปรเจ็กต์เดียว พร้อมจำกัดวงเงินค่าใช้จ่าย
  (`--max-cost`) และดูค่าใช้จ่ายล่วงหน้าได้ก่อนที่จะมีการเรียกเก็บเงินจริง (`--dry`)
- คุณสร้างระบบแปลภาษาบน rails และต้องการให้แอปนำไปใช้:
  `champollion connect` จะนำโมเดลที่ให้บริการอยู่เข้าสู่โปรเจ็กต์แอป และ `sync`
  จะทำการแปลโดยใช้โมเดลนั้น ทั้งนี้ โมเดลที่ฝึกฝนด้วยข้อมูลเฉพาะในท้องถิ่นจะเชื่อมต่อได้
  ก็ต่อเมื่อผู้ดูแลข้อมูลให้ความยินยอมแล้วเท่านั้น

`sync` ไม่ใช่วิธีที่คุณจะใช้สร้างระบบแปลภาษาสำหรับภาษาที่ยังไม่มีบริการใดรองรับได้ดี
หากต้องการทำเช่นนั้น ให้เริ่มต้นที่ [เริ่มต้นโปรเจ็กต์](/docs/start)
