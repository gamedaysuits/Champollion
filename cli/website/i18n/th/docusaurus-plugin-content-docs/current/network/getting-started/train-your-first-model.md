# ฝึกโมเดลแรกของคุณ (ด้วย agent ของคุณ)

คุณไม่จำเป็นต้องรู้วิธีฝึกโมเดลการแปลด้วยเครือข่ายประสาทเทียม สิ่งที่คุณต้องทำคือ **บอก coding agent ว่าคุณต้องการอะไร** — Claude, หรือโมเดลระดับ Sonnet/Flash, หรือ agent ใดก็ตามที่สามารถรันคำสั่ง shell ได้ **nmt-forge** ถูกออกแบบมาให้ agent ขับเคลื่อนได้ *อย่างเป็นระบบ*: ในทุกขั้นตอน เครื่องมือจะบอก agent อย่างชัดเจนว่าต้องทำอะไรต่อไป และจะปฏิเสธ — อย่างชัดเจน พร้อมวิธีแก้ไข — เมื่อขั้นตอนใดจะทำให้ผลลัพธ์ของคุณเสียหาย

หน้านี้คือวงจรทั้งหมด แต่ละขั้นตอนเขียนในรูปแบบ **สิ่งที่คุณบอก agent**, **สิ่งที่ forge ทำ**, **ลักษณะของการปฏิเสธ** (เพื่อที่ทั้งคุณและ agent จะไม่ตื่นตระหนกเมื่อเกิดขึ้น — การปฏิเสธคือสัญญาณที่เครื่องมือทำงานได้ถูกต้อง) และท้ายสุด **วิธีอ่านรายงาน**

:::tip กฎข้อเดียวสำหรับ agent ของคุณ
บอกมันว่า: *"รัน `nmt-forge status --json` ก่อนเสมอ และหลังจากทุกขั้นตอน แล้วทำตามที่ `next_command` บอก"* นิสัยเดียวนี้จะเปลี่ยน forge ให้เป็นเส้นทางนำทาง หาก agent ของคุณเชื่อมต่อผ่าน MCP วงจรเดียวกันนี้คือเครื่องมือ `forge_status` — ดู [Agent Guide](/docs/network/getting-started/agent-guide)
:::

## ขั้นตอนที่ 0 — ชี้ agent ไปยังภาษาของคุณ

**คุณพูดว่า:** *"ฉันต้องการฝึกโมเดลแปลภาษาอังกฤษ→[ภาษาของคุณ] เริ่มต้นด้วยการค้นหาว่า forge รู้อะไรเกี่ยวกับมันบ้าง รหัส ISO 639-3 คือ `crk`"* (ใช้รหัสภาษาของคุณ)

**forge ทำ:** `nmt-forge discover crk` อ่านการ์ดของภาษา — สคริปต์, พจนานุกรม, ตัววิเคราะห์ทางสัณฐานวิทยา, คลังข้อมูลที่มีอยู่และชุดประเมินผล (พร้อมแฟล็ก `do_not_train` / กักกันใดๆ) และเมตริกผู้ตัดสินเฉพาะภาษา จากนั้นจัดวางภาษาของคุณบน **asset ladder**: (1) ข้อความคู่ขนาน → การฝึกแบบมีการป้องกัน; (2) + ข้อความเดี่ยว → backtranslation แบบมีแท็ก; (3) + พจนานุกรม/ไวยากรณ์ → ข้อมูลสังเคราะห์แบบอ้างอิง; (4) + ตัววิเคราะห์ → การสังเคราะห์แบบตรวจสอบ round-trip; (5) + เมตริกผู้ตัดสิน → เมตริกเฉพาะของภาษานั้นในการให้คะแนนและการเลือก checkpoint

**ช่องว่างหมายถึง UNKNOWN ไม่ใช่ศูนย์** การ์ดที่มีข้อมูลน้อยไม่ได้หมายความว่า "ภาษานี้ไม่มีทรัพยากร" — อาจเป็นเพราะยังไม่ได้บันทึกทรัพยากรนั้นไว้ คุณสามารถนำคลังข้อมูลคู่ขนานของคุณเองมาใช้ได้เสมอ

จากนั้น: *"สร้างโครงสร้างโปรเจกต์"* → `nmt-forge init crk` เขียน workspace, config เริ่มต้น และสรุป `NEXT_STEPS`

---

## ขั้นตอนที่ 1 — แบ่งข้อมูลอย่างป้องกันการโกง

**คุณพูดว่า:** *"นี่คือคลังข้อมูลคู่ขนานของฉัน `corpus.jsonl` แบ่งเป็น train/dev/test และลงทะเบียนชุด dev และ test"*

**forge ทำ:** `nmt-forge split corpus.jsonl --test 200 --dev 100 --seed 7
--out data/splits --register mypair` มันสร้างการแบ่งแบบ **group-disjoint**: คู่ประโยคใดก็ตามที่มีต้นฉบับ *หรือ* เป้าหมายร่วมกันจะอยู่ **ฝั่งเดียวกัน** นี่คือวิธีที่พบบ่อยที่สุดที่ทำให้คะแนนในสถานการณ์ทรัพยากรน้อยถูกพองขึ้น — ตำราเรียนแมปแบบฝึกหัดภาษาอังกฤษหลายข้อไปยังคำเป้าหมายเดียว การแบ่งแบบสุ่มธรรมดาจะวางสำเนาหนึ่งไว้ใน train และคู่แฝดไว้ใน test และโมเดลจะ "แปล" คำตอบที่มันจำมาได้

**ลักษณะของการปฏิเสธ:** หากคุณส่งการแบ่งที่คุณทำเองให้ forge และมันไม่ใช่แบบ disjoint, `verify-split` จะหยุดทำงานพร้อมระบุ key ที่ซ้ำกัน — *"แถวเหล่านี้มีเป้าหมาย canonical ร่วมกันระหว่าง train และ test"* วิธีแก้ไข: ให้ forge ทำการแบ่งเอง

---

## ขั้นตอนที่ 2 — ตรวจสอบการรั่วไหลของข้อมูล

**คุณพูดว่า:** *"ก่อนที่เราจะฝึก ตรวจสอบคลังข้อมูลฝึกสอนว่ามีการรั่วไหลกับชุดประเมินผลหรือไม่"*

**forge ทำ:** `nmt-forge leak-audit corpus.jsonl` มันตรวจสอบคลังข้อมูลของคุณกับทุกชุด dev/test/sealed ที่ลงทะเบียนไว้:

- **ข้อความซ้ำหรือใกล้เคียงกันในฝั่งเป้าหมาย** (คำตอบอ้างอิงอยู่ในข้อมูลฝึกสอนของคุณ) → **ร้ายแรง** นี่คือการรั่วไหลของคำตอบ
- **ข้อความต้นฉบับใกล้เคียงกันแต่มี *คำตอบต่างกัน*** → **เพื่อข้อมูล, เก็บไว้** prompt เดียวกัน การแปลต่างกันคือคู่ contrast ที่ถูกต้อง ไม่ใช่การรั่วไหล — forge รายงานแต่ไม่ลบออก (ความแตกต่างนี้เป็น bug จริงที่เราพบจากการทดสอบใช้งานจริง: เวอร์ชันก่อนหน้าระบุ 44 แถวว่าร้ายแรง ทั้งที่มีเพียง 17 แถวที่เป็นการรั่วไหลจริง)

**ลักษณะของการปฏิเสธ:** *"แถว 118: ข้อความเป้าหมายซ้ำกับชุด test `mypair-test` (Jaccard 0.83) — การรั่วไหลของคำตอบ"* วิธีแก้ไข: agent ของคุณรัน `nmt-forge leak-audit corpus.jsonl --clean-to corpus.clean.jsonl` และฝึกด้วยข้อมูลที่ผ่านการกรอง

---

## ขั้นตอนที่ 3 — ทำนายก่อนดูผล

**คุณพูดว่า:** *"เขียนสิ่งที่เราคาดว่าโมเดลจะทำ แล้วค่อยฝึก"*

**forge ทำ:** `nmt-forge prereg new p1 --eval-set mypair-test --predictions
predictions.md` คุณ (หรือ agent ของคุณ อย่างชัดเจน) ยืนยันการทำนายที่พิสูจน์ได้ — เมตริกใด, ทิศทางใด, ขนาดเท่าใด — **ก่อน**ที่คะแนน test ใดๆ จะมีอยู่

**ลักษณะของการปฏิเสธ:** หาก agent ของคุณพยายามให้คะแนนชุด test โดยไม่มีการลงทะเบียนล่วงหน้า, `score` จะปฏิเสธ: *"การให้คะแนนชุด test ถูกปฏิเสธโดยไม่มีการลงทะเบียนล่วงหน้าที่มีอยู่ก่อนการอ่านคะแนนครั้งแรก"* นี่คือสิ่งที่แยกผลลัพธ์ที่แท้จริงออกจากการเล่าเรื่องแบบ results-first วิธีแก้ไข: ลงทะเบียนล่วงหน้าก่อน

:::info เหตุใดสิ่งนี้จึงรู้สึกเหมือนงานพิเศษ
มันคืองานที่ต้องทำ การป้องกันทุกอย่างที่นี่คือความผิดพลาดที่เคยหลอกนักวิจัยจริงๆ เครื่องมือทำให้เส้นทางที่ซื่อสัตย์เป็นเส้นทางที่ง่าย และเส้นทางที่ไม่ซื่อสัตย์เป็นเส้นทางที่หยุดคุณ
:::

## ขั้นตอนที่ 4 — ตรวจสอบ gate แล้วฝึก

**คุณพูดว่า:** *"การรัน training จะผ่านการตรวจสอบทั้งหมดหรือไม่? ถ้าใช่ ให้ฝึก"*

**forge ทำ:** `nmt-forge preflight run` แสดงรายการ gate ทุกอันที่การรันจะผ่าน — dev-fence มีอยู่, leak-audit สะอาด, schedule floor ถูกกำหนด, decode headroom ตรวจสอบแล้ว — แต่ละอันมี ✓ หรือ ✗ พร้อมวิธีแก้ไข เมื่อทุกอย่างเป็นสีเขียว:
`nmt-forge run config.json`

การฝึกเป็นขั้นตอนเดียวที่ **ไม่ใช่** การเรียกเครื่องมือทันที — มันใช้ GPU และใช้เวลาตั้งแต่นาทีถึงชั่วโมง agent ของคุณรันในเทอร์มินัลและดูบรรทัด `[schedule-sanity]` forge กำหนด **floor** สำหรับ early-stopping จากข้อมูล mix ของคุณ เพื่อให้การรันที่มีข้อมูลสังเคราะห์มากไม่หยุดกลางคันเมื่อ real-dev loss ผันผวน (รูปแบบความล้มเหลวจริง — ดู [Diagnosing a Training Run](/docs/network/getting-started/diagnosing-training))

เมื่อเสร็จสิ้น forge จะ **เลือก checkpoint บนชุด dev ที่มีการป้องกัน** (ไม่ใช่บนชุด test) และเขียน `run-manifest.json`

## ขั้นตอนที่ 5 — ปิดวงจร: ประเมินและวินิจฉัย

**คุณพูดว่า:** *"ให้คะแนนโมเดลบน test battery และบอกฉันว่าต้องปรับปรุงอะไร"*

**forge ทำ:** `nmt-forge evaluate .forge/runs/<run>/run-manifest.json --config
config.json` คำสั่งนี้ **ปิดวงจร** ในคำสั่งเดียว: มัน decode test battery ด้วย checkpoint ที่การรันเลือก, ให้คะแนน (แบบ prereg-gated พร้อม confidence interval 95% บนทุกตัวเลข) และเพิ่มส่วน **Diagnosis & Recommendations** ในภาษาธรรมดา (ก่อนที่คำสั่งนี้จะมีอยู่ คุณต้อง symlink checkpoint และรัน decoder ด้วยมือ — ซึ่งเป็นจุดที่ผู้เริ่มต้นมักติดขัด)

### วิธีอ่านรายงาน battery-lint

รายงานคือตารางคะแนน **แยกตาม register** (ตำราเรียน, ราชการ, เรื่องเล่าปากเปล่า, …) แต่ละอันพร้อม confidence interval ตามด้วยการวินิจฉัย การวินิจฉัยระบุ **register ที่อ่อนแอที่สุด** ของคุณ และสำหรับแต่ละอัน สาเหตุที่น่าจะเป็นและ **lever** ที่ต้องดึงต่อไป:

| หากการวินิจฉัยบอกว่า… | หมายความว่า… | Lever |
|---|---|---|
| `R1-vocabulary-gap` | register นั้นได้คะแนนต่ำ **และ** output ไม่สมบูรณ์; โมเดลขาดคำศัพท์ | **VOCABULARY** — ขยาย lexicon แล้วตรวจสอบ funnel อีกครั้ง |
| `R2-structure-gap` | คำศัพท์รู้จักแต่ *โครงสร้างประโยค* ไม่รู้จัก | **STRUCTURE** — เพิ่ม construction ที่ขาดหายไป (templates/compositor) |
| `R3-mixed-convention` | output มีการสะกดปะปนกัน | **ORTHOGRAPHY** — ทำให้คลังข้อมูลเป็นมาตรฐานเดียว แล้วฝึกใหม่ |
| `R4-optimism-bound` | คะแนน "เต็ม" ถูกพองขึ้นจากแถว eval ที่ใกล้เคียงกัน | **MEASUREMENT** — อ้างคะแนน strict สำหรับ generalization |
| `R5-low-power` | confidence interval กว้าง | **MEASUREMENT** — อย่าดำเนินการกับ delta ที่เล็กกว่า CI; ขยายชุด eval |
| `R7-transfer-plateau` | ดีมากกับข้อมูลสังเคราะห์ แต่ติดขัดกับข้อความจริง | **REAL-DATA** — backtranslate ข้อมูล monolingual หรือหาประโยคคู่ขนานจริง |

ผลการค้นพบแต่ละอันมีหลักฐานที่ทำให้เกิดขึ้น สำหรับผลการค้นพบ `--json` agent ของคุณสามารถดำเนินการได้โดยอัตโนมัติ: `nmt-forge lint <battery-manifest.json>`

## สิ่งที่คุณเพิ่งทำ

คุณฝึกโมเดลที่คะแนนของมันน่าเชื่อถือได้จริง: ไม่มีคำตอบที่รั่วไหล, checkpoint ที่เลือกโดยไม่แอบดูชุด test, error bar บนทุกตัวเลข, การทำนายที่เขียนก่อนผลลัพธ์ และการวินิจฉัยที่ระบุ lever ถัดไปแทนที่จะปล่อยให้คุณเดาเอง นั่นคือจุดประสงค์ทั้งหมด — **ผลลัพธ์ที่ซื่อสัตย์คือค่าเริ่มต้น และไม่ต้องใช้ความเชี่ยวชาญด้าน MT เลย**

เมื่อตัวเลขน่าผิดหวัง (มันจะเป็นเช่นนั้นในครั้งแรก) ไปที่
[Diagnosing a Training Run](/docs/network/getting-started/diagnosing-training) —
มันเริ่มจากอาการ เขียนขึ้นสำหรับช่วงเวลานั้นโดยเฉพาะ
