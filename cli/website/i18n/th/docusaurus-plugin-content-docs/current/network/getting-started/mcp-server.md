# MCP Server — ประตูสำหรับเอเจนต์

`champollion-mcp-server` เปิดให้เอเจนต์ AI เข้าถึง Champollion ผ่านทาง [Model
Context Protocol](https://modelcontextprotocol.io) หากคุณเป็นเอเจนต์ หรือกำลัง
เชื่อมต่อเอเจนต์เข้ากับระบบ นี่คือประตูบานนั้น: **เครื่องมือ 34 ตัว ทรัพยากร 3 รายการ และพรอมต์ 4 รายการ**
ผ่าน stdio

ทุกสิ่งในที่นี้สามารถเข้าถึงได้ผ่าน HTTP ธรรมดาเช่นกัน — ดู [Machine-readable endpoints](#machine-readable-endpoints) — แต่ MCP server เป็นเพียงพื้นผิวเดียวที่อนุญาตให้เอเจนต์ *ลงมือทำ* (แปลภาษา, รันเบนช์มาร์ก, ฝึกสอนโมเดล) แทนที่จะแค่อ่านเพียงอย่างเดียว

## การติดตั้ง

```bash
npx -y champollion-mcp-server
```

จากนั้นลงทะเบียนกับไคลเอนต์ของคุณ สำหรับ Claude Code:

```bash
claude mcp add champollion -- npx -y champollion-mcp-server
```

สำหรับไคลเอนต์ที่กำหนดค่าผ่านไฟล์ (Claude Desktop, Cursor, Antigravity) ให้เพิ่ม:

```json
{
  "mcpServers": {
    "champollion": {
      "command": "npx",
      "args": ["-y", "champollion-mcp-server"]
    }
  }
}
```

## อ่านส่วนนี้ก่อนที่คุณจะนำไปใช้งานจริง

**เครื่องมือ 14 จาก 34 ตัวใช้งานได้ตั้งแต่ติดตั้ง `npx` เปล่า ๆ และ `translate` จะใช้งานได้
เมื่อมี engine ส่วนเครื่องมืออีก 19 ตัวที่เหลือนั้นต้องใช้แพ็กเกจ Python ซึ่งแพ็กเกจ npm
ไม่ได้มีมาให้และไม่สามารถแถมมาด้วยได้** เครื่องมือเหล่านี้จะไม่ล้มเหลวแบบเงียบ ๆ — แต่ละตัวจะส่งคืน
ข้อผิดพลาดที่ระบุสิ่งที่ขาดหายไปและนำไปแก้ไขต่อได้ — ทว่าคุณควรทราบโครงร่างนี้ไว้ก่อน
ที่จะวางแผนการทำงาน

| เครื่องมือ | ใช้งานได้หลัง `npx` เลยหรือไม่? | สิ่งที่ต้องใช้เพิ่มเติม |
|---|---|---|
| `search_languages`, `get_language`, `language_overview`, `list_corpora`, `get_results`, `get_run_card`, `get_metric_reliability`, `list_contests`, `get_contest`, `get_project_info`, `list_queue`, `get_queue_item`, `estimate_cost`, `get_training_guardrails` | **ได้** — แบบอ่านอย่างเดียว (read-only), ให้บริการจากปลายทางสาธารณะ | ไม่ต้องใช้อะไรเพิ่มเติม |
| `translate` | **ได้** หากมี engine | คีย์ API สำหรับ engine ที่คุณเลือก — หรือไม่ต้องมี หากใช้วิธีการ `local` และเซิร์ฟเวอร์โมเดลบนเครื่องของคุณเอง |
| `run_benchmark`, `get_run_status`, `preview_publish`, `publish_report` | ไม่ได้ | ชุดทดสอบการประเมินผล (eval harness) — `pipx install mt-eval-harness` |
| เครื่องมือ `forge_*` ทั้ง 15 ตัว | ไม่ได้ | NMT Forge 0.2.0 ขึ้นไป — `python3 -m pip install nmt-forge` (เพิ่ม `'nmt-forge[hf]'` เพื่อเทรนและให้บริการ) เครื่องมือนี้จะนำ eval harness มาด้วยในตัวและค้นหาการ์ดภาษาได้เองโดยอัตโนมัติ ไม่จำเป็นต้องโคลนคลังโค้ด |

ไม่จำเป็นต้องโคลนคลังโค้ดสำหรับกระบวนการใด ๆ ทั้งสิ้น

## เครื่องมือเหล่านี้ทำอะไรได้บ้าง

**เรียกดูและประเมินราคาของงาน** `list_queue` และ `get_queue_item` จะไล่ดูคิวเบนช์มาร์กที่เปิดอยู่ — ซึ่งเป็นรายการการวัดผลที่จัดอันดับไว้ที่จะช่วยปรับปรุงแผนที่ได้มากที่สุด `estimate_cost` จะประเมินราคาชุดการรันก่อนที่คุณจะเสียค่าใช้จ่ายใดๆ

**ค้นหาข้อมูล** `search_languages` ค้นหาการ์ดภาษาด้วยชื่อ,
รหัส, ตระกูลภาษา หรือภูมิภาค และรองรับการสะกดผิดได้ แต่ละผลลัพธ์ยังระบุด้วยว่า
ภาษานั้นมีผู้พูดที่ใด (ประเทศ, จุดบนแผนที่, พื้นที่ทางภูมิศาสตร์ขนาดใหญ่/macroarea) และชื่อเรียก
อื่น ๆ ของภาษา — โดยจะแสดงเฉพาะข้อเท็จจริงที่มีการระบุแหล่งที่มาในการ์ดเท่านั้น พร้อมแหล่งที่มาของแต่ละข้อมูล เพื่อให้
สามารถแยกแยะภาษาที่มีชื่อคล้ายกันได้ ตำแหน่งที่ตั้งที่ไม่มีแหล่งที่มาอ้างอิงจะ
ไม่แสดงโดยเด็ดขาด โดยบรรทัดนั้นจะแจ้งให้ทราบและให้ลิงก์ไปยังระเบียน Glottolog ของภาษานั้น
แทน การ์ดที่ดึงข้อมูลมาจากตารางการ์ดที่เผยแพร่ของ champollion.dev (ในการติดตั้งแบบ npm
คือทุกภาษาที่อยู่นอกเหนือชุดหลักที่แถมมา) จะยังไม่มีแหล่งที่มารายฟิลด์
ในตอนนี้ — ซึ่งจะมาพร้อมกับการอัปโหลดตารางในครั้งถัดไป — ดังนั้นบรรทัดเหล่านั้น
จึงแสดงลิงก์ Glottolog แทนที่จะเป็นตำแหน่งที่ตั้ง `language_overview` คือ
จุดเริ่มต้นแบบหน้าเดียวสำหรับการสร้างระบบสำหรับภาษาใดภาษาหนึ่ง: มีอะไรอยู่บ้าง, รันอะไรได้บ้าง,
และขั้นตอนถัดไปคืออะไร `get_language` ส่งคืนการ์ดฉบับเต็มพร้อมแหล่งอ้างอิง
`list_corpora` แสดงรายการคลังข้อมูลคอร์ปัสสำหรับการประเมินผล (evaluation corpora) ที่ลงทะเบียนไว้
สำหรับคู่ภาษาหรือตระกูลเกณฑ์มาตรฐาน (benchmark family) — แสดงเฉพาะข้อมูลกำกับ (ขนาด,
สัญญาอนุญาต, ระดับการปนเปื้อนของข้อมูล และระบุว่า harness สามารถดึงข้อมูลได้เอง, จำเป็นต้องใช้
access token หรือกักกันข้อมูลไว้); เนื้อหาของคอร์ปัสจะไม่ถูกส่งคืนโดยเด็ดขาด
และคู่ภาษาที่คอร์ปัสทั้งหมดถูกกักกันไว้จะมีการระบุแจ้งไว้ แทนที่จะดูเหมือนว่า
ไม่รองรับ `get_results` และ `get_run_card` อ่านผลการรันที่ให้คะแนนแล้ว
จากกระดานผู้นำสาธารณะ (public leaderboard) `get_metric_reliability` ตอบคำถามที่
เอเจนต์ส่วนใหญ่ตอบผิด — *ควรเชื่อถือเมตริกใดสำหรับภาษากลุ่มเป้าหมายนี้* —
โดยอิงจากความสัมพันธ์กับการประเมินของมนุษย์แยกตามตระกูลภาษา `list_contests`
และ `get_contest` แสดงการแข่งขันและเงื่อนไขที่ประกาศไว้ โดยการเข้าร่วมการแข่งขันนั้นเป็น
ขั้นตอน CLI ที่ต้องได้รับการอนุมัติจากมนุษย์ และไม่สามารถทำผ่านเครื่องมือได้

**ลงมือปฏิบัติ** `translate` รันข้อความผ่านไปป์ไลน์ที่ผ่านการทดสอบ พร้อมด้วย Translation
Memory (ข้อความซ้ำไม่มีค่าใช้จ่าย) และเกตคุณภาพแบบดีเทอร์มินิสติก ทุกคำตอบ
จะระบุชื่อ engine ที่รันจริง พร้อมโมเดลและปลายทาง (endpoint) หากมีข้อมูลเหล่านั้น
`run_benchmark` เริ่มต้นการประเมินผลและส่งคืน **job id ทันที**
เนื่องจากการรันจริงจะใช้เวลานานกว่า timeout ของไคลเอนต์ใด ๆ โดยคุณจะโพลล์ `get_run_status` ด้วย
id นั้น งานที่รันจะยังคงอยู่แม้เซิร์ฟเวอร์จะรีสตาร์ต: การรันจะดำเนินต่อไป และ
การโพลล์ id เดิมในภายหลังจะยังคงส่งคืนสถานะและผลลัพธ์ จะไม่มีข้อมูลใด
ถูกเผยแพร่นอกจากคุณจะส่ง `publish: true` เข้าไป แผนการทำงานจะระบุว่ามีข้อมูลใดบ้างที่จะ
เผยแพร่สู่สาธารณะ — ทุกแถวพร้อมข้อความประโยค หรือเฉพาะคะแนน; พรอมต์ หรือเฉพาะ
แฮชของพรอมต์; และเผยแพร่ที่ไหน — และการเผยแพร่จริงจำเป็นต้องระบุ `publish_ack` ด้วย
ข้อความตรงตามที่แผนระบุไว้ทุกคำ เพื่อให้แน่ใจว่าผู้ใช้ได้เห็นข้อความนั้นก่อนแล้ว การรันที่ดำเนินการโดยไม่มีการเผยแพร่
สามารถนำมาเผยแพร่ในภายหลังได้ภายใต้เกตควบคุมเดียวกัน `preview_publish` เป็นแบบอ่านอย่างเดียว:
จะแสดงตัวอย่างการเผยแพร่ของตัว harness เอง ข้อความที่ตรงกันทุกคำ และคำสั่งเรียก
`publish_report` ที่แน่นอนที่จะใช้เผยแพร่ โดยตัวมันเองไม่สามารถเผยแพร่ได้ มัน
มีคำอธิบายกำกับ (annotation) ของ MCP คือ `readOnlyHint: true` ดังนั้นโฮสต์ของเอเจนต์ที่ถาม
ก่อนเขียนข้อมูลทุกครั้งจึงสามารถอนุญาตได้โดยอัตโนมัติ `publish_report` ทำหน้าที่เขียนข้อมูล
(กำกับด้วย `destructiveHint` และ `openWorldHint`) และ `scores_only`
จะระงับข้อความประโยคเอาไว้ แผนการทำงานทุกแผนจะเปิดด้วย
สถานะ `EVAL PACK:` ของภาษาเป้าหมายเสมอ — `missing` (พร้อมคำสั่งที่ใช้
ติดตั้ง), `ready` หรือ `none needed` — และระบุสัญญาอนุญาตของคอร์ปัสและ
เงื่อนไข `do_not_train` ของคอร์ปัส เนื่องจากการรันจะส่ง `--yes` ไปด้วย หากไม่มี FST (ตัว
วิเคราะห์หรือรันไทม์ pyhfst) การรันจะไม่หยุดชะงัก: กระบวนการจะดำเนินต่อไป และการ์ด
การรันจะทำเครื่องหมายการยอมรับของ FST เป็นไม่ได้คำนวณ (not computed) หากมีส่วนประกอบอื่นใดขาดหายไปจะหยุดการรัน
ก่อนที่จะเริ่มแปล `skip_fst` และ `skip_eval_standard` จะให้คะแนนโดยไม่มีส่วนประกอบ
เหล่านั้น และการ์ดการรันจะทำเครื่องหมายสิ่งที่ละเว้นไว้ แผนยังระบุด้วยว่าจะมีการ
คำนวณ COMET หรือไม่ (harness จะคำนวณเมื่อใดก็ตามที่ติดตั้ง `unbabel-comet` ไว้;
`comet: true` จะกำหนดให้การรันจำเป็นต้องมีเมตริกนี้) และ `metricx` กับ `fuse`
จะร้องขอ MetricX-24 และตัวเปรียบเทียบสไตล์ FUSE ที่ต้องเลือกเปิดใช้ของ harness สำหรับแต่ละ
รายการ แผนจะระบุจาก harness ว่าได้ติดตั้งไว้หรือไม่, ต้องติดตั้งอะไร
และจะดาวน์โหลดอะไรบ้าง การรันที่ยืนยันแล้วซึ่งร้องขอเมตริกที่ harness
ไม่สามารถคำนวณได้จะถูกปฏิเสธ แทนที่จะรันไปโดยไม่มีเมตริกนั้น บรรทัด `Results:`
และ `Cache:` ของแผนจะระบุตำแหน่งที่บันทึกไฟล์ล็อก รายงาน และแคชการแปล
ไฟล์ทดสอบที่อยู่ภายในโฟลเดอร์ที่ `mt-eval contest prepare` ระบุว่าสามารถปล่อยได้
(`public/` ของการแข่งขัน) จะรันและบันทึกไปยังโฟลเดอร์ `runs/` ของการแข่งขันแทน เพื่อไม่ให้
มีสิ่งใดที่เกิดจากการรันถูกปล่อยออกไปพร้อมกัน โมเดลที่อยู่บนเครื่อง
ของคุณเอง (เซิร์ฟเวอร์โลคัล หรือ `method: "local-model"` ซึ่ง harness รันแบบ
in-process และไม่จำเป็นต้องมีการรับรอง) จะถูกรายงานเป็น `$0 API cost (runs on
this machine)`

**เทรนโมเดลโดยไม่หลอกตัวเอง** `get_training_guardrails` ส่งคืนกฎเกณฑ์
ที่สกัดมาจากความล้มเหลวจริงที่ตรวจวัดได้ เครื่องมือ `forge_*` ทั้ง 15 ตัวจะรัน
[NMT Forge](/docs/network/getting-started/training-honestly) ทีละขั้นตอนโดยมีการควบคุมอย่างรัดกุม —
โดยเริ่มจาก `forge_status` ก่อนและหลังทุก ๆ ขั้นตอน (จะระบุคำสั่ง
ถัดไปและเครื่องมือที่ใช้รัน), `forge_preflight` เพื่อดูว่าคำสั่งจะติดเกตใดบ้าง
ก่อนที่จะปฏิเสธ, `forge_prereg_template` และ `forge_prereg`
เพื่อบันทึกผลการทำนายล่วงหน้าก่อนที่จะมีคะแนนทดสอบใด ๆ ปรากฏ (และก่อนที่จะมีการ
ทดสอบเกณฑ์มาตรฐานบนชุดทดสอบ: การอ่านคะแนนจะบล็อกการลงทะเบียนล่วงหน้าในภายหลัง),
`forge_export` เพื่อให้คะแนนชุดทดสอบหนึ่งครั้งและแพ็กเกจโมเดลที่เทรนแล้ว,
`forge_compare` เพื่อทดสอบ A/B ระหว่างสองโมเดลพร้อมข้อควรระวังเรื่องคู่แฝดเสมือน (near-twin caveat) ของแต่ละโมเดลข้างผู้ชนะ และ
`forge_prereg_verdict` เพื่อบันทึกคำตัดสินของผู้ใช้เองสำหรับผลการทำนายที่ forge
ไม่สามารถตัดสินได้ (ช่วงข้อความอิสระ) — แสดงผลเป็นการตัดสินของมนุษย์ ไม่ใช่ผล
จากการคำนวณ `forge_status` แสดงรายการการรันที่เทรนไว้ทุกครั้งพร้อมคะแนน dev และ
จะระบุเมื่อ dev set อิ่มตัว (คะแนน dev สมบูรณ์แบบจนไม่มีความต่างให้ระบบคัดเลือก checkpoint เลือกได้)
เมื่อ eval harness ใส่ข้อควรระวังไว้บนคะแนนทดสอบ (เช่น ผลลัพธ์แทบจะคงที่: ส่งคืนผลลัพธ์
เดิมเพียงไม่กี่แบบสำหรับทุกประโยคต้นทาง) `forge_export`, `forge_status`,
`forge_compare` และ `forge_lint` จะส่งต่อข้อควรระวังนั้นด้วยถ้อยคำของ harness เอง และ
ข้อควรระวังหลักจะแสดงขึ้นมาก่อนในขั้นตอนถัดไป: คะแนนจะไม่ถูกอ้างถึงโดยปราศจาก
ข้อควรระวังนี้ การปฏิเสธจะส่งกลับมา
พร้อมสิ่งที่ผิดพลาด เหตุผลว่าทำไมจึงสำคัญ และวิธีแก้ไข สองขั้นตอนที่กินเวลาเกินกว่าการเรียก
เครื่องมือใด ๆ และต้องรันในเทอร์มินัลแทน ได้แก่: การเทรน (`nmt-forge run`) และการให้บริการ
โมเดลที่ส่งออก (`nmt-forge serve` ซึ่งจะนำโมเดลไปอยู่หลังปลายทางโลคัลที่
`translate` และ CLI สามารถเรียกใช้ได้)

### แปลภาษาด้วยโมเดลที่คุณนำไปปรับใช้ (Deploy)

`nmt-forge serve` จะแสดงที่อยู่สองรายการสำหรับโมเดลที่ให้บริการ ชี้
`translate` ไปยังที่อยู่ใดที่อยู่หนึ่ง:

| อาร์กิวเมนต์ | ใช้ร่วมกับ | ตัวอย่าง |
|---|---|---|
| `base_url` | `method: "local"` — เซิร์ฟเวอร์ที่เข้ากันได้กับ OpenAI (รวมถึง `"openai"` ด้วย) | `http://127.0.0.1:8378/v1` |
| `endpoint` | `method: "api"` — สัญญา API ของ champollion | `http://127.0.0.1:8378/translate` |
| `model` | engine ของ LLM เท่านั้น; จะถูกปฏิเสธสำหรับ API การแปลภาษาด้วยเครื่อง (MT) ซึ่งไม่มีคอนเซปต์นี้ | `llama3.1` |
| `project_dir` | method ใดก็ได้ — ใช้ Translation Memory ของโปรเจกต์นั้น | `~/my-app` |

เซิร์ฟเวอร์บนเครื่องของคุณเองไม่จำเป็นต้องมีคีย์ ส่วนปลายทาง `api` ระยะไกลจะอ่าน
คีย์จาก `CHAMPOLLION_API_KEY` ในสภาพแวดล้อมของเซิร์ฟเวอร์ ตัวเครื่องมือจะปฏิเสธ
อาร์กิวเมนต์ที่ไม่รู้จักโดยระบุชื่อ แทนที่จะเพิกเฉย ดังนั้นการสะกดอาร์กิวเมนต์ผิด
จะไม่ส่งข้อความของคุณไปยังโมเดลอื่นโดยไม่รู้ตัวอย่างแน่นอน

### ตำแหน่งที่เซิร์ฟเวอร์เก็บสถานะ

ทุกอย่างจะอยู่ใน `~/.champollion-mcp/` (ตั้งค่า `CHAMPOLLION_MCP_HOME` เพื่อย้าย
ตำแหน่ง):

- **Translation Memory ของ `translate`** จะเป็นไฟล์ของตัวเอง
  คือ `.champollion/tm.json` ในโฟลเดอร์นั้น ซึ่งแยกต่างหากจาก `.champollion/tm.json` ของแต่ละโปรเจกต์
  ส่งค่า `project_dir` เพื่อใช้ไฟล์ของโปรเจกต์แทน
  ซึ่งเป็นไฟล์เดียวกับที่ `champollion sync` ใช้งานในโปรเจกต์นั้น
- **งานของ `run_benchmark`** จะถูกบันทึกไว้ใน `jobs.json` ซึ่งจะเก็บรายการ
  ล่าสุด 50 รายการ แต่ละงานจะมีโฟลเดอร์ใน `jobs/` พร้อมผลลัพธ์ของงาน และสำหรับ
  รายการในคิวหรือคอร์ปัสที่ลงทะเบียนไว้ จะมีผลลัพธ์ของ harness รวมอยู่ด้วย การรันบนไฟล์
  ทดสอบที่คุณถือครองจะเขียนผลลัพธ์และแคชไว้ข้าง ๆ ไฟล์นั้น ใน
  `results/` — ยกเว้นไฟล์ในโฟลเดอร์ที่ `mt-eval contest prepare`
  ทำเครื่องหมายว่าปล่อยได้ ซึ่งการรันจะเขียนไปยังโฟลเดอร์ `runs/` ของการแข่งขันแทน
  การรันคิวจะเขียนรายงานไปยัง `eval/logs/harness/queue/` ภายใต้โฟลเดอร์ทำงานของเซิร์ฟเวอร์
  เช่นเดียวกับที่ harness ปฏิบัติเสมอมา

:::note[การใช้จ่ายถูกจำกัดไว้ตามการออกแบบ]
`run_benchmark` **จะปฏิเสธการรันคิวที่ไม่มีการจำกัดขอบเขต** คุณต้องส่งผ่านขอบเขตเพียงหนึ่งอย่างเท่านั้น — `budget`, `top`, หรือ `item_id` ที่ระบุเฉพาะเจาะจง จะไม่มีการเรียกใช้แบบ "แค่รันคิว" เนื่องจากเอเจนต์ที่เข้าใจคิวผิดอาจใช้จ่ายไปโดยไม่มีขีดจำกัด
:::

## เวอร์ชันของโปรโตคอล

การรับส่งข้อมูลเป็นแบบ **stdio เท่านั้น** — หนึ่งโปรเซสเซิร์ฟเวอร์ต่อหนึ่งเอเจนต์

[การปรับปรุงเมื่อ 2026-07-28](https://blog.modelcontextprotocol.io/posts/2026-07-28/) ของ MCP ทำให้โปรโตคอลเป็นแบบ stateless โดยค่าเริ่มต้น โดยยกเลิกการทำ handshake แบบ `initialize` และเฮดเดอร์ `Mcp-Session-Id` เซิร์ฟเวอร์นี้ไม่ได้รับผลกระทบในด้านการออกแบบ: มันไม่ได้ใช้ความสามารถที่ถูกยกเลิกไปแล้ว (Roots, Sampling, Logging), ไม่เคยใช้การรับส่งข้อมูลแบบ HTTP+SSE รุ่นเก่า, และปฏิบัติตามคำแนะนำใหม่สำหรับสถานะข้ามการเรียกใช้ (cross-call state) อยู่แล้ว — `run_benchmark` จะสร้าง job handle ที่ชัดเจนซึ่งโมเดลจะส่งกลับมา แทนที่จะพึ่งพา transport session

มัน **ยังไม่ได้** รับการอัปเกรดเป็นเวอร์ชันปรับปรุงใหม่ เนื่องจากยังไม่มี TypeScript SDK ที่เผยแพร่ออกมาที่รองรับเวอร์ชันนี้ ดู [server README](https://github.com/gamedaysuits/Champollion/tree/main/mcp-server) สำหรับจุดยืนแบบเต็ม
