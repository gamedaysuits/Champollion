# ฝึกโมเดลอย่างซื่อสัตย์ (nmt-forge)

**สรุปใน 30 วินาที:** ผลลัพธ์ MT สำหรับภาษาทรัพยากรน้อยที่อ้างว่า "พัฒนาขึ้น" ส่วนใหญ่มักล้มเหลวเมื่อนำกลับมาตรวจสอบซ้ำ — ไม่ว่าจะเป็นชุดทดสอบรั่วไหลเข้าไปในการเทรน, การใช้ชุดทดสอบเลือก checkpoint, หรือสิ่งที่ได้เพิ่มขึ้นมาเป็นเพียงสัญญาณรบกวน (noise) ที่ไม่มี error bar เลย **nmt-forge** คือชุดเครื่องมือสำหรับการเทรนที่ทำให้ความผิดพลาดเหล่านั้นเกิดขึ้นได้ยากในเชิงโครงสร้าง: เส้นทางการทำงานปกติจะทำในสิ่งที่ถูกต้อง ส่วนเส้นทางที่ผิดจะปฏิเสธการทำงานพร้อมข้อความที่ระบุว่าเกิด*อะไร*ขึ้น *ทำไม*จึงทำให้ผลลัพธ์เสียหาย และวิธี*แก้ไข*อย่างแม่นยำ เครื่องมือนี้ทำหน้าที่เทรน ส่วน [eval harness](/docs/network/specifications/harness) ทำหน้าที่ประเมินคะแนน กลไกป้องกัน (guard) ทุกตัวถูกสร้างขึ้นจากข้อผิดพลาดที่เราเคยเจอ วัดผล และบันทึกไว้จริงขณะพัฒนาระบบแปลภาษา Plains Cree ติดตั้งได้ด้วย `python3 -m pip install 'nmt-forge[hf]'` และโมเดลเริ่มต้นสามารถเทรนบน CPU ของแล็ปท็อปได้

```bash
$ nmt-forge score --eval-set textbook-test --hyps decoded.txt

[preregister] no preregistration for eval set 'textbook-test' at its current content hash
  why: results looked at without written-down expectations become
       post-hoc stories; ...
  fix: write one FIRST: ... — then score
```

นั่นคือบุคลิกทั้งหมดของชุดเครื่องมือนี้ในการปฏิเสธครั้งเดียว

## เรื่องราวในห้านาที

นี่คือความล้มเหลวที่ชุดเครื่องมือนี้ถือกำเนิดขึ้นมา ตำราเรียนภาษา Cree แมปแบบฝึกหัดภาษาอังกฤษหลายรายการไปยังเป้าหมายเดียว: *"Feed him"* และ *"Feed her"* ทั้งคู่แปลเป็น `asam` การแบ่งแบบสุ่มมาตรฐานนำสำเนาหนึ่งไปไว้ในชุดฝึกและคู่แฝดของมันไปไว้ในชุดทดสอบ — ดังนั้นโมเดลจึงเคยเห็นคำตอบ "ทดสอบ" จริง ๆ 17 จาก 54 รายการ และแถวเหล่านั้นได้คะแนน chrF++ 83 เทียบกับ 44 สำหรับรายการที่สะอาด ทุกอย่างที่ตามมา (โมเดล "แชมป์" ผลการค้นพบที่สร้างบนมัน) ต้องถูกทิ้งทั้งหมด

ตัวแบ่งข้อมูลของ nmt-forge ทำให้สิ่งนั้นเป็นไปไม่ได้ **โดยโครงสร้าง**: คู่ที่มีต้นฉบับ *หรือ* เป้าหมายร่วมกันจะถูกจัดกลุ่ม กลุ่มทั้งหมดจะอยู่ฝั่งเดียวกัน และการตรวจสอบ zero-overlap จะทำงานหลังการแบ่งทุกครั้ง:

```bash
$ nmt-forge split corpus.jsonl --test 150 --dev 42 --seed 42 \
      --out data/split --register textbook
split corpus.jsonl: 1240 rows in 1187 share-groups (largest 4)
  train 1048 · dev 42 · test 150  → data/split/
  verified: 0 shared canonical source/target keys across sides
```

(หากชุดทดสอบของคุณเป็นไฟล์ที่แยกไว้และลงทะเบียนเรียบร้อยแล้ว — เช่น ชุดข้อมูลที่ครูผู้สอนตรวจสอบแล้วซึ่งคุณเก็บไว้เป็นส่วนตัว — `--test 0` จะแบ่งเฉพาะ train และ dev)

กลไกป้องกันตัวอื่นๆ ทั้งหมดมีรูปแบบเดียวกัน — คือข้อผิดพลาดจริงที่ถูกเปลี่ยนเป็นกลไกป้องกันอัตโนมัติ กลไกเหล่านี้รวมกันเป็น **แนวทางป้องกันสำหรับการเทรน (training guardrails)**: ควรอ่านก่อนที่คุณจะแบ่งข้อมูล (`nmt-forge init` และ `nmt-forge status` จะชี้มาที่นี่ในขั้นตอนนี้ ส่วน agent จะได้รับกฎชุดเดียวกันพร้อมข้อผิดพลาดที่วัดผลได้เบื้องหลังแต่ละกฎผ่านเครื่องมือ MCP `get_training_guardrails`)

| กลไกป้องกัน | ข้อผิดพลาดที่กำจัด |
|---|---|
| **split-guard** | คำตอบของชุดทดสอบแอบแฝงอยู่ในการเทรนผ่านทาง source/target ที่ซ้ำกัน |
| **dev-fence** | การใช้ชุดทดสอบในการเลือก checkpoint (การเทรนจะปฏิเสธไม่เริ่มทำงานหากไม่มีชุด dev ที่ลงทะเบียนไว้) |
| **leak-audit** | การเทรนด้วยข้อความชุดประเมิน — ไม่ว่าจะเป็น prompt ที่เหมือนกันทุกประการ (แม้คำแปลจะต่างกัน), คำตอบที่เหมือนกันทุกประการหรือใกล้เคียงมาก, หรือทั้งไฟล์ นอกจากนี้ยังระบุสิ่งที่*เก็บไว้*โดยตั้งใจและเหตุผล: คู่ประโยคเทมเพลตที่สลับแค่คำ (*"I see the dog"* / *"I see the cat"*) ถือเป็นการฝึกซ้อม ไม่ใช่การเฉลยคำตอบ จึงมีรายงานให้ทราบแต่ไม่ถูกลบออก — เว้นแต่ทุกแถวในชุดทดสอบจะมีคู่แบบนี้ ซึ่งในกรณีนั้น `--clean-to … --drop-test-twins` จะลบคู่แฝดในการเทรนของชุดทดสอบที่คงที่ออกไป มีความเป็นดีเทอร์มินิสติก (deterministic): คลังข้อมูลเดิม ย่อมได้ผลลัพธ์เดิม |
| **funnel-audit** | ข้อมูลสูญหายระหว่างไปป์ไลน์โดยไม่รู้ตัว (เช่น อักขระทางอักขรวิธีตัวเดียวเคยลบคำกริยาในพจนานุกรมไป 1,375 คำ โดยไม่มีใครเห็นเป็นเวลาหลายสัปดาห์) |
| **convention-lint** | การเทรนด้วยหลักการสะกดคำที่ปะปนกัน (ซึ่งทำให้โมเดลสะกดผสมกันกลางประโยค) |
| **coverage-map** | ข้อมูลสังเคราะห์นับล้านคู่ที่ไม่มีประโยคคำสั่ง ไม่มีประโยคคำถาม ไม่มีการแสดงความเป็นเจ้าของ — ปริมาณที่บดบังช่องโหว่เชิงโครงสร้าง |
| **sample-strata** | เทมเพลตเพียงสองประเภทกินสัดส่วนสัญญาณการเทรนไปถึงครึ่งหนึ่ง |
| **ci-scoring** | คะแนนที่ไม่มี error bar (ทุกตัวเลขจะแสดงผลพร้อม 95% bootstrap CI — ไม่มีการแสดงผลคะแนนเดี่ยวๆ แบบลอยๆ) |
| **schedule-sanity** | early stopping สั่งหยุดการรันที่เน้นข้อมูลสังเคราะห์ตั้งแต่ยังไม่ถึงครึ่ง epoch: เมื่อมีข้อมูลสังเคราะห์ 97% ร่วมกับชุด dev *ของจริง*ที่ตรงไปตรงมา ค่า dev loss จะแตะจุดต่ำสุดอย่างรวดเร็วแล้วค่อยๆ ลอยสูงขึ้น — นั่นเป็นเพราะโมเดลกำลังฟิตกับก้อนข้อมูลสังเคราะห์ ไม่ใช่การลู่เข้า (convergence) เกณฑ์ขั้นต่ำในการหยุดจะถูกคำนวณจากสัดส่วนข้อมูลของคุณโดยอัตโนมัติ และทุกการแทรกแซงจะอธิบายเหตุผลด้วยแนวโน้ม dev-loss ปัญหานี้ถูกค้นพบ*โดย*โพรโทคอลที่รัดกุม — การตั้งค่าที่ตรงไปตรงมาจะเผยให้เห็นบั๊กที่แท้จริง |
| **eval-ledger** | การนำข้อมูลประเมินไปใช้อย่างปรับตามผลลัพธ์โดยมองไม่เห็น (ทุกการอ่านข้อมูลจะถูกบันทึก; ชุดข้อมูลที่ปิดผนึกไว้สามารถอ่านได้ครั้งเดียวเท่านั้น) |
| **preregister** | การพยากรณ์ย้อนหลัง (postdiction) ที่สวมรอยเป็นการทำนายล่วงหน้า (หากไม่มีการลงทะเบียนล่วงหน้า → จะไม่มีคะแนนทดสอบและไม่มีตารางเปรียบเทียบ; รูปแบบการทำนายมีแบบเดียวคือ JSON array — `nmt-forge prereg template` จะสร้างไฟล์ต้นแบบมาให้แก้ไข) |
| **score caveats** | การอ้างอิงคะแนนที่ eval harness มีเงื่อนไขกำกับไว้ — เช่น *ผลลัพธ์ที่แทบจะคงที่ (near-constant output)* (ประโยคเดิมๆ ไม่กี่ประโยคถูกส่งออกให้กับอินพุตที่ต่างกันจำนวนมาก: ผลลัพธ์ไม่ได้แปรผันตามอินพุต), ผลลัพธ์ที่ยาวหรือสั้นกว่าข้อความอ้างอิงมาก, หรือการคัดลอกจากต้นฉบับ forge ไม่ได้คำนวณสิ่งเหล่านี้เอง แต่จะส่งต่อทุกข้อควรระวังที่ harness บันทึกไว้ โดยใช้ถ้อยคำของ harness แนบไว้ข้างคะแนน — ในสรุปการส่งออก, `forge-model.json`, `DEPLOY.md`, `status`, `report`, `compare` และ `lint` — และจะไม่มีทางเสนอคะแนนที่มีเงื่อนไขกำกับว่าเป็น "ตัวเลขสำหรับใช้อ้างอิง" โดยปราศจากข้อควรระวังนั้น |

## ทุกภาษา ทุกทรัพยากร — เริ่มจาก card

nmt-forge เป็นเครื่องมือเดียวสำหรับภาษาทั้งหมดราว 8,700 ภาษาในดัชนีของ Champollion และเริ่มต้นด้วยการสอบถามดัชนีว่าภาษานั้นมีข้อมูลอะไรอยู่จริงบ้าง:

```bash
$ nmt-forge discover nav        # Navajo — a sparse card
  ✓ rung 1: parallel text → train with every guard (no pack needed)
  ? rung 2: monolingual text → the tagged backtranslation lane
  ? rung 4: morphological analyzer → round-trip-VERIFIED synthesis
  note: no analyzer on the card → synthesis is off the menu until one
  exists; every guard and the training loop work regardless
```

เครื่องหมาย `?` คือเครื่องมือที่ซื่อสัตย์: การไม่มีข้อมูลใน card หมายถึง **ไม่ทราบ** ไม่ใช่ "ภาษานี้ไม่มีอะไรเลย" ทุกภาษาไต่ขึ้น **asset ladder** เดียวกัน — (1) ข้อความคู่ขนานเพียงอย่างเดียวก็ได้รับ training loop ที่มีการป้องกันครบถ้วน (2) ข้อความ monolingual เพิ่ม backtranslation (3) พจนานุกรมบวกไวยากรณ์ที่ตีพิมพ์ทำให้คุ้มค่าที่จะสร้าง template pack ที่อ้างอิงได้ (4) morphological analyzer ปลดล็อกการสังเคราะห์ที่ตรวจสอบแล้ว (5) LYSS referee นำ metric ของภาษานั้นเองเข้าสู่การให้คะแนนและการเลือก checkpoint card ที่สมบูรณ์ (Plains Cree) เชื่อมต่อขั้น 4–5 โดยอัตโนมัติ — ชุดทดสอบมาพร้อมแฟล็ก `NEVER TRAIN ON THIS` และ plugin lane ของ referee พร้อมให้วางได้ทันที

จากนั้น `nmt-forge init <code>` จะสร้างโครงร่างโปรเจกต์ขึ้นจาก card: ทั้งพื้นที่ทำงาน (workspace), การกำหนดค่าเริ่มต้น (starter config) และสรุปข้อมูลย่อ `NEXT_STEPS.md` ที่เขียนขึ้นสำหรับคุณ*และ agent ของคุณ*พร้อมลำดับคำสั่งที่แน่นอน เครื่องมือนี้ทำงานได้จาก `pip install` แบบธรรมดา — การ์ดจะถูกอ่านจากไดเรกทอรีที่คุณระบุ, checkout ในเครื่อง หรือดัชนีการ์ดสาธารณะ (ซึ่งแคชไว้สำหรับการใช้งานแบบออฟไลน์) — และภาษาที่ยังไม่มีการ์ดก็สามารถสร้างโปรเจกต์ได้เช่นกัน (`--no-card --name "<name>"`) โดยข้อเท็จจริงในแต่ละการ์ดจะถูกบันทึกว่าไม่ทราบข้อมูล (unknown) แทนที่จะเป็นการแต่งขึ้นมาเอง

## จากแล็ปท็อปสู่โมเดลพร้อมให้บริการ

ลูปการทำงานที่ตรงไปตรงมานี้ไม่จำเป็นต้องใช้ GPU `init` จะเขียนพรีเซ็ตโมเดลหนึ่งในสามแบบลงในการกำหนดค่า โดยระบุเป็นตัวเลขที่ชัดเจน:

| พรีเซ็ต | ความต้องการ | สิ่งที่คาดหวังได้ |
|---|---|---|
| `cpu-tiny` (ค่าเริ่มต้น) — ทรานส์ฟอร์เมอร์ขนาดเล็กที่เทรนขึ้นใหม่ตั้งแต่ต้น (from scratch) โดยเรียนรู้คลังคำศัพท์จากแถวข้อมูลเทรนของคุณเท่านั้น | CPU แล็ปท็อป ไม่ต้องดาวน์โหลด | มีประสิทธิภาพจำกัดตามการออกแบบ: สำหรับข้อมูล 1–2 พันคู่ประโยค chrF++ จะอยู่ที่ประมาณ 5–30 — จะแปลได้ตามวลีและรูปแบบในข้อมูลของคุณ ไม่ใช่การแปลทั่วไป |
| `cpu-finetune --base <hf-id>` — โมเดล Marian/opus-mt พรีเทรนขนาดเล็กที่คุณระบุ สำหรับคู่ภาษาที่ใกล้เคียงกัน | CPU ดาวน์โหลดประมาณ 300 MB | มักจะดีกว่า `cpu-tiny` เมื่อมีคู่ภาษาที่เกี่ยวข้องกัน — ให้ทำการวัดผลดู |
| `nllb-600m` — NLLB-200 distilled 600M ร่วมกับ LoRA | GPU | จุดเริ่มต้นที่ทรงพลังที่สุด |

`cpu-tiny` มีไว้เพื่อให้ลูปการทำงาน*ทั้งหมด*เกิดขึ้นได้จริงตั้งแต่วันแรก — ทั้งแนวรั้ว (fence), การตรวจสอบ (audits), การทดสอบที่ลงทะเบียนล่วงหน้า (preregistered test) และโมเดลที่ CLI สามารถเรียกใช้งานได้ — เพื่อที่ว่าเมื่อมีโมเดลที่ดีขึ้นในภายหลัง ก็สามารถนำมาใส่ในโปรเจกต์เดิมและวัดผลด้วยวิธีเดียวกันได้ หลังจากการเทรนเสร็จสิ้น มีเพียงสองคำสั่งที่ต้องทำต่องานให้เสร็จสมบูรณ์:

```bash
nmt-forge export .forge/runs/<run>/run-manifest.json --prereg <id> --out export/
nmt-forge serve export/model     # http://127.0.0.1:8378
```

`export` จะให้คะแนนชุดทดสอบหนึ่งครั้ง (ต้องมีการลงทะเบียนล่วงหน้า, ช่วงความเชื่อมั่น 95%; `--prereg <id>` จะระบุชื่อการลงทะเบียนล่วงหน้าที่เขียนขึ้นสำหรับโมเดลนี้ด้วย `nmt-forge prereg new <id>` — หากมีสองโมเดลในชุดทดสอบเดียวกัน แต่ละโมเดลจะถูกตัดสินด้วยเกณฑ์ของตัวเอง โดย export จะปฏิเสธการคาดเดาเอาเอง), เขียนผลลัพธ์เป็นรายงาน mt-eval ที่ `mt-eval compare` อ่านได้ และแพ็กเกจเป็นโมเดลแบบเบ็ดเสร็จในตัวพร้อมไฟล์ manifest ของปลั๊กอิน champollion และ `DEPLOY.md` จากนั้น `serve` จะสื่อสารตามข้อกำหนดสัญญา api-method ของ champollion และเอนด์พอยต์ที่เข้ากันได้กับ OpenAI เพื่อให้ `champollion sync --method local` สามารถแปลภาษาด้วยโมเดลนี้ได้ โดยจะรับฟังการเชื่อมต่อเฉพาะบน localhost เท่านั้น เว้นแต่คุณจะใส่โทเคนให้ ทุกคำสั่งรองรับ `--json` สำหรับ agent (เอกสาร JSON หนึ่งชุดบน stdout; การปฏิเสธจะแสดงเป็น `{"error": {…, "why", "fix"}}` พร้อม exit code 2) ดูคำแนะนำแบบเต็มได้ที่ [เทรนโมเดลแรกของคุณ](/docs/network/getting-started/train-your-first-model) และเมื่อคุณมีผลงานที่คุ้มค่าแก่การทดสอบแล้ว [ส่งผลงาน Method](/docs/network/getting-started/submit-a-method) จะช่วยเปลี่ยนให้กลายเป็นรายการบน Network

## ข้อมูลสังเคราะห์ที่คุณสามารถปกป้องได้

สำหรับภาษาที่มี morphological analyzer (FST) forge ผลิตข้อมูลฝึกผ่าน **language pack** — และบังคับใช้ *emit law* ที่ไม่มี pack ใดสามารถเลือกไม่ทำตามได้: ทุกคำที่สร้างขึ้นต้องผ่าน round-trip ผ่าน analyzer (generate → analyze → analysis เดิม) ทุก template อ้างอิงไวยากรณ์ที่ตีพิมพ์ที่มันถอดความ ทุก plausibility filter ถูกตั้งชื่อและนับ และทุกแถวถูกประทับตรา `synthetic: true` ตราประทับนั้นมีความสำคัญ: registry **ปฏิเสธแถวสังเคราะห์ในชุดทดสอบ** การทดสอบใช้ข้อมูลจริงเท่านั้น

forge เองไม่มี language pack มาให้ — มันเป็นเครื่องมือทั่วไป Pack อยู่กับภาษาของตนและเชื่อมต่อผ่าน module path หรือ entry point (Plains Cree pack อยู่ในโครงการ crk-translate):

```bash
nmt-forge synth nmt_forge_crk.pack:get_pack --out data/synth.jsonl
```

Analyzer และพจนานุกรมเป็นเครื่องมือแยกต่างหากที่ผู้ใช้ดึงมาเองภายใต้ใบอนุญาตของตนเอง — ไม่มีการรวมไว้ด้วยกัน ไม่มีการแจกจ่ายซ้ำ

## กรรมการของภาษาคุณเอง อยู่ในวงจร

มาตรฐานการประเมิน LYSS (linter ต่อภาษาที่รู้ว่า เช่น การสะกดสองแบบของ Cree ต่างกันเพียงแค่รูปแบบสระยาวที่มีเอกสารรองรับ) เชื่อมต่อกับทุก scoring surface — และเข้าสู่การเลือก checkpoint ดังนั้นโมเดลที่ชนะคือโมเดลที่ *กรรมการของภาษา* ชอบ ไม่ใช่แค่ chrF++:

```bash
nmt-forge score --eval-set textbook-test --hyps decoded.txt \
    --plugin champollion_lyss.crk.metrics:CrkLinterMetric

  chrf++                            46.02  [43.11, 48.87] 95% CI
  crk_linter:equivalent_match_rate   0.31  [ 0.24,  0.38] 95% CI
```

ตัวเลข plugin ทุกตัวได้รับ confidence interval กรรมการที่ขาด prerequisite จะรายงาน *unavailable* แทนที่จะให้คะแนนที่แต่งขึ้น

เช่นเดียวกันกับ **full harness metric stack** — nmt-forge รองรับทุกอย่างที่ [eval harness](/docs/network/specifications/harness) รองรับ รวมถึง neural metric (COMET, COMET-QE, MetricX) โดยรัน inference ครั้งเดียวและ bootstrap confidence interval จากคะแนนต่อรายการที่แคชไว้ ก่อนที่คุณจะเลือก checkpoint บน automatic metric ใด ๆ `discover` จะแสดง [ความน่าเชื่อถือที่วัดได้](/docs/network/specifications/metric-reliability) ของแต่ละ metric สำหรับตระกูลภาษาของคุณ — สำหรับ Inuktitut BLEU แทบไม่สัมพันธ์กับการตัดสินของมนุษย์ (r=0.16) ในขณะที่ COMET ทำได้ (r=0.86) สำหรับตระกูลภาษาที่มีทรัพยากรน้อยส่วนใหญ่ คำตอบที่ซื่อสัตย์คือ *ยังไม่ได้วัด* เครื่องมือบอกคุณว่าตัวเลขใดควรเชื่อก่อนที่คุณจะ optimize ไปหามัน

## ไปศึกษาเพิ่มเติมได้ที่

- **เพิ่งเริ่มต้นกับคำศัพท์เหล่านี้ใช่ไหม?** [การเทรน MT ด้วยภาษาที่เข้าใจง่าย](/docs/network/context/mt-training-concepts) นิยามศัพท์ทุกคำ — ข้อมูล train กับข้อมูล eval, loss กับ decoding, การรั่วไหล (leakage), chrF++, backtranslation, ภาวะคงที่ (the plateau) — พร้อมตัวอย่างการทำงานจริง เขียนขึ้นสำหรับผู้ที่ไม่มีพื้นฐานมาก่อน
- **พร้อมสร้างแล้วหรือยัง?** [หากคุณต้องการเทรนโมเดลของคุณเอง](/docs/network/tutorials/train-your-own-model) เป็นคำแนะนำทีละขั้นตอนที่เน้นการทำงานร่วมกับ agent: เลือกภาษา → รวบรวมข้อมูล → สังเคราะห์ข้อมูล → แบ่งข้อมูล (split) → เทรน → ประเมินผล → ปรับปรุงซ้ำ → ให้บริการและส่งผลงาน โดยแสดงให้เห็นว่า guardrail แต่ละตัวช่วยดักจับข้อผิดพลาดได้อย่างไร [สร้าง MT สำหรับภาษาของคุณ](/docs/build-mt-for-your-language) นำการเทรนมาวางในบริบทของเส้นทางการพัฒนาทั้งหมด — ตั้งแต่การค้นหาสิ่งที่มีอยู่แล้ว การวัดผลตัวเลือกต่างๆ ไปจนถึงการติดตั้งใช้งาน
- **เทรน แล้วส่งผลงาน:** โมเดลที่เทรนอย่างตรงไปตรงมาจะกลายเป็นรายการบน Network ผ่านทาง [ส่งผลงาน Method](/docs/network/getting-started/submit-a-method)
- **แถบแสดงความคลาดเคลื่อน (error bars):** [การทดสอบนัยสำคัญทางสถิติ](/docs/network/specifications/significance) คือหลักคณิตศาสตร์ที่ forge ใช้อยู่เป็นค่าเริ่มต้น
- **ควรเชื่อถือเมตริกใด:** ตรวจสอบ [ความน่าเชื่อถือของเมตริก](/docs/network/specifications/metric-reliability) ก่อนที่จะเลือก checkpoint จากเมตริกอัตโนมัติใดๆ
- **ทุกคำสั่งและแฟล็ก:** [เอกสารอ้างอิงคำสั่ง forge](/docs/network/getting-started/forge-command-reference) ซึ่งสร้างขึ้นจากตัวเครื่องมือเองโดยตรง
- **การจำแนกประเภทความล้มเหลว (failure taxonomy)** — ข้อผิดพลาดแต่ละรายการ ตัวอย่างที่เป็นรูปธรรม และกลไกป้องกันที่คอยดักจับสิ่งเหล่านั้น — จะมาพร้อมกับซอร์สโค้ดของ nmt-forge โดย agent จะได้รับกฎชุดเดียวกันนี้จากเครื่องมือ `get_training_guardrails` ของเซิร์ฟเวอร์ MCP (ตัวเลือก `topic`) และทุกการปฏิเสธจะระบุรายละเอียดว่าเกิดอะไรขึ้น/ทำไม/และแก้ไขอย่างไรในตัวเองเสมอ
