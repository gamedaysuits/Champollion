# การรายงานข้อผิดพลาดและการเป็นเจ้าของการแก้ไข

> **จุดยืน.** การผิดพลาดเป็นสิ่งที่หลีกเลี่ยงไม่ได้สำหรับแพลตฟอร์มที่เผยแพร่ข้อเท็จจริงและการประเมินเกี่ยวกับภาษาหลายพันภาษา สิ่งที่ *ไม่จำเป็น* ต้องเป็นเช่นนั้นคือ ใครจะได้รับความเชื่อถือเมื่อมีการรายงานข้อผิดพลาด และใครเป็นเจ้าของการแก้ไข คำตอบของเราคือ รายงานจากผู้พูดที่คล่องแคล่วมีน้ำหนักเหนือกว่าระบบอัตโนมัติของเราเสมอ ทุกการแก้ไขมีข้อมูลที่มาระบุว่าใครเปลี่ยนแปลงอะไรและเพราะเหตุใด และชุมชนสามารถถอนหรือยับยั้งการใช้ข้อมูลภาษาของตนได้ — ไม่ใช่ในฐานะความอนุเคราะห์ แต่เป็นคุณสมบัติที่บังคับใช้ได้ในระดับสถาปัตยกรรม

แพลตฟอร์มข้อมูลส่วนใหญ่ปฏิบัติต่อรายงานข้อผิดพลาดเหมือนตั๋วสนับสนุน: ผู้ใช้ร้องเรียน ผู้ดูแลตัดสินใจ บันทึกเปลี่ยนแปลงโดยไม่มีการแจ้ง สำหรับข้อมูลภาษาของชนพื้นเมือง โมเดลนั้นกลับหัวกลับหาง บุคคลที่รายงานข้อผิดพลาดมักมีอำนาจมากกว่าแพลตฟอร์ม — ผู้พูดที่บอกว่าคำหนึ่งผิดไม่ใช่ "ผู้ใช้" แต่คือแหล่งความจริงที่กำลังแก้ไขตัวแทน การออกแบบด้านล่างนี้เกิดจากการนำเรื่องนี้มาพิจารณาอย่างจริงจัง

## ข้อผิดพลาดสองประเภท หลักการเดียว

แพลตฟอร์มเผยแพร่การอ้างสิทธิ์สองประเภทที่อาจผิดพลาดได้:

1. **ข้อเท็จจริงเกี่ยวกับภาษา** — การ์ดข้อมูลภาษาที่ขับเคลื่อนการประเมินผล: ข้อมูลการจำแนกประเภท, อักขรวิธี, ลักษณะทางภาษาศาสตร์, เมตริกใดที่นำมาปรับใช้ การ์ดอาจระบุจำนวนผู้พูดโดยประมาณผิด, ความสัมพันธ์ระหว่างภาษาถิ่นผิด หรือสถานะของระบบการเขียนผิด
2. **การตัดสินเกี่ยวกับการแปล** — คำแปลอ้างอิงในคลังข้อความ (corpus) ที่ผู้พูดมองว่าไม่ถูกต้องหรือไม่เป็นธรรมชาติ, เมตริกอัตโนมัติที่ปฏิเสธคำที่ใช้ได้หรือยอมรับคำที่ใช้ไม่ได้, คะแนนอัตโนมัติระดับสูงสำหรับผลลัพธ์ที่ผู้พูดไม่ยอมรับ

หลักการที่ครอบคลุมทั้งสองประเภท ซึ่งมีผลผูกพันอยู่แล้วใน [ข้อกำหนดการให้คะแนน](/docs/network/specifications/scoring) และ [ข้อกำหนด Benchmark §7](/docs/network/specifications/benchmark#7-human-validation): **ผลลัพธ์อัตโนมัติเป็นเพียงตัวแทน ผู้พูดคือแหล่งความจริง** พันธกิจที่เผยแพร่ใน [โปรโตคอลการตรวจสอบโดยผู้พูด §6](/docs/network/specifications/speaker-validation#6-what-speakers-get) ระบุอย่างตรงไปตรงมา: หากผู้พูดบอกว่า linter ผิดในเรื่องใด เราจะแก้ไข linter

## เส้นทางของรายงาน

นี่คือเส้นทางที่รายงานดำเนินไป พร้อมสถานะที่ตรงไปตรงมา — บางส่วนทำงานอยู่แล้วในปัจจุบัน บางส่วนระบุไว้แล้วแต่ยังไม่ได้สร้าง

**การรายงานการแปลที่ผิดหรือการตัดสินเมตริก (ทำงานอยู่แล้วในปัจจุบัน ผ่านช่องทางตรง)** ผู้พูดที่พบการแปลอ้างอิงที่ผิด คำที่ถูกปฏิเสธอย่างไม่ถูกต้อง หรือ "คำเทียบเท่า" ที่ยอมรับไม่ได้ สามารถรายงานผ่านระบบติดตามปัญหาของ repository สาธารณะของโครงการ หรือติดต่อโครงการโดยตรง เวอร์ชันที่มีโครงสร้าง — หน้าจอการให้คะแนนพร้อมตัวเลือก *ปฏิเสธ / เข้าใจใจความ / ยอมรับได้ / ดีเยี่ยม* และหมายเหตุข้อความอิสระ — คือส่วนติดต่อการตรวจสอบของชุมชน ซึ่งระบุไว้ใน [ข้อกำหนด Benchmark §7.3](/docs/network/specifications/benchmark#7-human-validation) แต่ยังไม่เปิดใช้งาน จนกว่าจะพร้อม รายงานจะได้รับการจัดการแบบตัวต่อตัว และงานตรวจสอบ (การตรวจสอบโดยผู้พูดที่มีโครงสร้างและได้รับค่าตอบแทน — ดู [วิธีที่ผู้พูดได้รับค่าตอบแทน](/docs/network/perspectives/how-speakers-get-paid)) คือช่องทางการแก้ไขหลัก

**การรายงานข้อเท็จจริงที่ผิดบนการ์ดภาษา (ทำงานอยู่แล้วในปัจจุบัน ช่องทางเดียวกัน)** การแก้ไขการ์ดดำเนินตามเส้นทางเดียวกัน: รายงาน ตรวจสอบ เปลี่ยนแปลงพร้อมเวอร์ชัน เนื่องจากการ์ดขับเคลื่อนพฤติกรรมการประเมิน — เมตริกใดที่โหลด โมเดลใดที่แนะนำ — การแก้ไขการ์ดอาจเปลี่ยนคะแนน ดังนั้นการแก้ไขจึงถูกนำไปใช้เป็นการเปลี่ยนแปลงข้อมูลที่บันทึกไว้ ไม่ใช่การแก้ไขแบบเงียบ

**สิ่งที่เกิดขึ้นต่อไป — ใครเป็นผู้ตัดสินใจ:**

- **การตัดสินใจทางภาษาศาสตร์เป็นสิทธิ์ของผู้พูดภาษานั้น** ไม่ว่ารูปแบบนั้นจะถูกต้องหรือไม่ การใช้คำสองแบบมีความหมายเทียบเท่ากันหรือไม่ หรือระดับภาษาเหมาะสมหรือไม่ — แพลตฟอร์มเป็นเพียงผู้นำคำตอบไปปรับใช้ ไม่ได้เป็นผู้กำหนดคำตอบ ในกรณีที่ผู้พูดมีความเห็นต่างกัน (เช่น ภาษาถิ่น, แบบแผนอักขรวิธี) คำตอบจะถูกบันทึกไว้เป็นความผันแปร ไม่ได้ถูกชี้ขาดโดยเรา — โครงสร้างข้อมูล (schemas) ของคลังข้อความและ linter รองรับการระบุตัวแปรทางภาษาถิ่นให้เป็นทางเลือกที่ยอมรับได้ แทนที่จะบังคับให้มีรูปแบบที่ชนะเพียงหนึ่งเดียว
- **การตัดสินใจเกี่ยวกับข้อมูลของชุมชนเป็นสิทธิ์ขององค์กรกำกับดูแลของชุมชนนั้น** สำหรับภาษาที่มีองค์กรกำกับดูแล การเปลี่ยนแปลงคลังข้อความสำหรับการประเมินผล, การยอมรับข้อแก้ไขเข้าสู่ชุดทดสอบแบบปิด (sealed test sets), และผลกระทบต่อการนำไปใช้งานจริง จะต้องดำเนินการผ่านองค์กรเหล่านั้น — นั่นคือการควบคุมข้อมูลภาษาโดยชุมชน — ดูที่ [อำนาจอธิปไตยเหนือข้อมูล](/docs/network/sovereignty/data-sovereignty) — ซึ่งนำไปปฏิบัติจริงในฐานะกระบวนการ ไม่ใช่เพียงคำประกาศ
- **ข้อผิดพลาดเชิงกลไกจะได้รับการแก้ไขโดยตรง** คำพิมพ์ผิด, ลิงก์เสีย, ฟิลด์ที่แจงส่วน (parse) ผิด — รายงาน แก้ไข และบันทึกประวัติ ไม่ใช่ทุกเรื่องที่จำเป็นต้องผ่านคณะกรรมการ

## การแก้ไขมีข้อมูลที่มา

การแก้ไขที่ไม่สามารถตรวจสอบย้อนกลับได้คือเพียงความเห็นที่ใหม่กว่า กฎข้อมูลที่มาสามข้อใช้กับทุกข้อเท็จจริงและทุกการแก้ไข:

1. **ทุกข้อเท็จจริงระบุแหล่งที่มา** การ์ดภาษาและรายการคลังข้อมูลบันทึกว่าแต่ละค่ามาจากไหน — ชุดข้อมูลที่เผยแพร่ การมีส่วนร่วมของชุมชน หรือการตรวจสอบของผู้พูด
2. **ค่าที่ได้มาถูกระบุว่าเป็นของเรา ไม่ใช่ของต้นทาง** เมื่อแพลตฟอร์มคำนวณบางอย่าง — การรวม การเข้ารหัสใหม่ การรวมค่า — จะถูกบันทึกเป็นการได้มาของแพลตฟอร์ม *จาก* แหล่งต้นทาง ไม่ใช่เขียนภายใต้ชื่อของต้นทาง ชุดข้อมูลต้นทางไม่ควรถูกตำหนิหรือให้เครดิตสำหรับตัวเลขที่ไม่ได้เผยแพร่
3. **การแก้ไขกลายเป็นส่วนหนึ่งของบันทึก** การแก้ไขของผู้พูดถูกบันทึกเป็นการยืนยันใหม่ที่มีการระบุที่มา (ระบุชื่อหรือไม่ระบุชื่อ ตามที่ผู้พูดเลือก — เงื่อนไขเดียวกับงานตรวจสอบ) ที่แทนที่ค่าเดิม ประวัติของสิ่งที่เปลี่ยนแปลงยังคงตรวจสอบได้ เวอร์ชันคลังข้อมูลมี hash-manifest ([ความร่วมมือคลังข้อมูล §4.4](/docs/network/specifications/corpus-partnership)) ดังนั้นคลังข้อมูลที่แก้ไขแล้วจึงเป็นเวอร์ชันใหม่ที่มองเห็นได้ชัดเจน และทุก run card บันทึกเวอร์ชันที่แน่นอนที่ใช้ในการให้คะแนน — คะแนนเก่ายังคงตีความได้ คะแนนใหม่สะท้อนการแก้ไข

## สิทธิ์ยับยั้ง อย่างเป็นรูปธรรม

"การควบคุมของชุมชน" เป็นสิ่งที่อ้างได้ง่าย นี่คือสิ่งที่มันหมายถึงในสถาปัตยกรรมที่เผยแพร่:

- **ผู้พูดสามารถถอนการมีส่วนร่วมของตนได้** ผู้พูดสามารถดึงการให้คะแนนของตนออกได้ตลอดเวลา และการถอนจะลบออกจากการวิเคราะห์ทั้งหมด ([การตรวจสอบโดยผู้พูด §5](/docs/network/specifications/speaker-validation#5-data-governance)) ผู้พูดยังมีสิทธิ์ยับยั้งการเผยแพร่ผลลัพธ์ที่พวกเขาเห็นว่ามีปัญหา
- **ชุมชนสามารถหยุดการประเมินได้ทั้งหมด** ชุดทดสอบที่ปิดผนึกถูกเข้ารหัส โดยมีการถือครองคีย์ในลักษณะที่แพลตฟอร์มเพียงอย่างเดียวไม่สามารถสร้างขึ้นใหม่ได้ ชุมชนสามารถเพิกถอนการเข้าถึงการประเมินโดยปฏิเสธการมีส่วนร่วมในการสร้างคีย์ใหม่ ([ความร่วมมือคลังข้อมูล §4.3](/docs/network/specifications/corpus-partnership#4-cryptographic-sealing-and-sandbox-testing)) "จะเกิดอะไรขึ้นถ้าเราต้องการหยุด?" มีคำตอบที่ระบุไว้: ข้อมูลที่ปิดผนึกจะไม่ถูกเปิดเผยและการประเมินจะสิ้นสุดลง
- **ไม่มีคะแนนใดที่แทนที่การตัดสินใจของชุมชน** วิธีการที่ขึ้นอันดับต้นของ leaderboard ยังคงนำไปใช้งานได้ก็ต่อเมื่อองค์กรกำกับดูแลอนุมัติเท่านั้น ([การโอนความเป็นเจ้าของ](/docs/network/sovereignty/ownership-transfer)) — และชุมชนที่ตัดสินใจว่า MT ไม่ควรนำไปใช้กับภาษาของตนเลยกำลังใช้ระบบตามที่ออกแบบไว้ ไม่ใช่ทำลายมัน (ดู [การแปลไม่ใช่การฟื้นฟู](/docs/network/perspectives/translation-is-not-revitalization))

## สิ่งที่เรายังไม่ได้สร้าง

เพื่อให้สอดคล้องกับเจตนารมณ์ของเนื้อหาในส่วนนี้: อินเทอร์เฟซการตรวจสอบโดยชุมชนอยู่ในแผนงาน ยังไม่เปิดให้ใช้งานจริง ปัจจุบันยังไม่มีการจัดตั้งองค์กรกำกับดูแลสำหรับภาษาใด ๆ — ยังไม่มีการแต่งตั้งผู้ดูแลจากชุมชนสำหรับชุดวัดเปรียบเทียบมาตรฐาน (benchmark) ใด ๆ รวมถึง Plains Cree และเราจะไม่เปิดเผยชื่อผู้ดูแลต่อสาธารณะก่อนที่พวกเขาจะให้ความยินยอม จนกว่าส่วนประกอบเหล่านั้นจะพร้อมใช้งาน การส่งข้อแก้ไขจะดำเนินการผ่านช่องทางตรงที่ระบุตัวตนได้ และข้อกำหนดทางเทคนิค (spec) ที่เผยแพร่แล้ว — ไม่ใช่หน้านี้ — จะยังคงเป็นคำอธิบายกระบวนการที่มีผลผูกพัน หากหน้านี้และข้อกำหนดทางเทคนิคมีเนื้อหาขัดแย้งกัน ให้ยึดตามข้อกำหนดทางเทคนิคเป็นหลัก และเราถือว่าความขัดแย้งดังกล่าวเป็นข้อผิดพลาด (bug) ที่ควรค่าแก่การรายงานเช่นกัน

## สิ่งนี้หมายความว่าอะไรสำหรับคุณ

:::info[หากคุณเป็นสมาชิกชุมชน]
หากมีสิ่งใดเกี่ยวกับภาษาของคุณบนแพลตฟอร์มนี้ที่ไม่ถูกต้อง ไม่ว่าจะเป็นข้อเท็จจริง การแปล หรือป้ายกำกับ — รายงานของคุณคือคำให้การจากแหล่งข้อมูลโดยตรง ไม่ใช่คำร้องเรียนที่รอการจัดลำดับความสำคัญ คุณเป็นผู้ตัดสินใจว่าจะให้เครดิตการแก้ไขด้วยชื่อของคุณหรือไม่ คุณสามารถถอนการมีส่วนร่วมของคุณได้ในภายหลัง และชุมชนของคุณสามารถระงับการใช้ข้อมูลของตนได้โดยสิ้นเชิง เริ่มต้นได้ที่ [สำหรับชุมชนภาษา](/docs/network/community/for-language-communities) หรือเปิด issue บน repository สาธารณะได้เลย
:::

:::info[หากคุณเป็นนักวิจัย]
การแก้ไขในที่นี้คือข้อมูลที่มีที่มาที่ไปชัดเจน ไม่ใช่การแก้ไขแบบเงียบๆ: เวอร์ชันของ corpus ถูกแฮชไว้, run card ระบุเวอร์ชันที่แน่นอนที่ใช้ในการประเมิน และค่าที่ได้จากการคำนวณถูกระบุว่าเป็นค่าที่ได้มา หากคุณนำคะแนนหรือ corpus จาก Network ไปใช้ต่อ ให้อ้างอิงเวอร์ชันด้วย — และให้ถือว่าคลื่นการแก้ไขที่ขับเคลื่อนโดยผู้พูดภาษาเป็นผลการค้นพบเกี่ยวกับความถูกต้องของตัวชี้วัด เพราะนั่นคือสิ่งที่มันเป็นจริงๆ
:::

:::info[หากคุณเป็นผู้พัฒนา]
คะแนนของวิธีการของคุณอาจเปลี่ยนแปลงได้อย่างถูกต้องโดยที่โค้ดของคุณไม่ได้เปลี่ยนแปลงเลย — คำที่ถูกปฏิเสธอย่างผิดพลาดได้รับการเพิ่มเข้า allowlist, การแปลอ้างอิงได้รับการแก้ไข, หรือคลาสของตัวแปรได้รับการแก้ไข ออกแบบระบบให้รองรับสิ่งนี้: ระบุเวอร์ชัน corpus ใน run card ของคุณ ([ข้อกำหนด Run Card](/docs/network/specifications/run-card)), ติดตาม changelog ของชุดข้อมูล และถือว่าการแก้ไขจากผู้พูดภาษาเป็นสัญญาณข้อผิดพลาดที่เชื่อถือได้มากที่สุดที่คุณจะได้รับโดยไม่มีค่าใช้จ่าย
:::
