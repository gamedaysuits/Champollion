# การรายงานข้อผิดพลาดและการเป็นเจ้าของการแก้ไข

> **จุดยืน** การมีข้อผิดพลาดย่อมเป็นสิ่งที่หลีกเลี่ยงไม่ได้สำหรับแพลตฟอร์มที่เผยแพร่ข้อเท็จจริงและการประเมินผลเกี่ยวกับหลากหลายภาษา แต่สิ่งที่ไม่ควรปล่อยให้เป็นไปตามยถากรรมคือ *ใคร* จะได้รับความเชื่อถือเมื่อมีรายงานข้อผิดพลาดเข้ามา และ *ใคร* เป็นเจ้าของสิทธิ์ในการแก้ไข คำตอบของเราคือ รายงานจากผู้ใช้ภาษาอย่างคล่องแคล่วมีความสำคัญเหนือกว่าระบบอัตโนมัติของเรา ทุกการแก้ไขจะระบุแหล่งที่มาและประวัติว่าใครเป็นผู้เปลี่ยน เปลี่ยนอะไร และเพราะเหตุใด และชุมชนสามารถถอนหรือยับยั้ง (veto) การใช้ข้อมูลภาษาของตนได้เสมอ โดยไม่ใช่แค่การให้เกียรติตามมารยาท แต่เป็นคุณสมบัติที่บังคับใช้จริงในสถาปัตยกรรมของระบบ

แพลตฟอร์มข้อมูลส่วนใหญ่ปฏิบัติต่อรายงานข้อผิดพลาดเหมือนตั๋วสนับสนุน: ผู้ใช้ร้องเรียน ผู้ดูแลตัดสินใจ บันทึกเปลี่ยนแปลงโดยไม่มีการแจ้ง สำหรับข้อมูลภาษาของชนพื้นเมือง โมเดลนั้นกลับหัวกลับหาง บุคคลที่รายงานข้อผิดพลาดมักมีอำนาจมากกว่าแพลตฟอร์ม — ผู้พูดที่บอกว่าคำหนึ่งผิดไม่ใช่ "ผู้ใช้" แต่คือแหล่งความจริงที่กำลังแก้ไขตัวแทน การออกแบบด้านล่างนี้เกิดจากการนำเรื่องนี้มาพิจารณาอย่างจริงจัง

## ข้อผิดพลาดสองประเภท หลักการเดียว

แพลตฟอร์มเผยแพร่การอ้างสิทธิ์สองประเภทที่อาจผิดพลาดได้:

1. **ข้อเท็จจริงเกี่ยวกับภาษา** — การ์ดข้อมูลภาษาที่ขับเคลื่อนการประเมินผล: ข้อมูลการจำแนกประเภท, อักขรวิธี, ลักษณะทางภาษาศาสตร์, เมตริกใดที่นำมาปรับใช้ การ์ดอาจระบุจำนวนผู้พูดโดยประมาณผิด, ความสัมพันธ์ระหว่างภาษาถิ่นผิด หรือสถานะของระบบการเขียนผิด
2. **การตัดสินเกี่ยวกับการแปล** — คำแปลอ้างอิงในคลังข้อความ (corpus) ที่ผู้พูดมองว่าไม่ถูกต้องหรือไม่เป็นธรรมชาติ, เมตริกอัตโนมัติที่ปฏิเสธคำที่ใช้ได้หรือยอมรับคำที่ใช้ไม่ได้, คะแนนอัตโนมัติระดับสูงสำหรับผลลัพธ์ที่ผู้พูดไม่ยอมรับ

หลักการที่ครอบคลุมทั้งสองประเภท ซึ่งมีผลผูกพันอยู่แล้วใน [ข้อกำหนดการให้คะแนน](/docs/network/specifications/scoring) และ [ข้อกำหนด Benchmark §7](/docs/network/specifications/benchmark#7-human-validation): **ผลลัพธ์อัตโนมัติเป็นเพียงตัวแทน ผู้พูดคือแหล่งความจริง** พันธกิจที่เผยแพร่ใน [โปรโตคอลการตรวจสอบโดยผู้พูด §6](/docs/network/specifications/speaker-validation#6-what-speakers-get) ระบุอย่างตรงไปตรงมา: หากผู้พูดบอกว่า linter ผิดในเรื่องใด เราจะแก้ไข linter

## เส้นทางของรายงาน

นี่คือเส้นทางที่รายงานดำเนินไป พร้อมสถานะที่ตรงไปตรงมา — บางส่วนทำงานอยู่แล้วในปัจจุบัน บางส่วนระบุไว้แล้วแต่ยังไม่ได้สร้าง

**การรายงานคำแปลหรือการตัดสินของตัวชี้วัดที่ไม่ถูกต้อง (ใช้งานได้แล้ววันนี้ ผ่านช่องทางโดยตรง)** ผู้ใช้ภาษาที่พบคำแปลอ้างอิงที่ไม่ถูกต้อง คำที่ถูกคัดออกอย่างผิดพลาด หรือ "คำเทียบเคียง" ที่ยอมรับไม่ได้ สามารถรายงานผ่านเครื่องมือติดตามปัญหา (issue tracker) ในคลังข้อมูลสาธารณะของโครงการ หรือติดต่อโครงการโดยตรงได้ รูปแบบที่มีโครงสร้างชัดเจนของฟังก์ชันนี้ — หน้าจอการให้คะแนนพร้อมตัวเลือก *ปฏิเสธ / พอเข้าใจใจความ / ยอมรับได้ / ยอดเยี่ยม* และช่องข้อความอิสระสำหรับบันทึก — คือส่วนต่อประสานสำหรับการตรวจทานโดยชุมชน ซึ่งระบุไว้ใน [ข้อกำหนดเกณฑ์มาตรฐาน ข้อ 7.3](/docs/network/specifications/benchmark#7-human-validation) แต่ยังไม่เปิดใช้งานจริง จนกว่าจะเปิดใช้งาน รายงานต่างๆ จะได้รับการจัดการแบบบุคคลต่อบุคคล และงานการตรวจสอบความถูกต้องด้วยตนเอง (การตรวจทานโดยผู้ใช้ภาษาที่ได้รับค่าตอบแทนและมีโครงสร้างชัดเจน — ดู [การทำงานร่วมกับผู้ใช้ภาษา](/docs/working-with-speakers)) ถือเป็นกระบวนการหลักในการแก้ไขข้อมูล

**การรายงานข้อเท็จจริงที่ผิดบนการ์ดภาษา (ทำงานอยู่แล้วในปัจจุบัน ช่องทางเดียวกัน)** การแก้ไขการ์ดดำเนินตามเส้นทางเดียวกัน: รายงาน ตรวจสอบ เปลี่ยนแปลงพร้อมเวอร์ชัน เนื่องจากการ์ดขับเคลื่อนพฤติกรรมการประเมิน — เมตริกใดที่โหลด โมเดลใดที่แนะนำ — การแก้ไขการ์ดอาจเปลี่ยนคะแนน ดังนั้นการแก้ไขจึงถูกนำไปใช้เป็นการเปลี่ยนแปลงข้อมูลที่บันทึกไว้ ไม่ใช่การแก้ไขแบบเงียบ

**สิ่งที่เกิดขึ้นต่อไป — ใครเป็นผู้ตัดสินใจ:**

- **การตัดสินทางภาษาเป็นสิทธิ์ของผู้ใช้ภาษานั้นๆ** ไม่ว่ารูปคำจะถูกต้องหรือไม่ ข้อความสองแบบมีความหมายเทียบเท่ากันหรือไม่ หรือระดับภาษาเหมาะสมหรือไม่ — แพลตฟอร์มมีหน้าที่นำคำตอบไปใช้งานจริง ไม่ใช่เป็นผู้กำหนดคำตอบ ในกรณีที่ผู้ใช้ภาษามีความเห็นไม่ตรงกัน (เช่น ภาษาถิ่น ขนบการสะกดคำ) คำตอบจะถูกบันทึกไว้ในฐานะความแปรผันของภาษา โดยเราจะไม่เป็นผู้ตัดสินขาด — สกีมาของคลังข้อมูลและตัวตรวจทานโค้ด (linter) รองรับการติดแท็กความแปรผันทางภาษาถิ่นให้เป็นทางเลือกที่ยอมรับได้ แทนที่จะบังคับให้มีเพียงคำตอบเดียวที่ชนะ
- **การตัดสินใจเกี่ยวกับข้อมูลของชุมชนเป็นสิทธิ์ขององค์กรกำกับดูแลของชุมชนนั้น** สำหรับภาษาที่มีองค์กรกำกับดูแล การเปลี่ยนแปลงคลังข้อมูลการประเมินผล การยอมรับการแก้ไขเข้าสู่ชุดทดสอบที่ปิดผนึก และผลกระทบต่อการนำไปใช้งานจริง จะต้องผ่านความเห็นชอบจากองค์กรเหล่านี้ — นี่คือการควบคุมข้อมูลภาษาโดยชุมชน — ดู [ภาษาของคุณ กฎของคุณ](/docs/your-words-your-rules) — ซึ่งนำไปปฏิบัติในฐานะกระบวนการทำงานจริง ไม่ใช่เพียงแค่คำขวัญ
- **ข้อผิดพลาดทางเทคนิคสามารถแก้ไขได้ทันที** คำพิมพ์ผิด ลิงก์เสีย เขตข้อมูลที่แจงส่วนผิดพลาด — เมื่อได้รับรายงาน จะได้รับการแก้ไขและบันทึกประวัติทันที ไม่ใช่ทุกเรื่องที่ต้องตั้งคณะกรรมการพิจารณา

## การแก้ไขมีข้อมูลที่มา

การแก้ไขที่ไม่สามารถตรวจสอบย้อนกลับได้คือเพียงความเห็นที่ใหม่กว่า กฎข้อมูลที่มาสามข้อใช้กับทุกข้อเท็จจริงและทุกการแก้ไข:

1. **ทุกข้อเท็จจริงต้องระบุแหล่งที่มา** การ์ดข้อมูลภาษาและรายการในคลังข้อมูลจะบันทึกว่าแต่ละค่ามาจากที่ใด — ชุดข้อมูลที่เผยแพร่ การมีส่วนร่วมของชุมชน หรือการตรวจทานของผู้ใช้ภาษา
2. **ค่าที่ได้จากการประมวลผลต่อต้องระบุว่าเป็นของเรา ไม่ใช่ของต้นทาง** เมื่อแพลตฟอร์มคำนวณสิ่งใดขึ้นมา — เช่น การรวมค่า การแปลงรหัส หรือค่าผสม — จะต้องบันทึกว่าเป็นค่าที่แพลตฟอร์มแปลงผล *มาจาก* แหล่งข้อมูลต้นทาง และจะไม่ระบุภายใต้ชื่อของต้นทางเด็ดขาด ชุดข้อมูลต้นทางไม่ควรต้องรับผิดชอบหรือได้รับเครดิตสำหรับตัวเลขที่ตนเองไม่ได้เผยแพร่
3. **การแก้ไขจะกลายเป็นส่วนหนึ่งของบันทึกประวัติ** การแก้ไขโดยผู้ใช้ภาษาจะถูกบันทึกเป็นข้อความยืนยันใหม่ที่มีการระบุที่มา (ระบุชื่อหรือไม่ระบุชื่อก็ได้ ตามที่ผู้ใช้ภาษาเลือก — ภายใต้เงื่อนไขเดียวกับงานตรวจสอบความถูกต้อง) ซึ่งจะเข้ามาแทนที่ค่าเดิม ประวัติการเปลี่ยนแปลงทั้งหมดยังคงตรวจสอบย้อนหลังได้ เวอร์ชันของคลังข้อมูลจะใช้รหัสแฮชกำกับอย่างชัดเจน ([การลงทะเบียนคลังข้อมูล](/docs/network/sovereignty/registering-corpora)) ดังนั้นคลังข้อมูลที่แก้ไขแล้วจะเป็นเวอร์ชันใหม่อย่างชัดเจน และการ์ดการทำงานทุกใบจะบันทึกไว้อย่างแม่นยำว่าถูกคิดคะแนนเทียบกับเวอร์ชันใด — คะแนนเดิมยังคงตีความได้ ส่วนคะแนนใหม่จะสะท้อนการแก้ไขนั้น

## สิทธิ์ยับยั้ง อย่างเป็นรูปธรรม

"การควบคุมของชุมชน" เป็นสิ่งที่อ้างได้ง่าย นี่คือสิ่งที่มันหมายถึงในสถาปัตยกรรมที่เผยแพร่:

- **ผู้ใช้ภาษาสามารถถอนข้อมูลที่ตนมีส่วนร่วมได้** ผู้ใช้ภาษาสามารถเพิกถอนการให้คะแนนของตนเมื่อใดก็ได้ และการถอนข้อมูลจะลบข้อมูลนั้นออกจากการวิเคราะห์ทั้งหมด ([การตรวจสอบความถูกต้องโดยผู้ใช้ภาษา ข้อ 5](/docs/network/specifications/speaker-validation#5-data-governance)) นอกจากนี้ ผู้ใช้ภาษายังมีอำนาจยับยั้ง (veto) การเผยแพร่ผลลัพธ์ที่พวกเขาเห็นว่ามีปัญหาได้อีกด้วย
- **ชุมชนสามารถยุติการประเมินผลได้โดยสิ้นเชิง** ชุดทดสอบที่ปิดผนึกจะได้รับการเข้ารหัส และ Champollion ไม่ได้ถือส่วนของกุญแจถอดรหัสไว้ แพลตฟอร์มเพียงลำพังจึงไม่มีทางกู้ข้อมูลขึ้นมาใหม่ได้เลย ปัจจุบันกุญแจของชุดข้อมูลที่ปิดผนึกจะถือโดยผู้จัดงาน — ส่วนผู้ดูแลกุญแจของชุมชน: ยังไม่มีการแต่งตั้ง เมื่อผู้ดูแลที่ชุมชนแต่งตั้งถือส่วนของกุญแจสำหรับชุดข้อมูลนั้นแล้ว พวกเขาสามารถยุติการประเมินผลได้โดยปฏิเสธที่จะเข้าร่วมการประกอบกุญแจเพื่อถอดรหัส ([การลงทะเบียนคลังข้อมูล](/docs/network/sovereignty/registering-corpora)) คำถามที่ว่า "ถ้าเราต้องการหยุดล่ะ?" มีคำตอบที่ระบุไว้อย่างชัดเจน: ข้อมูลที่ปิดผนึกจะไม่ถูกเปิดเผย และการประเมินผลจะสิ้นสุดลงทันที
- **ไม่มีคะแนนใดมีอำนาจเหนือการตัดสินใจของชุมชน** อันดับบนกระดานผู้นำไม่ได้ให้สิทธิ์แก่ใครในการนำวิธีใดๆ ไปปรับใช้กับภาษาของชุมชน ([การโอนกรรมสิทธิ์](/docs/network/sovereignty/ownership-transfer)) — และการที่ชุมชนตัดสินใจว่าจะต้องไม่มีการนำ MT ไปปรับใช้กับภาษาของตนเลย ถือเป็นการใช้สิทธิ์ตามที่ระบบออกแบบไว้ ไม่ใช่การทำลายระบบ (ดู [การแปลไม่ใช่การฟื้นฟูภาษา](/docs/network/perspectives/translation-is-not-revitalization))

## สิ่งที่เรายังไม่ได้สร้าง

เพื่อให้สอดคล้องกับเจตนารมณ์ของเนื้อหาในส่วนนี้: อินเทอร์เฟซการตรวจสอบโดยชุมชนอยู่ในแผนงาน ยังไม่เปิดให้ใช้งานจริง ปัจจุบันยังไม่มีการจัดตั้งองค์กรกำกับดูแลสำหรับภาษาใด ๆ — ยังไม่มีการแต่งตั้งผู้ดูแลจากชุมชนสำหรับชุดวัดเปรียบเทียบมาตรฐาน (benchmark) ใด ๆ รวมถึง Plains Cree และเราจะไม่เปิดเผยชื่อผู้ดูแลต่อสาธารณะก่อนที่พวกเขาจะให้ความยินยอม จนกว่าส่วนประกอบเหล่านั้นจะพร้อมใช้งาน การส่งข้อแก้ไขจะดำเนินการผ่านช่องทางตรงที่ระบุตัวตนได้ และข้อกำหนดทางเทคนิค (spec) ที่เผยแพร่แล้ว — ไม่ใช่หน้านี้ — จะยังคงเป็นคำอธิบายกระบวนการที่มีผลผูกพัน หากหน้านี้และข้อกำหนดทางเทคนิคมีเนื้อหาขัดแย้งกัน ให้ยึดตามข้อกำหนดทางเทคนิคเป็นหลัก และเราถือว่าความขัดแย้งดังกล่าวเป็นข้อผิดพลาด (bug) ที่ควรค่าแก่การรายงานเช่นกัน

## สิ่งนี้หมายความว่าอะไรสำหรับคุณ

:::info[หากคุณเป็นสมาชิกของชุมชน]
หากมีสิ่งใดเกี่ยวกับภาษาของคุณบนแพลตฟอร์มนี้ที่ไม่ถูกต้อง — ไม่ว่าจะเป็นข้อเท็จจริง คำแปล หรือป้ายกำกับ — รายงานของคุณคือเสียงยืนยันจากข้อเท็จจริงในพื้นที่จริง ไม่ใช่แค่เรื่องร้องเรียนที่รอการคัดกรอง คุณสามารถเลือกได้ว่าจะให้ระบุชื่อของคุณในการแก้ไขหรือไม่ ข้อมูลที่คุณมีส่วนร่วมสามารถถอนคืนได้ในภายหลัง และชุมชนของคุณสามารถสั่งระงับการใช้ข้อมูลของตนได้ทันที เริ่มต้นได้ที่ [ภาษาของคุณ กฎของคุณ](/docs/your-words-your-rules) หรือเพียงเปิดประเด็นปัญหา (issue) ในคลังข้อมูลสาธารณะ
:::

:::info[หากคุณเป็นนักวิจัย]
การแก้ไขในที่นี้คือข้อมูลที่มีที่มาที่ไปชัดเจน ไม่ใช่การแก้ไขแบบเงียบๆ: เวอร์ชันของ corpus ถูกแฮชไว้, run card ระบุเวอร์ชันที่แน่นอนที่ใช้ในการประเมิน และค่าที่ได้จากการคำนวณถูกระบุว่าเป็นค่าที่ได้มา หากคุณนำคะแนนหรือ corpus จาก Network ไปใช้ต่อ ให้อ้างอิงเวอร์ชันด้วย — และให้ถือว่าคลื่นการแก้ไขที่ขับเคลื่อนโดยผู้พูดภาษาเป็นผลการค้นพบเกี่ยวกับความถูกต้องของตัวชี้วัด เพราะนั่นคือสิ่งที่มันเป็นจริงๆ
:::

:::info[หากคุณเป็นผู้พัฒนา]
คะแนนของวิธีการของคุณอาจเปลี่ยนแปลงได้อย่างถูกต้องโดยที่โค้ดของคุณไม่ได้เปลี่ยนแปลงเลย — คำที่ถูกปฏิเสธอย่างผิดพลาดได้รับการเพิ่มเข้า allowlist, การแปลอ้างอิงได้รับการแก้ไข, หรือคลาสของตัวแปรได้รับการแก้ไข ออกแบบระบบให้รองรับสิ่งนี้: ระบุเวอร์ชัน corpus ใน run card ของคุณ ([ข้อกำหนด Run Card](/docs/network/specifications/run-card)), ติดตาม changelog ของชุดข้อมูล และถือว่าการแก้ไขจากผู้พูดภาษาเป็นสัญญาณข้อผิดพลาดที่เชื่อถือได้มากที่สุดที่คุณจะได้รับโดยไม่มีค่าใช้จ่าย
:::
