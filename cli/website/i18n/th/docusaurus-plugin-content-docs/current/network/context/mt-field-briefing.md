## ส่วนที่ 1: การปฏิวัติของระบบประสาท (2013–2017) {#part-1-the-neural-revolution-20132017}

### ระบอบเก่า: การแปลด้วยเครื่องเชิงสถิติ

เพื่อทำความเข้าใจการปฏิวัติที่เปลี่ยนโฉมการแปลด้วยเครื่องในช่วงกลางทศวรรษ 2010 คุณต้องเข้าใจก่อนว่าสิ่งที่มีอยู่ก่อนหน้านั้นคืออะไร — และเหตุใดมันจึงล้มเหลว

ตั้งแต่ราวปี 2003 ถึง 2015 กระบวนทัศน์หลักใน MT คือ **Statistical Machine Translation (SMT)** โดยเฉพาะอย่างยิ่ง **phrase-based SMT** แนวคิดหลักนั้นดูเรียบง่ายอย่างหลอกลวง: แทนที่จะเขียนกฎเกี่ยวกับการทำงานของภาษา คุณรวบรวมข้อความคู่ขนานจำนวนมหาศาล — เอกสารที่มนุษย์แปลเป็นสองภาษา — แล้วปล่อยให้อัลกอริทึมทางสถิติเรียนรู้ความสอดคล้องกัน ระบบจะแยกประโยคต้นฉบับออกเป็นวลีที่ทับซ้อนกัน (ไม่ใช่วลีทางภาษาศาสตร์ แต่เป็นกลุ่ม n-gram ตามอำเภอใจ) ค้นหาการแปลที่มีความน่าจะเป็นทางสถิติสำหรับแต่ละกลุ่ม จากนั้นประกอบประโยคเป้าหมายโดยใช้ **language model** ที่รับประกันว่าผลลัพธ์มีความคล่องแคล่ว

เครื่องมือหลักของยุคนี้คือ **Moses** ซึ่งเป็น SMT toolkit แบบโอเพนซอร์สที่พัฒนาขึ้นเป็นหลักที่มหาวิทยาลัยเอดินบะระภายใต้การนำของ Philipp Koehn เปิดตัวในปี 2006 Moses กลายเป็น Linux ของการวิจัย MT — แทบทุกห้องปฏิบัติการวิจัย MT ในโลกใช้มัน เครื่องมือคู่หูของมัน **cdec** (พัฒนาโดย Chris Dyer ที่ Carnegie Mellon) มีความสามารถที่คล้ายกันด้วยรูปแบบที่แตกต่างออกไป เครื่องมือทั้งสองนี้กำหนดทิศทางการวิจัย MT เป็นเวลาหนึ่งทศวรรษ

Phrase-based SMT ทำงานได้ดีอย่างน่าประหลาดใจสำหรับคู่ภาษาที่มีข้อมูลคู่ขนานอุดมสมบูรณ์และลำดับคำที่คล้ายกัน เช่น อังกฤษ–ฝรั่งเศส อังกฤษ–สเปน อังกฤษ–เยอรมัน แต่มันมีข้อจำกัดเชิงโครงสร้างที่ลึกซึ้ง ระบบไม่มีแนวคิดเรื่องความหมาย มันเป็นการจับคู่รูปแบบบนสตริงพื้นผิว ประกอบการแปลจากชิ้นส่วนที่จำไว้ มันดิ้นรนกับการพึ่งพาระยะไกล (สรรพนามที่อ้างถึงคำนามหลายอนุประโยคก่อนหน้า) กับการเรียงลำดับใหม่ระหว่างภาษาที่แตกต่างกันทางประเภทวิทยา (เช่น อังกฤษ–ญี่ปุ่น ซึ่งกริยาปรากฏในตำแหน่งตรงข้ามกัน) และกับปรากฏการณ์ใดๆ ที่ต้องการการนามธรรมที่แท้จริงเหนือโครงสร้างภาษา การปรับปรุงแต่ละครั้งต้องการวิศวกรรมที่ซับซ้อนมากขึ้นเรื่อยๆ: กฎการเรียงลำดับที่สร้างด้วยมือ คุณลักษณะแบบกระจาย language model ขนาดมหึมา สถาปัตยกรรมกำลังเข้าใกล้เพดานของมัน

### การค้นพบ: Sequence-to-Sequence พร้อม Attention

รอยแตกแรกในกระบวนทัศน์ SMT ไม่ได้มาจากชุมชน MT แต่มาจากนักวิจัยด้าน deep learning ที่ทำงานกับปัญหาการสร้างแบบจำลองลำดับ

ในเดือนกันยายน 2014 **Dzmitry Bahdanau, Kyunghyun Cho และ Yoshua Bengio** ที่ Université de Montréal ได้ตีพิมพ์บทความที่จะพิสูจน์ว่าเป็นการเปลี่ยนแปลงครั้งสำคัญ: ["Neural Machine Translation by Jointly Learning to Align and Translate"](https://arxiv.org/abs/1409.0473) (นำเสนอที่ ICLR 2015) นวัตกรรมสำคัญคือ **attention mechanism**

เพื่อทำความเข้าใจว่าเหตุใดสิ่งนี้จึงสำคัญ คุณต้องมีบริบทก่อนหน้า เพียงไม่กี่เดือนก่อนหน้านั้น Ilya Sutskever, Oriol Vinyals และ Quoc V. Le ที่ Google ได้ตีพิมพ์ ["Sequence to Sequence Learning with Neural Networks"](https://arxiv.org/abs/1409.3215) (NIPS 2014) ซึ่งแสดงให้เห็นว่าเครือข่ายประสาทที่มีสถาปัตยกรรม **encoder–decoder** สามารถแปลประโยคได้ encoder อ่านประโยคต้นฉบับทีละคำและบีบอัดมันเป็นเวกเตอร์ความยาวคงที่เดียว — สรุปตัวเลขของอินพุตทั้งหมด จากนั้น decoder สร้างประโยคเป้าหมายทีละคำจากเวกเตอร์นั้น

สิ่งนี้ดูสง่างาม แต่มีข้อบกพร่องที่สำคัญ: เวกเตอร์เดียวเป็น **คอขวด** ข้อมูลทั้งหมดในประโยคต้นฉบับสามสิบคำต้องถูกบีบผ่านเวกเตอร์หนึ่งตัวที่มี เช่น 1,000 ตัวเลข ประโยคสั้นแปลได้ค่อนข้างดี ประโยคยาวเสื่อมคุณภาพอย่างมาก เพราะโมเดลลืมคำก่อนหน้าเมื่อถึงเวลาที่มันเข้ารหัสคำหลังๆ เสร็จ

attention mechanism ของ Bahdanau แก้ปัญหานี้ได้ แทนที่จะบีบอัดต้นฉบับทั้งหมดเป็นเวกเตอร์เดียว decoder ได้รับอนุญาตให้ **มองย้อนกลับ** ไปยัง hidden state ทั้งหมดของ encoder — การแสดงแทนระดับกลางในทุกตำแหน่งต้นฉบับ — และถ่วงน้ำหนักแบบไดนามิกว่าตำแหน่งใดมีความเกี่ยวข้องมากที่สุดสำหรับการสร้างแต่ละคำเป้าหมาย เมื่อสร้างคำภาษาอังกฤษว่า "cat" โมเดลสามารถให้ความสนใจกับคำภาษาฝรั่งเศสว่า "chat" ในต้นฉบับมากที่สุด แม้ว่าจะอยู่ห่างกันในประโยค โมเดลเรียนรู้ที่จะ *จัดแนว* คำต้นฉบับและเป้าหมายเป็นส่วนหนึ่งของกระบวนการแปล แทนที่จะพึ่งพาสรุปที่บีบอัดเดียว

นี่คือนวัตกรรมพื้นฐาน Attention ไม่เพียงแต่ปรับปรุง MT เท่านั้น มันกลายเป็นกลไกหลักของความก้าวหน้าเกือบทั้งหมดในการประมวลผลภาษาธรรมชาติที่ตามมา

### Google หันมาใช้ระบบประสาท

ผลลัพธ์ทางวิชาการในปี 2014–2015 นั้นน่าประทับใจแต่ยังไม่พร้อมสำหรับการผลิต สิ่งนั้นเปลี่ยนไปในปลายปี 2016

ในเดือนกันยายน 2016 ทีมงานขนาดใหญ่ที่ Google นำโดย **Yonghui Wu** ได้ตีพิมพ์ ["Google's Neural Machine Translation System: Bridging the Gap Between Human and Machine Translation"](https://arxiv.org/abs/1609.08144) ระบบที่รู้จักกันในชื่อ **GNMT** (Google Neural Machine Translation) เป็นสถาปัตยกรรม encoder–decoder ระดับอุตสาหกรรมพร้อม attention ที่ฝึกบนทรัพยากรข้อมูลคู่ขนานอันมหาศาลของ Google บทความนี้อ้างอย่างน่าตกใจว่า: สำหรับคู่ภาษาบางคู่ GNMT ลดข้อผิดพลาดในการแปลลง 55–85% เมื่อเทียบกับระบบ phrase-based SMT ที่มีอยู่ของ Google

ในเดือนพฤศจิกายน 2016 Google เริ่มเปลี่ยน Google Translate จาก phrase-based SMT เป็น GNMT สำหรับคู่ภาษาหลักอย่างเงียบๆ การเปลี่ยนแปลงนี้เสร็จสมบูรณ์โดยพื้นฐานสำหรับคู่ที่มีทรัพยากรสูงภายในปี 2017 สำหรับผู้ใช้ การเปลี่ยนแปลงนั้นน่าทึ่ง การแปลที่เคยอ่านดูแข็งกระด้าง ขาดตอน และบางครั้งไม่สมเหตุสมผล กลายเป็นสิ่งที่คล่องแคล่วขึ้นอย่างมาก — บางครั้งน่าประหลาดใจ ยุคของ "Google Translate ที่ไม่สมเหตุสมผล" ในฐานะมุกตลกกำลังสิ้นสุดลง

การตอบสนองต่อการแข่งขันเกิดขึ้นอย่างรวดเร็ว ในเดือนสิงหาคม 2017 **DeepL** ซึ่งก่อตั้งโดย **Gereon Frahling** ในเมืองโคโลญจน์ ประเทศเยอรมนี ได้เปิดตัวบริการแปลภาษา DeepL เติบโตมาจากโปรเจกต์ฐานข้อมูลคำศัพท์สองภาษา Linguee และสร้างความแตกต่างด้วยคุณภาพการแปลที่ได้รับการยอมรับ — โดยเฉพาะอย่างยิ่งสำหรับคู่ภาษาในยุโรป ซึ่งทำให้ DeepL สร้างชื่อเสียงในหมู่นักแปลมืออาชีพได้อย่างรวดเร็วในเรื่องการสร้างผลลัพธ์ที่เป็นธรรมชาติและถูกต้องตามหลักภาษามากกว่า Google โมเดลธุรกิจของ DeepL (freemium พร้อม API แบบชำระเงิน) และการมุ่งเน้นที่คุณภาพมากกว่าความครอบคลุม จะเป็นตัวกำหนดตำแหน่งทางการตลาดของบริษัทในอนาคต DeepL รองรับภาษาประมาณ 33 ภาษา — ซึ่งน้อยกว่า 194 ภาษาในรายการ Cloud Translation ของ Google มาก — แต่มาพร้อมกับจุดยืนที่ให้ความสำคัญกับคุณภาพเป็นอันดับแรก

### Transformer

หาก attention mechanism ของ Bahdanau คือรากฐาน **Transformer** ก็คืออาคารที่สร้างบนมัน — และอาคารนั้นเป็นตึกระฟ้า

ในเดือนมิถุนายน 2017 ทีมนักวิจัยแปดคนที่ Google — **Ashish Vaswani, Noam Shazeer, Niki Parmar, Jakob Uszkoreit, Llion Jones, Aidan N. Gomez, Łukasz Kaiser และ Illia Polosukhin** — ได้ตีพิมพ์ ["Attention Is All You Need"](https://arxiv.org/abs/1706.03762) ที่ NIPS 2017 ชื่อเรื่องไม่ใช่การพูดเกินจริง มันเป็นการอ้างสิทธิ์ทางสถาปัตยกรรมที่แม่นยำ ในขณะที่โมเดลก่อนหน้าใช้ recurrent neural networks (RNNs) เป็นแกนหลัก — ประมวลผลคำตามลำดับ ทีละคำ เหมือนอ่านประโยคจากซ้ายไปขวา — Transformer ละทิ้ง recurrence ทั้งหมดและพึ่งพา attention เพียงอย่างเดียว

นวัตกรรมสำคัญคือ:

1. **Self-attention**: แต่ละคำในประโยคให้ความสนใจกับทุกคำอื่นในประโยคเดียวกัน คำนวณความสัมพันธ์แบบขนานแทนที่จะเป็นลำดับ สิ่งนี้จับการพึ่งพาระยะไกลโดยไม่มีคอขวดข้อมูลของ RNNs และ — ที่สำคัญ — มันทำงานแบบขนานบนฮาร์ดแวร์สมัยใหม่ (GPUs และ TPUs) ทำให้การฝึกเร็วขึ้นอย่างมาก

2. **Multi-head attention**: แทนที่จะคำนวณรูปแบบ attention เดียว โมเดลคำนวณรูปแบบ attention หลายรูปแบบพร้อมกัน ("heads") แต่ละรูปแบบอาจจับความสัมพันธ์ทางภาษาศาสตร์ประเภทต่างๆ — ไวยากรณ์ ความหมาย ตำแหน่ง

3. **Positional encoding**: เนื่องจาก self-attention ประมวลผลคำทั้งหมดพร้อมกัน (ต่างจาก RNNs ที่ประมวลผลตามลำดับ) โมเดลจึงไม่มีแนวคิดโดยธรรมชาติเกี่ยวกับลำดับคำ Positional encodings — ฟังก์ชันทางคณิตศาสตร์ที่ฉีดเข้าไปในอินพุต — ให้ข้อมูลนี้

Transformer ไม่เพียงแต่มีประสิทธิภาพเหนือกว่าโมเดลที่ใช้ RNN บน translation benchmarks เท่านั้น มันฝึก **เร็วกว่าหลายเท่า** เนื่องจากความขนานของมัน สิ่งนี้อาจสำคัญพอๆ กับการปรับปรุงคุณภาพ: นักวิจัยสามารถทำซ้ำได้เร็วขึ้น ฝึกบนข้อมูลมากขึ้น และขยายขนาดเป็นโมเดลที่ใหญ่ขึ้น วงจรอันดีงามของการขยายขนาดได้เริ่มต้นขึ้น

ภายในสองปี สถาปัตยกรรม Transformer ได้กลายเป็นพื้นฐานสำหรับงานที่ล้ำสมัยเกือบทั้งหมดใน NLP — ไม่ใช่แค่ MT แต่รวมถึง language modelling, text classification, question answering, summarisation และในที่สุดก็ large language models (GPT, BERT, LLaMA) ที่จะเปลี่ยนโฉมภูมิทัศน์ AI ที่กว้างขึ้น ทุกระบบที่กล่าวถึงในส่วนที่เหลือของบทสรุปนี้สร้างบน Transformer

### จุดเปลี่ยน WMT 2016

**Conference on Machine Translation** (WMT) ซึ่งจัดขึ้นทุกปีในฐานะ workshop ที่จัดร่วมกับการประชุม NLP หลัก ดำเนิน **shared tasks** ที่แข่งขันกัน ซึ่งทีมวิจัยส่งระบบ MT และถูกจัดอันดับเทียบกันบนชุดทดสอบมาตรฐาน WMT เป็นสิ่งที่ใกล้เคียงที่สุดที่สาขา MT มีกับ public leaderboard

ที่ **WMT 2016** ระบบ neural MT มีประสิทธิภาพเหนือกว่าระบบ phrase-based SMT อย่างเด็ดขาดในเกือบทุกคู่ภาษาใน shared task นี่คือช่วงเวลาที่ศูนย์กลางแรงโน้มถ่วงของสาขาเปลี่ยนไป นักวิจัยที่ใช้เวลาทั้งอาชีพสร้างระบบ phrase-based เริ่มปรับตัวสู่กระบวนทัศน์ neural ภายในสองปี สิ่งพิมพ์ใหม่ที่ใช้ phrase-based SMT สำหรับสิ่งอื่นนอกจากการเปรียบเทียบทางประวัติศาสตร์ก็หยุดลงโดยพื้นฐาน Moses เครื่องมือที่กำหนดทศวรรษหนึ่ง ถูกเลิกใช้งานโดยพื้นฐาน

การเปลี่ยนแปลงนั้นรวดเร็วอย่างน่าทึ่งตามมาตรฐานของการเปลี่ยนกระบวนทัศน์ทางวิชาการ — อาจสามถึงสี่ปีจากบทความปี 2014 ของ Bahdanau ไปสู่การครอบงำเกือบสมบูรณ์ของ neural MT ภายในปี 2018 สำหรับนักวิจัยที่เข้าสู่สาขาในวันนี้ phrase-based SMT คือบริบททางประวัติศาสตร์ ไม่ใช่ทิศทางการวิจัยที่ยังมีชีวิต แต่มันเป็นบริบทที่จำเป็น เพราะสมมติฐาน benchmarks และนิสัยการประเมินผลของยุค SMT ยังคงสะท้อนอยู่ในสาขา

## ส่วนที่ 2: การหันสู่ความเป็นพหุภาษา (2018–2022) {#part-2-the-multilingual-turn-20182022}

### โมเดลเดียว หลายภาษา

ระบบ neural MT รุ่นแรกเป็น **bilingual**: หนึ่งโมเดลต่อหนึ่งคู่ภาษา อังกฤษ–ฝรั่งเศสต้องการโมเดลหนึ่ง ฝรั่งเศส–อังกฤษต้องการโมเดลแยกต่างหาก การขยายแนวทางนี้ไปยัง N ภาษาในทางทฤษฎีต้องการโมเดล N×(N−1) — คอขวดด้านวิศวกรรมและข้อมูลที่จำกัด neural MT ให้อยู่กับคู่ที่มีทรัพยากรดีเพียงไม่กี่คู่

คำถามที่กำหนดปี 2018–2022 คือ: *โมเดล neural เดียวสามารถเรียนรู้ที่จะแปลระหว่างหลายภาษาพร้อมกันได้หรือไม่?* คำตอบปรากฏว่าใช่ พร้อมผลที่ลึกซึ้งและซับซ้อน

### การแสดงแทนข้ามภาษา: mBERT และ XLM-R

ก่อนที่โมเดลการแปลพหุภาษาจะมาถึง การค้นพบที่ไม่คาดคิดในโมเดล *ความเข้าใจ* ภาษาได้วางเวที

ในปลายปี 2018 Google เปิดตัว **Multilingual BERT (mBERT)** — โมเดล Transformer เดียวที่ฝึกบนข้อความ Wikipedia จาก 104 ภาษา BERT (Bidirectional Encoder Representations from Transformers) ไม่ใช่โมเดลการแปล มันเป็น language encoder เอนกประสงค์ที่ฝึกเพื่อทำนายคำที่ถูกปิดบังในข้อความ สิ่งที่ทำให้นักวิจัยประหลาดใจคือคุณสมบัติที่เกิดขึ้นเอง: mBERT พัฒนา **cross-lingual representations** โดยไม่เคยได้รับการสอนอย่างชัดเจนว่าภาษาต่างๆ มีความสัมพันธ์กัน หากคุณ fine-tune mBERT บนงาน sentiment classification ภาษาอังกฤษแล้วนำไปใช้กับข้อความภาษาฝรั่งเศส — โดยไม่มีข้อมูลฝึกภาษาฝรั่งเศสเลย — มันทำงานได้ดีอย่างน่าทึ่ง ปรากฏการณ์นี้เรียกว่า **zero-shot cross-lingual transfer** ชี้ให้เห็นว่าโมเดลพหุภาษากำลังเรียนรู้พื้นที่การแสดงแทนที่ใช้ร่วมกันในภาษาต่างๆ

ในปี 2020 **Alexis Conneau** และเพื่อนร่วมงานที่ Facebook AI Research (ปัจจุบันคือ Meta) ผลักดันสิ่งนี้ต่อไปด้วย **XLM-R** (Cross-lingual Language Model – RoBERTa) ที่ฝึกบนข้อมูล CommonCrawl ที่กรองแล้ว 2.5 เทราไบต์ใน 100 ภาษา XLM-R มีประสิทธิภาพเหนือกว่า mBERT อย่างมีนัยสำคัญบน cross-lingual benchmarks มันแสดงให้เห็นว่าด้วยข้อมูลและความจุโมเดลที่เพียงพอ encoder เดียวสามารถสร้างการแสดงแทนพหุภาษาที่แข็งแกร่งได้

โมเดลเหล่านี้ไม่ใช่นักแปลในตัวเอง แต่มันให้รากฐานแนวคิดและเทคนิคสำหรับ multilingual MT หากโมเดลสามารถเรียนรู้การแสดงแทนที่ใช้ร่วมกันใน 100 ภาษา โมเดลการแปลก็ควรจะสามารถแปลระหว่างภาษาเหล่านั้นได้ — อย่างน้อยในหลักการ

### การแปลแบบ Many-to-Many: M2M-100

ระบบ multilingual MT แบบดั้งเดิมมีความลับที่น่าอาย: พวกมันส่งการแปลส่วนใหญ่ **ผ่านภาษาอังกฤษ** การแปลจากโปรตุเกสเป็นญี่ปุ่นหมายถึงการแปลโปรตุเกสเป็นอังกฤษก่อน จากนั้นอังกฤษเป็นญี่ปุ่น แนวทาง "English-centric" นี้เป็นเรื่องปฏิบัติ — ข้อมูลคู่ขนานส่วนใหญ่มีภาษาอังกฤษอยู่ด้านหนึ่ง — แต่มันนำเข้าข้อผิดพลาดที่ทบทวีและกำหนดโครงสร้างภาษาอังกฤษให้กับการแปลทุกครั้ง

ในเดือนตุลาคม 2020 Facebook AI ตีพิมพ์ **M2M-100** (Fan et al., ["Beyond English-Centric Multilingual Machine Translation"](https://arxiv.org/abs/2010.11125), JMLR 2021): โมเดลการแปลแบบ many-to-many ที่ครอบคลุม **100 ภาษาและ 2,200 ทิศทางการแปล** โดยไม่ผ่านภาษาอังกฤษ นี่เป็นความก้าวหน้าเชิงแนวคิด โมเดลสามารถแปลโดยตรงระหว่าง เช่น เบงกาลีและสวาฮีลี โดยใช้ข้อมูลคู่ขนานที่ขุดจากเว็บสำหรับคู่ที่ไม่ใช่ภาษาอังกฤษ

M2M-100 พิสูจน์ว่าการใช้ภาษาอังกฤษเป็นตัวกลางไม่ใช่ข้อจำกัดที่จำเป็นของ multilingual MT แต่มันยังเผยให้เห็นข้อจำกัดของแนวทาง: คุณภาพไม่สม่ำเสมออย่างมากในคู่ภาษาต่างๆ โดยบางทิศทางแทบใช้งานไม่ได้ ช่องว่างระหว่าง "โมเดลนี้ *ครอบคลุม* 2,200 ทิศทาง" และ "โมเดลนี้ *ทำงานได้ดี* ใน 2,200 ทิศทาง" จะกลายเป็นธีมหลัก

### NLLB-200: ไม่ทิ้งภาษาใดไว้เบื้องหลัง

ความพยายาม multilingual MT ที่ทะเยอทะยานที่สุดของ Meta มาถึงในเดือนกรกฎาคม 2022 ด้วย **NLLB-200** (["No Language Left Behind: Scaling Human-Centered Machine Translation"](https://arxiv.org/abs/2207.04672) ตีพิมพ์เป็นบทความวิจัย Meta AI ที่มีผู้เขียนร่วมกว่า 200 คน) เป้าหมายระบุไว้ชัดเจนในชื่อ: สร้างโมเดลเดียวที่รองรับ 200 ภาษา โดยมุ่งเน้นเป็นพิเศษที่ภาษาทรัพยากรต่ำที่ถูกละเลยโดย MT เชิงพาณิชย์ก่อนหน้านี้

การมีส่วนร่วมทางเทคนิคของ NLLB-200 มีความสำคัญ:

- **สถาปัตยกรรม**: Transformer แบบ dense และตัวแปร **Mixture-of-Experts (MoE)** ซึ่งพารามิเตอร์ย่อยต่างๆ ของโมเดลเปิดใช้งานสำหรับคู่ภาษาต่างๆ ตัวแปรที่ใหญ่ที่สุด NLLB-200-MoE-54B มี 54 พันล้านพารามิเตอร์ เวอร์ชัน distilled 600M พารามิเตอร์ทำให้การ deploy เป็นไปได้จริง

- **การขุดข้อมูล**: ทีมพัฒนาเครื่องมืออัตโนมัติเพื่อขุดประโยคคู่ขนานจากการ crawl เว็บ รวมถึงโมเดลระบุภาษา (ครอบคลุม 200+ ภาษา) และตัวกรองประโยคคู่ขนาน pipeline นี้มีความสำคัญอย่างยิ่งสำหรับการรวบรวมข้อมูลฝึกสำหรับภาษาที่มีการปรากฏตัวบนเว็บน้อยที่สุด

- **FLORES-200**: benchmark การประเมินผลมาตรฐานที่ครอบคลุมทั้ง 200 ภาษาด้วยประโยคที่แปลโดยมืออาชีพ FLORES-200 กลายเป็นเครื่องมือสำคัญสำหรับสาขา — ก่อนหน้านี้ไม่มี benchmark สำหรับภาษาส่วนใหญ่เหล่านี้

- **การเปิดเผยแบบเปิด**: ทั้งโมเดลและ FLORES-200 ถูกเปิดเผยอย่างเปิดเผย ทำให้นักวิจัยทั่วโลกสามารถสร้างต่อยอดจากงานนี้ได้

NLLB-200 เป็นหลักไมล์สำคัญ แต่ข้อจำกัดของมันก็สำคัญพอๆ กันที่ต้องเข้าใจ คุณภาพแตกต่างกันอย่างมากในภาษาต่างๆ สำหรับคู่ที่มีทรัพยากรดี (อังกฤษ–ฝรั่งเศส อังกฤษ–จีน) โมเดลมีความสามารถแต่ไม่ใช่ state-of-the-art เมื่อเทียบกับระบบเฉพาะทาง สำหรับภาษาทรัพยากรต่ำ คุณภาพผลลัพธ์มีตั้งแต่ใช้งานได้ไปจนถึงแทบไม่ทำงาน ขึ้นอยู่กับปริมาณข้อมูลฝึกที่ขุดได้ โมเดลยังแสดง **curse of multilinguality**: การเพิ่มภาษาเพิ่มเติมในโมเดลที่มีความจุคงที่จะลดคุณภาพการแสดงแทนสำหรับแต่ละภาษา ภาษาทรัพยากรต่ำได้รับประโยชน์จาก transfer learning (โครงสร้างที่ใช้ร่วมกับภาษาที่เกี่ยวข้องที่มีทรัพยากรสูงกว่า) แต่ภาษาทรัพยากรสูงอาจ *แย่ลงจริงๆ* เมื่อโมเดลพยายามรับใช้นายหลายคนเกินไป นี่ไม่ใช่แค่ปัญหาการขยายขนาด — มันสะท้อนความตึงเครียดพื้นฐานในการออกแบบโมเดลพหุภาษา

### ชุด Seamless

Meta ยังคงผลักดัน multilingual MT ต่อไปด้วยตระกูลโมเดล **Seamless** ในปี 2023–2024 **SeamlessM4T** ("Massively Multilingual and Multimodal Machine Translation" สิงหาคม 2023) เป็นโมเดลเดียวที่จัดการ **speech-to-speech, speech-to-text, text-to-speech และ text-to-text translation** ในประมาณ 100 ภาษา (พร้อมความครอบคลุมที่แตกต่างกันในแต่ละ modality) สิ่งนี้แสดงถึงการบรรจบกันของเส้นทางการวิจัยที่แยกจากกันก่อนหน้านี้ — automatic speech recognition (ASR), text translation และ text-to-speech (TTS) — เป็นระบบพหุภาษาแบบรวม

ชุด **Seamless Communication** ที่ตามมาเพิ่มความสามารถในการสตรีม (การแปลแบบเกือบเรียลไทม์) และการแปลเสียงพูดที่แสดงออก (รักษาลักษณะเสียงเช่นอารมณ์และรูปแบบการพูดข้ามภาษา) ระบบเหล่านี้ยังคงเป็นต้นแบบการวิจัยมากกว่าเครื่องมือที่พร้อมสำหรับการผลิต แต่มันส่งสัญญาณทิศทางของสาขา: multimodal พหุภาษา และเรียลไทม์

### ความหมายของ "Massively Multilingual" ในทางปฏิบัติ

สำหรับนักวิจัยที่เข้าสู่สาขานี้ สิ่งสำคัญคือต้องแยกแยะระหว่าง **ความครอบคลุมภาษา** ของโมเดลและ **คุณภาพภาษา** ของมัน โมเดลที่ "รองรับ 200 ภาษา" อาจให้การแปลที่ยอดเยี่ยมสำหรับ 20 ภาษา ผลลัพธ์ที่ใช้งานได้สำหรับ 50 ภาษา และข้อความที่แทบสุ่มสำหรับส่วนที่เหลือ ตัวเลขหัวข้อนั้นทำให้เข้าใจผิดหากไม่มีการประเมินคุณภาพต่อภาษา

**Curse of multilinguality** เป็นคำศัพท์ทางเทคนิคสำหรับปัญหาการเจือจางความจุ: โมเดลที่มีพารามิเตอร์จำกัดไม่สามารถแสดงแทนทุกภาษาได้อย่างเท่าเทียมกัน การเพิ่มภาษาเพิ่มเติมเป็นประโยชน์ต่อภาษาที่มีทรัพยากรต่ำที่สุด (ผ่าน cross-lingual transfer จากภาษาที่เกี่ยวข้อง) แต่เป็นอันตรายต่อภาษาที่มีทรัพยากรสูงที่สุด (โดยใช้ความจุที่อาจอุทิศให้กับภาษาเหล่านั้น) สิ่งนี้สร้างความตึงเครียดในการออกแบบ: คุณสร้างโมเดลสากลเดียว หรือโมเดลเฉพาะทางหลายตัว? สาขายังไม่ได้แก้ปัญหานี้

## ส่วนที่ 3: ยุค LLM (2022–2026) {#part-3-the-llm-era-20222026}

### เมื่อ AI เอนกประสงค์เรียนรู้ที่จะแปล

การมาถึงของ large language models (LLMs) — GPT-3.5/4, Gemini, Claude, LLaMA — สร้างสถานการณ์แปลกประหลาดในสาขา MT โมเดลเหล่านี้ไม่ได้รับการฝึกโดยเฉพาะสำหรับการแปล พวกมันได้รับการฝึกเพื่อทำนาย token ถัดไปในคลังข้อความขนาดมหาศาล ส่วนใหญ่เป็นภาษาอังกฤษแต่เพิ่มความเป็นพหุภาษามากขึ้น อย่างไรก็ตาม เมื่อได้รับคำสั่งเช่น "แปลประโยคภาษาฝรั่งเศสต่อไปนี้เป็นภาษาอังกฤษ" พวกมันสร้างการแปลที่สำหรับคู่ภาษาทรัพยากรสูง ดีอย่างน่าประหลาดใจ

สิ่งนี้นำเสนอคำถามเกี่ยวกับอัตลักษณ์ของสาขา: หาก AI เอนกประสงค์สามารถแปลได้ดีพอๆ กับระบบการแปลที่สร้างขึ้นเพื่อวัตถุประสงค์นั้น "การแปลด้วยเครื่อง" ยังคงเป็นพื้นที่การวิจัยที่แตกต่างหรือไม่? คำตอบ ณ ปี 2026 คือใช่อย่างมีเงื่อนไข — แต่ความสัมพันธ์ระหว่างการวิจัย MT และการพัฒนา LLM เอนกประสงค์ได้พัวพันกันอย่างลึกซึ้ง

### Benchmarks แรก: LLMs เทียบกับ MT เฉพาะทาง

การประเมินผล LLMs สำหรับการแปลอย่างเป็นระบบเริ่มต้นในต้นปี 2023 ไม่นานหลังจากการเปิดตัว ChatGPT (พฤศจิกายน 2022) และ GPT-4 (มีนาคม 2023)

**Jiao et al. (2023)** ใน ["Is ChatGPT A Good Translator? Yes With GPT-4 As The Engine"](https://arxiv.org/abs/2301.08745) ให้การประเมินในช่วงแรก ผลการค้นพบของพวกเขาสร้างรูปแบบที่คงที่อย่างน่าทึ่ง: LLMs **มีความสามารถสูงสำหรับคู่ภาษายุโรปทรัพยากรสูง** (อังกฤษ–เยอรมัน อังกฤษ–ฝรั่งเศส อังกฤษ–จีน) และ **อ่อนแอกว่าอย่างมีนัยสำคัญสำหรับคู่ทรัพยากรต่ำและที่แตกต่างกันทางประเภทวิทยา** พวกเขายังแนะนำ **pivot prompting** — สั่งให้โมเดลแปลผ่านภาษากลาง — ซึ่งปรับปรุงประสิทธิภาพในคู่ที่ยาก

**Hendy et al. (2023)** ที่ Microsoft ([arXiv:2302.09210](https://arxiv.org/abs/2302.09210)) ดำเนินการประเมินผลที่ครอบคลุมมากขึ้นใน 18 ทิศทางการแปล ข้อสรุปของพวกเขา: โมเดล GPT เทียบเท่า MT เชิงพาณิชย์ที่ล้ำสมัยสำหรับคู่ทรัพยากรสูง แต่มี "ความสามารถจำกัด" ในภาษาทรัพยากรต่ำ

ภายในปี 2024–2025 ภาพชัดเจนขึ้น สำหรับ **คู่ทรัพยากรสูง** LLMs ที่ดีที่สุด (GPT-4o, Gemini 2.5 Pro, Claude 3.5 Sonnet) เทียบเท่าหรือเกินกว่าระบบ MT เฉพาะทาง โดยเฉพาะสำหรับงานที่ต้องการความเข้าใจบริบท การแสดงออกเป็นสำนวน และความสอดคล้องระดับเอกสาร — พื้นที่ที่ neural MT แบบดั้งเดิมซึ่งประมวลผลประโยคแยกกัน มักดิ้นรนมาโดยตลอด สำหรับ **คู่ทรัพยากรต่ำ** โมเดลพหุภาษาเฉพาะทางเช่น NLLB-200 และระบบที่สร้างขึ้นเพื่อวัตถุประสงค์ของ Google Translate ยังคงมีประสิทธิภาพเหนือกว่า LLMs บ่อยครั้งอย่างมีนัยสำคัญ

### BLOOM: ช่วงเวลาพหุภาษาแบบเปิด

ในเดือนกรกฎาคม 2022 ความร่วมมือ **BigScience** — ความพยายามอาสาสมัครหนึ่งปีที่ประสานงานโดย Hugging Face ซึ่งมีนักวิจัยหลายร้อยคนทั่วโลก — เปิดตัว **BLOOM**: large language model พหุภาษาแบบ open-access ที่มี 176 พันล้านพารามิเตอร์ ครอบคลุม **46 ภาษาธรรมชาติและ 13 ภาษาโปรแกรม** ฝึกบน ROOTS corpus โดยใช้ซูเปอร์คอมพิวเตอร์ Jean Zay ในฝรั่งเศส BLOOM เป็น LLM พหุภาษาแบบ open-access ขนาดใหญ่อย่างแท้จริงตัวแรก

BLOOM ไม่ใช่นักแปลเฉพาะทาง แต่ความสำคัญของมันสำหรับ MT นั้นมีนัยสำคัญ มันแสดงให้เห็นว่าโมเดล open-source สามารถรองรับหลายสิบภาษาในระดับขนาดใหญ่ได้ ให้รากฐานสำหรับการวิจัยพหุภาษานอกห้องปฏิบัติการขององค์กร ตัวแปรที่ปรับแต่งด้วยคำสั่ง **BLOOMZ** แสดงความสามารถในการ generalize ข้ามภาษา — ที่ fine-tune บนงานในภาษาหนึ่ง มันสามารถทำงานเหล่านั้นในภาษาอื่นได้

### LLaMA และการระเบิดของ Fine-Tuning

ชุด **LLaMA** (Large Language Model Meta AI) ของ Meta เริ่มต้นในเดือนกุมภาพันธ์ 2023 ใช้เส้นทางที่แตกต่าง LLaMA 1 เน้นภาษาอังกฤษเป็นหลัก โดยมีความสามารถพหุภาษาจำกัด LLaMA 2 (กรกฎาคม 2023) ปรับปรุงเล็กน้อยแต่ยังคงจัดประเภทการใช้งานที่ไม่ใช่ภาษาอังกฤษว่า "นอกขอบเขต" จุดเปลี่ยนมาถึงด้วย **LLaMA 3** (เมษายน 2024) ซึ่งขยายข้อมูลฝึกเจ็ดเท่าและแนะนำ vocabulary 128,000 token — ปรับปรุงการเข้ารหัสข้อความที่ไม่ใช่ภาษาอังกฤษอย่างมาก LLaMA 3 รองรับแปดภาษาอย่างเป็นทางการ (อังกฤษ เยอรมัน ฝรั่งเศส อิตาลี โปรตุเกส ฮินดี สเปน ไทย) พร้อมคุณภาพที่แตกต่างกันสำหรับภาษาอื่นๆ อีกมาก

ความสำคัญของ LLaMA สำหรับ MT อยู่ที่บทบาทของมันในฐานะ **foundation model สำหรับ fine-tuning** น้อยกว่าความสามารถในการแปลโดยตรง ทั้ง Tower และ ALMA ซึ่งเป็น translation LLMs เฉพาะทางที่กล่าวถึงด้านล่าง สร้างบน LLaMA weights แบบเปิดสร้างระบบนิเวศที่เจริญรุ่งเรืองของอนุพันธ์เฉพาะทาง

### Translation LLMs เฉพาะทาง: Tower และ ALMA

การพัฒนาที่สำคัญที่สุดในปี 2023–2024 คือการเกิดขึ้นของ LLMs ที่ fine-tune โดยเฉพาะสำหรับการแปล — ระบบไฮบริดที่สืบทอดความซับซ้อนเชิงบริบทของ LLMs เอนกประสงค์แต่ได้รับการปรับให้เหมาะสมสำหรับคุณภาพการแปล

**ALMA** (Advanced Language Model-based trAnslator) พัฒนาโดย **Haoran Xu** และเพื่อนร่วมงานที่ Johns Hopkins University แสดงให้เห็นข้อมูลเชิงลึกสำคัญ: คุณไม่จำเป็นต้องมีคลังข้อมูลคู่ขนานขนาดใหญ่เพื่อสร้างนักแปลที่ยอดเยี่ยม ALMA ใช้แนวทาง **two-stage fine-tuning** บน LLaMA-2: ขั้นแรก continued pre-training บนข้อมูล monolingual ที่ไม่ใช่ภาษาอังกฤษเพื่อขยายความรู้พหุภาษา จากนั้น fine-tuning บนชุดข้อมูลคู่ขนานขนาดเล็กที่มีคุณภาพสูง ผลงานต่อมา **ALMA-R** (มกราคม 2024) แนะนำ **Contrastive Preference Optimisation (CPO)** — ฝึกโมเดลบนข้อมูลความชอบ (การแปลที่ดีกว่าเทียบกับแย่กว่า) แทนที่จะเป็นแค่ข้อความคู่ขนาน ผลลัพธ์: โมเดล 7B และ 13B พารามิเตอร์ที่เทียบเท่าหรือเกินกว่า GPT-4 บน translation benchmarks บทความนี้ตีพิมพ์ที่ ICLR 2024 ([arXiv:2309.11674](https://arxiv.org/abs/2309.11674)) เวอร์ชันต่อมา **X-ALMA** ขยายความครอบคลุมเป็น 50 ภาษาโดยใช้โมดูล plug-and-play เฉพาะภาษา

**Tower** พัฒนาโดย **Unbabel** (บริษัท AI translation ของโปรตุเกส) ร่วมกับ SARDINE Lab และ MICS Lab มีมุมมองที่กว้างขึ้น แทนที่จะปรับให้เหมาะสมสำหรับการแปลเพียงอย่างเดียว Tower ครอบคลุม **pipeline การแปลทั้งหมด**: การแก้ไขต้นฉบับ การรู้จำชื่อเฉพาะ การ post-editing การจัดอันดับการแปล และการตรวจจับข้อผิดพลาด โมเดล Tower เริ่มต้น (7B และ 13B อิงจาก LLaMA-2) มีประสิทธิภาพเหนือกว่า NLLB-200-54B **Tower v2** (70B นำเสนอที่ WMT 2024) มีประสิทธิภาพเหนือกว่า GPT-4o, Claude 3.5 Sonnet และ DeepL **Tower+** ล่าสุด (2025) ขยายเป็น 22–27 ภาษาและแก้ปัญหา "catastrophic forgetting" — แนวโน้มของโมเดลที่ fine-tune ที่จะสูญเสียความสามารถทั่วไป — ผ่าน preference optimisation และ reinforcement learning

### Prompting เทียบกับ Fine-Tuning: การถกเถียงที่ยังดำเนินอยู่

คำถามที่คงอยู่ในพื้นที่ LLM-MT คือดีกว่าหรือไม่ที่จะ **prompt** LLM เอนกประสงค์สำหรับการแปล (zero-shot หรือ few-shot) หรือ **fine-tune** โมเดลโดยเฉพาะสำหรับการแปล หลักฐานชี้ให้เห็นว่าคำตอบขึ้นอยู่กับงาน:

- **Prompting** รักษาความสามารถทั่วไปของ LLM — การควบคุมความเป็นทางการ การควบคุมสไตล์ ความสอดคล้องระดับเอกสาร — และไม่ต้องการการฝึกเพิ่มเติม เหมาะสำหรับการทำซ้ำอย่างรวดเร็วและการแปลที่สร้างสรรค์หรือเชิงบริบท
- **Fine-tuning** ให้ความแม่นยำสูงกว่าในคู่ภาษาและโดเมนเฉพาะ แต่เสี่ยงต่อการลดความสามารถอื่นๆ ("catastrophic forgetting") ต้องการข้อมูลคู่ขนานและการคำนวณ
- **แนวทางไฮบริด** มีความโดดเด่นมากขึ้นในทางปฏิบัติ: โมเดลที่ fine-tune สำหรับการแปลเริ่มต้น พร้อม LLM-based post-editing หรือ self-refinement passes

### สถานะปัจจุบันของ State of the Art (2025–2026)

คำตอบที่ซื่อสัตย์สำหรับ "ระบบ MT ที่ดีที่สุดคืออะไร?" คือ: **ขึ้นอยู่กับสถานการณ์**

| กรณีการใช้งาน | แนวทางที่ดีที่สุด | เหตุผล |
|---|---|---|
| ทรัพยากรสูง ปริมาณสูง | Commercial NMT (Google, DeepL) | ความเร็ว ต้นทุน ความสม่ำเสมอ |
| ทรัพยากรสูง คุณภาพสูง | LLMs (GPT-4o, Gemini 2.5 Pro) หรือ Tower+ | ความเข้าใจบริบท การจัดการสำนวน |
| ทรัพยากรต่ำ ความครอบคลุมกว้าง | Meta OMT, NLLB-200, Google Translate | ความครอบคลุมพหุภาษาที่สร้างขึ้นเพื่อวัตถุประสงค์นั้น |
| ทรัพยากรต่ำ คู่เฉพาะ | NLLB หรือ LLM ที่ fine-tune บนข้อมูลโดเมน | การปรับปรุงคุณภาพแบบกำหนดเป้าหมาย |
| การวิจัย open-source | Tower+, ALMA-R, X-ALMA | weights แบบเปิด ทำซ้ำได้ มีความสามารถสูง |

ในเดือนมีนาคม 2026 Meta เปิดตัว **OMT (Omnilingual Machine Translation)** — ผู้สืบทอดของ NLLB-200 ขยายความครอบคลุมจาก 200 เป็น **1,600+ ภาษา** OMT แก้ปัญหาที่ Meta เรียกว่า "generation bottleneck": large language models สามารถเข้าใจหลายภาษาได้แต่ดิ้นรนในการสร้างข้อความที่คล่องแคล่วในภาษาเหล่านั้น OMT มีสองสถาปัตยกรรม — OMT-LLaMA (decoder-only, 1B–8B พารามิเตอร์) และ OMT-NLLB (encoder-decoder) — และแนะนำเครื่องมือประเมินผลใหม่รวมถึง BOUQuET และ BLASER 3 (เมตริกการประมาณคุณภาพแบบไม่ต้องอ้างอิง) รายงานเบื้องต้นระบุว่าโมเดล 1B–8B พารามิเตอร์เทียบเท่าหรือเกินกว่า LLM baseline 70B ในงานการแปล ว่า OMT จะรวม Plains Cree หรือภาษา Algonquian อื่นๆ ในที่สุดหรือไม่ยังต้องรอดูกัน

บทความผลการค้นพบ WMT 2024 shared task มีชื่อที่เหมาะสมว่า **"The LLM Era Is Here but MT Is Not Solved Yet"** LLMs ได้ยกเพดานสำหรับการแปลทรัพยากรสูงแต่ยังไม่ได้แก้ปัญหาพื้นฐานของ low-resource MT ความเพียงพอของการประเมินผล หรือความซับซ้อนทางสัณฐานวิทยา

## ส่วนที่ 4: ปัญหาภาษาทรัพยากรต่ำ {#part-4-the-low-resource-problem}

### เหตุใดภาษาส่วนใหญ่จึงถูกทิ้งไว้เบื้องหลัง

จากภาษาที่มีการใช้งานอยู่ประมาณ 7,000 ภาษาทั่วโลก บริการ MT เชิงพาณิชย์ที่เปิดให้บริการครอบคลุมเพียงประมาณ 200 ภาษา และเมื่อรวมระบบแปลภาษาด้วยเครื่อง (machine translation) ทุกรูปแบบเข้าด้วยกัน จะครอบคลุมเพียงประมาณ 550 ภาษาเท่านั้น ([วิธีที่เรานับ](/docs/network/context/coverage-counting)) ภาษาที่เหลือส่วนใหญ่ **ไม่มีระบบแปลภาษาด้วยเครื่องเลย** การจะเข้าใจว่าทำไมถึงเป็นเช่นนั้น จำเป็นต้องเข้าใจว่าระบบ MT ต้องการอะไร และภาษาส่วนใหญ่ขาดอะไรไป

Neural MT ต้องการ **ข้อมูลคู่ขนาน**: คอลเลกชันขนาดใหญ่ของประโยคที่แปลระหว่างสองภาษาโดยมนุษย์ สำหรับอังกฤษ–ฝรั่งเศส ข้อมูลนี้มีอยู่อย่างอุดมสมบูรณ์ — การดำเนินการของรัฐสภายุโรป (Europarl) เอกสาร UN คลังข่าว และ translation memories เชิงพาณิชย์ให้ประโยคคู่ขนานหลายร้อยล้านประโยค สำหรับภาษาเช่น Plains Cree (*nêhiyawêwin*) ซึ่งพูดโดยประมาณ 20,000 คนส่วนใหญ่ในแคนาดาตะวันตก ข้อมูลดังกล่าวแทบไม่มีอยู่ ไม่มีการดำเนินการ UN ใน Plains Cree ไม่มีคลังข่าวสองภาษา ข้อความคู่ขนานทั้งหมดที่มีอยู่อาจวัดได้เป็นพันประโยคแทนที่จะเป็นล้าน

สาขาใช้ระดับทรัพยากรโดยประมาณเพื่อจัดหมวดหมู่ภาษา:

| ระดับ | ข้อมูลคู่ขนานที่มีอยู่ | ตัวอย่าง |
|---|---|---|
| ทรัพยากรสูง | >10 ล้านคู่ประโยค | อังกฤษ ฝรั่งเศส เยอรมัน จีน สเปน |
| ทรัพยากรปานกลาง | 1–10 ล้านคู่ | ตุรกี เวียดนาม สวาฮีลี |
| ทรัพยากรต่ำ | 100K–1 ล้านคู่ | โยรูบา กวารานี มอลตา |
| ทรัพยากรต่ำมาก | <100K คู่ | Plains Cree เกชัว ภาษาพื้นเมืองส่วนใหญ่ |
| แทบเป็นศูนย์ | <10K คู่ | ภาษาหลายพันภาษาทั่วโลก |

### ปัญหา Tokenizer

ก่อนที่โมเดล neural จะประมวลผลข้อความได้ มันต้องแปลงอักขระเป็น token ตัวเลข — กระบวนการที่เรียกว่า **tokenisation** อัลกอริทึม tokenisation ที่โดดเด่นคือ **Byte Pair Encoding (BPE)** ที่ทำให้เป็นที่นิยมโดย Sennrich et al. (2016) และนำไปใช้ในเครื่องมือเช่น **SentencePiece** (Kudo & Richardson, 2018) BPE ทำงานโดยเรียนรู้ลำดับอักขระที่พบบ่อยที่สุดในคลังฝึกและสร้าง vocabulary ของหน่วยย่อยคำ ในภาษาอังกฤษ คำทั่วไปเช่น "the" กลายเป็น token เดียว คำที่หายากถูกแบ่งเป็นชิ้นย่อยคำ ("unforgivable" → "un" + "forgiv" + "able")

ปัญหาคือ vocabulary ของ BPE ได้รับการฝึกเป็นหลักบนภาษาทรัพยากรสูง โดยภาษาอังกฤษมักครอบงำ สำหรับภาษาทรัพยากรต่ำ โดยเฉพาะภาษาที่มีสัณฐานวิทยาซับซ้อนหรือสคริปต์ที่ไม่ใช่ Latin ผลที่ตามมานั้นรุนแรง:

- **การแบ่งส่วนมากเกินไป**: คำเดียวในภาษา polysynthetic เช่น Plains Cree อาจเข้ารหัสทั้งประโยค คำว่า *nikî-nipâw* ("ฉันนอนหลับ") จะถูกแบ่งออกเป็นชิ้นส่วนจำนวนมาก — อาจเป็น byte แต่ละตัว — เพราะอัลกอริทึม BPE ไม่เคยเห็นลำดับอักขระเหล่านี้มาก่อน สิ่งที่เป็นหน่วยความหมายเดียวสำหรับผู้พูดกลายเป็นชิ้นส่วนที่ไม่มีความหมายหลายชิ้นสำหรับโมเดล

- **ปัญหา fertility**: คำเดียวในภาษาที่มีสัณฐานวิทยาซับซ้อนอาจต้องการ 5–15 token ในขณะที่การแปลภาษาอังกฤษใช้ 1–3 สิ่งนี้สร้างความไม่สมมาตรอย่างมากในความยาวลำดับที่ลดคุณภาพการจัดแนว attention และการแปล

- **บทลงโทษสคริปต์**: ภาษาที่ใช้สคริปต์ที่ไม่ใช่ Latin (Cree syllabics, Ethiopic, Devanagari) ถูก tokenise อย่างมีประสิทธิภาพน้อยกว่า บางครั้งถอยกลับไปเป็น byte แต่ละตัว ซึ่งหมายความว่า context window ที่มีประสิทธิภาพของโมเดลนั้นเล็กกว่าอย่างมากสำหรับภาษาเหล่านี้

นี่ไม่ใช่แค่ความไม่สะดวกทางเทคนิค vocabulary ของ tokenizer เข้ารหัสอคติต่อภาษาที่มีทรัพยากรดีในระดับพื้นฐานที่สุดของระบบ โมเดลที่ใช้ 15 token เข้ารหัสคำ Cree เดียวมีความจุเหลือน้อยกว่ามากสำหรับการทำความเข้าใจส่วนที่เหลือของประโยค เมื่อเทียบกับโมเดลที่ประมวลผลภาษาอังกฤษ ซึ่งข้อมูลเดียวกันอาจใช้ 3 token

### ปัญหาคุณภาพข้อมูล

ข้อมูลคู่ขนานที่จำกัดที่มีอยู่สำหรับภาษาทรัพยากรต่ำมักมาจาก **โดเมนที่แคบ** แหล่งที่มาที่ใหญ่ที่สุดสองแหล่งของข้อความคู่ขนานพหุภาษาสำหรับภาษาที่ขาดแคลนทรัพยากรคือ:

1. **การแปลพระคัมภีร์**: พระคัมภีร์ได้รับการแปลเป็นกว่า 700 ภาษา และบางส่วนเป็นกว่า 3,000 ภาษา สิ่งนี้ทำให้ข้อความทางศาสนาเป็นทรัพยากรคู่ขนานที่มีอยู่มากที่สุดสำหรับหลายภาษา — แต่โมเดลที่ฝึกเป็นหลักบนข้อความพระคัมภีร์เรียนรู้ register คำศัพท์ และโดเมนเฉพาะ มันสามารถสร้าง "thou shalt not" แต่ไม่สามารถแปล "please book a flight"

2. **JW300**: ชุดข้อมูลที่ดึงมาจากสิ่งพิมพ์ของพยานพระยะโฮวา ครอบคลุมประมาณ 300 ภาษา แม้จะมีขนาดใหญ่และพหุภาษา JW300 ก็ก่อให้เกิดทั้งปัญหาการเบี่ยงเบนของโดเมน (เนื้อหาทางศาสนา) และข้อกังวลด้านจริยธรรมเกี่ยวกับที่มาและความยินยอมของการแปลพื้นฐาน

**การปนเปื้อนของ benchmark** เป็นอีกข้อกังวลที่ร้ายแรง เมื่อข้อมูลคู่ขนานมีน้อย ข้อความเดียวกันอาจลงเอยทั้งในชุดฝึกและชุดประเมินผล — การรั่วไหลของข้อมูลที่ทำให้เมตริกคุณภาพสูงเกินจริง ยิ่งกลุ่มข้อมูลเล็กลง ยิ่งยากที่จะป้องกันและตรวจจับ

### การเพิ่มข้อมูล: ทำให้มากขึ้นจากน้อย

นักวิจัยได้พัฒนาเทคนิคเพื่อยืดข้อมูลที่จำกัด:

- **Backtranslation** (Sennrich et al., 2016): ฝึกโมเดลเริ่มต้นบนข้อมูลคู่ขนานที่มีอยู่ จากนั้นใช้มันแปลข้อความ **monolingual** ภาษาเป้าหมายกลับเป็นภาษาต้นฉบับ สิ่งนี้สร้างข้อมูลคู่ขนานสังเคราะห์ที่มีเสียงรบกวนแต่สามารถปรับปรุงคุณภาพโมเดลได้อย่างมีนัยสำคัญ Backtranslation ได้กลายเป็นเทคนิคมาตรฐานในทุกระดับทรัพยากร

- **ข้อมูลสังเคราะห์ที่สร้างโดย LLM**: การใช้ large language models เพื่อสร้างข้อมูลฝึกสำหรับคู่ทรัพยากรต่ำ สิ่งนี้มีแนวโน้มที่ดีแต่นำเข้าความเสี่ยง — ข้อความที่สร้างขึ้นอาจแสดง "translationese" (รูปแบบที่ไม่เป็นธรรมชาติหรือได้รับอิทธิพลจากต้นฉบับ) และสามารถขยายอคติที่มีอยู่ใน LLM

- **Cross-lingual transfer**: การฝึกบนข้อมูลคู่ขนานจากภาษาที่เกี่ยวข้องที่มีทรัพยากรสูงกว่า (เช่น การใช้ข้อมูลสเปน–อังกฤษเพื่อ bootstrap Guaraní–อังกฤษ MT) และหวังว่าคุณลักษณะโครงสร้างที่ใช้ร่วมกันจะถ่ายโอน สิ่งนี้ทำงานได้ดีกว่าสำหรับภาษาที่เกี่ยวข้องอย่างใกล้ชิดมากกว่าภาษาที่แตกต่างกันทางประเภทวิทยา

- **Morphological segmentation**: การประมวลผลล่วงหน้าข้อความเพื่อแบ่งคำออกเป็น morphemes (หน่วยความหมายที่เล็กที่สุด) ก่อนป้อนให้โมเดล สำหรับภาษา agglutinative และ polysynthetic สิ่งนี้สามารถปรับปรุงประสิทธิภาพ tokenisation และคุณภาพการแปลได้อย่างมาก แนวทางนี้เชื่อมโยงโดยตรงกับเครื่องมืออิงกฎที่กล่าวถึงในส่วนถัดไป

## ส่วนที่ 5: Finite-State Transducers และระบบอิงกฎ {#part-5-finite-state-transducers-and-rule-based-systems}

### เหตุใดกฎยังคงสำคัญ

เรื่องราวจนถึงตอนนี้เป็นเรื่องของการครอบงำของ neural: ระบบสถิติถูกแทนที่ด้วยเครือข่ายประสาท เครือข่ายประสาทถูกแทนที่ด้วย Transformers Transformers ขยายขนาดเป็น LLMs แต่มีประเพณีคู่ขนานในภาษาศาสตร์เชิงคำนวณที่ไม่เคยหายไป — และสำหรับบางภาษา มันยังคงขาดไม่ได้

**ระบบอิงกฎ** เข้ารหัสความรู้ทางภาษาศาสตร์อย่างชัดเจน: กฎสัณฐานวิทยา พจนานุกรม รูปแบบการถ่ายโอนทางวากยสัมพันธ์ พวกมันไม่ได้เรียนรู้จากข้อมูล พวกมันถูกสร้างโดยนักภาษาศาสตร์ที่เข้าใจภาษาที่เกี่ยวข้อง สำหรับภาษาที่มีทรัพยากรดี แนวทางนี้ถูกแซงหน้าโดยวิธีการที่ขับเคลื่อนด้วยข้อมูลมานานแล้ว แต่สำหรับภาษาที่มีสัณฐานวิทยาซับซ้อนและข้อมูลน้อยที่สุด ระบบอิงกฎมักให้การวิเคราะห์ที่เชื่อถือได้เพียงอย่างเดียวที่มีอยู่

### Finite-State Transducers: บทนำ

**Finite-State Transducer (FST)** เป็นอุปกรณ์เชิงคำนวณที่แมประหว่างสองระดับของการแสดงแทน — โดยทั่วไประหว่างรูปแบบพื้นผิว (สิ่งที่คุณเห็นในข้อความ) และการวิเคราะห์พื้นฐาน (ความหมายทางภาษาศาสตร์) คิดว่ามันเป็นเครื่องที่มีสถานะและการเปลี่ยนผ่าน: มันอ่านสัญลักษณ์อินพุต เคลื่อนที่ระหว่างสถานะ และสร้างสัญลักษณ์เอาต์พุต

สำหรับตัวอย่างที่เป็นรูปธรรม ลองพิจารณาคำ Plains Cree *nikî-nipâw* FST-based morphological analyser สามารถรับรูปแบบพื้นผิวนี้และสร้าง:

> nipâw + Verb + AI + Independent + Past + 1st Person Singular

สิ่งนี้บอกคุณว่าคำนี้คือกริยา *nipâw* ("นอนหลับ") ใน independent order กาลอดีต บุรุษที่หนึ่งเอกพจน์ — "ฉันนอนหลับ" transducer เข้ารหัสกฎของสัณฐานวิทยา Cree: คำนำหน้าใดระบุบุคคล คำใดทำเครื่องหมายกาล รูปแบบกริยาใดรับรูปแบบการผันใด ที่สำคัญ สิ่งนี้ทำงาน **แบบสองทิศทาง**: เมื่อได้รับการวิเคราะห์ FST สามารถสร้างรูปแบบพื้นผิวที่ถูกต้องได้

โครงสร้างพื้นฐานทางเทคนิคสำหรับการสร้าง FSTs ประกอบด้วย:

- **HFST** (Helsinki Finite-State Transducer Technology): toolkit แบบโอเพนซอร์สที่ดูแลรักษาที่มหาวิทยาลัยเฮลซิงกิ ให้กรอบการคำนวณสำหรับการสร้างและเรียกใช้ transducers HFST นำไปใช้รูปแบบที่พัฒนาโดย Xerox (lexc, twolc, xfst) และเข้ากันได้กับ **foma** ซึ่งเป็น FST toolkit แบบโอเพนซอร์สอีกตัวหนึ่ง

- **lexc**: รูปแบบสำหรับระบุ **lexicon** — รายการ morphemes (รากศัพท์ คำนำหน้า คำต่อท้าย) และรูปแบบการสร้างคำที่รวมกัน

- **twolc**: รูปแบบสำหรับระบุ **กฎ morphophonological** — การเปลี่ยนแปลงเสียงที่เกิดขึ้นเมื่อ morphemes รวมกัน (เช่น vowel harmony, consonant mutation)

### GiellaLT: โครงสร้างพื้นฐานอาร์กติก

**GiellaLT** (จากคำ Northern Sámi *giella* ที่แปลว่า "ภาษา") เป็นโครงสร้างพื้นฐานด้านเทคโนโลยีภาษาที่ตั้งอยู่ที่ **UiT — The Arctic University of Norway** ในเมือง Tromsø มันเป็นความพยายามที่ครอบคลุมที่สุดในโลกในการสร้างเครื่องมือ FST-based สำหรับภาษาพื้นเมืองและภาษาชนกลุ่มน้อย

เดิมรู้จักกันในชื่อ **Giellatekno** (งานวิจัย) และ **Divvun** (เครื่องมือทางภาษา) โปรเจกต์นี้ — นำโดยนักภาษาศาสตร์ **Trond Trosterud** และ **Sjur Nørstebø Moshagen** — ได้พัฒนาเครื่องมือวิเคราะห์หน่วยคำ (morphological analysers) ระบบตรวจคำผิด และเครื่องมือทางภาษาอื่นๆ สำหรับภาษาต่างๆ กว่า **100 ภาษา** โดยมุ่งเน้นไปที่กลุ่มภาษา Sámi (Northern Sámi, Lule Sámi, South Sámi และอื่นๆ) กลุ่มภาษา Uralic รวมถึงภาษาในแถบอาร์กติกและภาษาพื้นเมืองอื่นๆ

GiellaLT ใช้ HFST เป็น computational backend และได้พัฒนาโครงสร้างพื้นฐานที่ใช้ร่วมกันที่ซับซ้อน: ระบบ build ทั่วไป กรอบการทดสอบที่ใช้ร่วมกัน และส่วนประกอบทางภาษาศาสตร์ที่นำกลับมาใช้ใหม่ได้ โค้ดทั้งหมดเป็น open-source โฮสต์บน [GitHub](https://github.com/giellalt) พร้อม repositories หลายร้อยรายการรวมถึงโครงสร้างพื้นฐานหลักและ repos เฉพาะภาษา (เช่น `lang-sme` สำหรับ Northern Sámi, `lang-crk` สำหรับ Plains Cree) เอกสารของโครงการอยู่ที่ [giellalt.github.io](https://giellalt.github.io/) พอร์ทัลสาธารณะ **[Borealium.org](https://borealium.org)** — ได้รับการสนับสนุนทางการเงินจาก Nordic Council of Ministers — ให้การเข้าถึงฟรีสำหรับเครื่องมือตรวจสอบ แป้นพิมพ์ พจนานุกรม เครื่องมือเรียนรู้ภาษา (Oahpa) และการสังเคราะห์เสียงพูดสำหรับภาษา Sámi, Kven, Faroese, Greenlandic และอื่นๆ

ความสัมพันธ์ระหว่าง GiellaLT และนโยบายภาษาระดับชาตินั้นน่าสังเกต การสนับสนุนทางการเงินส่วนใหญ่ของโครงการมาจาก **Norwegian Sámi Parliament** และโปรแกรมภาษาของรัฐบาล Nordic สะท้อนถึงความมุ่งมั่นทางการเมืองต่อเทคโนโลยีภาษาพื้นเมืองที่ผิดปกติในด้านขนาดและระยะเวลา

### Apertium: MT อิงกฎแบบ Open-Source

**[Apertium](https://www.apertium.org/)** เป็นแพลตฟอร์ม machine translation อิงกฎแบบ open-source ที่พัฒนาขึ้นเดิมที่ Universitat d'Alacant (สเปน) ด้วยการสนับสนุนทางการเงินจากรัฐบาลสเปนและคาตาลัน มันเริ่มต้นในปี 2004 โดยมุ่งเน้นที่คู่ภาษาที่เกี่ยวข้อง (สเปน–คาตาลัน สเปน–โปรตุเกส) ซึ่งกฎการถ่ายโอนแบบตื้น — แปลทีละคำพร้อมการปรับสัณฐานวิทยา — ให้ผลลัพธ์ที่ดีอย่างน่าประหลาดใจ ผู้มีส่วนร่วมหลักรวมถึง **Francis M. Tyers** ซึ่งมีบทบาทสำคัญทั้งในการพัฒนา Apertium และการนำไปใช้กับภาษาที่ขาดแคลนทรัพยากร

สถาปัตยกรรมของ Apertium เป็น **pipeline** แบบคลาสสิก:

1. **Morphological analysis** (FST-based): ระบุ lemma และคุณลักษณะสัณฐานวิทยาของแต่ละคำ
2. **Part-of-speech disambiguation**: เลือกการวิเคราะห์ที่ถูกต้องเมื่อคำมีความกำกวม
3. **Lexical transfer**: แมป lemma ภาษาต้นฉบับไปยัง lemma ภาษาเป้าหมาย
4. **Structural transfer**: ใช้กฎเพื่อจัดการการเปลี่ยนแปลงลำดับคำ ข้อตกลง และความแตกต่างทางวากยสัมพันธ์อื่นๆ
5. **Morphological generation** (FST-based): สร้างรูปแบบพื้นผิวภาษาเป้าหมายที่ผันอย่างถูกต้อง

ณ ปี 2025 Apertium รองรับคู่ภาษาหลายร้อยคู่ในระดับคุณภาพที่แตกต่างกัน ทั้งหมดโฮสต์บน [GitHub](https://github.com/apertium) มันยังคงได้รับการพัฒนาอย่างแข็งขันโดยชุมชนนานาชาติและมีประโยชน์เป็นพิเศษสำหรับคู่ภาษาที่เกี่ยวข้องอย่างใกล้ชิดซึ่งแนวทางอิงกฎของมันสามารถบรรลุคุณภาพที่สมเหตุสมผลโดยไม่ต้องมีข้อมูลฝึก

### แนวทางไฮบริด: FST + Neural

พรมแดนที่มีแนวโน้มมากที่สุดสำหรับ low-resource MT อาจเป็น **สถาปัตยกรรมไฮบริด** ที่รวม morphological analysis อิงกฎกับการแปล neural แนวคิดนั้นตรงไปตรงมา: ใช้ FST เพื่อแบ่งคำออกเป็น morphemes (แก้ปัญหา tokenization ที่อธิบายในส่วนที่ 4) จากนั้นป้อนข้อความที่แบ่งส่วนแล้วให้กับระบบ neural MT

สำหรับภาษา polysynthetic เช่น Plains Cree ซึ่งหมายความว่าโมเดล neural ได้รับลำดับของหน่วยที่มีความหมายแทนที่จะเป็นชิ้นส่วน byte ตามอำเภอใจ **Alberta Language Technology Lab (ALT Lab)** ที่มหาวิทยาลัย Alberta นำโดย **Antti Arppe** ได้สร้าง FST-based morphological analysers ที่ครอบคลุมและเครื่องมือพจนานุกรมที่เผชิญกับชุมชนสำหรับ Plains Cree โดยใช้โครงสร้างพื้นฐาน GiellaLT งานที่ตีพิมพ์ล่าสุดของพวกเขา (Arppe 2025, AmericasNLP) แสดงให้เห็นการแมป FST-based ระหว่างรูปแบบคำ Cree ที่ผันและวลีภาษาอังกฤษ — โดยพื้นฐานแล้วคือ "การแปลที่จำกัด" ผ่านวิธีการ finite-state ที่ทำงานในระดับคำ/วลีแทนที่จะเป็นประโยคเต็ม ที่น่าสังเกตคือ ALT Lab **ไม่ได้** ตีพิมพ์ระบบ hybrid FST+neural MT พวกเขาทำงานที่มีรากฐานทางภาษาศาสตร์ อิงกฎ และให้ความสำคัญกับความน่าเชื่อถือและประโยชน์ต่อชุมชนมากกว่าแนวทาง neural เชิงทดลอง ในขณะเดียวกัน Nguyen, Hammerly และ Silfverberg (2025, AmericasNLP) แสดงให้เห็น hybrid LLM+FST pipeline สำหรับกริยา Ojibwe ที่ UBC บรรลุผลลัพธ์ที่แข็งแกร่ง (chrF 0.82) — ซึ่งเป็นแอนะล็อกที่ตีพิมพ์ที่ใกล้เคียงที่สุดกับแนวทางไฮบริดสำหรับภาษา Algonquian

กลยุทธ์ไฮบริดนี้แสดงถึงการบรรจบกันของสองประเพณีที่ดำเนินผ่านประวัติศาสตร์ของ MT: ความรู้ที่ชัดเจนของนักภาษาศาสตร์และการเรียนรู้ทางสถิติของวิศวกร สำหรับภาษาที่ต้องการ MT มากที่สุด ไม่มีประเพณีใดเพียงพอเพียงลำพัง

## ส่วนที่ 6: การวัดคุณภาพ — ปัญหาการประเมินผล {#part-6-measuring-quality--the-evaluation-problem}

### คุณรู้ได้อย่างไรว่าการแปลดีหรือไม่?

คำถามนี้ฟังดูง่าย แต่ในความเป็นจริงมันเป็นหนึ่งในปัญหาที่ยังไม่ได้รับการแก้ไขที่ยากที่สุดในสาขา และวิธีที่คุณตอบมันจะกำหนดว่าระบบใดดูเหมือน "ทำงานได้" และระบบใดไม่ทำงาน

### BLEU: มาตรฐานที่ไม่สมบูรณ์

เป็นเวลากว่าสองทศวรรษ เมตริกอัตโนมัติที่โดดเด่นใน MT คือ **BLEU** (Bilingual Evaluation Understudy) แนะนำโดย Papineni et al. ที่ IBM ในปี 2002 BLEU วัดว่าลำดับคำ (n-grams) ของการแปลด้วยเครื่องทับซ้อนกับการแปลอ้างอิงของมนุษย์หนึ่งรายการหรือมากกว่ามากเพียงใด มันรวมถึงบทลงโทษความสั้นเพื่อป้องกันไม่ให้ระบบเล่นกับคะแนนด้วยผลลัพธ์สั้น

BLEU กลายเป็นสกุลเงินของสาขาเพราะมันรวดเร็ว ราคาถูก ไม่ขึ้นกับภาษา และทำซ้ำได้ เกือบทุกบทความ MT ที่ตีพิมพ์ระหว่างปี 2002 ถึง 2020 รายงานคะแนน BLEU WMT shared tasks ใช้มันเป็นเมตริกหลักมาหลายปี

แต่ BLEU มีข้อบกพร่องที่ลึกซึ้งซึ่งชัดเจนมากขึ้นเรื่อยๆ:

- **ไม่มีความเข้าใจความหมาย**: BLEU เป็นการจับคู่พื้นผิวล้วนๆ หากการแปลใช้คำพ้องความหมายที่สมบูรณ์แบบที่ไม่ปรากฏในการอ้างอิง BLEU จะลงโทษมัน ประโยค "the cat sat on the mat" ได้คะแนนศูนย์เทียบกับการอ้างอิง "the feline rested on the rug"
- **การแยกแยะระดับประโยคที่ไม่ดี**: BLEU ถูกออกแบบมาเป็นเมตริกระดับ corpus ในระดับประโยค มันไม่น่าเชื่อถือและมีเสียงรบกวน
- **ความตาบอดทางสัณฐานวิทยา**: สำหรับภาษา agglutinative (ตุรกี ฟินแลนด์ สวาฮีลี) ซึ่ง lemma เดียวสามารถมีรูปแบบที่ผันได้หลายสิบรูปแบบ การจับคู่ระดับคำที่เข้มงวดล้มเหลวอย่างร้ายแรง กริยาที่ผันอย่างถูกต้องซึ่งแตกต่างจากการอ้างอิงด้วยคำต่อท้ายหนึ่งตัวได้คะแนนศูนย์
- **ความสัมพันธ์ที่อ่อนแอกับการตัดสินของมนุษย์**: การวิเคราะห์อภิมาน โดยเฉพาะ Reiter (2018) แสดงให้เห็นว่าความสัมพันธ์ของ BLEU กับการประเมินคุณภาพของมนุษย์มักอ่อนแอ โดยเฉพาะสำหรับระบบคุณภาพสูงและสำหรับภาษาที่ห่างไกลจากภาษาอังกฤษ

### chrF และ chrF++

**chrF** (character F-score) แนะนำโดย Maja Popović ในปี 2015 แก้ปัญหาความตาบอดทางสัณฐานวิทยาของ BLEU โดยวัดการทับซ้อนในระดับ **อักขระ** แทนที่จะเป็นระดับคำ สิ่งนี้ให้เครดิตบางส่วนสำหรับ stems และรากศัพท์ที่ใช้ร่วมกันแม้ว่าการผันจะแตกต่างกัน — สำคัญสำหรับภาษาที่มีสัณฐานวิทยาสมบูรณ์ **chrF++** (Popović, 2017) เพิ่ม n-grams ระดับคำกลับเข้ามา บรรลุความสัมพันธ์ที่ดีกว่ากับการตัดสินของมนุษย์มากกว่าเมตริกเฉพาะอักขระหรือเฉพาะคำ ทั้งสองนำไปใช้ใน **sacreBLEU** ซึ่งเป็น toolkit การประเมินผลมาตรฐาน และได้กลายเป็นเมตริกรองมาตรฐานใน WMT shared tasks

### COMET และ xCOMET: การประเมินผล Neural

ความก้าวหน้าที่สำคัญที่สุดในการประเมินผล MT คือการเปลี่ยนไปสู่ **เมตริก neural** — โมเดลการประเมินผลที่เป็น Transformers ในตัวเอง ฝึกเพื่อทำนายการตัดสินคุณภาพของมนุษย์

**COMET** (Crosslingual Optimized Metric for Evaluation of Translation) พัฒนาโดย Ricardo Rei และเพื่อนร่วมงานที่ **Unbabel** (2020) ใช้ cross-lingual encoder (XLM-RoBERTa) เพื่อ embed ประโยคต้นฉบับ การแปล และการอ้างอิง จากนั้นทำนายคะแนนคุณภาพ ต่างจาก BLEU COMET ทำงานในพื้นที่ความหมาย — มันรู้จักการถอดความ จับการรักษาความหมาย และแสดงความสัมพันธ์ที่สูงกว่ามากกับการตัดสินของมนุษย์อย่างสม่ำเสมอมากกว่าเมตริกระดับพื้นผิว COMET ชนะหรือได้อันดับหนึ่งใน WMT Metrics Shared Tasks ตั้งแต่ปี 2020 เป็นต้นมา

**xCOMET** (Guerreiro et al., 2024 ตีพิมพ์ใน TACL) ก้าวไปไกลกว่านั้น: นอกจากคะแนนคุณภาพแล้ว มันยังสร้าง **การตรวจจับช่วงข้อผิดพลาดแบบละเอียด** — ระบุข้อผิดพลาดเฉพาะในการแปล จัดประเภทตามประเภท (ความแม่นยำ ความคล่องแคล่ว คำศัพท์) และความรุนแรง (เล็กน้อย สำคัญ วิกฤต) สิ่งนี้เชื่อมช่องว่างระหว่างการให้คะแนนอัตโนมัติและการวิเคราะห์ทางภาษาศาสตร์ของมนุษย์

### AfriCOMET: การประเมินผลสำหรับผู้ที่ขาดการบริการ

COMET มาตรฐานที่ฝึกเป็นหลักบนการตัดสินของมนุษย์ในภาษายุโรปอาจไม่ generalize ได้ดีกับภาษาที่แตกต่างกันทางประเภทวิทยา **AfriCOMET** (Wang, Adelani et al., NAACL 2024) แก้ปัญหานี้โดย fine-tuning บนข้อมูลการประเมินผลของมนุษย์จาก **13 ภาษาแอฟริกัน** และใช้ **AfroXLM-R** — encoder พหุภาษาที่ฝึกโดยเฉพาะเพื่อแสดงแทนภาษาแอฟริกันได้ดีขึ้น งานนี้ผลิตโดยชุมชน Masakhane (ดูส่วนที่ 7) แสดงให้เห็นว่าเมตริกการประเมินผลเองต้องได้รับการปรับให้เหมาะสมสำหรับความหลากหลายทางภาษา

### การประเมินผลของมนุษย์: MQM และ Direct Assessment

เมตริกอัตโนมัติเป็นตัวแทน ความจริงพื้นฐานยังคงเป็น **การประเมินผลของมนุษย์** ซึ่งมีสองรูปแบบหลัก:

**Direct Assessment (DA)** ขอให้ผู้ประเมินมนุษย์ให้คะแนนการแปลในระดับ 0–100 มันค่อนข้างรวดเร็วและราคาถูก (สามารถใช้ผู้ประเมินที่ crowd-source ได้) และเป็นวิธีการประเมินผลของมนุษย์หลักที่ WMT ตั้งแต่ปี 2017 ถึง 2020 จุดอ่อนของมัน: เมื่อคุณภาพ MT ดีขึ้น ผู้ประเมินที่ไม่ใช่ผู้เชี่ยวชาญไม่สามารถแยกแยะระหว่างระบบที่ให้ผลลัพธ์ใกล้เคียงระดับมืออาชีพได้อีกต่อไป DA กลายเป็นสิ่งที่ไม่น่าเชื่อถือที่ด้านบนของสเปกตรัมคุณภาพ

**Multidimensional Quality Metrics (MQM)** แทนที่ DA เป็นวิธีการประเมินผลของมนุษย์หลักของ WMT ตั้งแต่ปี 2021 เป็นต้นมา MQM ใช้ **นักแปลมืออาชีพ** ที่ทำเครื่องหมายช่วงข้อผิดพลาดเฉพาะในการแปล จัดประเภทข้อผิดพลาดตามประเภท (การแปลผิด การละเว้น ไวยากรณ์ คำศัพท์) และความรุนแรง (เล็กน้อย = 1 คะแนน สำคัญ = 5 คะแนน วิกฤต = 25 คะแนน) สิ่งนี้สร้างทั้งคะแนนคุณภาพและข้อมูลการวินิจฉัยที่นำไปปฏิบัติได้ — คุณรู้ไม่เพียงแค่ว่าการแปล *แย่แค่ไหน* แต่ *อะไรผิดพลาดโดยเฉพาะ*

| คุณลักษณะ | DA | MQM |
|---|---|---|
| ผู้ประเมิน | Crowd-workers | นักแปลมืออาชีพ |
| วิธีการ | คะแนน 0–100 แบบองค์รวม | การทำเครื่องหมายช่วงข้อผิดพลาด |
| การวินิจฉัย | ไม่มี | การจัดประเภทข้อผิดพลาดโดยละเอียด |
| ต้นทุน | ต่ำกว่า | สูงกว่า |
| ความน่าเชื่อถือ | อ่อนแอกว่าสำหรับ MT คุณภาพสูง | มาตรฐานทองคำ |
| การใช้งานหลักของ WMT | 2017–2020 | 2021–ปัจจุบัน |

### วิกฤตการประเมินผลสำหรับภาษาทรัพยากรต่ำ

สำหรับภาษาทรัพยากรต่ำ ปัญหาการประเมินผลถูกทบทวีด้วยปัจจัยหลายประการ:

- **ไม่มีผู้ประเมินที่มีคุณสมบัติ**: MQM ต้องการนักแปลมืออาชีพที่พูดได้สองภาษา สำหรับ LRLs หลายภาษา การหาผู้ประเมินดังกล่าวนั้นยากมาก
- **ไม่มีการแปลอ้างอิง**: ทั้ง COMET และ BLEU ต้องการการแปลอ้างอิงสำหรับการเปรียบเทียบ สำหรับหลายโดเมนและภาษา สิ่งเหล่านี้ไม่มีอยู่
- **อคติของเมตริก**: ทั้งเมตริกพื้นผิวและเมตริก neural ได้รับการพัฒนาและตรวจสอบบนข้อมูลภาษายุโรป พฤติกรรมของพวกมันในภาษาที่แตกต่างกันทางประเภทวิทยานั้นไม่แน่นอน
- **ความเสี่ยงจาก hallucination**: ในการตั้งค่าทรัพยากรต่ำ โมเดล MT อาจสร้างผลลัพธ์ที่คล่องแคล่วซึ่งไม่เกี่ยวข้องกับต้นฉบับเลย — ปรากฏการณ์ที่เรียกว่า **hallucination** เมตริกพื้นผิวอาจกำหนดคะแนนที่ไม่ใช่ศูนย์ให้กับผลลัพธ์ที่ hallucinate หากมันแชร์ n-grams กับการอ้างอิงโดยบังเอิญ

การสร้าง **ชุดการประเมินผลแบบกำหนดเอง** — แม้แต่ชุดเล็กๆ ที่มี 200–500 คู่ประโยคที่คัดสรรอย่างระมัดระวังในโดเมนเป้าหมาย — เป็นสิ่งจำเป็นสำหรับความพยายาม low-resource MT ที่จริงจังใดๆ การพึ่งพา FLORES-200 หรือคะแนน BLEU เพียงอย่างเดียวโดยไม่มีการประเมินผลเฉพาะโดเมนเป็นสูตรสำหรับความมั่นใจที่ผิดพลาด

## ส่วนที่ 7: ภูมิทัศน์เชิงสถาบัน {#part-7-the-institutional-landscape}

### ผู้เล่นองค์กร

สาขา MT ถูกกำหนดโดยผู้เล่นองค์กรหลักไม่กี่ราย แต่ละรายมีกลยุทธ์ที่แตกต่างกัน:

**Google Translate** ยังคงเป็นระบบ MT ที่มีผู้ใช้งานมากที่สุดในโลก โดย Cloud Translation API ของ Google ระบุว่ารองรับ **194 ภาษา** ([รายการที่ Google เผยแพร่](https://docs.cloud.google.com/translate/docs/languages) — ผลิตภัณฑ์สำหรับผู้บริโภคทั่วไปโฆษณาว่ามีมากกว่านั้น แต่ Google ไม่ได้เผยแพร่รายการอย่างเป็นทางการที่ตายตัวสำหรับผลิตภัณฑ์ดังกล่าว) โครงการ **1000 Languages Initiative** ของ Google (ประกาศเมื่อปี 2022) มีเป้าหมายที่จะสร้างโมเดล AI ที่ครอบคลุมภาษาที่มีผู้พูดมากที่สุด 1,000 ภาษาทั่วโลก Cloud Translation API มีให้บริการสองระดับ: Basic (NMT รุ่นเก่า) และ Advanced (โมเดลล่าสุด) Google ได้ผสานรวมความสามารถของ Gemini LLM เข้ากับ Translate มากขึ้นเรื่อยๆ โดยมีฟีเจอร์การแปลที่รับรู้บริบทและถูกต้องตามหลักภาษาปรากฏขึ้นในปี 2025

**Meta** วางตำแหน่งตัวเองเป็นผู้ขับเคลื่อนหลักของ open-source multilingual MT ผ่าน NLLB-200, M2M-100, FLORES-200 และชุด Seamless ปรัชญาของ Meta ในการเปิดเผยโมเดลแบบเปิดได้เปลี่ยนแปลงการวิจัยทางวิชาการ โดยให้ baselines และเครื่องมือที่มิฉะนั้นจะต้องใช้ทรัพยากรการคำนวณที่ต้องห้าม

**DeepL** ครองช่องทางที่เน้นคุณภาพ รองรับประมาณ **33 ภาษา** — ทั้งหมดค่อนข้างมีทรัพยากรดี — พร้อมชื่อเสียงด้านผลลัพธ์ที่เป็นธรรมชาติและเป็นสำนวนที่นักแปลมืออาชีพชื่นชอบ รูปแบบธุรกิจของ DeepL (freemium สำหรับผู้บริโภค + API แบบชำระเงินสำหรับองค์กร) และพารามิเตอร์ความเป็นทางการ (ควบคุม register ทางการเทียบกับไม่เป็นทางการ) สะท้อนถึงการมุ่งเน้นที่ workflow การแปลมืออาชีพมากกว่าความครอบคลุมภาษาที่กว้าง

**Microsoft Translator** (ส่วนหนึ่งของ Azure AI Services) ให้บริการแปลภาษาครอบคลุม **135 ภาษา** พร้อมการผสานการทำงานระดับองค์กรผ่าน Microsoft 365 และ Teams ฟีเจอร์ Custom Translator ช่วยให้องค์กรต่างๆ สามารถปรับแต่ง (fine-tune) โมเดลด้วยข้อมูลเฉพาะทาง (domain-specific data) ได้

**Unbabel** รวม MT กับ human post-editing ใน workflow "human-in-the-loop" ควบคู่กับการมีส่วนร่วมในการวิจัย (COMET, xCOMET, Tower) มันแสดงถึงการประยุกต์ใช้เชิงพาณิชย์ของกระบวนทัศน์ "MT + human review"

**LibreTranslate** สร้างบน engine **Argos Translate** ให้ทางเลือก MT แบบ open-source ที่ self-hostable ได้อย่างสมบูรณ์โดยไม่มีการพึ่งพาองค์กร — สำคัญสำหรับองค์กรที่มีข้อกำหนดด้านอธิปไตยข้อมูล

### ชุมชนระดับรากหญ้า

งานที่สำคัญที่สุดบางส่วนใน MT — โดยเฉพาะสำหรับภาษาที่ขาดการบริการ — เกิดขึ้นในองค์กรวิจัยที่ขับเคลื่อนโดยชุมชน:

**[Masakhane](https://www.masakhane.io/)** (จากภาษา isiZulu ที่แปลว่า "เราสร้างร่วมกัน") เป็นชุมชนวิจัยระดับรากหญ้าที่มุ่งเน้น NLP สำหรับภาษาแอฟริกัน ก่อตั้งในปี 2019 ด้วยสมาชิกหลายร้อยคนทั่วทวีปและชาวต่างแดน Masakhane ได้ผลิตชุดข้อมูลพื้นฐาน (MasakhaNER, MAFAND-MT, MENYO-20k, AfriQA) เมตริกการประเมินผล (AfriCOMET) และการวิจัยที่ก้าวหน้า NLP ภาษาแอฟริกันอย่างมีนัยสำคัญ บุคคลสำคัญรวมถึง **David Ifeoluwa Adelani** (Mila / UCL) โค้ดและข้อมูลโฮสต์บน [GitHub](https://github.com/masakhane-io) ศูนย์กลางการสื่อสารหลักคือ Slack workspace ของพวกเขา (เข้าร่วมผ่าน masakhane.io) พร้อมการประชุมชุมชนรายสัปดาห์ Masakhane ดำเนินการตามหลักการของความเป็นเจ้าของแอฟริกันของเทคโนโลยีภาษาแอฟริกัน — การต่อต้านโดยเจตนาต่อรูปแบบการวิจัยที่ขูดรีดซึ่งสถาบันภายนอกรวบรวมข้อมูลจากชุมชนภาษาโดยไม่มีความร่วมมือที่มีความหมาย พวกเขาห้ามปรามอย่างชัดเจนต่อ "parachute research" ซึ่งคนนอกดึงข้อมูลทางภาษาโดยไม่มีความร่วมมือกับชุมชนที่มีความหมาย

**AmericasNLP** เป็นชุดการประชุม workshop (จัดร่วมกับ NAACL) ที่มุ่งเน้น NLP สำหรับภาษาพื้นเมืองของทวีปอเมริกา จัดโดยนักวิจัยรวมถึง **Manuel Mager**, **Arturo Oncevay** และ **Luis Chiruzzo** มันดำเนิน shared tasks บน MT สำหรับภาษาเช่น Quechua, Guaraní, Aymara, Nahuatl, Rarámuri และอื่นๆ workshop นี้นำเสนอความท้าทายการวิจัยที่เป็นเอกลักษณ์ของทวีปอเมริกา — สัณฐานวิทยา polysynthetic ระบบเสียงวรรณยุกต์ ความขาดแคลนข้อมูลอย่างรุนแรง และมิติทางการเมืองของเทคโนโลยีภาษาสำหรับผู้คนที่ถูกล่าอาณานิคม

**[ALT Lab](https://altlab.ualberta.ca)** (Alberta Language Technology Lab) ที่มหาวิทยาลัย Alberta นำโดย **Antti Arppe** มุ่งเน้นโดยเฉพาะที่เครื่องมือเชิงคำนวณสำหรับ Plains Cree และภาษาพื้นเมืองอื่นๆ ของแคนาดาตะวันตก ALT Lab สร้าง FST-based morphological analysers และเครื่องมือภาษาที่เผชิญกับชุมชน (โดยใช้โครงสร้างพื้นฐาน GiellaLT) และทำงานในความร่วมมืออย่างใกล้ชิดกับชุมชนที่พูด Cree — เป็นแบบอย่างสำหรับการพัฒนาเทคโนโลยีภาษาที่เน้นชุมชน โครงการสาธารณะของพวกเขา **[21st Century Tools for Indigenous Languages](https://21c.tools)** ให้พจนานุกรมออนไลน์และเครื่องมือสัณฐานวิทยาที่สร้างบนโครงสร้างพื้นฐานนี้

**[NRC Indigenous Languages Technology](https://nrc.canada.ca)** (National Research Council Canada) นำโดย **Patrick Littell** ดูแลโปรแกรมที่ใช้งานอยู่ซึ่งรองรับ 25+ ภาษาพื้นเมืองทั่วแคนาดา รวมถึงภาษา Cree หลายสำเนียง Algonquin, Innu และ Michif NRC ILT ได้ตีพิมพ์การวิจัย MT สำหรับอังกฤษ–Inuktitut (โดยใช้ Nunavut Hansard corpus) และพัฒนาเครื่องมือ open-source รวมถึง **kiyânaw Transcribe** (การถอดเสียง Cree และ Ojibwe) morphological analysers และ **ReadAlong Studio** (การจัดแนวเสียง-ข้อความ) โค้ดทั้งหมดเป็น open-source และ NRC ไม่อ้างสิทธิ์ลิขสิทธิ์ในข้อมูลทางภาษาของชุมชนอย่างชัดเจน

**[Aya](https://cohere.com/research/aya)** (Cohere For AI) เป็นโครงการ open-science multilingual LLM ที่มีผู้มีส่วนร่วม 3,000+ คนจาก 119+ ประเทศ แม้จะไม่ใช่ระบบ MT เฉพาะทาง โมเดล Aya (Aya-101 ครอบคลุม 101 ภาษา, Aya 23 ครอบคลุม 23 ภาษาที่มีผลกระทบสูง, Tiny Aya ครอบคลุม 70 ภาษาที่ 3.35B พารามิเตอร์) มีประสิทธิภาพสูงสำหรับงานการแปล **Aya Collection** — ตัวอย่างการฝึกแบบ instruction-style 513M รายการ — เป็นชุดข้อมูลคำสั่งพหุภาษาแบบเปิดที่ใหญ่ที่สุด รูปแบบการกำกับดูแลชุมชนนั้นคุ้มค่าแก่การศึกษา

**[GhanaNLP / Khaya](https://ghananlp.org)** เป็นโครงการ NLP ที่ขับเคลื่อนโดยชุมชนซึ่งผลิตแพลตฟอร์มการแปล **Khaya** — หนึ่งในระบบ MT ที่กำกับดูแลโดยชุมชนไม่กี่ระบบที่ deploy จริงสำหรับการใช้งานประจำวัน Khaya ให้ neural machine translation, ASR และ TTS สำหรับ ~12 ภาษาของกานา (Twi, Ewe, Ga, Fante, Kusaal และอื่นๆ) ผ่านเว็บ แอปมือถือ และ developer API แนวทางของพวกเขา — คู่ประโยคคู่ขนาน 40,000+ คู่ที่สร้างผ่านความร่วมมือของนักภาษาศาสตร์และข้อเสนอแนะจากชุมชน — แสดงให้เห็นว่า MT ที่กำกับดูแลโดยชุมชนสามารถใช้งานได้จริง ไม่ใช่แค่ความปรารถนา

### การสนับสนุนทางการเงินและนโยบาย

การวิจัย MT สำหรับภาษาทรัพยากรต่ำขึ้นอยู่กับกระแสการสนับสนุนทางการเงินที่แตกต่างอย่างมากจาก venture capital และรายได้จากโฆษณาที่ค้ำจุน MT เชิงพาณิชย์:

- **Lacuna Fund**: กองทุนข้อมูลร่วมมือที่ได้รับการสนับสนุนจาก Rockefeller Foundation, Google.org, IDRC ของแคนาดา และ GIZ ของเยอรมนี Lacuna สนับสนุนการสร้าง **ชุดข้อมูลที่มีป้ายกำกับ** สำหรับภาษาที่ไม่ได้รับการเป็นตัวแทน — เติมช่องว่างข้อมูลที่เป็นสาเหตุหลักของช่องว่างคุณภาพ MT

- **AI4D** (Artificial Intelligence for Development): โปรแกรมที่สนับสนุน AI research fellowships สำหรับเทคโนโลยีภาษาแอฟริกัน ดำเนินการผ่าน IDRC และ Swedish International Development Cooperation Agency

- **UNESCO International Decade of Indigenous Languages (2022–2032)**: กรอบทางการเมืองที่ยกระดับโปรไฟล์ของเทคโนโลยีภาษาพื้นเมืองทั่วโลก แม้ว่าการสนับสนุนทางการเงินสำหรับการวิจัยที่เป็นรูปธรรมจะยังน้อย

- **Inter-American Development Bank**: สนับสนุนทางการเงินโครงการ **GuaranIA** สำหรับ Guaraní–สเปน MT ในปารากวัย ซึ่งเป็นตัวอย่างของการเงินเพื่อการพัฒนาที่สนับสนุนเทคโนโลยีภาษา

- **สภาวิจัยแห่งชาติ**: งาน low-resource MT จำนวนมากได้รับการสนับสนุนทางการเงินผ่านช่องทางวิชาการมาตรฐาน (NSF, NSERC, EU Horizon programmes) มักเป็นส่วนประกอบของทุน AI หรือภาษาศาสตร์ที่กว้างขึ้น

## ส่วนที่ 8: พรมแดนเปิด {#part-8-open-frontiers}

### สิ่งที่ยังไม่ได้รับการแก้ไข

สาขา MT ในปี 2026 มีความสามารถมากขึ้นและซื่อสัตย์มากขึ้นเกี่ยวกับข้อจำกัดของมันมากกว่าจุดใดก่อนหน้านี้ ปัญหาพรมแดนหลายประการกำหนดภูมิทัศน์การวิจัยปัจจุบัน:

**การแปลระดับเอกสาร** ยังคงไม่ได้รับการแก้ไขเป็นส่วนใหญ่ ระบบ MT ส่วนใหญ่ — รวมถึง LLMs หลายตัว — แปลทีละประโยค สูญเสียความสอดคล้องของวาทกรรม การแก้ไขสรรพนามข้ามขอบเขตประโยค และความสม่ำเสมอของสไตล์ นักแปลมนุษย์อ่านเอกสารทั้งหมดก่อนแปล ระบบ MT ส่วนใหญ่ประมวลผลประโยคแยกกัน การวิจัยเกี่ยวกับ document-level MT นั้นแข็งขัน แต่ยังไม่ได้ผลิตระบบที่รักษาความสอดคล้องในข้อความยาวได้อย่างน่าเชื่อถือ

**วาทกรรมและ pragmatics** — ช่องว่างระหว่างความหมายตามตัวอักษรและเจตนาในการสื่อสาร — ยังคงท้าทาย MT การประชดประชัน การพูดน้อยกว่าความจริง การอ้างอิงทางวัฒนธรรม และความไวต่อ register (ทางการเทียบกับไม่เป็นทางการ เคารพเทียบกับสบายๆ) ถูกจับได้บางส่วนโดย LLMs ที่ดีที่สุดแต่ไม่สม่ำเสมอ นักแปลที่ทำงานระหว่างภาษาญี่ปุ่นและอังกฤษต้องนำทางระบบ honorific ที่ซับซ้อน ระบบ MT ปัจจุบันจัดการสิ่งนี้ได้ไม่สม่ำเสมออย่างดีที่สุด

**การแปล multimodal** — การแปลในบริบทกับรูปภาพ วิดีโอ หรือเสียง — เป็นพื้นที่การวิจัยที่กำลังเกิดขึ้น รายการเมนูที่อธิบายว่า "flying fish roe" สมเหตุสมผลอย่างสมบูรณ์แบบพร้อมรูปภาพประกอบ โดยไม่มีมัน MT อาจสร้างสิ่งที่แปลกประหลาด ชุด Seamless และ multimodal LLMs (Gemini, GPT-4o) ได้เริ่มแก้ปัญหานี้ แต่ multimodal MT ที่แข็งแกร่งยังคงเป็นพรมแดน

**การแปลเสียงพูดเป็นเสียงพูดแบบเรียลไทม์** ที่มีความหน่วงตามธรรมชาติ (ความล่าช้าน้อยกว่า 3 วินาที) การรักษาอัตลักษณ์ผู้พูด และการถ่ายโอนน้ำเสียงทางอารมณ์กำลังเข้าใกล้ความพร้อมสำหรับการผลิตสำหรับคู่ทรัพยากรสูง Google, Meta และ startups หลายรายแสดงระบบต้นแบบในปี 2025 สำหรับภาษาทรัพยากรต่ำ การแปลเสียงพูดแบบเรียลไทม์ยังคงห่างไกล

**"ไมล์สุดท้าย" สำหรับภาษาทรัพยากรต่ำ** อาจเป็นปัญหาที่ยังไม่ได้รับการแก้ไขที่สำคัญที่สุดของสาขา ช่องว่างระหว่างคะแนน FLORES-200 benchmark และประโยชน์ที่แท้จริงสำหรับชุมชนภาษานั้นกว้างมาก โมเดลที่ได้คะแนน 15 BLEU บน Plains Cree–อังกฤษไม่มีประโยชน์สำหรับวัตถุประสงค์ใดๆ ในทางปฏิบัติ การปิดช่องว่างนี้ต้องการไม่เพียงแค่โมเดลที่ดีขึ้น แต่ยังต้องการข้อมูลที่ดีขึ้น การประเมินผลที่ดีขึ้น tokenisation ที่ดีขึ้น และ — ที่สำคัญ — ความร่วมมืออย่างแท้จริงกับชุมชนภาษาแทนที่จะเป็นการดึงทรัพยากรทางภาษาสำหรับสิ่งพิมพ์ทางวิชาการ

**Post-editing และความร่วมมือระหว่างมนุษย์กับ AI** กำลังกลายเป็นกระบวนทัศน์ที่โดดเด่นสำหรับการแปลมืออาชีพ แทนที่จะแทนที่นักแปลมนุษย์ MT ถูกวางตำแหน่งมากขึ้นเรื่อยๆ ในฐานะตัวสร้างร่างแรกที่นักแปลมนุษย์ปรับแต่งต่อ การทำความเข้าใจวิทยาศาสตร์การรับรู้ของ post-editing การวัดความพยายาม post-editing และการออกแบบ interfaces ที่สนับสนุนความร่วมมือระหว่างมนุษย์กับ AI เป็นพื้นที่การวิจัยที่แข็งขันพร้อมผลกระทบเชิงพาณิชย์โดยตรง

### มิติทางการเมือง

MT ไม่ใช่สิ่งที่เป็นกลางทางการเมือง การเลือกว่าจะรองรับภาษาใด จะรวบรวมข้อมูลใด ใครควบคุมโมเดล และมาตรฐานคุณภาพของใครที่ใช้ ล้วนเป็นการตัดสินใจที่มีผลสำคัญต่อชุมชนภาษา

การครอบงำของภาษาอังกฤษในฐานะภาษากลางเข้ารหัสมุมมองเฉพาะของการแปลว่าเป็นสิ่งที่ไหลผ่านภาษาอังกฤษ การใช้ข้อความพระคัมภีร์และมิชชันนารีเป็นข้อมูลฝึกสำหรับภาษาพื้นเมืองก่อให้เกิดคำถามเกี่ยวกับความยินยอมและความเหมาะสมทางวัฒนธรรม การกระจุกตัวของความสามารถ MT ในบริษัทไม่กี่แห่งใน Silicon Valley สร้างความสัมพันธ์การพึ่งพาที่บางชุมชนภาษาต่อต้านอย่างชัดเจน

**อธิปไตยของข้อมูล (Data sovereignty)** เป็นข้อกังวลหลัก ในแคนาดา **หลักการอธิปไตยทางข้อมูลของ First Nations** — ความเป็นเจ้าของ การควบคุม การเข้าถึง และการครอบครองข้อมูลโดยชุมชน — ยืนยันว่าชุมชนพื้นเมืองเป็นเจ้าของข้อมูลของตน มีอำนาจควบคุมวิธีการรวบรวมและใช้งานข้อมูล สามารถเข้าถึงข้อมูล และครอบครองข้อมูลนั้นทางกายภาพ สำหรับ MT สิ่งนี้หมายความว่าข้อมูลการฝึกสอน (training data) ที่ได้มาจากข้อความภาษาพื้นเมือง คลังข้อมูลสำหรับการประเมิน (evaluation corpora) ที่สร้างจากความรู้ของชุมชน และโมเดลการแปลที่ฝึกสอนด้วยทรัพยากรที่ชุมชนถือครอง ล้วนอยู่ภายใต้การกำกับดูแลของชุมชน — ไม่ใช่การกำกับดูแลของสถาบันวิจัยหรือบริษัทเทคโนโลยีใดๆ ที่สร้างโมเดลนั้นขึ้นมา

สิ่งนี้มีผลกระทบทางเทคนิคโดยตรง ระบบ MT ที่สร้างขึ้นด้วยข้อมูลของชุมชนไม่สามารถนำมาเปิดเป็นโอเพนซอร์สในความหมายทั่วไปได้ หากชุมชนยังไม่ได้ให้ความยินยอม เกณฑ์มาตรฐานการประเมิน (Evaluation benchmarks) ไม่สามารถเผยแพร่ได้หากข้อมูลทดสอบมีเนื้อหาที่ละเอียดอ่อนทางวัฒนธรรม "โมเดลที่ชุมชนเป็นเจ้าของ" ไม่ใช่ความขัดแย้งในตัวเอง — แต่เป็นข้อกำหนดในการออกแบบ ความพยายามอย่างจริงจังใดๆ ในการทำ MT สำหรับภาษาพื้นเมืองที่มีทรัพยากรน้อย (low-resource MT) จะต้องมุ่งสู่อธิปไตยทางข้อมูลเป็นค่าเริ่มต้น ไม่ใช่สิ่งที่มาคิดได้ในภายหลัง

สิ่งเหล่านี้ไม่ใช่แค่เชิงอรรถด้านจริยธรรม — มันกำหนดลำดับความสำคัญของการวิจัย การตัดสินใจด้านการสนับสนุนทางการเงิน และสถาปัตยกรรมทางเทคนิค "การสร้าง MT ที่ดีขึ้น" ไม่สามารถแยกออกจากคำถามเกี่ยวกับใครได้รับประโยชน์ ใครตัดสินใจ และความรู้ทางภาษาของใครที่ได้รับการให้คุณค่า

## ภาคผนวก ค: เครื่องมือ ชุดข้อมูล และทรัพยากรเชิงปฏิบัติ {#appendix-c-tools-datasets-and-practical-resources}

ภาคผนวกนี้ครอบคลุมเครื่องมือและแหล่งข้อมูลที่เป็นรูปธรรมซึ่งสำคัญในงาน MT ในปัจจุบัน เขียนขึ้นสำหรับผู้ที่รู้จักการใช้งาน terminal แต่อาจไม่รู้จักระบบนิเวศ MT

### Frameworks การฝึก

เหล่านี้คือ software packages ที่ใช้ *ฝึก* โมเดล neural MT ตั้งแต่ต้น (หรือ fine-tune โมเดลที่มีอยู่) คุณจะใช้สิ่งเหล่านี้หากคุณกำลังสร้างโมเดลการแปลของคุณเองแทนที่จะใช้โมเดลที่มีอยู่ผ่าน API

| Framework | ผู้พัฒนา | ภาษา | หมายเหตุ |
|---|---|---|---|
| **[Marian NMT](https://marian-nmt.github.io/)** | Microsoft / U. Edinburgh | C++ | NMT trainer แบบ open-source ที่เร็วที่สุด — สามารถฝึกโมเดลได้เร็วกว่าทางเลือก PyTorch-based 3–5 เท่า เขียนใน C++ ล้วนๆ พร้อม dependencies น้อยที่สุด ขับเคลื่อน Microsoft Translator ทุกโมเดล OpusMT (ดูด้านล่าง) ฝึกด้วยมัน ตั้งชื่อตาม Marian Rejewski นักคณิตศาสตร์ชาวโปแลนด์ที่ช่วยถอดรหัส Enigma |
| **[fairseq](https://github.com/facebookresearch/fairseq)** | Meta AI | Python (PyTorch) | toolkit วิจัยหลักของ Meta — ใช้สร้าง M2M-100, NLLB-200 และงาน MT ที่ตีพิมพ์ส่วนใหญ่ของ Meta มีโมดูลสูง: คุณสามารถสลับสถาปัตยกรรม ฟังก์ชัน loss และการประมวลผลข้อมูล ตัวเลือกมาตรฐานสำหรับนักวิจัยที่ทำซ้ำหรือขยายงานของ Meta |
| **[OpenNMT](https://opennmt.net/)** | Harvard NLP / SYSTRAN | Python (PyTorch, TF) | จุดเริ่มต้นที่เข้าถึงได้มากที่สุดสำหรับการฝึกโมเดล MT แบบกำหนดเอง เริ่มต้นเป็นโครงการวิจัยของ Harvard ปัจจุบันดูแลรักษาโดย SYSTRAN (บริษัท MT เชิงพาณิชย์) รวมถึง CTranslate2 สำหรับการ deploy (ดูด้านล่าง) เอกสารที่ดีสำหรับผู้เริ่มต้น |

**คุณจะใช้สิ่งเหล่านี้เมื่อใด?** หากคุณมีข้อมูลคู่ขนาน (แม้แต่สองสามพันคู่ประโยค) และต้องการฝึกหรือ fine-tune โมเดลการแปลเฉพาะทางสำหรับคู่ภาษาเฉพาะ คุณจะ **ไม่** ใช้สิ่งเหล่านี้สำหรับการแปลที่ใช้ LLM (การ prompt GPT/Claude/Gemini) ซึ่งไม่ต้องการการฝึก — แค่ API calls

### Inference และการ Deploy

เครื่องมือเหล่านี้รัน *โมเดลที่ฝึกแล้ว* เพื่อสร้างการแปล คิดว่า training frameworks ด้านบนเป็น "โรงงานที่สร้างรถ" และเครื่องมือเหล่านี้เป็น "กุญแจจุดระเบิดที่สตาร์ทรถ"

| เครื่องมือ | สิ่งที่ทำ | เมื่อใดที่จะใช้ |
|---|---|---|
| **[CTranslate2](https://github.com/OpenNMT/CTranslate2)** | engine C++ ที่รัน Transformer models ด้วยความเร็วสูงและหน่วยความจำต่ำ รองรับ INT8/INT4 quantisation (ลดขนาดโมเดลเหลือ 1/4 พร้อมการสูญเสียคุณภาพน้อยที่สุด) รันบน CPU หรือ GPU โดยไม่ต้องติดตั้ง PyTorch รองรับ NLLB, M2M-100, OpusMT, LLaMA, Whisper | เมื่อคุณต้องการ self-host โมเดลการแปลบนเซิร์ฟเวอร์หรือแล็ปท็อปโดยไม่มี GPU cluster ตัวเลือกหลักสำหรับการ deploy โมเดล MT แบบ open-source ในการผลิต |
| **[Hugging Face Transformers](https://huggingface.co/models?pipeline_tag=translation)** | Python library ที่โหลดและรันโมเดลด้วยโค้ดไม่กี่บรรทัด: `pipe = pipeline('translation', model='Helsinki-NLP/opus-mt-en-fr'); pipe('Hello world')` ให้โมเดล OpusMT bilingual ที่ pre-train แล้ว ~1,500 โมเดล บวก NLLB-200, mBART, mT5 และ M2M-100 | เมื่อคุณต้องการเส้นทางที่เร็วที่สุดจาก "ฉันต้องการแปลบางอย่าง" ไปสู่โค้ดที่ทำงานได้ Python สองบรรทัดและคุณก็แปลได้ throughput ต่ำกว่า CTranslate2 แต่ตั้งค่าง่ายกว่ามาก |

### ตระกูลโมเดลที่ Pre-Train แล้ว

เหล่านี้คือโมเดลการแปลที่ *ฝึกแล้ว* ที่คุณสามารถดาวน์โหลดและใช้งานได้ทันที ไม่ต้องการการฝึก — แค่โหลดและแปล

| ตระกูลโมเดล | ภาษา | ผู้พัฒนา | สิ่งที่เป็น | ที่ไหนที่จะหา |
|---|---|---|---|---|
| **[OpusMT / Helsinki-NLP](https://huggingface.co/Helsinki-NLP)** | 1,000+ คู่ | University of Helsinki (Jörg Tiedemann) | คอลเลกชันโมเดลการแปล bilingual แบบ open-source ที่ใหญ่ที่สุด แต่ละโมเดลจัดการคู่ภาษาหนึ่งคู่ (เช่น `opus-mt-en-fr` สำหรับ English→French) ฝึกบนข้อมูล OPUS โดยใช้ Marian NMT แปลงเป็นรูปแบบ PyTorch สำหรับ Hugging Face คุณภาพแตกต่างกัน — ยอดเยี่ยมสำหรับคู่ทรัพยากรดี ขอบเขตสำหรับทรัพยากรต่ำ | Hugging Face (`Helsinki-NLP/opus-mt-*`) |
| **NLLB-200** | 200 ภาษา | Meta | โมเดลพหุภาษาเดียวที่แปลระหว่างภาษาใดๆ ใน 200 ภาษา มีในตัวแปร 600M, 1.3B และ 3.3B พารามิเตอร์ เวอร์ชัน 600M รันบนแล็ปท็อป เวอร์ชัน 3.3B ต้องการ GPU ที่ดี คุณภาพแตกต่างกันอย่างมาก — แข็งแกร่งสำหรับทรัพยากรปานกลาง มักไม่ดีสำหรับทรัพยากรต่ำจริงๆ | Hugging Face (`facebook/nllb-200-*`) |
| **M2M-100** | 100 ภาษา | Meta | ผู้บุกเบิก NLLB-200 — โมเดลแรกที่แปลโดยตรงระหว่างคู่ที่ไม่ใช่ภาษาอังกฤษ (เช่น Bengali↔Swahili) โดยไม่ผ่านภาษาอังกฤษ สำคัญทางประวัติศาสตร์ ส่วนใหญ่ถูกแทนที่โดย NLLB-200 | Hugging Face (`facebook/m2m100_*`) |
| **Tower / Tower+** | 22–27 ภาษา | Unbabel | ไม่ใช่แค่นักแปล — จัดการ pipeline การแปลเต็มรูปแบบ (การแก้ไข NER post-editing การประมาณคุณภาพ) ใน LLM เดียว Fine-tune จาก LLaMA ณ ปี 2025 Tower v2 (70B) มีประสิทธิภาพเหนือกว่า GPT-4o และ DeepL บน benchmarks หลายรายการ | Hugging Face |
| **ALMA / X-ALMA** | 50 ภาษา | Johns Hopkins University | โมเดลที่ใช้ LLaMA ที่ fine-tune โดยเฉพาะสำหรับการแปลโดยใช้ preference optimisation (สอนโมเดลว่าการแปลใดที่มนุษย์ชอบ) เวอร์ชัน 7B และ 13B เทียบเท่าคุณภาพ GPT-4 บนคู่ทรัพยากรสูง X-ALMA ขยายเป็น 50 ภาษาด้วยโมดูล adapter เฉพาะภาษา | Hugging Face |

### แหล่งข้อมูลคู่ขนาน

### Sub-Corpora หลักภายใน OPUS

OPUS รวบรวม corpora คู่ขนานอิสระหลายรายการ เมื่อมองหาข้อมูลในภาษาเฉพาะ คอลเลกชันย่อยเหล่านี้คุ้มค่าแก่การตรวจสอบ:

- **OpenSubtitles** — คำบรรยายภาพยนตร์และทีวี ปริมาณมหาศาลแต่มีเสียงรบกวน — คำบรรยายมักถูกทำให้เรียบง่าย ไม่เป็นทางการ และอาจมีข้อผิดพลาดในการถอดเสียง
- **JW300** — สิ่งพิมพ์ของพยานพระยะโฮวา ครอบคลุม ~300 ภาษา ความครอบคลุมภาษาที่กว้างที่สุดของ corpus เดียวใดๆ แต่มีการเบี่ยงเบนโดเมนอย่างหนักไปทางเนื้อหาทางศาสนาและมีการโต้แย้งทางจริยธรรม (ดูส่วนที่ 4)
- **Bible** — การแปลพระคัมภีร์ใน 700+ ภาษา โดเมนที่แคบที่สุดของทั้งหมด (ข้อความทางศาสนาโบราณ) แต่สำหรับหลายภาษา เป็นข้อความคู่ขนานเดียวที่มีอยู่
- **Tanzil** — การแปลอัลกุรอาน มีประโยชน์สำหรับข้อมูลที่จับคู่กับภาษาอาหรับ
- **GNOME / KDE** — สตริง software localisation ("File → Save", "Are you sure you want to delete?") มีประโยชน์สำหรับโดเมนเทคนิค/UI แต่เป็นสูตรมากๆ
- **EMEA** — เอกสาร European Medicines Agency มีประโยชน์สำหรับการแปลโดเมนชีวการแพทย์

## ภาคผนวก ง: อภิธานศัพท์ {#appendix-d-glossary}

**Attention mechanism**: ส่วนประกอบของเครือข่ายประสาทที่ช่วยให้โมเดลสามารถมุ่งเน้นแบบไดนามิกไปยังส่วนต่างๆ ของอินพุตเมื่อสร้างแต่ละส่วนของเอาต์พุต แนะนำโดย Bahdanau et al. (2014) สำหรับ MT ทำให้เป็นแบบทั่วไปใน Transformer (2017)

**Backtranslation**: เทคนิคการเพิ่มข้อมูลซึ่งข้อความ monolingual ภาษาเป้าหมายถูกแปลกลับเป็นภาษาต้นฉบับโดยระบบ MT เบื้องต้น สร้างข้อมูลคู่ขนานสังเคราะห์สำหรับการฝึก

**BLEU**: Bilingual Evaluation Understudy เมตริกการประเมินผล MT อัตโนมัติที่อิงจากการทับซ้อนของ n-gram precision กับการแปลอ้างอิง

**BPE (Byte Pair Encoding)**: อัลกอริทึม subword tokenisation ที่รวมคู่อักขระที่พบบ่อยที่สุดซ้ำๆ เพื่อสร้าง vocabulary ใช้ในระบบ NMT และ LLM สมัยใหม่เกือบทั้งหมด

**COMET**: เมตริกการประเมินผล MT neural ที่ใช้ cross-lingual embeddings เพื่อทำนายการตัดสินคุณภาพของมนุษย์ ทำงานบนต้นฉบับ + hypothesis + การอ้างอิง

**Curse of multilinguality**: ปรากฏการณ์ที่การเพิ่มภาษาเพิ่มเติมในโมเดลพหุภาษาลดคุณภาพต่อภาษาเนื่องจากความจุโมเดลคงที่

**Encoder–decoder**: สถาปัตยกรรม neural ซึ่ง encoder ประมวลผลลำดับอินพุตเป็นการแสดงแทน และ decoder สร้างลำดับเอาต์พุตจากการแสดงแทนเหล่านั้น

**FLORES-200**: benchmark การประเมินผล MT มาตรฐานที่ครอบคลุม 200 ภาษา สร้างโดย Meta ควบคู่กับ NLLB-200

**FST (Finite-State Transducer)**: อุปกรณ์เชิงคำนวณที่แมประหว่างลำดับสัญลักษณ์อินพุตและเอาต์พุตโดยใช้สถานะและการเปลี่ยนผ่าน ใช้ใน computational morphology เพื่อวิเคราะห์และสร้างรูปแบบคำ

**Hallucination**: ใน MT คือการสร้างผลลัพธ์ที่คล่องแคล่วซึ่งไม่เกี่ยวข้องกับหรือไม่ซื่อสัตย์ต่อข้อความต้นฉบับ พบบ่อยเป็นพิเศษในการตั้งค่าทรัพยากรต่ำ

**High-resource language**: ภาษาที่มีข้อความดิจิทัลและข้อมูลการแปลคู่ขนานอุดมสมบูรณ์ (โดยทั่วไป >10M คู่ประโยคกับภาษาอังกฤษ) ตัวอย่าง: ฝรั่งเศส เยอรมัน จีน สเปน

**LLM (Large Language Model)**: โมเดลภาษา neural ที่มีพารามิเตอร์หลายพันล้านตัว ฝึกบนคลังข้อความขนาดมหาศาลเพื่อทำนาย token ถัดไป ตัวอย่าง: GPT-4, Gemini, LLaMA, Claude

**Low-resource language (LRL)**: ภาษาที่มีข้อความดิจิทัลและข้อมูลคู่ขนานจำกัด (<1M คู่ประโยค) ภาษาส่วนใหญ่ของโลกอยู่ในหมวดหมู่นี้

**MQM (Multidimensional Quality Metrics)**: กรอบการประเมินผลของมนุษย์ซึ่งนักแปลมืออาชีพทำเครื่องหมายช่วงข้อผิดพลาดเฉพาะในการแปล จัดประเภทตามประเภทและความรุนแรง

**NMT (Neural Machine Translation)**: MT ที่ใช้เครือข่ายประสาท ต่างจากแนวทางสถิติ (SMT) หรืออิงกฎ (RBMT)

**Parallel data / parallel corpus**: คอลเลกชันของข้อความในสองภาษาที่เป็นการแปลของกันและกัน จัดแนวในระดับประโยค ทรัพยากรการฝึกหลักสำหรับ MT

**Polysynthetic language**: ภาษาที่คำประกอบด้วย morphemes หลายตัว มักเข้ารหัสข้อมูลที่ต้องการประโยคเต็มในภาษา analytic เช่นภาษาอังกฤษ ตัวอย่าง: Plains Cree, Mohawk, Inuktitut

**SentencePiece**: subword tokeniser และ detokeniser ที่ไม่ขึ้นกับภาษาซึ่งนำไปใช้ BPE และ unigram language model segmentation ใช้กันอย่างแพร่หลายใน NLP พหุภาษา

**Transformer**: สถาปัตยกรรม neural ที่โดดเด่นสำหรับ NLP ตั้งแต่ปี 2017 อิงจาก self-attention mechanisms ทั้งหมด แนะนำใน "Attention Is All You Need" (Vaswani et al., 2017)

**Zero-shot cross-lingual transfer**: การนำโมเดลที่ฝึกในภาษาหนึ่ง (โดยทั่วไปคือภาษาอังกฤษ) ไปใช้กับภาษาอื่นโดยไม่มีข้อมูลฝึกภาษาเป้าหมาย โดยอาศัยการแสดงแทนพหุภาษาที่ใช้ร่วมกัน
