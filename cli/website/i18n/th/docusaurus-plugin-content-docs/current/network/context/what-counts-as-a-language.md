# อะไรคือ "ภาษา" ในที่นี้?

> **สรุปสาระสำคัญ.** เครือข่ายนี้จัดหมวดหมู่ภาษาตามมาตรฐาน ISO 639-3 ประเมินผลเป็นรายภาษา (ไม่ใช่กลุ่มภาษาแบบ macrolanguage) รวมภาษามือในฐานะภาษาธรรมชาติ รวมภาษาประดิษฐ์ที่ ISO รับรอง ไม่รวมภาษาโปรแกรมมิ่ง และแสดงข้อโต้แย้งด้านอนุกรมวิธานโดยไม่ตัดสินฝ่ายใด หน้านี้อธิบายเหตุผลของแต่ละข้อและความหมายต่อ leaderboard

โครงการใดก็ตามที่ประเมินการแปลในหลายพันภาษาต้องเผชิญกับคำถามเก่าแก่ที่ตอบยากอย่างน่าประหลาดใจ: อะไรคือ "ภาษา"? นักภาษาศาสตร์รู้มานานแล้วว่าเส้นแบ่งระหว่าง "ภาษา" กับ "ภาษาถิ่น" นั้นเป็นเรื่องสังคมและการเมืองพอๆ กับโครงสร้าง — วลีอมตะที่ว่า *"ภาษาคือภาษาถิ่นที่มีกองทัพและกองทัพเรือ"* ถูกทำให้เป็นที่รู้จักโดยนักภาษาศาสตร์ภาษา Yiddish ชื่อ Max Weinreich ในปี 1945 (เขาให้เครดิตแก่ผู้ฟังคนหนึ่งในการบรรยายของเขา) เราไม่อาจหลีกเลี่ยงคำถามนี้ได้ ต่อไปนี้คือคำตอบและเหตุผลของเรา

## ภาษามือคือภาษา ไม่มีข้อยกเว้น

ภาษามือเป็นภาษาธรรมชาติ — มีไวยากรณ์ครบถ้วน เด็กสามารถเรียนรู้ได้ตามธรรมชาติ และมีชุมชนผู้ใช้ภาษาที่มีชีวิต ข้อนี้ได้รับการยืนยันทางภาษาศาสตร์ตั้งแต่ที่ William Stokoe พิสูจน์ในปี 1960 ว่า American Sign Language มีโครงสร้างภายในแบบเดียวกับภาษาพูด และงานวิจัยกว่าหกสิบปีนับจากนั้น (Klima & Bellugi 1979; Sandler & Lillo-Martin 2006) ยิ่งตอกย้ำประเด็นนี้ให้ชัดเจนขึ้น ISO 639-3 กำหนดรหัสภาษาเฉพาะให้แก่ภาษามือแต่ละภาษา Glottolog จัดหมวดหมู่ร่วมกับตระกูลภาษาพูด รายการในแคตาล็อกของเรามีภาษามือมากกว่า 160 ภาษา โดยติดแท็ก `modality: signed`

บางภาษาเป็นภาษาพื้นเมืองที่ใกล้สูญพันธุ์: Plains Indian Sign Language (`psd`) ซึ่งในอดีตเคยเป็น lingua franca สำคัญระหว่างชนเผ่าทั่วทวีปอเมริกาเหนือ ปัจจุบันอยู่ในภาวะใกล้สูญพันธุ์อย่างวิกฤต (Davis 2010, *Hand Talk*) การสูญพันธุ์ของภาษามือ *คือ* การสูญพันธุ์ของภาษาพื้นเมือง และอยู่ในพันธกิจของโครงการนี้

**หมายเหตุขอบเขตที่ตรงไปตรงมา.** ปัจจุบัน Network ประเมินการแปลด้วยเครื่องแบบ *ข้อความ* เป็นหลัก การแปลด้วยเครื่องสำหรับภาษามือ — ซึ่งต้องทำงานกับวิดีโอ ไวยากรณ์เชิงพื้นที่ และภาษาที่ยังไม่มีรูปแบบการเขียนที่ใช้กันอย่างแพร่หลาย — เป็นปัญหาทางเทคนิคที่แตกต่างออกไปและยังไม่มีทางแก้ที่ครอบคลุม (ดู Yin et al. 2021, "Including Signed Languages in Natural Language Processing," ACL) เราไม่ได้ให้บริการส่วนนี้ในขณะนี้ รายการภาษามือในแคตาล็อกของเราระบุไว้ชัดเจนว่า: **ยังไม่รองรับ — ไม่ใช่ "ไม่ใช่ภาษา"**

## มีสองรูปแบบ และการเขียนไม่ใช่หนึ่งในนั้น

ภาษามีรูปแบบหลักสองประเภท: **ภาษาพูด** และ **ภาษามือ** การเขียนไม่ใช่รูปแบบที่สาม — มันคือเทคโนโลยีที่ถูกสร้างขึ้นบนภาษา และภาษาส่วนใหญ่ในโลกดำรงอยู่ได้โดยไม่มีระบบการเขียนมาตรฐาน นั่นคือเหตุผลที่การ์ดภาษาของเราติดตามข้อมูลการเขียนแยกต่างหาก (ระบบอักษรที่ภาษานั้นใช้ หรือว่าไม่มีระบบการเขียนมาตรฐานเลย) และติดตามอย่างตรงไปตรงมา: สำหรับแพลตฟอร์ม MT แบบข้อความ การที่ภาษาหนึ่งมีระบบการเขียนหรือไม่นั้นเป็นข้อมูลสำคัญ ไม่ใช่เชิงอรรถ — และภาษาที่ไม่มีระบบการเขียนก็ไม่ใช่ภาษาที่ด้อยกว่า

## ภาษาประดิษฐ์: รวม ภาษาโปรแกรมมิ่ง: ไม่รวม

เราปฏิบัติตามแนวทางของ ISO 639-3 มาตรฐานนี้รับรองภาษาประดิษฐ์เฉพาะเมื่อเป็นภาษาที่สมบูรณ์ ออกแบบมาเพื่อการสื่อสารของมนุษย์ มีวรรณกรรม และมีชุมชนที่ส่งต่อภาษาไปยังผู้ใช้รุ่นที่สอง — และมาตรฐานนี้ยกเว้นภาษาโปรแกรมคอมพิวเตอร์อย่างชัดเจน Esperanto ซึ่งมีเจ้าของภาษาโดยกำเนิด ผ่านเกณฑ์นี้ Python ไม่ผ่าน เพราะไม่มีใครเรียนรู้ Python เป็นภาษาแรกจากพ่อแม่ แคตาล็อกของเรารวมภาษาประดิษฐ์ประมาณสองโหลที่ ISO รับรอง โดยระบุประเภทไว้ชัดเจน และไม่มีภาษาโปรแกรมมิ่ง

## เราประเมินรายภาษา ไม่ใช่กลุ่มภาษา

ISO 639-3 แยกแยะระหว่าง *ภาษาเดี่ยว* กับ *macrolanguage* — รหัสกลุ่มอย่าง `cre` (Cree), `ara` (Arabic) หรือ `zho` (Chinese) ที่ครอบคลุมภาษาเดี่ยวที่มีความใกล้ชิดกันหลายภาษา หน่วยการประเมินของ Network คือ **ภาษาเดี่ยว** ด้วยเหตุผลเชิงปฏิบัติ: ทรัพยากรการแปลมีความเฉพาะเจาะจงต่อสำเนียง ตัววิเคราะห์สัณฐานวิทยาที่สร้างสำหรับ Plains Cree (`crk`) ไม่สามารถสร้างผลลัพธ์สำหรับ Moose Cree (`crm`) ได้ คลังข้อมูล Egyptian Arabic ไม่ได้บอกอะไรมากนักเกี่ยวกับคุณภาพของวิธีการในภาษา Moroccan Arabic คะแนนที่ผูกกับรหัส macrolanguage จะเป็นการอ้างสิทธิ์เกี่ยวกับสำเนียงที่ไม่เคยได้รับการประเมินจริง — เราจึงไม่ทำเช่นนั้น

Macrolanguage ยังคงปรากฏในแคตาล็อกในรูปแบบ **หน้า hub**: การนำทางที่เชื่อมโยงอัตลักษณ์กลุ่มกับสมาชิกภาษาเดี่ยว สะท้อนการสังเกตของ ISO เองว่าอัตลักษณ์ทั้งสองระดับมีความเป็นจริง ในระดับต่ำกว่าภาษาเดี่ยว เราแสดงข้อมูลภาษาถิ่นและสายตระกูลจากต้นไม้ languoid ของ Glottolog (Hammarström & Forkel 2022) ซึ่งจำลองตระกูล ภาษา และภาษาถิ่นเป็นลำดับชั้นที่นำทางได้

**แล้วคลังข้อมูล (corpora) ที่ระบุมาด้วยรหัสแบบครอบคลุม (umbrella code) ล่ะ?** ข้อมูลในโลกแห่งความเป็นจริงจำนวนมากมักเป็นเช่นนั้น เช่น ชุดข้อมูลที่เผยแพร่โดยระบุว่าเป็น "Quechua", "Persian" หรือ "Chinese (Simplified)" เราถือว่าป้ายกำกับจากต้นทางเป็น *ข้อมูลเมทาดาตาที่ต้องนำมาแจกแจงความหมาย* ไม่ใช่ข้อเท็จจริงสัมบูรณ์ที่ต้องปฏิบัติตามหรือตัดทิ้ง ในกรณีเชิงกลไกจะสามารถแจกแจงได้โดยอัตโนมัติตามตาราง ISO ทางการ เช่น แท็กระบบการเขียน (script tag) จะถูกตัดออก (`cmn-Hans` คือภาษาจีนกลางที่เขียนด้วยอักษรจีนตัวย่อ — ระบบการเขียนจะถูกบันทึกไว้ ส่วนอัตลักษณ์ทางภาษาคือ `cmn`) และรหัสที่เลิกใช้แล้วจะเป็นไปตามรหัสทางการที่มาแทนที่ เมื่อผู้เผยแพร่ระบุไว้เป็นลายลักษณ์อักษรว่าข้อมูลของตนเป็นภาษาย่อยใดแน่ชัด — เช่น FLORES+ กำกับระเบียน Quechua ของตนเป็น `quy` ซึ่งคือ Ayacucho Quechua — เราจะบันทึกการแจกแจงนั้น *พร้อมการอ้างอิง* ลงในรายการทะเบียนของคลังข้อมูลนั้น และคลังข้อมูลดังกล่าวจะได้รับการประเมินเทียบมาตรฐาน (benchmark) ภายใต้ภาษาเดี่ยวที่แท้จริง และเมื่อไม่มีใครระบุได้ว่าชุดข้อมูลนั้นประกอบด้วยภาษาย่อยใด (ชุดประโยคจากชุมชนบางชุดจงใจเก็บไว้ในหมวด "Arabic" แบบกว้าง ๆ) เราจะไม่คาดเดาเอง: คลังข้อมูลจะยังคงถูกจัดหมวดหมู่ภายใต้ป้ายกำกับเดิมของตนเอง และถูกคัดออกจากคิวงานโดยมีเหตุผลที่เครื่องอ่านได้ระบุไว้ในเมทาดาตาของคิว และคะแนนในอดีตใด ๆ ของคลังข้อมูลนั้นจะยังคงผูกไว้กับโหนดแบบครอบคลุมที่ติดป้ายกำกับตามจริง — โดยจะไม่ถูกนำไปยกประโยชน์ให้ภาษาย่อยที่ไม่เคยผ่านการประเมินจริงอย่างเงียบ ๆ เด็ดขาด การแจกแจงทุกรายการสามารถสืบหาที่มาซ้ำได้เสมอ: ทั้งตาราง ISO ที่ตรึงไว้ ประทับการแจกแจงของแต่ละคลังข้อมูล และรายการอ้างอิงทั้งหมดล้วนจัดส่งไว้ในทะเบียนสาธารณะ

## เมื่อผู้มีอำนาจไม่เห็นด้วยกัน เราแสดงทั้งสองฝ่าย

ในบางครั้ง ISO 639-3 และ Glottolog อาจแบ่งแยกหรือรวมกลุ่มภาษาแตกต่างกัน และบางครั้งชุมชนก็อาจไม่เห็นด้วยกับทั้งสองมาตรฐาน เราจะไม่ทำหน้าที่ตัดสิน ชี้ขาด การ์ดภาษาจะมีส่วน *taxonomy notes* ที่แสดงข้อแตกต่างดังกล่าวพร้อมแหล่งที่มา และการตั้งชื่อจะเป็นไปตามที่ชุมชนกำหนดเมื่อใดก็ตามที่ชุมชนแสดงความประสงค์ไว้ ท้ายที่สุดแล้ว การที่ภาษาย่อยใดจะเป็น "ภาษาหนึ่งภาษา" หรือไม่ ส่วนหนึ่งเป็นเรื่องของอัตลักษณ์ — และคำถามเกี่ยวกับอัตลักษณ์นั้นถือเป็นสิทธิ์ของชุมชนเอง ซึ่งเป็นหลักการที่เรานำมาจากกรอบการกำกับดูแลข้อมูลของชนพื้นเมือง (Indigenous data-governance frameworks)

## ทิศทางการวิจัย: การประเมินในฐานะเครื่องมือวัด

สิ่งหนึ่งที่พื้นที่ประลองเช่นนี้สร้างขึ้นมา ซึ่งแทบจะเป็นผลพลอยได้ คือหลักฐานรูปแบบใหม่ว่าภาษาย่อยต่าง ๆ มีความใกล้เคียงกันจริงเพียงใด *ในทางปฏิบัติการ* หากวิธีการแปลวิธีหนึ่งที่คงค่าไว้ สามารถรองรับภาษาย่อยที่เกี่ยวข้องกันหลายภาษาได้ดีพอจนกระทั่งผู้ใช้ภาษานั้นยอมรับผลลัพธ์ได้ ภาษาย่อยเหล่านั้นก็ถือว่าเกาะกลุ่มกันในทางปฏิบัติ หากพวกมันจำเป็นต้องใช้คลังข้อมูลแยกต่างหากและวิธีการแปลที่แยกจากกัน ภาษาย่อยเหล่านั้นก็ถือว่ามีความแตกต่างกันในทางปฏิบัติการ — ไม่ว่าการเมืองเรื่องการตั้งชื่อจะระบุไว้อย่างไรก็ตาม สิ่งนี้คล้ายคลึงกับธรรมเนียมปฏิบัติด้านการสังเกตเชิงประจักษ์ในอดีต ตั้งแต่การทดสอบความเข้าใจร่วมกันจากข้อความที่บันทึกไว้ ไปจนถึงการวัดระยะห่างทางคลังศัพท์แบบอัตโนมัติ แต่มาพร้อมกับมุมมองใหม่ที่อิงตามการนำไปใช้งานจริง

เรานำเสนอสิ่งนี้อย่างระมัดระวัง ในฐานะทิศทางการวิจัยมากกว่าการอ้างสิทธิ์ ผลลัพธ์การถ่ายโอนวิธีการมีตัวแปรกวนจากขนาดคลังข้อมูล โดเมน ระบบการเขียน และการปนเปื้อนของข้อมูลฝึก และการจัดกลุ่มใดๆ ก็ตามมีความสัมพันธ์กับวิธีการและเกณฑ์คุณภาพเสมอ เหนือสิ่งอื่นใด: สัญญาณนี้สามารถ *ให้ข้อมูลประกอบ* การสนทนาเรื่องภาษาและภาษาถิ่นได้ แต่ไม่มีวันแทนที่วิธีที่ชุมชนระบุภาษาของตนเอง
