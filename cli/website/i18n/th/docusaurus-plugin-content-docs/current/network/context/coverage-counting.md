# จำนวนความครอบคลุม: วิธีที่เราใช้นับ

> **บทสรุปผู้บริหาร** เมื่อเว็บไซต์ระบุว่า **552 ภาษาที่มีผู้ใช้งานอยู่ (living languages) มีการแปลด้วยเครื่อง (machine translation) ในรูปแบบใดรูปแบบหนึ่ง** และ **196 ภาษาให้บริการโดยบริการที่เปิดใช้งานจริง (deployed service)** ตัวเลขทั้งสองนี้คือการนับที่แตกต่างกันและแยกออกจากกันอย่างจงใจ หน้านี้จะให้คำจำกัดความของทั้งสองระดับ (tiers) ระบุแหล่งข้อมูลหลักแหล่งเดียว (single source of truth) ที่ใช้อ่านตัวเลขแต่ละตัวในขณะที่บิลด์ (build time) และอธิบายวิธีการอัปเดตรายการเหล่านี้ ความครอบคลุมคือ *การกล่าวอ้างถึงการมีอยู่* ไม่ใช่การกล่าวอ้างถึงคุณภาพ

## สองระดับ

**ระดับ 1 — เอนจิน MT เฉพาะทางใดๆ ("ครอบคลุม").** ภาษาที่มีผู้ใช้งานอยู่จะนับว่าครอบคลุม หากปรากฏอยู่ในรายการภาษาที่รองรับซึ่งเผยแพร่โดยเอนจิน MT เฉพาะทาง *ใดๆ* ที่เราติดตาม — ไม่ว่าจะเป็นบริการสำหรับผู้บริโภค/API ที่เปิดใช้งานจริง (Google Translate, Microsoft Translator, DeepL, LibreTranslate, …) **หรือ** โมเดลการวิจัยแบบเปิด (NLLB-200, OPUS-MT, M2M-100, MADLAD-400, …) นี่คือการรวมกลุ่ม (union) ที่ทำให้จุดบนแผนที่เครือข่ายสว่างเป็นสีเขียว

**ระดับ 2 — บริการที่เปิดใช้งานจริง ("ให้บริการ").** เกณฑ์ที่เข้มงวดขึ้น: ภาษาต้องอยู่ในรายการของเอนจินที่ทุกคนสามารถ *ใช้งานได้จริงในปัจจุบัน* ในฐานะผู้บริโภคหรือบริการ API จุดตรวจสอบ (checkpoint) ของการวิจัยแบบเปิดที่คุณต้องดาวน์โหลด โฮสต์ และให้บริการด้วยตนเองจะไม่นับรวมในที่นี้ นี่คือตัวเลขที่ตอบคำถามว่า "ผู้พูดภาษานี้สามารถแปลหน้าเว็บได้ทันทีโดยไม่ต้องทำงานด้านวิศวกรรมหรือไม่?"

ทั้งสองระดับมีอยู่เพื่อตอบคำถามที่แตกต่างกัน และการรวมเข้าด้วยกันจะทำให้ความครอบคลุมของโลกดูเกินจริง ทั้งสองระดับจะนับเฉพาะ **ภาษาเดี่ยวที่มีผู้ใช้งานอยู่ตามมาตรฐาน ISO 639-3** เท่านั้น (`isoType: 'L'`)

## ตัวเลขมาจากไหน (ไม่มีการพิมพ์ด้วยมือ)

จำนวนที่แสดงทุกรายการคือ **การอ่านข้อมูลขณะบิลด์ (build-time read)** จาก SSOT ของระบบ — ไม่มีตัวเลขใดบนเว็บไซต์ที่ถูกพิมพ์ลงในข้อความและปล่อยทิ้งไว้จนล้าสมัย:

1. **รายการของแต่ละเอนจิน** อยู่ใน `cli/shared/catalogue/method-coverage.json` — หนึ่งรายการต่อหนึ่งเอนจิน นำเข้าแบบ *อ้างอิงเท่านั้น (cite-only)* จากรายการภาษาที่รองรับซึ่งผู้ให้บริการเผยแพร่เอง พร้อมด้วย `source_url` และวันที่ `asOf` Champollion ไม่ได้ตรวจสอบหรือทำซ้ำรายการเหล่านี้ เนื่องจากเป็นการกล่าวอ้างของผู้ให้บริการเอง
2. **กระบวนการบิลด์จะหาจุดตัด (intersect)** ระหว่างรายการเหล่านั้นกับดัชนีภาษาที่มีผู้ใช้งานอยู่ และส่งออกจำนวนของแต่ละระดับไปยังสถิติการบิลด์ของเว็บไซต์ (`stats.coverage.dedicatedLiving` สำหรับระดับ 1, `stats.coverage.serviceLiving` สำหรับระดับ 2, จาก `stats.livingTotal` ภาษาที่มีผู้ใช้งานอยู่)
3. **หน้าเว็บจะเรนเดอร์สถิติ** และระบบตรวจสอบความสอดคล้องก่อนพุช (pre-push parity gate) จะทำให้การบิลด์ล้มเหลวหากข้อความและสถิติไม่ตรงกัน

## "194 ภาษา" และ "187 ภาษา" สามารถเป็นจริงได้ทั้งคู่

รายการของผู้ให้บริการและจำนวนของ *ภาษา* ไม่ใช่สิ่งเดียวกัน ดังนั้นแต่ละรายการใน SSOT จะประกาศว่าตัวเลขของตนคืออะไร:

- **`publisher-list-rows`** — ความยาวของรายการที่ผู้ให้บริการเผยแพร่เอง ตรงตามที่พวกเขาเผยแพร่ทุกประการ หน้า Cloud Translation ของ Google แสดงรายการ **194** แถวสำหรับโมเดล NMT ของตน นั่นคือตัวเลขที่เว็บไซต์นี้อ้างอิงถึง Google ตามชื่อ
- **`champollion-derived-enumeration`** — การยุบรวมรายการนั้นของ *เรา* ให้เป็นภาษาพื้นฐานตามมาตรฐาน ISO 639-3 ที่แตกต่างกัน 194 แถวของ Google เหล่านั้นคือ **187** ภาษา เนื่องจาก `zh-CN` และ `zh-TW` คือภาษาเดียวกันในสองระบบตัวเขียน เช่นเดียวกับ `pt-PT` และ `pt-BR` และอื่นๆ ตัวเลขนี้เป็นของเรา ไม่ใช่ของผู้ให้บริการ
- **`publisher-stated-headline`** — ยอดรวมที่ผู้ให้บริการยืนยันโดยไม่มีการเผยแพร่รายการสนับสนุนเบื้องหลัง จะไม่มีการดึงข้อมูลใดๆ มาจากตัวเลขนี้

ช่องว่างระหว่างสองตัวแรกเป็นเรื่องของคณิตศาสตร์ ไม่ใช่ความขัดแย้ง และเกิดขึ้นกับผู้ให้บริการทุกราย: Microsoft 135 แถว → 128 ภาษา, LibreTranslate 49 → 47, ตัวแปร FLORES 200 รายการของ NLLB-200 → 196 แผนที่และจำนวนของแต่ละระดับจะอ่านจาก *รายการที่แจกแจง (enumerated list)* เสมอ ไม่ใช่อ่านจากหัวข้อ ระบบตรวจสอบก่อนพุชจะทำให้การบิลด์ล้มเหลวหากเกณฑ์ที่ประกาศไว้ของรายการและรายการนั้นขัดแย้งกัน

โปรดทราบด้วยว่าผู้ให้บริการอาจเผยแพร่หลายรายการ หน้าของ Google มีตารางแยกต่างหากสำหรับระดับ Translation LLM (127 แถว ณ วันที่ 2026-08-16) และไม่ได้ระบุยอดรวมทั้งหมดเลย — ดังนั้นคำถามที่ว่า "Google รองรับกี่ภาษา?" จึงไม่มีคำตอบเดียวที่เผยแพร่ออกมา และเว็บไซต์นี้ก็ไม่ได้สร้างคำตอบขึ้นมาเอง

## ความครอบคลุมที่กล่าวอ้างไม่ใช่คุณภาพ — และไม่สามารถนำไปใช้งานจริงได้เสมอไป

ภาษาที่อยู่ในรายการของผู้ให้บริการหมายความว่าผู้ให้บริการ *กล่าวอ้างว่ารองรับ* เท่านั้น ไม่มีอะไรมากไปกว่านั้น ข้อควรระวังเพื่อความโปร่งใสสองประการที่เว็บไซต์นี้นำไปใช้ในทุกที่ที่จำนวนเหล่านี้ปรากฏ:

- **ความครอบคลุม ≠ คุณภาพ** การแปลนั้นดีหรือไม่เป็นอีกคำถามหนึ่งที่ต้องวัดผลแยกต่างหาก — นั่นคือจุดประสงค์ทั้งหมดของเครือข่ายการวัดประสิทธิภาพ (benchmark network) การกล่าวอ้างด้านคุณภาพจะอยู่บนกระดานผู้นำ (leaderboard) โดยจัดกลุ่มตาม (วิธีการ, ชุดข้อมูล, ตัวชี้วัด) ส่วนการกล่าวอ้างด้านความครอบคลุมจะอยู่ที่นี่
- **ที่กล่าวอ้าง ≠ นำไปใช้งานจริงได้** โมเดลการวิจัยที่เน้นความครอบคลุมอาจกล่าวอ้างจำนวนภาษาที่สูงมาก ในขณะที่เอกสารประกอบของตนเองรายงานคุณภาพที่ใช้งานได้จริงสำหรับกลุ่มย่อยที่เล็กกว่ามาก ในกรณีที่ผู้ให้บริการเผยแพร่การประเมินตนเองดังกล่าว เว็บไซต์จะแสดงจำนวนที่กล่าวอ้าง *และ* ตัวเลขที่นำไปใช้งานจริงได้/คุณภาพของผู้ให้บริการเอง โดยแต่ละรายการจะอ้างอิงจากเอกสารของผู้ให้บริการ

## วินัยในการรีเฟรชข้อมูล

รายการของผู้ให้บริการมีการเปลี่ยนแปลง จำนวนก็ต้องเปลี่ยนตามอย่างเป็นระบบ:

- แต่ละรายการใน `method-coverage.json` จะมีวันที่ `asOf` ของตนเอง และไฟล์จะมี `asOf` ในระดับบนสุด — ซึ่งเป็นวันที่ของการกวาดข้อมูล (sweep) ครั้งล่าสุด ส่วนแสดงผลที่แสดงจำนวนความครอบคลุมจะแสดงหรือลิงก์ไปยังวันที่นี้
- **การกวาดข้อมูล SOTA (SOTA sweep)** (การตรวจสอบรายการที่เผยแพร่ของผู้ให้บริการทุกรายอีกครั้ง การเพิ่มเอนจินที่ติดตามใหม่) เป็นงานบำรุงรักษาตามรอบเวลา การกวาดข้อมูลจะอัปเดต SSOT และทุกจำนวนบนเว็บไซต์จะเปลี่ยนตามในการบิลด์ครั้งถัดไป ไม่จำเป็นต้อง "จดจำ" สิ่งใดในข้อความบนหน้าเว็บ
- ในระหว่างการกวาดข้อมูล จำนวนจะมีความใหม่ตรงตามวันที่ `asOf` ของตน — ซึ่งเป็นเหตุผลว่าทำไมวันที่เหล่านั้นจึงเป็นส่วนหนึ่งของข้อมูล ไม่ใช่แค่ธรรมเนียมการทำเชิงอรรถ

## ยินดีรับการแก้ไขและข้อเสนอแนะ

หากรายการของผู้ให้บริการมีการเปลี่ยนแปลง มีการจัดประเภทภาษาผิด หรือคุณคิดว่าการแบ่งระดับไม่ถูกต้อง โปรดแจ้งให้เราทราบ — โดยเปิด Issue ที่ [github.com/gamedaysuits/Champollion/issues](https://github.com/gamedaysuits/Champollion/issues) หรือส่งอีเมลมาที่ [info@champollion.dev](mailto:info@champollion.dev)

## แหล่งที่มา

- **รายการของแต่ละเอนจิน** — `cli/shared/catalogue/method-coverage.json`: รายการภาษาที่รองรับซึ่งเผยแพร่โดยเอนจินแต่ละตัว (อ้างอิงเท่านั้น; `source_url` + `asOf` ต่อรายการ)
- **ชุดภาษาที่มีผู้ใช้งานอยู่** — ภาษาเดี่ยวที่มีผู้ใช้งานอยู่ตามมาตรฐาน ISO 639-3 (`isoType: 'L'`) ในดัชนีภาษาที่สร้างจากการ์ดภาษาที่อ้างอิง
- **จำนวนของแต่ละระดับ** — ส่งออกจากการบิลด์ `stats.coverage.dedicatedLiving` (ระดับ 1), `stats.coverage.serviceLiving` (ระดับ 2), `stats.livingTotal` ได้มาจาก Champollion
- **การประมาณการประชากรที่สร้างจากจำนวนเหล่านี้** — ดูที่ [ช่องว่างความครอบคลุม: วิธีที่เราใช้ประมาณการ](/docs/network/context/coverage-gap-estimate)
