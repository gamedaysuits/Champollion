# การวัดสิ่งที่วัดไม่ได้: ปัญหาการประเมินผลในการแปลด้วยเครื่อง

**การสำรวจแนวทางที่สาขาวิชาใช้วัดคุณภาพการแปล จุดที่ล้มเหลว และสิ่งที่ LYSS (Linguistically-informed Yield & Structural Scoring) นำเสนอเป็นทางเลือก**

---

> *"เมตริกอัตโนมัติคือการโกหกที่สะดวก มันให้ตัวเลขแก่เรา และตัวเลขนั้นทำให้เราเขียนบทความได้ และบทความนั้นทำให้เราอ้างความก้าวหน้าได้ ส่วนว่าความก้าวหน้าเกิดขึ้นจริงหรือไม่นั้นเป็นอีกคำถามหนึ่ง"*
> — ดัดแปลงจากความเห็นที่ปรากฏซ้ำๆ ใน WMT Metrics Shared Tasks

---

## บทนำ

การแปลด้วยเครื่องมีปัญหาด้านการวัดผล

สาขาวิชานี้ใช้เวลาสองทศวรรษในการสร้างระบบที่ซับซ้อนมากขึ้นเรื่อยๆ — ตั้งแต่ phrase tables ไปจนถึง attention mechanisms และ language models ขนาดล้านล้านพารามิเตอร์ — และตลอดช่วงเวลานั้น สาขาวิชานี้ก็ยังคงต่อสู้กับคำถามที่ดูเรียบง่ายแต่หลอกลวง: *คุณจะรู้ได้อย่างไรว่าการแปลนั้นดี?*

คำถามนี้ไม่ใช่เรื่องทางวิชาการ เมตริกที่คุณเลือกจะกำหนดว่าระบบใด "ชนะ" มันกำหนดสิ่งที่ได้รับทุน สิ่งที่ได้รับการตีพิมพ์ สิ่งที่ถูกนำไปใช้งาน และ — สำหรับภาษาที่ต้องการ MT มากที่สุด — ว่าการแปลของชุมชนจะถูกตัดสินว่าล้มเหลวหรือไม่ ทั้งที่ความจริงแล้วถูกต้อง

ประวัติศาสตร์ของการประเมิน MT คือประวัติศาสตร์ย่อของค่านิยมของสาขาวิชา การครอบงำของ BLEU เป็นเวลาเกือบสองทศวรรษสะท้อนให้เห็นถึงความนิยมในการวัดผลที่ถูก รวดเร็ว และไม่ขึ้นกับภาษา มากกว่าการประเมินที่อาศัยความรู้ทางภาษาศาสตร์ การเติบโตของเมตริกแบบ neural อย่าง COMET สะท้อนถึงความซับซ้อนที่เพิ่มขึ้นของสาขาวิชา — และการพึ่งพาข้อมูลฝึกสอนที่เน้น English อย่างต่อเนื่อง การขาดหายไปเกือบสมบูรณ์ของการประเมินที่ตระหนักถึงสัณฐานวิทยาสะท้อนถึงสาขาวิชาที่จนกระทั่งเมื่อไม่นานมานี้ถูกสร้างขึ้นโดยและเพื่อผู้พูดภาษา analytic ของยุโรป

บทความนี้ติดตามวิวัฒนาการของการประเมิน MT ตั้งแต่ BLEU จนถึงปัจจุบัน ระบุจุดที่แนวทางที่มีอยู่ล้มเหลวอย่างเป็นระบบสำหรับภาษาที่มีสัณฐานวิทยาซับซ้อนและทรัพยากรน้อย และตรวจสอบว่าทางเลือกที่อิงภาษาศาสตร์อาจมีลักษณะอย่างไร บทความนี้เป็นเอกสารประกอบของเอกสารบริบทอื่นๆ ของโครงการ — [*From Pāṇini to Transformers*](./history-of-language-and-computation.md) (ซึ่งติดตามประวัติศาสตร์ทางปัญญาของภาษาและการคำนวณ) และ [*Field Briefing*](./mt-field-briefing.md) (ซึ่งสำรวจภูมิทัศน์ MT ในปัจจุบัน) ในขณะที่เอกสารเหล่านั้นถามว่า "เรามาถึงจุดนี้ได้อย่างไร?" และ "มีอะไรอยู่บ้าง?" บทความนี้ถามว่า: "เราจะรู้ได้อย่างไรว่าสิ่งใดสิ่งหนึ่งใช้งานได้?"

## ส่วนที่ 1: ยุคการจับคู่สตริง (2002–2015)

### BLEU และการกำเนิดของการประเมินอัตโนมัติ



ยุคสมัยใหม่ของการประเมิน MT เริ่มต้นด้วยบทความเดียว: "BLEU: a Method for Automatic Evaluation of Machine Translation" ของ Kishore Papineni, Salim Roukos, Todd Ward และ Wei-Jing Zhu ที่ตีพิมพ์ใน ACL 2002 BLEU (Bilingual Evaluation Understudy) วัดว่าลำดับคำ (n-grams) ของการแปลด้วยเครื่องทับซ้อนกับการแปลอ้างอิงของมนุษย์หนึ่งรายการหรือมากกว่านั้นมากเพียงใด โดยมีการลงโทษความสั้นเพื่อป้องกันไม่ให้ระบบได้คะแนนสูงด้วยผลลัพธ์ที่สั้น และคำนวณค่าเฉลี่ยเรขาคณิตของความแม่นยำ n-gram ที่ลำดับ 1 ถึง 4

BLEU กลายเป็นสกุลเงินของสาขาวิชาด้วยเหตุผลง่ายๆ: มันรวดเร็ว ถูก ทำซ้ำได้ และไม่ขึ้นกับภาษา ก่อน BLEU การประเมินระบบ MT ต้องใช้การประเมินของมนุษย์ที่มีราคาแพงและช้า BLEU เสนอตัวเลขที่คำนวณได้ในมิลลิวินาที เปรียบเทียบข้ามบทความได้ และใช้จัดอันดับระบบในงาน shared tasks ภายในไม่กี่ปี มันกลายเป็นสิ่งจำเป็น — บทความที่ไม่มีคะแนน BLEU ไม่สามารถตีพิมพ์ได้

แต่ BLEU มีข้อบกพร่องที่ลึกซึ้งและมีเอกสารอ้างอิงชัดเจน ซึ่งสาขาวิชาใช้เวลาสองทศวรรษพยายามแก้ไข:

**ไม่มีความเข้าใจเชิงความหมาย** BLEU เป็นการจับคู่พื้นผิวล้วนๆ "The cat sat on the mat" ได้คะแนนศูนย์เมื่อเทียบกับข้อความอ้างอิง "the feline rested on the rug" ทุกคำเป็นคำพ้องความหมายที่ถูกต้อง ความหมายเหมือนกัน แต่คะแนนเป็นศูนย์

**ตาบอดต่อสัณฐานวิทยา** สำหรับภาษาแบบ agglutinative และ polysynthetic การจับคู่ระดับคำที่เข้มงวดล้มเหลวอย่างร้ายแรง กริยา Cree ที่ผันอย่างถูกต้องซึ่งแตกต่างจากข้อความอ้างอิงเพียงหนึ่ง morpheme ได้คะแนนศูนย์ — แม้ว่าความแตกต่างนั้นจะเป็น particle ที่เลือกใช้ได้ทางไวยากรณ์หรือลำดับคำที่ถูกต้องเท่าเทียมกัน

**การแยกแยะระดับประโยคที่ไม่ดี** BLEU ถูกออกแบบมาเป็นเมตริกระดับ corpus ในระดับประโยค มันมีสัญญาณรบกวนและไม่น่าเชื่อถือ — แต่ก็ถูกนำไปใช้กับประโยคแต่ละประโยคเป็นประจำ

**อคติต่อข้อความอ้างอิงเดียว** BLEU ถือว่ามีการแปลที่ถูกต้อง *หนึ่ง* รายการ (หรือชุดอ้างอิงขนาดเล็ก) สำหรับภาษาที่มีลำดับคำอิสระ คำศัพท์ที่มีคำพ้องความหมายมาก หรือความกำกวมที่เป็นระบบ (เช่น "we" แบบ inclusive/exclusive ของ Cree) อาจมีการแปลที่ถูกต้องเท่าเทียมกันหลายสิบรายการ และ BLEU ลงโทษทั้งหมดยกเว้นรายการที่ตรงกับข้อความอ้างอิง

**ความสัมพันธ์กับการตัดสินของมนุษย์ที่อ่อนแอ** การวิเคราะห์อภิมาน — โดยเฉพาะ Reiter (2018, *Computational Linguistics*) — แสดงให้เห็นว่าความสัมพันธ์ของ BLEU กับการประเมินคุณภาพของมนุษย์มักอ่อนแอ โดยเฉพาะสำหรับระบบคุณภาพสูงและสำหรับภาษาที่ห่างไกลจาก English

ข้อบกพร่องเหล่านี้เป็นที่รู้จักเกือบตั้งแต่ต้น แต่ BLEU ยังคงอยู่เพราะทางเลือกอื่นแย่กว่า — ไม่ใช่ในด้านความแม่นยำ แต่ในด้านความสะดวก สาขาวิชาเพิ่มประสิทธิภาพสำหรับเมตริกที่คำนวณได้ ไม่ใช่เมตริกที่ต้องการ

### NIST (Doddington, 2002)

เมตริก NIST ที่ตีพิมพ์ในปีเดียวกับ BLEU โดย George Doddington ใน HLT 2002 ปรับเปลี่ยนสูตร BLEU สองวิธี ประการแรก ถ่วงน้ำหนัก n-grams ด้วย **information content** — n-grams ที่หายากได้รับน้ำหนักสูงกว่า n-grams ทั่วไป โดยอิงจากสัญชาตญาณว่าการแปลวลีที่ผิดปกติได้อย่างถูกต้องนั้นให้ข้อมูลมากกว่าการแปล "of the" ได้อย่างถูกต้อง ประการที่สอง ใช้ **ค่าเฉลี่ยเลขคณิต** แทนค่าเฉลี่ยเรขาคณิตของ BLEU ทำให้ได้คะแนนที่เสถียรกว่าซึ่งไม่ยุบตัวเป็นศูนย์เมื่อ n-gram ลำดับใดลำดับหนึ่งไม่มีการจับคู่ NIST ถูกใช้อย่างกว้างขวางในโปรแกรมการประเมิน DARPA TIDES และ NIST OpenMT แต่ไม่เคยบรรลุการครอบงำของ BLEU ในชุมชนวิจัยที่กว้างขึ้น แม้จะมีการปรับปรุง แต่ก็ยังมีข้อจำกัดพื้นฐานเดียวกับ BLEU: การจับคู่สตริงระดับพื้นผิวโดยไม่มีแนวคิดเรื่องความหมาย

### METEOR (Banerjee & Lavie, 2005)

METEOR (Metric for Evaluation of Translation with Explicit ORdering) เป็นความพยายามในช่วงแรกเพื่อแก้ไขความเข้มงวดของ BLEU ในขณะที่ BLEU ทำการจับคู่คำที่แน่นอน METEOR แนะนำนวัตกรรมสามประการ:

1. **Stemming**: คำถูกลดรูปเป็น stem ก่อนการเปรียบเทียบ ให้เครดิตบางส่วนสำหรับตัวแปรทางสัณฐานวิทยา (เช่น "running" จับคู่กับ "ran" หลัง stemming)
2. **การจับคู่คำพ้องความหมาย**: โดยใช้ WordNet METEOR รับรู้ว่า "car" และ "automobile" เป็นแนวคิดเดียวกัน
3. **การจัดแนวคำ**: แทนที่จะนับการทับซ้อนของ n-gram METEOR จัดแนวคำระหว่าง hypothesis และ reference อย่างชัดเจน จากนั้นคำนวณความแม่นยำและ recall พร้อมการลงโทษการแตกกระจาย

METEOR แสดงความสัมพันธ์กับการตัดสินของมนุษย์สูงกว่า BLEU อย่างสม่ำเสมอ แต่ต้องการทรัพยากรเฉพาะภาษา (stemmers, ฐานข้อมูลคำพ้องความหมาย) ที่จำกัดการนำไปใช้ และช้ากว่าในการคำนวณ สำหรับ English มันดีกว่า สำหรับภาษาที่มีทรัพยากรน้อย stemmers และฐานข้อมูลคำพ้องความหมายไม่มีอยู่เลย

### TER (Snover et al., 2006)

Translation Edit Rate วัดจำนวนการแก้ไขขั้นต่ำ (การแทรก การลบ การแทนที่ และ *phrase shifts*) ที่จำเป็นในการแปลง hypothesis เป็น reference โดยปรับตามความยาวของ reference การดำเนินการ phrase-shift — การย้ายลำดับคำที่ต่อเนื่องกันไปยังตำแหน่งอื่น — เป็นการยอมรับโดยตรงว่าลำดับคำไม่ตายตัวข้ามภาษา แนวทาง edit-distance ของ TER นั้นเข้าใจง่าย (วัดว่า "ผู้แก้ไขหลังการแปลต้องทำงานมากแค่ไหน?") แต่มีข้อจำกัดพื้นฐานเดียวกัน: เปรียบเทียบกับข้อความอ้างอิงเดียวและไม่มีแนวคิดเรื่องความหมาย

### chrF และ chrF++ (Popović, 2015; 2017)

นวัตกรรมเมตริกที่สำคัญที่สุดระหว่าง BLEU และยุค neural มาจาก Maja Popović **chrF** (character F-score) วัดการทับซ้อนในระดับ *ตัวอักษร* แทนระดับคำ โดยคำนวณความแม่นยำและ recall ของ character n-gram **chrF++** เพิ่ม word-level unigrams และ bigrams กลับเข้าไปในการผสม

เหตุใดสิ่งนี้จึงสำคัญสำหรับภาษาที่มีสัณฐานวิทยาซับซ้อน: การจับคู่ระดับตัวอักษรให้ *เครดิตบางส่วน* สำหรับ morphemes ที่ใช้ร่วมกัน คำ Cree *nikî-nipâw* ("ฉันนอนหลับ") และ *kikî-nipâw* ("คุณนอนหลับ") ใช้ character n-grams ส่วนใหญ่ร่วมกันแม้จะเป็นคำที่แตกต่างกัน chrF จะให้เครดิตบางส่วนอย่างมาก ในขณะที่ BLEU จะให้ศูนย์

chrF++ กลายเป็นเมตริกรองมาตรฐานใน WMT shared tasks ที่ใช้งานใน **sacreBLEU** (Post, 2018) และได้รับการยอมรับอย่างกว้างขวางว่าเหนือกว่า BLEU สำหรับภาษาที่มีสัณฐานวิทยาซับซ้อน แต่ยังคงเป็นเมตริกการจับคู่สตริง — ดีกว่า BLEU แต่มีข้อจำกัดพื้นฐานเดียวกัน: สมมติว่าคุณภาพการแปลสามารถวัดได้จากการทับซ้อนของรูปแบบพื้นผิว

## ส่วนที่ 2: การปฏิวัติเมตริก Neural (2018–ปัจจุบัน)



### ข้อมูลเชิงลึก: เรียนรู้การให้คะแนน

เมตริกการจับคู่สตริงในส่วนที่ 1 มีการเลือกออกแบบพื้นฐานร่วมกัน: เป็นสูตรที่สร้างด้วยมือ มีคนตัดสินใจว่าความแม่นยำ n-gram การทับซ้อนของตัวอักษร หรือ edit distance เป็นตัวแทนที่ดีของคุณภาพการแปล จากนั้นทุกคนก็ใช้สูตรนั้นมาเป็นทศวรรษ

การปฏิวัติเมตริก neural เริ่มต้นด้วยคำถามที่แตกต่าง: *จะเป็นอย่างไรถ้าเราฝึกโมเดลให้ทำนายคุณภาพการแปล เช่นเดียวกับที่เราฝึกโมเดลให้แปล?*

### BERTScore (Zhang et al., 2020)

BERTScore ที่ตีพิมพ์ใน ICLR 2020 โดย Tianyi Zhang และเพื่อนร่วมงานที่ Cornell และ MIT เป็นเมตริกที่ได้รับการยอมรับอย่างกว้างขวางรายการแรกที่ย้ายการประเมินจากการจับคู่สตริงที่แน่นอนไปสู่ความคล้ายคลึงเชิงความหมาย กลไกนั้นสง่างาม: เข้ารหัสทั้ง hypothesis และ reference ผ่านโมเดล Transformer ที่ผ่านการฝึกล่วงหน้า (BERT, RoBERTa หรือ DeBERTa) คำนวณ cosine similarity ระหว่างคู่ token embeddings ทุกคู่ จากนั้นใช้ greedy matching เพื่อคำนวณความแม่นยำ (การจับคู่ที่ดีที่สุดของแต่ละ token ใน hypothesis ใน reference) recall (การจับคู่ที่ดีที่สุดของแต่ละ token ใน reference ใน hypothesis) และ F1

BERTScore จัดการคำพ้องความหมาย การถอดความ และการเปลี่ยนแปลงลำดับคำได้อย่างเป็นธรรมชาติ — "the feline rested on the rug" ได้รับความคล้ายคลึงสูงกับ "the cat sat on the mat" เพราะ contextual embeddings จับความเท่าเทียมเชิงความหมาย ด้วย multilingual BERT มันขยายไปยังภาษาใดก็ตามที่โมเดลครอบคลุม

แต่ BERTScore ไม่ได้ *ฝึก* บนการตัดสินคุณภาพของมนุษย์ มันใช้ pre-trained embeddings ตามที่เป็น ซึ่งหมายความว่ามันจับความคล้ายคลึงเชิงความหมายทั่วไปแทนที่จะเรียนรู้โดยเฉพาะว่าอะไรทำให้ *การแปล* ดี ความแตกต่างนี้สำคัญ: ประโยคสามารถมีความคล้ายคลึงเชิงความหมายกับข้อความอ้างอิงในขณะที่เป็นการแปลที่ไม่ดี (register ผิด การละเว้นการปฏิเสธ qualifier ที่สร้างขึ้น) BERTScore ยังรับอคติทางภาษาใดก็ตามที่มีอยู่ในโมเดลพื้นฐาน — สำหรับภาษาที่มีการแสดงน้อยในข้อมูลฝึกสอนของ BERT embeddings อาจไม่จับความแตกต่างที่มีความหมาย

### BLEURT (Sellam et al., 2020)

BLEURT (Bilingual Evaluation Understudy with Representations from Transformers) ที่ตีพิมพ์ใน ACL 2020 โดย Thibault Sellam, Dipanjan Das และ Ankur Parikh ที่ Google แนะนำนวัตกรรมสำคัญ: **การ pre-training บน synthetic perturbations** ก่อน fine-tuning บนการตัดสินของมนุษย์ ข้อมูลเชิงลึกคือการ fine-tune language model โดยตรงบนชุดข้อมูลการตัดสินของมนุษย์ WMT ขนาดเล็กทำให้ได้เมตริกที่เปราะบาง — มัน overfit กับรูปแบบเฉพาะในข้อมูลฝึกสอนและล้มเหลวกับ input ที่อยู่นอกการกระจาย

วิธีแก้ปัญหาของ BLEURT คือสูตรการฝึกสองขั้นตอน ในขั้นตอนแรก คู่ประโยค synthetic หลายล้านคู่ถูกสร้างขึ้นผ่านการลบคำแบบสุ่ม การแทรก การแทนที่ และ backtranslation โมเดลถูกฝึกให้ทำนายคะแนนเมตริกอัตโนมัติที่มีอยู่ (BLEU, ROUGE, BERTScore, entailment) สำหรับคู่เหล่านี้ — เรียนรู้แนวคิดทั่วไปของความคล้ายคลึงของข้อความ ในขั้นตอนที่สอง โมเดลที่ผ่านการ pre-train ถูก fine-tune บนคะแนน WMT Direct Assessment การ "อุ่นเครื่อง" นี้ปรับปรุงความทนทานอย่างมาก

BLEURT-20 ขยายแนวทางไปสู่การประเมินหลายภาษาโดยใช้ encoder RemBERT ของ Google แต่ BLEURT ยังคงเป็น reference-only — ไม่ใช้ข้อความต้นฉบับ ซึ่งหมายความว่าไม่สามารถตรวจจับ hallucinations ที่เกิดขึ้นอย่างคล่องแคล่ว และขึ้นอยู่กับคุณภาพของข้อความอ้างอิงทั้งหมด

### COMET (Rei et al., 2020)

COMET (Crosslingual Optimized Metric for Evaluation of Translation) แสดงถึงสถานะปัจจุบันของศิลปะในการประเมิน MT อัตโนมัติ พัฒนาโดย Ricardo Rei และเพื่อนร่วมงานที่ **Unbabel** COMET ใช้ cross-lingual encoder (XLM-RoBERTa) เพื่อเข้ารหัส input สามรายการ — ประโยคต้นฉบับ MT hypothesis และการแปลอ้างอิง — และทำนายคะแนนคุณภาพที่ฝึกบนการตัดสิน Direct Assessment ของมนุษย์

COMET ชนะหรือได้อันดับหนึ่งใน WMT Metrics Shared Tasks ตั้งแต่ปี 2020 เป็นต้นมา ความสัมพันธ์กับการตัดสินของมนุษย์สูงกว่าเมตริกการจับคู่สตริงใดๆ อย่างมาก มันรับรู้การถอดความ จับการรักษาความหมาย และจัดการการเปลี่ยนแปลงคำพ้องความหมายที่ BLEU พลาดไปทั้งหมด

แต่ COMET มีข้อจำกัดที่สำคัญสำหรับวัตถุประสงค์ของเรา: มันถูกฝึกบนการตัดสินของมนุษย์จาก WMT ซึ่งส่วนใหญ่เป็นภาษายุโรป cross-lingual encoder (XLM-R) ถูกฝึกบนข้อมูล CommonCrawl ที่ Plains Cree, North Sámi และภาษาพื้นเมืองส่วนใหญ่แทบไม่มีอยู่ สำหรับภาษาเหล่านี้ การแสดงภายในของ COMET ไม่น่าเชื่อถือ — มันอาจสร้างคะแนน แต่คะแนนเหล่านั้นไม่ได้อิงจากความเข้าใจที่แท้จริงเกี่ยวกับโครงสร้างของภาษา

### xCOMET (Guerreiro et al., 2024)

xCOMET ที่ตีพิมพ์ใน TACL 2024 โดย Nuno Guerreiro, Ricardo Rei และเพื่อนร่วมงานที่ Unbabel และ Instituto Superior Técnico ขยาย COMET จาก scorer แบบ black-box ไปสู่ **เครื่องมือวินิจฉัย** นวัตกรรมสำคัญคือ multi-task learning: ควบคู่กับคะแนนคุณภาพระดับประโยค xCOMET ทำ **subword-level sequence tagging** เพื่อระบุ error spans เฉพาะในการแปลและจัดประเภทเป็น minor, major หรือ critical

สิ่งนี้เชื่อมช่องว่างระหว่างการให้คะแนนอัตโนมัติและการวิเคราะห์ข้อผิดพลาดของมนุษย์แบบ MQM แทนที่จะรายงานเพียงว่า "การแปลนี้ได้คะแนน 0.73" xCOMET สามารถชี้ไปยังคำเฉพาะที่ผิดและระบุความรุนแรง การฝึกใช้แนวทาง curriculum learning: ฝึกบนข้อมูล Direct Assessment สำหรับ sentence-level regression ก่อน จากนั้นเพิ่มข้อมูลที่มีคำอธิบาย MQM พร้อม error span labels สำหรับการฝึกร่วม

xCOMET บรรลุประสิทธิภาพ state-of-the-art ในการประเมินระดับประโยค ระดับระบบ และระดับ span พร้อมกัน ทำงานทั้งในโหมด reference-based และ reference-free แต่ต้องการข้อมูลฝึกสอนที่มีคำอธิบาย MQM — ซึ่งมีราคาแพงในการสร้างและมีอยู่ส่วนใหญ่สำหรับคู่ภาษายุโรป

### AfriCOMET (Wang & Adelani, NAACL 2024)

AfriCOMET ที่ตีพิมพ์ใน NAACL 2024 โดย Jiayi Wang, David Ifeoluwa Adelani และเพื่อนร่วมงานในชุมชน Masakhane เป็นหลักฐานที่สำคัญที่สุดว่าเมตริก neural *ต้อง* ได้รับการปรับสำหรับภาษาที่ไม่ได้รับการบริการ — มันไม่ได้ generalize โดยอัตโนมัติ

บทความนี้แสดงให้เห็นปัญหาก่อน: COMET มาตรฐานที่ฝึกบนข้อมูล WMT จากภาษายุโรปแสดงความสัมพันธ์กับการตัดสินของมนุษย์ที่อ่อนแอกว่าอย่างมีนัยสำคัญเมื่อนำไปใช้กับ 13 ภาษาแอฟริกัน (รวมถึง Amharic, Hausa, Igbo, Swahili, Yoruba และ Zulu) การแก้ไขต้องการการเปลี่ยนแปลงสองอย่าง ประการแรก แทนที่ XLM-R ด้วย **AfroXLM-R** ซึ่งเป็น cross-lingual encoder ที่ฝึกมาโดยเฉพาะเพื่อแสดงภาษาแอฟริกันได้ดีขึ้น ประการที่สอง สร้าง **AfriMTE** ซึ่งเป็นชุดข้อมูลการประเมินของมนุษย์ใหม่พร้อมแนวทาง MQM แบบง่ายที่ออกแบบสำหรับผู้ใส่คำอธิบายที่ไม่ใช่ผู้เชี่ยวชาญ — เพราะการหานักแปลมืออาชีพที่พูดได้สองภาษาสำหรับภาษาเหล่านี้เป็นเรื่องยาก

AfriCOMET พิสูจน์แนวคิด: เมตริก neural เฉพาะตระกูลภาษาสามารถเหนือกว่าเวอร์ชันทั่วไปได้อย่างมาก แต่ยังพิสูจน์ต้นทุน: มีคนต้องสร้าง AfroXLM-R รวบรวมข้อมูลการตัดสินของมนุษย์สำหรับ 13 ภาษา และฝึกโมเดลใหม่ สำหรับ Plains Cree ไม่มี encoder ที่เทียบเท่า ชุดข้อมูลการตัดสินของมนุษย์ หรือเมตริกที่ปรับแล้ว เส้นทาง AfriCOMET จะต้องสร้างทั้งหมดนี้ตั้งแต่ต้น — ความพยายามหลายปีที่เกี่ยวข้องกับการประเมินของมนุษย์ที่อิงชุมชนและอาจต้องใช้ encoder เฉพาะตระกูล Algonquian

### GEMBA: LLM-as-Evaluator (Kocmi & Federmann, 2023)

GEMBA (GPT Estimation Metric Based Assessment) ที่ตีพิมพ์ใน EAMT 2023 โดย Tom Kocmi และ Christian Federmann ที่ Microsoft ถามคำถามที่รุนแรง: จะเป็นอย่างไรถ้าคุณแค่ *ถาม* GPT-4 ว่าการแปลดีหรือไม่?

แนวทางนั้นเรียบง่ายอย่างน่าประหลาดใจ **GEMBA-DA** prompt LLM ด้วยต้นฉบับและ hypothesis และขอคะแนนคุณภาพในระดับ 0–100 **GEMBA-MQM** ให้ตัวอย่างที่มีคำอธิบายสามรายการและขอให้ LLM ระบุ error spans เฉพาะ จัดประเภทตามประเภทและความรุนแรง และสร้างคะแนนแบบ MQM ไม่จำเป็นต้องมีการฝึกเมตริกเฉพาะ

ผลลัพธ์น่าทึ่ง: ในระดับระบบ GEMBA บรรลุความสัมพันธ์กับการตัดสินของมนุษย์ที่แข่งขันได้หรือ state-of-the-art คำอธิบาย error ของ GEMBA-MQM แม้จะไม่น่าเชื่อถือเท่าผู้ใส่คำอธิบายมนุษย์ แต่ให้ข้อมูลวินิจฉัยที่ตีความได้โดยไม่ต้องมีการฝึกเฉพาะทาง

แต่ GEMBA ก่อให้เกิดความกังวลอย่างจริงจัง มันขึ้นอยู่กับโมเดล closed-source ที่เป็นกรรมสิทธิ์ซึ่งพฤติกรรมเปลี่ยนแปลงระหว่างเวอร์ชัน API ผลลัพธ์ไม่สามารถทำซ้ำได้ในความหมายที่เข้มงวด มีราคาแพงในระดับขนาดใหญ่ (ค่าใช้จ่าย API สำหรับการประเมินชุดทดสอบ WMT ทั้งหมด) และ — สำคัญอย่างยิ่งสำหรับวัตถุประสงค์ของเรา — ความรู้ของ LLM เกี่ยวกับภาษาที่มีทรัพยากรน้อยนั้นไม่แน่นอน GPT-4 อาจเข้าใจหรือไม่เข้าใจสัณฐานวิทยา Plains Cree ดีพอที่จะประเมินการแปล ไม่มีทางรู้ได้โดยไม่ทดสอบ และไม่มีการรับประกันว่าพฤติกรรมจะสอดคล้องกันข้ามการอัปเดตโมเดล Kocmi และ Federmann เองแนะนำไม่ให้ใช้ GEMBA เพื่ออ้างการปรับปรุงในบทความวิชาการเนื่องจากลักษณะ black-box ของการประเมิน

### MetricX และ WMT 2024 Metrics Shared Task

**MetricX-24** ที่พัฒนาโดย Juraj Juraska, Daniel Deutsch, Mara Finkelstein และ Markus Freitag ที่ Google ชนะ WMT 2024 Metrics Shared Task สร้างบน **mT5** (Multilingual T5 ซึ่งเป็นโมเดล encoder-decoder แทนที่จะเป็น encoder-only XLM-R ที่ COMET ใช้) MetricX ใช้เส้นทางสถาปัตยกรรมที่แตกต่าง ใช้ two-stage fine-tuning — ก่อนบนข้อมูล Direct Assessment จากนั้นบนคะแนน MQM — พร้อม **synthetic data augmentation** ที่กว้างขวางซึ่งกำหนดเป้าหมายโหมดความล้มเหลวของเมตริกที่รู้จัก (undertranslation, การแปลที่คล่องแต่ผิด, hallucinations)

บทความผลการค้นพบ WMT 2024 ที่มีชื่อว่า **"Are LLMs Breaking MT Metrics?"** ถามว่าการแปลที่สร้างโดย LLM ได้ทำลายระบบนิเวศเมตริกหรือไม่ คำตอบคือไม่อย่างมีเงื่อนไข: เมตริก neural ที่ fine-tune (MetricX-24, COMET variants) ยังคงมีประสิทธิภาพ แม้ว่าเมตริกที่อิง LLM (GEMBA variants) จะแสดงความแข็งแกร่งที่น่าประหลาดใจในระดับระบบ ผลการค้นพบสำคัญ:

- **เมตริกที่ตระหนักถึงต้นฉบับ** (ใช้ต้นฉบับ + อ้างอิง + hypothesis) เหนือกว่าเมตริก reference-only อย่างสม่ำเสมอ
- **โมเดล hybrid** ที่ทำงานทั้งในโหมด reference-based และ reference-free จากสถาปัตยกรรมเดียวเป็นทิศทางที่กำลังเกิดขึ้น
- **ช่องว่างทรัพยากรน้อย** ยังคงมีอยู่: เมตริกทั้งหมดทำงานได้แย่ลงกับภาษาที่มีการแสดงน้อย และช่องว่างไม่ได้แคบลง
- **เมตริกที่ฝึกด้วย MQM** (ใช้คำอธิบาย error ที่ละเอียด) เหนือกว่าเมตริกที่ฝึกด้วย DA (ใช้คะแนน scalar) อย่างสม่ำเสมอ

ผลกระทบต่อการประเมินทรัพยากรน้อยนั้นชัดเจน: สาขาวิชากำลังรวมตัวกันบนเมตริก neural ขนาดใหญ่ที่ฝึกและตระหนักถึงต้นฉบับเป็นมาตรฐานทองคำ เมตริกเหล่านี้ต้องการข้อมูลฝึกสอนจำนวนมาก การคำนวณ และ — สำคัญอย่างยิ่ง — ข้อมูลการประเมินของมนุษย์ในภาษาเป้าหมาย สำหรับภาษาที่ไม่มีทรัพยากรเหล่านี้เลย pipeline เมตริก state-of-the-art ไม่สามารถนำไปใช้ได้เลย

### ปัญหาอคติ: เมตริก Neural และภาษาที่มีทรัพยากรน้อย

การปฏิวัติเมตริก neural เป็นปรากฏการณ์ที่มีทรัพยากรสูงเป็นส่วนใหญ่ เมตริกที่ฝึกทุกรายการในส่วนก่อนหน้าถูกฝึกบนข้อมูลการตัดสินของมนุษย์ WMT ซึ่งครอบคลุมประมาณ 20 คู่ภาษา — ทั้งหมดเกี่ยวข้องกับภาษายุโรป จีน หรือญี่ปุ่น encoder พื้นฐาน (XLM-R, mT5, InfoXLM) ถูกฝึกบนข้อมูล CommonCrawl ที่การแสดงเป็นสัดส่วนกับการมีอยู่บนเว็บ: English ครอบงำ ภาษายุโรปได้รับการครอบคลุมดี และภาษาส่วนใหญ่จาก 7,000+ ภาษาของโลกแทบไม่มีอยู่เลย

สำหรับภาษาอย่าง Plains Cree สิ่งนี้สร้างความล้มเหลวแบบ cascading:

1. **ไม่มีข้อมูลฝึกสอน**: ไม่มีการตัดสินของมนุษย์ WMT สำหรับการแปล Cree ดังนั้นไม่มีเมตริกใดที่ถูกฝึกเพื่อประเมินมัน
2. **ไม่มีการครอบคลุม encoder**: คำศัพท์ของ XLM-R ถูกสร้างบน CommonCrawl ที่ข้อความ Cree หายากอย่างยิ่ง tokeniser แบ่งคำ Cree เป็น byte fragments โดยพลการ และ contextual embeddings สำหรับ fragments เหล่านั้นถูกฝึกไม่ดี
3. **ไม่มีการตรวจสอบ**: ไม่มีใครวัดว่า COMET, BLEURT หรือ MetricX สร้างคะแนนที่มีความหมายสำหรับ Cree หรือไม่ อาจสร้าง *ตัวเลข* แต่ไม่มีหลักฐานว่าตัวเลขเหล่านั้นสัมพันธ์กับคุณภาพการแปลที่แท้จริง
4. **ไม่มีเส้นทางสู่การปรับปรุง**: แนวทาง AfriCOMET — สร้าง encoder เฉพาะตระกูลภาษา รวบรวมข้อมูลการประเมินของมนุษย์ ฝึกเมตริกใหม่ — เป็นความพยายามหลายปีหลายสถาบัน สำหรับชุมชนภาษาที่มีผู้พูด 20,000 คน โครงสร้างพื้นฐานการวิจัยเพื่อสนับสนุนสิ่งนี้ยังไม่มีอยู่ในปัจจุบัน

ผลลัพธ์คือความขัดแย้ง: ภาษาที่ต้องการการประเมิน MT อย่างเร่งด่วนที่สุด (เพราะระบบ MT ของพวกเขาอ่อนแอที่สุดและต้องการการประเมินที่ระมัดระวังที่สุด) เป็นภาษาที่เครื่องมือประเมินที่ดีที่สุดน่าเชื่อถือน้อยที่สุด การตอบสนองของสาขาวิชาคือการแนะนำ chrF++ เป็นทางเลือก "ดีพอ" — และมันดีกว่า — แต่ chrF++ ยังคงเป็นเมตริกการจับคู่สตริงที่ไม่สามารถตรวจจับความเท่าเทียม ไม่สามารถจัดการลำดับคำอิสระ และไม่มีแนวคิดเรื่องความถูกต้องทางสัณฐานวิทยา

## ส่วนที่ 3: เหนือกว่าการให้คะแนน — การประเมินเชิงวินิจฉัยและภาษาศาสตร์

### การแบ่ง Adequacy/Fluency

ก่อนที่เมตริกอัตโนมัติจะมีอยู่ การประเมินของมนุษย์สำหรับ MT ใช้กรอบงานที่มีสองมิติ: **adequacy** (การแปลถ่ายทอดความหมายของต้นฉบับหรือไม่?) และ **fluency** (การแปลถูกต้องตามไวยากรณ์และเป็นธรรมชาติในภาษาเป้าหมายหรือไม่?) ความแตกต่างนี้ที่ถูกรวบรวมในการประเมิน MT ของ DARPA ในช่วงแรกและต่อมาที่ NIST ยอมรับสิ่งที่เมตริกอัตโนมัติจะใช้เวลาสองทศวรรษในการพยายามกู้คืน: คุณภาพการแปลไม่ใช่มิติเดียว

กรอบงาน adequacy/fluency ตกจากความนิยมเมื่อ Direct Assessment (คะแนน scalar เดียว) แทนที่มันที่ WMT แต่ข้อมูลเชิงลึกพื้นฐานยังคงสำคัญ: การแปลสามารถคล่องแต่ผิด (hallucination) หรือไม่คล่องแต่ถูกต้อง (ตัวแปรทางสัณฐานวิทยา) ไม่มีคะแนนเดียวที่จับทั้งสองอย่าง

### MQM: มาตรฐานทองคำ (Lommel et al., 2014; Freitag et al., 2021)

**Multidimensional Quality Metrics (MQM)** แทนที่ Direct Assessment เป็นการประเมินของมนุษย์หลักของ WMT ตั้งแต่ปี 2021 เป็นต้นมา MQM ใช้นักแปลมืออาชีพที่ทำเครื่องหมาย error spans เฉพาะ จัดประเภทตามประเภท (mistranslation, omission, addition, grammar, terminology) และความรุนแรง (minor = 1 คะแนน, major = 5 คะแนน, critical = 25 คะแนน) สิ่งนี้สร้างทั้งคะแนนคุณภาพและข้อมูลวินิจฉัยที่นำไปปฏิบัติได้

MQM เป็นสิ่งที่ใกล้เคียงกับวิธีการประเมินที่ "ถูกต้อง" มากที่สุด — มันบอกคุณไม่เพียงแค่ว่าการแปล *แย่แค่ไหน* แต่ *อะไรที่ผิดพลาดโดยเฉพาะ* แต่ต้องการนักแปลมืออาชีพที่พูดได้สองภาษา ซึ่งสำหรับภาษาที่มีทรัพยากรน้อยส่วนใหญ่ไม่มีอยู่ในจำนวนที่เพียงพอสำหรับการประเมินที่เชื่อถือได้ทางสถิติ

### MorphEval: การประเมินสัณฐานวิทยาแบบ Contrastive (Burlot & Yvon, 2017)

MorphEval เป็นงานก่อนหน้าที่ตรงที่สุดสำหรับการประเมิน MT ที่ตระหนักถึงสัณฐานวิทยา แนะนำโดย Franck Burlot และ François Yvon ที่ WMT 2017 และขยายในปี 2018 MorphEval ประเมิน *ความสามารถ* ทางสัณฐานวิทยาโดยใช้ **contrastive test suites**

**วิธีการทำงาน:** test suite ประกอบด้วยคู่ประโยคในภาษาต้นฉบับที่แตกต่างกันด้วยความแตกต่างทางสัณฐานวิทยาหนึ่งอย่างพอดี — เช่น เอกพจน์กับพหูพจน์ ปัจจุบันกับอดีต เพศชายกับเพศหญิง ระบบ MT แปลทั้งสองประโยค หากระบบถ่ายทอดความแตกต่างในการแปลได้อย่างถูกต้อง (เช่น สร้างเป้าหมายพหูพจน์เมื่อต้นฉบับเป็นพหูพจน์และเป้าหมายเอกพจน์เมื่อต้นฉบับเป็นเอกพจน์) ความแตกต่างนั้นจะได้คะแนนว่าถูกต้อง

**ภาษาที่ครอบคลุม:** English→Czech, English→Latvian (v1, WMT 2017); ขยายไปยัง English→French, English→German, English→Finnish, Turkish→English (v2, WMT 2018)

**ผลการค้นพบสำคัญ:** MorphEval เปิดเผยว่าแม้แต่ระบบ neural MT ที่มีประสิทธิภาพสูงสุดก็มีความล้มเหลวทางสัณฐานวิทยาที่เป็นระบบ — พวกมันสามารถสร้างผลลัพธ์ที่คล่องในขณะที่ผิดพลาดด้านกาล จำนวน หรือ case ข้อผิดพลาดเหล่านี้มองไม่เห็นสำหรับ BLEU และมองเห็นได้บางส่วนสำหรับ COMET

**ความพร้อมใช้งาน:** Open source บน GitHub ([franckbrl/morpheval](https://github.com/franckbrl/morpheval), [franckbrl/morpheval_v2](https://github.com/franckbrl/morpheval_v2))

**ข้อจำกัด:** MorphEval ต้องการ contrastive test suites ที่สร้างขึ้นต่อภาษาเป้าหมาย ออกแบบโดยนักภาษาศาสตร์ที่เข้าใจความแตกต่างทางสัณฐานวิทยาของภาษานั้น ไม่มี test suites สำหรับภาษา polysynthetic ใดๆ วิธีการทดสอบ *ความสามารถ* (ระบบสามารถจัดการความแตกต่างนี้ได้หรือไม่?) แทนที่จะเป็น *ความถูกต้อง* (ระบบสร้างคำจริงหรือไม่?) หรือ *ความเท่าเทียม* (การแปลสองรายการที่แตกต่างกันนี้ถูกต้องทั้งคู่หรือไม่?)

### CheckList: การทดสอบพฤติกรรมสำหรับ NLP (Ribeiro et al., ACL 2020)

**CheckList** ที่ตีพิมพ์ใน ACL 2020 โดย Marco Tulio Ribeiro และเพื่อนร่วมงาน (ชนะ Best Paper) นำเข้าแนวคิดจากวิศวกรรมซอฟต์แวร์เข้าสู่การประเมิน NLP: **unit testing** แทนที่จะประเมินประสิทธิภาพรวมของโมเดลบน benchmark CheckList กำหนดเมทริกซ์ของ **ความสามารถ** (คำศัพท์ การปฏิเสธ named entities การใช้เหตุผลเชิงเวลา coreference) ที่ตัดกับ **ประเภทการทดสอบ**:

- **Minimum Functionality Tests (MFT)**: กรณีทดสอบที่เรียบง่ายและมีเป้าหมายที่โมเดลที่มีความสามารถใดๆ ควรผ่าน
- **Invariance Tests (INV)**: การรบกวน input ที่ *ไม่ควร* เปลี่ยน output (เช่น การเปลี่ยนชื่อไม่ควรเปลี่ยน sentiment)
- **Directional Expectation Tests (DIR)**: การรบกวนที่ *ควร* เปลี่ยน output ในทิศทางที่คาดเดาได้

CheckList ถูกออกแบบมาสำหรับ sentiment analysis และ NLI ในตอนแรก แต่กระบวนทัศน์นั้นนำไปใช้กับ MT ได้โดยตรง สามารถสร้าง MFTs สำหรับปรากฏการณ์ทางสัณฐานวิทยา ("ระบบสร้างรูปพหูพจน์ที่ถูกต้องหรือไม่?") INV tests สำหรับลำดับคำอิสระ ("การเรียงลำดับคำ Cree ใหม่เปลี่ยนการแปล English หรือไม่?") และ DIR tests สำหรับคุณลักษณะทางสัณฐานวิทยา ("การเปลี่ยนต้นฉบับจากอดีตเป็นปัจจุบันเปลี่ยนกาลเป้าหมายหรือไม่?")

กระบวนทัศน์ CheckList มีความเกี่ยวข้องเป็นพิเศษเพราะมันทำให้เป็นทางการในสิ่งที่ MorphEval ทำโดยสัญชาตญาณ: ทดสอบความสามารถเฉพาะแทนที่จะวัดคะแนนรวม คลาสตัวแปรของ linter ของเรา (WORD_ORDER, ORTHOGRAPHIC, OPTIONAL_PARTICLE ฯลฯ) เป็น invariance rules โดยพื้นฐาน — พวกมันกำหนดการรบกวนที่ไม่ควรเปลี่ยนคำตัดสินการประเมิน

### Challenge Sets และการประเมินแบบมีเป้าหมาย

กระบวนทัศน์ที่กว้างขึ้นของ **challenge sets** — test suites ที่สร้างขึ้นซึ่งกำหนดเป้าหมายปรากฏการณ์ทางภาษาเฉพาะ — ได้กลายเป็นวิธีการประเมินเสริมที่ได้รับการยอมรับที่ WMT ตั้งแต่ประมาณปี 2017

**Isabelle, Cherry & Foster (2017)** ที่ NRC Canada บุกเบิกแนวทางสำหรับ MT ด้วย test sets ที่สร้างด้วยมือซึ่งแยกความแตกต่างทางโครงสร้างระหว่างภาษา — กรณีที่การแปลตรงตัวมักจะไม่ถูกต้อง งานต่อเนื่องของพวกเขา (Isabelle & Kuhn, 2018) สร้างประโยค French 506 ประโยคที่กำหนดเป้าหมายความท้าทายการแปลเฉพาะ ให้ภาพที่ละเอียดของความสามารถของระบบ

**LingEval97** (Sennrich, EACL 2017) สร้างคู่การแปล English→German แบบ contrastive 97,000 คู่ที่ทดสอบว่าโมเดล NMT กำหนดความน่าจะเป็นสูงกว่าให้กับการแปลที่ถูกต้องเทียบกับคู่ที่มีข้อผิดพลาด morphosyntactic ที่นำเข้า ผลการค้นพบสำคัญ: โมเดลระดับตัวอักษรเก่งในการถอดอักษรแต่ทำงานได้แย่กว่าในการตกลง morphosyntactic ระยะไกล

**ACES** (Amrhein, Moghe & Guillou, 2022–2023) ขยายแนวทาง challenge set อย่างมาก: 36,476 ตัวอย่างครอบคลุม 146 คู่ภาษาที่ทดสอบปรากฏการณ์ทางภาษา 68 อย่างที่แตกต่างกัน ACES ถูกใช้เพื่อ meta-evaluate เมตริกที่ส่งมายัง WMT metrics shared task — ทดสอบว่า *เมตริก* สามารถตรวจจับความแตกต่างได้หรือไม่ ไม่ใช่แค่ว่า *ระบบ* สามารถสร้างมันได้ ขยายไปยัง **SPAN-ACES** พร้อม error span annotations

**MT-GenEval** (Currey et al., EMNLP 2022) และ **WinoMT** (Stanovsky, Smith & Zettlemoyer, ACL 2019) กำหนดเป้าหมายความแม่นยำด้านเพศโดยเฉพาะ WinoMT น่าสังเกตเพราะใช้ **การวิเคราะห์สัณฐานวิทยา** บนภาษาเป้าหมายอย่างชัดเจนเพื่อตรวจสอบเพศของอาชีพที่แปล — หนึ่งในกรณีที่หายากที่ morphological analyser ถูกใช้เป็นส่วนหนึ่งของเครื่องมือประเมิน MT

**Hjerson** (Popović & Ney, 2011) เป็นเครื่องมือ open-source สำหรับการจัดประเภท error MT อัตโนมัติที่ใช้ **lemmas และ POS tags** เพื่อจัดประเภท error เป็นห้าประเภท: morphological, reordering, missing words, extra words และ lexical errors นี่อาจเป็นงานก่อนหน้าที่ใกล้เคียงกับ linter ของเราในแง่จิตวิญญาณมากที่สุด — มันใช้การวิเคราะห์ทางภาษาเพื่อให้หมวดหมู่ error เชิงวินิจฉัยแทนที่จะเป็นคะแนนเดียว

เส้นด้ายร่วม: สาขาวิชายอมรับซ้ำแล้วซ้ำเล่าว่าคะแนนรวมไม่เพียงพอ การประเมินเชิงวินิจฉัยให้ความละเอียดที่จำเป็นในการเข้าใจว่า *ทำไม* ระบบจึงล้มเหลว แต่แนวทางเชิงวินิจฉัยต้องการความเชี่ยวชาญทางภาษาต่อภาษา และความเชี่ยวชาญนั้นกระจุกตัวอยู่ในภาษายุโรป

### AmericasNLP: การประเมินในสนามรบ

ชุดการประชุม AmericasNLP workshop (ร่วมกับ NAACL) ที่มุ่งเน้น NLP สำหรับภาษาพื้นเมืองของทวีปอเมริกา ให้จุดเปรียบเทียบที่ตรงที่สุดสำหรับความท้าทายการประเมินของเรา

ตั้งแต่ปี 2021 ถึง 2023 shared task ใช้ **chrF** เป็นเมตริกการประเมินหลัก — เลือกเพราะความทนทานในการตั้งค่าทรัพยากรน้อยและการจับคู่ระดับตัวอักษรซึ่งให้เครดิตบางส่วนสำหรับการทับซ้อนทางสัณฐานวิทยา ผู้จัดงานยอมรับข้อจำกัดของ chrF แต่ไม่มีทางเลือกที่ดีกว่าที่สามารถทำงานข้ามประเภทที่หลากหลายที่แสดง (Quechua, Guaraní, Aymara, Nahuatl, Rarámuri และอื่นๆ)

ในปี 2025 AmericasNLP แนะนำ **Shared Task 3** เฉพาะสำหรับการพัฒนาเมตริกการประเมิน MT สำหรับภาษาพื้นเมือง — เป็นครั้งแรกที่สาขาวิชายอมรับอย่างชัดเจนว่าเมตริกที่มีอยู่ไม่เพียงพอสำหรับภาษาเหล่านี้ การส่งที่ชนะ **FUSE** (Feature-Union Scorer) รวม multilingual sentence embeddings (fine-tuned LaBSE) ความคล้ายคลึงทางคำศัพท์ ความคล้ายคลึงทางสัทศาสตร์ และ fuzzy token matching ผ่าน Ridge regression และ Gradient Boosting FUSE ไม่ใช้ morphological analysers — feature engineering เป็น language-agnostic

นี่คือช่องว่างที่งานของเราครอบครอง AmericasNLP ระบุปัญหา (เมตริกมาตรฐานล้มเหลวสำหรับภาษาพื้นเมือง) และเริ่มพัฒนาทางเลือก (FUSE) แต่ไม่มีทางเลือกใดที่ใช้ความรู้ทางสัณฐานวิทยาที่ FSTs ให้ ชุมชน AmericasNLP ใช้ chrF++ เพราะเป็นตัวเลือกทั่วไปที่ดีที่สุดที่มีอยู่ ในขณะที่ชุมชน GiellaLT สร้างเครื่องมือสัณฐานวิทยาที่ซับซ้อนซึ่งไม่เคยถูกเชื่อมต่อเข้ากับการประเมิน MT ทั้งสองชุมชนยังไม่ได้รวมกัน

## ส่วนที่ 4: การประเมินแบบ Reference-Free และ Quality Estimation

สัญญาณการประเมินที่สำคัญที่สุดบางส่วนใน harness ของเราไม่ต้องการการแปลอ้างอิงเลย การตรวจสอบความถูกต้องของ FST ("นี่เป็นคำจริงหรือไม่?") ต้องการเพียง MT output เท่านั้น ตัวตรวจจับ hallucination ต้องการต้นฉบับและ hypothesis ตัวตรวจจับ code-switching ต้องการเพียง hypothesis และความรู้เกี่ยวกับ script ของภาษาเป้าหมาย การเข้าใจว่าสิ่งเหล่านี้อยู่ที่ไหนในภูมิทัศน์ที่กว้างขึ้นของการประเมินแบบ reference-free เป็นสิ่งจำเป็นสำหรับการวางตำแหน่งอย่างถูกต้อง

### กระบวนทัศน์ Quality Estimation

**Quality Estimation (QE)** เป็นสาขาย่อยของการประเมิน MT ที่เกี่ยวข้องกับการทำนายคุณภาพการแปล *โดยไม่มี* การแปลอ้างอิง มันเป็น shared task เฉพาะที่ WMT ตั้งแต่ปี 2012 โดยได้รับแรงจูงใจจากความต้องการในทางปฏิบัติในการประเมินคุณภาพ MT ในเวลาที่ deploy — เมื่อคุณกำลังแปลข้อความใหม่และไม่มีข้อความอ้างอิงของมนุษย์เพื่อเปรียบเทียบ

งาน QE ได้พัฒนาผ่านสามรุ่น **Feature-based QE** (2012–2016) ดึง features ที่สร้างด้วยมือจากต้นฉบับและ hypothesis — language model perplexity ความถี่คำ การทับซ้อน n-gram กับข้อมูล monolingual — และฝึก classifiers เพื่อทำนายคุณภาพ **Neural QE** (2017–2021) แทนที่ features ที่สร้างด้วยมือด้วย learned representations โดยทั่วไปใช้ bilingual encoders **QE ปัจจุบัน** (2022–ปัจจุบัน) ถูกครอบงำโดยแนวทางที่อิง COMET โดยเฉพาะ **CometKiwi**

### CometKiwi และ Reference-Free COMET

**CometKiwi** (Rei et al., WMT 2022) ตัวแปร reference-free ของ COMET ใช้ InfoXLM เพื่อเข้ารหัสประโยคต้นฉบับและ MT hypothesis (โดยไม่มีข้อความอ้างอิง) และทำนายคะแนนคุณภาพ มันบรรลุผลลัพธ์ state-of-the-art ใน WMT 2022 และ 2023 QE shared tasks

ผลการค้นพบที่น่าทึ่ง: reference-free CometKiwi เข้าใกล้ความสัมพันธ์กับการตัดสินของมนุษย์ที่บรรลุโดย reference-based COMET สิ่งนี้แนะนำว่าสำหรับภาษาที่มีทรัพยากรดี ข้อความต้นฉบับมีสัญญาณการประเมินเกือบเท่ากับการแปลอ้างอิง แต่ข้อแม้เดียวกันใช้: encoder ของ CometKiwi มีการแสดงน้อยมากสำหรับภาษาที่มีทรัพยากรน้อย ดังนั้นการทำนาย reference-free สำหรับ Cree หรือ Sámi จึงไม่น่าเชื่อถือ

นี่คือจุดที่เมตริกที่อิง FST ของเราเสนอสิ่งที่แตกต่างอย่างแท้จริง การตรวจสอบความถูกต้องของ FST เป็น **สัญญาณคุณภาพ reference-free แบบ deterministic** ที่ไม่ต้องการโมเดลที่ฝึกและไม่มีข้อมูลการตัดสินของมนุษย์ หาก FST บอกว่าคำหนึ่งไม่ใช่คำ Cree ที่ถูกต้อง คำนั้นก็ไม่ใช่คำ Cree ที่ถูกต้อง — โดยมีข้อแม้ของการปฏิเสธเท็จสำหรับ loanwords, neologisms และ proper nouns สัญญาณคุณภาพแบบ hard, rule-based ประเภทนี้ไม่มีสิ่งเทียบเท่าในระบบนิเวศ neural QE

### การตรวจจับ Hallucination ใน MT

Hallucination ใน MT — ผลลัพธ์ที่คล่องซึ่งไม่เกี่ยวข้องกับต้นฉบับเลย — เป็นโหมดความล้มเหลวที่ร้ายแรง โดยเฉพาะในการตั้งค่าทรัพยากรน้อยที่โมเดลมีข้อมูลฝึกสอนไม่เพียงพอในการเรียนรู้การโต้ตอบต้นฉบับ-เป้าหมายที่เชื่อถือได้

สถานะทางวิชาการของศิลปะในการตรวจจับ hallucination ใช้แนวทางหลายอย่าง:

- **การตรวจจับที่อิง embedding**: เปรียบเทียบ embeddings ต้นฉบับและ hypothesis ในพื้นที่ร่วม (LASER, LaBSE) และทำเครื่องหมายกรณีที่ความคล้ายคลึงต่ำกว่าเกณฑ์
- **การตรวจจับที่อิงความน่าจะเป็น**: ใช้คะแนนความเชื่อมั่นของโมเดล MT เอง — hallucinations มักมีความน่าจะเป็น output สูงแต่ความน่าจะเป็นที่มีเงื่อนไขต้นฉบับต่ำ
- **Contrastive perturbation**: เปรียบเทียบ MT output สำหรับต้นฉบับจริงกับ output สำหรับต้นฉบับที่รบกวนหรือไม่เกี่ยวข้อง หาก output คล้ายกันอย่างน่าสงสัย โมเดลกำลังละเลยต้นฉบับ
- **LLM-as-judge**: Prompt LLM เพื่อประเมินว่าการแปลซื่อสัตย์ต่อต้นฉบับหรือไม่

harness ของเราใช้ **heuristic detection plugin** ที่รวมสัญญาณสี่อย่าง: length inflation (hypothesis ยาวกว่าที่คาดมาก) repetition (วลีซ้ำ) entity mismatch (named entities ในต้นฉบับที่หายไปจาก hypothesis) และ source echo (hypothesis คล้ายกับข้อความต้นฉบับมากเกินไป แนะนำการคัดลอกที่ไม่ได้แปล) นี่เป็นระดับ baseline เมื่อเทียบกับ academic SOTA — มันจับ hallucinations ที่ร้ายแรงแต่จะพลาดรายการที่ละเอียดอ่อน คุณค่าของมันอยู่ที่การเป็น **หน้าจอที่ถูก รวดเร็ว และ reference-free** ที่สามารถทำเครื่องหมายความล้มเหลวที่เลวร้ายที่สุดโดยไม่ต้องใช้ GPU หรือการเรียก API

### การตรวจจับ Code-Switching

Code-switching ใน MT output — ที่ระบบสร้างคำในภาษาต้นฉบับแทนที่จะแปล — เป็นโหมดความล้มเหลวที่แตกต่างจาก hallucination โดยทั่วไปเกิดขึ้นเมื่อโมเดลพบคำที่ไม่สามารถแปลได้และกลับไปคัดลอกต้นฉบับ

plugin การตรวจจับ code-switching ของเราใช้ **Unicode block analysis** (ตรวจจับตัวอักษรจาก script ของภาษาต้นฉบับในสิ่งที่ควรเป็น output ภาษาเป้าหมาย) และ **common-word lists** (ระบุคำความถี่สูงในภาษาต้นฉบับที่ปรากฏโดยไม่ได้แปล) สำหรับ Cree ซึ่งใช้ทั้ง SRO (Latin-based) และ syllabics สิ่งนี้ต้องการความระมัดระวัง — English และ SRO ใช้ Latin script ร่วมกัน ดังนั้น Unicode block analysis เพียงอย่างเดียวจึงไม่เพียงพอ

วรรณกรรมทางวิชาการเกี่ยวกับการตรวจจับ code-switching ใน MT นั้นน้อยเมื่อเทียบกับการตรวจจับ hallucination งานส่วนใหญ่มุ่งเน้นที่ code-switching ใน *input* text (ผู้พูดสองภาษาที่ผสมภาษา) แทนที่จะเป็นใน *output* text (ระบบ MT ที่ล้มเหลวในการแปล) แนวทาง heuristic ของเราตามความรู้ของเราไม่ได้ล้าหลังอย่างมีนัยสำคัญจาก state of the art ที่ตีพิมพ์ใดๆ สำหรับปัญหาเฉพาะนี้

## ส่วนที่ 5: ช่องว่างทางสัณฐานวิทยา

### สิ่งที่เมตริกที่มีอยู่มองไม่เห็น

นี่คือข้อโต้แย้งหลักของบทความนี้ และต้องการการสาธิตที่เป็นรูปธรรม

พิจารณาคู่ประโยค Plains Cree:

| | ข้อความ |
|--|------|
| **ต้นฉบับ (English)** | "I saw the man" |
| **อ้างอิง (Cree)** | *nikî-wâpamâw nâpêw* |
| **Hypothesis A** | *nâpêw nikî-wâpamâw* |
| **Hypothesis B** | *nikî-wâpamikow nâpêsis* |

**Hypothesis A** เป็นการแปลที่สมบูรณ์แบบ — มีคำเดียวกันในลำดับที่แตกต่างกัน ซึ่งถูกต้องตามไวยากรณ์ใน Cree (ลำดับคำอิสระ) **Hypothesis B** หมายความว่า "เด็กชายถูกฉันมองเห็น" — ทิศทางของการกระทำผิด (*-ikow* เป็น inverse) ผู้อ้างอิงผิด (*nâpêsis* = "เด็กชาย" ไม่ใช่ "ผู้ชาย")

| เมตริก | Hypothesis A (ถูกต้อง) | Hypothesis B (ผิด) | สามารถแยกแยะได้หรือไม่? |
|--------|----------------------|---------------------|------------------------|
| BLEU | ~30% | ~20% | แทบไม่ได้ |
| chrF++ | ~65% | ~55% | บ้าง |
| COMET | ไม่ทราบ (ไม่มีข้อมูลฝึกสอน Cree) | ไม่ทราบ | ไม่น่าเชื่อถือ |
| **FST acceptance** | 100% | 100% | ไม่ (ทั้งคู่เป็น Cree ที่ถูกต้อง) |
| **Linter** | EQUIVALENT (WORD_ORDER) | MISS | **ใช่** |
| **Semantic validator** | VALID | WRONG | **ใช่** |

linter และ semantic validator ประสบความสำเร็จในขณะที่ BLEU, chrF++ และ COMET ล้มเหลว — ไม่ใช่เพราะพวกมันเป็น "เมตริกที่ดีกว่า" ในความหมายสากล แต่เพราะพวกมันมีการเข้าถึง *ความรู้ทางภาษา* ที่เมตริกการจับคู่สตริงและ neural ไม่มี พวกมันรู้ว่า Cree มีลำดับคำอิสระ พวกมันรู้ว่า *wâpamêw* และ *wâpamikow* เป็น lemmas ที่แตกต่างกันพร้อมโครงสร้าง argument ที่แตกต่างกัน พวกมันรู้ว่า *nâpêw* และ *nâpêsis* เป็นคำที่แตกต่างกัน

ความรู้นี้มาจาก FST (ซึ่งเข้ารหัสไวยากรณ์สัณฐานวิทยา) พจนานุกรมสองภาษา (ซึ่งให้ English glosses สำหรับแต่ละ lemma) และ variant classes ที่กำหนดด้วยมือ (ซึ่งเข้ารหัสกฎความเท่าเทียมที่อิงภาษาศาสตร์) ไม่มีความรู้ใดที่มีให้กับเมตริกที่ถือว่าการแปลเป็นสตริง

### เหตุใดสาขาวิชาจึงไม่ได้แก้ไขสิ่งนี้

ช่องว่างทางสัณฐานวิทยาในการประเมิน MT ไม่ใช่ความลึกลับ สาขาวิชารู้ว่ามันมีอยู่ เหตุผลที่มันยังคงอยู่เป็นโครงสร้าง:

1. **อคติต่อขนาด** ชุมชนการประเมิน MT เพิ่มประสิทธิภาพสำหรับเมตริกที่ทำงานข้ามคู่ภาษา WMT ทั้งหมด เมตริกที่อิง FST ทำงานสำหรับ ~30 ภาษา COMET ทำงานสำหรับ 100+ chrF++ ทำงานสำหรับทุกภาษาที่มีระบบการเขียน ชุมชนให้รางวัลความเป็นสากลมากกว่าความแม่นยำ

2. **ไซโลชุมชน** คนที่สร้าง FSTs (นักภาษาศาสตร์เชิงคำนวณที่ UiT Tromsø, NRC Canada, University of Alberta) และคนที่สร้างเมตริกการประเมิน (นักวิจัย ML ที่ Google, Unbabel, WMT) เข้าร่วมการประชุมที่แตกต่างกัน ตีพิมพ์ในสถานที่ที่แตกต่างกัน และดำเนินการภายใต้โครงสร้างแรงจูงใจที่แตกต่างกัน การผสมข้ามสายพันธุ์ที่จำเป็นในการสร้างเมตริกการประเมินที่อิง FST ยังไม่เกิดขึ้น — ไม่ใช่เพราะมันถูกลองและล้มเหลว แต่เพราะชุมชนไม่เคยรวมกัน

3. **ความวิตกกังวลเรื่องการครอบคลุม** FSTs มีปัญหาการปฏิเสธเท็จที่รู้จัก: loanwords, neologisms และ proper nouns อาจถูกปฏิเสธว่าไม่ถูกต้องแม้ว่าจะยอมรับได้อย่างสมบูรณ์ สิ่งนี้ทำให้นักวิจัยกังวลเกี่ยวกับการใช้ FSTs เป็นเมตริก — การปฏิเสธเท็จทำให้อัตราข้อผิดพลาดสูงขึ้น ความกังวลนั้นถูกต้องแต่วัดได้: การวัดอัตราการปฏิเสธเท็จบนข้อความที่รู้ว่าดีนั้นตรงไปตรงมา

4. **ความต้องการไม่เพียงพอ** มีคนน้อยมากที่สร้าง MT สำหรับภาษา polysynthetic และคนที่ทำ (ALT Lab, NRC, ผู้เข้าร่วม AmericasNLP) มักใช้ chrF++ เพราะนั่นคือสิ่งที่มีอยู่ ยังไม่มีการผลักดันอย่างเป็นรูปธรรมจากชุมชน MT ทรัพยากรน้อยสำหรับการประเมินที่ตระหนักถึงสัณฐานวิทยา ส่วนหนึ่งเพราะชุมชนมีขนาดเล็กและส่วนหนึ่งเพราะการสร้างเมตริกดังกล่าวต้องการความเชี่ยวชาญทั้งใน NLP engineering และสัณฐานวิทยาของภาษาเป้าหมายเฉพาะ

5. **สมมติฐานเมตริก neural** สมมติฐานที่แพร่หลายตั้งแต่ปี 2020 คือเมตริก neural จะแก้ปัญหาสัณฐานวิทยาในที่สุดผ่าน learned representations หากคุณฝึก COMET บนข้อมูลเพียงพอจากภาษาที่มีสัณฐานวิทยาซับซ้อน ข้อโต้แย้งก็คือมันจะเรียนรู้การจัดการการเปลี่ยนแปลงทางสัณฐานวิทยาโดยปริยาย สิ่งนี้อาจเป็นจริงสำหรับภาษาที่มีสัณฐานวิทยาซับซ้อนที่มีทรัพยากรสูง (Finnish, Turkish, Czech) ไม่น่าจะเป็นจริงสำหรับภาษาที่มีการแสดงเป็นศูนย์อย่างมีประสิทธิภาพในข้อมูลฝึกสอน

## ส่วนที่ 6: LYSS — ทางเลือกที่อิงภาษาศาสตร์

### สิ่งที่ champollion สร้าง: LYSS (Linguistically-informed Yield & Structural Scoring)

harness การประเมินของโครงการ champollion ใช้กรอบการให้คะแนนแบบผสมที่เรียกว่า **LYSS** ซึ่งรวมเมตริกมาตรฐาน (chrF++, exact match) กับสี่หมวดหมู่ของเมตริกที่อิงภาษาศาสตร์ ชื่อสะท้อนถึงจุดเน้นของกรอบงาน: การวัด *yield* (ความหมายที่รอดผ่านกระบวนการแปลมากเพียงใด) ผ่าน *structural scoring* (การตรวจสอบแบบ deterministic ที่อิงภาษาศาสตร์แทนที่จะเป็น learned embeddings)

#### 1. Morphological Validity Gate (GiellaLT FST Metric)

เมตริกที่เรียบง่ายที่สุดและนำไปใช้ได้กว้างขวางที่สุด: ป้อนทุกคำของ MT output ผ่าน GiellaLT finite-state morphological analyser สำหรับภาษาเป้าหมาย หาก FST สามารถ parse คำได้ (คืนการวิเคราะห์อย่างน้อยหนึ่งรายการ) คำนั้นถูกต้องทางสัณฐานวิทยา หากไม่ คำนั้นไม่มีอยู่ในภาษาเป้าหมาย — มันเป็นคำที่สร้างขึ้น ข้อผิดพลาดทางสัณฐานวิทยา การสะกดผิด หรือ loanword ที่ไม่อยู่ใน lexicon

**Output:** `fst_validity_rate` (0.0–1.0 สูงกว่า = ดีกว่า) Macro-average (ค่าเฉลี่ยของอัตราต่อรายการ) และ micro-average (คำที่ถูกต้องทั้งหมด / คำทั้งหมด)

**Dependencies:** `pyhfst` (Helsinki Finite-State Technology Python bindings) ไฟล์ analyser `.hfstol` ที่คอมไพล์แล้วสำหรับภาษาเป้าหมาย

**Extensibility:** ทำงานสำหรับภาษาใดก็ตามที่มี GiellaLT FST analyser — ปัจจุบัน 30+ ภาษา ส่วนใหญ่เป็น Sámi, Uralic และภาษาพื้นเมืองอาร์กติก

**ความสัมพันธ์กับงานก่อนหน้า:** MorphEval ทดสอบว่าระบบสามารถจัดการความแตกต่างเฉพาะได้หรือไม่ เมตริก FST ทดสอบว่า output ของระบบประกอบด้วยคำจริงหรือไม่ สิ่งเหล่านี้เสริมกัน: MorphEval ทดสอบความสามารถ เมตริก FST ทดสอบความถูกต้อง

#### 2. Linguistic Equivalence Classes (CRK Linter)

linter แก้ไขสิ่งที่อาจเป็นโหมดความล้มเหลวที่ร้ายแรงที่สุดของการประเมินที่อิงข้อความอ้างอิง: **การลงโทษการแปลที่ถูกต้องซึ่งแตกต่างจากข้อความอ้างอิง**

Plains Cree linter (844 บรรทัด) ใช้ **variant classes** หกคลาส แต่ละคลาสเข้ารหัสกฎความเท่าเทียมที่อิงภาษาศาสตร์:

- **WORD_ORDER**: Cree มีลำดับคำที่อิสระตามหลักปฏิบัติ (Wolfart, 1973 §3.2) *nikî-wâpamâw nâpêw* และ *nâpêw nikî-wâpamâw* มีความหมายเหมือนกัน linter สร้างการเรียงสับเปลี่ยนทั้งหมดและตรวจสอบว่า hypothesis ตรงกับรายการใดรายการหนึ่ง
- **ORTHOGRAPHIC**: Standard Roman Orthography มีจุดการเปลี่ยนแปลงที่รู้จัก — circumflex กับ macron (*â* กับ *ā*) การใส่ยัติภังค์ของ preverbs (*nikî-nipâw* กับ *nikî nipâw* กับ *nikînipâw*) linter ทำให้สิ่งเหล่านี้เป็นมาตรฐาน
- **OPTIONAL_PARTICLE**: discourse particles บางอย่าง (*mâka*, *êkwa*, *êwako*) สามารถมีหรือไม่มีก็ได้โดยไม่เปลี่ยนข้อเสนอหลัก linter ตรวจสอบว่า hypothesis ตรงกับข้อความอ้างอิงหลังจากลบ particle ออก
- **LEMMA_SYNONYM**: lemmas Cree บางรายการสามารถใช้แทนกันได้ในบริบทเฉพาะ สิ่งนี้ใช้รายการคำพ้องความหมายที่ดูแลรักษา (เช่น ตัวแปรตามภาษาถิ่น) และเมื่อ FST พร้อมใช้งาน ตรวจสอบว่า hypothesis และข้อความอ้างอิงใช้การวิเคราะห์สัณฐานวิทยาร่วมกันหรือไม่
- **PROGRESSIVE_AMBIGUITY**: รูปแบบ progressive ของ English ("is walking") สามารถแปลเป็น Cree โดยใช้โครงสร้างที่แตกต่างกัน linter รับรู้ว่าสิ่งเหล่านี้เท่าเทียมกัน
- **INCLUSIVE_EXCLUSIVE**: Cree แยกแยะ "we" แบบ inclusive (*ki-* prefix) จาก "we" แบบ exclusive (*ni-* prefix) — ความแตกต่างที่ English รวมเป็น pronoun เดียว linter รับรู้ว่ารูปแบบใดก็ตามอาจถูกต้องเมื่อต้นฉบับ English กำกวม

linter สร้างคำตัดสินสามรายการ: **EXACT** (hypothesis ตรงกับข้อความอ้างอิง) **EQUIVALENT** (hypothesis แตกต่างแต่จัดประเภทเป็นตัวแปรที่ถูกต้อง) หรือ **MISS** (ไม่พบการจับคู่) ในระดับรวม มันคำนวณ `equivalent_match_rate` — สัดส่วนของการแปลที่แน่นอนหรือเท่าเทียมกัน

**ความสัมพันธ์กับงานก่อนหน้า:** ความคล้ายคลึงที่ใกล้เคียงที่สุดคือ **HyTER** (Dreyer & Marcu, NAACL-HLT 2012) ซึ่งเข้ารหัสการแปลที่ถูกต้องจำนวนมากอย่างเอกซ์โปเนนเชียลเป็น paraphrase networks และวัด edit distance ไปยังรูปแบบที่ถูกต้องที่ใกล้ที่สุด linter ของเราคล้ายกันในเชิงแนวคิด — มันกำหนดชุดการแปลที่ถูกต้องสำหรับแต่ละข้อความอ้างอิง — แต่ใช้กฎการแปลงที่กำหนดทางภาษาศาสตร์แทนฐานข้อมูล paraphrase HyTER ถูกออกแบบสำหรับ English ไม่มีใครสร้าง paraphrase networks สำหรับ Cree variant classes ของเราเป็นการประมาณแบบ compact, rule-based ของสิ่งที่ HyTER ทำด้วย graphs

ในกรอบงาน CheckList variant classes ของเราทำหน้าที่เป็น **invariance tests**: การแปลงที่ไม่ควรเปลี่ยนคำตัดสินการประเมิน ความแตกต่างคือการทดสอบ CheckList มักถูกนำไปใช้กับ *โมเดล* กฎตัวแปรของเราถูกนำไปใช้กับ *เมตริก*

#### 3. Deterministic Semantic Validation (CRK Semantic Metric)

semantic validator (792 บรรทัด) พยายามทำสิ่งที่ทะเยอทะยานกว่า: **การเปรียบเทียบความหมายแบบ deterministic** โดยไม่มี neural embeddings มันทำงานในสี่ขั้นตอน:

1. **การวิเคราะห์ทางสัณฐานวิทยา**: ทั้งข้อความสมมติฐานและข้อความอ้างอิงจะถูกส่งผ่านตัววิเคราะห์ CRK FST ซึ่งจะส่งคืนคำหลัก (lemma) และคุณลักษณะทางสัณฐานวิทยาสำหรับแต่ละคำ
2. **การหาคำอธิบายความหมาย**: คำหลักแต่ละคำจะถูกค้นหาผ่าน API พจนานุกรม itwêwina — ซึ่งให้บริการพจนานุกรม Wolvengrey (2001) ควบคู่ไปกับพจนานุกรม Maskwacîs และ Alberta Elders — เพื่อรับคำอธิบายความหมายภาษาอังกฤษ
3. **การสกัดคำเนื้อหา**: โดยใช้ไปป์ไลน์ภาษาอังกฤษของ spaCy (`en_core_web_md`) คำไวยากรณ์จะถูกกรองออกจากทั้งคำอธิบายความหมายภาษาอังกฤษและข้อความต้นฉบับ
4. **การให้คะแนนความทับซ้อน**: ความทับซ้อนของคำเนื้อหาระหว่างคำอธิบายความหมายของข้อความสมมติฐานและคำอธิบายความหมายของข้อความอ้างอิงจะเป็นตัวกำหนดผลการตัดสินทางความหมาย

validator สร้างคำตัดสินแบบหมวดหมู่: **EXACT_MATCH**, **VALID** (คำที่แตกต่างแต่ความหมายเดียวกัน), **GRAMMAR_ISSUES** (lemmas ที่ถูกต้องแต่มีปัญหาไวยากรณ์ระดับประโยค — agreement, animacy, verb form), **PARTIAL** (รักษาความหมายบางส่วน), **INCOMPLETE** (ความหมายหายไปบางส่วน), **WRONG** (ความหมายต่างกัน) หรือ **NO_OUTPUT**

**ความสัมพันธ์กับงานก่อนหน้า:** นี่คือ **การประมาณแบบ deterministic ของการคำนวณความคล้ายคลึงเชิงความหมายของ COMET** ในขณะที่ COMET ใช้ cross-lingual embeddings ที่เรียนรู้เพื่อประเมินว่าสองประโยคมีความหมายเหมือนกันหรือไม่ validator ของเราใช้ chain ของการค้นหาแบบ deterministic: FST → dictionary → spaCy ข้อดีคือความโปร่งใส (ทุกขั้นตอนสามารถตรวจสอบและ deterministic ได้) และความเป็นอิสระจากข้อมูลฝึกสอน ข้อเสียคือความเปราะบาง: คุณภาพของการประเมินขึ้นอยู่กับการครอบคลุมของ FST และความสมบูรณ์ของพจนานุกรมทั้งหมด

แนวทางนี้มีความเกี่ยวข้องในเชิงแนวคิดกับ **MEANT** (Lo & Wu, 2011; Lo, 2017) ซึ่งใช้ semantic role labelling เพื่อประเมินว่าโครงสร้าง "ใครทำอะไรกับใคร" ถูกรักษาไว้ในการแปลหรือไม่ แนวทางของเราหยาบกว่า (การทับซ้อนของ content-word แทนที่จะเป็น semantic roles) แต่ทำงานบนภาษาที่ไม่มีเครื่องมือ SRL

#### 4. Behavioral Detection Plugins (Hallucination, Code-Switching, Terminology)

plugins เพิ่มเติมสามรายการให้ **สัญญาณคุณภาพพฤติกรรม** ที่เสริมเมตริกสัณฐานวิทยา:

- **Hallucination detection** (259 บรรทัด): สัญญาณ heuristic สี่อย่างที่ถ่วงน้ำหนักและรวมกัน — length inflation (40%), repetition (30%), entity mismatch (20%), source echo (10%) สิ่งเหล่านี้เป็นหน้าจอที่ถูกและ reference-free ที่จับการสร้างขึ้นอย่างร้ายแรง
- **Code-switching detection** (~280 บรรทัด): Unicode block analysis บวก common-word lists เพื่อตรวจจับ tokens ภาษาต้นฉบับที่ไม่ได้แปล คืน `code_switching_rate` (0.0–1.0)
- **Terminology adherence** (199 บรรทัด): ตรวจสอบว่าคำศัพท์ glossary ที่ระบุถูกแปลอย่างสอดคล้องกัน คืน `terminology_adherence` (0.0–1.0) หรือ None หากไม่มีการกำหนดค่า glossary

plugins เหล่านี้ถูกวางตำแหน่งอย่างซื่อสัตย์ว่าเป็น **baseline heuristic detectors** ไม่ใช่ state-of-the-art คุณค่าของพวกมันอยู่ที่การให้สัญญาณที่ถูก รวดเร็ว และตีความได้ซึ่งสามารถคำนวณควบคู่กับเมตริกสัณฐานวิทยาที่ซับซ้อนกว่า ในกรอบการให้คะแนนแบบผสม พวกมันมีน้ำหนักต่ำ (0.05 แต่ละรายการ)

### ข้อจำกัดที่ซื่อสัตย์

แนวทางนี้มีข้อจำกัดที่สำคัญที่ต้องยอมรับก่อนการอ้างความแปลกใหม่หรือประโยชน์ใดๆ:

1. **อัตราการปฏิเสธเท็จของ FST** FST จะปฏิเสธคำที่ถูกต้องซึ่งไม่อยู่ใน lexicon — loanwords, neologisms, proper nouns, คำที่ผสมรหัส สิ่งนี้ทำให้อัตราข้อผิดพลาดทางสัณฐานวิทยาสูงขึ้น อัตราการปฏิเสธเท็จยังไม่ได้รับการวัดอย่างเป็นทางการบน corpus ที่เป็นตัวแทนของข้อความ Cree โดยไม่มีการวัดนี้ ความแม่นยำของเมตริกความถูกต้องของ FST ยังไม่ทราบ

2. **ความครอบคลุมของพจนานุกรม** คุณภาพของตัวตรวจสอบความหมายขึ้นอยู่กับความครอบคลุมของพจนานุกรม Wolvengrey อย่างสิ้นเชิง คำภาษา Cree ที่ไม่มีอยู่ในพจนานุกรมจะไม่สร้างคำอธิบายความหมายใดๆ ซึ่งตัวตรวจสอบจะถือว่าเป็นช่องโหว่ทางความหมาย พจนานุกรมมีรายการคำศัพท์ประมาณ 18,000–22,000 รายการ (จำนวนแตกต่างกันไปตามฉบับและวิธีการนับ) — ซึ่งถือว่ามีจำนวนมาก แต่ก็ยังไม่ครอบคลุมทั้งหมด

3. **ความสมบูรณ์ของ variant class** variant classes หกคลาสของ linter ถูกออกแบบตามวรรณกรรมทางภาษาศาสตร์และการสังเกตรูปแบบ MT output อาจมีหมวดหมู่ความเท่าเทียมเพิ่มเติมที่ไม่ได้จับ — ตัวแปรตามภาษาถิ่น ความแตกต่างของ register คำพ้องความหมายระดับ discourse ไม่มีกระบวนการที่เป็นทางการเพื่อรับรองความสมบูรณ์

4. **ไม่มีการศึกษาความสัมพันธ์กับมนุษย์** ช่องว่างที่สำคัญที่สุด: ไม่มีใครวัดว่าคำตัดสินของ linter (EXACT/EQUIVALENT/MISS) หรือคำตัดสินของ semantic validator สัมพันธ์กับการตัดสินคุณภาพการแปลของมนุษย์หรือไม่ เมตริก neural ใช้เวลาหลายปีในการสร้างความสัมพันธ์กับการประเมินของมนุษย์ (WMT shared tasks) เมตริกของเราไม่มีการตรวจสอบดังกล่าว

5. **ความเฉพาะเจาะจงของภาษา** variant classes รายการคำพ้องความหมาย และกฎ optional particle เฉพาะสำหรับ Plains Cree การ port ไปยัง North Sámi, Inuktitut หรือภาษาอื่นใดต้องการนักภาษาศาสตร์ที่เข้าใจสัณฐานวิทยา ความยืดหยุ่นของลำดับคำ และการเปลี่ยนแปลงทางอักขรวิธีของภาษานั้น *กรอบงาน* สามารถ port ได้ *กฎ* ไม่สามารถ

6. **ช่องว่างการเชื่อมต่อเมตริก** ณ เวลาที่เขียนนี้ เมตริกสี่รายการจากเก้ารายการในโปรไฟล์การให้คะแนนแบบผสม (semantic_score, morphological_accuracy, equivalent_match_rate, orthographic_accuracy) มีการเชื่อมต่อ plugin ที่ไม่สมบูรณ์หรือไม่ชัดเจนใน arena harness คะแนนแบบผสมถูกคำนวณจากประมาณห้าเมตริกพร้อมน้ำหนักที่กระจายใหม่

### สิ่งที่จำเป็นในการตรวจสอบแนวทางนี้

เพื่อให้งานนี้สามารถตีพิมพ์ได้ — ในสถานที่ใดก็ตาม ในระดับความจริงจังทางวิชาการใดก็ตาม — จำเป็นต้องมีการทดลองต่อไปนี้:

1. **การศึกษาความสัมพันธ์กับการตัดสินของมนุษย์** รวบรวมการประเมินคุณภาพของมนุษย์สำหรับชุดการแปล English→Cree (ควรมี 200+ คู่ประโยคที่ประเมินโดยผู้พูดสองภาษา 3+ คน) คำนวณความสัมพันธ์ระหว่างคะแนนของมนุษย์และแต่ละเมตริกของเรา นี่คือการตรวจสอบที่สำคัญที่สุดเพียงอย่างเดียว โดยไม่มีมัน เมตริกเป็นเพียง engineering artifacts ไม่ใช่เครื่องมือประเมิน

2. **การวัดอัตราการปฏิเสธเท็จของ FST** เรียกใช้ FST analyser บน corpus ของข้อความ Cree ที่รู้ว่าดี (เช่น ข้อความ Cree ที่ตีพิมพ์ parallel corpora ที่ตรวจสอบแล้ว) และวัดว่าคำที่ถูกต้องกี่เปอร์เซ็นต์ถูกปฏิเสธ สิ่งนี้วัดความแม่นยำของเมตริกความถูกต้องของ FST

3. **การตรวจสอบภาษาที่สอง** Port เมตริกความถูกต้องของ FST ไปยัง GiellaLT ภาษาที่สอง (น่าจะเป็น North Sámi ซึ่งมี FST analyser ที่สมบูรณ์ที่สุดในระบบนิเวศ GiellaLT) แสดงให้เห็นว่าเมตริกสร้างผลลัพธ์ที่สมเหตุสมผลบน Sámi MT output สิ่งนี้ตรวจสอบการอ้างสิทธิ์ extensibility

4. **การเปรียบเทียบกับ COMET** เรียกใช้ COMET บนข้อมูล Cree เดียวกันและเปรียบเทียบคะแนนกับเมตริกของเราและกับการตัดสินของมนุษย์ หาก COMET สร้างคะแนนที่มีความหมายสำหรับ Cree (ซึ่งเราสงสัย แต่ยังไม่ได้ทดสอบ) เมตริกของเราต้องเหนือกว่ามันเพื่อให้มีประโยชน์ หาก COMET สร้างสัญญาณรบกวน (ซึ่งเราคาดหวัง) สิ่งนี้ตรวจสอบความจำเป็นของแนวทางของเรา

5. **MorphEval diagnostic complement** สร้าง test suite แบบ MorphEval ขนาดเล็ก (50–100 contrasts) สำหรับ Plains Cree ที่กำหนดเป้าหมายคุณลักษณะสัณฐานวิทยาที่โดดเด่นที่สุดของภาษา (obviative, inverse, conjunct/independent, inclusive/exclusive, preverb chains) เรียกใช้ระบบ MT กับมันและแสดงว่าข้อมูลวินิจฉัยสามารถนำไปปฏิบัติได้

6. **การตรวจสอบการเชื่อมต่อและการรวม** แก้ไขช่องว่างการเชื่อมต่อโปรไฟล์การให้คะแนนที่ระบุในรายการ codebase ตรวจสอบให้แน่ใจว่าเมตริกแบบผสมทั้งเก้ารายการสร้างค่าและคะแนนรวมถูกคำนวณอย่างถูกต้อง

## ส่วนที่ 7: การวางตำแหน่งและงานในอนาคต

### LYSS อยู่ที่ไหนในภูมิทัศน์การประเมิน

อนุกรมวิธานของแนวทางการประเมิน MT ที่วางตำแหน่งอย่างซื่อสัตย์:

| มิติ | เมตริกสตริง (BLEU, chrF++) | เมตริก neural (COMET, MetricX) | LLM-as-judge (GEMBA) | เชิงวินิจฉัย (MorphEval, CheckList) | **LYSS** |
|-----------|-------------------------------|---|----|-------|--------|
| ประเภทสัญญาณ | การทับซ้อนพื้นผิว | ความคล้ายคลึงเชิงความหมายที่เรียนรู้ | การตัดสินแบบเปิด | การทดสอบความสามารถแบบมีเป้าหมาย | ความถูกต้องทางสัณฐานวิทยา + ความเท่าเทียมที่อิงกฎ |
| ข้อมูลฝึกสอนที่ต้องการ | ไม่มี | การตัดสินของมนุษย์ (หลายพัน) | LLM ที่ผ่านการฝึกล่วงหน้า | test suites ที่ออกแบบโดยนักภาษาศาสตร์ | FST + dictionary + variant rules |
| การนำไปใช้กับ LRL | สากลแต่อ่อนแอ | จำกัดโดยการครอบคลุม encoder | จำกัดโดยการครอบคลุม LLM | จำกัดโดยการสร้าง test suite | จำกัดโดยความพร้อมใช้งาน FST (~30 ภาษา) |
| ต้องการข้อความอ้างอิง | ใช่ | ใช่ (หรือ source-only QE) | ไม่บังคับ | ใช่ (contrastive) | ใช่ (LYSS-eq/LYSS-sem) / ไม่ (LYSS-fst) |
| ความสามารถในการตีความ | ต่ำ (ตัวเลข) | ต่ำ (ตัวเลข) | สูง (เหตุผลเป็นข้อความ) | สูง (pass/fail ต่อปรากฏการณ์) | สูง (คำตัดสิน + variant classes) |

**LYSS ไม่ใช่**: การแทนที่ COMET สำหรับภาษาที่มีทรัพยากรดี เมตริกสากล หรือการประเมินที่ตระหนักถึงสัณฐานวิทยารายการแรก

**LYSS คือ**: กรอบงานแบบบูรณาการที่รวม FST-based morphological validation กับเมตริกมาตรฐานสำหรับกรณีเฉพาะของภาษาที่เมตริก neural ขาดการครอบคลุมและเครื่องมือที่อิงกฎ (FSTs, dictionaries) มีอยู่ มีสามส่วนประกอบหลัก:
- **LYSS-fst** — ความถูกต้องทางสัณฐานวิทยาผ่าน FST (`fst_acceptance_rate`)
- **LYSS-eq** — ความเท่าเทียมทางภาษาผ่าน linter (`equivalent_match_rate`)
- **LYSS-sem** — การตรวจสอบความหมายแบบ deterministic (`semantic_score`)

**LYSS ขยาย**: ข้อมูลเชิงลึกหลักของ MorphEval (ใช้เครื่องมือสัณฐานวิทยาสำหรับการประเมิน) จากการทดสอบความสามารถเชิงวินิจฉัยไปสู่การให้คะแนนคุณภาพแบบต่อเนื่อง

**LYSS เสริม**: chrF++ (ซึ่งให้เครดิตบางส่วนสำหรับ morphemes ที่ใช้ร่วมกันแต่ไม่สามารถตรวจจับความเท่าเทียม), COMET (ซึ่งทำงานในพื้นที่เชิงความหมายแต่ขาดข้อมูลฝึกสอนสำหรับ LRL) และ FUSE (ซึ่งใช้ feature engineering แต่ไม่ใช่ morphological analysers)

**งานก่อนหน้าที่ใกล้เคียงที่สุดคือ**: Hjerson (การจัดประเภท error ทางภาษา) + HyTER (equivalence classes ผ่าน paraphrase networks) + เมตริกการครอบคลุมแบบ naive ของ Apertium (การตรวจสอบความถูกต้องที่อิง FST) การมีส่วนร่วมของ LYSS ไม่ใช่เทคนิคเดียวใดๆ แต่เป็นการรวมแนวคิดเหล่านี้ — โดยเฉพาะความถูกต้องที่อิง FST และความเท่าเทียมที่อิงกฎ — เข้าสู่ evaluation harness ที่ใช้งานได้สำหรับภาษา polysynthetic

### การรวม MorphEval

วิธีการ contrastive test suite ของ MorphEval และแนวทางการให้คะแนนแบบต่อเนื่องของเราเสริมกัน:

- **MorphEval** ตอบ: "ระบบนี้สามารถจัดการการทำเครื่องหมายกาลได้หรือไม่? การตกลงจำนวน? การกำหนด case?"
- **เมตริก FST ของเรา** ตอบ: "ระบบนี้สร้างคำจริงหรือไม่?"
- **linter ของเรา** ตอบ: "การแปลนี้เท่าเทียมกับข้อความอ้างอิงแม้จะมีความแตกต่างพื้นผิวหรือไม่?"
- **semantic validator ของเรา** ตอบ: "การแปลนี้มีความหมายที่ถูกต้องหรือไม่?"

MorphEval เป็น open source การสร้าง test suite สำหรับ Plains Cree จะต้องการนักภาษาศาสตร์ในการออกแบบคู่ contrastive ที่ครอบคลุมความแตกต่างทางสัณฐานวิทยาเฉพาะ Cree (obviation, inverse marking, conjunct/independent order, inclusive/exclusive "we," preverb chains) นี่เป็นงานที่มากพอสมควรแต่มีขอบเขต — สัปดาห์ ไม่ใช่เดือน — และจะให้ความสามารถเชิงวินิจฉัยที่ไม่มีเครื่องมือประเมินอื่นใดเสนอสำหรับ Cree

### คำถามเรื่อง Extensibility

ภาษาอื่นใดที่สามารถนำแนวทางนี้ไปใช้ได้? ข้อจำกัดหลักคือความพร้อมใช้งานของ FST โครงสร้างพื้นฐาน GiellaLT ให้ morphological analysers สำหรับ 30+ ภาษา ส่วนใหญ่ในสามตระกูล:

- **ภาษา Sámi** (North Sámi, Lule Sámi, South Sámi, Skolt Sámi, Inari Sámi): FSTs ที่สมบูรณ์พร้อมการครอบคลุมกว้าง North Sámi เป็นเป้าหมายที่ port ได้ทันทีที่สุด
- **ภาษา Uralic** (Finnish, Estonian, Komi, Erzya, Moksha): analysers ที่พัฒนาดี แม้ว่า Finnish และ Estonian อาจไม่ต้องการการประเมินที่อิง FST อย่างเร่งด่วน (พวกมันมีการครอบคลุมเมตริก neural มากกว่า)
- **ภาษาพื้นเมืองอาร์กติก** (Inuktitut ผ่าน Uqailaut, Greenlandic): analysers มีอยู่แต่การครอบคลุมแตกต่างกัน
- **ภาษา GiellaLT อื่นๆ**: Faroese, Irish, Cornish, Livonian และอื่นๆ ที่มีระดับความสมบูรณ์ของ FST ที่แตกต่างกัน

นอกเหนือจาก GiellaLT แพลตฟอร์ม **Apertium** ให้ morphological analysers สำหรับประมาณ 40+ คู่ภาษา ระบบนิเวศ **HFST** (Helsinki Finite-State Technology) เป็นโครงสร้างพื้นฐานที่ใช้ร่วมกันที่ทั้ง GiellaLT และ Apertium ใช้ ซึ่งหมายความว่า analyser ของ Apertium ใดๆ ก็สามารถเชื่อมต่อเข้ากับเมตริกความถูกต้องของ FST เดียวกันได้ในหลักการ

ข้อจำกัดในทางปฏิบัติไม่ใช่ความพร้อมใช้งานของ FST แต่เป็น **การดูแลรักษา variant class** กฎความเท่าเทียมของ linter ต้องการความเชี่ยวชาญทางภาษาต่อภาษาเป้าหมาย สำหรับ North Sámi สิ่งนี้จะต้องการความเข้าใจความยืดหยุ่นของลำดับคำ Sámi ข้อตกลงทางอักขรวิธี และการเปลี่ยนแปลงตามภาษาถิ่น สำหรับ Inuktitut จะต้องการความเข้าใจสัณฐานวิทยา polysynthetic ในระดับที่เทียบเคียงกับสิ่งที่ทำสำหรับ Cree อย่างไรก็ตาม เมตริกความถูกต้องของ FST สามารถ deploy ได้ทันทีสำหรับภาษาใดก็ตามที่มี GiellaLT analyser — ไม่ต้องการงานทางภาษาเพิ่มเติม

### สู่บทความ

การตีพิมพ์ที่อิงงานนี้จะกำหนดเป้าหมายสถานที่เหล่านี้ตามธรรมชาติ:

- **WMT Metrics Shared Task** (ร่วมกับ EMNLP): สถานที่ที่ตรงที่สุด จะต้องใช้เมตริกเป็น shared-task submission และประเมินบน WMT test sets — ซึ่งปัจจุบันไม่รวมภาษา polysynthetic ใดๆ สามารถส่งเป็นบทความ "findings" หรือเข้าร่วมใน challenge sets subtask
- **LREC-COLING** (Language Resources and Evaluation Conference): เหมาะสมตามธรรมชาติสำหรับบทความ resource/tool ที่อธิบายกรอบงานการประเมินและทรัพยากรทางภาษาที่ใช้ (FSTs, dictionaries, variant rules)
- **ACL หรือ NAACL** (main conference): จะต้องมีการศึกษาความสัมพันธ์กับมนุษย์และอย่างน้อยหนึ่งภาษาเพิ่มเติมเพื่อให้ถึงมาตรฐานสำหรับบทความ main conference
- **AmericasNLP workshop**: ผู้ฟังที่ตอบรับมากที่สุดสำหรับการประเมิน MT ภาษาพื้นเมือง มาตรฐานการตีพิมพ์ต่ำกว่า แต่มีผลกระทบสูงภายในชุมชนเป้าหมาย
- **ComputEL** (Computational Approaches to Endangered Languages): สถานที่ที่มุ่งเน้นสำหรับงานประเภทนี้โดยเฉพาะ

การตีพิมพ์ใดๆ จะต้องมีผู้เขียนร่วมที่มีความเชี่ยวชาญด้านภาษาศาสตร์ Cree (เพื่อตรวจสอบ variant classes และตีความผลลัพธ์) และควรมีผู้พูด Cree ที่พูดได้สองภาษา (เพื่อให้การประเมินคุณภาพของมนุษย์สำหรับการศึกษาความสัมพันธ์) สิ่งนี้ไม่ใช่ทางเลือก — บทความเกี่ยวกับการประเมิน MT ของ Cree ที่เขียนทั้งหมดโดยผู้ที่ไม่ใช่ผู้พูด Cree จะเป็น อย่างดีที่สุด ไม่สมบูรณ์ และอย่างเลวร้ายที่สุด เป็นการสืบต่อพลวัตการวิจัยแบบ extractive ที่สาขาวิชาพยายามก้าวข้าม

## ภาคผนวก C: อภิธานศัพท์การประเมิน

| คำศัพท์ | คำนิยาม |
|------|------------|
| **Adequacy** | การแปลถ่ายทอดความหมายของต้นฉบับหรือไม่ |
| **Fluency** | การแปลถูกต้องตามไวยากรณ์และเป็นธรรมชาติในภาษาเป้าหมายหรือไม่ |
| **Direct Assessment (DA)** | วิธีการประเมินของมนุษย์ที่ผู้ใส่คำอธิบายให้คะแนนการแปลในระดับ 0–100 |
| **MQM** | Multidimensional Quality Metrics — การประเมินของมนุษย์ที่อิง error-span พร้อมความรุนแรงที่จัดประเภท |
| **Quality Estimation (QE)** | การทำนายคุณภาพการแปลโดยไม่มีการแปลอ้างอิง |
| **FST** | Finite-State Transducer — อุปกรณ์เชิงคำนวณที่เข้ารหัสกฎสัณฐานวิทยาของภาษา |
| **GiellaLT** | โครงสร้างพื้นฐานสำหรับเทคโนโลยีภาษาที่อิงกฎ ส่วนใหญ่สำหรับ Sámi และภาษาอาร์กติกอื่นๆ |
| **HFST** | Helsinki Finite-State Technology — กรอบซอฟต์แวร์ที่เป็นพื้นฐานของ GiellaLT และ Apertium |
| **SRO** | Standard Roman Orthography — ระบบการเขียนที่อิง Latin สำหรับ Plains Cree |
| **Syllabics** | Canadian Aboriginal Syllabics — ระบบการเขียนแบบ abugida ที่ใช้สำหรับ Cree และภาษา Algonquian อื่นๆ |
| **Polysynthetic** | ประเภทภาษาที่คำเดียวสามารถเข้ารหัสเทียบเท่ากับประโยค English ทั้งประโยคผ่านการเติม affixes อย่างกว้างขวาง |
| **Obviation** | หมวดหมู่ทางไวยากรณ์ในภาษา Algonquian ที่แยกแยะระหว่างผู้อ้างอิงบุรุษที่สามสองคน |
| **Inverse** | หมวดหมู่คล้าย voice ในภาษา Algonquian ที่ทำเครื่องหมายว่า patient มีอันดับสูงกว่า agent ในลำดับชั้น animacy |
| **WMT** | Conference on Machine Translation — สถานที่หลักสำหรับ MT shared tasks และการประเมิน |
| **Contrastive evaluation** | การทดสอบว่าระบบสามารถแยกแยะ inputs ที่แตกต่างกันน้อยที่สุดซึ่งต้องการ outputs ที่แตกต่างกันได้หรือไม่ |
| **Challenge set** | test suite ที่สร้างขึ้นซึ่งกำหนดเป้าหมายปรากฏการณ์ทางภาษาเฉพาะ |
| **Equivalence class** | ชุดของรูปแบบพื้นผิวที่แตกต่างกันซึ่งแสดงถึงความหมายเดียวกันและควรได้รับคะแนนการประเมินเดียวกัน |
