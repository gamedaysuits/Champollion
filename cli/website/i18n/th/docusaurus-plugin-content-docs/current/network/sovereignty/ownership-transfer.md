# ความเป็นเจ้าของและข้อกำหนด

> **บทสรุปสำหรับผู้บริหาร** Champollion ไม่มีข้อตกลงฉบับครอบคลุม ซึ่งเป็นความตั้งใจในการออกแบบ
> ข้อกำหนดจะถูกกำหนดเป็นรายคลังข้อมูล รายภาษา และรายรางวัลโดยผู้ดูแลที่เป็นเจ้าของข้อมูล
> — หน้าที่ของแพลตฟอร์มคือเคารพข้อกำหนดเหล่านั้นไม่ว่าจะเป็นรูปแบบใด หน้านี้จะอธิบาย
> มิติต่าง ๆ ที่เอกสารข้อกำหนดครอบคลุม และ**เทมเพลตการส่งมอบให้ชุมชน**:
> จุดเริ่มต้นที่องค์กรกำกับดูแลของชุมชนสามารถนำไปปรับใช้และแก้ไขได้เมื่อเป็นผู้จัดประกวดรางวัลและเลือก
> ข้อกำหนด `pass_to_holders`

## กรอบข้อกำหนด

Champollion ถูกออกแบบให้มีความยืดหยุ่นในข้อกำหนด เพื่อให้ใบอนุญาตทั้งหมดได้รับการเคารพ
— และเพื่อให้รองรับการจัดการรูปแบบใหม่: corpus ที่เป็นความลับ
ชุดทดสอบที่ชุมชนถือครอง และข้อกำหนดการปรับใช้แบบอธิปไตย ภาษาต่าง ๆ
จะมีข้อตกลงที่แตกต่างกัน corpus ที่ใช้ CC0 corpus ของชุมชนเพื่อการวิจัยเท่านั้น
และชุดมาตรฐานทองคำที่ปิดผนึกซึ่งกำกับดูแลโดยสภาชนเผ่า ล้วนสามารถเข้าร่วมได้
ต่างคนต่างมีข้อกำหนดของตนเอง

สิ่งที่เป็นมาตรฐานเดียวกันคือกลไกที่ปฏิบัติตามข้อกำหนดเหล่านั้น: exposure lanes,
license gates, quarantine และการลงทะเบียน fetch-from-source (ดู
[การลงทะเบียน Corpora](/docs/network/sovereignty/registering-corpora)) สิ่งที่
*ไม่เคย* เป็นมาตรฐานเดียวกันคือตัวข้อตกลงเอง

เมื่อผู้ดูแล corpus กำหนดข้อกำหนด — สำหรับการเข้าร่วม benchmark สำหรับรางวัลที่ได้รับการสนับสนุน
หรือสำหรับสิ่งอื่นใด — เอกสารข้อกำหนดจะตอบคำถามชุดเล็ก ๆ ดังนี้:

| มิติ | คำถามสำคัญ |
|---|---|
| **การเปิดเผยคลังข้อมูล** | อยู่ในระดับใด — สาธารณะ, เพื่อการวิจัยเท่านั้น หรือส่วนตัว? มีการแสดงข้อความอ้างอิงหรือไม่? |
| **ความเป็นเจ้าของวิธีการ** | หากได้รับรางวัล ใครเป็นเจ้าของวิธีการที่ชนะ — ผู้พัฒนา, ชุมชน หรือเป็นเจ้าของร่วมกัน? |
| **การนำไปใช้งาน** | ใครสามารถนำวิธีการนี้ไปใช้งานได้บ้าง ที่ไหน และภายใต้เงื่อนไขใด? |
| **การโฮสต์ด้วยตนเอง** | วิธีการดังกล่าวต้องทำงานบนโครงสร้างพื้นฐานที่ชุมชนควบคุมทั้งหมดหรือไม่? |
| **การเก็บรักษาความลับ** | ชุดทดสอบถูกปิดผนึกไว้หรือไม่? ใครเป็นผู้ถือกุญแจ? ใครเป็นผู้อนุมัติการประเมินผลในแต่ละครั้ง? |
| **ค่าตอบแทน** | ผู้สร้าง, ผู้ตรวจสอบความถูกต้อง และผู้ตรวจทานได้รับค่าตอบแทนเท่าใด? (ค่าเริ่มต้นที่เผยแพร่: [การทำงานร่วมกับผู้พูดภาษา](/docs/working-with-speakers)) |

ไม่มีข้อใดที่แพลตฟอร์มกำหนดคำตอบ ค่าเริ่มต้นด้านล่างเป็นเพียงแม่แบบ
ไม่ใช่กฎ

## เทมเพลตการส่งมอบให้ชุมชน

ผู้จัดประกวดแบบปิดผนึกจะเลือกหนึ่งในสามข้อกำหนดของรางวัล — `pass_to_holders`,
`retain_ip` หรือ `release_open` — และเผยแพร่ข้อกำหนดดังกล่าวก่อนที่จะมีผู้เข้าร่วม
([ข้อกำหนดรางวัล](/docs/network/specifications/prizes#condition-7-in-detail-the-term-is-one-choice-of-three))
การได้อันดับบนกระดานผู้นำแบบเปิดไม่ได้มีการถ่ายโอนสิทธิ์ใด ๆ ภายใต้ข้อกำหนดเหล่านี้ เทมเพลตนี้ระบุรายละเอียดของ `pass_to_holders` สำหรับคลังข้อมูลภาษาชนพื้นเมือง โดยนำเสนอเป็นจุดเริ่มต้นเพื่อให้องค์กรกำกับดูแลของชุมชนนำไปปรับแก้ ซึ่งมีการทำงานดังนี้:

### 1. การพัฒนาวิธีการ
นักวิจัย นักศึกษา หรือนักพัฒนาสร้างวิธีการแปล — pipeline ที่ใช้ FST-gated,
LLM ที่ได้รับการฝึกสอน โมเดลที่ fine-tuned หรือแนวทางอื่นใด — โดยใช้
ทรัพยากรของตนเองและข้อมูลที่มีใบอนุญาตแบบเปิด

### 2. การประเมินผ่านเครือข่าย
วิธีการถูก benchmark ผ่าน [eval harness](/docs/network/specifications/harness)
การส่งทุกครั้งถูกประทับลายนิ้วมือไปยัง Git commit และเวอร์ชันชุดข้อมูลที่เฉพาะเจาะจง
คะแนนสามารถทำซ้ำได้

### 3. การรีวิวโดยชุมชน
ผลลัพธ์ถูกรีวิวโดยนักทำงานด้านภาษาของชุมชน คะแนน leaderboard ที่สูง
พิสูจน์ว่าวิธีการ *ใช้งานได้* แต่ไม่ได้พิสูจน์ว่ามัน *เหมาะสม* ผู้พูดสองภาษา
ตรวจสอบตัวอย่างผลลัพธ์ และผู้รีวิวของชุมชนสามารถปฏิเสธวิธีการได้ด้วยเหตุผลใดก็ตาม

### 4. การโอนความเป็นเจ้าของ
เมื่อวิธีการผ่านเกณฑ์รางวัล (เมตริกอัตโนมัติ **และ** การตรวจสอบโดยมนุษย์)
นักพัฒนาโอนวิธีการ — source code น้ำหนักที่ฝึกแล้ว
การกำหนดค่า ข้อมูลการฝึกสอน — ให้กับองค์กรกำกับดูแลของชุมชน
(สภาชนเผ่า หน่วยงานด้านภาษา หรือหน่วยงานที่คล้ายกันที่ชุมชนเลือก
ไม่ใช่ Champollion) ชุมชนเป็นเจ้าของ artifact อย่างสมบูรณ์: สามารถ
ตรวจสอบ แก้ไข ปรับใช้ เก็บไว้ หรือออกใบอนุญาต โดยไม่มีการอ้างสิทธิ์ต่อเนื่องจากนักพัฒนาหรือจาก Champollion

ส่วนประกอบของบุคคลที่สามที่นักพัฒนาไม่ได้เป็นเจ้าของ (โมเดลฐาน open-weight,
FST ที่ใช้ AGPL) ไม่สามารถโอนความเป็นเจ้าของได้ — สิ่งเหล่านี้ส่งต่อไปยัง
ชุมชนภายใต้ใบอนุญาตแบบเปิดของตนเอง ซึ่งเป็นเหตุผลที่การรับรองรางวัลกำหนดให้
dependency ทุกรายการต้องมีสิทธิ์ที่ชุมชนสามารถรับได้จริง
ดูคลาส dependency ใน
[ข้อกำหนด Method Interface](/docs/network/specifications/methods#method-validity-and-dependency-classes)

นักพัฒนาเก็บสิ่งที่นักวิจัยควรเก็บ: สิทธิ์ที่ไม่มีข้อจำกัดในการ
เผยแพร่แนวทางและผลลัพธ์ การนำเทคนิคของตนไปใช้ที่ใดก็ได้ และ
การระบุแหล่งที่มาถาวรในฐานะผู้สร้างวิธีการ

### 5. การปรับใช้ — หากและอย่างไรที่ชุมชนเลือก
ชุมชนตัดสินใจว่าจะปรับใช้วิธีการหรือไม่ โดยใคร และภายใต้เงื่อนไขใด การปรับใช้อิสระ
เป็นเรื่องของชุมชนทั้งหมด:
**Champollion ไม่รับส่วนแบ่งใด ๆ จากสิ่งที่ชุมชนได้รับจาก asset ที่ตนเป็นเจ้าของ**
และไม่มีสิทธิ์การปรับใช้ของตนเอง

:::note[สถานะ: เทมเพลต ไม่ใช่ประวัติผลงานจริง]
ยังไม่มีการเปิดประกวดรางวัลและยังไม่มีการถ่ายโอนสิทธิ์ใด ๆ เกิดขึ้น เทมเพลตนี้ถูกจัดทำขึ้นเพื่อให้ข้อกำหนดที่ตั้งใจไว้มีความโปร่งใสก่อนที่ใครจะลงแรง และเพื่อให้องค์กรกำกับดูแลของชุมชนมีร่างที่เป็นรูปธรรมในการพิจารณา แทนที่จะเริ่มต้นจากหน้ากระดาษว่างเปล่า ทั้งนี้ เอกสารที่ลงนามร่วมกันซึ่งร่างขึ้นโดยที่ปรึกษากฎหมายสำหรับคู่สัญญาแต่ละฝ่ายโดยเฉพาะ คือสิ่งที่จะทำให้ข้อตกลงทั้งหมดนี้มีผลผูกพันทางกฎหมาย
:::

## สำหรับนักวิจัย

หากคุณกำลังพัฒนาวิธีการสำหรับภาษาพื้นเมือง:

1. **สร้างความสัมพันธ์** กับชุมชนภาษาก่อนที่คุณจะเริ่ม
2. **ใช้ข้อมูลที่มีใบอนุญาตแบบเปิด** สำหรับการพัฒนา (ไม่ใช่ทรัพยากรที่ชุมชนจำกัดการใช้งาน)
3. **บันทึก provenance** ใน [run card](/docs/network/specifications/run-card) ของคุณ — ทรัพยากรทุกรายการ ใบอนุญาต และแหล่งที่มา
4. **อ่านข้อกำหนดของรางวัลก่อนสร้างเพื่อมัน** — หากข้อกำหนดรวมถึงการโอน
   การมีส่วนร่วมของคุณคือสถาปัตยกรรมและเทคนิค (ของคุณที่จะเผยแพร่และนำกลับมาใช้ใหม่)
   การมีส่วนร่วมของชุมชนคือความรู้ทางภาษาที่ทำให้มันใช้งานได้สำหรับภาษาของพวกเขา
