# เทมเพลตข้อกำหนด

> **สรุปสำหรับผู้บริหาร** ข้อกำหนดเริ่มต้นที่ชุมชนหรือองค์กรสามารถนำไปปรับใช้เมื่อดำเนินการ [sovereign contest](/docs/network/sovereignty/run-a-sovereign-contest) ทิศทางการออกแบบตลอดทั้งเอกสารเน้นไปที่ **การลดการพึ่งพาความไว้วางใจ**: ทุกที่ที่เป็นไปได้ ข้อกำหนดจะถูกรองรับด้วยกลไก (แฮช, เกต, บันทึกที่เพิ่มได้อย่างเดียว) แทนที่จะเป็นคำสัญญา แต่ละข้อกำหนดประกอบด้วยย่อหน้าสั้นหนึ่งย่อหน้าและคำอธิบายภาษาธรรมดา

:::warning[นี่ไม่ใช่คำแนะนำทางกฎหมาย]
เนื้อหาเหล่านี้เป็นเพียง *แนวคิด* ในการร่างเอกสารจากโครงการวิจัยที่ไม่แสวงหากำไร ไม่ใช่คำแนะนำทางกฎหมาย และเราไม่ใช่ทนายความ กฎหมายแตกต่างกันไปตามเขตอำนาจศาล และกรอบการกำกับดูแลข้อมูลของชนพื้นเมือง (เช่น หลักการอธิปไตยทางข้อมูลของ First Nations) กำหนดพันธกรณีที่ไม่มีเทมเพลตใดสามารถปฏิบัติตามได้ครบถ้วน กรุณาให้ที่ปรึกษากฎหมายของคุณเอง — และกระบวนการกำกับดูแลของชุมชนของคุณเอง — ตรวจสอบทุกสิ่งก่อนที่คุณจะนำไปใช้อ้างอิง
:::

## ข้อกำหนดหลัก

### 1. คลังข้อมูลเป็นและยังคงเป็นทรัพย์สินของเจ้าของ

*ข้อกำหนด* คลังข้อมูลสำหรับการประเมิน รายการทั้งหมดในนั้น และเมทาดาทาที่ได้รับทั้งหมด ยังคงเป็นทรัพย์สินแต่เพียงผู้เดียวของชุมชน/องค์กรที่ลงทะเบียน การใช้งานการลงทะเบียน, การแข่งขัน, หรือกลไกการประเมินของ Network ไม่ถือเป็นการโอนสิทธิ์ กรรมสิทธิ์ หรือผลประโยชน์ใดๆ ในคลังข้อมูลให้แก่แพลตฟอร์ม นักพัฒนาวิธีการ หรือผู้สนับสนุนรายใด แพลตฟอร์มไม่เก็บสำเนาและไม่อ้างสิทธิ์ใบอนุญาตใดๆ นอกเหนือจาก digest ของ encrypted blob

*ภาษาธรรมดา:* การดำเนินการแข่งขันกับคลังข้อมูลของคุณไม่ได้ให้สิทธิ์ใครในคลังข้อมูลนั้น Champollion ถือแฮช ไม่ใช่การอ้างสิทธิ์

### 2. การประเมินให้สิทธิ์เฉพาะคะแนน — ไม่มีอะไรอื่น

*ข้อกำหนด* การรันการประเมินที่ได้รับอนุญาตให้สิทธิ์แก่แพลตฟอร์มและนักพัฒนาวิธีการในการรับและเผยแพร่เฉพาะ **คะแนนตัวเลขและสถิติรวมเท่านั้น** ไม่ให้สิทธิ์ **ใดๆ** ในการเก็บรักษาเนื้อหาคลังข้อมูลหลังจากการรัน **ไม่** ให้สิทธิ์ในการฝึก, ปรับแต่ง, หรือสอนโมเดลใดๆ ด้วยข้อมูลนั้น และ **ไม่** ให้สิทธิ์ในการสร้างคลังข้อมูลที่ได้รับ, ตัวอย่างที่จดจำ, หรือตารางค้นหาจากข้อมูลนั้น การเก็บรักษาเนื้อหาใดๆ หลังจากการรันจะยุติใบอนุญาตและทำให้ผลลัพธ์ของการรันนั้นเป็นโมฆะ

*ภาษาธรรมดา:* สิ่งที่ออกมาจากการรันแบบปิดผนึกคือตัวเลข ประโยคไม่เคยออกมา — ไม่ใช่ใน leaderboard, ไม่ใช่ใน training set, ไม่ใช่ใน cache ของใคร

### 3. ความสมบูรณ์ที่ยึดด้วยแฮช: digest ถูกเผยแพร่ เนื้อหาไม่เคยถูกเผยแพร่

*ข้อกำหนด* คลังข้อมูลถูกระบุโดย SHA-256 digest ที่เผยแพร่ของ encrypted blob และป้ายกำกับเวอร์ชันเท่านั้น เฉพาะ blob ที่ตรงกับ digest เท่านั้นที่นับเป็นคลังข้อมูล การรันใดๆ กับไบต์ที่ไม่ตรงกันถือเป็นโมฆะ การเผยแพร่ digest ไม่ใช่การเผยแพร่เนื้อหา และไม่มีสิ่งใดในข้อกำหนดเหล่านี้ที่บังคับให้เจ้าของต้องเปิดเผยเนื้อหาแก่ใครเลย

*ภาษาธรรมดา:* ทุกคนสามารถตรวจสอบได้ว่าใช้คลังข้อมูล *ใด*; ไม่มีใครได้ *อ่าน* มัน หากไบต์ไม่ตรงกับแฮช การรันนั้นไม่นับ

### 4. ค่าเริ่มต้นแบบปิดเมื่อล้มเหลว

*ข้อกำหนด* ความคลุมเครือทุกอย่างจะถูกแก้ไขในทิศทางของการไม่เข้าถึงและไม่เผยแพร่ คำขอที่ไม่ได้รับการอนุมัติอย่างชัดเจนจากเกณฑ์ผู้ดูแลจะถูกปฏิเสธ การอนุญาตที่หมดอายุหรือถูกใช้แล้วถือเป็นโมฆะ ผลลัพธ์ที่ไม่สามารถตรวจสอบที่มาได้จะไม่ถูกเผยแพร่ คลังข้อมูลที่การลงทะเบียนหมดอายุจะหยุดสามารถรันได้ ความเงียบไม่ถือเป็นความยินยอม

*ภาษาธรรมดา:* เมื่อสงสัย คำตอบคือไม่ ไม่มีสิ่งใดที่ค่าเริ่มต้นเป็นแบบเปิด

### 5. การอนุญาตของผู้ดูแลเป็นเกตสำหรับทุกการรัน

*ข้อกำหนด* ไม่มีการประเมินใดที่จะดำเนินการกับคลังข้อมูลที่ปิดผนึกได้โดยไม่มีการอนุญาตที่บันทึกไว้และได้รับการอนุมัติตามเกณฑ์ และการอนุญาตแบบใช้ครั้งเดียวที่มีกรอบเวลาซึ่งผูกกับวิธีการเฉพาะ, เวอร์ชันคลังข้อมูล, และสภาพแวดล้อมการประเมิน เหตุการณ์การอนุญาตทั้งหมด รวมถึงการปฏิเสธและความพยายามที่ถูกบล็อก จะถูกบันทึกในบันทึกการตรวจสอบที่เพิ่มได้อย่างเดียวและสามารถเล่นซ้ำได้แบบสาธารณะ

*ภาษาธรรมดา:* ผู้ดูแลของคุณอนุมัติทุกการรัน ทีละการรัน และประวัติทั้งหมดเป็นสาธารณะและป้องกันการแก้ไข (เครื่องมือ cryptographic threshold-signing ยังอยู่ระหว่างการพัฒนา — ดู [กล่องสถานะใน runbook](/docs/network/sovereignty/run-a-sovereign-contest) — ดังนั้นในปัจจุบันข้อกำหนดนี้ถูกบังคับใช้เป็นกระบวนการที่บันทึกไว้ ยังไม่ใช่ในรูปแบบคณิตศาสตร์)

### 6. กองทุนรางวัลถือโดยผู้สนับสนุนและกฎการมอบรางวัลเป็นสาธารณะ

*ข้อกำหนด* กองทุนรางวัลถือโดยองค์กรผู้สนับสนุนที่ระบุชื่อหรือกองทุนชุมชนที่กำหนด — ไม่ใช่โดยแพลตฟอร์ม เกณฑ์การมอบรางวัลถูกเผยแพร่ก่อนการแข่งขันเปิด สามารถตรวจสอบได้จากคะแนนที่เผยแพร่บวกกับคำตัดสินการตรวจสอบของผู้พูดของชุมชน และการตัดสินใจมอบรางวัลเป็นของผู้ถือกองทุนแต่เพียงผู้เดียว

*ภาษาธรรมดา:* เงินอยู่กับผู้ที่นำมาวาง, เกณฑ์เป็นสาธารณะ, และว่าเกณฑ์ถูกผ่านหรือไม่สามารถตรวจสอบได้โดยทุกคน Champollion ไม่สามารถจ่าย, ระงับ, หรือเปลี่ยนทิศทางรางวัลได้ เพราะ Champollion ไม่เคยมีเงินนั้น

## ความเสี่ยงจาก Trojan horse {#trojan-horse-risks}

เอกสารข้อกำหนดที่ซื่อสัตย์จะระบุวิธีที่การจัดการสามารถถูกโจมตีได้ ใส่สิ่งเหล่านี้ในของคุณ — ผู้สนับสนุนหรือชุมชนที่ได้อ่านแล้วจะยากต่อการถูกเผาไหม้

### การส่งวิธีการที่เป็นอันตรายที่พยายามขโมยข้อมูลทดสอบ

"วิธีการ" คือโค้ดที่ส่งมา วิธีการที่เป็นศัตรูสามารถพยายามลักลอบนำประโยคทดสอบออกไป — เข้ารหัสในผลลัพธ์, เขียนลงในบันทึก, หรือส่งกลับบ้าน
**การบรรเทา:** การส่งออกเฉพาะคะแนน (ข้อความผลลัพธ์ต่อรายการจากการรันแบบปิดผนึกจะไม่ถูกเผยแพร่ — บังคับใช้ที่ชั้นข้อมูลในปัจจุบัน); **sandbox แบบไม่มี egress** สำหรับการรันแบบปิดผนึก (🔲 อยู่ระหว่างการพัฒนา — จนกว่าจะเปิดตัว ให้ถือว่าการบรรเทานี้เป็นบางส่วนและให้น้ำหนักกับการอนุมัติของผู้ดูแลของคุณตามนั้น); และ **งบประมาณ query/run ต่อวิธีการต่อรอบ** — วิธีการได้รับจำนวนการรันแบบปิดผนึกที่น้อยและคงที่ ดังนั้นคลังข้อมูลจึงไม่สามารถสร้างใหม่ได้โดยการตรวจสอบซ้ำแม้ผ่านช่องทางคะแนน

### คลังข้อมูลที่ส่งมาถูกวางยาพิษหรือปนเปื้อน

การโจมตีสามารถดำเนินไปในทิศทางตรงกันข้ามได้เช่นกัน: มีคนเสนอคลังข้อมูลทดสอบ "สำเร็จรูป" ให้ชุมชนที่ผิดพลาดอย่างละเอียด, น่ารังเกียจ, หรือเป็นสาธารณะอยู่แล้ว (ดังนั้นวิธีการจึงจดจำมันและคะแนนไม่มีความหมาย)
**การบรรเทา:** ข้อกำหนดที่มาของทุกรายการ (ใครเป็นผู้แต่ง, เมื่อใด, จากแหล่งใด); [การตรวจสอบของผู้พูด](/docs/network/specifications/speaker-validation) ของคลังข้อมูลเองก่อนการปิดผนึก; และการตรวจสอบการปนเปื้อนกับข้อมูลสาธารณะก่อนที่คลังข้อมูลจะได้รับการยอมรับเป็น qualifier หรือมาตรฐานทอง

### Trojan ใบอนุญาตใน dependencies

วิธีการที่ชนะที่แอบรวมเนื้อหาหรือโค้ดที่ใบอนุญาตห้ามการใช้งานที่ชุมชนตั้งใจ (การใช้งานเชิงพาณิชย์, การแจกจ่ายซ้ำ) จะทำให้การโอนเป็นพิษ — คุณชนะเครื่องมือที่ไม่สามารถใช้งานได้ตามกฎหมาย
**การบรรเทา:** การประกาศประเภท dependency และเกตใบอนุญาตแบบกลไกสำหรับการส่ง (ดูตารางประเภท dependency ใน [Prize Specification](/docs/network/specifications/prizes)); dependencies ที่ไม่ได้ประกาศถือเป็นการตัดสิทธิ์

### การฟิชชิ่งข้อมูลรับรอง

ใครก็ตามที่ดำเนินการแข่งขันจะกลายเป็นเป้าหมายของการโจมตี "วาง token ของคุณที่นี่เพื่อยืนยันการลงทะเบียน" **การบรรเทา:** อย่าวาง token, คีย์, หรือข้อมูลรับรองลงในหน้าของบุคคลที่สามหรือแชร์ในแชท; การยืนยันตัวตนทั้งหมดในโครงการนี้เกิดขึ้นผ่าน OAuth flow ของ CLI และ **ไม่มี browser personal-access-token flow อีกต่อไป** — หน้าใดที่ขอสิ่งนั้นถือเป็นการเป็นศัตรู การตัดสินใจของผู้ดูแลควรเกิดขึ้นผ่านช่องทางที่ชุมชนของคุณไว้วางใจอยู่แล้ว

### การผิดนัดรางวัลจากฝั่งผู้สนับสนุน

โหมดความล้มเหลวที่เงียบ: วิธีการผ่านเกณฑ์และผู้สนับสนุนไม่จ่าย
**การบรรเทา:** เผยแพร่ตัวตนของผู้ถือกองทุนและการจัดการการถือครอง (บัญชีองค์กร, กองทุน, ตัวแทน escrow) *ก่อน* การแข่งขันเปิด; ทำให้เงื่อนไขการมอบรางวัลสามารถตรวจสอบได้จากคะแนนที่เผยแพร่เพื่อให้การผิดนัดมองเห็นได้สาธารณะว่าเป็นการผิดนัด ไม่ใช่ปฏิเสธได้ว่าเป็นการตัดสิน; และเลือกผู้ถือที่มีสิ่งที่จะสูญเสียในแง่ชื่อเสียง Champollion ไม่สามารถรับประกันความเสี่ยงนี้ได้ — โดยการออกแบบมันไม่เคยถือกองทุน — ดังนั้นความน่าเชื่อถือของรางวัลคือความน่าเชื่อถือของผู้ถือที่ระบุชื่อนั้นเอง

## การใช้เทมเพลตเหล่านี้

คัดลอกสิ่งที่เหมาะสม ลบสิ่งที่ไม่เหมาะสม เพิ่มสิ่งที่การกำกับดูแลของคุณต้องการ และเผยแพร่ผลลัพธ์พร้อมกับการแข่งขันของคุณเพื่อให้ผู้เข้าร่วมตกลงกับข้อกำหนด *ของคุณ* ไม่ใช่กับความรู้สึก ข้อกำหนดต่อชุมชน — รวมถึงการโอนความเป็นเจ้าของวิธีการสำหรับรางวัลที่มีผู้สนับสนุน — เป็นบรรทัดฐานที่นี่ ไม่ใช่ข้อยกเว้น: ดู [Ownership & Terms](/docs/network/sovereignty/ownership-transfer)
