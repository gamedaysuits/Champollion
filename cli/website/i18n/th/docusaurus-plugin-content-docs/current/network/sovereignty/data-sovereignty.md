# การดูแลรักษาข้อมูล

> **บทสรุปผู้บริหาร** Champollion เป็นเครื่องมือสำหรับการวิจัยและพัฒนาด้าน machine-translation — ซึ่งเปิดเผยซอร์สโค้ด (source-available) และใช้งานได้ฟรีสำหรับวัตถุประสงค์ที่ไม่ใช่เชิงพาณิชย์ โดยมีระบบทดสอบประเมินผล (evaluation harness) เป็นแบบ open source หน้านี้ระบุถึงจุดยืนเกี่ยวกับข้อมูลภาษาอย่างครบถ้วน: คลังข้อมูลภาษา (corpora) เป็นของกลุ่มบุคคลผู้เป็นเจ้าของภาษานั้น ทุก license และข้อกำหนดของชุมชนจะได้รับการเคารพผ่านกลไกของระบบแทนที่จะเป็นเพียงคำสัญญา และแพลตฟอร์มจะไม่มีการกำหนดเงื่อนไขใดๆ ของตนเองทับซ้อนลงบนภาษาของใครก็ตาม

:::info[ข้อมูลภาษาคือข้อมูลชีวภาพ]
ข้อมูลภาษาคือ**ข้อมูลชีวภาพ** เช่นเดียวกับข้อมูลทางพันธุกรรมหรือข้อมูลสุขภาพ ภาษาหนึ่งๆ นั้นแฝงไว้ด้วยอัตลักษณ์ ความสัมพันธ์ทางเครือญาติ และความผูกพันของผู้คนที่ใช้ภาษานั้น — และเช่นเดียวกับจีโนม ภาษาไม่อาจทำให้ไม่ระบุตัวตนได้อย่างมีนัยสำคัญ: แม้จะลบชื่อออกไป ภาษาก็ยังคงเข้ารหัสความเป็นตัวตนของผู้คนเหล่านั้นอยู่ดี ดังนั้น ผู้ที่มอบคลังข้อมูลภาษาจึงถือกุญแจไขไปสู่ข้อมูลนั้น รวมถึงทุกสิ่งที่วัดเทียบกับมัน นี่คือหลักการพื้นฐานที่ทุกอย่างด้านล่างนี้ยึดถือ
:::

จากหลักการนั้น การออกแบบจึงตามมา Champollion ปฏิบัติต่อผู้มีส่วนร่วมในคลังข้อมูลทุกคนในฐานะ **ผู้ดูแล**: คลังข้อมูลยังคงเป็นของพวกเขา — ทั้งในทางกฎหมาย ทางกายภาพ และทางปฏิบัติ — ในขณะที่โครงสร้างพื้นฐานทำให้มัน *วัดได้*

## พันธกิจ

1. **เราไม่เก็บข้อมูลไว้เลย** คลังข้อมูลถูกลงทะเบียนเป็นการ์ดข้อมูลเมตาที่ตรึงด้วยแฮช และดึงข้อมูลจากที่โฮสต์ของผู้ดูแลเองในเวลาประเมินผล ไม่มีสิ่งใดถูกคัดลอกเข้ามาในที่เก็บนี้หรือให้บริการจากโครงสร้างพื้นฐานของเรา นำไฟล์เก็บถาวรของคุณออกไปออฟไลน์ และการประเมินผลเทียบกับมันก็จะหยุดลงทันที ดูที่ [การลงทะเบียนคลังข้อมูล](/docs/network/sovereignty/registering-corpora)

2. **ใบอนุญาตทุกฉบับได้รับการเคารพ — โดยกลไก ไม่ใช่คำสัญญา** คลังข้อมูลที่ไม่ใช่เชิงพาณิชย์และเพื่อการวิจัยเท่านั้นจะถูกกีดกันโดยกลไกจากการใช้งานใดๆ ที่ใบอนุญาตไม่อนุญาต ข้อจำกัดที่ชุมชนระบุไว้นอกเหนือจากใบอนุญาตจะถูกบันทึกพร้อมแหล่งที่มาและได้รับการปฏิบัติตามในลักษณะเดียวกัน การบังคับใช้อยู่ใน CI gates และ database triggers ไม่ใช่ในจรรยาบรรณ

3. **เงื่อนไขเป็นของผู้ดูแล และแตกต่างกันไป** ภาษาต่างๆ จะมีข้อตกลงที่แตกต่างกัน — คลังข้อมูล CC0 สาธารณะ คลังข้อมูลชุมชนเพื่อการวิจัยเท่านั้น และชุดทดสอบที่ปิดผนึกพร้อมข้อกำหนดการใช้งานแบบอธิปไตยสามารถเข้าร่วมได้ทั้งหมด แต่ละอันตามเงื่อนไขของตนเอง ไม่มีสัญญาสากลที่นี่และไม่มีการอ้างสิทธิ์เริ่มต้นในสิ่งใดทั้งสิ้น ดูที่ [กรอบเงื่อนไข](/docs/network/sovereignty/ownership-transfer)

4. **คลังข้อมูลลับได้รับการรองรับในฐานะสถาปัตยกรรม ไม่ใช่ข้อยกเว้น** ชุมชนสามารถเก็บชุดทดสอบไว้แบบปิดผนึก — เก็บไว้บนโครงสร้างพื้นฐานของตนเอง ไม่เคยถูกมองเห็นโดย Champollion หรือนักพัฒนา — และยังคงให้วิธีการถูกให้คะแนนเทียบกับมันได้ ความสามารถในการวัดโดยไม่ต้องดึงข้อมูลออกมาคือเป้าหมายการออกแบบ ไม่ใช่วิธีแก้ปัญหาชั่วคราว

5. **การระบุแหล่งที่มาและเครดิตเดินทางไปพร้อมกับข้อมูล** เครดิตของผู้สร้างและนักภาษาศาสตร์เป็นสิ่งบังคับในทุกพื้นที่ที่คลังข้อมูลปรากฏ ในกรณีที่ชุมชนได้ใช้ป้าย TK หรือ BC ของ [Local Contexts](https://localcontexts.org/) เราจะแสดงป้ายเหล่านั้นและปฏิบัติตามโปรโตคอลที่ป้ายเหล่านั้นเข้ารหัสไว้ เราแสดงป้าย Labels เท่านั้น เราไม่สร้างป้ายเหล่านั้นเอง

6. **ผู้มีส่วนร่วมได้รับค่าตอบแทน** การสร้างและตรวจสอบคลังข้อมูลเป็นงานวิชาชีพในอัตราที่เผยแพร่ไว้ — ดูที่ [วิธีที่ผู้พูดได้รับค่าตอบแทน](/docs/network/perspectives/how-speakers-get-paid) การจ่ายเงินไม่ได้ซื้อคลังข้อมูล: ผู้สร้างได้รับค่าตอบแทน *และ* ยังคงเป็นผู้ดูแลต่อไป

## วิธีที่ license กลายมาเป็นการบังคับใช้

ความมุ่งมั่นข้อที่ 2 มีรูปแบบที่เฉพาะเจาะจง และคุ้มค่าที่จะระบุไว้ให้ครบถ้วน — นี่คือวิธีการทำงานจริงของคำว่า "ทุก license จะได้รับการเคารพ" ไม่ใช่แค่บทสรุปของความตั้งใจดี

**ทุก benchmark จะถูกระงับไว้เมื่อเข้าสู่ระบบ** ชุดทดสอบที่เพิ่งถูกจัดทำแคตตาล็อกจะถูกกักกันไว้เป็นค่าเริ่มต้น: สามารถมองเห็นได้ในดัชนี แต่จะถูกแยกออกจากคิวการประเมินผล จากการแข่งขัน และจากการจัดอันดับทุกรายการ จะไม่มีการทึกทักเอาเองเกี่ยวกับคลังข้อมูลภาษาใดๆ เมื่อนำเข้าสู่ระบบ — แม้แต่ license ที่ดูเหมือนจะอนุญาตให้ใช้งานได้อิสระ (permissive) ก็ตาม — จนกว่าข้อกำหนดเหล่านั้นจะได้รับการตรวจสอบเทียบกับข้อความ license จริงที่ถูกปักหมุดไว้จากต้นทาง (pinned upstream revision)

**คำตัดสินจากการตรวจสอบเป็นไปตามกลไก และกรณีที่ตัดสินยากจะยังคงถูกระงับไว้** license แบบ permissive ที่ระบุไว้อย่างชัดเจนจะปลดล็อกคลังข้อมูลภาษาสำหรับทุกช่องทางการใช้งาน (lane) license แบบ non-commercial ที่ระบุไว้อย่างชัดเจนจะปลดล็อกให้เข้าสู่ช่องทางการวิจัย ซึ่งจะถูกแยกออกจากการใช้งานเชิงพาณิชย์ การชิงรางวัล และ API surface ทุกประเภท และ license ที่ไม่ได้ระบุไว้ ถูกดัดแปลง ผสมผสาน หรือทำขึ้นเฉพาะ จะ**ไม่มีการตีความแทนผู้ถือสิทธิ์โดยเด็ดขาด**: คลังข้อมูลภาษาจะยังคงอยู่ในแคตตาล็อกแต่ถูกระงับไว้ — อยู่นอกคิว การแข่งขัน และการจัดอันดับ — จนกว่าผู้ถือสิทธิ์จะระบุข้อกำหนดหรือบันทึกการอนุญาต คำตัดสิน วันที่ ช่องทางการใช้งาน และเกณฑ์การตัดสิน จะถูกประทับตราในรูปแบบที่เครื่องอ่านได้ลงบนการ์ดคลังข้อมูลภาษา (corpus card) และรายการใน registry เพื่อให้คำถามที่ว่า "ทำไมสิ่งนี้ถึงรันได้?" มีคำตอบที่อ้างอิงได้เสมอ และเช่นเดียวกันกับคำถามที่ว่า "ทำไมสิ่งนี้ถึงรันไม่ได้?"

**การส่งข้อความไปยังโมเดลถือเป็นการส่งผ่านข้อมูล และมีการควบคุม** การประเมินโมเดลหมายถึงการส่งประโยคต้นทางไปให้โมเดล — นั่นคือการที่คลังข้อมูลภาษาออกจากแหล่งที่อยู่ และมันจะถูกควบคุมตาม license คลังข้อมูลภาษาที่มี license แบบ permissive สามารถใช้ช่องทางมาตรฐานได้ คลังข้อมูลภาษาภายใต้ license แบบ non-commercial ที่ระบุไว้ จะเดินทางผ่านช่องทางที่มีสัญญาว่าจะไม่นำข้อมูลที่ป้อนไปใช้ฝึกสอน (train) เท่านั้น — ซึ่งระบุไว้อย่างชัดเจนว่า: เป็นการรับประกันว่าจะไม่มีการฝึกสอน (no-training) ไม่ใช่การรับประกันว่าจะไม่มีการเก็บรักษาข้อมูล (no-retention) คลังข้อมูลภาษาภายใต้การอนุญาตที่ไม่ได้ระบุไว้หรือถูกดัดแปลง จะถูกปฏิเสธการประเมินผลระยะไกล (remote evaluation) โดยสิ้นเชิงจนกว่าจะมีการบันทึกความยินยอม และชุดข้อมูลชุมชนที่ถูกปิดผนึก (sealed community sets) จะไม่มีวันออกจากโครงสร้างพื้นฐานของผู้ดูแล (steward) เลย เมื่อระบบควบคุม (gate) ปฏิเสธ ข้อความการปฏิเสธจะอ้างอิงคำตัดสินจากการตรวจสอบ license

**การบังคับใช้อยู่ภายใต้ไคลเอนต์ทุกตัว** การระงับ (holds) จะถูกบังคับใช้โดย database trigger ที่ไม่มีไคลเอนต์ใดสามารถข้ามผ่านได้ กฎการห้ามโฮสต์ (no-hosting) จะถูกบังคับใช้โดย repository gate ที่สแกนทุก path ที่ถูกติดตามเพื่อหาเนื้อหาของคลังข้อมูลภาษา และ transmission gate จะทำงานอยู่ภายในระบบทดสอบประเมินผล (evaluation harness) เอง สิ่งเหล่านี้สามารถปฏิเสธเราได้ ซึ่งนั่นคือประเด็นสำคัญ

## สิ่งที่นี่ไม่ใช่

Champollion ไม่ใช่นายหน้าข้อมูล ไม่ใช่ผู้ให้บริการแปล และไม่ใช่แพลตฟอร์มเชิงพาณิชย์ มันคือเครื่องมือวิจัย คะแนนสูงในลีดเดอร์บอร์ดพิสูจน์ว่าวิธีการทำงานได้ในทางเทคนิค มันไม่ใช่ใบอนุญาตให้เผยแพร่การแปล แจกจ่ายคลังข้อมูล หรือใช้งานสิ่งใดขัดต่อความต้องการของชุมชน การตัดสินใจเหล่านั้นเป็นของผู้ดูแลเสมอ

## กรอบแนวคิดที่หล่อหลอมการออกแบบนี้

จุดยืนนี้ไม่ได้ถูกคิดค้นขึ้นที่นี่ มันได้รับข้อมูลและเป็นหนี้บุญคุณต่องานกำกับดูแลข้อมูลของชนพื้นเมืองในช่วงสองทศวรรษที่ผ่านมา:

- **หลักการอธิปไตยทางข้อมูลของ First Nations** — First Nations ในแคนาดาได้ประกาศหลักการความเป็นเจ้าของ การควบคุม การเข้าถึง และการครอบครองข้อมูลของชุมชนเอง โมเดลการดูแลรักษาที่นี่ได้รับการออกแบบให้เข้ากันได้กับหลักการเหล่านี้
- **[หลักการ CARE](https://www.gida-global.org/care)** (Collective Benefit, Authority to Control, Responsibility, Ethics) — Global Indigenous Data Alliance
- **[Te Mana Raraunga](https://www.temanararaunga.maori.nz/)** — เครือข่ายอธิปไตยข้อมูลของชาวเมารี
- **[Kaitiakitanga License](https://tehiku.nz/)** — ใบอนุญาตที่อิงการปกป้องดูแลของ Te Hiku Media สำหรับข้อมูล te reo Māori ซึ่งเป็นอิทธิพลโดยตรงต่อโมเดลการดูแลรักษาแบบผู้ดูแลถือกุญแจที่ใช้ที่นี่

เราชี้ให้ทุกคนที่ออกแบบการกำกับดูแลสำหรับข้อมูลภาษาของตนเองไปยังแหล่งที่มาเหล่านั้นโดยตรง — พวกเขาคือผู้มีอำนาจ ไม่ใช่เรา ในกรณีที่ชุมชนนำกรอบแนวคิดใดๆ เหล่านี้มาใช้กับคลังข้อมูลของตน การ์ดคลังข้อมูลจะบันทึกการยืนยันนั้นและเครื่องมือจะปฏิบัติตาม

Champollion แสดง **"Open to Collaborate" Notice** ของ Local Contexts: เราสร้างความสัมพันธ์กับชุมชนที่ภาษาของพวกเขาปรากฏที่นี่ และ Labels ที่ชุมชนเป็นผู้เขียนมีความสำคัญเหนือกว่าสิ่งที่เราพูดเกี่ยวกับข้อมูลของพวกเขา
