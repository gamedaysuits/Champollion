# การลงทะเบียน Corpora และ Exposure Lanes

> **บทสรุปผู้บริหาร** คุณสามารถลงทะเบียนคลังข้อมูลประเมินผลกับ Network เพื่อให้สามารถ
> เทียบเคียงสมรรถนะ (benchmark) ของวิธีการต่าง ๆ กับคลังข้อมูลดังกล่าวได้**โดยไม่ต้องส่งมอบข้อมูลให้เรา** ทุก
> คลังข้อมูลจะได้รับการลงทะเบียนเป็น*การ์ดข้อมูลกำกับ (metadata card)* ที่ล็อกด้วย sha ไม่ใช่เนื้อหา — ประโยค
> จริงจะถูกดึงมาจากแหล่งที่มา ณ เวลาประเมินผล เมื่อคุณลงทะเบียน
> คุณจะต้องตัดสินใจเลือกสองส่วนที่เป็นอิสระต่อกัน: **ระดับการเปิดเผยข้อมูล (exposure tier)** — ข้อมูลจะออกจาก
> เครื่องของคุณมากน้อยเพียงใด (`local-only`, `private`, `public` หรือ `sealed` ซึ่งคลังข้อมูลจะถูก
> เข้ารหัสบนอุปกรณ์ของคุณด้วยคีย์ผู้ดูแลแบบ M-of-N) — และ**ขอบเขตสิทธิ์การใช้งาน
> (license lane)** ซึ่งควบคุมว่าคลังข้อมูลสามารถนำไปใช้ทำอะไรได้บ้าง (สาธารณะ, เพื่อการวิจัย
> ที่ไม่ใช่เชิงพาณิชย์เท่านั้น หรือส่วนตัว) นี่คือกลไกที่ช่วยให้ชุมชนทำให้ภาษาของตน
> *สามารถวัดผลได้* โดยไม่ทำให้ภาษานั้น*ถูกสกัดข้อมูลออกไปได้*

การประเมิน machine translation มักต้องการสิ่งที่ตรงข้ามกับอธิปไตยของข้อมูล: "อัปโหลด test set ของคุณเพื่อให้เรา score เทียบกับมัน" นั่นเป็นสิ่งที่ยอมรับไม่ได้สำหรับ corpora ของภาษาพื้นเมืองและชุมชนอื่น ๆ ที่ถือครองข้อมูล ซึ่งข้อมูลเป็นของผู้คนที่มันมาจาก Network ถูกสร้างขึ้นเพื่อให้คุณไม่ต้องทำการแลกเปลี่ยนนั้น

## 1. การลงทะเบียนคือ metadata ไม่ใช่เนื้อหา {#1-registration-is-metadata-not-content}

corpus ที่ลงทะเบียนแล้วคือ **card**: ระเบียน JSON ขนาดเล็กที่อธิบาย *ที่อยู่* ของ corpus และ *สิ่งที่มันคือ* พร้อม content hash เพื่อให้สามารถตรวจสอบ bytes ที่แน่นอนได้ — แต่ **ไม่มีประโยค** card หนึ่งใบประกอบด้วย:

| ฟิลด์ | ความหมาย |
|-------|-----------|
| `url` | แหล่งที่ดึง corpus มา (archive ต้นทางที่คุณควบคุม) |
| `sha256` | Content hash ของ archive ที่ pin ไว้ — พิสูจน์ว่าไม่มีใครสับเปลี่ยนข้อมูล |
| `license` | SPDX identifier (หรือ `LicenseRef-…` สำหรับลิขสิทธิ์เฉพาะ) |
| `language_pair` | ต้นทาง → ปลายทาง เช่น `eng-crk` |
| `do_not_train` | ตั้งค่าเสมอ — ข้อมูล evaluation ต้องไม่ถูกนำไป train |
| `attribution` | เครดิตของ builder/linguist ที่แสดงทุกที่ที่ corpus ปรากฏ |

ในเวลา evaluation harness จะ **ดึงข้อมูลจากแหล่งที่มา** ตรวจสอบ `sha256` และ score เทียบกับ references ที่ดึงมาใหม่ Network ไม่เคยจัดเก็บ โฮสต์ หรือเผยแพร่เนื้อหา corpus หากคุณนำ archive ต้นทางออกไป corpus ก็จะหยุดทำงานได้ — การควบคุมยังอยู่กับคุณ นี่คือวินัย fetch-from-source เดียวกันที่ใช้กับ catalogue ทั้งหมด (ดู [Evaluation Datasets](/docs/network/leaderboard/datasets))

:::info[เหตุใดจึงใช้ hash แทนการเก็บสำเนา]
content hash ช่วยให้สามารถ **ตรวจสอบซ้ำ** คะแนนที่รายงานด้วยตนเองเทียบกับ corpus
ต้นฉบับที่ไม่ได้ถูกแก้ไข โดยที่เราไม่จำเป็นต้องครอบครอง corpus นั้นเลย
การรันที่ตัวเลขไม่สามารถทำซ้ำได้เทียบกับแหล่งที่มาที่ผูกด้วย hash จะถูกปฏิเสธ
ความสามารถในการตรวจสอบและการไม่ครอบครองไม่ได้ขัดแย้งกัน — hash คือสิ่งที่ทำให้ทั้งสองเป็นไปได้
:::

## 2. สองตัวเลือกที่แยกจากกัน

การลงทะเบียนจะถามคำถามสองข้อที่เป็นอิสระต่อกัน และควรแยกสองข้อนี้
ออกจากกันเพราะคุ้มครองสิ่งที่ไม่เหมือนกัน:

1. **สิ่งใดบ้างที่ออกจากเครื่องของคุณ** — *ระดับการเปิดเผยข้อมูล (exposure tier)*
2. **คลังข้อมูลของคุณสามารถนำไปใช้ทำอะไรได้บ้าง** — *ขอบเขตสิทธิ์การใช้งาน (license lane)*

คลังข้อมูลอาจถูกปิดผนึก (sealed) และเป็นแบบไม่ใช่เชิงพาณิชย์ หรือเป็นแบบสาธารณะและใช้งานเชิงพาณิชย์ได้อย่างชัดเจน หรือ
เป็นการจับคู่ในรูปแบบอื่นใดก็ได้ ตัวเลือกหนึ่งไม่ได้บ่งชี้หรือผูกมัดอีกตัวเลือกหนึ่ง

### 2a. ระดับการเปิดเผยข้อมูล — สิ่งใดบ้างที่ออกจากเครื่องของคุณ

มีสี่ระดับ ซึ่งกำหนดไว้ใน `cli/lib/corpus-registration.mjs` **เนื้อหาคลังข้อมูลที่เป็น
ข้อความธรรมดา (plaintext) จะไม่ถูกอัปโหลดในระดับใดเลย** — นี่ไม่ใช่การตั้งค่านโยบาย แต่เป็น
ความจริงสำหรับทุกระดับ การลงทะเบียนจะกำหนดค่าเริ่มต้นเป็นระดับที่มีความเป็นส่วนตัวสูงสุดเสมอ

| ระดับ | ลงทะเบียนแล้วหรือไม่? | สิ่งที่เราได้รับ | มีการติดตามการ์ด |
|---|:---:|---|:---:|
| **ส่วนตัว / เฉพาะภายในเครื่อง (local-only)** | ❌ | ไม่มีอะไรเลย ทั้งการ์ดและข้อความจะคงอยู่บนเครื่องของคุณ **ค่าเริ่มต้น** | ❌ |
| **ลงทะเบียนแบบส่วนตัว** | ✅ | ข้อมูลกำกับเท่านั้น — ชุดข้อมูลทดสอบลับ (held-out set) สไตล์ WMT คุณเป็นผู้ดูแลข้อมูลเอง ผลลัพธ์สามารถเผยแพร่ได้โดยไม่ต้องเปิดเผยข้อมูล | ✅ |
| **ลงทะเบียนแบบสาธารณะ** | ✅ | ข้อมูลกำกับ + ตัวชี้สำหรับดึงข้อมูลจากต้นทาง ข้อความของคุณจะถูกดึงมาจากต้นน้ำตามความต้องการ และไม่เคยถูกโฮสต์ที่นี่ จำเป็นต้องมีสัญญาอนุญาตที่อนุญาตให้แจกจ่ายซ้ำได้ | ✅ |
| **ปิดผนึก (Sealed)** | ✅ | การ์ดที่ไม่มีเนื้อหา ข้อความที่เข้ารหัสแล้ว (ciphertext) จะคงอยู่กับคุณ | ✅ |

#### ป้องกันไม่ให้ชุดทดสอบเข้าถึงบริการ AI ภายนอกทุกราย

การไม่อัปโหลดข้อความของคุณเป็นการรับประกันขั้นหนึ่ง แต่การไม่*ส่ง*ข้อความไปยัง API ของโมเดล
ในขณะที่คุณทำการประเมินผลก็เป็นการรับประกันอีกขั้นหนึ่ง และสำคัญที่สุดสำหรับชุดทดสอบที่
มีถ้อยคำละเอียดอ่อน ให้ทำเครื่องหมายไฟล์ว่าเป็นแบบเฉพาะภายในเครื่องโดยวางไฟล์ขนาดเล็กไว้
ข้าง ๆ โดยตั้งชื่อตามชื่อไฟล์เดิมแล้วเพิ่ม `.champollion.json` เข้าไป:

```bash
# data/nurse_checked_test.tsv  →  data/nurse_checked_test.tsv.champollion.json
echo '{"transmission": "local-only"}' > data/nurse_checked_test.tsv.champollion.json
```

วิธีนี้ใช้ได้กับคลังข้อมูลทุกรูปแบบ (TSV, JSONL, คู่ข้อความธรรมดา, JSON) นับจาก
นั้นเป็นต้นไป `mt-eval run` จะถือว่าคลังข้อมูลนี้ถูกปิดผนึก:
- หากใช้ผู้ให้บริการภายนอก (OpenRouter, OpenAI, Anthropic, Gemini) การรันจะ
  **ถูกปฏิเสธก่อนที่จะมีการส่งข้อความใด ๆ** และก่อนที่จะมีการขอ API key;
- หากใช้ `--provider local` ที่ชี้ไปยังโมเดลบนเครื่องนี้ (ที่อยู่ loopback
  เช่น `http://localhost:11434/v1`) การรันจะดำเนินต่อไปได้;
- หากใช้ `--method local-model -m <model>` (โมเดล NLLB, OPUS-MT หรือ MADLAD
  ที่ harness โหลดในโปรเซสของตนเอง; จำเป็นต้องมี `-m`) การรันจะดำเนินต่อไปได้:
  ไม่มีประโยคใดออกจาก
  เครื่อง และการดาวน์โหลดน้ำหนักโมเดลจะเป็นการย้ายไฟล์โมเดล ไม่ใช่ข้อความของคุณ;
- หากใช้เอนจิน MT หรือปลั๊กอินของวิธีประเมินผล (`--method <plugin dir>`) การรันจะ
  ถูกปฏิเสธ เว้นแต่คุณจะรับรองว่าการส่งข้อมูลเป็นการทำงานภายในเครื่องทั้งหมด
  (`--attest-local-transport` ซึ่งจะถูกบันทึกไว้ในบันทึกการรัน): เนื่องจาก harness ไม่สามารถ
  มองเห็นได้ว่าปลั๊กอินหรือบริการส่งข้อความไปที่ใด;
- เมทริกซ์การประเมินผลเฉพาะของภาษาจากการ์ดภาษาจะ**ไม่ถูก
  โหลด** เมทริกซ์เหล่านี้มาจากแพ็กเกจแยกต่างหากที่สามารถค้นหาคำบน
  บริการภายนอกได้ เช่น พจนานุกรมออนไลน์ การรันจะถูกให้คะแนนโดยไม่มี
  เมทริกซ์เหล่านั้น และการ์ดการรันจะระบุว่าเมทริกซ์ถูกระงับไว้และเพราะเหตุใด;
- `mt-eval publish` จะระงับประโยคต่าง ๆ ไว้ และโดยค่าเริ่มต้น จะแทนที่
  coaching หรือพรอมต์ที่กำหนดเองด้วย sha256 ของพรอมต์นั้น ดังนั้นตัวอย่างพรอมต์ที่ดึงมาจาก
  ประโยคของคุณเองจะยังคงอยู่บนเครื่องนี้เช่นกัน ข้อมูลกำกับบางส่วนเกี่ยวกับคลังข้อมูล
  จะถูกเผยแพร่สู่สาธารณะพร้อมกับคะแนน: id, เวอร์ชัน, คู่ภาษา, ขนาด,
  sha256 ของไฟล์, สัญญาอนุญาตและการระบุแหล่งที่มา, เกรดการปนเปื้อน, การ
  ทำเครื่องหมายว่าใช้เฉพาะภายในเครื่อง และชื่อเซกเมนต์ สำหรับ id ที่ไม่ใช่
  ชุดข้อมูลที่ลงทะเบียนไว้ การเผยแพร่จะสร้างแถวสาธารณะใน `datasets` ที่มี
  id, คู่ภาษา, ขนาด และ sha256 เดียวกัน พร้อมทั้งโดเมน ชื่อเซกเมนต์ และ
  ช่วงความยาก การแสดงตัวอย่างของ `--dry-run` จะแสดงรายการเหล่านี้สำหรับการรันของคุณ ควบคู่ไปกับ
  สิ่งที่ยังคงอยู่บนเครื่องนี้: ทุกประโยค, ไฟล์ และพาธของไฟล์ คนอื่นจะเห็น
  คะแนนบนชุดทดสอบที่พวกเขาไม่สามารถเปิดดูได้ เป็นการเทียบเคียงสมรรถนะด้วยตนเอง ผู้อื่น
  ไม่สามารถรันซ้ำได้ และค่า sha256 จะช่วยให้ผู้ที่ถือไฟล์เดียวกันเท่านั้นสามารถ
  ยืนยันได้ว่าเป็นไฟล์ดังกล่าว;
- สิ่งที่เครื่องมือพิมพ์ออกมาจะตัดประโยคออกไป เนื่องจาก AI agent ที่อ่าน
  เทอร์มินัลจะส่งสิ่งที่อ่านได้ไปยังผู้ให้บริการโมเดลของตน `mt-eval compare`
  จะแสดง id ของรายการและคะแนนแทนที่จะแสดงประโยค และข้อความแสดงข้อผิดพลาด
  ที่ยกคำพูดจากประโยคจะถูกพิมพ์โดยตัดประโยคนั้นออกไป `--show-text` จะพิมพ์ประโยคเหล่านั้นสำหรับ
  บุคคลที่อยู่ที่เทอร์มินัล ไฟล์ที่เขียนลงในโฟลเดอร์ผลลัพธ์ของคุณจะเก็บ
  ข้อความไว้ และแต่ละไฟล์จะมีเครื่องหมายของคลังข้อมูลกำกับไว้: บันทึกการรัน, รายงาน,
  ไฟล์เปรียบเทียบ และแดชบอร์ดทุกรายการที่ harness เขียนขึ้นจากคลังข้อมูล จะได้รับ
  `.champollion.json` ของตนเองพร้อมข้อกำหนดเดียวกันบวกด้วย `derived_from` เครื่องมือ
  ถัดไป หรือการรันไฟล์นั้นในภายหลัง ก็จะถือว่าไฟล์นั้นได้รับการคุ้มครองเช่นกัน
  เทอร์มินัลจะระบุชื่อแต่ละไฟล์ที่เก็บข้อความไว้;
- แคชการแปลจะแยกรายการของคลังข้อมูลนี้ไว้ต่างหาก: ภายใต้
  `<cache-dir>/protected/<namespace>/` (โดยค่าเริ่มต้นคือ
  `eval/cache/harness/protected/…`) ในเนมสเปซที่มีคีย์ตามการตั้งค่า
  ของการรัน, sha256 ของคลังข้อมูล และข้อกำหนดของคลังข้อมูล เพื่อให้รายการถูก
  ส่งคืนให้กับการรันบนคลังข้อมูลเดียวกันนี้เท่านั้น — จะไม่ส่งให้กับการรันบนคลังข้อมูลอื่นหรือ
  คลังข้อมูลที่ไม่มีเครื่องหมายกำกับ ทุกไฟล์แคชในนั้นจะมีเครื่องหมาย `.champollion.json`
  เดียวกันนี้ (รายการที่แคชไว้ก่อนที่จะมีมาตรการคุ้มครองนี้จะอยู่ในแคชปกติ
  โดยไม่มีเครื่องหมายกำกับ ให้ลบ `eval/cache/harness/` หนึ่งครั้งเพื่อล้างรายการเหล่านั้น)

เครื่องหมายนี้ทำได้เพียงทำให้คลังข้อมูลมีความเข้มงวดมากขึ้นเท่านั้น ไม่มีสัญญาอนุญาตและไม่มี
แฟล็ก `--allow-data-collection` ใดที่จะผ่อนปรนได้ หากไฟล์เครื่องหมาย
ไม่สามารถอ่านได้ การรันจะหยุดทำงานแทนที่จะเพิกเฉยต่อไฟล์นั้น

**การปิดผนึก (Sealed) คือการรับประกันที่แข็งแกร่งที่สุดที่ระบบมอบให้** คลังข้อมูลของคุณจะ
ถูกเข้ารหัส**บนอุปกรณ์ของคุณ** ด้วยคีย์ของกลุ่มผู้ดูแล และข้อความที่เข้ารหัสแล้ว (ciphertext)
จะคงอยู่บนเครื่องของคุณหรือโหนดประเมินผลของคุณ Champollion จะได้รับเฉพาะ
การ์ดที่ไม่มีเนื้อหาเท่านั้น บนโหนดออฟไลน์ คีย์จะถูกแบ่งย่อยออกเพื่อให้ต้องใช้ผู้ดูแล
ร่วมกันจำนวน **M จาก N คน** ในการอนุมัติการรัน กระบวนการดังกล่าวถูกสร้างขึ้นแล้วแต่
ยังไม่เคยถูกนำไปใช้กับผู้ดูแลจริง ชุดข้อมูลที่ปิดผนึกจะได้รับการจัดทำแคตตาล็อกแต่ถูกกักกันไว้ และจะถูกจับคู่กับ
คลังข้อมูล*คัดเลือกคุณสมบัติ (qualifier)* แบบสาธารณะ ซึ่งวิธีการหนึ่ง ๆ จะต้องผ่านการทดสอบนี้ก่อนจึงจะสามารถ
เสนอให้ทำการรันแบบปิดผนึกได้ โปรดดู [เรียกใช้ Sovereign Contest](/docs/network/sovereignty/run-a-sovereign-contest) และ [Sovereign Eval Node](/docs/network/sovereignty/sovereign-eval-node)

### 2b. ขอบเขตสิทธิ์การใช้งาน — คลังข้อมูลสามารถนำไปใช้ทำอะไรได้บ้าง

นอกจากนี้ สัญญาอนุญาตยังควบคุมว่าผลลัพธ์จะสามารถปรากฏที่ใดได้บ้าง

#### สาธารณะ

corpus ที่มีลิขสิทธิ์เปิด (เช่น CC0, CC-BY) ซึ่ง references อาจปรากฏบนพื้นผิวสาธารณะและ runs อาจติดอันดับบน public leaderboard เนื้อหายังคงเป็น fetch-from-source — "public" ควบคุม *การเปิดเผย references และ rankings* ไม่ใช่การโฮสต์ catalogue ส่วนใหญ่ (Tatoeba, GlobalVoices, TICO-19, IN22, SMOL, ALT, Turkic-x-WMT, WMT24++) อยู่ใน lane นี้

#### วิจัยที่ไม่ใช่เชิงพาณิชย์เท่านั้น

corpus ภายใต้ลิขสิทธิ์ non-commercial (เช่น CC BY-NC-SA หรือลิขสิทธิ์เฉพาะของชุมชน/NGO เช่น `LicenseRef-TWB-Gamayun` ของ Gamayun kits) สามารถ **benchmark เพื่อการวิจัย** ได้ — methods รันบนมัน scores ถูกคำนวณ — แต่มัน **ถูกแยกออกจากทุกเส้นทางเชิงพาณิชย์ รางวัล และ API** สิทธิ์การใช้งานขึ้นอยู่กับ **การใช้งาน** ไม่ใช่ corpus:

- **commercial lane เข้มงวด** — สิ่งที่ไม่มีลิขสิทธิ์เชิงพาณิชย์อย่างชัดเจนจะถูกยกเว้น
- **research lane ผ่อนปรน** — corpora non-commercial ยินดีต้อนรับ
- **quarantine ชนะเสมอ** — corpus ที่ถูกตั้งค่าสถานะว่าเป็น subset ที่ไม่เหมาะสม (หรือถูกห้ามด้วยเหตุผลอื่น) จะไม่สามารถติดอันดับใน *lane ใด ๆ* ได้ ไม่ว่าจะมีลิขสิทธิ์อะไร

นี่คือวิธีที่ชุมชนสามารถให้ corpus ของตนขับเคลื่อนความก้าวหน้าของการวิจัย ในขณะที่ยังคงป้องกันไม่ให้มันถูกนำไปใช้ในผลิตภัณฑ์ใด ๆ

#### ส่วนตัว

corpus ที่ลงทะเบียนสำหรับ **scored runs ของคุณเอง** ซึ่ง references จะไม่ถูกเผยแพร่ คุณถือครองแหล่งที่มา คุณรัน evaluation คุณตัดสินใจว่าจะแสดงอะไร หากมี corpus แบบ private สามารถเปลี่ยนเป็น public หรือ non-commercial ในภายหลังได้ — การเปิดเผยจะ *ขยายออก* เท่านั้นโดยการตัดสินใจอย่างชัดเจนของเจ้าของ ไม่มีการเปลี่ยนแปลงโดยปริยาย

| ขอบเขตสิทธิ์การใช้งาน | เทียบเคียงสมรรถนะได้ | แสดงข้อมูลอ้างอิงต่อสาธารณะ | สามารถจัดอันดับบนบอร์ดสาธารณะได้ | อยู่ในเส้นทางเชิงพาณิชย์ / รางวัล / API |
|------|:---:|:---:|:---:|:---:|
| **สาธารณะ** | ✅ | ✅ | ✅ | ✅ (หากสัญญาอนุญาตยินยอม) |
| **วิจัยที่ไม่ใช่เชิงพาณิชย์เท่านั้น** | ✅ | ขึ้นอยู่กับสัญญาอนุญาต | ขอบเขตการวิจัยเท่านั้น | ❌ |
| **ส่วนตัว** | ✅ (การรันของคุณ) | ❌ | ❌ | ❌ |

:::note[เลนเชิงพาณิชย์คือราวกันตก ไม่ใช่ธุรกิจ]
Champollion เองเป็นโครงการไม่แสวงหากำไร — ไม่มี API แบบชำระเงินหรือผลิตภัณฑ์ใดอยู่เบื้องหลัง
เลนเชิงพาณิชย์/รางวัลมีขึ้นเพื่อเป็นราวกันตก *เชิงป้องกันล่วงหน้า*: มันบันทึกไว้โดยอัตโนมัติว่า
corpus ใดบ้างที่อาจปรากฏในบริบทของรางวัลหรือเชิงพาณิชย์ได้อย่างถูกต้องตามกฎหมาย
เพื่อให้การใช้งานในอนาคต — โดยผู้ใดก็ตาม — ไม่สามารถละเมิดสัญญาอนุญาตหรือเงื่อนไขของผู้ดูแลได้
:::

## 3. การรับประกันอธิปไตย

การลงทะเบียนถูกออกแบบรอบ [ตำแหน่งการดูแลข้อมูล](/docs/network/sovereignty/data-sovereignty) โดยเฉพาะ:

- **การครอบครองอยู่กับแหล่งที่มา** เราถือ hash และ URL ไม่ใช่ข้อมูล
- **การควบคุมเป็นของเจ้าของ** lane เป็นทางเลือกของเจ้าของ และการเปิดเผยจะขยายออกเท่านั้นโดยการตัดสินใจอย่างชัดเจน การนำ archive ต้นทางออกจะเพิกถอนความสามารถในการรัน
- **Non-commercial หมายถึง non-commercial** corpora แบบ NC ถูกยกเว้นจาก commercial, prize และ API lanes อย่างเป็นกลไก — ไม่ใช่แค่คำสัญญา แต่เป็น gate
- **Subsets ที่ไม่เหมาะสมไม่สามารถติดอันดับได้** Quarantine ลบล้างลิขสิทธิ์ ดังนั้น corpus ที่ถูกห้ามจากการติดอันดับจะถูกห้ามทุกที่
- **Attribution เป็นสิ่งบังคับ** เครดิต builder/linguist จะติดไปกับ card ทุกพื้นผิวที่ corpus ปรากฏ

สำหรับวิธีการกำหนดเงื่อนไขต่อภาษา — รวมถึงการโอน method-ownership สำหรับ sponsored prizes — ดู [Ownership & Terms](/docs/network/sovereignty/ownership-transfer)

## 4. วิธีการลงทะเบียน

schema ของ corpus card และ tooling สำหรับ build/verify ได้รับการบันทึกไว้ใน [Corpus Design Framework](/docs/network/specifications/corpus-design) และ [Corpus Creation cookbook](/docs/network/tutorials/corpus-creation) โดยสรุป:

1. โฮสต์ corpus archive ในที่ที่คุณควบคุม (มันอยู่ที่นั่น — ไม่มีการคัดลอกเข้า Network)
2. เขียน card: `url`, `sha256`, `license`, `language_pair`, `attribution`, `do_not_train`
3. เลือก exposure lane (public / non-commercial / private)
4. ลงทะเบียน card จากนั้น methods สามารถ benchmark เทียบกับ corpus แบบ fetch-from-source ภายใต้กฎของ lane ได้

คุณไม่ต้องอัปโหลดประโยคเลย และสามารถหยุดได้ทุกเมื่อ

### รหัสการ์ด (Card id)

`champollion register-corpus` จะเขียนการ์ดให้คุณและกำหนดรหัสให้อยู่ใน
รูปแบบ `eval-<source>-<target>-<name>[-<role>]-v1`:

- **name** มาจาก `--name`: "Ward phrases" จะกลายเป็น `ward-phrases` ผู้
  เผยแพร่จะถูกนำมาใช้เฉพาะเมื่อชื่อไม่มีอักขระ a–z หรือ 0–9 เลย เช่น
  ชื่อที่เขียนด้วยอักษรแทนพยางค์ (syllabics) เท่านั้น
- **role** ระบุว่าชุดข้อมูลมีไว้เพื่ออะไร: `--role test`, `--role dev` หรือ
  `--role train` โดยจะปรากฏในรหัสก็ต่อเมื่อคุณส่งค่าเข้าไปเท่านั้น เครื่องมือจะไม่
  คาดเดาบทบาท ดังนั้นชุดทดสอบที่แยกเก็บไว้ (held-out test set) จะถูกเรียกว่าชุดทดสอบก็ต่อเมื่อคุณ
  ระบุไว้เช่นนั้น

```bash
champollion register-corpus --yes --name "Ward phrases" --pair "eng>xyz" \
  --license proprietary --tier private --role test --size 120 --domain medical
```

คำสั่งนี้จะลงทะเบียน `eval-eng-xyz-ward-phrases-test-v1` หากต้องการเลือกรหัส
ด้วยตนเอง ให้ส่ง `--id eval-…` ซึ่งจะถูกนำไปใช้ตรงตามที่ระบุไว้ทุกประการ

### รหัสสัญญาอนุญาตใดสำหรับชุดทดสอบส่วนตัว

`--license` จะบันทึกข้อกำหนดที่เจ้าของข้อมูลยินยอมให้อย่างแท้จริง
นี่ไม่ใช่ตัวแทนชั่วคราว (placeholder) และเครื่องมือจะไม่เลือกให้คุณ กรุณาสอบถามเจ้าของข้อมูล
ก่อน (ครอบครัว, บุคลากรทางการแพทย์/คลินิก, ผู้ดูแลข้อมูลของชุมชน) จากนั้นให้เลือก
รหัสที่ตรงกับสิ่งที่พวกเขาอนุญาต:

| สิ่งที่เจ้าของข้อมูลอนุญาต | `--license` |
|---|---|
| พวกเขาเผยแพร่ข้อความภายใต้สัญญาอนุญาตมาตรฐานอยู่แล้ว | รหัส SPDX ของสัญญาอนุญาตนั้น เช่น `CC-BY-NC-4.0` |
| ใช้สำหรับการให้คะแนนระบบเท่านั้น: ห้ามนำไปฝึกฝน (train) โดยเด็ดขาด, ห้ามแจกจ่ายซ้ำ, ห้ามให้บริการประเมินผลแบบมีค่าใช้จ่าย | `community-eval-grant-nc` (`LicenseRef-Champollion-Eval-Grant-NC`) |
| เหมือนข้อข้างต้น แต่อนุญาตให้ประเมินผลคะแนนสำหรับผู้ใช้ที่ชำระเงินได้ | `community-eval-grant` (`LicenseRef-Champollion-Eval-Grant`) |
| ไม่อนุญาตให้ใช้ประโยชน์นอกเหนือจากการใช้งานของตนเอง: สงวนลิขสิทธิ์ทั้งหมด | `proprietary` (`LicenseRef-Proprietary`) |
| ข้อกำหนดเฉพาะของพวกเขาเองที่ไม่มีในตัวเลือกข้างต้น | `LicenseRef-<a name for their terms>` พิมพ์ตามที่เป็น โดยมีการบันทึกข้อกำหนดไว้ในที่ที่ผู้ดูแลข้อมูลจัดเก็บ |

ทุกรหัส `LicenseRef-…` ในตาราง (รวมถึงสิทธิ์การประเมินผลทั้งสองแบบและ
`proprietary`) ถือเป็นสิทธิ์ที่กำหนดขึ้นเฉพาะ (bespoke grant): Champollion จะไม่ตีความแทน
เจ้าของข้อมูลโดยเด็ดขาด การประเมินผลจากระยะไกลกับชุดข้อมูลนี้จะถูกปฏิเสธจนกว่าผู้ดูแลข้อมูล
จะบันทึกการอนุญาตของพวกเขา ดังนั้นจะมีเพียงโมเดลบนเครื่องของคุณเองเท่านั้นที่ได้รับการทดสอบ
กับชุดข้อมูลนี้ หากคุณไม่แน่ใจ ตัวเลือกที่รัดกุมที่สุดที่ยังคงเปิดโอกาสให้
คุณวัดผลได้คือ `community-eval-grant-nc` ให้บันทึกไว้เป็นการชั่วคราวและ
ให้ผู้ดูแลข้อมูลยืนยันหรือระบุตัวเลือกที่ถูกต้อง

สัญญาอนุญาตไม่ได้เปลี่ยนทิศทางว่าประโยคจะถูกส่งไปที่ใด ชุดข้อมูลเฉพาะภายในเครื่อง (เครื่องหมาย
`.champollion.json` หรือ `--tier local-only`) จะคงอยู่บนเครื่องของคุณ
ไม่ว่าสัญญาอนุญาตจะระบุไว้อย่างไร: เครื่องหมายนี้จะปฏิเสธโมเดลทางไกลทุกตัว และ
สัญญาอนุญาตไม่สามารถผ่อนปรนข้อกำหนดนี้ได้ สัญญาอนุญาตจะควบคุมสิ่งที่ผู้อื่นอาจทำกับ
ชุดข้อมูลหากมีการแชร์ในอนาคต และควบคุมว่าชุดข้อมูลจะสามารถเข้าสู่ขอบเขตการประเมินผลใดได้บ้าง เมื่อไฟล์ใด
ได้รับการลงทะเบียนด้วย `--data` แล้ว รหัสของไฟล์จะถูกบันทึกไว้ใน
ไฟล์ `.champollion.json` ที่อยู่ข้างกันและจะไม่มีวันเปลี่ยนแปลง การลงทะเบียนไฟล์นั้น
ซ้ำอีกครั้งจะหยุดทำงานและขอให้คุณส่งรหัสด้วย `--id`

สำหรับชุดทดสอบที่โมเดลอาจถูกนำไปฝึกฝนด้วย (`--role test` หรือ
ชุดข้อมูลเฉพาะภายในเครื่องหรือชุดข้อมูลส่วนตัวที่ไม่มีการระบุบทบาท) จากนั้นคำสั่งจะพิมพ์
ขั้นตอนของ nmt-forge ที่ต้องทำก่อนการให้คะแนนครั้งแรกของชุดข้อมูล: ลงทะเบียนชุดข้อมูล,
ตรวจสอบคัดกรองคลังข้อมูลสำหรับการฝึกฝนของคุณเทียบกับชุดข้อมูล และบันทึกผลการทำนายของคุณ
การรัน baseline `mt-eval run` จะตามมาหลังจากขั้นตอนเหล่านั้น การเทียบเคียงสมรรถนะ (benchmark) คือการอ่านเพื่อคิดคะแนน
และ nmt-forge จะปฏิเสธการส่งผลทำนายที่ถูกบันทึกหลังจากที่มีการอ่านผลคะแนนไปแล้ว

`mt-eval run --corpus <that file>` จะค้นหาการ์ดผ่านไฟล์
`.champollion.json` เดียวกันนี้ รหัสชุดข้อมูลของการรันจะตรงกับรหัสของการ์ด ดังนั้นทุกการรัน
บนชุดข้อมูลนี้จะใช้ชื่อเดียวกัน และชื่อไฟล์จะยังคงอยู่บนการรันในฐานะพาธของ
คลังข้อมูล เกรดการปนเปื้อนของการ์ดจะถูกรายงานตามที่การ์ดระบุ
ไว้ ทั้งสองส่วนนี้จะมีผลเฉพาะตราบใดที่ไฟล์นั้นยังคงเป็นไฟล์เดียวกับที่คุณลงทะเบียนไว้: หากมีการ
เปลี่ยนแปลงหลังจากนั้น การรันจะแจ้งเตือนและไม่นำค่าทั้งสองมาใช้

การ์ดแบบ `local-only`, `private` หรือ `sealed` จะระบุว่าข้อความยังไม่ได้รับการเผยแพร่
(`Contamination: NONE`) ดังนั้นการลงทะเบียนจะเปรียบเทียบไฟล์ที่คุณส่งเข้ามา
ด้วย `--data` (หรือ `--seal-input`) กับคลังข้อมูลสาธารณะก่อนเป็นอันดับแรก หากเป็นการเช็คเอาต์
เรโพซิโทรี จะทำการเปรียบเทียบกับการ์ดคลังข้อมูลที่เก็บอยู่ แต่หากเป็นการติดตั้งผ่าน npm ซึ่ง
ไม่มีการส่งมอบการ์ดคลังข้อมูลมาด้วย จะทำการเปรียบเทียบกับแคตตาล็อกคลังข้อมูลสาธารณะ: CLI
จะดาวน์โหลด id และผลรวมตรวจสอบ (checksum) ของคลังข้อมูลสาธารณะ แล้วนำมาเปรียบเทียบบน
เครื่องของคุณ เพื่อไม่ให้ผลรวมตรวจสอบของไฟล์ของคุณหลุดออกไปจากเครื่อง เมื่อไฟล์ตรงกันแบบไบต์ต่อ
ไบต์กับคลังข้อมูลสาธารณะ (sha256 เดียวกัน) การลงทะเบียนจะหยุดทำงานและระบุชื่อคลังข้อมูลนั้น
ให้ลงทะเบียนเป็นแบบสาธารณะ, ใช้ประโยคที่เป็นส่วนตัวอย่างแท้จริง หรือคง
ระดับเดิมไว้แล้วระบุสถานะการเปิดเผยข้อมูลด้วย `--contamination` (จากนั้นการ์ดจะบันทึก
ว่าข้อความเป็นสาธารณะ) ชุดข้อมูลที่ปิดผนึกซึ่งมีข้อความเป็นสาธารณะจะถูกปฏิเสธ: เพราะจะไม่
สามารถทดสอบอะไรได้เลย

เมื่อไม่สามารถทำการเปรียบเทียบได้ (คุณออฟไลน์อยู่ หรือไม่สามารถเข้าถึง
แคตตาล็อกได้) การ์ดจะได้รับการจัดเกรดเป็น `Contamination: UNCHECKED` ไม่ใช่ `NONE` เว้นแต่
คุณจะระบุเกรดด้วยตนเองโดยใช้ `--contamination` ให้ลงทะเบียนใหม่อีกครั้งในขณะออนไลน์เพื่อ
ทำการเปรียบเทียบ `mt-eval` จะปฏิบัติต่อคลังข้อมูล `UNCHECKED` เสมือนคลังข้อมูลใด ๆ ที่
ไม่ได้รับการจัดเกรดเป็น `LOW`: คะแนนของการรันจะเข้าสู่ขอบเขตการเปรียบเทียบเชิงสัมพัทธ์เท่านั้น การ
ตรวจสอบจะเปรียบเทียบทั้งไฟล์ ดังนั้นชุดข้อมูลสาธารณะที่มีการแก้ไขหรือจัดรูปแบบใหม่จะไม่
ถูกตรวจพบว่าเป็นไฟล์เดิม; `mt-eval contest prepare` จะทำการเปรียบเทียบเป็นรายแถว
