# การแปลบางส่วน (มนุษย์ + เครื่อง)

> **แนวคิด:** แปลตัวอย่างที่เป็นตัวแทนด้วยมนุษย์ก่อน พิสูจน์ว่าวิธีการของเครื่องตรงกับสไตล์ของมนุษย์ในตัวอย่างนั้น แล้วจึงแปลส่วนที่เหลือทั้งหมดด้วยเครื่องอัตโนมัติ — ผสมผสานคุณภาพของมนุษย์เข้ากับขนาดของเครื่อง โดยมนุษย์เป็นผู้กำหนดมาตรฐาน และเครื่องเป็นผู้ปฏิบัติตาม

:::info[นี่คือ cookbook ไม่ใช่การ implement ที่สมบูรณ์]
คู่มือนี้อธิบายภาพรวมของ workflow แบบผสมผสานระหว่างมนุษย์และเครื่องจักร เหมาะเป็นพิเศษสำหรับเอเจนซีแปลภาษา นักภาษาชุมชน และบริบทด้านการศึกษา
:::

## เมื่อใดควรใช้แนวทางนี้

- คุณมี**ผู้พูดภาษาที่คล่องแคล่ว**แต่เวลาของพวกเขามีจำกัด
- คุณต้องแปล**ปริมาณมาก** แต่มีเพียงส่วนเล็กน้อยที่ต้องการความสมบูรณ์แบบ
- คุณต้องการ**กำหนดเกณฑ์คุณภาพ**ด้วยการแปลของมนุษย์ก่อน แล้วจึงขยายขนาดด้วย MT
- คุณทำงานใน**บริบทด้านการศึกษาหรือชุมชน** ที่การตรวจสอบโดยมนุษย์ในส่วนย่อยเป็นไปได้จริง

## วิธีการทำงาน

```
[Full corpus: 1,000 entries]
        │
        ├── [100 entries] ──→ Human translator ──→ Gold translations
        │                                              │
        │                                              ▼
        │                                    Train / prompt machine
        │                                    method to match style
        │                                              │
        └── [900 entries] ──→ Machine method ──→ Auto translations
                                                       │
                                                       ▼
                                              [Optional: human review
                                               of flagged entries]
```

1. **เลือกตัวอย่างที่เป็นตัวแทน** — ครอบคลุมประเภทประโยค ความยาว และหัวข้อที่หลากหลาย
2. **แปลตัวอย่างด้วยมนุษย์** — กำหนดมาตรฐานทองสำหรับสไตล์ ระดับภาษา และคำศัพท์เฉพาะ
3. **กำหนดค่าวิธีการของเครื่อง** — ใช้การแปลของมนุษย์เป็นข้อมูลสำหรับ coaching, ตัวอย่าง few-shot หรือข้อมูล fine-tuning
4. **ประเมินเครื่องด้วยตัวอย่างของมนุษย์** — เครื่องตรงกับสไตล์ของมนุษย์หรือไม่?
5. **แปลส่วนที่เหลือด้วยเครื่องอัตโนมัติ** — หากคุณภาพของเครื่องเป็นที่ยอมรับในตัวอย่าง
6. **การตรวจสอบโดยมนุษย์ (ไม่บังคับ)** — ทำเครื่องหมายผลลัพธ์ที่มีความมั่นใจต่ำเพื่อให้ผู้พูดตรวจสอบ

## การประกันคุณภาพ: การทดสอบความตรงกันของสไตล์

```bash
# Translate the human-translated sample with your machine method
mt-eval run \
  --corpus data/human-sample.json \
  --name coached-v3

# Compare: does the machine match the human translator's choices?
# Look at: chrF++ (similarity), FST acceptance (validity),
# and qualitative patterns (register, formality, terminology)
```

## การเลือกตัวอย่าง

**ครอบคลุมการกระจาย** รายการ 100 รายการของคุณควรประกอบด้วย:
- วลีสั้น (1–3 คำ) และประโยคเต็ม
- คำศัพท์ทั่วไปและคำศัพท์เฉพาะทาง
- โครงสร้างง่ายและซับซ้อน
- คุณลักษณะทางไวยากรณ์หลายรูปแบบ (คำถาม คำสั่ง เงื่อนไข)

**อย่าเลือกเฉพาะรายการที่ง่าย** ตัวอย่างต้องรวมรายการที่วิธีการของคุณมีแนวโน้มจะมีปัญหา — นั่นคือจุดที่คุณภาพของมนุษย์มีความสำคัญที่สุด

## Workflow การตรวจสอบโดยชุมชน

สำหรับชุมชนภาษาพื้นเมือง แนวทางนี้ให้ความเคารพต่อเวลาของผู้พูด:

1. **ผู้พูดแปล 50–100 รายการ** (งานที่ต้องใช้สมาธิ 2–4 ชั่วโมง)
2. **เครื่องแปล 900 รายการที่เหลือ** โดยใช้งานของผู้พูดเป็นข้อมูล coaching
3. **ผู้พูดตรวจสอบรายการที่ถูกทำเครื่องหมาย** — เฉพาะรายการที่เครื่องมีความมั่นใจน้อยที่สุด (อีก 1–2 ชั่วโมง)
4. **ผลลัพธ์:** การแปล 1,000 รายการที่มีคุณภาพใกล้เคียงมนุษย์ โดยใช้เวลาของผู้พูดประมาณ 5 ชั่วโมง แทนที่จะเป็น ~50 ชั่วโมง

## ข้อดีและข้อเสีย

| | |
|---|---|
| ✅ ผสมผสานคุณภาพของมนุษย์กับขนาดของเครื่อง | ❌ ต้องการการลงทุนจากมนุษย์ในช่วงแรก |
| ✅ ให้ความเคารพต่อความพร้อมของผู้พูดที่มีจำกัด | ❌ เครื่องอาจไม่สามารถจับความละเอียดอ่อนของสไตล์ได้ทั้งหมด |
| ✅ Workflow การประกันคุณภาพที่เป็นธรรมชาติ | ❌ การเลือกตัวอย่างส่งผลต่อคุณภาพโดยรวม |
| ✅ เหมาะอย่างยิ่งสำหรับบริบทชุมชน/การศึกษา | ❌ การตรวจสอบโดยมนุษย์อาจเป็นคอขวดสำหรับรายการที่ถูกทำเครื่องหมาย |
