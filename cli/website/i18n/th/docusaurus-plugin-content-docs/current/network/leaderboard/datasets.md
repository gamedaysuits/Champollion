# ชุดข้อมูลสำหรับการประเมิน

> **บทสรุปสำหรับผู้บริหาร** หน้านี้อธิบายชุดข้อมูลการประเมิน (evaluation datasets) ที่มีให้ใช้งานสำหรับการทดสอบประสิทธิภาพ (benchmarking) รวมถึงสกีมาของรายการคลังข้อมูล ระดับความยาก (1–5) และข้อกำหนดด้านแหล่งที่มา แคตตาล็อกนี้ประกอบด้วย**ชุดข้อมูลการประเมินแบบดึงข้อมูลจากต้นทาง (fetch-from-source) ประมาณ 4,700 ชุดจาก 19 ตระกูลคลังข้อมูล** (TICO-19, IN22, Tatoeba, GlobalVoices, SMOL, ALT, Turkic-x-WMT, WMT24++, ชุดทดสอบแบบไม่เปิดเผย WMT newstest/General ปี 2014–2025, MAFAND-MT, NusaX, NusaTranslation, LoResMT, AmericasNLP 2021, NICT-SAP, BSD, MENYO-20k, Gamayun, EdTeKLA) รวมทั้ง FLORES+ — *เนื้อหา*ของคลังข้อมูลจะไม่ถูกโฮสต์ไว้ที่นี่ แต่ละชุดข้อมูลคือการ์ดเมทาดาตาที่ล็อกค่า sha (sha-pinned metadata card) ซึ่งถูกสร้างขึ้นใหม่แบบกำหนดผลลัพธ์แน่นอน (deterministically) จากไฟล์เก็บถาวรต้นน้ำที่ล็อกไว้ **เลนสำหรับวัตถุประสงค์ที่ไม่ใช่เชิงพาณิชย์ / สำหรับการวิจัยเท่านั้น** (Gamayun, EdTeKLA, MAFAND-MT, NusaTranslation, LoResMT, AmericasNLP, NICT-SAP, BSD, MENYO-20k และชุดสำหรับการใช้งานวิจัยของ WMT) จะถูกแยกออกจากเส้นทางเชิงพาณิชย์ / ชิงรางวัล / API ใดๆ และภายในเลนนี้ คลังข้อมูลที่อยู่ภายใต้การอนุญาตที่มีการแก้ไข กำหนดขึ้นเฉพาะ หรือไม่ได้ระบุไว้ จะถูก**ควบคุมด้วยความยินยอม (consent-gated)** เพิ่มเติม — การประเมินผ่าน API โมเดลระยะไกลจะปฏิเสธการทำงาน เว้นแต่ข้อความสัญญาอนุญาตจะอนุญาตให้ใช้เพื่อการประเมินโดยตรง (บันทึกเป็นการตัดสินใจอย่างชัดเจนในแต่ละชุดข้อมูล เช่นเดียวกับชุดสำหรับการใช้งานวิจัยของ WMT) หรือมีการบันทึกการอนุญาตจากผู้ถือสิทธิ์ไว้ในรายการชุดข้อมูล ชุดข้อมูลอ้างอิงที่มนุษย์คัดสรรสองชุด ได้แก่ EDTeKLA Dev v1 (Plains Cree) และ FLORES+ Devtest (คู่ภาษาที่ลงรายการไว้ 870 คู่ แต่ละคู่มี 1,012 ประโยค) มีรายละเอียดระบุไว้ด้านล่างนี้ โดยรายละเอียดจำนวนรายการทั้งหมดของ EdTeKLA ระบุไว้เพียงครั้งเดียวใน[ส่วนของชุดข้อมูลดังกล่าว](#edtekla-development-set-v1)

ชุดข้อมูลคือเป้าหมายคงที่ที่ harness ใช้ในการทดสอบ แต่ละชุดข้อมูลเป็นไฟล์ JSON ที่ประกอบด้วยคู่ต้นฉบับ→เป้าหมายพร้อมการอ้างอิงมาตรฐานทองคำ harness จะให้คะแนนผลลัพธ์ของโมเดลเทียบกับการอ้างอิงเหล่านี้ โดยไม่มีการแก้ไขใดๆ

:::danger[ห้ามนำข้อมูลการประเมินไปใช้ฝึกโมเดล]

⚠️ **ชุดข้อมูลเหล่านี้มีไว้สำหรับการประเมินเท่านั้น** วิธีการที่ถูกฝึก fine-tune few-shot-prompted หรือสัมผัสกับข้อมูลสำหรับการประเมินในรูปแบบใดก็ตาม จะให้คะแนนที่สูงเกินจริงและจะ**ถูกตัดสิทธิ์จากลีดเดอร์บอร์ด**

ใช้ corpus แยกต่างหากสำหรับการฝึก ชุดข้อมูลสำหรับการประเมินต้องไม่ถูกเปิดเผยต่อโมเดลของคุณในระหว่างการพัฒนา
:::

## รูปแบบชุดข้อมูล {#dataset-format}

ชุดข้อมูลทุกชุดใช้สคีมา JSON เดียวกัน:

```json
{
  "dataset": {
    "id": "dataset-slug",
    "version": "1.0",
    "language_pair": "EN→CRK",
    "description": "Human-readable description of the dataset",
    "source_language": "en",
    "target_language": "crk",
    "created": "2025-05-01",
    "license": "CC-BY-NC-4.0",
    "provenance": ["gold_standard", "textbook"]
  },
  "entries": [
    {
      "id": 1,
      "source": "Hello",
      "reference": "tânisi",
      "difficulty": 1,
      "provenance": "gold_standard",
      "register": "conversational",
      "context": "greeting",
      "notes": "Common greeting, SRO orthography"
    }
  ]
}
```

:::info[สคีมามาตรฐาน]
[ข้อกำหนด Benchmark](/docs/network/specifications/benchmark) กำหนดสคีมาคอร์ปัสและรายการมาตรฐาน หน้านี้จัดทำเอกสารชุดข้อมูลที่มีอยู่และวิธีการสร้างชุดข้อมูลใหม่
:::

### บล็อก `dataset` ระดับบนสุด

| ฟิลด์ | ประเภท | คำอธิบาย |
|-------|------|-------------|
| `id` | `string` | ตัวระบุชุดข้อมูลที่ไม่ซ้ำกัน (ใช้ใน run card และลีดเดอร์บอร์ด) |
| `version` | `string` | Semantic version การเพิ่มค่านี้จะทำให้การเปรียบเทียบ run card ก่อนหน้าใช้ไม่ได้ |
| `language_pair` | `string` | ป้ายชื่อสำหรับแสดงผล (เช่น `EN→CRK`) |
| `description` | `string` | ไม่บังคับ สรุปที่มนุษย์อ่านได้ |
| `source_language` | `string` | รหัสภาษาต้นฉบับตาม BCP 47 |
| `target_language` | `string` | รหัสภาษาเป้าหมายตาม BCP 47 |
| `created` | `string` | วันที่สร้างตาม ISO 8601 |
| `license` | `string` | ตัวระบุสัญญาอนุญาต SPDX |
| `provenance` | `string[]` | รายการแท็กที่มาของข้อมูลที่ใช้ในรายการต่างๆ |

### ฟิลด์รายการ

| ฟิลด์ | ประเภท | จำเป็น | คำอธิบาย |
|-------|------|----------|-------------|
| `id` | `integer` | ✅ | ตัวระบุรายการที่ไม่ซ้ำกันภายใน corpus |
| `source` | `string` | ✅ | ข้อความต้นฉบับที่ต้องการแปล |
| `reference` | `string` | ✅ | การแปลอ้างอิงมาตรฐานทองคำ |
| `difficulty` | `integer` | ✅ | ระดับความยาก 1–5 (ดูด้านล่าง) |
| `provenance` | `string` | ✅ | ที่มาของรายการนี้ (เช่น `gold_standard`, `textbook`, `elicited`) |
| `register` | `string` | ✅ | ระดับทะเบียน/ความเป็นทางการ (เช่น `conversational`, `formal`, `ceremonial`) |
| `context` | `string` | ✅ | หน้าที่การสื่อสาร (เช่น `greeting`, `declaration`, `instruction`) |
| `notes` | `string` | ❌ | บริบทเสริมสำหรับผู้ตรวจสอบที่เป็นมนุษย์ |
| `morphological_analysis` | `string` | ❌ | การวิเคราะห์สัณฐานวิทยามาตรฐานทองคำ |
| `variant_class` | `string` | ❌ | ป้ายกำกับคลาสที่จัดกลุ่มรูปแบบการแปลที่ยอมรับได้ |

## ชุดข้อมูลที่มีอยู่

แคตตาล็อกนี้ประกอบด้วย**ชุดข้อมูลการประเมินแบบดึงข้อมูลจากต้นทางประมาณ 4,700 ชุดจาก 19 ตระกูลคลังข้อมูล** รวมกับชุดข้อมูลอ้างอิงที่มนุษย์คัดสรรสองชุด (EDTeKLA + FLORES)
ที่มีรายละเอียดด้านล่าง — รวมทั้งหมดในรีจิสทรี **5,601 ชุดข้อมูล** ณ วันที่ 2026-09-06 ทุกคลังข้อมูล
คือ**การ์ดเมทาดาตาที่ล็อกค่า sha** — เนื้อหาของคลังข้อมูลจะไม่ถูกโฮสต์ไว้ที่นี่ แต่จะถูกสร้างขึ้นใหม่
แบบกำหนดผลลัพธ์แน่นอนจากไฟล์เก็บถาวรต้นน้ำที่ล็อกไว้ ณ เวลาที่ทำการประเมิน
ทุกชุดข้อมูลมี `do_not_train` การ์ดต้นทางหนึ่งใบจะกระจายออกเป็นชุดข้อมูลเฉพาะแต่ละคู่ภาษา
จำนวนมาก ดังนั้นยอดรวมในรีจิสทรีจึงมากกว่าการ์ดต้นทางที่มีอยู่ประมาณ 1,417 ใบ
ชุดข้อมูลในเลนเปิดจะป้อนเข้าสู่คิว sweep โดยตรง ส่วนเลนสำหรับการวิจัยเท่านั้นจะทำงาน
ตามต้องการเมื่อสัญญาอนุญาตระบุไว้อย่างชัดเจนว่าอนุญาต (การอนุญาตที่มีการแก้ไข/กำหนดขึ้นเฉพาะ/ไม่ได้ระบุไว้
จะถูกควบคุมด้วยความยินยอมสำหรับการประเมินผ่าน API โมเดลระยะไกล)

:::info[เลนที่ไม่ใช่เชิงพาณิชย์สำหรับการวิจัยเท่านั้น]
แคตตาล็อกส่วนใหญ่ใช้สัญญาอนุญาตแบบเสรี (CC0, CC-BY-2.0/3.0/4.0, MIT,
Apache-2.0) และสามารถใช้ได้ในทุกเลน มีส่วนน้อย — ได้แก่ **Gamayun** (สัญญาอนุญาต
เฉพาะของ TWB) และ **EDTeKLA** (CC BY-NC-SA ที่มีการแก้ไขและจำกัดขอบเขตตามอำนาจอธิปไตย) — ที่เป็นแบบ**ไม่ใช่เชิงพาณิชย์**: ซึ่งจะถูก
ตัดออกจากเส้นทางเชิงพาณิชย์ ชิงรางวัล หรือ API ใดๆ ทั้งหมด สำหรับคลังข้อมูลที่อยู่ภายใต้
การอนุญาตที่มีการแก้ไข กำหนดขึ้นเฉพาะ หรือไม่ได้ระบุไว้ การประเมินผ่าน API โมเดลระยะไกล
จะถูก**ควบคุมด้วยความยินยอม**เพิ่มเติม: harness จะปฏิเสธการส่งข้อความไปยัง
API โมเดลของบุคคลที่สาม เว้นแต่ข้อความสัญญาอนุญาตจะอนุญาตให้ใช้เพื่อการประเมินโดยตรง
(บันทึกเป็นการตัดสินใจอย่างชัดเจนในแต่ละชุดข้อมูล — ซึ่งชุดสำหรับการใช้งานวิจัยของ WMT
มีการบันทึกนี้ไว้) หรือมีการบันทึกการอนุญาตอย่างชัดเจนจากผู้ถือสิทธิ์ไว้ใน
รายการชุดข้อมูล (การประเมินในเครื่องยังคงทำได้) สิทธิ์ในการใช้งานจะขึ้นอยู่กับ**กรณีการใช้งาน**: เลนเชิงพาณิชย์จะเข้มงวด
เลนวิจัยจะผ่อนปรน และสถานะการกักกันจะมีความสำคัญสูงสุดเสมอ (คลังข้อมูลของ EdTeKLA จะถูก
กักกันทันที และฐานข้อมูลจะปฏิเสธคะแนนใดๆ ที่ส่งเข้ามาสำหรับคลังข้อมูลนี้) ดูที่
[การลงทะเบียนคลังข้อมูลและเลนการเปิดเผย](/docs/network/sovereignty/registering-corpora) สำหรับ
วิธีที่คลังข้อมูลใช้เลือกเลน
:::

ชุดข้อมูลอ้างอิงมีรายละเอียดด้านล่าง corpus ของแต่ละตระกูลใช้สคีมา JSON เดียวกันและแสดงอยู่ในรีจิสทรีชุดข้อมูล

:::note[แคตตาล็อกไม่ใช่กระดานที่มีข้อมูลครบถ้วน]
แคตตาล็อกคอร์ปัสขนาดใหญ่คือสิ่งที่วิธีการต่าง ๆ *สามารถ* นำมาทดสอบประสิทธิภาพได้ — ไม่ใช่กระดานจัดอันดับที่เต็มไปด้วยผลลัพธ์ กระดานดังกล่าวอยู่ในระหว่างการเริ่มต้น ดูรายละเอียดที่

## การสร้างชุดข้อมูลใหม่

ในการสร้างชุดข้อมูลสำหรับคู่ภาษาหรือโดเมนใหม่:

### 1. จัดโครงสร้าง JSON

ปฏิบัติตามสคีมา [รูปแบบชุดข้อมูล](#dataset-format) ทุกรายการต้องมี `source`, `reference`, `difficulty`, `provenance`, `register` และ `context`

### 2. กำหนด ID ที่ไม่ซ้ำกัน

ใช้ slug ที่สื่อความหมาย: `{project}-{split}-v{version}` (เช่น `edtekla-dev-v1`, `quechua-test-v1`)

### 3. ตรวจสอบมาตรฐานทองคำ

ค่า `reference` ทุกค่าต้องได้รับการตรวจสอบโดยผู้พูดภาษาที่คล่องแคล่วหรือนำมาจากแหล่งที่ตีพิมพ์และผ่านการตรวจสอบโดยผู้เชี่ยวชาญ การอ้างอิงที่สร้างโดยเครื่องจะทำให้วัตถุประสงค์ของการประเมินสูญเสียไป

### 4. กำหนดระดับความยาก

กำหนดระดับความยากเป็นจำนวนเต็มให้กับแต่ละรายการ:

| ระดับ | คำอธิบาย | ตัวอย่าง |
|------|-------------|----------|
| 1 — คำศัพท์พื้นฐาน | คำเดี่ยว คำทักทายทั่วไป ตัวเลข | "hello" → "tânisi" |
| 2 — ประโยคง่าย | ประธาน-กริยา หรือ SVO กาลปัจจุบัน | "I see the dog" |
| 3 — ความซับซ้อนปานกลาง | กาลอดีต/อนาคต possessive animacy | "I saw his dog yesterday" |
| 4 — สัณฐานวิทยาซับซ้อน | Obviation passive voice conjunct order | "the woman whose son went to the store" |
| 5 — ขั้นสูง | หลายอนุประโยค ทะเบียนทางการ พิธีกรรม สำนวน | ย่อหน้าเต็มพร้อมน้ำเสียงที่เหมาะสมกับทะเบียน |

### 5. ติดแท็กที่มาของข้อมูล

แต่ละรายการควรระบุที่มา แท็กที่ใช้บ่อย:

- `gold_standard` — ตรวจสอบโดยผู้พูดภาษาที่คล่องแคล่ว
- `textbook` — นำมาจากสื่อการศึกษาที่ตีพิมพ์แล้ว
- `elicited` — ผลิตผ่านเซสชันการรวบรวมข้อมูลแบบมีโครงสร้าง
- `corpus` — ดึงมาจาก parallel corpus

### 6. ตรวจสอบความถูกต้องของไฟล์

รัน harness กับชุดข้อมูลของคุณด้วยโมเดลใดก็ได้เพื่อตรวจสอบว่า JSON มีรูปแบบถูกต้องและฟิลด์ที่จำเป็นทั้งหมดมีอยู่ครบถ้วน:

```bash
mt-eval run --corpus path/to/your-dataset.json --dry-run
```

harness จะแสดงข้อผิดพลาดเมื่อพบฟิลด์ที่ขาดหายไป index ที่ซ้ำกัน หรือการละเมิดสคีมา

### 7. ส่งเพื่อรวมเข้าในระบบ

เปิด pull request ไปยัง [eval harness repository](https://github.com/gamedaysuits/Champollion) ที่เพิ่ม **การ์ดเมทาดาทาแบบ fetch-from-source** — รายการในรีจิสทรีที่ชี้ harness ไปยังแหล่งที่มา upstream (loader/URL, SHA pin, สัญญาอนุญาต และที่มาของข้อมูล) **ห้ามคอมมิตเนื้อหา corpus เอง** Champollion ไม่โฮสต์หรือติดตามข้อความ corpus ของบุคคลที่สาม harness จะดึงการอ้างอิงจากแหล่งที่มา upstream ในเวลารันและให้คะแนนเทียบกับข้อมูลที่ดึงมาใหม่ ตรวจสอบในเครื่องก่อน (ขั้นตอนที่ 6) จากนั้นส่งเฉพาะการ์ดเท่านั้น รวมเอกสารประกอบวิธีการตรวจสอบและแหล่งที่มาของข้อมูลด้วย

## FLORES+ Devtest

benchmark หลายภาษาที่ครอบคลุมกว้างขวาง ดูแลโดย [Open Language Data Initiative (OLDI)](https://huggingface.co/datasets/openlanguagedata/flores_plus) ใช้สำหรับการเปรียบเทียบ frontier หลายโมเดลของ Champollion

| คุณสมบัติ | ค่า |
|----------|-------|
| **ID** | การ์ดหนึ่งใบต่อคู่: `eval-flores-devtest-v1-<src>-<tgt>` (เช่น `eval-flores-devtest-v1-amh-fra`) |
| **คู่ภาษา** | 870 คู่ที่จัดทำแคตตาล็อกและสามารถรันได้ (812 คู่ระหว่างภาษาที่ไม่ใช่ภาษาอังกฤษสองภาษา) |
| **จำนวนรายการ** | 1,012 ประโยคต่อคู่ |
| **สัญญาอนุญาต** | [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/) |
| **แหล่งที่มา** | Meta FLORES-200 ปัจจุบันดูแลโดย OLDI — ดึงจากแหล่งที่มา SHA-pinned ต่อคู่ (เนื้อหา corpus ไม่ได้ถูกติดตามที่นี่) |
| **การปนเปื้อน** | **สูง** — เชิงสัมพัทธ์เท่านั้น สำหรับการทดสอบ/สาธิตเท่านั้น (ดูหมายเหตุ) |

:::warning[มีการปนเปื้อนสูง — ใช้เปรียบเทียบเชิงสัมพัทธ์เท่านั้น ไม่ใช่เกณฑ์มาตรฐานสัมบูรณ์]
FLORES+ เป็นข้อมูลสาธารณะที่รวบรวมจากเว็บ ซึ่งโมเดล frontier มีแนวโน้มสูงมากที่จะเคยเห็นข้อมูลนี้แล้ว
Champollion รันในเลน **เชิงสัมพัทธ์เท่านั้น**: สามารถใช้เปรียบเทียบวิธีการต่าง ๆ แบบตัวต่อตัวได้ แต่ **ไม่รายงานเป็นคะแนนคุณภาพสัมบูรณ์** และ **ไม่ใช้เป็น chain edge** บน[แผนที่การแปล](https://champollion.dev)
ใช้สำหรับ **การทดสอบและการสาธิตเท่านั้น**
:::

:::danger[สำหรับการประเมินเท่านั้น]
FLORES+ มีวัตถุประสงค์เพื่อการประเมินเท่านั้น ผู้ดูแลระบบขอร้องอย่างชัดเจนว่า **ห้ามนำไปใช้เป็นข้อมูลฝึกโมเดล** โปรดตรวจสอบให้แน่ใจว่าเนื้อหาของ FLORES+ ถูกยกเว้นออกจากคอร์ปัสฝึกโมเดลทั้งหมด
:::
