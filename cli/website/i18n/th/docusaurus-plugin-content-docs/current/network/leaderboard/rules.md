# การประเมิน MT

> **สรุปสำหรับผู้บริหาร** หน้านี้กำหนดเกณฑ์การส่งผลงานเข้าลีดเดอร์บอร์ด เมตริกการให้คะแนน (chrF++, FST acceptance, exact match, equivalent match, semantic score) นโยบายป้องกันการโกง ระดับการตรวจสอบ และขั้นตอนการส่งผลงาน วิธีการที่ถูกเปิดเผยต่อข้อมูลการประเมินจะถูกตัดสิทธิ์

champollion มีกรอบการประเมินการแปลด้วยเครื่อง ออกแบบมาเพื่อ **การเปรียบเทียบประสิทธิภาพที่ทำซ้ำได้** ของวิธีการแปล — โดยเฉพาะสำหรับภาษาที่มีทรัพยากรน้อยและภาษาพื้นเมือง ซึ่งไม่มีเกณฑ์มาตรฐาน MT มาตรฐาน และการอ้างสิทธิ์ด้านคุณภาพเป็นเรื่องยากที่จะตรวจสอบ

## ลีดเดอร์บอร์ด

จุดศูนย์กลางคือ **[Method Leaderboard](https://champollion.dev/leaderboard)** — กระดานคะแนนสาธารณะที่อัปเดตแบบเรียลไทม์และ **เปิดรับการส่งผลงาน** ซึ่งนักวิจัยและสมาชิกในชุมชนสามารถส่งและเปรียบเทียบวิธีการแปลภาษาด้วยการประเมินผลที่มีลายนิ้วมือดิจิทัล (fingerprinted) และสามารถทำซ้ำได้ (reproducible)

ทุกการส่งผลงานประกอบด้วย:

- **Fingerprinted pipeline** — ผูกกับ Git commit และ config hash ที่เฉพาะเจาะจง เพื่อให้สามารถตรวจสอบย้อนกลับผลลัพธ์ไปยังโค้ดที่สร้างมันขึ้นมาได้อย่างแม่นยำ
- **Versioned dataset** — มีการแฮชเนื้อหาและจัดการเวอร์ชัน คะแนนจะสามารถเปรียบเทียบกันได้เฉพาะภายในชุดข้อมูลเวอร์ชันเดียวกันเท่านั้น
- **Standardised metrics** — การให้คะแนนทั้งหมดถูกคำนวณโดย evaluation harness ที่ใช้ร่วมกัน เพื่อขจัดความแตกต่างในการนำไปใช้งาน (implementation)
- **Trust tiers** — ระดับความน่าเชื่อถือ ได้แก่ self-benchmarked, Champollion Verified หรือ Community Validated
- **Cost tracking** — ติดตามต้นทุน API ต่อการส่งผลงาน เพื่อให้เห็นความคุ้มค่าระหว่างต้นทุนและคุณภาพอย่างโปร่งใส

ลีดเดอร์บอร์ดให้คะแนนห้าเมตริก โดยสามเมตริกใช้ได้กับทุกภาษา และสองเมตริกพร้อมใช้งานสำหรับ Plains Cree และจะถูกขยายขอบเขตเมื่อเราพัฒนาต่อไป:

| เมตริก | ประเภท | สิ่งที่วัด |
|--------|------|------------------|
| **chrF++** | Character n-gram F-score | เมตริกคุณภาพหลัก — สัมพันธ์กับการตัดสินของมนุษย์ได้ดี โดยเฉพาะสำหรับภาษาที่มีความซับซ้อนทางสัณฐานวิทยา |
| **Exact Match** | สัดส่วนของการจับคู่ที่สมบูรณ์แบบ | ความแม่นยำเข้มงวด — บ่อยแค่ไหนที่การแปลตรงกับมาตรฐานทองคำพอดี |
| **FST Acceptance** | อัตราการผ่านด่านทางสัณฐานวิทยา | สำหรับวิธีการที่มีการตรวจสอบด้วย finite-state transducer — ผลลัพธ์กี่สัดส่วนที่ถูกต้องทางสัณฐานวิทยา |
| **Equivalent Match** | อัตราตัวแปรที่ยอมรับได้ | เศษส่วนที่ตรงกับข้อมูลอ้างอิงหรือตัวแปรที่ยอมรับได้ (ลำดับคำ, แบบแผนการสะกด) ปัจจุบันใช้กับ CRK กำลังขยายขอบเขต |
| **Semantic Score** | ความซื่อสัตย์ทางความหมาย | การรักษาความหมาย — การแปลถ่ายทอดความหมายที่ตั้งใจไว้โดยไม่คำนึงถึงรูปแบบพื้นผิวหรือไม่ ปัจจุบันใช้กับ CRK กำลังขยายขอบเขต |

:::info[ชุดเมตริกครบถ้วน]
[ข้อกำหนดการให้คะแนน](/docs/network/specifications/scoring) กำหนดรายการเมตริกทั้งหมด (หกหมวดหมู่: surface, structural, semantic, behavioral, compliance และ reported comparators) สูตรคะแนนรวม ตารางน้ำหนัก และเกณฑ์ระดับคุณภาพ
:::

### FLORES+ Devtest — สำหรับการพัฒนาเท่านั้น

> [!WARNING]
> **FLORES+ มีให้ใช้งานสำหรับการพัฒนาและการดีบักเท่านั้น และไม่ได้ใช้สำหรับการประเมินลีดเดอร์บอร์ดอย่างเป็นทางการ** FLORES+ (เดิมคือ Meta FLORES-200) เป็นชุดข้อมูลเกณฑ์มาตรฐานที่เปิดเผยต่อสาธารณะอย่างกว้างขวาง ซึ่ง LLM ชั้นนำเกือบแน่นอนว่าได้รับการฝึกบนชุดข้อมูลนี้ คะแนนจาก FLORES+ ไม่ได้สะท้อนคุณภาพการแปลในโลกจริงสำหรับวิธีการที่ใช้ LLM อย่างน่าเชื่อถือ วิธีการที่ไม่ใช่ LLM (FST, rule-based, fine-tuned NMT) ได้รับผลกระทบน้อยกว่า แต่คะแนน FLORES+ ก็ยังไม่ได้เผยแพร่ไปยังลีดเดอร์บอร์ด

FLORES+ fixtures ยังคงมีให้ใช้งานใน `test/benchmark/fixtures/` สำหรับการทดสอบ pipeline เบื้องต้น การตรวจสอบข้ามภาษา และการใช้งานในการพัฒนา การประเมินอย่างเป็นทางการใช้คลังข้อมูลที่กำหนดเองซึ่งสร้างจากข้อความที่มนุษย์เขียนและไม่ได้เผยแพร่ต่อสาธารณะในรูปแบบคู่ขนาน

ดู [Evaluation Datasets](/docs/network/leaderboard/datasets) สำหรับ schema ชุดข้อมูลครบถ้วน ระดับความยาก และวิธีสร้างชุดข้อมูลของคุณเอง

:::danger[ห้ามนำข้อมูลการประเมินไปใช้ฝึกโมเดล]

**ชุดข้อมูลเหล่านี้มีไว้สำหรับการประเมินเท่านั้น** วิธีการที่ถูกฝึก fine-tune few-shot-prompted หรือถูกเปิดเผยต่อข้อมูลการประเมินในรูปแบบใดก็ตาม จะให้คะแนนที่สูงเกินจริงและจะ **ถูกตัดสิทธิ์จากลีดเดอร์บอร์ด**

นี่ไม่ใช่คำแนะนำ — แต่เป็นกฎที่สำคัญที่สุดของความซื่อสัตย์ในการประเมิน ใช้คลังข้อมูลแยกต่างหากสำหรับการฝึก ชุดข้อมูลการประเมินต้องไม่ถูกมองเห็นโดยโมเดลของคุณในระหว่างการพัฒนา

หากคุณใช้ข้อมูล coaching หรือตัวอย่าง few-shot ข้อมูลเหล่านั้นต้องมาจาก **แหล่งที่แยกต่างหากโดยสิ้นเชิง** หากไม่แน่ใจ อย่านำมาใช้
:::

:::warning[ความไม่แน่นอนของ LLM]

ผลลัพธ์ของ LLM ไม่แน่นอน คะแนนแสดงถึงการวัดผล ณ จุดเวลาหนึ่งภายใต้เวอร์ชันโมเดลและการกำหนดค่า API ที่เฉพาะเจาะจง ผู้ให้บริการโมเดลอาจอัปเดต weights กลยุทธ์การ decoding หรือตัวกรองความปลอดภัยได้ตลอดเวลา ซึ่งอาจทำให้คะแนนเปลี่ยนแปลงระหว่างการรัน ลีดเดอร์บอร์ดบันทึก model slug และ timestamp ที่แน่นอนสำหรับทุกการส่งผลงาน
:::

## ลักษณะของวิธีการที่ดี

วิธีการทั้งหมดไม่ได้เท่าเทียมกัน นี่คือสิ่งที่แยกแยะงานที่เข้มงวดออกจากคะแนนที่สูงเกินจริง

### ลักษณะของวิธีการที่แข็งแกร่ง

- **การแยกข้อมูลฝึกและข้อมูลประเมินอย่างชัดเจน** — วิธีการของคุณไม่เคยเห็นชุดข้อมูลการประเมินในระหว่างการพัฒนา การปรับแต่ง การออกแบบ prompt หรือการเลือกตัวอย่าง few-shot
- **ทำซ้ำได้** — ผู้อื่นสามารถ clone repo ของคุณ รัน harness และได้คะแนนเดียวกัน (ภายในขอบเขตความไม่แน่นอนของ LLM)
- **มีเอกสาร** — [method card](/docs/network/specifications/methods) ของคุณอธิบายว่าวิธีการทำอะไร ใช้เครื่องมืออะไร และมีข้อจำกัดอะไร
- **ซื่อสัตย์เกี่ยวกับขอบเขต** — หากวิธีการของคุณใช้ได้กับคู่ภาษาเดียวเท่านั้น ให้ระบุ หากประสิทธิภาพลดลงกับรูปแบบสัณฐานวิทยาบางอย่าง ให้บันทึกไว้
- **ตระหนักถึงชุมชน** — สำหรับภาษาพื้นเมือง วิธีการของคุณเคารพอธิปไตยของข้อมูล คุณได้ปรึกษากับชุมชนภาษาหรือใช้เฉพาะข้อมูลที่มีสัญญาอนุญาตแบบเปิด

### สัญญาณเตือน (สิ่งที่ทำให้ถูกตัดสิทธิ์)

| สัญญาณเตือน | เหตุใดจึงเป็นปัญหา |
|----------|--------------------|
| การฝึกบนข้อมูลการประเมิน | ทำลายจุดประสงค์ของการประเมินโดยสิ้นเชิง คะแนนที่สูงเกินจริงทำให้ทุกคนเข้าใจผิด |
| การเลือกผลลัพธ์ที่ดีที่สุด | รัน 10 ครั้งและส่งผลการรันที่ดีที่สุดโดยไม่เปิดเผยผลการรันอื่น |
| การประมวลผลภายหลังที่ไม่เปิดเผย | การแก้ไขผลลัพธ์ด้วยตนเองก่อนการให้คะแนน |
| ข้อมูล coaching ที่ปนเปื้อน | การใช้ตัวอย่างจากชุดข้อมูลการประเมินเป็น few-shot prompts หรือรายการพจนานุกรม |
| การอ้างความพร้อมเชิงพาณิชย์โดยไม่มีแหล่งที่มา | หากวิธีการของคุณใช้ข้อมูล CC BY-NC-SA แสดงว่ายังไม่พร้อมสำหรับการใช้งานเชิงพาณิชย์ |

### ระดับการตรวจสอบ

ระดับการตรวจสอบอธิบาย **ว่าใครเป็นผู้ตรวจสอบผลลัพธ์** — แยกจากระดับคุณภาพ (Baseline → Fluent) ที่กำหนดไว้ใน [Scoring Specification, §5](/docs/network/specifications/scoring#5-quality-tiers) ซึ่งอธิบายความหมายของคะแนนรวมอัตโนมัติ

| ระดับ (Tier) | ความหมาย | วิธีการได้รับ |
|------|---------|--------------|
| **Self-benchmarked** | คุณรัน harness ด้วยตัวเองและส่งผลลัพธ์ | เผยแพร่ run card ของคุณด้วย `mt-eval publish` |
| **Champollion Verified** | เซิร์ฟเวอร์ให้คะแนนผลลัพธ์ที่คุณส่งมาใหม่อย่างอิสระ โดยเทียบกับ reference corpus ที่ปักหมุดด้วย SHA และสามารถทำซ้ำคะแนนของคุณได้ | อัตโนมัติ — ทุกการส่งผลงานจะถูกให้คะแนนใหม่ (ดูด้านล่าง) |
| **Community Validated** | ผู้พูดสองภาษาของภาษาเป้าหมาย ซึ่งมีคุณสมบัติตามโปรโตคอลของชุมชน ได้ตรวจสอบกลุ่มตัวอย่างแบบแบ่งชั้นของผลลัพธ์ (≥30 รายการ, ผู้ตรวจสอบ ≥2 คน) และ ≥70% ผ่านเกณฑ์ของชุมชน มอบให้ผ่านการทดสอบของชุมชนเองเท่านั้น; การลดระดับจากการสุ่มตรวจสอบ (spot-audit) จะเป็นไปในทิศทางเดียวกัน | ส่งโค้ดวิธีการไปยังองค์กรกำกับดูแล — พวกเขาจะรันโค้ดกับชุดข้อมูลมาตรฐานทองคำ (gold-standard set) และนำผลลัพธ์ไปให้ชุมชนตรวจสอบ |

### การขยายขนาดการตรวจสอบ: การตรวจสอบตามน้ำหนักชื่อเสียง (reputation-weighted auditing)

**เราไม่กล่าวอ้างถึงแหล่งที่มา (provenance)** แถวในกระดานผู้นำถูกสร้างขึ้นโดยผู้ร่วมสมทบ (contributor) ที่รัน *open-source* harness บนเครื่องของพวกเขา *เอง* "การรันนี้มาจาก harness จริงๆ" ไม่ใช่สิ่งที่เซิร์ฟเวอร์สามารถตรวจสอบได้สำหรับการประมวลผลแบบ self-hosted — คีย์ลายเซ็นของ harness อยู่ในมือของผู้ร่วมสมทบ ดังนั้นลายเซ็นจึงยืนยัน *เครื่องจักร ไม่ใช่ความซื่อสัตย์* แทนที่จะแสร้งทำเป็นอย่างอื่น **ความถูกต้องในที่นี้ได้มาจากการลงมือทำและแก้ไขได้ด้วยตัวเอง**: แถวข้อมูลมีความน่าเชื่อถือเพราะคะแนนนั้น **สามารถทำซ้ำได้ (reproducible)** และเพราะผู้ร่วมสมทบที่อยู่เบื้องหลังได้ **เดิมพันด้วยชื่อเสียงที่การถูกจับได้ว่าปลอมแปลงจะทำลายมันลง** การตรวจสอบจะดำเนินการในสี่ระดับ เพื่อให้มีความละเอียดถี่ถ้วนในจุดที่จำเป็นและมีต้นทุนต่ำในจุดที่ทำได้ — โปรเจกต์ไม่จำเป็นต้องรันงานของทุกคนใหม่ทั้งหมด

- **L0 — ให้คะแนนใหม่ทั้งหมด (ฟรี, 100%)** เซิร์ฟเวอร์จะคำนวณคะแนนของคุณใหม่จาก *ผลลัพธ์ที่คุณส่งมาเอง* โดยเทียบกับ **reference corpus ที่ปักหมุดด้วย SHA** (ไม่ใช่สำเนาที่คุณเก็บไว้) ด้วยเมตริกเดียวกับที่ harness ใช้ หากคะแนนไม่สามารถทำซ้ำได้จากผลลัพธ์ หรือข้อมูลอ้างอิงที่เก็บไว้ถูกแก้ไข การรันนั้นจะถูก **ตัดสิทธิ์ (disqualified)** — แค่ขั้นตอนนี้ก็สามารถกำจัดคะแนนที่ถูกพิมพ์หรือแก้ไขมาได้แล้ว การรันที่สามารถทำซ้ำได้จะได้รับการเลื่อนระดับเป็น **Champollion Verified** ซึ่งเป็นระดับเดียวที่กระดานจัดอันดับ ขั้นตอนนี้จะรันกับทุกการส่งผลงานและใช้เวลาเพียงเสี้ยววินาที
- **L1 — ระดับชื่อเสียงของผู้ร่วมสมทบ** ผู้ร่วมสมทบแต่ละคน (ระบุตัวตนจากการลงชื่อเข้าใช้) จะได้รับชื่อเสียง *ก็ต่อเมื่อ* ผ่านการตรวจสอบที่ลึกกว่าด้านล่างนี้เท่านั้น — ไม่ใช่จากปริมาณเพียงอย่างเดียว ดังนั้นการสร้างตัวตนใหม่ขึ้นมาจึงไม่มีประโยชน์ ชื่อเสียงเป็นสิ่ง **สาธารณะ** และมันจะเป็นตัวกำหนดว่าการตรวจสอบที่มีต้นทุนสูงจะเกิดขึ้นบ่อยแค่ไหน
- **L2 — รัน *กลุ่มตัวอย่าง* ใหม่ (การตรวจสอบที่มีต้นทุนสูง)** สำหรับชุดข้อมูลการพัฒนาแบบ *สาธารณะ* L0 ไม่สามารถจับผิดผู้ร่วมสมทบที่เพียงแค่คัดลอกข้อมูลอ้างอิงมาเป็น "คำแปล" ของตนเองได้ การจะจับผิดสิ่งนี้จำเป็นต้องรันโมเดลใหม่จริงๆ — ซึ่งใช้การประมวลผลจริง — ดังนั้นเราจึงทำกับ **กลุ่มตัวอย่าง** ไม่ใช่กับทุกคน การรันจะถูกสุ่มเพื่อรัน L2 ใหม่ด้วยความน่าจะเป็นที่เพิ่มขึ้นตาม **เดิมพัน (stakes)** (การรันที่เป็นสะพานเชื่อมแรกไปยังตระกูลภาษาทั้งหมดจะถูกรันใหม่ *เสมอ*), เพิ่มขึ้นตาม **ความผิดปกติ (anomaly)** (คะแนนที่ก้าวกระโดดจากสถิติเดิมจนดีเกินจริงจะถูกรันใหม่ *เสมอ*), และลดลงตาม **ชื่อเสียง (reputation)** (ผู้ร่วมสมทบที่ผ่านการตรวจสอบมาหลายครั้งจะถูกสุ่มตรวจน้อยมาก; ผู้มาใหม่หรือผู้ส่งผลงานแบบไม่ระบุตัวตนจะถูกตรวจสอบทุกการรันจนกว่าจะได้รับความไว้วางใจ) การผ่านการตรวจสอบ L2 จะช่วยเพิ่มชื่อเสียง
- **L3 — การยืนยันร่วมกัน (การตรวจสอบฟรี)** เมื่อผู้ร่วมสมทบที่ *เป็นอิสระต่อกัน* สองคนรันโมเดลเดียวกันบนคลังข้อมูลเดียวกัน และผลลัพธ์ที่ถูกให้คะแนนใหม่ของพวกเขา **ตรงกัน** ความสอดคล้องกันนั้น *คือ* การตรวจสอบ — และมันจะช่วยเพิ่มชื่อเสียงของทั้งคู่ หากเกิด **ความไม่สอดคล้องกัน** อย่างแท้จริง จะเป็นการตั้งค่าสถานะให้ทั้งสองการรันเข้าสู่การตรวจสอบ L2 การทำซ้ำ (replication) จะได้รับรางวัลแทนที่จะถูกมองว่าเป็นความซ้ำซ้อน

**การถูกจับได้ว่าปลอมแปลงเพียงครั้งเดียวถือเป็นหายนะ — เหมือนกับการถูกเพิกถอน (retraction)** การปลอมแปลงที่ได้รับการพิสูจน์แล้วจะทำให้ชื่อเสียงของผู้ร่วมสมทบกลายเป็นศูนย์, **ตรวจสอบประวัติที่ผ่านการยืนยันแล้วทั้งหมดของพวกเขาใหม่** (ทุกการรันที่ผ่านการยืนยันจะถูกส่งกลับไปตรวจสอบใหม่), และถูกบันทึกไว้ **ต่อสาธารณะ** ในบันทึกการตรวจสอบ (audit log) นี่คือสิ่งที่ทำให้การสุ่มตัวอย่างแบบเบาบางมีความปลอดภัย: การโกงชุดข้อมูลการพัฒนาสาธารณะอาจหลุดรอดไปได้ในการรันครั้งเดียว แต่ต้นทุนที่คาดหวัง — การสูญเสียความไว้วางใจที่ได้รับมาทั้งหมดและการถูกตรวจสอบประวัติทั้งหมดใหม่ — ทำให้มันเป็นการเดิมพันที่ไม่คุ้มค่า กฎเหล่านี้ผูกมัดการรันของผู้ดูแลระบบ (maintainers) อย่างเท่าเทียมกัน

**ทำไมการร่วมสมทบจึงยังคงคุ้มค่า** คุณเป็นผู้จ่ายในส่วนที่มีต้นทุนสูงเสมอ (การรันวิธีการของคุณ); โปรเจกต์จะจ่ายเฉพาะการให้คะแนน L0 ใหม่ฟรีสำหรับทุกคน บวกกับการรัน L2 ใหม่บน *กลุ่มตัวอย่างที่เล็กลง* — สูงสำหรับผู้มาใหม่และการรันที่มีเดิมพันสูง, ต่ำสำหรับผู้ร่วมสมทบที่พิสูจน์ตัวเองแล้ว ต้นทุนการตรวจสอบจะถูก *ถัวเฉลี่ยด้วยชื่อเสียงและแบ่งปันด้วยการยืนยันร่วมกัน*, ไม่ใช่การจ่ายเต็มจำนวนใหม่ทุกครั้ง

## วิธีการส่งผลงาน

1. **สร้างวิธีการของคุณ** — ดู [Building a Method](/docs/network/specifications/methods) สำหรับอินเทอร์เฟซของวิธีการ
2. **รัน harness** — ดู [Eval Harness](/docs/network/specifications/harness) สำหรับการตั้งค่าและการใช้งาน
3. **สร้าง run card** — harness จะสร้าง JSON run card ที่มีคะแนน ลายนิ้วมือดิจิทัล และข้อมูลเมตาของคุณ
4. **เผยแพร่** — `mt-eval publish eval/logs/harness/<your-run-card>.json` จะอัปโหลด run card ไปยังกระดานผู้นำ
5. **ปรากฏบนกระดานผู้นำ** — การรันของคุณจะถูกจัดเตรียมไว้ในสถานะ *self-benchmarked (unverified)* จากนั้นเซิร์ฟเวอร์จะให้คะแนนผลลัพธ์ของคุณใหม่โดยอัตโนมัติเมื่อเทียบกับคลังข้อมูลที่ปักหมุดด้วย SHA (L0); เมื่อสามารถทำซ้ำได้ การรันจะเลื่อนระดับเป็น *Champollion Verified* — ซึ่งเป็นระดับเดียวที่ [Method Leaderboard](https://champollion.dev/leaderboard) จัดอันดับ การตรวจสอบตามน้ำหนักชื่อเสียงที่ลึกขึ้นจะเป็นไปตามระดับความน่าเชื่อถือด้านบน

## นโยบายความซื่อสัตย์: การเพิกถอน, การรันใหม่, การถอดออกจากรายการ, ข้อพิพาท

เขียนไว้ล่วงหน้าเพื่อให้การบังคับใช้เป็นไปตามขั้นตอน ไม่ใช่เรื่องดราม่า กฎเหล่านี้ผูกมัดทุกคนอย่างเท่าเทียมกัน — รวมถึงการรันของผู้ดูแลระบบเองด้วย

**ไม่มีการเพิกถอน (No retractions)** การรันที่เผยแพร่แล้วถือเป็นบันทึกถาวร ไม่มีกลไกใด — สำหรับใครก็ตาม — ที่จะลบคะแนนเพียงเพราะมันน่าอาย แถวของการรันทุกแถวจะมี `submitted_at` timestamp ที่ประทับโดยเซิร์ฟเวอร์และเส้นทางการตรวจสอบ (audit trail) ที่ไม่สามารถเปลี่ยนแปลงได้; การดำเนินการกลั่นกรอง (moderation) เองก็จะถูกบันทึกไว้เช่นกัน

**การรันใหม่จะเป็นการต่อท้าย ไม่ใช่การแทนที่** หากคุณปรับปรุงวิธีการของคุณ ให้เผยแพร่การรันใหม่ การรันเก่าจะยังคงอยู่ การเปิดเผยแบบเลือกสรร (selective disclosure) — การทดสอบหลายรูปแบบเป็นการส่วนตัวและเผยแพร่เฉพาะผู้ชนะ — คือสิ่งที่ทำให้กระดานผู้นำอื่นๆ ถูกปั่นได้; บันทึกแบบต่อท้ายเท่านั้น (append-only) คือคำตอบเชิงโครงสร้าง การลบข้อมูลซ้ำซ้อนด้วยลายนิ้วมือดิจิทัล (fingerprint de-duplication) จะหยุดสแปมการส่งผลงานซ้ำที่เหมือนกันทุกไบต์; มันจะไม่เขียนประวัติศาสตร์ใหม่

**การถอดออกจากรายการ (Delisting) คือการปฏิบัติตามกฎ โดยมีการระบุกฎอย่างชัดเจน** การรันจะถูกถอดออกจากรายการ (ทำเครื่องหมาย `disqualified` ให้เห็นชัดเจน — ไม่ใช่การลบออกอย่างเงียบๆ) เฉพาะสาเหตุที่ระบุไว้เท่านั้น: ชุดข้อมูลถูกกักกันหรือเป็นเซตย่อยที่ไม่เหมาะสม (บังคับใช้โดยทริกเกอร์ฐานข้อมูลภายใต้ไคลเอนต์ทุกตัว), corpus-checksum ไม่ตรงกัน, คะแนนถูกปลอมแปลงหรืออยู่นอกช่วง, การละเมิดการป้องกันเนื้อหา, หรือการที่ผู้ดูแล (steward) ถอนการลงทะเบียนของข้อมูลพื้นฐาน การถอดออกจากรายการจะระบุชื่อกฎและหลักฐาน สาเหตุใหม่ๆ จะถูกเพิ่มที่นี่โดยการแก้ไขที่ระบุวันที่ก่อนที่จะถูกนำมาใช้เสมอ จะไม่มีการคิดค้นย้อนหลังสำหรับกรณีใดกรณีหนึ่ง

**ระดับความน่าเชื่อถือคือป้ายกำกับ ไม่ใช่การแก้ไข** แถว `self-benchmarked` คือการกล่าวอ้าง; แถว `Champollion Verified` ได้รับการให้คะแนนใหม่อย่างอิสระจากผลลัพธ์ของผู้ส่งผลงานโดยเทียบกับคลังข้อมูลที่ปักหมุดด้วย SHA; `Community Validated` มอบให้ผ่านการทดสอบของชุมชนเองเท่านั้น การตรวจสอบจะเปลี่ยนระดับของแถว — มันจะไม่เปลี่ยนคะแนนของแถว

**ชื่อเสียงเป็นสิ่งสาธารณะและแก้ไขได้ด้วยตัวเอง** ชื่อเสียงของผู้ร่วมสมทบ และบันทึกการตรวจสอบที่บันทึกทุกการให้คะแนนใหม่, การสุ่มรันใหม่, การยืนยันร่วมกัน, และการทำลายจากการปลอมแปลง ล้วนเป็นสาธารณะ ชื่อเสียงไม่ใช่ตัวคูณคะแนนและไม่เคยแตะต้องตัวเลขของการรัน — มันเพียงแค่กำหนดว่าการรันของผู้ร่วมสมทบจะถูกตรวจสอบซ้ำบ่อยแค่ไหน (ดู *การตรวจสอบตามน้ำหนักชื่อเสียง* ด้านบน) การปลอมแปลงที่ได้รับการพิสูจน์แล้วจะถูกบันทึกต่อสาธารณะเช่นเดียวกับการเพิกถอน และจะตรวจสอบประวัติที่ผ่านการยืนยันแล้วทั้งหมดของผู้ร่วมสมทบใหม่; กฎเดียวกันนี้ใช้กับการรันของผู้ดูแลระบบเองด้วย

**ข้อพิพาท (Disputes)** เปิด issue พร้อมระบุ run id และข้อเรียกร้องที่เฉพาะเจาะจง (คะแนนผิด, ชุดข้อมูลผิด, ใช้กฎผิดพลาด) ผู้ดูแลระบบจะรันการตรวจสอบแบบกำหนดได้ (deterministic checks) ใหม่ในที่สาธารณะ; ผลลัพธ์และหลักฐานจะถูกบันทึกไว้ใน issue นั้น หากข้อพิพาทเกี่ยวกับข้อมูลหรือการตรวจสอบของชุมชน อำนาจของชุมชนเองจะเป็นผู้ตัดสินและกระดานจะดำเนินการตามการตัดสินใจของพวกเขา สำหรับการแข่งขันชิงรางวัล จะใช้กฎเดียวกันบวกกับขั้นตอนการคัดเลือกและการตรวจสอบที่เผยแพร่ล่วงหน้าของการแข่งขัน — ผู้ชนะจะถูกตรวจสอบ **ก่อน** การจ่ายเงินรางวัล และการตัดสิทธิ์จะอ้างอิงกฎเหมือนกับการถอดออกจากรายการอื่นๆ ทุกประการ

## ทิศทางในอนาคต

- **การรันเปรียบเทียบโมเดลอย่างครอบคลุม** — การประเมินอย่างเป็นระบบของโมเดลชั้นนำ (GPT-4o, Claude, Gemini ฯลฯ) ในภาษาต่างๆ ของ champollion โดยใช้คลังข้อมูลการประเมินที่กำหนดเอง (ไม่ใช่เกณฑ์มาตรฐานสาธารณะ)
- **คู่ภาษาเพิ่มเติม** — Quechua, Inuktitut และภาษาที่มีทรัพยากรน้อยอื่นๆ เมื่อชุดข้อมูลที่ตรวจสอบโดยชุมชนพร้อมใช้งาน
- **การนำเข้าชุดข้อมูล** — เครื่องมือสำหรับแปลงชุดข้อมูลการประเมินภายนอก (WMT, Tatoeba ฯลฯ) เป็นรูปแบบการประเมินของ champollion
- **การรันอัตโนมัติซ้ำ** — การตรวจจับการเปลี่ยนแปลงเวอร์ชันโมเดลและการรัน benchmark ซ้ำเพื่อติดตามการเปลี่ยนแปลงของคะแนน
