# การประเมิน MT

> **บทสรุปสำหรับผู้บริหาร** หน้านี้กำหนดเกณฑ์การส่งผลงานขึ้นลีดเดอร์บอร์ด การให้คะแนน (chrF++ เป็นเมตริกหลัก พร้อมเมตริกมาตรฐานและการวินิจฉัยควบคู่กัน) นโยบายป้องกันการเล่นตุกติก ระดับการตรวจสอบยืนยัน และขั้นตอนการส่ง วิธีการที่เคยสัมผัสกับชุดข้อมูลประเมินผลจะถูกตัดสิทธิ์

champollion มีกรอบการประเมินการแปลด้วยเครื่อง ออกแบบมาเพื่อ **การเปรียบเทียบประสิทธิภาพที่ทำซ้ำได้** ของวิธีการแปล — โดยเฉพาะสำหรับภาษาที่มีทรัพยากรน้อยและภาษาพื้นเมือง ซึ่งไม่มีเกณฑ์มาตรฐาน MT มาตรฐาน และการอ้างสิทธิ์ด้านคุณภาพเป็นเรื่องยากที่จะตรวจสอบ

## ลีดเดอร์บอร์ด

หัวใจหลักคือ **[Method Leaderboard](https://champollion.dev/leaderboard)** — กระดานคะแนนสาธารณะที่ออนไลน์และ**เปิดรับการส่งผลงาน** ซึ่งนักวิจัยและสมาชิกชุมชนสามารถส่งและเปรียบเทียบวิธีการแปลด้วยการประเมินผลที่ทำซ้ำได้และมีการทำลายนิ้วมือ (fingerprinted)

ทุกการส่งผลงานประกอบด้วย:

- **ไปป์ไลน์ที่มีลายนิ้วมือ (Fingerprinted pipeline)** — ผูกโยงกับ Git commit และแฮชคอนฟิกที่เจาะจง เพื่อให้สามารถย้อนรอยผลลัพธ์ไปยังโค้ดที่สร้างขึ้นได้อย่างแม่นยำ
- **ชุดข้อมูลที่มีการกำหนดเวอร์ชัน (Versioned dataset)** — มีการทำแฮชเนื้อหาและกำหนดเวอร์ชัน คะแนนจะเปรียบเทียบกันได้เฉพาะภายในเวอร์ชันของชุดข้อมูลเดียวกันเท่านั้น
- **เมตริกมาตรฐาน (Standardised metrics)** — การคำนวณคะแนนทั้งหมดดำเนินการโดยชุดเครื่องมือประเมินผล (evaluation harness) ส่วนกลาง ซึ่งขจัดความแตกต่างในการเขียนโค้ดคำนวณ
- **ระดับความน่าเชื่อถือ (Trust tiers)** — self-benchmarked, Champollion Verified หรือ Community Validated
- **การติดตามต้นทุน (Cost tracking)** — ค่าใช้จ่าย API ต่อการส่งแต่ละครั้ง เพื่อให้เห็นความคุ้มค่าระหว่างต้นทุนกับคุณภาพอย่างโปร่งใส

ลีดเดอร์บอร์ดจัดอันดับการรันตามรูปแบบที่ WMT, FLORES-200 และภารกิจร่วม AmericasNLP รายงานผลการประเมิน MT: โดยใช้**เมตริกมาตรฐานเดียวคือ chrF++** ซึ่งแสดงผลพร้อมช่วงความเชื่อมั่น 95% และ sacreBLEU signature — เช่น `chrF++ 47.5 [45.9, 49.0]` ข้อมูลอื่น ๆ ทั้งหมดจะแสดงควบคู่กัน ไม่นำมารวมคำนวณปะปนกัน:

| เมตริก | บทบาท | สิ่งที่วัดผล |
|--------|------|------------------|
| **chrF++** | **เมตริกหลักและเมตริกจัดอันดับ** | Character n-gram F-score เทียบกับชุดอ้างอิง (sacreBLEU, `word_order=2`) รองรับภาษาที่มีการเปลี่ยนแปลงรูปคำที่ซับซ้อน (rich morphology) ได้ดีกว่าเมตริกระดับคำ |
| **BLEU, spBLEU, TER, COMET** | เมตริกมาตรฐาน แสดงควบคู่กับเมตริกหลัก | เมตริกอื่น ๆ ที่งานวิจัย MT รายงาน รวมถึง COMET เมื่อมีการคำนวณ พร้อม id ของโมเดล |
| **Exact Match** | การวินิจฉัย | ความถี่ที่ผลการแปลตรงกับชุดอ้างอิงทุกประการ |
| **FST Acceptance** | การวินิจฉัย | สำหรับภาษาที่มี finite-state transducer: สัดส่วนของคำในผลลัพธ์ที่เป็นรูปคำที่ถูกต้อง เมตริกนี้ไม่เปรียบเทียบกับต้นทางหรือชุดอ้างอิง จึงไม่นับเป็นคะแนน |
| **Equivalent Match** | การวินิจฉัย | สัดส่วนที่ตรงกับชุดอ้างอิงหรือรูปแบบอื่นที่ยอมรับได้ (ลำดับคำ รูปแบบการสะกด) ปัจจุบันรองรับ CRK และกำลังขยายผล |
| **Semantic Score** | การวินิจฉัย | การคงความหมาย โดยตัวตรวจสอบแบบดีเทอร์มินิสติก ปัจจุบันรองรับ CRK และกำลังขยายผล |
| **Score caveats** | แสดงควบคู่กับเมตริกหลัก | เมื่อผลลัพธ์คัดลอกข้อความต้นทาง สั้นหรือยาวกว่าชุดอ้างอิงมาก ผลลัพธ์ซ้ำเดิมสำหรับหลายอินพุต หรือแถวข้อมูลทดสอบมีข้อมูลฝาแฝดในชุดข้อมูลฝึกฝน |

การตัดสินว่าการรันหนึ่งดีกว่าอีกการรันหนึ่งหรือไม่นั้น พิจารณาจากการทดสอบนัยสำคัญแบบจับคู่ (paired significance test) บน chrF++ ไม่ใช่จากลำดับตัวเลขสองค่า — ช่วงที่ทับซ้อนกันเป็นสัญญาณเตือนว่าลำดับอาจเป็นเพียงสัญญาณรบกวน ([Statistical Significance Testing](/docs/network/specifications/significance)) การจัดอันดับการแข่งขันใช้การทดสอบนี้เพื่อสร้างกลุ่มอันดับ (rank clusters) chrF++ ใช้จัดอันดับระบบบนชุดข้อมูลเดียวกันเท่านั้น ไม่นำมาเปรียบเทียบข้ามภาษา ไม่มีคะแนนอัตโนมัติใดที่บ่งบอกป้ายกำกับคุณภาพได้ — มีเพียงการตรวจสอบโดยมนุษย์ซึ่งเป็นผู้พูดภาษานั้นเท่านั้นที่รับรองคุณภาพได้ คะแนนรวมแบบถ่วงน้ำหนักและระดับคุณภาพที่เคยใช้ก่อนหน้านี้ถูกยกเลิกแล้ว คะแนนรวมของการ์ดรุ่นเก่าจะแสดงเป็น "legacy composite (retired)" หากมีแสดง

## ชุดข้อมูลที่มีอยู่

เครื่องมือต่าง ๆ จะระบุไว้เองว่าการรันหนึ่ง ๆ สามารถคิดคะแนนจากอะไรได้บ้าง หน้านี้จึงไม่ได้ทำรายการแยกไว้ต่างหาก:

```bash
# the runnable corpora for a pair: size, contamination, domain, licence, provider
mt-eval corpora --source eng --target crk

# …and the catalogued ones that can never run, each with its reason
mt-eval corpora --source eng --target crk --include-quarantined
```

หน้า [Evaluation Datasets](/docs/network/leaderboard/datasets) อธิบายเกี่ยวกับแคตตาล็อก รูปแบบคอร์ปัส ระดับความยาก ขอบเขตสิทธิ์การใช้งาน (licence lanes) และวิธีสร้างคอร์ปัสของคุณเอง กฎสามข้อจากแคตตาล็อกดังกล่าวจะเป็นตัวตัดสินว่าสิ่งใดสามารถจัดอันดับได้:

- **คอร์ปัสที่ถูกกักกัน (quarantined corpus) จะไม่ได้รับการจัดอันดับโดยเด็ดขาด** คอร์ปัสเหล่านี้อยู่ในแคตตาล็อกแต่ไม่สามารถนำไปรันได้ และฐานข้อมูลจะปฏิเสธคะแนนที่ส่งเข้ามาสำหรับคอร์ปัสดังกล่าว คอร์ปัสภาษาอังกฤษ→ครีทุ่งราบ (Plains Cree) ของ EdTeKLA (`eval-eng-crk-edtekla-dev-v1` และ `eval-eng-crk-edtekla-textbook`) อยู่ในสถานะกักกัน โดยใช้สัญญาอนุญาต CC BY-NC-SA แบบดัดแปลงที่ครอบคลุมถึงอธิปไตยทางข้อมูล (`LicenseRef-EdTeKLA-Modified-CC-BY-NC-SA-4.0`) และถูกแยกออกจากการจัดอันดับบนลีดเดอร์บอร์ด การชิงรางวัล และการใช้งานเชิงพาณิชย์ทุกประเภท
- **คอร์ปัสที่มีการปนเปื้อน (contaminated corpus) จะจัดอันดับแบบสัมพัทธ์เท่านั้น** FLORES+ และคอร์ปัสใดก็ตามที่ได้รับการประเมินการปนเปื้อนในระดับ `HIGH` หรือ `MEDIUM` หรือยังไม่ได้ประเมิน จะได้รับการประทับตราว่า relative-comparison-only (เปรียบเทียบเชิงสัมพัทธ์เท่านั้น) บนการ์ดการรัน ซึ่งจะเปรียบเทียบเฉพาะวิธีการที่รันบนคอร์ปัสนั้น และไม่รายงานเป็นคุณภาพแบบสัมบูรณ์ มีเพียงคอร์ปัสที่ได้รับการประเมินในระดับ `LOW` เท่านั้นที่จะได้รับการจัดอันดับตามคุณภาพแบบสัมบูรณ์
- **ปฏิบัติตามขอบเขตสิทธิ์การใช้งานอย่างเคร่งครัด** คอร์ปัสที่ไม่ใช่เชิงพาณิชย์จะไม่มีสิทธิ์เข้าร่วมในเส้นทางเชิงพาณิชย์และชิงรางวัล ส่วนคอร์ปัสที่อยู่ภายใต้การอนุญาตแบบดัดแปลง แบบเฉพาะ หรือไม่ได้ระบุไว้ จะปฏิเสธการประเมินผลผ่าน API ของโมเดลระยะไกล จนกว่าจะมีการบันทึกการอนุญาตจากผู้ถือสิทธิ์ไว้ในรายการข้อมูล

**การแข่งขันจะรันบนชุดข้อมูลลับที่ผู้จัดเป็นผู้เก็บรักษา** การแข่งขันจะไม่คิดคะแนนจากคอร์ปัสสาธารณะเหล่านี้ ผู้จัด ซึ่งอาจเป็นชุมชนหรือองค์กร จะเก็บรักษาชุดทดสอบลับ (held-out test set) ไว้บนโครงสร้างพื้นฐานของตนเอง ผู้เข้าแข่งขันจะต้องผ่านเกณฑ์บนชุดข้อมูลสำหรับพัฒนา (dev set) สาธารณะที่ผู้จัดปล่อยออกมาก่อน จากนั้นจึงส่งโมเดลหรือวิธีการให้โหนดของผู้จัดนำไปรัน ผู้ดูแลของผู้จัดจะอนุมัติการรันแต่ละครั้ง และจะมีเพียงคะแนนเท่านั้นที่ส่งออกมา ดูเพิ่มเติมที่ [Run a Sovereign Contest](/docs/network/sovereignty/run-a-sovereign-contest)

:::danger[ห้ามนำข้อมูลการประเมินไปใช้ฝึกโมเดล]

**ชุดข้อมูลเหล่านี้มีไว้สำหรับการประเมินเท่านั้น** วิธีการที่ถูกฝึก fine-tune few-shot-prompted หรือถูกเปิดเผยต่อข้อมูลการประเมินในรูปแบบใดก็ตาม จะให้คะแนนที่สูงเกินจริงและจะ **ถูกตัดสิทธิ์จากลีดเดอร์บอร์ด**

นี่ไม่ใช่คำแนะนำ — แต่เป็นกฎที่สำคัญที่สุดของความซื่อสัตย์ในการประเมิน ใช้คลังข้อมูลแยกต่างหากสำหรับการฝึก ชุดข้อมูลการประเมินต้องไม่ถูกมองเห็นโดยโมเดลของคุณในระหว่างการพัฒนา

หากคุณใช้ข้อมูล coaching หรือตัวอย่าง few-shot ข้อมูลเหล่านั้นต้องมาจาก **แหล่งที่แยกต่างหากโดยสิ้นเชิง** หากไม่แน่ใจ อย่านำมาใช้
:::

:::warning[ความไม่แน่นอนของ LLM]

ผลลัพธ์ของ LLM ไม่แน่นอน คะแนนแสดงถึงการวัดผล ณ จุดเวลาหนึ่งภายใต้เวอร์ชันโมเดลและการกำหนดค่า API ที่เฉพาะเจาะจง ผู้ให้บริการโมเดลอาจอัปเดต weights กลยุทธ์การ decoding หรือตัวกรองความปลอดภัยได้ตลอดเวลา ซึ่งอาจทำให้คะแนนเปลี่ยนแปลงระหว่างการรัน ลีดเดอร์บอร์ดบันทึก model slug และ timestamp ที่แน่นอนสำหรับทุกการส่งผลงาน
:::

## ลักษณะของวิธีการที่ดี

วิธีการทั้งหมดไม่ได้เท่าเทียมกัน นี่คือสิ่งที่แยกแยะงานที่เข้มงวดออกจากคะแนนที่สูงเกินจริง

### ลักษณะของวิธีการที่แข็งแกร่ง

- **การแยกข้อมูลฝึกและข้อมูลประเมินอย่างชัดเจน** — วิธีการของคุณไม่เคยเห็นชุดข้อมูลการประเมินในระหว่างการพัฒนา การปรับแต่ง การออกแบบ prompt หรือการเลือกตัวอย่าง few-shot
- **ทำซ้ำได้** — ผู้อื่นสามารถ clone repo ของคุณ รัน harness และได้คะแนนเดียวกัน (ภายในขอบเขตความไม่แน่นอนของ LLM)
- **มีเอกสาร** — [method card](/docs/network/specifications/methods) ของคุณอธิบายว่าวิธีการทำอะไร ใช้เครื่องมืออะไร และมีข้อจำกัดอะไร
- **ซื่อสัตย์เกี่ยวกับขอบเขต** — หากวิธีการของคุณใช้ได้กับคู่ภาษาเดียวเท่านั้น ให้ระบุ หากประสิทธิภาพลดลงกับรูปแบบสัณฐานวิทยาบางอย่าง ให้บันทึกไว้
- **ตระหนักถึงชุมชน** — สำหรับภาษาพื้นเมือง วิธีการของคุณเคารพอธิปไตยของข้อมูล คุณได้ปรึกษากับชุมชนภาษาหรือใช้เฉพาะข้อมูลที่มีสัญญาอนุญาตแบบเปิด

### สัญญาณเตือน (สิ่งที่ทำให้ถูกตัดสิทธิ์)

| สัญญาณเตือน | เหตุใดจึงเป็นปัญหา |
|----------|--------------------|
| การฝึกบนข้อมูลการประเมิน | ทำลายจุดประสงค์ของการประเมินโดยสิ้นเชิง คะแนนที่สูงเกินจริงทำให้ทุกคนเข้าใจผิด |
| การเลือกผลลัพธ์ที่ดีที่สุด | รัน 10 ครั้งและส่งผลการรันที่ดีที่สุดโดยไม่เปิดเผยผลการรันอื่น |
| การประมวลผลภายหลังที่ไม่เปิดเผย | การแก้ไขผลลัพธ์ด้วยตนเองก่อนการให้คะแนน |
| ข้อมูล coaching ที่ปนเปื้อน | การใช้ตัวอย่างจากชุดข้อมูลการประเมินเป็น few-shot prompts หรือรายการพจนานุกรม |
| การอ้างความพร้อมเชิงพาณิชย์โดยไม่มีแหล่งที่มา | หากวิธีการของคุณใช้ข้อมูล CC BY-NC-SA แสดงว่ายังไม่พร้อมสำหรับการใช้งานเชิงพาณิชย์ |

### ระดับการตรวจสอบ

ระดับการตรวจสอบยืนยันจะอธิบายว่า**ใครเป็นผู้ตรวจสอบผลลัพธ์** ไม่ใช่ป้ายกำกับคุณภาพ (ระดับคุณภาพอัตโนมัติแบบเดิมถูก[ยกเลิกการใช้งาน](/docs/network/specifications/scoring#5-quality-tiers)แล้ว)

| ระดับ | ความหมาย | วิธีการได้รับ |
|------|---------|--------------|
| **Self-benchmarked** | คุณรันชุดเครื่องมือประเมินผลด้วยตนเองและส่งผลลัพธ์เข้ามา | เผยแพร่การ์ดการรันของคุณด้วย `mt-eval publish` |
| **Champollion Verified** | โครงการได้คำนวณคะแนนผลลัพธ์ที่คุณส่งเข้ามาใหม่อย่างเป็นอิสระเทียบกับคอร์ปัสอ้างอิงที่ระบุแฮช SHA ไว้ และได้คะแนนซ้ำเดิมตรงกัน | เครื่องมือคำนวณคะแนนซ้ำ (re-scorer) เป็นเครื่องมือสำหรับผู้ดูแลโครงการ รันด้วยตนเองเป็นชุด (batch) โดยไม่มีการกำหนดเวลาอัตโนมัติ จึงไม่มีการส่งผลงานใดที่ได้รับการคำนวณคะแนนใหม่ทันทีที่ส่งเข้ามา (ดูด้านล่าง) |
| **Community Validated** | ผู้พูดสองภาษาของภาษาเป้าหมายที่ผ่านเกณฑ์ตามระเบียบปฏิบัติของชุมชนเอง ได้ตรวจสอบกลุ่มตัวอย่างแบบแบ่งชั้นของผลลัพธ์ (≥30 รายการ, ผู้ตรวจ ≥2 คน) และมีผลงาน ≥70% ที่ผ่านเกณฑ์มาตรฐานของชุมชน ได้รับการรับรองจากการทดสอบของชุมชนเองเท่านั้น และการปรับลดระดับจากการสุ่มตรวจก็ใช้เกณฑ์สมมาตรเช่นกัน | ส่งโค้ดของวิธีการไปยังองค์กรกำกับดูแล — พวกเขาจะรันโค้ดเทียบกับชุดข้อมูลมาตรฐานทองคำ (gold-standard set) และนำผลลัพธ์ไปให้ชุมชนตรวจสอบ |

**การประเมินที่ผ่านการตรวจสอบโดยชุมชน (Community-validated) เป็นช่องทางแยกต่างหาก และยังไม่มีคะแนนการประเมินโดยมนุษย์ในขณะนี้:** ชุดเครื่องมือสามารถเลือกได้ว่าระบบใดบ้างที่จะครอบคลุมภายใต้งบประมาณการตรวจโดยมนุษย์ที่มีอยู่อย่างจำกัด จากอันดับที่หยุดนิ่งของการแข่งขันที่ปิดแล้ว (เฉพาะกลุ่มที่เสมอกันทั้งกลุ่ม — ไม่มีการแบ่งคลัสเตอร์ออกเป็นสองส่วน) แต่จะไม่มีการบันทึกเรตติง และในปัจจุบันยังไม่มีสิ่งใดบนลีดเดอร์บอร์ดที่มีการประเมินโดยมนุษย์

**อันดับจะจัดเป็นกลุ่ม (clusters) ไม่ใช่ลำดับที่เรียงเด็ดขาด** รายการข้างเคียงที่การทดสอบนัยสำคัญไม่สามารถแยกความต่างได้จะใช้อันดับร่วมกันและแสดงเป็น*ช่วงอันดับ* (rank range) ในการแข่งขันแบบปิดมิดชิด (sealed contest) ซึ่งผลลัพธ์รายส่วน (per-segment output) จะไม่ออกจากเครื่องของผู้จัด การทดสอบแบบจับคู่จะรันบนเครื่องนั้นและส่งออกมาเฉพาะคำตัดสินที่มีการลงนามกำกับเท่านั้น หากไม่มีสิ่งเหล่านี้ การเสมอกันจะพิจารณาจากหลักฐานช่วงความเชื่อมั่นหรือความเท่ากันของคะแนน วิธีการทำงานและระดับความน่าเชื่อถือของหลักฐานแต่ละขั้นได้รับการระบุไว้ใน [Statistical Significance Testing → Ranking clusters](/docs/network/specifications/significance#ranking-clusters)

### การขยายขนาดของการตรวจสอบยืนยัน: การตรวจสอบแบบถ่วงน้ำหนักตามชื่อเสียง

**เราไม่ได้อ้างว่าสามารถตรวจสอบแหล่งที่มาได้สมบูรณ์ (provenance)** แถวข้อมูลบนลีดเดอร์บอร์ดสร้างขึ้นโดยผู้ร่วมพัฒนาที่รันชุดเครื่องมือแบบ*โอเพนซอร์ส*บนเครื่องของ*ตนเอง* ข้อความที่ว่า "การรันนี้ผ่านชุดเครื่องมือมาจริง ๆ" ไม่ใช่สิ่งที่เซิร์ฟเวอร์จะตรวจสอบยืนยันได้สำหรับการประมวลผลบนเครื่องส่วนตัว — กุญแจลงนามของชุดเครื่องมืออยู่ในมือของผู้ร่วมพัฒนา ดังนั้นลายเซ็นจึงเป็นการรับรอง*เครื่อง ไม่ใช่ความซื่อสัตย์* แทนที่จะแสร้งทำเป็นอย่างอื่น **ความถูกต้องในที่นี้จึงได้มาจากการพิสูจน์ตนเองและแก้ไขข้อผิดพลาดได้ในตัว**: แถวข้อมูลมีความน่าเชื่อถือเนื่องจากคะแนนนั้น**ทำซ้ำได้ (reproducible)** และเนื่องจากผู้ร่วมพัฒนาที่อยู่เบื้องหลังได้**นำชื่อเสียงมาเป็นเดิมพัน ซึ่งหากถูกจับได้ว่าสร้างข้อมูลเท็จ ชื่อเสียงนั้นจะถูกทำลายลงทันที** การตรวจสอบยืนยันจะดำเนินการเป็นสี่ชั้น เพื่อให้มีความละเอียดถี่ถ้วนในจุดที่จำเป็น และประหยัดต้นทุนในจุดที่ทำได้ — โดยที่โครงการไม่จำเป็นต้องรันงานของทุกคนใหม่ทั้งหมด

- **L0 — คำนวณคะแนนใหม่ทั้งหมด (ฟรี, ~100%)** ตัวคำนวณคะแนนซ้ำจะคำนวณคะแนนของคุณใหม่จาก*ผลลัพธ์ที่คุณส่งเข้ามาเอง*เทียบกับ**คอร์ปัสอ้างอิงที่ระบุแฮช SHA ไว้** (ไม่ใช่สำเนาที่คุณเก็บไว้) โดยใช้เมตริกเดียวกับที่ชุดเครื่องมือประเมินผลใช้ หากคะแนนที่ได้ไม่ตรงกับผลลัพธ์ที่ส่งมา หรือคอร์ปัสอ้างอิงที่เก็บไว้มีการแก้ไข การรันนั้นจะ**ถูกตัดสิทธิ์** — แค่จุดนี้จุดเดียวก็คัดกรองคะแนนที่พิมพ์ขึ้นเองหรือแก้ไขมาได้แล้ว การรันที่ได้คะแนนตรงกันจะได้รับการเลื่อนขั้นเป็น **Champollion Verified** — ซึ่งเป็นระดับที่การจัดอันดับการแข่งขันใช้เป็นค่าเริ่มต้น และเป็นระดับเดียวที่มีสิทธิ์รับรางวัล ฟังก์ชันนี้สร้างเสร็จแล้วและประหยัดต้นทุนมาก แต่เป็น**คำสั่งสำหรับผู้ดูแลโครงการที่รันด้วยตนเอง**: ไม่มีระบบอัตโนมัติทำงานเมื่อส่งข้อมูล และไม่มีการตั้งเวลาไว้ จนกว่าจะมีการเปลี่ยนแปลง ทุกแถวข้อมูลที่ส่งเข้ามาจะอยู่ในระดับ self-benchmarked ตลอดไป
- **L1 — ลำดับขั้นชื่อเสียงของผู้ร่วมพัฒนา** ผู้ร่วมพัฒนาแต่ละราย (ระบุตัวตนด้วยการเข้าสู่ระบบ) จะได้รับชื่อเสียง*จากการผ่านการตรวจสอบในระดับที่ลึกขึ้นด้านล่างนี้เท่านั้น* — ไม่ใช่จากปริมาณการส่งผลงาน ดังนั้นการสร้างบัญชีใหม่หลาย ๆ บัญชีจึงไม่มีประโยชน์ ชื่อเสียงนี้เป็น**ข้อมูลสาธารณะ** และจะเป็นตัวกำหนดความถี่ในการเรียกใช้การตรวจสอบที่มีค่าใช้จ่ายสูง
- **L2 — รัน*กลุ่มตัวอย่าง*ใหม่ (การตรวจสอบที่มีค่าใช้จ่ายสูง ปัจจุบันมีเฉพาะนโยบาย ยังไม่มีตัวรันซ้ำ)** สำหรับชุดข้อมูลสำหรับพัฒนาที่เป็น*สาธารณะ* L0 ไม่สามารถดักจับผู้ร่วมพัฒนาที่เพียงแค่คัดลอกชุดข้อมูลอ้างอิงมาเป็น "ผลการแปล" ได้ การตรวจจับกรณีนี้จำเป็นต้องรันโมเดลจริง ๆ ขึ้นมาใหม่ — ซึ่งใช้ทรัพยากรประมวลผลจริง — ดังนั้นเราจะทำกับ**กลุ่มตัวอย่าง**เท่านั้น ไม่ได้ทำกับทุกคน **นโยบายการสุ่มตัวอย่าง**ได้รับการสร้างและทดสอบแล้ว: การรันจะถูกเลือกด้วยความน่าจะเป็นที่สูงขึ้นตาม**ความสำคัญของผลงาน (stakes)** (การรันที่เปิดสะพานเชื่อมสู่ตระกูลภาษาใหม่เป็นครั้งแรกจะถูกเลือก*เสมอ*), สูงขึ้นตาม**ความผิดปกติ (anomaly)** (คะแนนที่ก้าวกระโดดจากสถิติเดิมอย่างเหลือเชื่อจะถูกเลือก*เสมอ*), และลดลงตาม**ชื่อเสียง (reputation)** (ผู้ร่วมพัฒนาที่ผ่านการตรวจสอบมาหลายครั้งจะถูกสุ่มตรวจนาน ๆ ครั้ง ส่วนผู้มาใหม่หรือผู้ส่งแบบไม่เปิดเผยตัวตนจะถูกตรวจสอบทุกการรันจนกว่าจะสร้างความน่าเชื่อถือได้) การผ่านการตรวจสอบ L2 จะช่วยเพิ่มชื่อเสียง **อย่างไรก็ตาม ตัวรันซ้ำตามนโยบายนี้ยังไม่มีอยู่จริง** ดังนั้นจึงยังไม่เคยมีการตรวจสอบ L2 เกิดขึ้น: การรันที่ถูกเลือกจะถูกบันทึกเป็น *L2-pending*
- **L3 — การยืนยันความสอดคล้อง (การตรวจสอบยืนยันฟรี)** เมื่อผู้ร่วมพัฒนาที่เป็น*อิสระจากกัน*สองคนรันโมเดลเดียวกันบนคอร์ปัสเดียวกัน แล้วผลลัพธ์ที่คำนวณคะแนนใหม่ของทั้งคู่**ตรงกัน** ความสอดคล้องนั้นถือเป็น*การตรวจสอบยืนยัน* — และจะช่วยเพิ่มชื่อเสียงของทั้งสองคน หากมี**ความคลาดเคลื่อน**อย่างแท้จริง ทั้งสองการรันจะถูกตั้งค่าแจ้งเตือนเพื่อส่งไปตรวจสอบ L2 การทำซ้ำเพื่อยืนยันผลจะได้รับรางวัลตอบแทน แทนที่จะถูกมองว่าเป็นความซ้ำซ้อน

**การถูกจับได้ว่าสร้างข้อมูลเท็จแม้เพียงครั้งเดียวส่งผลร้ายแรงอย่างยิ่ง — เหมือนกับการเพิกถอนงานวิจัย** ข้อมูลเท็จที่พิสูจน์ได้จะทำให้ชื่อเสียงของผู้ร่วมพัฒนาลดลงเหลือศูนย์ **ประวัติที่เคยได้รับการยืนยันทั้งหมดจะถูกตรวจสอบใหม่** (ทุกการรันที่เคยผ่านการตรวจสอบจะถูกส่งกลับไปตรวจสอบอีกครั้ง) และจะมีการบันทึกไว้ในบันทึกการตรวจสอบ (audit log) อย่าง**เปิดเผยต่อสาธารณะ** นี่คือสิ่งที่ทำให้การสุ่มตรวจตัวอย่างเพียงเล็กน้อยมีความปลอดภัย: การโกงบนชุดข้อมูลพัฒนาสาธารณะอาจหลุดรอดไปได้ในการรันครั้งหนึ่ง แต่ต้นทุนที่ต้องจ่าย — การสูญเสียความไว้วางใจทั้งหมดที่สร้างมาและการที่ประวัติทั้งหมดต้องถูกรื้อมาตรวจสอบอย่างละเอียด — ทำให้การเสี่ยงนี้ไม่คุ้มค่าเลย กฎเหล่านี้มีผลผูกพันกับการรันของผู้ดูแลโครงการด้วยเช่นกัน

**ทำไมการร่วมพัฒนาจึงยังคุ้มค่า** คุณจ่ายเฉพาะส่วนที่มีค่าใช้จ่ายสูงเสมอ (การรันวิธีการของคุณ) โครงการจ่ายเฉพาะการคำนวณคะแนนใหม่ระดับ L0 ที่ไม่มีค่าใช้จ่ายสำหรับทุกคน บวกกับการรันซ้ำระดับ L2 บน*กลุ่มตัวอย่างที่ลดจำนวนลงเรื่อย ๆ* — สูงสำหรับผู้มาใหม่และการรันที่มีเดิมพันสูง และต่ำสำหรับผู้ร่วมพัฒนาที่ได้รับการพิสูจน์แล้ว ต้นทุนการตรวจสอบยืนยันจะ*ถูกเกลี่ยเฉลี่ยด้วยชื่อเสียงและแบ่งปันผ่านการยืนยันความสอดคล้อง* โดยไม่ต้องจ่ายเต็มจำนวนใหม่ทุกครั้ง

2. **รันชุดเครื่องมือประเมินผล** — ดูที่ [Eval Harness](/docs/network/specifications/harness) สำหรับการตั้งค่าและการใช้งาน
3. **สร้างการ์ดการรัน (run card)** — ชุดเครื่องมือจะสร้างการ์ดการรันแบบ JSON ที่มีคะแนน ลายนิ้วมือ และข้อมูลกำกับ (metadata) ของคุณ
4. **เผยแพร่** — `mt-eval publish eval/logs/harness/<run-id>_report.json --prod` จะอัปโหลดการ์ดการรันขึ้นสู่ลีดเดอร์บอร์ด (ดูตัวอย่างก่อนได้ด้วย `--dry-run`)
5. **แสดงผลบนลีดเดอร์บอร์ด** — การรันของคุณจะแสดงเป็น *self-benchmarked (unverified)* หน้า [Method Leaderboard](https://champollion.dev/leaderboard) จะแสดงรายการและจัดอันดับทุกแถวข้อมูลที่ไม่ใช่ `disqualified` รวมถึงแถวที่ประเมินผลด้วยตนเอง (self-benchmarked) พร้อมติดป้ายกำกับตามจริง หากต้องการดูเฉพาะผลลัพธ์ที่คำนวณคะแนนใหม่แล้ว ให้กรองดูเฉพาะ *Champollion Verified* ทั้งนี้ การคำนวณคะแนนใหม่ระดับ L0 เพื่อเลื่อนขั้นขึ้นสู่ระดับนั้นเป็นงานแบบกลุ่มของผู้ดูแลโครงการ และไม่มีการกำหนดเวลาอัตโนมัติ ดังนั้นในปัจจุบัน ทุกแถวบนกระดานจึงเป็นเพียงข้อกล่าวอ้างที่รายงานด้วยตนเอง ระดับ Verified-only จะเป็นค่าเริ่มต้นสำหรับการจัดอันดับใน**การแข่งขัน** และเป็นระดับเดียวที่มีสิทธิ์รับรางวัล

## นโยบายความโปร่งใสและถูกต้อง: การเพิกถอน การรันซ้ำ การถอดรายการ และข้อพิพาท

เขียนขึ้นล่วงหน้าเพื่อให้การบังคับใช้เป็นไปตามขั้นตอน ไม่ใช่เรื่องดราม่า กฎเหล่านี้มีผลผูกพันทุกคนอย่างเท่าเทียมกัน — รวมถึงการรันของผู้ดูแลโครงการด้วย

**ไม่มีการเพิกถอนผลงาน** การรันที่เผยแพร่แล้วถือเป็นบันทึกถาวร ไม่มีกลไกใด — สำหรับใครก็ตาม — ในการลบคะแนนเพียงเพราะผลลัพธ์น่าอับอาย ทุกแถวการรันจะมีการประทับเวลา `submitted_at` จากเซิร์ฟเวอร์ และมีบันทึกการตรวจสอบที่แก้ไขไม่ได้ (immutable audit trail) แม้แต่การดำเนินการตรวจสอบของผู้ดูแลก็ได้รับการบันทึกไว้เช่นกัน

**การรันซ้ำจะเป็นการเพิ่มต่อท้าย ไม่มีการแทนที่** หากคุณปรับปรุงวิธีการของคุณ ให้เผยแพร่การรันใหม่ การรันเดิมจะยังคงอยู่ การเลือกเปิดเผยเฉพาะผลลัพธ์ที่ดี (selective disclosure) — เช่น การทดสอบหลาย ๆ รูปแบบเป็นการส่วนตัวแล้วเผยแพร่เฉพาะผลลัพธ์ที่ชนะ — คือสิ่งที่ทำให้ลีดเดอร์บอร์ดอื่น ๆ ถูกเล่นตุกติกได้ การบันทึกแบบเพิ่มต่อท้ายเท่านั้น (append-only) จึงเป็นคำตอบเชิงโครงสร้าง การกำจัดข้อมูลซ้ำด้วยลายนิ้วมือจะหยุดยั้งสแปมการส่งซ้ำที่ไบต์เหมือนกันทุกประการ แต่จะไม่เขียนทับประวัติเดิม

**การถอดรายการเป็นการบังคับใช้ตามกฎ พร้อมระบุกฎอย่างชัดเจน** การรันจะถูกถอดรายการ (ทำเครื่องหมายว่า `disqualified` ให้เห็นชัดเจน — ไม่ได้ถูกลบออกไปเงียบ ๆ) เฉพาะกรณีที่มีสาเหตุระบุไว้เท่านั้น: การใช้ชุดข้อมูลที่ถูกกักกันหรือเป็นสับเซตที่ไม่ถูกต้อง (บังคับใช้โดยทริกเกอร์ของฐานข้อมูลที่อยู่ใต้ไคลเอนต์ทั้งหมด), ค่าเช็คซัมของคอร์ปัสไม่ตรงกัน, คะแนนถูกปลอมแปลงหรืออยู่นอกช่วงที่เป็นไปได้, การละเมิดการป้องกันเนื้อหา (content-guard) หรือผู้ดูแลข้อมูลเพิกถอนการลงทะเบียนของข้อมูลเบื้องหลัง การถอดรายการจะระบุชื่อกฎและหลักฐาน สาเหตุใหม่จะถูกเพิ่มลงในที่นี้โดยระบุวันที่แก้ไขก่อนที่จะนำไปบังคับใช้จริงเสมอ และจะไม่มีการคิดกฎย้อนหลังขึ้นมาเพื่อใช้กับกรณีใดกรณีหนึ่งโดยเฉพาะ

### การรายงานผลลัพธ์ (Flagging a result)

*เพิ่มเมื่อ 2026-09-07*

:::caution[ยังไม่เปิดรับการรายงานผลในขณะนี้]

ระบบรายงานผลสร้างเสร็จแล้ว และฐานข้อมูลก็พร้อมใช้งานตั้งแต่วันที่ 2026-09-07 — แต่แบบฟอร์มสำหรับส่งรายงานยังไม่ได้นำขึ้นระบบใหม่เชื่อมกับฐานข้อมูล ดังนั้นปุ่ม *Flag this result* จึงยังไม่สามารถส่งข้อมูลได้ ระบบจะแจ้งข้อผิดพลาดแทนที่จะยอมรับรายงานเข้ามาอย่างเงียบ ๆ ในระหว่างนี้ กรุณาส่งอีเมลไปที่ `info@champollion.dev` ประกาศนี้จะถูกนำออกในวันที่แบบฟอร์มเปิดให้ใช้งาน

:::

**ทุกคนสามารถรายงานผลลัพธ์ได้** ขยายแถวข้อมูลนั้นบนลีดเดอร์บอร์ดแล้วใช้ปุ่ม *Flag this result*: ระบบจะเปิดแบบฟอร์มข้อความที่ผูกไว้กับ id ของการรันนั้นเรียบร้อยแล้ว โดยคุณสามารถระบุสิ่งที่คุณเชื่อว่าไม่ถูกต้องและเหตุผลที่คุณทราบ — ไม่ว่าจะเป็นคอร์ปัสที่ปนเปื้อน เมตริกที่ไม่ตรงกับป้ายกำกับ วิธีการแปลที่ระบุที่มาไม่ถูกต้อง หรือสิ่งอื่นใด การรายงานผลต้องระบุเหตุผลเสมอ การรายงานผลโดยไม่มีเหตุผลถือเป็นการโหวตลบ (downvote) และกระดานนี้ไม่มีระบบโหวตลบ

**การรายงานผลเป็นข้อความส่วนตัว ไม่ใช่การลงคะแนนโหวต** ข้อความจะส่งถึงผู้ดูแลโครงการในรูปแบบทิกเก็ตและไม่เผยแพร่ไปที่อื่น จะไม่มีการแสดงจำนวนการรายงานผล — ไม่ว่าจะบนแถวข้อมูล ในการ์ดการรัน หรือที่ใดก็ตาม — เนื่องจากการแสดงตัวเลขการนับจะกลายเป็นช่องทางให้เกิดการกลั่นแกล้ง และสถานะของผลลัพธ์ต้องขึ้นอยู่กับหลักฐาน ไม่ใช่จำนวนคนที่คัดค้าน การส่งรายงานผลเพียงอย่างเดียวจะไม่เปลี่ยนสถานะใด ๆ ของแถวข้อมูลนั้น

**รายงานผลที่ได้รับการยอมรับจะแสดงผลในรูปแบบเดียวเท่านั้น:** ผลลัพธ์จะถูกทำเครื่องหมายว่า `disqualified` ด้วยสาเหตุที่มีระบุไว้ในหน้านี้แล้ว เช่นเดียวกับการถอดรายการกรณีอื่น ๆ สาเหตุใหม่จะถูกเพิ่มลงในที่นี้**โดยระบุวันที่แก้ไขก่อนที่จะนำไปบังคับใช้กับใครก็ตาม** — ดังนั้นการรายงานผลจึงไม่สามารถทำให้เกิดกฎลับหรือกฎที่มีผลย้อนหลังได้ หากรายงานผลไม่ได้รับการยอมรับ แถวข้อมูลจะยังคงเดิมไม่มีการเปลี่ยนแปลง และหากคุณทิ้งที่อยู่อีเมลไว้ คุณจะได้รับคำตอบไม่ว่าจะได้รับการยอมรับหรือไม่ก็ตาม

**ระดับความน่าเชื่อถือคือป้ายกำกับ ไม่ใช่การแก้ไขข้อมูล** แถวข้อมูลที่เป็น `self-benchmarked` คือผลการอ้างอิงของผู้ส่ง แถวข้อมูลที่เป็น `Champollion Verified` ได้รับการคำนวณคะแนนใหม่โดยอิสระจากผลลัพธ์ที่ผู้ส่งยื่นเข้ามาเทียบกับคอร์ปัสที่ระบุแฮช SHA และ `Community Validated` จะมอบให้ผ่านการทดสอบของตัวชุมชนเองเท่านั้น การตรวจสอบยืนยันจะเปลี่ยนเฉพาะระดับ (tier) ของแถวข้อมูล — จะไม่เปลี่ยนคะแนนของแถวข้อมูลโดยเด็ดขาด

**ชื่อเสียงเป็นข้อมูลสาธารณะและแก้ไขข้อผิดพลาดได้ในตัว** ชื่อเสียงของผู้ร่วมพัฒนาและบันทึกการตรวจสอบ (audit log) ที่บันทึกการคำนวณคะแนนซ้ำทุกครั้ง การสุ่มรันใหม่ การยืนยันความสอดคล้อง (corroboration) และการลงโทษเมื่อตรวจพบการปลอมแปลง ล้วนเปิดเผยต่อสาธารณะ ชื่อเสียงไม่ใช่ตัวคูณคะแนนและจะไม่แตะต้องตัวเลขคะแนนของการรัน — เพียงแต่กำหนดความถี่ในการตรวจสอบการรันของผู้ร่วมพัฒนารายนั้นซ้ำ (ดูหัวข้อ *การตรวจสอบแบบถ่วงน้ำหนักตามชื่อเสียง* ด้านบน) การปลอมแปลงที่พิสูจน์ได้จะถูกบันทึกไว้อย่างเปิดเผยต่อสาธารณะเช่นเดียวกับการเพิกถอนงานวิจัย และจะมีการตรวจสอบประวัติที่เคยได้รับการยืนยันทั้งหมดของผู้ร่วมพัฒนารายนั้นใหม่ กฎข้อนี้ใช้บังคับกับการรันของผู้ดูแลโครงการด้วยเช่นกัน

**ข้อพิพาท** เปิด issue พร้อมระบุ id ของการรันและข้อกล่าวอ้างที่เจาะจง (คะแนนไม่ถูกต้อง ชุดข้อมูลไม่ถูกต้อง นำกฎไปใช้ผิด) ผู้ดูแลจะรันการตรวจสอบแบบดีเทอร์มินิสติกใหม่ในที่สาธารณะ จากนั้นผลลัพธ์และหลักฐานจะถูกโพสต์ลงใน issue หากข้อพิพาทเกี่ยวข้องกับข้อมูลหรือการตรวจสอบความถูกต้องของชุมชน ผู้มีอำนาจของชุมชนนั้นจะเป็นผู้ตัดสิน และกระดานจะดำเนินการตามการตัดสินใจดังกล่าว สำหรับการแข่งขันชิงรางวัล จะใช้กฎเดียวกันนี้ร่วมกับเกณฑ์คุณสมบัติและขั้นตอนการตรวจสอบที่เผยแพร่ไว้ล่วงหน้าของการแข่งขัน — ผู้ชนะจะได้รับการตรวจสอบ**ก่อน**การจ่ายเงินรางวัล และการตัดสิทธิ์จะระบุกฎอย่างชัดเจนเช่นเดียวกับการถอดรายการอื่น ๆ

## ทิศทางในอนาคต

- **การรันเปรียบเทียบโมเดลอย่างครอบคลุม** — การประเมินอย่างเป็นระบบของโมเดลชั้นนำ (GPT-4o, Claude, Gemini ฯลฯ) ในภาษาต่างๆ ของ champollion โดยใช้คลังข้อมูลการประเมินที่กำหนดเอง (ไม่ใช่เกณฑ์มาตรฐานสาธารณะ)
- **คู่ภาษาเพิ่มเติม** — Quechua, Inuktitut และภาษาที่มีทรัพยากรน้อยอื่นๆ เมื่อชุดข้อมูลที่ตรวจสอบโดยชุมชนพร้อมใช้งาน
- **การนำเข้าชุดข้อมูล** — เครื่องมือสำหรับแปลงชุดข้อมูลการประเมินภายนอก (WMT, Tatoeba ฯลฯ) เป็นรูปแบบการประเมินของ champollion
- **การรันอัตโนมัติซ้ำ** — การตรวจจับการเปลี่ยนแปลงเวอร์ชันโมเดลและการรัน benchmark ซ้ำเพื่อติดตามการเปลี่ยนแปลงของคะแนน
