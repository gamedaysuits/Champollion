# กรอบการออกแบบ Corpus สำหรับการประเมินผล

เมื่อคุณประเมิน frontier model บน FLORES+ และได้คะแนน 85 chrF++ คุณจะไม่สามารถแยกแยะได้ว่า "โมเดลนี้แปลได้ดี" หรือ "โมเดลจดจำคู่ประโยคเฉพาะเหล่านี้ได้" ความคลุมเครือเพียงประการเดียวนี้คือเหตุผลที่ framework นี้ถูกสร้างขึ้น: evaluation corpus จะคุ้มค่าแก่การสร้างก็ต่อเมื่อคะแนนที่ได้มีความหมายตามที่กล่าวอ้าง และนั่นต้องอาศัยการออกแบบอย่างรอบคอบ — คู่ประโยคใหม่, การติดตามแหล่งที่มา, การแบ่งชั้นโดเมน และการแบ่งระดับความยาก หน้านี้คือแหล่งข้อมูลอ้างอิงหลักสำหรับวิธีการออกแบบ สร้าง และบำรุงรักษา evaluation datasets ของ Champollion

> **เวอร์ชัน:** 1.0 · **สถานะ:** ฉบับร่าง · เอกสารประกอบ: เวิร์กโฟลว์ [Corpus Partnership](/docs/network/specifications/corpus-partnership) นำระเบียบวิธีนี้ไปปฏิบัติจริงร่วมกับแผนกวิจัย

## 1. หลักการออกแบบ

### 1.1 — เหตุใดจึงไม่ใช้ Benchmark สาธารณะ?

Parallel corpora สาธารณะ (FLORES+, Tatoeba, WMT test sets, OPUS) สามารถใช้สำหรับการพัฒนาและดีบักได้ แต่**ถูกยกเว้นจากการประเมินผล leaderboard อย่างเป็นทางการ** เหตุผลนั้นตรงไปตรงมา:

**Contamination.** Frontier LLMs ได้รับการฝึกฝนบนข้อมูลที่ดึงมาจากเว็บจำนวนมหาศาล ข้อความคู่ขนานใดๆ ที่มีอยู่แบบสาธารณะ — โดยเฉพาะใน benchmark datasets ที่ได้รับการคัดสรรและถูกอ้างอิงอย่างกว้างขวาง — มีแนวโน้มที่จะอยู่ในข้อมูลการฝึกฝนของโมเดลเหล่านั้น นี่ไม่ใช่แค่ข้อกังวลทางทฤษฎี — [งานวิจัยได้แสดงให้เห็น](https://arxiv.org/abs/2311.04850) ถึงผลกระทบของการปนเปื้อนที่วัดได้บน MT benchmarks (Public benchmarks ยังคงทำงานอยู่ที่นี่ — แต่จะอยู่ในช่องทาง *relative-comparison* ที่สามารถจัดอันดับวิธีการต่างๆ เทียบกันได้เท่านั้น จะไม่ใช้เป็นตัวชี้วัดคุณภาพสัมบูรณ์เด็ดขาด)

สำหรับ Champollion สิ่งนี้มีความสำคัญอย่างยิ่งเนื่องจาก:
- Leaderboard จะเปรียบเทียบวิธีการของ LLM, บริการ MT แบบคลาสสิก และระบบที่สร้างขึ้นเฉพาะทางแบบเคียงข้างกัน
- คุณค่าที่เรานำเสนอคือ *การประเมินที่ซื่อสัตย์และเข้มงวด*
- ผู้ใช้เป้าหมายของเรา (ชุมชนภาษา) ตัดสินใจเรื่องการนำไปใช้งานโดยอิงจากคะแนนเหล่านี้

### 1.2 — ข้อกำหนดหลัก

corpus ประเมินผลของ Champollion ทุกชุดต้องเป็นไปตาม:

| ข้อกำหนด | เหตุผล |
|-------------|-----------|
| **เขียนโดยมนุษย์** | ไม่มีข้อมูลสังเคราะห์ ข้อความต้นฉบับและการแปลอ้างอิงทั้งหมดต้องเขียนโดยมนุษย์ LLM อาจช่วยในการจัดแนวและจัดรูปแบบ แต่ห้ามสร้างเนื้อหา |
| **ไม่เผยแพร่สาธารณะในรูปแบบคู่ขนาน** | ข้อความต้นฉบับอาจเป็นสาธารณะ การแปลอ้างอิงอาจเป็นสาธารณะ แต่ *การจับคู่* เฉพาะนั้นต้องไม่มีอยู่ในรูปแบบ parallel corpus ที่ดาวน์โหลดได้ |
| **ติดตามที่มา** | ทุกรายการต้องมีเอกสารระบุแหล่งที่มา: เอกสารต้นฉบับ ผู้แปล ใบอนุญาต วันที่ |
| **อิงข้อมูลทางภาษาศาสตร์** | การครอบคลุมต้องได้รับการชี้นำจากลักษณะทางประเภทวิทยา ไม่ใช่การสุ่มตัวอย่าง |
| **แบ่งชั้นตามโดเมน** | รายการต้องครอบคลุมโดเมนข้อความที่กำหนดด้วยการแทนค่าที่ควบคุมได้ |
| **แบ่งระดับความยาก** | รายการต้องได้รับการกำหนดระดับความยาก (1–5) ตามความซับซ้อนเชิงโครงสร้าง |
| **ควบคุมเวอร์ชัน** | เวอร์ชัน corpus ใช้ content hash คะแนนสามารถเปรียบเทียบได้เฉพาะภายในเวอร์ชันเดียวกันเท่านั้น |
| **ชุมชนตรวจสอบได้** | การแปลอ้างอิงต้องสามารถตรวจสอบได้โดยสมาชิกชุมชนภาษา |

### 1.3 — ความเป็นกลางด้านประเภท Corpus ความยาว และสไตล์

Champollion คือศูนย์กลางการประเมินการแปลแบบเปิดที่**เป็นกลางต่อนิยามของหน่วยการแปล** รายการใน corpus คือข้อความที่มีความยาวตามอำเภอใจ — ประโยคสั้นเดี่ยว ประโยคยาวหลายอนุประโยค ย่อหน้า หรือเอกสารทั้งฉบับ — และแพลตฟอร์มประเมินทั้งหมดด้วยวิธีเดียวกัน **ไม่มีข้อจำกัดเฉพาะข้อความสั้นหรือง่าย** harness ไม่กำหนดขีดจำกัดความยาว (ตั้งค่า output token headroom ไว้อย่างเผื่อเหลือเผื่อขาดโดยเจตนาเพื่อหลีกเลี่ยงการตัดการแปลที่ยาว) ระดับความยาก (§3) และโดเมน (§2.1) คือ *แกนที่กำหนดค่าได้* ไม่ใช่ประตูที่กีดกันเนื้อหาที่ยากหรือยาว

ศูนย์กลางนี้เป็นกลางและกำหนดค่าได้ในทุกแกน:

| แกน | ช่วง |
|------|-------|
| **ระดับความละเอียด** | ประโยค · ประโยคยาว · ย่อหน้า · เอกสาร (`sizeUnit: entries \| sentences \| segments \| documents`) |
| **ความยาวและความซับซ้อน** | สั้น → ยาว; ง่าย → ซับซ้อนมาก (ระดับความยาก 1–5) |
| **สไตล์และ register** | ทางการ, ไม่เป็นทางการ, เทคนิค, วรรณกรรม, สนทนา, ราชการ (taxonomy โดเมน, §2.1) |
| **วิธีการ** | `TranslationMethod` ใดก็ได้ — LLM, neural NMT, rule-based, hybrid, มนุษย์ |
| **ภาษาและคู่ภาษา** | คู่ทิศทางใดก็ได้ ไม่มีอคติต่อภาษาที่มีทรัพยากรสูงในตัวแพลตฟอร์ม |

corpus ประกาศประเภท ระดับความละเอียด register และความยาก ของตัวเองใน card และ harness จะปฏิบัติตามที่ card ประกาศ **development** corpus ที่ใช้แหล่งข้อมูลจาก Tatoeba เป็นค่าเริ่มต้นนั้นเป็นประโยคสั้นเพราะ Tatoeba เป็นเช่นนั้น — นั่นเป็นคุณสมบัติของ source corpus เหล่านั้น **ไม่ใช่ข้อจำกัดของแพลตฟอร์ม** ชุดข้อมูลประเมินระดับเอกสารและแบบยาวเป็น first-class; ลงทะเบียนด้วยวิธีเดียวกัน (และสำหรับรายการที่ยาวมาก ให้กำหนดค่า request batch ให้เล็กลง)

## 2. การเลือกข้อความต้นฉบับ

### 2.1 — Taxonomy โดเมน

Champollion ประเมินการแปลสำหรับ **บริบทการใช้งานจริง** ไม่ใช่แบบฝึกหัดทางวิชาการ ทุกรายการใน corpus ถูกติดแท็กด้วยโดเมนจาก **canonical 16-code domain taxonomy** ซึ่งได้รับการตรวจสอบในขั้นตอนการสร้าง

taxonomy ถูกกำหนดไว้ครั้งเดียว — ใน [Benchmark Specification §2.7](/docs/network/specifications/benchmark#27-domain) ซึ่งเป็นแหล่งข้อมูลหลัก — และไม่ได้ระบุซ้ำที่นี่เพื่อหลีกเลี่ยงความคลาดเคลื่อน รหัสต่างๆ ได้แก่: `conv`, `ecommerce`, `edu`, `financial`, `gov`, `legal`, `literary`, `marketing`, `medical`, `news`, `religious`, `scientific`, `subtitles`, `support`, `tech` และ `ui` ดู §2.7 สำหรับคำอธิบายและผู้ใช้ทั่วไปของแต่ละรหัส ห้ามนำรหัสโดเมนที่อยู่นอกชุดนั้นมาใช้

### 2.2 — การกระจายโดเมน

corpus ประเมินผลมาตรฐานควรมุ่งกระจายครอบคลุมโดเมนที่เกี่ยวข้องมากที่สุดสำหรับชุมชนเป้าหมาย รหัสและเปอร์เซ็นต์ที่แน่นอนจะแตกต่างกันตามคู่ภาษา ตารางด้านล่างเป็น *ตัวอย่าง* การกระจายเป้าหมาย โดยใช้รหัส canonical จาก §2.1:

| โดเมน | รหัส | เป้าหมาย % | เหตุผล |
|--------|------|----------|-----------|
| Software UI | `ui` | 25% | บริบทการใช้งานหลักสำหรับผู้ใช้ champollion CLI |
| รัฐบาล / ราชการ | `gov` | 15% | การแปลที่มีความสำคัญสูงและมีนัยทางกฎหมาย |
| การศึกษา | `edu` | 15% | กรณีการใช้งานหลักสำหรับการฟื้นฟูภาษา |
| วรรณกรรม / เรื่องเล่า | `literary` | 10% | ทดสอบความละเอียดอ่อนทางวัฒนธรรมและ register วรรณกรรม |
| สนทนา | `conv` | 10% | ทดสอบ register ไม่เป็นทางการและรูปแบบการพูดที่เป็นธรรมชาติ |
| เทคนิค | `tech` | 10% | ทดสอบความแม่นยำและความสอดคล้องของคำศัพท์ |
| การแพทย์ / สุขภาพ | `medical` | 10% | ความสำคัญสูง ทดสอบคำศัพท์เฉพาะโดเมน |
| ข่าว / สื่อสารมวลชน | `news` | 5% | ทดสอบคำศัพท์ร่วมสมัยและ register กลาง |

### 2.3 — เกณฑ์การเลือกต้นฉบับ

เมื่อเลือกข้อความต้นฉบับสำหรับ corpus ใหม่:

1. **ความเข้ากันได้ของใบอนุญาต** ข้อความต้นฉบับต้องอยู่ภายใต้ใบอนุญาตที่อนุญาตให้ใช้ใน corpus ประเมินผล ควรเลือก CC BY, CC BY-SA หรือสาธารณสมบัติ พร้อมบันทึกใบอนุญาต

2. **ความทันสมัย** ควรเลือกข้อความที่เผยแพร่ภายใน 10 ปีที่ผ่านมา ภาษามีการพัฒนา — โดยเฉพาะคำศัพท์ด้านเทคโนโลยี การปกครอง และการแพทย์

3. **ความหลากหลายของ register** ภายในแต่ละโดเมน ควรหาข้อความในระดับความเป็นทางการที่แตกต่างกัน แถลงการณ์ของรัฐบาล (ทางการ) และโพสต์โซเชียลมีเดียของรัฐบาล (ไม่เป็นทางการ) ต่างก็อยู่ในโดเมน `admin` แต่มี register ต่างกัน

4. **ความเกี่ยวข้องทางวัฒนธรรม** สำหรับภาษาพื้นเมืองและภาษาชนกลุ่มน้อย ควรให้ความสำคัญกับข้อความที่มีความหมายต่อชุมชน — เอกสารการจัดการที่ดิน สื่อการศึกษาในภาษานั้น ข้อความอนุรักษ์วัฒนธรรม — มากกว่าข้อความที่มีอยู่ในรูปแบบคู่ขนานโดยบังเอิญ

5. **ห้ามใช้ต้นฉบับที่แปลด้วยเครื่อง** หากเอกสาร "คู่ขนาน" ถูกสร้างโดยการนำต้นฉบับผ่าน Google Translate แล้วแก้ไขภายหลัง เอกสารนั้น**ไม่สามารถ**ใช้เป็นการแปลอ้างอิงได้ การแปลอ้างอิงต้องเป็นการแปลโดยมนุษย์ที่เป็นอิสระ

## 3. ระบบระดับความยาก

### 3.1 — นิยามระดับ

ทุกรายการได้รับการกำหนดระดับความยาก (1–5) ตามความซับซ้อนเชิงโครงสร้างของ *ข้อความต้นฉบับ* ไม่ใช่ความยากในการแปล (ซึ่งแตกต่างกันตามวิธีการ)

| ระดับ | ชื่อ | ลักษณะเชิงโครงสร้าง |
|------|-------|---------------------------|
| 1 | **พื้นฐาน** | ประโยคง่าย อนุประโยคเดียว กาลปัจจุบัน คำศัพท์ทั่วไป ไม่มีสำนวน ไม่มีโครงสร้างซ้อน |
| 2 | **ระดับกลาง** | ประโยคผสม สองอนุประโยคเชื่อมด้วยคำสันธาน กาลอดีต/อนาคต คำศัพท์เฉพาะโดเมนบางส่วน |
| 3 | **ขั้นสูง** | ประโยคซับซ้อน อนุประโยคขึ้นต้น อนุประโยคสัมพันธ์ กาลผสม คำศัพท์เฉพาะโดเมน กริยาวาจกถูกกระทำ |
| 4 | **ผู้เชี่ยวชาญ** | อนุประโยคซ้อนหลายชั้น register กฎหมาย/เทคนิค โครงสร้างเงื่อนไข แนวคิดนามธรรม การอ้างอิงทางวัฒนธรรม |
| 5 | **สุดขีด** | ร้อยแก้วหนาแน่นที่มีความท้าทายหลายอย่างพร้อมกัน: การซ้อนอนุประโยค การอ้างอิงสรรพนามที่กำกวม สำนวนวัฒนธรรม register ผสม คำศัพท์หายาก |

### 3.2 — ปัจจัยความยากที่อิงข้อมูลทางภาษาศาสตร์

นอกเหนือจากความซับซ้อนเชิงโครงสร้าง ความยากยังถูกปรับโดย **ระยะห่างทางประเภทวิทยา** ระหว่างภาษาต้นทางและปลายทาง ปัจจัยเหล่านี้มาจากลักษณะประเภทวิทยา WALS และข้อมูลการจำแนกใน language card:

| ปัจจัย | ความยากต่ำ | ความยากสูง |
|--------|---------------|-----------------|
| **ลำดับคำ** | ลำดับพื้นฐานเดียวกัน (เช่น SVO→SVO) | ลำดับพื้นฐานต่างกัน (เช่น SVO→SOV) |
| **ประเภทสัณฐานวิทยา** | ประเภทคล้ายกัน (เช่น analytic→analytic) | ประเภทต่างกัน (เช่น analytic→polysynthetic) |
| **เพศทางไวยากรณ์** | ระบบเดียวกันหรือไม่มีเพศ | ต้นทางไม่มีเพศ ปลายทางมีระบบเพศซับซ้อน |
| **ระดับความสุภาพ/register** | ไม่มีการทำเครื่องหมาย register | ปลายทางมีระบบ register ซับซ้อน (เช่น ญี่ปุ่น เกาหลี) |
| **อักษร** | อักษรเดียวกัน | อักษรต่างกัน (ต้องมีการถ่ายอักษร) |
| **ความมีชีวิต (Animacy)** | ไม่มีการแยกแยะ animacy | ปลายทางมีการสอดคล้องตาม animacy (เช่น Cree) |
| **หลักฐานทางภาษา (Evidentiality)** | ไม่มี evidentiality | ปลายทางทำเครื่องหมายแหล่งข้อมูลทางไวยากรณ์ |

### 3.3 — การกระจายระดับ

corpus มาตรฐานควรมีสัดส่วนโดยประมาณดังนี้:

| ระดับ | เป้าหมาย % | เหตุผล |
|------|----------|-----------|
| 1 | 15% | กำหนดเส้นฐาน — แม้แต่วิธีการที่ไม่ดีก็ควรจัดการได้ |
| 2 | 25% | การแปลเชิงปฏิบัติที่ใช้งานทั่วไป |
| 3 | 30% | จุดที่ความแตกต่างด้านคุณภาพของวิธีการเริ่มปรากฏชัด |
| 4 | 20% | แยกแยะวิธีการที่ดีออกจากวิธีการที่ยอดเยี่ยม |
| 5 | 10% | การทดสอบเพดาน — วิธีการน้อยมากที่จะจัดการได้ดี |

## 4. คุณภาพการแปลอ้างอิง

### 4.1 — ข้อกำหนดสำหรับผู้แปล

การแปลอ้างอิงต้องผลิตโดยมนุษย์ที่:

1. **พูดได้คล่อง** ในภาษาปลายทาง (เจ้าของภาษาหรือเทียบเท่า)
2. **อ่านออกเขียนได้** ทั้งในภาษาต้นทางและปลายทาง
3. **มีความรู้ด้านโดเมน** สำหรับโดเมนของข้อความ (ผู้แปลการแพทย์สำหรับข้อความสุขภาพ เป็นต้น)
4. **เป็นอิสระ** — ผู้แปลต้องไม่มีสิทธิ์เข้าถึง output ของ MT สำหรับข้อความเดียวกันระหว่างการแปล

### 4.2 — คำชี้แจงสำหรับผู้แปล

ผู้แปลทุกคนได้รับคำชี้แจงที่ประกอบด้วย:

- **register** ที่ต้องใช้ (ทางการ สนทนา ฯลฯ)
- **กลุ่มเป้าหมาย** (ประชาชนทั่วไป ผู้เชี่ยวชาญ เด็ก ฯลฯ)
- **ข้อตกลงด้านคำศัพท์** เฉพาะของชุมชนภาษา
- คำแนะนำชัดเจน: "แปลความหมาย ไม่ใช่คำต่อคำ การแปลที่ฟังดูเป็นธรรมชาติมีคุณค่ามากกว่าการแปลตรงตัว"

### 4.3 — การประกันคุณภาพ

1. **การแปลคู่** ในอุดมคติ แต่ละรายการควรมีการแปลอ้างอิงอิสระสองชุดโดยผู้แปลต่างคน ในกรณีที่ทำไม่ได้ ให้ให้ความสำคัญกับการแปลคู่สำหรับระดับ 4–5

2. **การตรวจสอบโดยชุมชน** การแปลอ้างอิงควรได้รับการตรวจสอบโดยผู้พูดอย่างน้อยหนึ่งคนที่ไม่ได้เป็นผู้แปล

3. **รูปแบบที่ยอมรับได้** สำหรับแต่ละการอ้างอิง ให้บันทึกรูปแบบที่ยอมรับได้ที่ทราบ (ลำดับคำ ข้อตกลงการสะกด รูปแบบถิ่น) สิ่งเหล่านี้จะป้อนเข้าสู่เมตริก `equivalent_match_rate`

### 4.4 — สิ่งที่ทำให้การอ้างอิงไม่ดี

| ปัญหา | เหตุใดจึงทำให้การประเมินไม่ถูกต้อง |
|---------|------------------------------|
| แปลด้วยเครื่องแล้วแก้ไขภายหลัง | การแก้ไขภายหลังยังคงโครงสร้าง MT ไว้ ทำให้วิธีการที่ให้การแปลที่เป็นธรรมชาติกว่าได้คะแนนต่ำ |
| แปลโดยผู้เรียน ไม่ใช่ผู้พูดที่คล่อง | การอ้างอิงอาจมีข้อผิดพลาดที่ทำให้ output MT ที่ถูกต้องได้คะแนนต่ำ |
| แปลตรงตัวเกินไป | การแปลที่เป็นธรรมชาติได้คะแนนต่ำเมื่อเทียบกับการอ้างอิงที่แปลตรงตัว |
| การตีความเดียวสำหรับต้นฉบับที่กำกวม | ทำให้การตีความทางเลือกที่ถูกต้องได้คะแนนต่ำ |

## 5. การป้องกันการปนเปื้อน

### 5.1 — แบบจำลองภัยคุกคามจากการปนเปื้อน

| ภัยคุกคาม | คำอธิบาย | มาตรการลดความเสี่ยง |
|--------|-------------|------------|
| **ข้อมูลฝึกซ้อนทับ** | LLM ถูกฝึกบน parallel corpus | ไม่เผยแพร่ parallel corpus สาธารณะ |
| **การรั่วไหลแบบ few-shot** | ผู้เขียนวิธีการใช้รายการประเมินเป็นตัวอย่าง few-shot | ตรวจสอบ fingerprint: รายการในคำสั่งจะถูกตรวจจับและแจ้งเตือน |
| **การปนเปื้อนทางอ้อม** | ข้อความต้นฉบับมีอยู่ในข้อมูลฝึก LLM (แบบ monolingual) | ยอมรับได้ — ข้อความต้นฉบับ monolingual เป็นสิ่งที่คาดหวัง *การจับคู่* ต้องเป็นสิ่งใหม่ |
| **การปนเปื้อนจากชุมชน** | ผู้ตรวจสอบชุมชนแชร์รายการสาธารณะ | เงื่อนไขใบอนุญาตห้ามการแจกจ่าย parallel corpus ซ้ำ |

### 5.2 — ระดับความลับของ Corpus

| ระดับ | การมองเห็น | การใช้งาน |
|------|-----------|-----|
| **ชุดพัฒนาสาธารณะ** | เปิดเผยทั้งหมด | การพัฒนาวิธีการ ดีบัก การทดสอบ regression คะแนน**ไม่**เผยแพร่ใน leaderboard |
| **ชุดประเมินที่ซ่อนไว้** | ข้อความต้นฉบับมองเห็นได้ การอ้างอิงเป็นความลับ | การประเมิน leaderboard อย่างเป็นทางการ วิธีการได้รับข้อความต้นฉบับและส่งคืนการแปล การให้คะแนนเกิดขึ้นฝั่งเซิร์ฟเวอร์ การอ้างอิงไม่เคยถูกเปิดเผยต่อวิธีการ |
| **ชุดมาตรฐานทอง** | ความลับทั้งหมด ควบคุมโดยชุมชน | การประเมินที่ชุมชนรับรอง จัดการโดยองค์กรกำกับดูแล ใช้สำหรับระดับการยืนยัน "Community Validated" |

### 5.3 — นโยบายการหมุนเวียน

corpus ประเมินผลควร**หมุนเวียน**เป็นระยะ:

1. หลังจาก corpus ถูกใช้งานมา 12 เดือน ให้เริ่มสร้างชุดทดแทน
2. เลิกใช้ corpus เก่าโดยเปลี่ยนสถานะเป็น "ชุดพัฒนา" (สาธารณะ)
3. เลื่อนระดับ corpus ใหม่เป็น "ชุดประเมินที่ซ่อนไว้"
4. วิธีนี้ป้องกันการปนเปื้อนแบบค่อยเป็นค่อยไปจากการปรับแต่งซ้ำๆ ต่อเป้าหมายที่ตายตัว

## 6. ขั้นตอนการสร้าง Corpus

### 6.1 — กระบวนการทีละขั้นตอน

```
Step 1: Language Pair Selection
    └─ Identify target language, read language card
    └─ Review typological features (WALS), contact influences, scripts
    └─ Identify which difficulty factors apply

Step 2: Source Text Curation
    └─ Identify candidate source documents per domain
    └─ Verify licenses
    └─ Extract candidate sentences/segments
    └─ Classify by domain and preliminary difficulty tier

Step 3: Segment Selection
    └─ Sample segments to match domain distribution (§2.2)
    └─ Sample segments to match difficulty distribution (§3.3)
    └─ Ensure linguistic phenomenon coverage (§6.2)
    └─ Target minimum corpus size (§6.3)

Step 4: Reference Translation
    └─ Assign segments to qualified translators
    └─ Provide translation brief
    └─ Collect translations
    └─ Dual-translate Tier 4–5 entries

Step 5: Quality Assurance
    └─ Community review of references
    └─ Document acceptable variants
    └─ Flag and resolve disagreements

Step 6: Metadata & Packaging
    └─ Assign final difficulty tiers
    └─ Add provenance metadata per entry
    └─ Content-hash the corpus for versioning
    └─ Package as corpus JSON per harness spec

Step 7: Registration
    └─ Register in Supabase datasets table
    └─ Add to ATTRIBUTION.md if new sources used
    └─ Document in arena website
```

### 6.2 — การครอบคลุมปรากฏการณ์ทางภาษาศาสตร์

ทุก corpus ควรมีรายการที่ทดสอบปรากฏการณ์ทางภาษาศาสตร์เฉพาะที่เกี่ยวข้องกับคู่ภาษา สิ่งเหล่านี้มาจากฟิลด์ `linguisticChallenges` และ `contactInfluences` ของ language card:

**ปรากฏการณ์สากล (ทุกคู่ภาษา):**
- การแก้ไขสรรพนาม (antecedent ที่กำกวม)
- การปฏิเสธ (เดี่ยว คู่ ขอบเขต)
- ตัวบ่งปริมาณ (ทั้งหมด บางส่วน ไม่มี ส่วนใหญ่)
- การแสดงเวลา (วันที่สัมพัทธ์ ระยะเวลา)
- ชื่อเฉพาะ (บุคคล สถานที่ องค์กร)
- ตัวเลขและการวัด
- รายการและการแจกแจง

**ปรากฏการณ์เฉพาะคู่ภาษา (จาก language card):**
- สำหรับภาษาปลายทางแบบ polysynthetic: สัณฐานวิทยากริยาซับซ้อน การรวมคำ
- สำหรับภาษาปลายทางที่มีเพศ: การสอดคล้องเพศ การอ้างอิงแบบกลาง/ครอบคลุม
- สำหรับภาษาปลายทาง SOV: กริยาท้ายอนุประโยค บุพบทหลัง
- สำหรับภาษาวรรณยุกต์: ความแตกต่างของความหมายตามวรรณยุกต์
- สำหรับภาษาที่มีระดับความสุภาพ: เครื่องหมาย register บริบทสังคม
- สำหรับภาษาผสม: ขอบเขตการสลับรหัส การรวมคำยืม

### 6.3 — ขนาด Corpus ขั้นต่ำ

ความน่าเชื่อถือทางสถิติต้องการจำนวนรายการขั้นต่ำ สิ่งเหล่านี้อิงจากข้อกำหนด paired bootstrap confidence interval (จาก `significance.py`):

| วัตถุประสงค์ | รายการขั้นต่ำ | แนะนำ |
|---------|-----------------|-------------|
| ชุดพัฒนา | 50 | 100–200 |
| ชุดประเมินที่ซ่อนไว้ | 100 | 200–500 |
| ชุดมาตรฐานทอง | 200 | 500+ |
| ขั้นต่ำต่อโดเมน | 10 | 25+ |
| ขั้นต่ำต่อระดับ | 10 | 20+ |

**เหตุใดจึงต้องมีขั้นต่ำ 100 รายการสำหรับการประเมิน?** เมื่อมีรายการน้อยกว่า ~100 รายการ การทดสอบนัยสำคัญแบบ paired bootstrap (1,000 resamples) ไม่สามารถตรวจจับความแตกต่างที่เล็กกว่า ~5 คะแนน chrF++ ได้อย่างน่าเชื่อถือ เมื่อมี 200+ รายการ เราสามารถตรวจจับความแตกต่าง ~2 คะแนนที่ p<0.05 ได้

## 8. มาตรการป้องกันการโกง

### 8.1 — ความสมบูรณ์ของ Corpus

| มาตรการ | การดำเนินการ |
|---------|----------------|
| **Content hashing** | เวอร์ชัน corpus = SHA-256 ของ entry ID ที่เรียงลำดับ + การอ้างอิง การแก้ไขใดๆ จะสร้างเวอร์ชันใหม่ |
| **Entry fingerprinting** | แต่ละรายการมี ID ที่มาจากเนื้อหา หากมีการส่งผลลัพธ์ต่อ corpus ที่ถูกแก้ไข fingerprint จะไม่ตรงกัน |
| **การบังคับใช้ชุดที่ซ่อนไว้** | สำหรับการประเมินอย่างเป็นทางการ วิธีการได้รับเฉพาะข้อความต้นฉบับ การอ้างอิงไม่เคยถูกเปิดเผย การให้คะแนนเกิดขึ้นฝั่งเซิร์ฟเวอร์ |
| **กำหนดการหมุนเวียน** | corpus หมุนเวียนทุกปีเพื่อป้องกันการปรับแต่งระยะยาวต่อเป้าหมายที่ตายตัว |

### 8.2 — ความสมบูรณ์ของการส่ง

| มาตรการ | การดำเนินการ |
|---------|----------------|
| **Deterministic fingerprint** | การกำหนดค่าการรัน (โมเดล อุณหภูมิ คำสั่ง เวอร์ชัน corpus) ถูก hash การกำหนดค่าเดียวกันให้ fingerprint เดียวกัน |
| **การตรวจจับการเลือกเฉพาะ** | ผู้ส่งต้องเปิดเผยการรันทั้งหมด ไม่ใช่เฉพาะที่ดีที่สุด การส่งหลายครั้งที่มี fingerprint เดียวกันจะถูกแจ้งเตือน |
| **การตรวจสอบการปนเปื้อน** | หากรายการประเมินปรากฏตรงๆ ในคำสั่งหรือข้อมูลฝึกของวิธีการ การส่งนั้นจะถูกตัดสิทธิ์ |

## 10. การบูรณาการกับ Language Card

กรอบ corpus บูรณาการกับระบบ language card:

1. **การเลือกโดเมน** ได้รับข้อมูลจากฟิลด์ `linguisticChallenges` ของ card — หากภาษามีความท้าทายเฉพาะ (polysynthesis, วรรณยุกต์, animacy) corpus ต้องมีรายการที่ทดสอบสิ่งเหล่านั้น

2. **การปรับเทียบความยาก** ใช้ฟิลด์ `classification` ของ card — ระยะห่างทางประเภทวิทยาระหว่างตระกูลภาษาต้นทางและปลายทางส่งผลต่อนิยามของ "ยาก"

3. **การครอบคลุม register** ใช้ฟิลด์ `registers` ของ card — หากภาษามี register ที่กำหนดไว้ (formal-filipino, taglish-professional, taglish-casual) corpus ควรมีรายการในแต่ละระดับ register

4. **การทดสอบอิทธิพลจากการสัมผัสภาษา** ใช้ฟิลด์ `contactInfluences` ของ card — สำหรับภาษาที่มีชั้นการยืมคำหนัก (Filipino: สเปน + อังกฤษ + อาหรับ) ให้มีรายการที่ทดสอบว่าวิธีการจัดการคำยืมได้ถูกต้องหรือแปลมากเกินไป

5. **การจัดการอักษร** ใช้ฟิลด์ `scripts[]` ของ card — สำหรับภาษาที่มีหลายอักษร (เซอร์เบีย: Cyrillic + Latin) ให้มีรายการที่ทดสอบการเลือกอักษรที่ถูกต้อง

## อ้างอิง

- **Champollion Scoring Specification** — กำหนดเมตริกทั้งหมด น้ำหนักผสม ระดับคุณภาพ
- **Champollion Benchmark Specification** — โปรโตคอลการประเมิน รูปแบบ corpus อธิปไตยข้อมูล
- **WALS** (World Atlas of Language Structures) — ฐานข้อมูลลักษณะประเภทวิทยา
- **Glottolog** — แหล่งข้อมูลหลักสำหรับการจำแนกภาษา
- **ISO 639-3** — มาตรฐานการระบุภาษา
- **EdTeKLA** — แหล่งที่มาของ corpus ประเมินผลชุดแรก
