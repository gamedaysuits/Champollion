# ข้อกำหนดความน่าเชื่อถือของเมตริก

> **สรุปสำหรับผู้บริหาร** คะแนน benchmark จะมีความหมายก็ต่อเมื่อเมตริกที่อยู่เบื้องหลังมีความน่าเชื่อถือ — และเมตริกอัตโนมัติไม่ได้สอดคล้องกับการตัดสินของมนุษย์ในระดับเดียวกันทุกภาษา เอกสารนี้ระบุวิธีที่ Champollion วัด **ความน่าเชื่อถือของเมตริก**: สำหรับแต่ละตระกูลภาษา เมตริกอัตโนมัติแต่ละตัว (BLEU, spBLEU, chrF, chrF++, COMET, MetricX) มีความสัมพันธ์กับการตัดสินคุณภาพของมนุษย์มากน้อยเพียงใด โดยคำนวณจากคลังข้อมูล WMT Metrics shared-task (2019–2025) ผลลัพธ์คือ evidence artifact ที่เผยแพร่ในรูปแบบที่เครื่องอ่านได้ ซึ่ง harness, CLI และ MCP server ใช้อ้างอิงก่อนนำเสนอคะแนนใดๆ ว่าน่าเชื่อถือ เท่าที่เราทราบ ไม่มีโครงสร้างพื้นฐานการประเมินอื่นใดที่เผยแพร่หลักฐานนี้ในระดับต่อภาษา นี่คือสิ่งที่เปลี่ยน "เราใช้เมตริกวัด" ให้กลายเป็น "นี่คือระดับที่ควรเชื่อถือผลลัพธ์"
>
> **ขอบเขต** เอกสารนี้กำหนด *ว่า evidence ความน่าเชื่อถือคืออะไร มาจากไหน คำนวณอย่างไรอย่างแม่นยำ และสิ่งที่ตั้งใจไม่รวมไว้คืออะไร* คำนิยามของเมตริกอยู่ใน [ข้อกำหนดการให้คะแนน](/docs/network/specifications/scoring); การทดสอบทางสถิติของความแตกต่างของคะแนนอยู่ใน [นัยสำคัญ](/docs/network/specifications/significance) importer ที่สร้าง artifact ใหม่คือ `arena/scripts/import_wmt_metaeval.py` ใน harness repository — โค้ดคือคำตอบสุดท้ายสำหรับรายละเอียดการนำไปใช้งาน และเปิดให้ตรวจสอบได้

## 1. ปัญหาที่เอกสารนี้แก้ไข

คุณภาพการแปลด้วยเครื่องในท้ายที่สุดแล้วคือการตัดสินของมนุษย์ เมตริกอัตโนมัติมีอยู่เพราะการประเมินโดยมนุษย์นั้นช้าและมีค่าใช้จ่ายสูง คะแนนอัตโนมัติทุกตัวคือ *ตัวแทน* ของสิ่งที่ผู้รู้สองภาษาที่มีความสามารถจะบอก สูตรย่อของทั้งสาขา — "ระบบ A ชนะระบบ B ด้วย 2 BLEU" — ตั้งสมมติฐานโดยปริยายว่าตัวแทนนั้นน่าเชื่อถือ

สมมติฐานนั้นได้รับการทดสอบมาหลายปีโดย WMT Metrics shared task แต่เกือบทั้งหมดเป็น *ในภาพรวม*: เมตริกถูกจัดอันดับตามค่าเฉลี่ยความสัมพันธ์กับการตัดสินของมนุษย์ในคู่ภาษาต่างๆ ที่แต่ละปีครอบคลุม — ส่วนใหญ่เป็นคู่ภาษายุโรปที่มีทรัพยากรสูงบวกกับภาษาจีนและญี่ปุ่น รายละเอียดระดับต่อภาษามีอยู่ในข้อมูลดิบและในเอกสารผลการวิจัยรายปี แต่ไม่ได้เผยแพร่ที่ใดในรูปแบบ evidence layer ที่ query ได้ต่อตระกูลภาษา ซึ่ง evaluation pipeline สามารถอ้างอิงได้

รายละเอียดนี้มีความสำคัญอย่างมากสำหรับภาษาที่มีทรัพยากรน้อยและภาษาที่มีสัณฐานวิทยาซับซ้อน ผลการนำเข้าของเราเองสองรายการแสดงให้เห็นถึงความสำคัญนี้ (§7 มีตารางฉบับสมบูรณ์):

- **English→Inuktitut (wmt20)** ความสัมพันธ์ระดับระบบของ BLEU กับการตัดสินของมนุษย์คือ **+0.16** — แทบไม่มีข้อมูลเลย chrF ทำได้ +0.35 COMET ทำได้ +0.86 leaderboard ที่จัดอันดับด้วย BLEU สำหรับคู่ภาษานี้จะเป็นการจัดอันดับสัญญาณรบกวน ในขณะที่ leaderboard เดียวกันที่จัดอันดับด้วย COMET มีความหมาย
- **English→Maasai (wmt25)** ความล้มเหลวในทิศทางตรงข้าม: ความสัมพันธ์ของ MetricX-25 คือ **−0.09** — เมตริกที่ *เรียนรู้* ระดับ state-of-the-art ที่ให้คะแนนภาษาที่ไม่มีในข้อมูลฝึกสอนให้ตัวเลขที่ไม่สัมพันธ์กับการตัดสินของมนุษย์ ในขณะที่ chrF++ ที่คำนวณได้ (เมตริก string "ธรรมดา" ที่ไม่มีข้อมูลฝึกสอน) ทำได้ +0.50

ทั้งสองรูปแบบความล้มเหลวไม่ปรากฏในค่าเฉลี่ยรวม และชี้ไปในทิศทางตรงข้าม: สำหรับภาษาหนึ่ง เมตริกที่เรียนรู้คือตัวเดียวที่ใช้ได้ สำหรับอีกภาษาหนึ่ง มันคือตัวเดียวที่ *ใช้ไม่ได้* โครงสร้างพื้นฐานใดๆ ที่ให้คะแนนคู่ภาษาหลายร้อยคู่ด้วยชุดเมตริกคงที่ — อย่างที่ Champollion ทำ — มีหน้าที่ต้องให้หลักฐานนี้แก่ผู้ใช้

## 2. คำนิยาม

คำนิยามด้านล่างเป็นขั้นต่ำที่จำเป็นสำหรับการอ่านเอกสารที่เหลืออย่างแม่นยำ ผู้อ่านที่คุ้นเคยกับการประเมิน MT สามารถข้ามไปที่ §3 ได้

**เมตริกอัตโนมัติ** ฟังก์ชันจาก (ผลลัพธ์ของระบบ, การแปลอ้างอิง, และบางครั้งต้นฉบับ) ไปยังตัวเลข *เมตริก string* — BLEU, spBLEU, chrF, chrF++ — เปรียบเทียบความทับซ้อนของพื้นผิวระหว่างผลลัพธ์และอ้างอิง *เมตริกที่เรียนรู้* — COMET, MetricX, BLEURT — เป็นโมเดล neural ที่ฝึกบนการตัดสินของมนุษย์ในอดีตเพื่อทำนายคุณภาพ ตัวระบุมาตรฐานสำหรับเมตริกทั้งหมดในเอกสารนี้มาจาก metric registry ของ Champollion (`shared/metric-registry.json`): `bleu`, `spbleu`, `chrf_plain`, `chrf_plus_plus`, `comet_score`, `metricx_score`

**โปรโตคอลการตัดสินของมนุษย์** แคมเปญ WMT รวบรวมคะแนนคุณภาพของมนุษย์ภายใต้โปรโตคอลหลายแบบ ซึ่ง artifact นี้แยกไว้อย่างชัดเจน:

- **DA (Direct Assessment)** — ผู้ทำงาน crowdsource หรือนักวิจัยให้คะแนนการแปล 0–100 DA แบบ *z-normalized* (เขียนว่า `wmt-z`) ทำให้คะแนนของผู้ให้คะแนนแต่ละคนมีค่าเฉลี่ย 0 ความแปรปรวน 1 เพื่อขจัดผลของความใจกว้างของผู้ให้คะแนน
- **DA+SQM** (`da-sqm`, `wmt`) — DA ที่รวบรวมในระดับ 0–100 พร้อมคำอธิบายจุดยึดของ scalar quality metric; ใช้ตั้งแต่ WMT22
- **MQM (Multidimensional Quality Metrics)** (`mqm`) — ผู้ทำคำอธิบายมืออาชีพทำเครื่องหมายและจำแนกช่วงข้อผิดพลาดแต่ละรายการพร้อมระดับความรุนแรง จำนวนข้อผิดพลาดที่ถ่วงน้ำหนักกลายเป็นคะแนนระดับ segment ช้า แพง และเป็นสัญญาณที่น่าเชื่อถือที่สุดที่มีอยู่ รวบรวมเฉพาะสำหรับคู่ภาษาที่มีทรัพยากรสูงไม่กี่คู่ต่อปี (คำอธิบายมาจากการเผยแพร่ `wmt-mqm-human-evaluation` ของ Google)
- **ESA (Error Span Annotation)** (`esa`, `esa-merged`) — โปรโตคอลของ WMT24 และ WMT25 ที่รวมการทำเครื่องหมายช่วงข้อผิดพลาดกับการให้คะแนนแบบ scalar ถูกกว่า MQM และให้ข้อมูลมากกว่า DA

**Meta-evaluation** การประเมินผู้ประเมิน: วัดว่าคะแนนของเมตริกอัตโนมัติแต่ละตัวสอดคล้องกับคะแนนของมนุษย์สำหรับการแปลชุดเดียวกันได้ดีเพียงใด ความสอดคล้องวัดที่สองระดับ:

- **ระดับระบบ** (`sys`): ระบบ MT แต่ละระบบได้รับคะแนนมนุษย์รวมหนึ่งคะแนนและคะแนนเมตริกรวมหนึ่งคะแนนสำหรับชุดทดสอบ ความสอดคล้องคำนวณข้ามระบบ คำถามคือ: *เมตริกจัดอันดับระบบทั้งหมดในแบบเดียวกับมนุษย์หรือไม่?* — คำถามที่ leaderboard ใส่ใจ
- **ระดับ segment** (`seg`): ความสอดคล้องข้ามคู่ (ระบบ, ประโยค) แต่ละคู่ คำถามคือ: *เมตริกสามารถแยกแยะประโยคที่ดีจากประโยคที่แย่ได้หรือไม่?* — คำถามที่ quality estimation และการกรองข้อมูลใส่ใจ ยากกว่ามาก และความสัมพันธ์ต่ำกว่าอย่างเป็นระบบ

**สถิติความสัมพันธ์** สถิติมาตรฐานสี่ตัว กำหนดที่นี่ตามที่คำนวณจริง:

- **Pearson's r** — ความสัมพันธ์เชิงเส้นระหว่างเวกเตอร์คะแนนสองตัว
- **Spearman's ρ** — Pearson's r คำนวณบนอันดับเฉลี่ย วัดความสอดคล้องแบบ monotonic ไม่ไวต่อสเกล
- **Kendall's τ-b** — ในบรรดาคู่รายการทั้งหมด ส่วนเกิน (ปรับ tie) ของคู่ที่เรียงลำดับสอดคล้องกันเหนือคู่ที่เรียงลำดับขัดแย้งกัน เราใช้สูตร τ-b ที่ปรับ tie มาตรฐาน (เทียบเท่ากับ `scipy.stats.kendalltau`; การนำไปใช้งานของเราไม่มี dependency และตรวจสอบข้ามกับ reference แบบ brute-force ใน test suite)
- **ความแม่นยำการจัดอันดับแบบคู่** (ระดับระบบเท่านั้น) — ในบรรดาคู่ระบบทั้งหมดที่มนุษย์เรียงลำดับ *อย่างเคร่งครัด* สัดส่วนที่เมตริกเรียงลำดับในแบบเดียวกัน โดยนับ tie ของเมตริกเป็นความล้มเหลวในการทำซ้ำลำดับ นี่คือสถิติความแม่นยำของ Kocmi et al. (2021) ซึ่งแคมเปญ WMT ล่าสุดใช้เป็นตัวเลขหลักระดับระบบ

**ตระกูลภาษา** การจัดกลุ่มทางลำดับวงศ์ตระกูลของภาษา *เป้าหมาย* (ภาษาที่แปลไปสู่) ตามที่บันทึกไว้ในฐานข้อมูลภาษาของ Champollion (`languages.family`, ดึงมาจาก Glottolog) §5 อธิบายว่าทำไมจึงใช้ฝั่งเป้าหมาย และสิ่งที่ตระกูลสามารถและไม่สามารถเป็นตัวแทนได้

**ไม่รวม: wmt24pp** การเผยแพร่ WMT24++ ขยายความครอบคลุมไปยัง 55 คู่ภาษา แต่มาพร้อม *อ้างอิงและผลลัพธ์ระบบเท่านั้น* — ไม่มีการตัดสินของมนุษย์ — ดังนั้นจึงไม่สามารถคำนวณความสัมพันธ์ได้ มันถูกระบุไว้ใน exclusion ledger ของ artifact แทนที่จะถูกละทิ้งโดยไม่มีการบันทึก

## 4. วิธีการ

importer ดำเนินการผ่านแต่ละ (test set, คู่ภาษา) และคำนวณหนึ่ง **cell** ต่อ (human-judgment lane, ระดับ, เมตริก):

1. **ค้นหา human lane** ไฟล์คะแนนมนุษย์ที่มีอยู่ทั้งหมดสำหรับคู่นั้นถูกจับคู่กับ allowlist ที่ชัดเจน (§4.1) ไฟล์ระดับผู้ให้คะแนน, ไฟล์ช่วงข้อผิดพลาดดิบ และคะแนนระดับเอกสาร/โดเมนอยู่นอกขอบเขต
2. **ยกเว้น "ระบบ" มนุษย์** ไฟล์คะแนน WMT รวมการแปลอ้างอิงเองเป็นระบบที่ให้คะแนน (`refA`, `refb`, `HUMAN.0`…) การหาความสัมพันธ์ของเมตริกกับอ้างอิงของตัวเองไม่มีความหมาย ดังนั้นระบบใดๆ ที่ตรงกับชุดอ้างอิงของคู่หรือ prefix `ref`/`human`/`synthetic` จะถูกยกเว้นตลอด
3. **จัดแนว** ระดับระบบ: จุดตัดของระบบที่มีทั้งคะแนนมนุษย์และคะแนนเมตริก (ค่าที่หายไปถูกละทิ้ง ไม่ถูกบังคับให้เป็นศูนย์) ระดับ segment: ทุก (ระบบ, segment) ที่มีคะแนนทั้งสอง รวมกันข้ามระบบโดยไม่จัดกลุ่ม — นี่คือการ flatten แบบ "no averaging" ของ mt-metrics-eval ไฟล์ที่ไม่สม่ำเสมอ (จำนวน segment ไม่ตรงกัน) ทำให้ cell ล้มเหลวแทนที่จะจัดแนวโดยประมาณ
4. **คำนวณ** Pearson, Spearman และ Kendall τ-b ที่ทั้งสองระดับ ความแม่นยำการจัดอันดับแบบคู่ที่ระดับระบบ Cell ที่มีระบบที่จัดแนวน้อยกว่า 3 ระบบ (sys) หรือน้อยกว่า 10 จุดที่จัดแนวข้ามอย่างน้อย 2 ระบบ (seg) หรือมีความแปรปรวนเป็นศูนย์ในฝั่งใดฝั่งหนึ่ง จะถูกบันทึกใน exclusion ledger ว่าเป็น degenerate (20 cell ใน build ปัจจุบัน)
5. **รวมขึ้น** ต่อตระกูลภาษาเป้าหมาย ต่อเมตริก ต่อระดับ: ค่าเฉลี่ยถ่วงน้ำหนัก n ของแต่ละสถิติข้ามเซลล์ *preferred* (§4.1) โดยเก็บรายการ (test set, คู่) ที่มีส่วนร่วมไว้เพื่อให้สามารถแยกย่อย aggregate ใดๆ กลับไปยัง input ได้

### 4.1 การกำหนดความต้องการ human lane

เมื่อคู่หนึ่งมี human-judgment lane หลายตัว ทั้งหมดจะถูกคำนวณ แต่มีเพียงตัวเดียวที่ถูกทำเครื่องหมายว่า **preferred** และเฉพาะ cell preferred เท่านั้นที่เข้าสู่การรวมตระกูล — มิฉะนั้นคู่ที่ตัดสินภายใต้ทั้ง MQM และ DA จะถูกนับสองครั้ง ลำดับความต้องการเรียงตามคุณภาพสัญญาณ:

```
mqm > esa-merged > esa > da-sqm > wmt-z > wmt-appraise-z > wmt-appraise > wmt > wmt-raw
```

การทำคำอธิบายข้อผิดพลาดโดยผู้เชี่ยวชาญ (MQM) มีอันดับสูงกว่าโปรโตคอล error-span (ESA) ซึ่งมีอันดับสูงกว่า scalar direct assessment ภายใน DA, lane ที่ z-normalized มีอันดับสูงกว่า lane ดิบ cell ที่ไม่ preferred ยังคงอยู่ใน artifact สำหรับผู้ที่ต้องการศึกษาผลของโปรโตคอล

### 4.2 ตัวตนและเวอร์ชันของเมตริก

เมตริกที่เรียนรู้เปลี่ยนแปลงทุกปี (COMET-20, COMET-22, MetricX-23/24/25 เป็นโมเดลที่แตกต่างกัน) และการปฏิบัติต่อพวกมันเป็นเมตริกเดียวจะทำให้ความแตกต่างที่ meta-evaluation มีอยู่เพื่อดึงออกมาเลือนหาย ดังนั้นทุก cell จึงบันทึก **ชื่อคะแนน upstream ตามตัวอักษร** (`COMET-22`, `MetricX-25-Ref`, `metricx_xxl_MQM_2020`…) ควบคู่กับ canonical registry id และ artifact แสดงรายการชื่อ upstream ที่ป้อนแต่ละ id ในกรณีที่แคมเปญให้คะแนนเมตริกกับอ้างอิงหลายตัว reference stream ที่ใช้จะถูกบันทึกต่อ cell ด้วย

คะแนนถูกใช้ตามที่ archive แจกจ่ายมาอย่างแม่นยำ (ทุก lane สูงกว่าดีกว่า คะแนนข้อผิดพลาด MQM และ MetricX ถูกเก็บแบบ negated upstream) ไม่มีการพลิกเครื่องหมายหรือปรับสเกล ความสัมพันธ์ไม่แปรเปลี่ยนตามสเกล และแบบแผนการวางแนวได้รับการตรวจสอบเชิงประจักษ์ก่อนการนำเข้า

### 4.3 lane chrF++ ที่คำนวณได้

chrF++ — เมตริก string หลักของ harness — ถูกส่งเข้าแคมเปญ wmt20 เท่านั้น ดังนั้นคะแนน upstream จึงมีอยู่สำหรับหนึ่งปี สำหรับ test set อื่นๆ ทุกชุด importer คำนวณ chrF++ เอง (sacreBLEU, `word_order=2`) จากผลลัพธ์ระบบที่ cache ไว้กับอ้างอิงที่บันทึกไว้ cell เหล่านี้ถูกทำเครื่องหมายว่า `computed: true` และชื่อ upstream ของพวกมันบอกไว้ชัดเจน: คะแนนที่ Champollion คำนวณจะไม่ถูกนำเสนอเป็นการส่งเข้า WMT cell เมตริกอื่นๆ ทั้งหมดเป็นค่า upstream ตามตัวอักษร สิ่งเดียวที่ Champollion เพิ่มให้คือการคำนวณความสัมพันธ์

## 5. การตัดสินใจออกแบบ ทางเลือก และเหตุผล

นี่คือการตัดสินใจที่ผู้ตรวจสอบควรตั้งคำถาม แต่ละข้อแสดงสิ่งที่เลือก สิ่งที่ไม่ได้เลือก และเหตุผล

**จัดกลุ่มตามตระกูลภาษาเป้าหมาย** *เลือก:* รวมตามตระกูลของภาษาที่แปล *ไปสู่* *ทางเลือก:* ต่อคู่เท่านั้น (ไม่มีการรวม); typology ฝั่งต้นทางหรือระดับคู่; เวกเตอร์คุณลักษณะ typological แทนลำดับวงศ์ตระกูล *เหตุผล:* ความน่าเชื่อถือของเมตริกถูกกำหนดโดยความยากของภาษา *ผลลัพธ์* ที่จะให้คะแนน — ความซับซ้อนทางสัณฐานวิทยาทำให้ความไม่ตรงกันของพื้นผิวสูงขึ้นสำหรับเมตริก string และความขาดแคลนข้อมูลฝึกสอนทำให้เมตริกที่เรียนรู้เสื่อมลง — ทั้งสองเป็นคุณสมบัติของเป้าหมาย ตระกูลเป็น key ที่หยาบแต่มีอยู่ทั่วไป (ทุกภาษาในฐานข้อมูลของ Champollion มีหนึ่งตระกูล) คุณลักษณะ typological จะละเอียดกว่า แต่หายไปหรือเป็นที่ถกเถียงสำหรับภาษาที่มีทรัพยากรน้อยที่นี่มีอยู่เพื่อ cell ต่อคู่ถูกเก็บไว้ครบถ้วน ดังนั้นการรวมที่ละเอียดกว่า (ตาม genus, ตามประเภทสัณฐานวิทยา) สามารถสร้างจาก artifact ได้โดยไม่ต้องนำเข้าใหม่

**ความสัมพันธ์ระดับ segment แบบ flatten** *เลือก:* Kendall τ-b บนเวกเตอร์ (ระบบ, segment) ที่รวมกัน *ทางเลือก:* ความแม่นยำแบบคู่ที่จัดกลุ่มตาม item พร้อมการปรับ tie (acc*-eq ของผลการวิจัย WMT ล่าสุด); τ เฉลี่ยต่อ segment ข้าม segment *เหตุผล:* สถิติแบบ flatten เป็นตัวเลือกที่ง่ายที่สุดที่ป้องกันได้ ทำซ้ำได้อย่างแม่นยำจากคำนิยามโดยไม่ต้องมีขั้นตอนการปรับ tie และรักษาความสามารถในการเปรียบเทียบข้ามภาษาที่ artifact นี้ต้องการ มัน *ไม่ใช่* สถิติหัวข้อ WMT ล่าสุด และ §8 ระบุว่านั่นเป็นข้อจำกัดแทนที่จะแกล้งทำเป็นว่าเทียบเท่า

**Metric tie นับเป็นข้อเสียของเมตริก** ในความแม่นยำแบบคู่ เมตริกที่ไม่สามารถแยกแยะสองระบบที่มนุษย์แยกได้ล้มเหลวในการทำซ้ำลำดับมนุษย์ การให้เครดิตครึ่งหนึ่งจะให้รางวัลกับการ quantize คะแนน

**ค่าเฉลี่ยถ่วงน้ำหนักในการรวม** การรวมตระกูลถ่วงน้ำหนักแต่ละ cell ตามขนาดตัวอย่าง (ระบบที่ระดับ sys, จุดที่ระดับ seg) ดังนั้นคู่ MQM 17 ระบบนับมากกว่าคู่ DA 6 ระบบ ค่าต่อ cell ที่ไม่ถ่วงน้ำหนักยังคงมีอยู่

**เกณฑ์** Cell ต้องการระบบที่จัดแนวอย่างน้อย 3 ระบบ (ความสัมพันธ์บน 2 จุดไม่มีความหมาย) หรือจุด segment ที่จัดแนวอย่างน้อย 10 จุดข้ามอย่างน้อย 2 ระบบ นี่คือเกณฑ์ขั้นต่ำสำหรับการคำนวณที่ degenerate ไม่ใช่การอ้างนัยสำคัญ — §8

**วินัย verbatim-upstream** Champollion ไม่คำนวณซ้ำสิ่งที่อ้างอิงได้ (ยกเว้น lane chrF++ ที่ทำเครื่องหมายไว้) เพราะเมตริกที่เรียนรู้ที่ให้คะแนนใหม่จะนำ version และ environment drift ที่ชื่อ upstream ต่อ cell มีอยู่เพื่อป้องกัน การแลกเปลี่ยน — ช่องว่างความครอบคลุมที่แคมเปญไม่ได้รันเมตริก — มองเห็นได้เป็น cell ที่หายไปแทนที่จะถูกปิดบัง

**การยกเว้นแบบ fail-honest** ทุกสิ่งที่ข้ามไป (test set ที่ไม่มีการตัดสินของมนุษย์, รหัสภาษาที่แก้ไขไม่ได้, cell ที่ degenerate) ถูกเขียนลงใน exclusion ledger พร้อมเหตุผล ผู้อ่าน artifact สามารถระบุสิ่งที่ *ไม่* อยู่ในนั้น — คุณสมบัติที่รายงานรวมส่วนใหญ่ขาด

หลักฐานถูกส่งเป็นไฟล์ JSON ที่เครื่องอ่านได้หนึ่งไฟล์ ติดตามใน monorepo (ตั้งใจไม่รวมใน npm/PyPI packages):

```
shared/schemas/metric-reliability.schema.json  # its JSON-Schema contract
```

- **Champollion CLI:** `champollion recommend SRC TGT` (สัญญา payload เดียวกัน; artifact ถูกติดตามใน monorepo ดังนั้น packaged install จะลดระดับเป็นหมายเหตุ "index not available" ที่ชัดเจน)

- **รูปแบบกว้างๆ สอดคล้องกับผลการวิจัยรวมของสาขา** บน Indo-European 42 คู่ เมตริกที่เรียนรู้นำ (MetricX +0.84, COMET +0.81) โดย chrF ตามหลังและ BLEU อยู่ท้าย — ผลมาตรฐาน WMT ที่ทำซ้ำที่นี่จากข้อมูลดิบเป็นจุดยึดการตรวจสอบความถูกต้อง
- **ความเบี่ยงเบนต่อตระกูลคือสิ่งสำคัญ** สำหรับ Inuktitut แบบ polysynthetic เมตริก string พังทลายและ COMET เป็นสัญญาณเดียวที่ใช้ได้ สำหรับ Maasai และ English→Arabic ใน wmt25 MetricX มีความสัมพันธ์ *เชิงลบ* ในขณะที่เมตริก string ยังคงใช้งานได้ — เมตริกที่เรียนรู้ที่ extrapolate เกินการกระจายการฝึกสอนล้มเหลวอย่างเงียบๆ ด้วยคะแนนที่ดูมั่นใจ นี่คือกรณีที่ค่าเฉลี่ยรวมลบออกพอดี
- **ตระกูลที่มีคู่เดียวคือหลักฐาน ไม่ใช่ข้อสรุป** แปดจากสิบเอ็ดตระกูลอาศัยคู่หนึ่งหรือสองคู่จากแคมเปญเดียว การอ่านที่ซื่อสัตย์ของ "Eskimo-Aleut: BLEU +0.16" คือ *"ในแคมเปญเดียวที่มนุษย์ตัดสิน en→iu, BLEU ไม่มีข้อมูล"* — การวัดที่บันทึกไว้ สัญญาณเตือน และเหตุผลในการรวบรวมเพิ่มเติม ไม่ใช่กฎเกี่ยวกับตระกูล
- **Cell เชิงลบไม่ได้หมายความว่าเมตริกพังทุกที่** หมายความว่า: ในคู่นั้น ในกลุ่มระบบของแคมเปญนั้น เมตริกเรียงลำดับระบบขัดกับการตัดสินของมนุษย์ การจำกัดช่วง (ดู §8) สามารถลดความสัมพันธ์ใดๆ ได้เมื่อระบบรวมกลุ่มกันอย่างแน่นหนาในด้านคุณภาพ

## 8. ข้อจำกัด

ระบุอย่างตรงไปตรงมา เพราะคุณค่าของ artifact อยู่ที่ความซื่อสัตย์:

1. **ตระกูลเป็นตัวแทน ไม่ใช่กลไก** ตระกูลลำดับวงศ์ตระกูลมีความสัมพันธ์กับ แต่ไม่ได้กำหนด คุณสมบัติทางสัณฐานวิทยาที่ขับเคลื่อนพฤติกรรมเมตริก cell ต่อคู่ (พร้อม genus ที่บันทึกต่อภาษา) อนุญาตให้แบ่งส่วนละเอียดขึ้น key ตระกูลเป็นค่าเริ่มต้นที่ query ได้ ไม่ใช่การอ้างสาเหตุ typological
2. **ความครอบคลุมคือสิ่งที่ WMT ตัดสิน ไม่ใช่สิ่งที่โลกพูด** 57 คู่ ถ่วงน้ำหนักยุโรปอย่างมาก ทุกคู่ xx→English รวมเข้า Indo-European ทั้ง macro-family (Algonquian, Austronesian, Quechuan, …) *ไม่มีความครอบคลุมการตัดสินของมนุษย์เลย* สำหรับภาษาเหล่านั้น พื้นผิวของ Champollion ตอบ UNMEASURED แทนที่จะยืมตัวเลขของเพื่อนบ้าน โปรแกรม sovereign-benchmark ของ Champollion — ชุดทดสอบที่ควบคุมโดยชุมชนพร้อมการตรวจสอบโดยเจ้าของภาษา — คือการแก้ไขระยะยาวสำหรับช่องว่างนี้โดยเฉพาะ
3. **การถ่ายโอนภายในตระกูลเป็นสมมติฐาน** เมื่อภาษาที่ query ไม่เคยถูกตัดสินโดยตรง หลักฐานระดับตระกูลมาจากภาษา *อื่นๆ* ในตระกูล และทุกพื้นผิวที่บริโภคบอกไว้อย่างชัดเจน
4. **ยังไม่มี confidence interval** Cell มีขนาดตัวอย่างแต่ไม่มี bootstrap interval การรวมตระกูลที่มีคู่เดียวโดยเฉพาะควรอ่านด้วยความกว้างที่ §7 บอกเป็นนัย การเพิ่ม bootstrap CI ต่อ cell (harness มีเครื่องจักรสำหรับ score CI อยู่แล้ว) เป็นงานที่วางแผนไว้
5. **การจำกัดช่วง** ความสัมพันธ์คำนวณบนระบบที่ส่งเข้าของแต่ละแคมเปญ แคมเปญล่าสุดรวมระบบที่แข็งแกร่งหลายระบบไว้ด้วยกันอย่างแน่นหนา ซึ่งลดความสัมพันธ์สำหรับเมตริกทั้งหมด — ส่วนหนึ่งของเหตุผลที่ cell ที่ได้จาก wmt25 (Maasai, Arabic) แสดงค่าสุดขีด การระบุแหล่งที่มาต่อ testset บนทุก cell ทำให้ตรวจสอบได้
6. **การเลือกสถิติระดับ segment** τ-b แบบ flatten นั้นง่ายและทำซ้ำได้ แต่ไม่ใช่ความแม่นยำแบบจัดกลุ่มที่ปรับ tie ของเอกสารผลการวิจัย WMT ล่าสุด ตัวเลขที่นี่ไม่ควรเปรียบเทียบตัวต่อตัวกับสิ่งพิมพ์เหล่านั้น
7. **สิทธิ์การใช้งานข้อมูล** ข้อมูลการตัดสินของมนุษย์ upstream ไม่มีคำแถลงสิทธิ์การใช้งานที่ชัดเจน (§3.1) Champollion ไม่แจกจ่ายซ้ำข้อมูลใดๆ เผยแพร่เฉพาะสถิติที่ได้มาพร้อมการระบุแหล่งที่มาครบถ้วน และเก็บ artifact นี้ไว้ใน **non-commercial evidence lane** (`license_lane.commercial_ok: false`) จนกว่าท่าทีจะได้รับการแก้ไข lane MQM ยังติดตามไปยังการเผยแพร่คำอธิบาย Apache-2.0 ของ Google
8. **Archive เป็นเป้าหมายที่เคลื่อนที่** แคมเปญใหม่ถูกเพิ่มไปยัง tarball URL เดิม pin ระบุ snapshot ของเราอย่างแม่นยำ การสร้างใหม่กับ snapshot ที่ใหม่กว่าคือ artifact เวอร์ชันใหม่พร้อม pin ใหม่ ไม่ใช่การอัปเดตแบบเงียบๆ

## 9. การทำซ้ำ

artifact สามารถสร้างใหม่จากแหล่งที่มาได้โดยทุกคน:

```bash
# 1. Fetch the archive (912 MB compressed; NOT immutable — keep the pins)
mkdir -p ~/.mt-eval/mt-metrics-eval && cd ~/.mt-eval/mt-metrics-eval
curl -sSL -D mt-metrics-eval-v2.headers -o mt-metrics-eval-v2.tgz \
     https://data.statmt.org/wmt26/mt-metrics-eval-v2.tgz
shasum -a 256 mt-metrics-eval-v2.tgz > mt-metrics-eval-v2.sha256
tar xzf mt-metrics-eval-v2.tgz

# 2. Regenerate (refuses to run without a checksum pin)
python3 arena/scripts/import_wmt_metaeval.py
```

โปรดทราบว่า README ของ archive เองชี้ไปยัง URL storage.googleapis.com ที่เลิกใช้แล้ว `data.statmt.org` คือ host ที่ใช้งานอยู่ importer เป็น Python standard library ล้วนๆ (sacreBLEU เฉพาะสำหรับ lane chrF++ ที่คำนวณได้) การนำไปใช้งานความสัมพันธ์ของมันถูกตรวจสอบข้ามกับ reference แบบ brute-force ใน `arena/tests/test_wmt_metaeval.py` และสัญญาโครงสร้างของ artifact ถูกบังคับใช้โดย JSON schema บวกกับ integrity test ใน runtime ทั้งสอง

## 10. เครดิตและการอ้างอิง

การตัดสินของมนุษย์ที่สรุปที่นี่เป็นผลงานของ **ผู้จัดงานและผู้ทำคำอธิบาย WMT Metrics shared-task** — รวมถึง Markus Freitag, Nitika Mathur, Tom Kocmi และผู้ร่วมงานหลายคนในแคมเปญ 2019–2025 — และของ **โปรแกรมคำอธิบาย Google MQM** (Freitag et al., *Experts, Errors, and Context*, TACL 2021; `google/wmt-mqm-human-evaluation`) archive และ toolkit ดูแลรักษาเป็น `google-research/mt-metrics-eval` ความแม่นยำการจัดอันดับแบบคู่ตาม Kocmi, Federmann et al. (2021), *To Ship or Not to Ship* การมีส่วนร่วมของ Champollion คือการจัดระเบียบต่อตระกูลภาษา การคำนวณความสัมพันธ์ และโครงสร้างความซื่อสัตย์รอบๆ มัน — ทุกตัวเลขใน artifact พร้อม provenance `champollion-derived` ที่ระบุ upstream ที่ได้มา และไม่มีข้อความ การตัดสิน หรือคะแนนของพวกเขาถูกแจกจ่ายซ้ำ

เมื่ออ้างตัวเลขความน่าเชื่อถือจาก artifact นี้ ให้อ้างทั้งแคมเปญ WMT ที่ cell ระบุแหล่งที่มาและเวอร์ชัน artifact ของ Champollion (บล็อก `sources` มี data pin ที่แน่นอน) และเคารพ non-commercial evidence lane ที่อธิบายใน §8
