# ข้อกำหนดการสร้างคิว

**เวอร์ชันสูตร: `ecv-v3` (ค่าลูกโซ่ที่คาดหวังพร้อมความน่าเชื่อถือของสะพาน)**
เอกสารนี้คือนิยามเชิงบรรทัดฐานของวิธีการเรียงลำดับ
[champollion.dev/queue.json](https://champollion.dev/queue.json)
การนำไปใช้งาน
(`arena/scripts/generate_sweep_queue.py` ใน public harness repo)
สะท้อนหน้านี้ทีละส่วน โดยข้อมูลเมตาของคิวจะสะท้อนค่าพารามิเตอร์ที่ใช้จริงในขณะสร้าง และ **ทุกรายการมีรายละเอียดสูตรครบถ้วน** เพื่อให้สามารถคำนวณอันดับใดก็ได้ด้วยมือจาก JSON ที่เผยแพร่เพียงอย่างเดียว หากหน้านี้และคิวขัดแย้งกัน ถือเป็น bug — กรุณารายงาน

**คิวในปัจจุบัน สรุปในหนึ่งย่อหน้า** คิวสาธารณะประกอบด้วยทั้งรายการ LLM
(เงื่อนไขพรอมต์แบบ naive และ coached) และรายการเอ็นจินบริการ MT
บนบอร์ดเดียวกัน โดยจัดอันดับตามลำดับการสำรวจ (`map`, §2.2): การวัดผลครั้งแรก
ข้ามคู่ภาษา ภาษา และตระกูลภาษาต่อหนึ่งดอลลาร์ พร้อมทั้งการบูสต์
การอ่านค่าครั้งแรกสำหรับภาษาที่ไม่เคยถูกวัดมาก่อน (§2.2), ระดับงบประมาณ
ที่เผยแพร่ในการแสดงตัวอย่าง (§2.1.1) และอันดับที่สมบูรณ์ซึ่งให้บริการจาก
ฐานข้อมูล (ไฟล์สแตติกจะเก็บเฉพาะส่วนบนสุดเมื่ออันดับทั้งหมด
เกินขีดจำกัดขนาดไฟล์ และระบุไว้อย่างชัดเจน) หัวข้อด้านล่างนี้คือคำนิยาม
เชิงบรรทัดฐาน ซึ่งบันทึกประวัติการตัดสินใจตามวันเวลาไว้ด้วย — เมทาดาตาบน
คิวที่ให้บริการจะระบุพารามิเตอร์ที่แน่นอนที่ใช้ในการจัดอันดับ

> **v3 (2026-06-13).** ทุก edge ขณะนี้คือ *สะพาน* ที่มีสองตัวเลข —
> คุณภาพและความน่าเชื่อถือ — และ chain matrix ทำงานบนผลคูณของทั้งสอง
> (§1.5) รายการคำศัพท์เดี่ยว 62 คำที่รันครั้งเดียวไม่สามารถนับเป็น path ได้อีกต่อไป
> การทำซ้ำ คอร์ปัสขนาดใหญ่ขึ้น คอร์ปัสที่สมบูรณ์ขึ้น และช่วงความเชื่อมั่นที่แคบลง
> ล้วนมีมูลค่าที่ตีราคาได้ คิว v2 (เฉพาะคุณภาพ) ยังคงตีความได้ผ่านข้อมูลเมตาของตัวเอง

## 1. วัตถุประสงค์: mesh ที่ถ่วงน้ำหนักด้วยคุณภาพ

วัตถุประสงค์คือ *การแปลระหว่างภาษา ซึ่งสร้างขึ้นจากเชนของแต่ละคู่ภาษา
ที่ผ่านการวัดผลแล้ว* การแปลระหว่างสองภาษาที่ไม่มีเบঞ্চมาร์ก
โดยตรงจะให้บริการโดย **การต่อเชน** คู่ภาษาที่มีเบঞ্চมาร์ก
(X→pivot→Y) ดังนั้น คุณค่าของเบঞ্চมาร์กจึงไม่ใช่จำนวน
คลังข้อมูล แต่เป็น **ขีดความสามารถของเชนในกราฟ (chain capacity of its graph)**

**นิยาม.** ให้ *กราฟ benchmark* มีหนึ่ง node ต่อหนึ่งภาษา และสำหรับทุกคู่ภาษาที่มีการรันที่เผยแพร่แล้วและไม่ถูกตัดสิทธิ์อย่างน้อยหนึ่งครั้ง จะมี **ความแข็งแกร่งของ edge**

```
s(e) = (best published corpus-level chrF++ on that pair) / 100   ∈ [0, 1]
```

chrF++ ระดับคอร์ปัสคือตัวเลขที่เผยแพร่เป็นมาตรฐาน (ดู
[ข้อกำหนดการให้คะแนน](/docs/network/specifications/scoring)) โดย *best* เพราะ
chain จะเลือกเส้นทางผ่านระบบที่ดีที่สุดที่พิสูจน์แล้วต่อ hop
คู่ที่ไม่มีการรันที่เผยแพร่จะมี s(e) = 0

**ความแข็งแกร่งของ chain ที่ประมาณการ** ของ path P ระหว่างสองภาษาคือ

```
strength(P) = λ^(|P|−1) · Π_{e ∈ P} s(e)
```

— คุณภาพของ edge ประกอบกันแบบคูณ และแต่ละ *junction* (pivot กลาง) มีต้นทุนเป็นปัจจัยความเที่ยงตรงเพิ่มเติม **λ < 1**
ทั้งสองตัวเลือกมีพื้นฐานจากวรรณกรรมการแปลผ่าน pivot:
การแปลผ่าน pivot สูญเสียคุณภาพอย่างสม่ำเสมอเมื่อเทียบกับการแปลตรง
เกินกว่าที่การประกอบแบบไร้เดียงสาจะแนะนำ (Utiyama & Isahara
2007; Wu & Wang 2007) ขนาดของการสูญเสียขึ้นอยู่กับ pivot ที่เลือก (Paul et al. 2009)
และการสร้างคู่ *ตรง* ที่ไม่ยึดภาษาอังกฤษเป็นศูนย์กลางให้ผลดีกว่าการใช้ภาษาอังกฤษเป็น pivot อย่างวัดได้ในระดับขนาดใหญ่ — ประมาณ ~10 BLEU ในการตั้งค่า many-to-many ของ M2M-100 (Fan et al. 2021) λ คือตัวเตือนถาวรในสูตรว่า chain ที่ประมาณการไม่ใช่การวัด: มีเพียงการรันตรงเท่านั้นที่ลบส่วนลดออกได้

**best-chain matrix** และ **mesh objective** คือ

```
Q(u,v) = max over paths P from u to v of strength(P)      (1 if u = v, 0 if disconnected)

Φ = mean over ordered language pairs (u ≠ v) of Q(u,v)    ∈ [0, 1]
```

Q คำนวณอย่างแม่นยำในฐานะปัญหา shortest-path ภายใต้การแปลง log มาตรฐาน (น้ำหนัก edge −ln(λ·s(e)) ≥ 0, Dijkstra, จากนั้น
Q = exp(−d)/λ) Φ คือการสร้าง *global efficiency* ของ [Latora & Marchiori
(2001)](https://arxiv.org/abs/cond-mat/0101396) โดยแทนที่ kernel 1/distance ด้วย chain fidelity แบบคูณ — kernel ที่เป็นธรรมชาติเมื่อ edge มีการรักษาคุณภาพต่อ hop แทนที่จะเป็นความยาวหน่วย (คิว v1 จัดอันดับโดย unweighted global efficiency gain — กรณีพิเศษของตระกูลนี้ที่คุณรู้เพียงว่า edge มีอยู่หรือไม่)

### 1.5 ความน่าเชื่อถือ: สะพานคือ (q, r)

คะแนนที่โดดเด่นบนคอร์ปัสขนาดเล็ก บาง และไม่เคยทำซ้ำไม่ใช่สะพาน
v3 จึงแบ่ง edge ที่วัดแล้วทุกอันออกเป็น:

```
quality      q(e)   = best published corpus-level chrF++ / 100
reliability  r(e)   = f_size · f_rich · f_conf · f_repl        ∈ [0, 1]
effective    s_eff(e) = q(e) · r(e)        ← what chains compose over
```

| ปัจจัย | นิยาม | เครดิตเต็มที่ | จุดยึด |
|---|---|---|---|
| `f_size` | min(1, n/100), n = จำนวน entry ที่ประเมินของการรันที่ดีที่สุด | 100 entries | ระดับนัยสำคัญของ [corpus-design](/docs/network/specifications/corpus-design); Koehn (2004) ตรวจสอบ bootstrap testing บนชุด ~300 ประโยค — แม้แต่ 300 ก็ถือว่า "เล็ก" ดังนั้นขนาดจึงลดความน่าเชื่อถือแทนที่จะเป็นเพียงเกณฑ์การแสดงผล |
| `f_rich` | min(1, L̄/5), L̄ = ความยาวต้นฉบับ *effective* เฉลี่ย | 5 effective words | AmericasNLP (Mager et al. 2021) นำ chrF มาใช้เพราะหน่วยระดับคำแตกสลายบนสัณฐานวิทยาที่ซับซ้อน; Mager et al. (2022) บันทึก whitespace token ว่าเป็นหน่วยที่ผิด |
| `f_conf` | min(1, 5/h), h = ครึ่งความกว้าง chrF 95% CI ของการรันที่ดีที่สุด (proxy `50/√n` เมื่อไม่ได้เผยแพร่) | CI ≤ ±5 chrF | ระดับ noise ที่ต่ำกว่านั้น delta ไม่สามารถแยกแยะได้บนคอร์ปัสขนาดเล็ก; Kocmi et al. (2021) แสดงให้เห็นว่า delta ภายใน CI มักขัดแย้งกับความชอบของมนุษย์ |
| `f_repl` | min(1, runs/2) | 2 การรันที่เผยแพร่ | Marie, Fujita & Rubino (2021) ประเมิน meta 769 บทความ: การเปรียบเทียบครั้งเดียวที่ไม่ได้ทำซ้ำคือความล้มเหลวด้านความน่าเชื่อถือที่บันทึกไว้ในสาขา |

**ความยาว effective** วัดในหน่วยเนื้อหา ไม่ใช่คำที่คั่นด้วยช่องว่าง: `L̄ = mean source chars / c(L)` โดยที่ *character economy*
`c(L)` คือค่ามัธยฐานของอักขระในฝั่งภาษา L ต่อคำภาษาอังกฤษในฝั่งที่จัดแนวแล้ว วัดจากคอร์ปัสคู่ขนานของโปรเจกต์นี้เอง
(มากกว่า 7,400 entries ที่จัดแนวแล้วเมื่อ v3 เปิดตัว: cmn 1.6, jpn 2.3, kor 2.6;
eng baseline 5.0; deu 6.0; crk 4.7 — คำ polysynthetic ตีราคาตามเนื้อหาที่บรรจุ) ไม่มีตารางค้นหา typology; การประมาณการจะแม่นยำขึ้นเมื่อคอร์ปัสเติบโต; ภาษาที่ไม่มีข้อมูลคู่กับ eng ใช้ economy เริ่มต้น บันทึกต่อคอร์ปัสในรีจิสทรี (บล็อก `richness`)

**ระดับสะพาน** (คำศัพท์การแสดงผล): **established** — n ≥ 100,
L̄ ≥ 5, h ≤ 5, runs ≥ 2; **provisional** — วัดแล้วแต่ไม่ผ่านเกณฑ์ใดเกณฑ์หนึ่ง;
**registered** — ไม่มีการรันที่เผยแพร่ การอ้างสิทธิ์ chain ("คุณสามารถไปจาก X
ถึง Y ได้") แข็งแกร่งเพียงเท่ากับระดับของ hop ที่อ่อนแอที่สุด และการแสดงผล mesh แสดงความน่าเชื่อถือเป็นความทึบแสงของ edge

**การตรวจสอบตัวอย่าง** (จาก verification script ที่ check-in ไว้ รันก่อน v3 เปิดตัว): *รายการคำศัพท์เดี่ยว 62 คำ, รันหนึ่งครั้ง* → r ≈ **0.04**
(ไม่ใช่ path); *200 ประโยค, ±3 CI, 3 การรัน* → r = **1.00**; คอร์ปัสภาษาญี่ปุ่น 101 entry ที่จำนวนคำแบบไร้เดียงสาเป็น 1.0 (artifact ของ script)
ฟื้นฟูเป็น 6.5 effective words และ `f_rich` เต็ม
Bounds และ per-factor monotonicity ผ่านการทดสอบ property

**มูลค่าของการรันหนึ่งครั้งภายใต้ v3.** การรันสามารถปรับปรุงสะพานได้สองวิธี และ
ΔΦ ใช้ค่าที่ดีกว่าระหว่าง: **(a)** กลายเป็นการรันที่ดีที่สุดของ edge —
`ŝ_eff = คุณภาพที่คาดการณ์ × r(n ของคอร์ปัส, richness, CI proxy,
runs+1)`; หรือ **(b)** เพียงแค่ทำซ้ำ — best ปัจจุบันยังคงอยู่,
`f_repl` เพิ่มขึ้น การทำซ้ำบน edge ที่รันครั้งเดียวจึงเป็นมูลค่าจริงที่ตีราคาได้ และคอร์ปัสที่ใหญ่กว่าหรือสมบูรณ์กว่าบนคู่ที่วัดแล้วมีอันดับสูงกว่าการรันซ้ำบนคอร์ปัสขนาดเล็ก รายการแสดง `edge_quality`,
`edge_reliability`, `edge_tier`, `effective_strength`,
`post_run_reliability` และ `predicted_effective` ควบคู่กับฟิลด์การคาดการณ์ v2

**สิ่งที่ Φ ไม่ใช่.** Φ คือสกุลเงินการจัดลำดับความสำคัญภายในของคิว
ไม่ใช่การอ้างสิทธิ์ความสามารถ input ของมันคือคะแนน development-set พร้อมข้อแม้ทั้งหมดของ [Corpus Design
Framework](/docs/network/specifications/corpus-design): การปนเปื้อนของข้อมูลฝึกที่เป็นไปได้ทำให้แต่ละคะแนนเป็นขอบบน ค่า chrF++ ไม่สามารถเปรียบเทียบได้อย่างเคร่งครัดข้ามภาษา และคอร์ปัสขนาดเล็กมีช่วงความเชื่อมั่นกว้าง สูตรต้องการเพียงให้ Φ *จัดลำดับการรันตามประโยชน์*; มันไม่เคยถูกเผยแพร่เป็นการรับประกันคุณภาพ

## 2. ปัญหาการตัดสินใจ

รายการที่เปิดอยู่ในคิวคือทุกชุดค่าผสมของ (corpus, model, condition)
ที่มีสิทธิ์ (development split, สัญญาอนุญาตที่เผยแพร่ต่อได้,
ไม่ถูกกักกัน, มีสิทธิ์ส่งต่อ และ
**สามารถระบุเบঞ্চมาร์กได้** — ดูเกตการระบุตัวตนของภาษาใน §2.2) และ
ยังไม่อยู่บนลีดเดอร์บอร์ด การรันซ้ำที่เหมือนเดิมทุกประการของชุดค่าผสมที่ครอบคลุมแล้ว
จะถูกคัดออก — ลายนิ้วมือของ run-card จะคัดข้อมูลซ้ำออกเมื่อเผยแพร่ — แต่
โมเดลหรือเงื่อนไขใหม่บนคู่ภาษาที่วัดผลไปแล้วยังคงเป็นรายการที่เปิดอยู่

compute ที่มีส่วนร่วมคืองบประมาณ การเลือกว่าจะรันรายการเปิดใดต่อไปเพื่อให้ mesh ปรับปรุงเร็วที่สุดคือการ maximization แบบ budgeted coverage และแนวทางมาตรฐานคือการเลือกแบบ greedy โดย **มูลค่าส่วนเพิ่มต่อหน่วยต้นทุน**: สำหรับ objective แบบ monotone submodular กฎ greedy มีการรับประกัน (1 − 1/e) แบบคลาสสิก (Nemhauser,
Wolsey & Fisher 1978) และรูปแบบ benefit/cost-ratio คือ algorithm มาตรฐานภายใต้งบประมาณ (Khuller, Moss & Naor 1999) เราใช้กฎ ratio เป็นหลักการจัดอันดับ (หมายเหตุความซื่อสัตย์: objective ของเราให้ผลตอบแทนลดลงแบบ coverage-like ในแกนกลางที่กำหนดได้ แต่ชั้นการคาดการณ์แบบ stochastic หมายความว่าเราอ้างการรับประกัน greedy เป็น *แรงจูงใจ* ไม่ใช่ทฤษฎีบทเกี่ยวกับระบบนี้โดยเฉพาะ)

```
ECV(item) = ΔΦ(item) / max(est_cost_usd, COST_FLOOR)
```

รายการจัดอันดับโดย ECV จากมากไปน้อย การเสมอกันแบ่งโดย: naive ก่อน coached, ถูกกว่าก่อน, จากนั้น item id

### 2.1 การแก้ไขการจัดอันดับ — 2026-07-12

การปรับแต่งสี่รายการที่ซ้อนทับบนกฎ greedy ECV โดยแต่ละรายการจะสะท้อนอยู่ใน
metadata ของ queue (`priority_parameters.contamination_ecv_factors`,
`priority_parameters.frontier_interleave`, `metadata.preview_policy`):

1. **ตัวคูณการปนเปื้อน** ECV ของแต่ละรายการจะถูกคูณด้วย
   ค่าตัวประกอบจากระดับการปนเปื้อนของ corpus นั้น: **LOW 1.0 / MEDIUM
   0.4 / HIGH 0.1** โดยระดับที่ไม่ทราบหรือขาดหายไปจะถูกถือว่าเป็น
   MEDIUM (ห้ามสันนิษฐานว่าสะอาด) เหตุผล: กราฟ clean chain อนุญาตเฉพาะ edge ที่มีการปนเปื้อนระดับ LOW เท่านั้น ดังนั้น run ที่ไม่ใช่ LOW จึงไม่สามารถเข้าสู่กราฟนั้นได้ และต้องไม่มีอันดับสูงกว่างาน clean-mesh ที่มีต้นทุนเท่ากัน รายการที่ไม่ใช่ LOW ยังคงอยู่ใน queue — การเปรียบเทียบภายใน relative-lane มีคุณค่าจริง — เพียงแต่จัดอันดับไว้หลังงานที่สะอาด
2. **การสลับ Frontier** หลังจากการเรียงลำดับแบบ greedy ทุกๆ ช่องลำดับความสำคัญที่ 5
   จะบรรจุรายการที่มีอันดับสูงสุดที่ยังไม่ได้จัดวางจากชุด frontier-model (ซึ่งดูแลเป็นข้อมูลใน generator และสะท้อนอยู่ใน metadata) เพื่อให้หลักฐานจาก frontier เข้าถึง prediction priors ได้เร็ว แทนที่จะรอจนกว่า tier ราคาถูกจะอิ่มตัว เป็นการจัดเรียงใหม่ล้วนๆ: ไม่มีรายการใดถูกตัดออกหรือซ้ำกัน รายการ frontier ที่ได้รับช่องตามธรรมชาติจะคงช่องนั้นไว้ และลำดับความสำคัญจะนับจากลำดับที่ถักทอแล้ว — การจัดอันดับที่เผยแพร่คือความจริง
3. **ขีดจำกัด source-hub ใน Preview** การแสดงตัวอย่างสาธารณะ top-25 จะแสดง
   รายการที่ใช้ภาษาต้นทางเดียวกันได้สูงสุด **6** รายการ เพื่อป้องกันไม่ให้ hub ที่มีทรัพยากรมากผูกขาดหน้าต่างแสดงผล รายการที่เกินขีดจำกัดยังคงลำดับความสำคัญจริงใน queue เต็ม โดย preview จะดึงรายการถัดไปที่มีสิทธิ์ตามลำดับการจัดอันดับ
4. **การยกเว้นภาษาประดิษฐ์ใน Preview** รายการที่มีภาษาต้นทางหรือภาษาปลายทางเป็นภาษาประดิษฐ์จะถูกข้ามโดย preview การพิจารณาขึ้นอยู่กับ card-family (กลุ่ม Artificial Language ของ Glottolog อ่านจาก language cards — ไม่ใช่ชุดภาษาที่กำหนดตายตัว) และรายการโค้ดที่ได้มาจะเผยแพร่ใน
   `metadata.preview_policy` เพื่อให้การรีเฟรชฝั่ง server ใช้การคัดเลือกเดียวกัน

(3) และ (4) เป็น **นโยบายการนำเสนอเท่านั้น**: `queue.json` ฉบับเต็ม
การจัดอันดับ และลำดับความสำคัญของมันไม่ได้รับผลกระทบใดๆ

### 2.1.1 ระดับงบประมาณ — "เงิน $X ซื้ออะไรได้บ้าง?" (2026-08-24)

`queue-preview.json` มีอาร์เรย์ `budget_tiers` ที่สรุปสำหรับ
งบประมาณ **$1 / $10 / $100 / $1,000** ซึ่งเป็นพรีฟิกซ์ที่ซื้อได้ตามลำดับความคุ้มค่า (greedy affordable prefix)
ของอันดับที่เผยแพร่: ไล่ดูรายการตามลำดับความสำคัญ เลือกแต่ละรายการ
ที่ต้นทุนโดยประมาณยังคงอยู่ในงบประมาณ ข้ามรายการที่เกินงบ
และเติมรายการที่ถูกกว่าในลำดับถัดไปเรื่อยๆ แต่ละระดับจะรายงานว่า
ซื้อได้กี่รายการ, ต้นทุนโดยประมาณรวมเท่าใด, ครอบคลุมคู่ภาษา
และโมเดลที่แตกต่างกันกี่รายการ และงบประมาณครอบคลุมลึกเพียงใดในอันดับ
(`max_priority`)

เนื่องจากการจัดอันดับเป็นไปตามมูลค่าส่วนเพิ่มต่อต้นทุนอยู่แล้ว (§2) พรีฟิกซ์
ที่ซื้อได้ตามลำดับความคุ้มค่า **จึงเป็น** การจัดสรรที่โมเดลนี้แนะนำ
สำหรับการใช้จ่ายนั้น — ผู้ร่วมสมทบรายย่อยและรายใหญ่ต่างอ่านคำตอบที่ชัดเจนและเหมาะสมที่สุด
ได้จากอันดับที่เผยแพร่เดียวกัน แทนที่จะเป็นรายการเดียว
ที่ไม่ได้ปรับขนาดให้เหมาะกับใครอย่างแท้จริง ระดับเหล่านี้เป็นเพียงบทสรุปเท่านั้น:
การจัดสรรที่แท้จริงก็คือตัวอันดับเอง โดยไล่ดูตามลำดับเทียบกับงบประมาณ
ของคุณเอง การรีเฟรชฝั่งเซิร์ฟเวอร์จะคำนวณระดับงบประมาณใหม่บนรายการที่เหลืออยู่
ด้วยการไล่ดูแบบเดียวกันทุกประการ (ตัวสร้างและฟังก์ชันรีเฟรช
ถูกนำมาใช้งานในลักษณะฝาแฝด และได้รับการทดสอบทั้งสองฝั่ง)

คิวฐานข้อมูล (`queue_top()` / `queue_pairs()`) ให้บริการอันดับ

**เกตการระบุตัวตนของภาษา** (2026-07-19) รายการในคิวจะกำหนดเป้าหมายเฉพาะ
**รหัส ISO 639-3 รายภาษาที่ใช้งานอยู่** เท่านั้น — คะแนนที่เทียบกับ macrolanguage
("Arabic") หรือรหัสกลุ่มตระกูลภาษา ("Berber languages") จะเป็นการอ้างสิทธิ์
ที่ไม่สามารถพิสูจน์ว่าเป็นเท็จได้สำหรับวิวัฒน์ภาษา (varieties) ที่ไม่เคยได้รับการประเมิน (เป็นเหตุผลเดียวกับ
ที่ FLORES-200/NLLB ปฏิบัติตามโดยการกำหนดรหัสข้อมูลเป็น `arb`/`quy`/`zsm`) ป้ายกำกับ
คลังข้อมูลต้นทางจะถูก *แปลงให้ตรงกัน (resolved)* โดยไม่ยอมรับตามนั้นหรือละทิ้งไปเฉยๆ: แท็กระบบการเขียน
จะถูกแยกออกโดยอัตโนมัติ (คลังข้อมูล `eng→cmn-Hans` จะเข้าคิวสำหรับ `eng→cmn`,
โดยระบบการเขียนจะถูกเก็บไว้เป็นเมทาดาตาสำหรับแสดงผลรายการ `source_script`/
`target_script`); รหัสที่เลิกใช้อย่างเป็นทางการจะเปลี่ยนตามรหัส ISO ตัวถัดไปอย่างเป็นทางการ; และคลังข้อมูลที่ติดป้ายกำกับระดับ macro จะเข้าคิวได้ก็ต่อเมื่อมี **การแปลงวิวัฒน์ภาษา**
ที่บันทึกและอ้างอิงไว้บนรายการรีจิสทรีของตนเท่านั้น (เช่น FLORES+
ระบุเอกสารภาษา Quechua ของตนเป็น `quy`) คลังข้อมูลที่ไม่สามารถแปลงได้ตามทั้งสองแนวทาง
จะถูกคัดออกพร้อมระบุเหตุผลที่อ่านได้ด้วยเครื่องซึ่งเผยแพร่ไว้ใน
`metadata.doctrine_exclusions` (ยอดรวม, จำนวนนับตามเหตุผล, เหตุผล
ของแต่ละคลังข้อมูล) และนับไว้ในบัญชีพื้นที่รกร้าง
(`service_landscape.invisible_reasons.corpus_excluded_by_doctrine`) —
เป็นการคัดออกที่มองเห็นได้ชัดเจน ไม่มีการตัดทิ้งแบบเงียบๆ ผลลัพธ์ในอดีต
บนคลังข้อมูลที่ติดป้ายกำกับแบบคลุมเครือจะยังคงรักษาโหนดเมชที่มีชื่อระบุไว้อย่างตรงไปตรงมา
(โหนด `scope`: `macrolanguage` / `collective` / `retired`) โดยไม่ถูกรวม
เข้ากับวิวัฒน์ภาษาที่เป็นสมาชิก ข้อมูลนำเข้าสำหรับการแปลงทั้งหมดได้รับการเผยแพร่:
สแตมป์ `language_resolution` ของแต่ละรายการในรีจิสทรีจะระบุ
รหัสที่แปลงแล้ว ขอบเขต และการอ้างอิงการตรึง

**โหมดการจัดอันดับ** (`metadata.rank_mode` อธิบายไว้ใน
`metadata.priority_model`) ลำดับสองแบบของรายการชุดเดียวกัน:

- **ecv** — กฎ expected-chain-value แบบละโมบของ §2–§3: การปรับปรุง
  เมชต่อต้นทุนดอลลาร์โดยประมาณ ลำดับการแสวงหาประโยชน์ (exploitation ordering); เหมาะสำหรับ
  กรณีที่บอร์ดมีความหนาแน่นเพียงพอสำหรับการทำนายและ ΔΦ สามารถให้สัญญาณที่มีความหมาย
- **map** (map-value v2) — ลำดับการสำรวจ (survey ordering):
  `MapValue = novelty × uncertainty × promise × connectivity ×
  corpus-quality × contamination ÷ cost` ซึ่งประกอบขึ้นจากการติดตามแบบละโมบที่แน่นอน
  *Novelty* คือเครดิตการอ่านค่าครั้งแรกตามตำแหน่ง ซึ่งจะลดลงเมื่อ
  รายการที่จัดวางไปแล้วครอบครองคู่ภาษาแบบมีทิศทางเดียวกัน (1/(1+n)), ภาษาเป้าหมาย,
  ตระกูลภาษาเป้าหมาย, เซลล์ method × target-family และ
  เซลล์ target × domain (แต่ละส่วนลดลงแบบ 1/√(1+n); ตระกูลภาษาจากการ์ดภาษา,
  โดเมนจากอนุกรมวิธานของรีจิสทรีคลังข้อมูล — ความครอบคลุมเริ่มต้นของเป้าหมาย
  ควรกระจายข้ามระดับภาษา ไม่ใช่ทำซ้ำโดเมนแรก
  ที่วัดผลไปแล้ว) *Uncertainty* คือความลึกในการถอยกลับ (back-off depth) ของการทำนายตาม §3.1
  (คู่ภาษา 0.25 · ภาษาเป้าหมาย 0.55 · ภาษาต้นทาง 0.75 · ทั่วไป
  1.0) × 1/(1+การรันที่เผยแพร่บนเอดจ์) *Promise* คือความแข็งแกร่ง
  ที่ทำนายตาม §3.1 โดยกำหนดค่าต่ำสุดไว้ที่ 0.25 — ภาษาที่ไม่รู้จักแต่น่าจะใช้งานได้จะขึ้นนำ
  และการสำรวจพื้นที่รกร้างที่มีแนวโน้มเป็นไปได้ยังคงมีคุณค่า *Connectivity*
  จะจัดอันดับคู่ภาษาที่ **เชื่อมโยงเครือข่ายที่วัดผลแล้วเข้ากับภาษาที่
  ยังไม่สามารถเข้าถึงได้** ให้สูงขึ้น: ปลายทางถือว่า *established* เมื่ออยู่บน
  เอดจ์ของเมชที่วัดผลแล้ว (`mesh.json`, สถานะ `measured`) หรืออยู่ในรายการ
  ความครอบคลุมที่เผยแพร่ของบริการ MT ใดๆ (ผ่านนามแฝง macrolanguage ซึ่งเป็นนามแฝงเดียวกัน
  กับเกตเลนด้านบน); **bridges** (ปลายทาง established พอดีหนึ่งฝั่ง) และ
  **islands** (ไม่มีทั้งสองฝั่ง) จะได้คะแนน 1.0 ทั้งคู่ —
  ตั้งแต่วันที่ 2026-08-27 การอ่านค่าครั้งแรกของพื้นที่รกร้างที่ตัดขาดจะนับเต็มส่วน
  (islands เคยได้คะแนน 0.5 ภายใต้การปรับขนาดแบบขยายออกจากเครือข่ายของวันที่ 2026-07-19
  ซึ่งลดความสำคัญของกลุ่มหางแถวลึกที่สุดในเชิงโครงสร้าง) — ในขณะที่
  การเพิ่มความหนาแน่น **interior** (ทั้งสองฝั่ง established) ได้คะแนน 0.5:
  การเสริมความแข็งแกร่งระหว่างจุดที่ทราบอยู่แล้วเป็นหน้าที่ของโหมด ecv ส่วน
  **การบูสต์การอ่านค่าครั้งแรก** (×2.0) จะคูณมูลค่าการสำรวจ
  ของรายการใดก็ตามที่ภาษาต้นทางหรือภาษาเป้าหมายมีผลการวัดที่เผยแพร่
  เป็นศูนย์ในทุกที่เพิ่มเติม — หลักการข้อที่เก้าที่ระบุไว้อย่างชัดเจนคือ: **การอ่านค่าครั้งแรก
  ของภาษามีความสำคัญกว่าการปรับปรุงให้ละเอียด** ปัจจัยความไม่แน่นอน
  เพียงอย่างเดียวไม่สามารถสะท้อนสิ่งนี้ได้ (ปัจจัยนี้ให้คะแนนคู่ภาษาที่ยังไม่ได้วัด
  ระหว่างสองภาษาที่วัดผลมาเป็นอย่างดี เท่ากับภาษาที่ไม่เคยถูกวัดมาก่อน); การบูสต์
  ทำให้การอ่านค่าครั้งแรกของกลุ่มหางแถวกลายเป็นวัตถุประสงค์ที่ระบุไว้อย่างชัดเจน
  แทนที่จะเป็นเรื่องบังเอิญที่เกิดขึ้น ปัจจัยทั้งสองจะส่งผ่าน
  `metadata.map_value_parameters` และนำไปใช้แบบเดียวกันภายในองค์ประกอบการสำรวจ
  ของ edv (§2.3)

  อีกครึ่งหนึ่งของหลักการข้อที่เก้าอยู่นอกเหนือการจัดอันดับ: ไม่มีการจัดลำดับ
  ของรายการที่มีอยู่แบบใดที่สามารถเข้าถึงภาษาที่ไม่มีคลังข้อมูล
  เลยได้ (~7,500 ภาษาที่เป็นรหัสเดี่ยวและยังมีผู้ใช้อยู่ในปัจจุบัน) **รายการสิ่งที่ต้องการสำหรับคลังข้อมูล**
  (`/corpus-wishlist.json` ซึ่งสร้างขึ้นใหม่ควบคู่ไปกับคิว)
  เผยแพร่แนวหน้าการจัดหาดังกล่าว: ทุกภาษาที่เป็นรหัสเดี่ยว ยังมีผู้ใช้อยู่
  และไม่มีคลังข้อมูล จะถูกจัดอันดับตามจำนวนผู้พูดที่ดีที่สุดที่มีการอ้างอิง —
  จำนวนผู้พูดทำหน้าที่เป็นตัวแทนความเป็นไปได้สำหรับชุมชน
  ที่สามารถสร้างคลังข้อมูลขึ้นมาได้จริง — ทุกจำนวนนับได้รับการอ้างอิงถึงแหล่งที่มา
  และไม่มีการชี้ขาดตัดสิน
  *Corpus-quality* คือศักยภาพความน่าเชื่อถือที่แท้จริงของคลังข้อมูล
  `f_size × f_rich` จาก §1.5 — การสำรวจควรเน้นไปที่คลังข้อมูล
  ที่สามารถรองรับน้ำหนักได้ ดังนั้นรายการคำศัพท์คำเดี่ยวขนาด 62 รายการจะไม่ถูกนำมาเป็น
  รายการเด่นเพียงเพราะมีราคาถูกอีกต่อไป; การไม่มีการวัดความสมบูรณ์
  จะยังคงมีสถานะเป็นกลาง (การไม่มีการวัดผลไม่ใช่หลักฐานของความขาดแคลน)
  วินัยด้านต้นทุนและการปนเปื้อนจะเหมือนกับ ecv ทุกประการ การสลับรายการแนวหน้า
  และการตัดสินกรณีคะแนนเท่ากัน (§2.1) ยังคงใช้อย่างไม่มีการเปลี่ยนแปลง เหมาะสำหรับ
  ระยะการสำรวจ: ซึ่งจะเพิ่มสิ่งที่ *แผนที่ได้เรียนรู้* ต่อดอลลาร์ให้สูงสุด — การวัดผล
  ครั้งแรกข้ามคู่ภาษา, ภาษา, ตระกูลภาษา, เซลล์วิธี และ
  โดเมน โดยเติบโตออกจากเครือข่ายที่วัดผลแล้วแทนที่จะกระจัดกระจาย —
  โดยยอมแลกกับการเติบโตของความแข็งแกร่งของเมชที่ช้าลงอย่างตั้งใจ

> **map-value v2 (2026-07-19)** ส่วนเพิ่มเติมสองรายการตามคำสั่งของผู้ก่อตั้ง
> สำหรับลำดับการสำรวจ: คู่ภาษาที่ *เชื่อมโยงเข้าสู่เครือข่ายที่วัดผลแล้ว* ในขณะนี้
> จะได้รับการจัดอันดับนำหน้าการหยั่งเชิงแบบตัดขาดและการเพิ่มความหนาแน่นภายใน และ
> คุณภาพคลังข้อมูล (เกณฑ์ขนาดขั้นต่ำ × ความสมบูรณ์ที่มีประสิทธิภาพ, §1.5) บวกกับ
> การกระจายโดเมนต่อภาษาเป้าหมายจะร่วมกำหนดน้ำหนักการจัดอันดับ — ทรัพยากรประมวลผลของผู้ร่วมสมทบ
> ควรเชื่อมโยงเส้นทางที่สร้างแล้วเข้ากับเส้นทางใหม่ บนคลังข้อมูลที่ดีพอ
> ที่จะรองรับน้ำหนักได้ สัญญาอนุญาตยังคงเป็น **เกต ไม่ใช่น้ำหนัก**: กฎเกณฑ์
> ด้านสัญญาอนุญาตและช่องทางการส่งต่อจะเป็นตัวตัดสินว่าสิ่งใดสามารถนำเข้าคิวได้บ้าง (§2
> และ `transmission_note` ของคิว); ในบรรดาคลังข้อมูลที่มีสิทธิ์
> การจัดอันดับจะไม่คำนึงถึงสัญญาอนุญาต ดังนั้นชุดข้อมูลการวิจัยที่ถูกจำกัดแต่มีการตรึงไว้ —
> ซึ่งมักเป็นคลังข้อมูลเพียงชุดเดียวของคู่ภาษา — จะไม่ถูกตัดโอกาสอย่างเป็นระบบ
> คิว v1 (novelty × uncertainty × promise เท่านั้น) ยังคงสามารถตีความได้
> ผ่านเมทาดาตาของตนเอง

ค่าของปัจจัยที่แน่นอนซึ่งใช้ในการสร้างจะส่งมอบใน
`metadata.map_value_parameters`; ข้อมูลนำเข้าด้านการเชื่อมต่อและคุณภาพ
สามารถคำนวณย้อนกลับได้จาก `mesh.json` ที่เผยแพร่ (เอดจ์ที่วัดผลแล้ว),
ความครอบคลุมร่วมของบริการที่แสดงในเมทาดาตา และ `registry.json`
(จำนวนรายการ + ความสมบูรณ์) นอกจากนี้ แต่ละรายการยังคงรักษาฟิลด์การวินิจฉัย
ecv-v3 ไว้อย่างครบถ้วนไม่ว่าจะอยู่ในโหมดใด ทำให้สามารถคำนวณลำดับการจัดอันดับใดๆ
ย้อนกลับได้จากอาร์ทิแฟกต์เดียวกัน

### 2.3 โหมดการจัดอันดับ `edv` — expected decision value (2026-08-27)

*สถานะ: นำไปใช้งานแล้ว ปิดใช้งานเป็นค่าเริ่มต้นจนกว่าจะมีการเปรียบเทียบเชิงวัดผลใน
§2.3.6 ค่าเริ่มต้นที่เผยแพร่ยังคงเป็น `map` จนกว่าจะถึงเวลานั้น*

คิวจะซื้อผลลัพธ์เพียงสองอย่างเท่านั้น: **แผนที่ขีดความสามารถ** (วิธีใด
เก่งด้านใด พร้อมความไม่แน่นอนที่ตรงไปตรงมา) และ **เมชการกำหนดเส้นทาง**
(คู่ภาษาที่วัดผลแล้วซึ่งนำมาต่อเชนเป็นเส้นทางได้) `edv` กำหนดราคาของแต่ละ
รายการที่เข้าเกณฑ์ตามระดับที่รายการนั้นพัฒนาผลลัพธ์ทั้งสอง ในรูปแบบพอร์ตโฟลิโอแบบถ่วงน้ำหนัก:

```
EDV(item) = [ w_judge·Ĵ + w_mesh·M̂ + w_survey·Ŝ ] × contamination ÷ max(cost, COST_FLOOR)
```

โดยมีค่าเริ่มต้น `w_judge = 0.35, w_mesh = 0.25, w_survey = 0.40`
(ผู้ก่อตั้งสามารถปรับเปลี่ยนได้; ทุกการสร้างจะระบุน้ำหนักที่ใช้จริงใน
`metadata.edv_parameters`) ปัจจัยการปนเปื้อน (§2.1 วิธีแก้ไขที่ 1) จะถูกนำไปใช้
เพียงครั้งเดียว ในฐานะตัวคูณภายนอก การอนุญาตให้ใช้สิทธิ์และการส่งต่อยังคงเป็น
**เกต ไม่ใช่น้ำหนัก** — คุณสมบัติจะถูกตัดสิน
ก่อนที่จะมีการคำนวณมูลค่าใดๆ และการจัดอันดับจะไม่คำนึงถึงสัญญาอนุญาตในบรรดา
คลังข้อมูลที่มีสิทธิ์

#### 2.3.1 Ĵ — มูลค่าการตัดสินวิธี (method-judgment value)

กำหนดราคาว่าการรันนี้ช่วยพัฒนา **การตัดสินเปรียบเทียบวิธีบนคลังข้อมูลเดียวกัน**
ได้มากเพียงใด — ซึ่งเป็นการอ้างสิทธิ์ข้ามวิธีเพียงอย่างเดียวที่งานวิจัย
การวัดผลของโครงการนี้อนุญาต (การศึกษาการถ่ายโอนความยาก W2
ปฏิเสธการเชื่อมโยงความสามารถข้ามภาษา; ผลลัพธ์เชิงบวกที่ได้รับอนุญาต —
การปรับปรุง additive method × corpus ภายในภาษาเดียวกัน — คือสิ่งที่
องค์ประกอบนี้นำมาใช้อย่างแท้จริง คะแนนจะถูกนำมาใช้สำหรับการจัดลำดับและการแยกความแตกต่าง
เท่านั้น ไม่เคยถูกแปลงเป็นความน่าจะเป็นของการยอมรับได้ ตามโครงการนำร่อง
การเทียบมาตรฐาน)

สำหรับรายการที่เข้าเกณฑ์ (คลังข้อมูล C, วิธี M, เงื่อนไข): **คู่เปรียบเทียบ (contrast
partners)** คือวิธี M′ ที่มีการรันที่เผยแพร่แล้วบน
(C, เงื่อนไขเดียวกัน) สำหรับแต่ละคู่เปรียบเทียบ เมื่อ `sep` คือระยะห่างของคะแนน
ในหน่วยจุด chrF ต่อค่าครึ่งความกว้างของ CI รวม (CI ที่บันทึกไว้; ใช้พร็อกซี `50/√n`
เมื่อไม่ได้เผยแพร่) และ `sep_pred` คือค่าเดียวกันที่คำนวณเทียบกับคะแนนที่ทำนายตาม §3.1:

| สถานะการเปรียบเทียบของ {M, M′} บนคู่ภาษา | เครดิต |
|---|---|
| **unmet** — ยังไม่มีคลังข้อมูลร่วมกัน | `JUDGE_FIRST = 1.0` |
| **contested** — มีคลังข้อมูลร่วมกัน ทั้งหมด `sep < Z_DEC` | `JUDGE_CONTESTED = 0.8 × clip(sep_pred / Z_DEC, 0, 1)` |
| **decided** — บางส่วน `sep ≥ Z_DEC`, คลังข้อมูล n_dec ตัดสินได้ | `JUDGE_DECIDED = 0.25 / (1 + n_dec)` |

แต่ละค่าจะคูณด้วย `w_top = 1/√(rank(M)·rank(M′))` — การตัดสิน
อันดับที่หนึ่งเทียบกับอันดับที่สองมีมูลค่ามากกว่าอันดับที่เจ็ดเทียบกับอันดับที่แปด การจัดอันดับ
วิธีต่อคู่ภาษาจะใช้การฟิตแบบ additive method × corpus ที่ได้รับอนุญาต
(alternating least squares บนเซลล์ที่สังเกตได้) เมื่อคู่ภาษานั้นมี ≥2
วิธี × ≥2 คลังข้อมูลที่วัดผลแล้ว มิฉะนั้นจะใช้คะแนนที่ดีที่สุดของแต่ละวิธี; การฟิตนี้
**เป็นแบบเฉพาะแต่ละคู่ภาษาอย่างเคร่งครัด ไม่มีการนำมารวมกันข้ามภาษา** `Z_DEC = 1.96`

การเปรียบเทียบระหว่าง coached และ naive บน (C, M) เดียวกัน จะเพิ่ม
`JUDGE_COND = 0.5 / (1 + n_cond)` การเปรียบเทียบของรายการจะถูกรวมเข้าด้วยกันโดยมี
ผลตอบแทนที่ลดลงเรื่อยๆ (`JUDGE_GAMMA = 0.7` ต่อการเปรียบเทียบที่เพิ่มขึ้น,
เรียงลำดับจากมากไปน้อย) บวกด้วย **seed term**
`JUDGE_SEED = 0.25 × min(1, m_C/3) × corpus-quality` (m_C = วิธีอื่นใน
ไลน์อัปที่มีรายการคิวบน C) ดังนั้นบอร์ดที่ว่างเปล่าจึงยังคงเลือก
คลังข้อมูลที่สามารถตัดสินการเปรียบเทียบในอนาคตได้ — มูลค่าของสถานที่จัด ไม่ใช่
คะแนนที่ยืมมา ในระหว่างการประกอบ องค์ประกอบการตัดสินจะลดทอนลง
`1/(1 + items already placed on the same pair and condition lane)`

#### 2.3.2 M̂ และ Ŝ

`M̂` คือผลได้ของเมชที่คาดหวัง (ΔΦ) ของ §3 ซึ่งไม่มีการเปลี่ยนแปลง โดยเมทริกซ์เชน
จะถูกตรึงไว้ ณ เวลาที่สร้าง `Ŝ` คือแกนหลักของ map-value v2 ใน §2.2 —
`uncertainty × promise × connectivity × corpus-quality` พร้อมการลดทอนของ
ความแปลกใหม่ตามตำแหน่ง (positional novelty decay) — ไม่มีการเปลี่ยนแปลง *ระดับ* ของคะแนนที่ทำนาย
(promise) จะอยู่ใน Ŝ เท่านั้น; Ĵ จะใช้เฉพาะ *ระยะห่าง* ของคะแนนเท่านั้น — องค์ประกอบ
ทั้งสองจึงไม่สามารถนับความคาดหวังในแง่ดีซ้ำซ้อนกันได้

#### 2.3.3 การแปลงให้เป็นมาตรฐาน (Normalization)

องค์ประกอบทั้งสามอยู่บนสเกลที่ไม่สามารถเปรียบเทียบกันได้โดยตรง ดังนั้นแต่ละ
องค์ประกอบสแตติกจะถูกหารด้วยเปอร์เซ็นไทล์ที่ 95 ขององค์ประกอบนั้นบนชุดรายการที่เข้าเกณฑ์
(จำกัดไว้ที่ `EDV_NORM_CAP = 4.0`); ตัวแปลงให้เป็นมาตรฐานทั้งสามจะส่งมอบใน
`metadata.edv_parameters.normalizers` ทำให้ทุกค่า EDV ที่เผยแพร่
สามารถคำนวณย้อนกลับได้จากอาร์ทิแฟกต์ของตนเอง

#### 2.3.4 การประกอบ (Assembly)

การจัดลำดับจะใช้การติดตามแบบ lazy-greedy ที่แน่นอนเช่นเดียวกับโหมด map: ตัวคูณ
ที่ขึ้นกับลำดับทุกตัว (survey novelty, การลดทอนการจัดวางของ judge) จะเป็นฟังก์ชัน
แบบโมโนโทนไม่เพิ่มขึ้น (monotone non-increasing) เมื่อมีการจัดวางรายการ ดังนั้นรายการในฮีปที่ไม่อัปเดต
จะมีแต่การประเมินค่าสูงเกินไปเท่านั้น — คุณสมบัติ lazy-greedy จึงยังคงอยู่และการติดตาม
จะเทียบเท่ากับการใช้วิธี brute-force greedy การสลับรายการแนวหน้า นโยบายการแสดงตัวอย่าง
และระดับงบประมาณยังคงมีผลโดยไม่มีการเปลี่ยนแปลง

#### 2.3.5 ความสามารถในการอธิบาย (Explainability)

ทุกรายการจะยังคงรักษาข้อมูลต่อไปนี้ไว้ในการวินิจฉัยของตน: รายการเปรียบเทียบที่ได้รับเครดิต
(คู่เปรียบเทียบ, สถานะ, ระยะห่างที่ทำนาย, น้ำหนักอันดับ), เทอม seed และการลดทอน,
ฟิลด์ทั้งหมดของ §2.2 และ §3, น้ำหนัก และตัวแปลงให้เป็นมาตรฐาน — ค่า EDV ที่เผยแพร่
จึงสามารถคำนวณใหม่ได้อย่างแม่นยำจากแถวนั้น "รายการนี้ได้อันดับนี้มาอย่างไร?"
สามารถตอบได้โดยไม่ต้องใช้สถานะภายนอกใดๆ

#### 2.3.6 เกณฑ์การนำมาใช้จริง (Adoption criterion)

`edv` จะกลายเป็นค่าเริ่มต้นที่เผยแพร่ได้ก็ต่อเมื่อผ่านการเปรียบเทียบเชิงวัดผล
กับ `map` และ `ecv` บนบอร์ดเดียวกันแล้วเท่านั้น: โดยต้องอยู่ภายใน 10% ของ map บนทุก
เมตริกการสำรวจ (เปอร์เซ็นไทล์ความลึกของการอ่านค่าครั้งแรก, คู่ภาษา/ภาษา/ตระกูลภาษา
ที่แตกต่างกัน ณ ระดับความลึก, อัตราคู่ภาษาใหม่ส่วนเพิ่ม), ดีกว่าอย่างเคร่งครัด
บนเมตริกการตัดสินทั้งสอง (การเปรียบเทียบที่แข่งขันกันได้รับการคลี่คลายต่อการจำลอง $1k; การกู้คืน
อันดับของวิธี ณ ระดับการใช้จ่ายคงที่) และการเติบโตของเมชต่อดอลลาร์
ต้องไม่ด้อยกว่า map รายงานการเปรียบเทียบจะได้รับการเผยแพร่
ควบคู่ไปกับการสลับเปลี่ยนโหมด

## 3. มูลค่าของการรันหนึ่งครั้ง

### 3.1 การคาดการณ์คะแนนก่อนรัน

คะแนนที่คาดหวังของ (pair, model, condition) ที่ยังไม่ได้รันคือผลรวมที่เรียบง่ายและตรวจสอบได้อย่างสมบูรณ์โดยเจตนา — การคาดการณ์ main-effects สองทางบวก optimism แบบมีโครงสร้าง โดยทุก term เผยแพร่บนรายการ:

```
ŝ = clip( pair_prior + model_offset + condition_offset + exploration_bonus,  0, S_CAP )
```

- **`pair_prior`** — hierarchical back-off เหนือความแข็งแกร่งที่เผยแพร่:
  ค่าเฉลี่ยบนคู่นี้ → ค่าเฉลี่ยบนภาษาเป้าหมายนี้ → ค่าเฉลี่ยบนภาษาต้นฉบับนี้ → ค่าเฉลี่ยทั่วโลก → `S0_FALLBACK` ระดับที่ใช้เผยแพร่เป็น `prior_basis`
- **`model_offset`** — model นี้ทำได้ดีแค่ไหนเมื่อเทียบกับ model *อื่น* บนคู่เดียวกัน เฉลี่ยบนทุกคู่ที่มีการเปรียบเทียบ ศูนย์สำหรับ model ที่ไม่เคยเห็น
- **`condition_offset`** — delta coached-minus-naive ที่สังเกตได้บนคู่เดียวกัน (ถอยกลับไปที่ภาษาเป้าหมายเดียวกัน) และ **ศูนย์ในกรณีอื่น**: ผลกำไรจากการ coaching เป็นจริงเมื่อวัดแล้วแต่ไม่ถือว่าถ่ายโอนข้ามภาษา ดังนั้นบนคู่ที่ไม่มีหลักฐาน แบบแผน baseline-first จะใช้
- **`exploration_bonus`** — optimism ในสภาวะที่ไม่แน่นอน พร้อม UCB1 schedule (Auer, Cesa-Bianchi & Fischer 2002):
  `κ·sqrt(2·ln(1+N)/(1+n))` โดยที่ N คือจำนวนรวมของการรันที่ให้คะแนนที่เผยแพร่ และ n คือจำนวนบน (pair, model) นี้ เซลล์ที่ไม่เคยลองจะได้รับ bonus ที่ใหญ่ที่สุด; เซลล์ที่วัดดีแล้วจะลดลงสู่ศูนย์
  เราใช้ schedule — รูปร่างที่ทำให้ arm ที่สำรวจน้อยกลับมาในอัตราที่เหมาะสม — ไม่ใช่ทฤษฎีบท regret ซึ่งสมมติ bandit แบบ stationary ที่ระบบนี้ไม่ใช่

### 3.2 mesh gain ในรูปแบบปิด

การรันสามารถปรับปรุง mesh ได้โดยการยก edge ของคู่ขึ้นสู่
`s' = max(s(e), ŝ)` เท่านั้น สำหรับการเปลี่ยนแปลง edge เดียว best chain ใหม่ระหว่างสองภาษาใดก็ตามจะเพิกเฉยต่อ edge ใหม่หรือใช้มันครั้งเดียวพอดี ดังนั้น matrix ที่อัปเกรดแล้ว — และด้วยเหตุนี้ ΔΦ — จึงมีรูปแบบบรรทัดเดียวที่แม่นยำ (ไม่ต้องแก้กราฟทั้งหมดใหม่):

```
Q'(u,v) = max( Q(u,v),  E(u,a)·s'·E(b,v),  E(u,b)·s'·E(a,v) )

E(x,y) = λ·Q(x,y) for x ≠ y;  E(x,x) = 1        (edge e = {a, b})

ΔΦ = mean over ordered pairs of (Q'(u,v) − Q(u,v))
```

E คือ "best chain ไปยัง endpoint ของ edge ใหม่ โดยจ่าย junction เพื่อต่อเข้ากับมัน"; สองเทอมคือสองทิศทางของการข้าม edge นี้ สิ่งนี้ทดสอบใน harness suite เทียบกับการคำนวณ Φ แบบ brute-force

การคาดการณ์ที่ไม่สามารถเอาชนะความแข็งแกร่งของ edge ปัจจุบันได้จะให้ ΔΦ = 0: สูตรใช้เงินของผู้บริจาคเพื่อยืนยันสิ่งที่ไม่รู้ ไม่ใช่วัดซ้ำสิ่งที่พิสูจน์แล้ว (exploration bonus ป้องกันไม่ให้เซลล์ที่อ่อนแอหรือ sample น้อยถูกอดอาหารตลอดไป)

### 3.3 สิ่งที่นับเป็นหลักฐานเทียบกับสิ่งที่สามารถ queue ได้

สองเกณฑ์ที่แตกต่างกัน โดยเจตนาไม่สมมาตร:

- **หลักฐาน** มาจากการรันที่เผยแพร่และไม่ถูกตัดสิทธิ์ *ทุกครั้ง* —
  รวมถึงการรันบนคอร์ปัสที่ไม่สามารถ queue ได้สาธารณะ (เช่น ชุดที่มีใบอนุญาตไม่เชิงพาณิชย์) การวัดคู่ที่เผยแพร่คือความรู้ ไม่ว่าคุณจะรันซ้ำได้หรือไม่
- **Actions** (รายการคิว) มาจากคอร์ปัสที่รันได้อย่างเปิดเผยเท่านั้น:
  development split, ใบอนุญาตตระกูล CC-BY, ดึงข้อมูลได้โดยทุกคน

ภาษาที่เข้าถึงได้เฉพาะผ่านคอร์ปัสที่ queue ไม่ได้ยังคงอยู่ในกราฟ: การปรับปรุง edge *รอบๆ* พวกมันเปลี่ยนค่า chain ของพวกมัน และสูตรคำนึงถึงสิ่งนี้

## 4. พารามิเตอร์

| พารามิเตอร์ | ค่าเริ่มต้น | ความหมายและเหตุผล |
|---|---|---|
| `λ` (`lambda_junction_discount`) | **0.9** | การรักษา fidelity ต่อ junction ของ chain ที่ *ประมาณการ* เข้ารหัส "การวัดตรงดีกว่าการเชื่อมต่อแบบ product-equal" (Utiyama & Isahara 2007; Wu & Wang 2007; Fan et al. 2021) การลดราคา ~10% คือตัวเลือกการปรับเทียบ ทบทวนเมื่อสามเหลี่ยมที่วัดแล้วสะสม (§6) |
| `κ` (`kappa_exploration_scale`) | **0.05** | ขนาด exploration bonus ในหน่วยความแข็งแกร่ง 0.05 ≡ 5 chrF++ points — ระดับ noise ที่ต่ำกว่านั้นความแตกต่างของคะแนนไม่สามารถแยกแยะได้บนคอร์ปัสที่มีน้อยกว่า 100 entry ([Corpus Design §6.3](/docs/network/specifications/corpus-design)) Optimism ถูกจำกัดที่ความละเอียดของเครื่องมือ |

| `S0_FALLBACK` | **0.5** | Prior ของคู่เป็นทางเลือกสุดท้าย ใช้เฉพาะเมื่อไม่มีผลลัพธ์ที่เผยแพร่เลย (ค่าเฉลี่ยทั่วโลกที่สังเกตได้ — ≈ 0.54 จากการรัน 429 ครั้งแรก — เป็นที่นิยมเมื่อมีผลลัพธ์ใดๆ อยู่) |
| `COST_FLOOR` | **$0.01** | ระดับพื้นสำหรับตัวหาร ECV เพื่อให้การรันที่แทบไม่มีค่าใช้จ่ายไม่สามารถอ้างสิทธิ์มูลค่าต่อดอลลาร์ที่ไม่มีขอบเขต |
| `N_FULL` | **100** | Evaluated entries สำหรับเครดิตขนาดเต็ม (§1.5) |
| `L_HEALTHY` | **5.0** | Effective words สำหรับเครดิต richness เต็ม (§1.5) |
| `H_NOISE` | **±5 chrF** | ครึ่งความกว้าง CI สำหรับเครดิตความเชื่อมั่นเต็ม; CI ที่ขาดหายไป proxy เป็น 50/√n (ยึดที่ ±5 ที่ n=100) |
| `RUNS_FULL` | **2** | การรันที่เผยแพร่สำหรับเครดิต replication เต็ม |

**การกำหนดเวอร์ชัน.** การเปลี่ยนแปลงพารามิเตอร์หรือสูตรจะเพิ่ม `formula_version`
(metadata) และบรรทัดเวอร์ชันของหน้านี้ คิวจะสะท้อนค่าที่ใช้จริงเสมอภายใต้ `metadata.priority_parameters` รวมถึง Φ ปัจจุบัน เพื่อให้คิวในอดีตยังคงตีความได้ การรัน sensitivity อยู่ห่างเพียง flag เดียว: `generate_sweep_queue.py --lam 0.8 --kappa 0.1`

การสร้างจากการรันที่ให้คะแนน 424 ครั้ง, 59 edge ที่วัดแล้ว, 60 ภาษา;
**Φ = 0.272** รายการอันดับต้น:

```
eng>fao · claude-haiku-4.5 · naive
  edge_strength        0.0      (no published eng→fao runs)
  pair_prior           0.613    basis: target-language (Faroese runs exist via dan→fao)
  model_offset        −0.114    (haiku trails other models on shared pairs)
  condition_offset     0.0      (no coaching evidence for fao)
  exploration_bonus   +0.174    (never-run cell: κ·√(2·ln 425 / 1))
  predicted_strength   0.673
  expected_mesh_gain   0.0181   (eng→fao is a near-component join)
  est_cost_usd         0.0101
  ecv_per_usd          1.79     ← rank #1
```

อ่านย้อนกลับ: ภาษา Faroese เชื่อมต่อกับ mesh เฉพาะผ่านภาษาเดนมาร์ก ดังนั้น edge eng→fao ที่วัดแล้วจึงตัดทางผ่านตระกูล chain ขนาดใหญ่ (ΔΦ ขนาดใหญ่); model คาดการณ์ว่าอยู่กลางๆ บนคู่แบบนี้ (prior + offset) ไม่มีใครเคยลองเซลล์นี้ (bonus ขนาดใหญ่) และการรันมีค่าใช้จ่ายหนึ่งเซนต์ ไม่มีสิ่งอื่นใดในคิวที่ซื้อ mesh ต่อดอลลาร์ได้มากกว่า
การคำนวณเดียวกัน พร้อม input ทุกตัวที่เผยแพร่ ให้ผลทุกอันดับอื่น

## 6. ข้อจำกัดที่ทราบ (และสิ่งที่จะแก้ไขได้)

1. **chrF++ ไม่สามารถเปรียบเทียบได้ข้ามภาษา.** สัณฐานวิทยาเลื่อนระดับ; edge 0.5 เข้าสู่ภาษา Basque ไม่ใช่ความสำเร็จเดียวกับเข้าสู่ภาษาดัตช์ การบรรเทา: ลำดับความสำคัญถูกครอบงำโดย *โครงสร้าง* (การเปลี่ยนผ่าน s = 0 → s > 0) ที่ผลกระทบของระดับเป็นลำดับที่สอง การแก้ไข: การ normalize คะแนนต่อภาษา หรือ metric ที่มีการปรับเทียบข้ามภาษาที่ดีกว่าเมื่อมีให้สำหรับภาษาเหล่านี้
2. **chain model แบบ product-λ คือ prior ไม่ใช่การวัด.** มีการสนับสนุนในทิศทางจากวรรณกรรม pivot แต่ไม่ได้ปรับเทียบสำหรับการแปล LLM การแก้ไข (วางแผนไว้): mesh ขณะนี้มีสามเหลี่ยมที่วัดแล้ว (เช่น deu→fra ตรงควบคู่กับ deu→eng→fra) ดังนั้นผลลัพธ์ที่เชื่อมต่อสามารถให้คะแนนได้โดยตรงและ λ fit กับข้อมูลแทนที่จะเลือก
3. **การปนเปื้อนและสถานะ dev-set.** ความแข็งแกร่งของ edge รับข้อแม้ทุกอย่างของ development set สาธารณะ — ถือว่า Φ เป็นสัญญาณการวางแผนขอบบน ไม่ใช่การอ้างสิทธิ์ความสามารถ
   ([Corpus Design](/docs/network/specifications/corpus-design))
4. **ความตาบอดด้าน domain.** Edge ที่วัดบนข้อความสนทนาถือเป็นตัวเลขเดียว; chain ที่ข้าม domain จะเสื่อมลงมากกว่าที่ λ คาดการณ์
5. **ทิศทาง.** Edge ขณะนี้ไม่มีทิศทาง (หลักฐาน X→Y จุด X↔Y) เมื่อการประกอบ chain กลายเป็นไวต่อทิศทางในทางปฏิบัติ ความแข็งแกร่งจะแยกตามทิศทาง — สูตรไม่เปลี่ยน กราฟเพียงแค่เพิ่มเป็นสองเท่า
