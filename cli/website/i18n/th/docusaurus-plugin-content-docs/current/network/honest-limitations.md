# ข้อจำกัดทางเทคนิค

> **เพิ่งเคยมาที่นี่ใช่ไหม?** [สิ่งที่ระบบยังทำไม่ได้ในตอนนี้](/docs/what-it-cant-do-yet) อธิบายเรื่องเดียวกันนี้ด้วยถ้อยคำที่เข้าใจง่าย หน้านี้เป็นฉบับที่มีความแม่นยำทางเทคนิค สำหรับนักพัฒนา นักวิจัย และเอเจนต์

นี่คือข้ออ้างสิทธิ์ที่เราจะ**ไม่**กล่าวเกินจริง หากมีสิ่งใดในส่วนอื่นของเว็บไซต์นี้ที่สื่อถึงความสามารถเกินกว่าที่ระบุไว้ที่นี่ โปรดถือว่าเป็นข้อผิดพลาดและ[แจ้งให้เราทราบ](/docs/network/perspectives/reporting-errors-and-owning-corrections)

โครงสร้างพื้นฐานสำหรับการประเมินจะได้รับความไว้วางใจก็ต่อเมื่อมีความซื่อสัตย์เกี่ยวกับขอบเขตของตนเอง
ต่อไปนี้คือข้อจำกัดของเรา ระบุไว้อย่างชัดเจนพอที่จะตรวจสอบได้

## 1. การตรวจสอบความถูกต้องทางสัณฐานวิทยาเชิงลึกขึ้นอยู่กับทั้ง FST *และ* ชุดทดสอบที่จัดอันดับได้

การตรวจสอบความถูกต้องทางสัณฐานวิทยาโดยใช้ FST — ซึ่งเป็นการตรวจสอบว่าทุกคำที่เป็นผลลัพธ์เป็นคำที่สร้างขึ้นอย่างถูกต้องตามหลักภาษาในภาษาเป้าหมาย — จำเป็นต้องมีสองสิ่งสำหรับคู่ภาษาหนึ่งๆ: FST ที่ harness ได้ล็อกเวอร์ชัน (pinned) ไว้ และชุดการประเมินผลสำหรับคู่ภาษานั้นที่สามารถจัดอันดับได้ ตัว `GiellaLTFSTMetric` เองนั้นเป็นแบบ**ทั่วไป (generic)**: โดยจะให้คะแนนภาษาใดก็ได้ที่มี FST ของ GiellaLT ที่ถูกพินไว้ (ภาษาครีพื้นราบ (Plains Cree), กลุ่มภาษาซามิ, ภาษาฟินแลนด์, ภาษานอร์เวย์แบบบุ๊กมอล, ภาษาอินุกติตุต และอื่นๆ) หลายภาษาเหล่านั้นมีชุดการประเมินผลแบบเปิด (Tatoeba, WMT, WMT24++) — [หน้ารายการชุดข้อมูล](/docs/network/leaderboard/datasets) แสดงรายการแคตตาล็อก, `mt-eval corpora --source eng --target <code>` แสดงรายการสิ่งที่สามารถรันได้สำหรับคู่ภาษา และ `mt-eval corpora --with-fst` จะแสดงเฉพาะคู่ภาษาที่ภาษาเป้าหมายมี FST ที่พินไว้ พร้อมทั้งระบุว่าได้ติดตั้งไว้บนเครื่องของคุณหรือไม่
ภาษาครีพื้นราบ (Plains Cree) ซึ่งเป็นภาษาที่เป็นจุดเริ่มต้นของงาน FST นี้ ถือเป็นข้อยกเว้น: ชุดการประเมินผลทั้งสองชุดของภาษานี้ (EdTeKLA) ถูกจัดแคตตาล็อกไว้เป็นป้ายกำกับที่ถูกกักกัน (quarantined labels) และฐานข้อมูลจะปฏิเสธคะแนนใดๆ ก็ตามที่ส่งเข้ามาเทียบกับชุดข้อมูลเหล่านี้

ยังมีข้อจำกัดเพิ่มเติมอีกสองประการ ในกรณีที่ FST ที่พินไว้เป็นเพียง **acceptor** สำหรับการตรวจตัวสะกดเท่านั้น (ภาษาซามิเหนือ, ภาษาอัมฮาริก, ภาษาบาสก์) ตัว FST จะบอกได้เพียงว่าคำนั้นมีอยู่หรือไม่ แต่ไม่ได้บอกว่ามีการผันรูปอย่างถูกต้องหรือไม่ ดังนั้นจึงไม่มีการคำนวณ `morphological_accuracy` — และ acceptor ยังยอมรับคำภาษาอังกฤษบางคำรวมถึงคำที่ขึ้นต้นด้วยตัวพิมพ์ใหญ่ ทำให้การยอมรับของ FST สามารถให้คะแนนกับผลลัพธ์ที่ไม่ได้แปลได้ (run card จะแสดงข้อควรระวังเรื่องการคัดลอกข้อความต้นฉบับ ดูที่ [ข้อควรระวังเกี่ยวกับคะแนน](/docs/network/specifications/scoring#2-8-score-caveats)) การยอมรับของ FST เป็นเพียงการวินิจฉัย: จะไม่ถูกรวมเข้ากับคะแนนหลักอย่าง chrF++ หรือนำมาใช้จัดอันดับการรัน
นอกจากนี้ ยังให้คะแนนกับประโยคที่ถูกต้องเพียงประโยคเดียวที่ถูกแสดงซ้ำสำหรับทุกๆ อินพุตด้วย โดย run card จะแสดงข้อควรระวังเกี่ยวกับผลลัพธ์ที่แทบจะคงที่ (near-constant-output caveat)
และทุกคู่ภาษาที่ไม่มี FST จะได้รับการให้คะแนนด้วยเมตริกระดับพื้นผิว (chrF++, BLEU) และการตรวจสอบพฤติกรรม แม้สิ่งเหล่านี้จะเป็นสัญญาณที่มีประโยชน์ แต่ก็**ไม่ได้**รับประกันความถูกต้องทางสัณฐานวิทยา เราไม่อ้างสิทธิ์การตรวจสอบความถูกต้องทางสัณฐานวิทยาสำหรับภาษาใดก็ตามที่ไม่มีทั้ง FST และชุดการประเมินผลที่สามารถจัดอันดับได้

## 2. ระดับความน่าเชื่อถือ: ทุกแถวยังเป็นการรายงานผลด้วยตนเองในปัจจุบัน {#2-trust-tiers-are-self-reported-at-launch}

คะแนนส่วนใหญ่คำนวณโดยผู้ร่วมพัฒนาที่รันชุดประเมิน (harness) ด้วยตนเองและเผยแพร่ผลลัพธ์ **การตรวจสอบยืนยัน (Verification)** — การประเมินคะแนนการส่งผลงานซ้ำจากผลลัพธ์ของผลงานเองเทียบกับคลังข้อมูลมาตรฐานที่ตรึงด้วย SHA — ถูกสร้างขึ้นแล้ว แต่เป็นคำสั่งสำหรับผู้ดูแลที่ต้องรันด้วยตนเอง: ไม่มีระบบใดรันโดยอัตโนมัติเมื่อมีการส่งผลงาน และไม่มีการตั้งเวลาทำงานล่วงหน้า ดังนั้นในปัจจุบัน ทุกแถวจึงเข้ามาและคงอยู่ในฐานะการวัดผลด้วยตนเอง ([กฎเกณฑ์การส่งผลงาน](/docs/network/leaderboard/rules#verification-tiers)) โปรดอ่านป้ายแสดงความน่าเชื่อถือในแต่ละแถว: **"รายงานด้วยตนเอง (self-reported)" มีความหมายตรงตามนั้นทุกประการ** และเป็นค่าเริ่มต้น

## 3. การตรวจสอบโดยผู้พูดในชุมชนยังไม่เกิดขึ้น

รางวัลที่เสนอไว้กำหนดให้ต้องได้**การยอมรับ ≥ 70% จากผู้พูดสองภาษา** (ยังไม่มีการเปิดชิงรางวัล) เกณฑ์คัดกรองดังกล่าวถูกระบุไว้แล้ว และเครื่องมือสำหรับดำเนินการกำลังอยู่ระหว่างการสร้าง — ทว่า**ยังไม่มีการดำเนินการตรวจสอบโดยผู้พูดในชุมชน** และ**ยังไม่มีคะแนนใดบนไซต์นี้ที่ผ่านเกณฑ์คัดกรองโดยผู้พูด** chrF++ และตัวเลขอัตโนมัติอื่นๆ ทั้งหมดเป็นเพียงสัญญาณจากเครื่องจักร ไม่ใช่คำตัดสินของชุมชน ซึ่งเป็นเหตุผลว่าทำไมจึงไม่มีคะแนนใดในที่นี้ที่มีป้ายกำกับคุณภาพ

## 4. แซนด์บ็อกซ์การประเมินผลและพิธีการจัดการคีย์มีอยู่จริง แต่ยังไม่มีผู้ดูแลคนใดใช้งาน

เราดึงคลังข้อมูลจากแหล่งต้นทางและตรึงด้วย SHA และส่วนแบ่งชุดข้อมูลทดสอบที่เก็บแยกไว้ (held-out splits) จะถูกปิดผนึก เมื่อชุมชนถือชุดทดสอบที่เป็นความลับไว้ วิธีการประเมินสามารถให้คะแนนเทียบกับชุดข้อมูลนั้นได้โดยที่ชุดข้อมูลไม่เคยหลุดออกจากมือของพวกเขา — และการประเมินดังกล่าวในขณะนี้มี **สองช่องทาง** ช่องทางที่แนะนำสำหรับโมเดลนิวรัลมาตรฐานคือแบบ **declarative**: ผู้เข้าร่วมจะส่งเฉพาะข้อมูลเท่านั้น — ค่าน้ำหนัก safetensors + tokenizer แบบ declarative + ไฟล์คอนฟิก — และผู้จัดจะรันข้อมูลดังกล่าวในเอนจินการอนุมาน (inference engine) ที่เชื่อถือได้ของตนเอง (`trust_remote_code=False`, แบบออฟไลน์; ยืดหยุ่นเรื่องสถาปัตยกรรมเนื่องจากความปลอดภัยขึ้นอยู่กับรูปแบบที่ปลอดโค้ด ไม่ใช่ชื่อสถาปัตยกรรม) ไม่มีการรันโค้ดของผู้เข้าร่วมเลยแม้แต่น้อย จึงไม่มีสิ่งใดที่ต้องนำไปใส่แซนด์บ็อกซ์ (sandbox); การตรวจสอบความปลอดภัยคือการตรวจความถูกต้องของรูปแบบที่สามารถตัดสินผลได้ชัดเจน (นี่คือ safetensors ไม่ใช่ pickle ใช่หรือไม่? ไม่มี `trust_remote_code` ใช่หรือไม่?) ไม่ใช่ความพยายามที่จะพิสูจน์ว่าโค้ดใดๆ มีความปลอดภัย สำหรับวิธีการที่เป็นโค้ดอย่างแท้จริง (ไปป์ไลน์, ระบบไฮบริดที่ใช้ LLM ช่วยชี้แนะ) ทางเลือกสำรองคือ **แซนด์บ็อกซ์** ที่แยกออกจากเครือข่าย (การตรวจสอบแบบคงที่, คอนเทนเนอร์ `--network=none`, การส่งข้อมูลออกเฉพาะคะแนนเท่านั้น, การส่งไฟล์แบบแอร์แกปแท้จริงที่เลือกได้) เนื่องจากแซนด์บ็อกซ์ไม่มีการเชื่อมต่อเครือข่าย วิธีการต่างๆ จึงจะรันที่นั่นได้ก็ต่อเมื่อมีโมเดลทั้งหมดที่เรียกใช้อยู่ภายในบันเดิลของตนเอง: ระบบไฮบริดที่ใช้ LLM ชี้แนะจะต้องแนบ LLM ของตนมาเป็น open weights เนื่องจากไม่สามารถเข้าถึง API ของโฮสต์ LLM ได้ แซนด์บ็อกซ์รองรับโค้ดที่ไม่น่าเชื่อถือแทนที่จะปฏิเสธไม่รัน จึงเป็นช่องทางที่ยอมรับตามตรงว่ารัดกุมน้อยกว่า — หลักประกันหลักที่แบกรับภาระคือ `--network=none` (การสแกนแบบสถิตตามหลักฮิวริสติกไม่สามารถตรวจสอบโมเดลแบบไบนารีได้) และการเสริมความแข็งแกร่งในระดับที่ลึกกว่า (seccomp, microVMs) ถูกชะลอไว้ก่อน ดู [จัดการแข่งขันแบบอธิปไตย](/docs/network/sovereignty/run-a-sovereign-contest) สำหรับรายละเอียดที่แน่ชัดว่าอะไรที่ใช้งานได้จริงแล้วและอะไรที่ยังไม่พร้อม **พิธีการจัดการกุญแจ (key ceremony)** ของโหนดออฟไลน์นั้นถูกสร้างขึ้นแล้ว — กุญแจของชุดข้อมูลถูกแบ่งเป็นแบบ M-of-N และประกอบกลับคืนเฉพาะในหน่วยความจำระหว่างการรันที่ได้รับอนุญาตตามองค์ประชุมเท่านั้น — แต่ยังไม่เคยถูกนำไปใช้กับผู้ดูแลจริง และส่วนแบ่งกุญแจยังคงเป็นไฟล์ธรรมดาในเวอร์ชันแรกนี้ สิ่งที่**ยังไม่ได้**สร้าง: การลงนามแบบกำหนดเกณฑ์ขั้นต่ำ (threshold signing) (คะแนนจะได้รับการลงนามโดยกุญแจโหนดเดียว) และการรับรองความถูกต้องด้วยฮาร์ดแวร์ (hardware attestation) (ไฟล์กำกับคะแนนลงนามด้วยซอฟต์แวร์เท่านั้น) ยังไม่มีการแต่งตั้งผู้ดูแลกุญแจของชุมชน ดังนั้นการประเมินเพื่อชิง**รางวัล**ระดับมาตรฐานระดับทองจึงยังคงปิดอยู่ จนกว่าจะมีผู้ดูแลและความยินยอมจากชุมชนอย่างเป็นทางการ

## 5. กุญแจยังคงถือโดยผู้จัดในปัจจุบัน ยังไม่มีการแต่งตั้งผู้ดูแลชุมชน {#5-key-custody-is-designed-no-custodians-are-appointed-yet}

**ในปัจจุบัน กุญแจของชุดข้อมูลที่ปิดผนึกไว้จะถูกถือไว้โดยผู้จัด** — ไม่ว่าใครก็ตามที่เป็นผู้ปิดผนึก บนเครื่องของพวกเขาเอง **Champollion ไม่ได้ถือส่วนแบ่งกุญแจใดๆ** *กลไก*การดูแลรักษาสำหรับผู้ถือมากกว่าหนึ่งรายถูกสร้างขึ้นแล้ว: พิธีการจัดการกุญแจแบบ M-of-N ของโหนดออฟไลน์จะแบ่งกุญแจของชุดข้อมูลระหว่างผู้ดูแล แต่ยังไม่ได้มีการรันร่วมกับผู้ดูแลจริง ผู้ดูแลจะได้รับการคัดเลือกโดยชุมชนเอง และในขณะนี้ยังไม่มีผู้ใดได้รับการแต่งตั้ง: **ผู้ดูแลกุญแจของชุมชน — ยังไม่มีการแต่งตั้งแต่อย่างใด** การดูแลรักษากุญแจไม่ใช่ความยินยอม: กระบวนการสร้างความสัมพันธ์เพื่อขอความยินยอมจากชุมชนเป็นแนวทางเฉพาะของตนเอง ที่ดำเนินไปช้ากว่าและมีความสำคัญมากกว่า

## 6. เราวัดผลวิธีการต่างๆ บนเกณฑ์มาตรฐาน เราไม่ได้ให้คะแนนการแปลแต่ละประโยค {#system-vs-output}

มีสองสิ่งที่แตกต่างกันซึ่งถูกเรียกว่า "การแปลด้วยเครื่องที่เชื่อถือได้" เราทำเพียงอย่างใดอย่างหนึ่งในนั้น

**ระดับระบบ — สิ่งที่เราทำ** กำหนดคู่ภาษา ชุดทดสอบ และวิธีการหนึ่งๆ: วิธีการนั้นได้คะแนนเท่าใด ภายใต้เมตริกใด ในโดเมนใด ในช่องทางการปนเปื้อนใด และที่ระดับความไว้วางใจใด? นั่นคือข้อความยืนยันเกี่ยวกับ *วิธีการบนเกณฑ์มาตรฐาน* รวมทั้งข้อความยืนยันว่าใครเป็นผู้กำหนดเกณฑ์ กฎการให้คะแนนได้รับการเผยแพร่ คลังข้อมูลได้รับการพิน และสำหรับเกณฑ์มาตรฐานที่มีอธิปไตย ชุมชนที่เป็นเจ้าของชุดทดสอบจะเป็นผู้ตัดสินว่าสิ่งใดผ่าน ตารางผู้นำ แผนที่ run card และ `mt-eval` ทั้งหมดนี้ล้วนเป็นสิ่งนี้ และเป็นเพียงสิ่งนี้เท่านั้น

**ระดับผลลัพธ์ — สิ่งที่เราไม่ได้ทำ** กำหนดประโยคต้นฉบับหนึ่งประโยคและคำแปลของประโยคนั้นหนึ่งคำแปล: มีโอกาสมากน้อยเพียงใดที่คำแปล*นั้น*จะถูกต้อง? ใน MT และ NLP สิ่งนั้นคือการประมาณคุณภาพ (quality estimation) และการวัดปริมาณความไม่แน่นอน (uncertainty quantification) ซึ่งเป็นสาขาการวิจัยเฉพาะทางของตนเอง เรา**ไม่เผยแพร่ค่าความเชื่อมั่นต่อเซกเมนต์สำหรับการแปลใดๆ** และไม่มีสิ่งใดในที่นี้ที่เป็นความน่าจะเป็นที่ปรับเทียบแล้วว่าผลลัพธ์ที่ระบุจะถูกต้อง แถวที่มีคะแนนสูงไม่ใช่การรับประกันสำหรับประโยคถัดไปที่วิธีการนั้นจะสร้างขึ้น

ในทางกลับกันก็เป็นข้อผิดพลาดที่เกิดขึ้นได้ง่ายกว่า และมีผลผูกพันกับเราเช่นกัน เมื่อส่วนต่อประสานใดในที่นี้ระบุว่าไม่มีวิธีการใดในคู่ภาษาหนึ่งที่ได้คะแนนดีพอที่จะนำไปใช้งานจริง — ดังเช่นที่ [บริการแปลโดยมนุษย์](/human-services) ระบุไว้ — นั่นคือข้อความยืนยันเกี่ยวกับวิธีการที่ถูกวัดผลบนชุดทดสอบที่ถูกวัดผล ซึ่งเป็นเหตุผลที่ดีที่จะไม่ส่งมอบผลลัพธ์จากเครื่องสำหรับคู่ภาษานั้น แต่นั่นไม่ใช่คำตัดสินสำหรับประโยคใดประโยคหนึ่งโดยเฉพาะ

**การประมาณคุณภาพเป็นช่องว่างที่เปิดรับไว้ ไม่ใช่ช่องโหว่ที่ซ่อนอยู่** ตัว harness มีการคำนวณคะแนนทางนิวรัลแบบไม่อิงข้อความอ้างอิงอยู่แล้วหนึ่งคะแนน นั่นคือ AfriCOMET-QE (`qe_score`) เพื่อใช้เป็นสัญญาณความเพียงพอสำหรับการรันที่ไม่มีชุดข้อมูลอ้างอิงมาตรฐานทองคำ ค่านี้จะถูกรายงานเป็นตัวเลข**ระดับคลังข้อมูล**ในช่องทางนิวรัลที่แยกต่างหาก ได้รับการคำนวณซ้ำโดย verifier และไม่เคยถูกรวมเข้ากับคะแนนหลักอย่าง chrF++ ([ข้อกำหนดการให้คะแนน](/docs/network/specifications/scoring#how-runs-are-scored)) เมตริกต่างๆ เป็นปลั๊กอิน ([ข้อกำหนดปลั๊กอิน](/docs/reference/plugin-spec)) ดังนั้นเมตริก QE ระดับเซกเมนต์จึงเป็นสิ่งที่ harness นี้สามารถรองรับได้ จนกว่าเมตริกดังกล่าวจะได้รับการเชื่อมต่อ เผยแพร่ และประเมินอภิมาน (meta-evaluated) ต่อภาษาในลักษณะเดียวกับเมตริกที่อิงตามข้อความอ้างอิง ([ความน่าเชื่อถือของเมตริก](/docs/network/specifications/metric-reliability)) เราจะไม่ระบุสิ่งใดเกี่ยวกับผลลัพธ์แต่ละรายการ
