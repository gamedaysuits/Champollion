# การขับเคลื่อน Rails ผ่าน MCP

โปรไฟล์เริ่มต้นของเซิร์ฟเวอร์ MCP คือ rails: เครื่องมือหกตัวที่จะนำทางโครงการภาษาหนึ่งโครงการตั้งแต่โฟลเดอร์ว่างเปล่าไปจนถึงโมเดลที่ผ่านการวัดผลแล้วบนคอมพิวเตอร์ของผู้ใช้เอง เครื่องมือแต่ละตัวจะรัน `champollion` CLI เป็นโพรเซสแยกต่างหากที่มีขอบเขตชัดเจน — ซึ่งเป็นคำสั่งเดียวกันกับที่ผู้ใช้พิมพ์ นอกจากนี้เซิร์ฟเวอร์ยังส่งคำแนะนำการใช้งานสั้นๆ (`instructions-rails.md`) ให้แก่ไคลเอนต์ของคุณ ณ เวลาที่เชื่อมต่อ

## การเชื่อมต่อ

เซิร์ฟเวอร์สื่อสารผ่าน MCP ทาง stdio และต้องใช้ Node.js 20.11 ขึ้นไป การกำหนดค่าที่ไคลเอนต์ที่ใช้การกำหนดค่าด้วยไฟล์ทุกตัวรองรับ:

```json
{
  "mcpServers": {
    "champollion": { "command": "npx", "args": ["-y", "champollion-mcp-server"] }
  }
}
```

| ไคลเอนต์ | ตำแหน่งที่ใส่ |
|---|---|
| Claude desktop | Settings → Developer → Edit Config ใส่รายการ บันทึก แล้วรีสตาร์ทแอป |
| Claude Code | `claude mcp add champollion -- npx -y champollion-mcp-server` |
| Cursor | `mcp.json` ในโฟลเดอร์ `.cursor` ของโครงการ หรือใน `.cursor` ในโฮมโฟลเดอร์ |

ไคลเอนต์อื่นๆ ที่สามารถเริ่มเซิร์ฟเวอร์ stdio ภายในเครื่องได้จะใช้คำสั่งเดียวกัน หน้านี้จะอธิบายเฉพาะสามตัวข้างต้นเท่านั้น

**พาธของเครื่องมือ** เซิร์ฟเวอร์จะค้นหา CLI ที่ต้องพึ่งพาโดยอัตโนมัติ โดยจะค้นหา `nmt-forge` บน `PATH` จากนั้นใน `UV_TOOL_BIN_DIR` (ค่าเริ่มต้นคือ `~/.local/bin` ซึ่งเป็นตำแหน่งที่ `uv tool install` วางไว้) — ไคลเอนต์ที่เปิดจากแอปเดสก์ท็อปมักจะมี `PATH` สั้นกว่าเทอร์มินัล การกำหนดค่าทับ ให้ระบุเป็นตัวแปรสภาพแวดล้อมใน `env` ของรายการเซิร์ฟเวอร์:

| ตัวแปร | ผลลัพธ์ |
|---|---|
| `CHAMPOLLION_MCP_PROFILE` | `rails` (ค่าเริ่มต้น) หรือ `full` |
| `CHAMPOLLION_CLI_BIN` | จุดเริ่มต้น (entry point) ของ `champollion` CLI ที่จะรันแทนตัวที่แถมมา |
| `NMT_FORGE_BIN` | เอ็กซีคิวเทเบิล `nmt-forge` (ขั้นตอน journey ของ CLI จะใช้ตัวแปรเดียวกันนี้) |
| `UV_TOOL_BIN_DIR` | ตำแหน่งที่จะค้นหา `nmt-forge` และ `uv` หลังจาก `PATH` |

## โปรไฟล์

| โปรไฟล์ | เลือกด้วย | คืออะไร |
|---|---|---|
| rails | ค่าเริ่มต้น | เครื่องมือหกตัวและคำแนะนำสั้นๆ โครงการภาษาหนึ่งโครงการตั้งแต่ต้นจนจบ |
| full | `--profile full` ใน `args` หรือ `CHAMPOLLION_MCP_PROFILE=full` | เครื่องมือทุกตัว: การ์ดภาษา คลังข้อมูล เกณฑ์เปรียบเทียบ (benchmarks) คิว การแข่งขัน การฝึกฝนของ forge การเผยแพร่ |

ค่าอื่นๆ จะหยุดการทำงานของเซิร์ฟเวอร์: `unknown MCP profile "<value>" (rails or
full)` ชุดเครื่องมือทั้งหมดระบุไว้ใน
[หน้าเซิร์ฟเวอร์ MCP](/docs/network/getting-started/mcp-server) สำหรับโครงการภาษา ให้ใช้โปรไฟล์ rails ต่อไป: ซึ่งเป็นโปรไฟล์ที่ทุกขั้นตอนจะถูกอ่านจากไฟล์ของโครงการ

## ลูปการทำงาน

1. ยังไม่มีโครงการ → `start_project` การเรียกครั้งแรกจะไม่สร้างอะไรเลย: ให้บอก `ask_first` แก่ผู้ใช้ จากนั้นทำการเรียกตามที่ระบุไว้สำหรับคำตอบของพวกเขา
2. `project_status` → อ่าน `step.mode`, `step.say`, `step.why`
3. ทำตามที่โหมดระบุ โดยใช้ `step.call` — คำสั่งเรียกที่แน่นอนสำหรับการดำเนินการในขั้นตอนนี้
4. กลับไปที่ข้อ 2 หลังจากมีการเปลี่ยนแปลงใดๆ ที่คุณหรือผู้ใช้ทำขึ้นเอง ให้เรียก `project_status` อีกครั้ง: ขั้นตอนถัดไปจะถูกอ่านจากไฟล์เสมอ
5. `step: null` → สิ้นสุด rails แล้ว แจ้งให้ผู้ใช้ทราบตามที่ `finished` ระบุ

| `step.mode` | สิ่งที่ต้องทำ | `step.call` |
|---|---|---|
| `auto` | รันคำสั่ง | `run_next_step` พร้อม `project_dir`, `step_id` |
| `confirm` | แจ้งให้ผู้ใช้ทราบว่าขั้นตอนนี้ทำอะไร (การติดตั้ง, การฝึกฝน) ถามว่าใช่หรือไม่ รันคำสั่งก็ต่อเมื่อตอบใช่เท่านั้น หากตอบ "ไม่ใช่ตอนนี้" ให้บันทึกไว้: จะไม่มีอะไรทำงาน | `run_next_step` โดยเพิ่ม `confirmed: true` หลังจากที่ตอบใช่; `declined: true` หากตอบ "ไม่ใช่ตอนนี้" |
| `ask_user` | ถาม `step.question` ด้วยถ้อยคำธรรมดา ส่งคำตอบของผู้ใช้ตามคีย์ใน `step.answers` หากตอบ "ไม่ใช่ตอนนี้": เมื่อ `not-now` เป็นหนึ่งในค่า `enum` ของช่องนั้นเอง ถือว่าเป็นคำตอบ — ให้ส่งค่านั้นไป มิฉะนั้นให้บันทึกไว้: จะไม่มีอะไรทำงาน | `run_next_step` พร้อม `answers` — แต่ละช่องเขียนเป็น `<…>` ซึ่งต้องแทนที่ด้วยคำพูดของผู้ใช้; `declined: true` สำหรับ "ไม่ใช่ตอนนี้" ที่ไม่ใช่หนึ่งในตัวเลือกคำตอบ |
| `wait` | มีบางอย่างกำลังทำงานอยู่ | `project_status` พร้อม `wait_seconds: 120` ทำซ้ำตราบใดที่โหมดยังคงเป็น `wait` |
| `use_tool` | คุณดำเนินการตอนนี้ด้วย `step.tool` อย่าส่งคืนกลับไป | เช่น `add_data` พร้อม `path: "<each file the person named, where it is>"` |
| `human_only` | ผู้ใช้เป็นคนดำเนินการ: แจ้ง `step.say` แก่พวกเขา | ไม่มี |

`step.command` คือสิ่งที่ rails รัน — ไม่ใช่ชื่อเครื่องมือ `<…>` ในการเรียกคือช่องสำหรับคำตอบหรือไฟล์ของผู้ใช้ ช่องที่ส่งกลับไปในสภาพเดิมจะถูกปฏิเสธ

## เครื่องมือทั้งหกตัว

### `start_project`

| อาร์กิวเมนต์ | ชนิดข้อมูล | ความหมาย |
|---|---|---|
| `folder` | string, จำเป็น | โฟลเดอร์ใหม่สำหรับโครงการ สัมพัทธ์กับ `parent_dir` |
| `from` | string, จำเป็น | ภาษาต้นทางที่ผู้ใช้ป้อน: รหัสหรือชื่อ |
| `to` | string, จำเป็น | ภาษาปลายทางที่ได้ออกมา: รหัสหรือชื่อ |
| `target_name`, `source_name` | string | ชื่อภาษาตามที่เจ้าของภาษาเรียก จำเป็นสำหรับรหัสการใช้งานส่วนบุคคล (`qaa`–`qtz`) |
| `purpose` | string | จุดประสงค์ของการแปล ตามคำพูดของผู้ใช้ |
| `parent_dir` | string | ตำแหน่งที่จะสร้างโฟลเดอร์ (ค่าเริ่มต้น: ไดเรกทอรีการทำงานของเซิร์ฟเวอร์) |
| `confirmed` | boolean | `true` เฉพาะหลังจากที่ผู้ใช้ตกลงเรื่องทิศทางการแปลแล้วเท่านั้น |

หากไม่มี `confirmed: true` จะรัน `champollion new --dry` และส่งคืน
`made: false`, `ask_first` (ประโยคที่จะพูด: *"เครื่องมือแปลนี้รับ X และให้ผลลัพธ์เป็น Y — คุณป้อน X เข้าไป และได้ Y ออกมา ต้องการทิศทางแบบนี้ใช่หรือไม่?"*), `if_yes` และ `if_the_other_way` (แต่ละอันเป็นการเรียกที่สมบูรณ์) และ `languages` — สิ่งที่แต่ละชื่อได้รับการระบุ พร้อมด้วย `matchedAs` เมื่อคำของผู้ใช้เป็นอีกชื่อหนึ่งที่การ์ดบันทึกไว้ และ `alsoNamed` เมื่อคำเดียวกันเป็นชื่อของภาษาอื่นด้วย ให้แจ้งทั้งสองอย่างกลับไป หากระบุ `confirmed: true` จะสร้างโครงการและส่งคืน `project`, `languages` และ `next` (ขั้นตอนแรก)

ชื่อที่ไม่มีการ์ดใดบันทึกไว้และไม่มีชื่อที่ใกล้เคียง: การปฏิเสธจะเพิ่ม
`if_it_has_no_code` ซึ่งเป็นการเรียกเดิมพร้อม `to: "qaa"` และใส่ชื่อของพวกเขาเป็น `target_name` ใช้ตัวเลือกนี้เฉพาะสำหรับชื่อที่ผู้ใช้ระบุเท่านั้น

### `project_status`

อาร์กิวเมนต์: `project_dir` (จำเป็น); `wait_seconds` (0–120) หากระบุ `wait_seconds` จะอ่านซ้ำทุก 5 วินาทีในขณะที่ขั้นตอนเป็น `wait` และจะส่งคืนผลลัพธ์เมื่อขั้นตอนเปลี่ยนไปหรือหมดเวลา

ส่งคืน `project`, `stage` (`"2/6 Gather your data"`), `step` (`id`, `mode`,
`say`, `why`, `call` และหากมี `question`, `answers`, `command`,
`tool`, `for_the_person`) รวมถึงสิ่งเหล่านี้เมื่อเกี่ยวข้อง:

| ฟิลด์ | คืออะไร | สิ่งที่คุณต้องทำ |
|---|---|---|
| `true_now` | บันทึกของ Forge เอง ในรูปแบบประโยค: โมเดลที่ฝึกฝนแล้วและคะแนน chrF++ บนชุด dev ที่ดีที่สุด ผลการตรวจสอบการรั่วไหล (leak audit) สำหรับแต่ละชุดทดสอบ คะแนนชุดทดสอบ การฝึกฝนกำลังทำงานอยู่หรือไม่ และมีการให้บริการโมเดลหรือไม่และที่ใด | แจ้งสิ่งที่ทำไปแล้วจากข้อความเหล่านี้เท่านั้น ห้ามเพิ่มเติม |
| `waiting_for_agreement` | ไฟล์ที่เจ้าของภาษายังไม่ได้ให้ความยินยอม (`speakers_agreed: not-yet`): แต่ละไฟล์จะมี `file`, `question`, `say` และ `call` ของตัวเอง | ถามแต่ละคำถามเพียงครั้งเดียวต่อเซสชันอย่างสุภาพ และทำการเรียกเมื่อผู้ใช้แจ้งว่าทุกคนยินยอมแล้วเท่านั้น |
| `files_not_added` | ไฟล์ที่ `add_data` ปฏิเสธในเซสชันนี้ซึ่งยังไม่ได้อยู่ในโครงการ พร้อมเหตุผลการปฏิเสธของแต่ละไฟล์ | นำแต่ละไฟล์เข้ามา (ข้อความปฏิเสธจะบอกวิธี) หรือแจ้งให้ผู้ใช้ทราบว่าไฟล์ใดถูกละไว้และเพราะเหตุใด |
| `model_in_use` | เมื่อโมเดลเปิดให้บริการแล้ว ควบคู่ไปกับขั้นตอนของรอบการปรับปรุง: `say` (หน้าทดลองใช้และวิธีใช้งาน) และ `for_the_person` (คำสั่ง `champollion connect` ที่นำโมเดลไปใส่ในแอปหรือเว็บไซต์ของพวกเขา) | แจ้งให้ผู้ใช้ทราบหนึ่งครั้ง พวกเขาจะรันคำสั่งเชื่อมต่อเมื่อต้องการ |
| `blockers`, `warnings` | ของ Forge แบบคำต่อคำ | ส่งต่อแบบคำต่อคำ |
| `finished` | เมื่อไม่มีขั้นตอนเหลืออยู่: สิ่งที่ผู้ใช้สามารถทำได้ในตอนนี้ (ทดลองใช้โมเดลบนหน้าเว็บ หรือนำไปใช้ในแอป) | แจ้งให้ผู้ใช้ทราบ |
| `error` | เหตุผลที่ไม่สามารถระบุขั้นตอนได้ | ส่งต่อข้อมูลนี้ |

โฟลเดอร์โครงการที่ไม่มีอยู่จริง หรือไม่มี `champollion.project.json`
จะถูกปฏิเสธพร้อมแสดงโครงการที่พบในบริเวณใกล้เคียง

### `run_next_step`

| อาร์กิวเมนต์ | ชนิดข้อมูล | ความหมาย |
|---|---|---|
| `project_dir` | string, จำเป็น | โฟลเดอร์โครงการ |
| `step_id` | string, จำเป็น | `step.id` (หรือ id ของรายการ `waiting_for_agreement`) ที่เพิ่งส่งคืนมา |
| `answers` | object of strings | `ask_user`: คำตอบของผู้ใช้ตามคีย์ใน `step.answers` |
| `confirmed` | boolean | `confirm`: `true` เฉพาะหลังจากที่ผู้ใช้ตอบใช่เท่านั้น รวมถึง: ขั้นตอนที่ล้มเหลวสองครั้ง เฉพาะเมื่อผู้ใช้บอกให้ลองใหม่อีกครั้งตามสภาพเดิม |
| `declined` | boolean | `true` เมื่อผู้ใช้ตอบว่าไม่ใช่ตอนนี้สำหรับขั้นตอน `confirm` หรือสำหรับคำถามที่ไม่มีคำตอบ `not-now` ของตัวเอง: จะไม่มีอะไรทำงาน และจะไม่ถามซ้ำอีกในเซสชันนี้ ในกรณีที่ `not-now` เป็นหนึ่งในตัวเลือกคำตอบ ให้ส่งค่านั้นใน `answers` |

- id ที่ต่างออกไปจะถูกปฏิเสธ: `the project changed since that step was named
  — call project_status again`, with `current`
- `human_only` จะถูกปฏิเสธ (`a person does this step: …`); ขั้นตอน `human_only`
  ที่เอเจนต์ทำด้วยเครื่องมือจะถูกปฏิเสธพร้อมแจ้งเครื่องมือที่ต้องใช้
- `wait` จะถูกปฏิเสธ; `confirm` ที่ไม่มี `confirmed: true` จะถูกปฏิเสธ (`ask the
  person first, then call again with confirmed: true`)
- `ask_user`: จำเป็นต้องมีคำตอบทุกข้อ (`missing the answer "<key>" — ask the
  person who holds the data; never answer for them`); a `<…>` จะถูกปฏิเสธ;
  คำตอบที่อยู่นอกเหนือ `enum` จะถูกปฏิเสธ
- เฉพาะโปรแกรมของ rails เองเท่านั้นที่จะรัน: `champollion`, `nmt-forge` และ `uv tool
  install … nmt-forge`. A command using `|`, `;`, `<`, `>`, `` ` ``, `$` หรือ
  `&` เดี่ยวๆ จะถูกปฏิเสธ; `&&` เชื่อมส่วนต่างๆ เข้าด้วยกัน รันตามลำดับ และหยุดลงเมื่อพบข้อผิดพลาดแรก
- แต่ละส่วนมีขีดจำกัดเวลาไว้ที่ 10 นาที (การติดตั้ง `uv` อยู่ที่ 15 นาที)
- `declined: true` ในขั้นตอนที่ไม่ใช่ทั้ง `confirm` และ `ask_user` จะถูกปฏิเสธ:
  `this step does not wait on the person's yes (<mode>) — there is
  nothing to decline`
- `declined: true` ในขั้นตอนที่ `answers` มี `not-now` รวมอยู่ด้วย (ปัจจุบันคือ `try_it` ของข้อเสนอโมเดลที่แข็งแกร่งกว่า) จะถูกปฏิเสธ และการปฏิเสธจะส่ง `answers` ของขั้นตอนนั้นมาด้วย:
  `"not now" is one of this step's own answers — pass it in
  answers (try_it: "not-now"): it is recorded, and this comes back only after
  more rounds; declined would ask again next session`

ส่งคืน `ran` — ต่อส่วน: `command`, `exit_code`, `timed_out` เมื่อดำเนินการเสร็จ และ 40 บรรทัดสุดท้ายของ `output` — และ `next` ซึ่งเป็นขั้นตอนถัดไปในรูปแบบของ `project_status`

#### "ไม่ใช่ตอนนี้"

มีสองวิธีในการบันทึก และตัวขั้นตอนเองจะเป็นตัวกำหนดว่าใช้วิธีใด:

| ขั้นตอน | "ไม่ใช่ตอนนี้" คือ | สิ่งที่บันทึก | เมื่อใดที่จะกลับมาถามใหม่ |
|---|---|---|---|
| ขั้นตอน `ask_user` ที่ `answers` มี `not-now` รวมอยู่ด้วย (ข้อเสนอโมเดลที่แข็งแกร่งกว่า: `try_it`, `yes` หรือ `not-now`) | คำตอบหนึ่ง: `answers: {"try_it": "not-now"}` | บัญชีแยกประเภทของ Forge (`model-change`, `answer: "not-now"`); ไม่มีการเปลี่ยนแปลงอื่นใด | หลังจากผ่านไปอีกสองรอบที่ชุด dev ตัดสินว่า **no-change** หรือ **worse** — ข้ามเซสชันได้ |
| ขั้นตอน `confirm` (การฝึกฝน, การติดตั้ง, การนำโมเดลไปใช้งาน) หรือคำถามที่ผู้ใช้ยังไม่สามารถตอบได้ในขณะนี้ | `declined: true` | หน่วยความจำของเซิร์ฟเวอร์นี้เท่านั้น | เมื่อเซิร์ฟเวอร์รีสตาร์ท (ในเซสชันถัดไป) |

`declined: true` จะไม่รันสิ่งใด และส่งคืน `declined` (id ของขั้นตอน), `ran: []`,
`say` (*"ไม่ได้รันสิ่งใด จะไม่ถามซ้ำอีกในเซสชันนี้ หากผู้ใช้พูดถึงขึ้นมาและตอบใช่ ค่อยดำเนินการในตอนนั้น"*) และ `next` การปฏิเสธจะถูกเก็บไว้ตลอดอายุการทำงานของเซิร์ฟเวอร์ — หนึ่งเซสชัน เซิร์ฟเวอร์ที่รีสตาร์ทใหม่จะลืมข้อมูลนี้ ในระหว่างที่ยังมีผลอยู่ ขั้นตอนนี้จะส่งกลับมาจาก `project_status` และ `run_next_step` พร้อม `declined_this_session` (เวลาใด ในรูปแบบเวลา ISO) และ `say` ของขั้นตอนจะเริ่มต้นด้วย *"พวกเขาตอบไม่ใช่ตอนนี้ (HH:MM UTC) สำหรับสิ่งนี้: …"* และลงท้ายด้วย *"อย่าถามซ้ำอีกในเซสชันนี้ — จะไม่มีสิ่งที่ต้องอาศัยคำตอบใช่ของพวกเขาทำงาน หากพวกเขาพูดขึ้นมาเองและตอบใช่ ให้ดำเนินการโดยใช้ confirmed: true (หรือคำตอบของพวกเขา)"* การระบุ `confirmed: true` หรือส่งคำตอบในภายหลัง จะเป็นการดำเนินการในขั้นตอนนี้และล้างสถานะการปฏิเสธออกไป
**หมายเหตุ** อย่าถามซ้ำอีกในเซสชันนี้ และอย่าเลี่ยงข้ามขั้นตอนนี้ หากผู้ใช้ยกเรื่องนี้ขึ้นมาพูดเองและตอบใช่ ให้ดำเนินการในตอนนั้น

#### เมื่อขั้นตอนล้มเหลว

**เงื่อนไขล็อก** ขั้นตอนที่ล้มเหลวสองครั้งติดต่อกัน (รหัสออกไม่ใช่ศูนย์หรือหมดเวลา นับตลอดอายุการทำงานของเซิร์ฟเวอร์) จะถูกปฏิเสธในครั้งที่สามเว้นแต่จะระบุ `confirmed: true` พร้อมด้วย `last_output` **หมายเหตุ** แฟล็กนั้นคุณสามารถเป็นผู้กำหนดได้: ให้แจ้งผู้ใช้ว่ามีข้อความว่าอย่างไร และให้พวกเขาแก้ไข (การรันคำสั่งที่แก้ไขแล้วในเทอร์มินัลสามารถทำได้ — จากนั้นเรียก `project_status`) หรือพวกเขาสั่งให้ลองใหม่อีกครั้งตามสภาพเดิม

### `add_data`

| อาร์กิวเมนต์ | ชนิดข้อมูล | ความหมาย |
|---|---|---|
| `project_dir` | string, จำเป็น | โฟลเดอร์โครงการ |
| `path` | string, จำเป็น | ไฟล์ที่ตำแหน่งอยู่: แบบสัมบูรณ์ หรือสัมพัทธ์กับโฟลเดอร์โครงการหรือตำแหน่งที่เซิร์ฟเวอร์เริ่มต้น |
| `into` | `parallel` (ค่าเริ่มต้น) · `test` · `lexicon` | คู่ประโยคสำหรับเรียนรู้ ประโยคทดสอบที่ตรวจสอบแล้ว รายการคำศัพท์ |
| `source_col`, `target_col` | string | คอลัมน์เป็นตัวอักษร (`A`), ตัวเลข หรือส่วนหัวของคอลัมน์ สำหรับ ELAN คือหมายเลข tier ที่การปฏิเสธระบุไว้ (หรือ tier id ที่แน่นอนที่ผู้ใช้พิมพ์) สำหรับ LIFT คือรหัสภาษา |
| `sheet` | string | แผ่นงานหรือตารางใด เมื่อมีหลายรายการ |
| `header` | boolean | `true`: แถวแรกเป็นส่วนหัว; `false`: แถวแรกเป็นข้อมูล |
| `usfm_source` | string | คัมภีร์ USFM เท่านั้น: ข้อความของอีกภาษาหนึ่ง (ไฟล์หรือโฟลเดอร์ `.usfm`) |
| `replace` | boolean | อ่านไฟล์ที่เพิ่มไว้แล้วใหม่อีกครั้ง (ส่วนหัวหรือคอลัมน์อื่น) โดยคำตอบของผู้ถือครองข้อมูลจะยังคงถูกเก็บไว้ |

เครื่องมือนี้จะรัน `champollion data add` ในตอนแรกให้เรียกโดยใส่เฉพาะพาธ: ส่วนหัวที่ระบุชื่อภาษาของคู่นั้นจะใช้กำหนดคอลัมน์ มิฉะนั้นเครื่องมือจะถาม และให้คุณไปถามผู้ใช้ — อย่าตัดสินใจจากเนื้อหาด้วยตนเอง เครื่องมือนี้สามารถอ่านสเปรดชีต (`.xlsx`, `.ods`, `.csv`), `.tsv` และ `.txt`, ตารางใน Word `.docx`, พจนานุกรม Toolbox และ LIFT, ไฟล์ ELAN `.eaf` และ USFM

ส่งคืน `result` (รายงานของ CLI: จำนวนนับ, คอลัมน์, ELAN tier ตามหมายเลข และหมายเลขแถวที่การตรวจสอบแถวระบุไว้ — แถวที่คัดลอกมา, แถวซ้ำ, ความยาวผิดปกติ, แถวที่สลับหรือเลื่อนตำแหน่ง โดยไม่มีการลบสิ่งใดออก — และจะไม่มีประโยคข้อความออกมาเด็ดขาด), `read_from` เมื่อพบไฟล์จากโฟลเดอร์เริ่มต้นของเซิร์ฟเวอร์ และ `also` เมื่อไฟล์มีข้อมูลเพิ่มเติม (เช่น ประโยคตัวอย่างของพจนานุกรมในรูปแบบคู่ประโยค หรือคำแปลอธิบายในรูปแบบรายการคำศัพท์) — แต่ละรายการจะเป็นการเรียก `add_data` ที่สมบูรณ์ ให้ดำเนินการเรียกเว้นแต่ข้อตกลงของผู้ใช้สำหรับไฟล์นั้นจะห้ามไว้ ให้ส่งต่อผลการตรวจสอบแถวตามสภาพจริง: ผู้ใช้จะไปดูแถวเหล่านั้นในไฟล์ของตนเอง
([กฎข้อมูล](/docs/agents/data-rules#what-tools-print-and-never-print))
ห้ามขอให้ผู้ใช้ย้ายไฟล์เด็ดขาด `inbox/` เป็นเพียงที่ที่พวกเขาอาจนำไฟล์มาวางไว้เท่านั้น

### `try_translation`

อาร์กิวเมนต์: `project_dir`; `text` — สูงสุด 10 บรรทัด ไม่เกิน 2,000 ตัวอักษร บรรทัดละหนึ่งประโยค ซึ่งเป็นข้อความที่ผู้ใช้ให้มา

เครื่องมือจะค้นหาโมเดลที่โครงการนี้เปิดให้บริการอยู่ (งาน `serve` ล่าสุดที่สมบูรณ์ใน `nmt-forge jobs --json`) บนคอมพิวเตอร์เครื่องนี้เท่านั้น และอ่าน `/health` ของโมเดลนั้น

- **เงื่อนไขล็อก** หาก `output_local_only` ไม่ใช่ `false` (จริง หรือไม่ทราบ) ระบบจะไม่ส่งคำแปลกลับมา: `shown_to_person_only: true`, `open` (หน้าเว็บของโมเดลเอง) และ `say` ให้แนะนำผู้ใช้ไปยังหน้านั้น อย่าขอให้พวกเขานำคำแปลมาวางกลับให้คุณ
- เซิร์ฟเวอร์ที่ร้องขอโทเค็นจะถูกปฏิเสธ: จะไม่มีการส่งมอบโทเค็นให้แก่เอเจนต์โดยเด็ดขาด
- มิฉะนั้นจะส่งคืน `model`, `pair`, `translations` (`source`,
  `translation` ต่อบรรทัด), `errors` (หากมี) และ `say`: ให้ส่งต่อข้อมูลเหล่านี้ตามสภาพจริง เซิร์ฟเวอร์ไม่ได้ตรวจสอบสิ่งใดในข้อมูลที่ส่งคืนมา

### `explain`

อาร์กิวเมนต์: `topic` ข้อความด้วยถ้อยคำธรรมดาสำหรับส่งต่อ:

| `topic` | ครอบคลุม |
|---|---|
| `rails` | โฟลเดอร์โครงการและลำดับของขั้นตอน |
| `privacy` | ความหมายของ sidecar; เหตุใดคุณจึงต้องไม่เปิดไฟล์ด้วยตนเอง |
| `quality` | สิ่งที่คะแนนรับประกันและไม่ได้รับประกัน |
| `modes` | วิธีดำเนินการในแต่ละประเภทของขั้นตอน |
| `improve` | รอบการทำงานหลังจากที่มีการนำโมเดลไปใช้งาน: ประมาณหนึ่งในสิบแถวของการตรวจสอบ *"ถูกดึงกลับมาจากชีตก่อนหน้าโดยเจตนา (ชีตระบุไว้เช่นนั้น …)"*; การเสนอโมเดลที่ดีกว่าเพื่อนำไปใช้และผู้ใช้ตอบใช่ (*"คำตัดสินเพียงอย่างเดียวไม่ได้เปลี่ยนแปลงอะไร"*); คำตัดสินว่าข้อมูลน้อยเกินไป; ข้อเสนอโมเดลที่แข็งแกร่งกว่าหลังจาก *"สองรอบติดต่อกันที่ชุด dev ตัดสินได้ว่าไม่เห็นการพัฒนา (นับจากโมเดลล่าสุดที่นำไปใช้งาน)"* |
| `off_rails` | การออกนอกราง (Stepping off): รันคำสั่งสำหรับผู้เชี่ยวชาญ แล้วเรียก `project_status` |

## หมายเหตุสำหรับทั้งเซสชัน

- **หมายเหตุ** ทุกสิ่งที่คุณอ่านจะถูกส่งไปยังผู้ให้บริการโมเดลของคุณ `add_data`,
  `project_status` และ `run_next_step` จะรายงานเฉพาะจำนวนนับ คอลัมน์ และสถานะ โดยไม่รายงานประโยคข้อความเด็ดขาด; รักษาแนวทางนี้ไว้ ห้ามเปิดไฟล์ด้วยตัวคุณเอง
- **หมายเหตุ** คำตอบใน `ask_user`, `confirmed: true` และคำตอบรับใน
  `waiting_for_agreement` ต้องเป็นของผู้ใช้ เครื่องมือจะตรวจสอบว่ามีคำตอบอยู่และรูปแบบถูกต้องหรือไม่ มีเพียงคุณเท่านั้นที่สามารถตรวจสอบให้แน่ใจได้ว่าเป็นคำตอบของผู้ใช้จริง
- **หมายเหตุ** ถ่ายทอด `blockers`, `warnings` และข้อควรระวังทุกข้อแบบคำต่อคำ รวมถึงตัวเลขทุกจำนวนพร้อมหน่วยและชุดข้อมูลที่ใช้วัดผล
  ([การแนะนำ](/docs/agents/coaching))
