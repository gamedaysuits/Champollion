# กฎเกี่ยวกับข้อมูลและการส่งข้อมูล

ผู้ถือครองข้อมูลภาษามีสิทธิ์ตัดสินใจว่าจะใช้ข้อมูลนั้นอย่างไร ราง (rails) จะบันทึกการตัดสินใจของพวกเขาไว้ข้าง ๆ แต่ละไฟล์ และเครื่องมือทุกชิ้นจะปฏิบัติตามสิ่งที่บันทึกไว้ โดยมีความเป็นเจ้าของและการควบคุมข้อมูลภาษาของชุมชนเป็นกฎในการออกแบบ ไม่ใช่เพียงแค่การตั้งค่า หน้าเอกสารนี้คือชุดกฎอย่างชัดเจน: แต่ละฟิลด์ทำหน้าที่อะไร เครื่องมือจะปฏิเสธสิ่งใด และส่วนใดบ้างที่มีเพียงคุณเท่านั้นที่เก็บรักษาได้

## ไซด์คาร์ (set/1)

ข้างไฟล์ข้อมูลใด ๆ `<file>.champollion.json`, `$schema`
`https://champollion.dev/schemas/set/1.json` คีย์ที่ไม่รู้จักจะถูกปฏิเสธ บันทึกข้อความ
จะอยู่ใต้ `x-` ไซด์คาร์ที่เขียนขึ้นก่อน set/1 (ไม่มี `$schema`) จะถูกอ่านเป็น set/0
และยังคงใช้ได้ (`champollion upgrade` จะเขียนทับใหม่)

| ฟิลด์ | ค่า | ผลลัพธ์ |
|---|---|---|
| `transmission` | `local-only` (ค่าเดียวเท่านั้น) | มีเพียงโมเดลบนคอมพิวเตอร์เครื่องนี้เท่านั้นที่มองเห็นข้อความได้ เครื่องมือทุกชิ้นจะปฏิเสธที่จะส่งข้อความนี้ไปที่ใดก็ตาม (รวมถึง `mt-eval project offer`) |
| `role` | `train` · `dev` · `test` · `sealed` · `input` · `resource` | ไฟล์นี้มีไว้สำหรับอะไร `test` และ `sealed` จะไม่ถูกใช้ฝึกฝนโมเดลโดยเด็ดขาด |
| `kind` | `parallel` · `monolingual` · `lexicon` · `grammar` · `glossary` | ข้อมูลที่บรรจุอยู่ |
| `pair` | `{source, target}` | ทิศทางของคอลัมน์ในไฟล์ ตามรหัสของการ์ด |
| `fields` | `{source, target}` | คอลัมน์หรือฟิลด์ JSON ใดบรรจุฝั่งใด |
| `terms.training` | `allowed` · `not-allowed` | `not-allowed`: ห้ามโมเดลใดฝึกฝนจากไฟล์นี้ |
| `terms.owner` | ข้อความ | ใครเป็นผู้ถือครอง ด้วยคำพูดของผู้ถือครองเอง |
| `terms.speakers` | ข้อความ | ข้อความนี้เป็นถ้อยคำของใคร ด้วยคำพูดของผู้ถือครองเอง |
| `terms.speakers_agreed` | `yes` · `not-yet` · `some-said-no` | ผู้เป็นเจ้าของถ้อยคำเหล่านี้ยินยอมหรือไม่ |
| `terms.consent_record` | พาธ | บันทึกความยินยอม สัมพัทธ์กับโฟลเดอร์ของไฟล์ |
| `holders_agreed` | `{by, date}` | ผู้ถือครองคนใดที่ยินยอมให้เอาต์พุตแบบ local-only วางไว้ที่ตำแหน่งนั้นได้ (ไม่ได้ผ่อนปรนข้อจำกัดใด ๆ) |
| `derived_from` | พาธ | ไฟล์ที่ได้รับการคุ้มครองซึ่งใช้สร้างไฟล์นี้ โดยเครื่องหมายกำกับถูกส่งต่อมายังที่นี่ |
| `id`, `name`, `license`, `tier`, `segment`, `sha256`, `rows`, `card`, `registeredAt` | | เขียนโดย `champollion network register-corpus`; ไฟล์ที่มีการเปลี่ยนแปลง (sha256 เปลี่ยน) จะไม่ได้รับ id ของการ์ดอีกต่อไป |
| `written_by` | ข้อความ | คำสั่งที่ใช้เขียน |

**การล็อก** ไซด์คาร์มีแต่จะทำให้ไฟล์เข้มงวดขึ้นเท่านั้น: จะไม่ผ่อนปรนสิ่งที่เอนเวโลปของคลังข้อมูลหรือรายการในรีจิสทรีระบุไว้เด็ดขาด

## เฉพาะภายในเครื่อง (local-only) และค่าเริ่มต้นชั่วคราว

`champollion data add` จะทำเครื่องหมายไฟล์ที่เขียนว่าเป็น local-only เมื่อ `defaults.transmission` ของโปรเจกต์
คือ `local-only` (สิ่งที่ `champollion new` เขียน) และ
จะเป็นเช่นนั้นเสมอสำหรับ `--into test` เครื่องหมายดังกล่าวคือการปกป้องของเครื่องมือจนกว่าผู้ถือครอง
จะให้คำตอบ โดยมีการตั้งแฟลก `"x-transmission-default": true`

- คำตอบแรกของผู้ถือครองคือสิ่งตัดสิน `champollion data mark <file>
  --may-leave` lifts a provisional mark; `--local-only` จะกำหนดให้เป็นไปตามการตัดสินใจของพวกเขา (แฟลกจะถูกลบออก)
- **หมายเหตุ** เครื่องมือไม่สามารถบอกได้ว่าใครเป็นผู้รันคำสั่ง ให้ยกเลิกเครื่องหมายชั่วคราว
  เฉพาะเมื่อได้รับคำตอบจากผู้ถือครองเองเท่านั้น
- **การล็อก** เครื่องหมาย local-only ที่ผู้ถือครองกำหนดไว้ไม่สามารถยกเลิกได้ด้วยคำสั่ง
  ใด ๆ: *"ไฟล์นี้ถูกทำเครื่องหมายเป็น local-only และไซด์คาร์มีแต่จะเข้มงวดขึ้นเท่านั้น การที่ข้อมูลจะออกจากคอมพิวเตอร์เครื่องนี้ได้หรือไม่เป็นการตัดสินใจของผู้ถือครอง — หากพวกเขายินยอม ให้แก้ไขไซด์คาร์ด้วยตนเอง"*
- **การล็อก** `data mark` บนไฟล์ที่ยังไม่ได้กำหนดเป็น local-only จำเป็นต้องมี `--local-only` หรือ
  `--may-leave`: *"การที่ข้อความในไฟล์นี้จะถูกส่งไปยังบริการ AI ภายนอกได้หรือไม่เป็นการตัดสินใจของผู้ถือครอง ดังนั้นจึงไม่มีการสันนิษฐานเอาเองเด็ดขาด"*

ความหมายของ local-only ในเครื่องมือแต่ละชิ้น:

| ตำแหน่ง | สิ่งที่เกิดขึ้น |
|---|---|
| การประเมินผลใด ๆ (`mt-eval run`, การให้คะแนนของ forge) | นโยบายจะเปลี่ยนรูปเป็น `sealed` (ระดับ `local-only`): มีเพียงเอนด์พอยต์แบบ loopback, อะแดปเตอร์ในโพรเซสของ harness เอง (`local-model`) หรือวิธีภายนอกที่รันด้วย `--attest-local-transport` เท่านั้นที่สามารถมองเห็นข้อความได้ |
| เอาต์พุตของเทอร์มินัลและ `--json` | ประโยคในไฟล์จะถูกระงับไว้ โดยจะแสดงหมายเลขบรรทัด, id, จำนวนนับ และคะแนนแทน พร้อมข้อความหนึ่งบรรทัดระบุเหตุผล |
| ไฟล์ที่แยกย่อยออกมา | ส่วนแบ่งไฟล์ (splits), สำเนาที่ล้างข้อมูลแล้ว, สมมติฐาน (hypotheses) และบันทึกการรันจะยังคงเก็บข้อความไว้ (เนื่องจากอยู่ในโฟลเดอร์ของบุคคลนั้น) และจะส่งต่อเครื่องหมายนี้ในไซด์คาร์ของไฟล์เหล่านั้นเอง |
| โมเดลที่ฝึกฝนจากไฟล์นี้ | เอาต์พุตของโมเดลจะเป็นแบบ local-only ด้วยเช่นกัน (`forge-model.json` `trained_on.terms`; ที่ไม่ได้รับการบันทึกจะถือว่าเป็น local-only): `try_translation` จะส่งคืนเฉพาะหน้าของโมเดล, `champollion connect`, `mt-eval serve` ภายนอก loopback และ `mt-eval translate` ภายนอกโปรเจกต์จำเป็นต้องมี `--holders-agreed-by` และ `sync` จะระงับคำตอบไว้ ไม่ว่าจะผ่านวิธี `api` หรือ `local` ก็ตาม ([การให้บริการ](/docs/agents/serving)) |
| ไฟล์แนะแนวทางหรือพจนานุกรม | ไฟล์แนะแนวทางที่มีไซด์คาร์จะส่งต่อนโยบายไปยังพรอมต์ เอาต์พุตของการรันคลังคำศัพท์จะถูกระงับไว้เมื่อพจนานุกรมถูกกำหนดเป็น local-only |

**หมายเหตุ** `--attest-local-transport` จะประกาศว่าเอนด์พอยต์ของวิธีนั้นเป็นแบบโลคัล ให้ส่งแฟลกนี้
เฉพาะเมื่อคุณได้ตรวจสอบแล้วว่าเอนด์พอยต์อยู่บนเครื่องนี้จริง ๆ เท่านั้น: ที่อยู่ loopback อาจเป็นพร็อกซีที่ส่งต่อข้อมูลไปที่ใดก็ได้

## การฝึกฝนโมเดล

- **การล็อก** nmt-forge ปฏิเสธที่จะฝึกฝนโมเดลด้วยไฟล์ที่ไซด์คาร์ระบุว่า
  `terms.training: not-allowed`; ไซด์คาร์ที่อ่านไม่ได้จะถือว่ามี
  ข้อจำกัดเสมอ จะไม่ถือว่าไม่มีข้อจำกัด
- **การล็อก** `champollion data combine` จะไม่รวมไฟล์ที่ไม่อนุญาตเด็ดขาด: โดยจะย้าย
  ไฟล์นั้นพร้อมไซด์คาร์ไปยัง `data/not-for-training/` เครื่องมือจะปฏิเสธไฟล์ที่
  ผู้ถือครองยังไม่ได้ให้คำตอบ — คือไม่มี `terms.training` หรือไม่มี
  `terms.speakers_agreed` (*"ยังไม่มีใครบอกว่าทุกคนที่เป็นเจ้าของถ้อยคำในไฟล์นี้ยินยอมหรือไม่ — champollion จะถามผู้คนในลำดับถัดไป ค่อยรวมไฟล์ภายหลัง"*) —
  และไฟล์ที่รวมแล้วจะใช้ข้อกำหนดที่เข้มงวดที่สุดในบรรดาไฟล์ทั้งหมด (เป็น local-only หากมีไฟล์ใดไฟล์หนึ่งเป็น, เป็น not-allowed หากมีไฟล์ใดไฟล์หนึ่งเป็น, และระบุชื่อเจ้าของทุกคน)
- **การล็อก** ขั้นตอนข้อกำหนดของ Journey จะถือว่าไฟล์ใน `data/parallel/`,
  `data/lexicon/`, `data/grammar/` หรือ `data/monolingual/` ได้รับคำตอบแล้วก็ต่อเมื่อ
  ไซด์คาร์ของไฟล์นั้นมีทั้ง `terms.training` และ `terms.speakers_agreed` (และ
  คำตอบเกี่ยวกับการฝึกฝนต้องมาจากผู้ถือครอง ไม่ใช่การแจ้งเตือนเพื่อความปลอดภัยของเครื่องมือตามด้านล่าง); ก่อนหน้านั้น
  ระบบจะถามซ้ำ และรางจะไม่ดำเนินการต่อ
- **หมายเหตุ** nmt-forge จะอ่าน `terms.training` ไม่ใช่ `speakers_agreed` หากมีไฟล์
  คู่ภาษาเพียงไฟล์เดียวจะไม่มีการรวมไฟล์ ดังนั้นจึงมีเพียงขั้นตอนข้อกำหนดเท่านั้นที่รอ
  คำตอบนั้น: ห้ามฝึกฝนโมเดลด้วยไฟล์ที่ไม่มีคำตอบของผู้พูดโดยเด็ดขาด
- **การล็อก** ไฟล์ `test` หรือ `sealed` จะไม่ถูกใช้ฝึกฝนโมเดลโดยเด็ดขาด: `--training
  allowed` จะถูกปฏิเสธสำหรับไฟล์นั้น และการกำหนดบทบาทอื่นให้ไฟล์ก็จะถูกปฏิเสธเช่นกัน
- **การล็อก** `not-allowed` ไม่สามารถเปลี่ยนเป็น `allowed` ด้วยคำสั่ง
  ได้ (*"หากผู้ถือครองยินยอมให้ฝึกฝนโมเดล ให้แก้ไขไซด์คาร์ด้วยตนเอง"*) — ยกเว้นกรณีเดียวด้านล่าง
- คัมภีร์ทางศาสนา (USFM) จะนำเข้ามาพร้อมกับทำเครื่องหมาย `terms.training: not-allowed` เพื่อ
  เป็นการระวังความปลอดภัยของเครื่องมือ (`"x-training-default": true`); คำตอบของผู้ถือครอง
  จะเข้ามาแทนที่ค่านี้

## ถ้อยคำของใคร และใครยินยอม

`--speakers` จะบันทึกว่าไฟล์นี้เก็บถ้อยคำของใคร; `--speakers-agreed` จะบันทึกว่า
พวกเขายินยอมหรือไม่

| `speakers_agreed` | ผลลัพธ์ |
|---|---|
| `yes` | ฝึกฝนตามที่ผู้ถือครองระบุ |
| `not-yet` | บังคับให้การฝึกฝนเป็น `not-allowed` จนกว่าทุกคนจะยินยอม; ไฟล์จะปรากฏใน `waiting_for_agreement` |
| `some-said-no` | ห้ามโมเดลใดเรียนรู้จากไฟล์นี้โดยเด็ดขาด: *"แยกถ้อยคำของพวกเขาออกไปไว้ในไฟล์อื่น แล้วทำเครื่องหมายส่วนที่เหลือ"* |
| (ไม่มีคำตอบ) | ขั้นตอนข้อกำหนดจะคอยถามซ้ำ และ `data combine` จะปฏิเสธไฟล์นี้ (ตามด้านบน) |

**การผ่อนปรนเพียงอย่างเดียวที่ทำได้ด้วยคำสั่ง:** `not-yet` → `yes` ร่วมกับ
`--training allowed` ไฟล์ที่ `combine` เคยแยกเก็บไว้จะถูกนำกลับมาที่
`data/parallel/` สำหรับการรวมไฟล์ครั้งต่อไป

**หมายเหตุ** ให้ถามคำถาม `waiting_for_agreement` เพียงเซสชันละหนึ่งครั้งอย่างสุภาพ และ
ตอบคำถามนี้เฉพาะเมื่อบุคคลนั้นยืนยันว่าทุกคนยินยอมแล้วเท่านั้น

**`--holders-agreed-by "<who>"`** ระบุชื่อบุคคลในกลุ่มผู้ถือครองข้อมูลที่
ยินยอมให้ส่งเอาต์พุตแบบ local-only ไปยังตำแหน่งเฉพาะได้: เช่น ไปยังไฟล์ภาษาของแอป
(locale files) (`champollion connect` บันทึกเป็น `holdersAgreed` ของคู่ภาษา), ไปยัง
แอดเดรสที่เครื่องอื่นเข้าถึงได้ (`mt-eval serve`, `nmt-forge serve` รายงาน
ใน `/health`) หรือไปยังไฟล์นอกโปรเจกต์ (`mt-eval translate`
บันทึกเป็น `holders_agreed` ของไซด์คาร์) คำสั่งนี้ไม่ได้ผ่อนปรนสิ่งอื่นใดเพิ่มเติม:
เอาต์พุตจะยังคงเป็น local-only สำหรับเครื่องมือทุกชิ้น **หมายเหตุ** ให้ระบุเฉพาะชื่อที่บุคคลนั้นให้มาเท่านั้น

## สิ่งที่เครื่องมือจะพิมพ์ และไม่พิมพ์โดยเด็ดขาด

| เครื่องมือ | สิ่งที่พิมพ์ | สิ่งที่ไม่พิมพ์โดยเด็ดขาด |
|---|---|---|
| `champollion data add` | จำนวนนับ, คอลัมน์ (ตัวอักษร, อัตราส่วนการมีข้อมูล, ความยาวเฉลี่ย, สัดส่วนของอักษรละติน), เซลล์ส่วนหัวเฉพาะเมื่อเป็นชื่อภาษาใดภาษาหนึ่งของคู่ภาษา, ระดับชั้นของ ELAN ตามหมายเลข และหมายเลขแถวที่การตรวจสอบแถวระบุไว้ | ประโยค; เซลล์ส่วนหัวอื่น ๆ ใด ๆ (จะพิมพ์ความยาวแทน); id ของเทียร์ ELAN |
| `champollion data mark`, `combine`, `next`, `validate` | ฟิลด์, จำนวนนับ, สถานะ | ข้อความของไฟล์ข้อมูล — เครื่องมือเหล่านี้จะไม่เปิดไฟล์เลย |
| `champollion improve …` | จำนวนนับและเปอร์เซ็นต์ | ประโยคในชีต |
| `champollion sync` (วิธี `local` และ `api`) | คีย์ที่ข้อความมีคำที่โมเดล forge ไม่เคยพบในการฝึกฝน จาก `meta.unseen_words` ของเซิร์ฟเวอร์ | ตัวข้อความ หรือตัวคำศัพท์เอง |
| `nmt-forge`, `mt-eval` | สำหรับคลังข้อมูลแบบ local-only, ปิดผนึก หรือต้องได้รับความยินยอม: id, หมายเลขบรรทัด, จำนวนนับ, คะแนน; `[sentence withheld]` ภายในข้อความแจ้งข้อผิดพลาด | ประโยคในคลังข้อมูล ไม่ว่าจะในเอาต์พุตสำหรับมนุษย์หรือ `--json` |
| เครื่องมือ MCP rails | สิ่งที่ CLI พิมพ์ แบบตัดทอน | ประโยค; เอาต์พุตของโมเดลแบบ local-only |

**หมายเหตุ** `--show-text` (nmt-forge; `mt-eval compare`) จะพิมพ์ประโยคที่ถูกระงับไว้
คำสั่งนี้มีไว้สำหรับผู้ใช้งานที่หน้าเทอร์มินัลของตนเองเท่านั้น ไม่ใช่สำหรับเอเจนต์ —
เพราะสิ่งที่คุณอ่านจะถูกส่งไปยังผู้ให้บริการโมเดลของคุณ

**หมายเหตุ** ไม่มีเครื่องมือใดสามารถห้ามไม่ให้คุณเปิดไฟล์ได้ ห้ามเปิด พิมพ์
สรุป หรือวางไฟล์ข้อมูล ประโยคทดสอบ รายการคำศัพท์ หรือ
ชีตของผู้คน — รวมถึง `input-words.json` ของไฟล์ส่งออกด้วยเช่นกัน: ไฟล์ดังกล่าวแสดงรายการคำศัพท์จากประโยคฝึกฝนของพวกเขา และจะถูกเก็บไว้ข้างโฟลเดอร์โมเดล ห้ามนำเข้าไปไว้ข้างในโฟลเดอร์โมเดลโดยเด็ดขาด
([การให้บริการ](/docs/agents/serving#what-an-export-holds))

**การตรวจสอบแถว** เมื่อมีการนำไฟล์เข้ามา (คู่ภาษา, ชุดทดสอบ หรือรายการคำศัพท์)
`data add` จะตรวจสอบแถวของไฟล์เทียบกับสองคอลัมน์ของตัวไฟล์เอง — โดยไม่ต้องใช้พจนานุกรม และไม่มีการลบข้อมูลใดออก เครื่องมือจะนับจำนวนและระบุหมายเลขแถวสำหรับ:

- ข้อความที่คัดลอกมา: คำแปลเป็นประโยคต้นฉบับซ้ำอีกครั้ง (หากเป็นชื่อเฉพาะหรือคำยืมถือว่ายอมรับได้ มิฉะนั้นจะถือว่าคำแปลขาดหายไป);
- คู่ภาษาที่ซ้ำกับคู่ก่อนหน้า;
- คำแปลที่ยาวหรือสั้นกว่าอัตราส่วนปกติของไฟล์มาก (ข้อความถูกตัดทอน หรือมีสองประโยคในเซลล์เดียว);
- แถวที่ดูเหมือนสลับฝั่งกัน: ข้อความต้นฉบับอ่านดูเหมือนคำแปลของไฟล์ และกลับกัน;
- กลุ่มแถวต่อเนื่องที่ดูเหมือนเลื่อนไปหนึ่งแถว: คำแปลตรงกับแถวถัดไปหรือแถวก่อนหน้ามากกว่า — ตัวเลข เครื่องหมายปรัศนี และความยาวตรงกับแถวที่ห่างออกไปหนึ่งแถว รวมถึงคำศัพท์ด้วย: โดยวัดจากความสอดคล้องระหว่างคำต้นฉบับของแถวนั้นกับคำในคำแปล ตามความถี่ที่คำทั้งสองปรากฏร่วมกันในส่วนอื่น ๆ ของไฟล์เดียวกัน (คำที่พบน้อยจะมีน้ำหนักมากกว่า โดยไม่นับแถวนั้นเอง)
  วิธีนี้ช่วยตรวจจับการเลื่อนบรรทัดในไฟล์ที่มีประโยคแบบเทมเพลตซึ่งมีความยาวใกล้เคียงกันทั้งหมด และจะไม่มีผลเพิ่มเติมหากคำในไฟล์มีข้อมูลน้อยเกินไป

เครื่องมือจะพิมพ์หมายเลขแถวสูงสุดประเภทละ 12 แถว (สูงสุด 6 กลุ่มสำหรับแถวที่เลื่อนไปหนึ่งแถว) — สำหรับสเปรดชีต จะเป็นแถวในไฟล์ของผู้ใช้เองโดยนับรวมส่วนหัวด้วย — และจะบันทึก
จำนวนนับลงใน `x-import.quality` ของไซด์คาร์ การตรวจสอบความยาว การสลับฝั่ง และการเลื่อนแถว
จำเป็นต้องมีคู่ภาษาอย่างน้อย 20 คู่ ส่วนรายการคำศัพท์ (`--into lexicon`) จะตรวจสอบเฉพาะข้อความที่คัดลอกมาและการซ้ำเท่านั้น **หมายเหตุ** ให้ส่งต่อหมายเลขแถวไป: เพื่อให้ผู้ใช้เปิดดูแถวเหล่านั้นในไฟล์ของตนเองและตัดสินใจ ห้ามเปิดไฟล์เพื่อดูด้วยตนเองโดยเด็ดขาด

**ไฟล์ ELAN** เมื่อ `data add` ไม่สามารถระบุได้ว่าเทียร์ใดเป็นของฝั่งใด (ฝั่งที่ไม่ได้ระบุด้วยแฟลก และไม่มีเทียร์ที่บันทึกภาษาของฝั่งนั้นไว้เพียงหนึ่งเทียร์พอดี) เครื่องมือจะปฏิเสธ
และแสดงรายการเทียร์ตามหมายเลข เรียงตามลำดับในไฟล์: `tier <n> (<language or
"no language">, <count> annotation(s))`, with `, under tier <m>` สำหรับเทียร์
ที่อ้างอิงถึงอีกเทียร์หนึ่ง ให้ส่งหมายเลขเหล่านี้เป็น `--source-col` และ `--target-col`
(`champollion data add <file> --source-col <number> --target-col <number>`);
ไซด์คาร์จะบันทึกหมายเลขเหล่านี้ไว้ (`x-import.elan_tiers`) หมายเลขหรือ id ที่
ไม่ได้ระบุถึงเทียร์ใดจะถูกปฏิเสธ (`no such tier — … Name a tier by its number`) และ
เทียร์ที่ภาษาที่บันทึกไว้ไม่ใช่ภาษาของฝั่งนั้นก็จะถูกปฏิเสธเช่นกัน เทียร์สองเทียร์จะถูกจับคู่กัน
ก็ต่อเมื่อเทียร์หนึ่งอ้างอิงถึงอีกเทียร์หนึ่ง หรือใช้ช่วงเวลาร่วมกันเท่านั้น — ไม่มีการคาดเดาเอาเองเด็ดขาด **หมายเหตุ** id ของเทียร์คือสิ่งใดก็ตามที่ผู้สร้างไฟล์พิมพ์ไว้ และ
มักเป็นชื่อของบุคคล ดังนั้น `data add` จึงไม่พิมพ์ id นั้นออกมาโดยเด็ดขาด ผู้ใช้อาจพิมพ์ id ที่ตรงกันด้วยตนเอง ส่วนคุณให้ส่งเป็นหมายเลข
ไฟล์ LIFT จะจับคู่ตามรหัสภาษา ส่วนไฟล์ Toolbox จะจับคู่ตามมาร์กเกอร์ MDF
(`\ge` และ `\xe` เป็นภาษาอังกฤษตามมาตรฐาน)

## โหมดการส่งข้อมูล

การประเมินผลทุกครั้งจะแปลงคลังข้อมูลเป็นโหมดใดโหมดหนึ่งก่อนที่จะส่งข้อมูลใด ๆ ออกไป
(`arena/mt_eval_harness/transmission_policy.py`) และจะบันทึกไว้ในบันทึก
การรัน:

| โหมด | เมื่อใด | โมเดลทางไกล |
|---|---|---|
| `cleared` | สัญญาอนุญาตที่ผ่านการตรวจสอบแล้วว่าแจกจ่ายต่อได้ | อนุญาต |
| `no-train` | สัญญาอนุญาตมาตรฐาน Creative Commons แบบไม่ใช้เพื่อการค้า หรือไม่ดัดแปลง; หรือคลังข้อมูลที่ไม่ได้ลงทะเบียนซึ่งไม่ได้ระบุสัญญาอนุญาต | เฉพาะผ่านช่องทางที่ไม่ฝึกฝนโมเดลจากอินพุต: OpenRouter ที่ตรึงไว้กับ `data_collection: deny`, API ของผู้ให้บริการโดยตรง หรือโลคัล ซึ่งเป็นการรับประกันว่าจะไม่มีการนำไปฝึกฝน ไม่ใช่การรับประกันว่าจะไม่มีการเก็บรักษาข้อมูล |
| `consent-required` | สัญญาอนุญาตที่มีการปรับแต่ง กำหนดขึ้นเอง หรือไม่ได้ระบุ (`LicenseRef-*`) | ถูกปฏิเสธจนกว่ารายการของชุดข้อมูลจะบันทึกการอนุญาตสิทธิ์ `transmission_consent` (`granted_by`, `date`, `scope`, `evidence`); ทั้งนี้การใช้งานแบบโลคัลยังคงทำงานได้ |
| `sealed` | ส่วนที่แยกเก็บไว้ หรือเซกเมนต์ระดับมาตรฐานทอง, ชุดข้อมูลที่ถูกกักกัน หรือเครื่องหมาย local-only ของผู้ดูแล | ถูกปฏิเสธ โดยไม่มีการแทนที่ข้อกำหนดใด ๆ |

- **การล็อก** ข้อความของคลังข้อมูล `consent-required` หรือ `sealed` จะถูกระงับ
  ไม่ให้แสดงบนเทอร์มินัลด้วยเช่นกัน
- วิธีภายนอก (ปลั๊กอิน) บนคลังข้อมูล `no-train` จะมีการแจ้งเตือน แต่ไม่
  ถูกปฏิเสธ: เนื่องจาก harness ไม่สามารถมองเห็นช่องทางของปลั๊กอินได้ ส่วนบนคลังข้อมูล `consent-required`
  และ `sealed` จะถูกปฏิเสธ ยกเว้นจะมี `--attest-local-transport`
- **การล็อก** ผู้ให้บริการแบบโลคัลจะถือว่าเป็นโลคัลก็ต่อเมื่อเอนด์พอยต์เป็น
  ที่อยู่ loopback (`localhost`, `127.0.0.1`, `::1`, unix socket) เท่านั้น — ห้ามตัดสิน
  จากชื่อของมันโดยเด็ดขาด
- **หมายเหตุ** ห้ามบันทึกการอนุญาตสิทธิ์ `transmission_consent` และห้ามตีความ
  สัญญาอนุญาตแทนผู้ถือสิทธิ์โดยเด็ดขาด การอนุญาตสิทธิ์จะถูกบันทึกโดยผู้ดูแลชุดข้อมูล
  หลังจากที่ผู้ถือสิทธิ์ได้ให้สิทธิ์แล้วเท่านั้น
- **หมายเหตุ** `--allow-data-collection` จะยกเลิกการตรึง no-train เฉพาะสำหรับ
  คลังข้อมูลที่ไม่ได้ลงทะเบียนและไม่ได้ระบุสัญญาอนุญาตเท่านั้น ซึ่งเป็นการยืนยันว่าผู้เรียกใช้เป็นผู้ถือสิทธิ์ ให้ส่งแฟลกนี้เฉพาะเมื่อบุคคลนั้นระบุว่าตนเป็นผู้ถือสิทธิ์เท่านั้น

## ระดับชั้นการลงทะเบียน

การลงทะเบียนคลังข้อมูลเป็นทางเลือก: รางไม่จำเป็นต้องใช้เลย การลงทะเบียนจะเขียนการ์ด
เมทาดาตาเพื่อให้สามารถตั้งชื่อ เปรียบเทียบ และแสดงรายการคลังข้อมูลได้ หากผู้ถือครองเลือกที่จะทำ
`champollion network register-corpus` สามารถโต้ตอบได้ที่เทอร์มินัล
และเขียนสคริปต์ควบคุมได้ด้วยแฟลกต่าง ๆ (`--tier`, `--data`, `--license`, `--name`, …)
**หมายเหตุ** ระดับชั้น เช่นเดียวกับข้อกำหนดทุกข้อ เป็นการตัดสินใจของผู้ถือครอง

| ระดับชั้น | การ์ด | ตัวข้อความ | สิ่งที่ปฏิเสธ |
|---|---|---|---|
| `local-only` (ค่าเริ่มต้น) | ถูกเขียนไว้ข้างไฟล์ `--data` (หรือ `--out` หรือที่นี่) โดยไม่เขียนลงในโฟลเดอร์การ์ดส่วนกลางเด็ดขาด | จะไม่ออกจากคอมพิวเตอร์เครื่องนี้เด็ดขาด; ไซด์คาร์จะได้รับ `transmission: local-only` | — |
| `private` | เมทาดาตาพร้อม `quarantine: true`; จากการติดตั้งผ่าน npm จะยังคงอยู่เฉพาะในเครื่อง และการแสดงรายการจะเป็นคำขอแยกต่างหาก (`champollion network submit --type dataset`) | ไม่อัปโหลดเด็ดขาด; ไม่มีเครื่องหมายการส่งข้อมูล — สัญญาอนุญาตจะเป็นตัวกำหนดโหมด | — |
| `public` | เมทาดาตาพร้อมพอยน์เตอร์สำหรับดึงข้อมูลจากแหล่งต้นทาง (`--repo-url`, `--builder`) | ไม่มีการโฮสต์เด็ดขาด: ดึงมาจากแหล่งต้นทาง | สัญญาอนุญาตแบบไม่ใช้เพื่อการค้า, ไม่ดัดแปลง, มีข้อจำกัด หรือยังไม่ได้รับการยืนยัน (*"ให้ลงทะเบียนแบบส่วนตัวหรือ local-only แทน"*); `--data` |
| `sealed` | เมทาดาตาพร้อม `quarantine: true` และบล็อกที่ปิดผนึก (`--seal-input`, `--threshold-pubkey`, `--custodian-group`, `--qualifier-id`) | มีอยู่เฉพาะข้อความเข้ารหัสเท่านั้น ซึ่งเขียนลงใน `<id>.sealed.json` หรือ `--seal-out` | ไฟล์ที่เป็นสำเนาแบบไบต์ต่อไบต์ของคลังข้อมูลสาธารณะ; `--data` |

ในทุกระดับชั้น จะไม่มีการอัปโหลดสิ่งใดขณะลงทะเบียน (`--json` ระบุว่า
`uploadedContent: false`) การเรียกเครือข่ายเพียงครั้งเดียวจากการติดตั้งผ่าน npm คือการเปรียบเทียบ
sha256 ของไฟล์กับแคตตาล็อกสาธารณะบนคอมพิวเตอร์เครื่องนี้ (ค่าแฮชจะไม่ออกจากเครื่องเด็ดขาด);
หากใช้ `CHAMPOLLION_OFFLINE=1` บนการ์ดจะระบุว่าไม่ได้ดำเนินการเปรียบเทียบ
เมื่อใช้ `--data` ไซด์คาร์จะบันทึก `id`, `name`, `license`, `tier`,
`sha256`, `rows`, `card` และ `registeredAt` **การล็อก** id ที่ลงทะเบียนแล้วจะ
ไม่มีการสร้างใหม่เด็ดขาด: การลงทะเบียนไฟล์เดิมซ้ำภายใต้ id อื่นจะถูกปฏิเสธ และ
ไฟล์ที่มีการเปลี่ยนแปลง (sha256 เปลี่ยน) จะไม่ได้รับ id หรือเกรดของการ์ดนั้นอีกต่อไป

## เอาต์พุตถือเป็นงานดัดแปลง

เอาต์พุตของโมเดลที่ประมวลผลจากประโยคที่มีข้อจำกัดถือเป็นงานดัดแปลงของประโยคเหล่านั้น และการประเมินผล
จะสร้างเอาต์พุตดังกล่าวเป็นจำนวนมาก เครื่องมือจะปฏิบัติต่อเอาต์พุตเช่นเดียวกับที่
ปฏิบัติต่ออินพุต:

- สำหรับทุกคลังข้อมูลที่ไม่ใช่ `cleared` การรันจะบันทึกและพิมพ์ข้อความแจ้งเตือน:
  การทำนายผลเป็นงานดัดแปลงด้วยเครื่องจากประโยคที่มีข้อจำกัด และห้ามนำไป
  แจกจ่าย
- ในกรณีที่ข้อความถูกระงับไว้ (local-only, ปิดผนึก, ต้องได้รับความยินยอม) ทุก
  ไฟล์ที่สร้างขึ้นจากข้อความนั้น — เช่น บันทึกการรัน, รายงาน, การเปรียบเทียบ, ข้อมูลในแคช,
  เอาต์พุตของ `mt-eval translate`, ฝั่งที่แยกย่อยของ forge, คลังข้อมูลที่ล้างแล้ว และ
  สมมติฐาน — จะได้รับไซด์คาร์ set/1 ที่มีเครื่องหมายกำกับส่งต่อมา (`derived_from`,
  `written_by`) ส่วนคลังข้อมูลแบบ `no-train` จะได้รับข้อความแจ้งเตือนแต่ไม่มีไซด์คาร์
- โมเดลที่ฝึกฝนจากข้อความแบบ local-only จะเขียนเอาต์พุตแบบ local-only (ตามด้านบน)
- `mt-eval publish` จะไม่อัปโหลดประโยคของคลังข้อมูลแบบ local-only เด็ดขาด แม้จะใช้
  `--publish-entries` ก็ตาม และโดยค่าเริ่มต้นจะเผยแพร่พรอมต์ที่ผ่านการชี้แนะในรูปแบบค่าแฮชเท่านั้น
  สำหรับคลังข้อมูลดังกล่าว สำหรับคลังข้อมูลอื่น ๆ พรอมต์จะได้รับการเผยแพร่ เว้นแต่จะระบุ
  `--redact-coaching`

**หมายเหตุ** การเผยแพร่เป็นการตัดสินใจของผู้คน โดยใช้คำพูดของพวกเขาเอง และต้อง
แสดงตัวอย่าง (`--dry-run`) ให้พวกเขาดูก่อนเสมอ ห้ามเผยแพร่ วาง หรือส่ง
เอาต์พุตของการรันแทนพวกเขาโดยเด็ดขาด
