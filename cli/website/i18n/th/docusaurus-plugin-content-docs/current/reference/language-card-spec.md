# ข้อกำหนดการ์ดภาษา

> **แหล่งข้อมูลจริงแหล่งเดียว (Single source of truth)** เอกสารนี้กำหนดรูปแบบมาตรฐานของ language card ทุกใบ การ์ดจะยืนยันเฉพาะสิ่งที่แหล่งอ้างอิงยืนยันเท่านั้น: ฟิลด์ที่ไม่มีแหล่งข้อมูลใดยืนยันจะถูก **ละเว้น ไม่ใช่ null** — ฟิลด์ที่หายไปหมายความว่า "ไม่มีแหล่งข้อมูลกล่าวถึง" ไม่เคยหมายความว่า "ไม่มีอะไรให้รู้" สคีมาที่ตรวจสอบด้วยเครื่องได้จะจัดส่งเป็น `shared/schemas/language-card.schema.json` ในแพ็กเกจ npm และ [ตัวอย่างมาตรฐานด้านล่าง](#canonical-template) ถูกสร้างขึ้นจากคลังข้อมูลจริง (live corpus) ในทุกๆ การบิลด์เว็บไซต์ ดังนั้นหน้านี้จึงไม่มีทางคลาดเคลื่อนไปจากการ์ดที่มันอธิบาย

## การรีบิลด์ atlas รอบ 2026-08 — มีอะไรเปลี่ยนแปลงในสคีมานี้บ้าง

ตอนนี้คลังข้อมูลการ์ดเป็น **ผลลัพธ์จากการบิลด์ (build output)**: การ์ดทุกใบถูกฉาย (project) จากที่เก็บสแนปช็อตต้นทางที่ถูกปักหมุดไว้ และจะถูกรีบิลด์ — ไม่เคยถูกแก้ไขโดยตรง — เมื่อข้อเท็จจริงมีการเปลี่ยนแปลง มีสี่สิ่งที่เกี่ยวกับรูปแบบที่เปลี่ยนไปพร้อมกับการรีบิลด์ครั้งนั้น:

1. **ฟิลด์ที่มีข้อโต้แย้งจะมาพร้อมกับซองระบุที่มา (attribution envelope)** ในกรณีที่แหล่งอ้างอิงมีความขัดแย้งกันอย่างแท้จริง ฟิลด์นั้นจะไม่ใช่ค่าแบบแบน (flat value) แต่จะเป็น `{"agreement": "...", "consensus": <value?>, "values": [{"value": ..., "source": "..."}]}`. This applies to `name`, `classification.family`, `speakerEstimates`, `endangerment` และฟิลด์ใดๆ ที่แหล่งข้อมูลใหม่ทำให้เกิดข้อโต้แย้ง ผู้ใช้งานควรอ่านการ์ดผ่านอะแดปเตอร์ที่เผยแพร่ (`normalizeCard()` ในแพ็กเกจ npm) แทนที่จะทึกทักเอาว่าเป็นค่าแบบแบน — `display()` จะแปลงซองข้อมูลให้เป็นค่าที่ตกลงกัน และจงใจที่จะไม่ส่งคืนค่าใดๆ เมื่อมีข้อโต้แย้งที่แท้จริง แทนที่จะเลือกผู้ชนะ

2. **ฟิลด์ที่ถูกเปลี่ยนชื่อ** `endonym` แทนที่ `nativeName` · `codeAliases` แทนที่ `aliases` · `scripts[]` (สคริปต์ที่ได้รับการรับรองทั้งหมด) แทนที่ `script` แบบแบน โดยสคริปต์หลักจะถูกดึงมาจากแท็ก BCP 47 สูงสุดของการ์ด · `endangerment` (การประเมินของทุกแหล่งข้อมูล ตามมาตราส่วนของแหล่งข้อมูลนั้นเอง) แทนที่ออบเจ็กต์ `vitality` เดี่ยว · `isoLanguageType` และ `isoScope` ตอนนี้ใช้คำของ ISO 639-3 เอง ("Living", "Macrolanguage") แทนที่จะเป็นตัวย่อ ฟิลด์ใหม่: `modality` ("spoken"/"signed" ดึงมาจากสายวิวัฒนาการของ Glottolog), `glottologBucket` (กลุ่มที่ไม่ใช่เชิงลำดับวงศ์ตระกูลของ Glottolog ซึ่งถูกแยกออกจากช่อง family), `locale`/`localeScoped`

3. **ฟิลด์ที่ไม่ได้รับการยืนยันจะถูกละเว้น ไม่ใช่ null** ฟิลด์ที่ไม่มีแหล่งข้อมูลใดยืนยันจะหายไปจากการ์ด กฎก่อนหน้านี้ ("การ์ดทุกใบต้องมีฟิลด์ระดับบนสุดทุกฟิลด์ แม้ว่าจะเป็น null") ถูกยกเลิกแล้ว: ค่าว่างบนพื้นผิวสาธารณะจะถูกตีความว่าเป็นการอ้างว่าไม่มีอะไรให้รู้ ซึ่งไม่เหมือนกับการยังไม่ได้ค้นหา

4. **มี Locale card อยู่จริง** ควบคู่ไปกับ language card การฉายข้อมูลโลแคล (locale projections) (`fra-CA`, `cmn-Hant`) จะนำข้อเท็จจริงของภาษาที่ถูกแปลงสำหรับดินแดนหรือสคริปต์ ซึ่งระบุโดยบล็อก `locale: {language, region, script}` โลแคลไม่ใช่ภาษา: ให้แยกโลแคลออกจากการนับจำนวนภาษาโดยใช้บล็อกนั้น

## หลักการออกแบบ

1. **อ้างอิงแหล่งที่มาทุกอย่าง** การกล่าวอ้างข้อเท็จจริงทุกอย่างต้องสืบย้อนไปถึงแหล่งข้อมูลปฐมภูมิที่มีการระบุชื่อและเวอร์ชัน การกล่าวอ้างที่ไม่มีแหล่งที่มาคือการกล่าวอ้างที่ตรวจสอบไม่ได้ แมป `_fieldSources` (และคำอธิบายประกอบ `source` ต่อฟิลด์ในออบเจ็กต์ย่อย) ทำให้แหล่งที่มามีความชัดเจน

2. **รักษาความขัดแย้งไว้** เมื่อผู้มีอำนาจตัดสินใจไม่ตรงกัน (แหล่งหนึ่งบอกว่ามีผู้พูด 50,000 คน อีกแหล่งบอกว่า 20,000 คน) การ์ดจะเก็บ *ทั้งสองค่า* พร้อมระบุแหล่งที่มา — ตามรูปแบบซองข้อมูลด้านบน เราจะไม่หาค่าเฉลี่ย แก้ไข หรือเลือกข้าง ผู้ใช้สามารถสำรวจความแตกต่างนี้ได้เอง

3. **การหายไปหมายถึงไม่ได้รับการยืนยัน** ฟิลด์ที่หายไปหมายความว่าไม่มีแหล่งข้อมูลใดยืนยันค่า เมื่อคุณสมบัติใดไม่สามารถนำมาใช้ได้อย่างแท้จริง (เช่น เพศทางไวยากรณ์สำหรับภาษาที่ไม่มีสิ่งนี้) ค่าที่อ้างอิงจะระบุไว้อย่างชัดเจนแทนที่จะปล่อยว่างไว้

4. **รีบิลด์ ไม่เคยแพตช์** การ์ดถูกฉายจากแหล่งข้อมูลที่ปักหมุดไว้โดยการบิลด์แบบกำหนดได้ (deterministic build) ข้อบกพร่องของข้อเท็จจริงจะถูกแก้ไขที่ตัวจัดการแหล่งข้อมูล (source handler) และคลังข้อมูลจะถูกรีบิลด์ — ไม่มีการแก้ไขในตำแหน่งเดิม (in-place edits) ไม่มีการเพิ่มข้อมูลแบบผสานอย่างเดียว (merge-only enrichment layer)

| ชั้น | ตำแหน่ง | วัตถุประสงค์ |
|-------|----------|---------|
| **การ์ดภาษา** | `shared/language-cards/<code>.json` | การกำหนดค่าต่อภาษา: อัตลักษณ์ การจำแนก ทรัพยากร และทุกอย่าง |

## โมเดลการสืบทอด

> **ส่วนใหญ่เป็นประวัติศาสตร์ตั้งแต่การรีบิลด์ atlas** ไม่มี language card บนดิสก์ใดที่มี `extends` อีกต่อไป — การ์ดทุกใบถูกสร้างขึ้นอย่างสมบูรณ์โดยการบิลด์ เนื่องจากข้อความที่สืบทอดมาไม่สามารถอ้างอิงได้ (การกล่าวอ้างระดับตระกูลภาษาใช้ที่อยู่ระดับภาษา) กลไกนี้ยังคงอยู่เพียงแห่งเดียว: ออฟไลน์บันเดิลของแพ็กเกจ npm จะจัดส่ง locale card เป็น `extends` เดลต้าขนาดกะทัดรัดเทียบกับภาษาของมัน ซึ่งถูกแปลงโดยการผสานแบบเดียวกับที่อธิบายไว้ที่นี่

เมื่อการ์ดกำหนด `"extends": "family-dravidian"` รันไทม์จะรวมการ์ดหลัก
เข้ากับการ์ดลูกโดยใช้ `_deepMerge()` (ใน `lib/registers.js`) ซึ่งช่วยให้
การ์ด genus กำหนด register ที่ใช้ร่วมกัน ระบบความเป็นทางการ และแนวทางเรื่องเพศ
ที่ส่งต่อไปยังภาษาสมาชิกทั้งหมด โดยไม่ต้องทำซ้ำข้อมูลในการ์ดแต่ละใบหลายร้อยใบ

### ความหมายของการรวม

| ค่าของการ์ดลูก | พฤติกรรม | เหตุผล |
|-------------|----------|-----|
| `null` | สืบทอดจากการ์ดหลัก | `null` หมายถึง "ฉันไม่ได้กำหนดค่านี้" — ค่าของการ์ดหลักจะถูกนำมาใช้ |
| ไม่ใช่ null | แทนที่การ์ดหลัก | ข้อมูลของการ์ดลูกเฉพาะเจาะจงกว่า — มีความสำคัญสูงกว่า |
| ออบเจกต์ซ้อน | รวมแบบเรียกซ้ำ | ฟิลด์ของการ์ดลูกแทนที่ ฟิลด์ของการ์ดหลักถูกเก็บไว้ |
| อาร์เรย์ | แทนที่ทั้งหมด | อาร์เรย์ไม่รวมทีละรายการ — อาร์เรย์ของการ์ดลูกชนะ |

### ฟิลด์อัตลักษณ์ (ไม่สืบทอดเด็ดขาด)

ฟิลด์บางฟิลด์เป็นของการ์ดนั้นเองและต้องไม่สืบทอดจากการ์ดหลักเด็ดขาด:

```
code, extends, _migration, aliases, iso639_1, iso639_3
```

แม้ว่าการ์ดหลักจะกำหนด `aliases: ["macro-code"]` การ์ดลูกจะไม่
สืบทอด alias เหล่านั้น ฟิลด์เหล่านี้เป็นค่าของการ์ดลูกเสมอ (รวมถึง
`null` หากไม่ได้กำหนดไว้)

**เหตุผล:** หากไม่มีกฎนี้ ภาษา Cree ทุกภาษาจะสืบทอด `aliases: ["cre"]`
จากการ์ดหลัก macrolanguage ทำให้ทุกสำเนียงกลายเป็น alias ของ macro

### ตัวอย่าง: วิธีที่การ์ด Cree ถูก Resolve

```
┌───────────────────────┐
│  family-algic.json    │  formality: null, registers: null
│  (no registers)       │
└──────────┬────────────┘
           │ extends
┌──────────┴────────────┐
│  genus-cree.json      │  formality: { system: "obviative-animate", ... }
│  (sourced registers)  │  registers: { formal: {...}, informal: {...} }
└──────────┬────────────┘
           │ extends
┌──────────┴────────────┐
│  crk.json             │  code: "crk", extends: "genus-cree"
│  (Plains Cree)        │  formality: null → inherits from genus-cree
│                       │  registers: null → inherits from genus-cree
│                       │  script: "Cans"  → own value, no inheritance
│                       │  code: "crk"     → identity field, never inherited
└───────────────────────┘
```

ในรันไทม์ `getLanguageCard("crk")` จะคืนค่าออบเจกต์ที่รวมแล้วพร้อม register ของ genus-cree
+ คุณสมบัติของ family-algic (ถ้ามี) + อัตลักษณ์และ metadata ของ crk เอง

### เทมเพลตการ์ด Genus

การ์ด Genus อยู่ใน `shared/language-cards/genera/` และกำหนดคุณสมบัติที่ใช้ร่วมกัน
สำหรับกลุ่มภาษา โดยใช้ schema เดียวกับการ์ดปกติแต่มีข้อตกลงที่แตกต่างกัน:

```jsonc
{
  // Identity — genus cards use a prefixed code, NOT an ISO 639-3 code
  "code": "genus-cree",           // "genus-", "family-", or "macrolanguage-" prefix
  "name": "Cree Languages",      // Human-readable group name
  "extends": "family-algic",     // Genus cards can extend family cards (chaining)

  // Formality — shared across the group, sourced from typological databases
  "formality": {
    "system": "obviative-animate",
    "description": "Cree languages use an obviative/proximate system...",
    "default": "formal",
    "source": "WALS 37A, 38A + Wolfart 1973"
  },

  // Registers — shared presets, if the group shares a formality system
  "registers": {
    "formal": {
      "label": "Formal (Proximate)",
      "description": "...",
      "prompt": "...",
      "isDefault": true
    },
    "informal": {
      "label": "Informal",
      "description": "...",
      "prompt": "..."
    }
  },

  // Gender — shared grammatical gender behavior
  "gender": {
    "grammatical": false,       // Cree doesn't have grammatical gender
    "inclusiveGuidance": null   //   so no inclusive guidance needed
  },

  // Everything else is null — individual cards provide their own
  // classification, geography, resources, etc.
  "classification": null,
  "methodSupport": null,
  // ...
}
```

**กฎสำคัญ:** การ์ด Genus ต้องมีเฉพาะข้อมูลที่ใช้ร่วมกันจริงๆ ทั่วทั้งกลุ่ม
และอ้างอิงจากแหล่งข้อมูลที่น่าเชื่อถือเท่านั้น หากระบบความเป็นทางการแตกต่างกันระหว่างสมาชิก
ควรระบุในการ์ดแต่ละใบ ไม่ใช่ใน genus

## ตัวอย่างมาตรฐาน \{#canonical-template}

> **ถูกสร้างขึ้น ไม่ได้ถูกเขียน** ทุกอย่างในส่วนนี้ดึงมาจากคลังข้อมูลจริงในเวลาบิลด์: การ์ด `crk` (Plains Cree) แบบเต็ม แบบไบต์ต่อไบต์ บวกกับข้อความที่ตัดตอนมาจากโลแคล `fra-CA` เมื่อคลังข้อมูลถูกรีบิลด์ การบิลด์เว็บไซต์ครั้งต่อไปจะดึงข้อมูลหน้านี้ใหม่ ไม่มีเทมเพลตที่ดูแลด้วยมือเหลือให้ล้าสมัยอีกต่อไป — เทมเพลตก่อนหน้านี้คลาดเคลื่อนไปจากสคีมาของการ์ดถึงหนึ่งรุ่นเต็มและถูกยกเลิกไปเมื่อ 2026-08-16

ตัวอย่างแสดง **รูปแบบบนดิสก์ (on-disk shape)** — สิ่งที่คุณจะได้รับหากคุณเปิดไฟล์ ผู้ใช้งานยังคงควรอ่านการ์ดผ่านอะแดปเตอร์ที่เผยแพร่ (`normalizeCard()` ในแพ็กเกจ npm): มันจะแปลงซองข้อมูล เชื่อมโยงชื่อก่อนการเปลี่ยนผ่าน (pre-cutover) และดึงค่าสำหรับแสดงผลเท่านั้น (สคริปต์หลัก, ระดับความมีชีวิตชีวา) ซึ่งการ์ดดิบจงใจที่จะไม่เก็บไว้

สิ่งที่ควรสังเกตขณะอ่าน:

1. **ซองระบุที่มา (Attribution envelopes)** `name`, `classification.family`, `endangerment`, `speakerEstimates`, `endonym`, `bcp47FullTag` และ `politenessDistinction` แต่ละอันจะเก็บ `{agreement, consensus?, values: [{value, source}]}`, every value attributed to its source. `endangerment` มี `"agreement": "incommensurable"`: แหล่งข้อมูลของมันประเมินในมาตราส่วนที่แตกต่างกัน ดังนั้นแต่ละค่าจะระบุ `scale` ของตัวเองแทนที่จะถูกแปลงไปเป็นของผู้ชนะ

2. **การละเว้นหมายถึงไม่ได้รับการยืนยัน** การ์ดไม่มี `iso639_1` (Plains Cree ไม่มีรหัส ISO 639-1) และไม่มี `phonologicalInventory` (ไม่มีแหล่งข้อมูลที่นำเข้ามายืนยัน) — ฟิลด์เหล่านั้นจะหายไปเฉยๆ ไม่เคยเป็น `null` หรือ `[]`

3. **แหล่งที่มาคือเลเยอร์ระดับเฟิร์สคลาส** `_fieldSources` แมปทุกฟิลด์ไปยังแหล่งข้อมูลที่ยืนยันมัน โดยมี `champollion-derived-v1` ทำเครื่องหมายค่าที่ Champollion คำนวณ `_card` ประทับตราประเภทของการ์ด, id, การแก้ไข (revision) และฟิลด์ใดที่ช่องทางการแก้ไข (correction lane) สามารถแตะต้องได้; `_atlas` ประทับตราการเผยแพร่คลังข้อมูล

4. **ไม่มีผลลัพธ์การรัน (run results)** ไม่มีสิ่งใดบนการ์ดที่เป็นคะแนนที่วัดได้จากผลลัพธ์ของวิธีการ — chrF, อัตราการยอมรับ FST และสิ่งที่คล้ายกันคือผลลัพธ์การรันที่ถูกคีย์ด้วย (method, dataset, metric) และอยู่บนลีดเดอร์บอร์ด การ์ดเพียงแค่ยืนยันว่าทรัพยากร *มีอยู่จริง* (`resources`, `lexicalResources`, `methodSupport`)

### Locale card คือการฉายข้อมูล ไม่ใช่ภาษา \{#locale-card-example}

ข้างๆ language card จะมี locale card (`fra-CA`, `cmn-Hant`): ข้อเท็จจริงของภาษาที่ **ถูกแปลงสำหรับดินแดนหรือสคริปต์** ซึ่งระบุโดยบล็อก `locale` ของมัน — ไม่เคยระบุด้วยรูปแบบรหัส Locale card จะสืบทอดข้อเท็จจริงของภาษาของมัน แปลงข้อเท็จจริงที่อยู่ในขอบเขตของสคริปต์และดินแดน (`script`, `localeScoped`) และ **ไม่ใช่ภาษา**: ให้แยก locale card ออกจากการนับจำนวนภาษาทุกครั้งและรายการต่อภาษาโดยใช้บล็อก `locale` นั้น

## การอ้างอิงฟิลด์ (Field Reference) \{#field-reference}

มีธรรมเนียมปฏิบัติสองข้อที่ใช้กับทุกตารางด้านล่าง:

- **"envelope"** หมายถึงซองระบุที่มา (attribution envelope) — `{agreement, consensus?, values: [{value, source, note?, scale?}]}` — ซึ่งเก็บการกล่าวอ้างของ *ทุก* แหล่งข้อมูล ฟิลด์ที่ระบุว่าเป็น `envelope` อาจปรากฏเป็นค่าแบบแบนบนการ์ดที่มีเพียงแหล่งข้อมูลเดียวที่กล่าวถึง (ตัวอย่างเช่น languoid ที่มีเฉพาะใน Glottolog จะมี `name` แบบแบน); ผู้ใช้งานต้องจัดการทั้งสองแบบ ซึ่งเป็นสิ่งที่อะแดปเตอร์ที่เผยแพร่ทำ
- ไม่มีฟิลด์ใดที่จำเป็นนอกเหนือจาก `code` และ `name`; สิ่งอื่นๆ ทั้งหมดจะถูก **ละเว้นเมื่อไม่มีแหล่งข้อมูลใดยืนยัน** แหล่งข้อมูลที่ยืนยันของแต่ละฟิลด์จะถูกบันทึกต่อการ์ดใน `_fieldSources` ดังนั้นตารางจึงอธิบาย *ชนิด* ของแหล่งข้อมูลแทนที่จะปักหมุดเวอร์ชันซึ่งอาจคลาดเคลื่อนได้

### § 1. ฟิลด์อัตลักษณ์

| Field | Shape | Notes |
|-------|-------|-------|
| `code` | `string` | **จำเป็น** ID ของการ์ดและชื่อไฟล์ ISO 639-3 สำหรับ language card (`crk`); languoid ที่มีเฉพาะใน Glottolog จะใช้ glottocode ของมัน; locale card จะใช้รหัสโลแคล (`fra-CA`) |
| `name` | envelope | **จำเป็น** ชื่ออ้างอิงภาษาอังกฤษ (รีจิสทรี ISO 639-3, LinguaMeta, Glottolog) |
| `endonym` | envelope | แทนที่ `nativeName` สิ่งที่ผู้พูดเรียกภาษานั้น ในภาษานั้น (LinguaMeta, Wikidata) จะหายไปเมื่อไม่มีแหล่งข้อมูลใดยืนยัน — เราจะไม่ประดิษฐ์หรือทับศัพท์ชื่อเรียกตนเอง (endonym) เด็ดขาด |
| `alternateNames` | `string[]` | ชื่อภาษาอังกฤษอื่นๆ ที่ได้รับการรับรอง |
| `iso639_1` | `string` | ปรากฏเฉพาะเมื่อมีรหัส ISO 639-1 แบบสองตัวอักษร (`fra` → `"fr"`) |
| `isoScope` | `string` | คำของ ISO 639-3 เอง — `"Individual"`, `"Macrolanguage"`, `"Special"` (แทนที่ตัวย่อ `"I"`/`"M"`/`"S"`) |
| `isoLanguageType` | `string` | แทนที่ `isoType` คำของ ISO 639-3 เอง — `"Living"`, `"Extinct"`, `"Ancient"`, `"Historical"`, `"Constructed"` |
| `macrolanguage` | `string` | Macrolanguage ที่ภาษานี้สังกัดอยู่ (`crk` → `"cre"`) การแมป macrolanguage ของ ISO 639-3 |
| `macrolanguageMembers` | `string[]` | บนการ์ดศูนย์กลางของ macrolanguage: รหัสสมาชิกแต่ละตัว (`nor` → `["nno", "nob"]`) |
| `canonicalisedMembers` | envelope | บนการ์ด macrolanguage: สมาชิกที่แท็กของพวกเขารีจิสทรี BCP 47 พับรวมเข้ากับแท็กของ macrolanguage นี้ (ตารางนามแฝง CLDR + SIL langtags โดยแต่ละอันมีการระบุที่มา) |
| `supersededCodes` | `string[]` | รหัส ISO 639-3 ที่ถูกยกเลิกซึ่งตอนนี้ SIL ชี้มาที่ภาษานี้ — บันทึกไว้ที่ตัวสืบทอดเพื่อให้คลังข้อมูลที่เผยแพร่ภายใต้รหัสเก่ายังคงสามารถแปลงได้ |
| `codeAliases` | `string[]` | แทนที่ `aliases` ตัวระบุระดับรหัสที่แปลงมายังการ์ดนี้ |
| `bcp47` | `string` | แท็ก BCP 47 ของภาษาตามที่ได้รับการยืนยัน (LinguaMeta) |
| `bcp47Tag` | envelope | ดึงมาจาก Champollion: แท็ก RFC 5646 (รหัส ISO 639 ที่สั้นที่สุดชนะ) |
| `bcp47FullTag` | envelope | รูปแบบ ภาษา–สคริปต์–ภูมิภาค สูงสุด (CLDR likelySubtags + SIL langtags) อะแดปเตอร์จะดึง **สคริปต์หลัก** จากแท็กนี้ |
| `modality` | `string` | `"spoken"` หรือ `"signed"` ดึงมาจากสายวิวัฒนาการของ Glottolog การเขียนเป็นคุณลักษณะของอักขรวิธี ไม่ใช่รูปแบบ (modality) — ภาษาที่ไม่มีภาษาเขียนยังคงเป็นภาษาพูดหรือภาษามืออย่างสมบูรณ์ |
| `locale` | `object` | **เฉพาะ Locale card เท่านั้น** `{language, region, script, publishedTag, source, note}` — เอกลักษณ์ของโลแคล ให้แยก locale card ออกจากการนับจำนวนภาษาโดยใช้บล็อกนี้ ไม่เคยใช้รูปแบบรหัส |
| `localeScoped` | `object` | เฉพาะ Locale card เท่านั้น: ค่าที่ถูกแปลงสำหรับดินแดน/สคริปต์ของโลแคล (เช่น `scriptName`, `cldrOfficialStatus`) |

### § 2. ฟิลด์การจำแนกประเภท

| Field | Shape | Notes |
|-------|-------|-------|
| `glottocode` | `string` | ตัวระบุของ Glottolog สำหรับ languoid นี้ (`crk` → `"plai1258"`) languoid ที่มีเฉพาะใน Glottolog — ภาษาที่ Glottolog บันทึกไว้แต่ ISO 639-3 ไม่มี — จะใช้ glottocode เป็น `code` ของการ์ด |
| `classification` | `object` | คอนเทนเนอร์สำหรับฟิลด์การจัดวางด้านล่าง แต่ละฟิลด์มีแหล่งที่มาแยกกันและถูกละเว้นแยกกัน — ภาษาโดดเดี่ยว (isolate) หรือภาษาที่จัดอยู่ในกลุ่มของ Glottolog จะมีเพียงบางส่วนของออบเจ็กต์นี้อย่างถูกต้อง |
| `classification.family` | envelope | ตระกูลภาษาระดับบนสุดที่หน่วยงานจัดหมวดหมู่แต่ละแห่งยืนยัน Glottolog และ WALS เป็นอนุกรมวิธานที่แยกจากกันซึ่งไม่ตรงกันเสมอไป ดังนั้นจึงเก็บไว้ทั้งสองอย่างและระบุที่มา กฎ Lint R5 จะตรวจสอบค่า Glottolog ภายในซองข้อมูลเทียบกับทรีของ Glottolog เอง: WALS อาจไม่เห็นด้วยกับ Glottolog แต่ Glottolog จะต้องไม่ถูกอ้างอิงผิด ภาษาโดดเดี่ยวจะไม่มีตระกูลภาษาเลย |
| `classification.familyGlottocode` | `string` | Glottocode ของตระกูลภาษาระดับบนสุดนั้น (`crk` → `"algi1248"`) |
| `classification.genus` | `string` | โหนดการจัดหมวดหมู่ระดับกลางของ WALS (`crk` → `"Algonquian"`) เป็นแนวคิดของ WALS **ไม่ใช่** ของ Glottolog — Glottolog เผยแพร่ทรีที่มีความลึกตามอำเภอใจโดยไม่มีระดับสกุล (genus) — ดังนั้นจึงปรากฏเฉพาะในที่ที่ WALS เข้ารหัสภาษาไว้เท่านั้น |
| `classification.ancestry` | `string[]` | เส้นทางการสืบเชื้อสายของ Glottolog ในรูปแบบ glottocode ของบรรพบุรุษ โดยเริ่มจากราก (`["algi1248", …, "plai1264"]`) ลำดับ **คือ** การกล่าวอ้าง: นี่คือเส้นทาง ไม่ใช่ชุดข้อมูลที่เรียงตามตัวอักษร |
| `classification.glottologBucket` | `string` | กลุ่มที่ไม่ใช่เชิงลำดับวงศ์ตระกูลของ Glottolog — `"Artificial Language"`, `"Pidgin"`, `"Mixed Language"`, `"Speech Register"`, `"Unclassifiable"`, `"Unattested"` ถูกแยกออกจากช่อง family เนื่องจากกลุ่มจัดหมวดหมู่ตามชนิด ไม่ใช่การสืบเชื้อสาย: การ์ดที่มีกลุ่มจะไม่มีตระกูลภาษา และนั่นคือผลลัพธ์ที่ตรงไปตรงมา |
| `isIsolate` | `boolean` | ระบุว่า Glottolog จัดให้ภาษานี้เป็นภาษาโดดเดี่ยว (isolate) หรือไม่ |

การ์ดก่อนการเปลี่ยนผ่านยังมี `genusGlottocode` ด้วย มันถูกยกเลิกไปพร้อมกับข้อผิดพลาดของหมวดหมู่ที่สร้างมันขึ้นมา: สกุล (genus) เป็นแนวคิดของ WALS และการนำมันไปใส่ในตัวระบุของ Glottolog เป็นการยืนยันโหนดทรีที่ Glottolog ไม่มี ลำดับชั้นของ Glottolog จะถูกเก็บไว้ใน `ancestry` แทน

### § 3. ฟิลด์ภูมิศาสตร์

| Field | Shape | Notes |
|-------|-------|-------|
| `macroarea` | `string` | พื้นที่มหภาค (macroarea) ของ Glottolog — `"Africa"`, `"Australia"`, `"Eurasia"`, `"North America"`, `"Papunesia"` หรือ `"South America"` |
| `coordinates` | `object` | `{lat, lng}` — จุดตัวแทนของ Glottolog เป็นจุด ไม่ใช่ดินแดน: มันวางภาษาไว้บนแผนที่และไม่ได้กล่าวอ้างใดๆ เกี่ยวกับขอบเขตหรือพรมแดน |
| `countries` | `string[]` | รหัส ISO 3166-1 alpha-2 ของประเทศที่ Glottolog เชื่อมโยงกับภาษานั้น (`["CA", "US"]`) |
| `cldrOfficialStatus` | `string` | สถานะอย่างเป็นทางการที่บางดินแดนมอบให้กับภาษา ตามที่ CLDR บันทึกไว้ (นำมาผ่าน LinguaMeta) — `"Official"`, `"Regional official"` บน locale card สถานะที่ถูกแปลงสำหรับดินแดนของ *โลแคลนั้น* จะอยู่ใน `localeScoped.cldrOfficialStatus` |

อาร์เรย์ `regions` ก่อนการเปลี่ยนผ่าน (การแจกแจงผู้พูดต่อประเทศพร้อมรหัสผู้ดูแลระบบ) และ `arealContext` (การเป็นสมาชิก Sprachbund) ถูกยกเลิกแล้ว: ไม่มีแหล่งข้อมูลที่นำเข้ามายืนยันสิ่งเหล่านี้ และการคัดสรรที่ไม่มีแหล่งที่มาจะไม่สามารถอยู่รอดจากการรีบิลด์ได้ การกล่าวอ้างจำนวนผู้พูดระดับภูมิภาคสามารถกลับมาได้ในวันที่แหล่งข้อมูลที่อ้างอิงได้เข้าสู่ไปป์ไลน์; จนกว่าจะถึงตอนนั้น การหายไปคือสถานะที่ตรงไปตรงมา

### § 4. ฟิลด์ระบบการเขียน

| Field | Shape | Notes |
|-------|-------|-------|
| `scripts` | `string[]` | แทนที่ `script` แบบแบน รหัส ISO 15924 ที่ได้รับการรับรอง **ทั้งหมด** (`crk` → `["Cans", "Latn"]`) แบบไม่เรียงลำดับ — อย่าอ่าน `scripts[0]` ว่าเป็นสคริปต์ "หลัก" เด็ดขาด สคริปต์หลักจะถูกดึงโดยอะแดปเตอร์จากแท็กสูงสุดของ `bcp47FullTag` |
| `scriptNames` | `string[]` | ชื่อที่แสดงผลซึ่งดึงมาจาก Champollion สำหรับ `scripts[]` (`"Unified Canadian Aboriginal Syllabics"`) |
| `textDirection` | `string` | แทนที่ `dir` คำของแหล่งข้อมูลเอง — `"left-to-right"` / `"right-to-left"` (เคยเป็น `"ltr"`/`"rtl"`) |
| `suppressScript` | `string` | CLDR Suppress-Script: สคริปต์ที่เป็นมาตรฐานสำหรับภาษาจนแท็ก BCP 47 ละเว้นมัน (`fra` → `"Latn"`) |
| `script` | `string` | **เฉพาะ Locale card เท่านั้น**: สคริปต์ที่ถูกแปลงตามโลแคล (`fra-CA` → `"Latn"`, `cmn-Hant` → `"Hant"`) Language card จะไม่มีฟิลด์สคริปต์แบบแบน |

ภาษาที่ไม่มีภาษาเขียนที่ได้รับการรับรองจะ **ไม่มีฟิลด์ `scripts`** — การหายไปหมายความว่าไม่มีแหล่งข้อมูลใดยืนยันสคริปต์ ไม่ใช่การอ้างว่าภาษานั้น "ไม่มีภาษาเขียน" (ภาษามือเป็นกลุ่มที่ใหญ่ที่สุดในลักษณะนี้: ไม่มีระบบสัญลักษณ์ใดที่ได้รับการยอมรับเป็นมาตรฐานชุมชนสำหรับการรู้หนังสือในชีวิตประจำวัน)

### § 5. ฟิลด์ข้อมูลประชากรและความมีชีวิตชีวา

| Field | Shape | Notes |
|-------|-------|-------|
| `speakerEstimates` | envelope | การประมาณการของทุกแหล่งข้อมูล พร้อมระบุที่มา ค่าอาจเป็นจำนวนที่แน่นอนหรือสตริงช่วงของแหล่งข้อมูลเอง (`"10000-99999"`) โดยมีข้อควรระวังของแหล่งข้อมูลถูกยกมาแบบคำต่อคำใน `note` `"agreement": "conflicting"` เป็นเรื่องปกติ — การแสดงความขัดแย้ง *คือ* ผลิตภัณฑ์; ไม่มีการหาค่าเฉลี่ยหรือเลือกค่าใดค่าหนึ่ง |
| `endangerment` | envelope | แทนที่ออบเจ็กต์ `vitality` เดี่ยว การประเมินของทุกแหล่งข้อมูล **ตามมาตราส่วนของแหล่งข้อมูลนั้นเอง** — แต่ละค่าจะมีฟิลด์ `scale` และ `"agreement": "incommensurable"` เป็นเรื่องปกติเนื่องจากคำศัพท์ของ ELCat, Glottolog AES และ LinguaMeta ไม่ใช่คำแปลของกันและกัน อะแดปเตอร์จะดึง *ระดับความมีชีวิตชีวา (vitality tier)* สำหรับแสดงผลหนึ่งค่าจากแหล่งข้อมูลที่ระบุชื่อเดียวตามลำดับความน่าเชื่อถือที่ประกาศไว้; ระดับนั้นมีไว้สำหรับแสดงผลเท่านั้น — ชุดข้อมูลที่ระบุที่มาทั้งหมดจะยังคงอยู่บนการ์ด |

จำนวนผู้พูดที่ *แสดงผล* ที่ใดก็ตามใน Champollion จะต้องตรงกับหนึ่งในรายการ `speakerEstimates` ที่อ้างอิง หรือมีแหล่งที่มา `champollion-derived` ที่ชัดเจน — บังคับใช้โดยกฎความสมบูรณ์ของการ์ด (card-integrity rules)

### § 5.5 ฟิลด์เอกสารและการปรากฏตัวในโลกดิจิทัล

| Field | Shape | Notes |
|-------|-------|-------|
| `documentation` | `object` | แทนที่ `documentationDepth` บันทึกของ Glottolog ว่าภาษานี้ได้รับการอธิบายไว้ดีเพียงใด ในคำศัพท์ของ Glottolog เอง |
| `documentation.medLevel` | `string` | ระดับคำอธิบายที่ครอบคลุมที่สุด (Most Extensive Description) ของ Glottolog แบบคำต่อคำ — `"long grammar"`, `"grammar"`, `"grammar sketch"`, `"phonology"`, `"wordlist"` |
| `documentation.medSourceId` | `string` | คีย์บรรณานุกรมของคำอธิบายที่ครอบคลุมที่สุดนั้นในแคตตาล็อกอ้างอิงของ Glottolog |
| `documentation.firstDocumented` | `number` | คอลัมน์ปีแรกของการจัดทำเอกสารของ Glottolog เอง แบบคำต่อคำ — ย้ายมาที่นี่จากฟิลด์ระดับบนสุดก่อนการเปลี่ยนผ่าน ปรากฏในภาษาเพียงไม่กี่ร้อยภาษา และความเบาบางนี้ก็เป็นสิ่งที่ควรค่าแก่การรับรู้ |
| `documentation.lastDocumented` | `number` | คอลัมน์ปีล่าสุดของการจัดทำเอกสารของ Glottolog แบบคำต่อคำ — ปรากฏในภาษาประมาณหนึ่งพันภาษา |
| `wikipediaEdition` | `object` | แทนที่ `digitalPresence` `{site, url, name}` — มี Wikipedia ฉบับเปิดในภาษานี้ (`afr` → `af.wikipedia.org`) มีอยู่เท่านั้น จงใจ **ไม่มีการนับจำนวนบทความ**: หลายฉบับส่วนใหญ่สร้างโดยบอท และฉบับที่ใหญ่ไม่ได้ "มีเอกสารประกอบดีกว่า" ฉบับที่เล็กในแง่ที่นักแปลสามารถนำไปใช้ได้ |
| `dialectCount` | `number` | คอลัมน์ `child_dialect_count` ของ Glottolog เอง แบบคำต่อคำ — เฉพาะภาษาถิ่นย่อยโดยตรงเท่านั้น ไม่ใช่ทั้งซับทรี นี่คือการยืนยันของ Glottolog ไม่ใช่การคำนวณของเรา: กฎก่อนหน้านี้ประทับตรามันเป็น `champollion-derived` และทำให้การ์ดหลายพันใบรับเครดิตสำหรับการนับของ Glottolog |

ส่วนที่เหลือของบล็อก `digitalPresence` ก่อนการเปลี่ยนผ่าน (ชั่วโมงของ Common Voice, จำนวนประโยคของ Tatoeba) ถูกยกเลิกจนกว่าแหล่งข้อมูลเหล่านั้นจะเข้าสู่ไปป์ไลน์ — คลังข้อมูล Tatoeba เองปรากฏในที่ที่มันควรอยู่แล้ว ในฐานะคลังข้อมูลคู่ขนานภายใต้ `resources.corpora` (§ 9)

### § 6. ฟิลด์ความเป็นทางการ Register และเพศ

คลังข้อมูลที่ถูกฉายจะมีเพียงหนึ่งฟิลด์ที่นี่ — ข้อเท็จจริงที่อ้างอิง:

| Field | Shape | Notes |
|-------|-------|-------|
| `politenessDistinction` | envelope | ระบุว่าภาษามีการสร้างไวยากรณ์ความสุภาพในรูปแบบบุรุษที่สองหรือไม่ ระบุที่มาข้าม Grambank GB415 (ไบนารี: ไม่มี/มี) และ WALS 45A (สี่ระดับ: ไม่มีความแตกต่าง / ไบนารี / หลายระดับ / หลีกเลี่ยงสรรพนาม) สิ่งเหล่านี้เป็นมาตราส่วนที่แตกต่างกัน ดังนั้นแต่ละค่าจะระบุ `scale` ของตัวเอง และซองข้อมูลจะรายงานว่าพวกมัน **ไม่สามารถเปรียบเทียบกันได้ (incommensurable)** แทนที่จะเป็นความขัดแย้ง |

**ระบบรีจิสเตอร์คือการกำหนดค่า ไม่ใช่ข้อเท็จจริงของการ์ด** คลังข้อมูลก่อนการเปลี่ยนผ่านเก็บข้อความ `formality` และพรอมต์ `registers` ไว้ในการ์ดเกือบหนึ่งพันแปดร้อยใบ — เกือบทั้งหมดถูกสร้างขึ้นจากสองแหล่งข้อมูลเดียวกันด้านบน จากนั้นถูกนำมาใช้ราวกับว่าเป็นการกำหนดค่าที่คัดสรรด้วยมือ atlas จะเก็บข้อเท็จจริงไว้; พื้นผิวการกำหนดค่า — `formality`, `registers`, `gender`, `codeSwitching` — ยังคงเป็นส่วนหนึ่งของ **สคีมาที่คัดสรรของแพ็กเกจ npm** (`language-card.schema.json`) อยู่บนการ์ดศูนย์กลางสกุล/ตระกูลภาษาที่คัดสรรมา และเข้าถึง CLI ผ่านการผสาน `extends` ของระบบรีจิสเตอร์ที่อธิบายไว้ใน [โมเดลการสืบทอด (Inheritance Model)](#inheritance-model) พวกมันไม่ใช่ฟิลด์ atlas ที่ถูกฉาย: ไม่มีการ์ดใดในคลังข้อมูลที่ถูกฉายที่มีพวกมัน และการบิลด์ atlas จะไม่มีวันเขียนพวกมัน คำแนะนำใน [การเขียนพรีเซ็ตรีจิสเตอร์ที่ดี (Writing Good Register Presets)](#writing-good-register-presets) นำไปใช้กับช่องทางที่คัดสรรนั้น

### § 7. ฟิลด์โปรไฟล์ทางภาษาศาสตร์

| Field | Shape | Notes |
|-------|-------|-------|
| `typologicalProfile` | `object` | หนึ่งคีย์ต่อคุณลักษณะทางแบบแผนภาษา (typological feature) ที่นำเข้า แต่ละค่าคือการเข้ารหัสของแหล่งข้อมูลเอง แต่ละคีย์จะปรากฏเฉพาะในที่ที่แหล่งข้อมูลเข้ารหัสภาษานี้ ค่าบูลีนมาจากคุณลักษณะของ Grambank สตริงหมวดหมู่มาจากบทของ WALS; รีจิสทรีการตัดสินใจจะระบุพารามิเตอร์ต้นทางที่แน่นอนสำหรับทุกคีย์ |
| `phonologicalInventory` | `object` | `{consonants, vowels, tones, totalPhonemes, hasTone}` — จำนวนที่คำนวณโดย Champollion จากคลังข้อมูล PHOIBLE ที่อ้างอิง (PHOIBLE เผยแพร่หนึ่งแถวต่อเซกเมนต์และไม่ยืนยันจำนวน) ดังนั้นทุกค่าจะมีแหล่งที่มา `champollion-derived` **PHOIBLE เป็นผู้มีอำนาจเรื่องเสียงวรรณยุกต์เพียงผู้เดียว** (lint R1): Grambank ไม่มีคุณลักษณะเสียงวรรณยุกต์ และไม่มีสิ่งอื่นใดบนการ์ดที่สามารถอ้างสิทธิ์เรื่องเสียงวรรณยุกต์ได้ |
| `numeralSystem` | `object` | `{base}` — ฐานตัวเลข แบบคำต่อคำจาก *Numeral Systems of the World's Languages* ของ Chan (`"decimal"`, `"quinary-vigesimal"`, `"body tally"`; มีค่าที่แตกต่างกันเกือบร้อยค่า) จะหายไปเมื่อคอลัมน์ฐานของ Chan เองว่างเปล่า — ประมาณครึ่งหนึ่งของภาษาที่สำรวจ — เนื่องจากตัวสร้างก่อนหน้านี้เติมช่องว่างด้วย `"decimal"` และประดิษฐ์ค่าสำหรับสองพันภาษา |
| `pluralCategories` | `string[]` | หมวดหมู่พหูพจน์เชิงจำนวน (cardinal plural categories) ที่ CLDR ระบุสำหรับภาษานี้ — Arabic แยกความแตกต่าง `["zero", "one", "two", "few", "many", "other"]`, French มีสามหมวดหมู่, Chinese มีหนึ่งหมวดหมู่ อ่านจากคีย์ของชุดกฎของ CLDR เอง ดังนั้นจึงเป็นการกล่าวอ้างของ CLDR ไม่ใช่การดึงข้อมูลของเรา แทนที่ `rules.plurals.categories` ก่อนการเปลี่ยนผ่าน; ไปป์ไลน์ i18n จำเป็นต้องใช้มันเพื่อให้รู้ว่าข้อความต้องมีรูปแบบพหูพจน์กี่รูปแบบ |

คีย์ `typologicalProfile` ที่ถูกฉายในปัจจุบัน พร้อมพารามิเตอร์ต้นทาง:

- **บทของ WALS** (สตริงหมวดหมู่, ป้ายกำกับค่าของ WALS เอง): `fusion` (20A), `verbSynthesis` (22A), `affixPreference` (26A), `reduplication` (27A), `genderCount` (30A), `caseCount` (49A), `wordOrder` (81A), `subjectVerbOrder` (82A), `verbalAlignment` (100A), `negationOrder` (143A)
- **คุณลักษณะของ Grambank** (บูลีน): `hasGenderInPronouns` (GB030), `hasSexBasedGender` (GB051), `hasNumeralClassifiers` (GB057), `hasCoreCase` (GB070), `hasObliqueCase` (GB071), `marksPastTense` (GB083), `marksPresentTense` (GB084)

บล็อก `linguisticChallenges` และ `contactInfluences` ก่อนการเปลี่ยนผ่านจะไม่ถูกฉาย — ข้อความที่ผ่านการวิจัยโดยไม่มีแหล่งข้อมูลที่นำเข้าจะยังคงอยู่ในสคีมาที่คัดสรรของแพ็กเกจ npm เช่นเดียวกับพื้นผิวรีจิสเตอร์ใน § 6 (ตาราง [ประเภทอิทธิพลจากการติดต่อ (Contact Influence Types)](#contact-influence-types) ด้านล่างให้บริการช่องทางนั้น) บล็อก `rules` ถูกยกเลิกแล้ว: สิ่งที่สามารถอ้างอิงได้ในนั้นจะยังคงอยู่เป็น `pluralCategories` ที่นี่และฟิลด์สคริปต์ใน § 4

### § 8. ฟิลด์สารานุกรม

ยกเลิกจากการ์ดแล้ว บล็อก `encyclopedic` (บทความประวัติศาสตร์และภาษาถิ่น, ลิงก์สถาบัน), `culturalAphorism` และ `varieties` ก่อนการเปลี่ยนผ่านเป็นข้อความที่คัดสรรด้วยมือในระดับการ์ด ซึ่งการรีบิลด์จะลบออกตามการออกแบบ ข้อเท็จจริงเกี่ยวกับการเป็นสมาชิกที่ `varieties` ชี้ให้เห็น ตอนนี้เป็นฟิลด์เอกลักษณ์ที่อ้างอิงแล้ว (§ 1 `macrolanguageMembers` และ `canonicalisedMembers`) และความครอบคลุมของเครื่องมือต่อความหลากหลายจะได้รับคำตอบจากการ์ดของสมาชิกแต่ละรายเอง (`methodSupport`, `resources`) คำกล่าวที่เป็นตัวแทนอาจกลับมาผ่านช่องทางการมีส่วนร่วมของชุมชนพร้อมความยินยอมและการอ้างอิง; มันจะไม่กลับมาเป็นฟิลด์การ์ดที่ไม่มีการอ้างอิง

### § 9. ฟิลด์ทรัพยากรดิจิทัล

ทุกอย่างในส่วนนี้ยืนยัน **การมีอยู่และความสามารถ ไม่เคยยืนยันคุณภาพ**: ว่าทรัพยากรได้รับการเผยแพร่และใครเป็นผู้เผยแพร่ — ไม่เคยยืนยันว่ามันดี สมบูรณ์ หรือใช้งานได้ และไม่เคยเป็นคะแนนที่วัดได้ คะแนนที่วัดได้ใดๆ ของผลลัพธ์วิธีการคือผลลัพธ์การรันที่ถูกคีย์ด้วย (method, dataset, metric) อยู่บนลีดเดอร์บอร์ด และถูกห้ามบนการ์ด (lint R3)

| Field | Shape | Notes |
|-------|-------|-------|
| `resources` | `object` | คอนเทนเนอร์: แต่ละฟิลด์ย่อยด้านล่างเป็นรายการที่มีแหล่งที่มาแยกกัน จะถูกละเว้นเมื่อไม่มีแหล่งข้อมูลใดยืนยัน |
| `resources.fsts` | `object[]` | ตัววิเคราะห์สัณฐานวิทยาแบบ finite-state ที่เผยแพร่: `{name, url, publisher, license, licenceEstablished, archived}` ใบอนุญาตจะเดินทางไปพร้อมกับแต่ละรายการแทนที่จะถูกสันนิษฐานว่าเหมือนกันทั่วทั้งแคตตาล็อก — ขอบเขตของใบอนุญาตต้องการข้อกำหนดที่แท้จริง สำหรับภาษาที่มีการผสานคำ (polysynthetic language) FST มักจะเป็นการตรวจสอบโครงสร้างเพียงอย่างเดียวที่มีอยู่ |
| `resources.corpora` | `object[]` | คลังข้อมูลคู่ขนานที่รับรองภาษานี้: `{corpus, corpusId, pairCount, topPartners, alignmentPairsTotal, …}` ระบุผ่าน **คู่ (pairs)** เนื่องจากคลังข้อมูลคู่ขนานรับรองภาษาผ่านคู่เท่านั้น — "ครอบคลุม Swahili" โดยไม่บอกว่าเทียบกับอะไร เป็นการตอบคำถามที่ไม่มีใครถาม การมีอยู่และขนาด ไม่เคยเป็นคุณภาพ |
| `resources.monolingualCorpora` | `object[]` | คลังข้อมูลภาษาเดียว — แยกจาก `corpora` เพื่อให้ "มีคลังข้อมูล" ไม่เคยหมายถึงสองสิ่งที่ไม่สามารถเปรียบเทียบกันได้ |
| `resources.speech` | `object[]` | ทรัพยากรเสียงพูดที่เผยแพร่ การมีอยู่เท่านั้น |
| `resources.keyboards` | `object[]` | เลย์เอาต์แป้นพิมพ์ที่เผยแพร่ เรียบง่ายแต่สำคัญ: สำหรับอักขรวิธีที่ต้องการตัวอักษรที่ไม่มีเลย์เอาต์มาตรฐานใดสร้างได้ เลย์เอาต์คือความแตกต่างระหว่างภาษาที่พิมพ์ได้กับพิมพ์ไม่ได้ |
| `resources.typology` | `object[]` | ชุดข้อมูลทางแบบแผนภาษาที่ *เข้ารหัส* ภาษานี้ พร้อมขอบเขต: `{dataset, featuresCoded, datasetFeatureTotal}` การมีอยู่และขอบเขต ไม่เคยเป็นเนื้อหา — สิ่งที่คุณลักษณะบอกจะอยู่นอกการ์ดจนกว่าจะมีคนเขียนแมปพารามิเตอร์ที่ยอมรับมัน (สิ่งที่ยอมรับจะปรากฏใน `typologicalProfile` ของ § 7) จำนวนคุณลักษณะคือการคำนวณของเรา ดังนั้นพวกมันจึงมีแหล่งที่มา `champollion-derived` |
| `lexicalResources` | `object` | คอนเทนเนอร์สำหรับข้อเท็จจริงการมีอยู่ของคำศัพท์ |
| `lexicalResources.datasets` | `object[]` | รายการคำศัพท์ที่เผยแพร่พร้อมความครอบคลุม: `{dataset, forms, concepts, release}` |
| `lexicalResources.dictionaries` | `object[]` | พจนานุกรมที่เผยแพร่ — การมีอยู่ ไม่เคยเป็นคุณภาพ และ **มีทิศทาง** ตามที่ผู้เผยแพร่กำหนด: พจนานุกรมที่ไปทางหนึ่งเป็นทรัพยากรที่แตกต่างจากพจนานุกรมที่ไปอีกทางหนึ่ง รายการไม่มีรูปแบบที่เหมือนกัน (ชุดข้อมูล CLDF รู้จำนวนรายการของมัน; พื้นที่เก็บข้อมูลรู้คู่และทิศทางของมัน); แต่ละรายการระบุแหล่งที่มาของตัวเอง และใบอนุญาตและสถานะการเก็บถาวรจะเดินทางไปพร้อมกับแต่ละรายการ |
| `lexicalResources.colexificationConcepts` / `colexifyingForms` | `number` | จำนวนที่คำนวณโดย Champollion จาก CLICS³: แนวคิดที่ได้รับการรับรองสำหรับภาษานี้ และรูปแบบที่แมปกับแนวคิดที่แตกต่างกันสองแนวคิดขึ้นไป `champollion-derived` |
| `methodSupport` | `object` | วิธีการแปลใดที่ครอบคลุมภาษานี้ — ความสามารถ ไม่เคยเป็นคะแนน รูปแบบ: `{total, byTier, named, truncated}` ภาษาอังกฤษมีขอบวิธีการ (method edges) หลายพันรายการและภาษามัธยฐานมีสองสามโหล ดังนั้นการ์ดจึงเก็บ *รูปแบบ* ของหลักฐาน — `total` บวกจำนวน `byTier` ต่อระดับความเชื่อมั่น (`fetched`, `partially-confirmed`, `model-card-declared`) — และระบุชื่อเฉพาะรายการที่แข็งแกร่งที่สุด (แต่ละ `{value, variant, source, confidence}`) โดยมีการจำกัดจำนวน **บริการ (services)** ของรีจิสทรีจะถูกระบุชื่อเต็มเสมอ เหนือขีดจำกัด ดังนั้นการหายไปของบริการจาก `named` จึงเป็นคำตอบที่แท้จริง; การหายไปของรายการ model-card หมายความว่า "ไม่ได้อยู่ในกลุ่มที่แข็งแกร่งที่สุด" เท่านั้น และทุกขอบยังคงสามารถสืบค้นได้ในที่เก็บ atlas |
| `metricModelSupport` | envelope | โมเดลเมตริกการประเมินที่เผยแพร่ความครอบคลุมของภาษานี้ พร้อมตัวระบุโมเดลที่ harness โหลด (`masakhane/africomet-mtl`) ขับเคลื่อนพฤติกรรมจริง — การเลือกโมเดล COMET — และยังคงเป็นความสามารถ ไม่เคยเป็นคะแนน |

**พับรวมเข้ากับฟิลด์ด้านบน:** `keyboardSupport` ก่อนการเปลี่ยนผ่าน (→ `resources.keyboards`), `corpusAvailability` (→ `resources.corpora` / `resources.monolingualCorpora`) และ `databaseCoverage` (→ `resources.typology` บวก `lexicalResources` — รายการฐานข้อมูลตอนนี้เป็นข้อเท็จจริงความครอบคลุมที่อ้างอิงพร้อมขอบเขต ไม่ใช่บูลีน)

**ยกเลิกจากการ์ดแล้ว:** `omt1600`, `evalDatasets`, `pipelineReadiness` และ `metricPlugins` — ไม่มีสิ่งใดได้รับการยืนยันโดยแหล่งข้อมูลที่นำเข้า และระดับความพร้อมคือการตัดสิน ไม่ใช่การอ้างอิง

**คัดสรร ไม่ได้ถูกฉาย:** พื้นผิวการประกาศมาตรฐานการประเมิน (`evalStandard`, `evalMetrics`, `evalPack`) จะยังคงอยู่ในสคีมาที่คัดสรรของแพ็กเกจ npm พวกมันบอก harness การประเมินว่าแพ็กเกจผู้ตัดสินภายนอกใดให้คะแนนภาษา (ผู้ตัดสิน ไม่ใช่ผู้เข้าแข่งขัน — แกนหลักของ harness ไม่มีโค้ดผู้ให้คะแนนเฉพาะภาษา); harness จะอ่านพวกมันจากการ์ดเมื่อมีอยู่ แต่ไม่มีการ์ดใดในคลังข้อมูลที่ถูกฉายในปัจจุบันที่มีพวกมัน และการบิลด์ atlas จะไม่เขียนพวกมัน เช่นเดียวกันกับบล็อก `install` ที่ตัวติดตั้ง FST ของ harness อ่านจากรายการ `resources.fsts[]` (`get_fst_install_info()` ใน `language_cards.py`): รายการที่ถูกฉายจะมีเฉพาะข้อเท็จจริงการมีอยู่เท่านั้น

### § 10. ฟิลด์แหล่งที่มา

| Field | Shape | Notes |
|-------|-------|-------|
| `_fieldSources` | `object` | บนการ์ดทุกใบ แมปทุกเส้นทางฟิลด์บนการ์ด (`"classification.family"`, `"coordinates.lat"`) ไปยัง id แหล่งข้อมูลที่เรียงลำดับซึ่งยืนยันมัน (`["glottolog-v5.3", "wals-v2020.5"]`) ค่าที่ Champollion คำนวณจะมี `champollion-derived-v1` id แหล่งข้อมูลมีการระบุเวอร์ชัน — `grambank-v1.0.3`, `iso639-3-20260715` — ดังนั้นทุกการกล่าวอ้างจะสืบย้อนไปถึงรุ่นที่แน่นอนที่สร้างมันขึ้นมา |
| `coverage` | `object` | บนการ์ดทุกใบ และ **คำนวณโดยโปรเจ็กเตอร์ ไม่ได้รับการยืนยันโดยแหล่งข้อมูลใด**: `{sourceCount, componentsPresent, componentsTotal, notAttested}` — มีแหล่งข้อมูลที่แตกต่างกันกี่แห่งที่กล่าวถึงภาษานี้, มีส่วนประกอบของการ์ดกี่ส่วนที่มีค่าจากจำนวนทั้งหมดที่มีให้เติม, และมีกี่ค่าที่แหล่งข้อมูลบันทึกในเชิงบวกว่า *หายไป* (ค้นหาแล้วบอกว่าไม่มี — เป็นข้อเท็จจริงที่แตกต่างจากการไม่เคยค้นหา) นี่คือสิ่งที่ทำให้การ์ดที่บางสามารถบอกได้ว่า **ทำไม** มันถึงบางแทนที่จะดูเหมือนถูกละเลย |
| `_card` | `object` | ข้อมูลเมตาของการ์ดเอง: `{type, id, revision, correctableFields}` `type` คือ `"language"` หรือ `"locale"` (การ์ด method และ corpus ใช้โปรเจ็กเตอร์เดียวกัน); `revision` คือแฮชเนื้อหา ดังนั้นการเปลี่ยนแปลงใดๆ ในเนื้อหาของการ์ดจะเปลี่ยนแปลงมัน; `correctableFields` แสดงรายการเส้นทางฟิลด์ที่มีค่า — ฟิลด์ที่ช่องทางการแก้ไขสามารถแตะต้องได้ |
| `_atlas` | `object` | `{version}` — ตราประทับการเผยแพร่คลังข้อมูล (`"unreleased"` ระหว่างการเผยแพร่) จงใจให้เป็น id การเผยแพร่ **ไม่ใช่** การประทับเวลาการบิลด์: การประทับเวลาจะทำให้การบิลด์สองครั้งจากพินที่เหมือนกันแตกต่างกันตามปฏิทิน ซึ่งทำลายคุณสมบัติที่ให้ใครก็ตามสามารถตรวจสอบ atlas ได้ — พินเดียวกันเข้า ไบต์เดียวกันออก |

บล็อกแหล่งที่มาก่อนการเปลี่ยนผ่านถูกยกเลิกทั้งหมด: `dataSources` (ถูกแทนที่ด้วยแมป `_fieldSources` ต่อฟิลด์), `supportTier` (การตัดสินที่คำนวณได้ ถูกแทนที่ด้วยจำนวน `coverage` ที่เป็นกลาง), `_generated` (คลังข้อมูลทั้งหมดถูกสร้างขึ้น; ตราประทับคือ `_card.revision` บวก `_atlas.version`), `humanReviewed` และ `notes` (การคัดสรรที่เป็นของช่องทางที่มีบันทึกของตัวเอง) และ `firstDocumented`/`lastDocumented` ระดับบนสุด (ย้ายไปที่ `documentation` ใน § 5.5 ซึ่งแหล่งข้อมูลของพวกเขายืนยันพวกมันจริงๆ)

## นโยบายรหัสภาษา

Champollion ใช้ **ISO 639-3** เป็นตัวระบุมาตรฐาน รหัสมาตรฐานอื่นๆ
ถูกลงทะเบียนเป็น alias และ resolve ไปยังรหัส ISO 639-3 ในรันไทม์

| ลำดับความสำคัญ | มาตรฐาน | ตัวอย่าง | ฟิลด์ | การใช้งาน |
|----------|----------|---------|-------|-----|
| 1 (มาตรฐาน) | ISO 639-3 | `crk` | `code` | ชื่อไฟล์การ์ด, คีย์คอนฟิก, พารามิเตอร์ API |
| 2 (นามแฝง) | ISO 639-1 | `iu` | `codeAliases[]` | ยอมรับใน CLI, แปลงเป็น ISO 639-3 |
| 3 (นามแฝง) | BCP 47 | `fil` | `codeAliases[]` | ยอมรับใน CLI, แปลงเป็น ISO 639-3 |
| อ้างอิง | Glottocode | `plai1258` | `glottocode` | การจัดหมวดหมู่เท่านั้น ไม่ใช่สำหรับรันไทม์ |

**ลำดับการแปลง (Resolution order):** เมื่อผู้ใช้ระบุรหัส:
1. ตรงกันโดยตรงกับ `card.code` → พบ
2. ตรงกันกับ `card.codeAliases[]` → พบ, ส่งคืนการ์ดมาตรฐาน
3. ตรงกันกับ `card.iso639_1` → พบ (ทางเลือกสำรอง)
4. ไม่พบ → ข้อผิดพลาด

### ประวัติการย้าย: ISO 639-1 → ISO 639-3

ก่อน v8 ชื่อไฟล์การ์ดใช้รหัส ISO 639-1 เมื่อมีให้ใช้ (`fr.json`,
`de.json`, `ja.json`) ในการย้ายไปใช้ 639-3 การ์ดทั้งหมดถูกเปลี่ยนชื่อเป็น
รหัส ISO 639-3 ที่เทียบเท่า:

| ก่อน | หลัง | เหตุผล |
|--------|-------|-----|
| `fr.json` | `fra.json` | 639-3 เป็นมาตรฐาน |
| `de.json` | `deu.json` | 639-3 เป็นมาตรฐาน |
| `zh.json` | `cmn.json` | Macrolanguage → individual ค่าเริ่มต้น |
| `ar.json` | `arb.json` | Macrolanguage → Modern Standard Arabic |
| `ms.json` | `zsm.json` | Macrolanguage → Standard Malay |

**เกิดอะไรขึ้นกับรหัสเก่า?**
- รหัส 639-1 เก่าอยู่ใน `card.iso639_1`
- รหัส 639-1 เก่าอยู่ใน `card.codeAliases[]` (`fra` → `["fr"]`)
- `resolveCode("fr")` ส่งคืน `"fra"` ในช่วงรันไทม์ — เข้ากันได้กับเวอร์ชันเก่า
- ผู้ใช้ยังคงสามารถเขียน `"fr"` ในคอนฟิกของตนได้ — มันจะถูกแปลงอย่างโปร่งใส

**สิ่งที่เปลี่ยนแปลงในเชิงสถาปัตยกรรม:**
- `_deepMerge()` ตอนนี้ข้ามค่า `null` (สืบทอดจากการ์ดหลัก)
- `_deepMerge()` ตอนนี้มีชุดฟิลด์อัตลักษณ์ (code, extends, aliases ไม่สืบทอด)
- `formality.default` ตอนนี้ได้จาก register `isDefault: true` flags
- การ์ด 205 ใบที่ได้จาก Grambank ได้รับการแก้ไข `formality.default` เชิงโครงสร้าง
- การ์ด genus/family/macrolanguage 38 ใบให้เป้าหมายการสืบทอด

## กรณีพิเศษ

### ภาษามือ (Sign Languages)
ภาษามือ (เช่น ASE — American Sign Language) เป็นภาษาที่ถูกต้องตามกฎหมายซึ่งมีรหัส ISO 639-3 พวกมันมีภูมิศาสตร์และจำนวนผู้พูด แต่:
- `modality` คือ `"signed"` — การยืนยันเชิงบวกของการ์ดว่าภาษานั้น *คือ* อะไร; การไม่มีระบบการเขียนเป็นข้อเท็จจริงที่แยกต่างหาก
- `scripts` มักจะหายไป (ไม่มีระบบสัญลักษณ์ใดที่ได้รับการยอมรับเป็นมาตรฐานชุมชน) แม้ว่า `"Sgnw"` (SignWriting) จะปรากฏในที่ที่แหล่งข้อมูลยืนยัน
- `textDirection` หายไป
- `linguisticChallenges` ควรกล่าวถึงไวยากรณ์เชิงพื้นที่ (spatial grammar), ลักษณนาม (classifiers) ฯลฯ

### ภาษาโบราณและภาษาในอดีต (Ancient & Historical Languages)
ภาษาอย่าง Latin (`lat`, isoLanguageType `"Historical"`) และ Sanskrit (`san`) ยังคงถูกใช้ในบริบทเฉพาะ (พิธีกรรม, วิชาการ) แต่ไม่มีผู้พูดเป็นภาษาแม่:
- `isoLanguageType` ใช้คำสถานะของ ISO เอง (`"Ancient"`, `"Historical"`, `"Extinct"`) — การ์ดจะไม่ทำให้ซอฟต์ลงหรือลบล้างมันเด็ดขาด
- `endangerment` และ `speakerEstimates` รายงานสิ่งที่แหล่งข้อมูลที่อ้างอิงประเมินไว้จริงๆ พร้อมข้อควรระวังแบบคำต่อคำ (จำนวนชุมชน L2 จะยังคงถูกติดป้ายกำกับตามที่แหล่งข้อมูลติดป้ายกำกับไว้)
- `firstDocumented` / `lastDocumented` ระบุตำแหน่งของพวกมันในเวลา

### ภาษาประดิษฐ์ (Constructed Languages)
Esperanto (`epo`, isoLanguageType `"Constructed"`), Lojban ฯลฯ:
- `classification` อาจหายไป — Glottolog จัดเก็บภาษาประดิษฐ์ (conlangs) ไว้ภายใต้กลุ่มที่ไม่ใช่เชิงลำดับวงศ์ตระกูล และกลุ่มนี้จะไม่ถูกแสดงเป็นตระกูลภาษาเด็ดขาด
- `contactInfluences` สะท้อนถึงวัสดุต้นทาง (เช่น Esperanto ดึงมาจาก Romance, Germanic, Slavic)
- `endangerment` เป็นเรื่องผิดปกติ — ชุมชนผู้พูดเติบโตขึ้นแต่ไม่มีบ้านเกิดดั้งเดิม

### Macrolanguages
Arabic (`ara`), Chinese (`zho`), Cree (`cre`), Quechua (`que`) เป็น macrolanguage ที่ครอบคลุมภาษาเดี่ยวหลายภาษา:
- `isoScope: "Macrolanguage"` — ศูนย์กลางการนำทาง ไม่เคยเป็นเป้าหมายเกณฑ์มาตรฐาน
- `macrolanguageMembers` แสดงรายการรหัสสมาชิกแต่ละตัว; `canonicalisedMembers` บันทึกว่าสมาชิกใดที่รีจิสทรี BCP 47 พับรวมเข้ากับแท็กของ macrolanguage (แต่ละรีจิสทรีมีการระบุที่มา)
- `methodSupport` สะท้อนถึงสิ่งที่ *macrolanguage card* รองรับ (มักจะเป็นความหลากหลายที่เป็นมาตรฐาน)
- สมาชิกแต่ละรายมีการ์ดของตัวเอง โดยนำ `macrolanguage` กลับไปยังศูนย์กลาง

### ภาษาที่ไม่มีอักขรวิธีมาตรฐาน (Languages Without Standardized Orthography)
หลายภาษา (โดยเฉพาะภาษาที่มีมุขปาฐะ) ไม่มีระบบการเขียนที่เป็นมาตรฐาน หรือมีอักขรวิธีที่แข่งขันกัน:
- `scripts`, `scriptNames` และ `textDirection` หายไป — ไม่มีแหล่งข้อมูลใดยืนยันสคริปต์ ซึ่งไม่ใช่การอ้างว่า "ไม่มีภาษาเขียน"
- `notes` ควรอธิบายสถานการณ์ทางอักขรวิธี
- `linguisticChallenges` ควรสังเกตว่าสิ่งนี้ส่งผลต่อ MT อย่างไร (เช่น ไม่มีข้อมูลการฝึกอบรม)

### Diglossia
ภาษาอย่างภาษาอาหรับ (MSA กับสำเนียง) หรือ Guaraní (Jopará กับ Guaraní บริสุทธิ์):
- `codeSwitching` บันทึกสถานการณ์สำเนียงผสม
- `registers` สามารถเสนอ preset สำหรับระดับต่างๆ
- `varieties` สามารถแสดงรายการคู่ diglossic

## ประเภทอิทธิพลจากการสัมผัสภาษา

| ประเภท | ความหมาย | ตัวอย่าง |
|------|---------|---------|
| `superstrate` | ภาษาที่มีอำนาจเหนือกว่าถูกกำหนดให้กับชุมชน | French → English (หลัง ค.ศ. 1066) |
| `substrate` | ภาษาพื้นเมืองที่มีอิทธิพลต่อภาษาที่ถูกกำหนด | Celtic → English |
| `adstrate` | ภาษาเพื่อนบ้านที่มีอิทธิพลซึ่งกันและกัน | Norse → English |
| `learned_borrowing` | การยืมผ่านการศึกษา/วิชาการ | Latin → English |
| `lexical_borrowing` | การยืมคำศัพท์โดยตรงผ่านการสัมผัส | Spanish → Filipino |
| `relexification` | การแทนที่คำศัพท์ทั้งหมด | Portuguese → Papiamentu |

## ระดับความลึกของอิทธิพลจากการสัมผัสภาษา

| ระดับ | ความหมาย |
|-------|---------|
| `light` | คำยืมเพียงไม่กี่คำ ผลกระทบต่อโครงสร้างน้อยมาก |
| `moderate` | คำศัพท์จำนวนมากในโดเมนเฉพาะ |
| `heavy` | คำศัพท์แพร่หลายและลักษณะโครงสร้างบางส่วน |
| `structural` | ไวยากรณ์ ไวยากรณ์ประโยค และสัทวิทยาได้รับผลกระทบ |
| `defining` | อัตลักษณ์หลักถูกหล่อหลอมโดยการสัมผัส (creoles, ภาษาผสม) |

## การเขียน Register Preset ที่ดี

**prompt ของ preset ที่ดี:**
- ระบุลักษณะความเป็นทางการอย่างชัดเจน (เช่น "해요체", "vous-form", "siz-form")
- อธิบายสรรพนามหรือรูปแบบกริยาเฉพาะที่ต้องใช้
- ให้บริบทว่า register นี้เหมาะสมเมื่อใด
- กล่าวถึงข้อพิจารณาเรื่อง script หากเกี่ยวข้อง

**อย่า** ใส่แนวทางเรื่องเพศแบบครอบคลุมใน prompt ของ preset แนวทางเรื่องเพศ
ควรอยู่ใน `card.gender.inclusiveGuidance` — จะถูกแทรกแยกต่างหาก

```
❌ Bad:  "Standard Thai. Professional register."
✔ Good: "Professional Thai. Use คุณ (khun) for second person, เรา (rao)
         for first person when needed. Clear, concise phrasing
         appropriate for digital interfaces."
```

### ข้อตกลงการตั้งชื่อ Preset

คีย์ preset ควรสื่อความหมายและใช้ตัวพิมพ์เล็กคั่นด้วยขีดกลาง:
- ภาษา T-V: `formal-vous`, `informal-tu`, `formal-Sie`, `casual-du`
- ระดับการพูด: `polite-haeyo`, `formal-hapsyo`, `casual-hae`
- กลาง: `professional`, `neutral-professional`
- การสลับรหัส: `taglish-professional`, `pure-filipino`

## ข้อเท็จจริงของการ์ดได้รับการอัปเดตอย่างไร

การ์ดเป็น **ผลลัพธ์จากการบิลด์ (build output)** — การฉายแบบกำหนดได้จากสแนปช็อตต้นทางที่ปักหมุดไว้ ไม่มีขั้นตอนการเพิ่มข้อมูลต่อการ์ดอีกต่อไป: ช่องทางสคริปต์ `enrich-*` ที่รันด้วยมือถูกยกเลิกแล้ว และการแก้ไขที่ทำกับไฟล์การ์ดโดยตรงจะถูกลบออกโดยการบิลด์ครั้งต่อไป หากต้องการเปลี่ยนข้อเท็จจริง:

1. **ลงทะเบียนการตัดสินใจ** ทุกฟิลด์คือหนึ่งแถวในรีจิสทรีการตัดสินใจของการบิลด์: พารามิเตอร์ต้นทางใดที่ป้อนข้อมูลให้มัน, มันฉายข้อมูลอย่างไร, และค่าที่หายไปหมายถึงอะไร
2. **แก้ไขเลเยอร์การนำเข้า (ingest layer)** ค่าที่ผิดคือข้อบกพร่องในตัวจัดการแหล่งข้อมูล (หรือพินต้นทางที่ล้าสมัย) ไม่เคยเป็นสิ่งที่จะต้องแพตช์บนการ์ด
3. **รีบิลด์และเปลี่ยนผ่าน (cut over)** การบิลด์จะฉายการ์ดทุกใบใหม่จากสแนปช็อตที่ปักหมุดไว้; เกต (gates) จะปฏิเสธการบิลด์บางส่วน, ค่า null/ว่างเปล่า, และการ์ดที่ไม่ผ่านกฎความสมบูรณ์

### การจัดการความขัดแย้ง

เมื่อแหล่งข้อมูลไม่ตรงกัน:
1. **เก็บทั้งหมด** พร้อมระบุแหล่งที่มา — นั่นคือจุดประสงค์ของซองระบุที่มา
2. **ห้ามหาค่าเฉลี่ย** หรือเลือกข้าง — `consensus` จะปรากฏเฉพาะเมื่อแหล่งข้อมูลเห็นตรงกันจริงๆ เท่านั้น
3. **นำข้อควรระวังของแต่ละแหล่งข้อมูลมา** แบบคำต่อคำใน `note` ของค่านั้น
4. ค่าเดียวสำหรับการแสดงผลหรือการคำนวณจะถูก **ดึงโดยอะแดปเตอร์** จากลำดับความน่าเชื่อถือที่ประกาศไว้ — ตัวการ์ดเองจะเก็บข้อมูลทั้งหมดที่กระจายอยู่

```bash
node scripts/lint-language-cards.mjs              # all cards

```

### รายการตรวจสอบ PR

เมื่อส่งการเปลี่ยนแปลงที่แตะต้องการ์ด (จำไว้ว่า: เปลี่ยนการบิลด์ ไม่ใช่การ์ด):

- [ ] การแก้ไขอยู่ในตัวจัดการการนำเข้าหรือรีจิสทรีการตัดสินใจ — ไม่มีไฟล์การ์ดใดถูกแก้ไขด้วยมือ
- [ ] ฟิลด์มีเฉพาะค่าที่แหล่งข้อมูลยืนยันเท่านั้น — ไม่มีการเติม `null` หรือ `[]` เพื่อให้การ์ด "สมบูรณ์"
- [ ] `classification` มาจาก Glottolog (ไม่ได้สร้างด้วยมือ)
- [ ] แหล่งที่มาของทุกฟิลด์ที่ถูกแตะต้องจะอยู่ใน `_fieldSources` โดยค่าที่ Champollion คำนวณจะมีแหล่งที่มา `champollion-derived`
- [ ] ไม่มีคะแนนที่วัดได้ของผลลัพธ์วิธีการปรากฏที่ใดเลยบนการ์ด
- [ ] Linter และเกตความสมบูรณ์ของการ์ดผ่านโดยไม่มีข้อผิดพลาด
