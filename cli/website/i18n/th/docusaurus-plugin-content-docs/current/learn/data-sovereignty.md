# อธิปไตยของข้อมูลหมายถึงอะไรเมื่อคุณเขียนมันลงในซอฟต์แวร์

:::info[สำหรับใคร]
ทุกคน ไม่จำเป็นต้องมีพื้นฐานด้านกฎหมาย แมชชีนเลิร์นนิง หรือการปกครองของชนพื้นเมือง หากคุณเคยสงสัยว่าจริงๆ แล้วชุมชนต้องทำอย่างไรเพื่อรักษาการควบคุมข้อมูลภาษาของตนเองเมื่อมีคอมพิวเตอร์เข้ามาเกี่ยวข้อง หน้านี้คือคำตอบที่ครอบคลุม
:::

การพูดคุยส่วนใหญ่เกี่ยวกับข้อมูลและความยินยอมมักหยุดอยู่แค่การอนุญาต: มีใครตอบตกลงหรือไม่ แต่อธิปไตยของข้อมูลตั้งคำถามที่ยากกว่านั้น ใครคือ **เจ้าของ** สิ่งนี้? ใครเป็นผู้ตัดสินใจว่าจะเกิดอะไรขึ้นกับมัน? ใครสามารถเข้าถึงมันได้? และในทางกายภาพแล้วมันตั้งอยู่ที่ไหน?

คำถามทั้งสี่ข้อนี้มีชื่อเรียก และมีที่มาจากแหล่งเฉพาะเจาะจง

---

## 1. คำถามเหล่านี้ — และใครคือผู้ตั้งคำถามแรก

First Nations ในแคนาดาได้ประกาศหลักการอธิปไตยทางข้อมูลว่าด้วย **ความเป็นเจ้าของ (Ownership), การควบคุม (Control), การเข้าถึง (Access) และการครอบครอง (Possession)** ในฐานะการยืนยันอำนาจเหนือข้อมูลของตนเอง

ที่มาดังกล่าวไม่ใช่แค่เกร็ดความรู้ทั่วไป หลักการเหล่านี้ไม่ใช่รายการตรวจสอบจริยธรรมอเนกประสงค์ที่ใครๆ ก็หยิบไปใช้ได้ แต่เป็นการยืนยันอำนาจศาลของ First Nations เหนือข้อมูลของ First Nations ซึ่งเกิดขึ้นจากประวัติศาสตร์ที่มีการบันทึกไว้เกี่ยวกับการทำวิจัย *กับ* ชุมชน (ในฐานะผู้ถูกทดลอง) มากกว่าที่จะทำ *ร่วมกับ* พวกเขา และข้อมูลที่ได้ก็ไม่เคยถูกส่งกลับคืนมา

หลักการทั้งสี่ข้อโดยสังเขป:

| | คำถามที่ตอบ |
|---|---|
| **Ownership** | ใครเป็นเจ้าของข้อมูลนี้? ชุมชนเป็นเจ้าของความรู้ทางวัฒนธรรมและข้อมูลของตนร่วมกัน — ในลักษณะเดียวกับที่บุคคลเป็นเจ้าของข้อมูลส่วนบุคคลของตนเอง |
| **Control** | ใครเป็นผู้ตัดสินใจว่าจะเกิดอะไรขึ้นกับข้อมูล? ชุมชนควบคุมทุกขั้นตอนของสิ่งใดก็ตามที่เกี่ยวข้องกับพวกเขา: สิ่งที่ถูกรวบรวม วิธีการรวบรวม โดยใคร เพื่ออะไร และจะทำอย่างไรกับข้อมูลนั้นในภายหลัง |
| **Access** | ใครสามารถเข้าถึงได้? ชุมชนต้องสามารถเข้าถึงข้อมูลเกี่ยวกับตนเองได้ ไม่ว่าจะถูกเก็บไว้ที่ใด หรือใครเป็นผู้ถือครองก็ตาม |
| **Possession** | ในทางกายภาพแล้วมันตั้งอยู่ที่ไหน? ไม่เหมือนกับความเป็นเจ้าของ — การครอบครองคือข้อเท็จจริงที่เป็นรูปธรรมของการดูแลรักษา และเป็นกลไกที่ทำให้หลักการอีกสามข้อสามารถบังคับใช้ได้จริงแทนที่จะเป็นเพียงคำสัญญา |

มีกรอบการทำงานที่เกี่ยวข้องอื่นๆ อยู่ และไม่สามารถใช้แทนกันได้: **CARE** (Collective Benefit, Authority to Control, Responsibility, Ethics) สำหรับการกำกับดูแลข้อมูลของชนพื้นเมืองในวงกว้าง และ **Te Mana Raraunga** สำหรับอธิปไตยของข้อมูลชาวเมารี แต่ละกรอบการทำงานเกิดขึ้นในบริบททางกฎหมายและวัฒนธรรมของตนเอง การใช้ชื่อของกรอบการทำงานหนึ่งเพื่อเรียกหลักการของอีกกรอบการทำงานหนึ่งถือเป็นการลบเลือนตัวตนในรูปแบบหนึ่ง

## 2. ทำไมซอฟต์แวร์ถึงทำให้เรื่องนี้ชัดเจนขึ้น

หลักการสามารถดำรงอยู่บนหน้ากระดาษในฐานะความตั้งใจที่ดีได้ แต่ซอฟต์แวร์จะบีบบังคับให้เกิดคำถาม เพราะคอมพิวเตอร์ไม่ได้ทำงานตามความตั้งใจ — มันทำงานตามสิ่งที่ถูกสร้างขึ้นมา

ลองพิจารณาวิธีการทั่วไปในการประเมินระบบแปลภาษา เพื่อดูว่าระบบแปลภาษาของคุณได้ดีหรือไม่ ใครบางคนจำเป็นต้องมี **ชุดทดสอบ (test set)**: ประโยคในภาษาของคุณ จับคู่กับความหมายของประโยคนั้น แพลตฟอร์มการประเมินเกือบทุกแห่งจะขอให้คุณ **อัปโหลด** ชุดทดสอบนั้นเพื่อให้สามารถให้คะแนนได้

ลองอ่านข้อความนั้นอีกครั้งพร้อมกับคำถามทั้งสี่ข้อในมือ การอัปโหลดคือการถ่ายโอนการครอบครอง (possession) ซึ่งมักจะถ่ายโอนการควบคุม (control) ในทางปฏิบัติไปด้วย — เมื่อมีสำเนาอยู่บนเครื่องของคนอื่น ความสามารถของคุณในการบอกให้ "หยุด" จะกลายเป็นเพียงคำขอ ไม่ใช่ความสามารถในการจัดการ การเข้าถึง (access) จะกลายเป็นสิ่งที่คุณได้รับอนุญาตแทนที่จะเป็นสิ่งที่คุณมีสิทธิ์ ความเป็นเจ้าของ (ownership) จะเหลืออยู่แค่บนหน้ากระดาษและไม่มีความหมายอะไรมากนัก

สำหรับชุมชนที่ข้อมูลภาษาเคยถูกดึงออกไปก่อนหน้านี้ คำว่า "อัปโหลดและเชื่อใจเรา" ไม่ใช่คำขอที่เป็นกลาง มันมีรูปแบบเดียวกับสิ่งที่เคยเกิดขึ้นมาแล้ว

## 3. กลไกที่แท้จริงคืออะไร

จุดยืนของโปรเจกต์นี้คือ หากอธิปไตยมีอยู่จริง มันจะต้องเป็นคุณสมบัติของซอฟต์แวร์ ไม่ใช่แค่ย่อหน้าหนึ่งในนโยบาย และนี่คือหน้าตาของมันอย่างเป็นรูปธรรม สิ่งเหล่านี้ถูกอธิบายไว้เพื่อให้คุณสามารถประเมินและโต้แย้งได้

**การลงทะเบียนโดยไม่ต้องส่งมอบ** ชุดทดสอบจะถูกลงทะเบียนโดยการอธิบายว่า *มันอยู่ที่ไหน* และปักหมุดแฮชการเข้ารหัส (cryptographic hash) ของเนื้อหาที่แน่นอน — ไม่ใช่โดยการอัปโหลดประโยค ในเวลาที่ประเมิน ระบบจะดึงข้อมูลจากแหล่งที่มา ตรวจสอบว่าแฮชตรงกันหรือไม่ และให้คะแนน จะไม่มีการจัดเก็บข้อมูลใดๆ หากผู้ถือครองนำแหล่งที่มาออฟไลน์ คลังข้อมูล (corpus) นั้นก็จะหยุดการถูกประเมินไปโดยปริยาย การควบคุมยังคงอยู่ที่จุดเริ่มต้น เพราะการครอบครองไม่เคยถูกย้ายไปไหน

**การเข้ารหัสก่อนส่งออก สำหรับระดับที่เข้มงวดที่สุด** ในกรณีที่คลังข้อมูลต้องสามารถใช้งานได้โดยที่ไม่สามารถอ่านได้ มันจะถูกเข้ารหัส **บนอุปกรณ์ของผู้ถือครองเอง** ก่อนที่ข้อมูลใดๆ จะถูกส่งออกไป สิ่งที่โปรเจกต์นี้ได้รับคือข้อความไซเฟอร์ (ciphertext) และคำอธิบายที่ไม่มีเนื้อหาอยู่เลย

**ไม่มีฝ่ายใดฝ่ายหนึ่งสามารถถอดรหัสได้เพียงลำพัง** คีย์จะถูกแบ่งให้กับกลุ่มผู้ดูแล (custodians) เพื่อให้จำนวนหนึ่งของพวกเขา — สมมติว่าสามในห้าคน — ต้องดำเนินการร่วมกันเพื่ออนุมัติสิ่งใดๆ ไม่มีผู้ดูแลคนใดสามารถดำเนินการได้เพียงลำพัง และโปรเจกต์นี้ก็เช่นกัน: โมเดลที่ตัดสินใจเลือกคือ **Champollion จะไม่ถือครองส่วนแบ่งใดๆ เลย (holds zero shares)** ดังนั้นจึงไม่สามารถถอดรหัสได้ไม่ว่าจะได้รับความร่วมมือจากใครหรือไม่ก็ตาม การรันระบบจะเกิดขึ้นได้ก็ต่อเมื่อองค์ประชุมของผู้ดูแลตัดสินใจว่าควรทำ

> **สถานะปัจจุบันของเรื่องนี้** กลไกนี้ถูกสร้างขึ้นและสามารถทดสอบได้แล้ว *แต่ยังไม่มีการยืนยันผู้ดูแล* — องค์ประกอบนี้เป็นของชุมชนที่เกี่ยวข้อง และยังไม่มีกลุ่มใดที่ยินยอมถือครองส่วนแบ่ง จนกว่าพวกเขาจะยินยอม จะยังไม่มีชุดผู้ดูแลที่ใช้งานจริง และโปรเจกต์นี้จะไม่เปิดเผยชื่อผู้สมัครต่อสาธารณะ ดังนั้น โปรดอ่านย่อหน้าข้างต้นในฐานะกลไกการทำงานที่กำลังรอความสัมพันธ์ที่จะทำให้มันทำงานได้ ไม่ใช่สิ่งที่กำลังทำงานอยู่ในปัจจุบัน

**ผลลัพธ์โดยไม่มีการเปิดเผย** สิ่งที่ส่งกลับมาจากการประเมินที่ถูกปิดผนึกคือคะแนน ไม่ใช่ประโยค วิธีการหนึ่งสามารถพิสูจน์ได้ว่าทำงานได้ผลบนคลังข้อมูลที่ผู้สร้างวิธีการนั้น และโปรเจกต์นี้ ไม่เคยอ่านเลย

**ความยินยอมก่อนการส่งข้อมูล** การส่งข้อความไปยัง API ของโมเดลภายนอกถือเป็นการเปิดเผยข้อมูลในตัวมันเอง คลังข้อมูลภายใต้ใบอนุญาตของชุมชน ใบอนุญาตเฉพาะกิจ หรือใบอนุญาตที่ไม่ได้ระบุไว้ จะ **ปฏิเสธ** การประเมินระยะไกลจนกว่าผู้ถือสิทธิ์จะบันทึกการอนุญาตไว้อย่างชัดเจน การปฏิเสธนี้ถูกบังคับใช้ในโค้ด และไม่มีกระบวนการอัตโนมัติใดที่สามารถให้สิทธิ์แทนชุมชนได้

**การย้อนกลับในทิศทางเดียวเท่านั้น** การเปิดเผยข้อมูลสามารถผ่อนปรนได้โดยการตัดสินใจอย่างรอบคอบของผู้ถือครอง มันจะไม่ถูกผ่อนปรนโดยค่าเริ่มต้น โดยบังเอิญ หรือเพื่อความสะดวกของคนอื่น

## 4. สิ่งที่โปรเจกต์นี้ไม่ได้เป็น

**โปรเจกต์นี้ไม่ได้รับการตรวจสอบ รับรอง หรืออนุมัติตามกรอบอธิปไตยทางข้อมูลของชนพื้นเมืองใดๆ ไม่มีการประเมินใดๆ เกิดขึ้น ไม่มีการรอการประเมิน และไม่มีการบอกเป็นนัยใดๆ ทั้งสิ้น**

สิ่งที่มีอยู่คือ **ความพยายามในการนำอธิปไตยทางข้อมูลมาใช้ในโค้ด** — เพื่อนำหลักการที่ชนพื้นเมืองระบุไว้มาแสดงออกเป็นกลไกการทำงานแทนที่จะเป็นเพียงคำมั่นสัญญา ความพยายามนั้นเป็นของเรา แต่จะสำเร็จหรือไม่นั้นไม่ใช่สิ่งที่เราจะประกาศได้ การตัดสินใจเรื่องความสอดคล้องเป็นของชุมชนที่เกี่ยวข้อง และโปรเจกต์ที่ยืนยันความสอดคล้องของตนเองก็จะเป็นการจำลองท่าทีแบบเดียวกับที่หลักการเหล่านี้ถูกสร้างขึ้นมาเพื่อแก้ไข: นั่นคือคนนอกเป็นผู้ตัดสินว่าอะไรคือการจัดการข้อมูลของชุมชนที่เพียงพอ

และทั้งหมดนี้ก็ไม่ใช่การรับประกันว่าสิ่งต่างๆ จะเป็นไปไม่ได้ ซอฟต์แวร์มีข้อบกพร่อง ผู้ปฏิบัติงานทำผิดพลาดได้ ฝ่ายที่มีความมุ่งมั่นและถือครองบทบาทที่ถูกต้องมากพอยังคงเป็นความเสี่ยงตกค้างที่ไม่มีสถาปัตยกรรมใดสามารถลบออกได้ คำกล่าวอ้างของเรานั้นแคบกว่าและเราคิดว่ามีประโยชน์มากกว่า: **เส้นทางที่ง่ายถูกปิดลงแล้ว และเส้นทางที่ยากจะทิ้งร่องรอยไว้**

นอกจากนี้ยังมีช่องว่างระหว่างหลักการและกลไก และเราขอระบุให้ชัดเจนดีกว่าปล่อยให้คุณค้นพบเอง การครอบครอง (Possession) คือหลักการที่กลไกเหล่านี้ตอบสนองได้ดีที่สุด — โค้ดนั้นเก่งมากในการไม่ถือครองสิ่งใดๆ ความเป็นเจ้าของ (Ownership) และการควบคุม (Control) นั้นไปไกลกว่าที่ซอฟต์แวร์จะทำได้ด้วยตัวเอง โดยเข้าสู่เรื่องของข้อกำหนด การกำกับดูแล และความสัมพันธ์ที่ไม่มีการเข้ารหัสใดๆ สามารถจัดการได้ และทุกกลไกข้างต้นตั้งสมมติฐานว่าชุมชนมีศักยภาพและโครงสร้างพื้นฐานในการถือครองข้อมูลของตนเองอยู่แล้ว ซึ่งไม่ใช่สมมติฐานที่เป็นกลาง

---

## 5. โปรดโต้แย้งสิ่งนี้

ความพยายามนี้เปิดรับคำวิจารณ์ และคำเชิญนี้ไม่ใช่แค่การประดับตกแต่ง

หากคุณทำงานเกี่ยวกับการกำกับดูแลข้อมูลของชนพื้นเมือง, CARE, Te Mana Raraunga หรือเทคโนโลยีภาษาของชนพื้นเมือง — หรือหากคุณเป็นสมาชิกหรือตัวแทนของชุมชนที่มีภาษาอยู่ในดัชนีนี้ — เราต้องการรับฟังว่าสิ่งนี้ผิดพลาดตรงไหน โดยเฉพาะอย่างยิ่ง:

- จุดที่กลไกไม่ได้ทำตามที่หลักการกำหนดไว้
- จุดที่การนำเสนอสื่อความหมายของหลักการของชุมชนผิดเพี้ยนไป หรือขอยืมอำนาจของหลักการเหล่านั้นมาใช้
- จุดที่บางสิ่งถูกอธิบายว่าเป็นการปกป้องแต่กลับไม่ได้ปกป้องคุณจริง
- จุดที่ชุมชนต้องการสิ่งที่เรายังไม่ได้สร้างขึ้น
- จุดที่คำศัพท์ที่ใช้ไม่ถูกต้อง

ข้อโต้แย้งและการแก้ไขสามารถแจ้งผ่าน [ช่องทางการติดต่อและการขอลบข้อมูล](/docs/network/community/contact-objections-takedown) ซึ่งครอบคลุมถึงการขอให้ลบสิ่งใดๆ เกี่ยวกับภาษาที่คุณเป็นตัวแทนด้วย ไม่จำเป็นต้องใช้ถ้อยคำที่รักษาน้ำใจในการแจ้งเรื่องนี้

การยังไม่ได้รับการตรวจสอบคือข้อเท็จจริงเกี่ยวกับงานนี้ ไม่ใช่ข้อแก้ตัว ความพยายามที่เปิดรับการตรวจสอบคือความซื่อสัตย์ ส่วนความพยายามที่ไม่เปิดรับคือแค่คำกล่าวอ้าง

> หน้านี้เป็นคำอธิบายของความพยายามหนึ่งในการสร้างสิ่งต่างๆ ให้มุ่งสู่หลักการที่ชุมชนเป็นผู้เขียนขึ้นเอง — โปรดศึกษาหลักการเหล่านั้นตามที่ผู้เขียนระบุไว้ ความพยายามนี้ไม่ได้รับการรับรองจากองค์กรใดๆ ที่ดูแลหลักการเหล่านั้น
