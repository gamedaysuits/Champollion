# การกำหนดค่า

Champollion ทำงานได้โดยไม่ต้องกำหนดค่าใดๆ — ระบบจะตรวจจับไฟล์ locale รูปแบบ และภาษาเป้าหมายจากโปรเจกต์ของคุณโดยอัตโนมัติ หากต้องการควบคุมเพิ่มเติม ให้สร้าง `champollion.config.json` ในไดเรกทอรีรากของโปรเจกต์ หรือรัน:

```bash
npx champollion init
```

## เอกสารอ้างอิงการกำหนดค่าแบบเต็ม

```json title="champollion.config.json"
{
  "version": 3,
  "inputLocale": "en",
  "localesDir": "./locales",
  "localesPattern": null,
  "localesLayout": null,
  "contentDir": null,
  "translatableFields": null,
  "format": "auto",
  "model": "google/gemini-3.8-flash",
  "temperature": 0.3,
  "defaultMethod": "llm",
  "batchSize": 80,
  "coachingFile": null,
  "promptContext": null,
  "genderGuidance": null,
  "protectedTerms": [],
  "jsonConcurrency": 200,
  "contentConcurrency": 48,
  "fallbackPrefix": "[EN] ",
  "apiKeyEnvVar": "OPENROUTER_API_KEY",
  "noTranslate": [],
  "noTranslateUrls": true,
  "baseUrl": "",
  "pairs": {},
  "languages": {},
  "lint": {
    "srcDir": null,
    "ignore": ["node_modules", ".next", "dist"],
    "minLength": 2
  },
  "seo": {
    "urlPattern": "/:locale/:path",
    "pages": null
  },
  "typegen": {
    "output": null,
    "autoGenerate": false
  }
}
```

:::note[typegen ยังไม่ได้รับการพัฒนา]
บล็อกการกำหนดค่า `typegen` ได้รับการรับรู้และเก็บรักษาไว้โดย config loader แต่การสร้างประเภท TypeScript ยังไม่ได้รับการพัฒนา นี่เป็นเพียง placeholder สำหรับฟีเจอร์ที่วางแผนไว้ การตั้งค่าเหล่านี้ไม่มีผลใดๆ
:::


### ฟิลด์

| ฟิลด์ | ชนิดข้อมูล | ค่าเริ่มต้น | คำอธิบาย |
|-------|------|---------|-------------|
| `version` | `number` | `3` | เวอร์ชันสกีมาของการกำหนดค่า ต้องเป็น `3` เสมอ |
| `inputLocale` | `string` | `"en"` | รหัสภาษาต้นทาง (BCP 47) |
| `localesDir` | `string` | `"./locales"` | เส้นทางไปยังไฟล์โลแคล เก็บหนึ่งไฟล์ต่อหนึ่งภาษา (`fr.json`) หรือหนึ่งโฟลเดอร์ต่อหนึ่งภาษา (`fr/common.json`) ดูที่ [โครงสร้างไฟล์โลแคล](#locale-layouts) |
| `localesPattern` | `string` | `null` | ตำแหน่งที่ไฟล์ของแต่ละภาษาถูกเก็บไว้เมื่อไม่ตรงกับโครงสร้างทั้งสองแบบ โดยใช้ `{lang}` และ `{ns}` (ระบุหรือไม่ก็ได้): `"public/locales/{lang}/{ns}.json"`, `"src/strings/app_{lang}.json"` สัมพัทธ์กับรูทของโปรเจกต์ ใช้แทน `localesDir` ดูที่ [โครงสร้างไฟล์โลแคล](#locale-layouts) |
| `localesLayout` | `string` | `null` | ลบล้างการตรวจหาโครงสร้าง: `"flat"` (หนึ่งไฟล์ต่อภาษา) หรือ `"dir"` (หนึ่งโฟลเดอร์ต่อภาษา) จำเป็นเฉพาะเมื่อมีทั้ง `en.json` และ `en/` อยู่ร่วมกัน |
| `defaultNamespace` | `string` | `null` | ในโปรเจกต์แบบหนึ่งโฟลเดอร์ต่อภาษาที่มีหลายไฟล์ ไฟล์ที่ `champollion wrap` จะเพิ่มคีย์ใหม่เข้าไป (เช่น `"common"`) |
| `contentDir` | `string` | `null` | โฟลเดอร์ของ Markdown/MDX ที่จะแปล: โฟลเดอร์ `content/` ของ Hugo หรือโฟลเดอร์อื่นๆ เช่น `./newsletters` ในแอป Next.js คำแปลแต่ละไฟล์จะถูกเขียนไว้ข้างๆ ไฟล์ต้นทางในรูปแบบ `<name>.<locale>.md` ตัวอย่างเช่น `2026-10.md` → `2026-10.crk.md` ไฟล์ที่มีชื่อลงท้ายด้วย `<name>.<code>.md` อยู่แล้วจะถือว่าเป็นคำแปล ไม่ใช่ต้นทาง ดูที่ [การแปลเนื้อหา](/docs/guides/content-translation) |
| `translatableFields` | `string[]` | `null` | ลบล้างฟิลด์ frontmatter เริ่มต้นที่แปลได้สำหรับการแปลเนื้อหา `null` จะใช้ค่าเริ่มต้นในตัว (`title`, `description`, `summary`) |
| `format` | `string` | `"auto"` | รูปแบบไฟล์: `json`, `toml`, `yaml`, `po` ([gettext](#gettext)), `arb` ([Flutter](#arb)) หรือ `auto` (ตรวจหาจากนามสกุลของไฟล์ต้นทาง; `.yml` ถือเป็น YAML และเป้าหมายจะคง `.yml` ไว้) ค่าอื่นๆ จะหยุดการทำงานพร้อมข้อผิดพลาด |
| `model` | `string` | `"google/gemini-3.8-flash"` | โมเดลเริ่มต้นสำหรับวิธีแบบ LLM ระบุ slug ของโมเดลแบบตรงกันทุกประการ: slug แบบเต็มของ OpenRouter (`provider/model`) นามแฝงแบบย่อ (`gemini-flash`) และ id ที่คลุมเครือ (`~vendor/…`, `…-latest`) จะถูกปฏิเสธ พร้อมระบุ slug ที่ถูกต้องให้เขียน ผู้ให้บริการโดยตรงใช้ชื่อเปล่า (เช่น `gpt-4o`) ส่วน OpenRouter slug ของผู้ให้บริการรายนั้นจะถูกจับคู่ให้ (`openai/gpt-4o` → `gpt-4o`) และหากไม่มีโมเดลที่รองรับจะหยุดการทำงานก่อนส่งข้อมูล ([ชื่อโมเดล](/docs/guides/translation-methods#model-names)) |
| `temperature` | `number` | `0.3` | อุณหภูมิ (temperature) ของ LLM (0.0–2.0) ค่ายิ่งต่ำ = ผลลัพธ์ยิ่งแน่นอน (deterministic) |
| `defaultMethod` | `string` | `"llm"` | วิธีการแปลเริ่มต้น: `llm`, `llm-coached`, `openai`, `anthropic`, `gemini`, `local`, `google-translate`, `deepl`, `microsoft-translator`, `libretranslate`, `apertium`, `tilde`, `translated`, `api` โดย `local` คือเซิร์ฟเวอร์ที่เข้ากันได้กับ OpenAI บนเครื่องของคุณ (ค่าเริ่มต้นคือ Ollama) ถูกลบล้างได้ด้วยแฟล็ก CLI `--method` |
| `batchSize` | `number` | `80` | จำนวนคีย์ต่อแบทช์การแปล ค่ายิ่งสูง = เรียก API น้อยลง แต่ขนาดพรอมต์จะใหญ่ขึ้น |
| `coachingFile` | `string` | `null` | เส้นทางไปยังไฟล์พรอมต์สอนงาน (coaching prompt) แบบข้อความอิสระ (สัมพัทธ์กับรูทของโปรเจกต์) เนื้อหาจะถูกอ่านตอนเริ่มต้นและแทรกเข้าไปในระบบพรอมต์ในรูปแบบบล็อก `Coaching guidance:` |
| `promptContext` | `string` | `null` | ข้อความบริบทของแอปพลิเคชันที่แทรกเข้าไปในพรอมต์ระบบ (เช่น "E-commerce product descriptions") ช่วยให้โมเดลปรับการแปลให้เข้ากับโดเมนของคุณ |
| `genderGuidance` | `string` \| `false` | `null` | วิธีที่พรอมต์ LLM จัดการเพศทางไวยากรณ์ `null` จะใช้ค่าเริ่มต้นของแต่ละภาษาจากแค็ตตาล็อกของ Champollion — สำหรับภาษาฝรั่งเศส คือ *écriture inclusive* พร้อมจุดคั่นกลาง (`Connecté·e`, `Utilisateur·rice·s`) สำหรับภาษาเยอรมัน คือรูปแบบโคลอน (`Benutzer:innen`) `false` จะไม่ส่งคำแนะนำเรื่องเพศ ส่วนสตริงจะส่งคำแนะนำของคุณเอง (เช่น `"Use the masculine generic."`) สามารถกำหนดเป็นรายภาษาและรายคู่ภาษาได้เช่นกัน ดูที่ [คำแนะนำเรื่องเพศ](#gender-guidance) |
| `protectedTerms` | `string[]` | `[]` | ชื่อที่ต้องคงไว้ตามที่เขียนในทุกภาษา: บุคคล, บริษัท, ผลิตภัณฑ์ (เช่น `["Curtis Forbes", "Game Day Suits"]`) โมเดลจะได้รับคำสั่งให้คงชื่อเหล่านี้ไว้ และค่าที่ประกอบด้วยชื่อเหล่านี้เพียงอย่างเดียวจะไม่ถูกแจ้งเตือนว่ายังไม่ได้แปลหรือใช้อักษรผิด ซึ่งต่างจาก `noTranslate` ที่จะข้ามทั้ง**คีย์** |
| `jsonConcurrency` | `number` | `200` | จำนวนการแปลโลแคลแบบขนานสูงสุดสำหรับการซิงค์คีย์ JSON ถูกลบล้างได้ด้วยแฟล็ก CLI `--json-concurrency` |
| `contentConcurrency` | `number` | `48` | จำนวนการเรียก API แบบขนานสูงสุดสำหรับการแปลเนื้อหา (Markdown/MDX) ถูกลบล้างได้ด้วยแฟล็ก CLI `--content-concurrency` |
| `fallbackPrefix` | `string` | `"[EN] "` | คำนำหน้ามาร์กเกอร์ที่ใช้โดย `audit` และ `verify` เพื่อตรวจหาค่าเดิมที่ยังไม่ได้แปลจากการรันครั้งก่อนหน้า Champollion ไม่ได้เขียนคำนำหน้านี้ — เพียงแค่อ่านเพื่อตรวจหาเท่านั้น |
| `apiKeyEnvVar` | `string` | `"OPENROUTER_API_KEY"` | ชื่อตัวแปรสภาพแวดล้อม (environment variable) สำหรับ API key ใช้ลบล้างสำหรับชื่อตัวแปรที่กำหนดเอง |
| `minContentRetention` | `number` | `0.35` | สัดส่วนของตัวอักษร/ตัวเลขต้นทางที่ผลลัพธ์ต้องคงไว้ ก่อนที่[การตรวจสอบการลบเนื้อหา](/docs/concepts/quality-gate)จะตรวจสอบสัญญาณที่สอง สามารถกำหนดเป็นรายคู่ภาษาและรายภาษาได้เช่นกัน |
| `noTranslate` | `string[]` | `[]` | คีย์แบบ dot-path และรูปแบบ glob ที่ค่าของมันจะถูกคัดลอกไปยังทุกโลแคลตามตัวอักษร ดูที่ [คีย์ที่ไม่ต้องแปล](#no-translate) ยอมรับในรูปแบบ `skipKeys` เช่นกัน |
| `noTranslateUrls` | `boolean` | `true` | กำหนดให้ค่าต้นทางที่เป็นเพียง URL `scheme://` เป็นคีย์ที่ไม่ต้องแปล ตั้งค่าเป็น `false` เพื่อส่งคีย์ที่มีค่าเป็น URL ไปยังระบบแปล |
| `baseUrl` | `string` | `""` | Base URL สำหรับการสร้างอาร์ทิแฟกต์ SEO (hreflang, sitemaps, JSON-LD) |
| `pairs` | `object` | `{}` | การลบล้างวิธี โมเดล และคุณภาพเป็นรายคู่ภาษา ดูที่ [การกำหนดค่าคู่ภาษา](#pair-configuration) |
| `languages` | `object` | `{}` | การลบล้างเป็นรายภาษา ดูที่ [การกำหนดค่าภาษา](#language-configuration) |
| `lint.srcDir` | `string` | `null` | ไดเรกทอรีต้นทางสำหรับการสแกน lint โดย `null` = ตรวจหาอัตโนมัติจากเฟรมเวิร์ก |
| `lint.ignore` | `string[]` | `["node_modules", ...]` | รูปแบบ glob ที่จะแยกออกจากการ lint |
| `lint.minLength` | `number` | `2` | ความยาวสตริงขั้นต่ำที่จะแจ้งเตือนว่าเป็นค่าฮาร์ดโค้ด |
| `seo.urlPattern` | `string` | `"/:locale/:path"` | เทมเพลตรูปแบบ URL สำหรับการสร้างแท็ก hreflang |
| `seo.pages` | `string[]` | `null` | รายการหน้าเว็บที่ระบุอย่างชัดเจนสำหรับ SEO โดย `null` = ตรวจหาอัตโนมัติจากคีย์โลแคล |
| `typegen.output` | `string` | `null` | เส้นทางเอาต์พุตสำหรับประเภท TypeScript ที่สร้างขึ้น โดย `null` = ปิดใช้งาน |
| `typegen.autoGenerate` | `boolean` | `false` | สร้างประเภท TypeScript ใหม่อัตโนมัติหลังการซิงค์แต่ละครั้ง |

## โครงสร้างไฟล์โลแคล {#locale-layouts}

Champollion อ่านไฟล์โลแคลของคุณจากตำแหน่งที่เฟรมเวิร์กของคุณจัดเก็บไว้อยู่แล้ว ซึ่งมีสามรูปแบบ

**หนึ่งไฟล์ต่อภาษา** (`flat`) next-intl, vue-i18n, Hugo และการตั้งค่าที่สร้างขึ้นเองส่วนใหญ่:

```text
messages/
  en.json      ← source
  fr.json
  de.json
```

```json title="champollion.config.json"
{ "localesDir": "./messages" }
```

**หนึ่งโฟลเดอร์ต่อภาษา** (`dir`) i18next และ react-i18next ซึ่งแต่ละไฟล์คือ *เนมสเปซ* (namespace):

```text
public/locales/
  en/
    common.json      ← source namespaces
    admin/users.json
  fr/
    common.json
    admin/users.json
```

```json title="champollion.config.json"
{ "localesDir": "./public/locales" }
```

Champollion จะเลือก `dir` เมื่อ `<localesDir>/<inputLocale>/` เป็นโฟลเดอร์ของไฟล์โลแคล ทุกไฟล์ต้นทางจะถูกซิงค์ไปยังเส้นทางเดียวกันภายใต้โฟลเดอร์ของแต่ละภาษา พร้อมทั้งสร้างไฟล์และโฟลเดอร์ที่ยังไม่มีให้ โดยเนมสเปซสามารถเป็นเส้นทางแบบซ้อนกันได้ (`admin/users`)

**รูปแบบอื่นๆ** (`localesPattern`) ระบุเส้นทางด้วย `{lang}` และหากภาษานั้นมีหลายไฟล์ ให้ใช้ `{ns}`:

```json title="champollion.config.json"
{ "localesPattern": "src/translations/{ns}/{lang}.json" }
```

`{lang}` สามารถซ้ำได้ เช่นเดียวกับใน `"{lang}/app_{lang}.json"` ส่วน `{ns}` สามารถปรากฏได้หนึ่งครั้งและอาจครอบคลุมหลายโฟลเดอร์ รูปแบบไฟล์จะพิจารณาจากนามสกุลไฟล์ ยกเว้นจะมีการกำหนด `format` ไว้

`champollion init` จะค้นหาโครงสร้างเหล่านี้ให้คุณ โดยจะตรวจสอบแอป Flutter ก่อน (`pubspec.yaml` ร่วมกับ `l10n.yaml` หากมี) รวมถึงแค็ตตาล็อก gettext (`locale/<lang>/LC_MESSAGES/`, `translations/`, GNU `po/`) และเขียน `localesPattern` สำหรับกรณีเหล่านั้น จากนั้นจะตรวจสอบโฟลเดอร์ตามปกติของเฟรมเวิร์กของคุณ (`messages/` สำหรับ next-intl, `public/locales/` แล้วตามด้วย `locales/` สำหรับ i18next, `src/locales/` สำหรับ vue-i18n, `i18n/` สำหรับ Hugo) จากนั้นตรวจสอบ `locales`, `messages`, `i18n`, `lang`, `translations`, `public/locales`, `src/locales` และ `src/i18n` โดยจะใช้เฉพาะโฟลเดอร์ที่มีไฟล์ภาษาต้นทางของคุณอยู่เท่านั้น และจะพิมพ์สิ่งที่พบออกมา `init --langs fr,de` ยังจะสร้างไฟล์เป้าหมายที่ว่างเปล่าในโครงสร้างดังกล่าวด้วยเช่นกัน

:::note[วิธีที่ภาษาที่มีหลายไฟล์ทำการซิงค์]
แต่ละไฟล์จะถูกเปรียบเทียบ แปล และเขียนแยกจากกัน `.champollion.lock` จะบันทึกคีย์เป็น `<namespace>::<key>` (`common::nav.home`) เช่นเดียวกับ `--force-keys`, unit id ของ `xliff` และ `sync --dry --json` ส่วนคีย์เปล่าๆ ใน `--force-keys` จะจับคู่กับคีย์นั้นในทุกไฟล์ สำหรับโปรเจกต์แบบหนึ่งไฟล์ต่อภาษาจะเก็บคีย์แบบธรรมดา ไฟล์ล็อกจึงไม่เปลี่ยนแปลง

Translation Memory จะใช้ข้อความต้นทางเป็นคีย์ ไม่ใช่ตามไฟล์ ข้อความที่ปรากฏในสองเนมสเปซจะได้รับการแปลเพียงครั้งเดียวต่อภาษา ไฟล์ที่สองจะดึงข้อความนั้นมาจากแคชโดยไม่มีค่าใช้จ่าย
:::

หากมีทั้ง `en.json` และโฟลเดอร์ `en/` ที่มีข้อมูลอยู่ Champollion จะหยุดทำงานและขอให้คุณตั้งค่า `"localesLayout": "flat"` หรือ `"dir"` แทนการคาดเดา

### คีย์พหูพจน์ของ i18next {#i18next-plurals}

i18next เก็บรูปแบบพหูพจน์เป็นคีย์ระดับเดียวกัน (sibling keys) โดยมีคำต่อท้าย CLDR: `item_one`, `item_other` แต่ละภาษามีรูปแบบพหูพจน์ที่แตกต่างกัน ภาษาฝรั่งเศสและสเปนยังใช้ `_many` ภาษาอาหรับใช้หกรูปแบบ และภาษาญี่ปุ่นใช้เพียง `_other` เมื่อไฟล์ต้นทาง JSON มีคีย์เหล่านี้ แต่ละเป้าหมายจะได้รับรูปแบบเฉพาะของภาษานั้นๆ อย่างถูกต้อง ซึ่งอ่านมาจาก CLDR ผ่าน JavaScript `Intl.PluralRules` API:

```json title="en.json"
{ "item_one": "{{count}} item", "item_other": "{{count}} items" }
```

หลังจากการซิงค์ `fr.json` จะมี `item_one`, `item_many` และ `item_other` ส่วน `ja.json` จะมีเพียง `item_other` เท่านั้น การซิงค์จะระบุว่าภาษาของคุณแต่ละภาษาได้รับหรือตัดรูปแบบใดออกไปบ้าง

รูปแบบใหม่จะถูกแปลจากข้อความ `_other` ของต้นทาง โดย `_one` แปลมาจาก `_one` ส่วน `_zero` ในต้นทางจะถูกคงไว้ในทุกภาษา เนื่องจาก i18next จะค้นหาคีย์นี้สำหรับจำนวนที่เป็น 0 ในทุกภาษา หากการซิงค์ก่อนหน้าเคยเขียนรูปแบบที่ภาษานั้นไม่ได้ใช้ เช่น `item_one` ในภาษาญี่ปุ่น การซิงค์จะลบออกเฉพาะเมื่อ Translation Memory ระบุว่าการซิงค์เป็นผู้สร้างค่านั้นขึ้นมา หากเป็นค่าที่เขียนขึ้นเองด้วยมือจะถูกคงไว้ สำหรับคีย์ของรูปแบบที่ภาษานั้นไม่มีและต้นทางก็ไม่มีคีย์นั้นเช่นกัน (เช่น `item_two` ในภาษาสเปน) จะไม่ถูกลบโดยอัตโนมัติ: `verify` จะระบุชื่อคีย์ดังกล่าว และ `sync --prune plural-extras` จะลบเฉพาะคีย์เหล่านั้นพร้อมทั้งแจกแจงแต่ละรายการ (หากใช้ `--dry` จะแจ้งสิ่งที่จะถูกลบ) สำหรับภาษาที่ CLDR ไม่มีกฎพหูพจน์ รูปแบบของต้นทางจะถูกคัดลอกแบบหนึ่งต่อหนึ่ง และการซิงค์จะแจ้งให้ทราบ

### ข้อความ ICU {#icu}

ค่าที่เขียนด้วย ICU MessageFormat (next-intl, react-intl, vue-i18n, Flutter) จะผสมโค้ดเข้ากับข้อความ:

```json
{ "items": "{count, plural, =0 {No events} one {# event} other {# events}}" }
```

เฉพาะข้อความที่อยู่ภายในกิ่ง (branch) เท่านั้นที่จะถูกแปล [เกตตรวจสอบคุณภาพ (quality gate)](/docs/concepts/quality-gate) จะปฏิเสธคำแปลที่มีการเปลี่ยนแปลงส่วนอื่นๆ:

- ชื่อตัวแปร (`count`, `{name}`) ซึ่งจะต้องไม่ถูกเปลี่ยนชื่อหรือตัดทิ้ง
- คำว่า `plural`, `select` และ `selectordinal` รวมถึงชนิดของ `{price, number}`
- ตัวเลือก (selector) (`=0`, `one`, `other`, `male`) โดย `select` จะต้องคงตัวเลือกเดิมไว้อย่างถูกต้อง ส่วน `plural` จะคงตัวเลือกของต้นทางไว้และอาจเพิ่มหมวดหมู่ที่ภาษาเป้าหมายใช้ตาม CLDR: ภาษาฝรั่งเศสจะเพิ่ม `many` ภาษาโปแลนด์เพิ่ม `few` และ `many` หมวดหมู่ที่ภาษานั้นไม่ได้ใช้อาจถูกตัดออก เช่น ภาษาญี่ปุ่นจะคงไว้เพียง `other`
- `#` ในแต่ละกิ่งพหูพจน์ที่มี ยกเว้น `zero`, `one`, `two` และ `=N` ซึ่งบางภาษาอาจเขียนตัวเลขเป็นคำ
- `offset:N`, อาร์กิวเมนต์แบบซ้อน และการแปลง printf เช่น `%s`, `%d` และ `%(name)s`

โมเดลจะได้รับแจ้งว่าภาษาเป้าหมายใช้หมวดหมู่ใดบ้าง คำแปลที่ถูกปฏิเสธจะได้รับการลองแปลใหม่อีกหนึ่งครั้งพร้อมเหตุผล เช่น `ICU keyword 'other' was translated to 'óthér'` ทั้งนี้ เครื่องหมายอะโพสทรอฟีหน้าตัวแทนที่ (`d'{name}`) สามารถใช้ได้ `verify` และ `integrity` จะทำการตรวจสอบแบบเดียวกันนี้กับไฟล์ที่เขียนลงดิสก์ไปแล้ว สำหรับคำสั่ง `sync` แบบปกติจะคงค่าเดิมที่มีอยู่บนดิสก์ไว้ ดังนั้นผลการตรวจสอบแต่ละรายการจะแจ้งคำสั่งที่ใช้แก้ไข นั่นคือ `champollion sync --pair <pair> --redo keys:<key>` เมื่อค่าที่เสียหายมาจาก Translation Memory คำสั่งเหล่านั้นจะลบมันออกจากแคช เพื่อให้คำสั่งแปลคีย์นั้นใหม่อีกครั้งแทนที่จะนำข้อความเดิมมาใช้ จึงไม่จำเป็นต้องใช้ `--fresh`

### แค็ตตาล็อก gettext (.po) {#gettext}

ชี้ `localesPattern` (หรือ `localesDir`) ไปยังแค็ตตาล็อกของคุณ:

```json title="Django"
{ "localesPattern": "locale/{lang}/LC_MESSAGES/{ns}.po" }
```

```json title="GNU (po/fr.po, po/de.po, po/hello.pot)"
{ "localesDir": "./po", "format": "po" }
```

**ต้นทาง** คือแค็ตตาล็อกของภาษาต้นทาง เช่น `locale/en/LC_MESSAGES/django.po` จาก `django-admin makemessages -l en` ข้อความใน `msgid` คือข้อความที่จะแปลเมื่อ `msgstr` ว่างเปล่า เมื่อไม่มีแค็ตตาล็อกดังกล่าว ต้นทางจะเป็นเทมเพลต `.pot`:

- เมื่อใช้ `localesDir`: คือไฟล์ `.pot` เพียงไฟล์เดียวในโฟลเดอร์นั้น
- เมื่อใช้ `localesPattern`: `<name>.pot` ในโฟลเดอร์ก่อนหน้าตัวแทนที่ตัวแรกหรือโฟลเดอร์ระดับบนขึ้นไป `<name>` คือเนมสเปซ (`{ns}` หนึ่งเทมเพลตต่อหนึ่งโดเมน เช่น `django.pot`) หรือชื่อไฟล์ของแพตเทิร์นโดยไม่มี `{lang}` (`messages.po` → `messages.pot`)
- เมื่อใช้ `localesLayout: "dir"`: จะไม่มีการค้นหาเทมเพลต ให้เก็บแค็ตตาล็อกต้นทางไว้ใน `<localesDir>/<source>/`

หากพบสองเทมเพลตในตำแหน่งที่คาดว่าจะมีเพียงเทมเพลตเดียว การทำงานจะหยุดลง Champollion จะไม่คาดเดาว่าไฟล์ใดคือต้นทาง

**คีย์** แต่ละ `msgid` คือคีย์ รายการที่มี `msgctxt` จะมีคีย์เป็น `msgctxt` + U+0004 + `msgid` ซึ่งเป็นการเข้ารหัสของ gettext เอง คำว่า "Open" ที่เป็นคำกริยาและ "Open" ที่เป็นคำคุณศัพท์จะถือเป็นคนละคีย์และแยกรายการในแคช รายงานจะแสดงตัวคั่นเป็น `␄` (`verb␄Open`) และ `--force-keys "verb␄Open"` ยอมรับรูปแบบนี้ หากคุณไม่สามารถพิมพ์ `␄` ได้ ให้เขียน `\x04` (`--force-keys 'verb\x04Open'`) ซึ่งสามารถใช้งานได้ทั้งสองแบบ `--force-keys` (และ `--redo keys:`) จะแยกด้วยเครื่องหมายจุลภาค หากมีเครื่องหมายจุลภาคอยู่ภายใน msgid ให้เขียนเป็น `\,` และครอบอาร์กิวเมนต์ด้วยเครื่องหมายคำพูด: `--redo 'keys:Welcome back\, %(name)s!'` รายการที่ไม่มีการเปลี่ยนแปลงจะดึงมาจากแคชโดยไม่มีค่าใช้จ่าย

**สิ่งที่จะถูกแปล** รายการที่มี `msgstr` ว่างเปล่า หรือรายการที่มีแฟล็ก `fuzzy` จะถือว่ายังไม่ได้แปล การซิงค์จะแปลรายการนั้นและลบ `fuzzy` ออกพร้อมกับบรรทัด `#|` ของ msgid ก่อนหน้า ความคิดเห็นของผู้แปล (`# …`) จะถูกคงไว้ การอ้างอิง (`#:`), ความคิดเห็นที่แยกออกมา (`#.`) และแฟล็กจะนำมาจากต้นทาง ความคิดเห็น `#.` และ `msgctxt` จะถูกส่งไปยังโมเดลเป็นบริบท รายการที่การซิงค์ไม่ได้เปลี่ยนแปลงจะถูกเขียนกลับไบต์ต่อไบต์ รายการที่ต้นทางไม่มีแล้ว และรายการ `#~` ที่ล้าสมัย จะถูกเก็บไว้ที่ส่วนท้าย

แค็ตตาล็อกที่ Champollion สร้างขึ้น (`init --langs` หรือการซิงค์สำหรับโลแคลที่ยังไม่มีแค็ตตาล็อก) จะได้รับส่วนหัวแบบสมบูรณ์ตามที่ `msginit --no-translator` เขียนขึ้น ซึ่ง `msgfmt -c` ยอมรับ: `Project-Id-Version`, `Report-Msgid-Bugs-To` และ `POT-Creation-Date` คัดลอกจากเทมเพลต (`PACKAGE VERSION` จะถูกแทนที่ด้วยชื่อโฟลเดอร์ของโปรเจกต์ และจะไม่มี `POT-Creation-Date` หากไม่มีวันที่ของเทมเพลต), `PO-Revision-Date` (เวลาที่สร้างไฟล์), `Last-Translator: Automatically generated`, `Language-Team: none`, `Language`, `MIME-Version: 1.0`, `Content-Type: text/plain; charset=UTF-8`, `Content-Transfer-Encoding: 8bit` และ `Plural-Forms` ส่วนหัวของแค็ตตาล็อกที่มีอยู่แล้วจะไม่ถูกเขียนใหม่ — เฉพาะตัวแทนที่ `Plural-Forms` หรือ `charset=CHARSET` ในส่วนหัวเท่านั้นที่จะถูกเติมให้สมบูรณ์

**รูปพหูพจน์** รายการที่มี `msgid_plural` จะได้รับการแปลเป็นข้อความรูปพหูพจน์แบบ ICU หนึ่งข้อความ (`{n, plural, one {One file} other {%(count)d files}}`) โมเดลจึงเขียนทุกรูปแบบออกมาพร้อมกันในคราวเดียว จากนั้นข้อความจะถูกเขียนไปยัง `msgstr[0]`…`msgstr[n]` ผ่านส่วนหัว `Plural-Forms` ของภาษาเป้าหมาย แต่ละดัชนีจะใช้หมวดหมู่ CLDR ของตัวเลขที่เลือกดัชนีนั้น `nplurals=3` ของภาษารัสเซียคือ `one`, `few`, `many` หากภาษาเป้าหมายไม่มีส่วนหัว `Plural-Forms` หรือมีเพียง placeholder ของเทมเพลต ก็จะได้รับส่วนหัวที่ `msginit` เขียนสำหรับภาษานั้น เพื่อให้ช่อง `msgstr[]` ของแค็ตตาล็อกเป็นช่องที่ gettext และ Django เลือก: ภาษาฝรั่งเศส `nplurals=2; plural=(n > 1);`, ภาษาเยอรมัน `nplurals=2; plural=(n != 1);`, ภาษารัสเซีย `nplurals=3; …` ภาษาที่ `msginit` ไม่มีข้อมูล จะได้รับส่วนหัวที่แปลงมาจาก CLDR และผ่านการตรวจสอบเทียบกับ `Intl.PluralRules` สำหรับทุกตัวเลขจนถึง 3,000 และสำหรับตัวเลขจำนวนมาก หากไม่สามารถเขียนกฎของภาษาเป็นนิพจน์ gettext ได้ กระบวนการซิงก์จะหยุดลงและแจ้งคำสั่งสำหรับเขียนส่วนหัวดังกล่าว: `msginit --locale=<lang> --input=<template>.pot` รูปแบบที่แค็ตตาล็อกไม่มีช่องรองรับ (เช่น `many` ของภาษาฝรั่งเศส สำหรับ 1 000 000 ในแค็ตตาล็อกที่มีสองรูปแบบ) จะไม่ถูกร้องขอซ้ำ ไม่ถูกทำเครื่องหมาย หรือไม่ถูกรายงานว่าขาดหายไป ส่วนแค็ตตาล็อกที่มีส่วนหัวของตัวเองจะยังคงใช้ส่วนหัวเดิม และช่องของแค็ตตาล็อกนั้นจะเป็นช่องที่ได้รับการตรวจสอบ

**ข้อจำกัด** แค็ตตาล็อกต้องเป็นแบบ UTF-8 ให้แปลงรูปแบบอื่นด้วย `msgconv --to-code=UTF-8` สำหรับ msgid พหูพจน์ที่วงเล็บปีกกาไม่สมดุลจะไม่สามารถเขียนเป็นข้อความ ICU ได้ จึงจะมีการรายงานและเว้นไว้ให้คุณแปลเอง คุณยังคงควรเรียกใช้ `msgfmt --check-format` (Django: `compilemessages`) ก่อนนำขึ้นใช้งานจริง คำสั่งนี้จะตรวจสอบเฉพาะรายการที่ติดแฟล็ก `#, python-format` (หรือ `c-format`, …): `makemessages` จะเพิ่มแฟล็กให้กับรายการที่แยกออกมาพร้อมตัวแทนที่ `%` แต่แค็ตตาล็อกที่สร้างด้วยมืออาจไม่มีแฟล็กนี้ ทำให้รายการเหล่านั้นไม่ได้รับการตรวจสอบ `champollion verify` จะเปรียบเทียบตัวแทนที่ printf ของทุกรายการ — ทั้งชื่อและตัวอักษรชนิดข้อมูล — ไม่ว่าจะมีแฟล็กใดก็ตาม และการซิงค์จะคงแฟล็กของรายการต้นทางไว้ในแต่ละรายการที่แปล

### ไฟล์ ARB ของ Flutter (.arb) {#arb}

```json title="champollion.config.json"
{ "localesPattern": "lib/l10n/app_{lang}.arb" }
```

ใช้ `arb-dir` และ `template-arb-file` จาก `l10n.yaml` ของคุณหากแตกต่างกัน (`assets/i18n/intl_{lang}.arb`) เฉพาะข้อความเท่านั้นที่จะถูกแปล เมื่อทำการเขียน:

- `@@locale` จะถูกตั้งค่าเป็นภาษาเป้าหมายตามรูปแบบของ Flutter ให้ตรงกับชื่อไฟล์ (`app_pt_BR.arb` → `"pt_BR"`) โดย `gen-l10n` จะปฏิเสธไฟล์ที่ `@@locale` ไม่ตรงกับชื่อไฟล์
- ทุกออบเจกต์เมทาดาตา `@key` (ตัวแทนที่, ชนิดของตัวแทนที่, คำอธิบาย) จะถูกคัดลอกจากต้นทาง คีย์ที่ต้นทางไม่มีเมทาดาตาจะคงของเป้าหมายไว้
- คีย์จะเรียงตามลำดับของต้นทาง ข้อความที่ยังไม่ได้แปลจะถูกละไว้ เพื่อให้ Flutter ใช้ค่าสำรองจากเทมเพลต

`description` ของข้อความจะถูกส่งไปยังโมเดลเป็นบริบท ตัวแทนที่ `{name}` และพหูพจน์ ICU จะได้รับการปกป้องโดย[การตรวจสอบ ICU](#icu) นอกจากนี้ `verify` และ `integrity` ยังรายงาน `@@locale` ที่ไม่ถูกต้องและเมทาดาตาของตัวแทนที่แตกต่างจากต้นทาง การซิงค์ใดๆ ที่เขียนไฟล์ใหม่จะซ่อมแซมทั้งสองส่วน: `champollion sync --pair en:fr --force` จะดึงข้อความที่ไม่เปลี่ยนแปลงทุกข้อความมาจากแคช

## คีย์ที่ไม่ต้องแปล {#no-translate}

บางค่ามีรูปแบบการแสดงผลที่ถูกต้องเพียงรูปแบบเดียวในทุกภาษา: URL, เส้นทางที่เก็บโค้ด (repository path), ชื่อแพ็กเกจ, ตัวระบุผลิตภัณฑ์ คำแปลที่ถูกต้องของ `https://example.org/paper` ก็คือ `https://example.org/paper`

[เกตตรวจสอบคุณภาพ (quality gate)](/docs/concepts/quality-gate) ของ Champollion จะปฏิเสธคำแปลที่สะท้อนต้นทาง (source-echo) — คือคำแปลที่เหมือนกับต้นทางทุกประการ — เนื่องจากโดยปกติแล้วมักเกิดจากโมเดลปฏิเสธที่จะทำงาน สำหรับคีย์เหล่านี้ กลไกดังกล่าวทำให้คำตอบที่ถูกต้องกลายเป็นคำตอบที่ถูกปฏิเสธ และไม่มีผลลัพธ์ใดที่โมเดลสร้างขึ้นแล้วจะผ่านเกตได้ โมเดลที่มีประสิทธิภาพต่ำกว่าจะเรียนรู้ที่จะเอาชนะเกตโดยการแก้ไขค่าเล็กน้อย (เช่น สร้าง `#fragment` ขึ้นมาเอง, ใส่เครื่องหมายทับปิดท้ายเกินมา, หรือใส่อักขระ zero-width space ที่มองไม่เห็น) ซึ่งทำให้ส่งลิงก์ที่ใช้งานไม่ได้ขึ้นสู่ระบบ ส่วนโมเดลที่มีประสิทธิภาพสูงกว่าจะส่งคืนค่าเดิมโดยไม่เปลี่ยนแปลงและไม่ผ่านเกต ส่งผลให้ `sync` จบการทำงานด้วยรหัสที่ไม่ใช่ศูนย์ (non-zero exit) ในทุกรอบ

ให้ประกาศคีย์เหล่านั้นแทน:

```json title="champollion.config.json"
{
  "noTranslate": ["**.url", "pages.software.*.repo", "meta.appId"]
}
```

คีย์ที่ตรงกันจะถูก**คัดลอกจากโลแคลต้นทางตามตัวอักษร** — ไม่มีการส่งไปยังระบบแปล ไม่มีการตรวจผ่านเกตคุณภาพ ไม่นับเป็นข้อผิดพลาด และไม่มีการคิดค่าใช้จ่าย อีกทั้งยังถูกแยกออกจากการประมาณการค่าใช้จ่ายก่อนการรันด้วยเหตุผลเดียวกัน

### ไวยากรณ์ของรูปแบบ (Pattern syntax)

รูปแบบจะเป็น dot-path บนเนมสเปซของคีย์ที่ถูกทำให้แบนราบ (flattened key space) โดยมีไวลด์การ์ดสองแบบ:

| รูปแบบ | ตรงกับ | ไม่ตรงกับ |
|---------|---------|----------------|
| `nav.brand` | `nav.brand` (เส้นทางตรงกันทุกประการ) | `nav.brandName` |
| `**.url` | `url`, `pages.a.b.url` (โหนดปลายทาง (leaf) `url` ที่ระดับความลึกใดก็ได้) | `pages.urlLabel`, `pages.url.caption` |
| `pages.software.*.repo` | `pages.software.portal.repo` | `pages.software.a.b.repo` |
| `meta.og*` | `meta.ogImage`, `meta.ogTitle` | `meta.twitterImage`, `meta.og.image` |

`*` จะจับคู่ภายในส่วน (segment) เดียว ส่วน `**` จะจับคู่ตั้งแต่ศูนย์ส่วนขึ้นไปจนครบทั้งส่วน
รูปแบบที่ไม่มีไวลด์การ์ดจะเป็นเส้นทางคีย์แบบตรงกันทุกประการ

### URL ได้รับการจัดการเป็นค่าเริ่มต้น

เนื่องจากคีย์ที่มีค่าเป็น URL จะไม่มีผลลัพธ์ที่ถูกต้องภายใต้เกตตรวจสอบ `noTranslateUrls` จึงเป็น `true` มาตั้งแต่เริ่มต้น: ค่าต้นทางใดๆ ที่เป็นเพียง URL `scheme://` แบบสัมบูรณ์ (absolute URL) จะถือว่าเป็นคีย์ที่ไม่ต้องแปลโดยไม่ต้องกำหนดค่าเพิ่มเติม

การตรวจหานั้นกำหนดไว้อย่างรัดกุมโดยเจตนา — ค่าทั้งหมดหลังตัดช่องว่างแล้วจะต้องเป็น URL เท่านั้น ข้อความบรรยายที่มีลิงก์ประกอบอยู่ด้วย (`"Read the paper at https://…"`) จะยังคงได้รับการแปลตามปกติ

สามารถปิดการทำงานนี้ได้ด้วย `"noTranslateUrls": false` หาก URL ของคุณขึ้นอยู่กับแต่ละโลแคลอย่างแท้จริง (เช่น โฮสต์เอกสารแยกตามภาษา) — จากนั้นให้ประกาศ URL ที่ไม่ต้องแปลด้วย `noTranslate`

### การซ่อมแซมและการบังคับใช้

สำหรับคีย์ที่ไม่ต้องแปลจะมีค่าเป้าหมายที่ถูกต้องเพียงค่าเดียวเท่านั้น ดังนั้นความแตกต่างใดๆ จึงถือเป็นข้อบกพร่อง Champollion จะบังคับใช้กฎนี้ในทั้งสองทิศทาง:

- **`sync` จะทำการซ่อมแซม** คีย์ที่ไม่ต้องแปลที่เป้าหมายขาดหายไป มีคำนำหน้าเป็น `[EN] ` หรือมีการเปลี่ยนแปลง จะถูกเขียนทับใหม่จากต้นทาง ซึ่งไม่มีค่าใช้จ่ายในการเรียก API และเป็นการทำงานแบบ idempotent: เมื่อค่าตรงกันแล้ว การซิงค์ในภายหลังจะข้ามคีย์นั้นไปทั้งหมด
- **`verify` และ `integrity` จะแจ้งข้อผิดพลาด** คีย์ที่ไม่ต้องแปลที่มีค่าคลาดเคลื่อนจะถูกรายงานเป็น `NO-TRANSLATE DRIFT` พร้อมค่าที่คาดหวังและค่าจริง — โดยอักขระที่มองไม่เห็นจะถูก escape เป็น `\uXXXX` เนื่องจากความเสียหายประเภทนี้ไม่สามารถมองเห็นได้จากการเปรียบเทียบ diff ตามปกติ คำสั่ง `champollion integrity` จะจบการทำงานด้วยรหัส `1` ดังนั้นกระบวนการบิลด์ที่เชื่อมต่ออยู่จะดักจับ URL ที่เสียหายได้ก่อนนำขึ้นใช้งานจริง

หาก `integrity` ล้มเหลวในลักษณะนี้กับโปรเจกต์ที่คุณเพิ่งกำหนดค่า แสดงว่าเป็นการรายงานความเสียหายที่มีอยู่แล้วในไฟล์โลแคลของคุณ ให้รัน `champollion sync` หนึ่งครั้งเพื่อซ่อมแซม

## การแปลงชุดอักษร {#script-conversion}

บางภาษาที่ Champollion แปลสามารถ*เขียน*ได้มากกว่าหนึ่งวิธี โมเดลจะทำงานใน**ชุดอักษรสำหรับการทำงาน (working script)** ของภาษานั้นเสมอ (การถอดอักษรละติน — SRO สำหรับ Plains Cree, การถอดอักษร Okrand สำหรับ Klingon) และตัวแปลงแบบกำหนดผลลัพธ์แน่นอน (deterministic converter) จะสามารถเขียนผลลัพธ์ใหม่ให้อยู่ในชุดอักษรสำหรับการแสดงผลได้ ส่วนจะแปลงหรือไม่นั้นขึ้นอยู่กับการกำหนดค่า — **ไม่เคยมีค่าเริ่มต้น**:

| โลแคล | ชุดอักษรสำหรับการทำงาน | แปลงเป็น | ประเภท |
|--------|---------------|----------------|------|
| `crk` (Plains Cree) | `Latn` (SRO) | `Cans` (Syllabics) | ยูนิโค้ดจริง — **จำเป็นต้องเลือก** |
| `sr` / `srp` (Serbian) | `Latn` | `Cyrl` (Cyrillic) | ยูนิโค้ดจริง — **จำเป็นต้องเลือก** |
| `tlh` (Klingon) | `Latn` (การถอดอักษรโรมัน) | `Piqd` (pIqaD) | PUA — เลือกเปิดใช้งานเอง |
| `x-elvish-s` (Sindarin) | `Latn` | `Teng` (Tengwar) | PUA — เลือกเปิดใช้งานเอง |
| `x-kryptonian` | `Latn` | Kryptonian | PUA — เลือกเปิดใช้งานเองผ่าน `"script": "x-kryptonian"` |

**คู่ภาษาที่ใช้ยูนิโค้ดจริง (crk, sr) จำเป็นต้องทำการเลือก** Cree Syllabics และ Cyrillic เป็นยูนิโค้ดทั่วไป — แสดงผลได้ทุกที่ — และทั้งสองระบบอักขรวิธีมีการใช้งานจริง Champollion จะไม่ตัดสินใจเลือกระบบการเขียนของชุมชนแทนโปรเจกต์: `init` จะถามเมื่อคุณเลือกภาษานั้น และ `sync` จะปฏิเสธการทำงานจนกว่าการกำหนดค่าจะระบุว่าจะใช้อักษรใด:

```json
{
  "languages": {
    "crk": { "script": "Cans" }
  }
}
```

**ชุดอักษร PUA (tlh, x-elvish-s, x-kryptonian) มีค่าเริ่มต้นเป็นการถอดอักษรโรมัน** pIqaD, Tengwar และ Kryptonian *ไม่ได้อยู่ในยูนิโค้ด* — ตัวแปลงจะส่งจุดรหัสในพื้นที่ใช้งานส่วนตัว (Private Use Area - PUA) ซึ่งจะไม่แสดงผลอะไรเลย เว้นแต่คุณจะแนบฟอนต์ที่แมปเข้ากับจุดรหัสดังกล่าวไปด้วย การถอดอักษรโรมันเป็นผลลัพธ์เดียวที่แสดงผลได้ทุกที่ จึงถูกกำหนดเป็นค่าเริ่มต้น หากต้องการให้แสดงผลเป็นชุดอักษรสำหรับการแสดงผลแทน:

```json
{
  "languages": {
    "tlh": { "script": "Piqd" }
  }
}
```

…และเรียกใช้ `champollion fonts install` เพื่อให้เว็บไซต์ของคุณมีฟอนต์ที่สามารถแสดงผลได้ หากฟอนต์ของคุณจับคู่กับการถอดอักษรละติน (ฟอนต์ภาษาประดิษฐ์จำนวนมากเป็นเช่นนี้) ให้คงค่าเริ่มต้นไว้

`script` รับรหัส ISO 15924 ตัวพิมพ์ใหญ่หรือเล็กก็ได้ (`"cans"`, `"Cans"` และ `"CANS"` ถือว่าเหมือนกัน) นอกจากนี้ยังสามารถกำหนดเป็นรายคู่ภาษาได้ ซึ่งจะมีลำดับความสำคัญเหนือระดับภาษา ค่าที่ไม่ถูกต้องหรือชุดอักษรที่โลแคลไม่สามารถสร้างได้จะล้มเหลวตั้งแต่เริ่มต้น — ก่อนที่จะมีการเรียก API ใดๆ

### ตัวอักษรที่ไม่มีการจับคู่และ `scriptFallback` {#script-fallback}

ตัวแปลงจะแปลเฉพาะสิ่งที่ระบบอักขรวิธีกำหนดไว้เท่านั้น การถอดอักษรโรมันของ Klingon ไม่มี `d`, `c`, `f`, `g`, `i`, `k`, `s`, `x` หรือ `z` — ดังนั้นผลลัพธ์ของโมเดลที่มีคำนามเฉพาะ เช่น "GitHub" จึงไม่สามารถแปลงได้ทั้งหมด Champollion **จะไม่เขียนค่าที่ถูกแปลงเพียงครึ่งๆ กลางๆ อย่างเด็ดขาด**: หากมีตัวอักษรใดที่ไม่สามารถจับคู่ได้ ทั้งค่าจะคงอยู่ในชุดอักษรสำหรับการทำงาน และคำเตือนจะระบุตัวอักษรเหล่านั้นพร้อมทั้งบรรทัดการกำหนดค่าที่จะใช้จับคู่ตัวอักษรดังกล่าว

การจับคู่เหล่านั้นคุณสามารถประกาศเองได้:

```json
{
  "languages": {
    "tlh": {
      "script": "Piqd",
      "scriptFallback": { "d": "D", "f": "p", "z": "S" }
    }
  }
}
```

แต่ละกฎจะแทนที่ลำดับของชุดอักษรสำหรับการทำงานด้วยลำดับที่ตัวแปลง*สามารถ*จับคู่ได้ ก่อนที่การแปลงจะทำงาน กฎต่างๆ จะได้รับการตรวจสอบเมื่อเริ่มต้น — การแทนที่ที่ตัวมันเองไม่สามารถจับคู่ได้จะถูกปฏิเสธ

Champollion **ไม่มีกฎสำรองในตัว**: การประดิษฐ์การปรับเปลี่ยนทางอักขรวิธีขึ้นมาเอง โดยเฉพาะสำหรับระบบการเขียนของภาษาจริง ไม่ใช่หน้าที่ของเครื่องมือจัดทำดัชนี ชุมชนและกลุ่มแฟนคลับมีแบบแผนของตนเองอยู่แล้ว — โปรดนำมาปรับใช้ตามความเหมาะสมเป็นรายโปรเจกต์

### การแก้ไขการแปลงที่ไม่ต้องการ {#repair-script}

ก่อนเวอร์ชัน 0.3.0 การแปลงจะทำงานโดยไม่มีเงื่อนไข — โปรเจกต์ที่กำหนดเป้าหมายเป็นโลแคล PUA จะได้ผลลัพธ์ที่ไม่สามารถแสดงผลได้ไม่ว่าจะต้องการหรือไม่ก็ตาม เครื่องมือสองตัวนี้จะช่วยปิดช่องโหว่ดังกล่าว:

- **`champollion repair-script`** จะสแกนโลแคลที่การกำหนดค่าระบุว่า*ปิด*การแปลง เพื่อหาจุดรหัส PUA และกู้คืนการถอดอักษรโรมันกลับมาโดยใช้ตารางย้อนกลับของตัวแปลงเอง (ใช้ `--dry` เพื่อดูตัวอย่าง) สำหรับ pIqaD จะแปลงกลับได้ตรงกันทุกประการ ส่วนการแปลงกลับของ Tengwar และ Kryptonian จะสูญเสียการใช้อักษรพิมพ์ใหญ่และจะมีการแจ้งเตือน
- **`champollion integrity`** จะล้มเหลว (exit 1) เมื่อพบ PUA ในจุดที่ปิดการแปลงไว้ — เพื่อให้กระบวนการบิลด์ดักจับข้อความที่ไม่สามารถแสดงผลได้ก่อนนำขึ้นใช้งานจริง และรายงานจะแจ้งคำสั่งสำหรับซ่อมแซม

Translation Memory ไม่จำเป็นต้องซ่อมแซม: เพราะเก็บค่าก่อนการแปลงไว้ ดังนั้นการเปิดหรือปิด `script:` ในภายหลังจึงไม่ต้องจัดการใดๆ กับแคช

การแปลงชุดอักษรจะใช้กับสตริง UI (ไฟล์คีย์-ค่า และ JSON ของ Docusaurus) เนื้อหา Markdown จะไม่ถูกแปลง — ตัวแปลงอักขระแบบ greedy ไม่สามารถข้าม code span, URL และ front matter ได้อย่างปลอดภัย

## การกำหนดค่าคู่ {#pair-configuration}

แต่ละคู่ต้นทาง→เป้าหมายสามารถกำหนดค่าได้อย่างอิสระ:

```json
{
  "pairs": {
    "en:fr": {
      "method": "google-translate",
      "qualityTier": "high"
    },
    "en:ja": {
      "method": "llm",
      "model": "google/gemini-3.1-pro-preview"
    },
    "en:crk": {
      "method": "llm-coached"
    }
  }
}
```

### ฟิลด์ของคู่

| ฟิลด์ | ชนิดข้อมูล | คำอธิบาย |
|-------|------|-------------|
| `method` | `string` | วิธีการแปล: `llm`, `llm-coached`, `openai`, `anthropic`, `gemini`, `local`, `google-translate`, `deepl`, `microsoft-translator`, `libretranslate`, `apertium`, `tilde`, `translated`, `api` |
| `methodPlugin` | `string` | ชื่อปลั๊กอินที่ติดตั้ง (จาก `.champollion/methods/`) |
| `model` | `string` | ลบล้างโมเดลเริ่มต้นสำหรับคู่ภาษานี้ |
| `temperature` | `number` | ลบล้างอุณหภูมิ (temperature) เริ่มต้นสำหรับคู่ภาษานี้ |
| `batchSize` | `number` | ลบล้างขนาดแบทช์เริ่มต้นสำหรับคู่ภาษานี้ |
| `register` | `string` | ลบล้างระดับภาษา/โทนเสียง (คีย์พรีเซ็ตหรือข้อความอิสระ) |
| `endpoint` | `string` | URL เอนด์พอยต์ Remote API จำเป็นต้องระบุเมื่อ `method` เป็น `api` |
| `coachingFile` | `string` | เส้นทางไปยังไฟล์พรอมต์สอนงานสำหรับคู่ภาษานี้ อ่านสัมพัทธ์กับโปรเจกต์ ซึ่งจะแทนที่คำสอนงานที่มีความเฉพาะเจาะจงน้อยกว่า และหากอ่านไฟล์ไม่ได้จะหยุดการทำงาน |
| `promptContext` | `string` | บริบทของแอปพลิเคชันสำหรับคู่ภาษานี้ |
| `genderGuidance` | `string` \| `false` | คำแนะนำเรื่องเพศสำหรับพรอมต์ของคู่ภาษานี้: ข้อความของคุณเอง หรือ `false` หากไม่ต้องการระบุ ดูที่ [คำแนะนำเรื่องเพศ](#gender-guidance) |
| `qualityTier` | `string` | ป้ายกำกับที่คุณกำหนดให้กับผลลัพธ์ของคู่ภาษานี้: `standard`, `high`, `research`, `verified` ไม่มีการวัดผล และการซิงค์จะแปลเหมือนเดิมไม่ว่าจะระบุค่าใด โดย `status` จะแสดงค่านี้ (เฉพาะเมื่อกำหนดไว้) และ `serve` จะประกาศค่านั้น |
| `fallback` | `object` | วิธีการแปลลำดับที่สองสำหรับสิ่งที่วิธีหลักของคู่ภาษานี้ไม่สามารถแปลได้อย่างปลอดภัย ดูที่ [วิธีสำรอง](#fallback) ทั้งนี้ `null` จะนำวิธีสำรองที่ตั้งค่าไว้ในระดับภาษาออก |

### วิธีสำรอง {#fallback}

คู่ภาษาสามารถระบุวิธีลำดับที่สองได้ โดยวิธีหลักของคู่ภาษานั้นจะแปลก่อน สิ่งใดที่ไม่สามารถแปลได้อย่างปลอดภัยจะถูกส่งไปยังวิธีสำรองหนึ่งครั้ง:

- **ไฟล์คีย์-ค่า:** คีย์ที่[เกตตรวจสอบคุณภาพ](/docs/concepts/quality-gate)ปฏิเสธ (เช่น คีย์ที่ `{name}` ตกหล่น, พหูพจน์เสียหาย, ป้ายกำกับสองคำกลายเป็นย่อหน้า) และคีย์ที่วิธีดังกล่าวไม่ส่งค่าใดๆ กลับมา
- **Markdown (เนื้อหา Hugo และเอกสาร Docusaurus):** ฟิลด์ front-matter ที่วิธีนั้นละเว้นหรือลบคำออกจนหมด และบล็อกเนื้อหาที่ละเว้นไปจากการตอบกลับ เสียหาย (สูญเสียองค์ประกอบที่ได้รับการป้องกัน: โค้ด, แท็ก HTML, shortcode) หรือถูกทำให้ว่างเปล่า สำหรับการแบ่งส่วนแบบ `page` จะหมายถึงทั้งหน้า

```json
{
  "pairs": {
    "en:crk": {
      "method": "api",
      "endpoint": "http://127.0.0.1:8378/translate",
      "fallback": { "method": "llm-coached", "model": "google/gemini-3.8-flash" }
    }
  }
}
```

เมื่อไม่อนุญาตให้ข้อความใดๆ หลุดออกจากเครื่องของคุณ (เช่น โรงพยาบาล, โรงเรียน, ชุมชนที่เก็บรักษาข้อมูลภาษาของตนไว้ภายในเครื่อง) ให้ตั้งค่าวิธีสำรองเป็นโมเดลที่คุณรันด้วยตนเอง วิธี `local` จะส่งคำขอไปยังเซิร์ฟเวอร์ที่เข้ากันได้กับ OpenAI บนเครื่องนี้ (Ollama, llama.cpp, vLLM, LM Studio โดย `LOCAL_API_BASE` ใช้สำหรับตั้งค่าที่อยู่ ดูที่ [`local`](/docs/guides/translation-methods#local--your-own-model-ollama-vllm-lm-studio-a-trained-model)):

```json
{
  "pairs": {
    "en:crk": {
      "method": "api",
      "endpoint": "http://127.0.0.1:8378/translate",
      "fallback": { "method": "local", "model": "<your local model>" }
    }
  }
}
```

ควรเลือกใช้อันไหน:

- **โมเดลที่โฮสต์บนคลาวด์** (`llm-coached` ร่วมกับโมเดล Gemini หรือวิธี API อื่นๆ) มักจะเป็นความเห็นที่สองที่แข็งแกร่งกว่าสำหรับภาษาที่มีทรัพยากรน้อย (low-resource languages) และจะคิดค่าบริการตามคำขอ ให้ใช้ตัวเลือกนี้เมื่อข้อความสามารถส่งไปยังผู้ให้บริการรายนั้นได้
- **`local`** จะเก็บทุกคีย์ไว้บนเครื่องนี้ และการประมาณการจะแสดงเป็น `$0 API cost (runs on this machine)` ให้ใช้ตัวเลือกนี้เมื่อไม่มีข้อความใดได้รับอนุญาตให้ออกจากเครื่อง แม้ว่าโมเดลที่คุณรันบนเครื่องจะมีขนาดเล็กกว่าก็ตาม

ผลลัพธ์ของวิธีสำรองจะต้องผ่านเกตตรวจสอบคุณภาพเดียวกัน สิ่งที่แปลสำเร็จจะถูกแคชไว้ภายใต้วิธีของมันเองใน Translation Memory ทำให้แคชบันทึกว่าวิธีใดเป็นผู้สร้างแต่ละค่า การซิงค์ในภายหลังจะนำค่านั้นกลับมาใช้ใหม่แทนที่จะถามวิธีแรกอีกครั้ง หากใช้ `--fresh` หรือ `--retranslate` จะเป็นการขอให้แปลใหม่ สิ่งที่ไม่มีวิธีใดแปลได้จะยังคงสถานะเดิมเหมือนกรณีที่ไม่มีวิธีสำรอง: คีย์จะถูกปล่อยทิ้งไว้โดยไม่แปลและคงรายการล็อกเดิมไว้ ทำให้การซิงค์รอบถัดไปจะลองแปลคีย์นั้นใหม่ และ `champollion verify` จะแสดงรายการดังกล่าว บล็อก Markdown จะถูกเขียนเป็นข้อความต้นทางที่มีคำนำหน้า `[EN] ` โดยไม่ถูกแคช และไฟล์จะถูกประมวลผลใหม่อีกครั้งในการซิงค์รอบถัดไป สำหรับบล็อกหรือฟิลด์ front-matter ที่เกตตรวจสอบคุณภาพปฏิเสธจากทั้งสองวิธีจะถูกระงับไว้ (held back) และจะไม่ส่งไปยังวิธีเหล่านั้นอีกจนกว่า `--redo files:<page>` จะระบุชื่อหน้านั้น ([บล็อก Markdown และฟิลด์ front-matter ที่ถูกปฏิเสธ](/docs/concepts/quality-gate#refused-markdown-blocks-and-front-matter-fields)) หากฟิลด์ front-matter ถูกทำให้ว่างเปล่าโดยทั้งสองวิธี หรือมีหน้าที่ไม่มีวิธีใดแปลได้ ไฟล์นั้นจะถือว่าล้มเหลว เช่นเดียวกับกรณีที่ไม่มีวิธีสำรอง

วิธีสำรองยอมรับฟิลด์เดียวกับคู่ภาษา: `method` (จำเป็นต้องระบุ), `model`, `provider`, `endpoint`, `methodPlugin`, `coachingFile`, `coachingPrompt`, `promptContext`, `register`, `temperature`, `batchSize`, `maxRetries`, `qualityTier`, `contentSegmentation`, `name` และจะประมวลผลค่าเหมือนกับคู่ภาษา ฟิลด์ที่ไม่ได้กำหนด (ระดับภาษา, การสอนงาน, บริบทของพรอมต์, …) จะดึงมาจากคู่ภาษาของมัน `coachingFile` ของวิธีสำรองจะส่งไปยังพรอมต์และแคชคีย์ของมัน และ `champollion status` จะแสดงค่านั้น ระบบการเขียนเป็นของคู่ภาษา ดังนั้น `script` และ `scriptFallback` จึงถูกปฏิเสธในวิธีสำรอง เช่นเดียวกับ `fallback` ของวิธีสำรองเอง วิธีที่ไม่รู้จักหรือวิธีสำรองที่เหมือนกับคู่ภาษาของมันจะทำให้การซิงค์หยุดลงพร้อมข้อผิดพลาดที่ระบุชื่อคู่ภาษา วิธีสำรองจะต้องพร้อมทำงานก่อนที่การซิงค์จะเริ่มต้นขึ้น เช่นเดียวกับวิธีหลักของคู่ภาษา (เช่น ต้องมีการตั้งค่า API key ไว้แล้ว)

- **`--method` และ `--model` จะเปลี่ยนเฉพาะวิธีหลักของคู่ภาษาเท่านั้น** วิธีสำรองจะคงค่าตามที่ไฟล์การกำหนดค่าระบุไว้
- **ค่าใช้จ่าย** การประมาณการก่อนการรันจะครอบคลุมเฉพาะวิธีหลักของคู่ภาษาเท่านั้น เนื่องจากไม่มีใครทราบล่วงหน้าว่าจะมีสิ่งใดล้มเหลวบ้าง แต่ละแบทช์ของวิธีสำรองจะถูกประเมินราคาก่อนเริ่มรันทันทีด้วยตัวประมาณการเดียวกัน เมื่อใช้ `--max-cost` แบทช์ที่จะทำให้การรันมีค่าใช้จ่ายเกินเพดานที่กำหนดไว้ (ยอดประมาณการบวกกับแบทช์ของวิธีสำรองทั้งหมดก่อนหน้านี้) จะถูกข้ามไป พร้อมคำเตือนที่ระบุชื่อคีย์ รวมถึงวิธีสำรองที่ไม่สามารถประเมินค่าใช้จ่ายได้ (สิ่งที่ไม่ทราบไม่ใช่สิ่งที่ใช้งานได้ฟรี) คีย์เหล่านั้นจะยังคงอยู่ในสถานะล้มเหลว และการซิงค์จะจบการทำงานด้วยรหัสที่ไม่ใช่ศูนย์เหมือนกับความล้มเหลวบางส่วนอื่นๆ
- **การรายงานผล** `sync` จะพิมพ์หนึ่งบรรทัดต่อหนึ่งคู่ภาษา เช่น `[FALLBACK] en:crk — 6 key(s) the primary (api) could not translate safely → translated by llm-coached (4 accepted, 2 still failing)` ข้อมูลสรุปของ `--json` จะบอกเป็นรายคู่ภาษาว่าวิธีสำรองได้ทำอะไรไปบ้าง (`method`, `attempted`, `accepted`, `failed`, `cached`): ในแต่ละรายการของ `locales` สำหรับไฟล์คีย์-ค่า, ใน `fallback` สำหรับ JSON ของ Docusaurus และใน `content.fallback` สำหรับ Markdown `champollion status` จะแสดงวิธีสำรองไว้ภายใต้คู่ภาษาของมัน `--dry` ไม่สามารถทราบได้ว่าสิ่งใดจะล้มเหลว จึงไม่รายงานสิ่งใดเกี่ยวกับวิธีสำรอง
- **เมื่อผลลัพธ์ส่วนใหญ่มาจากวิธีสำรอง** เมื่อมากกว่าครึ่งหนึ่งของคำแปลใหม่ในการรันรอบนั้นสำหรับคู่ภาษาหนึ่งๆ (คำตอบที่ยอมรับของวิธีหลักบวกกับของวิธีสำรอง) มาจากวิธีสำรอง `sync` จะเพิ่มคำเตือนหนึ่งข้อ: จำนวนกี่รายการจากทั้งหมด, โดยวิธีและโมเดลใด, เพราะเหตุใดคำตอบของวิธีหลักจึงไม่ถูกนำมาใช้ (แจกแจงแต่ละเหตุผล: ประโยคที่ท่องจำถูกนำมาพูดซ้ำกับสตริงต้นทางที่แตกต่างกัน, ความยาวที่เพิ่มขึ้นผิดปกติ, …) และข้อเสนอแนะที่ควรพิจารณา — วิธีหลักของคู่นั้นอาจไม่เหมาะกับสตริงเหล่านี้, ให้ตรวจสอบสิ่งที่เขียนลงไป (`verify` ตรวจสอบโครงสร้าง, ผู้พูดภาษานั้นตรวจสอบความหมาย), ใช้วิธีสำรองที่แข็งแกร่งกว่า รายการใน `--json` จะมี `primaryAccepted` และ `primaryReasons` อยู่ข้างๆ `accepted` ส่วน `champollion status` จะแสดงสัดส่วนเดียวกันสำหรับไฟล์ต่างๆ ("จากวิธีสำรอง: 8 ค่าในไฟล์ (…) — 8 จาก 8 ค่าที่การซิงค์เขียน (100%)") และแจ้งเตือนเมื่อคำแปลส่วนใหญ่ของโลแคลมาจากวิธีสำรอง
- `champollion serve` จะใช้วิธีสำรองด้วยเช่นกัน ภายใต้เพดาน `--max-cost-per-request` / `--max-session-cost`

## การกำหนดค่าภาษา {#language-configuration}

ภาษารองรับสามรูปแบบ:

### อาร์เรย์ของรหัส (ง่ายที่สุด)

```json
{
  "languages": ["fr", "de", "ja"]
}
```

แต่ละภาษาจะได้รับ register เริ่มต้นจากตาราง register ในตัว ภาษาที่ไม่มีค่าเริ่มต้นจะได้รับ `"Professional register."`

### อ็อบเจกต์พร้อมสตริง register

ค่าสามารถเป็น **preset key** จาก language card หรือข้อความ register ที่กำหนดเอง:

```json
{
  "languages": {
    "fr": "casual-tu",
    "ko": "formal-hapsyo",
    "ja": "Custom: Polite Japanese for a gaming app."
  }
}
```

Champollion จะตรวจสอบว่าสตริงตรงกับ preset key ใน language card หรือไม่ หากตรงกัน จะใช้ register prompt แบบเต็มจาก card นั้น หากไม่ตรงกัน จะใช้สตริงนั้นตามที่เป็น ดู [ภาษาที่รองรับ](/docs/reference/supported-languages#language-cards) สำหรับ preset ที่มีอยู่

### อ็อบเจกต์พร้อมการกำหนดค่าแบบเต็ม

```json
{
  "languages": {
    "crk": {
      "name": "Plains Cree",
      "register": "SRO syllabics with grammatical precision.",
      "model": "google/gemini-3.1-pro-preview",
      "batchSize": 5,
      "maxRetries": 5,
      "script": "Cans"
    }
  }
}
```

คุณสามารถผสมรูปแบบย่อและอ็อบเจกต์แบบเต็มในบล็อกเดียวกันได้


### ฟิลด์ภาษา

| ฟิลด์ | ชนิดข้อมูล | คำอธิบาย |
|-------|------|-------------|
| `register` | `string` | คำแนะนำด้านสไตล์/โทนเสียง สามารถเป็น**คีย์พรีเซ็ต** (เช่น `casual-tu`, `formal-hapsyo`) หรือข้อความที่กำหนดเอง ดูที่ [การ์ดภาษา (Language Cards)](/docs/reference/supported-languages#language-cards) |
| `name` | `string` | ชื่อภาษาที่มนุษย์อ่านได้ (สำหรับแสดงสถานะ) |
| `model` | `string` | ลบล้างโมเดลเริ่มต้น |
| `temperature` | `number` | ลบล้างอุณหภูมิ (temperature) เริ่มต้น |
| `batchSize` | `number` | ลบล้างขนาดแบทช์เริ่มต้น |
| `coachingFile` | `string` | เส้นทางไปยังไฟล์พรอมต์สอนงานสำหรับภาษานี้ อ่านสัมพัทธ์กับโปรเจกต์ ซึ่งจะแทนที่การสอนงานระดับบนสุด และหากอ่านไฟล์ไม่ได้จะหยุดการทำงาน |
| `promptContext` | `string` | บริบทของแอปพลิเคชันสำหรับภาษานี้ |
| `genderGuidance` | `string` \| `false` | คำแนะนำเรื่องเพศสำหรับพรอมต์ของภาษานี้: ข้อความของคุณเอง หรือ `false` หากไม่ต้องการระบุ ดูที่ [คำแนะนำเรื่องเพศ](#gender-guidance) |
| `maxRetries` | `number` | จำนวนรอบสูงสุดในการลองใหม่สำหรับแบทช์ที่ล้มเหลว (ค่าเริ่มต้น: 3) |
| `script` | `string` | รหัส ISO 15924 ของระบบอักขรวิธีที่ Champollion จะเขียน (เช่น `"Cans"`, `"Piqd"`) ดูที่ [การแปลงชุดอักษร](#script-conversion) |
| `scriptFallback` | `object` | กฎการถอดอักษรสำหรับตัวอักษรที่ตัวแปลงชุดอักษรไม่สามารถจับคู่ได้ ดูที่ [การแปลงชุดอักษร](#script-conversion) |
| `endpoint` | `string` | URL เอนด์พอยต์ Remote API สำหรับ `"method": "api"` |
| `fallback` | `object` | วิธีการแปลลำดับที่สองสำหรับสิ่งที่วิธีของภาษานี้ไม่สามารถแปลได้อย่างปลอดภัย ดูที่ [วิธีสำรอง](#fallback) |

:::info[ลำดับการสืบทอด]
การตั้งค่าจะถูกแก้ไขตามลำดับนี้ (ค่าแรกมีผลก่อน):

**ระดับคู่** → **ระดับภาษา** → **การกำหนดค่าส่วนกลาง** → **ค่าเริ่มต้น**

ตัวอย่างเช่น หาก `pairs["en:fr"]` ตั้งค่า `model` จะแทนที่ค่า `model` ทั้งในระดับภาษาและระดับส่วนกลาง
:::

### คำแนะนำเรื่องเพศ {#gender-guidance}

พรอมต์ของ LLM จะมีคำแนะนำเกี่ยวกับเพศทางไวยากรณ์สำหรับภาษาที่มีระบบเพศ โดยนำมาจากแค็ตตาล็อกของ Champollion: ภาษาฝรั่งเศสจะขอให้ใช้ *écriture inclusive* พร้อมจุดคั่นกลางเมื่อไม่ทราบเพศของผู้อ่าน (`Connecté·e` ไม่ใช่ `Connecté(e)` หรือ `Connectée`; และใช้ `Utilisateur·rice·s` ในรูปพหูพจน์) ภาษาเยอรมันจะขอให้ใช้รูปแบบโคลอน (`Benutzer:innen`) ภาษาญี่ปุ่นจะขอให้ใช้คำที่เป็นกลาง `私` คำสั่ง `champollion init` จะพิมพ์ข้อมูลนี้ข้างๆ ระดับภาษาของแต่ละภาษา และ `champollion status` จะแสดงค่านี้แยกตามคู่ภาษาพร้อมทั้งระบุที่มาของข้อมูล

เลือกสไตล์อื่นได้ด้วย `genderGuidance` สำหรับทุกภาษาหรือเจาะจงเฉพาะภาษาใดภาษาหนึ่ง:

```json
{
  "languages": {
    "fr": { "register": "formal-vous", "genderGuidance": "Use the masculine generic (Connecté), as the Académie française recommends." },
    "de": { "register": "formal-Sie", "genderGuidance": false }
  }
}
```

`false` จะไม่ส่งคำแนะนำเรื่องเพศ ส่วนสตริงจะเข้าไปแทนที่คำแนะนำของแค็ตตาล็อก การตั้งค่านี้จะใช้กับวิธีที่รับคำแนะนำ (วิธีแบบ LLM) โดยระบบแปลภาษาด้วยเครื่อง (DeepL, Google, …) จะไม่ได้รับคำแนะนำนี้ การเปลี่ยนคำแนะนำเรื่องเพศจะทำให้พรอมต์เปลี่ยนไป จึงมีรายการในแคชแยกต่างหาก: สิ่งที่แปลไปแล้วจะคงเดิมจนกว่าคุณจะสั่งแปลใหม่ (`champollion sync --redo all` ซึ่งการซิงค์จะแนะนำเมื่อไฟล์ยังมีสไตล์แบบเดิมอยู่)

## ภาษาต้นทางที่ไม่ใช่ภาษาอังกฤษ

หากภาษาต้นทางของคุณไม่ใช่ภาษาอังกฤษ:

```bash
# CLI flag (one-time)
npx champollion sync --source fr
```

```json title="champollion.config.json (permanent)"
{
  "inputLocale": "fr"
}
```

## Lock File

Champollion จะสร้าง `.champollion.lock` เพื่อติดตามแฮช SHA-256 ของค่าต้นทางที่ได้รับการแปลแล้ว **โปรดคอมมิตไฟล์นี้** เพื่อให้นักพัฒนาทุกคนใช้ข้อมูลฐาน (baseline) ในการแปลร่วมกัน ในโปรเจกต์ที่มีหนึ่งโฟลเดอร์ต่อภาษา คีย์จะถูกบันทึกเป็น `<namespace>::<key>`

ในแต่ละโลแคลเป้าหมาย ไฟล์ล็อกจะบันทึกลายนิ้วมือ (fingerprint) ของแต่ละค่าที่การซิงค์เขียนขึ้น และของข้อความต้นทางที่นำมาแปล (เพื่อให้สามารถตรวจจับค่าที่บุคคลแก้ไขได้ และรายงานคำแปลที่ล้าสมัย) รวมถึงคีย์ที่การ redo ยังทำไม่เสร็จ (**pending**) และคีย์ที่เกตตรวจสอบคุณภาพปฏิเสธ (**held back** จากโมเดลเดิม) หากมีข้อมูลใดในกลุ่มนี้ต้องบันทึก ไฟล์จะเปลี่ยนไปใช้รูปแบบเวอร์ชัน 2 นั่นคือ `{"version": 2, "source": {…}, "locales": {…}}` ส่วนไฟล์ล็อกเวอร์ชัน 1 (แผนผังคีย์ → แฮช แบบแบนราบ) จะยังคงอ่านได้ตามปกติ การแก้ไขด้วยมือที่ถูกแทนที่จะถูกเก็บไว้ใน `.champollion-replaced-edits.jsonl` ที่อยู่ข้างๆ — โปรดคอมมิตทั้งสองไฟล์ ดูที่ [เกตตรวจสอบคุณภาพ](/docs/concepts/quality-gate#refused-keys-are-held-back) และ [การแก้ไขคำแปล](/docs/guides/professional-translators#editing-key-value-files)

เมื่อค่าต้นทางเปลี่ยนแปลง hash จะไม่ตรงกันอีกต่อไป และ champollion จะแปล key นั้นใหม่ในการซิงค์ครั้งถัดไป

## `.champollionignore`

สร้าง `.champollionignore` ในไดเรกทอรีรากของโปรเจกต์เพื่อยกเว้นไฟล์จากการสแกน `lint` ใช้รูปแบบ glob เช่น `.gitignore`:

```text title=".champollionignore"
src/components/legacy/**
src/utils/constants.js
**/*.test.js
```

## ไดเรกทอรี `.champollion/`

Champollion สร้างไดเรกทอรี `.champollion/` ในรูทของโปรเจกต์ของคุณสำหรับเก็บสถานะภายใน โปรดอย่าใส่ไดเรกทอรีนี้ในระบบควบคุมเวอร์ชัน (version control) — เนื่องจากเป็นแคชประจำแต่ละเครื่อง ไม่ใช่ซอร์สโค้ดของโปรเจกต์ คำสั่ง `champollion init` จะเพิ่มบรรทัดนี้ลงใน `.gitignore` และสร้างไฟล์นี้ขึ้นมาหากยังไม่มี (รวมถึงในโฟลเดอร์ที่ยังไม่ได้เป็น git repository เพื่อไม่ให้คำสั่ง `git init` และ `git add --all` ในภายหลังคอมมิตแคชเข้าไป):

```gitignore
.champollion/
```

คอมมิตไฟล์ล็อกที่อยู่ข้างๆ (`.champollion.lock`, `.champollion-content.lock`): ไฟล์เหล่านี้จะบันทึกว่าคำแปลแต่ละรายการสร้างขึ้นจากข้อความต้นทางใด

| ไฟล์ | วัตถุประสงค์ | ควบคอมมิตหรือไม่? |
|------|---------|--------|
| `tm.json` | แคช Translation Memory — เก็บคำแปลก่อนหน้าโดยมีคีย์เป็น ข้อความต้นทาง + โลแคล + วิธีการแปล | ไม่ต้อง (แคชในเครื่อง) |
| `xliff/*.xliff` | ไฟล์ส่งออก XLIFF สำหรับให้นักแปลมืออาชีพตรวจสอบ | ไม่ต้อง (ไฟล์ชั่วคราว) |
| `methods/` | แมนิเฟสต์ของปลั๊กอินวิธีการแปลที่ติดตั้ง | ถูกละเว้นโดยบรรทัด `.champollion/` หากต้องการแชร์ปลั๊กอินที่ติดตั้ง ให้แทนที่บรรทัดนั้นด้วย `.champollion/*` และ `!.champollion/methods/` |
| `backups/` | ไฟล์สำรองก่อนตัดบรรทัด (สร้างโดย `wrap --undo`) | ไม่ต้อง (เครือข่ายความปลอดภัย) |

ดู [Translation Memory](/docs/concepts/translation-memory) สำหรับรายละเอียดเกี่ยวกับ `tm.json` และวิธีที่ช่วยประหยัดค่าใช้จ่าย API

## Programmatic API

สำหรับ build script และการผสานรวมที่กำหนดเอง ให้ import โดยตรงจาก package:

```javascript
import { GeminiMethod, runSync, resolveConfig } from 'champollion';

// Use a method class directly
const gemini = new GeminiMethod();
const result = await gemini.translate(
  ['greeting', 'farewell'],
  { greeting: 'Hello', farewell: 'Goodbye' },
  { target: 'fr', name: 'French', register: 'formal', model: 'gemini-2.5-flash' },
  { cwd: process.cwd() }
);
// result = { greeting: 'Bonjour', farewell: 'Au revoir' }
```

### Export ที่มีให้ใช้งาน

| เอ็กซ์พอร์ต | หน้าที่การทำงาน |
|--------|-------------|
| `TranslationMethod` | คลาสพื้นฐานสำหรับทุกวิธีการแปล |
| `LLMMethod` | คลาสพื้นฐานสำหรับวิธีการแปลแบบ LLM (OpenRouter) |
| `DirectLLMMethod` | คลาสพื้นฐานสำหรับผู้ให้บริการ LLM โดยตรง (OpenAI, Anthropic, Gemini) |
| `OpenAIMethod`, `AnthropicMethod`, `GeminiMethod` | คลาสผู้ให้บริการ LLM โดยตรง |
| `DeepLMethod`, `MicrosoftTranslatorMethod`, `LibreTranslateMethod`, `TildeMethod`, `TranslatedMethod` | คลาส MT แบบดั้งเดิม |
| `GoogleTranslateMethod` | Google Cloud Translation |
| `LLMCoachedMethod` | LLM ที่มีการสอนงาน (OpenRouter + ข้อมูลการสอนงาน) |
| `APIMethod` | ไคลเอ็นต์ Remote API |
| `runSync`, `runContentSync` | ไพป์ไลน์การซิงค์แบบเต็มรูปแบบ |
| `translateWithFallback`, `translateAndValidate` | ไพป์ไลน์ของคู่ภาษาหนึ่งๆ สำหรับแบทช์ของคีย์ ตามที่ `sync` รัน: แคช, วิธีการแปล, เกตตรวจสอบคุณภาพ, แคช จากนั้นจึงเป็นวิธีสำรองของคู่นั้น ส่งคู่ภาษาจาก `resolvePairs`, `tm` จาก `loadTM` และ `cwd` ซึ่งเป็นไดเรกทอรีโปรเจกต์: วิธีการแปลจะอ่านคีย์, เอนด์พอยต์, การสอนงาน และกลอสซารีจากที่นั่น ไม่ใช่จาก `process.cwd()` |
| `createFallbackBudget` | ตัวป้องกัน `--max-cost` สำหรับแบทช์วิธีสำรอง (`{ maxCost, committed, cwd }`) |
| `discoverLocaleLayout`, `resolveLocaleFiles` | ไฟล์ที่ประกอบขึ้นเป็นแต่ละโลแคล (แบบแบน, โฟลเดอร์ต่อโลแคล หรือ `localesPattern`) |
| `resolveConfig`, `resolvePairs` | การแก้ไขและประมวลผลการกำหนดค่า (Config resolution) |
| `validateTranslations` | เกตตรวจสอบคุณภาพ (Quality gate) |
| `loadCoachingData`, `findDictionaryMatches` | ยูทิลิตีสำหรับการสอนงาน (Coaching utilities) |

### การขยาย Custom Provider

ขยาย `DirectLLMMethod` เพื่อเพิ่มผู้ให้บริการ LLM ใหม่ในประมาณ 40 บรรทัด:

```javascript
import { DirectLLMMethod } from 'champollion';

class MistralMethod extends DirectLLMMethod {
  constructor(options) {
    super(options);
    this.name = 'mistral';
  }
  _getApiKeyEnvVar()     { return 'MISTRAL_API_KEY'; }
  _getApiKeyOptionsKey() { return 'mistralApiKey'; }
  _getDefaultModel()     { return 'mistral-large-latest'; }
  _getProviderLabel()    { return 'Mistral'; }

  _buildApiRequest({ prompt, systemMessage, apiKey, model, temperature }) {
    return {
      url: 'https://api.mistral.ai/v1/chat/completions',
      headers: { 'Authorization': `Bearer ${apiKey}`, 'Content-Type': 'application/json' },
      body: {
        model,
        messages: [
          ...(systemMessage ? [{ role: 'system', content: systemMessage }] : []),
          { role: 'user', content: prompt },
        ],
        temperature,
      },
    };
  }

  _extractResponseText(json) {
    return json.choices?.[0]?.message?.content;
  }

  // Optional but recommended: provider-specific setup help when translation fails
  getSetupHelp() {
    if (!process.env.MISTRAL_API_KEY) {
      return [
        '',
        '  ┌─ Missing API Key ─────────────────────────────────────────────┐',
        '  │ Mistral requires an API key from https://console.mistral.ai   │',
        '  │ Run: export MISTRAL_API_KEY=...                               │',
        '  └────────────────────────────────────────────────────────────────┘',
      ];
    }
    return ['        API key is set but translation failed. Check your Mistral dashboard.'];
  }
}
```

คุณได้รับ translate, coaching, retry loop, การตรวจสอบโมเดล, quality tier และความช่วยเหลือในการตั้งค่าโดยไม่ต้องเขียนเพิ่ม เฉพาะรูปแบบ HTTP request เท่านั้นที่เฉพาะเจาะจงกับผู้ให้บริการ สำหรับ adapter ที่ไม่ใช่ LLM ที่ใช้ `fetch()` แบบดิบ ให้ใช้ helper `fetchWithRetry()` ที่ใช้ร่วมกันจาก `lib/methods/fetch-with-retry.js` แทนการเขียน retry loop ของตัวเอง
