# MT 評価

> **概要:** このページでは、リーダーボードの提出基準、スコアリング（chrF++を主要指標とし、標準的な指標や診断指標を併記）、不正対策ポリシー、検証ティア、および提出ワークフローについて定義します。評価データに接触したことのある手法は失格となります。

champollion には、翻訳手法の**再現可能なベンチマーク**を目的とした機械翻訳評価フレームワークが含まれています。これは特に、標準的な MT ベンチマークが存在せず、品質の主張を検証しにくい低リソース言語や先住民族言語を対象としています。

---

## リーダーボード

その中心となるのが**[手法リーダーボード（Method Leaderboard）](https://champollion.dev/leaderboard)**です。これは公開スコアボードであり、稼働中で**提出を受け付けています**。研究者やコミュニティメンバーが、フィンガープリント付きの再現可能な評価を用いて翻訳手法を提出し、比較することができます。

各提出には以下が含まれます：

- **フィンガープリント付きパイプライン** — 特定のGitコミットおよび設定ハッシュと紐付けられているため、結果を生成した正確なコードまで遡ることができます
- **バージョン管理されたデータセット** — コンテンツハッシュおよびバージョン管理が施されており、スコアは同一のデータセットバージョン間でのみ比較可能です
- **標準化された指標** — すべてのスコアリングは共有の評価ハーネスによって計算され、実装による差異を排除します
- **信頼ティア** — 自己ベンチマーク（Self-benchmarked）、Champollion検証済み（Champollion Verified）、コミュニティ検証済み（Community Validated）
- **コスト追跡** — 提出ごとのAPIコストを記録し、コストと品質のトレードオフを透明化します

リーダーボードは、WMT、FLORES-200、AmericasNLP共有タスクが機械翻訳の評価を報告するのと同じ方法で実行結果をランク付けします。すなわち、**1つの標準指標であるchrF++**を用い、95%信頼区間およびsacreBLEUシグネチャ（例: `chrF++ 47.5 [45.9, 49.0]`）とともに表示します。それ以外の指標はすべてその隣に表示され、chrF++と混ざり合うことは決してありません。

| 指標 | 役割 | 測定内容 |
|------|------|----------|
| **chrF++** | **主要かつ順位付けの指標** | 参照訳に対する文字n-gram Fスコア（sacreBLEU、`word_order=2`）。単語レベルの指標よりも豊富な形態論に適切に対応します |
| **BLEU、spBLEU、TER、COMET** | 標準指標（主要指標の隣に表示） | 機械翻訳の論文で報告されるその他の指標。COMETが計算された場合は、そのモデルIDとともに表示されます |
| **Exact Match** | 診断指標 | 翻訳が参照訳と完全に一致する頻度 |
| **FST Acceptance** | 診断指標 | 有限状態トランスデューサ（FST）が存在する言語向け: 出力単語のうち有効な語形である割合。原書や参照訳との比較ではないため、スコアとして扱われることはありません |
| **Equivalent Match** | 診断指標 | 参照訳または許容される異形（語順、正書法上の慣例）と一致する割合。現在はCRK向けで、汎用化を進めています。 |
| **Semantic Score** | 診断指標 | 決定論的バリデータによる意味の保持度。現在はCRK向けで、汎用化を進めています。 |
| **Score caveats** | 主要指標の隣に表示 | 出力が原文をそのままコピーしている場合、参照訳より大幅に短い・長い場合、多数の入力に対して同一の出力を繰り返している場合、またはテスト行が訓練データと重複している場合に表示されます |

ある実行結果が別のものより優れているかどうかは、chrF++での対応のある有意差検定によって判断され、2つの数値の大小関係だけで判断されることはありません。信頼区間の重複は、順序がノイズである可能性への警告です（[統計的有意差検定](/docs/network/specifications/significance)）。コンテストのランキングでは、この検定を用いて順位クラスターを形成します。chrF++は同一データセット上のシステム間でのみ順位付けを行い、言語をまたいで順位を付けることは決してありません。自動スコアが品質ラベルを持つことはなく、話者による人的レビューのみが品質を保証します。以前使用されていた重み付け複合スコアおよび品質ティアは廃止されました。古いカードの複合スコアが表示される場合でも、「レガシー複合スコア（廃止）」としてのみ表示されます。

:::info[完全な指標スイート]
[スコアリング仕様](/docs/network/specifications/scoring#how-runs-are-scored)では、実行結果のスコアリング方法と完全な指標一覧（表層、構造、意味、振る舞い、コンプライアンス、報告用比較指標の6つのカテゴリ）を定義しています。
:::

## 利用可能なデータセット

実行結果がどのデータでスコアリング可能であるかはツール側で一覧化されているため、このページでは独自のリストを保持しません。

```bash
# the runnable corpora for a pair: size, contamination, domain, licence, provider
mt-eval corpora --source eng --target crk

# …and the catalogued ones that can never run, each with its reason
mt-eval corpora --source eng --target crk --include-quarantined
```

[評価データセット](/docs/network/leaderboard/datasets)のページでは、カタログ、コーパス形式、難易度ティア、ライセンス区分、および独自のデータセットを作成する方法について説明しています。そのカタログの3つのルールによって、順位付けの対象となるかどうかが決定されます。

- **隔離（quarantine）されたコーパスは決して順位付けされない。** カタログには掲載されますが、実行可能になることはなく、データベースはそのコーパスに対するスコアの登録を拒否します。EdTeKLAの英語→平原クリー語コーパス（`eval-eng-crk-edtekla-dev-v1`および`eval-eng-crk-edtekla-textbook`）は隔離されています。これらは主権に配慮した修正版のCC BY-NC-SA（`LicenseRef-EdTeKLA-Modified-CC-BY-NC-SA-4.0`）が適用されており、すべてのリーダーボード、賞金レース、および商業用区分から除外されています。
- **汚染されたコーパスは相対比較のみで順位付けされる。** FLORES+、および汚染について`HIGH`や`MEDIUM`と評価された、あるいはまったく評価されていないコーパスは、その実行カードに「相対比較専用」とスタンプされます。そのコーパス上で実行された手法同士を比較するものであり、絶対的な品質として報告されることは決してありません。`LOW`と評価されたコーパスのみが、絶対的な品質に基づいて順位付けされます。
- **ライセンス区分は厳守される。** 非商用コーパスが商用パスや賞金パスに入ることはありません。修正版、特注、または未明示の許諾下にあるコーパスは、権利者の許可がそのエントリに記録されるまで、リモートモデルAPIによる評価を拒否します。

**コンテストは主催者が保持する封印されたセットで実施されます。** コンテストはこれらの公開コーパスでスコアリングされることはありません。コミュニティや組織などの主催者は、独自のインフラ上で封印された非公開テストセットを保持します。参加者は主催者が公開した開発セットで予選を通過した後、実行対象となるモデルまたは手法を主催者のノードに渡します。主催者の管理者が各実行を承認し、スコアのみが出力されます。[ソブリンコンテストの開催](/docs/network/sovereignty/run-a-sovereign-contest)を参照してください。

:::danger[評価データでのトレーニングは禁止]

**これらのデータセットは評価専用です。** 評価データを使って学習、ファインチューニング、few-shot プロンプティング、またはその他の方法で触れた手法は、スコアが人為的に水増しされるため、**リーダーボードから失格となります。**

これは提案ではなく、評価の完全性に関する最も重要なルールです。学習には別のコーパスを使用してください。評価セットは、開発中にモデルが見ていない状態を保つ必要があります。

コーチングデータや few-shot の例を使用する場合は、**完全に別のソース**から取得する必要があります。不明な場合は含めないでください。
:::

:::warning[LLMの非決定性について]

LLM の出力は非決定的です。スコアは、特定のモデルバージョンと API 設定のもとでの時点測定値を表します。モデルプロバイダーはいつでも重み、デコード戦略、または安全フィルターを更新する可能性があり、実行間でスコアのずれが生じることがあります。リーダーボードはすべての提出について、正確なモデルスラッグとタイムスタンプを記録します。
:::

## 優れた手法の条件

すべての手法が同等というわけではありません。厳密な研究と水増しされたスコアを分けるものを以下に示します。

### 優れた手法の特徴

- **学習データと評価データの明確な分離** — 開発、チューニング、プロンプトエンジニアリング、few-shot 例の選択において、手法が評価セットを一切見ていないこと
- **再現可能** — 他の人がリポジトリをクローンしてハーネスを実行し、同じスコアを得られること（LLM の非決定性の範囲内で）
- **文書化されている** — [手法カード](/docs/network/specifications/methods) に、手法の内容、使用ツール、および制限事項が記載されていること
- **スコープについて正直** — 特定の言語ペアにのみ対応している場合はその旨を明記し、特定の形態論的パターンで性能が低下する場合はそれを文書化すること
- **コミュニティを意識している** — 先住民族言語については、データ主権を尊重していること。言語コミュニティと協議しているか、オープンライセンスのデータのみを使用していること

### 危険信号（失格となるもの）

| 危険信号 | 問題の理由 |
|----------|--------------------|
| 評価データでの学習 | 評価の目的を完全に損なう。水増しされたスコアはすべての人を誤解させる |
| 結果のチェリーピッキング | 10 回実行して他の結果を開示せずに最良の結果を提出すること |
| 未開示の後処理 | スコアリング前に出力を手動で修正すること |
| 汚染されたコーチングデータ | 評価セットの例を few-shot プロンプトや辞書エントリとして使用すること |
| 出典なしで商用準備完了を主張すること | 手法が CC BY-NC-SA データを使用している場合、商用利用は不可 |

### 検証ティア

検証ティアは**誰が結果を検証したか**を示します。これらは品質ラベルではありません（以前の自動品質ティアは[廃止](/docs/network/specifications/scoring#5-quality-tiers)されました）。

| ティア | 意味 | 取得方法 |
|------|---------|--------------|
| **Self-benchmarked** | 自身でハーネスを実行し、結果を提出した場合 | `mt-eval publish` を使って実行カードを公開する |
| **Champollion Verified** | プロジェクト側が、提出された出力をSHA固定された参照コーパスに対して独自に再スコアリングし、スコアを再現できた場合 | 再スコアラーはメンテナー用のツールであり、バッチとして手動で実行されます。自動スケジュールはされていないため、提出時に即座に再スコアリングされることはありません（下記参照） |
| **Community Validated** | コミュニティ独自のプロトコルに基づいて認定された対象言語のバイリンガル話者が、出力の層化サンプル（30エントリ以上、査読者2名以上）をレビューし、70%以上がコミュニティの基準を満たした場合。コミュニティ自身のテストによってのみ付与され、抜き打ち監査による降格も対称的に行われます | 手法のコードをガバナンス組織に提出してください。組織側がゴールドスタンダードセットに対して実行し、出力をコミュニティレビューに回します |

**コミュニティ検証済みの判定は独立したレーンであり、現時点では人間による評価スコアは存在しません:** ハーネスは、終了したコンテストの確定ランキングから、決まった人間レビューの予算でカバーできるシステムを選択することはできますが（タイグループ全体単位のみ — クラスターが途中で分割されることはありません）、評価値は記録されず、現在リーダーボード上にあるもので人間の判定が付与されているものはありません。

**順位は厳密な順序ではなく、クラスターです。** 有意差検定で区別できない隣接するエントリは同一順位を共有し、順位の*範囲*が割り当てられます。セグメントごとの出力が主催者のマシンから一切出ない封印型コンテストでは、対応のある検定はそのマシン上で実行され、署名された判定のみが出力されます。それらがない場合、タイは信頼区間または点推定値の一致の証拠に依存します。その仕組みや、証拠の各段階の強弱については、[統計的有意差検定 → ランキングクラスター](/docs/network/specifications/significance#ranking-clusters)に詳述されています。

### 検証のスケーリング方法: レピュテーション加重監査

**私たちは出所（プロベナンス）を主張しません。** リーダーボードの行は、コントリビューターが*オープンソース*のハーネスを*自身の*マシンで実行することによって生成されます。セルフホストの計算資源に対して「この実行が本当にハーネスを通じて行われたか」をサーバー側で検証することはできません。ハーネスの署名キーはコントリビューターの手元にあるため、署名が証明するのは*機械であって誠実さではない*からです。そうではないと見せかける代わりに、**ここでの妥当性は実績によって獲得され、自己修正されます**。ある行が信頼できるのは、そのスコアが**再現可能**であること、そしてその背後にいるコントリビューターが、**改ざんが発覚すれば失墜するレピュテーション（信用）を賭けている**からです。検証は4つのレイヤーで実行されるため、必要な箇所では徹底的でありながら、可能な箇所では低コストに抑えられます。プロジェクト側が全員の作業をすべて再実行する必要はありません。

- **L0 — 全件再スコアリング（コストゼロ、約100%）。** 再スコアラーは、*提出された出力そのもの*から、**SHA固定された参照コーパス**（ローカルに保存されたコピーではありません）に対して、ハーネスと同じ指標を用いてスコアを再計算します。出力からスコアが再現されない場合、または保存された参照訳が改変されていた場合、その実行は**失格**となります。これだけで、手入力されたスコアや改ざんされたスコアは排除されます。再現が確認された実行は**Champollion Verified**に昇格します。これはコンテストのランキングでデフォルトとして使用されるティアであり、賞金の対象となる唯一のティアです。この仕組みは実装済みで低コストですが、**メンテナーが手動で実行するコマンド**です。提出時に自動実行されることはなく、スケジュールもされていません。これが変更されるまでは、すべての行は自己ベンチマーク（self-benchmarked）のまま届き、その状態を維持します。
- **L1 — コントリビューターのレピュテーションラダー。** 各コントリビューター（サインインによって識別）は、以下のより厳格なチェックをパスすること*のみ*によってレピュテーションを獲得します。提出量だけで獲得することは決してできないため、新しいIDを次々と作成しても意味はありません。レピュテーションは**公開**されており、コストの高いチェックがどの頻度でトリガーされるかを決定します。
- **L2 — サンプルの再実行（コストの高いチェック。現時点ではポリシーのみで、再実行ツールは未実装）。** *公開*開発セットの場合、L0では参照訳をそのまま自分の「翻訳」としてコピーしたコントリビューターを検知できません。それを検知するには実際にモデルを再実行する（本物の計算資源を使う）必要があり、全員ではなく**サンプル**に対して実施します。**サンプリングポリシー**は構築・テスト済みです。実行が選択される確率は、**重要度**が高いほど上がり（言語ファミリー全体への最初の架け橋となる実行は*常に*選択されます）、**異常値**であるほど上がり（これまでの最高値を不自然に大きく上回る実行は*常に*選択されます）、**レピュテーション**が高いほど下がります（多くの監査を通過したコントリビューターへの抜き打ちチェックは稀になり、新規参入者や匿名の提出者は信頼を獲得するまで実行ごとにチェックされます）。L2監査に合格するとレピュテーションが上がります。**このポリシーを実行する再実行ツールは存在しない**ため、これまでL2監査が実行されたことはありません。選択された実行は*L2-pending*として記録されます。
- **L3 — 裏付け（コストゼロの検証）。** 2名の*独立した*コントリビューターが同じコーパス上で同じモデルを実行し、再スコアリングされた出力が**一致**した場合、その一致そのものが検証となります。そして両者のレピュテーションが上がります。明白な**不一致**があった場合、両方の実行がL2監査の対象としてフラグ付けされます。再現の試みは、重複した無駄な作業としてではなく、報奨の対象として扱われます。

**1件の改ざん発覚は壊滅的です — 論文の撤回と同様です。** 改ざんが証明されると、コントリビューターのレピュテーションはゼロになり、**検証済みの過去履歴すべてが再監査され**（検証済みの実行すべてが再度検証プロセスに戻されます）、監査ログに**公に**記録されます。これが、少量のサンプリングでも安全性を保てる理由です。公開開発セットをごまかすことは1回の実行では見逃されるかもしれませんが、その期待コスト — 獲得したすべての信頼を失い、全記録が再び精査されること — を考えれば、割に合わない賭けになります。これらのルールは、メンテナー自身の実行に対しても対称的に適用されます。

**それでもコントリビュートする価値がある理由。** コントリビューターは常にコストの高い部分（手法の実行）を負担しますが、プロジェクト側が負担するのは、全員に対するコストゼロのL0再スコアと、*徐々に縮小するサンプル*に対するL2再実行のみです（新規参入者や重要度の高い実行では高く、実績のあるコントリビューターでは低くなります）。検証コストは*レピュテーションによって償却され、裏付けによって共有される*ため、毎回全額を払い直す必要はありません。

## 提出方法

1. **手法を構築する** — 手法のインターフェースについては[手法の構築](/docs/network/specifications/methods)を参照してください
2. **ハーネスを実行する** — セットアップと使用法については[評価ハーネス](/docs/network/specifications/harness)を参照してください
3. **実行カードを生成する** — ハーネスがスコア、フィンガープリント、メタデータを含むJSON実行カードを生成します
4. **公開する** — `mt-eval publish eval/logs/harness/<run-id>_report.json --prod` で実行カードをリーダーボードにアップロードします（`--dry-run` でプレビュー可能）
5. **リーダーボードに表示される** — あなたの実行結果は *self-benchmarked (unverified)* として一覧に表示されます。[手法リーダーボード](https://champollion.dev/leaderboard)には、`disqualified` でないすべての行が掲載・ランク付けされ、自己ベンチマークのものもその旨ラベル付けされて含まれます。再スコアリングされた結果のみを確認したい場合は *Champollion Verified* でフィルターしてください。実行をそのティアに昇格させるL0再スコアはメンテナーによるバッチ処理であり、定期スケジュールされていないため、現在ボード上のすべての行は自己申告の主張となっています。「Verified」のみの表示は**コンテスト**ランキングのデフォルトであり、賞金の対象となる唯一のティアです

## 整合性ポリシー: 撤回、再実行、登録解除、異議申し立て

執行が感情的な対立ではなく手順として機能するよう、事前に明文化されています。これらのルールは全員に対称的に適用され、メンテナー自身の実行も例外ではありません。

**撤回は不可。** 公開された実行結果は恒久的な記録となります。たとえ恥ずかしい結果であったとしても、スコアを削除する仕組みは — 誰に対しても — 存在しません。すべての実行行にはサーバーが刻印した `submitted_at` タイムスタンプと改ざん不能な監査証跡が付与され、モデレーション操作自体もログに記録されます。

**再実行は追記され、置き換えられることはありません。** 手法を改良した場合は、新しい実行結果を公開してください。古い実行結果はそのまま残ります。選択的開示 — 非公開で多くのバリエーションをテストし、勝ったものだけを公開すること — こそが、他のリーダーボードを不正可能なものにしてきた要因です。追記専用（append-only）の記録がその構造的な解決策となります。フィンガープリントによる重複排除はバイトレベルで完全に同一な再提出スパムを阻止しますが、履歴を書き換えることは決してありません。

**登録解除はルールの執行であり、適用されたルールが明示されます。** 実行結果が登録解除される（単に密かに削除されるのではなく、目に見える形で `disqualified` とマークされる）のは、明記された理由がある場合のみです。隔離されたデータセットや不適切なサブセットデータセットの使用（すべてのクライアントの下層にあるデータベーストリガーによって強制）、コーパスのチェックサム不一致、スコアの捏造または許容範囲外、コンテンツガード違反、または原データの管理者による登録取り消しなどがこれに該当します。登録解除時には、適用されたルールと証拠が明記されます。新しい解除事由が追加される場合は、事後的に特定のケースのために都合よく作られるのではなく、適用される前に日付付きの編集としてここに追加されます。

**誰でも結果にフラグを付けることができます。** リーダーボード上の該当行を展開し、*この結果にフラグを付ける（Flag this result）* を使用してください。その実行IDに紐付けられたメッセージフォームが開き、問題点とその根拠（汚染されたコーパス、ラベルと一致しない指標、誤った手法の帰属など）を記入できます。フラグには必ず理由を添える必要があります。理由のないフラグは単なる「低評価（downvote）」に過ぎず、このボードには低評価機能はありません。

**フラグは非公開メッセージであり、投票ではありません。** チケットとしてメンテナーにのみ届き、それ以外の場所へ送信されることはありません。フラグの件数が表示されることは — 行上でも、実行カード内でも、他のどこであっても — 決してありません。目に見えるカウント自体が不正の標的になり得ますし、結果の信憑性は異議を唱えた人数ではなく証拠に基づくべきだからです。フラグを送信したこと自体によって、その行の内容が変更されることはありません。

**フラグが認められた場合、現れる変化は1つだけです:** その結果は、このページにすでに記載されている理由に基づいて `disqualified` とマークされます。他のすべての登録解除と同様に、新しい理由は**誰かに適用される前に、日付付きの編集としてここに追加**されます。したがって、フラグによって秘密のルールや遡及的なルールが作られることは決してありません。フラグが認められなかった場合、その行は変更されずに維持され、連絡先を残していればどちらの結果であっても回答が届きます。

**信頼ティアはラベルであり、変更ではありません。** `self-benchmarked` の行は自己申告の主張であり、`Champollion Verified` の行は提出者の出力からSHA固定コーパスに対して独自に再スコアリングされたものであり、`Community Validated` はコミュニティ独自のテストによってのみ付与されます。検証によって変わるのは行のティアであり、行のスコア自体が変わることは決してありません。

**レピュテーションは公開され、自己修正されます。** コントリビューターのレピュテーション、およびすべての再スコア、抽出された再実行、裏付け、改ざんによるペナルティを記録した監査ログは公開されます。レピュテーションはスコアの乗数ではなく、実行結果の数値に影響を与えることは一切ありません。コントリビューターの実行結果がどれくらいの頻度で再監査されるかを決めるだけです（上記の*レピュテーション加重監査*を参照）。改ざんが証明された場合は論文の撤回と同様に公に記録され、そのコントリビューターの検証済み履歴全体が再監査されます。このルールはメンテナー自身の実行に対しても同様に適用されます。

**異議申し立て。** 実行IDと具体的な主張（スコアの誤り、データセットの誤り、ルールの誤適用など）を添えてIssueを作成してください。メンテナーが決定論的なチェックを公開の場で再実行し、その結果と証拠がIssueに記載されます。異議がコミュニティのデータや検証に関するものである場合、コミュニティ独自の権威が判断を下し、ボードはその決定を適用します。賞金コンテストの場合、同様のルールに加えて、コンテストで事前公開された予選および監査の手順が適用されます — 勝者は賞金支払い**前**に監査され、失格となる場合は他の登録解除とまったく同様にルールが引用されます。

## 今後の方向性

- **包括的なモデル比較実行** — カスタム評価コーパス（公開ベンチマークではなく）を使用した、champollion 対応言語全体にわたるフロンティアモデル（GPT-4o、Claude、Gemini など）の体系的な評価
- **より多くの言語ペア** — コミュニティ検証済みデータセットが利用可能になり次第、Quechua、Inuktitut、その他の低リソース言語を追加
- **データセットインポート** — 外部評価データセット（WMT、Tatoeba など）を champollion 評価フォーマットに変換するツール
- **自動再実行** — モデルバージョンの変更を検出し、スコアのずれを追跡するためにベンチマークを再実行する機能
