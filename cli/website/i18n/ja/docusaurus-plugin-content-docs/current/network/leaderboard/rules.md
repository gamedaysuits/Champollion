# MT 評価

> **エグゼクティブサマリー。** このページでは、リーダーボードへの提出基準、スコアリング指標（chrF++、FST 受理率、完全一致、同等一致、意味スコア）、不正防止ポリシー、検証ティア、および提出ワークフローを定義します。評価データに触れたことのある手法は失格となります。

champollion には、翻訳手法の**再現可能なベンチマーク**を目的とした機械翻訳評価フレームワークが含まれています。これは特に、標準的な MT ベンチマークが存在せず、品質の主張を検証しにくい低リソース言語や先住民族言語を対象としています。

---

## リーダーボード

中心となるのは**[Method Leaderboard](https://champollion.dev/leaderboard)**です。これは、研究者やコミュニティメンバーが、フィンガープリント付きの再現可能な評価を用いて翻訳メソッドを提出し、比較するための公開スコアボードであり、現在稼働中で**提出を受け付けています**。

各提出には以下が含まれます：

- **フィンガープリント付きパイプライン** — 特定のGitコミットおよび設定ハッシュと紐付いているため、結果を生成した正確なコードまで遡って追跡できます。
- **バージョン管理されたデータセット** — コンテンツハッシュ化され、バージョン管理されています。スコアは同じデータセットバージョン内でのみ比較可能です。
- **標準化されたメトリクス** — すべてのスコアリングは共有の評価ハーネスによって計算され、実装の違いを排除します。
- **信頼性ティア** — self-benchmarked、Champollion Verified、またはCommunity Validatedのいずれかになります。
- **コスト追跡** — 提出ごとのAPIコストが記録されるため、コストと品質のトレードオフが透明化されます。

リーダーボードは 5 つの指標でスコアを評価します。3 つはあらゆる言語に対応しており、2 つは Plains Cree 向けに利用可能で、今後の拡張に伴い汎用化される予定です：

| 指標 | 種類 | 測定内容 |
|--------|------|------------------|
| **chrF++** | 文字 n-gram F スコア | 主要品質指標 — 特に形態的に豊かな言語において、人間の判断とよく相関します |
| **完全一致** | 完全一致の割合 | 厳密な精度 — 翻訳がゴールドスタンダードと完全に一致する頻度 |
| **FST 受理率** | 形態論的ゲート通過率 | 有限状態トランスデューサー検証を持つ手法向け — 出力のうち形態論的に有効なものの割合 |
| **同等一致** | 許容バリアント率 | 参照訳または許容バリアント（語順、正書法の慣習）に一致する割合。現在は CRK のみ対応；汎用化予定 |
| **意味スコア** | 意味的忠実度 | 意味の保持 — 表層形式に関わらず、翻訳が意図された意味を捉えているか。現在は CRK のみ対応；汎用化予定 |

:::info[完全なメトリクス一覧]
[スコアリング仕様](/docs/network/specifications/scoring)では、完全なメトリクス一覧（表層・構造・意味・動作・準拠・報告比較の6カテゴリ）、複合スコアの計算式、重みテーブル、および品質ティアのしきい値を定義しています。
:::

**[→ リーダーボードを見る](https://champollion.dev/leaderboard)**

| **ライセンス** | [EdTeKLA's modified CC BY-NC-SA](https://github.com/EdTeKLA/IndigenousLanguages_Corpora) (`LicenseRef-EdTeKLA-Modified-CC-BY-NC-SA-4.0`, sovereignty-scoped) — 非営利。リーダーボード、賞、および商用/APIレーンから除外されています。 |

### FLORES+ デブテスト — 開発用途のみ

> [!WARNING]
> **FLORES+ は開発およびデバッグ目的で利用可能ですが、公式リーダーボード評価には使用されません。** FLORES+（元は Meta FLORES-200）は広く公開されているベンチマークデータセットであり、フロンティア LLM はほぼ確実に学習に使用しています。FLORES+ に対するスコアは、LLM ベースの手法における実際の翻訳品質を信頼性高く反映しません。非 LLM 手法（FST、ルールベース、ファインチューニング済み NMT）への影響は小さいですが、FLORES+ のスコアはリーダーボードに公開されません。

FLORES+ のフィクスチャは、パイプラインのスモークテスト、言語横断的な検証、および開発用途のために `test/benchmark/fixtures/` で引き続き利用可能です。公式評価では、並列形式で公開されていない人間が執筆したテキストから構築されたカスタムコーパスを使用します。

データセットの完全なスキーマ、難易度ティア、および独自データセットの作成方法については、[評価データセット](/docs/network/leaderboard/datasets) を参照してください。

:::danger[評価データでのトレーニングは禁止]

**これらのデータセットは評価専用です。** 評価データを使って学習、ファインチューニング、few-shot プロンプティング、またはその他の方法で触れた手法は、スコアが人為的に水増しされるため、**リーダーボードから失格となります。**

これは提案ではなく、評価の完全性に関する最も重要なルールです。学習には別のコーパスを使用してください。評価セットは、開発中にモデルが見ていない状態を保つ必要があります。

コーチングデータや few-shot の例を使用する場合は、**完全に別のソース**から取得する必要があります。不明な場合は含めないでください。
:::

:::warning[LLMの非決定性について]

LLM の出力は非決定的です。スコアは、特定のモデルバージョンと API 設定のもとでの時点測定値を表します。モデルプロバイダーはいつでも重み、デコード戦略、または安全フィルターを更新する可能性があり、実行間でスコアのずれが生じることがあります。リーダーボードはすべての提出について、正確なモデルスラッグとタイムスタンプを記録します。
:::

## 優れた手法の条件

すべての手法が同等というわけではありません。厳密な研究と水増しされたスコアを分けるものを以下に示します。

### 優れた手法の特徴

- **学習データと評価データの明確な分離** — 開発、チューニング、プロンプトエンジニアリング、few-shot 例の選択において、手法が評価セットを一切見ていないこと
- **再現可能** — 他の人がリポジトリをクローンしてハーネスを実行し、同じスコアを得られること（LLM の非決定性の範囲内で）
- **文書化されている** — [手法カード](/docs/network/specifications/methods) に、手法の内容、使用ツール、および制限事項が記載されていること
- **スコープについて正直** — 特定の言語ペアにのみ対応している場合はその旨を明記し、特定の形態論的パターンで性能が低下する場合はそれを文書化すること
- **コミュニティを意識している** — 先住民族言語については、データ主権を尊重していること。言語コミュニティと協議しているか、オープンライセンスのデータのみを使用していること

### 危険信号（失格となるもの）

| 危険信号 | 問題の理由 |
|----------|--------------------|
| 評価データでの学習 | 評価の目的を完全に損なう。水増しされたスコアはすべての人を誤解させる |
| 結果のチェリーピッキング | 10 回実行して他の結果を開示せずに最良の結果を提出すること |
| 未開示の後処理 | スコアリング前に出力を手動で修正すること |
| 汚染されたコーチングデータ | 評価セットの例を few-shot プロンプトや辞書エントリとして使用すること |
| 出典なしで商用準備完了を主張すること | 手法が CC BY-NC-SA データを使用している場合、商用利用は不可 |

### 検証ティア

検証ティアは**誰が結果を検証したか**を示すものであり、[スコアリング仕様 §5](/docs/network/specifications/scoring#5-quality-tiers) で定義されている品質ティア（Baseline → Fluent）とは別のものです。品質ティアは自動複合スコアの意味を説明するものです。

| ティア | 意味 | 取得方法 |
|------|---------|--------------|
| **Self-benchmarked** | 自身でハーネスを実行し、結果を提出した状態です。 | `mt-eval publish`を使用してランカードを公開します。 |
| **Champollion Verified** | サーバーが、提出された出力結果をshaで固定された参照コーパスに対して独立して再スコアリングし、スコアを再現した状態です。 | 自動 — すべての提出物は再スコアリングされます（下記参照）。 |
| **Community Validated** | コミュニティ独自のプロトコルで認定された対象言語のバイリンガル話者が、出力の層化抽出サンプル（30エントリ以上、2名以上のレビュアー）をレビューし、70%以上がコミュニティの基準を満たした状態です。コミュニティ独自のテストによってのみ付与されます。抜き打ち監査による降格も同様に行われます。 | ガバナンス組織にメソッドのコードを提出します。組織はゴールドスタンダードセットに対してコードを実行し、出力をコミュニティのレビューにかけます。 |

### 検証のスケール方法: レピュテーション加重監査

**私たちは出所を主張しません。** リーダーボードの行は、コントリビューターが
*自身の*マシンで*オープンソース*のハーネスを実行することによって生成されます。
「この実行は本当にハーネスを経由したものである」ということは、セルフホストされた
コンピューティング環境においてサーバーが検証できるものではありません。ハーネスの
署名キーはコントリビューターの手元にあるため、署名が認証するのは*マシンであり、
誠実さではない*からです。そうでないふりをする代わりに、**ここでの妥当性は獲得される
ものであり、自己修正機能を持っています**。ある行が信頼できるのは、そのスコアが
**再現可能**であるからであり、その背後にいるコントリビューターが、**捏造が発覚すれば
失墜するようなレピュテーションを賭けている**からです。検証は4つのレイヤーで
実行されるため、必要な部分では徹底的に、可能な部分では低コストで行われます。
プロジェクトが全員の作業を再実行する必要はありません。

- **L0 — すべてを再スコアリング (無料、100%)。** サーバーは、ハーネスが使用するのと同じ
  メトリクスを用いて、**shaで固定された参照コーパス**（保存されたコピーではありません）
  に対して、*提出された出力結果*からスコアを再計算します。出力からスコアが
  再現されない場合、または保存された参照が改ざんされていた場合、その実行は
  **失格 (disqualified)** となります。これだけで、手入力や編集されたスコアは排除されます。
  再現された実行は、ボードがランク付けする唯一のティアである**Champollion Verified**に
  昇格します。これはすべての提出に対して実行され、数ミリ秒で完了します。
- **L1 — コントリビューターのレピュテーションラダー。** 各コントリビューター（サインイン
  によって識別されます）は、以下のより深いチェックを通過することによって*のみ*
  レピュテーションを獲得します。量だけで獲得することは決してないため、新しいIDを
  次々と作成しても意味がありません。レピュテーションは**公開**されており、
  コストのかかるチェックがどの程度の頻度で実行されるかを決定します。
- **L2 — *サンプル*の再実行 (コストのかかるチェック)。** *公開された*開発セットの
  場合、参照を単に「翻訳」としてコピーしたコントリビューターをL0で捕捉することは
  できません。それを捕捉するには、実際にモデルを再実行する（実際の計算を行う）
  必要があるため、全員ではなく**サンプル**に対して行います。L2の再実行のために
  実行がサンプリングされる確率は、**重要度 (stakes)** が上がるにつれて高くなり
  （言語ファミリー全体への最初の架け橋となる実行は*常に*再実行されます）、
  **異常値 (anomaly)** が上がるにつれて高くなり（過去の最高値を上回る、出来すぎた
  飛躍は*常に*再実行されます）、**レピュテーション**が上がるにつれて低くなります
  （多くの監査を通過したコントリビューターが抜き打ちチェックされることは稀ですが、
  新規参入者や匿名の提出者は信頼を獲得するまですべての実行でチェックされます）。
  L2監査に合格するとレピュテーションが向上します。
- **L3 — 確証 (無料の検証)。** 2人の*独立した*コントリビューターが同じモデルを
  同じコーパスで実行し、再スコアリングされた出力が**一致**した場合、その一致自体が
  検証*となり*、両者のレピュテーションが向上します。純粋な**不一致**が生じた場合は、
  両方の実行にL2監査のフラグが立てられます。再現性は冗長なものとして扱われる
  のではなく、報奨の対象となります。

**一度でも捏造が発覚すれば、論文の撤回のように壊滅的な結果を招きます。** 捏造が
証明されると、コントリビューターのレピュテーションはゼロになり、**検証済みの履歴全体が
再監査され**（検証済みのすべての実行が再度検証に回されます）、監査ログに**公開**
記録されます。これが、軽いサンプリングでも安全である理由です。公開された開発セットでの
不正行為は、1回の実行では見過ごされるかもしれませんが、獲得したすべての信頼を失い、
記録全体が再調査されるという予想される代償を考えれば、割に合わない賭けとなります。
これらのルールは、メンテナー自身の実行にも同様に適用されます。

**それでも貢献する価値がある理由。** コストのかかる部分（メソッドの実行）は常に
あなたが負担します。プロジェクトが負担するのは、全員に対する無料のL0再スコアリングと、
*縮小していくサンプル*に対するL2再実行のみです。このサンプル率は、新規参入者や
重要度の高い実行では高く、実績のあるコントリビューターでは低くなります。検証コストは
毎回全額支払われるのではなく、*レピュテーションによって償却され、確証によって共有*されます。

## 提出方法

1. **メソッドの構築** — メソッドのインターフェースについては、[Building a Method](/docs/network/specifications/methods)を参照してください。
2. **ハーネスの実行** — セットアップと使用方法については、[Eval Harness](/docs/network/specifications/harness)を参照してください。
3. **ランカードの生成** — ハーネスは、スコア、フィンガープリント、およびメタデータを含むJSON形式のランカードを生成します。
4. **公開** — `mt-eval publish eval/logs/harness/<your-run-card>.json`を使用して、ランカードをリーダーボードにアップロードします。
5. **リーダーボードへの掲載** — 実行はまず*self-benchmarked (未検証)*としてステージングされ、その後サーバーがshaで固定されたコーパスに対して出力を自動的に再スコアリングします (L0)。再現されると、実行は[Method Leaderboard](https://champollion.dev/leaderboard)がランク付けする唯一のティアである*Champollion Verified*に昇格します。より深いレピュテーション加重監査は、上記の信頼性ティアに従います。

## 整合性ポリシー: 撤回、再実行、リストからの除外、異議申し立て

これらは、執行がドラマではなく手順となるように、あらかじめ書かれています。これらのルールは、
メンテナー自身の実行を含め、全員に等しく適用されます。

**撤回不可。** 公開された実行は永久的な記録となります。恥ずかしいからといって
スコアを削除するメカニズムは、誰に対しても存在しません。
すべての実行行には、サーバーが刻印した`submitted_at`タイムスタンプと
不変の監査証跡が付与されます。モデレーションアクション自体もログに記録されます。

**再実行は追記され、決して置き換えられません。** メソッドを改善した場合は、新しい
実行を公開してください。古い実行は残ります。選択的開示（多くのバリアントを
非公開でテストし、勝者のみを公開すること）は、他のリーダーボードがゲーム化
されやすかった原因です。追記のみの記録は、その構造的な解決策となります。
フィンガープリントの重複排除により、バイト単位で同一の再提出スパムは阻止されますが、
履歴が書き換えられることは決してありません。

**リストからの除外はルールの執行であり、ルール名が明記されます。** 実行がリストから
除外される（密かに削除されるのではなく、視覚的に`disqualified`とマークされる）
のは、リストに記載された原因の場合のみです。隔離されたデータセットや不適切な
サブセットのデータセット（すべてのクライアントの背後にあるデータベーストリガーによって
強制されます）、コーパスのチェックサムの不一致、捏造されたスコアや範囲外のスコア、
コンテンツガードの違反、またはスチュワードによる基礎データの登録撤回などが該当します。
除外の際には、ルールと証拠が明記されます。新しい原因は、適用される前に日付入りの
編集によってここに追加され、特定のケースのために遡及してでっち上げられることは決してありません。

**信頼性ティアはラベルであり、編集ではありません。** `self-benchmarked`の行は主張です。
`Champollion Verified`の行は、提出者の出力からshaで固定されたコーパスに対して
独立して再スコアリングされたものです。`Community Validated`は、
コミュニティ独自のテストによってのみ付与されます。検証によって行のティアは変更されますが、
行のスコアが変更されることは決してありません。

**レピュテーションは公開されており、自己修正機能を持っています。** コントリビューターの
レピュテーション、およびすべての再スコアリング、サンプリングされた再実行、確証、
捏造による失墜を記録する監査ログは公開されています。レピュテーションはスコアの乗数ではなく、
実行の数値に影響を与えることは決してありません。コントリビューターの実行が再監査される
頻度を設定するだけです（上記の*レピュテーション加重監査*を参照）。捏造が証明された場合は、
撤回と同様に公開記録され、コントリビューターの検証済み履歴全体が再監査されます。
同じルールがメンテナー自身の実行にも適用されます。

**異議申し立て。** 実行IDと具体的な主張（間違ったスコア、間違ったデータセット、
ルールの誤適用など）を記載してIssueを作成してください。メンテナーは公開の場で
決定論的なチェックを再実行し、その結果と証拠をIssueに記載します。異議申し立てが
コミュニティのデータや検証に関するものである場合、コミュニティ自身の権威が決定を下し、
ボードはその決定を実行します。賞金コンテストの場合も同じルールが適用され、さらに
コンテストの事前公開された予選および監査ステップが追加されます。勝者は支払いの
**前に**監査され、失格の場合は他のリスト除外とまったく同じようにルールが引用されます。

## 今後の方向性

- **包括的なモデル比較実行** — カスタム評価コーパス（公開ベンチマークではなく）を使用した、champollion 対応言語全体にわたるフロンティアモデル（GPT-4o、Claude、Gemini など）の体系的な評価
- **より多くの言語ペア** — コミュニティ検証済みデータセットが利用可能になり次第、Quechua、Inuktitut、その他の低リソース言語を追加
- **データセットインポート** — 外部評価データセット（WMT、Tatoeba など）を champollion 評価フォーマットに変換するツール
- **自動再実行** — モデルバージョンの変更を検出し、スコアのずれを追跡するためにベンチマークを再実行する機能
