# メトリクス信頼性仕様

> **要旨。** ベンチマークスコアの意味は、その背後にあるメトリクスの質に依存します。そして、自動メトリクスが人間の判断とどの程度一致するかは、言語によって大きく異なります。本ドキュメントでは、Champollion が**メトリクス信頼性**をどのように測定するかを規定します。すなわち、各言語ファミリーについて、各自動メトリクス（BLEU、spBLEU、chrF、chrF++、COMET、MetricX）が人間の品質判断とどの程度相関するかを、WMT Metrics 共有タスクのアーカイブ（2019〜2025年）から算出します。その出力は、公開済みの機械可読エビデンスアーティファクトであり、ハーネス、CLI、および MCP サーバーがスコアを信頼できるものとして提示する前に参照します。各言語ごとにこのエビデンスを公開している評価インフラは、私たちの知る限り他に存在しません。これこそが「メトリクスを実行した」という事実を「どの程度信頼すべきかの根拠がある」という事実へと変えるものです。
>
> **スコープ。** 本ドキュメントは、*信頼性エビデンスとは何か、どこから来るのか、どのように算出されるのか、そして何を意図的に除外しているのか*を定義します。メトリクスの定義そのものは [スコアリング仕様](/docs/network/specifications/scoring) に、スコア差の統計的検定は [有意性](/docs/network/specifications/significance) に記載されています。アーティファクトを再生成するインポーターはハーネスリポジトリ内の `arena/scripts/import_wmt_metaeval.py` です。コードが実装の詳細における最終的な根拠であり、レビューのために公開されています。

---

## 1. この仕様が解決する問題

機械翻訳の品質は、突き詰めれば人間の判断によるものです。自動メトリクスが存在するのは、人間による評価が時間とコストを要するためであり、すべての自動スコアは有能なバイリンガルが下す判断の*代理指標*です。「システム A はシステム B を BLEU で 2 ポイント上回る」というこの分野の慣用表現は、その代理指標が忠実であることを暗黙の前提としています。

この前提は WMT Metrics 共有タスクによって長年にわたって検証されてきましたが、ほぼ常に*集計ベース*でした。すなわち、メトリクスはその年のキャンペーンが対象とした言語ペア全体にわたる人間の判断との平均相関によってランク付けされます。対象は主に高リソースのヨーロッパ言語ペアに中国語と日本語を加えたものです。言語ごとの詳細は生データや年次調査論文に存在しますが、評価パイプラインが参照できる、クエリ可能な言語ファミリー別エビデンス層としてはどこにも公開されていません。

この詳細は、低リソース言語や形態論的に豊かな言語にとって非常に重要です。私たちのインポートから得られた 2 つの知見がその重要性を示しています（完全な表は §7 にあります）。

- **English→Inuktitut（wmt20）。** BLEU のシステムレベルでの人間の判断との相関は **+0.16** — 実質的に情報価値がありません。chrF は +0.35 を達成し、COMET は +0.86 に達します。この言語ペアで BLEU によってランク付けされたリーダーボードはノイズをランク付けしているに等しく、COMET によってランク付けされた同じリーダーボードはシグナルを持ちます。
- **English→Maasai（wmt25）。** 逆の失敗例：MetricX-25 の相関は **−0.09** — 最先端の*学習済み*メトリクスが、そのトレーニングに含まれていない言語をスコアリングすると、人間の判断と無相関な数値を出力します。一方、（トレーニングデータを必要としない「素朴な」文字列メトリクスである）計算済み chrF++ は +0.50 を達成します。

どちらの失敗パターンも全体平均には現れず、しかも逆方向を向いています。ある言語では学習済みメトリクスが唯一使えるものであり、別の言語では唯一*使えない*ものです。Champollion のように固定されたメトリクス群で数百の言語ペアをスコアリングするインフラは、このエビデンスをユーザーに提供する責任があります。

## 2. 定義

以下の定義は、本ドキュメントの残りの部分を正確に読むために必要な最小限のものです。MT 評価に精通している読者は §3 まで読み飛ばしても構いません。

**自動メトリクス。** （システム出力、参照訳、場合によってはソース）から数値への関数です。*文字列メトリクス* — BLEU、spBLEU、chrF、chrF++ — は出力と参照の表面的な重複を比較します。*学習済みメトリクス* — COMET、MetricX、BLEURT — は過去の人間の判断を学習して品質を予測するニューラルモデルです。本ドキュメントに登場するすべてのメトリクスの正規識別子は、Champollion のメトリクスレジストリ（`shared/metric-registry.json`）に由来します：`bleu`、`spbleu`、`chrf_plain`、`chrf_plus_plus`、`comet_score`、`metricx_score`。

**人間の判断プロトコル。** WMT キャンペーンはいくつかのプロトコルのもとで人間の品質スコアを収集しており、このアーティファクトではそれらを区別して扱います。

- **DA（直接評価）** — クラウドワーカーまたは研究者が翻訳を 0〜100 で評価します。*z 正規化* DA（`wmt-z` と表記）は各評価者のスコアを平均 0、分散 1 に標準化し、評価者の寛大さの影響を除去します。
- **DA+SQM**（`da-sqm`、`wmt`）— スカラー品質メトリクスのアンカー説明で注釈された 0〜100 スケールで収集された DA。WMT22 から使用されています。
- **MQM（多次元品質メトリクス）**（`mqm`）— 専門アノテーターが個々のエラースパンを重大度とともにマークし分類します。重み付きエラー数がセグメントスコアになります。低速でコストが高く、利用可能な中で最も信頼性の高いシグナルです。毎年少数の高リソース言語ペアのみで収集されます（アノテーションは Google の `wmt-mqm-human-evaluation` リリースに由来します）。
- **ESA（エラースパンアノテーション）**（`esa`、`esa-merged`）— WMT24 および WMT25 のプロトコルで、エラースパンのマーキングとスカラー評価を組み合わせたものです。MQM より低コストで、DA より情報量が多いです。

**メタ評価。** 評価者を評価すること：各自動メトリクスのスコアが、同じ翻訳に対する人間のスコアとどの程度一致するかを測定します。一致度は 2 つのレベルで測定されます。

- **システムレベル**（`sys`）：各 MT システムはテストセットに対して 1 つの集計人間スコアと 1 つの集計メトリクススコアを持ち、システム間で一致度を計算します。これは「メトリクスはシステム全体を人間と同じようにランク付けするか？」という問いに答えます — リーダーボードが関心を持つ問いです。
- **セグメントレベル**（`seg`）：個々の（システム、文）ペア間での一致度です。これは「メトリクスは良い文と悪い文を区別できるか？」という問いに答えます — 品質推定やデータフィルタリングが関心を持つ問いです。はるかに難しく、相関は系統的に低くなります。

**相関統計量。** 4 つの標準的な統計量を、ここで算出方法とともに正確に定義します。

- **Pearson の r** — 2 つのスコアベクトル間の線形相関。
- **Spearman の ρ** — 平均ランクに対して計算された Pearson の r。単調な一致度を測定し、スケールに依存しません。
- **Kendall の τ-b** — すべてのアイテムペアのうち、一致した順序のペアが不一致のペアを上回る（タイ調整済みの）超過割合。標準的なタイ調整済み τ-b の定式化を使用します（`scipy.stats.kendalltau` と等価。実装は依存関係なしで、テストスイートのブルートフォース参照と照合済みです）。
- **ペアワイズランキング精度**（システムレベルのみ）— 人間が*厳密に*順序付けるすべてのシステムペアのうち、メトリクスが同じ順序に並べる割合。メトリクスのタイは順序の再現失敗としてカウントされます。これは Kocmi et al.（2021）の精度統計量であり、近年の WMT キャンペーンがシステムレベルの主要指標として使用しています。

**言語ファミリー。** Champollion の言語データベース（`languages.family`、Glottolog から派生）に記録されている、翻訳先言語（翻訳される言語）の系統的グループ分けです。ターゲット側を使う理由と、ファミリーが何を代理できて何を代理できないかについては §5 で説明します。

## 4. 方法

インポーターは各（テストセット、言語ペア）を処理し、（人間の判断レーン、レベル、メトリクス）ごとに 1 つの**セル**を計算します。

1. **人間レーンの検出。** 当該ペアで利用可能なすべての人間スコアファイルを明示的な許可リスト（§4.1）と照合します。評価者レベルのファイル、生のエラースパンファイル、ドキュメント/ドメインレベルのスコアはスコープ外です。
2. **人間「システム」の除外。** WMT スコアファイルには、参照訳自体もスコアリングされたシステムとして含まれています（`refA`、`refb`、`HUMAN.0`…）。メトリクスを自身の参照と相関させることは無意味であるため、当該ペアの参照セットまたはプレフィックス `ref`/`human`/`synthetic` に一致するシステムはすべて除外されます。
3. **アライメント。** システムレベル：人間スコアとメトリクススコアの両方を持つシステムの共通部分（欠損値は削除され、ゼロに強制変換されることはありません）。セグメントレベル：両方のスコアを持つすべての（システム、セグメント）ペアをシステム間でグループ化せずにプールします — これは mt-metrics-eval の「平均化なし」フラット化です。不揃いなファイル（セグメント数の不一致）はおおよそのアライメントを行わずにセルを失敗させます。
4. **計算。** 両レベルで Pearson、Spearman、Kendall τ-b；システムレベルでペアワイズランキング精度。アライメントされたシステムが 3 未満（sys）、または少なくとも 2 システムにわたるアライメントされたポイントが 10 未満（seg）、あるいはどちらかの側の分散がゼロのセルは、縮退として除外台帳に記録されます（現在のビルドでは 20 セル）。
5. **ロールアップ。** ターゲット言語ファミリー、メトリクス、レベルごとに：*優先*セル（§4.1）にわたる各統計量の n 加重平均。寄与した（テストセット、ペア）のリストを保持し、任意の集計をその入力に分解できるようにします。

### 4.1 人間レーンの優先順位

あるペアに複数の人間の判断レーンがある場合、すべてが計算されますが、**優先**としてフラグが立てられるのは 1 つだけであり、ファミリーロールアップに入るのは優先セルのみです — そうしなければ、MQM と DA の両方で判断されたペアが二重にカウントされてしまいます。優先順位はシグナル品質によって決まります。

```
mqm > esa-merged > esa > da-sqm > wmt-z > wmt-appraise-z > wmt-appraise > wmt > wmt-raw
```

専門家によるエラーアノテーション（MQM）がエラースパンプロトコル（ESA）より優先され、ESA はスカラー直接評価より優先されます。DA 内では、z 正規化レーンが生のレーンより優先されます。優先されないセルもアーティファクトに残されており、プロトコル効果を研究したい人が利用できます。

### 4.2 メトリクスの同一性とバージョン管理

学習済みメトリクスは年ごとに変化し（COMET-20、COMET-22、MetricX-23/24/25 は異なるモデルです）、それらを 1 つのメトリクスとして扱うと、メタ評価が存在する理由である区別がぼやけてしまいます。そのため、すべてのセルは正規レジストリ ID とともに**上流の verbatim スコア名**（`COMET-22`、`MetricX-25-Ref`、`metricx_xxl_MQM_2020`…）を記録し、アーティファクトは各 ID に対してどの上流名が使われたかを一覧表示します。キャンペーンが複数の参照に対してメトリクスをスコアリングした場合、使用された参照ストリームもセルごとに記録されます。

スコアはアーカイブが配布する通りに使用されます（すべてのレーンで高いほど良い；MQM エラースコアと MetricX は上流で負値として保存されています）。符号の反転やスケール変換は適用されません。相関はスケールと向きの規則に対して不変であり、インポート前に経験的に検証されています。

### 4.3 計算済み chrF++ レーン

chrF++ — ハーネスの主要な文字列メトリクス — は wmt20 キャンペーンにのみ提出されたため、上流スコアは 1 年分しか存在しません。他のすべてのテストセットについては、インポーターがキャッシュされたシステム出力から記録された参照に対して chrF++ 自身を計算します（sacreBLEU、`word_order=2`）。これらのセルは `computed: true` としてフラグが立てられ、上流名にその旨が記載されています。Champollion が計算したスコアは WMT 提出物として提示されることはありません。他のすべてのメトリクスセルは上流の verbatim 値であり、Champollion が追加するのは相関の計算のみです。

## 5. 設計上の選択、代替案、および根拠

これらはレビュアーが検討すべき決定事項です。それぞれについて、選択したもの、選択しなかったもの、およびその理由を示します。

**ターゲット言語ファミリーによるキー付け。** *選択：* 翻訳先言語のファミリーで集計します。*代替案：* ペアのみ（集計なし）；ソース側またはペアレベルの類型論；系統ではなく類型論的特徴ベクトル。*根拠：* メトリクスの信頼性は*出力*言語の難しさによって支配されます — 形態論的豊かさは文字列メトリクスの表面的な不一致を増大させ、トレーニングデータの不足は学習済みメトリクスを劣化させます — どちらもターゲットの特性です。ファミリーは粗いキーですが、普遍的に利用可能です（Champollion のデータベースのすべての言語にファミリーがあります）。類型論的特徴はより細かいですが、まさにこれが存在する理由である低リソース言語では欠落しているか議論の余地があります。ペアごとのセルはすべて保持されているため、より細かい再集計（属、形態論的タイプ別）をアーティファクトから再インポートなしに構築できます。

**フラット化されたセグメントレベル相関。** *選択：* プールされた（システム、セグメント）ベクトルに対する Kendall τ-b。*代替案：* タイ較正付きのアイテムグループ化ペアワイズ精度（近年の WMT 調査の acc*-eq）；セグメント間で平均化されたセグメントごとの τ。*根拠：* フラット化された統計量は最もシンプルで妥当な選択であり、タイ較正手順なしにその定義から正確に再現可能であり、このアーティファクトが必要とする言語間の比較可能性を保持します。これは最新の WMT の主要統計量では*ありません*。§8 ではそれを限界として記載しており、等価性を装うことはしません。

**ペアワイズ精度ではメトリクスのタイはメトリクスに不利にカウントされます。** 人間が区別する 2 つのシステムを区別できないメトリクスは、人間の順序を再現することに失敗しています。半点を与えることはスコアの量子化を報酬することになります。

**ロールアップでの加重平均。** ファミリー集計は各セルをそのサンプルサイズ（sys レベルではシステム数、seg レベルではポイント数）で重み付けするため、17 システムの MQM ペアは 6 システムの DA ペアより多くカウントされます。加重なしのセルごとの値も引き続き利用可能です。

**閾値。** セルには ≥3 のアライメントされたシステム（2 ポイントの相関は無意味）または ≥2 システムにわたる ≥10 のアライメントされたセグメントポイントが必要です。これらは縮退した計算に対するフロアであり、有意性の主張ではありません — §8 参照。

**Verbatim 上流規律。** Champollion は引用できるものは何も再計算しません（フラグ付きの chrF++ レーンを除く）。再スコアリングされた学習済みメトリクスは、セルごとの上流名が防ごうとしているバージョンと環境のドリフトを引き起こすからです。トレードオフ — キャンペーンがメトリクスを実行しなかった場合のカバレッジギャップ — は、隠蔽されるのではなく欠損セルとして可視化されます。

**正直な除外。** スキップされたもの（人間の判断のないテストセット、解決できない言語コード、縮退したセル）はすべて理由とともに除外台帳に書き込まれます。アーティファクトの読者は、その中に*ない*ものを列挙できます — ほとんどの集計レポートが欠いている特性です。

## 6. 公開アーティファクト

エビデンスは 1 つの機械可読 JSON ファイルとして提供され、モノレポで追跡されます（npm/PyPI パッケージには意図的にバンドルされていません）。

```
shared/catalogue/metric-reliability.json    # the artifact (≈0.6 MB)
shared/schemas/metric-reliability.schema.json  # its JSON-Schema contract
```

現在のビルド：**57 言語ペア**、**10 テストセット**、**11 ターゲットファミリー**にわたる **1,810 セル**（1,052 優先）、21 件の台帳除外。トップレベルブロック：固定済み `sources` および `provenance`（すべての導出値は上流を指定する `champollion-derived` 出所を持ちます — 相関は私たちのものですが、判断はそうではありません）；`correlation_definitions`（§2 の正確な統計定義）；`metrics`（レジストリ ID ↔ 上流名）；`languages`（コード → ファミリー/属）；`families`（ロールアップ）；`cells`（完全に帰属された全相関）；`excluded`（台帳）。

現在 3 つのコンシューマーサーフェスがこれを読み取っています。

- **ハーネス CLI：** `mt-eval recommend SRC TGT` は、メソッドの可用性と引用された結果とともに「ターゲットのメトリクス信頼性」ブロックをレンダリングします。
- **Champollion CLI：** `champollion recommend SRC TGT`（同じペイロードコントラクト；アーティファクトはモノレポで追跡されているため、パッケージ化されたインストールは明示的な「インデックス利用不可」の注記に格下げされます）。
- **MCP サーバー：** `get_metric_reliability` ツールは、接続された AI エージェントに対して「言語 X にはどのメトリクスを信頼すべきか？」という問いに答えます。WMT キャンペーンで判断されたことのない言語には明示的な UNMEASURED 回答を返します。

| ウラル語族 | 3 | +0.85 | +0.88 | +0.91 | +0.91 | +0.75 | +0.81 |

この表の読み方 — および読んではいけない方法：

- **大まかなパターンはこの分野の集計的な知見と一致しています。** 42 ペアのインド・ヨーロッパ語族の大部分では、学習済みメトリクスがリードしており（MetricX +0.84、COMET +0.81）、chrF がその後に続き、BLEU が最下位です — これは標準的な WMT の結果であり、健全性確認として生データから再現されています。
- **ファミリーごとの偏差がこの表の本質です。** 多合成語的なイヌクティトゥット語では、文字列メトリクスは崩壊し、COMET が唯一使えるシグナルです。マサイ語と wmt25 の English→Arabic では、MetricX が*負の*相関を示す一方、文字列メトリクスは実用的な水準を保っています — 学習済みメトリクスがトレーニング分布を超えて外挿すると、自信ありげなスコアを出しながら静かに失敗します。これらはまさに全体平均が消し去ってしまうケースです。
- **単一ペアのファミリーはエビデンスであり、結論ではありません。** 11 ファミリーのうち 8 つは、単一キャンペーンの 1〜2 ペアに基づいています。「エスキモー・アレウト語族：BLEU +0.16」の正直な読み方は、*「人間が en→iu を判断した唯一のキャンペーンで、BLEU は情報価値がなかった」* — 記録された測定値、赤信号、そしてより多くのデータを収集する理由であり、そのファミリーに関する法則ではありません。
- **負のセルはメトリクスがどこでも壊れているという意味ではありません。** それは、そのペアの、そのキャンペーンのシステムプールにおいて、メトリクスが人間の判断に反してシステムを順序付けたことを意味します。システムが品質において密集している場合、範囲制限（§8 参照）によってあらゆる相関が低下する可能性があります。

## 8. 限界

アーティファクトの価値はその誠実さにあるため、率直に述べます。

1. **ファミリーは代理指標であり、メカニズムではありません。** 系統的ファミリーはメトリクスの挙動を左右する形態論的特性と相関しますが、それを決定するわけではありません。ペアごとのセル（言語ごとに属が記録されています）はより細かいスライシングを可能にします。ファミリーキーはクエリ可能なデフォルトであり、類型論的因果関係の主張ではありません。
2. **カバレッジは WMT が判断したものであり、世界が話す言語ではありません。** 57 ペアで、ヨーロッパ言語に大きく偏っています。すべての xx→English ペアはインド・ヨーロッパ語族に分類されます。マクロファミリー全体（アルゴンキン語族、オーストロネシア語族、ケチュア語族など）は*人間の判断によるカバレッジが全くありません*。それらについて、Champollion のサーフェスは隣接言語の数値を借用するのではなく UNMEASURED と回答します。Champollion 独自のソブリンベンチマークプログラム — ネイティブスピーカーによる検証を伴うコミュニティ管理のテストセット — が、まさにこのギャップに対する長期的な解決策です。
3. **ファミリー内転移は仮定です。** クエリされた言語が直接判断されたことがない場合、ファミリーレベルのエビデンスはそのファミリーの*他の*言語から来ており、すべてのコンシューマーサーフェスはその旨を明示します。
4. **信頼区間はまだありません。** セルにはサンプルサイズが含まれていますが、ブートストラップ区間はありません。特に単一ペアのファミリー集計は、§7 が示す幅を念頭に置いて読む必要があります。セルごとのブートストラップ CI の追加（ハーネスにはすでにスコア CI の機構があります）は計画中の作業です。
5. **範囲制限。** 相関は各キャンペーンの提出システムに対して計算されます。近年のキャンペーンでは多くの強力なシステムが密集しており、すべてのメトリクスの相関が低下します — wmt25 由来のセル（マサイ語、アラビア語）が極端な値を示す理由の一部です。すべてのセルのテストセット帰属によってこれを検査可能にしています。
6. **セグメントレベルの統計量の選択。** フラット化された τ-b はシンプルで再現可能ですが、最新の WMT 調査論文のタイ較正済みグループ化精度ではありません。ここでの数値はそれらの出版物と桁単位で比較すべきではありません。
7. **データライセンス。** 上流の人間の判断データには明示的なライセンス表記がありません（§3.1）。Champollion はそのいずれも再配布せず、完全な帰属を持つ導出統計のみを公開し、このアーティファクトを姿勢が解決されるまで**非商用エビデンスレーン**（`license_lane.commercial_ok: false`）に保持します。MQM レーンはさらに Google の Apache-2.0 アノテーションリリースに遡ります。
8. **アーカイブは動く標的です。** 新しいキャンペーンが同じ tarball URL に追加されます。固定情報は私たちのスナップショットを正確に識別します。新しいスナップショットに対する再生成は、新しいピンを持つ新しいアーティファクトバージョンであり、暗黙的な更新ではありません。

## 9. 再現

アーティファクトは誰でもソースから再生成できます。

```bash
# 1. Fetch the archive (912 MB compressed; NOT immutable — keep the pins)
mkdir -p ~/.mt-eval/mt-metrics-eval && cd ~/.mt-eval/mt-metrics-eval
curl -sSL -D mt-metrics-eval-v2.headers -o mt-metrics-eval-v2.tgz \
     https://data.statmt.org/wmt26/mt-metrics-eval-v2.tgz
shasum -a 256 mt-metrics-eval-v2.tgz > mt-metrics-eval-v2.sha256
tar xzf mt-metrics-eval-v2.tgz

# 2. Regenerate (refuses to run without a checksum pin)
python3 arena/scripts/import_wmt_metaeval.py
```

アーカイブ自身の README は廃止された storage.googleapis.com の URL を指していることに注意してください。`data.statmt.org` が現在のホストです。インポーターは純粋な Python 標準ライブラリです（計算済み chrF++ レーンのみ sacreBLEU を使用）。相関の実装は `arena/tests/test_wmt_metaeval.py` のブルートフォース参照と照合されており、アーティファクトの構造的コントラクトは JSON スキーマと両ランタイムの整合性テストによって強制されています。

## 10. クレジットと引用

ここで要約された人間の判断は、**WMT Metrics 共有タスクの主催者とアノテーター** — Markus Freitag、Nitika Mathur、Tom Kocmi、および 2019〜2025 年のキャンペーンにわたる多くの協力者を含む — および **Google MQM アノテーションプログラム**（Freitag et al., *Experts, Errors, and Context*, TACL 2021；`google/wmt-mqm-human-evaluation`）の成果です。アーカイブとツールキットは `google-research/mt-metrics-eval` として管理されています。ペアワイズランキング精度は Kocmi, Federmann et al.（2021）、*To Ship or Not to Ship* に従います。Champollion の貢献は、言語ファミリーごとの整理、相関の計算、およびその周囲の誠実さのための枠組みです — アーティファクト内のすべての数値は、その導出元の上流を指定する `champollion-derived` 出所を持ち、それらのテキスト、判断、またはスコアは一切再配布されません。

このアーティファクトの信頼性数値を引用する際は、セルが帰属する WMT キャンペーンと Champollion のアーティファクトバージョン（`sources` ブロックに正確なデータ固定情報が含まれています）の両方を引用し、§8 で説明されている非商用エビデンスレーンを尊重してください。
