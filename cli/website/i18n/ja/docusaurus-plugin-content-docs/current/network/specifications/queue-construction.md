# キュー構築仕様

**数式バージョン: `ecv-v3`（ブリッジ信頼性を考慮した期待チェーン値）。** このドキュメントは、[champollion.dev/queue.json](https://champollion.dev/queue.json) の順序付けに関する規範的な定義です。実装（公開ハーネスリポジトリ内の `arena/scripts/generate_sweep_queue.py`）はこのページをセクションごとに反映しており、キューのメタデータは生成時に使用された正確なパラメータ値を反映しています。また、**すべてのアイテムには数式の完全な内訳が含まれている**ため、公開されている JSON だけから手作業で任意のランクを再導出できます。このページとキューの内容が一致しない場合はバグです — ご報告ください。

**現在のキューの概要（1段落）** 公開キューには、LLMアイテム（naiveおよびcoachedのプロンプティング条件）とMTサービスエンジンアイテムの両方が1つのボード上に保持され、サーベイ順序（`map`、§2.2）に従ってランク付けされています。これには、言語ペア・言語・語族にわたる1ドルあたりのファーストライト、未測定言語に対する初回測定ブースト（§2.2）、プレビューで公開される予算ティア（§2.1.1）、およびデータベースから配信される完全なランキング（完全なランキングがサイズ上限を超えた場合、静的ファイルには上位スライスが含まれ、その旨が明記されます）が含まれます。以下のセクションは、決定履歴の日付とともに保持されている規範的定義です。配信されるキューのメタデータには、そのランキングを決定した正確なパラメータが明記されています。

> **v3 (2026-06-13).** すべてのエッジは、品質と信頼性という 2 つの数値を持つ*ブリッジ*となり、チェーン行列はその積で動作します（§1.5）。62 件の単語レベルの語彙アイテムを 1 回実行しただけでは、もはやパスとは見なされません。レプリケーション、より大きなコーパス、より豊富なコーパス、より狭い信頼区間はすべて価格付きの価値を持ちます。v2 キュー（品質のみ）は、それぞれのメタデータを通じて引き続き解釈可能です。

## 1. 目標：品質加重メッシュ

その目的は、*測定済みの個別ペアの連鎖から構築される言語間翻訳*です。直接的なベンチマークが存在しない2つの言語間の翻訳は、ベンチマーク済みペアを**連鎖**（X→pivot→Y）させることで提供されるため、ベンチマークの価値はそのコーパス数ではなく、**グラフの連鎖容量**にあります。

**定義。** *ベンチマークグラフ*は言語ごとに 1 つのノードを持ち、少なくとも 1 件の公開済みかつ失格でない実行が存在するすべての言語ペアに対して、**エッジ強度**

```
s(e) = (best published corpus-level chrF++ on that pair) / 100   ∈ [0, 1]
```

コーパスレベルの chrF++ が正規の公開値です（[スコアリング仕様](/docs/network/specifications/scoring)を参照）。*best* を使用するのは、チェーンがホップごとに最良の実証済みシステムを経由するためです。公開済み実行が存在しないペアは s(e) = 0 となります。

2 言語間のパス P の**推定チェーン強度**は

```
strength(P) = λ^(|P|−1) · Π_{e ∈ P} s(e)
```

— エッジの品質は乗算的に合成され、各*ジャンクション*（各中間ピボット）には追加の忠実度係数 **λ < 1** のコストがかかります。どちらの選択もピボット翻訳の文献に基づいています。ピボットを経由した翻訳は、単純な合成が示す以上に、直接翻訳と比べて品質が低下することが知られており（Utiyama & Isahara 2007; Wu & Wang 2007）、その損失の大きさはピボットの選択に依存します（Paul et al. 2009）。また、英語中心でない*直接*ペアを構築することは、M2M-100 の多対多設定において英語ピボットを大規模に上回ることが実証されています — 約 10 BLEU の差（Fan et al. 2021）。λ は、推定チェーンは測定値ではないという数式上の継続的な注意喚起です。直接実行のみがこの割引を取り除きます。

**最良チェーン行列**と**メッシュ目標**は次のとおりです。

```
Q(u,v) = max over paths P from u to v of strength(P)      (1 if u = v, 0 if disconnected)

Φ = mean over ordered language pairs (u ≠ v) of Q(u,v)    ∈ [0, 1]
```

Q は標準的な対数変換（エッジ重み −ln(λ·s(e)) ≥ 0、Dijkstra 法、その後 Q = exp(−d)/λ）による最短経路問題として正確に計算されます。Φ は [Latora & Marchiori (2001)](https://arxiv.org/abs/cond-mat/0101396) の*グローバル効率*の構成であり、1/距離カーネルを乗算的チェーン忠実度に置き換えたものです — エッジがユニット長ではなくホップごとの品質保持を持つ場合の自然なカーネルです。（キュー v1 は非加重グローバル効率ゲインでランク付けしていました — エッジの存在のみが既知である場合のこのファミリーの特殊ケースです。）

### 1.5 信頼性：ブリッジは (q, r) である

小さく薄く、一度も再現されていないコーパスでの派手なスコアはブリッジではありません。そのため v3 では、測定済みのすべてのエッジを次のように分割します。

```
quality      q(e)   = best published corpus-level chrF++ / 100
reliability  r(e)   = f_size · f_rich · f_conf · f_repl        ∈ [0, 1]
effective    s_eff(e) = q(e) · r(e)        ← what chains compose over
```

| 係数 | 定義 | 満点となる条件 | 根拠 |
|---|---|---|---|
| `f_size` | min(1, n/100)、n = 最良実行の評価エントリ数 | 100 エントリ | [コーパス設計](/docs/network/specifications/corpus-design)の有意性フロア。Koehn (2004) は約 300 文のセットでブートストラップ検定を検証しています — 300 でも「小さい」ため、サイズは表示のゲートではなく信頼性を割り引きます |
| `f_rich` | min(1, L̄/5)、L̄ = 平均*有効*ソース長 | 有効語 5 語 | AmericasNLP（Mager et al. 2021）は、語レベルの単位が豊かな形態論で機能しないため chrF を採用しました。Mager et al. (2022) は空白トークンが誤った単位であることを記録しています |
| `f_conf` | min(1, 5/h)、h = 最良実行の chrF 95% CI 半幅（未公開の場合はプロキシ `50/√n`） | CI ≤ ±5 chrF | 小さなコーパスではデルタが区別できないノイズフロア。Kocmi et al. (2021) は CI 内のデルタが人間の好みと頻繁に矛盾することを示しています |
| `f_repl` | min(1, runs/2) | 公開済み実行 2 件 | Marie, Fujita & Rubino (2021) は 769 本の論文をメタ評価し、再現されていない単一比較がこの分野の記録された信頼性の失敗であることを示しています |

**有効長**は空白区切りの語数ではなく、コンテンツ単位で測定されます: `L̄ = mean source chars / c(L)`。ここで*文字経済性* `c(L)` は、アラインされた側の英語 1 語に対する言語 L 側の中央文字数であり、このプロジェクト自身の並列コーパスから測定されます（v3 リリース時点で 7,400 件以上のアラインエントリ: cmn 1.6、jpn 2.3、kor 2.6; eng ベースライン 5.0; deu 6.0; crk 4.7 — 多合成語はその内容に応じて価格付け）。類型論のルックアップテーブルは使用しません。コーパスが成長するにつれて推定値は精緻化されます。eng とのペアデータがない言語はデフォルトの経済性を使用します。レジストリの `richness` ブロックにコーパスごとに記録されます。

**ブリッジ階層**（表示用語）: **established** — n ≥ 100、L̄ ≥ 5、h ≤ 5、runs ≥ 2; **provisional** — 測定済みだがいずれかの条件を満たさない; **registered** — 公開済み実行なし。チェーンの主張（「X から Y へ到達できる」）は、最も弱いホップの階層と同程度の強さしかなく、メッシュの可視化では信頼性をエッジの不透明度で表示します。

**検証例**（v3 リリース前に実行された検証スクリプトより）: *62 件の単語レベル語彙アイテム、1 回の実行* → r ≈ **0.04**（パスではない）; *200 文、±3 CI、3 回の実行* → r = **1.00**; 素朴な語数が 1.0（スクリプトの成果物）の 101 エントリの日本語コーパスは、6.5 有効語に修正され、`f_rich` が満点となります。境界値とファクターごとの単調性はプロパティテストで検証されています。

**v3 における実行の価値。** 実行はブリッジを 2 つの方法で改善でき、ΔΦ はそのうち良い方を採用します: **(a)** エッジの最良実行となる — `ŝ_eff = 予測品質 × r(そのコーパスの n、豊富さ、CI プロキシ、runs+1)`; または **(b)** 単に再現する — 現在の最良値は変わらず、`f_repl` が上昇します。したがって、単一実行エッジへのレプリケーションは実際の価格付きの価値であり、測定済みペアに対してより大きいまたは豊富なコーパスを使用することは、小さいコーパスの再実行よりも優先されます。アイテムは `edge_quality`、`edge_reliability`、`edge_tier`、`effective_strength`、`post_run_reliability`、`predicted_effective` を v2 の予測フィールドとともに公開します。

**Φ でないもの。** Φ はキューの内部優先順位付けの通貨であり、能力の主張ではありません。その入力は[コーパス設計フレームワーク](/docs/network/specifications/corpus-design)のすべての注意事項を持つ開発セットスコアです。訓練データの汚染の可能性により各スコアは上限値となり、chrF++ の値は言語間で厳密には比較できず、小さなコーパスは広い信頼区間を持ちます。数式は Φ を*有用性による実行の順序付け*にのみ使用します。品質保証として公開されることはありません。

## 2. 決定問題

キューのオープンアイテムは、対象条件を満たし（開発スプリット、再配布可能なライセンス、隔離されていないこと、送信対象であること、および**ベンチマーク解決可能**であること — §2.2の言語アイデンティティゲートを参照）、まだリーダーボードに存在しないすべての（コーパス、モデル、条件）の組み合わせです。対象範囲内の組み合わせの同一の再実行は除外されます（実行カードのフィンガープリントにより公開時に重複排除されます）が、測定済みペアに対する新しいモデルや条件はオープンアイテムとして残ります。

提供されたコンピュートは予算です。メッシュが最も速く改善されるように次に実行するオープンアイテムを選択することは、予算付きのカバレッジスタイルの最大化問題です。正規のアプローチは**単位コストあたりの限界価値**によるグリーディ選択です。単調劣モジュラ目標に対して、グリーディルールは古典的な (1 − 1/e) 保証を持ち（Nemhauser, Wolsey & Fisher 1978）、その利益/コスト比の形式は予算制約下での標準アルゴリズムです（Khuller, Moss & Naor 1999）。私たちはこの比率ルールをランキング原則として使用します。（正直な注記: 私たちの目標は決定論的なコアに被覆的な収穫逓減を持ちますが、確率的予測層があるため、グリーディ保証はこの正確なシステムに関する定理としてではなく、*動機付け*として引用しています。）

```
ECV(item) = ΔΦ(item) / max(est_cost_usd, COST_FLOOR)
```

アイテムは ECV の降順でランク付けされます。同点の場合: naive が coached より優先、コストが低い方が優先、次にアイテム ID で決定します。

### 2.1 ランキングの修正 — 2026-07-12

貪欲 ECV ルールに重ねて適用される4つの調整があり、それぞれキューのメタデータ（`priority_parameters.contamination_ecv_factors`、
`priority_parameters.frontier_interleave`、`metadata.preview_policy`）に反映されます。

1. **汚染乗数。** 各アイテムの ECV に、そのコーパスの汚染グレードに基づく係数を乗算します：**LOW 1.0 / MEDIUM 0.4 / HIGH 0.1**。グレードが不明または欠落している場合は MEDIUM として扱います（クリーンであると仮定しないこと）。理由：クリーンチェーングラフは LOW 汚染のエッジのみを受け入れるため、非 LOW の実行はそこに入ることができず、同等のコストでクリーンメッシュの作業より上位にランクされてはなりません。非 LOW のアイテムはキューに残ります — レーン内の相対比較は実際の価値を持ちます — ただし、クリーンな作業の後ろにランクされます。
2. **フロンティアのインターリーブ。** 貪欲ソートの後、5番目ごとの優先スロットに、フロンティアモデルセット（ジェネレーターのデータとして管理され、メタデータに反映される）からまだ配置されていない最上位のアイテムが割り当てられます。これにより、安価な層が飽和した後ではなく、早い段階でフロンティアの証拠が予測事前分布に届きます。純粋な並び替えであり、アイテムの削除や重複はありません。自然なスロットを獲得したフロンティアアイテムはそのスロットを維持し、優先度は織り込まれた順序から番号付けされます — 公開されたランキングが真の順序です。
3. **プレビューのソースハブ上限。** 上位25件のパブリックプレビューでは、同一ソース言語を共有するアイテムは最大 **6件** まで表示されます。これにより、リソースが豊富な単一のハブがショーウィンドウを独占できないようにします。上限を超えたアイテムは、フルキュー内での実際の優先度を維持します。プレビューは単にランキング順で次の適格なアイテムを取得します。
4. **プレビューの人工言語除外。** ソースまたはターゲットが人工言語であるアイテムは、プレビューでスキップされます。判定はカードファミリー駆動（Glottolog の Artificial Language バケット、言語カードから読み取り — ハードコードされた言語セットは使用しない）で行われ、導出されたコードリストは `metadata.preview_policy` に公開されるため、サーバーサイドの更新でも同じ選択が適用されます。

(3) と (4) は**表示ポリシーのみ**です：フル `queue.json`、そのランキング、および優先度には影響しません。

### 2.1.1 予算ティア — 「$Xで何ができるか？」（2026-08-24）

`queue-preview.json`には、**$1 / $10 / $100 / $1000**の予算について、公開されたランキングの欲張り法による予算内プレフィックスを要約した`budget_tiers`配列が含まれています。優先順位順にアイテムを走査し、推定コストが予算内に収まるアイテムを採用し、収まらないものをスキップして、後続の安価なアイテムで埋め続けます。各ティアは、その予算で購入できるアイテム数、推定合計コスト、対象となる個別の言語ペア数およびモデル数、そしてランキングのどの深さまで予算が到達するか（`max_priority`）を報告します。

ランキングはすでにコストあたりの限界価値（§2）となっているため、欲張り法による予算内プレフィックスは、まさにその支出に対してこのモデルが推奨する配分**そのもの**です。誰の規模にも暗黙に合致しない1つのリストを見るのではなく、小規模な貢献者も大規模な貢献者も、同一の公開ランキングから具体的かつ最適な答えを読み取ることができます。ティアは要約にすぎません。配分自体は、各自の予算に合わせて順番に走査されたランキングそのものです。サーバー側のリフレッシュでは、同一の走査を使用して残存アイテム全体でティアを再計算します（ジェネレータとリフレッシュ関数は同一の処理を行う双子として実装され、双方でテストされています）。

### 2.2 レーンとランキングモード — 2026-07-19

配信されるキューは、自身がどの**レーン**を保持し、どの**ランキングモード**で順序付けられたかを独自のメタデータ内で宣言します。メタデータが正式な情報源であり、本セクションではその語彙を定義します。

**レーン**（`metadata.lane`、`metadata.lane_policy`）。2026-08-27以降、パブリックキューには**both**レーンが保持されています。これには、LLMアイテム（モデル × プロンプティング条件）**および**MTサービスアイテム（条件`engine` — DeepL、Google Translate、Microsoft Translator、LibreTranslate、Tilde。それぞれが独自に公開しているカバレッジリスト内のペアに対してのみエンキューされます）が含まれます。2026-07-19の**llm**レーン（LLMアイテムのみ、少なくとも片側がすべてのMTサービスの公開カバレッジ外にあるペアに限定）では、サービスのベンチマークを実行されなかった主催者主導のキャンペーン用に確保していたため、カタログの大部分が保留されていました。サービスの測定こそがカバレッジマップの骨格*である*ため、現在では両方の作業が1つのボード上に配置されています。カバレッジの和集合（言語カードを介してマクロ言語のエイリアス化が行われます）は引き続き`service_coverage_methods`および`service_covered_languages`として反映され、llmレーンのキューは除外されたペアを`pairs_dropped_fully_covered`として報告します。

**Blobサイズ上限**（2026-08-27）。配信される`queue.json`はホスティング上の厳格な上限を持つ静的ファイルであるため、完全なランキングがこれを超過した場合、ファイルにはランキングの**上位スライス**が含まれ、`metadata.blob_truncated {kept, total}`にその旨が記載されます（黙って上限を適用することはありません）。データベースのキュー（`queue_top()` / `queue_pairs()`）は常に**完全な**ランキングを配信し、正式な作業リストとなります。プレビューのペア集計および予算ティアは、それらが同梱される成果物を表します。

**言語アイデンティティゲート**（2026-07-19）。キューアイテムは、**アクティブな個別のISO 639-3コード**のみを対象とします。マクロ言語（「アラビア語」など）や集合語族コード（「ベルベル諸語」など）に対するスコアは、評価されていない変種に関する反証不可能な主張になってしまいます（これは、FLORES-200/NLLBがデータを`arb`/`quy`/`zsm`としてコーディングする際に従っているのと同じ論拠です）。上流のコーパスラベルは機械的に従ったり破棄したりするのではなく、*解決（resolve）*されます。文字体系タグは機械的に除去され（`eng→cmn-Hans`コーパスは`eng→cmn`としてエンキューされ、文字体系はアイテムの表示メタデータ`source_script`/`target_script`として保持されます）、明確に廃止されたコードは公式なISOの後継コードに従います。また、マクロ言語ラベルが付与されたコーパスは、そのレジストリエントリに記録・引用された**変種解決（variety resolution）**がある場合にのみエンキューされます（例：FLORES+ではケチュア語を`quy`として文書化しています）。どちらの方法でも解決されないコーパスは、`metadata.doctrine_exclusions`に公開される機械可読な理由（合計、理由別カウント、コーパス別理由）とともに除外され、砂漠台帳（`service_landscape.invisible_reasons.corpus_excluded_by_doctrine`）にカウントされます。これらは可視化された除外であり、暗黙の削除ではありません。包括的ラベルが付いたコーパスに関する過去の結果は、メンバー変種にマージされることなく、誠実に命名された独自のメッシュノード（ノード`scope`: `macrolanguage` / `collective` / `retired`）を維持します。解決の入力はすべて公開されています。レジストリのエントリごとの`language_resolution`スタンプには、解決されたコード、スコープ、および固定引用情報が含まれています。

**ランキングモード**（`metadata.rank_mode`、`metadata.priority_model`で説明）。同一アイテムに対する2種類の順序付け：

- **ecv** — §2–§3の欲張り法による期待連鎖価値ルール：推定1ドルあたりのメッシュ改善。活用の順序付けであり、予測とΔΦがシグナルを持つ程度にボードが十分に密である場合に適しています。
- **map**（マップバリュー v2） — サーベイ順序：
  `MapValue = novelty × uncertainty × promise × connectivity × corpus-quality × contamination ÷ cost`。厳密な欲張り探索トレースによって組み立てられます。*novelty*（新規性）は位置に基づくファーストライトのクレジットであり、すでに配置されたアイテムが同一の有向ペア（1/(1+n)）、対象言語、対象語族、手法×対象語族セル、および対象×ドメインセル（それぞれ1/√(1+n)；語族は言語カードから、ドメインはコーパスレジストリの分類法から取得 — 対象言語の初期カバレッジはレジスター全体に分散すべきであり、最初に測定されたドメインを繰り返すべきではありません）を占めるにつれて減衰します。*uncertainty*（不確実性）は、§3.1の予測のバックオフ深度（ペア 0.25 · 対象言語 0.55 · 送信元言語 0.75 · グローバル 1.0）× 1/(1+エッジ上の公開済み実行数) です。*promise*（有望性）は、§3.1の予測強度（下限0.25）です — 機能する可能性の高い未知のものが先行し、砂漠である可能性が高い領域をマッピングすることにも価値があります。*connectivity*（接続性）は、**測定済みネットワークをまだ到達できない言語へと結びつける**ペアを上位にランク付けします。測定済みメッシュエッジ上にある（`mesh.json`、ステータス`measured`）、またはいずれかのMTサービスの公開カバレッジリスト内にある（マクロ言語のエイリアス化が適用され、上記のレーンゲートと同じエイリアス化が行われます）エンドポイントは*established*（確立済み）とみなされます。**ブリッジ**（確立されたエンドポイントが正確に1つ）および**孤島**（どちらも確立されていない）は、ともに1.0のスコアを獲得します — 2026-08-27以降、切断された砂漠のファーストライトは完全にカウントされます（2026-07-19のネットワーク拡張サイジングでは孤島のスコアは0.5であり、最も深いテールが構造的に降格されていました）。一方、**内部**の高密度化（両方とも確立済み）のスコアは0.5です。既知のポイント間の強化はecvモードの役割です。さらに、**初回測定ブースト**（×2.0）により、送信元言語または対象言語のいずれかがどこにも公開測定値を持っていない（ゼロである）アイテムのサーベイ価値が乗算されます。これは第9原則を明確に述べています：**言語の初回測定は精緻化に優先する**。不確実性係数だけではこれを表現できません（十分に測定された2言語間の未測定ペアと、一度も測定されていない言語を同一にスコアリングしてしまいます）。このブーストにより、ロングテールのファーストライトを偶発的な副産物ではなく、明示的な目標とすることができます。両方の係数は`metadata.map_value_parameters`に引き継がれ、edvのサーベイコンポーネント内でも同様に適用されます（§2.3）。

  第9原則のもう半分はランキングの外部に存在します。既存アイテムをどのように順序付けても、コーパスがまったくない言語（現在、約7,500の個別コードを持つ存続言語）には到達できません。**コーパスウィッシュリスト**（`/corpus-wishlist.json`、キューと並行して再生成）は、その獲得フロンティアを公開します。これは、コーパスがゼロである個別コードを持つすべての存続言語を、引用された最良の話者数順にランク付けしたものです。話者数は実際にコーパスを構築できるコミュニティの実現可能性のプロキシとして機能し、すべてのカウントはその情報源に帰属し、決して恣意的に裁定されることはありません。
  *corpus-quality*（コーパス品質）は、§1.5のコーパス本来の信頼性の可能性`f_size × f_rich`です — サーベイは負荷に耐えうるコーパスに着地すべきであるため、62エントリの単語語彙リストが安価であるという理由だけでトップに立つことはなくなりました。豊かさの測定値がない場合はニュートラルのままとなります（測定の不在は貧弱さの証拠ではありません）。
  コストとコンタミネーションの規律はecvと同一です。フロンティアのインターリーブとタイブレーク（§2.1）は変更なく適用されます。サーベイフェーズに適したアプローチであり、意図的にメッシュ強度の成長を遅らせる代償として、1ドルあたりで*マップが学習する内容*（散発的にならず測定済みネットワークから成長していく、ペア、言語、語族、手法セル、およびドメインにわたる初回測定）を最大化します。

> **マップバリュー v2（2026-07-19）。** サーベイ順序に対するファウンダー主導の2つの追加事項：*測定済みネットワークへと橋渡しする*ペアが、切断されたプローブや内部の高密度化よりも優先してランク付けされるようになり、コーパス品質（サイズの下限 × 有効な豊かさ、§1.5）および対象言語ごとのドメインの広がりがランキングに加重されるようになりました。貢献者の計算リソースは、負荷に耐えうる十分に優れたコーパス上で、確立されたパスを新しいパスへと結びつける必要があります。ライセンスは**重みではなくゲート**のままです。ライセンスおよび送信チャネルのルールによって、そもそも何をキューに入れられるかが決定され（§2、およびキューの`transmission_note`）、適格なコーパス間ではライセンスに関わらず平等にランク付けされるため、制限付きだが固定された研究用セット（特定のペアにとって唯一のコーパスであることが多い）が体系的に干上がることはありません。v1のキュー（novelty × uncertainty × promiseのみ）は、自身のメタデータを介して引き続き解釈可能です。

生成時に使用された正確な係数値は`metadata.map_value_parameters`に含まれています。接続性と品質の入力は、公開された`mesh.json`（測定済みエッジ）、メタデータに反映されたサービスカバレッジの和集合、および`registry.json`（エントリ数 + 豊かさ）から再導出可能です。また、各アイテムはモードに関係なく完全なecv-v3診断フィールドを保持しているため、同じ成果物からいずれの順序付けも再導出できます。

### 2.3 ランキングモード `edv` — 期待決定価値（2026-08-27）

*ステータス：実装済み。§2.3.6の測定比較が完了するまでデフォルトはオフ。それまでは公開デフォルトは`map`のままとなります。*

キューが購入する成果物は正確に2つあります。**機能マップ**（どの手法が何に優れているかを誠実な不確実性とともに示すもの）と、**ルーティングメッシュ**（ルートへと連鎖する測定済みペア）です。`edv`は、加重ポートフォリオとして、各候補アイテムがこれら両方をどれだけ前進させるかに応じて価格を決定します：

```
EDV(item) = [ w_judge·Ĵ + w_mesh·M̂ + w_survey·Ŝ ] × contamination ÷ max(cost, COST_FLOOR)
```

デフォルトは`w_judge = 0.35, w_mesh = 0.25, w_survey = 0.40`です
（ファウンダーによる調整が可能。各生成時に実際に使用された重みが`metadata.edv_parameters`に反映されます）。コンタミネーション係数（§2.1 対策1）は、外側の乗数として正確に1回適用されます。ライセンスと送信は**重みではなくゲート**のままです — 適格性は価値が計算される前に決定され、適格なコーパス間ではライセンスに関わらず平等にランク付けされます。

#### 2.3.1 Ĵ — 手法判定価値

その実行が**同一コーパスにおける手法比較の決着**をどれだけ進めるかを評価します — これは、本プロジェクト独自の大規模測定研究が保証する唯一の手法間クレームです。（W2の難易度転移研究では言語間での能力リンクが棄却されました。保証された肯定的な結果、すなわち同一言語内での加法的な手法×コーパス調整こそが、本コンポーネントが使用しているものです。キャリブレーションパイロットに従い、スコアは順序付けと分離のためだけに使用され、受容確率に変換されることはありません。）

候補（コーパスC、手法M、条件）について：**対照パートナー**は、（C、同一条件）で公開済みの実行をすでに持っている手法M′です。各パートナーについて、プールされた信頼区間（CI）の半値幅に対するchrFポイント単位のスコア分離を`sep`とし（記録されたCI。未公開の場合はプロキシ`50/√n`を使用）、§3.1の予測スコアに対して同様に計算されたものを`sep_pred`とします：

| ペア上における{M, M′}の対照状態 | クレジット |
|---|---|
| **unmet（未対面）** — 共有コーパスがまだ存在しない | `JUDGE_FIRST = 1.0` |
| **contested（競合中）** — 共有コーパスが存在し、すべて`sep < Z_DEC` | `JUDGE_CONTESTED = 0.8 × clip(sep_pred / Z_DEC, 0, 1)` |
| **decided（決着済み）** — 一部が`sep ≥ Z_DEC`であり、n_dec個のコーパスが決着させている | `JUDGE_DECIDED = 0.25 / (1 + n_dec)` |

それぞれに`w_top = 1/√(rank(M)·rank(M′))`が乗算されます — 1位と2位を決着させることは、7位と8位を決着させることよりも価値があります。ペアごとの手法ランキングでは、ペアに2つ以上の測定済み手法 × 2つ以上の測定済みコーパスがある場合は保証された加法的手法×コーパス適合（観測セルに対する交互最小二乗法）を使用し、それ以外の場合は手法ごとのベストスコアを使用します。この適合は**厳密にペアごとに行われ、言語間でプールされることはありません**。`Z_DEC = 1.96`。

同一の（C, M）に対するcoached対naiveの対照は、`JUDGE_COND = 0.5 / (1 + n_cond)`を追加します。アイテムの対照は収穫逓減を伴って合計され（降順にソートされ、追加の対照ごとに`JUDGE_GAMMA = 0.7`）、さらに空のボードでも将来の比較が判定可能なコーパスを優先できるように**シード項**`JUDGE_SEED = 0.25 × min(1, m_C/3) × corpus-quality`（m_C = C上にキューアイテムを持つラインナップ内の他の手法）が加えられます — これは開催場所としての価値（venue value）であり、借用されたスコアではありません。アセンブリ中、判定コンポーネントは`1/(1 + items already placed on the same pair and condition lane)`減衰します。

#### 2.3.2 M̂ および Ŝ

`M̂`は§3の期待メッシュゲイン（ΔΦ）であり、生成時に連鎖行列を凍結したまま変更されません。`Ŝ`は§2.2のマップバリューv2のコアであり、位置に基づく新規性減衰を伴う`uncertainty × promise × connectivity × corpus-quality`で変更されません。予測スコアの*レベル*（有望性）はŜにのみ存在し、Ĵはスコアの*分離*のみを使用します — 2つのコンポーネントが同じ楽観的予測を二重にカウントすることはありません。

#### 2.3.3 正規化

3つのコンポーネントは比較不能なスケール上に存在するため、各静的コンポーネントは候補セット全体における95パーセンタイル値で除算されます（`EDV_NORM_CAP = 4.0`で上限が設定されます）。3つの正規化パラメータは`metadata.edv_parameters.normalizers`に含まれており、公開されたすべてのEDV値を独自の成果物から再導出できるようになっています。

#### 2.3.4 アセンブリ

順序付けは、mapモードとまったく同じ遅延欲張り（lazy-greedy）探索トレースです。順序に依存する各乗数（サーベイの新規性、判定配置の減衰）はアイテムが配置されるにつれて単調非増加となるため、古いヒープエントリは過大評価にしかなり得ません。したがって、遅延欲張りの不変条件が維持され、探索トレースは総当たり欲張り法と同等になります。フロンティアのインターリーブ、プレビューポリシー、および予算ティアは変更なく適用されます。

#### 2.3.5 説明可能性

各アイテムは、その診断情報の中に、クレジット対象となった対照リスト（パートナー、状態、予測分離、ランク重み）、シード項および減衰項、すべての§2.2および§3フィールド、重み、ならびに正規化パラメータを保持します — 公開されたEDV値は行から正確に再計算可能です。「なぜこのアイテムがこのランクになったのか？」という問いには、外部の状態を必要とせずに答えることができます。

#### 2.3.6 採用基準

`edv`は、同一ボード上で`map`および`ecv`に対する測定比較が行われた後にのみ、公開デフォルトとなります。その基準は、すべてのサーベイ指標（ファーストライト深度パーセンタイル、特定深度における個別ペア/言語/語族数、限界新規ペア率）においてmapの10%以内であること、両方の判定指標（シミュレートされた1,000ドルあたりに解決された競合対照数、固定支出での手法ランキングの復元）において厳密に優れていること、そして1ドルあたりのメッシュ成長がmapを下回らないことです。比較レポートは切り替えと同時に公開されます。

## 3. 1 回の実行の価値

### 3.1 実行前のスコア予測

未実行の（ペア、モデル、条件）の期待スコアは、意図的にシンプルで完全に検査可能な和です — 双方向の主効果予測に構造化された楽観性を加えたもので、すべての項がアイテムに公開されています。

```
ŝ = clip( pair_prior + model_offset + condition_offset + exploration_bonus,  0, S_CAP )
```

- **`pair_prior`** — 公開済み強度に対する階層的バックオフ: このペアの平均 → このターゲット言語の平均 → このソース言語の平均 → グローバル平均 → `S0_FALLBACK`。使用されたレベルは `prior_basis` として公開されます。
- **`model_offset`** — このモデルが同じペアで*他の*モデルと比較してどの程度優れているか、比較が存在するすべてのペアで平均化したもの。未知のモデルはゼロです。
- **`condition_offset`** — 同じペア（ターゲット言語にフォールバック）での観測済みの coached マイナス naive のデルタ、**それ以外はゼロ**: コーチングゲインは測定された場所では実際のものですが、言語間での転移は仮定されないため、証拠のないペアではベースライン優先の慣例が適用されます。
- **`exploration_bonus`** — 不確実性に対する楽観性、UCB1 スケジュール（Auer, Cesa-Bianchi & Fischer 2002）: `κ·sqrt(2·ln(1+N)/(1+n))`。N は公開済みスコア付き実行の総数、n はこの（ペア、モデル）の実行数です。未試行のセルは最大のボーナスを得ます。十分に測定されたセルはゼロに向かって減衰します。私たちはスケジュール — 未探索のアームが適切なレートで再浮上するような形状 — を借用しており、後悔定理は借用していません。後悔定理はこのシステムが持たない定常バンディットを前提としています。

### 3.2 メッシュゲイン（閉形式）

実行がメッシュを改善できるのは、そのペアのエッジを `s' = max(s(e), ŝ)` に引き上げることによってのみです。単一エッジの変更に対して、任意の 2 言語間の新しい最良チェーンは新しいエッジを無視するか、ちょうど 1 回使用するかのどちらかです。そのため、アップグレードされた行列 — したがって ΔΦ — は正確な 1 行の形式を持ちます（グラフ全体を再解決する必要はありません）。

```
Q'(u,v) = max( Q(u,v),  E(u,a)·s'·E(b,v),  E(u,b)·s'·E(a,v) )

E(x,y) = λ·Q(x,y) for x ≠ y;  E(x,x) = 1        (edge e = {a, b})

ΔΦ = mean over ordered pairs of (Q'(u,v) − Q(u,v))
```

E は「新しいエッジのエンドポイントへの最良チェーンで、それに接続するためのジャンクションを支払うもの」です。2 つの項はエッジを横断する 2 つの方向です。これはハーネススイートで Φ のブルートフォース再計算に対してテストされています。

現在のエッジ強度を上回れない予測は ΔΦ = 0 となります。数式は寄付者のお金を未知の確認ではなく、実証済みの再測定に使わないようにします。（探索ボーナスにより、弱いまたはサンプル不足のセルが永遠に飢えることはありません。）

### 3.3 証拠として何が数えられるか vs. キューに入れられるもの

意図的に非対称な 2 つの異なるゲート:

- **証拠**は*すべての*公開済みかつ失格でない実行から得られます — 公開キューに入れられないコーパス（例: 非商用ライセンスのセット）での実行も含みます。ペアの公開済み測定値は、再実行できるかどうかに関わらず知識です。
- **アクション**（キューアイテム）は、公開実行可能なコーパスのみから得られます: 開発スプリット、CC-BY ファミリーライセンス、誰でも取得可能。

キュー可能でないコーパスを通じてのみ到達可能な言語もグラフに残ります。それらの*周辺*のエッジを改善することでチェーン値が変化し、数式はそれを考慮します。

## 4. パラメータ

| パラメータ | デフォルト | 意味と根拠 |
|---|---|---|
| `λ` (`lambda_junction_discount`) | **0.9** | *推定*チェーンのジャンクションごとの忠実度保持。「直接測定は積が等しいチェーンより優れている」をエンコードします（Utiyama & Isahara 2007; Wu & Wang 2007; Fan et al. 2021）。約 10% のヘアカットはキャリブレーションの選択であり、測定済みチェーントライアングルが蓄積されるにつれて見直されます（§6）。 |
| `κ` (`kappa_exploration_scale`) | **0.05** | 探索ボーナスのスケール（強度単位）。0.05 ≡ 5 chrF++ ポイント — 100 エントリ未満のコーパスではスコア差が区別できないノイズフロア（[コーパス設計 §6.3](/docs/network/specifications/corpus-design)）。楽観性は計測器の分解能で上限が設定されます。 |
| `S_CAP` | **0.95** | 予測上限 — 推定エッジは実証していない完全な忠実度を主張できません。 |
| `S0_FALLBACK` | **0.5** | 最後の手段のペア事前確率。公開済み結果がまったくない場合にのみ使用されます（観測されたグローバル平均 — 最初の 429 回の実行で ≈ 0.54 — は結果が存在する場合は常に優先されます）。 |
| `COST_FLOOR` | **$0.01** | ECV 分母のフロア。ほぼ無料の実行が無制限の 1 ドルあたりの価値を主張できないようにします。 |
| `N_FULL` | **100** | 完全なサイズクレジットのための評価エントリ数（§1.5）。 |
| `L_HEALTHY` | **5.0** | 完全な豊富さクレジットのための有効語数（§1.5）。 |
| `H_NOISE` | **±5 chrF** | 完全な信頼クレジットのための CI 半幅。CI が欠落している場合は 50/√n でプロキシ（n=100 で ±5 に固定）。 |
| `RUNS_FULL` | **2** | 完全なレプリケーションクレジットのための公開済み実行数。 |

**バージョン管理。** パラメータまたは数式の変更は `formula_version`（メタデータ）とこのページのバージョン行を更新します。キューは常に `metadata.priority_parameters` の下で使用された正確な値（現在の Φ を含む）を反映するため、過去のキューは引き続き解釈可能です。感度実行は 1 つのフラグで実行できます: `generate_sweep_queue.py --lam 0.8 --kappa 0.1`。

## 5. 計算例（実際の値、2026-06-12）

424 件のスコア付き実行、59 件の測定済みエッジ、60 言語に対して生成; **Φ = 0.272**。トップアイテム:

```
eng>fao · claude-haiku-4.5 · naive
  edge_strength        0.0      (no published eng→fao runs)
  pair_prior           0.613    basis: target-language (Faroese runs exist via dan→fao)
  model_offset        −0.114    (haiku trails other models on shared pairs)
  condition_offset     0.0      (no coaching evidence for fao)
  exploration_bonus   +0.174    (never-run cell: κ·√(2·ln 425 / 1))
  predicted_strength   0.673
  expected_mesh_gain   0.0181   (eng→fao is a near-component join)
  est_cost_usd         0.0101
  ecv_per_usd          1.79     ← rank #1
```

解釈: フェロー語はデンマーク語を通じてのみメッシュに接続されているため、測定済みの eng→fao エッジは大規模なチェーンファミリーのショートカットとなります（大きな ΔΦ）。このモデルはこのようなペアでは中程度と予測され（事前確率 + オフセット）、このセルは誰も試したことがなく（大きなボーナス）、実行コストは 1 セントです。キューの中で、1 ドルあたりのメッシュ改善がこれを上回るものは他にありません。同じ計算が、すべての入力を公開した状態で、他のすべてのランクを生成します。

## 6. 既知の制限事項（および修正方法）

1. **chrF++ は言語間で比較できません。** 形態論がスケールを変化させます。バスク語への 0.5 エッジはオランダ語への 0.5 エッジと同じ達成ではありません。緩和策: 優先順位はスケール効果が二次的な*構造*（s = 0 → s > 0 の遷移）によって支配されます。修正策: 言語ごとのスコア正規化、またはこれらの言語でより良いクロスリンガルキャリブレーションを持つメトリクスが利用可能になった場合。
2. **積-λ チェーンモデルは事前確率であり、測定値ではありません。** ピボット文献によって方向的に支持されていますが、LLM 翻訳に対してはキャリブレーションされていません。修正策（計画中）: メッシュには現在測定済みのトライアングルが含まれています（例: deu→fra 直接と deu→eng→fra の両方）。そのため、チェーン出力を直接スコアリングし、λ を選択するのではなくデータに適合させることができます。
3. **汚染と開発セットのステータス。** エッジ強度は公開開発セットのすべての注意事項を継承します — Φ を能力の主張としてではなく、上限の計画シグナルとして扱ってください（[コーパス設計](/docs/network/specifications/corpus-design)）。
4. **ドメインの盲点。** 会話テキストで測定されたエッジは 1 つの数値として扱われます。ドメインをまたぐチェーンは λ が予測する以上に劣化します。
5. **方向性。** エッジは現在無向です（X→Y の証拠が X↔Y を点灯させます）。チェーン合成が実際に方向に敏感になった場合、強度は方向ごとに分割されます — 数式は変わらず、グラフが単に 2 倍になります。
