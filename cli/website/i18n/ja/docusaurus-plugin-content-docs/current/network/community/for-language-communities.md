# 言語コミュニティの方へ

> **要約。** あなたのコミュニティは、すべての翻訳手法を評価するための「答え合わせの基準」となるテストセットを自ら所有し、データを外部に渡すことなく、独自のルールでコンテストを運営できます。このページでは、Networkが言語コミュニティに求めること（参照翻訳、翻訳レビュー、コーチングデータ）、コミュニティが得られるもの（公開レートによる有償作業、コードの所有権、完全なデプロイ制御）、そして最優先される主権の保証について説明します。プログラミングの知識は不要であり、私たちを信頼する必要もありません。保証は約束ではなく、構造的なものです。

Networkへの貢献にプログラマーである必要はありません。先住民言語や低リソース言語を話す方こそ、このエコシステムで最も重要な存在です。

---

## 主権が最優先

何かをお願いする前に、まず基本原則をお伝えします。**あなたの言語データはあなたのものです。** 言語データは*バイオデータ*です。コミュニティのアイデンティティや関係性を担うものであり、意味のある形で匿名化することはできません。そのため、データを提供する人々がそのデータの鍵を握り、それを基準として評価されるものすべての鍵も握っています。Networkは[先住民族のデータ主権の原則](/docs/network/sovereignty/data-sovereignty)に基づいて構築されています。

- 私たちはあなたの言語データをサーバーで収集・保存することはありません
- 翻訳手法は`api`アーキテクチャを使用しており、すべてのコーチングデータ、辞書、文法規則はあなたが管理するインフラ上に保持されます
- あなたの言語に対して手法を開発できる人を決めるのはあなたです
- リーダーボードのスコアは手法が機能することを証明するものであり、デプロイの許可を与えるものではありません

:::note[現状について]
以下に説明するオーナーシップ移転モデルは、**確定済みの設計であり、まだ稼働中のプログラムではありません。** リーダーボードは申請を受け付けており、現時点では公開済みの実行結果はなく、コミュニティへの移転も行われていません。このモデルがどのように機能するよう設計されているかをここで説明するのは、皆さんが私たちにその実現を求めるためであり、すでに動き出していることを示唆するものではありません。関係性と、皆さん自身のデータに対する権限が最優先です。それ以外はすべて、そこから生まれます。
:::

## テストセットを所有する

このシステムにおいてコミュニティが持てる最も強力な立場は、**ベンチマーク自体を所有すること**です。テストセットは答え合わせの基準です。それを持つ者が、その言語における「良い翻訳」の意味を決め、私たちの手法であれ、企業の手法であれ、誰の手法であれ、すべてが*あなたの*基準で評価されます。

- **登録はメタデータであり、コンテンツではありません。** コーパスをNetworkに登録するとは、説明カードを公開することを意味し、コーパスをアップロードすることではありません。[公開レーン](/docs/network/sovereignty/registering-corpora)はオープン、ゲート付き、完全主権型の中から選択できます。
- **主権型ベンチマークは非公開のままです。** 主権型レーンでは、テストセットはコミュニティのインフラ外に出ることはなく、私たちが見ることもありません。手法はあなたの側でスコアリングされ、スコアのみが送信されます。
- **独自のコンテストを運営できます。** ステップバイステップのランブック — [主権型コンテストの運営](/docs/network/sovereignty/run-a-sovereign-contest) — では、あなた自身のテストセット、ルール、公開内容（もしあれば）の決定など、コミュニティが主導する評価を独自の条件で開催する方法を説明しています。

これらすべての保証は、暗黙のものではなく明文化されています。[データ管理](/docs/network/sovereignty/data-sovereignty)（データ主権/CAREの立場と私たちが禁じられていること）および[所有権と条件](/docs/network/sovereignty/ownership-transfer)（手法が勝利した際に契約上何が起きるか）をご参照ください。

## 私たちが必要としていること

### 参照翻訳

評価のために、精選された翻訳ペアが必要です。片側に英語、もう片側にあなたの言語を配置したものです。これらはすべての翻訳手法を評価するための「答え合わせの基準」となります。

作成に使用できる素材の例：
- **教育資料** — 教科書の演習、授業計画、ワークシート
- **コミュニティ文書** — 会議の議事録、ニュースレター、お知らせ
- **日常的なフレーズ** — UI文字列、アプリのラベル、よく使う表現
- **文化的コンテンツ** — 物語、歌、または説明文（適切な許可を得たもの）

フォーマットはシンプルなJSONです：
```json
{
  "entries": [
    { "id": 1, "source": "Hello", "reference": "tânisi" },
    { "id": 2, "source": "Thank you", "reference": "kinanâskomitin" }
  ]
}
```

### 翻訳レビュー

機能する翻訳を生成すると主張するすべての手法には、人間による検証が必要です。バイリンガルの話者が出力結果をレビューし、コンピューターが正しく翻訳できたかどうか、そしてより重要なこととして、*なぜ*誤ったのかを教えてください。

### コーチングデータ

文法規則、辞書エントリ、形態論的パターン — これらは翻訳手法を機能させる言語リソースです。あなたの言語がどのように機能するかについての知識は、いかなるAIモデルにも代替できないものです。

## あなたが得られるもの

### 所有権

あなたの言語のための翻訳手法が構築され、Networkで検証されると、[所有権はコミュニティのガバナンス組織に移転されます](/docs/network/sovereignty/ownership-transfer)。コード、モデルの重み、デプロイはすべてあなたのものになります。

### 搾取ではなく、有償の作業

コーパス構築と翻訳レビューは専門的な作業であり、[公開レート](/docs/network/perspectives/how-speakers-get-paid)で報酬が支払われます。そして、支払いによってあなたのデータが買い取られることはありません。作業に対して報酬を受け取りながら、構築したものの所有者であり続けます。Champollionは非営利の研究プロジェクトです。何も販売せず、使用量を計測せず、コミュニティが所有する手法から得た収益の[いかなる取り分も受け取りません](/docs/network/sovereignty/economic-model)。

### 制御

あなたのガバナンス組織が以下を管理します：
- 手法にアクセスできる人
- 商業的に使用できるかどうか — 使用できる場合は、あなたの条件で、得られた収益をすべて保持
- いつ、どのように更新するか
- さらなる開発に使用するデータ

## 参加するには

:::tip[話者が今日からできること]
Champollion はコーパスの構築やホスティングを行いません。テストデータは常にそのソースから取得されます。コミュニティの話者が*今すぐ*文を提供したい場合、[Tatoeba](https://tatoeba.org) はあらゆる言語の文を一文ずつ受け付けており、[OPUS](https://opus.nlpl.eu/) のようなオープンコレクションは、ネットワークがベンチマークの構築に使用する対訳テキストを集約しています。そこに追加された文は、次回のコーパス構築時にここでの評価データになる可能性があります。話者が直接文を投稿できるアプリとコーパスビルダーは、ロードマップ上の次のステップとして計画されています。
:::

1. **連絡する** — [Networkリポジトリ](https://github.com/gamedaysuits/Champollion)でIssueを開くか、[info@champollion.dev](mailto:info@champollion.dev)にメールを送ってください
2. **言語を説明する** — どの語族に属しますか？話者数は？どの表記体系が使われていますか？どのような計算リソースが存在しますか（FST、辞書、コーパスなど）？
3. **小さく始める** — 精選された翻訳ペアが50件あれば、評価データセットを作成し、新しいリーダーボードトラックを開設するのに十分です。コーパス作業は[公開レートで報酬が支払われます](/docs/network/perspectives/how-speakers-get-paid)
4. **あなたのものとして保持する** — 選択したレーンでコーパスをメタデータとして登録してください（[コーパスの登録](/docs/network/sovereignty/registering-corpora)）。テストセットを完全に非公開にしたい場合は、[主権型コンテストのランブック](/docs/network/sovereignty/run-a-sovereign-contest)がその方法です
5. **ガバナンスにつなぐ** — コミュニティ内で言語データと技術に関する権限を持つのは誰ですか？Networkの主権モデルにはガバナンスパートナーが必要です
