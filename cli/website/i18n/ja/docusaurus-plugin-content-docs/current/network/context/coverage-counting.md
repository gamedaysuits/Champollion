# カバレッジ数: その集計方法

> **概要:** サイト上で「**552の現存する言語が何らかの機械翻訳を備えている**」および「**196の言語がデプロイされたサービスによって提供されている**」と記載されている場合、これらは意図的に分けられた2つの異なる集計です。このページでは、両方のティア（階層）を定義し、ビルド時に各数値が読み取られる単一の信頼できる情報源（SSOT）を明記し、リストの更新方法について説明します。カバレッジとは*存在の主張*であり、品質の主張ではありません。

## 2つのティア

**ティア1 — 任意の専用MTエンジン（「カバー済み」）:** 追跡対象となっている*いずれか*の専用MTエンジン（デプロイ済みのコンシューマー/APIサービス（Google Translate、Microsoft Translator、DeepL、LibreTranslateなど）、**または**オープンな研究モデル（NLLB-200、OPUS-MT、M2M-100、MADLAD-400など））の公開されたサポート言語リストに現存する言語が含まれている場合、その言語はカバーされていると見なされます。これは、ネットワークマップ上でドットを緑色に点灯させる和集合です。

**ティア2 — デプロイ済みサービス（「提供済み」）:** より厳格な基準です。誰もがコンシューマーまたはAPIサービスとして*今日実際に使用できる*エンジンのリストにその言語が含まれている状態を指します。自身でダウンロード、ホスト、および提供する必要があるオープンな研究チェックポイントは、ここには含まれません。これは、「話者がエンジニアリング作業なしで、今すぐウェブページを翻訳できるか？」という問いに答える数値です。

これら2つのティアが存在するのは、それぞれ異なる問いに答えるためであり、これらを統合してしまうと世界的なカバレッジを誇張することになるからです。どちらも**ISO 639-3の現存する個別言語**のみを対象として集計されます（`isoType: 'L'`）。

## 数値の出所（手入力なし）

表示されるすべての集計数は、機械的なSSOT（単一の信頼できる情報源）からの**ビルド時の読み取り**によるものです。サイト上の数値が文章中に手入力され、古くなったまま放置されることはありません。

1. **エンジンごとのリスト**は`cli/shared/catalogue/method-coverage.json`に存在します。エンジンごとに1つのエントリがあり、プロバイダー自身が公開しているサポート言語リストから*引用のみ*でインポートされ、その`source_url`と`asOf`の日付が付与されます。Champollionはこれらのリストを監査したり再現したりすることはなく、これらはプロバイダー自身の主張に基づいています。
2. **ビルド時に**これらのリストと現存する言語のインデックスを交差させ、サイトのビルド統計にティアごとの集計数を出力します（ティア1は`stats.coverage.dedicatedLiving`、ティア2は`stats.coverage.serviceLiving`、対象となる現存する言語は`stats.livingTotal`）。
3. **ページが統計をレンダリングし**、文章と統計にズレが生じた場合は、プッシュ前のパリティゲートによってビルドが失敗するようになっています。

## 「194言語」と「187言語」はどちらも真になり得る

プロバイダーのリストと*言語*の数は同じ対象ではないため、SSOTの各エントリではその数値がどちらであるかを宣言しています。

- **`publisher-list-rows`** — プロバイダー自身が公開しているリストの長さであり、公開されているそのままの数値です。GoogleのCloud Translationページには、NMTモデルとして**194**行がリストされています。これが、当サイトがGoogleの名前で帰属させている数値です。
- **`champollion-derived-enumeration`** — そのリストを個別のISO 639-3基本言語に*私たちが*集約したものです。`zh-CN`と`zh-TW`は2つの文字体系を持つ1つの言語であり、`pt-PT`と`pt-BR`なども同様であるため、Googleの同じ194行は**187**言語となります。この数値は私たちのものであり、プロバイダーのものではありません。
- **`publisher-stated-headline`** — プロバイダーが主張している合計数ですが、その根拠となるリストは公開されていません。ここから派生するものは何もありません。

最初の2つの数値の差は算術的なものであり、見解の相違ではありません。これはすべてのプロバイダーに当てはまります（Microsoftの135行 → 128言語、LibreTranslateの49 → 47、NLLB-200の200のFLORESバリアント → 196）。マップとティアの集計数は、見出しではなく常に*列挙されたリスト*を読み取ります。エントリの宣言された基準とそのリストが矛盾する場合、プッシュ前のゲートによってビルドが失敗します。

また、プロバイダーが複数のリストを公開する場合があることにも注意してください。Googleのページには、Translation LLMティア用の別の表（2026年8月16日時点で127行）が掲載されており、統合された合計数は一切記載されていません。そのため、「Googleはいくつの言語をサポートしているか？」という問いに対する単一の公開された回答はなく、当サイトがそれをでっち上げることもありません。

## 主張されるカバレッジは品質ではなく、常にデプロイ可能とは限らない

プロバイダーのリストに言語が含まれているということは、プロバイダーが*サポートを主張している*ということを意味するに過ぎません。これらの集計数が表示されるすべての場所で、当サイトは以下の2つの誠実な注記を適用しています。

- **カバレッジ ≠ 品質:** 翻訳の質が良いかどうかは、別途測定されるべき問題です。それこそがベンチマークネットワークの最大の目的です。品質に関する主張はリーダーボードにあり、（手法、データセット、指標）をキーとしています。カバレッジに関する主張はここにあります。
- **主張 ≠ デプロイ可能:** 幅広い研究モデルは非常に多くの言語数を主張することがありますが、そのドキュメントでは、実用的な品質を備えているのははるかに小さなサブセットであると報告されている場合があります。プロバイダーがそのような自己評価を公開している場合、当サイトでは主張されている集計数*と*プロバイダー自身のデプロイ可能/品質の数値の両方を表示し、それぞれプロバイダーの資料を引用しています。

## 更新の原則

プロバイダーのリストは変化するため、集計数も機械的にそれに追従する必要があります。

- `method-coverage.json`の各エントリには独自の`asOf`の日付があり、ファイルにはトップレベルの`asOf`（前回のスイープの日付）が含まれています。カバレッジ数を表示する画面では、この日付が表示されるかリンクされています。
- **SOTAスイープ**（すべてのプロバイダーの公開リストを再確認し、新たに追跡対象となったエンジンを追加すること）は定期的なメンテナンスタスクです。スイープによってSSOTが更新され、サイト上のすべての集計数は次のビルドでそれに追従します。ページのコピー内で何かを「覚えておく」必要はありません。
- スイープとスイープの間、集計数はその`asOf`の日付と全く同じ鮮度を保ちます。だからこそ、これらの日付は脚注の慣例ではなく、データの一部となっているのです。

## 修正と議論の歓迎

プロバイダーのリストが変更された場合、言語が誤って分類されている場合、またはティアの境界が間違って引かれていると思われる場合は、お知らせください。[github.com/gamedaysuits/Champollion/issues](https://github.com/gamedaysuits/Champollion/issues)でIssueを開くか、[info@champollion.dev](mailto:info@champollion.dev)までメールでご連絡ください。

## 情報源

- **エンジンごとのリスト** — `cli/shared/catalogue/method-coverage.json`: 各エンジン自身が公開しているサポート言語リスト（引用のみ。エントリごとに`source_url` + `asOf`）。
- **現存する言語のセット** — 引用された言語カードから構築された言語インデックス内のISO 639-3の現存する個別言語（`isoType: 'L'`）。
- **ティアの集計数** — ビルド時に出力される`stats.coverage.dedicatedLiving`（ティア1）、`stats.coverage.serviceLiving`（ティア2）、`stats.livingTotal`。Champollionから派生。
- **これらの集計数に基づいて構築された人口推計** — [カバレッジギャップ: その推計方法](/docs/network/context/coverage-gap-estimate)を参照してください。
