# エラーの報告と修正の主体性

> **立場について。** 数千もの言語に関する事実や評価を公開するプラットフォームにとって、誤りは避けられません。しかし、*避けられる*のは「エラーが報告されたとき誰の言葉が信頼されるか」「誰が修正を主導するか」という問題です。私たちの答えはこうです。流暢な話者による報告は自動化処理より優先される。すべての修正には「誰が何をなぜ変えたか」という来歴が記録される。そして、コミュニティは自分たちの言語データの使用を撤回または拒否できる——これは礼儀としてではなく、アーキテクチャによって強制される性質として。

多くのデータプラットフォームはエラー報告をサポートチケットとして扱います。ユーザーが苦情を申し立て、メンテナーが判断し、記録が静かに変更される。先住民族の言語データにとって、このモデルは逆さまです。エラーを報告する人物は、たいていプラットフォームよりも権威があります——ある単語が間違っていると指摘する話者は「ユーザー」ではなく、代理情報を修正する一次情報源です。以下の設計は、そのことを真剣に受け止めることから生まれています。

---

## 2種類のエラー、1つの原則

このプラットフォームが公開する主張には、誤りうる2種類があります。

1. **言語に関する事実** — 評価を駆動する言語カード：分類データ、正書法、言語的特徴、適用されるメトリクス。カードが話者数の推定値、方言関係、文字体系のステータスを誤って記載している場合があります。
2. **翻訳に関する判断** — 話者が誤りまたは不自然と判断するコーパス内の参照翻訳；有効な単語を拒否したり無効な単語を受け入れたりする自動メトリクス；話者が受け入れられないような出力への「Deployable」バッジ。

両方に適用される原則は、[Scoring Specification](/docs/network/specifications/scoring) および [Benchmark Specification §7](/docs/network/specifications/benchmark#7-human-validation) ですでに拘束力を持っています。**自動化された出力は代理情報であり、話者が一次情報源です。** [Speaker Validation Protocol §6](/docs/network/specifications/speaker-validation#6-what-speakers-get) に記載された公約はこう明言しています。話者がリンターの判断を誤りと指摘した場合、私たちはリンターを修正します。

## 報告の流れ

報告がたどる経路を、正直なステータス表示とともに示します——一部は現在稼働中、一部は仕様策定済みで未実装です。

**誤った翻訳またはメトリクス判断の報告（現在稼働中、直接チャンネル経由）。** 誤った参照翻訳、不当に拒否された単語、または受け入れられない「同等表現」を見つけた話者は、プロジェクトの公開リポジトリのイシュートラッカーまたはプロジェクトへの直接連絡を通じて報告できます。これの構造化バージョン——*reject / gist / acceptable / excellent* の選択肢とフリーテキストメモを備えた評価画面——はコミュニティレビューインターフェースであり、[Benchmark Specification §7.3](/docs/network/specifications/benchmark#7-human-validation) で仕様策定済みですが、まだ公開されていません。公開されるまでは、報告は個人間で処理され、バリデーションタスク自体（有償の構造化された話者レビュー——[話者への報酬について](/docs/network/perspectives/how-speakers-get-paid)を参照）が主な修正パイプラインとなります。

**言語カードの誤った事実の報告（現在稼働中、同じチャンネル）。** カードの修正も同じ経路をたどります。報告、レビュー、バージョン管理された変更。カードは評価の動作を駆動するため——どのメトリクスを読み込むか、どのモデルが推奨されるか——カードの修正はスコアを変える可能性があります。そのため、修正は記録されたデータ変更として適用され、サイレント編集は行われません。

**次に何が起きるか——誰が決めるか：**

- **言語的な判断はその言語の話者に帰属します。** ある形式が有効かどうか、2つの表現が同等かどうか、レジスターが適切かどうか——プラットフォームはその答えを実装しますが、答えを提供するのはプラットフォームではありません。話者間で意見が分かれる場合（方言、正書法の慣習）、答えは私たちが裁定するのではなく、バリエーションとして記録されます——コーパスとリンターのスキーマは、方言的変異形を一つの正解に絞り込むのではなく、許容可能な代替形としてタグ付けすることをサポートしています。
- **コミュニティのデータに関する決定は、そのガバナンス組織に帰属します。** ガバナンス組織を持つ言語については、評価コーパスへの変更、封印されたテストセットへの修正の受け入れ、デプロイメントの結果はすべてその組織を通じて行われます——それが言語データのコミュニティによる管理です（[データ主権](/docs/network/sovereignty/data-sovereignty)参照）——ポスターとしてではなく、プロセスとして実装されています。
- **機械的なエラーは単純に修正されます。** タイポ、リンク切れ、フィールドの解析ミス——報告、修正、記録。すべてに審議が必要なわけではありません。

## 修正には来歴が伴う

追跡できない修正は、単に新しい意見にすぎません。すべての事実とすべての修正に3つの来歴ルールが適用されます。

1. **すべての事実はその出典を明記します。** 言語カードとコーパスエントリは、各値の出典を記録します——公開データセット、コミュニティの貢献、話者のレビュー。
2. **派生値は上流のものではなく私たちのものとして表示されます。** プラットフォームが何かを計算する場合——集計値、再コーディング、複合値——それは上流ソースの名前で記録されるのではなく、上流ソース*から*のプラットフォーム派生として記録されます。上流データセットが公開していない数値について、そのデータセットが責任を問われたり、功績を認められたりすることはありません。
3. **修正は記録の一部になります。** 話者による修正は、古い値に取って代わる新しい帰属付きアサーション（話者の選択により実名または匿名——バリデーション作業と同じ条件）として記録されます。何が変更されたかの履歴は監査可能なまま残ります。コーパスバージョンはハッシュマニフェスト化されており（[Corpus Partnership §4.4](/docs/network/specifications/corpus-partnership)）、修正されたコーパスは明示的に新しいバージョンとなり、すべての実行カードはスコアリングに使用された正確なバージョンを記録します——古いスコアは解釈可能なまま残り、新しいスコアは修正を反映します。

## 拒否権、具体的に

「コミュニティの管理」は主張するのは簡単です。公開されたアーキテクチャにおいて、それが具体的に何を意味するかを示します。

- **話者は自分の貢献を撤回できます。** 話者はいつでも自分の評価を取り下げることができ、撤回するとすべての分析から除外されます（[Speaker Validation §5](/docs/network/specifications/speaker-validation#5-data-governance)）。また、話者は問題があると判断した結果の公開に対して拒否権を持ちます。
- **コミュニティは評価を完全に停止できます。** 封印されたテストセットは暗号化されており、プラットフォーム単独では再構築できないようにキーが保持されています。コミュニティはキーの再構築への参加を拒否することで評価アクセスを取り消すことができます（[Corpus Partnership §4.3](/docs/network/specifications/corpus-partnership#4-cryptographic-sealing-and-sandbox-testing)）。「停止したい場合はどうするか」には明確な答えがあります。封印されたデータは公開されず、評価は終了します。
- **いかなるスコアもコミュニティの決定を覆しません。** リーダーボードのトップに立つ手法であっても、ガバナンス組織が承認した場合にのみデプロイされます（[Ownership Transfer](/docs/network/sovereignty/ownership-transfer)）——そして、自分たちの言語に機械翻訳をデプロイすべきでないと決定したコミュニティは、システムを壊しているのではなく、設計通りに使用しています（[Translation Is Not Revitalization](/docs/network/perspectives/translation-is-not-revitalization) を参照）。

## まだ構築されていないもの

このドキュメント群の他のページと同様に、正直に述べます。コミュニティレビューインターフェースは計画中であり、まだ公開されていません。現在の言語のいずれについても、ガバナンス組織はまだ設立されていません——Plains Cree ベンチマークのコミュニティ管理者は確認中であり、同意を得る前に管理者を公開することはありません。これらの要素が整うまで、修正は直接的で帰属可能なチャンネルを通じて行われ、公開された仕様——このページではなく——がプロセスの拘束力ある説明として残ります。このページと仕様が矛盾する場合、仕様が優先されます。その矛盾自体も報告すべきバグと考えます。

## これがあなたにとって意味すること

:::info[コミュニティメンバーの方へ]
このプラットフォーム上のあなたの言語に関して、事実・翻訳・ラベルなど何か誤りがある場合、あなたの報告は現場の真実に基づく証言であり、トリアージされるべき苦情ではありません。訂正内容を氏名付きでクレジットするかどうかはあなたが決めます。提供した貢献は後から取り下げることができ、あなたのコミュニティはそのデータの使用を完全に停止させることもできます。まずは [言語コミュニティの方へ](/docs/network/community/for-language-communities) をご覧いただくか、公開リポジトリに Issue を立ててください。
:::

:::info[研究者の方へ]
ここでの訂正は出所が明確なデータであり、無言の編集ではありません。コーパスのバージョンはハッシュ化され、ランカードはスコアリングに使用した正確なバージョンを固定し、派生値は派生であることが明示されます。Network のスコアやコーパスを研究に利用する場合は、バージョンを引用してください。また、話者主導の訂正の波は、指標の妥当性に関する知見として扱ってください。実際にそういうものだからです。
:::

:::info[開発者の方へ]
あなたの手法のスコアは、コードを変更していなくても正当な理由で変わることがあります。誤って拒否されていた単語が許可リストに追加されたり、参照翻訳が修正されたり、バリアントクラスが修正されたりする場合です。そのことを前提に設計してください。ランカードにコーパスのバージョンを固定し（[ランカード仕様](/docs/network/specifications/run-card)）、データセットの変更履歴を確認し、話者による訂正を、無償で得られる最も信頼性の高いエラーシグナルとして扱ってください。
:::
