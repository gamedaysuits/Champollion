# エラーの報告と修正の主体性

> **方針：** 多くの言語に関する事実や評価を公開するプラットフォームにとって、誤りを犯すことは避けられません。しかし、誤りが報告されたときに誰の言葉が信じられるのか、そして修正の主体は誰なのかは、決して「避けられない成り行き」ではありません。私たちの答えは明確です。流暢な話者による報告は自動化システムよりも優先され、すべての修正には「誰が、何を、なぜ変更したのか」を示す来歴が記録されます。そしてコミュニティは、自らの言語データの使用を取り消したり、拒否（ベト）したりできます。これは単なる好意ではなく、アーキテクチャの必須要件として強制されます。

多くのデータプラットフォームはエラー報告をサポートチケットとして扱います。ユーザーが苦情を申し立て、メンテナーが判断し、記録が静かに変更される。先住民族の言語データにとって、このモデルは逆さまです。エラーを報告する人物は、たいていプラットフォームよりも権威があります——ある単語が間違っていると指摘する話者は「ユーザー」ではなく、代理情報を修正する一次情報源です。以下の設計は、そのことを真剣に受け止めることから生まれています。

---

## 2種類のエラー、1つの原則

このプラットフォームが公開する主張には、誤りうる2種類があります。

1. **言語に関する事実** — 評価を左右する言語カード：分類データ、正書法、言語的特徴、適用されるメトリクスなど。カードに誤った話者数の推定値、誤った方言の関係性、誤った表記体系のステータスが記載されている場合があります。
2. **翻訳に関する判断** — 話者が誤りまたは不自然だとみなすコーパス内の参照翻訳、有効な単語を拒絶したり無効な単語を受け入れたりする自動メトリクス、話者が受け入れない出力に対する高い自動スコアなど。

両方に適用される原則は、[Scoring Specification](/docs/network/specifications/scoring) および [Benchmark Specification §7](/docs/network/specifications/benchmark#7-human-validation) ですでに拘束力を持っています。**自動化された出力は代理情報であり、話者が一次情報源です。** [Speaker Validation Protocol §6](/docs/network/specifications/speaker-validation#6-what-speakers-get) に記載された公約はこう明言しています。話者がリンターの判断を誤りと指摘した場合、私たちはリンターを修正します。

## 報告の流れ

報告がたどる経路を、正直なステータス表示とともに示します——一部は現在稼働中、一部は仕様策定済みで未実装です。

**誤った翻訳や評価指標の判定を報告する（現在、直接窓口で受付中）。** 話者が誤った参照訳、誤って不合格とされた単語、あるいは受け入れられない「同等表現」を見つけた場合、プロジェクトの公開リポジトリの Issue トラッカー、またはプロジェクトへの直接連絡を通じて報告できます。これらを構造化した仕組み――*却下（reject） / 大意（gist） / 許容（acceptable） / 秀逸（excellent）* の選択肢と自由記述メモを備えた評価画面――がコミュニティレビューのインターフェースであり、[ベンチマーク仕様 §7.3](/docs/network/specifications/benchmark#7-human-validation) で定義されていますが、まだ公開されていません。それが稼働するまでは、報告は個別に対応され、検証タスク自体（有償の構造化された話者レビュー。[話者との協働](/docs/working-with-speakers) を参照）が主な修正パイプラインとなります。

**言語カードの誤った事実の報告（現在稼働中、同じチャンネル）。** カードの修正も同じ経路をたどります。報告、レビュー、バージョン管理された変更。カードは評価の動作を駆動するため——どのメトリクスを読み込むか、どのモデルが推奨されるか——カードの修正はスコアを変える可能性があります。そのため、修正は記録されたデータ変更として適用され、サイレント編集は行われません。

**次に何が起きるか——誰が決めるか：**

- **言語的な判断は、その言語の話者に委ねられます。** ある表現が妥当か、2つの表現が同等か、文脈に応じた表現のレベル（レジスター）が適切か――プラットフォームはその答えを実装するだけであり、自ら答えを提供するわけではありません。話者間で意見が分かれる場合（方言、表記規約など）は、私たちが優劣を決めるのではなく、変種として記録します。コーパスおよびリンターのスキーマは、1つの正解を強制するのではなく、方言の異形態を許容される代替表現としてタグ付けすることをサポートしています。
- **コミュニティのデータに関する決定は、そのガバナンス組織に委ねられます。** ガバナンス組織を持つ言語の場合、評価コーパスの変更、封印されたテストセットへの修正の反映、デプロイによる影響などは、その組織を通じて進められます。これが言語データに対するコミュニティの自己決定権（[あなたの言葉、あなたのルール](/docs/your-words-your-rules) を参照）であり、単なるお題目のポスターではなく、具体的なプロセスとして実装されています。
- **機械的なエラーは、そのまま修正します。** 誤字、リンク切れ、フィールドの解析ミスなどは、報告を受け、修正し、記録されます。何でもかんでも協議会にかける必要はありません。

## 修正には来歴が伴う

追跡できない修正は、単に新しい意見にすぎません。すべての事実とすべての修正に3つの来歴ルールが適用されます。

1. **すべての事実に情報源を明記します。** 言語カードやコーパスのエントリには、公開されたデータセット、コミュニティからのコントリビューション、話者のレビューなど、各値の出所が記録されます。
2. **派生値はアップストリームのものではなく、私たちのものとして明記します。** 集計値、再コーディング、複合値など、プラットフォーム側で計算した値は、アップストリームの情報源*から*のプラットフォーム派生値として記録され、アップストリームの名義で記載されることはありません。アップストリームのデータセットが、自ら公開していない数値によって責められたり、評価されたりしてはなりません。
3. **修正は記録の一部となります。** 話者による修正は、古い値を置き換える新たな帰属付きの主張（話者の選択に応じて実名または匿名。検証作業と同じ条件）として記録され、変更履歴は常に監査可能です。コーパスのバージョンはハッシュ値によって明示されるため（[コーパスの登録](/docs/network/sovereignty/registering-corpora) を参照）、修正されたコーパスは明確に新しいバージョンとなり、各ランカードにはどのバージョンに対してスコアリングが行われたかが正確に記録されます。これにより、過去のスコアの解釈可能性が保たれ、新しいスコアには修正が反映されます。

## 拒否権、具体的に

「コミュニティの管理」は主張するのは簡単です。公開されたアーキテクチャにおいて、それが具体的に何を意味するかを示します。

- **話者は自身のコントリビューションを取り消すことができます。** 話者はいつでも自分の評価を取り下げることができ、取り下げられた評価はすべての分析から除外されます（[話者検証 §5](/docs/network/specifications/speaker-validation#5-data-governance) を参照）。また話者は、問題があると判断した結果の公開に対して拒否権（ベト権）を持ちます。
- **コミュニティは評価を完全に停止できます。** 封印されたテストセットは暗号化されており、Champollion はキーのシェアを一切保持していないため、プラットフォーム単独で復元することは絶対にできません。現在、封印されたセットのキーは主催者が保持しています（コミュニティのキー保管者はまだ任命されていません）。コミュニティが指名した保管者がセットのキーシェアを保持するようになれば、キー復元への参加を拒否することで評価を停止できます（[コーパスの登録](/docs/network/sovereignty/registering-corpora) を参照）。「もし停止したくなったらどうするか？」という問いへの答えは明確に規定されています。封印されたデータは決して公開されず、評価は終了します。
- **いかなるスコアも、コミュニティの決定を覆すことはできません。** リーダーボードでの順位が高くても、そのコミュニティの言語に対して手法をデプロイする許可が得られるわけではありません（[所有権の移転](/docs/network/sovereignty/ownership-transfer) を参照）。そして、自らの言語に機械翻訳を一切デプロイすべきではないとコミュニティが判断した場合、それは設計通りのシステムの権利行使であり、システムを破綻させる行為ではありません（[翻訳は言語復興ではない](/docs/network/perspectives/translation-is-not-revitalization) を参照）。

## まだ構築されていないもの

このカテゴリの他の文書と同様に、コミュニティレビューのインターフェースは計画段階であり、まだ公開されていません。現在のところ、いずれの言語についてもガバナンス組織はまだ設立されておらず、Plains Cree を含め、どのベンチマークに対してもコミュニティカストディアン（管理者）は任命されていません。また、事前の同意を得る前にカストディアンを公表することもありません。これらが整備されるまでの間、修正は追跡可能な直接のチャネルを通じて行われ、このページではなく公開されている仕様（spec）がプロセスの拘束力を持つ正式な記述であり続けます。このページと仕様の間で矛盾がある場合は仕様が優先され、その不一致自体も報告すべきバグとみなされます。

## これがあなたにとって意味すること

:::info[コミュニティメンバーの方へ]
このプラットフォーム上でお使いの言語に関する情報（事実、翻訳、ラベルなど）に誤りがある場合、あなたの報告はトリアージされる単なる苦情ではなく、現場の事実に基づく証言です。修正に実名を記載するかどうかはご自身で選べます。提供したデータは後から取り消すこともでき、コミュニティは自らのデータの使用を完全に停止させることもできます。まずは [あなたの言葉、あなたのルール](/docs/your-words-your-rules) をご覧いただくか、公開リポジトリで Issue を作成してください。
:::

:::info[研究者の方へ]
ここでの訂正は出所が明確なデータであり、無言の編集ではありません。コーパスのバージョンはハッシュ化され、ランカードはスコアリングに使用した正確なバージョンを固定し、派生値は派生であることが明示されます。Network のスコアやコーパスを研究に利用する場合は、バージョンを引用してください。また、話者主導の訂正の波は、指標の妥当性に関する知見として扱ってください。実際にそういうものだからです。
:::

:::info[開発者の方へ]
あなたの手法のスコアは、コードを変更していなくても正当な理由で変わることがあります。誤って拒否されていた単語が許可リストに追加されたり、参照翻訳が修正されたり、バリアントクラスが修正されたりする場合です。そのことを前提に設計してください。ランカードにコーパスのバージョンを固定し（[ランカード仕様](/docs/network/specifications/run-card)）、データセットの変更履歴を確認し、話者による訂正を、無償で得られる最も信頼性の高いエラーシグナルとして扱ってください。
:::
