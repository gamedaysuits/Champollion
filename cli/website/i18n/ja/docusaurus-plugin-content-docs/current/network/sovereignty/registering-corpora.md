# コーパスの登録と公開レーンについて

> **概要:** 評価用コーパスをNetworkに登録することで、**データを私たちに渡すことなく**、各種手法をそのコーパスに対してベンチマークできます。すべてのコーパスはコンテンツではなく、SHA固定された*メタデータカード*として登録されます。実際の文は評価時にそのソースから取得されます。登録時には、2つの独立した選択を行います。1つは**露出ティア（exposure tier）** — お使いのマシンからどれだけの情報が出るか（`local-only`、`private`、`public`、またはコーパスがお使いのデバイス上でM-of-N管理者鍵の下で暗号化される`sealed`）、もう1つはコーパスの利用目的を規定する**ライセンスレーン（license lane）**（パブリック、非商用研究限定、またはプライベート）です。これは、コミュニティが自らの言語を*抽出可能（extractable）*にすることなく、*測定可能（measurable）*にするための仕組みです。

機械翻訳の評価は通常、データ主権とは相反する要求をします。「テストセットをアップロードしてください、採点します」というものです。しかし、Indigenous 言語やその他のコミュニティが保有するコーパスにとって、データはそれが生まれた人々のものであり、そのような要求は受け入れられません。ネットワークはそのようなトレードオフを強いることなく利用できるよう設計されています。

---

## 1. 登録はメタデータであり、コンテンツではない {#1-registration-is-metadata-not-content}

登録されたコーパスは**カード**です。コーパスの*所在*と*内容*を記述した小さな JSON レコードであり、正確なバイト列を検証できるコンテンツハッシュを含みますが、**文は含まれません**。カードには以下のフィールドが含まれます：

| フィールド | 内容 |
|-------|-----------|
| `url` | コーパスの取得元（あなたが管理する上流アーカイブ） |
| `sha256` | ピン留めされたアーカイブのコンテンツハッシュ — データが差し替えられていないことを証明する |
| `license` | SPDX 識別子（独自ライセンスの場合は `LicenseRef-…`） |
| `language_pair` | ソース → ターゲット（例：`eng-crk`） |
| `do_not_train` | 常に設定される — 評価データは学習に使用してはならない |
| `attribution` | コーパスが表示されるすべての場所に示されるビルダー/言語学者のクレジット |

評価時、ハーネスはソースから**取得**し、`sha256` を検証してから、取得したばかりの参照に対してスコアを算出します。ネットワークはコーパスのコンテンツを保存・ホスト・再配布することはありません。上流アーカイブをオフラインにすれば、そのコーパスは単純に実行不可能になります — 制御はあなたの手元に残ります。これはカタログ全体に適用されるソース取得の規律と同じです（[評価データセット](/docs/network/leaderboard/datasets)を参照）。

:::info[コピーではなくハッシュを使う理由]
コンテンツハッシュを使うことで、自己申告されたスコアを、コーパス本体を保持することなく**再検証**できます。ハッシュで固定されたソースに対して数値が再現されない実行は却下されます。検証可能性とデータ非保持は相反しません — ハッシュがあるからこそ、両方が同時に実現できるのです。
:::

## 2. 2つの独立した選択

登録時には2つの独立した質問が行われます。これらは保護する対象が異なるため、区別して考えることが重要です。

1. **お使いのマシンから何が出るか** — *露出ティア（exposure tier）*。
2. **コーパスを何に使用できるか** — *ライセンスレーン（license lane）*。

コーパスは封印（sealed）かつ非商用にも、パブリックかつ商用利用可にも、あるいはその他の任意の組み合わせにも設定できます。一方が他方を意味することはありません。

### 2a. 露出ティア — お使いのマシンから何が出るか

`cli/lib/corpus-registration.mjs`で定義されている4つのティアがあります。**平文のコーパスコンテンツはいずれのティアでもアップロードされません** — これはポリシー設定ではなく、すべてのティアに共通する事実です。登録は常に最もプライベートな設定がデフォルトになります。

| ティア | 登録されるか | 私たちが受け取るもの | カードの追跡 |
|---|:---:|---|:---:|
| **Private / local-only** | ❌ | なし。カードとテキストはお使いのマシンに留まります。**デフォルト。** | ❌ |
| **Register privately** | ✅ | メタデータのみ — WMT形式の非公開ホールドアウトセット。データは手元に保持され、データを公開することなく結果を公開できます。 | ✅ |
| **Register publicly** | ✅ | メタデータ + ソースからの取得ポインタ。テキストは必要に応じてアップストリームから取得され、ここでホストされることはありません。再配布が許可されたライセンスが必要です。 | ✅ |
| **Sealed** | ✅ | コンテンツを含まないカード。暗号文は手元に留まります。 | ✅ |

#### テストセットをあらゆる外部AIサービスから隔離する

テキストをアップロードしないことは1つの保証です。評価中にモデルAPIへテキストを*送信*しないことはもう1つの保証であり、機密性の高い文言を含むテストセットにとって極めて重要です。対象ファイルと同じ場所に、そのファイル名に`.champollion.json`を付加した小さなファイルを配置することで、ローカル専用（local-only）としてマークできます。

```bash
# data/nurse_checked_test.tsv  →  data/nurse_checked_test.tsv.champollion.json
echo '{"transmission": "local-only"}' > data/nurse_checked_test.tsv.champollion.json
```

これはあらゆるコーパス形式（TSV、JSONL、プレーンテキストのペア、JSON）で機能します。以降、`mt-eval run`はそのコーパスを封印されたものとして扱います。
- リモートプロバイダー（OpenRouter、OpenAI、Anthropic、Gemini）の場合、**テキストが送信される前、およびAPIキーが要求される前に実行が拒絶されます**。
- このマシン上のモデル（`http://localhost:11434/v1`などのループバックアドレス）を指す`--provider local`の場合、実行は進行します。
- `--method local-model -m <model>`（ハーネスが自身のプロセスでロードするNLLB、OPUS-MT、またはMADLADモデル。`-m`が必要）の場合、実行は進行します。マシンから文が出ることはなく、重みのダウンロードで移動するのはモデルファイルのみであり、テキストが移動することはありません。
- 機械翻訳エンジンまたはメソッドプラグイン（`--method <plugin dir>`）の場合、そのトランスポートが完全にローカルであることを証明（`--attest-local-transport`、実行ログに記録）しない限り実行は拒絶されます。ハーネスはプラグインやサービスがテキストをどこに送信するかを確認できないためです。
- 言語カードからのその言語固有の評価メトリクスは**ロードされません**。それらはオンライン辞書などの外部サービスで単語を検索する可能性のある別パッケージから提供されるためです。実行はそれらなしでスコアリングされ、実行カードにはそれらが除外されたこととその理由が記載されます。
- `mt-eval publish`は文を除外し、デフォルトでコーチングまたはカスタムプロンプトをそのSHA256に置き換えるため、ご自身の文から抽出されたプロンプトの例もお使いのマシンに留まります。コーパスに関する一部のメタデータはスコアとともに公開されます（ID、バージョン、言語ペア、サイズ、ファイルのSHA256、ライセンスと帰属、コンタミネーショングレード、ローカル専用としてマークされていること、およびセグメント名）。登録済みデータセットではないIDの場合、公開によって同じID、ペア、サイズ、SHA256に加え、そのドメイン、セグメント名、難易度範囲を持つ公開`datasets`行も作成されます。`--dry-run`プレビューには、お使いのマシンに留まるもの（すべての文、ファイル、およびそのパス）と並んで、今回の実行で公開される項目が一覧表示されます。これにより、他のユーザーには開くことのできないテストセットに対するスコアが表示されます。これは自己ベンチマーク（self-benchmarked）であり、他の誰も再実行できません。また、SHA256によって、同一のファイルを保持している人のみがそれがそのファイルであることを確認できます。
- ツールが出力する内容からは文が除外されます。ターミナルを読み取るAIエージェントが、読み取った内容をそのモデルプロバイダーに渡してしまうためです。`mt-eval compare`は文の代わりに入力IDとスコアを表示し、文を引用するエラーメッセージは文を削除した状態で出力されます。`--show-text`はターミナルにいる人間のためにそれらを出力します。結果フォルダーに書き込まれるファイルにはテキストが保持され、各ファイルにはコーパスのマークが付与されます。ハーネスがコーパスから書き込むすべての実行ログ、レポート、比較ファイル、ダッシュボードには、同じ条件に`derived_from`を加えた独自の`.champollion.json`が付与されます。これにより、次のツールやそのファイルに対する後続の実行でも保護対象として扱われます。ターミナルにはテキストを保持する各ファイルの名前が表示されます。
- 翻訳キャッシュはこのコーパスのエントリを隔離して保持します。`<cache-dir>/protected/<namespace>/`（デフォルトでは`eval/cache/harness/protected/…`）の下で、実行の設定、コーパスのSHA256、およびその利用条件をキーとする名前空間に保存されるため、エントリはこの同一コーパスでの実行にのみ再利用され、別のコーパスやマークされていないコーパスの実行に提供されることは決してありません。そこにあるすべてのキャッシュファイルには同じ`.champollion.json`マークが付与されます。（この保護機能が存在する前にキャッシュされたエントリは、通常のキャッシュにマークなしで保存されています。それらを消去するには`eval/cache/harness/`を一度削除してください。）

このマークはコーパスをより厳格にすることしかできません。いかなるライセンスや`--allow-data-collection`フラグもこれを緩和することはできません。マーカーファイルが読み取れない場合、実行はそれを無視するのではなく停止します。

**Sealed（封印）は本システムが提供する最も強力な保証です。**コーパスは管理者（custodian）グループの鍵を用いて**お使いのデバイス上で**暗号化され、暗号文はお使いのマシンまたは評価ノードに留まります。Champollionが受け取るのは、コンテンツを含まないカードのみです。オフラインノード上では鍵が分割されているため、実行を承認するには**M of N**の管理者が揃う必要があります。この儀式（セレモニー）は構築済みですが、実際の管理者による運用はまだ行われていません。Sealedセットはカタログ化されますが隔離（検疫）され、封印された実行を提案する前に手法がパスしなければならない公開*予選（qualifier）*コーパスとペアになっています。[Run a Sovereign Contest](/docs/network/sovereignty/run-a-sovereign-contest)および[Sovereign Eval Node](/docs/network/sovereignty/sovereign-eval-node)を参照してください。

### 2b. ライセンスレーン — コーパスを何に使用できるか

これとは別に、ライセンスは結果を掲載できる場所を規定します。

#### パブリック（Public）

オープンライセンス（例：CC0、CC-BY）のコーパスで、参照が公開の場に表示され、実行結果が公開リーダーボードにランク掲載される可能性があります。コンテンツは依然としてソース取得方式です — "public" は参照とランキングの*公開範囲*を規定するものであり、ホスティングを意味しません。カタログの大部分（Tatoeba、GlobalVoices、TICO-19、IN22、SMOL、ALT、Turkic-x-WMT、WMT24++ など）はこのレーンに属します。

#### 非商用研究限定（Non-commercial research-only）

非商用ライセンス（例：CC BY-NC-SA、または Gamayun キットの `LicenseRef-TWB-Gamayun` のようなコミュニティ/NGO 独自ライセンス）のコーパスです。**研究目的のベンチマーク**には使用できます — 手法を実行してスコアを算出できます — しかし、**商用・賞・API のすべての経路から除外されます。** 適格性は**コーパス単位ではなく、用途単位**で判断されます：

- **商用レーンは厳格** — 明確に商用ライセンスが付与されていないものはすべて除外されます；
- **研究レーンは寛容** — 非商用コーパスも歓迎されます；
- **隔離は常に優先** — 不適切なサブセットとしてフラグが立てられた（またはその他の理由で禁止された）コーパスは、ライセンスに関わらず、いかなるレーンでもランク掲載できません。

これにより、コミュニティは自分たちのコーパスを研究の進歩に役立てながら、誰かのプロダクトに取り込まれないようにすることができます。

#### プライベート（Private）

**自分のスコア付き実行**のために登録するコーパスで、参照は公開されません。ソースはあなたが保持し、評価を実行し、何をどこまで公開するかはあなたが決めます。private コーパスは後から public または non-commercial に変更できます — 公開範囲は、オーナーによる明示的な決定によってのみ*広がる*方向に変化し、暗黙的に変わることはありません。

| ライセンスレーン | ベンチマーク可能か | 参照が公開表示されるか | 公開ランキングに掲載可能か | 商用/賞金/APIパスに含まれるか |
|------|:---:|:---:|:---:|:---:|
| **Public** | ✅ | ✅ | ✅ | ✅（ライセンスで許可されている場合） |
| **Non-commercial research-only** | ✅ | ライセンスによる | 研究レーンのみ | ❌ |
| **Private** | ✅（自身の実行のみ） | ❌ | ❌ | ❌ |

:::note[商用レーンはガードレールであり、ビジネスではありません]
Champollion 自体は非商用です — 有料の API や製品は一切存在しません。商用・賞金レーンは*将来に向けた*ガードレールとして設けられています。これは、どのコーパスが賞金や商用の文脈で合法的に使用できるかを機械的に記録するものであり、将来にわたって誰もライセンスや管理者の利用規約を逸脱できないようにするためのものです。
:::

## 3. 主権の保証

登録は[データスチュワードシップの方針](/docs/network/sovereignty/data-sovereignty)に基づいて設計されています。具体的には：

- **保有はソース側に留まる。** ネットワークが保持するのはハッシュと URL のみであり、データは保持しません。
- **制御はオーナーにある。** レーンはオーナーが選択し、公開範囲は明示的な決定によってのみ広がります。上流アーカイブを削除すれば、実行可能性は失われます。
- **非商用は非商用を意味する。** NC コーパスは商用・賞・API レーンから機械的に除外されます — 約束ではなく、ゲートによって。
- **不適切なサブセットはランク掲載できない。** 隔離はライセンスより優先されるため、ランク掲載が禁止されたコーパスはどこでも禁止されたままです。
- **帰属表示は必須。** ビルダー/言語学者のクレジットは、コーパスが表示されるすべての場所にカードとともに伝わります。

言語ごとの条件の設定方法（スポンサー付き賞における手法所有権の移転を含む）については、[所有権と条件](/docs/network/sovereignty/ownership-transfer)を参照してください。

## 4. 登録方法

コーパスカードのスキーマとビルド/検証ツールについては、[コーパス設計フレームワーク](/docs/network/specifications/corpus-design)および[コーパス作成クックブック](/docs/network/tutorials/corpus-creation)に記載されています。概要は以下のとおりです：

1. コーパスアーカイブを自分が管理する場所にホストします（そこに留まります — ネットワークにコピーされることはありません）。
2. カードを作成します：`url`、`sha256`、`license`、`language_pair`、`attribution`、`do_not_train`。
3. 公開レーンを選択します（public / non-commercial / private）。
4. カードを登録します。これにより、レーンのルールに従って、ソース取得方式でコーパスに対する手法のベンチマークが可能になります。

文をアップロードする必要はありません。いつでも停止できます。

### カードID

`champollion register-corpus`はカードを作成し、`eval-<source>-<target>-<name>[-<role>]-v1`の形式のIDを付与します。

- **name**は`--name`に基づきます。「Ward phrases」は`ward-phrases`になります。発行者（publisher）は、名前にa〜zや0〜9の文字が含まれていない場合（例えば音節文字（syllabics）のみで書かれた名前など）にのみ使用されます。
- **role**はそのセットの用途（`--role test`、`--role dev`、または`--role train`）を示します。これは渡された場合にのみIDに含まれます。ツールが用途を勝手に推測することはないため、ホールドアウトテストセットは明示的に指定した場合にのみテストセットと呼ばれます。

```bash
champollion register-corpus --yes --name "Ward phrases" --pair "eng>xyz" \
  --license proprietary --tier private --role test --size 120 --domain medical
```

これにより`eval-eng-xyz-ward-phrases-test-v1`が登録されます。IDをご自身で選択する場合は`--id eval-…`を指定してください。指定されたとおりにそのまま使用されます。

### プライベートテストセットに使用するライセンスID

`--license`は、データを所有する人々が実際に認諾した条件を記録します。これはプレースホルダーではなく、ツールが自動的に選択することもありません。まず関係者（家族、臨床医、コミュニティのデータスチュワードなど）に確認し、その回答に合致するIDを選択してください。

| 所有者が認諾する内容 | `--license` |
|---|---|
| すでに標準ライセンスの下でテキストを公開している | そのSPDX ID（例: `CC-BY-NC-4.0`） |
| システムのスコアリングにのみ使用する: 学習への使用禁止、再配布禁止、有料スコアリング禁止 | `community-eval-grant-nc`（`LicenseRef-Champollion-Eval-Grant-NC`） |
| 上記と同様だが、有料ユーザー向けのスコアリングは許可 | `community-eval-grant`（`LicenseRef-Champollion-Eval-Grant`） |
| 自身の利用を超える認諾なし: 全著作権所有（All rights reserved） | `proprietary`（`LicenseRef-Proprietary`） |
| 上記のいずれにも該当しない独自の条件 | `LicenseRef-<a name for their terms>`（そのまま入力し、スチュワードが管理する場所に条件を明記） |

表内のすべての`LicenseRef-…` ID（2つの評価用認諾および`proprietary`を含む）は特注の認諾です。Champollionが所有者に代わってこれを解釈することはありません。スチュワードが許可を記録するまで、それに対するリモート評価は拒絶されるため、ご自身のマシン上のモデルのみがテスト対象となります。判断がつかない場合、測定を行いながらも最も安全側の選択肢は`community-eval-grant-nc`です。暫定的なものとして記録し、スチュワードに確認してもらうか、適切なものを指定してもらってください。

ライセンスによって文の送信先が変わることはありません。ローカル専用セット（`.champollion.json`マーカー、または`--tier local-only`）は、ライセンスの内容にかかわらずお使いのマシンに留まります。マーカーはすべてのリモートモデルを拒絶し、ライセンスがそれを緩和することは決してありません。ライセンスは、そのセットが万一共有された場合に他者がそれに対して行えることや、どの評価レーンに参加できるかを規定します。ファイルが`--data`で登録されると、そのIDは隣接する`.champollion.json`ファイルに記録され、変更されることはありません。そのファイルを再度登録しようとすると処理が停止し、`--id`でIDを渡すよう求められます。

モデルの学習対象となる可能性のあるテストセット（`--role test`、または役割が指定されていないローカル専用またはプライベートのセット）の場合、コマンドはそのセットの最初のスコア取得前に実行しなければならないnmt-forgeの手順を出力します（登録、学習コーパスに対するスクリーニング、および予測の記録）。ベースラインの`mt-eval run`はそれらの後に実行されます。ベンチマークはスコアリング読み取り（scoring read）であり、nmt-forgeはベンチマーク実行後に書き込まれた予測を拒絶します。

`mt-eval run --corpus <that file>`は同じ`.champollion.json`ファイルを通じてカードを見つけます。実行のデータセットIDはカードのIDとなるため、そのセットに対するすべての実行は同じ名前を持ち、ファイル名はコーパスパスとして実行情報に残ります。カードのコンタミネーショングレードは、カードに記載されているとおりに報告されます。これらはいずれも、ファイルが登録時のものである場合にのみ適用されます。それ以降に変更されている場合、実行時にその旨が示され、どちらも使用されません。

`local-only`、`private`、または`sealed`カードはそのテキストが未公開（`Contamination: NONE`）であることを示しているため、登録時にはまず、`--data`（または`--seal-input`）で渡されたファイルと公開コーパスとの比較が行われます。リポジトリのチェックアウトでは、自身が保持しているコーパスカードと比較されます。コーパスカードが同梱されないnpmインストール環境では、公開コーパスカタログと比較されます。CLIは公開コーパスのIDとチェックサムをダウンロードし、お使いのマシン上で比較を行うため、ファイルのチェックサムがマシン外に出ることはありません。ファイルが公開コーパスとバイト単位で一致する場合（同一のSHA256）、登録は停止し、該当するコーパス名が表示されます。公開として登録するか、真にプライベートな文を使用するか、あるいはティアを維持したまま`--contamination`で露出状況を明示してください（この場合、カードにはテキストが公開である旨が記録されます）。公開テキストの封印（sealed）セットは拒絶されます。何もテストできないためです。

比較が行えない場合（オフラインの場合、またはカタログにアクセスできない場合）、`--contamination`でグレードをご自身で指定しない限り、カードは`NONE`ではなく`Contamination: UNCHECKED`と評価されます。比較を行うには、オンライン状態で再登録してください。`mt-eval`は`UNCHECKED`のコーパスを、`LOW`と評価されていない他のコーパスと同様に扱います。そのスコアは相対比較専用（relative-comparison-only）レーンに入ります。このチェックはファイル全体を比較するため、編集または再フォーマットされた公開セットは認識されません。行単位の比較には`mt-eval contest prepare`を使用します。
