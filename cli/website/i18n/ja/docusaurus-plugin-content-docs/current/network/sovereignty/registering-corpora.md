# コーパスの登録と公開レーンについて

> **エグゼクティブサマリー:** 評価コーパスをネットワークに登録することで、**データを私たちに渡すことなく**、そのコーパスに対してメソッドのベンチマークを行うことができます。すべてのコーパスはコンテンツとしてではなく、SHAで固定された*メタデータカード*として登録されます。実際の文は、評価時にソースから取得されます。登録時には、2つの独立した選択を行います。1つは**公開ティア (exposure tier)** — マシンからどの程度のデータが外部に出るか (`local-only`、`private`、`public`、または `sealed`。この場合、コーパスはM-of-Nの管理者キーによってデバイス上で暗号化されます) — であり、もう1つは**ライセンスレーン (license lane)** — コーパスを何に使用できるかを規定するもの (パブリック、非営利の研究専用、またはプライベート) — です。これは、コミュニティが自らの言語を*抽出可能 (extractable)* にすることなく、*測定可能 (measurable)* にするためのメカニズムです。

機械翻訳の評価は通常、データ主権とは相反する要求をします。「テストセットをアップロードしてください、採点します」というものです。しかし、Indigenous 言語やその他のコミュニティが保有するコーパスにとって、データはそれが生まれた人々のものであり、そのような要求は受け入れられません。ネットワークはそのようなトレードオフを強いることなく利用できるよう設計されています。

---

## 1. 登録はメタデータであり、コンテンツではない {#1-registration-is-metadata-not-content}

登録されたコーパスは**カード**です。コーパスの*所在*と*内容*を記述した小さな JSON レコードであり、正確なバイト列を検証できるコンテンツハッシュを含みますが、**文は含まれません**。カードには以下のフィールドが含まれます：

| フィールド | 内容 |
|-------|-----------|
| `url` | コーパスの取得元（あなたが管理する上流アーカイブ） |
| `sha256` | ピン留めされたアーカイブのコンテンツハッシュ — データが差し替えられていないことを証明する |
| `license` | SPDX 識別子（独自ライセンスの場合は `LicenseRef-…`） |
| `language_pair` | ソース → ターゲット（例：`eng-crk`） |
| `do_not_train` | 常に設定される — 評価データは学習に使用してはならない |
| `attribution` | コーパスが表示されるすべての場所に示されるビルダー/言語学者のクレジット |

評価時、ハーネスはソースから**取得**し、`sha256` を検証してから、取得したばかりの参照に対してスコアを算出します。ネットワークはコーパスのコンテンツを保存・ホスト・再配布することはありません。上流アーカイブをオフラインにすれば、そのコーパスは単純に実行不可能になります — 制御はあなたの手元に残ります。これはカタログ全体に適用されるソース取得の規律と同じです（[評価データセット](/docs/network/leaderboard/datasets)を参照）。

:::info[コピーではなくハッシュを使う理由]
コンテンツハッシュを使うことで、自己申告されたスコアを、コーパス本体を保持することなく**再検証**できます。ハッシュで固定されたソースに対して数値が再現されない実行は却下されます。検証可能性とデータ非保持は相反しません — ハッシュがあるからこそ、両方が同時に実現できるのです。
:::

## 2. 2つの独立した選択

登録時には2つの独立した質問が行われます。これらは異なるものを保護するため、区別しておくことが重要です。

1. **マシンから何が外部に出るか** — *公開ティア (exposure tier)*。
2. **コーパスを何に使用できるか** — *ライセンスレーン (license lane)*。

コーパスは、封印 (sealed) されていて非営利である場合もあれば、パブリックで商用利用可能である場合もあり、その他のあらゆる組み合わせも可能です。一方が他方を意味するわけではありません。

### 2a. 公開ティア — マシンから何が外部に出るか

`cli/lib/corpus-registration.mjs` で定義されている4つのティアがあります。**どのティアにおいても、プレーンテキストのコーパスコンテンツがアップロードされることは決してありません**。これはポリシーの設定ではなく、すべてのティアに当てはまる事実です。登録は常に最もプライベートな設定がデフォルトになります。

| ティア | 登録 | 私たちが受け取るもの | カードの追跡 |
|---|:---:|---|:---:|
| **Private / local-only** | ❌ | なし。カードとテキストはマシン上に留まります。**デフォルト。** | ❌ |
| **Register privately** | ✅ | メタデータのみ — WMTスタイルのシークレットホールドアウトセット。あなたが管理を維持し、データを公開することなく結果を公開できます。 | ✅ |
| **Register publicly** | ✅ | メタデータ + ソースからの取得ポインタ。テキストはオンデマンドでアップストリームから取得され、ここでホストされることはありません。再配布が許可されたライセンスが必要です。 | ✅ |
| **Sealed** | ✅ | 暗号文 + コンテンツを含まないカード。それ以外は何もありません。 | ✅ |

**Sealed (封印) は、システムが提供する最も強力な保証です。** コーパスは、1バイトたりとも外部に出る前に、管理者グループのしきい値キーを使用して**デバイス上で**暗号化されます。Champollionは暗号文を受け取りますが、それを復号することはできません。また、単独の管理者も復号することはできません。実行を承認するには、**N人中M人**の管理者が協力する必要があります。Sealedセットはカタログ化されますが隔離されており、パブリックな*予選 (qualifier)* コーパスとペアになっています。メソッドは、Sealedでの実行を提案する前に、この予選コーパスをクリアする必要があります。[Run a Sovereign Contest](/docs/network/sovereignty/run-a-sovereign-contest) および [Sovereign Eval Node](/docs/network/sovereignty/sovereign-eval-node) を参照してください。

### 2b. ライセンスレーン — コーパスを何に使用できるか

これとは別に、ライセンスは結果をどこに表示できるかを規定します。

#### Public

オープンライセンス（例：CC0、CC-BY）のコーパスで、参照が公開の場に表示され、実行結果が公開リーダーボードにランク掲載される可能性があります。コンテンツは依然としてソース取得方式です — "public" は参照とランキングの*公開範囲*を規定するものであり、ホスティングを意味しません。カタログの大部分（Tatoeba、GlobalVoices、TICO-19、IN22、SMOL、ALT、Turkic-x-WMT、WMT24++ など）はこのレーンに属します。

#### Non-commercial research-only

非商用ライセンス（例：CC BY-NC-SA、または Gamayun キットの `LicenseRef-TWB-Gamayun` のようなコミュニティ/NGO 独自ライセンス）のコーパスです。**研究目的のベンチマーク**には使用できます — 手法を実行してスコアを算出できます — しかし、**商用・賞・API のすべての経路から除外されます。** 適格性は**コーパス単位ではなく、用途単位**で判断されます：

- **商用レーンは厳格** — 明確に商用ライセンスが付与されていないものはすべて除外されます；
- **研究レーンは寛容** — 非商用コーパスも歓迎されます；
- **隔離は常に優先** — 不適切なサブセットとしてフラグが立てられた（またはその他の理由で禁止された）コーパスは、ライセンスに関わらず、いかなるレーンでもランク掲載できません。

これにより、コミュニティは自分たちのコーパスを研究の進歩に役立てながら、誰かのプロダクトに取り込まれないようにすることができます。

#### Private

**自分のスコア付き実行**のために登録するコーパスで、参照は公開されません。ソースはあなたが保持し、評価を実行し、何をどこまで公開するかはあなたが決めます。private コーパスは後から public または non-commercial に変更できます — 公開範囲は、オーナーによる明示的な決定によってのみ*広がる*方向に変化し、暗黙的に変わることはありません。

| ライセンスレーン | ベンチマーク可能 | 参照の公開表示 | パブリックボードでのランク付け | 商用 / 賞金 / APIパスへの参加 |
|------|:---:|:---:|:---:|:---:|
| **Public** | ✅ | ✅ | ✅ | ✅ (ライセンスが許可する場合) |
| **Non-commercial research-only** | ✅ | ライセンスに依存 | リサーチレーンのみ | ❌ |
| **Private** | ✅ (自身の実行) | ❌ | ❌ | ❌ |

:::note[商用レーンはガードレールであり、ビジネスではありません]
Champollion 自体は非商用です — 有料の API や製品は一切存在しません。商用・賞金レーンは*将来に向けた*ガードレールとして設けられています。これは、どのコーパスが賞金や商用の文脈で合法的に使用できるかを機械的に記録するものであり、将来にわたって誰もライセンスや管理者の利用規約を逸脱できないようにするためのものです。
:::

## 3. 主権の保証

登録は[データスチュワードシップの方針](/docs/network/sovereignty/data-sovereignty)に基づいて設計されています。具体的には：

- **保有はソース側に留まる。** ネットワークが保持するのはハッシュと URL のみであり、データは保持しません。
- **制御はオーナーにある。** レーンはオーナーが選択し、公開範囲は明示的な決定によってのみ広がります。上流アーカイブを削除すれば、実行可能性は失われます。
- **非商用は非商用を意味する。** NC コーパスは商用・賞・API レーンから機械的に除外されます — 約束ではなく、ゲートによって。
- **不適切なサブセットはランク掲載できない。** 隔離はライセンスより優先されるため、ランク掲載が禁止されたコーパスはどこでも禁止されたままです。
- **帰属表示は必須。** ビルダー/言語学者のクレジットは、コーパスが表示されるすべての場所にカードとともに伝わります。

言語ごとの条件の設定方法（スポンサー付き賞における手法所有権の移転を含む）については、[所有権と条件](/docs/network/sovereignty/ownership-transfer)を参照してください。

## 4. 登録方法

コーパスカードのスキーマとビルド/検証ツールについては、[コーパス設計フレームワーク](/docs/network/specifications/corpus-design)および[コーパス作成クックブック](/docs/network/tutorials/corpus-creation)に記載されています。概要は以下のとおりです：

1. コーパスアーカイブを自分が管理する場所にホストします（そこに留まります — ネットワークにコピーされることはありません）。
2. カードを作成します：`url`、`sha256`、`license`、`language_pair`、`attribution`、`do_not_train`。
3. 公開レーンを選択します（public / non-commercial / private）。
4. カードを登録します。これにより、レーンのルールに従って、ソース取得方式でコーパスに対する手法のベンチマークが可能になります。

文をアップロードする必要はありません。いつでも停止できます。
