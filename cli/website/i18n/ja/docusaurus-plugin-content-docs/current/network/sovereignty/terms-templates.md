# 利用規約テンプレート

> **要旨。** コミュニティや組織が[ソブリンコンテスト](/docs/network/sovereignty/run-a-sovereign-contest)を運営する際に出発点として活用・改変できる規約の雛形です。全体を通じて**トラストレス寄り**の設計思想を採用しており、可能な限り、約束ではなくメカニズム（ハッシュ、ゲート、追記専用ログ）によって各条項を担保しています。各条項は短い本文と平易な解説で構成されています。

:::warning[これは法的アドバイスではありません]
以下は非営利の研究プロジェクトによる*草案のアイデア*であり、法的アドバイスではありません。また、私たちは法律の専門家ではありません。法律は管轄区域によって異なり、先住民データガバナンスの枠組みはいかなるテンプレートでも果たせない義務を課しています。実際に使用する前に、必ず自身の顧問弁護士およびコミュニティのガバナンスプロセスによるレビューを受けてください。
:::

## 基本条項

### 1. コーパスはオーナーの財産であり、今後もそうであり続ける

*条項。* 評価コーパス、その全エントリ、およびすべての派生メタデータは、登録コミュニティ／組織の単独所有物であり続けます。ネットワークの登録・コンテスト・評価機能の利用によって、コーパスに関するいかなる権利・権原・利益も、プラットフォーム、手法開発者、またはスポンサーに移転しません。プラットフォームはコピーを保持せず、暗号化されたブロブのダイジェスト以外のライセンスを主張しません。

*平易な解説：* コーパスに対してコンテストを実施しても、誰もコーパスの一部を取得することはできません。Champollion が保持するのはハッシュであり、権利の主張ではありません。

### 2. 評価はスコアのみのライセンスを付与する — それ以外は何も付与しない

*条項。* 承認された評価の実行は、プラットフォームおよび手法開発者に対し、**数値スコアおよび集計統計のみ**を受領・公開するライセンスを付与します。実行後にコーパスのコンテンツを保持する権利、それを用いてモデルのトレーニング・ファインチューニング・コーチングを行う権利、および派生コーパス・記憶済みサンプル・ルックアップテーブルを作成する権利は、**一切**付与されません。実行後にコンテンツが保持された場合、ライセンスは終了し、実行結果は無効となります。

*平易な解説：* シールドされた実行から出力されるのは数値です。文章は出力されません — リーダーボードにも、トレーニングセットにも、誰かのキャッシュにも。

### 3. ハッシュによる完全性の固定：ダイジェストは公開されるが、コンテンツは公開されない

*条項。* コーパスは、暗号化されたブロブの公開 SHA-256 ダイジェストとバージョンラベルによってのみ識別されます。ダイジェストに一致するブロブのみがコーパスとして認められ、一致しないバイト列に対する実行は無効です。ダイジェストの公開はコンテンツの公開ではなく、本規約のいかなる条項もオーナーにコンテンツの開示を義務付けるものではありません。

*平易な解説：* 誰でも*どの*コーパスが使用されたかを確認できますが、誰もそれを*読む*ことはできません。バイト列がハッシュと一致しない場合、その実行は無効です。

### 4. フェイルクローズドのデフォルト

*条項。* すべての曖昧さは、アクセス不可・非公開の方向に解決されます。カストディアンの閾値によって明示的に承認されていないリクエストは拒否されます。期限切れまたは使用済みの付与は無効です。出所を検証できない結果は公開されません。登録が失効したコーパスは実行不可となります。沈黙は同意を意味しません。

*平易な解説：* 疑わしい場合、答えはノーです。デフォルトでオープンになるものは何もありません。

### 5. カストディアンの承認がすべての実行を制御する

*条項。* 記録された閾値承認、および特定の手法・コーパスバージョン・評価環境に紐付けられた一回限りの時間制限付き付与なしに、シールドされたコーパスに対して評価を実行することはできません。拒否やブロックされた試みを含む、すべての承認イベントは追記専用の公開再生可能な監査ログに記録されます。

*平易な解説：* カストディアンは毎回の実行を一つずつ承認し、その全履歴は公開されており改ざんが証明可能です。（暗号学的な閾値署名ツールは現在開発中です — [ランブックのステータスボックス](/docs/network/sovereignty/run-a-sovereign-contest)を参照してください — そのため現時点では、この条項は数学的な保証ではなく記録されたプロセスとして施行されています。）

### 6. 賞金はスポンサーが保持し、授与ルールは公開される

*条項。* 賞金は、指定されたスポンサー組織またはコミュニティトラストが保持します — プラットフォームが保持することはありません。授与の閾値はコンテスト開始前に公開され、公開スコードとコミュニティ独自の話者検証の判定から検証可能であり、授与の決定は資金保持者のみに帰属します。

*平易な解説：* 資金は拠出した者のもとにあり、基準は公開されており、基準が達成されたかどうかは誰でも確認できます。Champollion は賞金の支払い・保留・転送を行うことができません — Champollion は資金を保持しないからです。

## トロイの木馬リスク {#trojan-horse-risks}

誠実な規約文書は、その仕組みが攻撃される可能性のある方法を明示します。これらをあなたの規約に含めてください — これらを読んだスポンサーやコミュニティは、被害を受けにくくなります。

### テストデータの持ち出しを試みる悪意のある手法の提出

「手法」は提出されたコードです。悪意のある手法は、テストの文章を外部に持ち出そうとする可能性があります — 出力にエンコードしたり、ログに書き込んだり、外部に送信したりする方法で。**緩和策：** スコアのみの出力（シールドされた実行からのエントリごとの出力テキストは公開されません — 現在データレイヤーで施行済み）；シールドされた実行のための**ネットワーク遮断サンドボックス**（🔲 開発中 — リリースまでは、この緩和策は部分的なものとして扱い、カストディアンの承認の重みを適切に考慮してください）；および**手法ごと・ラウンドごとのクエリ／実行予算** — 手法は少数の固定されたシールド実行しか受け取れないため、スコアチャネルを通じた繰り返しのプロービングによってもコーパスを再構築することはできません。

### 汚染または混入された提出コーパス

攻撃は逆方向にも行われる可能性があります：誰かがコミュニティに「既製の」テストコーパスを提供しますが、それが微妙に誤っていたり、不快なものであったり、すでに公開されていたりします（その場合、手法がそれを記憶しているためスコアは無意味になります）。**緩和策：** 各エントリの出所要件（誰が、いつ、どのソースから作成したか）；シーリング前のコーパス自体の[話者検証](/docs/network/specifications/speaker-validation)；および公開データに対する汚染スクリーニング（コーパスが予選またはゴールドスタンダードとして受け入れられる前に実施）。

### 依存関係内のライセンストロイの木馬

コミュニティが意図する用途（商用展開、再配布）を禁止するライセンスのコンテンツやコードを密かに含む受賞手法は、移転を台無しにします — 法的に使用できないツールを受け取ることになります。**緩和策：** 依存関係クラスの申告と提出物に対する機械的なライセンスゲート（[賞金仕様](/docs/network/specifications/prizes)の依存関係クラス表を参照）；未申告の依存関係は失格事由となります。

### 認証情報のフィッシング

コンテストを運営する者は誰でも、「登録を確認するためにここにトークンを貼り付けてください」という攻撃の標的になります。**緩和策：** トークン・キー・認証情報をサードパーティのページに貼り付けたり、チャットで共有したりしないでください；このプロジェクトのすべての認証は CLI の OAuth フローを通じて行われ、**ブラウザの個人アクセストークンフローはもう存在しません** — それを要求するページは悪意のあるものです。カストディアンの決定は、コミュニティがすでに信頼しているチャネルを通じて行うべきです。

### スポンサー側の賞金不払い

静かな失敗モード：手法が基準を達成したにもかかわらず、スポンサーが支払わない。**緩和策：** コンテスト開始*前*に資金保持者の身元と保持の取り決め（組織アカウント、トラスト、エスクローエージェント）を公開する；授与条件を公開スコアから検証可能にし、不払いが判断の問題として否定されるのではなく、公開された不払いとして可視化されるようにする；そして評判上失うものがある保持者を優先する。Champollion はこのリスクを引き受けることができません — 設計上、資金を保持しないからです — そのため、賞金の信頼性はその指定された保持者の信頼性そのものです。

## 使い方

適合する部分をコピーし、不要な部分を削除し、ガバナンスが必要とするものを追加し、その結果をコンテストと一緒に公開して、参加者が漠然とした雰囲気ではなく*あなたの*規約に同意するようにしてください。スポンサー付き賞金の手法所有権移転を含むコミュニティごとの規約は、ここでは例外ではなく標準です：[所有権と規約](/docs/network/sovereignty/ownership-transfer)を参照してください。
