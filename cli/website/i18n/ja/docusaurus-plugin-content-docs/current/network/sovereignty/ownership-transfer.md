# 所有権と利用規約

> **要約。** Champollion には、設計上、普遍的な合意事項はありません。
> 利用規約は、データを所有するスチュワードによって、コーパスごと、言語ごと、賞ごとに設定されます。
> プラットフォームの役割は、その規約を尊重することです。このページでは、規約書が対象とする項目と、
> 先住民言語コーパスのスポンサー付き賞におけるデフォルトの出発点である **Community Transfer Template** について説明します。

## 利用規約のフレームワーク

Champollion は、あらゆるライセンスが尊重されるよう、また、秘密コーパス、コミュニティが保有するテストセット、主権的なデプロイ要件といった新しい取り決めをサポートできるよう、利用規約において柔軟性を持つよう設計されています。言語が異なれば、合意内容も異なります。CC0 コーパス、研究専用のコミュニティコーパス、部族評議会が管理するシールドされたゴールドスタンダードセットも、それぞれ独自の条件のもとで参加できます。

統一されているのは、その規約を実現する仕組みです。公開レーン、ライセンスゲート、隔離、フェッチ元登録がそれにあたります（[コーパスの登録](/docs/network/sovereignty/registering-corpora)を参照）。*決して*統一されないのは、取り決めの内容そのものです。

コーパスのスチュワードが規約を設定する際——ベンチマーク参加のためであれ、スポンサー付き賞のためであれ、その他の目的のためであれ——規約書は以下の少数の問いに答えます。

| 項目 | 問い |
|---|---|
| **コーパスの公開範囲** | どのレーン（公開・研究専用・非公開）か？参照情報は表示されるか？ |
| **手法の所有権** | 賞が授与された場合、受賞手法の所有者は誰か——開発者か、コミュニティか、共同所有か？ |
| **デプロイ** | 誰が、どこで、どのような条件のもとで手法をデプロイできるか？ |
| **セルフホスティング** | 手法はコミュニティが管理するインフラ上で完全に動作しなければならないか？ |
| **秘密保持** | テストセットはシールドされているか？鍵を保持するのは誰か？各評価実行を承認するのは誰か？ |
| **報酬** | ビルダー、バリデーター、レビュアーへの報酬はどうなっているか？（公開されているデフォルト値：[話者への報酬について](/docs/network/perspectives/how-speakers-get-paid)） |

これらのいずれについても、プラットフォームが答えを押し付けることはありません。以下のデフォルト値はテンプレートであり、ルールではありません。

## Community Transfer Template

先住民言語コーパスのスポンサー付き賞において、コミュニティのガバナンス機関が改訂するための出発点として提供されるデフォルトテンプレートは、次のように機能します。

### 1. 手法の開発
研究者、学生、または開発者が、自身のリソースとオープンライセンスのデータを使用して、翻訳手法——FST ゲートパイプライン、コーチング済み LLM、ファインチューニング済みモデル、またはその他のアプローチ——を構築します。

### 2. ネットワーク評価
手法は [eval harness](/docs/network/specifications/harness) を通じてベンチマーク評価されます。すべての提出物は特定の Git コミットとデータセットバージョンにフィンガープリントされます。スコアは再現可能です。

### 3. コミュニティレビュー
結果はコミュニティの言語ワーカーによってレビューされます。リーダーボードの高スコアは手法が*機能する*ことを証明しますが、それが*適切である*ことを証明するものではありません。バイリンガルの話者が出力のサンプルを検証し、コミュニティのレビュアーはいかなる理由によっても手法を却下できます。

### 4. 所有権の移転
手法が賞の基準（自動評価指標**および**人間による検証）を満たした場合、開発者はその手法——ソースコード、学習済みウェイト、設定、コーチングデータ——をコミュニティのガバナンス組織（部族評議会、言語機関、またはコミュニティが選んだ類似の機関であり、Champollion が選ぶものではありません）に移転します。コミュニティはその成果物を完全に所有します。開発者や Champollion からの継続的な権利主張なしに、検査、修正、デプロイ、保留、またはライセンス供与を行うことができます。

開発者が所有していないサードパーティのコンポーネント（オープンウェイトのベースモデル、AGPL の FST など）は所有権を移転できません——それらはコミュニティに対して独自のオープンライセンスのもとで引き渡されます。これが、賞への参加資格として、すべての依存関係がコミュニティが実際に受け取れる権利を持つことを要求する理由です。
[Method Interface 仕様](/docs/network/specifications/methods#method-validity-and-dependency-classes)の依存関係クラスを参照してください。

開発者は、研究者として保持すべきものを保持します。アプローチと結果を制限なく公開する権利、自身の技術をどこでも再利用する権利、そして手法の作成者としての永続的なクレジットです。

### 5. デプロイ——コミュニティが選択する場合とその方法
コミュニティは、手法をデプロイするかどうか、誰が行うか、どのような条件のもとで行うかを決定します。独立したデプロイは完全にコミュニティの事柄です。**Champollion は、コミュニティが所有する資産から得た収益のいかなる分配も受け取らず**、独自のデプロイ権も保持しません。

:::note[ステータス: テンプレートであり、実績ではありません]
現時点では賞の募集も譲渡も行われておらず、リーダーボードに公開済みの実績はありません。このテンプレートは、誰かが労力を投じる前に意図する条件を透明にするため、また、コミュニティの統治機関が白紙の状態ではなく具体的な草案に対して意見を述べられるようにするために文書化されています。これを法的拘束力のあるものにするには、当事者のために専門家の助言を得て作成された署名済みの文書が必要です。
:::

## 研究者の方へ

先住民言語の手法を開発している場合：

1. 開始前に言語コミュニティとの**関係を構築する**
2. 開発には**オープンライセンスのデータを使用する**（コミュニティが制限しているリソースは使用しない）
3. [ランカード](/docs/network/specifications/run-card)に**出典を記録する**——すべてのリソース、そのライセンス、および出所
4. **構築前に賞の規約を読む**——規約に移転が含まれる場合、あなたの貢献はアーキテクチャと技術（公開・再利用はあなたの権利）であり、コミュニティの貢献はその言語で機能させる言語知識です
