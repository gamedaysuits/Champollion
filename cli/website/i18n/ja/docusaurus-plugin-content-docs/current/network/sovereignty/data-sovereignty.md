# データ管理

> **エグゼクティブサマリー。** Champollionは機械翻訳の研究開発ツールであり、ソースコードが利用可能で非営利目的であれば無料、その評価ハーネス（evaluation harness）はオープンソースです。このページでは、言語データに関する姿勢の全容を記載しています。コーパスはそれが由来する人々に帰属し、すべてのライセンスおよびコミュニティ規約は口約束ではなく機械的に尊重され、本プラットフォームが誰かの言語に対して独自の条件を課すことはありません。

:::info[言語データはバイオデータである]
言語データは**バイオデータ**です。遺伝情報や健康データと同様に、言語はそれを話す人々のアイデンティティ、親族関係、そして人と人とのつながりを担っています。また、ゲノムと同じように、言語データを真の意味で匿名化することはできません。名前を取り除いても、その言語にはその民族が誰であるかが刻み込まれているからです。したがって、コーパスを提供する人々はそのデータの、そしてそのデータをもとに測定されるあらゆるものの、管理権を持っています。以下に述べるすべての内容は、この前提に基づいています。
:::

その前提から、設計が導かれます。Champollion はすべてのコーパス貢献者を**スチュワード**として扱います。コーパスは法的にも、物理的にも、実際的にも貢献者のものであり続け、インフラはそれを*測定可能*にします。

## コミットメント

1. **データを保持しません。** コーパスはハッシュで固定されたメタデータカードとして登録され、評価時にスチュワード自身のホスティングから取得されます。このリポジトリにコピーされることも、私たちのインフラから提供されることもありません。アーカイブをオフラインにすれば、それに対する評価は単純に停止します。[コーパスの登録](/docs/network/sovereignty/registering-corpora)を参照してください。

2. **すべてのライセンスは口約束ではなく、ゲートによって尊重されます。** 非営利および研究専用のコーパスは、ライセンスで許可されていないあらゆる利用から機械的に除外されます。ライセンスを超えてコミュニティによって主張された制限事項は、その情報源とともに記録され、同様に遵守されます。この強制力は、行動規範ではなく、プッシュ前にローカルで実行されるプッシュ前ゲート（CIは現在無効化されています）およびデータベーストリガーに組み込まれています。

3. **条件はスチュワードのものであり、それぞれ異なります。** 言語によって合意内容は異なります。パブリックな CC0 コーパス、研究専用のコミュニティコーパス、主権的なデプロイ要件を持つ非公開テストセットのいずれも、それぞれの条件で参加できます。ここには普遍的な契約も、いかなるものに対するデフォルトの権利主張もありません。[条件フレームワーク](/docs/network/sovereignty/ownership-transfer)を参照してください。

4. **秘密コーパスは例外ではなくアーキテクチャとしてサポートされています。** コミュニティはテストセットを非公開のまま保持し、自身のインフラ上に保管し、Champollion や開発者に公開することなく、それに対してメソッドをスコアリングすることができます。抽出不可能性を保ちながら測定可能にすることは、回避策ではなく設計目標です。

5. **帰属とクレジットはデータとともに継承されます。** コーパスが表示されるすべての面において、構築者と言語学者のクレジット表記が義務付けられています。コミュニティが[Local Contexts](https://localcontexts.org/)のTKまたはBCラベルを適用している場合、私たちはそれらを表示し、それらが規定するプロトコルを尊重することを意図しています（ラベルのサポートはまだ実装されていません）。私たちはラベルを引き継ぎますが、自ら新たにラベルを発行することはありません。

6. **貢献者には対価が支払われます。** コーパスの構築と検証は専門的な仕事であり、資金が確保され次第（現在は資金を保有していません）、公開された料金で支払われます — [話者への支払いについて](/docs/network/perspectives/how-speakers-get-paid)を参照してください。支払いはコーパスの買い取りではありません。構築者は対価を受け取り、*かつ* 管理者（スチュワード）であり続けます。

## ライセンスが強制機構となる仕組み

コミットメント2は具体的な形を持っており、その詳細をすべて説明する価値があります。これは「すべてのライセンスが尊重される」ことが善意の要約などではなく、実際にどのように運用されるかを示すものです。

**すべてのベンチマークは保留（held）状態で登録されます。** 新たにカタログ化されたテストセットは、デフォルトで隔離されます。インデックスには表示されますが、評価キュー、コンテスト、すべてのランキングからは除外されます。取り込み時点では、コーパスに関して何の前提も置きません。一見パーミッシブ（寛容）に見えるライセンスであっても、固定されたアップストリームリビジョンの実際のライセンス本文に照らして規約が審査されるまでは同様です。

**審査の判定は機械的であり、判断が難しいケースは保留のままとなります。** 明確に記載されたパーミッシブライセンスは、すべてのレーンに対してコーパスを承認します。明確に記載された非営利ライセンスは、商用、賞金、APIのすべての面から除外された研究用レーンへと承認します。そして、未記載、改変、混合、または独自のライセンスである場合、**権利者に代わって都合よく解釈されることは決してありません**。権利者が規約を明記するか許諾を記録するまで、コーパスはカタログ化されたまま保留され、キュー、コンテスト、ランキングから外されます。判定結果、その日付、レーン、およびその根拠は、コーパスカードとレジストリエントリに機械可読な形式で記録されるため、「なぜこれが実行可能なのか？」にも「なぜ実行不可能なのか？」にも、常に引用可能な答えが存在します。

**モデルへのテキスト送信は「伝送」であり、ゲートが設けられています。** モデルを評価することはソースの文を送信することを意味します。これはコーパスが本来の場所を離れることを意味し、ライセンスごとに管理されます。パーミッシブライセンスのコーパスは標準チャネルを使用できます。明記された非営利ライセンス下のコーパスは、契約上入力データを学習に使用しないチャネルのみを介して送信されます。これはまさにその通りの文言、つまり「非保持」の保証ではなく「非学習」の保証として明記されているチャネルです。未記載または改変された許諾下のコーパスは、同意が記録されるまでリモート評価が完全に拒否され、封印されたコミュニティセットが管理者のインフラから外部に出ることは決してありません。ゲートが拒否した場合、その拒否メッセージにはライセンス審査の判定が引用されます。

**強制機構はすべてのクライアントの下位に位置しています。** 保留はどのクライアントもバイパスできないデータベーストリガーによって強制され、ホスティング禁止ルールは、追跡・プッシュされるすべてのパスでコーパスコンテンツをスキャンするプッシュ前ゲート（プッシュ前にローカルで実行。CIは現在無効化されています）によって強制され、伝送ゲートは評価ハーネス自体の内部で動作します。これらはいずれも私たちに対して拒絶することができ、それこそが重要な点です。

## これが該当しないもの

Champollion はデータブローカーでも、翻訳ベンダーでも、商業プラットフォームでもありません。研究ツールです。リーダーボードの高スコアはメソッドが技術的に機能することを証明しますが、翻訳を公開したり、コーパスを再配布したり、コミュニティの意向に反して何かをデプロイしたりするライセンスではありません。それらの決定は常にスチュワードに帰属します。

## この設計を形成したフレームワーク

このアプローチはここで考案されたものではありません。過去20年間の先住民データガバナンスの取り組みに基づき、その恩恵を受けています。

- **ファースト・ネーションズのデータ主権原則** — カナダのファースト・ネーションズ（First Nations）は、自らの情報に対するコミュニティの所有権、統制、アクセス、保有を明確に表明しています。ここでのスチュワードシップ（管理責任）モデルは、それらの主張と適合するように設計されています。
- **[CARE原則](https://www.gida-global.org/care)**（集団的利益、管理権限、責任、倫理）— グローバル先住民族データアライアンス（Global Indigenous Data Alliance）。
- **[Te Mana Raraunga](https://www.temanararaunga.maori.nz/)** — マオリ・データ主権ネットワーク（Māori Data Sovereignty Network）。
- **[Kaitiakitanga License](https://tehiku.nz/)** — Te Hiku Mediaによるマオリ語（te reo Māori）データのためのガーディアンシップ（後見）に基づくライセンス。ここで採用されている「管理者が鍵を保持する（steward-holds-the-keys）」保管モデルに直接的な影響を与えています。

自分たちの言語データのガバナンスを設計する方には、それらの情報源を直接参照することをお勧めします。権威はそちらにあり、私たちにはありません。コミュニティがこれらのフレームワークのいずれかをコーパスに採用した場合、コーパスカードにその主張が記録され、ツールがそれを遵守します。

Champollionは、Local Contextsの**「協働への開放（Open to Collaborate）」通知**およびラベルを採用することを意図していますが、いずれもまだ実装されていません。実装されたあかつきには、コミュニティ自身が作成したラベルが、コミュニティのデータに関して私たちが述べるいかなる事項にも優先します。
