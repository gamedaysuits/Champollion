# Sovereign Eval Node — ハードウェアとエアギャップ運用

Sovereign Eval Node（ソブリン評価ノード）は、**あなた**が管理するマシンであり、機密のテストセットを保持し、それに対して翻訳メソッドを評価します。メソッドがデータの場所に移動し、データ自体は決して移動しません。スコア、そしてスコアのみが出力されます。

このページは実践的な仕様書です。購入（または再利用）すべきハードウェア、そのセットアップ方法、そして「テストセットがマシンから決して離れていない」ということを、単なる信頼に基づく約束ではなく、証明可能な事実にするための運用規律について説明します。

:::info[現在提供されている機能と開発中としてラベル付けされている機能]
オーガナイザーノードソフトウェア（コンテストの準備、仮説の取り込み、しきい値制御によるスコアリング、ネットワークから隔離されたメソッド実行環境と import scan) **ships today** in `mt-eval` — see the [ソブリンコンテストガイド](/docs/network/sovereignty/run-a-sovereign-contest)）。**§4のしきい値キーセレモニーと保存時封印（sealed-at-rest）ワークフローも現在提供されています**：`mt-eval node ceremony init|share|verify|restore`、`mt-eval node seal`、実行時に提示されるクォーラムシェア（`node run-method --offline --share …`）、ハッシュチェーン化されたローカル承認台帳（`node ledger verify|head`）、署名付きスコアマニフェスト（`node sign-manifest` / `node verify-manifest`）、および§2〜§3のエアギャップツール（`node bundle`、`node manifest`、`node egress-check`）。単一キーペアの代用は、オーガナイザーが参照データを完全に保持しているコンテストにのみ残されています。すべての画面でどのレーンが使用されているかが明記されます。明確に言うと、v1に**含まれない**ものは以下の通りです。ハードウェアリモート構成証明（TEE）はサポートされておらず（§5）、プラットフォーム側のしきい値*署名*（ホストされたインフラストラクチャに対する管理者の電話承認）は将来の課題です。ソブリンノードでは、マシンでN個中M個のシェアを物理的に提示することによって管理が行われます（§4）。また、暗号化について正確に言えば、これはシャミアの秘密分散法（M-of-N）であり、**承認された実行中にノードのロックされたメモリ内でキーが再構築され**（その後ゼロクリアされます）、マルチパーティ計算では*ありません*。キーはオフラインマシン上で一時的に組み立てられた状態で存在します。最後に、コミュニティの同意ゲートが開くまで、このレーンは**合成データのみ**に対して実行されます。実際のコーパスは、その同意を待つことになります。
:::

## 1. リファレンスハードウェア

エグゼキューターは、ローカルNMTデコード、FST/形態素解析の検証、メトリクス計算など、自己完結型のメソッドを実行します。エアギャップ内ではクラウド呼び出しは一切発生しません（LLM-APIメソッドは、まさにエアギャップノードが拒否するクラスです。[ベンチマーク仕様](/docs/network/specifications/benchmark)のメソッドクラスを参照してください）。

| 階層 | 仕様 | 適合 | 概算費用 (2026年) |
|---|---|---|---|
| **最小** (動作可能) | 4コア x86_64 または Apple/ARM、16 GB RAM、500 GB SSD | メトリクス + FST評価、小規模NMTモデルのCPUデコード (低速だが正確) | US$0 (予備のノートPC) – $400 (中古) |
| **推奨** | 8コア、32 GB RAM、1 TB NVMe、NVIDIA GPU ≥ 12 GB VRAM (例: RTX 4070クラス) | 完全なテストバッテリーの快適なNMTデコード、並列メソッド評価 | 約US$900–1,600 (小型ワークステーション) |
| **機関向け** | 16コア、64–128 GB RAM、2 TB NVMe、24 GB+ VRAM | 多数のメソッドのコンテスト、大規模バッテリー、アーカイブされた暗号文ストア | 約US$2,500–4,000 |

すべての階層における必須要件：

- **無線通信機能がないこと、またはオフになっていることを証明できること。** 最適：Wi-Fi/Bluetoothカードが搭載されていないデスクトップPC。許容範囲：ワイヤレスカードが物理的に取り外されている、またはファームウェアで無効化されているノートPC。「機内モード」はエアギャップではありません。
- **ケーブルを抜いたままにできる有線NIC。** ケーブルがないことは、最も監査しやすいネットワーク制御です。
- **2つの専用USBドライブ**（INおよびOUTのラベル付き — §3を参照）。理想的には、ファームウェアで他のポートを無効化したマシン。
- **フルディスク暗号化**（Linuxの場合はLUKS）。これにより、盗難されたノードはただの文鎮になります。また、電源が不安定な場合はUPS（無停電電源装置）を使用してください。バッテリーの途中で中断された評価は回復可能ですが、わざわざ試す必要はありません。

## 2. ソフトウェアのセットアップ（1回のみ、約1時間）

1. **ネットワークケーブルを抜いた状態で**、USBインストーラーから最新のLinux LTS（Ubuntu/Debian）をインストールします。インストール時にフルディスク暗号化を有効にしてください。
2. 別のオンラインマシンで、オフラインバンドルをビルドします。`mt-eval node bundle --out <dir>` は `mt-eval[node]` とその依存関係をwheel化し、`--include` アーティファクトをコピーして、すべてのファイルに対するsha256マニフェストを書き込みます。ノードが必要とするすべてのものは、INドライブ経由で一度だけ渡されます。
3. INドライブでバンドルを転送します。インストールする前に、**ノード上で**マニフェストと照らし合わせてすべてのアーティファクトのsha256を検証します（`mt-eval node bundle --verify <dir>`）。
4. ノードの署名キーペアを作成し（`mt-eval node keygen`）、その公開鍵を記録します。誰もがスコアマニフェストを検証できるように、これを公開します（§5）。
5. それ以降、マシンがネットワークに接続されることはありません。これを最初に証明するために、封印された実行を行うことができます。`mt-eval node egress-check`（ノード設定の `assert_airgap` でも自動的に強制されます）は、ルート、プローブ、またはDNSが外部への経路を示した場合に拒否します。OSのアップデートは、意図的かつバンドル化され、ハッシュ検証されたイベントであり、バックグラウンドサービスではありません。

## 3. 転送の規律（各コンテスト、双方向）

エアギャップは製品ではなく、*手順*です。その手順は以下の通りです：

- **INドライブ**が運ぶもの：提出されたメソッドパッケージ、仮説ファイル、およびそれらのマニフェスト。何かが実行される前に、ノードはマニフェストと照らし合わせて各パッケージのハッシュを検証し、インポートスキャンが実行されます（ネットワークライブラリをインポートするメソッドは拒否されます。これは現在提供されています）。
- **OUTドライブ**が運ぶもの：署名付きスコアマニフェスト（集計スコア、それらが属するメソッド/設定のハッシュ、監査ログのヘッド）のみであり、*それ以外は何も運びません*。セグメントごとの出力は、オーガナイザーの管理下でノード上に保持されます。それらを公開するかどうかは、コミュニティによる意図的かつ独立した決定事項です。
- 常に1つのドライブにつき1つの方向のみです。ノードに接続したドライブは、オンラインマシンで自動マウントしてはいけません。`noexec,nodev` でマウントし、手動でマニフェストをコピーしてください。
- `mt-eval node manifest write <drive> --direction in|out` は、移動前にドライブ上のすべてのファイルをハッシュ化します。受信側の `mt-eval node manifest verify` は、追加、変更、または欠落しているものをすべて拒否します。
- すべての移動（日付、ドライブ、マニフェストのハッシュ）をノードの紙のログまたはノード上のログに記録します。退屈であることが重要です。ログは、「他に何かが持ち出されたか？」という問いに証拠をもって答えるためのものです。

## 4. キーの管理（M-of-N、コミュニティ保持）

封印されたテストセットは保存時に暗号化されます。復号化には、長老会議、言語機関、教育機関など、**コミュニティが選出した**管理者（カストディアン）が保持するキーシェアのクォーラム（定足数）が必要です。プラットフォームはシェアを一切保持しません。Champollionは封印されたセットを復号化できず、単独の管理者も復号化できません。

セレモニー（1回のオフラインセッション。提供されているツールで自動化されます）：`mt-eval node ceremony init` はノード上でセットキーを生成し、それをN個のシェアに分割し（任意のM個で再構築可能。それ未満では何も明らかになりません。この分散は情報理論的なものです）、同時にキーをゼロクリアします。`ceremony share` は、各管理者のシェアをトークン用のファイルと印刷可能な紙のバックアップとして出力します。`ceremony verify` は、配布されたコピーが再構築可能であることを証明します（何も永続化しません）。`ceremony share --wipe-originals` then destroys the node's own copies. `mt-eval node seal` は、コーパスをセレモニーの公開鍵で暗号化します。ノードは暗号文とコンテンツを含まないメタデータカードのみを保存し、それ以外は何も保存しません。それ以降、評価を実行するには、管理者がN個中M個のシェアを物理的に提示する必要があります（`node run-method --offline --share …`）。キーは**エグゼキューターのロックされたメモリ内でのみ**再構築され、その1回の許可された実行に使用された後、ゼロクリアされます。二度とディスクに触れることはありません。すべてのリクエスト、投票、許可、および使用は、ハッシュチェーン化されたローカル台帳（`node ledger verify`）に追記され、クォーラムなしでの試行は拒否され、*かつ*記録されます。

このメカニズムについて正直に一言で言えば、これはコミュニティが保持するオフラインマシンのメモリ内での再構築を伴うシャミアの秘密分散法であり、マルチパーティ計算ではありません。承認された実行中、キーはコミュニティが物理的に管理するハードウェア上で一時的に組み立てられた状態で存在します。これが守る特性は、*ディスク上に常駐するキーがないこと*、*クォーラムが存在しない状態での実行がないこと*、そして*すべての使用が検査可能な台帳にチェーンされること*です。キーがどこにも組み立てられないプラットフォーム側のしきい値署名は、将来の課題として残されており、言及される箇所にはそのように明記されています。

ローテーションや管理者の交代を行う場合は、セレモニーを再実行します。N−M個を超えるシェアが失われた場合は、コミュニティのソースコピーからセットが再封印されることを意味します。コミュニティは常に独自のプレーンテキストのオリジナルを保持します。なぜなら、[所有権](/docs/network/sovereignty/data-sovereignty)は決して私たちが保持するものではないからです。

## 5. ここでの「構成証明（attested）」が意味するもの — そして意味しないもの

すべての評価は、**署名付きスコアマニフェスト**を生成します。これには、スコア、メソッドパッケージのハッシュ、コーパスのチェックサム、および追記専用の監査ログのヘッドに対するノードの署名が含まれます。ノードの公開鍵を保持している人なら誰でも、`mt-eval node verify-manifest <manifest> --pubkey <published .pub.json>` を使用して、*このノード*が*これらの正確な入力*に対して*これらのスコア*を生成したことを検証できます。また、ハッシュチェーン化されたログにより、履歴の密かな改ざんを検出できます。

これが**ソフトウェア構成証明**です。これは記録の整合性を証明するものであり、v1が提供するものです。どのシリコンが実行を行ったかを証明するものでは**ありません**。ハードウェアリモート構成証明（TEE）は将来の課題であり、意図的に要件から外されています。v1の正直なセキュリティステートメントは次の通りです。オーガナイザーの規律（§3）、署名付きマニフェスト、およびコミュニティによるマシンの物理的な管理がトラストアンカー（信頼の基点）となります。これはまさに、主権を第一に考える設計において、信頼を置くべき場所そのものです。

## 6. 運用ループ

1. コンテストを発表します。ノードの公開鍵と開発セットのしきい値を公開します。
2. オンライン（通常のマシン）で提出物を受け取り、INマニフェストを組み立てます（`mt-eval node manifest write <drive> --direction in`）。
3. INドライブをノードに運び、ハッシュを検証します（`node manifest verify`）。
   import-scan (`node import-bundle`); queue methods.
4. 管理者はクォーラムのシェアを提示して実行を承認します（§4 — `node run-method <id> --offline --share … --share …`）。封印されたセットはエグゼキューター内でのみ復号化されます。クォーラムがなければ実行されず、その試行は台帳に記録されます。
5. 実行します。スコアが計算され、セグメントごとの出力はノード側に保持されます。
6. ティアダウン（終了処理）：作業用のプレーンテキストが消去され、監査ログが追記され、マニフェストに署名されます。
7. OUTドライブを持ち帰ります。スコアとマニフェストを公開し、誰でも検証できるようにします（`node verify-manifest`）。
8. 移動を記録します。ドライブは専用のままにし、ノードはオフライン（ダーク）のままにします。
