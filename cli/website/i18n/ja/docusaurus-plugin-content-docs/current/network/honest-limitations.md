# 技術的制限

> **初めての方へ** [現時点でできないこと](/docs/what-it-cant-do-yet) では、同じ内容を平易な言葉で説明しています。このページは、開発者、研究者、およびエージェント向けの詳細で厳密なバージョンです。

これらは、私たちが**決して**超えない主張・保証の範囲です。このサイトの他の場所でここに書かれている以上のことを示唆する記述があれば、バグとして扱い、[お知らせください](/docs/network/perspectives/reporting-errors-and-owning-corrections)。

評価インフラは、その限界について正直であることによってのみ信頼を得られます。以下に、確認できる形で率直に述べます。

## 1. 詳細な形態素検証にはFST*および*ランキング可能なテストセットの両方が必要

FSTベースの形態素検証（出力されるすべての単語が対象言語において適格な語形であるかの確認）を言語ペアに対して行うには、ハーネスが固定（pin）したFSTと、そのペアに対応するランキング可能な評価セットの2点が必要です。`GiellaLTFSTMetric`自体は**汎用的**であり、固定されたGiellaLT FSTを持つあらゆる言語（平原クリー語、サーミ諸語、フィンランド語、ノルウェー語ブークモール、イヌクティトゥット語など）をスコア付けします。これらの言語のいくつかにはオープンな評価セット（Tatoeba、WMT、WMT24++など）が存在します。[データセットページ](/docs/network/leaderboard/datasets)にはカタログが一覧表示されており、`mt-eval corpora --source eng --target <code>`には特定のペアで実行可能なものが、`mt-eval corpora --with-fst`にはターゲットに固定FSTを持つペアのみが、マシンにインストールされているかどうかの情報とともに一覧表示されます。FSTの取り組みが始まった言語である平原クリー語は例外であり、その2つの評価セット（EdTeKLA）は隔離ラベルとしてカタログ化されており、データベースはそれらに対して投稿されたいかなるスコアも拒否します。

さらに2つの制限が適用されます。固定されたFSTがスペルチェック用の**アクセプター**（Northern Sámi、アムハラ語、バスク語など）にすぎない場合、単語が存在するかどうかは判定できますが、正しく活用されているかは判定できないため、`morphological_accuracy`は計算されません。また、アクセプターは一部の英語や語頭が大文字の単語を受容するため、FST受容率は未翻訳の出力を評価（加点）してしまう可能性があります（この場合、実行カードにソースコピーの注意事項が表示されます。[スコアの注意事項](/docs/network/specifications/scoring#2-8-score-caveats)を参照してください）。FST受容率は診断用の指標であり、chrF++の見出しスコアに含まれたり実行の順位付けに使用されたりすることはありません。
また、すべての入力に対して1つの有効な文を繰り返すような出力にも加点してしまうため、その場合は実行カードにほぼ一定の出力（near-constant-output）に関する注意事項が表示されます。
そして、FSTのないすべてのペアは、表層的なメトリクス（chrF++、BLEU）および振る舞いチェックによってスコア付けされます。これらは有用なシグナルですが、形態素の妥当性を保証するものでは**ありません**。FSTとランキング可能な評価セットの双方が揃っていない言語について、形態素の妥当性が検証されていると主張することはありません。

## 2. 信頼性ティア：現状ではすべての行が自己申告です {#2-trust-tiers-are-self-reported-at-launch}

大半のスコアは、コントリビューター自身がハーネスを実行してその結果を公開することで算出されています。**検証（Verification）**——提出物の出力から、SHA固定された正規コーパスに対して再スコアリングを行う機能——は構築されていますが、メンテナーが手動で実行するコマンドです。提出時に自動実行されることも、スケジュール実行されることもないため、現状ではすべての行が自己ベンチマークされた状態で届き、その状態のままとなります（[提出ルール](/docs/network/leaderboard/rules#verification-tiers)）。各行の信頼性バッジをご確認ください。**「自己申告（self-reported）」はその言葉通りの意味**であり、これがデフォルトです。

## 3. コミュニティ話者による検証はまだ実施されていない

提案されている賞の要件には、**バイリンガル話者による承認率 ≥ 70%** が含まれています（現在、賞は公募されていません）。その判定ゲートは仕様化されており、それを実行するためのツールは構築中ですが、**コミュニティの話者によるレビューはまだ実施されておらず**、**このサイト上のスコアで話者ゲートをクリアしたものは存在しません**。chrF++ などのあらゆる自動評価指標の数値は機械的なシグナルにすぎず、コミュニティによる判定ではないため、ここに掲載されているどのスコアにも品質ラベルは付与されていません。

## 4. 評価サンドボックスとキーセレモニーは存在するが、保管担当者による使用実績はない

私たちはソースからコーパスを取得してSHA固定し、ホールドアウト分割は封印（シール）されます。コミュニティが非公開のテストセットを保持している場合、そのセットがコミュニティの手を離れることなく、手法をそのテストセットに対して評価できます。そして、その評価には現在**2つのレーン**があります。標準的なニューラルモデル向けの推奨レーンは**宣言型（declarative）**です。参加者はデータのみ（safetensorsの重み＋宣言型トークナイザー＋設定）を提出し、主催者は信頼できる独自の推論エンジン（`trust_remote_code=False`、オフライン。安全性はアーキテクチャ名ではなくコードフリーなフォーマットにあるため、アーキテクチャに関しては寛容です）でそれを実行します。参加者のコードは一切実行されないため、サンドボックス化する必要はありません。安全性の確認は決定可能なフォーマット検証（pickleではなくsafetensorsか？`trust_remote_code` は含まれていないか？）であり、任意のコードが安全であることを証明しようとするものではありません。真にコードである手法（パイプライン、LLM指導型のハイブリッドなど）向けのフォールバックは、ネットワークから隔離された**サンドボックス**（静的チェック、`--network=none` コンテナ、スコアのみの送信、オプションの完全なエアギャップによるファイル転送）です。サンドボックスにはネットワークがないため、手法がそこで実行されるには、呼び出すモデルがすべてバンドル内に含まれている必要があります。ホストされたLLM APIにはアクセスできないため、LLM指導型のハイブリッドはLLMをオープンウェイトとして同梱しなければなりません。サンドボックスは、信頼できないコードの実行を拒否するのではなく隔離して実行するため、率直に言えば強度の劣るレーンです。その最も重要な安全性の拠り所は `--network=none` であり（ヒューリスティックな静的スキャンではバイナリモデルを検証できません）、さらなる堅牢化（seccomp、microVM）は先送りにされています。何が実際に稼働しており何が稼働していないかの詳細については、[主権的コンテストの実施](/docs/network/sovereignty/run-a-sovereign-contest) を参照してください。オフラインノードの**キーセレモニーは構築されています**——セットの鍵はM-of-Nに分割され、クォーラムによって承認された実行中にのみメモリ上で再構築されます——が、実際の保管者とともに使用されたことは一度もなく、この最初のバージョンではシェア（分割鍵）はプレーンファイルです。構築されて**いない**もの：閾値署名（スコアは単一のノードキーで署名されます）およびハードウェア認証（スコアのマニフェストはソフトウェアでのみ署名されます）。コミュニティの鍵保管者は任命されていないため、保管者とコミュニティの合意が整うまで、ゴールドスタンダードの**賞（prize）**評価は非公開のままとなります。

## 5. 鍵は現状主催者が保持しており、コミュニティの保管者は任命されていません {#5-key-custody-is-designed-no-custodians-are-appointed-yet}

**現在、封印されたセットの鍵はその主催者**（それを封印した人物が自身のマシン上）**によって保持されています**。**Champollion は鍵のシェアを保持していません。** 複数の保持者のための保管*メカニズム*は構築されています。オフラインノードのM-of-Nキーセレモニーにより、セットの鍵が保管者間で分割されます。これは実際の保管者と共にはまだ実行されていません。保管者はコミュニティ自身によって選ばれますが、まだ誰も任命されていません：**コミュニティの鍵保管者——まだ誰も任命されていません。** 保管（カストディ）は同意（コンセント）ではありません。関係性に基づくコミュニティの同意プロセスは、それ自体が独立した、より時間を要する、そしてより重要な道筋です。

## 6. ベンチマーク上で手法を測定しており、個々の翻訳をスコア付けするわけではない {#system-vs-output}

「信頼できる機械翻訳」と呼ばれるものには2つの異なる側面があります。当プロジェクトが行っているのは、そのうちの1つです。

**システムレベル — 私たちが行うこと。** 言語ペア、テストセット、手法が与えられたとき、その手法はどのメトリクスで、どのドメインで、どのデータ汚染レーンで、どの信頼性ティアにおいてどのようなスコアを獲得するか？これは*ベンチマーク上の手法*に関する主張であり、基準を設定したのが誰であるかに関する主張でもあります。スコアリングルールは公開され、コーパスは固定されており、主権的ベンチマークにおいてはテストセットを所有するコミュニティが合格基準を決定します。リーダーボード、マップ、実行カード、そして`mt-eval`はすべてこれに該当し、これ以外の何物でもありません。

**出力レベル — 私たちが行わないこと。** 1つの原文とそれに対する1つの翻訳文が与えられたとき、*その*翻訳が正しい確率はどれくらいか？機械翻訳（MT）や自然言語処理（NLP）において、これは品質推定（QE）および不確実性の定量化と呼ばれ、それ自体が独立した研究分野です。私たちは**いかなる翻訳に対してもセグメントごとの信頼度を公開しておらず**、ここに記載されている数値はどれも特定の出力が正しいという較正された確率ではありません。ハイスコアを記録した行であっても、その手法が次に出力する文に対する保証にはなりません。

その逆はさらに陥りやすい間違いであり、私たち自身もこれに縛られます。[人手による翻訳サービス](/human-services)で記載されているように、あるペアにおいて本サイト上で本番展開に足る十分なスコアを獲得した手法が存在しないと示されている場合、それは測定対象のテストセット上で測定された手法についての記述です。これは、その言語ペアにおいて機械翻訳の出力をリリースしない十分な理由となります。ただし、それは特定の文に対する判定ではありません。

**品質推定は空いているスロットであり、隠れた欠落ではありません。** ハーネスは、ゴールドリファレンスのない実行に対する妥当性のシグナルとして、参照不要のニューラルスコアであるAfriCOMET-QE（`qe_score`）をすでに計算しています。これは別個のニューラルレーンにおいて**コーパスレベル**の数値として報告され、検証者によって再導出され、chrF++の見出しスコアには一切反映されません（[スコアリング仕様](/docs/network/specifications/scoring#how-runs-are-scored)を参照）。メトリクスはプラグインであるため（[プラグイン仕様](/docs/reference/plugin-spec)を参照）、セグメントレベルのQEメトリクスはこのハーネスに組み込み可能です。参照ベースのメトリクスと同様に言語ごとに連携、公開、メタ評価されるまでは（[メトリクスの信頼性](/docs/network/specifications/metric-reliability)を参照）、個々の出力について言及することはありません。
