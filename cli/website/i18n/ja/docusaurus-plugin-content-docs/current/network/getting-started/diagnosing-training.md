# トレーニングランの診断

モデルのトレーニングが完了しました。しかし、スコアが期待どおりではありません。このページでは、**現在確認できる現象**を出発点として、考えられる原因とそれを修正するforgeツールについて説明します。これらの多くは自動化されています。`nmt-forge export`（およびスコアのみを扱う`nmt-forge evaluate`）は、検出事項とその対処手段を記載した**Diagnosis & Recommendations**（診断と推奨事項）セクションを追加します。本ガイドはそれを分かりやすい言葉で説明したものであり、forgeが*警告*しか出せないいくつかの項目（⚠ **要注意**と表記）についても解説します。

エージェントに次のように指示してください：*「`nmt-forge lint <battery-manifest.json> --json`を実行し、最も深刻度の高い検出事項に対処してください。」* エクスポート後、バッテリーマニフェストは`export/evaluation/battery-hyps-battery.json`になります。その後、レポートされた内容と以下のセクションを照らし合わせてください。

---

## 「デフォルトモデルのスコアが低い」

デフォルトの`cpu-tiny`プリセットでトレーニングしたところ、テストスコアが5〜30 chrF++の間にとどまっています。

**原因:** これは本プリセットの想定どおりの動作です。独自の対訳ペアのみを使ってスクラッチから学習する小型のTransformerであるため、1,000〜2,000ペア程度では言語全般ではなく、データのフレーズや文型パターンのみを学習します。スコアがその上限に達するのは、データが高度にテンプレート化されている場合だけです。このプリセットの役割は、出荷用の本番モデルになることではなく、一連のループ（隔離された開発セット、監査済みデータ、事前登録されたテストセット、CLIから呼び出せるモデル）を実際に成立させることにあります。

**対処法:** 効果が高い順におおむね並べると、以下のいずれか1つを変更して開発セットで測定します。

1. **実データのペアを増やす。** このデータ規模では、どのような設定よりもデータ量が物を言います。
2. **事前学習済みモデルから開始する。** `nmt-forge init <code> --model cpu-finetune --base
   <hf-id>` は、CPU上で事前学習済みの小型Marian/opus-mtモデルをファインチューニングします。*関連する*言語ペアのモデルを選択し、それが必ず勝つと決めつけずに開発セット上で`cpu-tiny`と比較してください。`--model nllb-600m`は最も強力なスタート地点ですが、GPUが必要です。
3. **既存のデータからデータを増やす** — 単一言語テキストの逆翻訳（Back-translation）、または対象言語のアナライザーが存在する場合は検証済み合成データの生成（[独自のモデルをトレーニングしたい場合](/docs/network/tutorials/train-your-own-model)を参照）。

⚠ **要注意:** `cpu-tiny`による高スコアは、喜ぶ前に疑ってみる必要があります — [「スコアが良すぎるように見える」](#the-score-looks-too-good)を参照してください。

## 「教科書的な例では良好だが、実際の文では精度が落ちる」

**低リソース環境で最もよく見られる落とし穴です。** 合成データ・テンプレートデータのスコアは良好ですが、実際のテキストでは精度が崩れます。

**何が起きているか：** **転移プラトー**です。トレーニング中、実際の開発セットの損失が早い段階で底を打ち、その後上昇に転じた一方で、トレーニング損失は下がり続けました — モデルは翻訳を学習するのではなく、合成データの*量*を習得していたのです。合成データをさらに増やしても**改善にはなりません**。

**forge の診断結果：** `R7-transfer-plateau`（ランマニフェストのスケジュール履歴より）。**対処法：REAL-DATA。**

**修正方法：** 実際のテキストを追加してください。単言語のターゲット言語データを逆翻訳する（`nmt_forge.training.backtranslation`）か、実際の対訳文を収集してください。合成データの量は解決策ではありません — *実際の*データの多様性が鍵です。

⚠ **要注意：** データの混合比率が合成データ約99%で実際の開発セットが少量の場合、スコアに現れる*前*からこのリスクにさらされています。現時点では、問題のある比率を事前に検出するリントツールはありません — ミックスマニフェストのゴールド/合成データの件数を確認してください。

## 「特定のレジスターだけ他より大幅に精度が低い」

レジスター別の表を確認してください。特定のレジスター（例：行政や法律）が他と比べて大きく下回っています。

**原因は2つ考えられます — 診断では*カバレッジ*と出力が*未完成*かどうかを確認することで判別します：**

- **モデルが語彙を持っていない**（`R1-vocabulary-gap`：カバレッジが低く**かつ**未完成率が高い）。**対処法：VOCABULARY。** 語彙を拡充し（辞書・用例収集）、`nmt-forge` のファネル分析で新しいエントリが実際にコーパスに反映されているか確認してください — 1文字の正書法の不一致が、過去に何千もの語を無音で削除した事例があります。
- **モデルは語彙を持っているが文の構造を持っていない**（`R2-structure-gap`：カバレッジは問題なし、それでも未完成）。**対処法：STRUCTURE。** カバレッジマップを文法チェックリストと照合し、不足している構文を追加してください（命令形、wh疑問文、所有格、逆格など — テンプレートで扱われていなかったもの）。

## 「出力が1文の中で表記を混在させている」

モデルが同じ音を2通りの方法で書き、場合によっては1文の中で混在させています。

**何が起きているか：** トレーニングデータが、表記規則は互換性があるとモデルに教えてしまっています — コーパスに同じ内容が複数の正書法で含まれていたのです。

**forge の診断結果：** `R3-mixed-convention`。**対処法：ORTHOGRAPHY。**

**修正方法：** コーパスを`convention-lint`し、データの入力段階で**1つ**の標準的な表記規則に正規化してから再トレーニングしてください。混在表記率をテストスイートに含めておくと、改善の推移を確認できます。

## 「モデルBはモデルAより優れているが、差がわずかしかない」

2つのモデルを比較したところ、一方がわずかな差でリードしています。

**何が起きているか：** その差はノイズの範囲内かもしれません。80文のデータでは、chrF++ の 0.4 ポイント差はコイントスと同じです。

**forge の診断結果：** `R5-low-power`（信頼区間がデルタより広い）。**対処法：MEASUREMENT。**

**修正方法：** 信頼区間より小さい差には基づいて判断しないでください。そのレジスターの評価セットを拡充するか、2つの重複する区間ではなく*対応のある*有意差検定を報告する`nmt-forge compare`を使用してください。forge は生のスコアのみを表示することはありません — 区間は常に表示されており、まさにこのような状況を見極めるためのものです。

⚠ **要注意：** **単一シード**による結果には、シード間の分散バンドがありません。再シードしても再現しない改善は本物ではありません。重要な判断を行う場合は、2〜3つのシードで再実行してください。

## 「スコアが良すぎる」

特に初期段階やデータが少ない場合に、不自然なほど高いスコアが出ています。その直感を信じてください。

**順番に確認してください：**

1. **リーク（Leakage）。** `nmt-forge leak-audit <corpus>` — テスト文がトレーニングデータに混入していませんか？これは、テストプロンプトと同一のプロンプトを持つ行（訳文が異なる場合も含む）、テスト回答と同一の回答を持つ行、およびテスト回答を含んでいる・その断片である・90%以上一致する行を除外します。`nmt-forge run`は登録されたテストセットやシールドセット（封印されたセット）にリークするトレーニング行を拒絶するため、これは主にforge外部のデータやパイプライン、あるいは一度も登録していないテストセットで重要になります。
2. **チェックポイントの選択。** チェックポイントは、テストセットではなく**隔離された開発セット**に基づいて選択されましたか？forgeが開発セットなしでのトレーニングを拒絶するのはまさにこれを防ぐためですが、独自に手組みしたパイプラインではそうはいきません。
3. **ニアツインによる過度な楽観（Optimism from near-twins）。** `R4-optimism-bound`: 「full」のバッテリースコアが「strict」スコアより数ポイント高い場合、そのギャップはドリルの類似文（drill-sibling）による楽観的なバイアスです。`leak-audit`はテンプレートの類似文（トレーニングに*「I see the dog」*があり、テストセットに*「I see the cat」*があるなど）をあえて*保持*し、類似文を持つテスト行を一覧表示します。`eval.near_dupe_corpus`にトレーニングファイルを指定すると（スターター設定ではこれが設定されています）、レポートは類似文を*持たない*テスト行を「(strict)」として個別にスコア付けします。汎化性能を主張する際は、**必ずstrictの数値を引用してください**。もし*すべての*テスト行に類似文が存在し（`R4-recall-not-translation`: strictサブセットが空になり、スコアがトレーニングフレーズの再現度を測定している状態）、かつテストセットが固定されている場合は、`nmt-forge leak-audit <train> --clean-to <train>.notwins.jsonl
   --drop-test-twins` を使って類似文のないコーパスを別のファイルに書き出し、そのデータで2つ目の類似文なしモデルをトレーニングします（leak-auditは最初のモデルが学習したファイルに上書きしません）。あるいは、トレーニングのテンプレートから完全に独立して作成されたテスト文を用意してください。
4. **出力が入力に追従していない。** `R9-harness-score-caveat`: mt-evalレポートはスコアに条件付き（qualified）が付いていることを示しています。最も多いのは**ほぼ一定の出力**です。多くの異なるテスト文に対して、同一の少数の出力しか返されません（ある病院向けモデルでは、150の異なる文に対して9種類の出力しか返しませんでしたが、共通のフレーズが多くの参照訳と多くの文字を共有していたため、chrF++は48を記録しました）。類似文なしモデルで特によく見られます。トレーニングテンプレートが削除されたことで、小型モデルは最も出現頻度の高い文に頼ってしまいます。forgeはテストハーネスの文言のまま警告を伝達します — エクスポートサマリーの`DEPLOY.md`、`status`、`report`、`compare`、および`lint` — そして警告なしにそのようなスコアを「引用すべき数値」と呼ぶことは決してありません。スコアを翻訳品質として報告する前に、出力の一部（テストセットを保持しているマシン上の`<export>/evaluation/battery-hyps.jsonl`）を確認してください。より多くの、変化に富んだ実際の対訳ペアが改善の鍵となります。

## 「トレーニングがほぼ即座に停止した」

数百ステップで実行が終了し、モデルがデータをほとんど学習できていません。

**何が起きているか：** 早期停止が、合成データ比率が高い場合に想定される開発セットの揺らぎを収束と誤認しました。

**forgeの動作:** これはデフォルトで*防止*されています — `nmt-forge run`はデータの組み合わせから早期終了の**下限（floor）**を算出し、それを下回る早期終了を抑制して、その理由を`[schedule-sanity]`行に出力します。開発セットが評価される頻度も実行規模に基づいて導き出されるため、小規模な実行が評価されずに終わることはありません。予期しない停止が発生した場合は、それらの行を確認してください。実行マニフェストには、何がなぜ発生したかが正確に記録されています。（計画された最終ステップに単に達した実行は、早期終了ではなく完了として報告されます。）

## 「実行が開始直後に拒絶された」

**原因:** ゲート（事前チェック）が作動しました — 数時間後に失敗するよりもはるかに低コストです。一般的なものは以下のとおりです。

- **トレーニング用追加パッケージ（extra）が見つからない** — `nmt-forge preflight run --config
  config.json` shows `✗ backend-installed` と表示され、対処法として`python3 -m pip install 'nmt-forge[hf]'`が示されます。
- **開発セットがない、または無効である** — dev-fenceは、`data.dev`がロール`dev`を持つ登録済みセットでない実行を拒絶します。`nmt-forge split … --register project`で切り出してください。
- **リーク（Leakage）** — トレーニングファイルが、登録されたテストセットまたはシールドセットとプロンプトや回答を共有しています。`nmt-forge leak-audit <file> --clean-to
  <file.clean.jsonl>` でクリーンアップし、クリーンアップ後のファイルをconfigで指定してください。
- **実行時間（Wall-clock）** — 最初の数分間で、forgeはトレーニング速度を測定し、`model.time_budget_hours`を超えると予測される実行を拒絶します。CPUの場合、通常はプリセットにGPUが必要である（`nllb-600m`）か、データ構成が意図したよりもはるかに大きいことを意味します。メッセージには対処手段が提示されます。データ構成を小さくする、シーケンス長を短くする、または待機時間を許容できる場合は予算（上限時間）を増やすなどです。

**対処法:** 実行する前に毎回`nmt-forge preflight run --config config.json`を実行してください。すべてのゲートを✓/✗で一覧表示し、各✗に対する修正方法が提示されます。

## 「欲しかったメトリクスがレポートに表示されていない」

レポートは正直ですが、特定の軸（COMET、FST 妥当性チェックなど）が空白になっています。

**forge の診断結果：** `R6-referee-unavailable` — そのレーンが利用不可として理由とともに表示されています。**対処法：REFEREE。**

**対処法:** 指定されたレフェリーをインストールまたは設定し、再スコアリングしてください。言語カードでレフェリーが宣言されている場合、forgeのメッセージにインストールコマンドが表示されます（`mt-eval setup --lang <code>`）。現在出ているスコア自体に偽りはありません — レフェリーが用意されるまで、その特定の評価軸が見えていないだけです。

## 「モデルが `<unk>` や文字化けを出力する」

特に音節文字や拡張ラテン文字のスクリプトで発生します。

**プリセットによって異なります。**

- **`cpu-tiny`** はトレーニング行から独自の語彙を学習するため、トレーニングに出現するすべての文字がカバーされます。ここで`<unk>`が発生する場合、トレーニングに一度も出現しなかった文字（珍しい文字や発音区別符号、あるいは異なるUnicode形式など）が入力に含まれていることを意味します（テキストはNFCに正規化されるため、合成済みアクセントと結合文字アクセントは同じものとして扱われます）。トレーニングデータとテストデータで同じ正書法が使用されているか確認してください。
- **`cpu-finetune`および`nllb-600m`** は、事前学習済みベースモデルのトークナイザーを使用します。

⚠ **要注意 — まだ自動化されていません（事前学習済みベースモデル）。** ベースモデルの**トークナイザーがターゲットの文字体系（文字コード/スクリプト）に対応していない可能性**があります。forgeはまだトレーニング前にトークナイザーのカバレッジを監査しません。ターゲット言語の表記サンプルのトークナイザー適用結果を確認してください。その文字体系を語彙としてカバーしているベースモデルを選択するか（多くの低リソース言語はNLLBファミリーのベースモデルでカバーされています）、トレーニング前にトークナイザーを拡張してください。

## forge が拒否したが理由がわからない場合

拒否メッセージには常に、**何が**起きたか、**なぜ**それが結果を損なうか、そして**修正方法**が記載されています。それでも不明な場合は：

- `nmt-forge status` — 現在位置と、次に実行すべき1つのコマンド。
- `nmt-forge preflight <command>` — そのコマンドが通過するすべてのゲートを✓/✗で表示し、各✗の修正方法を示します。これにより、1つずつではなく一度にすべて解決できます（`run`、`evaluate`および`export`については、`--config config.json`を追加してください）。
- エージェントが結果を読み取る場合は、任意のコマンドに`--json`を追加してください。拒絶された場合、終了コード2とともに単一のJSONオブジェクト（`{"error": {"type", "guard", "message", "why", "fix", …}}`）として返されます。

拒否はセットアップのエラーではありません — 結果に影響が出る前にツールが誤りを検出しているのです。それがこのツールの設計思想です。
