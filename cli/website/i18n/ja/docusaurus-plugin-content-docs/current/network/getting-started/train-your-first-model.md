# 最初のモデルを訓練する（エージェントと一緒に）

ニューラル機械翻訳モデルの訓練方法を知っている必要はありません。必要なのは、**コーディングエージェント（Claude、Sonnet/Flashクラスのモデル、またはシェルコマンドを実行できる任意のエージェント）に何をしたいかを伝える**ことだけです。**nmt-forge** はエージェントが*機械的に*操作できるよう設計されています。各ステップで、ツールはエージェントに次に何をすべきかを正確に伝え、結果を損なうようなステップは——修正方法とともに、はっきりと——拒否します。

このページはループ全体を説明しています。各ステップは、**エージェントへの指示内容**、**forge が行うこと**、**拒否がどのように見えるか**（拒否が発生しても慌てないように——拒否はツールが正しく機能している証拠です）、そして最後に**レポートの読み方**という形式で書かれています。

:::tip エージェントへの唯一のルール
エージェントにこう伝えてください：*「常に最初に `nmt-forge status --json` を実行し、すべてのステップの後にも実行すること。`next_command` の指示に従うこと。」* このひとつの習慣が forge をガイド付きのレールに変えます。エージェントが MCP 経由で接続している場合、同じループが `forge_status` ツールになります——[エージェントガイド](/docs/network/getting-started/agent-guide)を参照してください。
:::

## ステップ 0 — エージェントに対象言語を指定する

**あなたの指示：** *「英語→[対象言語]のモデルを訓練したい。まず forge がその言語について何を知っているか調べてください。ISO 639-3 コードは `crk` です」*（対象言語のコードを使用してください）。

**forge が行うこと：** `nmt-forge discover crk` は言語のカードを読み込みます——スクリプト、辞書、形態素解析器、既存のコーパスと評価セット（`do_not_train` / 隔離フラグを含む）、および言語ごとの審判メトリクスです。対象言語を**アセットラダー**に位置づけます：(1) 対訳テキスト → ガード付き訓練；(2) + 単言語データ → タグ付きバックトランスレーション；(3) + 辞書/文法 → 引用付き合成データ；(4) + 解析器 → ラウンドトリップ検証済み合成；(5) + 審判メトリクス → スコアリングとチェックポイント選択における言語固有メトリクス。

**空白フィールドは UNKNOWN を意味し、ゼロではありません。** カードが疎であることは「この言語にリソースがない」ということではなく、単にそのリソースがまだ記録されていないだけかもしれません。独自の対訳コーパスをいつでも持ち込むことができます。

次に：*「プロジェクトをスキャフォールドしてください。」* → `nmt-forge init crk` がワークスペース、スターター設定、および `NEXT_STEPS` ブリーフを作成します。

## ステップ 1 — 不正のできないスプリットを作成する

**あなたの指示：** *「対訳コーパス `corpus.jsonl` を用意しました。train/dev/test に分割して、dev セットと test セットを登録してください。」*

**forge が行うこと：** `nmt-forge split corpus.jsonl --test 200 --dev 100 --seed 7
--out data/splits --register mypair`。**グループ非交叉**スプリットを作成します：ソースまたはターゲットを共有する任意の文ペアは**同じ**サイドに配置されます。これは低リソーススコアが水増しされる最も一般的な方法です——教科書が多くの英語ドリルをひとつのターゲット単語にマッピングし、単純なランダムスプリットが一方のコピーを train に、その双子を test に配置すると、モデルは記憶した答えを「翻訳」してしまいます。

**拒否がどのように見えるか：** 自分で作成したスプリットを forge に渡し、それが非交叉でない場合、`verify-split` は共有キーを明示してクラッシュします——*「これらの行は train と test 間で正規化されたターゲットを共有しています。」* 修正方法：forge にスプリットを行わせてください。

---

## ステップ 2 — リーケージをスクリーニングする

**あなたの指示：** *「訓練前に、評価セットに対して訓練コーパスのリーケージを確認してください。」*

**forge が行うこと：** `nmt-forge leak-audit corpus.jsonl`。登録されているすべての dev/test/シールドセットに対してコーパスをスクリーニングします：

- **ターゲット側の完全一致または近似重複**（参照回答が訓練データに含まれている）→ **致命的**。これは回答リーケージです。
- **ターゲットが*異なる*ソース側の近似重複** → **情報提供のみ、保持**。同じプロンプトで異なる翻訳は正当な最小対比ペアであり、リークではありません——forge はこれを報告しますが、削除しません。（この区別は実際のバグで、ドッグフーディングで発見しました：以前のバージョンは 44 行を致命的としてフラグしましたが、本物のリークは 17 行だけでした。）

**拒否がどのように見えるか：** *「行 118：test セット `mypair-test` のターゲット側近似重複（Jaccard 0.83）——回答リーケージ。」* 修正方法：エージェントが `nmt-forge leak-audit corpus.jsonl --clean-to corpus.clean.jsonl` を実行し、残ったデータで訓練します。

## ステップ 3 — 確認前に予測を記録する

**あなたの指示：** *「モデルに何を期待するかを書き留めてから、訓練を始めましょう。」*

**forge が行うこと：** `nmt-forge prereg new p1 --eval-set mypair-test --predictions
predictions.md`。あなた（またはエージェントが声に出して）は、テストスコアが存在する**前に**、反証可能な予測——どのメトリクスで、どの方向に、どの程度——をコミットします。

**拒否がどのように見えるか：** エージェントが事前登録なしに test セットをスコアリングしようとすると、`score` は拒否します：*「最初のスコアリング読み取りより前の事前登録なしに test セットをスコアリングすることは拒否されます。」* これが結果と結果先行のストーリーテリングを区別するものです。修正方法：先に事前登録してください。

:::info なぜこれが余分な作業に感じられるのか
これこそが本来の作業です。ここにあるすべてのガードは、実際の研究者を欺いてきた過ちです。このツールは、誠実なパスを簡単なパスにし、不誠実なパスを行き詰まるパスにします。
:::

## ステップ 4 — ゲートを確認してから訓練する

**あなたの指示：** *「訓練実行はすべてのチェックを通過しますか？通過するなら、訓練してください。」*

**forge が行うこと：** `nmt-forge preflight run` は実行がヒットするすべてのゲートをリストアップします——dev フェンスの存在、リーク監査のクリーン状態、スケジュールフロアの導出、デコードヘッドルームの確認——それぞれ ✓ または ✗ と修正方法付きで表示されます。すべてグリーンになったら：`nmt-forge run config.json`。

訓練は**即時のツール呼び出しではない**唯一のステップです——GPU を使用し、数分から数時間かかります。エージェントはターミナルで実行し、`[schedule-sanity]` の行を監視します。forge はデータミックスから早期停止の**フロア**を導出するため、合成データが多い実行では、実際の dev ロスが揺れたときに半エポックで終了することはありません（実際の失敗モードです——[訓練実行の診断](/docs/network/getting-started/diagnosing-training)を参照してください）。

訓練が完了すると、forge はフェンスされた dev セット（test セットではなく）で**チェックポイントを選択**し、`run-manifest.json` を書き込みます。

## ステップ 5 — ループを閉じる：評価と診断

**あなたの指示：** *「test バッテリーでモデルをスコアリングして、何を改善すべきか教えてください。」*

**forge が行うこと：** `nmt-forge evaluate .forge/runs/<run>/run-manifest.json --config
config.json`。このコマンドひとつで**ループを閉じます**：実行が選択したチェックポイントで test バッテリーをデコードし、スコアリングし（事前登録ゲート付き、すべての数値に 95% 信頼区間）、平易な言葉による**診断と推奨事項**セクションを追記します。（このコマンドが存在する前は、チェックポイントをシンリンクしてデコーダーを手動で実行する必要がありました——まさに初心者が迷子になる場所でした。）

### バッテリーリントレポートの読み方

レポートは**レジスター別**（教科書、政府文書、口承物語など）のスコアの表で、それぞれ信頼区間付きで表示され、その後に診断が続きます。診断は**最も弱いレジスター**を名指しし、それぞれについて最も可能性の高い原因と次に引くべき**レバー**を示します：

| 診断にこう書かれていたら… | 意味… | レバー |
|---|---|---|
| `R1-vocabulary-gap` | レジスターのスコアが低く**かつ**出力が未完成；モデルが語彙を持っていない | **VOCABULARY** — 語彙を増やし、ファネルを再確認する |
| `R2-structure-gap` | 単語は知られているが文の*形*が知られていない | **STRUCTURE** — 不足している構文を追加する（テンプレート/コンポジター） |
| `R3-mixed-convention` | 出力でスペルが混在している | **ORTHOGRAPHY** — コーパスをひとつの表記規則に正規化し、再訓練する |
| `R4-optimism-bound` | 「完全」スコアが近似双子の評価行によって水増しされている | **MEASUREMENT** — 汎化のために厳密スコアを引用する |
| `R5-low-power` | 信頼区間が広い | **MEASUREMENT** — CI より小さいデルタには行動しない；評価セットを拡大する |
| `R7-transfer-plateau` | 合成データでは優秀だが実テキストで停滞している | **REAL-DATA** — 単言語データをバックトランスレートするか、実際の対訳文を入手する |

各所見は、それが発火した証拠を含んでいます。`--json` の所見については、エージェントがプログラム的に対応できます：`nmt-forge lint <battery-manifest.json>`。

## 今やったこと

実際に信頼できるスコアを持つモデルを訓練しました：回答リーケージなし、test セットを覗かずに選択されたチェックポイント、すべての数値に誤差範囲、結果の前に書かれた予測、そして推測に任せるのではなく次のレバーを名指しする診断。それがすべての要点です——**誠実な結果がデフォルトであり、そこに到達するのに MT の専門知識は不要でした。**

数値が期待外れだったとき（最初はそうなるでしょう）、[訓練実行の診断](/docs/network/getting-started/diagnosing-training)を参照してください——症状から始まる、まさにそのような瞬間のために書かれたページです。
