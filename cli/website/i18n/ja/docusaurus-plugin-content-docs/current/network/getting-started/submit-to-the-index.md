# インデックスへの提出

> **概要。** Champollion インデックスへの追加を提案します — ベンチマーク、リソース、翻訳手法、人力翻訳サービス、または外部公開済みの結果が対象です。ブラウザまたは CLI から短い構造化フォームを送信します。**メンテナーがすべての提出を手動でレビューし**、IP・ライセンス・コミュニティ/主権への適合性を確認してから追加されます。**自動承認はありません。**

インデックスは共有マップです。手法のベンチマーク対象となるデータセット、補助となる辞書やツール、手法そのもの、人力翻訳者、そして他者が公開した結果が含まれます。誰でも追加を提案できます。ただし、これは言語コミュニティのためのインフラであるため、すべての提案は最初に人によるレビューゲートを通過します。

---

## 提出できるもの

| 種別 | 概要 | 追加される内容 |
|---|---|---|
| **ベンチマーク / データセット** | 評価用コーパスまたはベンチマーク | メタデータカード + *ソース元からの取得*ポインタ（コーパスのコンテンツ自体は含めません） |
| **リソース** | 辞書、アーカイブ、アプリ、FST（形態素解析器）、ツール | ポインタ + アクセスレベル（オープン / 制限あり / 同意必須）を含む一覧への掲載 |
| **翻訳手法** | MTエンジン、LLMプロバイダー、パイプライン | 実行およびベンチマーク測定を可能にするメソッドレジストリエントリ |
| **人手による翻訳サービス** | オプトイン方式のコミュニティオフィス、機関、個人の翻訳者 | 言語ペアごとの掲載（連絡先情報は帯域外で管理され、公開Issueには決して記載されません） |
| **外部で公開された結果** | 他のシステムや論文によって報告されたスコア | **引用** — 外部の結果は引用されるのみであり、独自の測定結果として再ホストや再順位付けを行うことはありません |
| **言語カードの修正** | [言語カード](/catalogue)の内容に誤り、古くなった情報、不足がある場合（話者数の推定、ステータス、文字体系、未掲載のリソースなど） | **データソースに適用される出典付きの修正**（カードは自動生成されるため、修正が永続化されます）。情報源の間で差異がある場合、カードには出典を明記した上でそのすべてが表示されます |

各言語カードには、その言語が事前に入力された状態で修正フォームを開く**「修正や追加を提案」**リンクも用意されています。

**コミュニティによる削除および制限のリクエスト:** コミュニティのメンバーまたは権限をお持ちの方で、ご自身の言語に関するデータの制限または削除を希望される場合は、修正フォームをご利用ください（公開を望まない場合は、帯域外でメンテナーに直接ご連絡いただくことも可能です）。これらは[データ主権レビュー](/docs/network/sovereignty/data-sovereignty)を通じて優先的に処理され、引用情報の提示は不要です。

## レビューの仕組み

重要な点として、**提出はロボットではなく人間がレビューします。** 提出すると GitHub issue が作成され、それがレビューキューになります。メンテナーがその issue を読み、プロジェクトのルールに照らして確認してから追加します。

- **知的財産およびライセンス:** 掲載の許可が得られている必要があります。非商用、再配布不可、またはライセンスが不明瞭な素材であっても*カタログへの掲載*自体は可能ですが、商用利用、賞金プログラム、パブリック取得のルートからは完全に除外されます。
- **コミュニティとデータ主権:** 先住民族およびコミュニティ言語のデータは、コミュニティの同意がある場合にのみ掲載されます。提供者や管理者の確認が得られる前に、その名称が公に公開されることはありません。
- **コーパスコンテンツのホストは行いません:** データセットはメタデータと、データの取得元へのポインタとしてのみ掲載されます。**申請内容に原文や参照訳の文を貼り付けないでください。**
- **個人情報の禁止:** 公開Issueにメールアドレス、電話番号、その他の個人情報（PII）を含めないでください。人手による翻訳サービスの場合、連絡先情報は帯域外でメンテナーに提供されます。
- **対象範囲:** 聖書・典礼文書およびその他の植民地支配により押し付けられたコーパスは対象外であり、申請は却下されます。

すべてのフォームの末尾には、必須の確認事項があります。

> *「これが公開掲載可能であり、コーパスの内容や個人情報を一切含まず、ソースのライセンスおよびコミュニティ/主権に関する制限を尊重していることを確認します。」*

## 提出方法は 2 つ

### ブラウザから

issue 選択画面を開き、提出内容に合ったフォームを選択してください。

➡️ **[GitHub で提出フォームを開く](https://github.com/gamedaysuits/Champollion/issues/new/choose)**

各フォームは、対応するインデックスに必要な項目（名前、言語 / 言語ペア、ライセンス、ソース URL など）と確認チェックボックスのみを求めます。

### CLI から

[champollion CLI](/docs/network/getting-started/submit-a-method) をお使いの場合、`champollion submit` が各フィールドを収集し、同じ GitHub フォームの**事前入力済み**バージョンの URL を生成します。

```bash
# Interactive — pick a type and answer the prompts
champollion submit

# See the submission types
champollion submit --list

# Fully scripted (prints a pre-filled GitHub issue URL)
champollion submit --yes --type dataset --attest \
  --field dataset-name="GlobalVoices eng-amh" \
  --field pairs=eng-amh \
  --field license=CC-BY-4.0 \
  --field source-url=https://globalvoices.org
```

CLI は URL を出力します — それを開き、ブラウザで確認事項を確認してから提出してください。`--out submission.json` を追加すると、提案内容のコンテンツを含まないローカルコピーも保存されます。CLI 自体は何もアップロードせず、インデックスへの書き込みも行いません。

---

## 提出後の流れ

1. 提出内容が GitHub issue として届き、レビューキューに入ります。
2. メンテナーが上記の IP / ライセンス / 主権ルールに照らしてレビューします。
3. **承認された場合：** メンテナーが通常の変更として関連するソース（データセットレジストリ、カード、手法または人力サービスレジストリ、外部結果カタログ）にエントリを追加し、issue に **accepted** ラベルを付けます。
4. **そのままでは掲載できない場合：** メンテナーが理由を添えて **declined** ラベルを付けるか、追加情報を求めます。

自動マージも自動公開もありません。毎回、人間が判断します。
