# 独自モデルのトレーニングを始めるには

これは、低リソース言語の機械翻訳モデルをトレーニングするための完全なウォークスルーです。「この言語を話せるが、データがほとんどない」という状態から、[Network](/docs/network/) に正直に報告・提出できるモデルを作るまでを解説します。初心者向けに書かれており、現代的な作業スタイルを前提としています。つまり、**コーディングエージェント**（Claude Code、OpenAI Codex、Cursor、OpenCode、Google Antigravity など）に指示を出し、エージェントがツールを実行するという方法です。

そのため、以下の各ステップは同じ構成になっています。

- 🗣️ **エージェントへの指示** — 平易な言葉で何を依頼するか。
- 🛠️ **ツールの動作** — [nmt-forge](/docs/network/getting-started/training-honestly) が代わりに実行する内容と、よくあるミスを事前に防ぐ**ガードレール**。
- 👀 **結果の読み方** — 「良い状態」とはどのようなものか、何に注意すべきか。

:::info[まず用語を確認しましょう]
*dev set*、*decoding*、*chrF++*、*leakage*、*round-trip verification* といった用語がまだ馴染みのない方は、先に [**MT Training in Plain Language**](/docs/network/context/mt-training-concepts) をお読みください。このページで使われるすべての用語が、具体例とともに定義されています。このページはそれらの用語をすべて前提としています。
:::

:::note[誠実さは機能であり、障壁ではありません]
このツールは意図的に主張を持った設計になっています。ガードレールは、実際のプロジェクトで実際に起きた、測定済みのミスを機械的に防ぐものです。そのため、誠実なパスがデフォルトであり、不誠実なショートカットは**修正方法を明示したメッセージとともに拒否されます**。このガイドで拒否が発生した場合、それはツールが正しく機能している証拠です。そうあるべきなのです。
:::

## 始める前に必要なもの

- **ターミナルとファイルシステムへのアクセスを持つコーディングエージェント**。これがドライバーです。
- **対象言語ペアの実際の翻訳済み文** — 人間が作成した数百ペアでも十分なスタートになります。バイリンガルの教科書、コミュニティのアーカイブ、翻訳された公的記録、教育資料などが使えます。量より質を重視してください。
- **任意ですが強力なもの:** ターゲット言語の単言語テキスト、バイリンガル辞書、出版された参照文法書、形態素解析器（FST）。これらをすべて揃えなくても始められます。ツールが、どれが存在するか、どれがどの機能を解放するかを正確に教えてくれます。
- **計算環境:** ガードレール、分割、合成、監査、スコアリングはノートパソコンで動作します。実際のモデルトレーニングのステップだけがGPUを必要とします（LoRAを使った小さなモデルであれば、控えめなハードウェアで対応できます）。

> 🗣️ **エージェントへの指示:** *「Champollion モノレポの `forge/` パッケージから nmt-forge をインストールし、`nmt-forge` コマンドが動作することを確認してください。英語 → \<your language\> の翻訳モデルを、誠実な方法でトレーニングします。」*

エージェントは Champollion MCP サーバーの `get_training_guardrails` ツールを呼び出して、10個のガードレールとそれぞれが防ぐミスを含む完全なルールブックを、コマンドを書く前に自身のコンテキストに読み込むことができます。エージェントを使っている場合は、まずそれを行うよう指示してください。

## ステップ 1 — 言語を選び、実際に何が存在するかを確認する

すべてのプロジェクトは、インデックスにその言語が*何を持っているか*を正直に問い合わせることから始まります。

> 🗣️ **エージェントへの指示:** *「対象言語の ISO 639-3 コードで `nmt-forge discover` を実行し、どのようなデータが存在し、何が不足しているかをまとめてください。」*

```bash
nmt-forge discover nav        # Navajo, as an example
```

🛠️ **ツールの動作。** ツールはその言語の Champollion **カード** — その言語について知られていることの唯一の情報源 — を読み込み、記録されているスクリプト、形態素解析器、辞書、コーパス、評価データセットを報告し、その言語を**アセットラダー**上に位置づけます。

```
THE ASSET LADDER — what this language can do TODAY:
  ✓ rung 1: parallel text → train with every guard (no pack needed)
  ? rung 2: monolingual text → the tagged backtranslation lane
  ? rung 3: dictionary (+ grammar) → a cited template pack is worth building
  ? rung 4: morphological analyzer → round-trip-VERIFIED synthesis
  ? rung 5: LYSS referee → the language's own metric in selection
```

👀 **結果の読み方。** `✓` マークは今すぐできること、`?` マークはアセットを待っているステップを示します。重要なのは、**カードに記載がないことは*不明*を意味し、「この言語には何もない」という意味ではありません。** カードが少ない場合は、知っていることを追加する招待状であり、行き詰まりではありません。カードが空でも、ランク1の完全なガード付きトレーニングループを利用できます。豊富なカード（Plains Cree など）は上位ランクを自動的に接続します。その評価セットは **NEVER TRAIN ON THIS** フラグ付きで届き、言語固有のレフェリーもすぐに接続できる状態で用意されています。

次に、プロジェクトをスキャフォールドします。

> 🗣️ **エージェントへの指示:** *「この言語ペアに対して `nmt-forge init` でプロジェクトをスキャフォールドし、生成される `NEXT_STEPS.md` を読み上げてください。」*

```bash
nmt-forge init nav --dir my-nav-mt --pair eng-nav
```

🛠️ これにより、ワークスペース（すべてのガードレールが参照する `.forge/` ディレクトリ）、**スターター設定**、そして*あなたとエージェント*向けに書かれた `NEXT_STEPS.md` ブリーフが作成されます。ブリーフにはコマンドの順序、言語のアセットラダー、および絶対に守るべき事項が含まれています。以降のすべての手順のマップとなります。

## ステップ 2 — 解析器と辞書を指定する（存在する場合）

このステップはラダーの**ランク 3〜4** に関するものです。言語に解析器がない場合は、[ステップ 4](#step-4--split-your-real-data-safely) にスキップしてください。実データ（およびバック翻訳データ）のみでトレーニングするのは、完全に正当なパスです。

解析器と辞書が*存在する*場合、検証済みのトレーニングデータを*生成*する能力が解放されます。これは、並列テキストが少ない言語にとって最大のレバーです。

> 🗣️ **エージェントへの指示:** *「カードにはこの言語の形態素解析器と辞書が記載されています。カードのインストール手順に従ってそれらを取得し、ドキュメントに記載された環境変数を通じて言語パックに指定し、解析器がいくつかの既知の単語をラウンドトリップできることを確認してください。」*

🛠️ **ツールの動作 — 越えない境界線。** 解析器（FST）と辞書は、**独自のライセンスを持つ、ユーザーが個別に取得する別ツール**です。このスイートはそれらを**バンドルしたり再配布したりしません** — 入手先とライセンスを案内し、ユーザーが取得します。これは官僚主義ではありません。多くの言語リソースには実際の許可条件と主権に関する制約があり、ツールはその設計によってそれらを尊重しています。

接続部分は**言語パック**です。これは、*あなたの*解析器、辞書、正書法ルール、文法に基づく文テンプレートをエンジンに適合させる小さなプラグインです。このスイート自体はパックを**一切**同梱しません — パックはそれぞれの言語とともに存在します（たとえば Plains Cree パックは独自のプロジェクトに存在し、モジュールパスで接続します）。

👀 **結果の読み方。** 解析器が**ラウンドトリップ**できることを確認してください。つまり、ある形を入力し、その表記を解析器に戻したとき、同じ文法タグが得られることです。そうならない場合、パックの**正規化器** — 2つのコンポーネントが接触するすべての場所で表記を正規化する関数 — におそらくルールの追加が必要です。これを正しく設定することは重要です。1つの未解決の文字（`ý` と `y`）が、生成パイプラインから1,375個の動詞を何週間も静かに削除し続けたことがありました。ツールの**ファネル監査**は各ステージでの生存数を正確にカウントするため、このような静かな脱落を隠すことができません。

## ステップ 3 — 文法ルールからトレーニングデータを合成する

解析器 + 辞書 + 文法に基づくテンプレートのパックがあれば、数十万の検証済みペアを生成できます。

> 🗣️ **エージェントへの指示:** *「`nmt-forge synth` を使って言語パックで合成トレーニングデータを生成し、カバレッジレポートを表示してください。」*

```bash
nmt-forge synth my_pack.module:get_pack --out data/synth.jsonl
```

🛠️ **ツールの動作 — 出力の法則。** 出力に到達するすべての行は、どのパックも回避できないルールを満たす必要があります。

- **ラウンドトリップ検証済み** — 生成されたすべての単語が *生成 → 解析 → 同じ解析結果* を通過するか、その行は破棄されます。未検証の形は一切出力されません。
- **文法引用済み** — すべてのテンプレート種別は、それが転写した出版済み文法書を引用します。引用のないテンプレートは存在しません。コードはそれらの読み込みを拒否します。
- **カバレッジチェック済み** — テンプレートは必要な文法現象のチェックリスト（命令形、疑問文、所有、逆形など）に対して照合されます。*必須*の現象に例が0件の場合、ビルドは失敗します。これは「百万文あっても、すべて同じ少数のパターン」という罠 — 構造的な穴を隠す量 — に対するガードです。
- **出所スタンプ済み** — すべての合成行には `synthetic: true` のマークが付きます。このスタンプは重要な意味を持ちます。レジストリは合成行をテストセットとして登録することを**拒否します**。テストは実データのみです。

👀 **結果の読み方。** カバレッジレポートで**カバレッジがゼロの必須項目**（テンプレートが一度も生成しなかった文法現象）と**種別分布**を確認してください。2つのテンプレート形が支配的な場合、サンプラーの種別ごとの上限（デフォルト15%）がそれらを再バランスし、単一のパターンがモデルの経験の半分を占めないようにします。

:::tip[解析器がない場合はバック翻訳を使用する]
ルールから合成できないが、ターゲット言語の**単言語**テキストがある場合は、エージェントに**バック翻訳**レーンを実行するよう依頼してください。`nmt-forge backtranslate` は単言語テキストを英語に機械翻訳し、各結果を**実際の**ターゲット文とペアにします。ターゲット側は本物のまま保たれます。ツールはまず**単言語テキストのリーク監査を行います** — そのテキストが評価データになっている可能性があるためです。詳しくは [Back-Translation cookbook](/docs/network/tutorials/back-translation) をご覧ください。
:::

## ステップ 4 — 実データを安全に分割する

次に、**実際の**ペアをトレーニング / dev / テストに分割します。ここに低リソース MT で最も結果を台無しにするミスが潜んでおり、ガードレールが真価を発揮します。

> 🗣️ **エージェントへの指示:** *「`nmt-forge split` を使って実コーパスをテストセットと dev セットにグループ非重複で分割し、登録してください。再現性のために固定シードを使用してください。」*

```bash
nmt-forge split corpus.jsonl --test 150 --dev 42 --seed 42 \
    --out data/split --register textbook
```

🛠️ **ツールの動作 — 分割ガード。** **グループ非重複分割**を実行します。ソースまたはターゲットを共有するすべてのペアを1つのグループにまとめ、グループ全体を一方の側に配置します。その後、**重複がゼロであることを検証**し、重複があれば処理を拒否します。

```
{"verified": "0 shared canonical source/target keys across sides", ...}
```

これは **「Feed him」/「Feed her」リーク**を防ぎます。教科書では両方の英語ドリルが1つのターゲット単語（`asam`）にマッピングされており、単純なランダム分割では一方のコピーがトレーニングに、もう一方がテストに入るため、モデルは記憶によって「合格」してしまいます。実際のプロジェクトでは、54のテスト行のうち17行がこの方法でリークし、クリーンな行の44に対して83というスコアを記録しました。そしてその数値に基づいて構築されたすべての知見が無効になりました。`--register textbook` は dev セットとテストセット（`textbook-dev` と `textbook-test` として）をワークスペースに記録し、以降のすべてのコマンドがそれらを*絶対にトレーニングに使ってはならない評価セット*として認識します。

👀 **結果の読み方。** **verified: 0 shared** という行が表示されることを確認してください。代わりに `SplitLeakageError` が表示された場合、行を手動で削除しないでください — それは問題を再配置するだけです。グループ非重複分割を再実行してください。それが修正方法であり、エラーメッセージにもそう書かれています。

:::danger[ベンチマークでトレーニングしないこと]
共有レジストリから評価データセットを取得した場合（`nmt-forge registry add-harness`）、ツールはそれにスタンプを押し、トレーニングに使用できないものとして扱います — レジストリの**すべての**ベンチマークは *do-not-train* フラグが付きます。正当に使用できるデータでファインチューニングしてください。ただし、テストセットは絶対に使用しないでください。これは Network 全体の[唯一のルール](/docs/network/leaderboard/rules)です。
:::

## ステップ 5 — トレーニングする

1つの設定ファイルでランク全体を記述し、1つのコマンドで再現可能な形で実行します。

> 🗣️ **エージェントへの指示:** *「トレーニング設定を記入してください — `dev` を登録済み dev セットに向け、ゴールドと合成データのレーンを列挙し、LoRA を使った小さなベースモデルを選択してから、`nmt-forge run` を実行してスケジュール診断を確認してください。」*

```jsonc
{
  "run_name": "my-first-run",
  "workspace": ".forge",
  "data": {
    "gold": ["data/train.jsonl"],
    "synthetic": [{"path": "data/synth.jsonl", "tag": "<synth>"}],
    "dev": "textbook-dev"            // registry name, role=dev — the fence
  },
  "mix": {"gold_upweight": 20, "kind_cap": 0.15, "seed": 42},
  "model": {"backend": "hf-seq2seq", "base": "facebook/nllb-200-distilled-600M"},
  "selection": {"metric": "generation:chrf++", "patience": 6},
  "decode": {"max_new_tokens": 256, "headroom_factor": 1.5},
  "regime": "auto"
}
```

```bash
nmt-forge run config.json
```

🛠️ **ツールの動作 — 4つのガードレールが同時に機能します。**

- **トレーニング前のリーク監査。** ゴールド、合成、バック翻訳テキストを含む*すべての*レーンが、*すべての*登録済み評価セットに対してスクリーニングされます。完全一致、近似重複（言い換え）、テストセットとのファイル全体の一致は致命的エラーです。混合データがクリーンになるまでトレーニングは開始されません。
- **Dev フェンス。** トレーニングは**登録済み dev セットなしでは開始を拒否**し、チェックポイントの選択は常にその dev セットに対してのみ行われます — テストセットは使用されません。（dev 行をテストセットと照合するコンテンツチェックも行い、`cp test.jsonl dev.jsonl` トリックを検出します。）チェックポイント選択には dev **損失**または dev **生成メトリック**を使用できます — dev セットをデコードして実際の出力をスコアリングする、より誠実なシグナルです。
- **スケジュールの健全性チェック。** 混合データが合成データ中心の場合、ツールは混合サイズからストップフロアを*導出*し、**プラトー**（モデルが簡単な合成学習を終え、まだ実際の品質に転移していない段階）を通じてトレーニングを継続します。これにより、単純な早期停止が計画の20分の1で終了する「半エポック死」を防ぎます。すべての介入は dev 損失の軌跡と理由を平易な言葉で出力します。
- **露出計算 + タグ付き合成データ。** ゴールドデータはアップウェイト（繰り返し）されるため、少ない実データが埋もれません。マニフェストには**ユニーク文ごとの有効露出数**が記録され、A/B テストの公平性が保たれます。合成ソースにはタグが付き、ゴールドはタグなしのままで出力スタイルのアンカーとなります。

👀 **結果の読み方。** ランは**信頼区間付きの dev レポート**を出力します — スコアのみの出力はありません。

```
dev report (95% CIs):
n=42 · set=textbook-dev
  chrf++       44.31  [41.20, 47.15] 95% CI
```

早期停止を*保留*してトレーニングを継続したことを説明する `schedule-sanity` メッセージが表示された場合、それはプラトーガードが機能している証拠です — 良い兆候です。ランは**マニフェスト**も書き出します。設定ハッシュ、データファイルハッシュ、シード、導出されたスケジュールが含まれており、ラン全体が再現可能です。

## ステップ 6 — 誠実に評価する

モデルができました。テストセットでスコアリングする前に、まず期待値を書き留めます — *最初に*。

> 🗣️ **エージェントへの指示:** *「テストセットのスコアリングに向けた事前登録を書いてください — 予測するメトリック、方向、マージン — その後テストセットをデコードしてスコアリングしてください。」*

```bash
# 1. Predict BEFORE you peek
nmt-forge prereg new run1 --eval-set textbook-test --predictions preds.json

# 2. Now score (decode first, then score the actual output)
nmt-forge score --eval-set textbook-test --hyps decoded.txt
```

🛠️ **ツールの動作 — 後付けストーリー防止ガード。**

- **事前登録。** 登録済み**テスト**セットのスコアリングには、最初の確認*前*に書かれた事前登録が必要です。それがなければ、比較テーブルは単純に**レンダリングを拒否します**。

  ```
  [preregister] no preregistration for eval set 'textbook-test'
    why: results looked at without written-down expectations become
         post-hoc stories
    fix: write one FIRST: nmt-forge prereg new ... — then score
  ```

  これは、後付けの解釈（「もちろん口承物語で改善した」）を予測として装うことへのガードです。*失敗した*予測を書き留めることが、成功した予測を信頼できるものにします。
- **常に信頼区間付き。** すべてのスコアは95%ブートストラップCIとともにレンダリングされます。CIなしの出力はありません。区間が重なる `+0.5` の上昇は勝利ではありません。
- **評価台帳。** すべての評価セットのすべての読み取りがログに記録されます（追記のみ、改ざん防止）。`nmt-forge ledger show --set textbook-test` に、セットがどれだけ「消費」されているかを確認できます。**シールド済み**セットは一回限りです — 一度スコアリングされたら閉じられます。

👀 **結果の読み方。** 数値を**区間とレジスターごとに**読み、喜ぶ前に**どのメトリックを信頼すべきか**を確認してください。

```bash
nmt-forge score --eval-set textbook-test --hyps decoded.txt \
    --metric chrf++ --metric comet --target-lang nav
```

`nmt-forge discover` は、あなたの言語ファミリーに対する各メトリックの**測定済み信頼性**を示します（WMT メタ評価から）。ファミリーによっては、BLEU のようなメトリックが人間の判断をほとんど反映しない一方で COMET が有効な場合があります。多くの低リソース言語ファミリーでは、正直な答えは*未測定*です — その場合、自動的な数値ではなく、ネイティブスピーカーの判断が真のシグナルです。[Metric Reliability](/docs/network/specifications/metric-reliability) をご覧ください。

:::tip[言語固有のレフェリー]
言語に LYSS 評価標準がある場合（たとえば、2つの表記が文書化された長母音の慣例のみで異なることを知っているリンター）、`--plugin` で接続すると chrF++ と並んでスコアリングされます — チェックポイントの*選択*にも使用できるため、勝つモデルはその言語固有のレフェリーが好むモデルになります。プラグインの数値にも信頼区間が付きます。
:::

## ステップ 7 — 反復する

次は改善です — そしてすべての改善は同じ誠実な方法で測定されます。

> 🗣️ **エージェントへの指示:** *「1つのことを変更してください — テンプレート種別の追加 / バック翻訳データの追加 / 別のベースモデル — 再トレーニングし、dev セットで有意差を確認しながら前のランと A/B 比較してください。」*

```bash
nmt-forge compare --eval-set textbook-dev \
    --hyps-a run1.txt --hyps-b run2.txt --metric chrf++
```

🛠️ **ツールの動作。** `compare` は単純な差分ではなく**ペア有意差検定**を実行するため、「B が A を上回る」という主張は統計的に裏付けられたものになります — ノイズではありません。**dev** セットで反復してください（それがその目的です）。**テスト**セットは頻度を抑えた事前登録済みのチェックに使用し、**シールド済み**セットは最後のために取っておいてください。

👀 **結果の読み方。** 真の改善は信頼区間*と*有意差検定の両方をクリアします。クリアしない場合でも、何かを学べます — そのレバーは期待より弱かったということであり、それを知ることには価値があります。プラトー / カバレッジ / リークガードにより、比較している数値は信頼できるものになっているため、自分の反復ループを実際に信頼できます。

データが乏しい言語に対して、効果の高い順に並べた一般的な次のレバーは以下の通りです。

1. **合成のカバレッジを増やす** — カバレッジレポートがフラグを立てた不足している文法現象を追加する。
2. **バック翻訳** — 単言語ターゲットテキストをより多くのトレーニングペアに変換する。
3. **より大きい、またはより適したベースモデル**、あるいは LoRA ランク / ハイパーパラメータのチューニング。
4. **カリキュラム** — 合成データで事前トレーニングし、その後実ペアでファインチューニングする。

## ステップ 8 — Network に提出する

誠実にトレーニングされたモデルは、まさに [Champollion Network](/docs/network/) が受け入れるために構築されたものです。

> 🗣️ **エージェントへの指示:** *「このモデルをメソッドとしてパッケージ化し、この言語ペアのリーダーボードに提出してください。」*

- **[Submit a Method](/docs/network/getting-started/submit-a-method)** は、あなたのモデルを Network エントリーに変換し、公開参照コーパスでスコアリングされ、あなたに帰属します。
- 評価がクリーンだったため — グループ非重複、dev フェンス、リーク監査済み、CI 付き、事前登録済み — あなたの提出は、ほとんどの低リソース MT の主張を沈める精査に耐えられます。アンチゲーミングアーキテクチャ（コミュニティが所有する秘密のテストセット、再現性チェック、ネイティブスピーカーによる検証）は、この方法で構築されたモデルにとって障壁ではなく、信頼性のスタンプです。
- あなたの言語に**賞**が設けられている場合、誠実に構築されたベースラインを上回る安定したメソッドは、まさにスポンサー付きプールが報いるものです。そして、先住民族の言語に対してメソッドが機能する場合、**所有権をコミュニティに移転できます** — ここで構築し、彼らが自分たちの条件でデプロイします。[Prize Specification](/docs/network/specifications/prizes) と [Ownership Transfer](/docs/network/sovereignty/ownership-transfer) をご覧ください。

## 全体の流れを一息で

1. **発見する** — 言語が何を持っているかを確認する（`discover`、`init`）— 記載なしは不明であり、ゼロではない。
2. **指定する** — 解析器 + 辞書が存在する場合はそれらを指定する（ランク 3〜4）、ライセンスを尊重しながら。
3. **合成する** — 検証済み、引用済み、カバレッジチェック済みのトレーニングデータを生成する（`synth`）— または単言語テキストを**バック翻訳**する。
4. **分割する** — 実データをグループ非重複で分割し、評価セットを登録する（`split`）。
5. **トレーニングする** — 1つの設定、dev フェンス、リーク監査済み、プラトー対応（`run`）。
6. **評価する** — 予測を先に書き、常に CI 付き、適切なメトリックで（`prereg`、`score`）。
7. **反復する** — 有意差検定付きの A/B で（`compare`）。
8. **提出する** — Network へ — 誠実な作業こそが目的。

低リソース MT の結果が間違う10通りの方法を暗記する必要はありませんでした。ツールが誠実なパスをデフォルトにし、ショートカットを説明付きで拒否しました。それがすべてのアイデアです。**ガードレールが初歩的なミスを防ぐので、あなたは言語に集中できます。**
