# コーパス作成ガイド

> **アイデア:** 翻訳手法を評価するには、まず評価コーパスが必要です。このガイドでは、データの収集源、フォーマット要件、品質基準、ライセンス、そしてネットワークへの貢献方法まで、コーパスをゼロから構築する方法を説明します。

:::info[これは翻訳手法ではありません]
このガイドは多くの手法の前提条件です。優れた評価コーパスは、他のすべてを可能にする基盤です。丁寧に選定された50ペアでも、新しいリーダーボードのトラックを開設するには十分です。
:::

## このアプローチを使うべき場面

- ネットワークのリーダーボードに**新しい言語ペアを追加**したい場合
- 生徒の翻訳をベンチマークしたい**語学教師**の場合
- バイリンガル資料にアクセスできる**コミュニティの言語担当者**の場合
- 言語ペアの標準化された評価セットが必要な**研究者**の場合

## コーパスのフォーマット

ハーネスはシンプルなJSONを受け付けます：

```json title="my-corpus.json"
{
  "metadata": {
    "name": "Quechua Dev v1",
    "version": "1.0.0",
    "source_language": "eng",
    "target_language": "que",
    "entry_count": 75,
    "license": "CC-BY-SA-4.0",
    "author": "Your Name / Organization",
    "description": "75 English-Quechua pairs from educational materials"
  },
  "entries": [
    {
      "id": 1,
      "source": "Hello, how are you?",
      "reference": "Allillanchu, imaynallan kashanki?"
    },
    {
      "id": 2,
      "source": "The sun is shining today",
      "reference": "Kunan p'unchay inti k'anchashan"
    }
  ]
}
```

## データの収集源

| 収集源 | 品質 | 量 | ライセンス |
|--------|---------|--------|-----------|
| **教科書・教育資料** | 高（専門家によるレビュー済み） | 低〜中 | 出版社に確認 |
| **政府文書** | 中（フォーマルな文体） | 中〜高 | パブリックドメインが多い |
| **バイリンガル辞書** | 高（検証済みの項目） | 中 | 様々 |
| **コミュニティの長老・話者** | 最高（ネイティブの直感） | 低（時間が限られる） | コミュニティが管理 |
| **宗教テキスト** | 中（特定ドメイン） | 高 | 通常オープン |
| **既存コーパス**（Hansard、FLORES） | 中〜高 | 高 | ライセンスを確認 |
| **手作成** | 最高 | 低 | 作成者が所有 |

## 品質基準

優れた評価コーパスの条件：

1. **多様なコンテンツ** — 挨拶や簡単なフレーズだけでなく、疑問文、命令文、複雑な文、専門用語を含めること
2. **検証済みの翻訳** — 少なくとも1人、理想的には2人の流暢な話者によるレビューを受けていること
3. **一貫した正書法** — 全体を通じて1つの文字体系、1つのスペル規則を使用すること
4. **独立したソース** — 手法がトレーニングに使用するテキストから派生していないこと
5. **明確なライセンス** — 評価目的での使用を許可する明示的なライセンスがあること

:::danger[コーパスの汚染]
評価コーパスは、学習データから**独立**していなければなりません。ある手法が評価コーパスのデータを使って学習またはプロンプト設計されていた場合、その手法は失格となります。コーパスは最初からホールドアウト用として設計してください。
:::

## サイズの目安

| サイズ | 可能になること |
|------|----------------|
| **50エントリ** | 最小限の評価 — 品質の大きな差を検出するのに十分 |
| **100〜200エントリ** | 信頼性の高いランキング — 手法間の統計的有意性を確保するのに十分 |
| **500エントリ以上** | 研究グレード — 堅牢な複合スコアと信頼区間 |
| **1,000エントリ以上** | ゴールドスタンダード — FLORESのdevtestカバレッジに相当 |

小さく始めましょう。50エントリあればリーダーボードのトラックを開設できます。後から拡張することも可能です。

## ネットワークへの貢献

1. **コーパスを作成する** — 上記のJSON形式で作成してください
2. **ライセンスを付与する** — オープンな評価にはCC BY-SA 4.0を推奨します。利用制限がある場合はCC BY-NC-SA 4.0を使用してください
3. **安定したソースでホストする**（自分のリポジトリ、機関アーカイブ、またはデータレジストリ）— Champollionはコーパスのコンテンツをホストしたり追跡したりすることはありません
4. **ソースからフェッチするメタデータカードを提出する** — [公開リポジトリ](https://github.com/gamedaysuits/Champollion)に対してPRを開き、ハーネスをアップストリームソースに向けるレジストリエントリ（ローダー/URL、SHAピン、ライセンス、出所情報）を追加してください。カードの形式については[データセット](/docs/network/leaderboard/datasets#creating-a-new-dataset)を参照してください
5. **リーダーボードが開設される** — カードがマージされると、対象の言語ペアのリーダーボードが利用可能になります

## 先住民言語コミュニティの方へ

コーパスの作成は**言語主権**の行為です。あなたのコーパスは、あなたの条件で：

- ライセンスとアクセス条件はあなたが決めます
- **公開開発セット**（手法の開発用）を提供しながら、**秘密テストセット**（公式評価用）をコミュニティの管理下に置くことができます
- [主権フレームワーク](/docs/network/sovereignty/data-sovereignty)があらゆるレベルでデータを保護します

小さなコーパスであっても**戦略的な資産**です — あなたの言語にとって「十分な品質」が何を意味するかを決めるベンチマークになります。
