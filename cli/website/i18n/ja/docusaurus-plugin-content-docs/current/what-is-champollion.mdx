# Champollionとは

**Champollionは、自分たちの言語のための機械翻訳を構築し、誰かがそれに頼る前に実際に機能することを実証するためのオープンソースツールキットです。**

大手テクノロジー企業が見落としがちな言語のために作られています。たとえば、クリー語でニュースレターを発行したい学校、対応する家族のためにベッドサイドの会話集を必要としている病院、自分たちの言語を任せるに足るツールが存在するのかを知りたいコミュニティなどです。人間であれ、これらのツールを指定されたAIエージェントであれ、*「どのように始めればよいか？」*という段階から、テスト済みでデプロイされた翻訳ワークフローまで進めることができます。

## プロセスと、各ステップのツール

| ステップ | 問い | ツール |
|---|---|---|
| **1. 既存の情報を把握する** | この言語について何が判明しているか（辞書、文法書、コーパス、モデル、公開された研究結果、サービスなど）？ | **[アトラス](/languages)** — <SSOTCount field="catalogLanguageCount" /> 言語カード。すべての値に出典が明記されています |
| **2. 独自のデータを保護する** | データを外部に渡すことなく、自分たちの文を使ってテストするにはどうすればよいか？ | **[コーパスの登録](/docs/network/sovereignty/registering-corpora)** と **[ソブリンノード](/docs/network/sovereignty/sovereign-eval-node)** — テストセットを自分のマシン、またはエアギャップ環境に保持します |
| **3. 選択肢を測定する** | *自分たちの*テキストに最も適した手法はどれで、どの程度の差があるか？ | **[ハーネス](/docs/network/specifications/harness)** (`mt-eval`) — 常に同一の手順で、任意のコーパスに対してあらゆる手法をスコアリングします |
| **4. より優れたものを構築する** | 自己満足に陥ることなく、自分たちでモデルをトレーニングまたは適応させられるか？ | **[NMT Forge](/docs/network/getting-started/training-honestly)** (`nmt-forge`) — テストデータの流出、不適切なデータ分割、ノイズに対する都合の良い解釈を防ぐガードレール付きのトレーニング |
| **5. 実証する（希望する場合はオープンに）** | 本当により優れているか？ 他の人が検証できるか？ | **[リーダーボードとコンテスト](/docs/network/getting-started/submit-a-method)** — 結果を公開するか、ノードから外部に出ない封印されたテストセットでコンテストを開催します |
| **6. 最良のものを組み合わせる** | このペアに対して誰が何を提供しており、どれを組み合わせられるか？ | **[ネットワーク](/docs/network/)** — 存在する手法とサービス、およびそれぞれの根拠データ |
| **7. 実際に使う** | アプリ、サイト、ドキュメントを翻訳する。 | **[Champollion CLI](/docs/intro)** — 実証されたものを言語ペアごとにデプロイ。翻訳メモリを備えているため、同じ文に対して二重にコストを払うことはありません |

**[MCPサーバー](/docs/network/getting-started/mcp-server)** は、上記のすべてのステップを実行するための「手」をAIエージェントに提供します。また、本ドキュメントは人間とエージェントの双方に向けて書かれています（機械可読形式：`/llms.txt`、`/llms-full.txt`）。

**測定こそが中核です。** カバレッジ（対応言語数）は大々的に発表されますが、品質が示されることはめったにありません。上記のすべてのステップは、どのようなデータか、手法のバージョンは何か、評価指標は何か、どの程度のコストがかかったかという来歴とともに、検証可能な数値で完結します。「このペアに対してはまだ機能するものがない」という誠実な結論も、私たちが公開する成果のひとつです。なぜなら、可視化されたギャップこそが、誰かが埋めることのできるギャップだからです。

## 私たちが従うルール

これらはマーケティングではなく、制約事項です。これらがソフトウェアにできることを形作ります。

**私たちは利用者のコーパスを一切保持しません。** テストセットの登録は、データを私たちの元へアップロードするのではなく、データがすでに置かれている場所を指定することによって行われます。手法のスコアリングは、私たちが一切保持しないコーパスに対して行われます。封印されたテストセットの場合、データは手元のマシン上で暗号化されてそこに留まり、実行の承認にはコミュニティの複数の鍵カストディアン（管理者）によるしきい値署名が必要となる設計になっています（現時点ではまだ誰も選任されていません）。

**言語データは生体データのように扱われます。** コーパスを提供する人々は、そのコーパスと、
それに対して測定されるすべてのものに対する鍵を保持します。同意は当然のものとみなされるのではなく、
求められるものであり、撤回することも可能です。

**私たちは主権の尊重を目指すものであり、主権を「認証」されたものではありません。** プロジェクトが言語データに対するコミュニティの所有権や管理権を尊重しているかどうかは、そのプロジェクト自身が主張できることではありません。私たちは誠実に開発を進め、そのメカニズムをありのままに説明します。判断を下すのは、関わるコミュニティ自身です。

**人間であれ機械であれ、あらゆる手法を歓迎します。** プロの翻訳者、FSTベースのルールシステム、
プロンプトによるフロンティアモデル、ファインチューニングされたNMTモデルは、同じテストセット上で
同じように比較されます。私たちが重視しているのは言語が翻訳されることであり、どのツールが勝つかではありません。

**できないことも公開します。** [正直な制限事項](/docs/network/honest-limitations)をご覧ください。
これは、このプロジェクトがまだ主張して*いない*ことのリストです。ここにある他の情報を信頼する前に、
まずこれをお読みください。

---

**Champollionはインデックスであり、裁定者ではありません。** すべての値は情報源を引用し、
その情報源が実際に述べていることを報告します。情報源間で意見が異なる場合（話者数については
非常に頻繁に起こります）、カードにはそれらすべてが帰属とともに表示されます。
私たちが勝者を選んだり、コンセンサスを捏造したりすることはありません。

## 名前について

Jean-François Champollion（ジャン＝フランソワ・シャンポリオン）は、3つの文字で同じテキストが書かれた
ロゼッタ・ストーンを使用して、エジプトのヒエログリフを解読しました。パラレルテキスト（対訳コーパス）は、
現在でも翻訳を学習するための方法です。また、この名前には、声に出して言及する価値のある緊張感も含まれています。
それは、搾取の時代に、ヨーロッパの学者が他人の書いたものを読んだということです。私たちはそのことについて
考えています。だからこそ、上記の主権に関するルールは、パンフレットの1ページではなく、
ソフトウェアの制約事項となっているのです。
