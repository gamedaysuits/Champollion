# はじめての翻訳機

ここからが楽しみなところです。翻訳機があなたの文から初めて学習し、それを実際に試してみる時です。また、最初の結果こそが人の記憶に残るものだからこそ、レールがもっとも慎重に働く場面でもあります。

## 教え始める前に

アシスタントがこれらを順番に進めていきます。ほとんどの作業はアシスタントが自動で行いますが、あなた自身の判断が必要な手順では立ち止まって確認を求めます。

1. **学習ツールをインストールする** —— 一度きりで、あなたが同意した場合にのみ行われます。お使いのコンピューターにダウンロードされます。
2. **文を1つのファイルにまとめる** —— ツールがファイルをまとめ、それぞれの最も厳しいルールを保ちつつ、完全な重複を除外します。どの翻訳機も学習に使ってはならないファイルは、削除されるのではなく脇に移動されます。
3. **テスト文と照合する** —— テスト文と同じ文や、ほぼ同じ文は脇に取り分けられます。
4. **期待することを書き留める** —— まだ結果が出る前に、あなた自身の言葉で書きます。「*せいぜい会話帳レベル*」という予想でもまったく構いません。これが書かれるまで、レールは先へ進みません。
5. **練習用の文を取り分けておく** —— 文が200未満のうちは4分の1、それ以降は50文、さらに増えたら10文に1つの割合で取り分けます。テスト文に手を触れずに、翻訳機が学習しながら確認できるようにするためです。
6. **辞書の性能を測る** —— 単語リストを用意してある場合、ツールはまず単純に各単語を引くだけでどこまでいけるかを調べます。翻訳機を使う価値があるのは、それを上回ったときだけです。

## 学習

続いて、翻訳機が学習を行います。すべてはお使いのコンピューター上で実行され、外部に送信されるものは一切ありません。ツールはコンピューターのメモリを確認し、処理できるものを選択します。新しいMacやNVIDIA製グラフィックスカードを搭載した環境では、より強力な翻訳機（またはメモリ消費の少ない軽量版）が選ばれ、その他のコンピューターでは、ずっと小型の翻訳機が選ばれます。1台のコンピューターで一度に学習できる翻訳機は1つだけです。

処理には少し時間がかかることがあります。小型のもので数分、強力なもので数時間です。翻訳機は自身の状態を監視しており、開始時に反応が見られない場合や、進捗が止まった場合、あるいは実行が丸1日を超えた場合には、停止してその理由を知らせます。処理が永遠に動き続けることはありません。

## 最初の結果

完了すると、テスト文を使って翻訳機がテストされ、**スコア**が表示されます。これは、話者が話した表現に翻訳がどれだけ近いかを100点満点で表した数値です。その横には、確実性の度合いを示す範囲と、該当するすべての警告が一言一句そのまま表示されます。

その後、ウェブブラウザ上で自分自身の文を使って、実際に試してみることができます。

## 実際の様子

ツールの練習用実行（数秒で終わるように作られた架空の文と模擬の翻訳機を使用）では、ある家族が*「せいぜいフレーズ集程度」*と予測しました。その結果は次のとおりです。

- 単語リストで単語を引いたスコアは、<WalkFact of="floor.devSentences" />文の練習用の文に対して100点中およそ<WalkFact of="floor.score" round />でした。
- 最初の翻訳機は、同じ練習用の文に対して約<WalkFact of="devModel.score" round />を記録しました — **単語リストを下回る結果です。**
- ツールはそのことをはっきりと示し、<WalkFact of="smallSample.n" />文の練習用の文では大きな違いしか捉えられないと警告しました。
- 予測は的中し、祖父がそれを記録しました。

これは失敗ではなく、本物の学びです。数十文程度では、最初は単語リストの方が優れていることがよくあります。レールは、準備ができたと告げるのではなく、そのことを確実に*把握*できるようにします。そして、それに続くラウンドを重ねることで、単語リストを超えていくのです。

## フレーズ集にとどまるとき

最初はほぼ必ずそうなります。学習した文と似た文はうまく翻訳できても、新しい文になると頼りなくなります。それでも、話者が手直しする下書き用として、あるいは繰り返し使うフレーズ用として、十分に役に立ちます。そして何より、これをより良くしていくためのラウンドの始まりでもあるのです。
