# トークナイザーが安価な言語を決定する仕組み

:::info[対象読者]
すべての人です。このページは、機械学習や言語学の背景知識がないことを前提としています。言語モデルとは何か（テキストを受け取り、テキストを生成するソフトウェア）を知っていれば十分です。
:::

すべての言語モデルには、目に見えない最初のステップがあります。単語を読み込む前に、ソフトウェアがその単語を断片（フラグメント）に分割します。モデルが実際に認識しているのは、この断片です。

このステップは**トークン化（tokenization）**と呼ばれますが、ほとんど誰も注目しません。しかし、これは注目に値します。なぜなら、ここで一部の言語が他の言語よりも数倍も使用コストが高くなる分岐点となるからです。しかもその決定は、品質、公平性、カバレッジについて誰かが考えるよりも前に行われます。

---

## 1. モデルは文字を読めない

ニューラルネットワークは数値の計算を行います。文字や単語という概念は持っていません。そのため、テキストはまず数値に変換される必要があります。

**トークナイザー**は、その変換を行い、最後に元に戻すソフトウェアです。文字列を整数のリストに変換し、各整数は巨大なルックアップテーブルの行を指し示します。

トークナイザーは2つの決定を下します。

**語彙（The vocabulary）** — モデルが認識できる断片の固定されたインベントリです。単語ではなく、*断片（pieces）*です。一般的なものは単語全体ですが、珍しいものは細かく分割されます。インベントリは事前に決められた固定サイズを持ち、多くの場合、数万のエントリになります。

**分割（The segmentation）** — 実際の文字列に対して、どの断片をどのような順序で配置するかを決定します。*unbelievable*という単語は、`un` + `believ` + `able`になるかもしれませんし、1つの断片になるかもしれませんし、11個の単一の文字になるかもしれません。どれになるかは、語彙に何が含まれているかに完全に依存します。

> **具体例:** `believ`が語彙に含まれている場合、*unbelievable*は3つの断片を消費します。含まれていない場合、トークナイザーはその単語をカバーできるまで、より小さな断片へとフォールバックしていきます。場合によっては1文字につき1つの断片になります。同じ単語、同じ意味であっても、あなたが入力するずっと前に下された決定によって、断片の数が3倍になったり11倍になったりするのです。

## 2. 語彙は「学習」されるものであり、間違ったものを最適化している

ここが人々を驚かせる部分です。

語彙は言語学者によって設計されるわけではありません。それは**大量のテキストから学習**されます。そのアルゴリズムの目的は**圧縮**、つまり「このテキストを可能な限り少ない断片でカバーすること」です。

意味は一切関係ありません。アルゴリズムは、単語とは何か、接頭辞とは何か、あるいは言語が存在することすら知りません。一緒に頻出するものをカウントし、頻繁に現れるシーケンスに独自のエントリを与えます。そうすることでテキストが短くなるからです。

その結果は機械的に導かれます。断片は、**その言語がテキストの山にどれだけ含まれていたか**にほぼ比例して各言語に割り当てられます。大きな割合を占めた言語には多くの専用の断片が割り当てられ、その単語は全体、あるいはほぼ全体として出力されます。ほとんど含まれていなかった言語には独自の断片がほとんど割り当てられず、その単語はたまたま適合した汎用的な断片によってカバーされることになります。

テキストの山にまったく含まれていなかった言語には、専用の断片が**ゼロ**になります。それでも機能はします。トークナイザーは個々の文字や生のバイトにフォールバックできるため、テキストを表現する*何らかの*方法を常に見つけ出します。ただ、何かを表現するためのコストが非常に高くなるだけです。

:::note[これはバグではありません]
何も誤作動はしていません。圧縮アルゴリズムは要求されたことを正確に実行しました。問題は、「トレーニングテキストを短くする」ことが「言語をうまく表現する」ことの代用として受け入れられたことであり、そのテキストに存在しない言語にとって、この代用は完全に破綻しているということです。
:::

## 3. ファーティリティ（Fertility）: 被害を表す数値

**ファーティリティ（Fertility）**とは、1つの単語が消費するトークンの平均数のことです。

トークナイザーが重点的にトレーニングされた言語の場合、ファーティリティは1に近くなります。つまり、ほとんどの単語が1つの断片になります。一度も見たことのない言語の場合、すべての単語を断片から組み立てる必要があるため、同じ指標が何倍も高くなる可能性があります。

この単一の数値は、4つの別々の「税金（負担）」へと連鎖します。

| 負担 | 意味 |
|---|---|
| **コスト (Cost)** | ほとんどの商用モデルはトークン単位で課金されます。1単語あたりのトークン数が多いということは、同じ文を翻訳、要約、または生成するためにより多くのお金がかかることを意味します。 |
| **コンテキスト (Context)** | モデルには固定のウィンドウサイズがあります。ファーティリティが高いということは、実際のドキュメントが収まる量が少なくなることを意味します。 |
| **計算 (Compute)** | シーケンスが長くなると、どこであっても、常に処理が遅くなります。 |
| **学習 (Learning)** | 最も困難な問題です。意味が多くの情報量の少ない断片に分散してしまうため、同一のデータであっても、モデルはより難しい問題を解決しなければならなくなります。 |

最初の3つは不公平なものです。4つ目は品質を損なうものです。

**これは単なる主張ではなく、測定された事実です。** Petrov、La Malfa、Torr、Bibiの研究によると、同じテキストを異なる言語に翻訳した場合、トークン化された長さが**最大15倍**も異なる可能性があり、多言語での使用を意図して構築されたトークナイザーであっても、この格差が持続することが判明しています。

彼らの発見は、明白な解決策を複雑なものにしています。文字レベルやバイトレベルのモデル、つまり「文字を使えばすべての言語が平等になる」という直感的な答えであっても、一部の言語ペアでは依然として**4倍以上**の差が示されました。より小さな単位にフォールバックすることで格差は縮まりますが、なくなるわけではありません。

> Aleksandar Petrov, Emanuele La Malfa, Philip Torr, Adel Bibi.
> *Language Model Tokenizers Introduce Unfairness Between Languages.*
> [NeurIPS 2023](https://proceedings.neurips.cc/paper_files/paper/2023/hash/74bb24dca8334adce292883b4b651eda-Abstract-Conference.html).

## 4. なぜこれが統計的だけでなく、構造的に一部の言語に打撃を与えるのか

トレーニングデータの山における過小評価が1つの原因です。しかし2つ目の原因もあり、それはデータを追加しても解決しません。

言語によって、1つの単語が果たす役割の大きさが異なります。

英語では、文は主に独立した単語の並びで構成されます。例: *I saw them*。3つの単語、3つの概念があり、その間に空白があります。トークナイザーは、このように振る舞う言語を扱う人々によって構築されたため、それを前提としています。ほとんどのトークナイザーは、文字通り空白を断片の境界として扱います。

他の言語では、意味を持つ部分を積み重ねることで、節全体を**1つの単語**に構築します。言語学者はこれらを**抱合語（polysynthetic languages）**と呼び、アメリカ大陸の先住民の言語などでよく見られます。

> **具体例:** 平原クリー語（nêhiyawêwin）では、*nikî-wâpamâwak*は概ね「私は彼らを見た」を意味します。これは1つの単語です。その中には、誰が行動しているか、行動が過去であること、見ること自体、そして誰が見られているかという、意味を持つ複数の部分が含まれています。
>
> 英語話者であればこれに4つの単語を使用し、英語でトレーニングされたトークナイザーはおそらく4つの断片を消費します。クリー語を見たことがないトークナイザーは、これらの部分のいずれのエントリも持っていないため、意味を持つ境界を一切無視して、この1つの単語をバラバラの断片に切り刻んでしまいます。

2つのことが同時に破綻しています。単語が本来よりもはるかに多くの断片を消費すること、そして断片が**意味の単位を分断**してしまうため、トークナイザーが破壊したばかりの構造をモデルが再構築しなければならないことです。

トレーニングデータの山にクリー語のテキストを追加すれば、最初の問題は改善されます。しかし、2つ目の問題には部分的にしか役立ちません。なぜなら、アルゴリズムは依然として圧縮を最適化しており、圧縮は境界に意味があることを知らないからです。

## 5. トークン化から誤った回答へ

「不適切な分割」から「誤った出力」への連鎖は短いです。

1. トークナイザーが、意味を持たない境界で単語を分割する。
2. 同じ概念が1つのの一貫した断片ではなく、多くの異なる断片の綴りで現れるため、モデルはより弱い関連性しか学習できない。
3. 生成時、モデルは出力を断片ごとに組み立てる。
4. 個々にはもっともらしい断片が組み合わさることで、その言語には**存在しない**単語が形成される可能性がある。

この最後のステップが重要です。単語が複数の部分から構築される言語において、モデルは、その言語を話さない人にとっては整っているように見えるものを生成する可能性があります。つまり、正しく見える断片が組み合わされて、話者なら絶対に口にしないような単語が作られてしまうのです。

標準的な自動スコアリングでは、これを見逃すことがよくあります。なぜなら、これらのスコアは主に参照回答との重複を測定するものであり、正しく見える断片で作られた誤った単語であっても、重複としてカウントされる可能性があるからです。

:::danger[品質スコアを超えてこれが重要である理由]
流暢でありながら誤っている出力は、明らかに壊れている出力よりも危険です。その言語を話さない読者には見分ける方法がありません。これが、Champollionがその言語を話す人による検証や、「これは期待される回答に似ているか？」だけでなく「これは実在する単語か？」を問う構造的なチェックを重視する大きな理由です。
:::

## 6. 誰が決定するのか、そしてなぜそれが真のポイントなのか

上記の内容はすべて、1つの選択から生じています。それは、**トークナイザーが学習したデータの山にどのテキストが含まれていたか**ということです。

その選択を行う者が、すべての言語がどのように分割されるか、使用にどれだけのコストがかかるか、そしてモデルがそれを表現するためにどれだけ苦労しなければならないかを決定します。その決定は、通常は少人数のグループによって初期段階で一度だけ行われ、そのモデルの寿命が尽きるまで事実上永続します。トークナイザーは後から調整できるものではないからです。

また、このことが議論されることはほとんどありません。言語技術に関する議論は、データ、モデルのサイズ、品質スコアに関するものになりがちです。言語がそもそも表現可能かどうかを決定するステップは、それらすべての根底にあるにもかかわらず、単なる配管工事（インフラ）のように扱われています。

だからこそ、このページが存在するのです。コミュニティが、自分たちの言語が機械によってどのように扱われるかを真にコントロールしたいのであれば、データをコントロールするだけでは不十分です。「*私たちの単語がどのように断片に分割されるかを誰が決定したのか？*」という問いには答えがあります。そして、世界のほとんどの言語にとって、現在のその答えは「他の誰か」であり、その言語がほとんど含まれていないテキストの山を圧縮したことによる副作用なのです。
