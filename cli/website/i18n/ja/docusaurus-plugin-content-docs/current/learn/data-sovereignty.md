# ソフトウェアにデータ主権を組み込むということの意味

:::info[対象読者]
すべての方。法律、機械学習、または先住民族のガバナンスに関する予備知識は前提としていません。コンピュータが関与するようになった後でも、コミュニティが自身の言語データの管理を維持するためには実際に何が必要なのか、疑問に思ったことがある方にとって、このページはその詳細な回答となります。
:::

データと同意についての議論の多くは、許可の有無、つまり「誰かが同意したかどうか」で終わってしまいます。
データ主権が投げかけるのは、より踏み込んだ問いです。すなわち、これを**所有**しているのは誰で、どう扱われるかを**決める**のは誰なのか——一度きりではなく、それが存在する限りずっと決めるのは誰なのか、ということです。

その問いは、どこからともなく現れたわけではありません。最初に、そして最も力強くその声を上げたのは先住民族の人々でした。

---

## 1. 問い――そして最初にそれを投げかけた人々

カナダのファースト・ネーションは、データ主権の原則——自らの情報に対するコミュニティの所有権と管理権——を管轄権の主張として明確に打ち出しました。それは、コミュニティと「共に（*with*）」ではなく、コミュニティを「対象として（*on*）」研究が行われ、その結果得られたデータが二度と戻ってこなかったという記録された歴史から生まれたものです。

この成り立ちは単なる豆知識ではありません。これらは誰もが勝手に流用できる汎用的な倫理チェックリストではなく、特定の法的・文化的な環境において特定の人々によって主張された管轄権の宣言であり、それらを定めたコミュニティに帰属するものです。このページでは、いかなる枠組みの原則もその作成者に代わって言い直すことはしません。作成者自身が述べている言葉を直接お読みください。

わかりやすく言えば、個人が自身の個人情報を所有するのと同じように、コミュニティはその文化的な知識やデータを共同で所有し、それに関わるあらゆる段階——何を、どのように、誰が、何のために収集し、その後どう扱うか——を決定します。

それぞれ固有のフレームワークが存在し、それらを互いに置き換えることはできません。先住民族のデータガバナンス全般を対象とする **CARE**（集団的利益 [Collective Benefit]、管理権限 [Authority to Control]、責任 [Responsibility]、倫理 [Ethics]）や、マオリのデータ主権を対象とする **Te Mana Raraunga** などがその例です。それぞれが独自の法的・文化的背景から生まれました。あるフレームワークの名称を別の原則に対して用いることは、それ自体が一種の不可視化（erasure）となります。

## 2. なぜソフトウェアがこれを先鋭化させるのか

原則は、紙の上では善意として存続することができます。しかし、ソフトウェアはこの問題を突きつけます。なぜなら、コンピュータは意図に基づいて動くのではなく、構築されたものに基づいて動くからです。

翻訳システムが評価される一般的な方法を考えてみてください。システムがあなたの言語をうまく翻訳できるかどうかを調べるには、**テストセット**（あなたの言語の文と、その意味のペア）が必要です。ほぼすべての評価プラットフォームは、スコアを算出するためにそのテストセットを**アップロード**するよう求めます。

所有と管理という観点から、もう一度考えてみてください。アップロードするということは、保管権を手渡すことを意味します。複製が他者のマシン上に存在することになるのです。そして通常は、実質的な管理権も手渡すことになります。「やめてほしい」と言うあなたの権利は、実効性のある能力ではなく単なる「お願い」になってしまいます。所有権は書類上だけ残り、ほとんど意味をなさなくなります。

過去に言語データを搾取されたことのあるコミュニティにとって、「アップロードして私たちを信じてください」という言葉は中立的な要求ではありません。それは、すでに起こったことと同じ構図なのです。

## 3. 実際のメカニズムとは何か

このプロジェクトの立場は、主権が本物であるならば、それはポリシーの1段落ではなく、ソフトウェアの特性でなければならないというものです。具体的にどのようなものか、以下に示します。これらは、あなたが評価し、議論できるように説明されています。

**引き渡すことのない登録。** テストセットの登録は、文そのものをアップロードするのではなく、その*所在*を記述し、その正確な内容の暗号化ハッシュを固定することによって行われます。評価時には、システムが元の場所からデータを取得し、ハッシュの一致を確認してスコアリングを行います。データは一切保存されません。保持者が元のデータをオフラインにすれば、そのコーパスは単に評価できなくなるだけです。データは一切移動していないため、管理権は最初あった場所にとどまります。

**最高強度の階層における、送信前の暗号化。** コーパスを一切読まれることなく利用可能にしなければならない場合、それは**保持者自身のデバイス上で**暗号化され、暗号文は保持者の手元に留まります。本プロジェクトが受け取るのは、コンテンツを含まない記述情報のみです。

**単独の当事者では復号できない仕組み。** 鍵はカストディアン（保管者）のグループに分散されるように設計されており、何らかの操作を承認するには、そのうちの一定数（例えば5人中3人）が共同で行動する必要があります。個々のカストディアンが単独で行動することはできず、本プロジェクトも同様です。**Champollionは鍵のシェア（断片）を一切保持しない**ため、誰かの協力があろうとなかろうと復号することはできません。実行が行われるのは、カストディアンの定足数がそれを承認したときだけです。

> **現在の実際の状況。** 現在のところ、封印されたセットの鍵は主催者が保持しています。つまり、それを封印した人が鍵を持っています。カストディアンの仕組みは構築されておりテスト可能ですが、実際のカストディアンを迎えて運用されたことはまだありません。コミュニティの鍵カストディアンは、まだ誰も選任されていません。その構成を決めるのは関係するコミュニティであり、シェアを保持することに同意したグループはまだ存在しないためです。同意が得られるまで、稼働中のカストディアンセットは存在せず、本プロジェクトが候補者を公に指名することもありません。したがって、上記の段落は、実際に運用するための関係性を待っている段階の機能する仕組みとしてお読みください。現在稼働中のものとしてではありません。

**露出を伴わない結果。** 封印された評価から戻ってくるのは、文ではなくスコアです。ある手法の作成者やこのプロジェクトが一度も読んだことのないコーパス上で、その手法が機能することを証明できます。

**送信前の同意。** 外部モデルのAPIにテキストを送信すること自体が、開示にあたります。コミュニティライセンス、カスタムライセンス、または明記されていないライセンスの下にあるコーパスは、権利保持者が明示的に許可を記録するまで、リモート評価を**拒否**します。この拒否はコードによって強制され、いかなる自動化プロセスもコミュニティに代わって許可を与えることはできません。

**一方向のみの可逆性。** 露出は、保持者の意図的な決定によってのみ緩和することができます。デフォルトで、偶然に、あるいは他の誰かの都合によって緩和されることは決してありません。

## 4. これが意味しないこと

**本プロジェクトは、いかなる先住民族データ主権フレームワークに対しても検証、認証、承認を受けていません。評価は行われておらず、保留中の評価もなく、それらが示唆されることもありません。**

現時点で存在するのは、**データ主権をコードとして実現しようとする試み**――先住民族によって明確に示された原則を受け止め、単なる誓約ではなく動作するメカニズムとして表現しようとする試みです。その試みは私たち自身のものです。それが成功しているかどうかを宣言することは、私たちの役割ではありません。適合性の判断は関係するコミュニティに委ねられるべきであり、プロジェクトが自ら適合を主張することは、これらの原則が是正しようとしている姿勢そのものを矮小な形で再現することになります。すなわち、外部の人間がコミュニティの情報の適切な扱い方を決めるという姿勢です。

また、これらはいずれも不可能を保証するものではありません。ソフトウェアには欠陥があります。オペレーターはミスをします。十分な適切な役割を保持する決意を持った当事者が存在することは、いかなるアーキテクチャでも排除できない残存リスクです。私たちの主張はより限定的であり、より有用であると考えています。つまり、**簡単な道は閉ざされており、困難な道には証拠が残る**ということです。

また、原則と仕組みの間にはギャップも存在します。私たちは、みなさんがそれを見つけるのを待つのではなく、自ら明記したいと考えています。これらの仕組みが最も役立つのは保管の面です。このコードは、データを「保持しない」ことに関しては本当に優れています。しかし、所有と管理はソフトウェア単体で対応できる範囲を超えて、暗号技術だけでは解決できない利用規約やガバナンス、関係性にまで及びます。そして、上記のすべての仕組みは、コミュニティが自らのデータを保持するための能力やインフラをすでに備えていることを前提としており、これは決して偏りのない中立な前提ではありません。

## 5. これについて議論してください

この試みは批判に開かれており、この招待は飾りではありません。

先住民族のデータガバナンス、CARE、Te Mana Raraunga、または先住民族の言語技術に携わっている方、あるいはこのインデックスに含まれる言語のコミュニティのメンバーや代表者の方がいらっしゃいましたら、本プロジェクトのどこに誤りがあるかをご指摘いただきたいと考えています。具体的には以下のような点です。

- メカニズムが原則の求める内容を満たしていない箇所
- 位置づけの説明がコミュニティの原則を誤って伝えている箇所、またはその権威を不当に借りている箇所
- 保護的であると説明されているものの、実際には保護として機能しない箇所
- コミュニティにとって必要であるにもかかわらず、まだ構築されていないものがある箇所
- 用語の選択そのものが不適切な箇所

異議申し立てや修正の要望は、
[お問い合わせと削除申請の窓口](/docs/your-words-your-rules)から行うことができます。
ご自身が代表する言語に関するあらゆる情報の削除要請もここに含まれます。その際、外交的・社交辞令的に振る舞う必要はまったくありません。

未審査であることはこの取り組みの事実であり、それを正当化するものではありません。審査を求める試みは誠実ですが、そうでないものは単なる主張にすぎません。

> このページは、コミュニティ自身が生み出した原則に向けて構築を進める、一つの試みに関する説明です。原則そのものについては、それらを提唱した当事者の言葉をご確認ください。この試みは、それらの原則を管理・運営するいかなる組織からも推奨・承認を受けているものではありません。
