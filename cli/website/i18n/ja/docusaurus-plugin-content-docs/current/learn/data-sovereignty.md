# ソフトウェアにデータ主権を組み込むということの意味

:::info[対象読者]
すべての方。法律、機械学習、または先住民族のガバナンスに関する予備知識は前提としていません。コンピュータが関与するようになった後でも、コミュニティが自身の言語データの管理を維持するためには実際に何が必要なのか、疑問に思ったことがある方にとって、このページはその詳細な回答となります。
:::

データと同意に関する議論の多くは、許可（誰かが「はい」と言ったかどうか）で止まってしまいます。データ主権は、より難しい一連の問いを投げかけます。これを**所有**しているのは誰か？これに何が起こるかを決めるのは誰か？誰がこれにアクセスできるのか？それは物理的にどこにあるのか？

これらの問いは、どこからともなく現れたわけではありません。最初に、そして最も力強くこれらの問いを明確にしたのは、先住民族です。

---

## 1. これらの問い — そして最初に問うたのは誰か

カナダのファースト・ネーションズ（First Nations）は、**所有（Ownership）、管理（Control）、アクセス（Access）、保持（Possession）**というデータ主権の原則を、自らの情報に対する管轄権の主張として明確にしました。それは、コミュニティと「共に（*with*）」ではなく、コミュニティを「対象として（*on*）」研究が行われ、その結果得られたデータが二度と戻ってこなかったという記録された歴史から生じたものです。

この起源は単なる豆知識ではありません。これらの原則は、誰でも使える汎用的な倫理チェックリストではありません。特定の民族が、特定の法的・文化的背景の中で行った管轄権の主張であり、それを打ち立てたコミュニティに属するものです。

4つの問いを簡単に説明します。

| | 答えるべき問い |
|---|---|
| **Ownership（所有）** | この情報を所有しているのは誰か？個人が自身の個人情報を所有するのと同じように、コミュニティはその文化的知識とデータを集団として所有します。 |
| **Control（管理）** | これに何が起こるかを決めるのは誰か？コミュニティは、自分たちに関わるあらゆる事柄のすべての段階（何が、どのように、誰によって、何のために収集され、その後どう扱われるか）を管理します。 |
| **Access（アクセス）** | 誰がこれにアクセスできるのか？コミュニティは、どこに保持されていようと、誰が保持していようと、自分たちに関する情報にアクセスできなければなりません。 |
| **Possession（保持）** | それは物理的にどこにあるのか？所有とは異なります。保持とは保管しているという具体的な事実であり、他の3つの原則を単なる約束ではなく、強制力のあるものにするためのメカニズムです。 |

独立したフレームワークが複数存在し、互いに互換性があるわけではありません。先住民族のデータガバナンス全般を対象とする**CARE**（Collective Benefit, Authority to Control, Responsibility, Ethics）や、マオリのデータ主権を対象とする**Te Mana Raraunga**などがあります。それぞれが独自の法的および文化的背景から生まれました。あるフレームワークの名前を別の原則に当てはめて使用することは、それ自体が一種の消去（erasure）となります。

## 2. なぜソフトウェアがこれを先鋭化させるのか

原則は、紙の上では善意として存続することができます。しかし、ソフトウェアはこの問題を突きつけます。なぜなら、コンピュータは意図に基づいて動くのではなく、構築されたものに基づいて動くからです。

翻訳システムが評価される一般的な方法を考えてみてください。システムがあなたの言語をうまく翻訳できるかどうかを調べるには、**テストセット**（あなたの言語の文と、その意味のペア）が必要です。ほぼすべての評価プラットフォームは、スコアを算出するためにそのテストセットを**アップロード**するよう求めます。

先ほどの4つの問いを念頭に置いて、もう一度読んでみてください。アップロードは「保持」を移転させます。通常、それは実質的な「管理」も移転させます。誰か他の人のマシンにコピーが存在するようになった時点で、「やめて」と言うあなたの能力は、権限ではなく単なるお願いになってしまいます。「アクセス」は、あなたが持っているものではなく、与えられるものになります。「所有」は紙の上では存続しますが、あまり意味を持たなくなります。

過去に言語データを搾取されたことのあるコミュニティにとって、「アップロードして私たちを信じてください」という言葉は中立的な要求ではありません。それは、すでに起こったことと同じ構図なのです。

## 3. 実際のメカニズムとは何か

このプロジェクトの立場は、主権が本物であるならば、それはポリシーの1段落ではなく、ソフトウェアの特性でなければならないというものです。具体的にどのようなものか、以下に示します。これらは、あなたが評価し、議論できるように説明されています。

**引き渡しを伴わない登録。** テストセットは、文をアップロードするのではなく、*それがどこにあるか*を記述し、その正確な内容の暗号化ハッシュをピン留めすることによって登録されます。評価時に、システムはソースから取得し、ハッシュが一致するかを確認してスコアを算出します。何も保存されません。保持者がソースをオフラインにすると、コーパスは単に評価できなくなります。「保持」が移動していないため、「管理」は元の場所にとどまります。

**最も強力な階層のための、送信前の暗号化。** コーパスが一度も読み取られることなく使用可能でなければならない場合、データが外部に出る前に**保持者自身のデバイス上で**暗号化されます。このプロジェクトが受け取るのは、暗号文と、内容を含まない説明のみです。

**単一の当事者では復号できない。** 鍵は管理者のグループ間で分割され、何かを承認するには、そのうちの一定数（例えば5人中3人）が共同で行動しなければなりません。個々の管理者が単独で行動することはできず、このプロジェクトも同様です。決定されたモデルでは、**Champollionはシェア（鍵の断片）を一切保持しない**ため、誰かの協力があろうとなかろうと復号することはできません。実行が行われるのは、管理者の定足数がそうすべきだと決定したからです。

> **現在の実際の状況。** メカニズムは構築されており、テスト可能です。*管理者は確定していません*。構成は関与するコミュニティに委ねられており、まだどのグループもシェアを保持することに同意していません。同意が得られるまでは、稼働中の管理者セットは存在せず、このプロジェクトが候補者を公表することもありません。したがって、上記の段落は、現在稼働しているものではなく、それを機能させるための関係構築を待っている、動作可能なメカニズムとしてお読みください。

**露出を伴わない結果。** 封印された評価から戻ってくるのは、文ではなくスコアです。ある手法の作成者やこのプロジェクトが一度も読んだことのないコーパス上で、その手法が機能することを証明できます。

**送信前の同意。** 外部モデルのAPIにテキストを送信すること自体が、開示にあたります。コミュニティライセンス、カスタムライセンス、または明記されていないライセンスの下にあるコーパスは、権利保持者が明示的に許可を記録するまで、リモート評価を**拒否**します。この拒否はコードによって強制され、いかなる自動化プロセスもコミュニティに代わって許可を与えることはできません。

**一方向のみの可逆性。** 露出は、保持者の意図的な決定によってのみ緩和することができます。デフォルトで、偶然に、あるいは他の誰かの都合によって緩和されることは決してありません。

## 4. これが意味しないこと

**このプロジェクトは、いかなる先住民族のデータ主権フレームワークについても、検証、認証、または承認を受けていません。評価は行われておらず、保留中のものもなく、暗示されるものもありません。**

存在するのは、**コードでデータ主権を制定しようとする試み**です。つまり、先住民族によって明確にされた原則を、単なる約束ではなく、機能するメカニズムとして表現しようとするものです。その試みは私たちのものです。それが成功するかどうかは、私たちが宣言することではありません。コンプライアンスの判断は関与するコミュニティに委ねられており、プロジェクトが自らのコンプライアンスを主張することは、これらの原則が正そうとしているまさにその姿勢（部外者がコミュニティの情報の適切な扱い方を決定すること）を縮小して再現することになります。

また、これらはいずれも不可能を保証するものではありません。ソフトウェアには欠陥があります。オペレーターはミスをします。十分な適切な役割を保持する決意を持った当事者が存在することは、いかなるアーキテクチャでも排除できない残存リスクです。私たちの主張はより限定的であり、より有用であると考えています。つまり、**簡単な道は閉ざされており、困難な道には証拠が残る**ということです。

原則とメカニズムの間にはギャップも存在します。私たちは、皆さんがそれを見つけるのを待つよりも、自らそれを明示したいと考えています。「保持」は、これらのメカニズムが最もよく機能する原則です。コードは、物を保持しないことに純粋に優れています。「所有」と「管理」は、ソフトウェア単独で到達できる範囲を超え、どれだけ暗号化を行っても解決できない条件、ガバナンス、関係性にまで及びます。そして、上記のすべてのメカニズムは、コミュニティが自身のデータを保持するための能力とインフラをすでに持っていることを前提としていますが、これは中立的な前提ではありません。

## 5. これについて議論してください

この試みは批判に開かれており、この招待は飾りではありません。

もしあなたが先住民族のデータガバナンス、CARE、Te Mana Raraunga、または先住民族の言語テクノロジーに携わっている場合、あるいはこのインデックスに含まれる言語のコミュニティのメンバーや代表者である場合、これのどこが間違っているかをお聞かせください。具体的には以下の点についてです。

- メカニズムが原則の要求を満たしていない箇所
- 枠組みがコミュニティの原則を誤って伝えている、またはその権威を借用している箇所
- 保護的であると説明されているが、実際には保護にならない箇所
- コミュニティが必要としているが、私たちが構築していないもの
- 用語自体が不適切な箇所

異議申し立てや訂正は、[連絡および削除ルート](/docs/network/community/contact-objections-takedown)を通じて行うことができます。これには、あなたが代表する言語に関するあらゆる情報の削除リクエストも含まれます。その際、外交的（丁寧）である必要はありません。

未審査であることはこの取り組みの事実であり、それを正当化するものではありません。審査を求める試みは誠実ですが、そうでないものは単なる主張にすぎません。

> このページは、コミュニティ自身がその作成者である原則に向けて構築しようとする、一つの試みの説明です。それらの原則は、作成者自身が述べる形で参照してください。この試みは、それらの原則を管理するいかなる組織からも承認されたものではありません。
