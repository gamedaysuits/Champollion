# セキュリティと安全性

Champollionは、ロケールデータが信頼できないソースから提供される可能性や、細工されたファイル名がディレクトリ境界を越えてしまう可能性、LLMの出力に予期しない内容が含まれ得る状況など、敵対的な環境でも安全に動作するように設計されています。

## 脅威モデル

| 脅威 | 攻撃ベクトル | 緩和策 |
|--------|--------------|-----------|
| **プロトタイプ汚染** | 細工されたJSONキー（`__proto__`、`constructor`） | パース時に拒否 |
| **パストラバーサル** | `../../etc/passwd`のようなロケールコード | 設定されたディレクトリへのファイル書き込みを検証 |
| **コードブロックの破損** | LLMがコードフェンス内を翻訳 | Unicodeセンチネルによる保護 |
| **存在しないキーの生成（ハルシネーション）** | 送信されていないキーをLLMが返却 | レスポンス検証 — 承認されたキーのみを書き込み |
| **トークン消費の暴走** | 無限リトライループ | `maxRetries`による予算上限の設定 |

## プロトタイプ汚染ガード

すべてのロケールキーは、処理前にブロックリストと照合して検証されます。

- `__proto__`
- `constructor`
- `prototype`

これらのパターンに一致するキーはエラーとして拒否されます。これにより、攻撃者が細工されたロケールファイルを使用してJavaScriptのオブジェクトプロトタイプを変更するのを防ぎます。

## パスの封じ込め

ロケールファイルを書き込む際、Champollionは出力先パスが設定されたディレクトリ（`localesDir`、`contentDir`）内に留まっていることを検証します。ロケールコードはサニタイズされるため、`../../secrets`のようなコードであっても、想定されたディレクトリの外部に書き込まれることはありません。

## ブロック保護

Markdownコンテンツの翻訳時には、テキストがLLMに送信される前に、構造化要素がUnicodeセンチネルのプレースホルダーに置き換えられます。

1. **コードブロック**（フェンスおよびインライン） → センチネル
2. **Hugoショートコード**（`{{< >}}`、`{{% %}}`） → センチネル  
3. **生HTML** → センチネル
4. **補間変数**（`{{ .Count }}`） → センチネル

翻訳後、センチネルは元のコンテンツに置き戻されます。LLMがコードブロック、ショートコード、HTMLを見ることはないため、これらが破損することはありません。

## レスポンス検証

LLMがJSONレスポンスを返すと、Champollionは以下の点を確認します。
- バッチで送信されたキーのみがレスポンスに含まれていること
- 余分なキーが挿入されていないこと
- レスポンスが有効なJSONとしてパースできること

ハルシネーションによって生成されたキーは警告なしで破棄されます。これにより、LLMの出力によってロケールファイルに予期しない翻訳が挿入されるのを防ぎます。

## クオリティゲート

すべての翻訳は、ディスクに書き込まれる前に5つの決定論的チェックによって検証されます。詳細は[品質ゲート](/docs/concepts/quality-gate)を参照してください。

## 指数バックオフ

API呼び出しでは、429（レート制限）および5xx（サーバーエラー）のレスポンスに対してジッター（ゆらぎ）を伴う指数バックオフが適用されます。遅延時間を延ばしながら3回リトライを行うことで、障害発生時にAPIへ過度な負荷をかけるのを防止します。

## リクエストのタイムアウト

すべてのAPIリクエストには、`AbortController`によって30秒のタイムアウトが設定されています。これにより、切断された接続で同期プロセスが無期限にハングするのを防ぎます。

## 翻訳失敗時の明確なエラー通知

APIが利用できない場合や翻訳が失敗した場合、Champollionは不正なデータをサイレントに書き込むのではなく、対処方法を含む明確なエラーをスローします。同期中に`[EN]`プレフィックスが付いたプレースホルダーが書き込まれることは決してありません。

```
[ERR] Content sync for fr: no API key available.
  Set OPENROUTER_API_KEY in .env.local to translate content.
```

1つのファイルで失敗が発生しても、同期全体が停止することはありません。エラーがログに記録された後、パイプラインは次のファイルの処理を続行するため、1回の実行で最大限の進捗を得ることができます。

## 同期後の検証

すべての翻訳が完了した後、Champollionは書き込まれたロケールファイルをディスクから再読み込みし、検証パスを実行します。これにより、同期処理が成功を報告しているにもかかわらず実際には翻訳に誤りがあるというギャップを検出します。

- **キーの整合性** — 各翻訳先言語にすべてのソースキーが存在すること
- **`[EN]`マーカー** — 過去の実行によるレガシーなフォールバックマーカーの有無
- **空の翻訳** — 混入した空の値
- **文字体系の準拠** — 非ラテン文字ロケールにおけるラテン文字のみの翻訳（文字はUnicodeスクリプトによって分類されるため、アクセント付きラテン文字や全角ラテン文字もラテン文字としてカウントされます）
- **プレースホルダーの維持** — ICUプレースホルダーがソースと一致していること

`--no-verify`でスキップするか、`npx champollion verify`で単独実行できます。

## テスト

セキュリティ特性は、敵対的テストスイートによって検証されています。

```bash
npm run test:redteam    # prototype pollution, path traversal, encoding attacks
```
