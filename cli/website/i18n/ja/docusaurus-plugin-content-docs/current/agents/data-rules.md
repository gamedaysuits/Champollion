# データと送信のルール

言語データを保持する人々が、その利用方法を決定します。レールはその決定を各ファイルの隣に記録し、すべてのツールがそこに書かれた内容に従います。これは、言語データに対するコミュニティの所有権と管理を、単なる設定ではなく設計原則としているためです。このページは、まさにそのルールセットです。各フィールドの役割、ツールが拒否する操作、そしてあなただけが保持できる部分について説明します。

## サイドカー（set/1）

任意のデータファイルの隣で、`<file>.champollion.json`、`$schema`
`https://champollion.dev/schemas/set/1.json`。未知のキーは拒否されます。メモは`x-`の下に配置します。set/1より前に作成されたサイドカー（`$schema`なし）はset/0として読み取られ、有効なまま維持されます（`champollion upgrade`がこれを書き換えます）。

| フィールド | 値 | 効果 |
|---|---|---|
| `transmission` | `local-only`（唯一の値） | このコンピューター上のモデルのみがテキストを見ることができます。すべてのツールは、どこへの送信も拒否します（`mt-eval project offer`を含む） |
| `role` | `train` · `dev` · `test` · `sealed` · `input` · `resource` | ファイルの用途。`test`と`sealed`は学習には一切使用されません |
| `kind` | `parallel` · `monolingual` · `lexicon` · `grammar` · `glossary` | ファイルが保持する内容 |
| `pair` | `{source, target}` | 列の並び順（カードの言語コード表記） |
| `fields` | `{source, target}` | どの列またはJSONフィールドがどちら側を保持するか |
| `terms.training` | `allowed` · `not-allowed` | `not-allowed`：いかなるモデルもこのファイルで学習することはできません |
| `terms.owner` | テキスト | 保持者が誰であるか（保持者自身の言葉による） |
| `terms.speakers` | テキスト | 誰の言葉を保持しているか（保持者自身の言葉による） |
| `terms.speakers_agreed` | `yes` · `not-yet` · `some-said-no` | その言葉の持ち主である人々が同意したかどうか |
| `terms.consent_record` | パス | ファイルのフォルダーからの相対パスによる同意メモ |
| `holders_agreed` | `{by, date}` | ローカル限定の出力がそのまま置かれることに同意した保持者（制限が緩和されることはありません） |
| `derived_from` | パス | このファイルの元となった保護対象ファイル。そのマークがここに引き継がれます |
| `id`、`name`、`license`、`tier`、`segment`、`sha256`、`rows`、`card`、`registeredAt` | | `champollion network register-corpus`によって書き込まれます。変更されたファイル（異なるsha256）にはカードのIDは付与されなくなります |
| `written_by` | テキスト | それを書き込んだコマンド |

**ロック。** サイドカーはファイルをより厳格にするだけであり、コーパスエンベロープやレジストリエントリの記述を緩和することは決してありません。

## ローカル限定と暫定デフォルト

`champollion data add`は、プロジェクトの`defaults.transmission`が`local-only`（`champollion new`が書き込むもの）である場合、また`--into test`については常に、書き出すファイルをローカル限定としてマークします。そのマークは、保持者が回答するまでのツールの保護機能であり、`"x-transmission-default": true`というフラグが付けられます。

- 保持者の最初の回答で決定されます。`champollion data mark <file>
  --may-leave` lifts a provisional mark; `--local-only` を実行すると、保持者の決定となりフラグが削除されます。
- **注意。** ツールは誰がコマンドを実行したかを識別できません。暫定マークの解除は、必ず保持者自身の回答に基づいて行ってください。
- **ロック。** 保持者が設定したローカル限定マークは、いかなるコマンドでも解除できません。「*このファイルはローカル限定としてマークされており、サイドカーは厳格になる一方です。このコンピューター外への持ち出しを許可するかどうかは保持者の決定によるため、同意が得られた場合は手動でサイドカーを編集してください。*」
- **ロック。** まだローカル限定になっていないファイルに対する`data mark`には、`--local-only`または`--may-leave`が必要です。「*このファイルのテキストを外部のAIサービスに送信してよいかどうかは保持者の判断によるものであり、勝手に想定されることはありません*」。

各ツールにおけるローカル限定の意味：

| 場所 | 動作 |
|---|---|
| あらゆる評価（`mt-eval run`、forgeのスコアリング） | ポリシーは`sealed`（ティア`local-only`）に解決されます。ループバックエンドポイント、ハーネス自身のインプロセスアダプター（`local-model`）、または`--attest-local-transport`で実行される外部メソッドのみがテキストを参照できます |
| ターミナルおよび`--json`の出力 | 文は非表示になります。代わりに、行番号、ID、件数、スコアが出力され、その理由を示す1行が表示されます |
| そこから切り出されたファイル | 分割データ、クリーニングされたコピー、仮説、実行ログにはテキストが保持されます（ユーザー自身のフォルダー内に配置されるため）。そして、独自のサイドカーにそのマークを引き継ぎます |
| そのデータで学習したモデル | 出力もローカル限定になります（`forge-model.json` `trained_on.terms`。記録がない場合はローカル限定とみなされます）。`try_translation`はモデルのページのみを返し、`champollion connect`、ループバック外の`mt-eval serve`、プロジェクト外の`mt-eval translate`には`--holders-agreed-by`が必要となり、`sync`は`api`および`local`メソッドのいずれを経由する場合でも回答を保留します（[配信](/docs/agents/serving)） |
| コーチングファイルまたは辞書 | サイドカー付きのコーチングファイルは、そのポリシーをプロンプトに引き継ぎます。辞書がローカル限定である場合、レキシコン実行の出力は非表示になります |

**注意。** `--attest-local-transport`は、メソッドのエンドポイントがローカルであることを宣言します。エンドポイントがこのマシン上にあることを確認した場合にのみ指定してください。ループバックアドレスであっても、任意の場所に転送するプロキシである可能性があります。

## 学習

- **ロック。** nmt-forgeは、サイドカーに`terms.training: not-allowed`と記されているファイルでの学習を拒否します。読み取れないサイドカーは「制限なし」ではなく、常に「制限あり」とみなされます。
- **ロック。** `champollion data combine`は許可されていないファイルを結合することはありません。そのファイルをサイドカーとともに`data/not-for-training/`に移動します。また、保持者がまだ回答していないファイル（`terms.training`がない、または`terms.speakers_agreed`がない場合。「*その中に言葉が含まれている全員が同意したかどうかを誰もまだ表明していません。champollionは次に人々に確認します。その後に結合してください*」）も拒否します。結合されたファイルには、各ファイルの中で最も厳格な条件が引き継がれます（1つでもローカル限定があればローカル限定、1つでも許可されていなければ不許可、すべての所有者が明記されます）。
- **ロック。** ジャーニーの条件確認ステップでは、`data/parallel/`、`data/lexicon/`、`data/grammar/`、または`data/monolingual/`内のファイルについて、サイドカーに`terms.training`と`terms.speakers_agreed`の両方が含まれている場合（かつ学習に関する回答が後述のツールの警告ではなく保持者自身のものである場合）にのみ回答済みとみなします。それまでは再度質問が行われ、レールは先へ進みません。
- **注意。** nmt-forgeが読み取るのは`terms.training`であり、`speakers_agreed`ではありません。1組のペアファイルのみの場合は結合が行われないため、その回答を待つのは条件確認ステップのみとなります。話者の回答がないファイルでは決して学習を行わないでください。
- **ロック。** `test`または`sealed`のファイルは決して学習に使用されません。それらのファイルに対して`--training allowed`を指定することは拒否され、別の役割を割り当てることも拒否されます。
- **ロック。** コマンドによって`not-allowed`を`allowed`に変更することはできません（「*保持者が学習に同意した場合は、手動でサイドカーを編集してください*」）。ただし、後述の1つの例外を除きます。
- 聖書データ（USFM）は、ツールの警告（`"x-training-default": true`）として`terms.training: not-allowed`がマークされた状態で取り込まれます。保持者の回答によってこれが置き換えられます。

## 誰の言葉か、誰が同意したか

`--speakers`はそのファイルが誰の言葉を保持しているかを記録し、`--speakers-agreed`はそれらの人々が同意したかどうかを記録します。

| `speakers_agreed` | 効果 |
|---|---|
| `yes` | 保持者が指定した通りに学習 |
| `not-yet` | 全員の同意が得られるまで学習は強制的に`not-allowed`になります。ファイルは`waiting_for_agreement`に表示されます |
| `some-said-no` | いかなるモデルもそのファイルから学習することはできません。「*その人たちの言葉を別のファイルに取り出し、残りにマークを付けてください*」 |
| （未回答） | 条件確認ステップで確認が続けられ、`data combine`はそのファイルを拒否します（上記参照） |

**コマンドによる唯一の緩和：** `--training allowed`とともに`not-yet` → `yes`にすることです。これにより、`combine`が除外していたファイルは、次回の結合のために`data/parallel/`に戻されます。

**注意。** `waiting_for_agreement`の質問は、1セッションにつき1回、穏やかに行い、全員が同意したという本人の「はい」という返答があった場合のみ回答として入力してください。

**`--holders-agreed-by "<who>"`**は、ローカル限定の出力を特定の場所へ配置することに同意したデータの保持者を指定します。アプリのロケールファイル（`champollion connect`、ペアの`holdersAgreed`として記録）、他のマシンからアクセス可能なアドレス（`mt-eval serve`、`nmt-forge serve`、`/health`で報告）、またはプロジェクト外のファイル（`mt-eval translate`、サイドカーの`holders_agreed`として記録）が対象となります。これ以外の制限が緩和されることはなく、出力はすべてのツールに対してローカル限定のままとなります。**注意。** 本人が伝えた名前のみを渡してください。

## ツールが出力するもの、決して出力しないもの

| ツール | 出力するもの | 決して出力しないもの |
|---|---|---|
| `champollion data add` | 件数、列情報（文字、入力率、平均長、ラテン文字の割合）、ペアの言語のいずれかを指している場合のみヘッダーセル、番号別のELANティア、および行チェックが特定した行番号 | 文、その他のヘッダーセル（代わりにその長さが出力されます）、ELANティアのID |
| `champollion data mark`、`combine`、`next`、`validate` | フィールド、件数、状態 | データファイルのテキスト — ファイルを開くこと自体がありません |
| `champollion improve …` | 件数と割合 | シート内の文 |
| `champollion sync`（`local`および`api`メソッド） | サーバーの`meta.unseen_words`に基づき、forgeモデルが学習で一度も目にしたことのない単語をテキストに含むキー | テキスト、または単語そのもの |
| `nmt-forge`、`mt-eval` | ローカル限定、封印済み、または同意が必要なコーパスの場合：ID、行番号、件数、スコア。エラーメッセージ内の`[sentence withheld]` | 人間向けまたは`--json`の出力に含まれる文 |
| MCPレールツール | CLIが出力するもの（省略形） | 文、ローカル限定モデルの出力 |

**注意。** `--show-text`（nmt-forge、`mt-eval compare`）は非表示の文を出力します。これは自身のターミナルにいる人間向けのものであり、エージェント向けではありません。エージェントが読み取った内容はモデルプロバイダーに送信されてしまいます。

**注意。** ファイルを開くことを防ぐツールはありません。人々のデータファイル、テスト文、単語リスト、スプレッドシートを決して開いたり、出力したり、要約したり、貼り付けたりしないでください。エクスポートされた`input-words.json`も同様です。これには学習文の単語が一覧化されており、モデルフォルダー内ではなく、必ずその横に配置されます（[配信](/docs/agents/serving#what-an-export-holds)）。

**行チェック。** ファイル（対訳ペア、テストセット、単語リスト）を取り込む際、`data add`は辞書を使用せず、何も除外することなく、ファイル自体の2つの列を対象に行をチェックします。件数をカウントし、行番号を特定します。

- コピー：訳文が原文と同一であるもの（固有名詞や借用語であれば問題ありませんが、そうでなければ訳抜けとなります）。
- 以前のペアの重複。
- ファイルの通常の比率と比べて極端に長い、または短い訳（途中で切れている、または1つのセルに2文入っているなど）。
- 入れ替わっているように見える行：原文がファイルの訳文のように読め、その逆も同様であるもの。
- 1行ずれているように見える連続した行：訳文が次または前の行により適合するもの。数字、疑問符、文の長さが1行分ずれて一致し、単語も同様に一致します（同一ファイル内の他の部分で2つの単語がどれくらい共起するかによって、ある行の原文の単語が訳文の単語とどれだけ一致するかを判定します。珍しい単語ほど重み付けが大きくなり、その行自体は計算から除外されます）。これにより、文の長さがどれも似通っているテンプレート文のファイルにおけるズレを発見できます。ファイル内の語彙情報が少なすぎる場合は何も追加されません。

種類ごとに最大12件の行番号（1行ズレの連続については最大6箇所）を出力します。スプレッドシートの場合は、ヘッダーを含めたユーザー自身のファイル内の行番号となります。そしてサイドカーの`x-import.quality`にその件数を記録します。長さ、入れ替え、ズレのチェックには最低20組のペアが必要です。単語リスト（`--into lexicon`）では、コピーと重複のみが対象となります。**注意。** 行番号をそのまま伝えてください。人々が自身のファイル内の該当行を確認して判断します。自分で確認するためにファイルを開くことは決してしないでください。

**ELANファイル。** `data add`がどのティアがどれであるかを判別できない場合（フラグで指定されておらず、その言語として記録されたティアがちょうど1つでない場合）、処理を拒否し、ファイル内の順序でティアを番号順に一覧表示します。別のティアを参照しているティアについては、`tier <n> (<language or
"no language">, <count> annotation(s))`, with `, under tier <m>` のように表示されます。その番号を`--source-col`および`--target-col`（`champollion data add <file> --source-col <number> --target-col <number>`）として指定してください。サイドカーにはその番号が記録されます（`x-import.elan_tiers`）。どのティアも指していない番号やIDは拒否され（`no such tier — … Name a tier by its number`）、記録された言語がその側の言語と一致しないティアも拒否されます。2つのティアは、一方が他方を参照しているか、タイムスロットを共有している場合にのみペアリングされ、推測でペアリングされることは決してありません。**注意。** ティアのIDはファイルの作成者が入力した文字列であり、多くの場合個人の名前が含まれているため、`data add`が出力することはありません。ユーザー自身が正確なIDを入力することは可能ですが、あなたは番号を指定してください。
LIFTファイルは言語コードで照合され、ToolboxファイルはMDFマーカーで照合されます（標準規格上、`\ge`と`\xe`は英語となります）。

## 送信モード

すべての評価は、何かが送信される前にコーパスを1つのモードに解決し（`arena/mt_eval_harness/transmission_policy.py`）、実行ログに記録します。

| モード | 条件 | リモートモデル |
|---|---|---|
| `cleared` | 再配布が許可されたライセンス | 許可 |
| `no-train` | 標準的なクリエイティブ・コモンズの非営利または改変禁止ライセンス、あるいはライセンスを明記していない未登録コーパス | 入力を学習に使用しないチャネル経由のみ：`data_collection: deny`に固定されたOpenRouter、一次ベンダーのAPI、またはローカル。これは「学習を行わない」保証であり、「データを保持しない」保証ではありません |
| `consent-required` | 改変されたライセンス、独自のライセンス、または明記されていないライセンス（`LicenseRef-*`） | データセットのエントリに`transmission_consent`の許諾（`granted_by`、`date`、`scope`、`evidence`）が記録されるまで拒否されます。ローカルは引き続き動作します |
| `sealed` | ホールドアウトセグメント、ゴールドスタンダードセグメント、隔離されたセット、または管理者によるローカル限定マーク | 拒否されます（オーバーライド不可） |

- **ロック。** `consent-required`または`sealed`のコーパスのテキストは、ターミナルにも出力されません。
- `no-train`コーパスに対する外部メソッド（プラグイン）は、警告が表示されるのみで拒否はされません（ハーネス側でプラグインの通信経路を確認できないためです）。`consent-required`および`sealed`コーパスでは、`--attest-local-transport`でない限り拒否されます。
- **ロック。** ローカルプロバイダーは、エンドポイントがループバックアドレス（`localhost`、`127.0.0.1`、`::1`、UNIXソケット）である場合にのみローカルとみなされ、その名前に基づいてローカルと判断されることは決してありません。
- **注意。** `transmission_consent`の許諾を記録したり、権利者に代わってライセンスを解釈したりしないでください。許諾は、権利者からの許可が得られた段階で、データセットの管理者によって記録されます。
- **注意。** `--allow-data-collection`は、ライセンスが明記されていない未登録コーパスに対してのみ非学習固定を解除します。これは呼び出し元が権利を保持していることを主張するものです。本人が権利を保持していると表明した場合にのみ指定してください。

## 登録ティア

コーパスの登録は任意です。レールにおいて必須となることはありません。登録を行うとメタデータカードが書き出され、コーパスの名前付け、比較、および保持者の選択に応じた一覧化が可能になります。`champollion network register-corpus`はターミナルで対話的に実行できるほか、フラグ（`--tier`、`--data`、`--license`、`--name`など）を指定してスクリプトから実行することも可能です。
**注意。** ほかのすべての条件と同様に、ティアの選択も保持者の決定によるものです。

| ティア | カード | テキスト | 拒否する操作 |
|---|---|---|---|
| `local-only`（デフォルト） | `--data`ファイル（または`--out`、あるいはここ）の隣に書き出され、共有カードフォルダーには決して書き出されません | このコンピューター外へ出ることはありません。サイドカーには`transmission: local-only`が付与されます | — |
| `private` | `quarantine: true`を含むメタデータ。npm installからはローカルに留まり、一覧表示には個別のリクエスト（`champollion network submit --type dataset`）が必要です | アップロードされることはありません。送信マークはなく、ライセンスによってモードが決定されます | — |
| `public` | メタデータに加えてソースからの取得ポインタ（`--repo-url`、`--builder`） | ホストされることはありません。ソースから取得されます | 非営利、改変禁止、制限付き、または未確認のライセンス（「*代わりに非公開またはローカル限定で登録してください。*」）、`--data` |
| `sealed` | `quarantine: true`を含むメタデータと封印ブロック（`--seal-input`、`--threshold-pubkey`、`--custodian-group`、`--qualifier-id`） | 暗号文のみが存在し、`<id>.sealed.json`または`--seal-out`に書き出されます | 公開コーパスのバイトコピーであるファイル、`--data` |

すべてのティアにおいて、登録時に何もアップロードされません（`--json`には`uploadedContent: false`と表示されます）。npm installからの唯一のネットワーク通信は、このコンピューター上でファイルのsha256を公開カタログのものと比較する処理です（ハッシュ値が外部へ出ることはありません）。`CHAMPOLLION_OFFLINE=1`を使用した場合、比較が行われなかった旨がカードに記録されます。`--data`の場合、サイドカーには`id`、`name`、`license`、`tier`、`sha256`、`rows`、`card`、`registeredAt`が記録されます。**ロック。** 登録済みIDが再導出されることは決してありません。同じファイルを別のIDで再登録することは拒否され、変更されたファイル（別のsha256）にはカードのIDやグレードが付与されなくなります。

## 出力は派生物

制限された文に対するモデルの出力は、その派生物となります。そして評価プロセスでは、そうした出力が大規模に生成されます。ツールは出力を入力と同様に扱います。

- `cleared`以外のすべてのコーパスにおいて、実行時に「その予測結果は制限された文の機械的派生物であり、配布してはならない」という通知が記録・表示されます。
- テキストが非表示となる場合（ローカル限定、封印済み、同意が必要）、そこから作成されたすべてのファイル（実行ログ、レポート、比較結果、キャッシュエントリ、`mt-eval translate`出力、forgeの分割データ、クリーニングされたコーパス、仮説など）には、そのマーク（`derived_from`、`written_by`）を引き継ぐset/1サイドカーが付与されます。`no-train`コーパスには通知が付与されますが、サイドカーは付与されません。
- ローカル限定のテキストで学習したモデルは、ローカル限定の出力を書き出します（上記参照）。
- `mt-eval publish`は、`--publish-entries`が指定されている場合であっても、ローカル限定コーパスの文をアップロードすることは決してなく、そのようなコーパスに対してはコーチングされたプロンプトをデフォルトでハッシュ値としてのみ公開します。それ以外のコーパスでは、`--redact-coaching`でない限りプロンプトが公開されます。

**注意。** 公開はコミュニティの人々自身の決定であり、彼ら自身の言葉で行われ、事前にプレビュー（`--dry-run`）が提示される必要があります。本人の代わりに実行結果の出力を公開したり、貼り付けたり、送信したりしないでください。
