# shared/

**Cross-runtime SSOT.** Every file here is the one authority for a set of values
that both runtimes — the Python harness (`arena/`) and the JavaScript CLI, MCP
server, and website (`cli/`, `mcp-server/`) — have to agree on. Change a value
**here**, never in a consumer. A number that lives in two places is a number that
will eventually disagree with itself.

Licensed Apache-2.0 (`LICENSE`), same as the CLI package that bundles it.

## The copy rule

The old rule in this file said "never copy it." That was wrong in a way worth
correcting precisely, because half the directory is copied on every npm publish.

- **The Python harness reads this directory directly.** It walks up from its own
  file until it finds `<root>/shared/<name>.json`
  (`arena/mt_eval_harness/metric_manifest.py`, `connection_quality.py`). No copy.
- **The JavaScript CLI cannot.** The published npm package has no monorepo root
  above it, so the SSOT has to travel *inside* the tarball.
  `npm run sync:shared` (`cli/scripts/sync-shared.mjs`, run automatically by
  `prepack`) copies a declared set of files into `cli/shared/`, which the CLI
  loader resolves first. The website twin gets `connection-quality.json` copied
  into `cli/website/src/utils/` the same way.

So the rule is not "never copy." It is:

> **Never hand-edit a copy.** Every copy under `cli/shared/` and
> `cli/website/src/` is generated by `sync:shared` from this directory, and
> equality-tested against it. Edit the file here, run `npm run sync:shared`, and
> let the parity tests confirm the copy followed.

Editing a copy directly is the failure this directory exists to prevent: for
`licenses.json` it means the CLI's non-commercial / no-redistribute gate and the
harness's license logic can classify the same corpus differently, and nothing
tells you.

`sync-shared.mjs` distinguishes two cases and refuses to blur them: root
`shared/` **absent** means a standalone checkout of the published package —
nothing to sync, exit 0; root `shared/` **present** but a declared file missing
means a real bug — it names the file and exits non-zero rather than shipping a
partial bundle.

## Files

### Method and model identity

#### `method-registry.json`

SSOT for translation **methods** (MT engines) and **LLM providers** — 14 entries.
The declarative contract shared by both tools: name, `kind`, env vars,
`method_class`, `paradigm`, license, cost, locale maps. `cli_name` records a CLI
registry key that differs from the canonical name (the `openrouter` provider is
`llm` in the CLI). Validated by `schemas/method-registry.schema.json`.

- **Python:** `arena/mt_eval_harness/method_manifest.py` → `load_method_manifest()`
- **JavaScript:** `cli/lib/method-manifest.js` → `loadMethodManifest()`

The imperative request/response code stays per-runtime (Python `HttpMTMethod`
subclasses, JS method classes); this file is the shared *config*. Add a method
here plus the matching adapter in each runtime, and the parity tests
(`arena/tests/test_method_registry_ssot.py`, `cli/test/method-registry-ssot.test.js`)
keep them locked together.

#### `model-aliases.json`

Short convenience names → full OpenRouter model slugs. The full model list is
fetched from OpenRouter at runtime; this file is only the aliases.

- **Python:** `arena/mt_eval_harness/config.py` → `MODEL_REGISTRY`
- **JavaScript:** `cli/lib/models.js` → `resolveModel()`

Guarded by `arena/tests/test_model_alias_ssot.py` and
`cli/test/model-aliases-ssot.test.js`.

#### `metric-registry.json`

SSOT for **metric identity** — 41 entries mapping a canonical metric id to its
status (`implemented` / proposed), scale, orientation, and card key. This is the
file that decides whether a metric name may be displayed at all: every metric
rendered on the site resolves through it, and an unregistered id is a hard
failure, not a fallback.

- **Python:** `arena/mt_eval_harness/metric_manifest.py`
- **JavaScript:** `cli/scripts/build-metric-pops.mjs`, `cli/scripts/build-seam-runs.mjs`

Validated by `schemas/metric-registry.schema.json`; guarded by
`arena/tests/test_metric_registry_ssot.py` and `arena/tests/test_lyss_roles.py`.

### Licensing

#### `licenses.json`

License metadata for **333 data sources** — the generated artifact
(`_generated` records the builder, timestamp, and inputs). Used by the queue
generator and the `give` script to enforce the rule that corpora with
`do_not_train: true` or non-commercial licenses stay out of the public queue.

Validated by `schemas/licenses.schema.json`.

#### `license-corrections.json`

**19 resolved license determinations, overlaid on top of `licenses.json`.**
`licenses.json` is regenerated from the facts DB and was stale for these sources;
this file is the conservative correction layer — NonCommercial, ShareAlike,
no-redistribution, mixed, and license-unstated sources are marked not
commercial-safe and not freely redistributable.

- **JavaScript:** `cli/lib/license-gate.mjs` (reads the bundled `cli/shared/`
  copy first), `cli/scripts/populate-licenses.mjs`

This file is temporary by design: once a full
`populate-licenses.mjs` → `build-trading-card-data.mjs` → `build-shared-licenses.mjs`
run folds these determinations into `licenses.json`, it becomes redundant and can
be deleted. Until then it is license-critical, and drift between the root copy
and the bundled copy means two runtimes classify the same corpus differently.

### Taxonomies and constants

#### `domain-taxonomy.json`

The **closed 17-code domain taxonomy** plus composite rules. Closed means closed:
`arena/scripts/build_registry.py` hard-fails on a content code that is not in
this file, rather than inventing a bucket.

- **Python:** `arena/scripts/build_registry.py`,
  `arena/scripts/corpora-builder/corpora_builder/{schema,domain_classifier,build_recipe_cards}.py`
- **JavaScript:** `cli/scripts/build-seam-runs.mjs`

Validated by `schemas/domain-taxonomy.schema.json`. Mirrored in
`cli/shared/schemas/corpora-card.schema.json`.

#### `connection-quality.json`

**cq-v1 constants** — the numbers behind composite pair strength (network map,
route finder, cross-pair leaderboard ordering). The math is specified in
`docs/CONNECTION_QUALITY_SPEC.md` and implemented as twins:

- **Python:** `arena/mt_eval_harness/connection_quality.py`
- **JavaScript:** `cli/website/src/utils/connectionQuality.mjs`

The *functions* stay in each twin — they cannot be JSON. Only the constants live
here, and both twins read them, so there is one authority for the numbers.
Floats carry an explicit `.0` so Python round-trips them as float. Derived values
(`W_CONTAM_UNKNOWN`, `W_TRUST_UNKNOWN`) are computed in code, never stored, to
avoid a second source.

Guarded by `arena/tests/test_connection_quality_ssot.py` and
`cli/test/connection-quality-ssot.test.js`, both wired into
`scripts/ssot_parity_gate.sh`.

#### `human-services.json`

Human translation services — provider type, dispatch channel, turnaround, rate,
domains, and per-provider sovereignty flags (`off_community_processing`,
`attribution_required`, `sovereignty_review`, `consent_attested`). Currently 3 entries,
all templates or pending confirmation. Named as `ssot:` by `cli/lib/submit.mjs`.

Every method is welcome, human and machine — this is the file where the human
half is declared. Validated by `schemas/human-services.schema.json`.

### `catalogue/` — cited external evidence

Results Champollion **cites** rather than reproduces. Nothing here is a
Champollion run: these are other people's published numbers, kept with their
provenance so `recommend` can say "someone measured this" without claiming
"we measured this." Champollion-run scores live on the leaderboard, never here.

| File | What it is | Bundled to npm? |
|---|---|---|
| `catalogue/external-results.json` | **Curated, hand-verified headline tier** — the rich results with full provenance. `recommend` tier 2 | Yes |
| `catalogue/external-mt-index.json` | **Bulk cited-results index**, 3.5 MB, built by `arena/scripts/import_mt_leaderboards.py`. `recommend` tier 3 | **No** — monorepo-only |
| `catalogue/metric-reliability.json` | **Which metric to believe for a target language** — WMT meta-eval correlations with human judgment, per language family. Built by `arena/scripts/import_wmt_metaeval.py`. `recommend` tier 4 | Yes |
| `catalogue/method-coverage.json` | **Per-provider claimed coverage** — 11 methods, cite-only ISO 639-3 lists. The SSOT for every per-provider language count shown anywhere. Never hardcode a provider count | Yes |
| `catalogue/sources/*.json` | Dated provenance snapshots of upstream model cards (m2m100, madlad400) — the receipts behind the coverage claims | No — not runtime data |

Consumers: `arena/mt_eval_harness/recommend.py`, `cli/lib/recommend.js`,
`arena/scripts/generate_sweep_queue.py`, `arena/scripts/verify_connection_quality.py`,
`cli/scripts/build-seam-hubs.mjs`, `cli/scripts/build-seam-runs.mjs`,
`cli/scripts/derive-method-coverage-small-models.mjs`.
Guarded by `arena/tests/test_method_coverage_catalogue.py` and
`arena/tests/test_wmt_metaeval.py`.

Because `external-mt-index.json` is not bundled, `recommend` tier 3 degrades to
"no bulk evidence" in the published npm package — honestly, not silently. This is
documented at `cli/lib/recommend.js`.

### `schemas/` — JSON Schema for the files above

Nine schemas, one per SSOT that has one:

| Schema | Validates |
|---|---|
| `domain-taxonomy.schema.json` | `domain-taxonomy.json` |
| `external-mt-index.schema.json` | `catalogue/external-mt-index.json` |
| `external-results.schema.json` | `catalogue/external-results.json` |
| `human-services.schema.json` | `human-services.json` |
| `licenses.schema.json` | `licenses.json` |
| `method-registry.schema.json` | `method-registry.json` |
| `metric-registry.schema.json` | `metric-registry.json` |
| `metric-reliability.schema.json` | `catalogue/metric-reliability.json` |
| `model-aliases.schema.json` | `model-aliases.json` |

Map-shaped SSOTs (alias → model id, source id → license entry) are validated in
two passes — document skeleton against the schema root, then every entry against
the `$defs` entry schema. See `cli/test/shared-ssot-schemas.test.js`.

`connection-quality.json` and `queue-selection-vectors.json` have no schema; they
are pinned by their parity tests instead.

Card schemas (`language-card`, `corpora-card`, `method-card`,
`champollion-plugin`) are **not** here — they live in `cli/shared/schemas/`,
because they describe CLI-owned data rather than cross-runtime SSOT.

### `queue-selection-vectors.json` — the drift guard

Cross-language test vectors for the queue item selection algorithm: 10 scenarios
plus a shared `items` fixture. This is the SSOT that stops the Python
`select_items()` and the JS `filterQueue()` from drifting apart.

```
queue-selection-vectors.json     <- single source of truth
          |
    +-----+-----+
    v           v
 Python        JS
 select_items  filterQueue
 (canonical)   (port)
    |           |
    v           v
 pytest      node --test
```

Both suites load the same scenarios and assert their implementation produces the
expected output. Change the selection algorithm in one runtime and not the other,
and the other suite fails.

- **Python:** `arena/tests/test_run_queue.py` → `TestSharedSelectionVectors`
- **JavaScript:** `mcp-server/test/tools.test.js` → `shared selection vectors (SSOT)`

Harness-and-agent side only — the CLI has no consumer, so this file is not
bundled to npm.

To add a scenario: append to `scenarios` with `name`, `params`, `expected_ids`;
add `override_items` if the defaults do not fit; then run both suites
(`cd arena && pytest`, `cd mcp-server && npm test`). Both must pass — if they do
not, the implementations have already drifted.

## What gets bundled where

`cli/scripts/sync-shared.mjs` is the manifest. It copies **18** files into
`cli/shared/` and **1** into the website tree:

- Runtime SSOT: `model-aliases`, `method-registry`, `metric-registry`,
  `human-services`, `licenses`, `license-corrections`, `domain-taxonomy`
- Catalogue: `external-results`, `method-coverage`, `metric-reliability`
- Schemas: the 8 corresponding to the above
- Derived: `connection-quality.json` → `cli/website/src/utils/connection-quality.json`

Deliberately excluded, so the omission reads as a decision rather than an
oversight: `catalogue/external-mt-index.json` (3.5 MB bulk index),
`queue-selection-vectors.json` (no CLI consumer), `catalogue/sources/`
(provenance, not runtime data).

`cli/package.json` ships `cli/shared/` wholesale to npm, minus `language-cards/`,
`corpora-cards/`, and `curated-intros/crk.md`. `prepack` runs `sync:shared`
first, so the published tarball always carries a freshly synced bundle — or the
publish fails.

## Known gaps

Stated rather than implied, so the next audit does not have to rediscover them.

- **`cli/test/shared-bundle-parity.test.js` guards 12 of the 18 bundled files.**
  Unguarded: `domain-taxonomy.json`, `catalogue/metric-reliability.json`, and the
  `domain-taxonomy`, `metric-reliability`, `human-services`, and `method-registry`
  schemas. The test also still cites `cli/package.json` as the manifest location;
  the manifest moved into `cli/scripts/sync-shared.mjs`.
- **`license-corrections.json` is scaffolding.** It should be folded into
  `licenses.json` by a full populate → build-trading-card-data →
  build-shared-licenses run, then deleted.
- **`connection-quality.json` and `queue-selection-vectors.json` have no schema.**
  Their parity tests are the only structural check.

## Adding a new shared file

1. Add the JSON here, in `shared/`. This directory is the SSOT — nowhere else.
2. Add a JSON Schema in `schemas/` and wire it into
   `cli/test/shared-ssot-schemas.test.js`.
3. Have the Python side load it by walking up to `<root>/shared/`. Have the JS
   side resolve the bundled `cli/shared/` copy first, then the root.
4. If the CLI needs it at runtime, add it to `BUNDLED` in
   `cli/scripts/sync-shared.mjs` **and** to `BUNDLE_MANIFEST` in
   `cli/test/shared-bundle-parity.test.js`. If it does not need it, add it to
   `EXCLUDED` with the reason — an unexplained omission looks like a bug.
5. Write a parity test in each suite that consumes it, and add fast ones to
   `scripts/ssot_parity_gate.sh`.
6. Document it in this README, in the section it belongs to, naming its
   consumers by path.
