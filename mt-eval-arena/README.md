# MT Eval Arena — Data Infrastructure

> Database infrastructure for the [the Network](https://champollion.dev/docs/network) and [Champollion](https://champollion.dev) projects. Houses Supabase migrations, data build scripts, and the pipeline that promotes data from the local SQLite ingestion layer to the Supabase serving layer.

## Architecture

```
SQLite (local ingestion)  →  Build Script (compute)  →  Supabase (managed SSOT)
        ↑                                                      ↑
  CLDF enrichment                                     Website queries here
  scripts populate                                    (runtime, read-only)
```

**Supabase is the managed source of truth** for all served data. The SQLite database is the local ingestion/enrichment layer — it never leaves the developer's machine.

## Directory Structure

```
mt-eval-arena/
├── supabase/
│   ├── migrations/       # Active Supabase migrations (applied in order)
│   └── historical/       # Archived migrations (read-only, never modify)
├── scripts/
│   ├── db.mjs            # SQLite accessor (reads local champollion.db)
│   ├── build-trading-card-data.mjs  # Compute stats from SQLite
│   └── upload-trading-cards.mjs     # Upsert computed data to Supabase
├── package.json
└── README.md
```

## Usage

### Prerequisites

- Node.js 20+
- Local `champollion.db` (generated by the CLI enrichment pipeline)
- Supabase service role key in `.env`

### Build and upload trading card data

```bash
npm install

# Build from SQLite (compute stats, rarity, abilities)
npm run build

# Upload to Supabase (upsert all trading card data)
npm run upload

# Or both in one step
npm run build-and-upload
```

### Apply a new migration

```bash
# Migrations are applied via the Supabase dashboard or CLI:
supabase db push --db-url <your-db-url>
```

## Migrations

### Active (`supabase/migrations/`)

Applied to the production Supabase instance. Numbered sequentially. Never reorder or modify applied migrations — only add new ones.

### Historical (`supabase/historical/`)

Archived from earlier development phases (CLI and crk-translate repos). Kept for reference only. **Never apply these — they are already reflected in the production schema.**

## Data Flow

| Data | Serving Layer | Updated By |
|------|--------------|------------|
| Trading card index (8K languages) | `trading_card_index` table | `upload-trading-cards.mjs` |
| Trading card detail (per-language) | `trading_card_detail` table | `upload-trading-cards.mjs` |
| Leaderboard (run cards) | `run_cards` table | `mt-eval publish` (harness CLI) |
| Contests | `contests` table | Direct Supabase insert |
| Datasets | `datasets` table | `mt-eval publish` (harness CLI) |
