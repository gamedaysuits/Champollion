# Local Supabase stack (rehearsal + from-scratch migration proof)

A **sibling** workdir of `../supabase/`, on purpose: that directory's `.temp/`
is linked to the *production* project ref, so any `supabase link`, `db push`
or `db reset --linked` run there targets prod. This workdir has no link and can
only reach `127.0.0.1`.

- `supabase/config.toml` — the local stack: API 54321, Postgres 54322 (major 17,
  as prod), storage on, email sign-up with confirmations OFF (so
  `POST /auth/v1/signup` returns a refresh token the harness consumes via
  `MT_EVAL_REFRESH_TOKEN`), studio/realtime/edge-runtime/analytics off.
- `supabase/migrations/` — GENERATED by `reset.sh` (gitignored), never
  edited by hand: byte-for-byte copies of the three CLI-era files in
  `../supabase/historical/` (they create `run_cards` and `datasets`; the
  canonical `001` already ALTERs `run_cards`, so a from-nothing build cannot
  start at 001 — found 2026-09-06) followed by every canonical
  `../supabase/migrations/NNN_*.sql` under a sortable timestamp prefix.
- `reset.sh [OUT_DIR]` — `supabase start` + `supabase db reset`, reports the
  first failing migration by name, then runs `sanity.sql` (with the Postgres
  container's own `psql` when the guest has none; retries `supabase status`
  until it reports `DB_URL`); writes `OUT_DIR/record.json`. Last from-nothing
  run 2026-09-07: 77 rows (3 historical + 001–074), 24 s, sanity passed —
  re-run several times that day as the sovereign rehearsal was driven end to
  end against it, with the same result each time.

  `OUT_DIR` also holds `status.env` (the local stack's anon and **service-role**
  keys). It is a throwaway key for a loopback stack, but it is still a key:
  `rehearse.sh` collects `record.json` and the reset log into its report
  directory and deliberately leaves `status.env` on the guest.
- `apply_migrations.sh [--prereqs] [--from NNN] [DB_URL]` — the diagnostic
  fallback: one file at a time with `psql -v ON_ERROR_STOP=1`, per-file timing,
  stops at the first error with its full text. Refuses any non-loopback URL.
  `--prereqs` creates `pg_net` and `supabase_vault` for a fresh stack.
- `sanity.sql` — asserts the tables, RPCs, the private `contest-intake`
  bucket, the 054 event trigger, `pg_net` + the `vault` schema (the 055
  trigger reads `vault.decrypted_secrets` on every `run_cards` INSERT), and the
  022 quarantine trigger.

Needs: the `supabase` CLI and a Docker daemon (the rehearsal's organizer guest
has both; see `arena/deploy/sovereign-node/`). Never point the harness at this
stack with `MT_EVAL_ALLOW_PROD`; it is not prod and needs no opt-in.
